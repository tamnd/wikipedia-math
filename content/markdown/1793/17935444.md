# Curve25519

::: {#o1 .subject cue=lead name="Curve25519"}

In [cryptography](wikipedia://en/18934432), **Curve25519** is an [elliptic curve](wikipedia://en/10225) used in [elliptic-curve cryptography](wikipedia://en/9966) (ECC) offering 128 [bits of security](https://en.wikipedia.org/wiki/Bits_of_security) (256-bit [key size](wikipedia://en/5749)) and designed for use with the [Elliptic-curve Diffie–Hellman](wikipedia://en/3357958) (ECDH) key agreement scheme, first described and implemented by [Daniel J. Bernstein](wikipedia://en/198983). It is one of the fastest curves in ECC, and is not covered by any known patents.[^o2] The [reference implementation](https://en.wikipedia.org/wiki/Reference_implementation) is [public-domain software](https://en.wikipedia.org/wiki/Public-domain_software).[^o3][^o4]

:::

The original Curve25519 paper defined it as a [Diffie–Hellman](https://en.wikipedia.org/wiki/Diffie–Hellman) (DH) function. Bernstein has since proposed that the name Curve25519 be used for the underlying curve, and the name **X25519** for the DH function.[^o5]

## Mathematical properties {#Mathematical_properties}

The curve used is y<sup>2</sup> = x<sup>3</sup> + 486662·x<sup>2</sup> + x, a [Montgomery curve](wikipedia://en/25780671), over the [prime field](https://en.wikipedia.org/wiki/Prime_field) defined by the [pseudo-Mersenne prime number](https://en.wikipedia.org/wiki/Pseudo-Mersenne_prime)[^o7] $2^{255} - 19$ (hence the numeric "25519" in the name), and it uses the base point with $x = 9$. This point generates a cyclic subgroup whose [order](wikipedia://en/493527) is the prime $2^{252} + 27742317777372353535851937790883648493$. This subgroup has a co-factor of 8, meaning the number of elements in the subgroup is $\tfrac{1}{8}$ that of the elliptic curve group. Using a prime order subgroup prevents mounting a [Pohlig–Hellman algorithm](wikipedia://en/1995624) attack.[^o14]

The protocol uses compressed elliptic point (only *X* coordinates), so it allows efficient use of the [Montgomery ladder](https://en.wikipedia.org/wiki/Montgomery_ladder) for [ECDH](https://en.wikipedia.org/wiki/Elliptic_curve_Diffie–Hellman), using only *XZ* coordinates.[^o8]

Curve25519 is constructed such that it avoids many potential implementation pitfalls.[^o9]

The curve is [birationally equivalent](wikipedia://en/382733) to a [twisted Edwards curve](wikipedia://en/25889726) used in the [Ed25519](https://en.wikipedia.org/wiki/Ed25519)[^o10][^o11] signature scheme.[^o12]

## History {#History}

In 2005, Curve25519 was first released by [Daniel J. Bernstein](wikipedia://en/198983).[^o14]

In 2013, interest began to increase considerably when it was discovered that the [NSA](https://en.wikipedia.org/wiki/NSA) had potentially implemented a [backdoor](https://en.wikipedia.org/wiki/Backdoor_%28computing%29) into the P-256 curve based [Dual\_EC\_DRBG](wikipedia://en/14259066) algorithm.[^o15] While not directly related,[^o16] suspicious aspects of the NIST's P curve constants[^o17] led to concerns[^o18] that the NSA had chosen values that gave them an advantage in breaking the encryption.[^o19][^o20]

"I no longer trust the constants. I believe the NSA has manipulated them through their relationships with industry."

Since 2013, Curve25519 has become the *[de facto](https://en.wikipedia.org/wiki/De_facto)* alternative to P-256, being used in a wide variety of applications.[^o21] Starting in 2014, [OpenSSH](wikipedia://en/25490426)[^o22] defaults to Curve25519-based [ECDH](https://en.wikipedia.org/wiki/ECDH) and [GnuPG](https://en.wikipedia.org/wiki/GnuPG) adds support for [Ed25519](https://en.wikipedia.org/wiki/Ed25519) keys for signing and encryption.[^o23] The use of the curve was eventually standardized for both key exchange and signature in 2020.[^o24][^o25]

In 2017, NIST announced that Curve25519 and [Curve448](wikipedia://en/56665655) would be added to Special Publication 800-186, which specifies approved elliptic curves for use by the US Federal Government.[^o26] Both are described in RFC 7748.[^o27] A 2019 draft of "FIPS 186-5" notes the intention to allow usage of [Ed25519](https://en.wikipedia.org/wiki/Ed25519)[^o28] for digital signatures. The 2023 update of Special Publication 800-186 allows usage of Curve25519.[^o29]

In February 2017, the [DNSSEC](https://en.wikipedia.org/wiki/DNSSEC) specification for using Ed25519 and Ed448 was published as 8080, assigning algorithm numbers 15 and 16.[^o30]

In 2018, [DKIM](https://en.wikipedia.org/wiki/DKIM) specification was amended so as to allow signatures with this algorithm.[^o31] Also in 2018, RFC 8446 was published as the new [Transport Layer Security v1.3](wikipedia://en/187813#TLS_1.3) standard. It recommends support for [X25519](https://en.wikipedia.org/wiki/X25519), [Ed25519](wikipedia://en/40775836#Ed25519), [X448](https://en.wikipedia.org/wiki/X448), and [Ed448](https://en.wikipedia.org/wiki/Ed448) algorithms.[^o32]
