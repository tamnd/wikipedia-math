# Abstract machine

::: {#o1 .subject cue=lead name="Abstract machine"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science), an **abstract machine** is a theoretical model that allows for a detailed and precise analysis of how a computer system functions.[^o2] It is similar to a [mathematical function](wikipedia://en/185427) in that it receives inputs and produces outputs based on predefined rules. Abstract machines vary from literal machines in that they are expected to perform correctly and independently of [hardware](https://en.wikipedia.org/wiki/Hardware_description_language).[^o3] Abstract machines are "[machines](https://en.wikipedia.org/wiki/Machine)" because they allow step-by-step execution of [programs](wikipedia://en/23015); they are "[abstract](https://en.wikipedia.org/wiki/Abstraction_%28computer_science%29)" because they ignore many aspects of actual ([hardware](https://en.wikipedia.org/wiki/Hardware_description_language)) machines.[^o4] A typical abstract machine consists of a definition in terms of input, output, and the set of allowable operations used to turn the former into the latter. They can be used for purely theoretical reasons as well as models for real-world computer systems.[^o3] In the [theory of computation](wikipedia://en/30402), abstract machines are often used in [thought experiments](https://en.wikipedia.org/wiki/Thought_experiments) regarding [computability](https://en.wikipedia.org/wiki/Computability) or to analyse the complexity of [algorithms](wikipedia://en/775).[^o4] This use of abstract machines is fundamental to the field of [computational complexity theory](wikipedia://en/7543), such as with [finite state machines](wikipedia://en/10931), [Mealy machines](wikipedia://en/331512), [push-down automata](wikipedia://en/24510), and [Turing machines](wikipedia://en/30403).[^o5]

:::

## Classification {#Classification}

Abstract machines are typically categorized into two types based on the quantity of operations they can execute simultaneously at any given moment: [deterministic abstract machines](https://en.wikipedia.org/wiki/Deterministic_algorithm) and [non-deterministic abstract machines](wikipedia://en/665957).[^o3] A [deterministic](https://en.wikipedia.org/wiki/Deterministic_algorithm) abstract machine is a system in which a particular beginning state or condition always yields the same outputs. There is no randomness or variation in how inputs are transformed into outputs.[^o7] In contrast, a [non-deterministic](wikipedia://en/665957) abstract machine can provide various outputs for the same input on different executions.[^o3] Unlike a deterministic algorithm, which gives the same result for the same input regardless of the number of iterations, a non-deterministic algorithm takes various paths to arrive at different outputs.[^o8] Non-deterministic algorithms are helpful for obtaining approximate answers when deriving a precise solution using a deterministic approach is difficult or costly.[^o9]

*Image: 2-state 3-symbol Turing Machine.png.* A run of a [Turing machine](wikipedia://en/30403)

[Turing machines](wikipedia://en/30403), for example, are some of the most fundamental abstract machines in computer science.[^o3] These machines conduct operations on a [tape (a string of symbols)](wikipedia://en/27701) of any length. Their instructions provide for both modifying the symbols and changing the symbol that the machine’s pointer is currently at. For example, a rudimentary Turing machine could have a single command, "convert symbol to 1 then move right", and this machine would only produce a string of 1s.[^o10] This basic Turing machine is deterministic; however, [nondeterministic Turing machines](wikipedia://en/21935) that can execute several actions given the same input may also be built.[^o3]

## Implementation {#Implementation}

Any implementation of an abstract machine in the case of physical implementation (in [hardware](https://en.wikipedia.org/wiki/Hardware_description_language)) uses some kind of physical device (mechanical or electronic) to execute the instructions of a [programming language](wikipedia://en/23015). An abstract machine, however, can also be implemented in [software](https://en.wikipedia.org/wiki/Software) or [firmware](https://en.wikipedia.org/wiki/Firmware) at levels between the abstract machine and underlying physical device.[^o13]

- [Implementation in hardware](https://en.wikipedia.org/wiki/Hardware_description_language): The direct implementation of abstract machine in hardware is a matter of using physical devices such as [memory](https://en.wikipedia.org/wiki/Memory_cell_%28computing%29), [arithmetic](https://en.wikipedia.org/wiki/Arithmetic_logic_unit) and [logic circuits](https://en.wikipedia.org/wiki/Logic_gate), buses, etc., to implement a physical machine whose machine language coincides with the [programming language](wikipedia://en/23015). Once constructed, it would be virtually hard to change such a machine.[^o13] A [CPU](https://en.wikipedia.org/wiki/Central_processing_unit) may be thought of as a concrete hardware realisation of an abstract machine, particularly the [processor's design](https://en.wikipedia.org/wiki/Processor_%28computing%29).[^o14]
- [Simulation using software](https://en.wikipedia.org/wiki/Software): Implementing an abstract machine with software entails writing programmes in a different [language](wikipedia://en/23015) to implement the [data structures](wikipedia://en/8519) and [algorithms](wikipedia://en/775) needed by the abstract machine. This provides the most flexibility since programmes implementing abstract machine constructs can be easily changed.[^o13] An abstract machine implemented as a software simulation, or for which an [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29) exists, is called a [virtual machine](https://en.wikipedia.org/wiki/Virtual_machine).[^o15]
- [Emulation using firmware](https://en.wikipedia.org/wiki/Firmware): Firmware implementation sits between hardware and software implementation. It consists of [microcode](https://en.wikipedia.org/wiki/Microcode) simulations of [data structures](wikipedia://en/8519) and [algorithms](wikipedia://en/775) for abstract machines.[^o13] [Microcode](https://en.wikipedia.org/wiki/Microcode) allows a computer programmer to write machine [instructions](https://en.wikipedia.org/wiki/Machine_code) without needing to fabricate [electrical circuitry](https://en.wikipedia.org/wiki/Electronic_circuit).[^o16]

## Programming language implementation {#Programming_language_implementation}

An abstract machine is, intuitively, just an [abstraction](https://en.wikipedia.org/wiki/Abstraction_%28computer_science%29) of the idea of a physical computer.[^o18] For actual execution, [algorithms](wikipedia://en/775) must be properly formalised using the constructs offered by a [programming language](wikipedia://en/23015). This implies that the algorithms to be executed must be expressed using programming language instructions.[^o4] The [syntax of a programming language](https://en.wikipedia.org/wiki/Syntax_%28programming_languages%29) enables the construction of [programs](https://en.wikipedia.org/wiki/Computer_program) using a finite set of constructs known as instructions. Most abstract machines share [a program store](https://en.wikipedia.org/wiki/Stored-program_computer) and [a state](https://en.wikipedia.org/wiki/State_%28computer_science%29), which often includes [a stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29) and registers.[^o13][^o19] In digital computers, the stack is simply a [memory unit](https://en.wikipedia.org/wiki/Memory_cell_%28computing%29) with an address register that can count only positive integers (after an initial value is loaded into it). The address register for the stack is known as [a stack pointer](https://en.wikipedia.org/wiki/Program_counter) because its value always refers to the top item on the stack.[^o20] The program consists of a series of instructions, with [a stack pointer](https://en.wikipedia.org/wiki/Program_counter) indicating the next instruction to be performed. When the instruction is completed, [a stack pointer](https://en.wikipedia.org/wiki/Program_counter) is advanced. This fundamental control mechanism of an abstract machine is also known as its [execution loop](https://en.wikipedia.org/wiki/Execution_%28computing%29).[^o4] Thus, an abstract machine for a programming language is any collection of [data structures](wikipedia://en/8519) and algorithms capable of storing and running programs written in the programming language. It bridges the gap between the [high level of a programming language](https://en.wikipedia.org/wiki/High-level_programming_language) and the [low level of an actual machine](https://en.wikipedia.org/wiki/Low-level_programming_language) by providing an intermediate language step for [compilation](https://en.wikipedia.org/wiki/Compiler). An abstract machine's instructions are adapted to the unique operations necessary to implement operations of a certain source language or set of source languages.[^o13]

### Imperative languages {#Imperative_languages}

In the late 1950s, the [Association for Computing Machinery (ACM)](https://en.wikipedia.org/wiki/Association_for_Computing_Machinery) and other allied organisations developed many proposals for [Universal Computer Oriented Language (UNCOL)](https://en.wikipedia.org/wiki/UNCOL), such as [Conway's machine](wikipedia://en/37035). The UNCOL concept is good, but it has not been widely used due to the poor performance of the generated [code](https://en.wikipedia.org/wiki/Code). In many areas of computing, its performance will continue to be an issue despite the development of the [Java Virtual Machine](https://en.wikipedia.org/wiki/Java_virtual_machine) in the late 1990s. [Algol Object Code](https://en.wikipedia.org/wiki/ALGOL) (1964), P4-machine (1976), [UCSD P-machine](https://en.wikipedia.org/wiki/UCSD_Pascal) (1977), and [Forth](https://en.wikipedia.org/wiki/Forth_%28programming_language%29) (1970) are some successful abstract machines of this kind.[^o4]

### Object-oriented languages {#Object-oriented_languages}

Abstract machines for [object-oriented programming languages](https://en.wikipedia.org/wiki/Object-oriented_programming) are often [stack-based](https://en.wikipedia.org/wiki/Stack-based_memory_allocation) and have special access instructions for [object fields](https://en.wikipedia.org/wiki/Object_%28computer_science%29) and [methods](https://en.wikipedia.org/wiki/Method_%28computer_programming%29). In these machines, [memory management](https://en.wikipedia.org/wiki/Memory_management) is often implicit performed by a [garbage collector](https://en.wikipedia.org/wiki/Garbage_collection_%28computer_science%29) (memory recovery feature built into programming languages).[^o23] [Smalltalk-80](https://en.wikipedia.org/wiki/Smalltalk) (1980), [Self](https://en.wikipedia.org/wiki/Self_%28programming_language%29) (1989), and [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) (1994) are examples of this implementation.[^o4]

### String processing languages {#String_processing_languages}

A [string processing language](wikipedia://en/27701) is a computer language that focuses on processing strings rather than numbers. There have been string processing languages in the form of [command shells](https://en.wikipedia.org/wiki/Shell_%28computing%29), [programming tools](https://en.wikipedia.org/wiki/Programming_tool), [macro processors](https://en.wikipedia.org/wiki/General-purpose_macro_processor), and [scripting languages](https://en.wikipedia.org/wiki/Scripting_language) for decades.[^o25] Using a suitable abstract machine has two benefits: increased [execution speed](https://en.wikipedia.org/wiki/Execution_%28computing%29) and enhanced portability. [Snobol4](https://en.wikipedia.org/wiki/SNOBOL) and [ML/I](https://en.wikipedia.org/wiki/ML/I) are two notable instances of early string processing languages that use an abstract machine to gain machine independence.[^o4]

### Functional programming languages {#Functional_programming_languages}

*Image: Machine de Krivine.jpg.* Pictorial representation of a [Krivine machine](https://en.wikipedia.org/wiki/Krivine_machine)

The early abstract machines for [functional languages](https://en.wikipedia.org/wiki/Functional_programming), including the [SECD machine](https://en.wikipedia.org/wiki/SECD_machine) (1964) and Cardelli's Functional Abstract Machine (1983), defined strict evaluation, also known as [eager or call-by-value evaluation](wikipedia://en/2977119),[^o4] in which function arguments are evaluated before the call and precisely once. Recently, the majority of research has been on [lazy (or call-by-need) evaluation](https://en.wikipedia.org/wiki/Lazy_evaluation),[^o27] such as the G-machine (1984), [Krivine machine](https://en.wikipedia.org/wiki/Krivine_machine) (1985), and Three Instruction Machine (1986), in which function arguments are evaluated only if necessary and at most once. One reason is because effective implementation of strict evaluation is now well-understood, therefore the necessity for an abstract machine has diminished.[^o4]

### Logical languages {#Logical_languages}

[Predicate calculus (first order logic)](wikipedia://en/10983) is the foundation of [logic programming languages](https://en.wikipedia.org/wiki/Logic_programming). The most well-known logic programming language is [Prolog](wikipedia://en/23485). The rules in Prolog are written in a uniform format known as universally quantified 'Horn clauses', which means to begin the calculation that attempts to discover a proof of the objective. The [Warren Abstract Machine WAM](https://en.wikipedia.org/wiki/Warren_Abstract_Machine) (1983),[^o4] which has become the de facto standard in Prolog program compilation, has been the focus of most study. It provides special purpose instructions such as data unification instructions and control flow instructions to support backtracking (searching algorithm).[^o29]

## Structure {#Structure}

A generic abstract machine is made up of a [memory](https://en.wikipedia.org/wiki/Memory_cell_%28computing%29) and an [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29). The memory is used to store data and programs, while the interpreter is the component that executes the instructions included in programs.[^o13]

*Image: The\_structure\_of\_an\_abstract\_machine.png.* The structure of an abstract machine

The interpreter must carry out the operations that are unique to the [language](wikipedia://en/23015) it is interpreting. However, given the variety of languages, it is conceivable to identify categories of operations and an "[execution mechanism](https://en.wikipedia.org/wiki/Execution_%28computing%29)" shared by all interpreters. The interpreter's operations and accompanying data structures are divided into the following categories:[^o13][^o31]

1. Operations for processing [primitive data](https://en.wikipedia.org/wiki/Primitive_data_type):
1. Operations and data structures for controlling the sequence of [execution of operations](https://en.wikipedia.org/wiki/Execution_%28computing%29);
1. Operations and data structures for controlling [data transfers](https://en.wikipedia.org/wiki/Data_communication);
1. Operations and data structures for [memory management](https://en.wikipedia.org/wiki/Memory_management).

### Processing primitive data {#Processing_primitive_data}

An abstract machine must contain operations for manipulating primitive data types such as strings and integers.[^o13] For example, integers are nearly universally considered a basic data type for both physical abstract machines and the abstract machines used by many [programming languages](wikipedia://en/23015). The machine carries out the [arithmetic operations](wikipedia://en/3118) necessary, such as addition and multiplication, within a single time step.[^o33]

### Sequence control {#Sequence_control}

Operations and structures for "sequence control" allow controlling the [execution flow](https://en.wikipedia.org/wiki/Execution_%28computing%29) of program instructions. When certain [conditions](https://en.wikipedia.org/wiki/Conditional_%28computer_programming%29) are met, it is necessary to change the typical sequential execution of a program.[^o13] Therefore, the [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29) employs data structures (such as those used to store the [address](https://en.wikipedia.org/wiki/Address_%28programming_language%29) of the next instruction to execute) that are modified by operations distinct from those used for data manipulation (for example, operations to update the address of the next instruction to execute).[^o35]

### Controlling data transfers {#Controlling_data_transfers}

Data transfer operations are used to control how operands and data are transported from [memory](https://en.wikipedia.org/wiki/Memory_cell_%28computing%29) to the interpreter and vice versa. These operations deal with the [store](https://en.wikipedia.org/wiki/Stored-program_computer) and the retrieval order of operands from the store.[^o13]

### Memory management {#Memory_management}

[Memory management](https://en.wikipedia.org/wiki/Memory_management) is concerned with the operations performed in memory to allocate data and applications. In the abstract machine, data and programmes can be held indefinitely, or in the case of programming languages, memory can be allocated or deallocated using a more complex mechanism.[^o13]

## Hierarchies {#Hierarchies}

*Image: A\_hierarchy\_of\_abstract\_machines.png.* A hierarchy of abstract machines

Abstract machine hierarchies are often employed, in which each machine uses the functionality of the level immediately below and adds additional functionality of its own to meet the level immediately above. A [hardware computer](https://en.wikipedia.org/wiki/Computer_hardware), constructed with physical electronic devices, can be added at the most basic level. Above this level, the abstract [microprogrammed machine level](https://en.wikipedia.org/wiki/Microcode) may be introduced. The abstract machine supplied by the [operating system](https://en.wikipedia.org/wiki/Operating_system), which is implemented by a program written in [machine language](https://en.wikipedia.org/wiki/Machine_code), is located immediately above (or directly above the [hardware](https://en.wikipedia.org/wiki/Computer_hardware) if the [firmware](https://en.wikipedia.org/wiki/Firmware) level is not there). On the one hand, the operating system extends the capability of the physical machine by providing higher-level primitives that are not available on the physical machine (for example, primitives that act on files). The [host machine](https://en.wikipedia.org/wiki/Hypervisor) is formed by the abstract machine given by the operating system, on which a [high-level programming language](https://en.wikipedia.org/wiki/High-level_programming_language) is implemented using an [intermediary machine](https://en.wikipedia.org/wiki/Virtual_machine), such as the Java Virtual machine and its byte code language. The level given by the abstract machine for the [high-level language](https://en.wikipedia.org/wiki/High-level_programming_language) (for example, Java) is not usually the final level of hierarchy. At this point, one or more applications that deliver additional services together may be introduced. A "web machine" level, for example, can be added to implement the functionalities necessary to handle Web communications ([communications protocols](https://en.wikipedia.org/wiki/Communication_protocol) or [HTML code presentation](https://en.wikipedia.org/wiki/HTML)). The "[Web Service](https://en.wikipedia.org/wiki/Web_service)" level is located above this, and it provides the functionalities necessary to make web services communicate, both in terms of interaction protocols and the behaviour of the processes involved. At this level, entirely new languages that specify the behaviour of so-called "business processes" based on Web services may be developed (an example is the [Business Process Execution Language](https://en.wikipedia.org/wiki/Business_Process_Execution_Language)). Finally, a specialised application can be found at the highest level (for example, [E-commerce](https://en.wikipedia.org/wiki/E-commerce)) which has very specific and limited functionality.[^o13]
