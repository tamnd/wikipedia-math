# Fractal compression

*Image: Zasada dzialania ifs 1.svg.* 2 triangles, example to show how fractal compression works

::: {#o1 .subject cue=lead name="Fractal compression"}

**Fractal compression** is a [lossy compression](https://en.wikipedia.org/wiki/Lossy_compression) method for [digital images](https://en.wikipedia.org/wiki/Digital_image), based on [fractals](wikipedia://en/10913). The method is best suited for textures and natural images, relying on the fact that parts of an image often resemble other parts of the same image.[^o2] Fractal [algorithms](https://en.wikipedia.org/wiki/Algorithms) convert these parts into mathematical data called "fractal codes" which are used to recreate the encoded image.

:::

## Iterated function systems {#Iterated_function_systems}

Fractal image representation may be described mathematically as an [iterated function system](wikipedia://en/505225) (IFS).[^o7]

### For binary images {#For_binary_images}

We begin with the representation of a [binary image](https://en.wikipedia.org/wiki/Binary_image), where the image may be thought of as a subset of $\mathbb{R}^2$. An IFS is a set of [contraction mappings](wikipedia://en/6239) *ƒ*<sub>1</sub>,...,*ƒ<sub>N</sub>*,

$$f_i:\mathbb{R}^2\to \mathbb{R}^2.$$

According to these mapping functions, the IFS describes a two-dimensional set *S* as the fixed point of the [Hutchinson operator](wikipedia://en/18502646)

$$H(A)=\bigcup_{i=1}^N f_i(A), \quad A \subset \mathbb{R}^2.$$

That is, *H* is an operator mapping sets to sets, and *S* is the unique set satisfying *H*(*S*) = *S*. The idea is to construct the IFS such that this set *S* is the input binary image. The set *S* can be recovered from the IFS by [fixed point iteration](https://en.wikipedia.org/wiki/Fixed_point_iteration): for any nonempty [compact](wikipedia://en/6042) initial set *A*<sub>0</sub>, the iteration *A*<sub>*k*+1</sub> = *H*(*A<sub>k</sub>*) converges to *S*.

The set *S* is self-similar because *H*(*S*) = *S* implies that *S* is a union of mapped copies of itself:

$$S=f_1(S)\cup f_2(S) \cup\cdots\cup f_N(S)$$

So we see the IFS is a fractal representation of *S*.

### Extension to grayscale {#Extension_to_grayscale}

IFS representation can be extended to a [grayscale image](https://en.wikipedia.org/wiki/Grayscale_image) by considering the image's [graph](wikipedia://en/87352) as a subset of $\mathbb{R}^3$. For a grayscale image *u*(*x*,*y*), consider the set *S* = {(*x*,*y*,*u*(*x*,*y*))}. Then similar to the binary case, *S* is described by an IFS using a set of contraction mappings *ƒ*<sub>1</sub>,...,*ƒ<sub>N</sub>*, but in $\mathbb{R}^3$,

$$f_i:\mathbb{R}^3\to \mathbb{R}^3.$$

### Encoding {#Encoding}

A challenging problem of ongoing research in fractal image representation is how to choose the *ƒ*<sub>1</sub>,...,*ƒ<sub>N</sub>* such that its fixed point approximates the input image, and how to do this efficiently.

A simple approach[^o7] for doing so is the following partitioned iterated function system (PIFS):

1. Partition the image domain into range blocks *R<sub>i</sub>* of size *s*×*s*.
1. For each *R<sub>i</sub>*, search the image to find a block *D<sub>i</sub>* of size 2*s*×2*s* that is very similar to *R<sub>i</sub>*.
1. Select the mapping functions such that *H*(*D<sub>i</sub>*) = *R<sub>i</sub>* for each *i*.

In the second step, it is important to find a similar block so that the IFS accurately represents the input image, so a sufficient number of candidate blocks for *D<sub>i</sub>* need to be considered. On the other hand, a large search considering many blocks is computationally costly. This bottleneck of searching for similar blocks is why PIFS fractal encoding is much slower than, for example, [DCT](wikipedia://en/59962) and [wavelet](wikipedia://en/50903) based image representation.

The initial square partitioning and [brute-force search](https://en.wikipedia.org/wiki/Brute-force_search) algorithm presented by Jacquin provides a starting point for further research and extensions in many possible directions—different ways of partitioning the image into range blocks of various sizes and shapes; fast techniques for quickly finding a close-enough matching domain block for each range block rather than brute-force searching, such as fast [motion estimation](https://en.wikipedia.org/wiki/Motion_estimation) algorithms; different ways of encoding the mapping from the domain block to the range block; etc.[^o8]

Other researchers attempt to find algorithms to automatically encode an arbitrary image as RIFS (recurrent iterated function systems) or global IFS, rather than PIFS; and algorithms for fractal video compression including [motion compensation](https://en.wikipedia.org/wiki/Motion_compensation) and three dimensional iterated function systems.[^o9][^o10]

Fractal image compression has many similarities to [vector quantization](wikipedia://en/47805) image compression.[^o11]

## Features {#Features}

With fractal compression, encoding is extremely computationally expensive because of the search used to find the self-similarities. Decoding, however, is quite fast. While this asymmetry has so far made it impractical for real time applications, when video is archived for distribution from disk storage or file downloads fractal compression becomes more competitive.[^o13][^o14]

At common compression ratios, up to about 50:1, fractal compression provides similar results to [DCT-based](wikipedia://en/59962) algorithms such as [JPEG](https://en.wikipedia.org/wiki/JPEG).[^o15] At high compression ratios fractal compression may offer superior quality. For satellite imagery, ratios of over 170:1[^o16] have been achieved with acceptable results. Fractal video compression ratios of 25:1–244:1 have been achieved in reasonable compression times (2.4 to 66 sec/frame).[^o17]

Compression efficiency increases with higher image complexity and color depth, compared to simple [grayscale](https://en.wikipedia.org/wiki/Grayscale) images.

### Resolution independence and fractal scaling {#Resolution_independence_and_fractal_scaling}

An inherent feature of fractal compression is that images become resolution independent[^o19] after being converted to fractal code. This is because the iterated function systems in the compressed file scale indefinitely. This indefinite scaling property of a fractal is known as "fractal scaling".

::: {#o21 .pointer-item cue=pointer name="Fractal interpolation"}

### Fractal interpolation {#Fractal_interpolation}

The resolution independence of a fractal-encoded image can be used to increase the display resolution of an image. This process is also known as "fractal interpolation". In fractal interpolation, an image is encoded into fractal codes via fractal compression, and subsequently decompressed at a higher resolution. The result is an up-sampled image in which iterated function systems have been used as the [interpolant](https://en.wikipedia.org/wiki/Interpolant).[^o22] Fractal interpolation maintains geometric detail very well compared to traditional interpolation methods like [bilinear interpolation](wikipedia://en/674484) and [bicubic interpolation](wikipedia://en/1396397).[^o23][^o24][^o25] Since the interpolation cannot reverse Shannon entropy however, it ends up sharpening the image by adding random instead of meaningful detail. One cannot, for example, enlarge an image of a crowd where each person's face is one or two pixels and hope to identify them.

:::

## History {#History}

[Michael Barnsley](wikipedia://en/1014175) led the development of fractal compression from 1985 at the Georgia Institute of Technology (where both Barnsley and Sloan were professors in the mathematics department).[^o27] The work was sponsored by [DARPA](https://en.wikipedia.org/wiki/DARPA) and the [Georgia Tech Research Corporation](https://en.wikipedia.org/wiki/Georgia_Tech_Research_Institute). The project resulted in several [patents](https://en.wikipedia.org/wiki/Patent) from 1987.[^o28] Barnsley's graduate student Arnaud Jacquin implemented the first automatic algorithm in software in 1992.[^o29][^o30] All methods are based on the [fractal transform](wikipedia://en/42960) using [iterated function systems](wikipedia://en/505225). Michael Barnsley and Alan Sloan formed Iterated Systems Inc.[^o31] in 1987 which was granted over 20 additional patents related to fractal compression.

A major breakthrough for Iterated Systems Inc. was the automatic fractal transform process which eliminated the need for human intervention during compression as was the case in early experimentation with fractal compression technology. In 1992, Iterated Systems Inc. received a US\$2.1 million government grant[^o32] to develop a prototype digital image storage and decompression chip using fractal transform image compression technology.

Fractal image compression has been used in a number of commercial applications: [onOne Software](https://en.wikipedia.org/wiki/OnOne_Software), developed under license from Iterated Systems Inc., [Genuine Fractals](https://en.wikipedia.org/wiki/Genuine_Fractals) 5 which is a [Photoshop](https://en.wikipedia.org/wiki/Photoshop) plugin capable of saving files in compressed FIF (Fractal Image Format). To date the most successful use of still fractal image compression is by [Microsoft](https://en.wikipedia.org/wiki/Microsoft) in its [Encarta](https://en.wikipedia.org/wiki/Encarta) multimedia encyclopedia,[^o34] also under license.

Iterated Systems Inc. supplied a shareware encoder (Fractal Imager), a stand-alone decoder, a Netscape plug-in decoder and a development package for use under Windows. The redistribution of the "decompressor DLL" provided by the ColorBox III SDK was governed by restrictive per-disk or year-by-year licensing regimes for proprietary software vendors and by a discretionary scheme that entailed the promotion of the Iterated Systems products for certain classes of other users.[^o35]

ClearVideo – also known as [RealVideo](https://en.wikipedia.org/wiki/RealVideo) (Fractal) – and SoftVideo were early fractal video compression products. ClearFusion was Iterated's freely distributed streaming video plugin for web browsers. In 1994 SoftVideo was licensed to [Spectrum Holobyte](https://en.wikipedia.org/wiki/Spectrum_Holobyte) for use in its [CD-ROM](https://en.wikipedia.org/wiki/CD-ROM) games including Falcon Gold and [Star Trek: The Next Generation A Final Unity](https://en.wikipedia.org/wiki/Star_Trek:_The_Next_Generation_A_Final_Unity).[^o36]

In 1996, Iterated Systems Inc. announced[^o37] an alliance with the [Mitsubishi](https://en.wikipedia.org/wiki/Mitsubishi) Corporation to market ClearVideo to their Japanese customers. The original ClearVideo 1.2 decoder driver is still supported[^o38] by Microsoft in [Windows Media Player](https://en.wikipedia.org/wiki/Windows_Media_Player) although the encoder is no longer supported.

Two firms, Total Multimedia Inc. and Dimension, both claim to own or have the exclusive licence to Iterated's video technology, but neither has yet released a working product. The technology basis appears to be Dimension's U.S. patents 8639053 and 8351509, which have been considerably analyzed.[^o39] In summary, it is a simple quadtree block-copying system with neither the bandwidth efficiency nor PSNR quality of traditional DCT-based codecs. In January 2016, TMMI announced that it was abandoning fractal-based technology altogether.

Research papers between 1997 and 2007 discussed possible solutions to improve fractal algorithms and encoding hardware.[^o40][^o41][^o42][^o43][^o44][^o45][^o46][^o47][^o48]

## Implementations {#Implementations}

A library called *Fiasco* was created by Ullrich Hafner. In 2001, *Fiasco* was covered in the *[Linux Journal](https://en.wikipedia.org/wiki/Linux_Journal)*. [^o51] According to the 2000-04 *Fiasco* manual, *Fiasco* can be used for video compression. [^o52] The [Netpbm](https://en.wikipedia.org/wiki/Netpbm) library includes the *Fiasco* library. [^o53][^o54]

Femtosoft developed an implementation of fractal image compression in [Object Pascal](https://en.wikipedia.org/wiki/Object_Pascal) and [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29). [^o55]
