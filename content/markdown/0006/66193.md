# Prefix code

::: {#o1 .subject cue=lead name="Prefix code"}

A **prefix code** is a type of [code](https://en.wikipedia.org/wiki/Code) system distinguished by its possession of the **prefix property**, which requires that there is no whole code word in the system that is a [prefix](https://en.wikipedia.org/wiki/Prefix_%28computer_science%29) (initial segment) of any other code word in the system. It is trivially true for fixed-length codes, so only a point of consideration for [variable-length codes](https://en.wikipedia.org/wiki/Variable-length_code).

:::

For example, a code with code $\{ \texttt{a}, \texttt{bb} \}$ has the prefix property; a code consisting of $\{\texttt{a},\texttt{b},\texttt{ab},\texttt{aa}\}$ does not, because a is a prefix of ab and also of aa. A prefix code is a [uniquely decodable code](https://en.wikipedia.org/wiki/Uniquely_decodable_code): given a complete and accurate sequence, a receiver can identify each word without requiring a special marker between words. However, there are uniquely decodable codes that are not prefix codes; for instance, the reverse of a prefix code is still uniquely decodable (it is a suffix code), but it is not necessarily a prefix code.

Prefix codes are also known as **prefix-free codes**, **prefix condition codes** and **instantaneous codes**. Although [Huffman coding](wikipedia://en/13883) is just one of many algorithms for deriving prefix codes, prefix codes are also widely referred to as "Huffman codes", even when the code was not produced by a Huffman algorithm. The term **comma-free code** is sometimes also applied as a synonym for prefix-free codes[^o2][^o3] but in most mathematical books and articles (e.g.[^o4][^o5]) a comma-free code is used to mean a [self-synchronizing code](wikipedia://en/41687), a subclass of prefix codes.

Using prefix codes, a message can be transmitted as a sequence of concatenated code words, without any [out-of-band](https://en.wikipedia.org/wiki/Out-of-band_data) markers or (alternatively) special markers between words to [frame](https://en.wikipedia.org/wiki/Framing_%28telecommunication%29) the words in the message. The recipient can decode the message unambiguously, by repeatedly finding and removing sequences that form valid code words. This is not generally possible with codes that lack the prefix property, for example $\{\texttt{0}, \texttt{1}, \texttt{10}, \texttt{11}\}$: a receiver reading a 1 at the start of a code word would not know whether that was the complete code word 1, or merely the prefix of the code word 10 or 11; so the string 10 could be interpreted either as a single codeword or as the concatenation of the words 1 then 0.

The variable-length [Huffman codes](wikipedia://en/13883), [telephone country codes](https://en.wikipedia.org/wiki/Telephone_country_code), the country and publisher parts of [ISBNs](https://en.wikipedia.org/wiki/ISBN), the Secondary Synchronization Codes used in the [UMTS](https://en.wikipedia.org/wiki/UMTS) [W-CDMA](https://en.wikipedia.org/wiki/W-CDMA) 3G Wireless Standard, and the [instruction sets](https://en.wikipedia.org/wiki/Instruction_set) (machine language) of most computer microarchitectures are prefix codes.

Prefix codes are not [error-correcting codes](https://en.wikipedia.org/wiki/Error-correcting_codes). In practice, a message might first be compressed with a prefix code, and then encoded again with [channel coding](https://en.wikipedia.org/wiki/Channel_coding) (including error correction) before transmission.

For every [uniquely decodable](https://en.wikipedia.org/wiki/Variable-length_code#Uniquely_decodable_codes) code there is a prefix code that has the same code word lengths.[^o6] [Kraft's inequality](https://en.wikipedia.org/wiki/Kraft's_inequality) characterizes the sets of code word lengths that are possible in a uniquely decodable code.[^o7]

## Techniques {#Techniques}

If every word in the code has the same length, the code is called a **fixed-length code**, or a **block code** (though the term [block code](wikipedia://en/1134659) is also used for fixed-size [error-correcting codes](https://en.wikipedia.org/wiki/Error-correcting_code) in [channel coding](https://en.wikipedia.org/wiki/Channel_coding)). For example, [ISO 8859-15](https://en.wikipedia.org/wiki/ISO_8859-15) letters are always 8 bits long. [UTF-32/UCS-4](https://en.wikipedia.org/wiki/UTF-32/UCS-4) letters are always 32 bits long. [ATM cells](https://en.wikipedia.org/wiki/Asynchronous_Transfer_Mode) are always 424 bits (53 bytes) long. A fixed-length code of fixed length $k$ bits can encode up to $2^{k}$ source symbols.

A fixed-length code is necessarily a prefix code. It is possible to turn any code into a fixed-length code by padding fixed symbols to the shorter prefixes in order to meet the length of the longest prefixes. Alternately, such padding codes may be employed to introduce redundancy that allows autocorrection and/or synchronisation. However, fixed length encodings are inefficient in situations where some words are much more likely to be transmitted than others.

[Truncated binary encoding](https://en.wikipedia.org/wiki/Truncated_binary_encoding) is a straightforward generalization of fixed-length codes to deal with cases where the number of symbols *n* is not a power of two. Source symbols are assigned codewords of length $k$ and $k + 1$, where $k$ is chosen so that $2^k < n \le 2^{k+1}$.

[Huffman coding](wikipedia://en/13883) is a more sophisticated technique for constructing variable-length prefix codes. The Huffman coding algorithm takes as input the frequencies that the code words should have, and constructs a prefix code that minimizes the weighted average of the code word lengths. (This is closely related to minimizing the entropy.) This is a form of [lossless data compression](https://en.wikipedia.org/wiki/Lossless_data_compression) based on [entropy encoding](https://en.wikipedia.org/wiki/Entropy_encoding).

Some codes mark the end of a code word with a special "comma" symbol (also called a [Sentinel value](https://en.wikipedia.org/wiki/Sentinel_value)), different from normal data.[^o10] This is somewhat analogous to the spaces between words in a sentence; they mark where one word ends and another begins. If every code word ends in a comma, and the comma does not appear elsewhere in a code word, the code is automatically prefix-free. However, reserving an entire symbol only for use as a comma can be inefficient, especially for languages with a small number of symbols. [Morse code](https://en.wikipedia.org/wiki/Morse_code) is an everyday example of a variable-length code with a comma. The long pauses between letters, and the even longer pauses between words, help people recognize where one letter (or word) ends, and the next begins. Similarly, [Fibonacci coding](wikipedia://en/48063) uses a 11 to mark the end of every code word.

[Self-synchronizing codes](wikipedia://en/41687) are prefix codes that allow [frame synchronization](https://en.wikipedia.org/wiki/Frame_synchronization).

## Related concepts {#Related_concepts}

A **suffix code** is a set of words none of which is a suffix of any other; equivalently, a set of words which are the reverse of a prefix code. As with a prefix code, the representation of a string as a concatenation of such words is unique. A **bifix code** is a set of words which is both a prefix and a suffix code.[^o13] An **optimal prefix code** is a prefix code with minimal average length. That is, assume an alphabet of $n$ symbols with probabilities $p(A_i)$ for a prefix code $C$. If $C'$ is another prefix code and $\lambda'_i$ are the lengths of the codewords of $C'$, then $\sum_{i=1}^n { \lambda_i p(A_i) } \leq \sum_{i=1}^n { \lambda'_i p(A_i) } \!$.[^o14]

:::

## Prefix codes in use today {#Prefix_codes_in_use_today}

Examples of prefix codes include:

- variable-length [Huffman codes](wikipedia://en/13883)
- [telephone country codes](https://en.wikipedia.org/wiki/Telephone_country_code)
- [Chen–Ho encoding](https://en.wikipedia.org/wiki/Chen–Ho_encoding)
- the country and publisher parts of [ISBNs](https://en.wikipedia.org/wiki/ISBN)
- the Secondary Synchronization Codes used in the [UMTS](https://en.wikipedia.org/wiki/UMTS) [W-CDMA](https://en.wikipedia.org/wiki/W-CDMA) 3G Wireless Standard
- [VCR Plus+ codes](https://en.wikipedia.org/wiki/VCR_Plus)
- [Unicode Transformation Format](https://en.wikipedia.org/wiki/Unicode_Transformation_Format), in particular the [UTF-8](https://en.wikipedia.org/wiki/UTF-8) system for encoding [Unicode](https://en.wikipedia.org/wiki/Unicode) characters, which is both a prefix-free code and a [self-synchronizing code](wikipedia://en/41687)[^o16]
- [opcode prefixes](https://en.wikipedia.org/wiki/Opcode_prefix) used in computer instruction sets
- [variable-length quantity](https://en.wikipedia.org/wiki/Variable-length_quantity)

### Techniques {#Techniques}

Commonly used techniques for constructing prefix codes include [Huffman codes](wikipedia://en/13883) and the earlier [Shannon–Fano codes](wikipedia://en/62544), and [universal codes](wikipedia://en/2522009) such as:

- [Elias delta coding](https://en.wikipedia.org/wiki/Elias_delta_coding)
- [Elias gamma coding](https://en.wikipedia.org/wiki/Elias_gamma_coding)
- [Elias omega coding](https://en.wikipedia.org/wiki/Elias_omega_coding)
- [Fibonacci coding](wikipedia://en/48063)
- [Levenshtein coding](wikipedia://en/4730929)
- [Unary coding](https://en.wikipedia.org/wiki/Unary_coding)
- [Golomb Rice code](https://en.wikipedia.org/wiki/Golomb_Rice_code)
- [Straddling checkerboard](wikipedia://en/395985) (simple cryptography technique which produces prefix codes)
- binary coding[^o18]
