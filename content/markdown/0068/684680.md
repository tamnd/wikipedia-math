# Strongly connected component

::: {#o1 .subject cue=lead name="Strongly connected component"}

*Image: Scc-1.svg.* Graph with shaded areas showing strongly connected components

In the [mathematical](wikipedia://en/18831) theory of [directed graphs](wikipedia://en/19721986), a graph is said to be **strongly connected** if every vertex is [reachable](wikipedia://en/2833097) from every other vertex. The **strongly connected components** of a directed graph form a [partition](wikipedia://en/340240) into [subgraphs](https://en.wikipedia.org/wiki/Subgraph_%28graph_theory%29) that are strongly connected themselves. It is possible to test the strong [connectivity](wikipedia://en/1614492) of a graph, or to find its strongly connected components, in [linear time](https://en.wikipedia.org/wiki/Linear_time) (that is, Θ(*V* + *E*)).

:::

::: {#o3 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

A [directed graph](wikipedia://en/19721986) is called **strongly connected** if there is a [path](wikipedia://en/638889) in each direction between each pair of vertices of the graph. That is, a path exists from the first vertex in the pair to the second, and another path exists from the second vertex to the first. In a directed graph *G* that may not itself be strongly connected, a pair of vertices *u* and *v* are said to be strongly connected to each other if there is a path in each direction between them.

The [binary relation](wikipedia://en/3931) of being strongly connected is an [equivalence relation](wikipedia://en/9259), and the [induced subgraphs](wikipedia://en/1655188) of its [equivalence classes](wikipedia://en/9260) are called **strongly connected components**. Equivalently, a **strongly connected component** of a directed graph *G* is a subgraph that is strongly connected, and is [maximal](https://en.wikipedia.org/wiki/Maximal_element) with this property: no set of additional edges or vertices from *G* can be included in the subgraph without breaking its property of being strongly connected. The collection of strongly connected components forms a partition of the set of vertices of *G*. A strongly connected component *C* is called *trivial* when *C* consists of a single vertex which is not connected to itself with an edge, and *non-trivial* otherwise.[^o4]

*Image: Graph Condensation.svg.* The yellow [directed acyclic graph](wikipedia://en/204002) is the condensation of the blue directed graph. It is formed by contracting each strongly connected component of the blue graph into a single yellow vertex.

If each strongly connected component is [contracted](https://en.wikipedia.org/wiki/Vertex_contraction) to a single vertex, the resulting graph is a [directed acyclic graph](wikipedia://en/204002), the **condensation** of *G*. A directed graph is acyclic if and only if it has no strongly connected subgraphs with more than one vertex, because a [directed cycle](https://en.wikipedia.org/wiki/Directed_cycle) is strongly connected and every non-trivial strongly connected component contains at least one directed cycle.

## Algorithms {#Algorithms}

### DFS-based linear-time algorithms {#DFS-based_linear-time_algorithms}

Several [algorithms](wikipedia://en/775) based on [depth-first search](wikipedia://en/97034) compute strongly connected components in linear time.

- [Kosaraju's algorithm](wikipedia://en/4072443) uses two passes of depth-first search. The first, in the original graph, is used to choose the order in which the outer loop of the second depth-first search tests vertices for having been visited already and [recursively](wikipedia://en/25407) explores them if not. The second depth-first search is on the [transpose graph](wikipedia://en/5966396) of the original graph, and each recursive exploration finds a single new strongly connected component.[^o8][^o14] It is named after [S. Rao Kosaraju](https://en.wikipedia.org/wiki/S._Rao_Kosaraju), who described it (but did not publish his results) in 1978; [Micha Sharir](https://en.wikipedia.org/wiki/Micha_Sharir) later published it in 1981.[^o9]
- [Tarjan's strongly connected components algorithm](wikipedia://en/8244667), published by [Robert Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan) in 1972,[^o10] performs a single pass of depth-first search. It maintains a [stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29) of vertices that have been explored by the search but not yet assigned to a component, and calculates "low numbers" of each vertex (an index number of the highest ancestor reachable in one step from a descendant of the vertex) which it uses to determine when a set of vertices should be popped off the stack into a new component.
- The [path-based strong component algorithm](wikipedia://en/12377419) uses a depth-first search, like Tarjan's algorithm, but with two stacks. One of the stacks is used to keep track of the vertices not yet assigned to components, while the other keeps track of the current path in the depth-first search tree. The first linear time version of this algorithm was published by [Edsger W. Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra) in 1976.[^o11]

Although Kosaraju's algorithm is conceptually simple, Tarjan's and the path-based algorithm require only one depth-first search rather than two.

### Reachability-based algorithms {#Reachability-based_algorithms}

Previous linear-time algorithms are based on depth-first search which is generally considered hard to parallelize. Fleischer et al.[^o13] in 2000 proposed a [divide-and-conquer](https://en.wikipedia.org/wiki/Divide_and_conquer_algorithm) approach based on [reachability](wikipedia://en/2833097) queries, and such algorithms are usually called reachability-based SCC algorithms. The idea of this approach is to pick a random pivot vertex and apply forward and backward reachability queries from this vertex. The two queries partition the vertex set into 4 subsets: vertices reached by both, either one, or none of the searches. One can show that a strongly connected component has to be contained in one of the subsets. The vertex subset reached by both searches forms a strongly connected component, and the algorithm then recurses on the other 3 subsets.

The expected sequential running time of this algorithm is shown to be O(*n* log *n*), a factor of O(log *n*) more than the classic algorithms. The parallelism comes from: (1) the reachability queries can be parallelized more easily (e.g. by a [breadth-first search](wikipedia://en/97026) (BFS), and it can be fast if the [diameter](wikipedia://en/2979341) of the graph is small); and (2) the independence between the subtasks in the divide-and-conquer process. This algorithm performs well on real-world graphs,[^o14] but does not have theoretical guarantee on the parallelism (consider if a graph has no edges, the algorithm requires O(*n*) levels of recursions).

Blelloch et al.[^o15] in 2016 shows that if the reachability queries are applied in a random order, the cost bound of O(*n* log *n*) still holds. Furthermore, the queries then can be batched in a prefix-doubling manner (i.e. 1, 2, 4, 8 queries) and run simultaneously in one round. The overall [span](https://en.wikipedia.org/wiki/Analysis_of_parallel_algorithms) of this algorithm is log<sub>2</sub> *n* reachability queries, which is probably the optimal parallelism that can be achieved using the reachability-based approach.

### Generating random strongly connected graphs {#Generating_random_strongly_connected_graphs}

Peter M. Maurer describes an algorithm for generating random strongly connected graphs,[^o17] based on a modification of an algorithm for [strong connectivity augmentation](wikipedia://en/66425729), the problem of adding as few edges as possible to make a graph strongly connected. When used in conjunction with the Gilbert or Erdős-Rényi models with node relabelling, the algorithm is capable of generating any strongly connected graph on *n* nodes, without restriction on the kinds of structures that can be generated.

## Applications {#Applications}

Algorithms for finding strongly connected components may be used to solve [2-satisfiability](https://en.wikipedia.org/wiki/2-satisfiability) problems (systems of Boolean variables with constraints on the values of pairs of variables): as (Aspvall Plass Tarjan 1979) showed, a 2-satisfiability instance is unsatisfiable if and only if there is a variable *v* such that *v* and its negation are both contained in the same strongly connected component of the [implication graph](wikipedia://en/9419642) of the instance.[^o21]

Strongly connected components are also used to compute the [Dulmage–Mendelsohn decomposition](wikipedia://en/2669524), a classification of the edges of a [bipartite graph](wikipedia://en/244431), according to whether or not they can be part of a [perfect matching](wikipedia://en/44031) in the graph.[^o22]

:::

## Related results {#Related_results}

A directed graph is strongly connected if and only if it has an [ear decomposition](wikipedia://en/32183016), a partition of the edges into a sequence of directed paths and cycles such that the first subgraph in the sequence is a cycle, and each subsequent subgraph is either a cycle sharing one vertex with previous subgraphs, or a path sharing its two endpoints with previous subgraphs.

According to [Robbins' theorem](wikipedia://en/36633800), an undirected graph may be [oriented](https://en.wikipedia.org/wiki/Graph_orientation) in such a way that it becomes strongly connected, if and only if it is [2-edge-connected](https://en.wikipedia.org/wiki/K-edge-connected_graph). One way to prove this result is to find an ear decomposition of the underlying undirected graph and then orient each ear consistently.[^o25]
