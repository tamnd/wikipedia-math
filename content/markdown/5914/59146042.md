# Accuracy paradox

::: {#o1 .subject cue=lead name="Accuracy paradox"}

The **accuracy paradox** is the [paradoxical](wikipedia://en/24390) finding that [accuracy](https://en.wikipedia.org/wiki/Accuracy) is not a good metric for [predictive models](https://en.wikipedia.org/wiki/Predictive_model) when [classifying](wikipedia://en/205393) in [predictive analytics](wikipedia://en/4141563). This is because a simple model may have a high level of accuracy but too crude to be useful. For example, if the incidence of category A is dominant, being found in 99% of cases, then predicting that every case is category A will have an accuracy of 99%. [Precision and recall](wikipedia://en/14343887) are better measures in such cases.[^o8][^o9] The underlying issue is that there is a class imbalance between the positive class and the negative class. Prior probabilities for these classes need to be accounted for in error analysis. Precision and recall help, but precision too can be biased by unbalanced class priors in the test sets.

:::

::: {#o3 .example cue=heading name="Example"}

## Example {#Example}

For example, a city of 1 million people has ten terrorists. A profiling system results in the following [confusion matrix](wikipedia://en/847558):

::: {#o4 .table cue=table}

|  | Fail | Pass | Sum |
|---|---|---|---|
| Fail | **10** | 0 | 10 |
| Pass | **990** | 999000 | 999990 |
| Sum | 1000 | 999000 | 1000000 |

:::

Even though the accuracy is $\tfrac{10 + 999000}{1000000}$ ≈ 99.9%, 990 out of the 1000 positive predictions are incorrect. The precision of $\tfrac{10}{10 + 990}$ = 1% reveals its poor performance. As the classes are so unbalanced, a better metric is the [F1 score](https://en.wikipedia.org/wiki/F1_score) = $\tfrac{2 \times 0.01 \times 1}{0.01 + 1}$ ≈ 2% (the recall being $\tfrac{10 + 0}{10}$ = 1).

:::
