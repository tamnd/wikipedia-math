# 1-vs-2 cycles problem

::: {#o1 .subject cue=lead name="1-vs-2 cycles problem"}

In the theory of parallel algorithms, the **1-vs-2 cycles problem** concerns a simplified case of [graph connectivity](https://en.wikipedia.org/wiki/Graph_connectivity). The input to the problem is a [2-regular graph](wikipedia://en/85821), forming either a single connected $n$-vertex cycle or two disconnected $n/2$-vertex cycles. The problem is to determine whether the input has one or two cycles.

:::

The **1-vs-2 cycles conjecture** or **2-cycle conjecture** is an unproven [computational hardness assumption](wikipedia://en/6158383) asserting that solving the 1-vs-2 cycles problem in the [massively parallel communication](https://en.wikipedia.org/wiki/Massively_parallel_communication) model requires at least a logarithmic number of rounds of communication, even for a randomized algorithm that succeeds with high probability (having a polynomially small failure probability). If so, this would be optimal, as connected components can be constructed in logarithmic rounds in this model.

This assumption implies similar communication [lower bounds](https://en.wikipedia.org/wiki/Lower_bound) for several other problems in this computational model, including [single-linkage clustering](wikipedia://en/13029194) and geometric [minimum spanning trees](wikipedia://en/41795). However, proving the 1-vs-2 cycles conjecture may be difficult, as any non-constant lower bound for the number of rounds for this problem would imply that the parallel complexity class [NC<sup>1</sup>](wikipedia://en/22073) does not contain all problems in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time), which would be a significant advance on current knowledge.
