# Crypt (Unix)

::: {#o1 .subject cue=lead name="Crypt"}

In [Unix](https://en.wikipedia.org/wiki/Unix) computing, **crypt** or **enigma** is a [utility program](https://en.wikipedia.org/wiki/List_of_utility_software) used for encryption. Due to the ease of breaking it, it is considered to be obsolete.

:::

The program is usually used as a [filter](https://en.wikipedia.org/wiki/Filter_%28software%29#Unix), and it has traditionally been implemented using a "rotor machine" [algorithm](wikipedia://en/775) based on the [Enigma machine](wikipedia://en/9256). It is considered to be [cryptographically](wikipedia://en/18934432) far too weak to provide any security against [brute-force attacks](wikipedia://en/53784) by modern, commodity [personal computers](https://en.wikipedia.org/wiki/Personal_computer).[^o3]

Some versions of Unix shipped with an even weaker version of the *crypt(1)* command in order to comply with [contemporaneous laws and regulations that limited the exportation of cryptographic software](wikipedia://en/826003). Some of these were simply implementations of the [Caesar cipher](wikipedia://en/48405) (effectively no more secure than [ROT13](wikipedia://en/48362), which is implemented as a Caesar cipher with a well-known key).

## History {#History}

Cryptographer [Robert Morris](wikipedia://en/230338) wrote a [M-209](wikipedia://en/743513)-based crypt, which first appeared in [Version 3 Unix](https://en.wikipedia.org/wiki/Research_Unix), to encourage codebreaking experiments; Morris managed to break crypt by hand. [Dennis Ritchie](https://en.wikipedia.org/wiki/Dennis_Ritchie) automated decryption with a method by [James Reeds](https://en.wikipedia.org/wiki/James_Reeds), and a new Enigma-based version appeared in [Version 7](https://en.wikipedia.org/wiki/Version_7_Unix), which Reeds and [Peter J. Weinberger](https://en.wikipedia.org/wiki/Peter_J._Weinberger) also broke.[^o5]

## *crypt(1)* under Linux {#crypt(1)_under_Linux}

[Linux distributions](https://en.wikipedia.org/wiki/Linux_distribution) generally do not include a Unix compatible version of the *crypt* command. This is largely due to a combination of three major factors:

1. *crypt* is relatively obscure and rarely used for e-mail attachments nor as a file format
1. *crypt* is considered to be cryptographically far too weak to withstand brute-force attacks by modern computing systems (Linux systems generally ship with [GNU Privacy Guard](wikipedia://en/38809) which is considered to be reasonably secure by modern standards)
1. During the early years of Linux development and adoption there was some concern that even as weak as the algorithm used by *crypt* was, that it might still run afoul of [ITAR](https://en.wikipedia.org/wiki/International_Traffic_in_Arms_Regulations)'s export controls; so mainstream distribution developers in the [United States](https://en.wikipedia.org/wiki/United_States) generally excluded it, leaving their customers to fetch GnuPG or other strong cryptographic software from international sites, sometimes providing packages or scripts to automate that process.

The source code to several old versions of the *crypt* command is available in The Unix Heritage Society's Unix Archive.[^o7] The recent crypt source code is available in the [OpenSolaris](https://en.wikipedia.org/wiki/OpenSolaris) project. A [public domain](https://en.wikipedia.org/wiki/Public_domain) version is available from the Crypt Breaker's Workbench.

Enhanced [symmetric encryption](wikipedia://en/53042) utilities are available for Linux (and should also be [portable](https://en.wikipedia.org/wiki/Software_portability) to any other [Unix-like](https://en.wikipedia.org/wiki/Unix-like) system) including [mcrypt](wikipedia://en/1921357) and [ccrypt](https://en.wikipedia.org/wiki/Ccrypt).[^o8] While these provide support for much more sophisticated and modern algorithms, they can be used to encrypt and decrypt files which are compatible with the traditional *crypt(1)* command by providing the correct command line options.

## Breaking crypt(1) encryption {#Breaking_crypt(1)_encryption}

Programs for breaking crypt(1) encryption are widely available. Bob Baldwin's [public domain](https://en.wikipedia.org/wiki/Public_domain) Crypt Breaker's Workbench, which was written in 1984-1985, is an interactive tool that provides successive plaintext guesses that must be corrected by the user. It also provides a working crypt(1) implementation used by modern BSD distributions.[^o10]

Peter Selinger's unixcrypt-breaker uses a simple statistical model similar to a dictionary-attack that takes a set of plain texts as input and processes it to guess plausible plaintexts, and does not require user interaction.[^o11]

## Relationship to password hash function {#Relationship_to_password_hash_function}

There is also a Unix [password hash](wikipedia://en/449781) function with the same name, [crypt](wikipedia://en/38472580). Though both are used for securing data in some sense, they are otherwise essentially unrelated. To distinguish between the two, writers often refer to the utility program as ***crypt(1)***, because it is documented in section 1 of the Unix [manual pages](https://en.wikipedia.org/wiki/Man_page), and refer to the password hash function as ***crypt(3)***, because its documentation is in section 3 of the manual.
