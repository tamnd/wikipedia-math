# Euclidean shortest path

::: {#o1 .subject cue=lead name="Euclidean shortest path"}

*Image: Interior-point-method-three-dimensions.png.* Example of a shortest path in a three-dimensional Euclidean space

The **Euclidean shortest path** problem is a problem in [computational geometry](wikipedia://en/176927): given a set of [polyhedral](wikipedia://en/23470) obstacles in a [Euclidean space](wikipedia://en/9697), and two points, find the shortest path between the points that does not intersect any of the obstacles.

:::

## Two dimensions {#Two_dimensions}

In two dimensions, the problem can be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) in a model of computation allowing addition and comparisons of real numbers, despite theoretical difficulties involving the [numerical precision](https://en.wikipedia.org/wiki/Precision_%28computer_science%29) needed to perform such calculations. These algorithms are based on two different principles, either performing a shortest path algorithm such as [Dijkstra's algorithm](wikipedia://en/45809) on a [visibility graph](wikipedia://en/1448291) derived from the obstacles or (in an approach called the *continuous Dijkstra* method) propagating a wavefront from one of the points until it meets the other.

## Higher dimensions {#Higher_dimensions}

In three (and higher) dimensions the problem is [NP-hard](https://en.wikipedia.org/wiki/NP-hard) in the general case,[^o4] but there exist efficient approximation algorithms that run in polynomial time based on the idea of finding a suitable sample of points on the obstacle edges and performing a visibility graph calculation using these sample points.

There are many results on computing shortest paths which stays on a polyhedral surface. Given two points s and t, say on the surface of a [convex polyhedron](https://en.wikipedia.org/wiki/Convex_polyhedron), the problem is to compute a shortest path that never leaves the surface and connects s with t. This is a generalization of the problem from 2-dimension but it is much easier than the 3-dimensional problem.

::: {#o6 .statement kind=statement/generalization cue=heading name="Variants"}

## Variants {#Variants}

There are variations of this problem, where the obstacles are *weighted*, i.e., one can go through an obstacle, but it incurs an extra cost to go through an obstacle. The standard problem is the special case where the obstacles have infinite weight. This is termed as the *[weighted region problem](https://en.wikipedia.org/wiki/Weighted_region_problem)* in the literature.

:::
