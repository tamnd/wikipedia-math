# VeraCrypt

::: {#o7 .subject cue=lead name="VeraCrypt"}

**VeraCrypt** is a [free and open-source](https://en.wikipedia.org/wiki/Free_and_open-source_software) [utility](https://en.wikipedia.org/wiki/Utility_software) for [on-the-fly encryption](wikipedia://en/7066791) (OTFE).[^o8] The software can create a virtual encrypted disk that works just like a regular disk, but within a file. It can also encrypt a [partition](https://en.wikipedia.org/wiki/Disk_partitioning)[^o9] or (in [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows)) the entire [storage device](wikipedia://en/28174) with [pre-boot authentication](https://en.wikipedia.org/wiki/Pre-boot_authentication).[^o10]

:::

VeraCrypt is a [fork](https://en.wikipedia.org/wiki/Fork_%28software_development%29) of the discontinued [TrueCrypt](wikipedia://en/905962) project.[^o11] It was initially released on 22 June 2013. Many security improvements have been implemented and concerns within the TrueCrypt code [audits](https://en.wikipedia.org/wiki/Information_security_audit) have been addressed. VeraCrypt includes optimizations to the original cryptographic hash functions and ciphers, which boost performance on modern [central processing units](https://en.wikipedia.org/wiki/Central_processing_unit).

## Encryption scheme {#Encryption_scheme}

VeraCrypt employs [AES](wikipedia://en/1260), [Serpent](wikipedia://en/385154), [Twofish](wikipedia://en/26508356), [Camellia](wikipedia://en/532475), and [Kuznyechik](wikipedia://en/50158212) as [ciphers](wikipedia://en/5244). Version 1.19 stopped using the [Magma](wikipedia://en/487471) cipher in response to a security audit.[^o13] For additional security, ten different combinations of [cascaded](wikipedia://en/1062541) algorithms are available:[^o14]

- AES–Twofish
- AES–Twofish–Serpent
- Camellia–Kuznyechik
- Camellia–Serpent
- Kuznyechik–AES
- Kuznyechik–Serpent–Camellia
- Kuznyechik–Twofish
- Serpent–AES
- Serpent–Twofish–AES
- Twofish–Serpent

The [cryptographic hash functions](wikipedia://en/439526) available for use in VeraCrypt are [BLAKE2s-256](wikipedia://en/30054589#BLAKE2), [SHA-256](wikipedia://en/1638777), [SHA-512](wikipedia://en/1638777), [Streebog](wikipedia://en/47024355) and [Whirlpool](wikipedia://en/567567).[^o15] VeraCrypt used to have support for [RIPEMD-160](wikipedia://en/26363), but it has since been removed in version 1.26.[^o16]

VeraCrypt's [block cipher mode of operation](wikipedia://en/160202) is [XTS](wikipedia://en/3395256#XTS).[^o17] It generates the header key and the secondary header key (XTS mode) using [PBKDF2](wikipedia://en/1568244) with a 512-[bit](https://en.wikipedia.org/wiki/Bit) [salt](wikipedia://en/701756). By default, they go through 200,000 or 500,000 iterations, depending on the underlying hash function used and whether it is system or non-system encryption.[^o18] The user can customize it to lower these numbers to as low as 2,048 and 16,000, respectively.[^o18]

## Security improvements {#Security_improvements}

- The VeraCrypt development team considered the TrueCrypt storage format too vulnerable to a [National Security Agency](wikipedia://en/21939) (NSA) attack, so it created a new format incompatible with that of TrueCrypt. Support for the older TrueCrypt format was dropped in October 2023 starting with VeraCrypt 1.26, but older versions of VeraCrypt are still capable of opening and converting volumes previously created in the TrueCrypt format.[^o20][^o21]
- An independent security audit of TrueCrypt released 29 September 2015 found TrueCrypt includes two vulnerabilities in the Windows installation driver allowing an attacker [arbitrary code execution](https://en.wikipedia.org/wiki/Arbitrary_code_execution) and [privilege escalation](https://en.wikipedia.org/wiki/Privilege_escalation) via [DLL hijacking](https://en.wikipedia.org/wiki/DLL_hijacking).[^o22] This was fixed in VeraCrypt in January 2016.[^o23]
- While TrueCrypt uses 1,000 iterations of the [PBKDF2](wikipedia://en/1568244)-[RIPEMD-160](https://en.wikipedia.org/wiki/RIPEMD-160) algorithm for system partitions, VeraCrypt uses either 200,000 iterations ([SHA-256](https://en.wikipedia.org/wiki/SHA-256), [BLAKE2s-256](wikipedia://en/30054589#BLAKE2), [Streebog](wikipedia://en/47024355)) or 500,000 iterations ([SHA-512](https://en.wikipedia.org/wiki/SHA-512), [Whirlpool](https://en.wikipedia.org/wiki/Whirlpool_%28cryptography%29)) by default (which is customizable by user to be as low as 2,048 and 16,000 respectively).[^o18] For standard containers and non-system partitions, VeraCrypt uses 500,000 iterations by default regardless of the hashing algorithm chosen (which is customizable by user to be as low as 16,000).[^o18] While these default settings make VeraCrypt slower at opening encrypted partitions, it also makes password-guessing attacks slower.[^o24]
- Additionally, since version 1.12, a new feature called "Personal Iterations Multiplier" (PIM) provides a parameter whose value is used to control the number of iterations used by the header key derivation function, thereby making [brute-force attacks](https://en.wikipedia.org/wiki/Brute-force_attacks) potentially even more difficult. VeraCrypt out of the box uses a reasonable PIM value to improve security,[^o25] but users can provide a higher value to enhance security. The primary downside of this feature is that it makes the process of opening encrypted archives even slower.[^o25][^o26][^o27][^o28]
- A vulnerability in the [bootloader](https://en.wikipedia.org/wiki/Booting#Boot-loader) was fixed on Windows and various optimizations were made as well. The developers added support for SHA-256 to the system boot encryption option and also fixed a ShellExecute security issue. [Linux](https://en.wikipedia.org/wiki/Linux) and [macOS](https://en.wikipedia.org/wiki/MacOS) users benefit from support for hard drives with sector sizes larger than 512. Linux also received support for the [NTFS](https://en.wikipedia.org/wiki/NTFS) formatting of volumes.
- [Unicode](https://en.wikipedia.org/wiki/Unicode) passwords are supported on all operating systems since version 1.17 (except for system encryption on Windows).[^o29]
- VeraCrypt added the capability to boot system partitions using [UEFI](https://en.wikipedia.org/wiki/UEFI) in version 1.18a.[^o29]
- Option to enable/disable support for the [TRIM](https://en.wikipedia.org/wiki/TRIM_%28computing%29) command for both system and non-system drives was added in version 1.22.[^o29]
- Erasing the system encryption keys from RAM during [shutdown](https://en.wikipedia.org/wiki/Shutdown_%28computing%29)/[reboot](https://en.wikipedia.org/wiki/Reboot) helps mitigate some [cold boot attacks](wikipedia://en/15893148), added in version 1.24.[^o29]
- RAM encryption for keys and passwords on [64-bit](https://en.wikipedia.org/wiki/X64) systems was added in version 1.24.[^o29]

### VeraCrypt audit {#VeraCrypt_audit}

QuarksLab conducted an audit of version 1.18 on behalf of the Open Source Technology Improvement Fund (OSTIF), which took 32 [man-days](https://en.wikipedia.org/wiki/Man-hour). The auditor published the results on 17 October 2016.[^o29][^o31][^o32] On the same day, IDRIX released version 1.19, which resolved major vulnerabilities identified in the audit.[^o33]

[Fraunhofer Institute for Secure Information Technology](https://en.wikipedia.org/wiki/Fraunhofer_Society#Institutes) (SIT) conducted another audit in 2020, following a request by Germany's [Federal Office for Information Security](https://en.wikipedia.org/wiki/Federal_Office_for_Information_Security) (BSI), and published the results in October 2020.[^o34][^o35]

## 2026 signing certificate revocation {#2026_signing_certificate_revocation}

In March 2026, VeraCrypt’s lead developer Mounir Idrassi disclosed that [Microsoft](https://en.wikipedia.org/wiki/Microsoft) had terminated the developer account used to digitally sign the software’s [Windows](https://en.wikipedia.org/wiki/Windows) drivers and [UEFI](https://en.wikipedia.org/wiki/UEFI) bootloader. As a result, no new Windows releases could be published; [Linux](https://en.wikipedia.org/wiki/Linux) and [macOS](https://en.wikipedia.org/wiki/MacOS) updates remained unaffected.[^o37] The same issue affected other Windows applications, including [WireGuard](https://en.wikipedia.org/wiki/WireGuard), [MemTest86](https://en.wikipedia.org/wiki/MemTest86), and [Windscribe](https://en.wikipedia.org/wiki/Windscribe).

Idrassi stated that he had attempted to sign Windows drivers for version 1.26.27 in January 2026, but his account was terminated with an automated message stating his company “did not meet verification requirements” – without specifics or any appeal mechanism.[^o38][^o39]

The certificate authority (CA) used for existing signatures was set to be revoked in late June 2026. Idrassi warned that Windows systems with [Secure Boot](https://en.wikipedia.org/wiki/Secure_Boot) enabled might then fail to load VeraCrypt’s bootloader, which may have rendered encrypted drives unbootable unless the CA issue was resolved.[^o37][^o38]

As of 10 April, 2026, Microsoft restored Idrassi's access to his Microsoft Partner Center account, allowing him to sign new versions. Idrassi then released a VeraCrypt 1.26.28 maintenance release with newly Microsoft-signed EFI bootloader components for current 1.26.x users, so people do not have to wait for VeraCrypt 1.27. The old VeraCrypt bootloader will still work even after the certificate expires, but future Windows configurations may require bootloaders signed with the new certificate.[^o40]

## Security precautions {#Security_precautions}

There are several kinds of attacks to which all software-based disk encryption is vulnerable. As with TrueCrypt, the VeraCrypt documentation instructs users to follow various security precautions to mitigate these attacks,[^o64][^o42] several of which are detailed below.

### Encryption keys stored in memory {#Encryption_keys_stored_in_memory}

*Image: Veracrypt Boot Loader 1.24 screenshot.png.* VeraCrypt Boot Loader

VeraCrypt stores its keys in [random-access memory](https://en.wikipedia.org/wiki/Random-access_memory) (RAM); on some personal computers [dynamic random-access memory](https://en.wikipedia.org/wiki/Dynamic_random-access_memory) (DRAM) will maintain its contents for several seconds after power is cut, or longer if the temperature is lowered. Even if there is some degradation in the memory contents, various algorithms may be able to recover the keys. This method, known as a [cold boot attack](wikipedia://en/15893148), which would apply in particular to a notebook computer obtained while in power-on, suspended, or screen-locked mode, was successfully used to attack a file system protected by [TrueCrypt](wikipedia://en/905962) versions 4.3a and 5.0a in 2008.[^o44] With version 1.24, VeraCrypt added the option of encrypting the in-RAM [keys](wikipedia://en/53039) and passwords on [x86-64](https://en.wikipedia.org/wiki/X86-64) editions of Microsoft Windows, with a CPU overhead of less than 10%, and the option of erasing all encryption keys from memory when a new device is connected.[^o29]

### Tampered hardware {#Tampered_hardware}

VeraCrypt documentation states that VeraCrypt is unable to secure data on a computer if an attacker physically accessed it and VeraCrypt is then used on the compromised computer by the user again. This does not affect the common case of a stolen, lost, or confiscated computer.[^o46] The attacker having physical access to a computer can, for example, install a hardware or a software [keylogger](https://en.wikipedia.org/wiki/Keylogger), a [bus-mastering](https://en.wikipedia.org/wiki/Bus_mastering) device capturing [memory](https://en.wikipedia.org/wiki/RAM) or install any other malicious [hardware](https://en.wikipedia.org/wiki/Hardware_Trojan_%28computing%29) or [software](https://en.wikipedia.org/wiki/Malware), allowing the attacker to capture unencrypted data (including encryption keys and passwords) or to decrypt encrypted data using captured passwords or encryption keys. Therefore, physical security is a basic premise of a secure system.[^o47]

Some kinds of malware are designed to [log keystrokes](https://en.wikipedia.org/wiki/Keystroke_logging), including typed passwords, that may then be sent to the attacker over the Internet or saved to an unencrypted local drive from which the attacker might be able to read it later, when they gain physical access to the computer.[^o48]

### Trusted Platform Module {#Trusted_Platform_Module}

VeraCrypt does not take advantage of Trusted Platform Module (TPM). VeraCrypt FAQ repeats the negative opinion of the original TrueCrypt developers verbatim.[^o50] The TrueCrypt developers were of the opinion that the exclusive purpose of the TPM is "to protect against attacks that require the attacker to have administrator privileges, or physical access to the computer". The attacker who has physical or administrative access to a computer can circumvent TPM, e.g., by installing a hardware [keystroke logger](https://en.wikipedia.org/wiki/Keystroke_logger), by resetting TPM, or by capturing memory contents and retrieving TPM-issued keys. The condemning text goes so far as to claim that TPM is entirely redundant.[^o51]

It is true that after achieving either unrestricted physical access or administrative privileges, it is only a matter of time before other security measures in place are bypassed.[^o52][^o53] However, stopping an attacker in possession of administrative privileges has never been one of the goals of TPM. (See Trusted Platform Module for details.) TPM might, however, reduce the success rate of the [cold boot attack](wikipedia://en/15893148) described above.[^o54][^o55][^o56][^o57][^o58] TPM is also known to be susceptible to SPI attacks.[^o59]

## Plausible deniability {#Plausible_deniability}

As with its predecessor [TrueCrypt](wikipedia://en/905962), VeraCrypt supports [plausible deniability](https://en.wikipedia.org/wiki/Plausible_deniability#Use_in_cryptography)[^o61] by allowing a single "hidden volume" to be created within another volume.[^o62] The Windows versions of VeraCrypt can create and run a hidden encrypted operating system whose [existence may be denied](wikipedia://en/1055437).[^o63] The VeraCrypt documentation lists ways in which the hidden volume deniability features may be compromised (e.g., by third-party software which may leak information through temporary files or via thumbnails) and possible ways to avoid this.[^o64]

## Performance {#Performance}

VeraCrypt supports [parallelized](https://en.wikipedia.org/wiki/Data_parallelism)[^o66] encryption for [multi-core systems](https://en.wikipedia.org/wiki/Multiprocessing). On Microsoft Windows, [pipelined](https://en.wikipedia.org/wiki/Pipeline_%28computing%29) read and write operations (a form of asynchronous processing)[^o66] to reduce the performance hit of encryption and decryption. On processors supporting the [AES-NI](https://en.wikipedia.org/wiki/AES-NI) instruction set, VeraCrypt supports hardware-accelerated AES to further improve performance.[^o66] On 64-bit CPUs VeraCrypt uses optimized [assembly](https://en.wikipedia.org/wiki/Assembly_language) implementation of Twofish, Serpent, and Camellia.[^o29]

## License and source model {#License_and_source_model}

VeraCrypt was [forked](https://en.wikipedia.org/wiki/Fork_%28software_development%29) from the since-discontinued [TrueCrypt](wikipedia://en/905962) project in 2013,[^o11] and originally contained mostly TrueCrypt code released under the TrueCrypt License 3.0. On 28 May 2014 TrueCrypt [ceased development](https://en.wikipedia.org/wiki/Abandonware) under unusual circumstances.[^o68][^o69][^o70] In the years since, more and more of VeraCrypt's code has been rewritten and released under the permissive [Apache License](https://en.wikipedia.org/wiki/Apache_License) 2.0.

The TrueCrypt license is generally considered to be [source-available](https://en.wikipedia.org/wiki/Source-available) but not [free and open source](https://en.wikipedia.org/wiki/Free_and_open_source). The Apache license is universally considered to be free and open source. The mixed VeraCrypt license is widely but not universally considered to be free and open source.

VeraCrypt is considered to be free and open source by:

- PC World[^o71]
- Techspot[^o72]
- [DuckDuckGo](https://en.wikipedia.org/wiki/DuckDuckGo)'s Open Source Technology Improvement Fund[^o73][^o74]
- [SourceForge](https://en.wikipedia.org/wiki/SourceForge)[^o75]
- Open Tech Fund[^o76]
- Fosshub[^o77]
- opensource.com[^o78]
- fossmint[^o79]
- The current VeraCrypt development team[^o80]

VeraCrypt is not considered free and open source by:

- [Debian](https://en.wikipedia.org/wiki/Debian):[^o81] Debian considers all software that does not meet the guidelines of its [DFSG](https://en.wikipedia.org/wiki/Debian_Free_Software_Guidelines) to be non-free.

The original TrueCrypt license (but not necessarily the current combined VeraCrypt license) is not considered free and open source by:

- The [Free Software Foundation](https://en.wikipedia.org/wiki/Free_Software_Foundation)[^o82][^o83]
- At least one member of the [Open Source Initiative](https://en.wikipedia.org/wiki/Open_Source_Initiative) (OSI). The director expressed concern about an older version of the TrueCrypt license,[^o84] but the OSI has not published a determination regarding either TrueCrypt or VeraCrypt.

## Use for criminal purposes {#Use_for_criminal_purposes}

VeraCrypt has been used by consumers of [child pornography](https://en.wikipedia.org/wiki/Child_pornography) to conceal illicit materials, with the [FBI](https://en.wikipedia.org/wiki/Federal_Bureau_of_Investigation) being unable to decrypt the encrypted content, leading to requests by [prosecutors](https://en.wikipedia.org/wiki/Prosecutor) to force the defendants to hand over their passwords under the *foregone conclusion* doctrine of the [All Writs Act](https://en.wikipedia.org/wiki/All_Writs_Act).[^o86][^o87][^o88]
