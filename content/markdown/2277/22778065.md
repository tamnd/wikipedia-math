# Inductive type

::: {#o1 .subject cue=lead name="Inductive type"}

In [type theory](wikipedia://en/40282), a system has **inductive types** if it has facilities for creating a new type from constants and functions that create terms of that type. The feature serves a role similar to [data structures](wikipedia://en/8519) in a [programming language](wikipedia://en/23015) and allows a type theory to add concepts like [numbers](wikipedia://en/21690), [relations](wikipedia://en/22517558), and [trees](wikipedia://en/48560). As the name suggests, inductive types can be self-referential, but usually only in a way that permits [structural recursion](https://en.wikipedia.org/wiki/Structural_recursion).

:::

The standard example is encoding the [natural numbers](wikipedia://en/21474) using [Peano's encoding](wikipedia://en/25005). It can be defined in [Rocq](wikipedia://en/581974) (formerly named *Coq*) as follows:

```coq
Inductive nat : Type :=
  | O : nat
  | S : nat -> nat.
```

Here, a natural number is created either from the constant "O" (representing zero) or by applying the function "S" to another natural number. "S" is the [successor function](wikipedia://en/325637) which represents adding one to a number. Thus, "S O" is one, "S (S O)" is two, "S (S (S O))" is three, and so on.

Since their introduction, inductive types have been extended to encode more and more structures, while still being [predicative](https://en.wikipedia.org/wiki/Impredicative) and supporting structural recursion.

::: {#o3 .statement cue=named-heading name="Induction principle"}

## Induction principle {#Induction_principle}

Inductive types usually come with a function to prove properties about them. Thus, "nat" may come with (in Rocq syntax):

```coq
nat_ind : (forall P : nat -> Prop, (P O) -> (forall n, P n -> P (S n)) -> (forall n, P n)).
```

In words: for any predicate "P" over natural numbers, given a proof of "P O" and a proof of "P n -> P (n+1)", we get back a proof of "forall n, P n". This is the familiar induction principle for natural numbers.

:::

## Implementations {#Implementations}

### W- and M-types {#W-_and_M-types}

W-types are [well-founded](wikipedia://en/319712) types in [intuitionistic type theory](wikipedia://en/345023) (ITT).[^o7] They generalize natural numbers, lists, binary trees, and other "tree-shaped" data types. Let $U$ be a [universe of types](wikipedia://en/296838#In_type_theory). Given a type $A$ : $U$ and a [dependent family](wikipedia://en/1949487) $B$ : $A$ → $U$, one can form a W-type $\mathsf{W}_{a:A} B(a)$. The type $A$ may be thought of as "labels" for the (potentially infinitely many) constructors of the inductive type being defined, whereas $B$ indicates the (potentially infinite) [arity](wikipedia://en/42301) of each constructor. W-types (resp. M-types) may also be understood as well-founded (resp. non-well-founded) trees with nodes labeled by elements $a$ : $A$ and where the node labeled by $a$ has $B$($a$)-many subtrees.[^o8] Each W-type is isomorphic to the initial algebra of a so-called [polynomial functor](wikipedia://en/56343400).

Let **0**, **1**, **2**, etc. be finite types with inhabitants 1<sub>**1**</sub> : **1**, 1<sub>**2**</sub>, 2<sub>**2**</sub>:**2**, etc. One may define the natural numbers as the W-type

$$\mathbb{N}:= \mathsf{W}_{x:\mathbf{2}} f(x)$$

with $f$ : **2** → $U$ is defined by $f$(1<sub>**2**</sub>) = **0** (representing the constructor for zero, which takes no arguments), and $f$(2<sub>**2**</sub>) = **1** (representing the successor function, which takes one argument).

One may define lists over a type $A$ : $U$ as $\operatorname{List}(A) := \mathsf{W}_{(x:\mathbf{1}+A)} f(x)$ where

$$\begin{aligned} f(\operatorname{inl}(1_{\mathbf{1}})) &= \mathbf{0} \\ f(\operatorname{inr}(a)) &= \mathbf{1} \end{aligned}$$

and 1<sub>**1**</sub> is the sole inhabitant of **1**. The value of $f(\operatorname{inl}(1_{\mathbf{1}}))$ corresponds to the constructor for the empty list, whereas the value of $f(\operatorname{inr}(a))$ corresponds to the constructor that appends $a$ to the beginning of another list.

The constructor for elements of a generic W-type $\mathsf{W}_{x:A}B(x)$ has type

$$\mathsf{sup}:\prod_{a:A}\Big(B(a)\to\mathsf{W}_{x:A}B(x)\Big)\to \mathsf{W}_{x:A}B(x).$$

We can also write this rule in the style of a [natural deduction](wikipedia://en/51072) proof,

$$\frac{ a:A \qquad f:B(a)\to\mathsf{W}_{x:A}B(x) }{ \mathsf{sup}(a,f):\mathsf{W}_{x:A}B(x) }.$$

The elimination rule for W-types works similarly to [structural induction](wikipedia://en/211399) on trees. If, whenever a property (under the [propositions-as-types](wikipedia://en/254299) interpretation) $C : \mathsf{W}_{x:A}B(x) \to U$ holds for all subtrees of a given tree it also holds for that tree, then it holds for all trees.

$$\frac{ w:\mathsf{W}_{a:A}B(a) \qquad a:A, \; f:B(a)\to\mathsf{W}_{x:A}B(x), \; c:\prod_{b:B(a)} C(f(b)) \;\vdash\; h(a,f,c):C(\mathsf{sup}(a,f)) }{ \mathsf{elim}(w,h):C(w) }$$

In extensional type theories, W-types (resp. M-types) can be defined up to [isomorphism](wikipedia://en/14828) as [initial algebras](wikipedia://en/4116488) (resp. final coalgebras) for [polynomial functors](wikipedia://en/56343400). In this case, the property of initiality (res. finality) corresponds directly to the appropriate induction principle.[^o9] In intensional type theories with the [univalence axiom](https://en.wikipedia.org/wiki/Univalence_axiom), this correspondence holds up to homotopy (propositional equality).[^o10][^o11][^o12]

M-types are [dual](wikipedia://en/310885) to W-types, and represent [coinductive](wikipedia://en/10904266) (potentially infinite) data such as [streams](https://en.wikipedia.org/wiki/Stream_%28computer_science%29).[^o13] M-types can be derived from W-types.[^o14]

### Mutually inductive definitions {#Mutually_inductive_definitions}

This technique allows *some* definitions of multiple types that depend on each other. For example, defining two [parity](wikipedia://en/143135) predicates on [natural numbers](wikipedia://en/21474) using two mutually inductive types in Rocq:

```coq
Inductive even : nat -> Prop :=
  | zero_is_even : even O
  | S_of_odd_is_even : (forall n:nat, odd n -> even (S n))
with odd : nat -> Prop :=
  | S_of_even_is_odd : (forall n:nat, even n -> odd (S n)).
```

### Induction-recursion {#Induction-recursion}

[Induction-recursion](https://en.wikipedia.org/wiki/Induction-recursion_%28type_theory%29) started as a study into the limits of ITT. Once found, the limits were turned into rules that allowed defining new inductive types. These types could depend upon a function and the function on the type, as long as both were defined simultaneously.

[Universe types](wikipedia://en/296838#In_type_theory) can be defined using induction-recursion.

### Induction-induction {#Induction-induction}

[Induction-induction](wikipedia://en/57750049) allows definition of a type and a family of types at the same time. So, a type $A$ and a family of types $B : A \to Type$.

### Higher inductive types {#Higher_inductive_types}

This is a current research area in [Homotopy type theory](wikipedia://en/33974223) (HoTT). This differs from ITT by its identity type (equality). Higher inductive types define a new type with constants and functions that create elements of the type, and new instances of the identity type that relate them.

A simple example is the $circle$ type, which is defined with two constructors, a basepoint;

$$base : circle$$

and a loop;

$$loop : base = base.$$

The existence of a new constructor for the identity type makes $circle$ a higher inductive type.
