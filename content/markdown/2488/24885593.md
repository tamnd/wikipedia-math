# Term (logic)

::: {#o1 .subject cue=lead name="Term"}

In [mathematical logic](wikipedia://en/19636), a **term** is an arrangement of dependent/bound symbols that denotes a [mathematical object](wikipedia://en/19453961) within an expression/formula. In particular, terms appear as components of a formula. This is analogous to natural language, where a [noun phrase](https://en.wikipedia.org/wiki/Noun_phrase) refers to an object and a whole [sentence](https://en.wikipedia.org/wiki/Sentence_%28linguistics%29) refers to a fact.

:::

A [first-order](wikipedia://en/10983) term is [recursively constructed](wikipedia://en/1047605) from constant symbols, [variable symbols](wikipedia://en/3728109), and [function symbols](https://en.wikipedia.org/wiki/Function_symbol_%28logic%29). An expression formed by applying a [predicate symbol](wikipedia://en/285109) to an appropriate number of terms is called an [atomic formula](wikipedia://en/4472066), which evaluates to [true](wikipedia://en/29920#Truth_in_mathematics) or [false](wikipedia://en/229823) in [bivalent logics](wikipedia://en/24097), given an [interpretation](wikipedia://en/14511671). For example, $(x+1)*(x+1)$ is a term built from the constant 1, the variable $x$, and the binary function symbols $+$ and $*$; it is part of the atomic formula $(x+1)*(x+1) \ge 0$ which evaluates to true for each [real-numbered](wikipedia://en/20646438) value of $x$.

Besides in [logic](wikipedia://en/46426065), terms play important roles in [universal algebra](wikipedia://en/45200), and [rewriting systems](https://en.wikipedia.org/wiki/Rewriting_system).

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

*Image: Tree structure of mathematical first-order terms svg.svg.* *Left to right:* tree structure of the term (*n*⋅(*n*+1))/2 and *n*⋅((*n*+1)/2)

Given a set *V* of variable symbols, a set *C* of constant symbols and sets *F*<sub>*n*</sub> of *n*-ary function symbols, also called operator symbols, for each natural number *n* ≥ 1, the set of (unsorted first-order) terms *T* is [recursively defined](wikipedia://en/1047605) to be the smallest set with the following properties:[^o4]

- every variable symbol is a term: $V \subseteq T$,
- every constant symbol is a term: $C \subseteq T$,
- from every *n* terms *t*<sub>1</sub>,...,*t*<sub>*n*</sub>, and every *n*-ary function symbol $f \in F_{n}$, a larger term *f*(*t*<sub>1</sub>, ..., *t*<sub>*n*</sub>) can be built.

Using an intuitive, pseudo-[grammatical](https://en.wikipedia.org/wiki/Grammar_formalism#Formal_definition) notation, this is sometimes written as:

*t* ::= *x* | *c* | *f*(*t*<sub>1</sub>, ..., *t*<sub>*n*</sub>).

The [signature](wikipedia://en/7788156) of the term language describes which function symbol sets *F*<sub>*n*</sub> are inhabited. Well-known examples are the unary function symbols $sin, cos \in F_{1}$, and the binary function symbols $+, -, \cdot, / \in F_{2}$. [Ternary operations](wikipedia://en/459413) and higher-arity functions are possible but uncommon in practice. Many authors consider constant symbols as 0-ary function symbols *F*<sub>0</sub>, thus needing no special syntactic class for them.

A term denotes a mathematical object from the [domain of discourse](wikipedia://en/229180). A constant *c* denotes a named object from that domain, a variable *x* ranges over the objects in that domain, and an *n*-ary function *f* maps *n*-[tuples](wikipedia://en/132729) of objects to objects. For example, if $n \in V$ is a variable symbol, $1 \in C$ is a constant symbol, and $add \in F_{2}$ is a binary function symbol, then $n \in T, 1 \in T$, and (hence) $add(n, 1) \in T$ by the first, second, and third term building rule, respectively. The latter term is usually written as *n*+1, using [infix notation](wikipedia://en/199014) and the more common operator symbol + for convenience.

### Term structure vs. representation {#Term_structure_vs._representation}

Originally, logicians defined a term to be a *character string* adhering to certain building rules.[^o6] However, since the concept of [tree](https://en.wikipedia.org/wiki/Tree_%28data_structure%29) became popular in computer science, it turned out to be more convenient to think of a term as a tree. For example, several distinct character strings, like "$(n\cdot(n+1))/2$", "$((n\cdot(n+1)))/2$", and "$\frac{n(n+1)}{2}$", denote the same term and correspond to the same tree, viz. the left tree in the above picture. Separating the tree structure of a term from its graphical representation on paper, it is also easy to account for parentheses (being only representation, not structure) and invisible multiplication operators (existing only in structure, not in representation).

### Structural equality {#Structural_equality}

Two terms are said to be *structurally*, *literally*, or *syntactically* equal if they correspond to the same tree. For example, the left and the right tree in the above picture are structurally *un*equal terms, although they might be considered "*semantically equal*" as they always evaluate to the same value in [rational arithmetic](wikipedia://en/19727024#Arithmetic). While structural equality can be checked without any knowledge about the meaning of the symbols, semantic equality cannot. If the function / is e.g. interpreted not as rational but as [truncating integer](https://en.wikipedia.org/wiki/Integer_division#Of_integers) division, then at *n*=2 the left and right term evaluates to 3 and 2, respectively. Structurally equal terms need to agree in their variable names.

In contrast, a term *t* is called a *renaming*, or a *variant*, of a term *u* if the latter resulted from consistently renaming all variables of the former, i.e. if *u* = *tσ* for some [renaming substitution](wikipedia://en/5438948#First-order_logic) σ. In that case, *u* is a renaming of *t*, too, since a renaming substitution σ has an inverse σ<sup>−1</sup>, and *t* = uσ<sup>−1</sup>. Both terms are then also said to be *equal modulo renaming*. In many contexts, the particular variable names in a term don't matter, e.g. the commutativity axiom for addition can be stated as *x*+*y*=*y*+*x* or as *a*+*b*=*b*+*a*; in such cases the whole formula may be renamed, while an arbitrary subterm usually may not, e.g. *x*+*y*=*b*+*a* is not a valid version of the commutativity axiom.[^o9] [^o10]

### Ground and linear terms {#Ground_and_linear_terms}

The set of variables of a term *t* is denoted by *vars*(*t*). A term that doesn't contain any variables is called a *[ground term](https://en.wikipedia.org/wiki/Ground_term)*; a term that doesn't contain multiple occurrences of a variable is called a *linear term*. For example, 2+2 is a ground term and hence also a linear term, *x*⋅(*n*+1) is a linear term, *n*⋅(*n*+1) is a non-linear term. These properties are important in, for example, [term rewriting](https://en.wikipedia.org/wiki/Term_rewriting).

Given a [signature](wikipedia://en/7788156) for the function symbols, the set of all terms forms the *[free](wikipedia://en/333835) [term algebra](wikipedia://en/2216678)*. The set of all ground terms forms the *[initial](wikipedia://en/4116488) term algebra*.

Abbreviating the number of constants as *f*<sub>0</sub>, and the number of *i*-ary function symbols as *f*<sub>*i*</sub>, the number θ<sub>*h*</sub> of distinct ground terms of a height up to *h* can be computed by the following recursion formula:

- θ<sub>0</sub> = *f*<sub>0</sub>, since a ground term of height 0 can only be a constant,
- $\theta_{h+1} = \sum_{i=0}^\infty f_i \cdot \theta_h^i$, since a ground term of height up to *h*+1 can be obtained by composing any *i* ground terms of height up to *h*, using an *i*-ary root function symbol. The sum has a finite value if there is only a finite number of constants and function symbols, which is usually the case.

### Building formulas from terms {#Building_formulas_from_terms}

Given a set *R*<sub>*n*</sub> of *n*-ary relation symbols for each natural number *n* ≥ 1, an (unsorted first-order) atomic formula is obtained by applying an *n*-ary relation symbol to *n* terms. As for function symbols, a relation symbol set *R*<sub>*n*</sub> is usually non-empty only for small *n*. In mathematical logic, more complex [formulas](wikipedia://en/10983#Formulas) are built from atomic formulas using [logical connectives](wikipedia://en/18153) and [quantifiers](wikipedia://en/43507260). For example, letting R denote the set of [real numbers](wikipedia://en/20646438), $\forall x: x \in R \Rightarrow (x+1)\cdot(x+1) \ge 0$ is a mathematical formula evaluating to true in the algebra of [complex numbers](wikipedia://en/5826). An atomic formula is called ground if it is built entirely from ground terms; all ground atomic formulas composable from a given set of function and predicate symbols make up the [Herbrand base](https://en.wikipedia.org/wiki/Herbrand_universe#Herbrand_base) for these symbol sets.

## Operations with terms {#Operations_with_terms}

*Image: Example term for position, path, depth, match svg.svg.* Tree structure of black example term $\frac{a*((a+1)*(a+2))}{1*(2*3)}$, with blue redex $x*(y*z)$

- Since a term has the structure of a tree hierarchy, to each of its nodes a *position*, or *path*, can be assigned, that is, a string of natural numbers indicating the node's place in the hierarchy. The empty string, commonly denoted by ε, is assigned to the root node. Position strings within the black term are indicated in red in the picture.
- At each position *p* of a term *t*, a unique *subterm* starts, which is commonly denoted by $t|_{p}$. For example, at position 122 of the black term in the picture, the subterm *a*+2 has its root. The relation *"is a subterm of"* is a [partial order](https://en.wikipedia.org/wiki/Partial_order) on the set of terms; it is [reflexive](wikipedia://en/200458) since each term is trivially a subterm of itself.
- The term obtained by *replacing* in a term *t* the subterm at a position *p* by a new term *u* is commonly denoted by $t[u]_{p}$. The term $t[u]_{p}$ can also be viewed as resulting from a generalized concatenation of the term *u* with a term-like object $t[.]$; the latter is called a **context**, or a *term with a hole* (indicated by "."; its position being *p*), in which *u* is said to be *embedded*. For example, if *t* is the black term in the picture, then $t[b+1]_{12}$ results in the term $\frac{a*(b+1)}{1*(2*3)}$. The latter term also results from embedding the term $b+1$ into the context $\frac{a*(\; . \;)}{1*(2*3)}$. In an informal sense, the operations of [instantiating](wikipedia://en/5438948#First-order_logic) and embedding are converse to each other: while the former appends function symbols at the bottom of the term, the latter appends them at the top. The [encompassment ordering](wikipedia://en/42964077) relates a term and any result of appends on both sides.
- To each node of a term, its *depth* (called *height* by some authors) can be assigned, i.e. its distance (number of edges) from the root. In this setting, the depth of a node always equals the length of its position string. In the picture, depth levels in the black term are indicated in green.
- The *size* of a term commonly refers to the number of its nodes, or, equivalently, to the length of the term's written representation, counting symbols without parentheses. The black and the blue term in the picture has the size 15 and 5, respectively.
- A term *u* *matches* a term *t*, if a substitution instance of *u* structurally equals a subterm of *t*, or formally, if $u\sigma = t|_{p}$ for some position *p* in *t* and some substitution σ. In this case, *u*, *t*, and σ are called the *pattern term*, the *subject term*, and the *matching substitution*, respectively. In the picture, the blue pattern term $x*(y*z)$ matches the black subject term at position 1, with the matching substitution $\{ x \mapsto a, y \mapsto a+1, z \mapsto a+2 \}$ indicated by blue variables immediately left to their black substitutes. Intuitively, the pattern, except for its variables, must be contained in the subject; if a variable occurs multiple times in the pattern, equal subterms are required at the respective positions of the subject.

## Related concepts {#Related_concepts}

### Sorted terms {#Sorted_terms}

When the domain of discourse contains elements of basically different kinds, it is useful to split the set of all terms accordingly. To this end, a *sort* (sometimes also called *type*) is assigned to each variable and each constant symbol, and a declaration [^o19] of domain sorts and range sort to each function symbol. A *sorted term* *f*(*t*<sub>1</sub>,...,*t*<sub>*n*</sub>) may be composed from sorted subterms *t*<sub>1</sub>,...,*t*<sub>*n*</sub> only if the $i$th subterm's sort matches the declared $i$th domain sort of *f*. Such a term is also called *well-sorted*; any other term (i.e. obeying the unsorted rules only) is called *ill-sorted*.

For example, a [vector space](wikipedia://en/32370#Definition) comes with an associated [field](wikipedia://en/10603) of scalar numbers. Let *W* and *N* denote the sort of vectors and numbers, respectively, let *V*<sub>*W*</sub> and *V*<sub>*N*</sub> be the set of vector and number variables, respectively, and *C*<sub>*W*</sub> and *C*<sub>*N*</sub> the set of vector and number constants, respectively. Then e.g. $\vec{0} \in C_W$ and $0 \in C_{N}$, and the vector addition, the scalar multiplication, and the inner product is declared as $+:W \times W \to W, *:W \times N \to W$, and $\langle .,. \rangle: W \times W \to N$, respectively. Assuming variable symbols $\vec{v},\vec{w} \in V_W$ and $a,b \in V_{N}$, the term $\langle (\vec{v}+\vec{0})*a,\vec{w}*b \rangle$ is well-sorted, while $\vec{v}+a$ is not (since + doesn't accept a term of sort *N* as 2nd argument). In order to make $a*\vec{v}$ a well-sorted term, an additional declaration $*:N \times W \to W$ is required. Function symbols having several declarations are called *overloaded*.

See [many-sorted logic](wikipedia://en/8169758) for more information, including extensions of the *many-sorted framework* described here.

### Lambda terms {#Lambda_terms}

*Terms with bound variables*

::: {#o21 .table cue=table name="Terms with bound variables"}

| Notation example | Bound variables | Free variables | Written as lambda-term |
|---|---|---|---|
| $n\to\infty x/n$ | *n* | *x* | *limit*(λ*n*. *div*(*x*,*n*)) |
| $\sum_{i=1}^n i^2$ | *i* | *n* | *sum*(1,*n*,λ*i*. *power*(*i*,2)) |
| $\int_a^b \sin(k \cdot t) dt$ | *t* | *a*, *b*, *k* | *integral*(*a*,*b*,λ*t*. *sin*(*k*⋅*t*)) |

:::

#### Motivation {#Motivation}

Mathematical notations as shown in the table do not fit into the scheme of a first-order term as defined above, as they all introduce an own *local*, or *bound*, variable that may not appear outside the notation's scope, e.g. $t \cdot \int_a^b \sin(k \cdot t) \; dt$ doesn't make sense. In contrast, the other variables, referred to as *free*, behave like ordinary first-order term variables, e.g. $k \cdot \int_a^b \sin(k \cdot t) \; dt$ does make sense.

All these operators can be viewed as taking a function rather than a value term as one of their arguments. For example, the *lim* operator is applied to a sequence, i.e. to a mapping from positive integer to e.g. real numbers. As another example, a [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) function to implement the second example from the table, Σ, would have a function pointer argument (see box below).

*[Lambda terms](https://en.wikipedia.org/wiki/Lambda_term)* can be used to denote *[anonymous functions](https://en.wikipedia.org/wiki/Anonymous_function)* to be supplied as arguments to *lim*, Σ, ∫, etc.

For example, the function *square* from the C program below can be written anonymously as a lambda term λ*i*. *i*<sup>2</sup>. The general sum operator Σ can then be considered as a ternary function symbol taking a lower bound value, an upper bound value and a function to be summed-up. Due to its latter argument, the Σ operator is called a *second-order function symbol*. As another example, the lambda term λ*n*. *x*/*n* denotes a function that maps 1, 2, 3, ... to *x*/1, *x*/2, *x*/3, ..., respectively, that is, it denotes the [sequence](wikipedia://en/27838#Definition) (*x*/1, *x*/2, *x*/3, ...). The *lim* operator takes such a sequence and returns its limit (if defined).

The rightmost column of the table indicates how each mathematical notation example can be represented by a lambda term, also converting common [infix](wikipedia://en/199014) operators into [prefix](wikipedia://en/25056) form.

```c
// implements general sum operator
int sum(int lwb, int upb, int fct(int)) {    
    int res = 0;
    for (int i=lwb; i<=upb; ++i)
        res += fct(i);
    return res;
}

// implements anonymous function (lambda i. i*i); however, C requires a name for it
int square(int i) { return i*i; }            

#include <stdio.h>
int main(void) {
    int n;
    scanf(" %d",&n);
    printf("%d\n", sum(1, n, square));        // applies sum operator to sum up squares
    return 0;
}
```

::: {#o24 .definition cue=heading name="Definition"}

#### Definition {#Definition}

Given a set *V* of variable symbols, the set of lambda terms is defined recursively as follows:

- every variable symbol *x*∈*V* is a lambda term;
- if *x*∈*V* is a variable symbol and *t* is a lambda term, then λ*x*.*t* is also a lambda term (abstraction);
- if *t*<sub>1</sub> and *t*<sub>2</sub> are lambda terms, then ( *t*<sub>1</sub> *t*<sub>2</sub> ) is also a lambda term (application).

The above motivating examples also used some constants like *div*, *power*, etc. which are, however, not admitted in pure lambda calculus.

Intuitively, the abstraction λ*x*.*t* denotes a unary function that returns *t* when given *x*, while the application ( *t*<sub>1</sub> *t*<sub>2</sub> ) denotes the result of calling the function *t*<sub>1</sub> with the input *t*<sub>2</sub>. For example, the abstraction λ*x*.*x* denotes the identity function, while λ*x*.*y* denotes the constant function always returning *y*. The lambda term λ*x*.(*x* *x*) takes a function *x* and returns the result of applying *x* to itself.

:::
