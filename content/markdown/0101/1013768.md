# LAPACK

::: {#o2 .subject cue=lead name="LAPACK"}

**LAPACK** ("Linear Algebra Package") is a standard [software library](https://en.wikipedia.org/wiki/Software_library) for [numerical linear algebra](wikipedia://en/7330660). It provides [routines](https://en.wikipedia.org/wiki/Subroutine) for solving [systems of linear equations](https://en.wikipedia.org/wiki/Systems_of_linear_equations) and [linear least squares](wikipedia://en/30035928), [eigenvalue problems](wikipedia://en/13576645), and [singular value decomposition](wikipedia://en/142207). It also includes routines to implement the associated [matrix factorizations](https://en.wikipedia.org/wiki/Matrix_factorization) such as [LU](wikipedia://en/6243993), [QR](wikipedia://en/305223), [Cholesky](wikipedia://en/134433) and [Schur decomposition](wikipedia://en/372514).[^o3] The routines handle both [real](wikipedia://en/20646438) and [complex](wikipedia://en/5826) matrices in both [single](https://en.wikipedia.org/wiki/Single_precision) and [double precision](https://en.wikipedia.org/wiki/Double_precision). LAPACK relies on an underlying [BLAS](https://en.wikipedia.org/wiki/Basic_Linear_Algebra_Subprograms) implementation to provide efficient and portable computational building blocks for its routines.[^o3]

:::

LAPACK was originally written in [FORTRAN 77](https://en.wikipedia.org/wiki/FORTRAN_77), but moved to [Fortran 90](https://en.wikipedia.org/wiki/Fortran_90) in version 3.2 (2008).[^o4] It is officially distributed through the [Netlib](https://en.wikipedia.org/wiki/Netlib) repository. Maintenance work is nowadays done in a [GitHub](https://en.wikipedia.org/wiki/GitHub) repository.[^o5]

LAPACK was designed as the successor to the linear equations and linear least-squares routines of [LINPACK](https://en.wikipedia.org/wiki/LINPACK) and the eigenvalue routines of [EISPACK](https://en.wikipedia.org/wiki/EISPACK). [LINPACK](https://en.wikipedia.org/wiki/LINPACK), written in the 1970s and 1980s, was designed to run on the then-modern [vector computers](https://en.wikipedia.org/wiki/Vector_processor) with shared memory. LAPACK, in contrast, was designed to effectively exploit the [caches](https://en.wikipedia.org/wiki/CPU_cache) on modern cache-based architectures and the [instruction-level parallelism](https://en.wikipedia.org/wiki/Instruction-level_parallelism) of modern [superscalar processors](https://en.wikipedia.org/wiki/Superscalar_processor),[^o3] and thus can run orders of magnitude faster than LINPACK on such machines, given a well-tuned [BLAS](https://en.wikipedia.org/wiki/Basic_Linear_Algebra_Subprograms) implementation.[^o3] LAPACK has also been extended to run on [distributed memory](https://en.wikipedia.org/wiki/Distributed_memory) systems in later packages such as [ScaLAPACK](https://en.wikipedia.org/wiki/ScaLAPACK) and PLAPACK.[^o6]

Netlib LAPACK is licensed under a three-clause [BSD style](https://en.wikipedia.org/wiki/BSD_licenses) license, a [permissive free software license](https://en.wikipedia.org/wiki/Permissive_free_software_license) with few restrictions.[^o7]

## Naming scheme {#Naming_scheme}

Subroutines in LAPACK have a naming convention which makes the identifiers very compact. This was necessary as the first [Fortran](https://en.wikipedia.org/wiki/Fortran) standards only supported identifiers up to six characters long, so the names had to be shortened to fit into this limit.[^o3]

A LAPACK subroutine name is in the form `pmmaaa`, where:

- `p` is a one-letter code denoting the type of numerical constants used. `S`, `D` stand for real [floating-point arithmetic](wikipedia://en/11376) respectively in single and double precision, while `C` and `Z` stand for [complex arithmetic](wikipedia://en/5826) with respectively single and double precision. The newer version, LAPACK95, uses [generic](https://en.wikipedia.org/wiki/Generic_function) subroutines in order to overcome the need to explicitly specify the data type.
- `mm` is a two-letter code denoting the kind of matrix expected by the algorithm. The codes for the different kind of matrices are reported below; the actual data are stored in a different format depending on the specific kind; e.g., when the code `DI` is given, the subroutine expects a vector of length `n` containing the elements on the diagonal, while when the code `GE` is given, the subroutine expects an $n\times n$ array containing the entries of the matrix.
- `aaa` is a one- to three-letter code describing the actual algorithm implemented in the subroutine, e.g. `SV` denotes a subroutine to solve [linear system](wikipedia://en/722503), while `R` denotes a rank-1 update.

For example, the subroutine to solve a linear system with a general (non-structured) matrix using real double-precision arithmetic is called `DGESV`.[^o3]

## Use with other programming languages and libraries {#Use_with_other_programming_languages_and_libraries}

Many programming environments today support the use of libraries with [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) binding (LAPACKE, a standardised C interface,[^o11] has been part of LAPACK since version 3.4.0[^o12]), allowing LAPACK routines to be used directly so long as a few restrictions are observed. Additionally, many other software libraries and tools for scientific and numerical computing are built on top of LAPACK, such as [R](wikipedia://en/376707),[^o13] [MATLAB](wikipedia://en/20412),[^o14] and [SciPy](https://en.wikipedia.org/wiki/SciPy).[^o15]

Several alternative [language bindings](https://en.wikipedia.org/wiki/Language_binding) are also available:

- [Armadillo](https://en.wikipedia.org/wiki/Armadillo_%28C++_library%29) for [C++](https://en.wikipedia.org/wiki/C++)
- [IT++](https://en.wikipedia.org/wiki/IT++) for C++
- [LAPACK++](https://en.wikipedia.org/wiki/LAPACK++) for C++
- Lacaml for [OCaml](https://en.wikipedia.org/wiki/OCaml)
- [SciPy](https://en.wikipedia.org/wiki/SciPy) for [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29)
- Gonum for [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29)
- [PDL::LinearAlgebra](https://metacpan.org/pod/PDL::LinearAlgebra) for [Perl Data Language](https://en.wikipedia.org/wiki/Perl_Data_Language)
- [Math::Lapack](https://metacpan.org/pod/Math::Lapack) for [Perl](https://en.wikipedia.org/wiki/Perl)
- [NLapack](https://github.com/2xmax/NLapack) for [.NET](https://en.wikipedia.org/wiki/.NET_Framework)
- [CControl](https://github.com/DanielMartensson/CControl) for [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) in embedded systems
- [lapack](https://docs.rs/lapack/latest/lapack/) for [rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29)

## Implementations {#Implementations}

As with BLAS, LAPACK is sometimes forked or rewritten to provide better performance on specific systems. Some of the implementations are:

**Accelerate**

[Apple](https://en.wikipedia.org/wiki/Apple_Inc.)'s framework for [macOS](https://en.wikipedia.org/wiki/MacOS) and [iOS](https://en.wikipedia.org/wiki/IOS_%28Apple%29), which includes tuned versions of [BLAS](https://en.wikipedia.org/wiki/BLAS) and LAPACK.[^o18][^o19]

**Netlib LAPACK**

The official LAPACK.

**Netlib [ScaLAPACK](https://en.wikipedia.org/wiki/ScaLAPACK)**

Scalable (multicore) LAPACK, built on top of [PBLAS](https://en.wikipedia.org/wiki/PBLAS).

**[Intel MKL](https://en.wikipedia.org/wiki/Intel_MKL)**

Intel's Math routines for their x86 CPUs.

**[OpenBLAS](https://en.wikipedia.org/wiki/OpenBLAS)**

Open-source reimplementation of BLAS and LAPACK.

**Gonum LAPACK**

A partial native [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29) implementation.

Since LAPACK typically calls underlying BLAS routines to perform the bulk of its computations, simply linking to a better-tuned BLAS implementation can be enough to significantly improve performance. As a result, LAPACK is not reimplemented as often as BLAS is.

### Similar projects {#Similar_projects}

These projects provide a similar functionality to LAPACK, but with a main interface differing from that of LAPACK:

**Libflame**

A dense linear algebra library. Has a LAPACK-compatible wrapper. Can be used with any BLAS, although [BLIS](https://en.wikipedia.org/wiki/BLIS_%28software%29) is the preferred implementation.[^o21]

**[Eigen](https://en.wikipedia.org/wiki/Eigen_%28C++_library%29)**

A header library for linear algebra. Has a BLAS and a partial LAPACK implementation for compatibility.

**MAGMA**

Matrix Algebra on GPU and Multicore Architectures (MAGMA) project develops a dense linear algebra library similar to LAPACK but for heterogeneous and hybrid architectures including multicore systems accelerated with [GPGPUs](https://en.wikipedia.org/wiki/GPGPU).

**PLASMA**

[The Parallel Linear Algebra for Scalable Multi-core Architectures](https://en.wikipedia.org/wiki/The_Parallel_Linear_Algebra_for_Scalable_Multi-core_Architectures) (PLASMA) project is a modern replacement of LAPACK for multi-core architectures. PLASMA is a software framework for development of asynchronous operations and features out of order scheduling with a runtime scheduler called QUARK that may be used for any code that expresses its dependencies with a [directed acyclic graph](wikipedia://en/204002).[^o22]
