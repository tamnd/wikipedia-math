# Counter-based random number generator

::: {#o1 .subject cue=lead name="Counter-based random number generator"}

A **counter-based random number generation** (**CBRNG**, also known as a counter-based pseudo-random number generator, or CBPRNG) is a kind of [pseudorandom number generator](wikipedia://en/45524) that uses only an integer counter as its internal state. They are generally used for generating pseudorandom numbers for large parallel computations.

:::

## Background {#Background}

We can think of a pseudorandom number generator (PRNG) as a function that transforms a series of bits known as the *state* into a new state and a random number.

That is, given a PRNG function and an initial state $\mathrm{state}_0$, we can repeatedly use the PRNG to generate a sequence of states and random numbers.

$$\begin{aligned} \mathrm{PRNG}(\mathrm{state}_0) &= \mathrm{state}_1,\ \mathrm{num}_1 \\ \mathrm{PRNG}(\mathrm{state}_1) &= \mathrm{state}_2,\ \mathrm{num}_2 \\ \mathrm{PRNG}(\mathrm{state}_2) &= \mathrm{state}_3,\ \mathrm{num}_3 \\ \mathrm{PRNG}(\mathrm{state}_3) &= \ldots \end{aligned}$$

In some PRNGs, such as the [Mersenne Twister](wikipedia://en/45538), the state is large, more than 2048 bytes. In other PRNGs, such as [xorshift](https://en.wikipedia.org/wiki/Xorshift), $\mathrm{state}_i$ and $\mathrm{num}_i$ are one and the same (and so the state is small, just 4, 8, or 16 bytes, depending on the size of the numbers being generated). But in both cases, and indeed in most traditional PRNGs, the state evolves unpredictably, so if you want to calculate a particular $\mathrm{state}_i$ given an initial state $\mathrm{state}_0$, you have to calculate $\mathrm{state}_1$, $\mathrm{state}_2$, and so on, running the PRNG $i$ times.

Such algorithms are inherently *sequential* and not amenable to running on parallel machines like [multi-core CPUs](https://en.wikipedia.org/wiki/Multi-core_CPU) and [GPUs](https://en.wikipedia.org/wiki/GPU).

In contrast, a counter-based random number generator (CBRNG) is a PRNG where the state "evolves" in a particularly simple manner: $\mathrm{state}_i = i$. This way you can generate each number independently, without knowing the result of the previous call to the PRNG.

This property make it easy to run a CBRNG on a multiple CPU threads or a GPU. For example, to generate $n$ random numbers on a GPU, you might spawn $n$ threads and have the $i$th thread calculate $\mathrm{PRNG}(i)$.

## CBRNGs based on block ciphers {#CBRNGs_based_on_block_ciphers}

Some CBRNGs are based on reduced-strength versions of [block ciphers](wikipedia://en/4594). Below we explain how this works.

When using a cryptographic [block cipher](wikipedia://en/4594) in [counter mode](wikipedia://en/160202#CTR), you generate a series of blocks of random bits. The $i$th block is calculated by encrypting the number $i$ using the encryption key $k$: $\mathrm{Block}_i = E(i, k)$.

This is similar to a CBRNG, where you calculate the $i$th random number as $\mathrm{PRNG}(i)$. Indeed, any block cipher can be used as a CBRNG; simply let $\mathrm{PRNG}(i) = E(i, \mathrm{seed})$!

This yields a strong, [cryptographically-secure source of randomness](wikipedia://en/182249). But cryptographically-secure pseudorandom number generators tend to be slow compared to insecure PRNGs, and in practice many uses of random numbers don't require this degree of security.

In 2011, Salmon et al. at [D. E. Shaw Research](https://en.wikipedia.org/wiki/D._E._Shaw_Research) introduced[^o4] two CBRNGs based on reduced-strength versions of block ciphers.

- [Threefry](https://en.wikipedia.org/wiki/Threefry) uses a reduced-strength version of the [Threefish](wikipedia://en/20019277) block cipher. (Juvenile fish are known as "[fry](https://en.wikipedia.org/wiki/Juvenile_fish)".)
- [ARS](https://en.wikipedia.org/wiki/ARS_%28random_number_generator%29) uses a reduced-strength version of the [AES](wikipedia://en/1260) block cipher. ("ARS" is a pun on "AES"; "AES" stands for "advanced encryption standard", and "ARS" stands for "advanced randomization system"[^o5]).

ARS is used in recent versions of [Intel](https://en.wikipedia.org/wiki/Intel)'s [Math Kernel Library](wikipedia://en/23820248)[^o6] and gets good performance by using instructions from the [AES-NI](https://en.wikipedia.org/wiki/AES-NI) instruction set, which specifically accelerate AES encryption.

Code implementing Threefry, ARS, and Philox (see below) is available from the authors.[^o7]

## CBRNGs based on multiplication {#CBRNGs_based_on_multiplication}

In addition to Threefry and ARS, Salmon et al. described a third counter-based PRNG, [Philox](https://en.wikipedia.org/wiki/Philox),[^o4] based on wide multiplies; e.g. multiplying two 32-bit numbers and producing a 64-bit number, or multiplying two 64-bit numbers and producing a 128-bit number.

As of 2020, Philox is popular on CPUs and GPUs. On GPUs, [nVidia](https://en.wikipedia.org/wiki/NVidia)'s cuRAND library[^o9] and [TensorFlow](https://en.wikipedia.org/wiki/TensorFlow)[^o10] provide implementations of Philox. On CPUs, Intel's [MKL](wikipedia://en/23820248) provides an implementation.

A more recent CBRNG based on multiplication is the Squares RNG,[^o11] which applies four rounds of squaring to a counter for a 32-bit output, or five rounds for a 64-bit output. Its author reports that both versions pass stringent tests of randomness and that they "may be the fastest counter-based generators".[^o11]

L'Ecuyer et al. confirm that the proposal passes the standard empirical tests of L'Ecuyer and Simard, but note that it fails with only three rounds and describe the construction as highly heuristic.[^o12] Unlike a block cipher, it is not known to produce every 32-bit output equally often as the counter runs over its full range, and output quality depends strongly on the key: for the key 0 the output is always 0, and for a small integer key $k$ approximately the first 2<sup>16</sup>/$k$ outputs are 0. Consequently, using 1, 2, ..., $s$ as keys to define $s$ streams — a common practice — gives poor results unless the keys are first hashed to random-looking values.[^o12]
