# Description logic

::: {#o1 .subject cue=lead name="Description logic"}

**Description logics** (**DL**) are a family of formal [knowledge representation](https://en.wikipedia.org/wiki/Knowledge_representation) languages. Many DLs are more expressive than [propositional logic](wikipedia://en/18154) but less expressive than [first-order logic](wikipedia://en/10983). In contrast to the latter, the core reasoning problems for DLs are (usually) [decidable](wikipedia://en/913118), and efficient decision procedures have been designed and implemented for these problems. There are general, spatial, temporal, spatiotemporal, and fuzzy description logics, and each description logic features a different balance between [expressive power](https://en.wikipedia.org/wiki/Expressive_power_%28computer_science%29) and [reasoning](https://en.wikipedia.org/wiki/Knowledge_representation_and_reasoning) [complexity](wikipedia://en/502426) by supporting different sets of mathematical constructors.[^o2]

:::

DLs are used in [artificial intelligence](https://en.wikipedia.org/wiki/Artificial_intelligence) to describe and reason about the relevant concepts of an application domain (known as *terminological knowledge*). It is of particular importance in providing a logical formalism for [ontologies](https://en.wikipedia.org/wiki/Ontology_%28information_science%29) and the [Semantic Web](https://en.wikipedia.org/wiki/Semantic_Web): the [Web Ontology Language](https://en.wikipedia.org/wiki/Web_Ontology_Language) (OWL) and its profiles are based on DLs. A major area of application of DLs and OWL is in biomedical informatics, where they assist in the codification of biomedical knowledge.[^o3] DLs and OWL are also applied in other domains, including defense, climate modeling, and large-scale industrial knowledge graphs.[^o4][^o5]

## Introduction {#Introduction}

A DL models *concepts*, *roles* and *individuals*, and their relationships.

The fundamental modeling concept of a DL is the *axiom*—a logical statement relating roles and/or concepts.[^o7] This is a key difference from the [frames](https://en.wikipedia.org/wiki/Semantic_frames) paradigm where a *frame specification* declares and completely defines a class.[^o7]

The [Web Ontology Language](https://en.wikipedia.org/wiki/Web_Ontology_Language) (OWL) uses again a different terminology, also given in the table below.

### Naming convention {#Naming_convention}

There are many varieties of description logics and there is an informal naming convention, roughly describing the operators allowed. The [expressivity](https://en.wikipedia.org/wiki/Expressive_power_%28computer_science%29) is encoded in the label for a logic starting with one of the following basic logics:

| $\mathcal{AL}$ | Attributive language. This is the base language which allows: |
|---|---|
|  | Atomic negation (negation of concept names that do not appear on the left-hand side of axioms) Concept intersection Universal restrictions Limited existential quantification |
| $\mathcal{FL}$ | Frame based description language,[^o12] allows: |
|  | Concept intersection Universal restrictions Limited existential quantification Role restriction |
| $\mathcal{EL}$ | Existential language, allows: |
|  | Concept intersection Existential restrictions (of full existential quantification) |

Followed by any of the following extensions:

| $\mathcal{F}$ | Functional properties, a special case of [uniqueness quantification](wikipedia://en/276894). |
|---|---|
| $\mathcal{E}$ | Full existential qualification (existential restrictions that have fillers other than $\top$). |
| $\mathcal{U}$ | Concept union. |
| $\mathcal{C}$ | Complex concept negation. |
| $\mathcal{H}$ | Role hierarchy (subproperties: `rdfs:subPropertyOf`). |
| $\mathcal{R}$ | Limited complex role inclusion axioms; reflexivity and irreflexivity; role disjointness. |
| $\mathcal{O}$ | Nominals. (Enumerated classes of object value restrictions: `owl:oneOf`, `owl:hasValue`). |
| $\mathcal{I}$ | Inverse properties. |
| $\mathcal{N}$ | Cardinality restrictions (`owl:cardinality`, `owl:maxCardinality`), a special case of [counting quantification](wikipedia://en/2150531) |
| $\mathcal{Q}$ | Qualified cardinality restrictions (available in OWL 2, cardinality restrictions that have fillers other than $\top$). |
| $^\mathcal{(D)}$ | Use of datatype properties, data values or data types. |

#### Exceptions {#Exceptions}

Some canonical DLs that do not exactly fit this convention are:

| $\mathcal{S}$ | An abbreviation for $\mathcal{ALC}$ with transitive roles. |
|---|---|
| $\mathcal{FL^-}$ | A sub-language of $\mathcal{FL}$, which is obtained by disallowing role restriction. This is equivalent to $\mathcal{AL}$ without atomic negation. |
| $\mathcal{FL}_o$ | A sub-language of $\mathcal{FL^-}$, which is obtained by disallowing limited existential quantification. |
| $\mathcal{EL^{++}}$ | Alias for $\mathcal{ELRO}$.[^o14] |

::: {#o16 .example cue=heading name="Examples"}

#### Examples {#Examples}

As an example, $\mathcal{ALC}$ is a centrally important description logic from which comparisons with other varieties can be made. $\mathcal{ALC}$ is simply $\mathcal{AL}$ with complement of any concept allowed, not just atomic concepts. $\mathcal{ALC}$ is used instead of the equivalent $\mathcal{ALUE}$.

A further example, the description logic $\mathcal{SHIQ}$ is the logic $\mathcal{ALC}$ plus extended cardinality restrictions, and transitive and inverse roles. The naming conventions aren't purely systematic so that the logic $\mathcal{ALCOIN}$ might be referred to as $\mathcal{ALCNIO}$ and other abbreviations are also made where possible.

The Protégé ontology editor supports $\mathcal{SHOIN}^\mathcal{(D)}$. Three major biomedical informatics terminology bases, [SNOMED CT](https://en.wikipedia.org/wiki/SNOMED_CT), GALEN, and GO, are expressible in $\mathcal{EL}$ (with additional role properties).

OWL 2 provides the expressiveness of $\mathcal{SROIQ}^\mathcal{(D)}$, OWL-DL is based on $\mathcal{SHOIN}^\mathcal{(D)}$, and for OWL-Lite it is $\mathcal{SHIF}^\mathcal{(D)}$.

:::

## History {#History}

Description logic was given its current name in the 1980s. Previous to this it was called (chronologically): *terminological systems*, and *concept languages*.

### Knowledge representation {#Knowledge_representation}

[Frames](https://en.wikipedia.org/wiki/Semantic_frames) and [semantic networks](https://en.wikipedia.org/wiki/Semantic_network) lack formal (logic-based) semantics.[^o19] DL was first introduced into [knowledge representation](https://en.wikipedia.org/wiki/Knowledge_representation) (KR) systems to overcome this deficiency.[^o19]

The first DL-based KR system was [KL-ONE](https://en.wikipedia.org/wiki/KL-ONE) (by [Ronald J. Brachman](https://en.wikipedia.org/wiki/Ronald_J._Brachman) and Schmolze, 1985). During the '80s other DL-based systems using *structural subsumption algorithms*[^o19] were developed including KRYPTON (1983), [LOOM](https://en.wikipedia.org/wiki/LOOM_%28ontology%29) (1987), BACK (1988), K-REP (1991) and CLASSIC (1991). This approach featured DL with limited expressiveness but relatively efficient (polynomial time) reasoning.[^o19]

In the early '90s, the introduction of a new *tableau based algorithm* paradigm allowed efficient reasoning on more expressive DL.[^o19] DL-based systems using these algorithms — such as KRIS (1991) — show acceptable reasoning performance on typical inference problems even though the worst case complexity is no longer polynomial.[^o19]

From the mid '90s, reasoners were created with good practical performance on very expressive DL with high worst case complexity.[^o19] Examples from this period include FaCT,[^o20] [RACER](https://en.wikipedia.org/wiki/RACER_system) (2001), CEL (2005), and [KAON 2](https://en.wikipedia.org/wiki/KAON) (2005).

DL reasoners, such as FaCT, FaCT++,[^o20] RACER, DLP and Pellet,[^o21] implement the [method of analytic tableaux](wikipedia://en/1027229). KAON2 is implemented by algorithms which reduce a SHIQ(D) knowledge base to a disjunctive [datalog](https://en.wikipedia.org/wiki/Datalog) program.

### Semantic web {#Semantic_web}

The [DARPA Agent Markup Language](https://en.wikipedia.org/wiki/DARPA_Agent_Markup_Language) (DAML) and [Ontology Inference Layer](https://en.wikipedia.org/wiki/Ontology_Inference_Layer) (OIL) [ontology languages](https://en.wikipedia.org/wiki/Ontology_Language) for the [Semantic Web](https://en.wikipedia.org/wiki/Semantic_Web) can be viewed as [syntactic](wikipedia://en/546039) variants of DL.[^o23] In particular, the formal semantics and reasoning in OIL use the $\mathcal{SHIQ}$ DL.[^o24] The [DAML+OIL](https://en.wikipedia.org/wiki/DAMLplusOIL) DL was developed as a submission to[^o25]—and formed the starting point of—the [World Wide Web Consortium](https://en.wikipedia.org/wiki/World_Wide_Web_Consortium) (W3C) Web Ontology Working Group.[^o26] In 2004, the Web Ontology Working Group completed its work by issuing the [OWL](https://en.wikipedia.org/wiki/Web_Ontology_Language)[^o27] recommendation. The design of OWL is based on the $\mathcal{SH}$ family of DL[^o28] with OWL DL and OWL Lite based on $\mathcal{SHOIN}^\mathcal{(D)}$ and $\mathcal{SHIF}^\mathcal{(D)}$ respectively.[^o28]

The W3C OWL Working Group began work in 2007 on a refinement of - and extension to - OWL.[^o29] In 2009, this was completed by the issuance of the [OWL2](https://en.wikipedia.org/wiki/Web_Ontology_Language) recommendation.[^o30] OWL2 is based on the description logic $\mathcal{SROIQ}^\mathcal{(D)}$.[^o31] Practical experience demonstrated that OWL DL lacked several key features necessary to model complex domains.[^o7]

## Modeling {#Modeling}

### TBox vs Abox {#TBox_vs_Abox}

In DL, a distinction is drawn between the so-called [TBox](https://en.wikipedia.org/wiki/Abox) (terminological box) and the [ABox](https://en.wikipedia.org/wiki/ABox) (assertional box). In general, the TBox contains sentences describing concept hierarchies (i.e., relations between [concepts](https://en.wikipedia.org/wiki/Concept)) while the ABox contains [ground sentences](https://en.wikipedia.org/wiki/Ground_sentence) stating where in the hierarchy, individuals belong (i.e., relations between individuals and concepts). For example, the statement:

::: {#o34 .equation cue=numblk name="1"}

$$Every employee is a person \tag{1}$$

:::

belongs in the TBox, while the statement:

::: {#o35 .equation cue=numblk name="2"}

$$Bob is an employee \tag{2}$$

:::

belongs in the ABox.

Note that the TBox/ABox distinction is not significant, in the same sense that the two "kinds" of sentences are not treated differently in first-order logic (which subsumes most DL). When translated into first-order logic, a subsumption [axiom](wikipedia://en/928) like ((1)) is simply a conditional restriction to [unary](wikipedia://en/161006) [predicates](wikipedia://en/285109) (concepts) with only variables appearing in it. Clearly, a sentence of this form is not privileged or special over sentences in which only constants ("grounded" values) appear like ((2)).

### Motivation for having Tbox and Abox {#Motivation_for_having_Tbox_and_Abox}

So why was the distinction introduced? The primary reason is that the separation can be useful when describing and formulating decision-procedures for various DL. For example, a reasoner might process the TBox and ABox separately, in part because certain key inference problems are tied to one but not the other one ('classification' is related to the TBox, 'instance checking' to the ABox). Another example is that the complexity of the TBox can greatly affect the performance of a given decision-procedure for a certain DL, independently of the ABox. Thus, it is useful to have a way to talk about that specific part of the [knowledge base](https://en.wikipedia.org/wiki/Knowledge_base).

The secondary reason is that the distinction can make sense from the knowledge base modeler's perspective. It is plausible to distinguish between our conception of terms/concepts in the world (class axioms in the TBox) and particular manifestations of those terms/concepts (instance assertions in the ABox). In the above example: when the hierarchy within a company is the same in every branch but the assignment to employees is different in every department (because there are other people working there), it makes sense to reuse the TBox for different branches that do not use the same ABox.

There are two features of description logic that are not shared by most other data description formalisms: DL does not make the [unique name assumption](https://en.wikipedia.org/wiki/Unique_name_assumption) (UNA) or the [closed-world assumption](wikipedia://en/2526582) (CWA). Not having UNA means that two concepts with different names may be allowed by some inference to be shown to be equivalent. Not having CWA, or rather having the [open world assumption](https://en.wikipedia.org/wiki/Open_world_assumption) (OWA) means that lack of knowledge of a fact does not immediately imply knowledge of the negation of a fact.

## Formal description {#Formal_description}

Like [first-order logic](wikipedia://en/10983) (FOL), a [syntax](wikipedia://en/546039) defines which collections of symbols are legal expressions in a description logic, and [semantics](wikipedia://en/29107) determine meaning. Unlike FOL, a DL may have several well known syntactic variants.[^o23]

### Syntax {#Syntax}

The syntax of a member of the description logic family is characterized by its recursive definition, in which the constructors that can be used to form concept terms are stated. Some constructors are related to logical constructors in [first-order logic](wikipedia://en/10983) (FOL) such as *[intersection](wikipedia://en/23476429)* or *[conjunction](wikipedia://en/18152)* of concepts, *[union](wikipedia://en/47949)* or *[disjunction](https://en.wikipedia.org/wiki/Disjunction)* of concepts, *[negation](wikipedia://en/161019)* or *[complement](wikipedia://en/54347)* of concepts, *[universal restriction](https://en.wikipedia.org/wiki/Universal_quantifier)* and *[existential restriction](https://en.wikipedia.org/wiki/Existential_quantifier)*. Other constructors have no corresponding construction in FOL including restrictions on roles for example, inverse, [transitivity](wikipedia://en/200463) and functionality.

::: {#o40 .definition kind=definition/notation cue=heading name="Notation"}

#### Notation {#Notation}

Let C and D be concepts, a and b be individuals, and R be a role.

If a is R-related to b, then b is called an R-successor of a.

*Conventional Notation*

::: {#o41 .table cue=table name="Conventional Notation"}

| Symbol | Description | Example | Read |
|---|---|---|---|
| $\top$ | ⊤ is a special concept with every individual as an instance | $\top$ | top |
| $\bot$ | [empty](wikipedia://en/9566) concept | $\bot$ | bottom |
| $\sqcap$ | *[intersection](wikipedia://en/23476429)* or *[conjunction](wikipedia://en/18152)* of concepts | $C \sqcap D$ | C and D |
| $\sqcup$ | *[union](wikipedia://en/47949)* or *[disjunction](https://en.wikipedia.org/wiki/Disjunction)* of concepts | $C \sqcup D$ | C or D |
| $\neg$ | *[negation](wikipedia://en/161019)* or *[complement](wikipedia://en/54347)* of concepts | $\neg C$ | not C |
| $\forall$ | *[universal restriction](https://en.wikipedia.org/wiki/Universal_quantifier)* | $\forall R.C$ | all R-successors are in C |
| $\exists$ | *[existential restriction](https://en.wikipedia.org/wiki/Existential_quantifier)* | $\exists R.C$ | an R-successor exists in C |
| $\sqsubseteq$ | Concept *inclusion* | $C \sqsubseteq D$ | all C are D |
| $\equiv$ | Concept *equivalence* | $C \equiv D$ | C is equivalent to D |
| $\dot =$ | Concept *definition* | $C \mathrel{\dot =} D$ | C is defined to be equal to D |
| $:$ | Concept *assertion* | $a : C$ | a is a C |
| $:$ | Role *assertion* | $(a,b) : R$ | a is R-related to b |

#### The description logic ALC {#The_description_logic_ALC}

The prototypical DL *Attributive Concept Language with Complements* ($\mathcal{ALC}$) was introduced by Manfred Schmidt-Schauß and Gert Smolka in 1991, and is the basis of many more expressive DLs.[^o19] The following definitions follow the treatment in Baader et al.[^o19]

Let $N_C$, $N_R$ and $N_O$ be (respectively) [sets](wikipedia://en/26691) of *concept names* (also known as *atomic concepts*), *role names* and *individual names* (also known as *individuals*, *nominals* or *objects*). Then the ordered triple ($N_C$, $N_R$, $N_O$) is the *signature*.

##### Concepts {#Concepts}

The set of $\mathcal{ALC}$ *concepts* is the smallest set such that:

- The following are *concepts*:
  - $\top$ (*top* is a *concept*)
  - $\bot$ (*bottom* is a *concept*)
  - Every $A \in N_C$ (all *atomic concepts* are *concepts*)
- If $C$ and $D$ are *concepts* and $R \in N_R$ then the following are *concepts*:
  - $C\sqcap D$ (the intersection of two *concepts* is a *concept*)
  - $C\sqcup D$ (the union of two *concepts* is a *concept*)
  - $\neg C$ (the complement of a *concept* is a *concept*)
  - $\forall R.C$ (the universal restriction of a *concept* by a *role* is a *concept*)
  - $\exists R.C$ (the existential restriction of a *concept* by a *role* is a *concept*)

::: {#o45 .statement kind=statement/axiom cue=named-heading name="Terminological axioms"}

##### Terminological axioms {#Terminological_axioms}

A *general concept inclusion* (GCI) has the form $C \sqsubseteq D$ where $C$ and $D$ are *concepts*. Write $C \equiv D$ when $C \sqsubseteq D$ and $D \sqsubseteq C$. A *TBox* is any finite set of GCIs.

:::

::: {#o47 .statement kind=statement/axiom cue=named-heading name="Assertional axioms"}

##### Assertional axioms {#Assertional_axioms}

- A *concept assertion* is a statement of the form $a : C$ where $a \in N_O$ and C is a *concept*.
- A *role assertion* is a statement of the form $(a,b) : R$ where $a, b \in N_O$ and R is a *role*.

An *ABox* is a finite set of assertional axioms.

:::

##### Knowledge base {#Knowledge_base}

A *knowledge base* (KB) is an ordered pair $(\mathcal{T}, \mathcal{A})$ for [TBox](https://en.wikipedia.org/wiki/Abox) $\mathcal{T}$ and [ABox](https://en.wikipedia.org/wiki/Abox) $\mathcal{A}$.

### Semantics {#Semantics}

The [semantics](wikipedia://en/29107) of description logics are defined by interpreting concepts as sets of individuals and roles as sets of ordered pairs of individuals. Those individuals are typically assumed from a given domain. The semantics of non-atomic concepts and roles is then defined in terms of atomic concepts and roles. This is done by using a recursive definition similar to the syntax.

#### The description logic ALC {#The_description_logic_ALC}

The following definitions follow the treatment in Baader et al.[^o19]

A *terminological interpretation* $\mathcal{I}=(\Delta^{\mathcal{I}}, \cdot^{\mathcal{I}})$ over a *signature* $(N_C,N_R,N_O)$ consists of

- a non-empty set $\Delta^{\mathcal{I}}$ called the [*domain*](wikipedia://en/229180)
- a *interpretation function* $\cdot^{\mathcal{I}}$ that maps:
  - every *individual* $a$ to an element $a^{\mathcal{I}} \in \Delta^{\mathcal{I}}$
  - every *concept* to a subset of $\Delta^{\mathcal{I}}$
  - every *role name* to a subset of $\Delta^{\mathcal{I}} \times \Delta^{\mathcal{I}}$

such that

- $$\top^{\mathcal{I}} = \Delta^{\mathcal{I}}$$
- $$\bot^{\mathcal{I}} = \emptyset$$
- $(C \sqcup D)^{\mathcal{I}} = C^{\mathcal{I}} \cup D^{\mathcal{I}}$ *([union](wikipedia://en/47949) means [disjunction](https://en.wikipedia.org/wiki/Disjunction))*
- $(C \sqcap D)^{\mathcal{I}} = C^{\mathcal{I}} \cap D^{\mathcal{I}}$ *([intersection](wikipedia://en/23476429) means [conjunction](wikipedia://en/18152))*
- $(\neg C)^{\mathcal{I}} = \Delta^{\mathcal{I}} \setminus C^{\mathcal{I}}$ *([complement](wikipedia://en/54347) means [negation](wikipedia://en/161019))*
- $$(\forall R.C)^{\mathcal{I}} = \{x \in \Delta^{\mathcal{I}} \mid \text{for} \; \text{every} \; y, (x,y) \in R^{\mathcal{I}} \; \text{implies} \; y \in C^{\mathcal{I}} \}$$
- $$(\exists R.C)^{\mathcal{I}} = \{x \in \Delta^{\mathcal{I}} \mid \text{there} \; \text{exists} \; y, (x,y) \in R^{\mathcal{I}} \; \text{and} \; y \in C^{\mathcal{I}}\}$$

Define $\mathcal{I} \models$ (read *in I holds*) as follows

##### TBox {#TBox}

- $\mathcal{I} \models C \sqsubseteq D$ if and only if $C^{\mathcal{I}} \subseteq D^{\mathcal{I}}$
- $\mathcal{I} \models \mathcal{T}$ if and only if $\mathcal{I} \models \Phi$ for every $\Phi \in \mathcal{T}$

##### ABox {#ABox}

- $\mathcal{I} \models a : C$ if and only if $a^{\mathcal{I}} \in C^{\mathcal{I}}$
- $\mathcal{I} \models (a,b) : R$ if and only if $(a^{\mathcal{I}},b^{\mathcal{I}}) \in R^{\mathcal{I}}$
- $\mathcal{I} \models \mathcal{A}$ if and only if $\mathcal{I} \models \phi$ for every $\phi \in \mathcal{A}$

##### Knowledge base {#Knowledge_base}

Let $\mathcal{K} = (\mathcal{T}, \mathcal{A})$ be a knowledge base.

- $\mathcal{I} \models \mathcal{K}$ if and only if $\mathcal{I} \models \mathcal{T}$ and $\mathcal{I} \models \mathcal{A}$

## Inference {#Inference}

### Decision problems {#Decision_problems}

In addition to the ability to describe concepts formally, one also would like to employ the description of a set of concepts to ask questions about the concepts and instances described. The most common decision problems are basic database-query-like questions like *instance checking* (is a particular instance (member of an ABox) a member of a given concept) and *relation checking* (does a relation/role hold between two instances, in other words does **a** have property **b**), and the more global-database-questions like *subsumption* (is a concept a subset of another concept), and *concept consistency* (is there no contradiction among the definitions or chain of definitions). The more operators one includes in a logic and the more complicated the TBox (having cycles, allowing non-atomic concepts to include each other), usually the higher the computational complexity is for each of these problems (see [Description Logic Complexity Navigator](http://www.cs.man.ac.uk/~ezolin/dl/) for examples).

## Relationship with other logics {#Relationship_with_other_logics}

### First-order logic {#First-order_logic}

Many DLs are [decidable](wikipedia://en/913118) [fragments](wikipedia://en/43571557) of [first-order logic](wikipedia://en/10983) (FOL)[^o19] and are usually fragments of [two-variable logic](wikipedia://en/43571383) or [guarded logic](wikipedia://en/19349240). In addition, some DLs have features that are not covered in FOL; this includes *concrete domains* (such as integer or strings, which can be used as ranges for roles such as *hasAge* or *hasName*) or an operator on roles for the [transitive closure](wikipedia://en/292239) of that role.[^o19]

### Fuzzy description logic {#Fuzzy_description_logic}

Fuzzy description logics combines [fuzzy logic](wikipedia://en/49180) with DLs. Since many concepts that are needed for [intelligent systems](https://en.wikipedia.org/wiki/Artificial_intelligence) lack well defined boundaries, or precisely defined criteria of membership, fuzzy logic is needed to deal with notions of vagueness and imprecision. This offers a motivation for a generalization of description logic towards dealing with imprecise and vague concepts.

### Modal logic {#Modal_logic}

Description logic is related to—but developed independently of—[modal logic](wikipedia://en/333365) (ML).[^o19] Many—but not all—DLs are syntactic variants of ML.[^o19]

In general, an object corresponds to a [possible world](wikipedia://en/911960), a concept corresponds to a modal proposition, and a role-bounded quantifier to a modal operator with that role as its accessibility relation.

Operations on roles (such as composition, inversion, etc.) correspond to the modal operations used in [dynamic logic](wikipedia://en/31631871).[^o60]

### Temporal description logic {#Temporal_description_logic}

Temporal description logic represents—and allows reasoning about—time dependent concepts and many different approaches to this problem exist.[^o65] For example, a description logic might be combined with a [modal](wikipedia://en/333365) [temporal logic](wikipedia://en/321481) such as [linear temporal logic](wikipedia://en/710307).

### Reasoners {#Reasoners}

There are some [semantic reasoners](https://en.wikipedia.org/wiki/Semantic_reasoner) that deal with OWL and DL. These are some of the most popular:

- [CEL](http://lat.inf.tu-dresden.de/systems/cel/) is an open source LISP-based reasoner (Apache 2.0 License).
- [Cerebra Engine](https://web.archive.org/web/20060419191746/http://www.cerebra.com/) was a commercial C++-based reasoner, acquired in 2006 by webMethods.
- [FaCT++](http://owl.man.ac.uk/factplusplus) is a free open-source C++-based reasoner.
- [KAON2](https://en.wikipedia.org/wiki/KAON) is a free (for non-commercial use) Java-based reasoner, offering fast reasoning support for OWL ontologies.
- [MSPASS](http://www.cs.man.ac.uk/~schmidt/mspass/) is a free open-source C reasoner for numerous DL models.
- [Pellet](https://web.archive.org/web/20070925082014/http://pellet.owldl.com/) is a dual-licensed (AGPL and proprietary) commercial, Java-based reasoner.
- [RacerPro](http://www.racer-systems.com/) of Racer Systems was a commercial (free trials and research licenses are available) lisp-based reasoner, today both an open source version of RACER exists from the original developers at Lübeck University using the BSD 3 license, and also a commercialized version, still named [RacerPro by Franz Inc.](https://franz.com/agraph/racer/racer_features.lhtml)
- [Sim-DL](https://sim-dl.sourceforge.net/) is a free open-source Java-based reasoner for the language ALCHQ. It also provides a similarity measurement functionality between concepts. To access this functionality a Protégé plugin can be used.
- [HermiT](http://hermit-reasoner.com/) is an [open-source](https://en.wikipedia.org/wiki/Open-source_model) reasoner based on the "hypertableau" calculus. It is developed by the [University of Oxford](https://en.wikipedia.org/wiki/University_of_Oxford).
- [Owlready2](https://owlready2.readthedocs.io/en/latest/) is a package for ontology-oriented programming in [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29). It can load OWL 2.0 ontologies as Python objects, modify them, save them, and perform reasoning via [HermiT](http://hermit-reasoner.com/) (included). Owlready2 allows a transparent access to OWL ontologies (contrary to usual Java-based API).
- [OWLAPY](https://github.com/dice-group/owlapy/releases). OWLAPY is an open-source Python framework for creating, manipulating, and reasoning with OWL ontologies. It includes a built-in StructuralReasoner for efficient, lightweight reasoning and wrappers for well-known Java-based reasoners like HermiT, Pellet, JFact, and Openllet.

### Editors {#Editors}

- [Protégé](https://en.wikipedia.org/wiki/Protégé_%28software%29) is a free, open-source ontology editor and a [knowledge base](https://en.wikipedia.org/wiki/Knowledge_base) framework, which can use DL reasoners offering DIG Interface as a [back end](https://en.wikipedia.org/wiki/Front_and_back_ends) for consistency checks.
- ronwalf/swoop, an [OWL](https://en.wikipedia.org/wiki/Web_Ontology_Language) browser/editor that takes the standard [web browser](https://en.wikipedia.org/wiki/Web_browser) as the basic UI [paradigm](wikipedia://en/175308).

### Interfaces {#Interfaces}

- dig, a standardized XML interface to DLs systems developed by the [DL Implementation Group (DIG)](http://dl.kr.org/dig/).
- owlapi, a [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) interface and implementation for the [Web Ontology Language](https://en.wikipedia.org/wiki/Web_Ontology_Language), used to represent [Semantic Web](https://en.wikipedia.org/wiki/Semantic_Web) ontologies.
- dice-group/owlapy, a [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) interface and implementation for the [Web Ontology Language](https://en.wikipedia.org/wiki/Web_Ontology_Language), used to represent [Semantic Web](https://en.wikipedia.org/wiki/Semantic_Web) ontologies.
