# Triple DES

::: {#o2 .subject cue=lead name="Triple DES"}

In [cryptography](wikipedia://en/18934432), **Triple DES** (**3DES** or **TDES**), officially the **Triple Data Encryption Algorithm** (**TDEA** or **Triple DEA**), is a [symmetric-key](https://en.wikipedia.org/wiki/Symmetric-key) [block cipher](wikipedia://en/4594), which applies the [Data Encryption Standard](wikipedia://en/7978) (DES) cipher algorithm three times to each data block. At the time of its development, the 56-bit [key size](wikipedia://en/5749) of DES was increasingly considered inadequate against newer [cryptanalysis](wikipedia://en/5715) techniques, and rapid growth in [computer performance](https://en.wikipedia.org/wiki/Computer_performance), as predicted by the [Moore's law](https://en.wikipedia.org/wiki/Moore's_law), made [brute-force attacks](wikipedia://en/53784) increasingly possible and practical. Triple DES increases the effective key size to 112 bits. A [CVE](https://en.wikipedia.org/wiki/Common_Vulnerabilities_and_Exposures) released in 2016, *[CVE-2016-2183](https://nvd.nist.gov/vuln/detail/CVE-2016-2183)*, disclosed a major security vulnerability in the DES and 3DES encryption algorithms. This CVE, combined with the inadequate key size of 3DES, led to [NIST](https://en.wikipedia.org/wiki/NIST) deprecating 3DES in 2019 and disallowing all uses (except processing already encrypted data) by the end of 2023.[^o3] It has been replaced with the more secure, more robust [Advanced Encryption Standard](wikipedia://en/1260), the AES.

:::

While US government and industry standards abbreviate the algorithm's name as TDES (Triple DES) and TDEA (Triple Data Encryption Algorithm),[^o4] RFC 1851 referred to it as 3DES from the time it first promulgated the idea, and this namesake has since come into wide use by most vendors, users, and cryptographers.[^o5][^o6][^o7]

## History {#History}

In 1978, a triple encryption method using DES with two 56-bit keys was proposed by [Walter Tuchman](https://en.wikipedia.org/wiki/Walter_Tuchman); in 1981, [Merkle](wikipedia://en/25849) and [Hellman](wikipedia://en/422387) proposed a more secure triple-key version of 3DES with 112 bits of security.[^o9]

## Standards {#Standards}

The Triple Data Encryption Algorithm is variously defined in several standards documents:

- [RFC](https://en.wikipedia.org/wiki/Request_for_Comments) 1851, *The ESP Triple DES Transform*[^o11] (approved in 1995)
- [ANSI](https://en.wikipedia.org/wiki/ANSI) ANS X9.52-1998 *Triple Data Encryption Algorithm Modes of Operation*[^o12] (approved in 1998, withdrawn in 2008[^o13])
- [FIPS](https://en.wikipedia.org/wiki/Federal_Information_Processing_Standards) PUB 46-3 *Data Encryption Standard (DES)*[^o14] (approved in 1999, withdrawn in 2005[^o15])
- [NIST](https://en.wikipedia.org/wiki/NIST) Special Publication 800-67 Revision 2 *Recommendation for the Triple Data Encryption Algorithm (TDEA) Block Cipher*[^o16] (approved in 2017, withdrawn in 2024[^o17])
- [ISO](https://en.wikipedia.org/wiki/ISO)/[IEC](https://en.wikipedia.org/wiki/International_Electrotechnical_Commission) 18033-3:2010: Part 3: Block ciphers[^o18] (approved in 2005)

## Algorithm {#Algorithm}

The original DES cipher's [key size](wikipedia://en/5749) of 56 bits was considered generally sufficient when it was designed, but the availability of increasing computational power made [brute-force attacks](wikipedia://en/53784) feasible. Triple DES provides a relatively simple method of increasing the key size of DES to protect against such attacks, without the need to design a completely new block cipher algorithm.

A naive approach to increase the strength of a block encryption algorithm with a short key length (like DES) would be to use two keys $(K1, K2)$ instead of one, and encrypt each block twice: $E_{K2}(E_{K1}(\textrm{plaintext}))$. If the original key length is $n$ bits, one would hope this scheme provides security equivalent to using a key $2n$ bits long. Unfortunately, this approach is vulnerable to the [meet-in-the-middle attack](wikipedia://en/423418): given a [known plaintext](https://en.wikipedia.org/wiki/Known_plaintext) pair $(x, y)$, such that $y = E_{K2}(E_{K1}(x))$, one can recover the key pair $(K1, K2)$ in $2^{n+1}$ steps, instead of the $2^{2n}$ steps one would expect from an ideally secure algorithm with $2n$ bits of key.

Therefore, Triple DES uses a "key bundle" that comprises three DES [keys](wikipedia://en/53039), $K1$, $K2$ and $K3$, each of 56 bits (excluding [parity bits](wikipedia://en/194467)). The encryption algorithm is:

$$\textrm{ciphertext} = E_{K3}(D_{K2}(E_{K1}(\textrm{plaintext}))).$$

That is, encrypt with $K1$, decrypt with $K2$, then encrypt with $K3$.

Decryption is the reverse:

$$\textrm{plaintext} = D_{K1}(E_{K2}(D_{K3}(\textrm{ciphertext}))).$$

That is, decrypt with $K3$, encrypt with $K2$, then decrypt with $K1$.

Each triple encryption encrypts one [block](wikipedia://en/294065) of 64 bits of data.

In each case, the middle operation is the reverse of the first and last. This improves the strength of the algorithm when using keying option 2 and provides [backward compatibility](https://en.wikipedia.org/wiki/Backward_compatibility) with DES with keying option 3.

### EEE operation {#EEE_operation}

The text above describes the mode common and standardized EDE (encrypt-decrypt-encrypt) sequence. There is a separate "EEE" (encrypt-encrypt-encrypt) sequence supported by some libraries in two-key or three-key setups.[^o22]

:::

## Keying options {#Keying_options}

The standards define three keying options:

**Keying option 1**

All three keys are independent. Sometimes known as 3TDEA[^o24] or triple-length keys.[^o25]This is the strongest, with 3 × 56 = 168 independent key bits. It is still vulnerable to the [meet-in-the-middle attack](wikipedia://en/423418), but the attack requires 2<sup>2 × 56</sup> steps.

**Keying option 2**

K<sub>1</sub> and K<sub>2</sub> are independent, and K<sub>3</sub> = K<sub>1</sub>. Sometimes known as 2TDEA[^o24] or double-length keys.[^o25]This provides a shorter key length of 56 × 2 or 112 bits and a reasonable compromise between DES and keying option 1, with the same caveat as above.[^o26] This is an improvement over "double DES" which only requires 2<sup>56</sup> steps to attack. NIST disallowed this option in 2015.[^o24]

**Keying option 3**

All three keys are identical, i.e. K<sub>1</sub> = K<sub>2</sub> = K<sub>3</sub>.This is backward-compatible with DES, since two of the operations cancel out. ISO/IEC 18033-3 never allowed this option, and NIST no longer allows K<sub>1</sub> = K<sub>2</sub> or K<sub>2</sub> = K<sub>3</sub>.[^o24][^o16]

Each DES key is 8 [odd-parity](https://en.wikipedia.org/wiki/Odd_parity) bytes, with 56 bits of key and 8 bits of error-detection.[^o12] A key bundle requires 24 bytes for option 1, 16 for option 2, or 8 for option 3.

With these restrictions on allowed keys, Triple DES was reapproved with keying options 1 and 2 only. Generally, the three keys are generated by taking 24 bytes from a strong random generator, and only keying option 1 should be used (option 2 needs only 16 random bytes, but strong random generators are hard to assert and it is considered best practice to use only option 1).

## Encryption of more than one block {#Encryption_of_more_than_one_block}

As with all block ciphers, encryption and decryption of multiple blocks of data may be performed using a variety of [modes of operation](https://en.wikipedia.org/wiki/Modes_of_operation), which can generally be defined independently of the block cipher algorithm. However, ANS X9.52 specifies directly, and NIST SP 800-67 specifies via SP 800-38A,[^o28] that some modes shall only be used with certain constraints on them that do not necessarily apply to general specifications of those modes. For example, ANS X9.52 specifies that for [cipher block chaining](https://en.wikipedia.org/wiki/Cipher_block_chaining), the [initialization vector](wikipedia://en/105971) shall be different each time, whereas ISO/IEC 10116[^o29] does not. FIPS PUB 46-3 and ISO/IEC 18033-3 define only the single-block algorithm, and do not place any restrictions on the modes of operation for multiple blocks.

## Security {#Security}

In general, Triple DES with three independent keys (keying option 1) has a key length of 168 bits (three 56-bit DES keys), but due to the [meet-in-the-middle attack](wikipedia://en/423418), the effective security it provides is only 112 bits.[^o24] Keying option 2 reduces the effective key size to 112 bits (because the third key is the same as the first). However, this option is susceptible to certain [chosen-plaintext](https://en.wikipedia.org/wiki/Chosen-plaintext) or [known-plaintext](https://en.wikipedia.org/wiki/Known-plaintext) attacks,[^o9][^o33] and thus it is designated by NIST to have only 80 [bits of security](https://en.wikipedia.org/wiki/Bits_of_security).[^o24] This can be considered insecure; as a consequence, Triple DES's planned deprecation was announced by NIST in 2017.[^o34]

The short block size of 64 bits makes 3DES vulnerable to block collision attacks if it is used to encrypt large amounts of data with the same key. The Sweet32 attack shows how this can be exploited in TLS and OpenVPN.[^o35] Practical Sweet32 attack on 3DES-based cipher-suites in TLS required $2^{36.6}$ blocks (785 GB) for a full attack, but researchers were lucky to get a collision just after around $2^{20}$ blocks, which took only 25 minutes.

[OpenSSL](wikipedia://en/438819) does not include 3DES by default since version 1.1.0 (August 2016) and considers it a "weak cipher".[^o36]

:::

## Usage {#Usage}

As of 2008, the [electronic payment](https://en.wikipedia.org/wiki/Electronic_payment) industry uses Triple DES and continues to develop and promulgate standards based upon it, such as [EMV](https://en.wikipedia.org/wiki/EMV).[^o38]

Earlier versions of [Microsoft OneNote](https://en.wikipedia.org/wiki/Microsoft_OneNote),[^o39] [Microsoft Outlook](https://en.wikipedia.org/wiki/Microsoft_Outlook) 2007[^o40] and Microsoft [System Center Configuration Manager](https://en.wikipedia.org/wiki/System_Center_Configuration_Manager) 2012[^o41] use Triple DES to password-protect user content and system data. However, in December 2018, Microsoft announced the retirement of 3DES throughout their Office 365 service.[^o42]

In 2025, starting with version 144, Firefox abandoned 3DES-CBC for encrypting credentials on the user's computer, and switched to AES-256-CBC.[^o43]
