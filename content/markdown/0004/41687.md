# Self-synchronizing code

::: {#o1 .subject cue=lead name="Self-synchronizing code"}

::: {#o2 .definition cue=dfni name="code words"}

In [coding theory](wikipedia://en/321869), especially in [telecommunications](https://en.wikipedia.org/wiki/Telecommunications), a **self-synchronizing code** is a [uniquely decodable code](https://en.wikipedia.org/wiki/Uniquely_decodable_code) in which the [symbol](https://en.wikipedia.org/wiki/Symbol_%28data%29) stream formed by a portion of one code word, or by the overlapped portion of any two adjacent code words, is not a valid code word.[^o7] Put another way, a set of strings (called **code words**) over an alphabet is called a self-synchronizing code if for each string obtained by concatenating two code words, the substring starting at the second symbol and ending at the second-last symbol does not contain any code word as substring. Every self-synchronizing code is a [prefix code](wikipedia://en/66193), but not all prefix codes are self-synchronizing.

:::

:::

Other terms for self-synchronizing code are **synchronized code**[^o9] or, ambiguously, **comma-free code**.[^o8] A self-synchronizing code permits the proper [framing](https://en.wikipedia.org/wiki/Frame_synchronization) of transmitted code words provided that no uncorrected errors occur in the [symbol stream](https://en.wikipedia.org/wiki/Data_stream); external [synchronization](https://en.wikipedia.org/wiki/Synchronization) is not required. Self-synchronizing codes also allow recovery from uncorrected errors in the stream; with most prefix codes, an uncorrected error in a single [bit](https://en.wikipedia.org/wiki/Bit) may propagate errors further in the stream and make the subsequent data [corrupted](https://en.wikipedia.org/wiki/Data_corruption).

Importance of self-synchronizing codes is not limited to [data transmission](https://en.wikipedia.org/wiki/Data_transmission). Self-synchronization also facilitates some cases of [data recovery](https://en.wikipedia.org/wiki/Data_recovery), for example of a [digitally encoded text](https://en.wikipedia.org/wiki/Character_encoding).

::: {#o4 .example cue=heading name="Examples"}

## Examples {#Examples}

- [UTF-8](https://en.wikipedia.org/wiki/UTF-8) is self-synchronizing at the byte level because the leading byte (`11xxxxxx`) and subsequent bytes (`10xxxxxx`) of a multi-byte code point have different bit patterns.
- [High Level Data Link Control](https://en.wikipedia.org/wiki/High_Level_Data_Link_Control) (HDLC)
- [Advanced Data Communication Control Procedures](https://en.wikipedia.org/wiki/Advanced_Data_Communication_Control_Procedures) (ADCCP)
- [Fibonacci coding](wikipedia://en/48063)

Counterexamples:

- The prefix code {00, 11} is not self-synchronizing; while 0, 1, 01 and 10 are not codes, 00 and 11 are.
- The prefix code {*ab*,*ba*} is not self-synchronizing because *abab* contains *ba*.
- The prefix code *b*<sup>∗</sup>a (using the [Kleene star](wikipedia://en/16750)) is not self-synchronizing (even though any new code word simply starts after *a*) because code word *ba* contains code word *a*.
