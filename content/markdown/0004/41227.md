# Hamming distance

::: {#o2 .subject cue=lead name="Hamming distance"}

In [information theory](wikipedia://en/14773), the **Hamming distance** between two [strings](wikipedia://en/27701) or vectors of equal length is the number of positions at which the corresponding [symbols](wikipedia://en/37673) are different. In other words, it measures the minimum number of *substitutions* required to change one string into the other, or equivalently, the minimum number of *errors* that could have transformed one string into the other. In a more general context, the Hamming distance is one of several [string metrics](https://en.wikipedia.org/wiki/String_metric) for measuring the [edit distance](wikipedia://en/406427) between two sequences. It is named after the American mathematician [Richard Hamming](wikipedia://en/99326).

:::

A major application is in [coding theory](wikipedia://en/321869), more specifically to [block codes](wikipedia://en/1134659), in which the equal-length strings are [vectors](wikipedia://en/32370) over a [finite field](wikipedia://en/11615).

::: {#o4 .definition cue=heading name="Definition"}

## Definition {#Definition}

The Hamming distance between two equal-length strings of symbols is the number of positions at which the corresponding symbols are different.[^o5]

:::

::: {#o7 .example cue=heading name="Examples"}

## Examples {#Examples}

The symbols may be letters, bits, or decimal digits, among other possibilities. For example, the Hamming distance between:

- "**karolin**" and "**kathrin**" is 3.
- "**karolin**" and "**kerstin**" is 3.
- "**kathrin**" and "**kerstin**" is 4.
- **0000** and **1111** is 4.
- **2173896** and **2233796** is 3.

:::

::: {#o9 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

For a fixed length *n*, the Hamming distance is a [metric](https://en.wikipedia.org/wiki/Metric_%28mathematics%29) on the set of the [words](https://en.wikipedia.org/wiki/Word_%28formal_language_theory%29) of length *n* (also known as a [Hamming space](wikipedia://en/4566542)), as it fulfills the conditions of non-negativity, symmetry, the Hamming distance of two words is 0 if and only if the two words are identical, and it satisfies the [triangle inequality](wikipedia://en/53941) as well:[^o12] Indeed, if we fix three words *a*, *b* and *c*, then whenever there is a difference between the *i*th letter of *a* and the *i*th letter of *c*, then there must be a difference between the *i*th letter of *a* and *i*th letter of *b*, or between the *i*th letter of *b* and the *i*th letter of *c*. Hence the Hamming distance between *a* and *c* is not larger than the sum of the Hamming distances between *a* and *b* and between *b* and *c*. The Hamming distance between two words *a* and *b* can also be seen as the [Hamming weight](wikipedia://en/1127884) of *a* − *b* for an appropriate choice of the − operator, much as the difference between two integers can be seen as a distance from zero on the number line.

For binary strings *a* and *b* the Hamming distance is equal to the number of ones ([population count](wikipedia://en/1127884)) in *a* [XOR](wikipedia://en/105979) *b*.[^o25] The metric space of length-*n* binary strings, with the Hamming distance, is known as the *Hamming cube*; it is equivalent as a metric space to the set of distances between vertices in a [hypercube graph](wikipedia://en/6706815). One can also view a binary string of length *n* as a vector in $\mathbb{R}^{n}$ by treating each symbol in the string as a real coordinate; with this embedding, the strings form the vertices of an *n*-dimensional [hypercube](wikipedia://en/39783), and the Hamming distance of the strings is equivalent to the [Manhattan distance](https://en.wikipedia.org/wiki/Manhattan_distance) between the vertices.

:::

## Error detection and error correction {#Error_detection_and_error_correction}

The **minimum Hamming distance** or **minimum distance** (usually denoted by *d<sub>min</sub>*) is used to define some essential notions in [coding theory](wikipedia://en/321869), such as [error detecting and error correcting codes](wikipedia://en/10375). In particular, a [code](https://en.wikipedia.org/wiki/Code_%28coding_theory%29) *C* is said to be *k* error detecting if, and only if, the minimum Hamming distance between any two of its codewords is at least *k*+1.[^o12]

For example, consider a code consisting of two codewords "000" and "111". The Hamming distance between these two words is 3, and therefore it is *k*=2 error detecting. This means that if one bit is flipped or two bits are flipped, the error can be detected. If three bits are flipped, then "000" becomes "111" and the error cannot be detected.

A code *C* is said to be *k-error correcting* if, for every word *w* in the underlying Hamming space *H*, there exists at most one codeword *c* (from *C*) such that the Hamming distance between *w* and *c* is at most *k*. In other words, a code is *k*-errors correcting if the minimum Hamming distance between any two of its codewords is at least 2*k*+1. This is also understood geometrically as any [closed balls](wikipedia://en/160556#In_general_metric_spaces) of radius *k* centered on distinct codewords being disjoint.[^o12] These balls are also called *[Hamming spheres](https://en.wikipedia.org/wiki/Hamming_sphere)* in this context.[^o13]

For example, consider the same 3-bit code consisting of the two codewords "000" and "111". The Hamming space consists of 8 words 000, 001, 010, 011, 100, 101, 110 and 111. The codeword "000" and the single bit error words "001","010","100" are all less than or equal to the Hamming distance of 1 to "000". Likewise, codeword "111" and its single bit error words "110","101" and "011" are all within 1 Hamming distance of the original "111". In this code, a single bit error is always within 1 Hamming distance of the original codes, and the code can be *1-error correcting*, that is *k=1*. Since the Hamming distance between "000" and "111" is 3, and those comprise the entire set of codewords in the code, the minimum Hamming distance is 3, which satisfies *2k+1 = 3*.

Thus a code with minimum Hamming distance *d* between its codewords can detect at most *d*-1 errors and can correct ⌊(*d*-1)/2⌋ errors.[^o12] The latter number is also called the *[packing radius](wikipedia://en/368621#Other_spaces)* or the *error-correcting capability* of the code.[^o13]

:::

## History and applications {#History_and_applications}

The Hamming distance is named after [Richard Hamming](wikipedia://en/99326), who introduced the concept in his fundamental paper on [Hamming codes](wikipedia://en/41226), *Error detecting and error correcting codes*, in 1950.[^o15] Hamming weight analysis of bits is used in several disciplines including [information theory](wikipedia://en/14773), [coding theory](wikipedia://en/321869), and [cryptography](wikipedia://en/18934432).[^o16]

It is used in [telecommunication](https://en.wikipedia.org/wiki/Telecommunication) to count the number of flipped bits in a fixed-length binary word as an estimate of error, and therefore is sometimes called the **signal distance**.[^o17] For *q*-ary strings over an [alphabet](https://en.wikipedia.org/wiki/Alphabet) of size *q* ≥ 2 the Hamming distance is applied in case of the [q-ary symmetric channel](wikipedia://en/74361), while the [Lee distance](wikipedia://en/17766039) is used for [phase-shift keying](https://en.wikipedia.org/wiki/Phase-shift_keying) or more generally channels susceptible to [synchronization errors](https://en.wikipedia.org/wiki/Synchronization_error) because the Lee distance accounts for errors of ±1.[^o18] If $q = 2$ or $q = 3$ both distances coincide because any pair of elements from $\mathbb{Z}/2\mathbb{Z}$ or $\mathbb{Z}/3\mathbb{Z}$ differ by 1, but the distances are different for larger $q$.

The Hamming distance is also used in [systematics](https://en.wikipedia.org/wiki/Systematics) as a measure of genetic distance.[^o19]

However, for comparing strings of different lengths, or strings where not just substitutions but also insertions or deletions have to be expected, a more sophisticated metric such as the [Levenshtein distance](https://en.wikipedia.org/wiki/Levenshtein_distance) may be more appropriate.[^o20]

## Algorithm example {#Algorithm_example}

The following function, written in Python 3, returns the Hamming distance between two strings:

```python3
def hamming_distance(string1: str, string2: str) -> int:
    """Return the Hamming distance between two strings."""
    if len(string1) != len(string2):
        raise ValueError("Strings must be of equal length.")
    dist_counter = 0
    for n in range(len(string1)):
        if string1[n] != string2[n]:
            dist_counter += 1
    return dist_counter
```

The following [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) function will compute the Hamming distance of two integers (considered as binary values, that is, as sequences of bits). The running time of this procedure is proportional to the Hamming distance rather than to the number of bits in the inputs. It computes the [bitwise](wikipedia://en/264399) [exclusive or](wikipedia://en/105979) of the two inputs, and then finds the [Hamming weight](wikipedia://en/1127884) of the result (the number of nonzero bits) using an algorithm of (Wegner 1960) that repeatedly finds and clears the lowest-order nonzero bit. Some compilers support the [\_\_builtin\_popcount](wikipedia://en/1127884#Language_support) function which can calculate this using specialized processor hardware where available.

```c
int hamming_distance(unsigned x, unsigned y)
{
    int dist = 0;

    // The ^ operators sets to 1 only the bits that are different
    for (unsigned val = x ^ y; val > 0; ++dist)
    {
        // We then count the bit set to 1 using the Peter Wegner way
        val = val & (val - 1); // Set to zero val's lowest-order 1
    }

    // Return the number of differing bits
    return dist;
}
```

A faster alternative is to use the population count (*popcount*) assembly instruction. Certain compilers such as GCC and Clang make it available via an intrinsic function:

```c
// Hamming distance for 32-bit integers
int hamming_distance32(unsigned int x, unsigned int y)
{
    return __builtin_popcount(x ^ y);
}

// Hamming distance for 64-bit integers
int hamming_distance64(unsigned long long x, unsigned long long y)
{
    return __builtin_popcountll(x ^ y);
}
```
