# Control flow

::: {#o1 .subject cue=lead name="Control flow"}

In [software](https://en.wikipedia.org/wiki/Software), **control flow** (or **flow of control**) describes how [execution](https://en.wikipedia.org/wiki/Execution_%28computing%29) progresses from one [command](https://en.wikipedia.org/wiki/Command_%28computing%29) to the next. In many contexts, such as [machine code](https://en.wikipedia.org/wiki/Machine_code) and an [imperative](https://en.wikipedia.org/wiki/Imperative_programming) [programming language](wikipedia://en/23015), control progresses sequentially (to the command located immediately after the currently executing command) except when a command transfers control to another point in which case the command is classified as a control flow command. Depending on context, other terms are used instead of *command*. For example, in machine code, the typical term is *instruction* and in an imperative language, the typical term is *statement*.

:::

Although an imperative language encodes control flow explicitly, languages of other [programming paradigms](https://en.wikipedia.org/wiki/Programming_paradigm) are less focused on control flow. A [declarative](https://en.wikipedia.org/wiki/Declarative_programming) language specifies desired results without prescribing an order of operations. A [functional language](https://en.wikipedia.org/wiki/Functional_programming) uses both [language constructs](https://en.wikipedia.org/wiki/Language_construct) and [functions](https://en.wikipedia.org/wiki/Function_%28computer_programming%29) to control flow even though they are usually not called control flow statements.

For a [central processing unit](https://en.wikipedia.org/wiki/Central_processing_unit) [instruction set](https://en.wikipedia.org/wiki/Instruction_set), a control flow instruction often alters the [program counter](https://en.wikipedia.org/wiki/Program_counter) and is either an unconditional [branch](https://en.wikipedia.org/wiki/Branch_%28computer_science%29) (a.k.a. jump) or a conditional branch. An alternative approach is [predication](https://en.wikipedia.org/wiki/Predication_%28computer_architecture%29) which conditionally enables instructions instead of branching.

An [asynchronous](https://en.wikipedia.org/wiki/Asynchrony_%28computer_programming%29) control flow transfer such as an [interrupt](https://en.wikipedia.org/wiki/Interrupt) or a [signal](https://en.wikipedia.org/wiki/Signal_%28IPC%29) alters the normal flow of control to a handler before returning control to where it was interrupted.

One way to attack software is to redirect the flow of execution. A variety of [control-flow integrity](https://en.wikipedia.org/wiki/Control-flow_integrity) techniques, including [stack canaries](https://en.wikipedia.org/wiki/Stack_canary), [buffer overflow protection](https://en.wikipedia.org/wiki/Buffer_overflow_protection), shadow stacks, and [vtable](https://en.wikipedia.org/wiki/Virtual_method_table) pointer verification, are used to defend against these attacks.[^o2][^o3][^o4]

## Structure {#Structure}

Control flow is closely related to code structure. Control flows along lines defined by structure and the execution rules of a language. This general concept of structure is not be confused with [structured programming](https://en.wikipedia.org/wiki/Structured_programming) which limits structure to sequencing, selection and iteration based on [block](https://en.wikipedia.org/wiki/Block_%28programming%29) organization.

### Sequences {#Sequences}

Sequential execution is the most basic structure. Although not all code is sequential in nature, imperative code is.

### Labels {#Labels}

A [label](https://en.wikipedia.org/wiki/Label_%28programming_language%29) identifies a position in [source code](https://en.wikipedia.org/wiki/Source_code). Some control flow statements reference a label so that control jumps to the labeled line. Other than marking a position, a label has no other effect.

Some languages limit a label to a number which is sometimes called a [line number](https://en.wikipedia.org/wiki/Line_number), although that implies the inherent index of the line, not a label. None-the-less, such numeric labels are typically required to increment from top to bottom in a file even if not be sequential. For example, in BASIC:

```qbasic
10 LET X = 3
20 PRINT X
30 GOTO 10
```

In many languages, a label is an alphanumeric [identifier](https://en.wikipedia.org/wiki/Identifier), usually appearing at the start of a line and immediately followed by a colon. For example, the following C code defines a label Success on line 3 which identifies a jump target point at the first statement that follows it (line 4).

```c
void f(bool ok) {
    if (ok) {
        goto success;
    }
    return;
success:
    printf("OK");
}
```

### Blocks {#Blocks}

Most languages provide for organizing sequences of code as a [block](https://en.wikipedia.org/wiki/Block_%28programming%29). When used with a control statement, the beginning of a block provides a jump target. For example, in the following C code (which uses curly braces to delimit a block), control jumps from line 1 to 4 if done is false.

```c
if (done) {
    printf("All done");
} else {
    printf("Still workin' on it");
}
```

## Control {#Control}

Many control commands have been devised for programming languages. This section describes notable constructs; it is organized by functionality.

### Functions {#Functions}

A function provides for control flow in that when called, execution jumps to the start of the function's code and when it completes, control returns the calling point. In the following C code, control jumps from line 6 to 2 in order to call function foo(). Then, after completing the function body (printing "Hi"), control returns to after the call, line 7.

```c
void foo() {
    printf("Hi");
}

void bar() {
    foo();
    printf("Done");
}
```

### Branches {#Branches}

A branch command moves the point of execution from the point in the code that contains the command to the point that the command specifies.

#### Jump {#Jump}

A jump command unconditionally branches control to another point in the code, and is the most basic form of controlling the flow of code.

In a high-level language, this is often provided as a [goto](https://en.wikipedia.org/wiki/Goto) statement. Although the [keyword](https://en.wikipedia.org/wiki/Keyword_%28computing%29) may be upper or lower case or one or two words depending on the language, it is like: `goto ''label''`. When control reaches a goto statement, control then jumps to the statement that follows the indicated label. The goto statement has been [considered harmful](https://en.wikipedia.org/wiki/Considered_harmful) by many computer scientists, including [Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra).

#### Conditional branch {#Conditional_branch}

A [conditional](https://en.wikipedia.org/wiki/Conditional_%28computer_programming%29) statement jumps control based on the value of a [Boolean](https://en.wikipedia.org/wiki/Boolean_data_type) expression. Common variations include:

**if-goto**

Jumps to a label based on a condition; a high-level programming statement that closely mimics a similar used machine code instruction

**if-then**

Rather than being restricted to a jump, a statement or block is executed if the expression is true. In a language that does not include the then keyword, this can be called an if statement.

**if-then-else**

Like if-then, but with a second action to be performed if the condition is false. In a language that does not include the then keyword, this can be called an if-else statement.

**Nested**

Conditional statements are often nested inside other conditional statements.

**Arithmetic if**

Early [Fortran](https://en.wikipedia.org/wiki/Fortran), had an [arithmetic if](https://en.wikipedia.org/wiki/Arithmetic_if) (a.k.a. three-way if) that tests whether a numeric value is negative, zero, or positive. This statement was deemed obsolete in Fortran-90, and deleted as of Fortran 2018.

**Operator**

Some languages have an [operator](https://en.wikipedia.org/wiki/Operator_%28programming%29) form, such as the [ternary conditional operator](https://en.wikipedia.org/wiki/Ternary_conditional_operator).

**When and unless**

[Perl](https://en.wikipedia.org/wiki/Perl) supplements a C-style if with when and unless.

**Messages**

[Smalltalk](https://en.wikipedia.org/wiki/Smalltalk) uses `ifTrue` and `ifFalse` messages to implement conditionals, rather than a language construct.

The following [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29) code shows a simple if-then-else. The syntax is similar in [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29):

```pascal
if a > 0 then
  writeln("yes")
else
  writeln("no");
```

In [C](https://en.wikipedia.org/wiki/C_%28programming_language%29):

```c
if (a > 0) { 
    puts("yes");
} else {
    puts("no");
}
```

In [bash](https://en.wikipedia.org/wiki/Bash_%28Unix_shell%29):

```bash
if [ $a -gt 0 ]; then
      echo "yes"
else
      echo "no"
fi
```

In [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29):

```python
if a > 0: 
    print("yes")
else:
    print("no")
```

In [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29):

```lisp
(princ
  (if (plusp a)
      "yes"
      "no"))
```

#### Multiway branch {#Multiway_branch}

A multiway branch jumps control based on matching values. There is usually a provision for a default action if no match is found. A [switch statement](https://en.wikipedia.org/wiki/Switch_statement) can allow compiler optimizations, such as [lookup tables](https://en.wikipedia.org/wiki/Lookup_table). In [dynamic languages](https://en.wikipedia.org/wiki/Dynamic_language), the cases may not be limited to constant expressions, and might extend to [pattern matching](https://en.wikipedia.org/wiki/Pattern_matching), as in the [shell script](https://en.wikipedia.org/wiki/Shell_script) example on the right, where the `*)` implements the default case as a [glob](https://en.wikipedia.org/wiki/Glob_%28programming%29) matching any string. Case logic can also be implemented in functional form, as in [SQL](wikipedia://en/29004)'s `decode` statement.

The following [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29) code shows a relatively simple switch statement. Pascal uses the case keyword instead of switch.

```pascal
case someChar of
  'a': actionOnA;
  'x': actionOnX;
  'y','z':actionOnYandZ;
  else actionOnNoMatch;
end;
```

In [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29):

```ada
case someChar is
  when 'a' => actionOnA;
  when 'x' => actionOnX;
  when 'y' | 'z' => actionOnYandZ;
  when others => actionOnNoMatch;
end;
```

In [C](https://en.wikipedia.org/wiki/C_%28programming_language%29):

```c
switch (someChar) {
    case 'a': 
        actionOnA; 
        break;
    case 'x': 
        actionOnX; 
        break;
    case 'y':
    case 'z': 
        actionOnYandZ;
        break;
    default: 
        actionOnNoMatch;
}
```

In [Bash](https://en.wikipedia.org/wiki/Bash_%28Unix_shell%29):

```bash
case $someChar in 
   a)    actionOnA ;;
   x)    actionOnX ;;
   [yz]) actionOnYandZ ;;
   *)    actionOnNoMatch  ;;
esac
```

In [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29):

```lisp
(case some-char
  ((#\a)     action-on-a)
  ((#\x)     action-on-x)
  ((#\y #\z) action-on-y-and-z)
  (else      action-on-no-match))
```

In [Fortran](https://en.wikipedia.org/wiki/Fortran):

```fortran
select case (someChar)
  case ('a')
    actionOnA
  case ('x')
    actionOnX
  case ('y','z')
    actionOnYandZ
  case default
    actionOnNoMatch
end select
```

### Loops {#Loops}

*Image: Programmingloops.svg.* basic types of program loops

In a loop, a sequence of statements—frequently called the loop body—gets re-executed (at least in part) after a conditional branch or jump to a previous step in the sequence. The number of times a loop gets executed usually depends on runtime state, for example: the body is executed once for each item of a collection (*definite iteration*), until a condition is met (*indefinite iteration*). Some loops, on the other hand, may repeat [infinitely](https://en.wikipedia.org/wiki/Infinite_loop). It is possible for a loop to be written as an infinite loop but for loop exit to be controlled by a test within the loop body that transfers control outside the loop. Early exit from a loop may be supported via a break statement.[^o16][^o17]

A loop inside the loop body of another loop is called a *nested loop*.[^o18][^o19][^o20]

In a [functional programming](https://en.wikipedia.org/wiki/Functional_programming) language, such as [Haskell](https://en.wikipedia.org/wiki/Haskell) and [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29), both [recursive](wikipedia://en/4044867) and [iterative](https://en.wikipedia.org/wiki/Fixed_point_combinator) processes are expressed with [tail recursive](https://en.wikipedia.org/wiki/Tail_recursion) procedures instead of looping constructs that are syntactic.

#### Numeric {#Numeric}

A relatively simple yet useful loop iterates over a range of numeric values. A simple form starts at an integer value, ends at a larger integer value and iterates for each integer value between. Often, the increment can be any integer value (even negative, to loop from a larger to a smaller value).

Example in BASIC:

```basic
FOR I = 1 TO N
   xxx
NEXT I
```

Example in Pascal:

```pascal
for I := 1 to N do begin
   xxx
end;
```

Example in Fortran:

```fortran
DO I = 1,N
    xxx
END DO
```

In many programming languages, only integers can be used at all or reliably. As a floating-point number is represented imprecisely due to hardware constraints, the following loop might iterate 9 or 10 times, depending on various factors such as rounding error, hardware, compiler. Furthermore, if the increment of X occurs by repeated addition, accumulated rounding errors may mean that the value of X in each iteration can differ quite significantly from the commonly expected sequence of 0.1, 0.2, 0.3, ..., 1.0.

**for** X := 0.1 **step** 0.1 **to** 1.0 **do**

#### Condition-controlled {#Condition-controlled}

Some loop constructs iterate until a condition is true. Some variations test the condition at the start of the loop; others test at the end. If the test is at the start, the body may be skipped completely. At the end, the body is always executed at least once.

Example in Visual Basic:

```visualbasic
DO WHILE (test)
    xxx
LOOP
```

Example in Pascal:

```pascal
repeat
    xxx
until test;
```

Example in C family of pre-test:

```c
while (test) {
    xxx
}
```

Example in C family of post-test:

```c
do
    xxx
while (test);
```

Although using the for keyword, the three-part C-style loop is a condition-based construct, not a numeric-based one. The second part, the condition, is evaluated before each loop, so the loop is pre-test. The first part is a place to initialize state, and the third part is for incrementing for the next iteration, but both aspects can be performed elsewhere. The following C code implements the logic of a numeric loop that iterates for i from 0 to n-1.

```c
for (int i = 0; i < n; ++i) {
    xxx
}
```

#### Enumeration {#Enumeration}

Some loop constructs enumerate the items of a collection; iterating for each item.

Example in Smalltalk:

```smalltalk
someCollection do: [:eachElement |xxx].
```

Example in Pascal:

```pascal
for Item in Collection do begin xxx end;
```

Example in Raku:

```raku
foreach (item; myCollection) { xxx }
```

Example in TCL:

```tcl
foreach someArray { xxx }
```

Example in PHP:

```php
foreach ($someArray as $k => $v) { xxx }
```

Example in Java:

```java
Collection<String> coll; 
for (String s : coll) {}
```

Example in C#:

```csharp
foreach (string s in myStringCollection) { xxx }
```

Example in PowerShell where 'foreach' is an alias of 'ForEach-Object':

```powershell
someCollection | foreach { $_ }
```

Example in Fortran:

```fortran
forall ( index = first:last:step... )
```

[Scala](wikipedia://en/3254510) has [for-expressions](wikipedia://en/3254510#For-expressions), which generalise collection-controlled loops, and also support other uses, such as [asynchronous programming](https://en.wikipedia.org/wiki/Asynchronous_programming). [Haskell](https://en.wikipedia.org/wiki/Haskell) has do-expressions and comprehensions, which together provide similar function to for-expressions in Scala.

#### Loop-and-a-half problem {#Loop-and-a-half_problem}

Common loop structures sometimes result in duplicated code, either repeated statements or repeated conditions. This arises for various reasons and has various proposed solutions to eliminate or minimize code duplication.[^o27] Other than the traditional unstructured solution of a *goto* statement,[^n1] general structured solutions include having a conditional (*if* statement) inside the loop (possibly duplicating the condition but not the statements) or wrapping repeated logic in a function (so there is a duplicated function call, but the statements are not duplicated).[^o27]

A common case is where the start of the loop is always executed, but the end may be skipped on the last iteration.[^n1] This was dubbed by Dijkstra a loop which is performed "*n* and a half times",[^o30] and is now called the ***loop-and-a-half****problem*.[^o17] Common cases include reading data in the first part, checking for end of data, and then processing the data in the second part; or processing, checking for end, and then preparing for the next iteration.[^n1][^o17] In these cases, the first part of the loop is executed $n$ times, but the second part is only executed $n - 1$ times.

This problem has been recognized at least since 1967 by Knuth, with Wirth suggesting solving it via early loop exit.[^n2] Since the 1990s this has been the most commonly taught solution, using a *break* statement, as in:[^o17]

**loop** *statements* **if** *condition* **break** *statements* **repeat**

A subtlety of this solution is that the condition is the *opposite* of a usual *while* condition: rewriting **while** *condition* ... **repeat** with an exit in the middle requires reversing the condition: **loop** ... **if not** *condition* **exit** ... **repeat**. The loop with test in the middle control structure explicitly supports the loop-an-a-half use case, without reversing the condition.[^n2]

#### Unstructured {#Unstructured}

A loop construct provides for structured completion criteria that either results in another iteration or continuing execution after the loop statement. But, various unstructured control flow constructs are supported by many languages.

**Early next iteration**

Some languages provide a construct that jumps control to the beginning of the loop body for the next iteration; for example, `continue` (most common), `skip`,[^o35] `cycle` (Fortran), or `next` (Perl and Ruby).

**Redo iteration**

Some languages, like Perl[^o36] and Ruby,[^o37] have a `redo` statement that jumps to the start of the body for the same iteration.

**Restart**

Ruby has a `retry` statement that restarts the entire loop from the first iteration.[^o38]

##### Early exit {#Early_exit}

Early exit jumps control to after the loop body [^o40][^o17] For example, when searching a list, can stop looping when the item is found. Some programming languages provide a statement such as `break` (most languages), `Exit` (Visual Basic), or `last` (Perl).

In the following Ada code, the loop exits when X is 0.

```ada
loop
    Get(X);
    if X = 0 then
        exit;
    end if;
    DoSomething(X);
end loop;
```

A more idiomatic style uses exit when:

```ada
loop
    Get(X);
    exit when X = 0;
    DoSomething(X);
end loop;
```

[Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) supports conditional execution of code depending on whether a loop was exited early (with a `break` statement) or not by using an else-clause with the loop. In the following Python code, the `else` clause is linked to the `for` statement, and not the inner `if` statement. Both Python's `for` and `while` loops support such an else clause, which is executed only if early exit of the loop has not occurred.

```python
for n in set_of_numbers:
    if isprime(n):
        print("Set contains a prime number")
        break
else:
    print("Set did not contain any prime numbers")
```

###### Multi-level breaks {#Multi-level_breaks}

Some languages support breaking out of nested loops; in theory circles, these are called **multi-level breaks**. One common use example is searching a multi-dimensional table. This can be done either via multilevel breaks (break out of $N$ levels), as in bash[^o42] and PHP,[^o43] or via labeled breaks (break out and continue at given label), as in Ada, Go, Java, Rust and Perl.[^o44] Alternatives to multilevel breaks include single breaks, together with a state variable which is tested to break out another level; exceptions, which are caught at the level being broken out to; placing the nested loops in a function and using return to effect termination of the entire nested loop; or using a label and a goto statement. Neither C nor C++ currently have multilevel break or named loops, and the usual alternative is to use a goto to implement a labeled break.[^o45] However, the inclusion of this feature has been proposed,[^o46] and was added to [C29](https://en.wikipedia.org/wiki/C29_%28C_standard_revision%29),[^o47] following the Java syntax. Python does not have a multilevel break or continue – this was proposed in [PEP 3136](https://www.python.org/dev/peps/pep-3136/), and rejected on the basis that the added complexity was not worth the rare legitimate use.[^o48]

The notion of multi-level breaks is of some interest in [theoretical computer science](wikipedia://en/323392), because it gives rise to what is today called the *Kosaraju hierarchy*.[^o49] In 1973 [S. Rao Kosaraju](https://en.wikipedia.org/wiki/S._Rao_Kosaraju) refined the [structured program theorem](https://en.wikipedia.org/wiki/Structured_program_theorem) by proving that it is possible to avoid adding additional variables in structured programming, as long as arbitrary-depth, multi-level breaks from loops are allowed.[^o50] Furthermore, Kosaraju proved that a strict hierarchy of programs exists: for every integer $n$, there exists a program containing a multi-level break of depth $n$ that cannot be rewritten as a program with multi-level breaks of depth less than *n* without introducing added variables.[^o49]

In his 2004 textbook, [David Watt](https://en.wikipedia.org/wiki/David_Watt_%28computer_scientist%29) uses Tennent's notion of [sequencer](https://en.wikipedia.org/wiki/S-algol) to explain the similarity between multi-level breaks and return statements. Watt notes that a class of sequencers known as *escape sequencers*, defined as "sequencer that terminates execution of a textually enclosing command or procedure", encompasses both breaks from loops (including multi-level breaks) and return statements. As commonly implemented, however, return sequencers may also carry a (return) value, whereas the break sequencer as implemented in contemporary languages usually cannot.[^o51]

##### Middle test {#Middle_test}

The following structure was proposed by [Dahl](https://en.wikipedia.org/wiki/Ole-Johan_Dahl) in 1972:[^o53]

**loop** **loop** xxx1 read(char); **while** test; **while** **not** atEndOfFile; xxx2 write(char); **repeat**; **repeat**;

The construction here can be thought of as a **do** loop with the **while** check in the middle, which allows clear loop-and-a-half logic. Further, by omitting individual components, this single construction can replace several constructions in most programming languages. If *xxx1* is omitted, we get a loop with the test at the top (a traditional **while** loop). If *xxx2* is omitted, we get a loop with the test at the bottom, equivalent to a **do while** loop in many languages. If **while** is omitted, we get an infinite loop. This construction also allows keeping the same polarity of the condition even when in the middle, unlike early exit, which requires reversing the polarity (adding a **not**),[^n2] functioning as **until** instead of **while**.

This structure is not widely supported, with most languages instead using **if** ... **break** for conditional early exit.

This is supported by some languages, such as [Forth](https://en.wikipedia.org/wiki/Forth_%28programming_language%29), where the syntax is BEGIN ... WHILE ... REPEAT,[^o55] and the [shell script](https://en.wikipedia.org/wiki/Shell_script) languages [Bourne shell](https://en.wikipedia.org/wiki/Bourne_shell) (`sh`) and [bash](https://en.wikipedia.org/wiki/Bash_%28Unix_shell%29), where the syntax is **while** ... **do** ... **done** or **until** ... **do** ... **done**, as:[^o56][^o57]

```bash
while
  statement-1
  statement-2
  ...
  condition
do
  statement-a
  statement-b
  ...
done
```

The shell syntax works because the **while** (or **until**) loop accepts a list of commands as a condition,[^o58] formally:

**while** *test-commands*; **do** *consequent-commands*; **done**

The value (exit status) of the list of *test-commands* is the value of the *last* command, and these can be separated by newlines, resulting in the idiomatic form above.

Similar constructions are possible in C and C++ with the [comma operator](https://en.wikipedia.org/wiki/Comma_operator), and [other languages with similar constructs](https://en.wikipedia.org/wiki/Comma_operator#Other_languages), which allow shoehorning a list of statements into the while condition:

```c
while (statement_1, statement_2, condition) {
    statement_a;
    statement_b;
}
```

While legal, this is marginal, and it is primarily used, if at all, only for short modify-then-test cases, as in:[^o59]

```c
while (read_string(s), strlen(s) > 0) {
    // ...
}
```

#### Loop variants and invariants {#Loop_variants_and_invariants}

[Loop variants](https://en.wikipedia.org/wiki/Loop_variant) and [loop invariants](https://en.wikipedia.org/wiki/Loop_invariant) are used to express correctness of loops.[^o61]

In practical terms, a loop variant is an integer expression which has an initial non-negative value. The variant's value must decrease during each loop iteration but must never become negative during the correct execution of the loop. Loop variants are used to guarantee that loops will terminate.

A loop invariant is an assertion which must be true before the first loop iteration and remain true after each iteration. This implies that when a loop terminates correctly, both the exit condition and the loop invariant are satisfied. Loop invariants are used to monitor specific properties of a loop during successive iterations.

Some programming languages, such as [Eiffel](https://en.wikipedia.org/wiki/Eiffel_%28programming_language%29) contain native support for loop variants and invariants. In other cases, support is an add-on, such as the [Java Modeling Language](https://en.wikipedia.org/wiki/Java_Modeling_Language)'s specification for [loop statements](https://www.eecs.ucf.edu/~leavens/JML//jmlrefman/jmlrefman_12.html#SEC168) in [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29).

#### Loop sublanguage {#Loop_sublanguage}

Some [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29) dialects provide an extensive sublanguage for describing Loops. An early example can be found in Conversional Lisp of [Interlisp](https://en.wikipedia.org/wiki/Interlisp). [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp)[^o63] provides a Loop macro which implements such a sublanguage.

### Non-local {#Non-local}

Many programming languages, especially those favoring more dynamic styles of programming, offer constructs for non-local control flow which cause execution to jump from the current execution point to a [predeclared](https://en.wikipedia.org/wiki/Predeclared) point. Notable examples follow.

#### Condition handling {#Condition_handling}

The earliest [Fortran](https://en.wikipedia.org/wiki/Fortran) compilers supported statements for handling exceptional conditions including `IF ACCUMULATOR OVERFLOW`, `IF QUOTIENT OVERFLOW`, and `IF DIVIDE CHECK`. In the interest of machine independence, they were not included in FORTRAN IV and the Fortran 66 Standard. However, since Fortran 2003 it is possible to test for numerical issues via calls to functions in the `IEEE_EXCEPTIONS` module.

[PL/I](https://en.wikipedia.org/wiki/PL/I) has some 22 standard conditions (e.g., ZERODIVIDE SUBSCRIPTRANGE ENDFILE) which can be raised and which can be intercepted by: ON *condition* action; Programmers can also define and use their own named conditions.

Like the *unstructured if*, only one statement can be specified so in many cases a GOTO is needed to decide where flow of control should resume.

Unfortunately, some implementations had a substantial overhead in both space and time (especially SUBSCRIPTRANGE), so many programmers tried to avoid using conditions.

A typical example of syntax:

**ON** *condition* **GOTO** *label*

#### Exception handling {#Exception_handling}

Many modern languages natively support [exception handling](https://en.wikipedia.org/wiki/Exception_handling). Generally, exceptional control flow starts with an exception object being thrown (a.k.a. raised). Control then proceeds to the inner-most exception handler for the [call stack](https://en.wikipedia.org/wiki/Call_stack). If the handler handles the exception, then flow control reverts to normal. Otherwise, control proceeds outward to containing handlers until one handles the exception or the program reaches the outermost scope and exits. As control flows to progressively outer handlers, aspects that would normally occur such as popping the call stack are handled automatically.

The following C++ code demonstrates structured exception handling. If an exception propagates from the execution of doSomething() and the exception object type matches one of the types specified in a catch clause, then that clause is executed. For example, if an exception of type SomeException is propagated by doSomething(), then control jumps from line 2 to 4 and the message "Caught SomeException" is printed and then control jumps to after the try statement, line 8. If an exception of any other type is propagated, then control jumps from line 2 to 6. If no exception, then control jumps from 2 to 8.

```cpp
try {
    doSomething();
} catch (const SomeException& e)
    std::println("Caught SomeException: {}", e.what());
} catch (...) {
    std::println("Unknown error");
}
doNextThing();
```

Many languages use the C++ keywords (throw, try and catch), but some languages use other keywords. For example, Ada uses exception to introduce an exception handler and when instead of catch. [AppleScript](https://en.wikipedia.org/wiki/AppleScript) incorporates placeholders in the syntax to extract information about the exception as shown in the following AppleScript code.

```applescript
try
    set myNumber to myNumber / 0
on error e number n from f to t partial result pr
    if ( e = "Can't divide by zero" ) then display dialog "You must not do that"
end try
```

In many languages (including Object Pascal, D, Java, C#, and Python) a finally clause at the end of a try statement is executed at the end of the try statement, whether an exception propagates from the rest of the try or not. The following C# code ensures that the stream stream is closed.

```csharp
FileStream stream = null;
try
{
    stream = new FileStream("logfile.txt", FileMode.Create);
    return ProcessStuff(stream);
} 
finally
{
    if (stream != null)
    {
        stream.Close();
    }
}
```

Since this pattern is common, C# provides the using statement to ensure cleanup. In the following code, even if ProcessStuff() propagates an exception, the `stream` object is released. Python's `with` statement and Ruby's block argument to `File.open` are used to similar effect.

```csharp
using (FileStream stream = new("logfile.txt", FileMode.Create))
{
    return ProcessStuff(stream);
}
```

#### Event-based early exit from nested loop {#Event-based_early_exit_from_nested_loop}

[Zahn's construct](https://en.wikipedia.org/wiki/Zahn's_construct) was proposed in 1974,[^o108] and discussed in (Knuth 1974). A modified version is presented here.

**exitwhen** EventA **or** EventB **or** EventC; xxx **exits** EventA: actionA EventB: actionB EventC: actionC **endexit**;

**exitwhen** is used to specify the events which may occur within *xxx*, their occurrence is indicated by using the name of the event as a statement. When some event does occur, the relevant action is carried out, and then control passes just after **endexit**. This construction provides a very clear separation between determining that some situation applies, and the action to be taken for that situation.

**exitwhen** is conceptually similar to [exception handling](https://en.wikipedia.org/wiki/Exception_handling), and exceptions or similar constructs are used for this purpose in many languages.

The following simple example involves searching a two-dimensional table for a particular item.

**exitwhen** found **or** missing; **for** I := 1 **to** N **do** **for** J := 1 **to** M **do** **if** table\[I,J\] = target **then** found; missing; **exits** found: print ("item is in table"); missing: print ("item is not in table"); **endexit**;
