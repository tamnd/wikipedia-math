# Type theory

::: {#o1 .subject cue=lead name="Type theory"}

In [mathematical logic](wikipedia://en/19636), and [theoretical computer science](wikipedia://en/323392), **type theory** is the study of [formal systems](wikipedia://en/396102) that classify expressions or [mathematical objects](wikipedia://en/19453961) by their types. Roughly speaking, a type plays a similar role to that played by a [data type](https://en.wikipedia.org/wiki/Data_type) in programming: it specifies what kind of thing an expression is and how it may be used. Type theories are used in the study of [programming languages](wikipedia://en/23015) ([type systems](wikipedia://en/199701)), [formal logic](https://en.wikipedia.org/wiki/Formal_logic), and the [formalization of mathematics](https://en.wikipedia.org/wiki/Formalization_of_mathematics).

:::

Some type theories have been proposed as alternatives to [set theory](wikipedia://en/27553) as a [foundation of mathematics](wikipedia://en/169358). Examples include [Alonzo Church](wikipedia://en/49731)'s [simple theory of types](wikipedia://en/1986011) and [Per Martin-Löf](wikipedia://en/1925764)'s [intuitionistic type theory](wikipedia://en/345023).

Many [proof assistants](wikipedia://en/1258607) are based on type theory. For example, the underlying formal language of [Rocq](wikipedia://en/581974) (formerly Coq) is the [calculus of inductive constructions](https://en.wikipedia.org/wiki/Calculus_of_inductive_constructions), while [Lean](wikipedia://en/62889984) is based on [dependent type theory](https://en.wikipedia.org/wiki/Dependent_type_theory).

## History {#History}

Type theory was created to avoid [paradoxes](wikipedia://en/24390) in [naive set theory](wikipedia://en/4944) and [formal logic](https://en.wikipedia.org/wiki/Formal_logic), such as [Russell's paradox](wikipedia://en/46095) which demonstrates that, without proper axioms, it is possible to define the set of all sets that are not members of themselves; this set both contains itself and does not contain itself. Between 1902 and 1908, [Bertrand Russell](wikipedia://en/4163) proposed various solutions to this problem.

By 1908, Russell arrived at a [ramified theory of types](wikipedia://en/38521219#The_1908_"ramified"_theory_of_types) together with an [axiom of reducibility](wikipedia://en/10591072), both of which appeared in [Whitehead](wikipedia://en/43395) and [Russell](wikipedia://en/4163)'s *[Principia Mathematica](wikipedia://en/24133)* published in 1910, 1912, and 1913. This system avoided contradictions suggested in Russell's paradox by creating a hierarchy of types and then assigning each concrete mathematical entity to a specific type. Entities of a given type were built exclusively of [subtypes](wikipedia://en/213508) of that type, thus preventing an entity from being defined using itself. This resolution of Russell's paradox is similar to approaches taken in other formal systems, such as [Zermelo-Fraenkel set theory](wikipedia://en/152214).[^o3]

Type theory is particularly popular in conjunction with [Alonzo Church](wikipedia://en/49731)'s [lambda calculus](wikipedia://en/18203). One notable early example of type theory is Church's [simply typed lambda calculus](wikipedia://en/1986011). Church's theory of types[^o4] helped the formal system avoid the [Kleene–Rosser paradox](wikipedia://en/14258729) that afflicted the original untyped lambda calculus. Church demonstrated that it could serve as a [foundation of mathematics](wikipedia://en/169358) and it was referred to as a [higher-order logic](wikipedia://en/562883).

In the modern literature, "type theory" refers to a typed system based around lambda calculus. One influential system is [Per Martin-Löf](wikipedia://en/1925764)'s [intuitionistic type theory](wikipedia://en/345023), which was proposed as a foundation for [constructive mathematics](https://en.wikipedia.org/wiki/Constructivism_%28mathematics%29). Another is [Thierry Coquand](wikipedia://en/31842262)'s [calculus of constructions](wikipedia://en/613557), which is used as the foundation by [Rocq](https://en.wikipedia.org/wiki/Rocq_%28software%29) (previously known as *Coq*), [Lean](wikipedia://en/62889984), and other computer [proof assistants](wikipedia://en/1258607). Type theory is an active area of research, one direction being the development of [homotopy type theory](wikipedia://en/33974223).

::: {#o6 .application cue=heading name="Applications"}

## Applications {#Applications}

### Mathematical foundations {#Mathematical_foundations}

The first computer proof assistant, called [Automath](https://en.wikipedia.org/wiki/Automath), used type theory to encode mathematics on a computer. Martin-Löf specifically developed [intuitionistic type theory](wikipedia://en/345023) to encode *all* mathematics to serve as a new foundation for mathematics. There is ongoing research into mathematical foundations using [homotopy type theory](wikipedia://en/33974223).

Mathematicians working in [category theory](wikipedia://en/5869) already had difficulty working with the widely accepted foundation of [Zermelo–Fraenkel set theory](wikipedia://en/152214). This led to proposals such as Lawvere's [Elementary Theory of the Category of Sets](https://en.wikipedia.org/wiki/Elementary_Theory_of_the_Category_of_Sets) (ETCS). Homotopy type theory continues in this line using type theory. Researchers are exploring connections between dependent types (especially the identity type) and [algebraic topology](wikipedia://en/38801) (specifically [homotopy](wikipedia://en/212250)).

::: {#o10 .proof cue=heading name="Proof assistants"}

### Proof assistants {#Proof_assistants}

Much of the current research into type theory is driven by [proof checkers](https://en.wikipedia.org/wiki/Automated_proof_checking), interactive [proof assistants](wikipedia://en/1258607), and [automated theorem provers](wikipedia://en/2546). Most of these systems use a type theory as the mathematical foundation for encoding proofs, which is not surprising, given the close connection between type theory and programming languages:

- [LF](wikipedia://en/901613) is used by [Twelf](https://en.wikipedia.org/wiki/Twelf), often to define other type theories;
- many type theories which fall under [higher-order logic](wikipedia://en/562883) are used by the [HOL family of provers](https://en.wikipedia.org/wiki/HOL_%28proof_assistant%29) and [PVS](https://en.wikipedia.org/wiki/Prototype_Verification_System);
- computational type theory is used by [NuPRL](https://en.wikipedia.org/wiki/NuPRL);
- [calculus of constructions](wikipedia://en/613557) and its derivatives are used by [Rocq](https://en.wikipedia.org/wiki/Rocq_%28software%29) (previously known as *Coq*), [Matita](https://en.wikipedia.org/wiki/Matita), and [Lean](wikipedia://en/62889984);
- UTT (Luo's Unified Theory of dependent Types) is used by [Agda](https://en.wikipedia.org/wiki/Agda_%28programming_language%29) which is both a programming language and proof assistant

Many type theories are supported by [LEGO](https://en.wikipedia.org/wiki/LEGO_%28proof_assistant%29) and [Isabelle](wikipedia://en/161886). Isabelle also supports foundations besides type theories, such as [ZFC](wikipedia://en/152214). [Mizar](wikipedia://en/209074) is an example of a proof system that only supports set theory.

:::

### Programming languages {#Programming_languages}

Any [static program analysis](https://en.wikipedia.org/wiki/Static_program_analysis), such as the type checking algorithms in the [semantic analysis](https://en.wikipedia.org/wiki/Semantic_analysis_%28compilers%29) phase of [compiler](https://en.wikipedia.org/wiki/Compiler), has a connection to type theory. A prime example is [Agda](https://en.wikipedia.org/wiki/Agda_%28programming_language%29), a programming language which uses UTT (Luo's Unified Theory of dependent Types) for its type system.

The programming language [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) was developed for manipulating type theories (see *[Logic for Computable Functions](wikipedia://en/161900)*) and its own type system was heavily influenced by them.

### Linguistics {#Linguistics}

Type theory is also widely used in [formal theories of semantics](https://en.wikipedia.org/wiki/Formal_semantics_%28linguistics%29) of [natural languages](wikipedia://en/21173),[^o14][^o15] especially [Montague grammar](wikipedia://en/709308)[^o16] and its descendants. In particular, [categorial grammars](https://en.wikipedia.org/wiki/Categorial_grammar) and [pregroup grammars](https://en.wikipedia.org/wiki/Pregroup_grammar) extensively use type constructors to define the types (*noun*, *verb*, etc.) of words.

The most common construction takes the basic types $e$ and $t$ for individuals and [truth-values](https://en.wikipedia.org/wiki/Truth-value), respectively, and defines the set of types recursively as follows:

- if $a$ and $b$ are types, then so is $\langle a,b\rangle$;
- nothing except the basic types, and what can be constructed from them by means of the previous clause are types.

A complex type $\langle a,b\rangle$ is the type of [functions](wikipedia://en/185427) from entities of type $a$ to entities of type $b$. Thus one has types like $\langle e,t\rangle$ that are interpreted as elements of the set of functions from entities to truth-values, i.e. [indicator functions](wikipedia://en/240790) of sets of entities. An expression of type $\langle\langle e,t\rangle,t\rangle$ is a function from sets of entities to truth-values, i.e. a (indicator function of a) set of sets. This latter type is standardly taken to be the type of [natural language quantifiers](wikipedia://en/7959499), like *everybody* or *nobody* ([Montague](wikipedia://en/610182) 1973, [Barwise](wikipedia://en/912858) and Cooper 1981).[^o17]

[Type theory with records](https://en.wikipedia.org/wiki/Type_theory_with_records) is a [formal semantics](https://en.wikipedia.org/wiki/Formal_semantics_%28linguistics%29) representation framework, using *[records](https://en.wikipedia.org/wiki/Record_%28computer_science%29)* to express *type theory types*. It has been used in [natural language processing](https://en.wikipedia.org/wiki/Natural_language_processing), principally [computational semantics](https://en.wikipedia.org/wiki/Computational_semantics) and [dialogue systems](https://en.wikipedia.org/wiki/Dialogue_systems).[^o18][^o19]

:::

### Social sciences {#Social_sciences}

[Gregory Bateson](https://en.wikipedia.org/wiki/Gregory_Bateson) introduced a theory of logical types into the social sciences; his notions of [double bind](https://en.wikipedia.org/wiki/Double_bind) and logical levels are based on Russell's theory of types.

## Logic {#Logic}

A type theory is a [mathematical logic](wikipedia://en/19636), which is to say it is a collection of [rules of inference](wikipedia://en/252311) that result in [judgments](wikipedia://en/15014170). Most logics have judgments asserting "The [proposition](wikipedia://en/81094) $\varphi$ is true", or "The [formula](wikipedia://en/1557634) $\varphi$ is a [well-formed formula](wikipedia://en/404582)".[^o22] A type theory has judgments that define types and assign them to a collection of formal objects, known as terms. A term and its type are often written together as $\mathrm{term}:\mathsf{type}$.

### Terms {#Terms}

A [term in logic](wikipedia://en/24885593) is [recursively defined](wikipedia://en/1047605) as a [constant symbol](wikipedia://en/4089175), [variable](wikipedia://en/3728109), or a [function application](wikipedia://en/20576545), where a term is applied to another term. Constant symbols could include the natural number $0$, the Boolean value $\texttt{true}$, and functions such as the [successor function](wikipedia://en/325637) $\mathrm{S}$ and [conditional operator](https://en.wikipedia.org/wiki/Conditional_operator) $\mathrm{if}$. Thus some terms could be $0$, $(\mathrm{S}\,0)$, $(\mathrm{S}\,(\mathrm{S}\,0))$, and $(\mathrm{if}\,\texttt{true}\,0\,(\mathrm{S}\,0))$.

### Judgments {#Judgments}

Most type theories have 4 judgments:

- "$T$ is a type"
- "$t$ is a term of type $T$"
- "Type $T_1$ is equal to type $T_2$"
- "Terms $t_1$ and $t_2$ both of type $T$ are equal"

Judgments may follow from assumptions. For example, one might say "assuming $x$ is a term of type $\mathsf{bool}$ and $y$ is a term of type $\mathsf{nat}$, it follows that $(\textrm{if}\,x\,y\,y)$ is a term of type $\mathsf{nat}$". Such judgments are formally written with the [turnstile symbol](wikipedia://en/7954712) $\vdash$.

$$x:\mathsf{bool},y:\mathsf{nat}\vdash(\mathrm{if}\,x\,y\,y): \mathsf{nat}$$

If there are no assumptions, there will be nothing to the left of the turnstile.

$$\vdash \mathrm{S}:\mathsf{nat}\to\mathsf{nat}$$

The list of assumptions on the left is the *context* of the judgment. Capital greek letters, such as [$\Gamma$](https://en.wikipedia.org/wiki/Gamma) and $\Delta$, are common choices to represent some or all of the assumptions. The 4 different judgments are thus usually written as follows.

::: {#o25 .table cue=table}

| Formal notation for judgments | Description |
|---|---|
| $\Gamma \vdash T$ Type | $T$ is a type (under assumptions $\Gamma$). |
| $\Gamma \vdash t : T$ | $t$ is a term of type $T$ (under assumptions $\Gamma$). |
| $\Gamma \vdash T_1 = T_2$ | Type $T_1$ is equal to type $T_2$ (under assumptions $\Gamma$). |
| $\Gamma \vdash t_1 = t_2 : T$ | Terms $t_1$ and $t_2$ are both of type $T$ and are equal (under assumptions $\Gamma$). |

:::

Some textbooks use a triple equal sign $\equiv$ to stress that this is [judgmental equality](wikipedia://en/15014170) and thus an [extrinsic](https://en.wikipedia.org/wiki/Intrinsic_and_extrinsic_properties) notion of equality.[^o26] The judgments enforce that every term has a type. The type will restrict which rules can be applied to a term.

### Rules of inference {#Rules_of_inference}

A type theory's [inference rules](wikipedia://en/252311) say what judgments can be made, based on the existence of other judgments. Rules are expressed as a [Gentzen](wikipedia://en/252329)-style [deduction](wikipedia://en/396102) using a horizontal line, with the required input judgments above the line and the resulting judgment below the line.[^o28] For example, the following inference rule states a [substitution](wikipedia://en/5438948) rule for judgmental equality.

$$\begin{array}{c} \Gamma\vdash t:T_1 \qquad \Delta\vdash T_1 = T_2 \\ \hline \Gamma,\Delta\vdash t:T_2 \end{array}$$

The rules are syntactic and work by [rewriting](wikipedia://en/415847). The [metavariables](wikipedia://en/29557417) $\Gamma$, $\Delta$, $t$, $T_1$, and $T_2$ may actually consist of complex terms and types that contain many function applications, not just single symbols.

To generate a particular judgment in type theory, there must be a rule to generate it, as well as rules to generate all of that rule's required inputs, and so on. The applied rules form a [proof tree](wikipedia://en/51072#Proofs_and_type_theory), where the top-most rules need no assumptions. One example of a rule that does not require any inputs is one that states the type of a constant term. For example, to assert that there is a term $0$ of type $\mathsf{nat}$, one would write the following.

$$\begin{array}{c} \hline \vdash 0 : \mathsf{nat} \\ \end{array}$$

#### Type inhabitation {#Type_inhabitation}

Generally, the desired conclusion of a proof in type theory is one of [type inhabitation](https://en.wikipedia.org/wiki/Type_inhabitation).[^o30] The decision problem of type inhabitation (abbreviated by $\exists t.\Gamma \vdash t : \tau?$) is:

Given a context $\Gamma$ and a type $\tau$, decide whether there exists a term $t$ that can be assigned the type $\tau$ in the type environment $\Gamma$.

[Girard's paradox](wikipedia://en/49481270#Girard's_paradox) shows that type inhabitation is strongly related to the [consistency](wikipedia://en/75802) of a type system with Curry–Howard correspondence. To be sound, such a system must have uninhabited types.

A type theory usually has several rules, including ones to:

- create a judgment (known as a *context* in this case)
- add an assumption to the context (context *weakening*)
- [rearrange the assumptions](wikipedia://en/697666)
- use an assumption to create a variable
- define [reflexivity](wikipedia://en/200458), [symmetry](wikipedia://en/200459) and [transitivity](wikipedia://en/200463) for judgmental equality
- define substitution for application of lambda terms
- list all the interactions of equality, such as substitution
- define a hierarchy of type universes
- assert the existence of new types

Also, for each "by rule" type, there are 4 different kinds of rules:

- "type formation" rules say how to create the type
- "term introduction" rules define the canonical terms and constructor functions, like "pair" and "S".
- "term elimination" rules define the other functions like "first", "second", and "R".
- "computation" rules specify how computation is performed with the type-specific functions.

For examples of rules, an interested reader may follow Appendix A.2 of the *Homotopy Type Theory* book,[^o26] or read Martin-Löf's Intuitionistic Type Theory.[^o31]

## Connections to foundations {#Connections_to_foundations}

The logical framework of a type theory bears a resemblance to [intuitionistic](wikipedia://en/169262), or constructive, logic. Formally, type theory is often cited as an implementation of the [Brouwer–Heyting–Kolmogorov interpretation](wikipedia://en/1925846) of intuitionistic logic.[^o31] Additionally, connections can be made to [category theory](wikipedia://en/5869) and [computer programs](https://en.wikipedia.org/wiki/Computer_programming).

### Intuitionistic logic {#Intuitionistic_logic}

When used as a foundation, certain types are interpreted to be [propositions](https://en.wikipedia.org/wiki/Propositions) (statements that can be proven), and terms inhabiting the type are interpreted to be proofs of that proposition. When some types are interpreted as propositions, there is a set of common types that can be used to connect them to make a [Boolean algebra](wikipedia://en/3959) out of types. However, the logic is not [classical logic](wikipedia://en/55868) but [intuitionistic logic](wikipedia://en/169262), which is to say it does not have the [law of excluded middle](wikipedia://en/17637) nor [double negation elimination](https://en.wikipedia.org/wiki/Double_negation_elimination).

Under this intuitionistic interpretation, there are common types that act as the logical operators:

::: {#o34 .table cue=table}

| Logic Name | Logic Notation | Type Notation | Type Name |
|---|---|---|---|
| True | $\top$ | $\top$ | Unit Type |
| False | $\bot$ | $\bot$ | Empty Type |
| [Implication](wikipedia://en/658808) | $A \to B$ | $A \to B$ | Function |
| [Not](https://en.wikipedia.org/wiki/Not_%28logic%29) | $\neg A$ | $A \to \bot$ | Function to Empty Type |
| [And](https://en.wikipedia.org/wiki/And_%28logic%29) | $A \land B$ | $A \times B$ | Product Type |
| [Or](https://en.wikipedia.org/wiki/Or_%28logic%29) | $A \lor B$ | $A + B$ | Sum Type |
| [For All](wikipedia://en/76174) | $\forall a \in A, P(a)$ | $\Pi a:A.P(a)$ | Dependent Product |
| [Exists](wikipedia://en/91420) | $\exists a \in A, P(a)$ | $\Sigma a: A.P(a)$ | Dependent Sum |

:::

Because the law of excluded middle does not hold, there is no term of type $\Pi A.A+ (A\to\bot)$. Likewise, double negation does not hold, so there is no term of type $\Pi A.((A\to\bot)\to\bot)\to A$.

It is possible to include the law of excluded middle and double negation into a type theory, by rule or assumption. However, terms may not compute down to canonical terms and it will interfere with the ability to determine if two terms are judgementally equal to each other.

#### Constructive mathematics {#Constructive_mathematics}

Per Martin-Löf proposed his intuitionistic type theory as a foundation for [constructive mathematics](https://en.wikipedia.org/wiki/Constructive_mathematics).[^o22] Constructive mathematics requires when proving "there exists an $x$ with property $P(x)$", one must construct a particular $x$ and a proof that it has property $P$. In type theory, existence is accomplished using the dependent product type, and its proof requires a term of that type.

An example of a non-constructive proof is [proof by contradiction](https://en.wikipedia.org/wiki/Proof_by_contradiction). The first step is assuming that $x$ does not exist and refuting it by contradiction. The conclusion from that step is "it is not the case that $x$ does not exist". The last step is, by double negation, concluding that $x$ exists. Constructive mathematics does not allow the last step of removing the double negation to conclude that $x$ exists.[^o42]

Most of the type theories proposed as foundations are constructive, and this includes most of the ones used by proof assistants. It is possible to add non-constructive features to a type theory, by rule or assumption. These include operators on continuations such as [call with current continuation](https://en.wikipedia.org/wiki/Call/cc#Relation_to_non-constructive_logic). However, these operators tend to break desirable properties such as [canonicity](https://en.wikipedia.org/wiki/Canonicity_%28type_theory%29) and [parametricity](wikipedia://en/9315395).

### Curry–Howard correspondence {#Curry–Howard_correspondence}

The [Curry–Howard correspondence](wikipedia://en/254299) is the observed similarity between logics and programming languages. The implication in logic, "A $\to$ B" resembles a function from type "A" to type "B". For a variety of logics, the rules are similar to expressions in a programming language's types. The similarity goes farther, as applications of the rules resemble programs in the programming languages. Thus, the correspondence is often summarized as "proofs as programs".

The opposition of terms and types can also be viewed as one of *implementation* and *specification*. By [program synthesis](https://en.wikipedia.org/wiki/Program_synthesis), (the computational counterpart of) type inhabitation can be used to construct (all or parts of) programs from the specification given in the form of type information.[^o44]

#### Type inference {#Type_inference}

Many programs that work with type theory (e.g., interactive theorem provers) also do type inferencing. It lets them select the rules that the user intends, with fewer actions by the user.

### Research areas {#Research_areas}

#### Category theory {#Category_theory}

Although the initial motivation for [category theory](wikipedia://en/5869) was far removed from foundationalism, the two fields turned out to have deep connections. As [John Lane Bell](wikipedia://en/25759134) writes: "In fact categories can *themselves* be viewed as type theories of a certain kind; this fact alone indicates that type theory is much more closely related to category theory than it is to set theory." In brief, a category can be viewed as a type theory by regarding its objects as types (or *sorts* [^o48]), i.e. "Roughly speaking, a category may be thought of as a type theory shorn of its syntax." A number of significant results follow in this way:[^o49]

- [cartesian closed categories](wikipedia://en/237037) correspond to the typed λ-calculus ([Lambek](https://en.wikipedia.org/wiki/Lambek), 1970);
- [C-monoids](https://en.wikipedia.org/wiki/C-monoid) (categories with products and exponentials and one non-terminal object) correspond to the untyped λ-calculus (observed independently by Lambek and [Dana Scott](wikipedia://en/161875) around 1980);
- [locally cartesian closed categories](https://en.wikipedia.org/wiki/Locally_cartesian_closed_category) correspond to [Martin-Löf type theories](https://en.wikipedia.org/wiki/Martin-Löf_type_theory) (Seely, 1984).

The interplay, known as [categorical logic](wikipedia://en/1063799), has been a subject of active research since then; see the monograph of Jacobs (1999) for instance.

#### Homotopy type theory {#Homotopy_type_theory}

[Homotopy type theory](wikipedia://en/33974223) attempts to combine type theory and category theory. It focuses on equalities, especially equalities between types. [Homotopy type theory](wikipedia://en/33974223) differs from [intuitionistic type theory](wikipedia://en/345023) mostly by its handling of the equality type. In 2016, [cubical type theory](wikipedia://en/83028216) was proposed, which is a homotopy type theory with normalization.[^o51][^o85]

## Definitions {#Definitions}

### Terms and types {#Terms_and_types}

#### Atomic terms {#Atomic_terms}

The most basic types are called atoms, and a term whose type is an atom is known as an atomic term. Common atomic terms included in type theories are [natural numbers](wikipedia://en/21474), often notated with the type $\mathsf{nat}$, [Boolean logic](https://en.wikipedia.org/wiki/Boolean_Logic) values ($\texttt{true}$ and $\texttt{false}$), notated with the type $\mathsf{bool}$, and [formal variables](wikipedia://en/3728109), whose type may vary.[^o30] For example, the following may be atomic terms.

- $$42:\mathsf{nat}$$
- $$\texttt{true}:\mathsf{bool}$$
- $$x:\mathsf{nat}$$
- $$y:\mathsf{bool}$$

#### Function terms {#Function_terms}

In addition to atomic terms, most modern type theories also allow for [functions](wikipedia://en/185427). Function types introduce an arrow symbol, and are [defined inductively](wikipedia://en/1047605): If $\sigma$ and $\tau$ are types, then the notation $\sigma\to\tau$ is the type of a function which takes a [parameter](wikipedia://en/25065) of type $\sigma$ and returns a term of type $\tau$. Types of this form are known as [*simple* types](wikipedia://en/1986011).[^o30]

Some terms may be declared directly as having a simple type, such as the following term, $\mathrm{add}$, which takes in two natural numbers in sequence and returns one natural number.

$$\mathrm{add}:\mathsf{nat}\to (\mathsf{nat}\to\mathsf{nat})$$

Strictly speaking, a simple type only allows for one input and one output, so a more faithful reading of the above type is that $\mathrm{add}$ is a function which takes in a natural number and returns a function of the form $\mathsf{nat}\to\mathsf{nat}$. The parentheses clarify that $\mathrm{add}$ does not have the type $(\mathsf{nat}\to \mathsf{nat})\to\mathsf{nat}$, which would be a function which takes in a function of natural numbers and returns a natural number. The convention is that the arrow is [right associative](https://en.wikipedia.org/wiki/Operator_associativity), so the parentheses may be dropped from $\mathrm{add}$'s type.[^o30]

#### Lambda terms {#Lambda_terms}

New function terms may be constructed using [lambda expressions](wikipedia://en/18203#Definition), and are called lambda terms. These terms are also defined inductively: a lambda term has the form $(\lambda v .t)$, where $v$ is a formal variable and $t$ is a term, and its type is notated $\sigma\to\tau$, where $\sigma$ is the type of $v$, and $\tau$ is the type of $t$.[^o30] The following lambda term represents a function which doubles an input natural number.

$$(\lambda x.\mathrm{add}\,x\,x): \mathsf{nat}\to\mathsf{nat}$$

The variable is $x$ and (implicit from the lambda term's type) must have type $\mathsf{nat}$. The term $\mathrm{add}\,x\,x$ has type $\mathsf{nat}$, which is seen by applying the function application inference rule twice. Thus, the lambda term has type $\mathsf{nat}\to\mathsf{nat}$, which means it is a function taking a natural number as an [argument](wikipedia://en/32842052) and returning a natural number.

A lambda term is an [anonymous function](https://en.wikipedia.org/wiki/Anonymous_function) because it lacks a name. The concept of anonymous functions appears in many programming languages.

### Inference Rules {#Inference_Rules}

#### Function application {#Function_application}

The power of type theories is in specifying how terms may be combined by way of [inference rules](wikipedia://en/252311).[^o4] Type theories which have functions also have the inference rule of [function application](wikipedia://en/20576545): if $t$ is a term of type $\sigma\to\tau$, and $s$ is a term of type $\sigma$, then the application of $t$ to $s$, often written $(t\,s)$, has type $\tau$. For example, if one knows the type notations $0:\textsf{nat}$, $1:\textsf{nat}$, and $2:\textsf{nat}$, then the following type notations can be [deduced](https://en.wikipedia.org/wiki/Deduction_system) from function application.[^o30]

- $$(\mathrm{add}\,1): \textsf{nat}\to\textsf{nat}$$
- $$((\mathrm{add}\,2)\,0): \textsf{nat}$$
- $$((\mathrm{add}\,1)((\mathrm{add}\,2)\,0)): \textsf{nat}$$

Parentheses indicate the [order of operations](wikipedia://en/212980); however, by convention, function application is [left associative](https://en.wikipedia.org/wiki/Left_associative), so parentheses can be dropped where appropriate.[^o30] In the case of the three examples above, all parentheses could be omitted from the first two, and the third may simplified to $\mathrm{add}\,1\, (\mathrm{add}\,2\,0): \textsf{nat}$.

#### Reductions {#Reductions}

Type theories that allow for lambda terms also include inference rules known as $\beta$-reduction and $\eta$-reduction. They generalize the notion of function application to lambda terms. Symbolically, they are written

- $(\lambda v. t)\,s\rightarrow t[v \colon= s]$ ($\beta$-reduction).
- $(\lambda v. t\, v)\rightarrow t$, if $v$ is not a [free variable](wikipedia://en/147460) in $t$ ($\eta$-reduction).

The first reduction describes how to evaluate a lambda term: if a lambda expression $(\lambda v .t)$ is applied to a term $s$, one replaces every occurrence of $v$ in $t$ with $s$. The second reduction makes explicit the relationship between lambda expressions and function types: if $(\lambda v. t\, v)$ is a lambda term, then it must be that $t$ is a function term because it is being applied to $v$. Therefore, the lambda expression is equivalent to just $t$, as both take in one argument and apply $t$ to it.[^o4]

For example, the following term may be $\beta$-reduced.

$$(\lambda x.\mathrm{add}\,x\,x)\,2\rightarrow \mathrm{add}\,2\,2$$

In type theories that also establish notions of [equality](wikipedia://en/90446) for types and terms, there are corresponding inference rules of $\beta$-equality and $\eta$-equality.[^o30]

### Common terms and types {#Common_terms_and_types}

#### Empty type {#Empty_type}

The [empty type](https://en.wikipedia.org/wiki/Empty_type) has no terms. The type is usually written $\bot$ or $\mathbb 0$. One use for the empty type is proofs of [type inhabitation](https://en.wikipedia.org/wiki/Type_inhabitation). If for a type $a$, it is consistent to derive a function of type $a\to\bot$, then $a$ is *uninhabited*, which is to say it has no terms.

#### Unit type {#Unit_type}

The [unit type](wikipedia://en/3646268) has exactly 1 canonical term. The type is written $\top$ or $\mathbb 1$ and the single canonical term is written $\ast$. The unit type is also used in proofs of type inhabitation. If for a type $a$, it is consistent to derive a function of type $\top\to a$, then $a$ is *inhabited*, which is to say it must have one or more terms.

#### Boolean type {#Boolean_type}

The Boolean type has exactly 2 canonical terms. The type is usually written $\textsf{bool}$ or $\mathbb B$ or $\mathbb 2$. The canonical terms are usually $\mathrm{true}$ and $\mathrm{false}$.

#### Natural numbers {#Natural_numbers}

Natural numbers are usually implemented in the style of [Peano Arithmetic](https://en.wikipedia.org/wiki/Peano_arithmetic). There is a canonical term $0:\mathsf{nat}$ for zero. Canonical values larger than zero use iterated applications of a [successor function](wikipedia://en/325637) $\mathrm{S}:\mathsf{nat}\to\mathsf{nat}$.

### Type constructors {#Type_constructors}

Some type theories allow for types of complex terms, such as functions or lists, to depend on the types of its arguments; these are called [type constructors](wikipedia://en/20627460). For example, a type theory could have the dependent type $\mathsf{list}\,a$, which should correspond to [lists](https://en.wikipedia.org/wiki/List_%28abstract_data_type%29) of terms, where each term must have type $a$. In this case, $\mathsf{list}$ has the kind $U\to U$, where $U$ denotes the [universe](wikipedia://en/296838) of all types in the theory.

#### Product type {#Product_type}

The product type, $\times$, depends on two types, and its terms are commonly written as [ordered pairs](wikipedia://en/22362) $(s,t)$. The pair $(s,t)$ has the product type $\sigma\times\tau$, where $\sigma$ is the type of $s$ and $\tau$ is the type of $t$. Each product type is then usually defined with eliminator functions $\mathrm{first}:\sigma\times\tau\to\sigma$ and $\mathrm{second}:\sigma\times\tau\to\tau$.

- $\mathrm{first}\,(s,t)$ returns $s$, and
- $\mathrm{second}\,(s,t)$ returns $t$.

Besides ordered pairs, this type is used for the concepts of [logical conjunction](wikipedia://en/18152) and [intersection](wikipedia://en/41780044).

#### Sum type {#Sum_type}

The sum type is written as either $+$ or $\sqcup$. In programming languages, sum types may be referred to as [tagged unions](wikipedia://en/453395). Each type $\sigma\sqcup\tau$ is usually defined with [constructors](https://en.wikipedia.org/wiki/Constructor_%28programming%29) $\mathrm{left}:\sigma\to(\sigma\sqcup\tau)$ and $\mathrm{right}:\tau\to(\sigma\sqcup\tau)$, which are [injective](wikipedia://en/45196), and an eliminator function $\mathrm{match}:(\sigma\to\rho)\to(\tau\to\rho)\to(\sigma\sqcup\tau)\to\rho$ such that

- $\mathrm{match}\,f\,g\,(\mathrm{left}\,x)$ returns $f\,x$, and
- $\mathrm{match}\,f\,g\,(\mathrm{right}\,y)$ returns $g\,y$.

The sum type is used for the concepts of [logical disjunction](https://en.wikipedia.org/wiki/Logical_or) and [union](wikipedia://en/47949).

### Polymorphic types {#Polymorphic_types}

Some theories also allow terms to have their definitions depend on types. For instance, an identity function of any type could be written as $\lambda x.x:\forall\alpha. \alpha\to\alpha$. The function is said to be polymorphic in $\alpha$, or generic in $x$.

As another example, consider a function $\mathrm{append}$, which takes in a $\mathsf{list}\,a$ and a term of type $a$, and returns the list with the element at the end. The type annotation of such a function would be $\mathrm{append}:\forall\,a.\mathsf{list}\,a\to a\to\mathsf{list}\,a$, which can be read as "for any type $a$, pass in a $\mathsf{list}\,a$ and an $a$, and return a $\mathsf{list}\,a$". Here $\mathrm{append}$ is polymorphic in $a$.

#### Products and sums {#Products_and_sums}

With polymorphism, the eliminator functions can be defined generically for *all* product types as $\mathrm{first}:\forall\,\sigma\,\tau.\sigma\times\tau\to\sigma$ and $\mathrm{second}:\forall\,\sigma\,\tau.\sigma\times\tau\to\tau$.

- $\mathrm{first}\,(s,t)$ returns $s$, and
- $\mathrm{second}\,(s,t)$ returns $t$.

Likewise, the sum type constructors can be defined for all valid types of sum members as $\mathrm{left}:\forall\,\sigma\,\tau.\sigma\to(\sigma\sqcup\tau)$ and $\mathrm{right}:\forall\,\sigma\,\tau.\tau\to(\sigma\sqcup\tau)$, which are [injective](wikipedia://en/45196), and the eliminator function can be given as $\mathrm{match}:\forall\,\sigma\,\tau\,\rho.(\sigma\to\rho)\to(\tau\to\rho)\to(\sigma\sqcup\tau)\to\rho$ such that

- $\mathrm{match}\,f\,g\,(\mathrm{left}\,x)$ returns $f\,x$, and
- $\mathrm{match}\,f\,g\,(\mathrm{right}\,y)$ returns $g\,y$.

### Dependent typing {#Dependent_typing}

Some theories also permit types to be dependent on terms instead of types. For example, a theory could have the type $\mathsf{vector}\,n$, where $n$ is a term of type $\mathsf{nat}$ encoding the length of the [vector](wikipedia://en/32370). This allows for greater specificity and [type safety](wikipedia://en/602650): functions with vector length restrictions or length matching requirements, such as the [dot product](wikipedia://en/157093), can encode this requirement as part of the type.[^o72]

There are foundational issues that can arise from dependent types if a theory is not careful about what dependences are allowed, such as [Girard's Paradox](https://en.wikipedia.org/wiki/Girard's_paradox). The logician [Henk Barendegt](wikipedia://en/1651213) introduced the [lambda cube](wikipedia://en/901593) as a framework for studying various restrictions and levels of dependent typing.[^o73]

#### Dependent products and sums {#Dependent_products_and_sums}

Two common [type dependences](wikipedia://en/1949487), dependent product and dependent sum types, allow for the theory to encode [BHK intuitionistic logic](https://en.wikipedia.org/wiki/BHK_interpretation) by acting as equivalents to [universal and existential quantification](https://en.wikipedia.org/wiki/Quantification_%28logic%29); this is formalized by [Curry–Howard correspondence](wikipedia://en/254299).[^o72] As they also connect to [products](wikipedia://en/24104095) and [sums](wikipedia://en/188946) in [set theory](wikipedia://en/27553), they are often written with the symbols $\Pi$ and $\Sigma$, respectively.

Sum types are seen in [dependent pairs](wikipedia://en/1949487), where the second type depends on the value of the first term. This arises naturally in computer science where functions may return different types of outputs based on the input. For example, the Boolean type is usually defined with an eliminator function $\mathrm{if}$, which takes three arguments and behaves as follows.

- $\mathrm{if}\,\texttt{true}\,x\,y$ returns $x$, and
- $\mathrm{if}\,\texttt{false}\,x\,y$ returns $y$.

Ordinary definitions of $\mathrm{if}$ require $x$ and $y$ to have the same type. If the type theory allows for dependent types, then it is possible to define a dependent type $x:\mathsf{bool}\,\vdash\,\mathrm{TF}\,x:U\to U\to U$ such that

- $\mathrm{TF}\,\texttt{true}\,\sigma\,\tau$ returns $\sigma$, and
- $\mathrm{TF}\,\texttt{false}\,\sigma\,\tau$ returns $\tau$.

The type of $\mathrm{if}$ may then be written as $\forall\,\sigma\,\tau.\Pi_{x:\mathsf{bool} }.\sigma\to\tau\to\mathrm{TF}\,x\,\sigma\,\tau$.

::: {#o76 .statement cue=named-heading name="Identity type"}

#### Identity type {#Identity_type}

Following the notion of Curry–Howard Correspondence, the [identity type](wikipedia://en/44638758) is a type introduced to mirror [propositional equivalence](wikipedia://en/18154), as opposed to the [judgmental (syntactic) equivalence](wikipedia://en/15014170) that type theory already provides.

An identity type requires two terms of the same type and is written with the symbol $=$. For example, if $x+1$ and $1+x$ are terms, then $x+1=1+x$ is a possible type. Canonical terms are created with a reflexivity function, $\mathrm{refl}$. For a term $t$, the call $\mathrm{refl}\,t$ returns the canonical term inhabiting the type $t=t$.

The complexities of equality in type theory make it an active research topic; [homotopy type theory](wikipedia://en/33974223) is a notable area of research that mainly deals with equality in type theory.

:::

#### Inductive types {#Inductive_types}

Inductive types are a general template for creating a large variety of types. In fact, all the types described above and more can be defined using the rules of inductive types. Two methods of generating inductive types are [induction-recursion](wikipedia://en/38365576) and [induction-induction](wikipedia://en/57750049). A method that only uses lambda terms is [Scott encoding](https://en.wikipedia.org/wiki/Mogensen–Scott_encoding).

Some [proof assistants](wikipedia://en/1258607), such as [Rocq](https://en.wikipedia.org/wiki/Rocq_%28software%29) (previously known as *Coq*) and [Lean](wikipedia://en/62889984), are based on the calculus for inductive constructions, which is a [calculus of constructions](wikipedia://en/613557) with inductive types.

:::

## Differences from set theory {#Differences_from_set_theory}

The most commonly accepted [foundation for mathematics](wikipedia://en/169358) is [first-order logic](wikipedia://en/10983) with the [language](wikipedia://en/10939) and [axioms](wikipedia://en/928) of [Zermelo–Fraenkel set theory](wikipedia://en/152214) with the [axiom of choice](wikipedia://en/840), abbreviated ZFC. Type theories having sufficient [expressibility](https://en.wikipedia.org/wiki/Expressive_power_%28computer_science%29) may also act as a foundation of mathematics. There are a number of differences between these two approaches.

- Set theory has both [rules](wikipedia://en/252311) and [axioms](wikipedia://en/928), while type theories only have rules. Type theories, in general, do not have axioms and are defined by their rules of inference.[^o26]
- Classical set theory and logic have the [law of excluded middle](wikipedia://en/17637). When a type theory encodes the concepts of "and" and "or" as types, it leads to [intuitionistic logic](wikipedia://en/169262), and does not necessarily have the law of excluded middle.[^o31]
- In set theory, an element is not restricted to one set. The element can appear in subsets and unions with other sets. In type theory, terms (generally) belong to only one type. Where a subset would be used, type theory can use a [predicate function](https://en.wikipedia.org/wiki/Predicate_%28mathematical_logic%29) or use a dependently-typed product type, where each element $x$ is paired with a proof that the subset's property holds for $x$. Where a union would be used, type theory uses the sum type, which contains new canonical terms.
- Type theory has a built-in notion of computation. Thus, "1+1" and "2" are different terms in type theory, but they compute to the same value. Moreover, functions are defined computationally as lambda terms. In set theory, "1+1=2" means that "1+1" is just another way to refer the value "2". Type theory's computation does require a complicated concept of equality.
- Set theory [encodes numbers as sets](wikipedia://en/428484). Type theory can encode numbers as functions using [Church encoding](wikipedia://en/2989409), or more naturally as [inductive types](wikipedia://en/345023#Inductive_types), and the construction closely resembles [Peano's axioms](wikipedia://en/25005).
- In type theory, proofs have types whereas in set theory, proofs are part of the underlying first-order logic.[^o26]

Proponents of type theory will also point out its connection to constructive mathematics through the [BHK interpretation](https://en.wikipedia.org/wiki/BHK_interpretation), its connection to logic by the [Curry–Howard isomorphism](https://en.wikipedia.org/wiki/Curry–Howard_isomorphism), and its connections to [category theory](wikipedia://en/5869).

### Properties of type theories {#Properties_of_type_theories}

Terms usually belong to a single type. However, there are type theories that define "subtyping".

Computation takes place by repeated application of rules. Many types of theories are [strongly normalizing](https://en.wikipedia.org/wiki/Strongly_normalizing), which means that any order of applying the rules will always end in the same result. However, some are not. In a normalizing type theory, the one-directional computation rules are called "reduction rules", and applying the rules "reduces" the term. If a rule is not one-directional, it is called a "conversion rule".

Some combinations of types are equivalent to other combinations of types. When functions are considered "exponentiation", the combinations of types can be written similarly to algebraic identities.[^o80] Thus, ${\mathbb 0} + A \cong A$, ${\mathbb 1} \times A \cong A$, ${\mathbb 1} + {\mathbb 1} \cong {\mathbb 2}$, $A^{B+C} \cong A^B \times A^C$, $A^{B\times C} \cong (A^B)^C$.

::: {#o82 .statement kind=statement/axiom cue=named-heading name="Axioms"}

### Axioms {#Axioms}

Most type theories do not have [axioms](wikipedia://en/928). This is because a type theory is defined by its rules of inference. This is a source of confusion for people familiar with Set Theory, where a theory is defined by both the rules of inference for a logic (such as [first-order logic](wikipedia://en/10983)) and axioms about sets.

Sometimes, a type theory will add a few axioms. An axiom is a judgment that is accepted without a derivation using the rules of inference. They are often added to ensure properties that cannot be added cleanly through the rules.

Axioms can cause problems if they introduce terms without a way to compute on those terms. That is, axioms can interfere with the [normalizing property](wikipedia://en/5085531) of the type theory.[^o83]

Some commonly encountered axioms are:

- "Axiom K" ensures "uniqueness of identity proofs". That is, that every term of an identity type is equal to reflexivity.[^o84]
- "Univalence axiom" holds that equivalence of types is equality of types. The research into this property led to [cubical type theory](wikipedia://en/83028216), where the property holds without needing an axiom.[^o85]
- "Law of excluded middle" is often added to satisfy users who want [classical logic](wikipedia://en/55868), instead of intuitionistic logic.

The [axiom of choice](wikipedia://en/840) does not need to be added to type theory, because in most type theories it can be derived from the rules of inference. This is because of the [constructive](https://en.wikipedia.org/wiki/Constructive_mathematics) nature of type theory, where proving that a value exists requires a method to compute the value. The axiom of choice is less powerful in type theory than most set theories, because type theory's functions must be computable and, being syntax-driven, the number of terms in a type must be countable. (See *Axiom of choice#In constructive mathematics*.)

:::
