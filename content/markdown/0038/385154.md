# Serpent (cipher)

::: {#o2 .subject cue=lead name="Serpent"}

**Serpent** is a [symmetric key](https://en.wikipedia.org/wiki/Symmetric_key) [block cipher](wikipedia://en/4594) that was a finalist in the [Advanced Encryption Standard (AES) contest](wikipedia://en/99431), in which it ranked second to [Rijndael](https://en.wikipedia.org/wiki/Rijndael).[^o3] Serpent was designed by [Ross Anderson](wikipedia://en/61571), [Eli Biham](wikipedia://en/348920), and [Lars Knudsen](https://en.wikipedia.org/wiki/Lars_Ramkilde_Knudsen).[^o4]

:::

Like other [AES](wikipedia://en/1260) submissions, Serpent has a [block size](wikipedia://en/294065) of 128 bits and supports a [key size](wikipedia://en/5749) of 128, 192, or 256 bits.[^o5] The [cipher](wikipedia://en/5244) is a 32-round [substitution–permutation network](https://en.wikipedia.org/wiki/Substitution–permutation_network) operating on a block of four 32-bit [words](https://en.wikipedia.org/wiki/Word_%28computer_architecture%29). Each round applies one of eight 4-bit to 4-bit [S-boxes](wikipedia://en/240991) 32 times in parallel. Serpent was designed so that all operations can be executed in [parallel](https://en.wikipedia.org/wiki/Parallel_computing), using 32 [bit slices](https://en.wikipedia.org/wiki/Bit_slice). This maximizes parallelism but also allows use of the extensive [cryptanalysis](wikipedia://en/5715) work performed on [DES](wikipedia://en/7978).

Serpent took a conservative approach to security, opting for a large security margin: the designers deemed 16 rounds to be sufficient against known types of attack but specified 32 rounds as insurance against future discoveries in cryptanalysis.[^o6] The official NIST report on AES competition classified Serpent as having a high security margin like [MARS](https://en.wikipedia.org/wiki/MARS_%28cryptography%29) and [Twofish](wikipedia://en/26508356) and in contrast to the adequate security margin of RC6 and Rijndael (currently AES).[^o3] In final voting, Serpent had the fewest negative votes among the finalists but ranked in second place overall because Rijndael had substantially more positive votes, the deciding factor being that Rijndael allowed for a far more efficient software implementation.

The Serpent cipher algorithm is in the [public domain](https://en.wikipedia.org/wiki/Public_domain) and has not been [patented](https://en.wikipedia.org/wiki/Patented).[^o7] The reference code is [public domain software](https://en.wikipedia.org/wiki/Public_domain_software), and the optimized code is licensed under the [GPL](https://en.wikipedia.org/wiki/GPL).[^o8] There are no restrictions or encumbrances regarding its use. As a result, anyone is free to incorporate Serpent in their software (or in hardware implementations) without paying license fees.

## Key schedule {#Key_schedule}

The Serpent key schedule consists of 3 main stages. In the first stage the key is initialized by adding padding if necessary. This is done in order to make short keys map to long keys of 256-bits, one "1" bit is appended to the end of the short key followed by "0" bits until the short key is mapped to a long key length.[^o5]

In the next phase, the "prekeys" are derived using the previously initialized key. 32-bit key parts XORed, the *FRAC* which is the fraction of the [Golden ratio](wikipedia://en/12386) and the round index is XORed with the key parts, the result of the [XOR](wikipedia://en/105979) operation is rotated to left by 11. The *FRAC* and round index were added to achieve an even distribution of the key's bits during the rounds.[^o5]

Finally the "subkeys" are derived from the previously generated "prekeys". This results in a total of 33 128-bit "subkeys".[^o5]

At the end the round key or "subkey" are placed in the "initial permutation IP" to place the key bits in the correct column.[^o5]

### Key schedule in C {#Key_schedule_in_C}

```c
#define FRAC 0x9e3779b9     //  fractional part of the golden ratio
#define ROTL(A, n) ((A) << n | (A) >> 32-n)

uint32_t key[8];        // key provided by user
uint32_t subkey[33][4]; // roundkeys
const uint8_t S[8][16] = {}; // S-boxes

/* key schedule: get prekeys */
void get_pre(uint32_t w[4*33], const uint32_t k[8]) {
    uint32_t x[4*33+8];
    for (int i = 0; i < 8; i++)
        x[i] = k[i];
    for (int i = 8; i < 140; i++) {
        x[i] = ROTL(x[i-8] ^ x[i-5] ^ x[i-3] ^ x[i-1] ^ FRAC ^ (i-8), 11);
        w[i-8] = x[i];
    }
}

/* key schedule: get subkeys */
void get_sk(const uint32_t w[4*33], uint32_t (*sk)[4]) {

	uint8_t i, p, j, s, k;
	
	for (i = 0; i < 33; i++) {
		p = 32 + 3 - i;
        for (j = 0; j < 4; j++)
            sk[i][j] = 0;
		for (k = 0; k < 32; k++) {
			s = S[p % 8][((w[4 * i + 0] >> k) & 0x1) << 0 |
						 ((w[4 * i + 1] >> k) & 0x1) << 1 |
						 ((w[4 * i + 2] >> k) & 0x1) << 2 |
						 ((w[4 * i + 3] >> k) & 0x1) << 3 ];
			for (j = 0; j < 4; j++) {
				sk[i][j] |= ((s >> j) & 0x1) << k;
			}
		}
	}
}

void key_schedule() {
    uint32_t w[4*33];
    get_pre(w, key);
    get_sk(w, subkey);
}
```

## S-boxes {#S-boxes}

The Serpent s-boxes are 4-bit [permutations](wikipedia://en/44027), and subject to the following properties:

- a 1-bit input difference will never lead to a 1-bit output difference, a differential characteristic has a probability of 1:4 or less.[^o22]
- linear characteristics have a probability between 1:2 and 1:4, linear relationship between input and output bits has a probability between 1:2 and 1:8.[^o22]
- the nonlinear order of the output bits as function of the input bits is 3. However there have been output bits found which in function of the input bits have an order of only 2.[^o22]

The Serpent s-boxes have been constructed based on the 32 rows of the [DES](wikipedia://en/7978) s-boxes. These were transformed by swapping entries, resulting arrays with desired properties were stored as the Serpent s-boxes. This process was repeated until a total of 8 s-boxes were found. The following key was used in this process: `"sboxesforserpent"`.[^o5]

## Permutations and transformations {#Permutations_and_transformations}

### Initial permutation (IP) {#Initial_permutation_(IP)}

The initial permutation works on 128 bits at a time moving bits around.

```cpp
for i in 0 .. 127
    swap( bit(i), bit((32 * i) % 127) )
```

### Final permutation (FP) {#Final_permutation_(FP)}

The final permutation works on 128 bits at a time moving bits around.

```cpp
for i in 0 .. 127
    swap( bit(i), bit((4 * i) % 127) )
```

### Linear transformation (LT) {#Linear_transformation_(LT)}

Consists of XOR, bit shift left and bit rotate left operations. These operations are performed on 4 32-bit words.

```cpp
// The input is the result of key mixing and substitution.
for (short i = 0; i < 4; i++) {
    X[i] = S[i][B[i] ^ K[i]];
}

// Linear transformation.
X[0] = ROTL(X[0], 13);
X[2] = ROTL(X[2], 3 );
X[1] = X[1] ^ X[0] ^ X[2];
X[3] = X[3] ^ X[2] ^ (X[0] << 3);
X[1] = ROTL(X[1], 1 );
X[3] = ROTL(X[3], 7 );
X[0] = X[0] ^ X[1] ^ X[3];
X[2] = X[2] ^ X[3] ^ (X[1] << 7);
X[0] = ROTL(X[0], 5 );
X[2] = ROTL(X[2], 22);

// The output becomes the new state.
for (short i = 0; i < 4; i++) {
    B[i + 1] = X[i];
}
```

## Rijndael vs. Serpent {#Rijndael_vs._Serpent}

[Rijndael](https://en.wikipedia.org/wiki/Rijndael) is a substitution-linear transformation network with ten, twelve, or fourteen rounds, depending on the key size, and with key sizes of 128 bits, 192 bits, or 256 bits, independently specified. Serpent is a substitution–permutation network which has thirty-two rounds, plus an initial and a final permutation to simplify an optimized implementation. The round function in Rijndael consists of three parts: a nonlinear layer, a linear mixing layer, and a key-mixing XOR layer. The round function in Serpent consists of key-mixing XOR, thirty-two parallel applications of the same 4×4 S-box, and a linear transformation, except in the last round, wherein another key-mixing XOR replaces the linear transformation. The nonlinear layer in Rijndael uses an 8×8 S-box whereas Serpent uses eight different 4×4 S-boxes. The 32 rounds mean that Serpent has a higher security margin than Rijndael; however, Rijndael with 10 rounds is faster and easier to implement for small blocks.[^o17] Hence, Rijndael was selected as the winner in the AES competition.

## Serpent-0 vs. Serpent-1 {#Serpent-0_vs._Serpent-1}

The original Serpent, Serpent-0, was presented at the 5th workshop on [Fast Software Encryption](https://en.wikipedia.org/wiki/Fast_Software_Encryption), but a somewhat tweaked version, Serpent-1, was submitted to the AES competition. The AES submission paper discusses the changes, which include key-scheduling differences.

## Security {#Security}

The [XSL attack](wikipedia://en/660941), if effective, would weaken Serpent (though not as much as it would weaken [Rijndael](https://en.wikipedia.org/wiki/Rijndael), which became [AES](wikipedia://en/1260)). However, many [cryptanalysts](https://en.wikipedia.org/wiki/Cryptanalysts) believe that once implementation considerations are taken into account the XSL attack would be more expensive than a [brute force attack](https://en.wikipedia.org/wiki/Brute_force_attack).

In 2000, a paper by Kohno et al. presents a [meet-in-the-middle attack](wikipedia://en/423418) against 6 of 32 rounds of Serpent and an [amplified boomerang attack](https://en.wikipedia.org/wiki/Amplified_boomerang_attack) against 9 of 32 rounds in Serpent.[^o20]

A 2001 attack by [Eli Biham](wikipedia://en/348920), [Orr Dunkelman](https://en.wikipedia.org/wiki/Orr_Dunkelman) and Nathan Keller presents a [linear cryptanalysis](wikipedia://en/59469) attack that breaks 10 of 32 rounds of Serpent-128 with 2<sup>118</sup> known plaintexts and 2<sup>89</sup> time, and 11 rounds of Serpent-192/256 with 2<sup>118</sup> known plaintexts and 2<sup>187</sup> time.[^o21]

A 2009 paper has noticed that the nonlinear order of Serpent S-boxes were not 3 as was claimed by the designers. Specifically, four elements had order 2.[^o22]

A 2011 attack by Hongjun Wu, Huaxiong Wang and Phuong Ha Nguyen, also using linear cryptanalysis, breaks 11 rounds of Serpent-128 with 2<sup>116</sup> known plaintexts, 2<sup>\107.5</sup> time and 2<sup>104</sup> memory.[^o23]

The same paper also describes two attacks which break 12 rounds of Serpent-256. The first requires 2<sup>118</sup> known plaintexts, 2<sup>\228.8</sup> time and 2<sup>228</sup> memory. The other attack requires 2<sup>116</sup> known plaintexts and 2<sup>121</sup> memory but also requires 2<sup>\237.5</sup> time.
