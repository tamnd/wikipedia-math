# Maximum common induced subgraph

::: {#o1 .subject cue=lead name="Maximum common induced subgraph"}

*Image: MCIS of 2 graphs.svg.* The **maximum common induced subgraph** of the [cube](https://en.wikipedia.org/wiki/Cube_graph) and [octahedral](wikipedia://en/24656270) graphs, shown in blue

In [graph theory](wikipedia://en/12401) and [theoretical computer science](wikipedia://en/323392), a **maximum common induced subgraph** of two graphs *G* and *H* is a graph that is an [induced subgraph](wikipedia://en/1655188) of both *G* and *H*, and that has as many vertices as possible.

:::

Finding this graph is [NP-hard](https://en.wikipedia.org/wiki/NP-hard). In the associated [decision problem](wikipedia://en/8336), the input is two graphs *G* and *H* and a number *k*. The problem is to decide whether *G* and *H* have a common induced subgraph with at least *k* vertices. This problem is [NP-complete](https://en.wikipedia.org/wiki/NP-complete).[^o2] It is a generalization of the induced [subgraph isomorphism problem](wikipedia://en/450062), which arises when *k* equals the number of vertices in the smaller of *G* and *H*, so that this entire graph must appear as an induced subgraph of the other graph.

Based on [hardness of approximation](wikipedia://en/20677277) results for the [maximum independent set](https://en.wikipedia.org/wiki/Maximum_independent_set) problem, the maximum common induced subgraph problem is also hard to approximate.[^o3] This implies that, unless [P = NP](https://en.wikipedia.org/wiki/P_=_NP), there is no [approximation algorithm](wikipedia://en/563105) that, in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) on $n$-vertex graphs, always finds a solution within a factor of $n^{1-\epsilon}$ of optimal, for any $\epsilon > 0$.[^o4]

One possible solution for this problem is to build a [modular product graph](wikipedia://en/13518199) of *G* and *H*. In this graph, the largest [clique](wikipedia://en/524466) corresponds to a maximum common induced subgraph of *G* and *H*. Therefore, [algorithms for finding maximum cliques](wikipedia://en/249254) can be used to find the maximum common induced subgraph.[^o5] Moreover, a modified maximum-clique algorithm can be used to find a maximum common *connected* subgraph.[^o6]

The McSplit algorithm (along with its McSplit↓ variant) is a [forward checking](https://en.wikipedia.org/wiki/Look-ahead_%28backtracking%29) algorithm that does not use the clique encoding, but uses a compact data structure to keep track of the vertices in graph *H* to which each vertex in graph *G* may be mapped. Both versions of the McSplit algorithm outperform the clique encoding for many graph classes.[^o7] A more efficient implementation of McSplit is McSplitDAL+PR, which combines a [Reinforcement Learning](wikipedia://en/66294) agent with some heuristic scores computed with the [PageRank](https://en.wikipedia.org/wiki/PageRank) algorithm.[^o8]

::: {#o10 .application cue=heading name="Applications"}

## Applications {#Applications}

Maximum common induced subgraph algorithms form the basis for both graph differencing and graph alignment. Graph differencing identifies and highlights differences between two graphs by pinpointing changes, additions, or deletions. Graph alignment involves finding correspondences between the vertices and edges of two graphs to identify similar structures.

Maximum common induced subgraph algorithms have a long tradition in [bioinformatics](wikipedia://en/4214), [cheminformatics](https://en.wikipedia.org/wiki/Cheminformatics),[^o11][^o12] [pharmacophore mapping](https://en.wikipedia.org/wiki/Pharmacophore),[^o13] [pattern recognition](wikipedia://en/126706),[^o14] [computer vision](https://en.wikipedia.org/wiki/Computer_vision), code analysis, compilers, and [model checking](wikipedia://en/321157).

The problem is also particularly useful in software engineering and [model-based systems engineering](https://en.wikipedia.org/wiki/Model-based_systems_engineering), where software code and engineering models (e.g., [Simulink](https://en.wikipedia.org/wiki/Simulink), [UML diagrams](https://en.wikipedia.org/wiki/Unified_Modeling_Language)) are represented as graph data structures. Graph differencing can be used to detect changes between different versions of software code and models for change auditing, debugging, version control and collaborative team development.
