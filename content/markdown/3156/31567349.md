# Widest path problem

::: {#o1 .subject cue=lead name="Widest path problem"}

*Image: CPT-Graphs-undirected-weighted.svg.* In this graph, the widest path from Maldon to Feering has bandwidth 29, and passes through Clacton, Tiptree, Harwich, and Blaxhall.

In [graph algorithms](https://en.wikipedia.org/wiki/Graph_algorithm), the **widest path problem** is the problem of finding a [path](wikipedia://en/638889) between two designated [vertices](wikipedia://en/638899) in a [weighted graph](https://en.wikipedia.org/wiki/Weighted_graph), maximizing the weight of the minimum-weight edge in the path. The widest path problem is also known as the **maximum capacity path problem**. It is possible to adapt most [shortest path](https://en.wikipedia.org/wiki/Shortest_path) algorithms to compute widest paths, by modifying them to use the bottleneck distance instead of path length.[^o2] However, in many cases even faster algorithms are possible.

:::

For instance, in a graph that represents connections between [routers](https://en.wikipedia.org/wiki/Router_%28computing%29) in the [Internet](https://en.wikipedia.org/wiki/Internet), where the weight of an edge represents the [bandwidth](https://en.wikipedia.org/wiki/Bandwidth_%28computing%29) of a connection between two routers, the widest path problem is the problem of finding an end-to-end path between two Internet nodes that has the maximum possible bandwidth.[^o3] The smallest edge weight on this path is known as the capacity or bandwidth of the path. As well as its applications in network routing, the widest path problem is also an important component of the [Schulze method](https://en.wikipedia.org/wiki/Schulze_method) for deciding the winner of a multiway election,[^o4] and has been applied to [digital compositing](https://en.wikipedia.org/wiki/Digital_compositing),[^o15] [metabolic pathway analysis](https://en.wikipedia.org/wiki/Metabolic_network_modelling#Metabolic_network_simulation),[^o5] and the computation of [maximum flows](https://en.wikipedia.org/wiki/Maximum_flow).[^o28]

A closely related problem, the **minimax path problem** or **bottleneck shortest path problem** asks for the path that minimizes the maximum weight of any of its edges. It has applications that include [transportation planning](https://en.wikipedia.org/wiki/Transportation_planning).[^o6] Any algorithm for the widest path problem can be transformed into an algorithm for the minimax path problem, or vice versa, by reversing the sense of all the weight comparisons performed by the algorithm, or equivalently by replacing every edge weight by its negation.

## Undirected graphs {#Undirected_graphs}

In an [undirected graph](https://en.wikipedia.org/wiki/Undirected_graph), a widest path may be found as the path between the two vertices in the [maximum spanning tree](wikipedia://en/41795) of the graph, and a minimax path may be found as the path between the two vertices in the minimum spanning tree.[^o8][^o11][^o9] It follows immediately from this equivalence that all pairs widest paths in an $n$-vertex undirected graph can be computed in time $O(n^2)$.[^o10]

In any graph, directed or undirected, there is a straightforward algorithm for finding a widest path once the weight of its minimum-weight edge is known: simply delete all smaller edges and search for any path among the remaining edges using [breadth-first search](wikipedia://en/97026) or [depth-first search](wikipedia://en/97034). Based on this test, there also exists a [linear time](https://en.wikipedia.org/wiki/Linear_time) [algorithm](wikipedia://en/775) for finding a widest $s-t$ path in an undirected graph, that does not use the maximum spanning tree. The main idea of the algorithm is to apply the linear-time path-finding algorithm to the [median](wikipedia://en/18837) edge weight in the graph, and then either to delete all smaller edges or contract all larger edges according to whether a path does or does not exist, and recurse in the resulting smaller graph.[^o11][^o12][^o13]

(Fernández Garfinkel Arbiol 1998) use undirected bottleneck shortest paths in order to form [composite](https://en.wikipedia.org/wiki/Digital_compositing) [aerial photographs](https://en.wikipedia.org/wiki/Aerial_photography) that combine multiple images of overlapping areas. In the subproblem to which the widest path problem applies, two images have already been [transformed into a common coordinate system](https://en.wikipedia.org/wiki/Image_registration); the remaining task is to select a *seam*, a curve that passes through the region of overlap and divides one of the two images from the other. Pixels on one side of the seam will be copied from one of the images, and pixels on the other side of the seam will be copied from the other image. Unlike other compositing methods that average pixels from both images, this produces a valid photographic image of every part of the region being photographed. They weigh the edges of a [grid graph](https://en.wikipedia.org/wiki/Grid_graph) by a numeric estimate of how visually apparent a seam across that edge would be, and find a bottleneck shortest path for these weights. Using this path as the seam, rather than a more conventional shortest path, causes their system to find a seam that is difficult to discern at all of its points, rather than allowing it to trade off greater visibility in one part of the image for lesser visibility elsewhere.[^o15]

A solution to the minimax path problem between the two opposite corners of a [grid graph](https://en.wikipedia.org/wiki/Grid_graph) can be used to find the [weak Fréchet distance](wikipedia://en/19539938) between two [polygonal chains](wikipedia://en/12056032). Here, each grid graph vertex represents a pair of line segments, one from each chain, and the weight of an edge represents the Fréchet distance needed to pass from one pair of segments to another.[^o16]

If all edge weights of an undirected graph are [positive](https://en.wikipedia.org/wiki/Positive_number), then the minimax distances between pairs of points (the maximum edge weights of minimax paths) form an [ultrametric](https://en.wikipedia.org/wiki/Ultrametric); conversely every finite ultrametric space comes from minimax distances in this way.[^o17] A [data structure](wikipedia://en/8519) constructed from the minimum spanning tree allows the minimax distance between any pair of vertices to be queried in constant time per query, using [lowest common ancestor](wikipedia://en/7196522) queries in a [Cartesian tree](https://en.wikipedia.org/wiki/Cartesian_tree). The root of the Cartesian tree represents the heaviest minimum spanning tree edge, and the children of the root are Cartesian trees [recursively](wikipedia://en/25407) constructed from the subtrees of the minimum spanning tree formed by removing the heaviest edge. The leaves of the Cartesian tree represent the vertices of the input graph, and the minimax distance between two vertices equals the weight of the Cartesian tree node that is their lowest common ancestor. Once the minimum spanning tree edges have been sorted, this Cartesian tree can be constructed in linear time.[^o18]

## Directed graphs {#Directed_graphs}

In [directed graphs](wikipedia://en/19721986), the maximum spanning tree solution cannot be used. Instead, several different algorithms are known; the choice of which algorithm to use depends on whether a start or destination vertex for the path is fixed, or whether paths for many start or destination vertices must be found simultaneously.

### All pairs {#All_pairs}

The all-pairs widest path problem has applications in the [Schulze method](https://en.wikipedia.org/wiki/Schulze_method) for choosing a winner in multiway [elections](https://en.wikipedia.org/wiki/Election) in which voters rank the candidates in [preference order](https://en.wikipedia.org/wiki/Ranked_voting_systems). The Schulze method constructs a [complete directed graph](wikipedia://en/1427502) in which the vertices represent the candidates and every two vertices are connected by an edge. Each edge is directed from the winner to the loser of a pairwise contest between the two candidates it connects, and is labeled with the margin of victory of that contest. Then the method computes widest paths between all pairs of vertices, and the winner is the candidate whose vertex has wider paths to each opponent than vice versa.[^o4] The results of an election using this method are consistent with the [Condorcet method](wikipedia://en/44446) – a candidate who wins all pairwise contests automatically wins the whole election – but it generally allows a winner to be selected, even in situations where the Condorcet method itself fails.[^o21] The Schulze method has been used by several organizations including the [Wikimedia Foundation](https://en.wikipedia.org/wiki/Wikimedia_Foundation).[^o22]

To compute the widest path widths for all pairs of nodes in a [dense](wikipedia://en/2777098) directed graph, such as the ones that arise in the voting application, the [asymptotically](wikipedia://en/15374087) fastest known approach takes time $O(n^{(3+\omega)/2})$ where ω is the exponent for [fast matrix multiplication](https://en.wikipedia.org/wiki/Fast_matrix_multiplication). Using the best known algorithms for matrix multiplication, this time bound becomes $O(n^{2.688})$.[^o23] Instead, the reference implementation for the Schulze method uses a modified version of the simpler [Floyd–Warshall algorithm](wikipedia://en/230401), which takes $O(n^{3})$ time.[^o4] For [sparse graphs](https://en.wikipedia.org/wiki/Sparse_graph), it may be more efficient to repeatedly apply a single-source widest path algorithm.

### Single source {#Single_source}

If the edges are sorted by their weights, then a modified version of [Dijkstra's algorithm](wikipedia://en/45809) can compute the bottlenecks between a designated start vertex and every other vertex in the graph, in linear time. The key idea behind the speedup over a conventional version of Dijkstra's algorithm is that the sequence of bottleneck distances to each vertex, in the order that the vertices are considered by this algorithm, is a [monotonic](https://en.wikipedia.org/wiki/Monotonic) subsequence of the sorted sequence of edge weights; therefore, the [priority queue](https://en.wikipedia.org/wiki/Priority_queue) of Dijkstra's algorithm can be implemented as a [bucket queue](https://en.wikipedia.org/wiki/Bucket_queue): an array indexed by the numbers from 1 to $m$ (the number of edges in the graph), where array cell $i$ contains the vertices whose bottleneck distance is the weight of the edge with position $i$ in the sorted order. This method allows the widest path problem to be solved as quickly as [sorting](wikipedia://en/28442); for instance, if the edge weights are represented as integers, then the time bounds for [integer sorting](https://en.wikipedia.org/wiki/Integer_sorting) a list of $m$ integers would apply also to this problem.[^o13]

### Single source and single destination {#Single_source_and_single_destination}

(Berman Handler 1987) suggest that service vehicles and emergency vehicles should use minimax paths when returning from a service call to their base. In this application, the time to return is less important than the response time if another service call occurs while the vehicle is in the process of returning. By using a minimax path, where the weight of an edge is the maximum travel time from a point on the edge to the farthest possible service call, one can plan a route that minimizes the maximum possible delay between receipt of a service call and arrival of a responding vehicle.[^o6] (Ullah Lee Hassoun 2009) use maximin paths to model the dominant reaction chains in [metabolic networks](https://en.wikipedia.org/wiki/Metabolic_network); in their model, the weight of an edge is the free energy of the metabolic reaction represented by the edge.[^o5]

Another application of widest paths arises in the [Ford–Fulkerson algorithm](wikipedia://en/53777) for the [maximum flow problem](wikipedia://en/403165). Repeatedly augmenting a flow along a maximum capacity path in the residual network of the flow leads to a small bound, $O(m \log U)$, on the number of augmentations needed to find a maximum flow; here, the edge capacities are assumed to be integers that are at most $U$. However, this analysis does not depend on finding a path that has the exact maximum of capacity; any path whose capacity is within a constant factor of the maximum suffices. Combining this approximation idea with the shortest path augmentation method of the [Edmonds–Karp algorithm](wikipedia://en/239230) leads to a maximum flow algorithm with running time $O(mn \log U)$.[^o28]

It is possible to find maximum-capacity paths and minimax paths with a single source and single destination very efficiently even in models of computation that allow only comparisons of the input graph's edge weights and not arithmetic on them.[^o13][^o29] The algorithm maintains a set $S$ of edges that are known to contain the bottleneck edge of the optimal path; initially, $S$ is just the set of all $m$ edges of the graph. At each iteration of the algorithm, it splits $S$ into an ordered sequence of subsets $S_{1}, S_{2}, ...$ of approximately equal size; the number of subsets in this partition is chosen in such a way that all of the split points between subsets can be found by repeated median-finding in time $O(m)$. The algorithm then reweights each edge of the graph by the index of the subset containing the edge, and uses the modified Dijkstra algorithm on the reweighted graph; based on the results of this computation, it can determine in linear time which of the subsets contains the bottleneck edge weight. It then replaces $S$ by the subset $S_{i}$ that it has determined to contain the bottleneck weight, and starts the next iteration with this new set $S$. The number of subsets into which $S$ can be split increases exponentially with each step, so the number of iterations is proportional to the [iterated logarithm](wikipedia://en/1038048) function, $O(n)$, and the total time is $O(m n)$.[^o29] In a model of computation where each edge weight is a machine integer, the use of repeated bisection in this algorithm can be replaced by a list-splitting technique of (Han Thorup 2002), allowing $S$ to be split into $O(\sqrt{m})$ smaller sets $S_{i}$ in a single step and leading to a linear overall time bound.[^o31]

## Euclidean point sets {#Euclidean_point_sets}

*Image: Gaussian moat 15x15.svg.* The dark blue band separates pairs of [Gaussian prime numbers](wikipedia://en/48628) whose minimax path length is 2 or more.

A variant of the minimax path problem has also been considered for sets of points in the [Euclidean plane](wikipedia://en/15575410). As in the undirected graph problem, this Euclidean minimax path problem can be solved efficiently by finding a [Euclidean minimum spanning tree](wikipedia://en/1040597): every path in the tree is a minimax path. However, the problem becomes more complicated when a path is desired that not only minimizes the hop length but also, among paths with the same hop length, minimizes or approximately minimizes the total length of the path. The solution can be approximated using [geometric spanners](wikipedia://en/11844294).[^o33]

In [number theory](wikipedia://en/21527), the unsolved [Gaussian moat](wikipedia://en/35633206) problem asks whether or not minimax paths in the [Gaussian prime numbers](wikipedia://en/48628) have bounded or unbounded minimax length. That is, does there exist a constant $B$ such that, for every pair of points $p$ and $q$ in the infinite Euclidean point set defined by the Gaussian primes, the minimax path in the Gaussian primes between $p$ and $q$ has minimax edge length at most $B$?[^o34]
