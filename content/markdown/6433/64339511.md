# Delegated credential

::: {#o1 .subject cue=lead name="Delegated credential"}

**Delegated credential** is a short-lived [TLS](wikipedia://en/187813) [certificate](wikipedia://en/223796) used to improve security by faster recovery from [private key](https://en.wikipedia.org/wiki/Private_key) leakage, without increasing the [latency](https://en.wikipedia.org/wiki/Network_delay) of the [TLS handshake](https://en.wikipedia.org/wiki/TLS_handshake). It is currently an [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) [Internet Draft](https://en.wikipedia.org/wiki/Internet_Draft),[^o2] and has been in use by [Cloudflare](https://en.wikipedia.org/wiki/Cloudflare)[^o3] and [Facebook](https://en.wikipedia.org/wiki/Facebook),[^o4] with browser support by [Firefox](https://en.wikipedia.org/wiki/Firefox).[^o5]

:::

## Motivation {#Motivation}

Modern websites and other services use [content delivery networks](https://en.wikipedia.org/wiki/Content_delivery_network) (CDNs), which are servers potentially distributed all over the world, in order to respond to a user's request as fast as possible, alongside other services that CDNs provide such as [DDoS mitigation](https://en.wikipedia.org/wiki/DDoS_mitigation). However, in order to establish a [secure](wikipedia://en/187813) connection, the server is required to prove possession of a private key associated with a certificate, which serves as a [chain of trust](https://en.wikipedia.org/wiki/Chain_of_trust) linking the public key and a trusted party. The trusted party is normally a [certificate authority](wikipedia://en/296370) (CA).

CAs issue these [digital certificates](wikipedia://en/223796) with an expiration time, usually a few months up to a year. It is the server's responsibility to renew the certificate close to its expiration date. Knowledge of a private key associated to a valid certificate is devastating for the site's security, as it allows [Man-in-the-middle attacks](wikipedia://en/144676), in which a malicious entity can impersonate to a user as a legitimate server. Therefore, these private keys should be kept secure, preferably not distributed over every server in the CDN. Specifically, if a private key is compromised, the corresponding certificate should optimally be [revoked](https://en.wikipedia.org/wiki/Certificate_revocation), such that browsers will no longer support this certificate. Certificate revocation has two main drawbacks. Firstly, current revocation methods do not work well across all browsers, and put the users at risk; and secondly, upon revocation, the server needs to quickly fetch a new valid certificate from the CA and deploy it across all [mirrors](https://en.wikipedia.org/wiki/Mirror_site).

## Design {#Design}

A delegated credential is a short-lived key (from a few hours to a few days) that the certificate's owner delegates to the server for use in TLS. It is in fact a [signature](wikipedia://en/1595662): the certificate's owner uses the certificate's private key to sign a delegated public key, and an expiration time.

Given this delegated credential, a browser can (if it supports it) verify the server's authenticity by verifying the delegated certificate and then verify the certificate itself.

## Advantages {#Advantages}

This approach has many advantage over current solutions:

- Delegated credentials are short-lived, so private keys can be changed frequently. Therefore, even if a particular delegated credential is compromised without certificate owner knowing it, that compromised credential could only be abused for a very short time.
- No revocation is needed for stolen certificates.
- The certificate owner does not need to expose its private key to the CDN servers, but rather periodically supply them with delegated credentials. Therefore, certificate owner can maintain exclusive control over its private key (and even store it in [HSM](https://en.wikipedia.org/wiki/Hardware_security_module)) while using third-party CDN servers.
- The delegated credential has its own key, so it can experiment with new algorithms such as [Ed25519](https://en.wikipedia.org/wiki/Ed25519). This can facilitate [cryptographic agility](wikipedia://en/59163115).
