# Streebog

::: {#o2 .subject cue=lead name="Streebog"}

**Streebog** (Стрибог) is a [cryptographic hash function](wikipedia://en/439526) defined in the Russian national standard [GOST](https://en.wikipedia.org/wiki/GOST) R 34.11-2012 *Information Technology – Cryptographic Information Security – Hash Function*. It was created to replace an obsolete [GOST](wikipedia://en/3080232) hash function defined in the old standard GOST R 34.11-94, and as an asymmetric reply to [SHA-3](wikipedia://en/20394543) [competition](wikipedia://en/20051952) by the US [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology).[^o3] The function is also described in RFC 6986 and one out of hash functions in [ISO/IEC](https://en.wikipedia.org/wiki/International_Organization_for_Standardization) 10118-3:2018.[^o4]

:::

## Description {#Description}

Streebog operates on 512-bit blocks of the input, using the [Merkle–Damgård construction](wikipedia://en/4076217) to handle inputs of arbitrary size.[^o6]

The high-level structure of the new hash function resembles the one from GOST R 34.11-94, however, the compression function was changed significantly.[^o7] The compression function operates in [Miyaguchi–Preneel](https://en.wikipedia.org/wiki/Miyaguchi–Preneel) mode and employs a 12-round [AES](wikipedia://en/1260)-like cipher with a 512-bit block and 512-bit key. (It uses an 8×8 matrix of bytes rather than AES's 4×4 matrix.)

Streebog-256 uses a different initial state than Streebog-512, and truncates the output hash, but is otherwise identical.

The function was named **Streebog** after [Stribog](https://en.wikipedia.org/wiki/Stribog), the god of rash wind in ancient Slavic mythology,[^o3] and is often referred by this name, even though it is not explicitly mentioned in the text of the standard.[^o8]

## Cryptanalysis {#Cryptanalysis}

In 2013 the Russian Technical Committee for Standardization "Cryptography and Security Mechanisms" (TC 26) with the participation of Academy of Cryptography of the Russian Federation declared an open competition for [cryptanalysis](wikipedia://en/5715) of the Streebog hash function,[^o11] which attracted international attention to the function.

Ma, *et al*, describe a [preimage attack](wikipedia://en/969477) that takes 2<sup>496</sup> time and 2<sup>64</sup> memory or 2<sup>504</sup> time and 2<sup>11</sup> memory to find a single preimage of GOST-512 reduced to 6 rounds.[^o12] They also describe a [collision attack](wikipedia://en/969624) with 2<sup>181</sup> [time complexity](wikipedia://en/405944) and 2<sup>64</sup> memory requirement in the same paper.

Guo, *et al*, describe a [second preimage attack](https://en.wikipedia.org/wiki/Second_preimage_attack) on full Streebog-512 with total time complexity equivalent to 2<sup>266</sup> compression function evaluations, if the message has more than 2<sup>259</sup> blocks.[^o13]

AlTawy and Youssef published an attack to a modified version of Streebog with different round constants.[^o14] While this attack may not have a direct impact on the security of the original Streebog hash function, it raised a question about the origin of the used parameters in the function. The designers published a paper explaining that these are pseudorandom constants generated with Streebog-like hash function, provided with 12 different natural language input messages.[^o15]

AlTawy, *et al*, found 5-round free-start collision and a 7.75 free-start near collision for the internal cipher with complexities 2<sup>8</sup> and 2<sup>40</sup>, respectively, as well as attacks on the compression function with 7.75 round semi free-start collision with time complexity 2<sup>184</sup> and memory complexity 2<sup>8</sup>, 8.75 and 9.75 round semi free-start near collisions with time complexities 2<sup>120</sup> and 2<sup>196</sup>, respectively.[^o16]

Wang, *et al*, describe a collision attack on the compression function reduced to 9.5 rounds with 2<sup>176</sup> time complexity and 2<sup>128</sup> memory complexity.[^o17]

In 2015 Biryukov, Perrin and Udovenko reverse engineered the unpublished S-box generation structure (which was earlier claimed to be generated randomly) and concluded that the underlying components are cryptographically weak.[^o18]
