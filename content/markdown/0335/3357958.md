# Elliptic-curve Diffie–Hellman

::: {#o1 .subject cue=lead name="Elliptic-curve Diffie–Hellman"}

**Elliptic-curve Diffie–Hellman** (**ECDH**) is a [key agreement](https://en.wikipedia.org/wiki/Key_agreement) protocol that allows two parties, each having an [elliptic-curve](wikipedia://en/9966) public–private key pair, to establish a [shared secret](wikipedia://en/7111246) over an [insecure channel](https://en.wikipedia.org/wiki/Insecure_channel).[^o2][^o3][^o4] This shared secret may be directly used as a key, or to [derive another key](wikipedia://en/449781). The key, or the derived key, can then be used to encrypt subsequent communications using a [symmetric-key cipher](wikipedia://en/53042). It is a variant of the [Diffie–Hellman](wikipedia://en/7903) protocol using [elliptic-curve cryptography](wikipedia://en/9966).

:::

## Key establishment protocol {#Key_establishment_protocol}

The following example illustrates how a shared key is established. Suppose [Alice](wikipedia://en/679079) wants to establish a shared key with [Bob](wikipedia://en/679079), but the only channel available for them may be eavesdropped by a third party. Initially, the [domain parameters](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography#Domain_parameters) (that is, $(p, a, b, G, n, h)$ in the prime case or $(m, f(x), a, b, G, n, h)$ in the binary case) must be agreed upon. Also, each party must have a key pair suitable for elliptic curve cryptography, consisting of a private key $d$ (a randomly selected integer in the interval $[1, n-1]$) and a public key represented by a point $Q$ (where $Q = d \cdot G$, that is, the result of [adding](wikipedia://en/28244303) $G$ to itself $d$ times). Let Alice's key pair be $(d_\text{A}, Q_\text{A})$ and Bob's key pair be $(d_\text{B}, Q_\text{B})$. Each party must know the other party's public key prior to execution of the protocol.

Alice computes point $(x_k, y_k) = d_\text{A} \cdot Q_\text{B}$. Bob computes point $(x_k, y_k) = d_\text{B} \cdot Q_\text{A}$. The shared secret is $x_k$ (the *x* coordinate of the point). Most standardized protocols based on ECDH derive a symmetric key from $x_k$ using some hash-based key derivation function.

The shared secret calculated by both parties is equal, because $d_\text{A} \cdot Q_\text{B} = d_\text{A} \cdot d_\text{B} \cdot G = d_\text{B} \cdot d_\text{A} \cdot G = d_\text{B} \cdot Q_\text{A}$.

The only information about her key that Alice initially exposes is her public key. So, no party except Alice can determine Alice's private key (Alice of course knows it by having selected it), unless that party can solve the elliptic curve [discrete logarithm](wikipedia://en/181334) problem. Bob's private key is similarly secure. No party other than Alice or Bob can compute the shared secret, unless that party can solve the elliptic curve [Diffie–Hellman problem](wikipedia://en/3237741).

The public keys are either static (and trusted, say via a certificate) or ephemeral (also known as **ECDHE**, where final 'E' stands for "ephemeral"). [Ephemeral keys](https://en.wikipedia.org/wiki/Ephemeral_key) are temporary and not necessarily authenticated, so if authentication is desired, authenticity assurances must be obtained by other means. Authentication is necessary to avoid [man-in-the-middle attacks](wikipedia://en/144676). If one of either Alice's or Bob's public keys is static, then man-in-the-middle attacks are thwarted. Static public keys provide neither [forward secrecy](wikipedia://en/2191130) nor key-compromise impersonation resilience, among other advanced security properties. Holders of static private keys should validate the other public key, and should apply a secure [key derivation function](wikipedia://en/449781) to the raw Diffie–Hellman shared secret to avoid leaking information about the static private key. For schemes with other security properties, see [MQV](wikipedia://en/1586447).

If Alice maliciously chooses invalid curve points for her key and Bob does not validate that Alice's points are part of the selected group, she can collect enough residues of Bob's key to derive his private key. Several [TLS](wikipedia://en/187813) libraries were found to be vulnerable to this attack.[^o6]

The shared secret is uniformly distributed on a subset of $[0, p)$ of size $(n+1)/2$. For this reason, the secret should not be used directly as a symmetric key, but it can be used as entropy for a key derivation function.

### Diffie-Hellman Key Agreement on Montgomery Curves {#Diffie-Hellman_Key_Agreement_on_Montgomery_Curves}

Let $A, B \in F_p$ such that $B(A^2 - 4) \neq 0$. The Montgomery form elliptic curve $E_{M,A,B}$ is the set of all $(x,y) \in F_p \times F_p$ satisfying the equation $By^2 = x(x^2 + Ax + 1)$ along with the point at infinity denoted as $\infty$. This is called the affine form of the curve. The set of all $F_p$-rational points of $E_{M,A,B}$, denoted as $E_{M,A,B}(F_p)$ is the set of all $(x,y) \in F_p \times F_p$ satisfying $By^2 = x(x^2 + Ax + 1)$ along with $\infty$. Under a suitably defined addition operation, $E_{M,A,B}(F_p)$ is a group with $\infty$ as the identity element. It is known that the order of this group is a multiple of 4. In fact, it is usually possible to obtain $A$ and $B$ such that the order of $E_{M,A,B}$ is $4q$ for a prime $q$. For more extensive discussions of Montgomery curves and their arithmetic one may follow.[^o8][^o9][^o10]

For computational efficiency, it is preferable to work with projective coordinates. The projective form of the Montgomery curve $E_{M,A,B}$ is $BY^2Z = X(X^2 + AXZ + Z^2)$. For a point $P = [ X : Y : Z ]$ on $E_{M,A,B}$, the $x$-coordinate map $x$ is the following:[^o10] $x(P) = [ X : Z ]$ if $Z \neq 0$ and $x(P) = [ 1 : 0 ]$ if $P = [ 0 : 1 : 0 ]$ . [Bernstein](wikipedia://en/198983)[^o11][^o13] introduced the map $x_0$ as follows: $x_0(X : Z) = XZ^{p - 2}$ which is defined for all values of $X$ and $Z$ in $F_p$. Following Miller,[^o12] Montgomery[^o8] and Bernstein,[^o13] the Diffie-Hellman key agreement can be carried out on a Montgomery curve as follows. Let $Q$ be a generator of a prime order subgroup of $E_{M,A,B}(F_p)$. Alice chooses a secret key $s$ and has public key $x_0(sQ)$; Bob chooses a secret key $t$ and has public key $x_0(tQ)$. The shared secret key of Alice and Bob is $x_0(stQ)$. Using classical computers, the best known method of obtaining $x_0(stQ)$ from $Q,x_0(sQ)$ and $x_0(tQ)$ requires about $O(p^{1/2})$ time using the [Pollards rho algorithm](wikipedia://en/580668).[^o14]

The most famous example of Montgomery curve is [Curve25519](wikipedia://en/17935444) which was introduced by Bernstein.[^o13] For Curve25519, $p = 2^{255} - 19, A = 486662$ and $B = 1$. The other Montgomery curve which is part of TLS 1.3 is [Curve448](wikipedia://en/56665655) which was introduced by Hamburg.[^o15] For Curve448, $p = 2^{448} - 2^{224} - 1, A = 156326$ and $B = 1$. Couple of Montgomery curves named M\[4698\] and M\[4058\] competitive to [Curve25519](wikipedia://en/17935444) and [Curve448](wikipedia://en/56665655) respectively have been proposed in.[^o16] For M\[4698\], $p = 2^{251} - 9, A = 4698, B = 1$ and for M\[4058\], $p = 2^{444} - 17, A = 4058, B = 1$. At 256-bit security level, three Montgomery curves named M\[996558\], M\[952902\] and M\[1504058\] have been proposed in.[^o17] For M\[996558\], $p = 2^{506} - 45, A = 996558, B = 1$, for M\[952902\], $p = 2^{510} - 75, A = 952902, B = 1$ and for M\[1504058\], $p = 2^{521} - 1, A = 1504058, B = 1$ respectively. Apart from these two, other proposals of Montgomery curves can be found at.[^o18]

## Software {#Software}

- [Curve25519](wikipedia://en/17935444) is a popular set of elliptic curve parameters and reference implementation by [Daniel J. Bernstein](wikipedia://en/198983) in [C](https://en.wikipedia.org/wiki/C_language). [Bindings](https://en.wikipedia.org/wiki/Language_binding) and alternative implementations are also available.
- [Curve448](wikipedia://en/56665655), an elliptic curve potentially offering 224 bits of security, developed by Mike Hamburg of [Rambus](https://en.wikipedia.org/wiki/Rambus) Cryptography Research.
- [LINE messenger app](https://en.wikipedia.org/wiki/Line_%28software%29) has used the ECDH protocol for its "Letter Sealing" [end-to-end encryption](wikipedia://en/1065362) of all messages sent through said app since October 2015.[^o20]
- [Signal Protocol](wikipedia://en/50607084) uses ECDH to obtain post-compromise security. Implementations of this protocol are found in [Signal](https://en.wikipedia.org/wiki/Signal_%28messaging_app%29), [WhatsApp](wikipedia://en/32058867), [Facebook Messenger](https://en.wikipedia.org/wiki/Facebook_Messenger) and [Skype](https://en.wikipedia.org/wiki/Skype).
