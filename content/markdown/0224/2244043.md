# CCM mode

::: {#o1 .subject cue=lead name="CCM mode"}

**CCM mode** (**counter with cipher block chaining message authentication code**; **counter with [CBC-MAC](wikipedia://en/2840574)**) is a [mode of operation](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation) for cryptographic [block ciphers](wikipedia://en/4594). It is an [authenticated encryption](wikipedia://en/2244296) algorithm designed to provide both [authentication](wikipedia://en/47967) and [confidentiality](wikipedia://en/353859). CCM mode is only defined for block ciphers with a block length of 128 bits.[^o2][^o3]

:::

The [nonce](wikipedia://en/6988390) of CCM must be carefully chosen to never be used more than once for a given [key](wikipedia://en/53039). This is because CCM is a derivation of [counter (CTR) mode](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation#Counter_.28CTR.29) and the latter is effectively a [stream cipher](wikipedia://en/49007).[^o4]

## Encryption and authentication {#Encryption_and_authentication}

As the name suggests, CCM mode combines [counter (CTR) mode](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation#Counter_.28CTR.29) for confidentiality with [cipher block chaining message authentication code (CBC-MAC)](wikipedia://en/2840574) for authentication. These two primitives are applied in an "authenticate-then-encrypt" manner: CBC-MAC is first computed on the message to obtain a [message authentication code (MAC)](wikipedia://en/567523), then the message and the MAC are encrypted using counter mode. The main insight is that the same encryption key can be used for both, provided that the counter values used in the encryption do not collide with the (pre-)[initialization vector](wikipedia://en/105971) used in the authentication. A [proof of security](wikipedia://en/1182348#In_cryptography)[^o6] exists for this combination, based on the security of the underlying block cipher. The proof also applies to a generalization of CCM for any [block size](wikipedia://en/294065), and for any size of [cryptographically strong](https://en.wikipedia.org/wiki/Cryptographically_strong) [pseudo-random function](https://en.wikipedia.org/wiki/Pseudo-random_function) (since in both counter mode and CBC-MAC, the block cipher is only ever used in one direction).

CCM mode was designed by [Russ Housley](https://en.wikipedia.org/wiki/Russ_Housley), Doug Whiting and [Niels Ferguson](wikipedia://en/204933). At the time CCM mode was developed, Russ Housley was employed by [RSA Laboratories](wikipedia://en/301240).

A minor variation of CCM, called CCM\*, is used in the [IEEE 802.15.4](https://en.wikipedia.org/wiki/IEEE_802.15.4) standard, used as the [MAC](https://en.wikipedia.org/wiki/Medium_access_control) layer in [Zigbee](https://en.wikipedia.org/wiki/Zigbee). CCM\* includes all of the features of CCM. It allows a choice of MAC lengths down to 0 (which disables authentication and becomes encryption-only).[^o7]

## Performance {#Performance}

CCM requires two block cipher encryption operations on each block of an encrypted-and-authenticated message, and one encryption on each block of associated authenticated data.

According to [Crypto++](https://en.wikipedia.org/wiki/Crypto++) benchmarks, AES CCM requires 28.6 [cycles per byte](https://en.wikipedia.org/wiki/Cycles_per_byte) on an [Intel Core 2 processor](https://en.wikipedia.org/wiki/Intel_Core_2) in 32-bit mode.[^o9]

Notable inefficiencies:

- CCM is not an "on-line" [authenticated encryption with associated data (AEAD)](wikipedia://en/2244296#Authenticated_encryption_with_associated_data), in that the length of the message (and associated data) must be known in advance.
- In the MAC construction, the length of the associated data has a variable-length encoding, which can be shorter than machine word size. This can cause pessimistic MAC performance if associated data is long (which is uncommon).
- Associated data is processed after message data, so it is not possible to pre-calculate state for static associated data.

## Patents {#Patents}

The catalyst for the development of CCM mode was the submission of [offset codebook (OCB) mode](wikipedia://en/2233546) for inclusion in the [IEEE 802.11i](https://en.wikipedia.org/wiki/IEEE_802.11i) standard. Opposition was voiced to the inclusion of OCB mode because of a pending [patent](https://en.wikipedia.org/wiki/Patent) application on the [algorithm](wikipedia://en/775). Inclusion of a patented algorithm meant significant licensing complications for implementors of the standard.

While the inclusion of OCB mode was disputed based on these [intellectual property](https://en.wikipedia.org/wiki/Intellectual_property) issues, it was agreed that the simplification provided by an authenticated encryption system was desirable. Therefore, Housley, et al. developed CCM mode as a potential alternative that was not encumbered by patents.

Even though CCM mode is less efficient than OCB mode, a patent free solution was preferable to one complicated by patent licensing issues. Therefore, CCM mode went on to become a mandatory component of the IEEE 802.11i standard, and OCB mode was relegated to optional component status, before eventually being removed altogether.

## Use {#Use}

CCM mode is used in [IEEE 802.11i](https://en.wikipedia.org/wiki/IEEE_802.11i) (as [CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29), the CCM encryption protocol for [WPA2](https://en.wikipedia.org/wiki/WPA2)), [IPsec](https://en.wikipedia.org/wiki/IPsec),[^o13] and [TLS](wikipedia://en/187813) 1.2,[^o14] as well as [Bluetooth Low Energy](https://en.wikipedia.org/wiki/Bluetooth_Low_Energy) (as of [Bluetooth 4.0](https://en.wikipedia.org/wiki/Bluetooth#Bluetooth_4.0)).[^o15]It is available for TLS 1.3, but not enabled by default in [OpenSSL](wikipedia://en/438819).[^o16] From version 0.8[^o17] to 0.8.3 it was the default in OpenZFS' native encryption[^o18].
