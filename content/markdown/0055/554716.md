# Oblivious transfer

::: {#o1 .subject cue=lead name="Oblivious transfer"}

In [cryptography](wikipedia://en/18934432), an **oblivious transfer** (**OT**) protocol is a type of protocol in which a sender transfers one of potentially many pieces of information to a receiver, but remains oblivious as to what piece (if any) has been transferred.

:::

The first form of oblivious transfer was introduced in 1981 by [Michael O. Rabin](wikipedia://en/298404).[^o2] In this form, the sender sends a message to the receiver with [probability](wikipedia://en/22934) 1/2, while the sender remains oblivious as to whether or not the receiver received the message. Rabin's oblivious transfer scheme is based on the [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) [cryptosystem](wikipedia://en/506383). A more useful form of oblivious transfer called **1–2 oblivious transfer** or "1 out of 2 oblivious transfer", was developed later by [Shimon Even](https://en.wikipedia.org/wiki/Shimon_Even), [Oded Goldreich](https://en.wikipedia.org/wiki/Oded_Goldreich), and [Abraham Lempel](https://en.wikipedia.org/wiki/Abraham_Lempel),[^o3] in order to build protocols for [secure multiparty computation](https://en.wikipedia.org/wiki/Secure_multiparty_computation). It is generalized to "1 out of *n* oblivious transfer" where the user gets exactly one database element without the server getting to know which element was queried, and without the user knowing anything about the other elements that were not retrieved. The latter notion of oblivious transfer is a strengthening of [private information retrieval](https://en.wikipedia.org/wiki/Private_information_retrieval), in which the database is not kept private.

[Claude Crépeau](https://en.wikipedia.org/wiki/Claude_Crépeau) showed that Rabin's oblivious transfer is equivalent to 1–2 oblivious transfer.[^o4]

Further work has revealed oblivious transfer to be a fundamental and important problem in cryptography. It is considered one of the critical problems in the field, because of the importance of the applications that can be built based on it. In particular, it is [complete](wikipedia://en/1176530) for [secure multiparty computation](https://en.wikipedia.org/wiki/Secure_multiparty_computation): that is, given an implementation of oblivious transfer it is possible to securely evaluate any polynomial time [computable function](wikipedia://en/1139338) without any additional primitive.[^o5]

## Rabin's oblivious transfer protocol {#Rabin's_oblivious_transfer_protocol}

In Rabin's oblivious transfer protocol, the sender generates an RSA public modulus *N*=*pq* where *p* and *q* are large [prime numbers](wikipedia://en/23666), and an exponent *e* [relatively prime](https://en.wikipedia.org/wiki/Relatively_prime) to *λ(N)* = (*p* − 1)(*q* − 1). The sender encrypts the message *m* as *m*<sup>*e*</sup> mod *N*.

1. The sender sends *N*, *e*, and *m*<sup>*e*</sup> mod *N* to the receiver.
1. The receiver picks a random *x* modulo *N* and sends *x*<sup>2</sup> mod *N* to the sender. Note that gcd(*x*,*N*) = 1 with overwhelming probability, which ensures that there are 4 square roots of *x*<sup>2</sup> mod *N*.
1. The sender finds a square root *y* of *x*<sup>2</sup> mod *N* and sends *y* to the receiver.

If the receiver finds *y* is neither *x* nor −*x* modulo *N*, the receiver will be able to [factor](wikipedia://en/15491) *N* and therefore decrypt *m*<sup>*e*</sup> to recover *m* (see [Rabin encryption](https://en.wikipedia.org/wiki/Rabin_encryption) for more details). However, if *y* is *x* or −*x* mod *N*, the receiver will have no information about *m* beyond the encryption of it. Since every [quadratic residue](wikipedia://en/200091) modulo *N* has four square roots, the probability that the receiver learns *m* is 1/2.

## 1–2 oblivious transfer {#1–2_oblivious_transfer}

In a 1–2 oblivious transfer protocol, Alice the sender has two messages *m*<sub>0</sub> and *m*<sub>1</sub>, and wants to ensure that the receiver only learns one. Bob, the receiver, has a bit *b* and wishes to receive *m*<sub>*b*</sub> without Alice learning *b*. The protocol of Even, Goldreich, and Lempel (which the authors attribute partially to [Silvio Micali](https://en.wikipedia.org/wiki/Silvio_Micali)) is general, but can be instantiated using RSA encryption as follows.

::: {#o8 .table cue=table}

| Alice (sender) |  |  |  | Bob (receiver) |  |  |
|---|---|---|---|---|---|---|
| Calculus | Secret | Public |  | Public | Secret | Calculus |
| Messages to be sent | $m_0, m_1$ |  |  |  |  |  |
| Generate RSA key pair and send public portion to Bob | $d$ | $N, e$ | $\Rightarrow$ | $N, e$ |  | Receive public key |
| Generate two random messages |  | $x_0, x_1$ | $\Rightarrow$ | $x_0, x_1$ |  | Receive random messages |
|  |  |  |  |  | $k, b$ | Choose $b \in \{0,1\}$ and generate random $k$ |
|  |  | $v$ | $\Leftarrow$ | $v = (x_b + k^e) \bmod N$ |  | Compute the encryption of $k$, blind with $x_b$ and send to Alice |
| One of these will equal $k$, but Alice does not know which | $\begin{aligned}k_0 & = (v - x_0)^d\bmod N \\k_1 & = (v - x_1)^d\bmod N\end{aligned}$ |  |  |  |  |  |
| Send both messages to Bob |  | $\begin{aligned}m'_0 = (m_0 + k_0)\bmod N \\ m'_1 = (m_1 + k_1)\bmod N\end{aligned}$ | $\Rightarrow$ | $m'_0, m'_1$ |  | Receive both messages |
|  |  |  |  |  | $m_b = (m'_b - k)\bmod N$ | Bob decrypts the $m'_b$, since he knows which $x_b$ he selected earlier |

:::

1. Alice has two messages, $m_0, m_1$, and wants to send exactly one of them to Bob. Bob does not want Alice to know which one he receives.
1. Alice generates an RSA key pair, comprising the modulus $N$, the public exponent $e$ and the private exponent $d$.
1. She also generates two random values, $x_0, x_1$, and sends them to Bob along with her public modulus and exponent.
1. Bob picks $b$ to be either 0 or 1 and selects $x_b$.
1. Bob generates a random value $k$ and uses it to blind $x_b$ by computing $v = (x_b + k^e)\bmod N$, which he sends to Alice.
1. Alice combines $v$ with both of her random values to produce $k_0 = (v - x_0)^d\bmod N$ and $k_1 = (v - x_1)^d\bmod N$. Now $k_b$ will be equal to $k,$ and the other will be a meaningless random value. However, since Alice does not know the value of $b$ that Bob chose, she cannot determine which of $k_0$ and $k_1$ is equal to $k$.
1. She combines the two secret messages with each of the possible keys, $m'_0 = (m_0 + k_0)\bmod N$ and $m'_1 = (m_1 + k_1)\bmod N$, and sends them both to Bob.
1. Bob knows $k$, so he is able to compute $m_b = (m'_b - k)\bmod N$. However, since he does not know $d$, he cannot compute $k_{1-b} = (v - x_{1-b})^d\bmod N$ and so cannot determine $(m_{1-b})\bmod N$.

## 1-out-of-*n* oblivious transfer and *k*-out-of-*n* oblivious transfer {#1-out-of-n_oblivious_transfer_and_k-out-of-n_oblivious_transfer}

A 1-out-of-*n* oblivious transfer protocol can be defined as a natural generalization of a 1-out-of-2 oblivious transfer protocol. Specifically, a sender has *n* messages, and the receiver has an index *i*, and the receiver wishes to receive the *i*-th among the sender's messages, without the sender learning *i*, while the sender wants to ensure that the receiver receive only one of the *n* messages.

1-out-of-*n* oblivious transfer is incomparable to [private information retrieval](https://en.wikipedia.org/wiki/Private_information_retrieval) (PIR). On the one hand, 1-out-of-*n* oblivious transfer imposes an additional privacy requirement for the database: namely, that the receiver learn at most one of the database entries. On the other hand, PIR requires communication [sublinear](https://en.wikipedia.org/wiki/Sublinear_time) in *n*, whereas 1-out-of-*n* oblivious transfer has no such requirement. However, assuming single server PIR is a sufficient assumption in order to construct 1-out-of-2 Oblivious Transfer.[^o10]

1-out-of-*n* oblivious transfer protocol with sublinear communication was first constructed (as a generalization of single-server PIR) by [Eyal Kushilevitz](https://en.wikipedia.org/wiki/Eyal_Kushilevitz) and [Rafail Ostrovsky](https://en.wikipedia.org/wiki/Rafail_Ostrovsky).[^o11] More efficient constructions were proposed by [Moni Naor](https://en.wikipedia.org/wiki/Moni_Naor) and [Benny Pinkas](https://en.wikipedia.org/wiki/Benny_Pinkas),[^o12] [William Aiello](https://en.wikipedia.org/wiki/William_Aiello), [Yuval Ishai](https://en.wikipedia.org/wiki/Yuval_Ishai) and [Omer Reingold](https://en.wikipedia.org/wiki/Omer_Reingold),[^o13] [Sven Laur](https://en.wikipedia.org/wiki/Sven_Laur) and [Helger Lipmaa](https://en.wikipedia.org/wiki/Helger_Lipmaa).[^o14] In 2017, [Kolesnikov et al.](https://en.wikipedia.org/wiki/Kolesnikov_et_al.),[^o15] proposed an efficient 1-n oblivious transfer protocol which requires roughly 4x the cost of 1-2 oblivious transfer in amortized setting.

[Brassard](https://en.wikipedia.org/wiki/Gilles_Brassard), [Crépeau](https://en.wikipedia.org/wiki/Claude_Crépeau) and [Robert](https://en.wikipedia.org/wiki/Jean-Marc_Robert) further generalized this notion to *k*-*n* oblivious transfer,[^o16] wherein the receiver obtains a set of *k* messages from the *n* message collection. The set of *k* messages may be received simultaneously ("non-adaptively"), or they may be requested consecutively, with each request based on previous messages received.[^o17]

## Generalized oblivious transfer {#Generalized_oblivious_transfer}

*k*-*n* Oblivious transfer is a special case of generalized oblivious transfer, which was presented by Ishai and Kushilevitz.[^o19] In that setting, the sender has a set *U* of *n* messages, and the transfer constraints are specified by a collection *A* of permissible subsets of *U*. The receiver may obtain any subset of the messages in *U* that appears in the collection *A*. The sender should remain oblivious of the selection made by the receiver, while the receiver cannot learn the value of the messages outside the subset of messages that he chose to obtain. The collection *A* is monotone decreasing, in the sense that it is closed under containment (i.e., if a given subset *B* is in the collection *A*, so are all of the subsets of *B*). The solution proposed by Ishai and Kushilevitz uses the parallel invocations of 1-2 oblivious transfer while making use of a special model of private protocols. Later on, other solutions that are based on [secret sharing](wikipedia://en/458253) were published – one by Bhavani Shankar, Kannan Srinathan, and [C. Pandu Rangan](https://en.wikipedia.org/wiki/C._Pandu_Rangan),[^o20] and another by Tamir Tassa.[^o21]

## Origins {#Origins}

In the early seventies [Stephen Wiesner](https://en.wikipedia.org/wiki/Stephen_Wiesner) introduced a primitive called **multiplexing** in his seminal paper "Conjugate Coding", which was the starting point of [quantum cryptography](wikipedia://en/28676005).[^o23] Unfortunately it took more than ten years to be published. Even though this primitive was equivalent to what was later called *1–2 oblivious transfer*, Wiesner did not see its application to cryptography.

## Quantum oblivious transfer {#Quantum_oblivious_transfer}

Protocols for oblivious transfer can be implemented with [quantum systems](https://en.wikipedia.org/wiki/Quantum_systems). In contrast to other tasks in [quantum cryptography](wikipedia://en/28676005), like [quantum key distribution](wikipedia://en/51910), it has been shown that quantum oblivious transfer cannot be implemented with unconditional security, i.e. the security of quantum oblivious transfer protocols cannot be guaranteed only from the laws of [quantum physics](https://en.wikipedia.org/wiki/Quantum_physics).[^o25]
