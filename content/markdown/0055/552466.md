# System identification

::: {#o1 .subject cue=lead name="System identification"}

The field of **system identification** uses [statistical methods](https://en.wikipedia.org/wiki/Statistical_method) to build [mathematical models](wikipedia://en/20590) of [dynamical systems](wikipedia://en/9087) from measured data.[^o2] System identification also includes the [optimal](https://en.wikipedia.org/wiki/Optimal_design#System_identification_and_stochastic_approximation) [design of experiments](wikipedia://en/9541) for efficiently generating informative data for [fitting](wikipedia://en/826997) such models as well as model reduction. A common approach is to start from measurements of the behavior of the system and the external influences (inputs to the system) and try to determine a mathematical relation between them without going into many details of what is actually happening inside the system; this approach is called **[black box](https://en.wikipedia.org/wiki/Black_box_%28systems%29)** system identification.

:::

## Overview {#Overview}

A dynamic mathematical model in this context is a mathematical description of the dynamic behavior of a [system](https://en.wikipedia.org/wiki/System) or process in either the time or frequency domain. Examples include:

- [physical](https://en.wikipedia.org/wiki/Physical_system) processes such as the movement of a falling body under the influence of [gravity](https://en.wikipedia.org/wiki/Gravity);
- [economic](https://en.wikipedia.org/wiki/Economic_system) processes such as international [trade](https://en.wikipedia.org/wiki/Trade) markets that react to external influences.

One of the many possible applications of system identification is in [control systems](wikipedia://en/7039). For example, it is the basis for modern [data-driven control systems](wikipedia://en/56275884), in which concepts of system identification are integrated into the controller design, and lay the foundations for formal [controller optimality](wikipedia://en/362565) proofs.

### Input-output vs output-only {#Input-output_vs_output-only}

System identification techniques can utilize both input and output data (e.g. [eigensystem realization algorithm](https://en.wikipedia.org/wiki/Eigensystem_realization_algorithm)) or can include only the output data (e.g. [frequency domain decomposition](wikipedia://en/35036820)). Typically an input-output technique would be more accurate, but the input data is not always available. In addition, the final estimated responses from arbitrary inputs can be analyzed by investigating their correlation and spectral properties.[^o5]

### Optimal design of experiments {#Optimal_design_of_experiments}

The quality of system identification depends on the quality of the inputs, which are under the control of the systems engineer. Therefore, systems engineers have long used the principles of the [design of experiments](wikipedia://en/9541).[^o7] In recent decades, engineers have increasingly used the theory of [optimal experimental design](https://en.wikipedia.org/wiki/Optimal_design) to specify inputs that yield [maximally precise](https://en.wikipedia.org/wiki/Efficient_estimator) [estimators](wikipedia://en/10043).[^o8][^o9]

## White-, grey-, and black-box {#White-,_grey-,_and_black-box}

*Image: System identification methods.png.* A diagram describing the different methods for identifying systems. In the case of a "white box" we clearly see the structure of the system, and in a "black box" we know nothing about it except how it reacts to input. An intermediate state is a "gray box" state in which our knowledge of the system structure is incomplete.

One could build a [white-box](https://en.wikipedia.org/wiki/White-box_testing) model based on [first principles](https://en.wikipedia.org/wiki/First_principles), e.g. a model for a physical process from the [Newton equations](wikipedia://en/55212), but in many cases, such models will be overly complex and possibly even impossible to obtain in reasonable time due to the complex nature of many systems and processes.

A more common approach is therefore to start from measurements of the behavior of the system and the external influences (inputs to the system) and try to determine a mathematical relation between them without going into the details of what is actually happening inside the system. This approach is called system identification. Two types of models are common in the field of system identification:

- **grey box model:** although the peculiarities of what is going on inside the system are not entirely known, a certain model based on both insight into the system and experimental data is constructed. This model does however still have a number of unknown free [parameters](wikipedia://en/25065) which can be estimated using system identification.[^o11][^o12] One example[^o13] uses the [Monod saturation model](wikipedia://en/34476926) for microbial growth. The model contains a simple hyperbolic relationship between substrate concentration and growth rate, but this can be justified by molecules binding to a substrate without going into detail on the types of molecules or types of binding. Grey box modeling is also known as semi-physical modeling.[^o14]
- **[black box](https://en.wikipedia.org/wiki/Black_box_%28systems%29) model:** No prior model is available. Most system identification algorithms are of this type.

In the context of [nonlinear system identification](wikipedia://en/40158142) Jin et al.[^o15] describe grey-box modeling by assuming a model structure a priori and then estimating the model parameters. Parameter estimation is relatively easy if the model form is known but this is rarely the case. Alternatively, the structure or model terms for both linear and highly complex nonlinear models can be identified using [NARMAX](wikipedia://en/40158142#NARMAX_methods) methods.[^o16] This approach is completely flexible and can be used with grey box models where the algorithms are primed with the known terms, or with completely black-box models where the model terms are selected as part of the identification procedure. Another advantage of this approach is that the algorithms will just select linear terms if the system under study is linear, and nonlinear terms if the system is nonlinear, which allows a great deal of flexibility in the identification.

## Identification for control {#Identification_for_control}

In [control systems](wikipedia://en/7039) applications, the objective of engineers is to obtain a [good performance](wikipedia://en/7039#Control_specification) of the [closed-loop](wikipedia://en/7039#Open-loop_and_closed-loop_%28feedback%29_control) system, which is the one comprising the physical system, the feedback loop and the controller. This performance is typically achieved by designing the control law relying on a model of the system, which needs to be identified starting from experimental data. If the model identification procedure is aimed at control purposes, what really matters is not to obtain the best possible model that fits the data, as in the classical system identification approach, but to obtain a model satisfying enough for the closed-loop performance. This more recent approach is called **identification for control**, or **I4C** in short.

The idea behind I4C can be better understood by considering the following simple example.[^o18] Consider a system with *true* [transfer function](wikipedia://en/31146) $G_0(s)$:

$$G_0(s) = \frac{1}{s+1}$$

and an identified model $\hat{G}(s)$:

$$\hat{G}(s) = \frac{1}{s}.$$

From a classical system identification perspective, $\hat{G}(s)$ is *not*, in general, a *good* model for $G_0(s)$. In fact, modulus and phase of $\hat{G}(s)$ are different from those of $G_0(s)$ at low frequency. What is more, while $G_0(s)$ is an [asymptotically stable](wikipedia://en/363360) system, $\hat{G}(s)$ is a simply stable system. However, $\hat{G}(s)$ may still be a model good enough for control purposes. In fact, if one wants to apply a [purely proportional](wikipedia://en/66256) [negative feedback](https://en.wikipedia.org/wiki/Negative_feedback) controller with high gain $K$, the closed-loop transfer function from the reference to the output is, for $G_0(s)$

$$\frac{KG_0(s)}{1+KG_0(s)} = \frac{K}{s+1+K}$$

and for $\hat{G}(s)$

$$\frac{K\hat{G}(s)}{1+K\hat{G}(s)} = \frac{K}{s+K}.$$

Since $K$ is very large, one has that $1+K \approx K$. Thus, the two closed-loop transfer functions are indistinguishable. In conclusion, $\hat{G}(s)$ is a *perfectly acceptable* identified model for the *true* system if such feedback control law has to be applied. Whether or not a model is *appropriate* for control design depends not only on the plant/model mismatch but also on the controller that will be implemented. As such, in the I4C framework, given a control performance objective, the control engineer has to design the identification phase in such a way that the performance achieved by the model-based controller on the *true* system is as high as possible.

Sometimes, it is even more convenient to design a controller without explicitly identifying a model of the system, but directly working on experimental data. This is the case of *direct* [data-driven control systems](wikipedia://en/56275884).

## Forward model {#Forward_model}

A common understanding in Artificial Intelligence is that the [controller](https://en.wikipedia.org/wiki/Controller_%28control_theory%29) has to generate the next move for a [robot](https://en.wikipedia.org/wiki/Robot). For example, the robot starts in the maze and then the robot decides to move forward. Model predictive control determines the next action indirectly. The term ["model"](wikipedia://en/20590) is referencing to a forward model which doesn't provide the correct action but simulates a scenario.[^o20] A forward model is equal to a [physics engine](https://en.wikipedia.org/wiki/Physics_engine) used in game programming. The model takes an input and calculates the future state of the system.

The reason why dedicated forward models are constructed is because it allows one to divide the overall control process. The first question is how to predict the future states of the system. That means, to simulate a [plant](https://en.wikipedia.org/wiki/Plant_%28control_theory%29) over a timespan for different input values. And the second task is to search for a [sequence](https://en.wikipedia.org/wiki/Sequence_of_events) of input values which brings the plant into a goal state. This is called predictive control.

The forward model is the most important aspect of a [MPC-controller](wikipedia://en/1100516). It has to be created before the [solver](https://en.wikipedia.org/wiki/Solver) can be realized. If it's unclear what the behavior of a system is, it's not possible to search for meaningful actions. The workflow for creating a forward model is called system identification. The idea is to [formalize a system](wikipedia://en/396102) in a set of equations which will behave like the original system.[^o21] The error between the real system and the forward model can be measured.

There are many techniques available to create a forward model: [ordinary differential equations](wikipedia://en/32742753) is the classical one which is used in [physics engines](https://en.wikipedia.org/wiki/Physics_engine) like [Box2D](https://en.wikipedia.org/wiki/Box2D). A more recent technique is a [neural network](https://en.wikipedia.org/wiki/Neural_network) for creating the forward model.[^o22]
