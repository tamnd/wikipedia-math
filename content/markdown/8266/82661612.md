# Move generation

::: {#o1 .subject cue=lead name="Move generation"}

**Move generation** is the computational process by which a program identifies the legal moves available from a given game state in [computer chess](https://en.wikipedia.org/wiki/Computer_chess) and generally other [strategy games](https://en.wikipedia.org/wiki/Strategy_game). In [general game playing](https://en.wikipedia.org/wiki/General_game_playing), the engine must produce only valid moves before evaluation can begin. Pseudo-legal moves follow basic movement rules, and fully legal moves satisfy all higher-level constraints such as [check (chess)](https://en.wikipedia.org/wiki/Check_%28chess%29). Because the number of possible positions grow [exponentially](wikipedia://en/99491) with [search depth](wikipedia://en/3509077), move generation has a major effect on speed and search.

:::

The field developed alongside early chess programming in the 1950s and later progressed through new board representations, [data structures](wikipedia://en/8519) and hardware support. Early systems depended on simple array-based boards and strict square-by-square testing, while later programs used methods such as the mailbox board, [rotated bitboards](https://en.wikipedia.org/wiki/Bitboard#rotated_bitboards) and [magic bitboards](https://en.wikipedia.org/wiki/Bitboard#Magic_bitboards). Some engines also used move generation using custom chips, like [Belle](https://en.wikipedia.org/wiki/Belle_%28chess_machine%29) and [Deep Blue](https://en.wikipedia.org/wiki/Deep_Blue_%28chess_computer%29).

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

In the context of computer chess and in general [strategic games](https://en.wikipedia.org/wiki/Strategy_game), move generation refers to the specific computational process where an [algorithm](wikipedia://en/775) identifies every legal transition from a given state.[^o4] This fundamental component of a [general game playing engine](https://en.wikipedia.org/wiki/General_game_playing) must follow the defined rules of the game to ensure the [search algorithm](https://en.wikipedia.org/wiki/Search_algorithm) only evaluates valid positions. Developers often distinguish between pseudo-legal moves, which follow basic piece movement patterns, and strictly legal moves that also include complex restrictions like [check (chess)](https://en.wikipedia.org/wiki/Check_%28chess%29).

The total number of potential outcomes grow exponentially as the [search depth](wikipedia://en/3509077) increases.[^o5] [Bitboards](https://en.wikipedia.org/wiki/Bitboard) represent the game state through [64-bit integers](https://en.wikipedia.org/wiki/64-bit_computing). Bitboards use [bitwise operations](wikipedia://en/264399) to calculate piece movements efficiently.[^o6] Pseudo-legal generation speeds up the calculation process further by temporarily ignoring whether a move accidentally leaves the king in check. Advanced systems integrate precomputed attack tables for "sliding pieces" like rooks and queens to eliminate redundant real-time processing.[^o7]

:::

## History {#History}

*Image: Deep\_Blue.jpg.* IBM Deep Blue, a chess computer that used [chess chips](https://en.wikipedia.org/wiki/Deep_Blue_%28chess_computer%29#Hardware) to accelerate move generation and search.

Move generation developed during the 1950s alongside the foundational concepts of [Alan Turing](wikipedia://en/1208) and [Claude Shannon](wikipedia://en/5693).[^o9][^o10] Early programs ran on massive [mainframe computers](https://en.wikipedia.org/wiki/Mainframe_computer) and relied on piece-centric array systems to determine valid board moves, because physical [computer memory](https://en.wikipedia.org/wiki/Computer_memory) was limited, engineers had to write highly restrictive instructions that checked every square on the board sequentially.[^o11]

During the 1970s, researchers at [Northwestern University](https://en.wikipedia.org/wiki/Northwestern_University) created the Chess series of programs, which introduced advanced board representations to reduce redundant processing loops.[^o12] The introduction of the mailbox board design provided quick [out-of-bounds](https://en.wikipedia.org/wiki/Bounds_checking) error handling; at the same time, university labs started experimenting with custom microchips engineered to execute move generation tasks directly in hardware.[^o13]

The [Belle](https://en.wikipedia.org/wiki/Belle_%28chess_machine%29) [chess engine](https://en.wikipedia.org/wiki/Chess_engine) demonstrated that offloading the move generation loop to custom circuitry could increase the number of nodes evaluated per second, and this hardware approach led to [Deep Blue](https://en.wikipedia.org/wiki/Deep_Blue_%28chess_computer%29).[^o14]

Calculating sliding attacks for rooks and bishops remained a problem because other pieces blocked them, requiring programs to track board occupancy, so software engineers resolved this issue by using [rotated bitboards](https://en.wikipedia.org/wiki/Bitboard#Rotated_bitboards). However, rotated bitboards still needed additional processing time to keep the various board views synchronized after every single move.[^o15] To overcome the [computational overhead](https://en.wikipedia.org/wiki/Overhead_%28computing%29) of rotated bitboards, developers invented [magic bitboards](https://en.wikipedia.org/wiki/Bitboard#Magic_bitboards) to handle sliding piece generation using [hashing](https://en.wikipedia.org/wiki/Zobrist_hashing). The engine only verifies the legality of a move if the search algorithm decides to explore that specific [branch](https://en.wikipedia.org/wiki/Branch_%28computer_science%29), which saves valuable [computing cycles](https://en.wikipedia.org/wiki/Instruction_cycle) on paths that are pruned.[^o16]

## Core concepts {#Core_concepts}

Move generation depends on [memory architecture](https://en.wikipedia.org/wiki/Memory_architecture), state tracking, and algorithmic verification to populate the game tree. The [data structure](wikipedia://en/8519) chosen for move representation must pack original squares, target squares, and special flags into compact [bit fields](https://en.wikipedia.org/wiki/Bit_field) to conserve [system memory](https://en.wikipedia.org/wiki/System_memory).[^o18] The generator then processes these structures through either pseudo-legal or strict legal move filters. Pseudo-legal generation speeds up the initial phase by delaying king safety checks while legal generation immediately validates all spatial and tactical constraints before passing data to the search loop.[^o19]

### Legal moves and pseudo-legal moves {#Legal_moves_and_pseudo-legal_moves}

In [abstract strategy game](https://en.wikipedia.org/wiki/Abstract_strategy_game) programming, a pseudo-legal move represents any action that follows basic piece mechanics but ignores broader constraints like immediate loss conditions.[^o21] The engine checks whether the move follows to movement rules of the game. but this calculation does not check if the move violates the rules of its corresponding game. Generating these moves requires very little [computation](wikipedia://en/5926) because the system skips complex safety verification steps.[^o22]

A legal move must satisfy every rule of the game and also preserve all mandatory safety requirements in the game states. Engines filter out illegal moves by simulating the action and analyzing the next board position.[^o23] If the simulated state reveals that the player or the engine has violated a core rule or allowed an instant defeat in the game, the engine rejects the move.[^o21]

### Move representation {#Move_representation}

In [game theory](wikipedia://en/11924) and computer game playing, a move representation defines the internal data structure used to encode a player's legal action within a specific board state. This architectural choice directly determines the computational efficiency of the broader move generation subsystem across various strategic games like [chess](https://en.wikipedia.org/wiki/Chess), [shogi](https://en.wikipedia.org/wiki/Shogi), and [Go](https://en.wikipedia.org/wiki/Go_%28game%29). Developers often pack critical execution data into a single [16-bit](https://en.wikipedia.org/wiki/16-bit_computing) or [32-bit](https://en.wikipedia.org/wiki/32-bit_computing) [integer](https://en.wikipedia.org/wiki/Integer_%28computer_science%29) by using [bitmask](https://en.wikipedia.org/wiki/Mask_%28computing%29) operators to save [cache memory](https://en.wikipedia.org/wiki/Cache_%28computing%29) and minimize overhead.[^n1] This compressed format typically holds the starting coordinate, the arrival coordinate, the moving piece type, and the distinct flag [bits](https://en.wikipedia.org/wiki/Bit) for special moves in chess like [castling](https://en.wikipedia.org/wiki/Castling), [en passant](https://en.wikipedia.org/wiki/En_passant), or piece [promotion](https://en.wikipedia.org/wiki/Promotion_%28chess%29).[^o26]

### Board representation {#Board_representation}

Board representation is the internal model a game engine uses to store the current position, and for board games it can be built in several ways. The bitboard method represents a board game by encoding various information about the position.[^o28] Move generation reads that encoded position to determine the legal continuations, so the representation has to make occupied squares, piece types, and other such rule data available to query.[^o9]

The choice of move generator applies to how it works during search. Specifically, the move generation is used many times, meaning an efficient generator is needed to maintain performance. This efficiency can be achieved by storing all possible moves in precomputed data so the program can access them quickly.[^n2] For non-sliding pieces, this lets the program filter destination squares directly from cached move sets, while sliding pieces need extra data tied to rank, file, or diagonal occupancy because their legal moves depend on the current line on the board.[^o30]

## Generation methods {#Generation_methods}

Move generation methods define the specific instructions and [computer code](https://en.wikipedia.org/wiki/Computer_code) used to calculate all valid actions a general game playing engine can execute from a specific state. Within these generation methods, move generation works as the core component that fills the [search tree](https://en.wikipedia.org/wiki/Search_tree), directly determining the speed and accuracy of the next evaluation phase. Programs apply rule-based generation to enforce complex game constraints sequentially, ensuring total legality at the cost of processing speed.[^o32]

Piece-based generation scans only the active pieces on the board to find potential actions.[^n3] General game playing engines simplify this process by using table-driven and lookup-based methods, which pull precalculated moves from memory to bypass [real-time computation](https://en.wikipedia.org/wiki/Real-time_computing).[^o34]

Bitboards, and other similar variants like PEXT Bitboard, rotated bitboards, use parallel bitwise operations on [binary arrays](https://en.wikipedia.org/wiki/Bit_array) to find valid moves instantly.[^o35] Incremental and cached generation methods reuse calculations from previous turns, updating only the specific parts of the board that changed.[^o36]

### Rule-based move generation {#Rule-based_move_generation}

Rule-based move generation uses explicit code to apply the rules of a game to a specific state.[^o38] A specialized function basically implements all of the rules to strictly verify which actions are valid. This process generates a list of all the legal moves as output, ensuring the software knows all rules before it begins any strategic search. Incremental generation will usually work faster than listing every option immediately, allowing the engine to process strictly necessary branches first.

### Piece-based move generation {#Piece-based_move_generation}

Piece-based move generation is an algorithmic approach in computer chess that scans the board to locate individual pieces and calculates their legal destinations one by one.[^o40] In move generation, this strategy isolates each active piece on the [chessboard](https://en.wikipedia.org/wiki/Chessboard) to determine it's valid moves.[^n4]

The engine uses specialized data structures like [mailbox arrays](https://en.wikipedia.org/wiki/0x88) or bitboards to identify piece coordinates sequentially. For each piece found, the system applies sliding piece or stepper piece rules to find empty squares or enemy captures.
