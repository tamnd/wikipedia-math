# Password manager

*Image: Bitwarden Desktop 2025.7.0 screenshot.webp.* [Bitwarden](wikipedia://en/59045761) is an example of a password manager. Pictured above is its vault interface showing a saved login entry, which keeps one's usernames and passwords.

::: {#o1 .subject cue=lead name="Password manager"}

A **password manager** is [software](https://en.wikipedia.org/wiki/Software) that stores [usernames](https://en.wikipedia.org/wiki/User_%28computing%29) and [passwords](wikipedia://en/24304) in a collection called a *password vault*. The vault is intended to be [encrypted](wikipedia://en/10294), and its [encryption key](wikipedia://en/53039) is commonly derived from a master password chosen by the user. Most password managers can generate passwords, save credentials as they are entered, and fill them when the user returns. Some can also synchronize records between devices, share credentials with other users, and store payment-card details, notes, and documents.

:::

Password managers are available as standalone [applications](https://en.wikipedia.org/wiki/Application_software), [browser extensions](https://en.wikipedia.org/wiki/Browser_extensions), features built into [web browsers](https://en.wikipedia.org/wiki/Web_browser), and services integrated with an [operating system](https://en.wikipedia.org/wiki/Operating_system). A vault may remain on one device, be synchronized through a provider's [servers](https://en.wikipedia.org/wiki/Server_%28computing%29), or be copied between devices through a separate [file-storage service](https://en.wikipedia.org/wiki/Cloud_storage). By generating and storing a different password for each account, a password manager can reduce the need to memorize many passwords or reuse the same password across accounts.

Because a single vault may contain credentials for many accounts, the vault and its master password are valuable targets for attack. Security depends on how the vault is protected and on features such as autofill, synchronization, sharing, and account recovery. Users may also avoid or stop using password managers because of concerns about security or control, inconvenience, or compatibility with websites.

Password managers have existed since the 1990s. They later became available as browser components, [mobile applications](https://en.wikipedia.org/wiki/Mobile_app), cloud-based services, and features built into an [operating system](https://en.wikipedia.org/wiki/Operating_system). Some password managers can also create and store [passkeys](wikipedia://en/73655368), login credentials based on [public-key cryptography](wikipedia://en/24222) that can replace passwords or serve as an additional [authentication factor](wikipedia://en/47967#Authentication_factors).

## Operation and features {#Operation_and_features}

A password manager keeps [login](https://en.wikipedia.org/wiki/Login) [credentials](https://en.wikipedia.org/wiki/Credential#Information_technology), such as [usernames](https://en.wikipedia.org/wiki/User_%28computing%29) and [passwords](wikipedia://en/24304), in a repository known as a *password vault*.[^n1] Ideally, the vault is [encrypted](wikipedia://en/10294) using a key generated from a password chosen by the user, commonly known as the *master password*.[^n1] Some password managers offer [multi-factor authentication](https://en.wikipedia.org/wiki/Multi-factor_authentication) for access to the password database.[^n2] [Cloud](https://en.wikipedia.org/wiki/Cloud_computing)-based password managers generally keep [server](https://en.wikipedia.org/wiki/Server_%28computing%29)-side vault data encrypted while encryption and decryption are performed by the user's client. The [client](https://en.wikipedia.org/wiki/Client_%28computing%29) sends encrypted data to the service and decrypts retrieved data locally.[^n3]

Password generation is a common feature of modern password managers, where users can configure properties such as length, permitted characters, and composition requirements.[^n1] Because the result is stored in the vault, users can assign separate generated passwords to different accounts without memorizing each one.[^n4] Some password managers also flag duplicate passwords or credentials that may need to be changed.[^n5] When a user enters a password manually on a login form, the password manager may prompt them to add that credential to the vault.[^n6] When the user returns, it can match the stored record to the site and fill the username and password fields.[^n7] Autofill may occur automatically or require user interaction, depending on the password manager and context. If several accounts are stored for a site, the user can select which account to use.[^n8]

Cloud-based services can synchronize an encrypted vault so that the same records are available on several devices.[^n3] Some cloud services support sharing vault data with other authorized users, including household or organizational groups, and may also provide [account-recovery](https://en.wikipedia.org/wiki/Data_recovery) features.[^n9] Vaults can also contain non-login information, such as [payment-card](https://en.wikipedia.org/wiki/Payment_card) details, notes, and personal documents.[^n9]

## Deployment models {#Deployment_models}

Password managers may be standalone applications, [browser extensions](https://en.wikipedia.org/wiki/Browser_extension), or features built into a [web browser](https://en.wikipedia.org/wiki/Web_browser). Some products are available in more than one of these forms.[^n10] A desktop application may work with a browser extension to fill saved credentials into website login forms.[^n10] Apple's [iCloud](https://en.wikipedia.org/wiki/ICloud) Keychain can enable passwords and [passkey](wikipedia://en/73655368) synchronization across [Apple](https://en.wikipedia.org/wiki/Apple_Inc.) devices approved by the user.[^n11] In [Google](https://en.wikipedia.org/wiki/Google)'s ecosystem, passwords and passkeys can be saved to a [Google Account](https://en.wikipedia.org/wiki/Google_Account) and used to sign in to apps and websites on devices using that account.[^n12]

A locally maintained password database is stored on the user's own device rather than on a provider-controlled server.[^n2] Some standalone password managers require users to synchronize their vaults manually rather than providing built-in cloud synchronization.[^n10] A vault file can instead be synchronized between devices through a separate file-sync service rather than through the password manager provider.[^n13] A separate backup helps preserve access to a locally maintained password database if the device is lost or stolen.[^n2]

In a cloud-synchronized password manager, encrypted vault data is kept on a remote server and synchronized with the user's devices.[^n3] Some services allow organizations to run the storage server on their own systems instead of using the vendor's server.[^n3] [Bitwarden](wikipedia://en/59045761) organizations can group shared records into collections and assign access to individual users or groups.[^n14] [1Password](https://en.wikipedia.org/wiki/1Password) Business provides administrative policies for authentication, sharing and permissions, and single sign-on.[^n15]

## History {#History}

Password management software dates back to the 1990s.[^n16] PassKeeper was available by March 1996.[^n17] The [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows)-based utility lets users to organize credentials and notes in an encrypted file.[^n18] In September 1997, Counterpane Systems released [Password Safe](wikipedia://en/1846387), a free utility for [Windows 95](https://en.wikipedia.org/wiki/Windows_95).[^n19] It stored its password database on the user's computer, protected it with Blowfish encryption, and used a single "Safe Combination" to access the saved passwords.[^n20] The first version of [1Password](https://en.wikipedia.org/wiki/1Password), then named 1Passwd, was released on May 19, 2006 and [LastPass](https://en.wikipedia.org/wiki/LastPass) was founded in 2008.[^n21][^n22] [Dashlane](https://en.wikipedia.org/wiki/Dashlane) had been operating since 2012,[^n23] and the [open-source](https://en.wikipedia.org/wiki/Open-source_software) [Bitwarden](wikipedia://en/59045761) launched in 2016.[^n24]

In June 2013, [Apple](https://en.wikipedia.org/wiki/Apple_Inc.) announced [iCloud Keychain](https://en.wikipedia.org/wiki/ICloud_Keychain) for [OS X Mavericks](https://en.wikipedia.org/wiki/OS_X_Mavericks). The built-in password manager used [iCloud](https://en.wikipedia.org/wiki/ICloud) to synchronize passwords only with trusted devices.[^n25] By 2014, password managers were built into browsers, offered by third parties, and available on mobile platforms. Some also backed up passwords to the cloud and synchronized them across devices.[^n26] In 2022, [Google](https://en.wikipedia.org/wiki/Google) began rolling out a common password-management interface in [Chrome](https://en.wikipedia.org/wiki/Google_Chrome) and [Android](https://en.wikipedia.org/wiki/Android_%28operating_system%29) settings.[^n27] Apple released the Keychain-based Passwords app in 2024 for accessing credentials including passwords, passcodes, and verification codes.[^n28]

## Security model {#Security_model}

When properly implemented and used, a password manager makes it practical to use a different generated password for each account without having to remember them all.[^n1] Use of password managers is associated with stronger password choices, particularly when a password generator is included.[^n29] Because one vault may contain credentials for many accounts, the password manager and its master password are valuable targets for attack.[^n30] One threat model assumes that the password manager server is fully malicious and may depart arbitrarily from its expected behavior. Under this model, expected protections include keeping vault contents secret, detecting unauthorized changes to vault data and metadata, and limiting sharing and account recovery to the intended users.[^n9]

### Vault protection {#Vault_protection}

The master password is commonly used to create the key that encrypts the vault.[^n1] An attacker who obtains a copy of an encrypted vault may try to guess its master password offline. To make offline guessing more expensive, password managers commonly apply deliberately slow password-based key derivation or hashing to the master password.[^n31] In a 2020 evaluation, some password managers left particular metadata unencrypted, including [site addresses](https://en.wikipedia.org/wiki/URL), usernames, account-use information, or security-related settings, depending on the product.[^n8] If integrity checks do not cover the vault as a whole, a malicious server may be able to alter, remove, or rearrange vault data without detection.[^n9]

### Autofill and phishing {#Autofill_and_phishing}

Password managers generally associate stored credentials with particular websites and may decline to suggest or fill them when the current address does not match.[^n30] Automatic filling can expose a stored password to malicious code on a compromised page without requiring the user to select the credential.[^n8] In a 2014 test, six of ten password managers were vulnerable to an attack in which a rogue [Wi-Fi](https://en.wikipedia.org/wiki/Wi-Fi) network loaded login pages in invisible frames and captured autofilled passwords.[^n32] Requiring the user to initiate filling prevents this kind of silent sweep attack, but user interaction alone does not eliminate all autofill risks.[^n33]

A malicious website can also imitate the unlock interface of a password manager [browser extension](https://en.wikipedia.org/wiki/Browser_extension).[^n30] In a 2025 [phishing](https://en.wikipedia.org/wiki/Phishing) simulation involving 29,809 people at an educational institution, one of four targeted third-party password managers was detected in 448 participants. One hundred and forty of those users (31.25%) entered their master password into the imitation interface.[^n34] A stolen master password can expose stored credentials, and phishing-resistant multi-factor authentication adds a separate barrier to using the stolen password.[^n35]

### Client security {#Client_security}

A password manager's client can be targeted through malicious websites, rogue applications on the user's device, or adversarial networks.[^n31] Browser-based autofill can be abused when credentials are released to a compromised page. User interaction prompts can themselves be exploited through [clickjacking](https://en.wikipedia.org/wiki/Clickjacking), where a deceptive page conceals or disguises the control being activated.[^n36] These client-side and network attacks differ from offline attacks in which an adversary first obtains an encrypted copy of the vault.[^n31]

### Cloud storage, sharing, and recovery {#Cloud_storage,_sharing,_and_recovery}

Cloud-based password managers often describe their client-side encryption as "[zero-knowledge encryption](https://en.wikipedia.org/wiki/Zero-knowledge_service)". In this usage, encryption is intended to prevent the provider from seeing the [plaintext](wikipedia://en/157935) contents of the vault.[^n3] The term has no strict technical definition. A 2026 analysis interpreted the vendors' security claims as implying protection even when the server behaves maliciously.[^n37] That analysis identified 25 attacks against [Bitwarden](wikipedia://en/59045761), [LastPass](https://en.wikipedia.org/wiki/LastPass), and [Dashlane](https://en.wikipedia.org/wiki/Dashlane) under this malicious-server threat model.[^n3] The attacks involved weaknesses in account recovery and sharing, failures to verify public keys, incomplete protection against changes to an entire vault, and legacy cryptographic compatibility.[^n9]

A 2024 study examined [injection](https://en.wikipedia.org/wiki/Code_injection) attacks in which a victim first accepts a shared item that the attacker can later update. Depending on the product, those updates could affect password-health metrics, site-icon requests, compressed vault size, or attachment deduplication.[^n38] Across the ten password managers studied, different attack variants could reveal passwords, usernames, website addresses, or attachment contents.[^n31] The first four vendors notified had deployed mitigations by the time of the study's publication, but disclosure to the remaining six was still underway. The paper described general-purpose detection and mitigation techniques against injection attacks as a direction for future research.[^n39]

### Password generation {#Password_generation}

The strength of a generated password depends on how unpredictably it is chosen and on settings such as its length and the characters the generator can use.[^n40] A 2020 evaluation generated 147 million passwords and found a small fraction of shorter outputs vulnerable to guessing attacks, including passwords under 10 characters in its online-attack tests and under 18 in its offline-attack tests.[^n41]

A flaw reported in [Kaspersky](https://en.wikipedia.org/wiki/Kaspersky_Lab) Password Manager used the system time to seed a pseudorandom-number generator that was not intended for cryptographic use.[^n42] Because system time was used as the seed, Kaspersky Password Manager could generate the same password on different installations during the same second. Information about when a password was generated could substantially narrow the guesses an attacker needed to try.[^n43] Kaspersky rolled out fixes between October and December 2019 and added a warning in October 2020 telling users to regenerate affected weak passwords.[^n42]

## Usability and human factors {#Usability_and_human_factors}

Password managers can reduce the burden of remembering many passwords, but using them also involves choices about trust, handling master password, password generation, and synchronization.[^n44] When they do not work as intended, some users resort to less secure methods, such as reusing old weak passwords or recording passwords outside the password manager.[^n45]

### Adoption and trust {#Adoption_and_trust}

A 2019 interview study of 30 password manager users and non-users found that those who relied on password managers built into browsers or [operating systems](https://en.wikipedia.org/wiki/Operating_system) were often drawn to them by convenience, while users who had installed a separate password manager more often named security as a reason for doing so.[^n46] Barriers to adopting a separate password manager included limited awareness, security concerns, a sense that there were too few passwords or little important data to justify using one, and discomfort with generated passwords that could not be remembered.[^n46] Some participants were unsure whether password-saving prompts came from the browser, the website, or the computer, and also where saved passwords were stored or whether the provider could read them.[^n46]

A 2021 interview study examined 26 adults over the age of 60, whose average age was 70.4 years.[^n47] Participants expressed concern about cloud storage, cross-device synchronization, loss of control over private information, and the consequences of keeping many passwords behind one point of access.[^n48] Recommendations and advice from family members or close friends were important influences on adoption among these participants.[^n49]

### Setup and routine use {#Setup_and_routine_use}

A longitudinal study gave 37 first-time users a three-month password manager license and surveyed them weekly during the first month, with a final follow-up. Of the 33 who completed the first weekly questionnaire, 19 remained by week four, a 42% drop.[^n50] Participants who later dropped out had lower first-week usability ratings than those who remained through week four.[^n51] Reported trust increased over the study, while usability ratings among the 19 participants who completed all four weekly questionnaires stayed roughly stable.[^n51]

Participants often found repeated master-password entry frustrating. When asked how they had created their master password, 44% of the responses described total or partial reuse of an existing password or personal information.[^n52] By week four, 78.94% of the remaining participants had warnings for weak or reused passwords. Despite seeing the password-health dashboard each week, none of them changed those credentials during the study.[^n53] Interviews in 2019 similarly found that users often retained weak or reused passwords when they first adopted a separate password manager and replaced them gradually over time.[^n54]

Compatibility problems can interrupt registration or login when a password manager fails to offer password generation, saves or fills a credential incorrectly, or generates a password that the website rejects.[^n55]

### Effects on password practices {#Effects_on_password_practices}

Using password managers is not consistently associated with stronger passwords or less reuse. Outcomes vary with how passwords are created, stored, and entered.[^n56] A 2018 study surveyed 476 people and collected browser data from 170 of them. In the browser sample, users who relied on password generators had stronger passwords and less reuse than those who created passwords manually.[^n56] Among recorded entries, 20% of Chrome-autofilled passwords and 25% of manually entered passwords were not reused, compared with 53% for LastPass and 78% for copy-and-paste. However, the study cautioned that the copy-and-paste subgroup was too small for firm conclusions.[^n57]

In an online experiment using simulated browser password manager prompts, the prompt design was associated with whether participants used the generated password.[^n58] Among 558 participants, 61.5% in the simulated [Safari](https://en.wikipedia.org/wiki/Safari_%28web_browser%29) condition used the generated password, compared with 35.2% in the Chrome condition and 41% in the [Firefox](https://en.wikipedia.org/wiki/Firefox) condition. The difference was statistically significant.[^n59] Acceptance was higher among participants who noticed the prompt and among those who had used a password generator before. Prior password manager use itself was not significantly associated with acceptance.[^n60]

## Adoption {#Adoption}

In a nationally representative [Pew Research Center](https://en.wikipedia.org/wiki/Pew_Research_Center) survey of 5,101 U.S. adults conducted in May 2023, 32% reported using a password manager, up from 20% in 2019.[^n61] Reported use was 49% among adults ages 18–29 and 37% among those ages 30–49. For adults aged 50 or above, the share was 25% or less.[^n61] Use also varied by education, where the reported use was 26% among adults with a high school education or less, 34% among those with some college education, and 38% among those with a bachelor's degree or higher.[^n61]

The Australian Cybercrime Survey estimated secure password manager usage at 25.0% in 2023 and 26.8% in 2024, after adjusting for differences between the samples in both years.[^n62] The survey did not use a nationally representative probability sample, and participants were drawn from opt-in online research panels.[^n63] Sampling quotas covered age, gender and place of residence, while weighting accounted for age, place of residence, education, internet use and social-media use.[^n64]

In an October 2024 online poll of 1,000 U.S. adults, 32% of password manager users primarily used Google Password Manager, followed by Apple's [iCloud](https://en.wikipedia.org/wiki/ICloud) Keychain or Passwords app at 23%, LastPass at 11%, and Bitwarden at 10%. In the same poll, 79% of password manager users said that they paid nothing for the service.[^n65]

## Interaction with websites and applications {#Interaction_with_websites_and_applications}

### Web forms {#Web_forms}

On a website, a password manager needs to recognize which fields contain a username, an existing password, or a new password so it can handle the credentials correctly.[^n66] The HTML `autocomplete` attribute can label these fields as `username`, `current-password`, and `new-password`, indicating what kind of value each field expects.[^n67] Standard HTML forms, appropriate input types, and correctly chosen `autocomplete` values make it easier for password managers to recognize fields and offer the appropriate generation, saving, or autofill action.[^n66]

Password managers can still run into problems when a site uses non-standard forms or password requirements that conflict with passwords generated by the password manager.[^n68] Testing from June to December 2022 found registration or login usability issues on more than a quarter of the 61 websites for which testing was completed, but the rate varied among Chrome, Safari, Bitwarden, and [Keeper](https://en.wikipedia.org/wiki/Keeper_%28password_manager%29).[^n69] Among the 60 websites where passwords were generated, 19 rejected at least one password produced by the four tested password managers because it conflicted with the site's password requirements.[^n70]

### Restrictions and compatibility {#Restrictions_and_compatibility}

Some websites have tried to limit password manager usage by blocking pasted passwords or by using HTML settings that ask browsers not to save or automatically fill login fields. In 2015, [British Gas](https://en.wikipedia.org/wiki/British_Gas) used `onpaste="return false"` on a password field and said it had chosen not to provide compatibility with password managers. Following criticism, the company said it would reconsider its approach.[^n71] Paste restrictions were also found on [T-Mobile](https://en.wikipedia.org/wiki/T-Mobile_US), the German [Barclaycard](https://en.wikipedia.org/wiki/Barclaycard) site, and [Western Union](https://en.wikipedia.org/wiki/Western_Union). T-Mobile said its restriction was unintended and later removed it.[^n72]

A site can use `autocomplete="off"` to ask the browser not to retain a field's value for later auto-completion, but modern browsers generally ignore it for username and password fields.[^n73] For other fields, `autocomplete="off"` can still discourage later auto-completion. A password field meant for a newly assigned password can instead use `autocomplete="newpassword"`.[^n73]

The [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) (NIST) guidance, *NIST SP 800-63B*, requires password verifiers to allow password managers and autofill, and recommends allowing passwords to be pasted when autofill [APIs](https://en.wikipedia.org/wiki/API) are unavailable.[^n29] [OWASP](https://en.wikipedia.org/wiki/OWASP) (Open Worldwide Application Security Project), in its Authentication Cheat Sheet, similarly recommends standard HTML username and password fields, support for passwords up to at least 64 characters and for printable characters, and the ability to paste into username, password, and multifactor authentication fields.[^n74]

### Native applications {#Native_applications}

[Android version 8](https://en.wikipedia.org/wiki/Android_Oreo) and later versions provide an autofill framework that lets services such as password managers fill supported fields in other apps.[^n75] A newer Credential Manager integration lets apps link username and password fields to credential requests, so credentials from available providers can appear in autofill suggestions.[^n76]

Apple's Password AutoFill links an app to a website through an associated-domain relationship. Developers set this up by declaring the domain in the app's entitlement and publishing a matching association file on the website.[^n77] Inline Password AutoFill suggestions are limited to credentials for the app's associated domains, but users can open the system credential list to choose another saved login.[^n78] Developers can identify text fields as username, password, new-password, or other supported content types so Password AutoFill can present suitable suggestions.[^n79]

## Relationship to passkeys {#Relationship_to_passkeys}

Some password managers can also act as providers for [passkeys](wikipedia://en/73655368), creating, storing, and managing them for the user.[^n80] A passkey is a login credential based on [public-key cryptography](wikipedia://en/24222), using a public key stored by the service and a corresponding private key kept by the user's authenticator.[^n81] Unlike passwords, passkeys do not require the user to send a shared secret to the website. The user instead approves the sign-in through the device or password manager, and the service verifies a cryptographic response.[^n80][^n81]

A passkey may remain on one authenticator or be synchronized by a provider across several of the user's devices.[^n80] Synchronization can make existing passkeys available on a replacement device without requiring the user to register a separate passkey for each device.[^n82] A properly configured synced passkey is tied to the site for which it was registered, so an authentication response obtained by a phishing site cannot be reused at the legitimate service.[^n29] When synchronized passkeys are backed up by a cloud-based provider, however, compromise of that storage can expose their private signing keys.[^n83]
