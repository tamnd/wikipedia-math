# SPKAC

::: {#o1 .subject cue=lead name="SPKAC"}

**SPKAC** (**Signed Public Key and Challenge**, also known as **Netscape SPKI**) is a format for sending a [certificate signing request](wikipedia://en/1124588) (CSR): it encodes a [public key](https://en.wikipedia.org/wiki/Public_key), that can be manipulated using [OpenSSL](wikipedia://en/438819).[^o2] It is created using the little documented [HTML](https://en.wikipedia.org/wiki/HTML) [keygen](wikipedia://en/180457) element[^o3] inside a number of [Netscape compatible browsers](https://en.wikipedia.org/wiki/Netscape_%28web_browser%29).

:::

## Standardisation {#Standardisation}

There exists an ongoing effort to standardise SPKAC through an [Internet Draft](https://en.wikipedia.org/wiki/Internet_Draft) in the [Internet Engineering Task Force](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) (IETF). The purpose of this work has been to formally define what has existed prior as a [de facto](https://en.wikipedia.org/wiki/De_facto) standard, and to address security deficiencies, particular with respect to historic insecure use of [MD5](wikipedia://en/18826) that has since been declared unsafe for use with [digital signatures](wikipedia://en/59644).6151

::: {#o6 .definition kind=definition/construction cue=heading name="Implementations"}

## Implementations {#Implementations}

[HTML5](https://en.wikipedia.org/wiki/HTML5) originally specified the `<keygen>` element to support SPKAC in the browser to make it easier to create [client side](https://en.wikipedia.org/wiki/Client_side) certificates through a [web service](https://en.wikipedia.org/wiki/Web_service) for protocols such as [WebID](https://en.wikipedia.org/wiki/WebID);[^o7][^o8] however, subsequent work for HTML 5.1 placed the keygen element "at-risk", and the first public working draft of HTML 5.2 removes the keygen element entirely.[^o9][^o10][^o11] The removal of the keygen element is due to non-interoperability and non-conformity from a standards perspective in addition to security concerns.[^o12]

The [World Wide Web Consortium](https://en.wikipedia.org/wiki/World_Wide_Web_Consortium) (W3C) Web Authentication Working Group developed the [WebAuthn](https://en.wikipedia.org/wiki/WebAuthn) (Web Authentication) API to replace the keygen element.[^o13]

[Bouncy Castle](wikipedia://en/3636963) provides a Java class.[^o14][^o15]

An implementation for [Erlang/OTP](https://en.wikipedia.org/wiki/Erlang_%28programming_language%29) exists too.[^o16]

An implementation for [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) is named pyspkac.[^o17]

PHP OpenSSL extension as of version 5.6.0.[^o18]

[Node.js](https://en.wikipedia.org/wiki/Node.js) implementation.[^o19]

### Deficiencies {#Deficiencies}

The user interface needs to be improved in browsers, to make it more obvious to users when a server is asking for the [client certificate](https://en.wikipedia.org/wiki/Client_certificate).[^o21]
