# Parametricity

::: {#o1 .subject cue=lead name="Parametricity"}

In [programming language theory](https://en.wikipedia.org/wiki/Programming_language_theory), **parametricity** is an abstract uniformity property enjoyed by [parametrically polymorphic](https://en.wikipedia.org/wiki/Parametric_polymorphism) functions, which captures the intuition that all instances of a polymorphic function act the same way.

:::

## Idea {#Idea}

Consider this example, based on a set *X* and the type *T*(*X*) = \[*X* → *X*\] of functions from *X* to itself. The higher-order function *twice*<sub>*X*</sub> : *T*(*X*) → *T*(*X*) given by *twice*<sub>*X*</sub>(*f*) = *f* ∘ *f*, is intuitively independent of the set *X*. The family of all such functions *twice*<sub>*X*</sub>, parametrized by sets *X*, is called a "[parametrically polymorphic function](https://en.wikipedia.org/wiki/Parametric_polymorphism)". We simply write **twice** for the entire family of these functions and write its type as $\forall$*X*. *T*(*X*) → *T*(*X*). The individual functions *twice*<sub>*X*</sub> are called the *components* or *instances* of the polymorphic function. Notice that all the component functions *twice*<sub>*X*</sub> act "the same way" because they are given by the same rule. Other families of functions obtained by picking one arbitrary function from each *T*(*X*) → *T*(*X*) would not have such uniformity. They are called ["*ad hoc* polymorphic functions"](https://en.wikipedia.org/wiki/Ad_hoc_polymorphism). *Parametricity* is the abstract property enjoyed by the uniformly acting families such as **twice**, which distinguishes them from *ad hoc* families. With an adequate formalization of parametricity, it is possible to prove that the parametrically polymorphic functions of type $\forall$*X*. *T*(*X*) → *T*(*X*) are one-to-one with natural numbers. The function corresponding to the natural number *n* is given by the rule *f* $\mapsto$ *f*<sup>*n*</sup>, i.e., the polymorphic [Church numeral](wikipedia://en/2989409) for *n*. In contrast, the collection of all *ad hoc* families would be too large to be a set.

## History {#History}

The *parametricity theorem* was originally stated by [John C. Reynolds](https://en.wikipedia.org/wiki/John_C._Reynolds), who called it the *abstraction theorem*.[^o4] In his paper "Theorems for free!",[^o5] [Philip Wadler](https://en.wikipedia.org/wiki/Philip_Wadler) described an application of parametricity to derive theorems about [parametrically polymorphic](https://en.wikipedia.org/wiki/Parametric_polymorphism) functions based on their types.

## Programming language implementation {#Programming_language_implementation}

Parametricity is the basis for many [program transformations](https://en.wikipedia.org/wiki/Program_transformation) implemented in [compilers](https://en.wikipedia.org/wiki/Compiler) for the [programming language](wikipedia://en/23015) [Haskell](https://en.wikipedia.org/wiki/Haskell). These transformations were traditionally thought to be correct in Haskell because of Haskell's [non-strict](https://en.wikipedia.org/wiki/Strict_function) semantics. Despite being a [lazy evaluation](https://en.wikipedia.org/wiki/Lazy_evaluation) programming language, Haskell does support certain primitive operations, such as the operator `seq`—that enable so-called *selective strictness*, allowing evaluation to be forced for certain expressions. In their paper "Free theorems in the presence of *seq*",[^o7] Patricia Johann and Janis Voigtlaender showed that because of the presence of these operations, the general parametricity theorem does not hold for Haskell programs; thus, these transformations are unsound in general.
