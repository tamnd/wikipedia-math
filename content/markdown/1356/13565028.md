::: {#o4 .subject cue=lead name="Certificate Management Protocol"}

The **Certificate Management Protocol** (CMP) is an Internet protocol standardized by the [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) used for obtaining X.509 [public-key certificates](wikipedia://en/223796) in a [PKI](wikipedia://en/194112).

:::

CMP is a very feature-rich and flexible protocol. So far it is the only protocol with support of all types of cryptography. This includes KEM keys, which have become more important for [post-quantum cryptography (PQC)](wikipedia://en/26605226).

CMP messages are self-contained, which makes the protocol independent of the transport mechanism and provides end-to-end security also over multiple hops. This distinguishes CMP and [CMC](https://en.wikipedia.org/wiki/Certificate_Management_over_CMS) from other certificate enrollment protocols including [EST](https://en.wikipedia.org/wiki/Enrollment_over_Secure_Transport). CMP messages are defined in [ASN.1](https://en.wikipedia.org/wiki/ASN.1) syntax and encoded using the [DER](https://en.wikipedia.org/wiki/Distinguished_Encoding_Rules) method.

CMP is described in 9810. Enrollment request messages employ the Certificate Request Message Format (CRMF), described in 4211 and updated in 9045. The only other protocol so far using CRMF is [Certificate Management over CMS](https://en.wikipedia.org/wiki/Certificate_Management_over_CMS) (CMC), described in 5273.

## History {#History}

The initial version of CMP is described in 2510, the respective CRMF version in 2511. Both were published in March 1999.

CMP version 2 was described in 4210, published in September 2005. HTTP transfer for CMP messages was first described by 6712, published in September 2012.

In November 2023, [CMP Updates](https://datatracker.ietf.org/doc/html/rfc9480), [CMP Algorithms](https://datatracker.ietf.org/doc/html/rfc9481), and [CoAP transfer for CMP](https://datatracker.ietf.org/doc/html/rfc9482), have been published as well as the [Lightweight CMP Profile](https://datatracker.ietf.org/doc/html/rfc9483) focusing on industrial use.

In July 2025, [RFC 9810](https://www.rfc-editor.org/rfc/rfc9810.html) was released, which combines the RFCs 4210 and 9480 into a self-contained document and adds further features, in particular support for [KEM](wikipedia://en/8597625) keys. At the same time, an update of the specification for HTTP(S) transfer of CMP messages was published in [RFC 9811](https://www.rfc-editor.org/rfc/rfc9811.html).

## PKI Entities {#PKI_Entities}

In a [Public-Key Infrastructure](wikipedia://en/194112) (PKI), so-called **end entities** (EEs) act as CMP client, requesting one or more certificates for themselves from a [certificate authority](wikipedia://en/296370) (CA), which issues the legal certificates and acts as a CMP server. None or any number of [registration authorities](https://en.wikipedia.org/wiki/Registration_authority) (RA), can be used to mediate between the EEs and CAs, having both a downstream CMP server interface and an upstream CMP client interface. Using a "cross-certification request" a CA can get a certificate signed by another CA.

## Features {#Features}

- Self-contained messages with protection being independent of message transfer – as opposed to related protocols [EST](https://en.wikipedia.org/wiki/Enrollment_over_Secure_Transport) and [SCEP](https://en.wikipedia.org/wiki/Simple_Certificate_Enrollment_Protocol), this supports built-in end-to-end proof of origin also over several hops.
- Proof of possession (POP) is usually done by a self-signature of the requested certificate contents, but CMP supports also other methods. This is crucial in particular for requesting certificates for [KEM](wikipedia://en/8597625)-only keys.
- CMP supports the very important aspect of proof of origin (i.e., proof of identity of the requester) in two variants: MAC-based with a shared secret (used initially) and signature-based (using pre-existing certificates).
- Key pair generation is usually done by the client side, but can also be requested from the server side.
- In case an end entity has lost its private key and it is stored by the CA, it might be recovered by requesting a "key pair recovery".
- Full certificate life-cycle support: an end entity can utilize CMP to obtain certificates from a CA, request updates for them, and also get them revoked.
- There are various further types of requests possible, for instance to retrieve CA certificates and to obtain PKI parameters and preferences of the server side.

## Transport {#Transport}

CMP messages are usually transferred over HTTP(S), but any reliable means of transportation can be used.

- Encapsulated in [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol) messages,[^o9] optionally using TLS ([HTTPS](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol_Secure)) for additional protection.
- Encapsulated in [CoAP](https://en.wikipedia.org/wiki/Constrained_Application_Protocol) messages, optionally using [DTLS](wikipedia://en/1500599) for additional protection.[^o10]
- [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol) or any other reliable, connection-oriented transport protocol.
- As a [file](https://en.wikipedia.org/wiki/Computer_file), e.g., over [FTP](https://en.wikipedia.org/wiki/File_Transfer_Protocol) or [SCP](https://en.wikipedia.org/wiki/Secure_Copy).
- By [email](https://en.wikipedia.org/wiki/Email), using the [MIME](https://en.wikipedia.org/wiki/Multipurpose_Internet_Mail_Extensions) encoding standard.

The [Content-Type](https://en.wikipedia.org/wiki/Content-Type) used is *application/pkixcmp*. Initially, *application/pkixcmp-poll*, *application/x-pkixcmp* or *application/x-pkixcmp-poll* were used.

## Implementations {#Implementations}

section

- [OpenSSL](wikipedia://en/438819) since version 3.0 includes extensive CMP support in C. The so-called [generic CMP client](https://github.com/siemens/gencmpclient) provides a high-level API for it, adhering to the [Lightweight CMP Profile](https://www.rfc-editor.org/rfc/rfc9483.html) defined in 9483.
- [Bouncy Castle](wikipedia://en/3636963) offers CMP support in Java and C#.[^o13]
- [RSA BSAFE Cert-J](https://en.wikipedia.org/wiki/RSA_BSAFE#Cert-J) provides CMP support in C and Java.
- [cryptlib](wikipedia://en/8028323) provides CMP support in C.
- The [CA](wikipedia://en/296370) software products [EJBCA](https://en.wikipedia.org/wiki/EJBCA)[^o13][^o14], Insta Certifier, Entrust Certificate Authority, Nexus Certificate Manager, DigiCert Device Trust Manager, and IBM z/OS PKI Services, implement subsets of CMPv2.
