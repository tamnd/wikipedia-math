# AES implementations

::: {#o1 .subject cue=lead name="AES implementations"}

There are various implementations of the [Advanced Encryption Standard](wikipedia://en/1260), also known as Rijndael.

:::

::: {#o3 .pointer-item cue=pointer name="AES-ECB"}

## Libraries {#Libraries}

Rijndael is free for any use public or private, commercial or non-commercial.[^o4] The authors of Rijndael used to provide a homepage[^o5] for the algorithm. Care should be taken when implementing AES in software, in particular around side-channel attacks.

The algorithm operates on plaintext blocks of 16 bytes. Encryption of shorter blocks is possible only by [padding](wikipedia://en/592505) the source bytes, usually with [null bytes](https://en.wikipedia.org/wiki/Null_character). This can be accomplished via several methods, the simplest of which assumes that the final byte of the cipher identifies the number of null bytes of padding added.

### Implementation Considerations {#Implementation_Considerations}

Careful choice must be made in selecting the [mode of operation](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation) of the cipher. The simplest mode encrypts and decrypts each 128-bit block separately. In this mode, called [electronic code book](https://en.wikipedia.org/wiki/Electronic_code_book) (ECB), blocks that are identical will be encrypted identically; this is entirely insecure. It makes some of the plaintext structure visible in the ciphertext. Selecting other modes, such as using a sequential counter over the block prior to encryption (i.e., CTR mode) and removing it after decryption avoids this problem. Another mode, [Cipher Block Chaining](https://en.wikipedia.org/wiki/Cipher_Block_Chaining) (CBC) is one of the most commonly used modes of AES due to its use in TLS. CBC uses a random initialization vector (IV) to ensure that distinct ciphertexts are produced even when the same plaintext is encoded multiple times. The IV can be transmitted in the clear without jeopardizing security. A common practice is to prepend the 16 byte IV to the ciphertext, which gives the decrypter easy access to the IV. Care must be taken to use a new IV for every encryption operation, since otherwise an attacker can recover plaintext.

- Current list of FIPS 197 validated cryptographic modules (hosted by NIST)
- Current list of FIPS 140 validated cryptographic modules with validated AES implementations (hosted by NIST) – Most of these involve a commercial implementation of AES algorithms. Look for "FIPS-approved algorithms" entry in the "Level / Description" column followed by "AES" and then a specific certificate number.

- [GnuTLS](wikipedia://en/949758)

- [Reference original implementation](http://embeddedsw.net/Cipher_Reference_Home.html)
- [axTLS](https://en.wikipedia.org/wiki/AxTLS)
- [Microsoft CryptoAPI](wikipedia://en/3302413) uses [Cryptographic Service Providers](wikipedia://en/3168110) to offer encryption implementations. The Microsoft AES Cryptographic Provider was introduced in Windows XP and can be used with any version of the Microsoft CryptoAPI.[^o8]
- [tiny-AES-c](https://github.com/kokke/tiny-AES-c) Small portable AES128/192/256 in C (suitable for embedded systems)
- [AES-256](http://www.literatecode.com/aes256) A byte-oriented portable AES-256 implementation in C
- [Solaris Cryptographic Framework](https://en.wikipedia.org/wiki/Solaris_Cryptographic_Framework) offers multiple implementations, with kernel providers for hardware acceleration on [x86](https://en.wikipedia.org/wiki/X86) (using the Intel [AES instruction set](wikipedia://en/23095336)) and on [SPARC](https://en.wikipedia.org/wiki/SPARC) (using the SPARC AES instruction set). It is available in [Solaris](https://en.wikipedia.org/wiki/Solaris_%28operating_system%29) and derivatives, as of Solaris 10.[^o9]
- [OpenAES](https://en.wikipedia.org/wiki/OpenAES) portable C cryptographic library
- [LibTomCrypt](https://en.wikipedia.org/wiki/LibTomCrypt) is a modular and portable cryptographic toolkit that provides developers with well known published block ciphers, one-way hash functions, chaining modes, pseudo-random number generators, public key cryptography and other routines.
- [libSodium](https://umbrella.cisco.com/blog/blog/2013/03/06/announcing-sodium-a-new-cryptographic-library/) API for [NaCl](http://nacl.cr.yp.to/)
- [AES Dust](https://github.com/odzhan/aes_dust) Compact implementation of AES-128 encryption in C, x86, AMD64, ARM32 and ARM64 assembly.
- [MSP430 AES](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/156/slaa397a.pdf) Implementation for embedded 16-bit microcontroller
- [Gladman AES](http://ccgi.gladman.plus.com/oldsite/cryptography_technology/index.php) AES code with optional support for Intel AES NI and VIA ACE by Dr. Brian Gladman.

### JavaScript {#JavaScript}

- [AES-JS](https://en.wikipedia.org/wiki/AES-JS) – portable JavaScript implementation of AES ECB and CTR modes
- Forge – JavaScript implementations of AES in CBC, CTR, OFB, CFB, and GCM modes
- [asmCrypto](https://en.wikipedia.org/wiki/AsmCrypto) – JavaScript implementation of popular cryptographic utilities with focus on performance. Supports CBC, CFB, CCM modes.
- [pidCrypt](https://en.wikipedia.org/wiki/PidCrypt) – open source JavaScript library. Only supports the CBC and CTR modes.

## Hardware {#Hardware}

- [x86-64](https://en.wikipedia.org/wiki/X86-64) and [ARM](https://en.wikipedia.org/wiki/ARM_architecture) processors include the [AES instruction set](wikipedia://en/23095336).
- On IBM [zSeries](https://en.wikipedia.org/wiki/ZSeries) mainframes, AES is implemented as the KM series of assembler opcodes when various Message Security Assist facilities are installed.
- [SPARC](https://en.wikipedia.org/wiki/SPARC) S3 core processors include the AES instruction set, which is used with [SPARC T4](https://en.wikipedia.org/wiki/SPARC_T4) and [SPARC T5](https://en.wikipedia.org/wiki/SPARC_T5) systems.
