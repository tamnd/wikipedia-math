# Circuit complexity

*Image: Three input boolean circuit.svg.* Example Boolean circuit. The $\wedge$ nodes are [AND gates](https://en.wikipedia.org/wiki/AND_gate), the $\vee$ nodes are [OR gates](https://en.wikipedia.org/wiki/OR_gate), and the $\neg$ nodes are [NOT gates](https://en.wikipedia.org/wiki/NOT_gate).

::: {#o1 .subject cue=lead name="Circuit complexity"}

In [theoretical computer science](wikipedia://en/323392), **circuit complexity** is a branch of [computational complexity theory](wikipedia://en/7543) in which [Boolean functions](wikipedia://en/753349) are classified according to the size or depth of the [Boolean circuits](wikipedia://en/7087423) that compute them. A related notion is the circuit complexity of a [recursive language](wikipedia://en/23290990) that is [decided](https://en.wikipedia.org/wiki/Machine_that_always_halts) by a **uniform** family of circuits $C_{1},C_{2},\ldots$ (see below).

:::

Proving lower bounds on size of Boolean circuits computing explicit Boolean functions is a popular approach to separating complexity classes. For example, a [prominent](wikipedia://en/2052415#Importance_of_P/poly) circuit class [P/poly](wikipedia://en/2052415) consists of Boolean functions computable by circuits of polynomial size. Proving that $\mathsf{NP}\not\subseteq \mathsf{P/poly}$ would separate [P](wikipedia://en/658550) and [NP](wikipedia://en/21562) (see below).

[Complexity classes](wikipedia://en/502426) defined in terms of Boolean circuits include [AC<sup>0</sup>](wikipedia://en/7400698), [AC](wikipedia://en/7401755), [TC<sup>0</sup>](wikipedia://en/7399828), [NC<sup>1</sup>](https://en.wikipedia.org/wiki/NC1_%28complexity%29), [NC](wikipedia://en/22073), and [P/poly](wikipedia://en/2052415).

## Size and depth {#Size_and_depth}

A Boolean circuit with $n$ input [bits](https://en.wikipedia.org/wiki/Bit) is a [directed acyclic graph](wikipedia://en/204002) in which every node (usually called *gates* in this context) is either an input node of [in-degree](https://en.wikipedia.org/wiki/In-degree) 0 labelled by one of the $n$ input bits, an [AND gate](https://en.wikipedia.org/wiki/AND_gate), an [OR gate](https://en.wikipedia.org/wiki/OR_gate), or a [NOT gate](https://en.wikipedia.org/wiki/NOT_gate). One of these gates is designated as the output gate. Such a circuit naturally computes a function of its $n$ inputs. The **size** of a circuit is the number of gates it contains and its **depth** is the maximal length of a path from an input gate to the output gate.

There are two major notions of circuit complexity.[^o17] The **circuit-size complexity** of a Boolean function $f$ is the minimal size of any circuit computing $f$. The **circuit-depth complexity** of a Boolean function $f$ is the minimal depth of any circuit computing $f$.

These notions generalize when one considers the circuit complexity of any [formal language](wikipedia://en/10939) that contains strings with different bit lengths, especially infinite languages. Boolean circuits, however, only allow a fixed number of input bits. Thus, no single Boolean circuit is capable of deciding such a language. To account for this possibility, one considers families of circuits $C_{1},C_{2},\ldots$ where each $C_{n}$ accepts inputs of size $n$. Each circuit family will naturally generate the language by circuit $C_{n}$ outputting $1$ when a length $n$ string is a member of the family, and $0$ otherwise. We say that a family of circuits is **size minimal** if there is no other family that decides on inputs of any size, $n$, with a circuit of smaller size than $C_n$ (respectively for **depth minimal** families). Thus, circuit complexity is meaningful even for [non-recursive languages](wikipedia://en/23290990). The notion of a **uniform family** enables variants of circuit complexity to be related to algorithm-based complexity measures of recursive languages. However, the non-uniform variant is helpful to find lower bounds on how complex any circuit family must be in order to decide given languages.

Hence, the **circuit-size complexity** of a formal language $A$ is defined as the function $t:\mathbb{N}\to\mathbb{N}$, that relates a bit length of an input, $n$, to the circuit-size complexity of a minimal circuit $C_{n}$ that decides whether inputs of that length are in $A$. The **circuit-depth complexity** is defined similarly.

## Uniformity {#Uniformity}

Boolean circuits are one of the prime examples of so-called non-uniform [models of computation](wikipedia://en/60492) in the sense that inputs of different lengths are processed by different circuits, in contrast with uniform models such as [Turing machines](wikipedia://en/30403) where the same computational device is used for all possible input lengths. An individual [computational problem](https://en.wikipedia.org/wiki/Computational_problem) is thus associated with a particular *family* of Boolean circuits $C_1, C_2, \dots$ where each $C_n$ is the circuit handling inputs of *n* bits. A *uniformity* condition is often imposed on these families, requiring the existence of some possibly [resource-bounded](wikipedia://en/4628222) Turing machine that, on input *n*, produces a description of the individual circuit $C_n$. When this Turing machine has a running time polynomial in *n*, the circuit family is said to be P-uniform. The stricter requirement of [DLOGTIME](wikipedia://en/7404967)-uniformity is of particular interest in the study of shallow-depth circuit-classes such as AC<sup>0</sup> or TC<sup>0</sup>. When no resource bounds are specified, a language is recursive (i.e., decidable by a Turing machine) if and only if the language is decided by a uniform family of Boolean circuits.

### Polynomial-time uniform {#Polynomial-time_uniform}

A family of Boolean circuits $\{C_n:n \in \mathbb{N}\}$ is *polynomial-time uniform* if there exists a [deterministic Turing machine](https://en.wikipedia.org/wiki/Deterministic_Turing_machine) *M*, such that

- *M* runs in polynomial time
- For all $n \in \mathbb{N}$, *M* outputs a description of $C_n$ on input $1^n$

### Logspace uniform {#Logspace_uniform}

A family of Boolean circuits $\{C_n:n \in \mathbb{N}\}$ is *[logspace uniform](wikipedia://en/1174850)* if there exists a [deterministic Turing machine](https://en.wikipedia.org/wiki/Deterministic_Turing_machine) *M*, such that

- *M* runs in logarithmic work space (i.e. *M* is a [log-space transducer](https://en.wikipedia.org/wiki/Log-space_transducer))
- For all $n \in \mathbb{N}$, *M* outputs a description of $C_n$ on input $1^n$

:::

## History {#History}

Circuit complexity goes back to [Shannon](wikipedia://en/5693) in 1949,[^o29] who proved that almost all Boolean functions on *n* variables require circuits of size Θ(2<sup>*n*</sup>/*n*). Despite this fact, complexity theorists have so far been unable to prove a superlinear lower bound for any explicit function.

Superpolynomial lower bounds have been proved under certain restrictions on the family of circuits used. The first function for which superpolynomial circuit lower bounds were shown was the [parity function](wikipedia://en/22399369), which computes the sum of its input bits modulo 2. The fact that parity is not contained in [AC<sup>0</sup>](wikipedia://en/7400698) was first established independently by [Ajtai](https://en.wikipedia.org/wiki/Miklós_Ajtai) in 1983[^o19][^o18] and by Furst, [Saxe](https://en.wikipedia.org/wiki/James_Benjamin_Saxe) and [Sipser](https://en.wikipedia.org/wiki/Michael_Fredric_Sipser) in 1984.[^o20] Later improvements by [Håstad](https://en.wikipedia.org/wiki/Johan_Håstad) in 1987[^o30] established that any family of constant-depth circuits computing the parity function requires exponential size. Extending a result of [Razborov](wikipedia://en/3533454),[^o31] Smolensky in 1987[^o33] proved that this is true even if the circuit is augmented with gates computing the sum of its input bits modulo some odd prime *p*.

The [*k*-clique problem](wikipedia://en/249254) is to decide whether a given graph on *n* vertices has a clique of size *k*. For any particular choice of the constants *n* and *k*, the graph can be encoded in binary using ${n \choose 2}$ bits, which indicate for each possible edge whether it is present. Then the *k*-clique problem is formalized as a function $f_k:\{0,1\}^{{n \choose 2}}\to\{0,1\}$ such that $f_k$ outputs 1 if and only if the graph encoded by the string contains a clique of size *k*. This family of functions is monotone and can be computed by a family of circuits, but it has been shown that it cannot be computed by a polynomial-size family of monotone circuits (that is, circuits with AND and OR gates but without negation). The original result of Razborov in 1985[^o31] was later improved to an exponential-size lower bound by [Alon](wikipedia://en/4939651) and Boppana in 1987.[^o34] In 2008, [Rossman](wikipedia://en/62461665)[^o32] showed that constant-depth circuits with AND, OR, and NOT gates require size $\Omega(n^{k/4})$ to solve the *k*-clique problem even in the [average case](https://en.wikipedia.org/wiki/Average-case_complexity). Moreover, there is a circuit of size $n^{k/4+O(1)}$ that computes $f_k$.

In 1999, [Raz](https://en.wikipedia.org/wiki/Ran_Raz) and [McKenzie](https://en.wikipedia.org/wiki/Pierre_McKenzie) later showed that the monotone NC hierarchy is infinite.[^o27]

The integer division problem lies in uniform [TC<sup>0</sup>](wikipedia://en/7399828).[^o26]

## Circuit lower bounds {#Circuit_lower_bounds}

Circuit lower bounds are generally difficult. Known results include

- Parity is not in nonuniform [AC<sup>0</sup>](wikipedia://en/7400698), proved by Ajtai in 1983[^o19][^o18] as well as by Furst, Saxe and Sipser in 1984.[^o20]
- Uniform [TC<sup>0</sup>](wikipedia://en/7399828) is strictly contained in [PP](wikipedia://en/659322), proved by [Allender](https://en.wikipedia.org/wiki/Eric_Allender).[^o28]
- The classes [O${}^{P}_{2}$](https://complexityzoo.net/Complexity_Zoo:O#o2p),[^o35] PP[^o15] and [MA](https://en.wikipedia.org/wiki/MA_%28complexity%29)/1[^o21] (MA with one bit of advice) are not in **SIZE**(*n<sup>k</sup>*) for any constant k.
- While it is suspected that the nonuniform class [ACC<sup>0</sup>](wikipedia://en/7729684) does not contain the majority function, it was only in 2010 that [Williams](https://en.wikipedia.org/wiki/Ryan_Williams_%28computer_scientist%29) proved that $\mathsf{NEXP} \not \subseteq \mathsf{ACC}^0$.[^o22]

It is open whether [NEXPTIME](wikipedia://en/663657) has nonuniform TC<sup>0</sup> circuits.

Proofs of circuit lower bounds are strongly connected to [derandomization](https://en.wikipedia.org/wiki/Derandomization). A proof that $\mathsf{P} = \mathsf{BPP}$ would imply that either $\mathsf{NEXP} \not \subseteq \mathsf{P/poly}$ or that the [permanent of a matrix](wikipedia://en/215889) cannot be computed by nonuniform arithmetic circuits (polynomials) of polynomial size and polynomial degree.[^o23]

In 1997, Razborov and [Rudich](https://en.wikipedia.org/wiki/Steven_Rudich) showed that many known circuit lower bounds for explicit Boolean functions imply the existence of so called [natural properties](wikipedia://en/662262) useful against the respective circuit class.[^o24] On the other hand, natural properties useful against P/poly would break strong pseudorandom generators. This is often interpreted as a "natural proofs" barrier for proving strong circuit lower bounds. In 2016, Carmosino, Impagliazzo, Kabanets and Kolokolova proved that natural properties can be also used to construct efficient learning algorithms.[^o25]

## Complexity classes {#Complexity_classes}

Many circuit complexity classes are defined in terms of class hierarchies. For each non-negative integer *i*, there is a class [NC<sup>i</sup>](wikipedia://en/22073), consisting of polynomial-size circuits of depth $O(\log^i(n))$, using bounded [fan-in](https://en.wikipedia.org/wiki/Fan-in) AND, OR, and NOT gates. The union NC of all of these classes is a subject of study. By considering unbounded fan-in gates, the classes [AC<sup>i</sup>](wikipedia://en/7401755) and AC (which is equal to NC) can be constructed. Many other circuit complexity classes with the same size and depth restrictions can be constructed by allowing different sets of gates.

## Relation to time complexity {#Relation_to_time_complexity}

If a certain language, $A$, belongs to the [time-complexity class](wikipedia://en/502426) $\text{TIME}(t(n))$ for some function $t:\mathbb{N}\to\mathbb{N}$, then $A$ has circuit complexity $\mathcal{O}(t(n) \log t(n))$. If the Turing Machine that accepts the language is [oblivious](wikipedia://en/6263864) (meaning that it reads and writes the same memory cells regardless of input), then $A$ has circuit complexity $\mathcal{O}(t(n))$.[^o11]

## Monotone circuits {#Monotone_circuits}

A monotone Boolean circuit is one that has only AND and OR gates, but no NOT gates. A monotone circuit can only compute a monotone Boolean function, which is a function $f:\{0,1\}^n \to \{0,1\}$ where for every $x,y \in \{0,1\}^n$, $x \leq y \implies f(x) \leq f(y)$, where $x\leq y$ means that $x_i \leq y_i$ for all $i \in \{1,\ldots,n\}$.
