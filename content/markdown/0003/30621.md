# Turing completeness

::: {#o1 .subject cue=lead name="Turing completeness"}

*Image: OTCA metapixel.gif.* [Conway's Game of Life](wikipedia://en/37035) is Turing-complete and can simulate any system, [including itself](wikipedia://en/25407) (pictured).

In [computability theory](wikipedia://en/155414), a system of data-manipulation rules (such as a [model of computation](wikipedia://en/1773278), a computer's [instruction set](https://en.wikipedia.org/wiki/Instruction_set), a [programming language](wikipedia://en/23015), or a [cellular automaton](wikipedia://en/54342)) is said to be **Turing-complete** or **computationally universal** if it can be used to simulate any [Turing machine](wikipedia://en/30403)[^o2][^o3] (devised by English mathematician and computer scientist [Alan Turing](wikipedia://en/1208)). This means that this system is able to recognize or decode other data-manipulation rule sets. Turing completeness is used as a way to express the power of such a data-manipulation rule set. Virtually all programming languages today are Turing-complete.

:::

A related concept is that of **Turing equivalence** – two computers P and Q are called equivalent if P can simulate Q and Q can simulate P.[^o4] The [Church–Turing thesis](wikipedia://en/6854) conjectures that any function whose values can be computed by an [algorithm](wikipedia://en/775) can be computed by a Turing machine, and therefore that if any real-world computer can simulate a Turing machine, it is Turing equivalent to a Turing machine. A [universal Turing machine](wikipedia://en/71435) can be used to simulate any Turing machine and by extension the purely computational aspects of any possible real-world computer.[^o5][^o6]

To show that something is Turing-complete, it is enough to demonstrate that it can be used to simulate some Turing-complete system. No physical system can have infinite memory, but if the limitation of finite memory is ignored, most programming languages are otherwise Turing-complete.[^o7][^o8]

## Non-mathematical usage {#Non-mathematical_usage}

In [colloquial](https://en.wikipedia.org/wiki/Colloquial) usage, the terms "Turing-complete" and "Turing-equivalent" are used to mean that any real-world general-purpose computer or computer language can approximately simulate the computational aspects of any other real-world general-purpose computer or computer language. In real life, this leads to the practical concepts of computing [virtualization](https://en.wikipedia.org/wiki/Virtualization) and [emulation](https://en.wikipedia.org/wiki/Emulator).

Real computers constructed so far can be functionally analyzed like a single-tape Turing machine (which uses a "tape" for memory); thus the associated mathematics can apply by abstracting their operation far enough. However, real computers have limited physical resources, so they are only [linear bounded automaton](wikipedia://en/1811962) complete. In contrast, the abstraction of a [universal computer](https://en.wikipedia.org/wiki/Universal_computer) is defined as a device with a Turing-complete instruction set, infinite memory, and infinite available time.

::: {#o11 .definition cue=heading name="Formal definitions"}

## Formal definitions {#Formal_definitions}

In [computability theory](wikipedia://en/155414), several closely related terms are used to describe the computational power of a computational system (such as an [abstract machine](wikipedia://en/60492) or [programming language](wikipedia://en/23015)):

**Turing completeness**

A computational system that can compute every Turing-[computable function](wikipedia://en/1139338) is called Turing-complete (or Turing-powerful). Alternatively, such a system is one that can simulate a [universal Turing machine](wikipedia://en/71435).

**Turing equivalence**

A Turing-complete system is called Turing-equivalent if every function it can compute is also Turing-computable; i.e., it computes precisely the same class of functions as do [Turing machines](wikipedia://en/30403). Alternatively, a Turing-equivalent system is one that can simulate, and be simulated by, a universal Turing machine. (All known physically-implementable Turing-complete systems are Turing-equivalent, which adds support to the [Church–Turing thesis](wikipedia://en/6854).)

**(Computational) universality**

A system is called universal with respect to a class of systems if it can compute every function computable by systems in that class (or can simulate each of those systems). Typically, the term 'universality' is tacitly used with respect to a Turing-complete class of systems. The term "weakly universal" is sometimes used to distinguish a system (e.g. a [cellular automaton](wikipedia://en/54342)) whose universality is achieved only by modifying the standard definition of [Turing machine](wikipedia://en/30403) so as to include input streams with infinitely many 1s.

:::

## History {#History}

Turing completeness is significant in that every real-world design for a computing device can be simulated by a [universal Turing machine](wikipedia://en/71435). The [Church–Turing thesis](wikipedia://en/6854) states that this is a law of mathematics – that a universal Turing machine can, in principle, perform any calculation that any other programmable [computer](https://en.wikipedia.org/wiki/Computer) can. This says nothing about the effort needed to write the [program](https://en.wikipedia.org/wiki/Computer_program), or the time it may take for the machine to perform the calculation, or any abilities the machine may possess that have nothing to do with computation.

[Charles Babbage](wikipedia://en/5698)'s [analytical engine](https://en.wikipedia.org/wiki/Analytical_engine) (1830s) would have been the first Turing-complete machine if it had been built at the time it was designed. Babbage appreciated that the machine was capable of great feats of calculation, including primitive logical reasoning, but he did not appreciate that no other machine could do better. From the 1830s until the 1940s, mechanical calculating machines such as adders and multipliers were built and improved, but they could not perform a conditional branch and therefore were not Turing-complete.

In the late 19th century, [Leopold Kronecker](wikipedia://en/318450) formulated notions of computability, defining [primitive recursive functions](wikipedia://en/24829). These functions can be calculated by rote computation, but they are not enough to make a universal computer, because the instructions that compute them do not allow for an infinite loop. In the early 20th century, [David Hilbert](wikipedia://en/8302) led a program to axiomatize all of mathematics with precise axioms and precise logical rules of deduction that could be performed by a machine. Soon it became clear that a small set of deduction rules are enough to produce the consequences of any set of axioms. These rules were proved by [Kurt Gödel](wikipedia://en/16736) in 1930 to be enough to produce every theorem.

The actual notion of computation was isolated soon after, starting with [Gödel's incompleteness theorem](https://en.wikipedia.org/wiki/Gödel's_incompleteness_theorem). This theorem showed that axiom systems were limited when reasoning about the computation that deduces their theorems. Church and Turing independently demonstrated that Hilbert's [Entscheidungsproblem](wikipedia://en/9672) (decision problem) was unsolvable,[^o13] thus identifying the computational core of the incompleteness theorem. This work, along with Gödel's work on [general recursive functions](wikipedia://en/26469), established that there are sets of simple instructions, which, when put together, are able to produce any computation. The work of Gödel showed that the notion of computation is essentially unique.

In 1941 [Konrad Zuse](https://en.wikipedia.org/wiki/Konrad_Zuse) completed the [Z3](https://en.wikipedia.org/wiki/Z3_%28computer%29) computer. Zuse was not familiar with Turing's work on computability at the time. In particular, the Z3 lacked dedicated facilities for a conditional jump, thereby precluding it from being Turing complete. However, in 1998, it was shown by Rojas that the Z3 is capable of simulating conditional jumps, and therefore Turing complete in theory. To do this, its tape program would have to be long enough to execute every possible path through both sides of every branch.[^o14]

The first computer capable of conditional branching in practice, and therefore Turing complete in practice, was the [ENIAC](https://en.wikipedia.org/wiki/ENIAC) in 1946. Zuse's [Z4](https://en.wikipedia.org/wiki/Z4_%28computer%29) computer was operational in 1945, but it did not support conditional branching until 1950.[^o15]

## Computability theory {#Computability_theory}

[Computability theory](wikipedia://en/155414) uses [models of computation](wikipedia://en/1773278) to analyze problems and determine whether they are [computable](https://en.wikipedia.org/wiki/Computability) and under what circumstances. The first result of computability theory is that there exist problems for which it is impossible to predict what a (Turing-complete) system will do over an arbitrarily long time.

The classic example is the [halting problem](wikipedia://en/21391870): create an algorithm that takes as input a program in some Turing-complete language and some data to be fed to *that* program, and determines whether the program, operating on the input, will eventually stop or will continue forever. It is trivial to create an algorithm that can do this for *some* inputs, but impossible to do this in general. For any characteristic of the program's eventual output, it is impossible to determine whether this characteristic will hold.

This impossibility poses problems when analyzing real-world computer programs. For example, one cannot write a tool that entirely protects programmers from writing infinite loops or protects users from supplying input that would cause infinite loops.

One can instead limit a program to executing only for a fixed period of time ([timeout](https://en.wikipedia.org/wiki/Timeout_%28computing%29)) or limit the power of flow-control instructions (for example, providing only loops that iterate over the items of an existing array). However, another theorem shows that there are problems solvable by Turing-complete languages that cannot be solved by any language with only finite looping abilities (i.e., languages that guarantee that every program will eventually finish to a halt). So any such language is not Turing-complete. For example, a language in which programs are guaranteed to complete and halt cannot compute the computable function produced by [Cantor's diagonal argument](wikipedia://en/51426) on all computable functions in that language.

## Turing oracles {#Turing_oracles}

A computer with access to an infinite tape of data may be more powerful than a Turing machine: for instance, the tape might contain the solution to the [halting problem](wikipedia://en/21391870) or some other Turing-undecidable problem. Such an infinite tape of data is called a [Turing oracle](https://en.wikipedia.org/wiki/Turing_oracle). Even a Turing oracle with random data is not computable ([with probability 1](wikipedia://en/351908)), since there are only countably many computations but uncountably many oracles. So a computer with a random Turing oracle can compute things that a Turing machine cannot.

## Digital physics {#Digital_physics}

All known laws of physics have consequences that are computable by a series of approximations on a digital computer. A hypothesis called [digital physics](https://en.wikipedia.org/wiki/Digital_physics) states that this is no accident because the [universe](https://en.wikipedia.org/wiki/Universe) itself is computable on a universal Turing machine. This would imply that no computer more powerful than a universal Turing machine can be built physically.[^o19]

## Examples {#Examples}

The computational systems (algebras, calculi) that are discussed as Turing-complete systems are those intended for studying [theoretical computer science](wikipedia://en/323392). They are intended to be as simple as possible, so that it would be easier to understand the limits of computation. Here are a few:

- [Automata theory](wikipedia://en/103356)
- [Formal grammar](wikipedia://en/18020716) (language generators)
- [Formal language](wikipedia://en/10939) (language recognizers)
- [Lambda calculus](wikipedia://en/18203)
- [Post–Turing machines](wikipedia://en/3688147)
- [Process calculus](wikipedia://en/853240)

Most [programming languages](wikipedia://en/23015) (their abstract models, maybe with some particular constructs that assume finite memory omitted), conventional and unconventional, are Turing-complete. This includes:

- All general-purpose languages in wide use.
  - [Procedural programming](https://en.wikipedia.org/wiki/Procedural_programming) languages such as [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29).
  - [Object-oriented](https://en.wikipedia.org/wiki/Object-oriented_programming_language) languages such as [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), [Smalltalk](https://en.wikipedia.org/wiki/Smalltalk) or [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29).
  - [Multi-paradigm](https://en.wikipedia.org/wiki/Multi-paradigm_programming_language) languages such as [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp), [Fortran](https://en.wikipedia.org/wiki/Fortran), [JavaScript](https://en.wikipedia.org/wiki/JavaScript), [Object Pascal](https://en.wikipedia.org/wiki/Object_Pascal), [Perl](https://en.wikipedia.org/wiki/Perl), [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [R](wikipedia://en/376707).
- Most languages using less common paradigms:
  - [Functional](https://en.wikipedia.org/wiki/Functional_programming) languages such as [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29) and [Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29).
  - [Logic programming](https://en.wikipedia.org/wiki/Logic_programming) languages such as [Prolog](wikipedia://en/23485).
  - [General-purpose macro processor](https://en.wikipedia.org/wiki/General-purpose_macro_processor) such as [m4](https://en.wikipedia.org/wiki/M4_%28computer_language%29).
  - [Declarative](https://en.wikipedia.org/wiki/Declarative_programming) languages such as [SQL](wikipedia://en/29004) and [XSLT](https://en.wikipedia.org/wiki/XSLT).[^o22][^o23]
  - [VHDL](https://en.wikipedia.org/wiki/VHDL) and other hardware description languages.
  - [TeX](https://en.wikipedia.org/wiki/TeX), a typesetting system.
  - [Esoteric programming languages](https://en.wikipedia.org/wiki/Esoteric_programming_language), a form of [mathematical recreation](https://en.wikipedia.org/wiki/Mathematical_recreation) in which programmers work out how to achieve basic programming constructs in an extremely difficult but mathematically Turing-equivalent language.

Some [rewrite systems](https://en.wikipedia.org/wiki/Rewrite_system) are Turing-complete.

Turing completeness is an abstract statement of ability, rather than a prescription of specific language features used to implement that ability. The features used to achieve Turing completeness can be quite different: Fortran systems would use loop constructs or possibly even [goto](https://en.wikipedia.org/wiki/Goto) statements to achieve repetition; Haskell and Prolog, lacking looping almost entirely, would use [recursion](wikipedia://en/25407). Most programming languages are describing computations on [von Neumann architectures](https://en.wikipedia.org/wiki/Von_Neumann_architecture), which have memory (RAM and register) and a control unit. These two elements make this architecture Turing-complete. Even pure [functional languages](https://en.wikipedia.org/wiki/Functional_language) are Turing-complete.[^o24][^o25]

Turing completeness in declarative SQL is implemented through [recursive common table expressions](https://en.wikipedia.org/wiki/Hierarchical_and_recursive_queries_in_SQL). Unsurprisingly, procedural extensions to SQL ([PLSQL](https://en.wikipedia.org/wiki/PLSQL), etc.) are also Turing-complete. This illustrates one reason why relatively powerful non-Turing-complete languages are rare: the more powerful the language is initially, the more complex are the tasks to which it is applied and the sooner its lack of completeness becomes perceived as a drawback, encouraging its extension until it is Turing-complete.

The untyped [lambda calculus](wikipedia://en/18203) is Turing-complete, but many typed lambda calculi, including [System F](wikipedia://en/767637), are not. The value of typed systems is based in their ability to represent most typical computer programs while detecting more errors.

[Rule 110](wikipedia://en/491028) and [Conway's Game of Life](wikipedia://en/37035), both [cellular automata](wikipedia://en/54342), are Turing-complete.

## Non-Turing-complete languages {#Non-Turing-complete_languages}

Many computational languages exist that are not Turing-complete. One such example is the set of [regular languages](wikipedia://en/25723), which are generated by [regular expressions](wikipedia://en/25717) and which are recognized by [finite automata](wikipedia://en/10931). A more powerful but still not Turing-complete extension of finite automata is the category of [pushdown automata](wikipedia://en/24510) and [context-free grammars](wikipedia://en/6759), which are commonly used to generate parse trees in an initial stage of program [compiling](https://en.wikipedia.org/wiki/Compiler). Further examples include some of the early versions of the pixel shader languages embedded in [Direct3D](https://en.wikipedia.org/wiki/Direct3D) and [OpenGL](https://en.wikipedia.org/wiki/OpenGL) extensions.

In [total functional programming](https://en.wikipedia.org/wiki/Total_functional_programming) languages, such as [Charity](https://en.wikipedia.org/wiki/Charity_%28programming_language%29) and [Epigram](https://en.wikipedia.org/wiki/Epigram_%28programming_language%29), all functions are total and must terminate. Charity uses a type system and [control constructs](wikipedia://en/45459) based on [category theory](wikipedia://en/5869), whereas Epigram uses [dependent types](wikipedia://en/1949487). The [LOOP](https://en.wikipedia.org/wiki/LOOP_%28programming_language%29) language is designed so that it computes only the functions that are [primitive recursive](wikipedia://en/24829). All of these compute proper subsets of the total computable functions, since the full set of total computable functions is not [computably enumerable](https://en.wikipedia.org/wiki/Recursively_enumerable_set). Also, since all functions in these languages are total, algorithms for [recursively enumerable sets](https://en.wikipedia.org/wiki/Recursively_enumerable_set) cannot be written in these languages, in contrast with Turing machines.

Although (untyped) [lambda calculus](wikipedia://en/18203) is Turing-complete, [simply typed lambda calculus](wikipedia://en/1986011) is not.
