# GNU Privacy Guard

::: {#o2 .subject cue=lead name="GNU Privacy Guard"}

**GNU Privacy Guard** (**GnuPG** or **GPG**) is a [free-software](https://en.wikipedia.org/wiki/Free-software) replacement for [Symantec](https://en.wikipedia.org/wiki/Symantec_Corporation)'s [cryptographic](wikipedia://en/18934432) software suite [PGP](wikipedia://en/23080). The software is compliant with the now obsoleted[^o3] 4880, the [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) standards-track specification of [OpenPGP](https://en.wikipedia.org/wiki/OpenPGP). Modern versions of PGP are [interoperable](https://en.wikipedia.org/wiki/Interoperability) with GnuPG and other OpenPGP v4-compliant systems.[^o4]

:::

November 2023 saw two drafts aiming to update the 2007 OpenPGP v4 specification (RFC4880), ultimately resulting in the RFC 9580 standard in July 2024. The proposal from the GnuPG developers, which is called LibrePGP, was not taken up by the OpenPGP Working Group and future versions of GnuPG will not support the current version of OpenPGP.[^o5]

GnuPG is part of the [GNU Project](https://en.wikipedia.org/wiki/GNU_Project) and received major funding from the [German government](https://en.wikipedia.org/wiki/Politics_of_Germany) in 1999.[^o6]

## Overview {#Overview}

GnuPG is a [hybrid-encryption](wikipedia://en/11756462) software program because it uses a combination of conventional [symmetric-key cryptography](wikipedia://en/53042) for speed, and [public-key cryptography](wikipedia://en/24222) for ease of secure key exchange, typically by using the recipient's public key to encrypt a [session key](wikipedia://en/63941) which is used only once. This mode of operation is part of the OpenPGP standard and has been part of PGP from its first version.

The GnuPG 1.x series uses an integrated cryptographic library, while the GnuPG 2.x series replaces this with [Libgcrypt](wikipedia://en/29870579).

GnuPG encrypts messages using [asymmetric key pairs](wikipedia://en/24222) individually generated by GnuPG users. The resulting public keys may be exchanged with other users in a variety of ways, such as Internet [key servers](wikipedia://en/616119). They must always be exchanged carefully to prevent identity spoofing by corrupting public key ↔ "owner" identity correspondences. It is also possible to add a cryptographic [digital signature](wikipedia://en/59644) to a message, so the message integrity and sender can be verified, if a particular correspondence relied upon has not been corrupted.

GnuPG also supports [symmetric encryption](wikipedia://en/53042) algorithms. By default, GnuPG uses the [AES](wikipedia://en/1260) symmetrical algorithm since version 2.1,[^o8] [CAST5](wikipedia://en/240998) was used in earlier versions. GnuPG does not use patented or otherwise restricted software or algorithms. Instead, GnuPG uses a variety of other, non-patented algorithms.[^o9] For a long time, it did not support the [IDEA](wikipedia://en/15076) encryption algorithm used in PGP. It was in fact possible to use IDEA in GnuPG by downloading a plugin for it, however, this might require a license for some uses in countries in which IDEA was patented. Starting with versions 1.4.13 and 2.0.20, GnuPG supports IDEA because the last patent of IDEA expired in 2012. Support of IDEA is intended "to get rid of all the questions from folks either trying to decrypt old data or migrating keys from PGP to GnuPG",[^o10] and hence is not recommended for regular use.

More recent releases of GnuPG 2.x ("modern" and the now deprecated "stable" series) expose most cryptographic functions and algorithms [Libgcrypt](wikipedia://en/29870579) (its cryptography library) provides, including support for [elliptic-curve cryptography](wikipedia://en/9966) (ECDH, ECDSA and EdDSA)[^o24] in the "modern" series (i.e. since GnuPG 2.1).

## History {#History}

GnuPG was initially developed by [Werner Koch](https://en.wikipedia.org/wiki/Werner_Koch).[^o14][^o15] The first production version, version 1.0.0, was released on September 7, 1999, almost two years after the first GnuPG release (version 0.0.0).[^o16][^o14] The [German Federal Ministry of Economics and Technology](https://en.wikipedia.org/wiki/Federal_Ministry_for_Economic_Affairs_and_Energy) funded the documentation and the port to [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows) in 2000.[^o15]

GnuPG is a system compliant to the OpenPGP standard, thus the history of OpenPGP is of importance; it was designed to interoperate with [PGP](wikipedia://en/23080), an email encryption program initially designed and developed by [Phil Zimmermann](wikipedia://en/23486).[^o17][^o18]

On February 7, 2014, a GnuPG [crowdfunding](https://en.wikipedia.org/wiki/Crowdfunding) effort closed, raising [€](https://en.wikipedia.org/wiki/Euro)36,732 for a new website and infrastructure improvements.[^o19]

### Branches {#Branches}

Since the release of a stable GnuPG 2.3, starting with version 2.3.3 in October 2021, three stable branches of GnuPG are actively maintained:[^o21]

- A "[stable](https://en.wikipedia.org/wiki/Software_release_life_cycle#Stable_release) branch", which currently is (as of 2026) the 2.5 branch.[^o22]
- An "old stable branch", which currently is (as of 2026) the 2.4 branch.
- The old "[legacy](https://en.wikipedia.org/wiki/Legacy_system#Perspectives_on_legacy_code) branch" (formerly called "classic branch"), which is and will stay the 1.4 branch.

Before GnuPG 2.3, two stable branches of GnuPG were actively maintained:

- "Modern" (2.2), with numerous new features, such as [elliptic-curve cryptography](wikipedia://en/9966), compared to the former "stable" (2.0) branch, which it replaced with the release of GnuPG 2.2.0 on August 28, 2017.[^o23] It was initially released on November 6, 2014.[^o24]
- "Classic" (1.4), the very old, but still maintained stand-alone version, most suitable for outdated or embedded platforms. Initially released on December 16, 2004.[^o25]

Different GnuPG 2.x versions (e.g. from the 2.2 and 2.0 branches) cannot be installed at the same time. However, it is possible to install a "classic" GnuPG version (i.e. from the 1.4 branch) along with any GnuPG 2.x version.[^o24]

Before the release of GnuPG 2.2 ("modern"), the now deprecated "stable" branch (2.0) was recommended for general use, initially released on November 13, 2006.[^o26] This branch reached its [end-of-life](https://en.wikipedia.org/wiki/End-of-life_%28product%29) on December 31, 2017;[^o27] Its last version is 2.0.31, released on December 29, 2017.[^o28]

Before the release of GnuPG 2.0, all stable releases originated from a single branch; i.e., before November 13, 2006, no multiple release branches were maintained in parallel. These former, sequentially succeeding (up to 1.4) release branches were:

- \1.2 branch, initially released on September 22, 2002,[^o29] with 1.2.6 as the last version, released on October 26, 2004.[^o30]
- \1.0 branch, initially released on September 7, 1999,[^o16] with 1.0.7 as the last version, released on April 30, 2002.[^o31]

(Note that before the release of GnuPG 2.3.0, branches with an odd minor release number (e.g. 2.1, 1.9, 1.3) were development branches leading to a stable release branch with a "+ 0.1" higher version number (e.g. 2.2, 2.0, 1.4); hence branches 2.2 and 2.1 both belong to the "modern" series, 2.0 and 1.9 both to the "stable" series, while the branches 1.4 and 1.3 both belong to the "classic" series.

With the release of GnuPG 2.3.0, this nomenclature was altered to be composed of a "stable" and "LTS" branch from the "modern" series, plus 1.4 as the last maintained "classic" branch. Also note that even or odd minor release numbers do not indicate a stable or development release branch, anymore.)

## Platforms {#Platforms}

*Image: Zypper new repository package signing key screenshot.png.* Example of usage of GnuPG: As [software repository](https://en.wikipedia.org/wiki/Software_repository) signing key for [openSUSE](https://en.wikipedia.org/wiki/OpenSUSE) (with [ZYpp](https://en.wikipedia.org/wiki/ZYpp))

Although the basic GnuPG program has a [command-line interface](https://en.wikipedia.org/wiki/Command-line_interface), there exists various [front-ends](https://en.wikipedia.org/wiki/Front_and_back_ends) that provide it with a [graphical user interface](https://en.wikipedia.org/wiki/Graphical_user_interface). For example, GnuPG encryption support has been integrated into [KMail](https://en.wikipedia.org/wiki/Kontact#E-Mail) and [Evolution](https://en.wikipedia.org/wiki/GNOME_Evolution), the graphical [email clients](https://en.wikipedia.org/wiki/Email_client) found in [KDE](https://en.wikipedia.org/wiki/KDE) and [GNOME](https://en.wikipedia.org/wiki/GNOME), the most popular [Linux](https://en.wikipedia.org/wiki/Linux) desktops. There are also graphical GnuPG front-ends, for example [Seahorse](https://en.wikipedia.org/wiki/Seahorse_%28software%29) for GNOME and [KGPG](https://en.wikipedia.org/wiki/KGPG) and [Kleopatra](https://en.wikipedia.org/wiki/Kleopatra_%28software%29) for KDE.

GPGTools provides a number of front-ends for OS integration of encryption and [key management](wikipedia://en/631063) as well as GnuPG installations via [Installer](https://en.wikipedia.org/wiki/Installer_%28macOS%29) [packages](https://en.wikipedia.org/wiki/Package_manager)[^o33] for [macOS](https://en.wikipedia.org/wiki/MacOS). GPG Suite[^o33] installs all related OpenPGP applications (GPG Keychain), plugins ([GPG Mail](https://en.wikipedia.org/wiki/GPG_Mail)) and dependencies (MacGPG), along with GPG Services (integration into macOS Services menu) to use GnuPG based encryption.

[Instant messaging](https://en.wikipedia.org/wiki/Instant_messaging) applications such as [Psi](https://en.wikipedia.org/wiki/Psi_%28instant_messaging_client%29) and Fire can automatically secure messages when GnuPG is installed and configured. Web-based software such as [Horde](https://en.wikipedia.org/wiki/Horde_%28software%29) also makes use of it. The cross-platform [extension](https://en.wikipedia.org/wiki/Add-on_%28Mozilla%29) [Enigmail](wikipedia://en/435217) provides GnuPG support for [Mozilla Thunderbird](https://en.wikipedia.org/wiki/Mozilla_Thunderbird) and [SeaMonkey](https://en.wikipedia.org/wiki/SeaMonkey). Similarly, Enigform provides GnuPG support for [Mozilla Firefox](https://en.wikipedia.org/wiki/Firefox). FireGPG was discontinued June 7, 2010.[^o34]

In 2005, g10 Code GmbH and Intevation GmbH released [Gpg4win](wikipedia://en/12220682), a software suite that includes GnuPG for Windows, GNU Privacy Assistant, and GnuPG plug-ins for [Windows Explorer](https://en.wikipedia.org/wiki/File_Explorer) and [Outlook](https://en.wikipedia.org/wiki/Microsoft_Outlook). These tools are wrapped in a standard Windows installer, making it easier for GnuPG to be installed and used on Windows systems.[^o35]

## Vulnerabilities {#Vulnerabilities}

The OpenPGP standard specifies several methods of [digitally signing](wikipedia://en/59644) messages. In 2003, due to an error in a change to GnuPG intended to make one of those methods more efficient, a security vulnerability was introduced.[^o37] It affected only one method of digitally signing messages, only for some releases of GnuPG (1.0.2 through 1.2.3), and there were fewer than 1000 such keys listed on the key servers.[^o38] Most people did not use this method, and were in any case discouraged from doing so, so the damage caused (if any, since none has been publicly reported) would appear to have been minimal. Support for this method has been removed from GnuPG versions released after this discovery (1.2.4 and later).

Two further vulnerabilities were discovered in early 2006; the first being that scripted uses of GnuPG for signature verification may result in [false positives](wikipedia://en/43286898),[^o39] the second that non-MIME messages were vulnerable to the injection of data which while not covered by the digital signature, would be reported as being part of the signed message.[^o40] In both cases updated versions of GnuPG were made available at the time of the announcement.

In June 2017, a vulnerability (CVE-2017-7526) was discovered within [Libgcrypt](wikipedia://en/29870579) by Bernstein, Breitner and others: a library used by GnuPG, which enabled a full key recovery for RSA-1024 and about more than 1/8 of RSA-2048 keys. This [side-channel attack](wikipedia://en/667678) exploits the fact that [Libgcrypt](wikipedia://en/29870579) used a [sliding windows method for exponentiation](wikipedia://en/10237#Sliding_window_method) which leads to the leakage of exponent bits and to full key recovery.[^o41][^o42] Again, an updated version of GnuPG was made available at the time of the announcement.

Around June 2018, the [SigSpoof](https://en.wikipedia.org/wiki/SigSpoof) attacks were announced. These allowed an attacker to convincingly spoof digital signatures.[^o43][^o44]

In January 2021, Libgcrypt 1.9.0 was released, which was found to contain a severe bug that was simple to exploit. A fix was released 10 days later in Libgcrypt 1.9.1.[^o45]

In December 2025, at [Chaos Communication Congress](https://en.wikipedia.org/wiki/Chaos_Communication_Congress), Lexi Groves (aka 49016) and Liam Wachter presented a series of vulnerabilities in GnuPG, ranging from [remote code execution](https://en.wikipedia.org/wiki/Remote_code_execution) to unauthorized subkey addition. The team reported those bugs to the GnuPG issue tracker, with some of them getting fixed and others still remaining unresolved.[^o46][^o47]

## Divergence from OpenPGP standard {#Divergence_from_OpenPGP_standard}

In November 2023, the LibrePGP standard was released. This was in response to changes made to the OpenPGP standard that were perceived by the GnuPG team to be unfounded. The GnuPG project no longer aims to comply with the OpenPGP standard, instead opting to comply with their own LibrePGP standard, which is meant to be based on the OpenPGP standard as it existed in November 2007.[^o49][^o50]
