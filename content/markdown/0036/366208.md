# Typed lambda calculus

::: {#o1 .subject cue=lead name="Typed lambda calculus"}

In [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), a **typed [lambda calculus](wikipedia://en/18203)** is a [typed](wikipedia://en/40282) formalism that uses the lambda symbol ($\lambda$) to denote anonymous function abstraction. In this context, types are usually objects of a [syntactic](wikipedia://en/546039) nature that are assigned to lambda terms; the exact nature of a type depends on the calculus considered (see kinds below). From a certain point of view, typed lambda calculi can be seen as refinements of the [untyped lambda calculus](https://en.wikipedia.org/wiki/Untyped_lambda_calculus), but from another point of view, they can also be considered the more fundamental theory and *untyped lambda calculus* a special case with only one type.[^o2]

:::

Typed lambda calculi are foundational [programming languages](https://en.wikipedia.org/wiki/Programming_languages) and are the base of typed [functional programming languages](https://en.wikipedia.org/wiki/Functional_programming_languages) such as [ML](https://en.wikipedia.org/wiki/ML_programming_language) and [Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29) and, more indirectly, typed [imperative programming languages](https://en.wikipedia.org/wiki/Imperative_programming). Typed lambda calculi play an important role in the design of [type systems](https://en.wikipedia.org/wiki/Type_systems) for programming languages; here, typability usually captures desirable properties of the program (e.g., the program will not cause a memory access violation).

Typed lambda calculi are closely related to [mathematical logic](wikipedia://en/19636) and [proof theory](wikipedia://en/183478) via the [Curry&ndash;Howard isomorphism](https://en.wikipedia.org/wiki/Curry&ndash;Howard_isomorphism) and they can be considered as the [internal language](https://en.wikipedia.org/wiki/Internal_language) of certain classes of [categories](wikipedia://en/5869). For example, the [simply typed lambda calculus](wikipedia://en/1986011) is the language of [Cartesian closed categories](wikipedia://en/237037) (CCCs).[^o3]

## Kinds of typed lambda calculi {#Kinds_of_typed_lambda_calculi}

Various typed lambda calculi have been studied. The [simply typed lambda calculus](wikipedia://en/1986011) has only one [type constructor](wikipedia://en/24047271), the arrow $\to$, and its only types are [basic types](https://en.wikipedia.org/wiki/Basic_type) and [function types](wikipedia://en/583532) $\sigma\to\tau$. [System T](wikipedia://en/16974776) extends the simply typed lambda calculus with a type of natural numbers and higher-order [primitive recursion](https://en.wikipedia.org/wiki/Primitive_recursion); in this system all functions provably [computable](wikipedia://en/1139338) in [Peano arithmetic](https://en.wikipedia.org/wiki/Peano_arithmetic) are definable. [System F](wikipedia://en/767637) allows [polymorphism](https://en.wikipedia.org/wiki/Polymorphism_%28computer_science%29) by using universal quantification over all types; from a logical perspective it can describe all functions that are provably total in [second-order logic](wikipedia://en/341428). Lambda calculi with [dependent types](https://en.wikipedia.org/wiki/Dependent_types) are the base of [intuitionistic type theory](wikipedia://en/345023), the [calculus of constructions](wikipedia://en/613557) and the [logical framework](https://en.wikipedia.org/wiki/LF_%28logical_framework%29) (LF), a pure lambda calculus with dependent types. Based on work by Berardi on [pure type systems](wikipedia://en/17870536), [Henk Barendregt](wikipedia://en/1651213) proposed the [lambda cube](wikipedia://en/901593) to systematize the relations of pure typed lambda calculi (including simply typed lambda calculus, System F, LF and the calculus of constructions).[^o5]

Some typed lambda calculi introduce a notion of *[subtyping](wikipedia://en/213508)*, i.e. if $A$ is a subtype of $B$, then all terms of type $A$ also have type $B$. Typed lambda calculi with subtyping are the simply typed lambda calculus with conjunctive types and [System F<sub>\<:</sub>](https://en.wikipedia.org/wiki/System_F-sub).

All the systems mentioned so far, with the exception of the untyped lambda calculus, are *[strongly normalizing](https://en.wikipedia.org/wiki/Strongly_normalizing)*: all computations terminate. Therefore, they cannot describe all [Turing-computable](https://en.wikipedia.org/wiki/Turing-computable) functions.[^o6] As another consequence they are consistent as a logic, i.e. there are uninhabited types. There exist, however, typed lambda calculi that are not strongly normalizing. For example the dependently typed lambda calculus with a type of all types (Type : Type) is not normalizing due to [Girard's paradox](https://en.wikipedia.org/wiki/Girard's_paradox). This system is also the simplest pure type system, a formalism which generalizes the lambda cube. Systems with explicit recursion combinators, such as [Plotkin's](https://en.wikipedia.org/wiki/Gordon_Plotkin) "[Programming language for Computable Functions](https://en.wikipedia.org/wiki/Programming_language_for_Computable_Functions)" (PCF), are not normalizing, but they are not intended to be interpreted as a logic. Indeed, PCF is a prototypical, typed functional programming language, where types are used to ensure that programs are well-behaved but not necessarily that they are terminating.

## Applications to programming languages {#Applications_to_programming_languages}

In [computer programming](https://en.wikipedia.org/wiki/Computer_programming), the routines (functions, procedures, methods) of [strongly typed programming languages](https://en.wikipedia.org/wiki/Strongly_typed_programming_language) closely correspond to typed lambda expressions.[^o8]
