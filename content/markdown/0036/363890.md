# One-way function

::: {#o1 .problem cue=unsolved}

Do one-way functions exist?

:::

::: {#o2 .subject cue=lead name="One-way function"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science), a **one-way function** is a [function](wikipedia://en/185427) that is easy to compute on every input, but hard to [invert](wikipedia://en/14907) given the [image](wikipedia://en/579311) of a random input. Here, "easy" and "hard" are to be understood in the sense of [computational complexity theory](wikipedia://en/7543), specifically the theory of [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) problems. This has nothing to do with whether the function is [one-to-one](https://en.wikipedia.org/wiki/One-to-one_function); finding any one input with the desired image is considered a successful inversion. (See , below.)

:::

The existence of such one-way functions is still an open [conjecture](wikipedia://en/6138). Their existence would prove that the [complexity classes](https://en.wikipedia.org/wiki/Complexity_classes) [P and NP are not equal](https://en.wikipedia.org/wiki/P_=_NP_problem), thus resolving the foremost unsolved question of theoretical computer science.[^o3] The converse is not known to be true, i.e. the existence of a proof that P ≠ NP would not directly imply the existence of one-way functions.[^o4]

In applied contexts, the terms "easy" and "hard" are usually interpreted relative to some specific computing entity; typically "cheap enough for the legitimate users" and "prohibitively expensive for any [malicious agents](https://en.wikipedia.org/wiki/Black_hat_hacking)". One-way functions, in this sense, are fundamental tools for [cryptography](wikipedia://en/18934432), [personal identification](https://en.wikipedia.org/wiki/Personal_identification), [authentication](wikipedia://en/47967), and other [data security](https://en.wikipedia.org/wiki/Data_security) applications. While the existence of one-way functions in this sense is also an open conjecture, there are several candidates that have withstood decades of intense scrutiny. Some of them are essential ingredients of most [telecommunications](https://en.wikipedia.org/wiki/Telecommunications), [e-commerce](https://en.wikipedia.org/wiki/E-commerce), and [e-banking](https://en.wikipedia.org/wiki/Online_banking) systems around the world.

## Theoretical definition {#Theoretical_definition}

A function *f* : {0, 1}<sup>\*</sup> → {0, 1}<sup>\*</sup> is **one-way** if *f* can be computed by a polynomial-time algorithm, but any polynomial-time [randomized algorithm](wikipedia://en/495383) $F$ that attempts to compute a pseudo-inverse for *f* succeeds with [negligible](wikipedia://en/8426019) probability. (The \* superscript means any number of repetitions, see [Kleene star](wikipedia://en/16750).) That is, for all randomized algorithms $F$, all positive integers *c* and all sufficiently large *n* = length(*x*),

$$\Pr[f(F(f(x))) = f(x)] < n^{-c},$$

where the probability is over the choice of *x* from the [discrete uniform distribution](https://en.wikipedia.org/wiki/Uniform_distribution_%28discrete%29) on {0, 1} <sup>*n*</sup>, and the randomness of $F$.[^o6]

Note that, by this definition, the function must be "hard to invert" in the [average-case, rather than worst-case](wikipedia://en/37956) sense. This is different from much of complexity theory (e.g., [NP-hardness](https://en.wikipedia.org/wiki/NP-hard)), where the term "hard" is meant in the worst-case. That is why even if some candidates for one-way functions (described below) are known to be [NP-complete](https://en.wikipedia.org/wiki/NP-complete), it does not imply their one-wayness. The latter property is only based on the lack of known algorithms to solve the problem.

It is not sufficient to make a function "lossy" (not one-to-one) to have a one-way function. In particular, the function that outputs the string of *n* zeros on any input of length *n* is *not* a one-way function because it is easy to come up with an input that will result in the same output. More precisely: For such a function that simply outputs a string of zeroes, an algorithm *F* that just outputs any string of length *n* on input *f*(*x*) will "find" a proper preimage of the output, even if it is not the input which was originally used to find the output string.

## Related concepts {#Related_concepts}

A **one-way permutation** is a one-way function that is also a permutation—that is, a one-way function that is [bijective](https://en.wikipedia.org/wiki/Bijective). One-way permutations are an important [cryptographic primitive](wikipedia://en/4928985), and it is not known if their existence is implied by the existence of one-way functions.

A [trapdoor one-way function](https://en.wikipedia.org/wiki/Trapdoor_one-way_function) or trapdoor permutation is a special kind of one-way function. Such a function is hard to invert unless some secret information, called the *trapdoor*, is known.

A **collision-free hash function** *f* is a one-way function that is also *collision-resistant*; that is, no [randomized polynomial time](https://en.wikipedia.org/wiki/Randomized_polynomial_time) algorithm can find a [collision](https://en.wikipedia.org/wiki/Hash_collision)—distinct values *x*, *y* such that *f*(*x*) = *f*(*y*)—with non-negligible probability.[^o9]

A [hard-core predicate](wikipedia://en/1182871) of a one-way function *f* is a predicate (i.e. single bit) *b* such that *b(x)* is easy to compute given *x* but hard to compute given only *f(x)*.

:::

## Theoretical implications of one-way functions {#Theoretical_implications_of_one-way_functions}

If *f* is a one-way function, then the inversion of *f* would be a problem whose output is hard to compute (by definition) but easy to check (just by computing *f* on it). Thus, the existence of a one-way function implies that [FP](wikipedia://en/663347) ≠ [FNP](wikipedia://en/663351), which in turn implies that P ≠ NP. However, P ≠ NP does not imply the existence of one-way functions.

The existence of a one-way function implies the existence of many other useful concepts, including:

- [Pseudorandom generators](wikipedia://en/1812809)
- [Pseudorandom function](https://en.wikipedia.org/wiki/Pseudorandom_function) families
- [Bit commitment schemes](wikipedia://en/439489)
- Private-key encryption schemes secure against [adaptive chosen-ciphertext attack](wikipedia://en/426533)
- [Message authentication codes](wikipedia://en/567523)
- [Digital signature schemes](https://en.wikipedia.org/wiki/Digital_signature_scheme) (secure against adaptive chosen-message attack)

## Candidates for one-way functions {#Candidates_for_one-way_functions}

The following are several candidates for one-way functions (as of April 2009). Clearly, it is not known whether these functions are indeed one-way; but extensive research has so far failed to produce an efficient inverting algorithm for any of them.

### Multiplication and factoring {#Multiplication_and_factoring}

The function *f* takes as inputs two prime numbers *p* and *q* in binary notation and returns their product. This function can be "easily" computed in [*O*(*b*<sup>2</sup>)](wikipedia://en/44578) time, where *b* is the total number of bits of the inputs. Inverting this function requires finding the [factors of a given integer](wikipedia://en/15491) *N*. The best factoring algorithms known run in $O\left(\exp\sqrt[3]{\frac{64}{9} b (\log b)^2}\right)$time, where b is the number of bits needed to represent *N*.

This function can be generalized by allowing *p* and *q* to range over a suitable set of [semiprimes](https://en.wikipedia.org/wiki/Semiprimes). Note that *f* is not one-way for randomly selected integers *p*, *q* > 1, since the product will have 2 as a factor with probability 3/4 (because the probability that an arbitrary *p* is odd is 1/2, and likewise for *q*, so if they're chosen independently, the probability that both are odd is therefore 1/4; hence the probability that *p* or *q* is even, is 1 − 1/4 = 3/4).

### The Rabin function (modular squaring) {#The_Rabin_function_(modular_squaring)}

The **Rabin function**,[^o3] or squaring [modulo](wikipedia://en/20087) $N=pq$, where $p$ and $q$ are primes is believed to be a collection of one-way functions. We write

$$\operatorname{Rabin}_N(x)\triangleq x^2\bmod N$$

to denote squaring modulo $N$: a specific member of the **Rabin collection**. It can be shown that extracting square roots, i.e. inverting the Rabin function, is computationally equivalent to factoring $N$ (in the sense of [polynomial-time reduction](wikipedia://en/159695)). Hence it can be proven that the Rabin collection is one-way if and only if factoring is hard. This also holds for the special case in which $p$ and $q$ are of the same bit length. The [Rabin signature algorithm](wikipedia://en/5954800) is based on the assumption that this Rabin function is one-way.

### Discrete exponential and logarithm {#Discrete_exponential_and_logarithm}

[Modular exponentiation](wikipedia://en/903032) can be done in polynomial time. Inverting this function requires computing the [discrete logarithm](wikipedia://en/181334). Currently there are several popular groups for which no algorithm to calculate the underlying discrete logarithm in polynomial time is known. These groups are all [finite abelian groups](https://en.wikipedia.org/wiki/Finite_abelian_group) and the general discrete logarithm problem can be described as thus.

Let *G* be a finite abelian group of [cardinality](wikipedia://en/6174) *n*. Denote its [group operation](https://en.wikipedia.org/wiki/Group_operation) by multiplication. Consider a [primitive element](wikipedia://en/19127149) *α* ∈ *G* and another element *β* ∈ *G*. The discrete logarithm problem is to find the positive integer *k*, where 1 ≤ *k* ≤ n, such that:

$$\alpha^k = \underbrace{\alpha \cdot \alpha \cdot \ldots \cdot \alpha}_{k \; \mathrm{times}} = \beta$$

The integer *k* that solves the equation *α<sup>k</sup>* = *β* is termed the **discrete logarithm** of *β* to the base *α*. One writes *k* = log<sub>*α*</sub> *β*.

Popular choices for the group *G* in discrete logarithm [cryptography](wikipedia://en/18934432) are the cyclic groups [(**Z**<sub>*p*</sub>)<sup>*×*</sup>](wikipedia://en/1195234) (e.g. [ElGamal encryption](wikipedia://en/59458), [Diffie–Hellman key exchange](wikipedia://en/7903), and the [Digital Signature Algorithm](wikipedia://en/59470)) and cyclic subgroups of [elliptic curves](wikipedia://en/10225) over [finite fields](wikipedia://en/11615) (*see* [elliptic curve cryptography](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography)).

An elliptic curve is a set of pairs of elements of a [field](wikipedia://en/10603) satisfying *y*<sup>2</sup> = *x*<sup>3</sup> + *ax* + *b*. The elements of the curve form a group under an operation called "point addition" (which is not the same as the addition operation of the field). Multiplication *kP* of a point *P* by an integer *k* (*i.e.*, a [group action](https://en.wikipedia.org/wiki/Group_action_%28mathematics%29) of the additive group of the integers) is defined as repeated addition of the point to itself. If *k* and *P* are known, it is easy to compute *R* = *kP*, but if only *R* and *P* are known, it is assumed to be hard to compute *k*.

### Cryptographically secure hash functions {#Cryptographically_secure_hash_functions}

There are a number of [cryptographic hash functions](wikipedia://en/439526) that are fast to compute, such as [SHA-256](https://en.wikipedia.org/wiki/SHA-256). Some of the simpler versions have fallen to sophisticated analysis, but the strongest versions continue to offer fast, practical solutions for one-way computation. Most of the theoretical support for the functions are more techniques for thwarting some of the previously successful attacks.

### Other candidates {#Other_candidates}

Other candidates for one-way functions include the hardness of the decoding of random [linear codes](wikipedia://en/1866743), the hardness of certain [lattice problems](https://en.wikipedia.org/wiki/Lattice_problems), and the [subset sum problem](wikipedia://en/36811) ([Naccache–Stern knapsack cryptosystem](wikipedia://en/6157535)).

## Universal one-way function {#Universal_one-way_function}

There is an explicit function *f* that has been proved to be one-way, if and only if one-way functions exist.[^o18] In other words, if any function is one-way, then so is *f*. Since this function was the first combinatorial complete one-way function to be demonstrated, it is known as the "universal one-way function". The problem of finding a one-way function is thus reduced to provingperhaps non-constructivelythat one such function exists.

There also exists a function that is one-way if polynomial-time bounded [Kolmogorov complexity](wikipedia://en/1635#Time-bounded_complexity) is mildly hard on average. Since the existence of one-way functions implies that polynomial-time bounded Kolmogorov complexity is mildly hard on average, the function is a universal one-way function.[^o19]

## Quantum one-way functions {#Quantum_one-way_functions}

[**Post-quantum one-way functions**](https://www.nist.gov/pqc) are classical functions whose inversion is assumed to remain computationally hard even for [quantum computers](wikipedia://en/25220).[^o21]**Quantum one-way functions (QOWFs)**, and related quantum cryptographic primitives, instead produce quantum states as outputs.[^o22] A typical QOWF efficiently maps of a classical input to a quantum state. As in the classical setting, the mapping is easy to compute but intended to be difficult to invert. Depending on the construction, this hardness may arise from computational assumptions or directly from the laws of quantum mechanics, such as the Holevo bound, the no-cloning theorem, and the impossibility of perfectly distinguishing non-orthogonal quantum states. Consequently, some QOWFs provide information-theoretic security, provided that only a bounded number of copies of the output state are available. QOWFs have been proposed as building blocks for quantum public-key cryptography, quantum digital signatures, quantum money, and other quantum cryptographic protocols.
