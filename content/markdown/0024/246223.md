# Component (graph theory)

::: {#o1 .subject cue=lead name="Component"}

*Image: Pseudoforest.svg.* A graph with three components

In [graph theory](wikipedia://en/12401), a **component** of an [undirected graph](https://en.wikipedia.org/wiki/Undirected_graph) is a [connected](https://en.wikipedia.org/wiki/Connected_graph) [subgraph](wikipedia://en/325802#subgraph) that is not part of any larger connected subgraph. The components of any graph [partition](wikipedia://en/11973947) its vertices into [disjoint sets](https://en.wikipedia.org/wiki/Disjoint_set), and are the [induced subgraphs](wikipedia://en/1655188) of those sets. A graph that is itself connected has exactly one component, consisting of the whole graph. Components are sometimes called **connected components**.

:::

The number of components in a given graph is an important [graph invariant](https://en.wikipedia.org/wiki/Graph_invariant), and is closely related to invariants of [matroids](wikipedia://en/244321), [topological spaces](wikipedia://en/30450), and [matrices](wikipedia://en/20556859). In [random graphs](wikipedia://en/358477), a frequently occurring phenomenon is the incidence of a [giant component](wikipedia://en/2379792), one component that is significantly larger than the others; and of a [percolation threshold](wikipedia://en/11790568), an edge probability above which a giant component exists and below which it does not.

The components of a graph can be constructed in [linear time](https://en.wikipedia.org/wiki/Linear_time), and a special case of the problem, [connected-component labeling](https://en.wikipedia.org/wiki/Connected-component_labeling), is a basic technique in [image analysis](https://en.wikipedia.org/wiki/Image_analysis). [Dynamic connectivity](https://en.wikipedia.org/wiki/Dynamic_connectivity) algorithms maintain components as edges are inserted or deleted in a graph, in low time per change. In [computational complexity theory](wikipedia://en/7543), connected components have been used to study algorithms with limited [space complexity](wikipedia://en/338946), and [sublinear time](https://en.wikipedia.org/wiki/Sublinear_time) algorithms can accurately estimate the number of components.

::: {#o3 .definition cue=heading name="Definitions and examples"}

## Definitions and examples {#Definitions_and_examples}

*Image: Equivalentie.svg.* A [cluster graph](wikipedia://en/50931136) with seven components

A component of a given undirected graph may be defined as a connected subgraph that is not part of any larger connected subgraph. For instance, the graph shown in the first illustration has three components. Every vertex $v$ of a graph belongs to one of the graph's components, which may be found as the [induced subgraph](wikipedia://en/1655188) of the set of vertices [reachable](wikipedia://en/2833097) from $v$. Every graph is the [disjoint union](wikipedia://en/9938459) of its components. Additional examples include the following special cases:

- In an [empty graph](https://en.wikipedia.org/wiki/Empty_graph), each vertex forms a component with one vertex and zero edges. More generally, a component of this type is formed for every [isolated vertex](https://en.wikipedia.org/wiki/Isolated_vertex) in any graph.
- In a [connected graph](https://en.wikipedia.org/wiki/Connected_graph), there is exactly one component: the whole graph.
- In a [forest](https://en.wikipedia.org/wiki/Forest_%28graph_theory%29), every component is a [tree](wikipedia://en/48560).
- In a [cluster graph](wikipedia://en/50931136), every component is a [maximal clique](https://en.wikipedia.org/wiki/Maximal_clique). These graphs may be produced as the [transitive closures](wikipedia://en/292239) of arbitrary undirected graphs, for which finding the transitive closure is an equivalent formulation of identifying the connected components.

Another definition of components involves the equivalence classes of an [equivalence relation](wikipedia://en/9259) defined on the graph's vertices. In an undirected graph, a vertex $v$ is *reachable* from a vertex $u$ if there is a [path](wikipedia://en/638889) from $u$ to $v$, or equivalently a [walk](https://en.wikipedia.org/wiki/Walk_%28graph_theory%29) (a path allowing repeated vertices and edges). Reachability is an equivalence relation, since:

- It is [reflexive](wikipedia://en/200458): There is a trivial path of length zero from any vertex to itself.
- It is [symmetric](wikipedia://en/200459): If there is a path from $u$ to $v$, the same edges in the reverse order form a path from $v$ to $u$.
- It is [transitive](wikipedia://en/200463): If there is a path from $u$ to $v$ and a path from $v$ to $w$, the two paths may be concatenated together to form a walk from $u$ to $w$.

The [equivalence classes](wikipedia://en/9260) of this relation partition the vertices of the graph into [disjoint sets](wikipedia://en/39359), subsets of vertices that are all reachable from each other, with no additional reachable pairs outside of any of these subsets. Each vertex belongs to exactly one equivalence class. The components are then the [induced subgraphs](wikipedia://en/1655188) formed by each of these equivalence classes. Alternatively, some sources define components as the sets of vertices rather than as the subgraphs they induce.

Similar definitions involving equivalence classes have been used to defined components for other forms of graph [connectivity](wikipedia://en/1614492), including the [weak components](https://en.wikipedia.org/wiki/Weak_component) and [strongly connected components](wikipedia://en/684680) of [directed graphs](wikipedia://en/19721986) and the [biconnected components](wikipedia://en/4842394) of undirected graphs.

:::

## Number of components {#Number_of_components}

The number of components of a given finite graph can be used to count the number of edges in its [spanning forests](https://en.wikipedia.org/wiki/Spanning_forest): In a graph with $n$ vertices and $c$ components, every spanning forest will have exactly $n-c$ edges. This number $n-c$ is the [matroid](wikipedia://en/244321)-theoretic [rank](wikipedia://en/17458495) of the graph, and the [rank](wikipedia://en/37123010) of its [graphic matroid](wikipedia://en/745714). The rank of the [dual cographic matroid](wikipedia://en/23515837) equals the [circuit rank](https://en.wikipedia.org/wiki/Circuit_rank) of the graph, the minimum number of edges that must be removed from the graph to break all its cycles. In a graph with $m$ edges, $n$ vertices and $c$ components, the circuit rank is $m-n+c$.

A graph can be interpreted as a [topological space](wikipedia://en/30450) in multiple ways, for instance by placing its vertices as points in [general position](wikipedia://en/383736) in three-dimensional [Euclidean space](wikipedia://en/9697) and representing its edges as line segments between those points. The components of a graph can be generalized through these interpretations as the [topological connected components](https://en.wikipedia.org/wiki/Connected_component_%28topology%29) of the corresponding space; these are equivalence classes of points that cannot be separated by pairs of disjoint closed sets. Just as the number of connected components of a topological space is an important [topological invariant](https://en.wikipedia.org/wiki/Topological_invariant), the zeroth [Betti number](wikipedia://en/346262), the number of components of a graph is an important [graph invariant](https://en.wikipedia.org/wiki/Graph_invariant), and in [topological graph theory](wikipedia://en/1631772) it can be interpreted as the zeroth Betti number of the graph.

The number of components arises in other ways in graph theory as well. In [algebraic graph theory](wikipedia://en/1620216) it equals the multiplicity of 0 as an [eigenvalue](https://en.wikipedia.org/wiki/Eigenvalue) of the [Laplacian matrix](wikipedia://en/1448472) of a finite graph. It is also the index of the first nonzero coefficient of the [chromatic polynomial](wikipedia://en/1460126) of the graph, and the chromatic polynomial of the whole graph can be obtained as the product of the polynomials of its components. Numbers of components play a key role in [Tutte's theorem on perfect matchings](wikipedia://en/1655060) characterizing finite graphs that have [perfect matchings](wikipedia://en/44031) and the associated [Tutte–Berge formula](wikipedia://en/13250641) for the size of a [maximum matching](https://en.wikipedia.org/wiki/Maximum_matching), and in the definition of [graph toughness](wikipedia://en/8839340).

## Algorithms {#Algorithms}

It is straightforward to compute the components of a finite graph in linear time (in terms of the numbers of the vertices and edges of the graph) using either [breadth-first search](wikipedia://en/97026) or [depth-first search](wikipedia://en/97034). In either case, a search that begins at some particular vertex $v$ will find the entire component containing $v$ (and no more) before returning. All components of a graph can be found by looping through its vertices, starting a new breadth-first or depth-first search whenever the loop reaches a vertex that has not already been included in a previously found component. (Hopcroft Tarjan 1973) describe essentially this algorithm, and state that it was already "well known".

[Connected-component labeling](https://en.wikipedia.org/wiki/Connected-component_labeling), a basic technique in computer [image analysis](https://en.wikipedia.org/wiki/Image_analysis), involves the construction of a graph from the image and component analysis on the graph. The vertices are the subset of the [pixels](https://en.wikipedia.org/wiki/Pixel) of the image, chosen as being of interest or as likely to be part of depicted objects. Edges connect [adjacent pixels](wikipedia://en/21569386), with adjacency defined either orthogonally according to the [Von Neumann neighborhood](wikipedia://en/8485219), or both orthogonally and diagonally according to the [Moore neighborhood](wikipedia://en/4323874). Identifying the connected components of this graph allows additional processing to find more structure in those parts of the image or identify what kind of object is depicted. Researchers have developed component-finding algorithms specialized for this type of graph, allowing it to be processed in pixel order rather than in the more scattered order that would be generated by breadth-first or depth-first searching. This can be useful in situations where sequential access to the pixels is more efficient than random access, either because the image is represented in a hierarchical way that does not permit fast random access or because sequential access produces better [memory access patterns](https://en.wikipedia.org/wiki/Memory_access_pattern).

There are also efficient algorithms to dynamically track the components of a graph as vertices and edges are added, by using a [disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure) to keep track of the partition of the vertices into equivalence classes, replacing any two classes by their union when an edge connecting them is added. These algorithms take [amortized](wikipedia://en/236683) time $O(\alpha(n))$ per operation, where adding vertices and edges and determining the component in which a vertex falls are both operations, and $\alpha$ is a very slowly growing inverse of the very quickly growing [Ackermann function](wikipedia://en/2925). One application of this sort of incremental connectivity algorithm is in [Kruskal's algorithm](wikipedia://en/53776) for [minimum spanning trees](wikipedia://en/41795), which adds edges to a graph in sorted order by length and includes an edge in the minimum spanning tree only when it connects two different components of the previously-added subgraph. When both edge insertions and edge deletions are allowed, [dynamic connectivity](https://en.wikipedia.org/wiki/Dynamic_connectivity) algorithms can still maintain the same information, in amortized time $O(\log^2 n/\log\log n)$ per change and time $O(\log n/\log\log n)$ per connectivity query, or in near-logarithmic randomized [expected time](https://en.wikipedia.org/wiki/Expected_time).

Components of graphs have been used in [computational complexity theory](wikipedia://en/7543) to study the power of [Turing machines](wikipedia://en/30403) that have a working memory limited to a [logarithmic](wikipedia://en/17860) number of bits, with the much larger input accessible only through read access rather than being modifiable. The problems that can be solved by machines limited in this way define the [complexity class](wikipedia://en/502426) [L](wikipedia://en/1149999). It was unclear for many years whether connected components could be found in this model, when formalized as a [decision problem](wikipedia://en/8336) of testing whether two vertices belong to the same component, and in 1982 a related complexity class, [SL](wikipedia://en/1174919), was defined to include this connectivity problem and any other problem equivalent to it under logarithmic-space [reductions](wikipedia://en/848067). It was finally proven in 2008 that this connectivity problem can be solved in logarithmic space, and therefore that SL = L.

In a graph represented as an [adjacency list](wikipedia://en/392431), with random access to its vertices, it is possible to estimate the number of connected components, with constant probability of obtaining [additive (absolute) error](https://en.wikipedia.org/wiki/Absolute_error) at most $\varepsilon n$, in [sublinear time](https://en.wikipedia.org/wiki/Sublinear_time) $O(\varepsilon^{-2}\log\varepsilon^{-1})$.

:::

## In random graphs {#In_random_graphs}

*Image: Critical 1000-vertex Erdős–Rényi–Gilbert graph.svg.* An [Erdős–Rényi–Gilbert random graph](wikipedia://en/10477221) with 1000 vertices with edge probability $p=1/(n-1)$ (in the critical range), showing a large component and many small ones

In [random graphs](wikipedia://en/358477) the sizes of components are given by a [random variable](wikipedia://en/25685), which, in turn, depends on the specific model of how random graphs are chosen. In the $G(n, p)$ version of the [Erdős–Rényi–Gilbert model](wikipedia://en/10477221), a graph on $n$ vertices is generated by choosing randomly and independently for each pair of vertices whether to include an edge connecting that pair, with probability $p$ of including an edge and probability $1-p$ of leaving those two vertices without an edge connecting them. The connectivity of this model depends on $p$, and there are three different ranges of $p$ with very different behavior from each other. In the analysis below, all outcomes occur [with high probability](https://en.wikipedia.org/wiki/With_high_probability), meaning that the probability of the outcome is arbitrarily close to one for sufficiently large values of $n$. The analysis depends on a parameter $\varepsilon$, a positive constant independent of $n$ that can be arbitrarily close to zero.

**Subcritical $p < (1-\varepsilon)/n$**

In this range of $p$, all components are simple and very small. The largest component has logarithmic size. The graph is a [pseudoforest](wikipedia://en/13511542). Most of its components are trees: the number of vertices in components that have cycles grows more slowly than any unbounded function of the number of vertices. Every tree of fixed size occurs linearly many times.

**Critical $p \approx 1/n$**

The largest connected component has a number of vertices proportional to $n^{2/3}$. There may exist several other large components; however, the total number of vertices in non-tree components is again proportional to $n^{2/3}$.

**Supercritical $p >(1+\varepsilon)/n$**

There is a single [giant component](wikipedia://en/2379792) containing a linear number of vertices. For large values of $p$ its size approaches the whole graph: $|C_1| \approx yn$ where $y$ is the positive solution to the equation $e^{-p n y }=1-y$. The remaining components are small, with logarithmic size.

In the same model of random graphs, there will exist multiple connected components with high probability for values of $p$ below a significantly higher threshold, $p<(1-\varepsilon)(\log n)/n$, and a single connected component for values above the threshold, $p>(1+\varepsilon)(\log n)/n$. This phenomenon is closely related to the [coupon collector's problem](wikipedia://en/14721784): in order to be connected, a random graph needs enough edges for each vertex to be incident to at least one edge. More precisely, if random edges are added one by one to a graph, then with high probability the first edge whose addition connects the whole graph touches the last isolated vertex.

For different models including the random subgraphs of grid graphs, the connected components are described by [percolation theory](wikipedia://en/187805). A key question in this theory is the existence of a [percolation threshold](wikipedia://en/11790568), a critical probability above which a giant component (or infinite component) exists and below which it does not.
