# Unit type

::: {#o1 .subject cue=lead name="Unit type"}

In the area of [mathematical logic](wikipedia://en/19636) and [computer science](https://en.wikipedia.org/wiki/Computer_science) known as [type theory](wikipedia://en/40282), a **unit type** is a [type](https://en.wikipedia.org/wiki/Data_type) that allows only one value (and thus can hold no information). The carrier (underlying set) associated with a unit type can be any [singleton set](https://en.wikipedia.org/wiki/Singleton_set). There is an [isomorphism](wikipedia://en/14828) between any two such sets, so it is customary to talk about *the* unit type and ignore the details of its value. One may also regard the unit type as the type of 0-[tuples](wikipedia://en/132729), i.e. the [product](wikipedia://en/237868) of no types.

:::

The unit type is the [terminal object](https://en.wikipedia.org/wiki/Terminal_object) in the [category](wikipedia://en/5869) of types and typed functions. It should not be confused with the *zero* or [empty type](https://en.wikipedia.org/wiki/Empty_type), which allows *no* values and is the [initial object](https://en.wikipedia.org/wiki/Initial_object) in this category. Similarly, the [Boolean](https://en.wikipedia.org/wiki/Boolean_data_type) is the type with *two* values.

The unit type is implemented in most [functional programming](https://en.wikipedia.org/wiki/Functional_programming) languages. The [void type](https://en.wikipedia.org/wiki/Void_type) that is used in some imperative programming languages serves some of its functions, but because its carrier set is empty, it has some limitations (as detailed below).

## In programming languages {#In_programming_languages}

Several computer [programming languages](wikipedia://en/23015) provide a unit type to specify the result type of a [function](https://en.wikipedia.org/wiki/Function_%28computer_science%29) with the sole purpose of causing a [side effect](https://en.wikipedia.org/wiki/Side_effect_%28computer_science%29), and the argument type of a function that does not require arguments.

- In [Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29), [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29), and [Elm](https://en.wikipedia.org/wiki/Elm_%28programming_language%29), the unit type is called `()` and its only value is also `()`, reflecting the 0-tuple interpretation.
- In [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) descendants (including [OCaml](https://en.wikipedia.org/wiki/OCaml), [Standard ML](https://en.wikipedia.org/wiki/Standard_ML), and [F#](https://en.wikipedia.org/wiki/F_Sharp_%28programming_language%29)), the type is called `unit` but the value is written as `()`.
- In [Scala](wikipedia://en/3254510), the unit type is called `Unit` and its only value is written as `()`.
- In [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp) the type named NULL is a unit type which has one value, namely the symbol NIL. This should not be confused with the NIL *type*, which is the [bottom type](https://en.wikipedia.org/wiki/Bottom_type).
- In [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), there is a type called `NoneType` which allows the single value of `None`. In Python's optional static type annotations, this type is represented as `None`.[^o3]
- In [Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29), the unit type is called `Void` or `()` and its only value is also `()`, reflecting the 0-tuple interpretation.
- In [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), the unit type is called `Void` and its only value is `null`. It cannot be instantiated. It is used in [generics](https://en.wikipedia.org/wiki/Generics_in_Java) for denoting return types of `void`.
- In [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29), the unit type is written `struct{}` and its value is `struct{}{}`.
- In [PHP](https://en.wikipedia.org/wiki/PHP), the unit type is called null, which only value is NULL itself.
- In [JavaScript](https://en.wikipedia.org/wiki/JavaScript), both `Null` (its only value is `null`) and `Undefined` (its only value is `undefined`) are built-in unit types.
- in [Kotlin](https://en.wikipedia.org/wiki/Kotlin_%28programming_language%29), `Unit` is a singleton with only one value: the `Unit` object.
- In [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29), `nil` is the only instance of the `NilClass` class.
- In [C++](https://en.wikipedia.org/wiki/C++), the `std::monostate` unit type was added in [C++17](https://en.wikipedia.org/wiki/C++17). Before that, it is possible to define a custom unit type using an empty struct such as `struct Empty {}`.
- In [Dart](https://en.wikipedia.org/wiki/Dart_%28programming_language%29), both `Null` and the empty record (`()`, since Dart 3) have a single possible value, respectively, `null` and `()`.

### Void type as unit type {#Void_type_as_unit_type}

In [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29), [D](https://en.wikipedia.org/wiki/D_%28programming_language%29), and [PHP](https://en.wikipedia.org/wiki/PHP), `[[void return type|void]]` is used to designate a function that does not return anything useful, or a function that accepts no arguments. The unit type in C is conceptually similar to an empty `struct`, but a struct without members is not allowed in the C language specification (this is allowed in C++). Instead, '`void`' is used in a manner that simulates some, but not all, of the properties of the unit type, as detailed below. Like most imperative languages, C allows functions that do not return a value; these are specified as having the void return type. Such functions are called procedures in other imperative languages like [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29), where a syntactic distinction, instead of type-system distinction, is made between functions and procedures.

#### Difference in calling convention {#Difference_in_calling_convention}

The first notable difference between a true unit type and the void type is that the unit type may always be the type of the argument to a function, but the void type cannot be the type of an argument in C, despite the fact that it may appear as the sole argument in the list. This problem is best illustrated by the following program, which is a compile-time error in C:

```c
void f(void) {}
void g(void) {}

int main(void) {
    f(g()); // compile-time error here
    return 0;
}
```

This issue does not arise in most programming practice in C, because since the `void` type carries no information, it is useless to pass it anyway; but it may arise in [generic programming](https://en.wikipedia.org/wiki/Generic_programming), such as C++ [templates](https://en.wikipedia.org/wiki/Template_%28programming%29), where `[[void return type|void]]` must be treated differently from other types. In C++ however, empty classes are allowed, so it is possible to implement a real unit type; the above example becomes compilable as:

```cpp
class UnitType {};
constexpr UnitType UNIT;

UnitType f(UnitType) noexcept { 
    return UNIT; 
}

UnitType g(UnitType) noexcept { 
    return UNIT; 
}

int main() {
    f(g(UNIT));
    return 0;
}
```

For brevity, `UNIT` is not implemented as a [singleton](https://en.wikipedia.org/wiki/Singleton_pattern); see [singleton pattern](https://en.wikipedia.org/wiki/Singleton_pattern) for further explanation on singleton units.

#### Difference in storage {#Difference_in_storage}

The second notable difference is that the void type is special and can never be stored in a [record type](https://en.wikipedia.org/wiki/Record_%28computer_science%29), i.e. in a struct or a class in C/C++. In contrast, the unit type can be stored in records in functional programming languages, i.e. it can appear as the type of a field; the above implementation of the unit type in C++ can also be stored. While this may seem a useless feature, it does allow one for instance to elegantly implement a [set](https://en.wikipedia.org/wiki/Set_%28computer_science%29) as a [map](https://en.wikipedia.org/wiki/Associative_array) to the unit type; in the absence of a unit type, one can still implement a set this way by storing some dummy value of another type for each key.

#### In Generics {#In_Generics}

In Java Generics, type parameters must be reference types. The wrapper type `Void` is often used when a unit type parameter is needed.

```java
import java.util.concurrent.*;

ExecutorService executorService = Executors.newFixedThreadPool(2);

CompletableFuture<Void> future = CompletableFuture.runAsync(() -> {
    try {
        // Simulate some work
        System.out.println("Task started.");
        Thread.sleep(2000); // Simulate a 2-second task
        System.out.println("Task completed.");
    } catch (InterruptedException e) {
        System.err.println("Task was interrupted.");
    }
}, executorService);
```

Although the `Void` type can never have any instances, it does have one value, `null` (like all other reference types), so it acts as a unit type. In practice, any other non-instantiable type, e.g. `Math`, can also be used for this purpose, since they also have exactly one value, `null`.

```java
public static Void f(Void x) { 
    return null; 
}

public static Void g(Void x) { 
    return null; 
}

public static void main(String[] args) {
    f(g(null));
}
```

### Null type {#Null_type}

Statically typed languages give a type to every possible expression. They need to associate a type to the `null` expression. A type will be defined for `null` and it will only have this value.

For example in D, it is possible to declare functions that may only return `null` (in fact, `typeof(null)` is `void`):

```d
typeof(null) returnThatSpecialThing() {
    return null;
}

void writeTypeOfNull() {
    writeln(typeof(null)); // prints: void
}
```

`null` is the only value that `typeof(null)`, a unit type, can have.
