# .onion

::: {#o2 .subject cue=lead name=".onion"}

**.onion** is a special-use [top-level domain](https://en.wikipedia.org/wiki/Top-level_domain) name designating an anonymous [onion service](wikipedia://en/20556944#Onion_services), which was formerly known as a "hidden service",[^o3] reachable via the [Tor](wikipedia://en/20556944) network. Such addresses are not actual [DNS names](https://en.wikipedia.org/wiki/Domain_Name_System), and the .onion TLD is not in the [Internet DNS root](https://en.wikipedia.org/wiki/DNS_root_zone), but with the appropriate proxy software installed, Internet programs such as [web browsers](https://en.wikipedia.org/wiki/Web_browser) can access sites with .onion [addresses](https://en.wikipedia.org/wiki/URL) by sending the request through the Tor network.

:::

The "onion" name refers to [onion routing](https://en.wikipedia.org/wiki/Onion_routing), the technique used by Tor to achieve a degree of [anonymity](https://en.wikipedia.org/wiki/Anonymity).

The purpose of using such a system is to make both the information provider and the person accessing the information more difficult to trace, whether by one another, by an intermediate network host, or by an outsider. Sites that offer dedicated .onion addresses may provide an additional layer of identity assurance via [EV HTTPS Certificates](https://en.wikipedia.org/wiki/Extended_Validation_Certificate) or [Domain-validated HTTPS certificates](https://en.wikipedia.org/wiki/Domain-validated_certificate).[^o4] Provision of an onion site also helps mitigate [SSL stripping](https://en.wikipedia.org/wiki/SSL_stripping) attacks by [malicious exit nodes](https://en.wikipedia.org/wiki/Tor_%28anonymity_network%29#Exit_node_eavesdropping) on the Tor network upon users who would otherwise access traditional HTTPS [clearnet](https://en.wikipedia.org/wiki/Clearnet_%28networking%29) sites over Tor.[^o5] Because connections to onion services do not use exit relays, they are not subject to exit node tampering.[^o6]

## Format {#Format}

Addresses in the onion TLD are generally opaque, non-[mnemonic](https://en.wikipedia.org/wiki/Mnemonic), alpha-numerical strings which are automatically generated based on a [public key](https://en.wikipedia.org/wiki/Public_key) when an [onion service](https://en.wikipedia.org/wiki/Tor_%28anonymity_network%29#Onion_services) is configured. These strings can be made up of any letter of the alphabet, and decimal digits from 2 to 7, representing in [base32](https://en.wikipedia.org/wiki/Base32) either an 80-bit [hash](wikipedia://en/439526) ("version 2", or 16-character) or a 256-bit [ed25519](wikipedia://en/40775836#Ed25519) public key along with a version number and a checksum of the key and version number ("version 3", "next gen", or 56-character). As a result, in the past all combinations of sixteen base32 characters could potentially be valid version 2 addresses (though as the output of a cryptographic hash, a randomly selected string of this form having a corresponding onion service should be [extremely unlikely](wikipedia://en/969477)), while in the current version 3 only combinations of 56 base32 characters that correctly encoded an ed25519 public key, a checksum, and a version number (i.e., 3) are valid addresses.[^o8] It is possible to set up a partially human-readable .onion URL (e.g. starting with an organization name) by generating massive numbers of [key pairs](wikipedia://en/24222) (a computational process that can be [parallelized](https://en.wikipedia.org/wiki/Parallel_computing)) until a sufficiently desirable URL is found.[^o9][^o10]

Beginning in October 2021, stable releases of Tor software no longer support V2 (16 character) addresses.[^o11]

## WWW to .onion gateways {#WWW_to_.onion_gateways}

Proxies into the Tor network like [Tor2web](wikipedia://en/41841421) allow access to onion services from non-Tor browsers and for search engines that are not Tor-aware. By using a gateway, users give up their own anonymity and trust the gateway to deliver the correct content. Both the gateway and the onion service can [fingerprint](https://en.wikipedia.org/wiki/Browser_fingerprint) the browser, and access user IP address data. Some proxies use caching techniques that claim to provide better page-loading[^o13] than the official [Tor Browser](https://en.wikipedia.org/wiki/Tor_%28anonymity_network%29#Tor_Browser).

## .exit (defunct pseudo-top-level domain) {#.exit_(defunct_pseudo-top-level_domain)}

**.exit** was a [pseudo-top-level domain](https://en.wikipedia.org/wiki/Pseudo-top-level_domain) used by [Tor](https://en.wikipedia.org/wiki/Tor_%28anonymity_network%29) users to indicate on the fly to the Tor software the preferred [exit node](https://en.wikipedia.org/wiki/Exit_node) that should be used while connecting to a service such as a [web server](https://en.wikipedia.org/wiki/World_Wide_Web), without having to edit the configuration file for Tor (*torrc*).

The syntax used with this domain was *hostname* + *.exitnode* + *.exit*, so that a user wanting to connect to http://www.torproject.org/ through node *tor26* would have to enter the URL *http://www.torproject.org.tor26.exit*.

Example uses for this would include accessing a site available only to addresses of a certain country or checking if a certain node is working.

Users could also type *exitnode.exit* alone to access the IP address of *exitnode*.

The .exit notation was deprecated as of version 0.2.9.8.[^o16] It is disabled by default as of version 0.2.2.1-alpha due to potential application-level attacks,[^o17] and with the release of 0.3-series Tor as "stable"[^o18] may now be considered defunct.

:::

## Official designation {#Official_designation}

The domain was formerly a [pseudo-top-level domain](https://en.wikipedia.org/wiki/Pseudo-top-level_domain) host suffix, similar in concept to such endings as [.bitnet](https://en.wikipedia.org/wiki/.bitnet) and [.uucp](https://en.wikipedia.org/wiki/.uucp) used in earlier times.

On 9 September 2015 [ICANN](https://en.wikipedia.org/wiki/ICANN), [IANA](https://en.wikipedia.org/wiki/Internet_Assigned_Numbers_Authority) and the [IETF](https://en.wikipedia.org/wiki/IETF) designated .onion as a 'special use domain', giving the domain an official status following a proposal from [Jacob Appelbaum](https://en.wikipedia.org/wiki/Jacob_Appelbaum) of the Tor Project and [Facebook](https://en.wikipedia.org/wiki/Facebook) security engineer [Alec Muffett](wikipedia://en/41277583).[^o20][^o21][^o22]

## HTTPS support {#HTTPS_support}

Prior to the adoption of [CA/Browser Forum](https://en.wikipedia.org/wiki/CA/Browser_Forum) Ballot 144, an [HTTPS](wikipedia://en/13586) certificate for a .onion name could only be acquired by treating .onion as an Internal Server Name.[^o24] Per the CA/Browser Forum's Baseline Requirements, these certificates could be issued, but were required to expire before 1 November 2015.[^o25]

Despite these restrictions, [DuckDuckGo](https://en.wikipedia.org/wiki/DuckDuckGo) launched an onion site with a self-signed certificate in July 2013;[^o26] [Facebook](https://en.wikipedia.org/wiki/Facebook) obtained the first SSL Onion certificate to be issued by a Certificate authority in October 2014,[^o27] [Blockchain.info](https://en.wikipedia.org/wiki/Blockchain.info) in December 2014,[^o28] and [The Intercept](https://en.wikipedia.org/wiki/The_Intercept) in April 2015.[^o29] *[The New York Times](https://en.wikipedia.org/wiki/The_New_York_Times)* later joined in October 2017, but discontinued the site in April 2025.[^o30]

Following the adoption of CA/Browser Forum Ballot 144 and the designation of the domain as 'special use' in September 2015, .onion meets the criteria for RFC 6761.[^o31] Certificate authorities may issue SSL certificates for HTTPS .onion sites per the process documented in the [CA/Browser Forum](https://en.wikipedia.org/wiki/CA/Browser_Forum)'s Baseline Requirements,[^o32] introduced in Ballot 144.[^o24]

As of August 2016, 13 onion domains are https signed across 7 different organisations via [DigiCert](https://en.wikipedia.org/wiki/DigiCert).[^o33]
