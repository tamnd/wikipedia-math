# Pass (software)

::: {#o1 .subject cue=lead name="Pass"}

**pass** is a [password manager](wikipedia://en/4696394) inspired by the [Unix philosophy](https://en.wikipedia.org/wiki/Unix_philosophy). It has a [command-line interface](https://en.wikipedia.org/wiki/Command-line_interface), and uses [GnuPG](https://en.wikipedia.org/wiki/GnuPG) for encryption and decryption of stored passwords.[^o3][^o4]

:::

The passwords are encrypted and stored in separate files, and can be organized via the operating system's [filesystem](https://en.wikipedia.org/wiki/File_system). A password file can contain additional text, such as the username, the email address, comments, or anything the user would like, since the password files are nothing more than encrypted text files.

There are several [graphical user interfaces](https://en.wikipedia.org/wiki/Graphical_user_interface) (GUIs) available, such as [QtPass](https://en.wikipedia.org/wiki/QtPass) for [Linux](https://en.wikipedia.org/wiki/Linux)/[Windows](https://en.wikipedia.org/wiki/Windows)/[MacOS](https://en.wikipedia.org/wiki/MacOS) or Password Store for [Android operating systems](https://en.wikipedia.org/wiki/Android_%28operating_system%29). A [syncing](https://en.wikipedia.org/wiki/Synchronization_%28computer_science%29) system is not implemented, but syncing can be achieved by using the [Git](https://en.wikipedia.org/wiki/Git) [version control](https://en.wikipedia.org/wiki/Version_control) system. The built in Git functionality also allows for automated version history tracking of the password store.

## Vulnerabilities {#Vulnerabilities}

In June 2018, pass was found to be vulnerable to a variant of the [SigSpoof](https://en.wikipedia.org/wiki/SigSpoof) attack.[^o6][^o7] The issue was [patched](https://en.wikipedia.org/wiki/Patch_%28computing%29) the same day that the [vulnerability](https://en.wikipedia.org/wiki/Vulnerability_%28computing%29) was disclosed.[^o6]
