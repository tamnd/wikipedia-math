# Cryptographic nonce

*Image: Nonce-cnonce-uml.svg.* Typical client–server communication during a nonce-based [authentication](wikipedia://en/47967) process including both a server nonce and a client nonce

::: {#o1 .subject cue=lead name="Cryptographic nonce"}

In [cryptography](wikipedia://en/18934432), a **nonce** is an arbitrary number that can be used just once in a cryptographic communication.[^o2] It is often a [random](wikipedia://en/19196523) or [pseudo-random](wikipedia://en/23210) number issued in an [authentication protocol](https://en.wikipedia.org/wiki/Authentication_protocol) to ensure that each communication session is unique, and therefore that old communications cannot be reused in [replay attacks](wikipedia://en/614094). Nonces can also be useful as [initialization vectors](wikipedia://en/105971) and in [cryptographic hash functions](https://en.wikipedia.org/wiki/Cryptographic_hash_functions).

:::

::: {#o4 .definition cue=heading name="Definition"}

## Definition {#Definition}

A nonce is an arbitrary number used only once in a cryptographic communication, in the spirit of a [nonce word](https://en.wikipedia.org/wiki/Nonce_word). They are often [random](wikipedia://en/19196523) or [pseudo-random](https://en.wikipedia.org/wiki/Pseudo-random) numbers.[^o5] Many nonces also include a [timestamp](https://en.wikipedia.org/wiki/Timestamp) to ensure exact timeliness, though this requires [clock synchronisation](https://en.wikipedia.org/wiki/Clock_synchronisation) between organisations. The addition of a client nonce ("**cnonce**") helps to improve the security in some ways as implemented in [digest access authentication](wikipedia://en/1381205). To ensure that a nonce is used only once, it should be time-variant (including a suitably fine-grained timestamp in its value), or generated with enough random bits to ensure an insignificantly low chance of repeating a previously generated value. Some authors define pseudo-randomness (or unpredictability) as a requirement for a nonce.[^o6]

Nonce is a word dating back to [Middle English](https://en.wikipedia.org/wiki/Middle_English) for something only used once or temporarily (often with the construction "for the nonce"). It descends from the construction "then anes" ("the one \[purpose\]").[^o7] A [false etymology](https://en.wikipedia.org/wiki/False_etymology) claiming it to stand for "number used once"[^o8] or similar is incorrect.

## Usage {#Usage}

section

### Authentication {#Authentication}

[Authentication protocols](https://en.wikipedia.org/wiki/Authentication_protocol) may use nonces to ensure that old communications cannot be reused in [replay attacks](wikipedia://en/614094). For instance, nonces are used in [HTTP](https://en.wikipedia.org/wiki/HTTP) [digest access authentication](wikipedia://en/1381205) to calculate an [MD5](wikipedia://en/18826) digest of the [password](wikipedia://en/24304).[^o11] The nonces are different each time the 401 authentication challenge [response code](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes) is presented, thus making [replay attacks](wikipedia://en/614094) virtually impossible. The scenario of ordering products over the Internet can provide an example of the usefulness of nonces in replay attacks. An attacker could take the encrypted information and—without needing to decrypt—could continue to send a particular order to the supplier, thereby ordering products over and over again under the same name and purchase information. The nonce is used to give 'originality' to a given message so that if the company receives any other orders from the same person with the same nonce, it will discard those as invalid orders.

A nonce may be used to ensure security for a [stream cipher](wikipedia://en/49007). Where the same key is used for more than one message and then a different nonce is used to ensure that the [keystream](wikipedia://en/10441065) is different for different messages encrypted with that key; often the message number is used.

Secret nonce values are used by the [Lamport signature](wikipedia://en/3200486) scheme as a signer-side secret which can be selectively revealed for comparison to public hashes for signature creation and verification.

### Hashing {#Hashing}

Nonces are used in [proof-of-work systems](https://en.wikipedia.org/wiki/Proof-of-work_system) to vary the input to a [cryptographic hash function](wikipedia://en/439526) so as to obtain a hash for a certain input that fulfils certain arbitrary conditions. In doing so, it becomes far more difficult to create a "desirable" hash than to verify it, shifting the burden of work onto one side of a transaction or system. For example, proof of work, using hash functions, was considered as a means to combat [email spam](https://en.wikipedia.org/wiki/Email_spam) by forcing email senders to find a hash value for the email (which included a timestamp to prevent pre-computation of useful hashes for later use) that had an arbitrary number of leading zeroes, by hashing the same input with a large number of values until a "desirable" hash was obtained.

Similarly, the [Bitcoin](wikipedia://en/28249265) [blockchain](wikipedia://en/44065971) hashing algorithm can be tuned to an arbitrary difficulty by changing the required minimum/maximum value of the hash so that the number of bitcoins awarded for new blocks does not increase linearly with increased network computation power as new users join. This is likewise achieved by forcing Bitcoin miners to add nonce values to the value being hashed to change the hash algorithm output. As cryptographic hash algorithms cannot easily be predicted based on their inputs, this makes the act of blockchain hashing and the possibility of being awarded bitcoins something of a lottery, where the first "miner" to find a nonce that delivers a desirable hash is awarded bitcoins.
