# WebTorrent

::: {#o1 .subject cue=lead name="WebTorrent"}

**WebTorrent** is a [peer-to-peer](https://en.wikipedia.org/wiki/Peer-to-peer_%28computing%29) (P2P) [streaming](https://en.wikipedia.org/wiki/Stream_%28computing%29) [torrent client](https://en.wikipedia.org/wiki/Torrent_client) written in [JavaScript](https://en.wikipedia.org/wiki/JavaScript) that enables [BitTorrent](https://en.wikipedia.org/wiki/BitTorrent) functionality directly within [web browsers](https://en.wikipedia.org/wiki/Web_browser). Created by [Feross Aboukhadijeh](https://en.wikipedia.org/wiki/Feross_Aboukhadijeh), the developer behind [YouTube Instant](https://en.wikipedia.org/wiki/YouTube_Instant), WebTorrent implements the [BitTorrent protocol](https://en.wikipedia.org/wiki/BitTorrent_protocol) using [WebRTC](https://en.wikipedia.org/wiki/WebRTC) for peer-to-peer data transfer, allowing users to download and stream torrents without requiring traditional torrent client software.

:::

The project consists of both a browser-based [JavaScript library](https://en.wikipedia.org/wiki/JavaScript_library) and **WebTorrent Desktop**, a standalone [desktop application](https://en.wikipedia.org/wiki/Desktop_application) built with [Electron](https://en.wikipedia.org/wiki/Electron_%28software_framework%29). WebTorrent Desktop serves as a bridge between the WebTorrent network and traditional BitTorrent networks, enabling interoperability between web-based and conventional torrent clients. The software supports common [video file formats](https://en.wikipedia.org/wiki/Video_file_format) and [audio file formats](https://en.wikipedia.org/wiki/Audio_file_format) for in-browser streaming, making it particularly suitable for [media streaming](https://en.wikipedia.org/wiki/Media_streaming) applications.

WebTorrent is [open-source software](https://en.wikipedia.org/wiki/Open-source_software) distributed under the [MIT License](https://en.wikipedia.org/wiki/MIT_License) and is actively developed on [GitHub](https://en.wikipedia.org/wiki/GitHub). The project has gained significant adoption in the [web development](https://en.wikipedia.org/wiki/Web_development) community for its ability to bring decentralized file sharing capabilities to web applications without requiring users to install additional software or browser plugins.

## History {#History}

Before creating WebTorrent, the developers first created PeerCDN, a peer-to-peer [content delivery network](https://en.wikipedia.org/wiki/Content_delivery_network) which was bought by [Yahoo!](https://en.wikipedia.org/wiki/Yahoo!) in 2013.

The idea behind WebTorrent is to make a BitTorrent-like protocol that works on the web browser, maintaining as much compatibility with BitTorrent as possible.[^o5] Any [web browser](https://en.wikipedia.org/wiki/Web_browser) should be able to connect to a [peer-to-peer swarm](https://en.wikipedia.org/wiki/Glossary_of_BitTorrent_terms#Swarm), fetch content, verify that it is correct, and display it to the user – all as much as possible without centralized servers relying on a network entirely of people's browsers.[^o6] WebTorrent uses the same [protocol](https://en.wikipedia.org/wiki/Communication_protocol) as BitTorrent but uses a different [transport layer](https://en.wikipedia.org/wiki/Transport_layer). WebTorrent primarily relies on [WebRTC](https://en.wikipedia.org/wiki/WebRTC) connections, while BitTorrent uses [TCP](https://en.wikipedia.org/wiki/Transmission_Control_Protocol) connections and [UDP](https://en.wikipedia.org/wiki/User_Datagram_Protocol) datagrams directly.[^o6]

## WebTorrent Desktop {#WebTorrent_Desktop}

The WebTorrent Desktop bridges the two networks of WebRTC-based WebTorrent and TCP/UDP-based BitTorrent simultaneously. The BitTorrent client [Vuze](https://en.wikipedia.org/wiki/Vuze) (formerly [Azureus](https://en.wikipedia.org/wiki/Azureus_%28software%29)) less gracefully but adequately functionally incorporated WebTorrent adding simultaneous network bridging to their software. The developers used [Electron](https://en.wikipedia.org/wiki/Electron_%28software_framework%29) that makes desktop apps using JavaScript with access to all the [APIs](https://en.wikipedia.org/wiki/API) from [Chrome](https://en.wikipedia.org/wiki/Chrome_%28programming_language%29) and [Node](https://en.wikipedia.org/wiki/Node.js).[^o6]

:::

## Functionality {#Functionality}

Online video is the core focus as that is where WebTorrent is most useful. It is less suited for smaller files or data sets but is ideal for larger files.[^o6]

File availability, as with BitTorrents, is dependent on torrent [seeding](https://en.wikipedia.org/wiki/Seeding_%28computing%29). If only a few users are sharing a file, then an HTTP server that provides [webseeding](https://en.wikipedia.org/wiki/Webseeding) would be the fallback. There is no sharing without webseeding. However, this could have some positive implications. Rather than using a middleman upload site to share a large private file with another person, with WebTorrent you may directly connect without leaving traces somewhere or potentially being archived on some upload site. You simply drag and drop your file to create a magnet link that you can share with your friend. Connections are already encrypted, but you may add extra layers of encryption with keys to send another way. RAM limits may be managed with [IndexedDB](https://en.wikipedia.org/wiki/Indexed_Database_API).[^o6]

The client prioritizes downloading pieces chronologically, so that the file is able to be streamed uninterrupted even before the download is complete.[^o15]

## Adoption {#Adoption}

WebTorrent uses widely supported open web standards like WebRTC and therefore works in any modern browser, including [Google Chrome](https://en.wikipedia.org/wiki/Google_Chrome), [Firefox](https://en.wikipedia.org/wiki/Firefox), and [Opera](https://en.wikipedia.org/wiki/Opera_%28web_browser%29) for Desktop and Android, [Microsoft Edge](https://en.wikipedia.org/wiki/Microsoft_Edge) and [Safari](https://en.wikipedia.org/wiki/Safari_%28web_browser%29).[^o11]

### Brave {#Brave}

[Brave](https://en.wikipedia.org/wiki/Brave_%28web_browser%29) web browser bundles WebTorrent into the native executables and integrates WebTorrent into its UI.[^o13]

### Torrent Clients {#Torrent_Clients}

Some torrent clients supports seeding to WebTorrent peers, for example [BiglyBT](https://en.wikipedia.org/wiki/BiglyBT) (has Android version) and clients based on the [libtorrent](https://en.wikipedia.org/wiki/Libtorrent)[^o15] like [QBittorrent](https://en.wikipedia.org/wiki/QBittorrent), [Deluge](https://en.wikipedia.org/wiki/Deluge_%28software%29) and [LibreTorrent](https://f-droid.org/packages/org.proninyaroslav.libretorrent/) (Android).

### Websites {#Websites}

#### BitChute {#BitChute}

Launched in 2017,[^o18] [BitChute](https://en.wikipedia.org/wiki/BitChute) is a [video hosting service](https://en.wikipedia.org/wiki/Video_hosting_service) that used WebTorrent P2P technology.[^o19][^o20] It claimed in order to ease bandwidth issues of centralized streaming.[^o18] According to [Fredrick Brennan](https://en.wikipedia.org/wiki/Fredrick_Brennan), there is little evidence BitChute actually uses peer-to-peer technology.[^o21] By April 2021, the option to host videos using WebTorrent on BitChute "appears to have been deprecated", according to *[Ars Technica](https://en.wikipedia.org/wiki/Ars_Technica)*.[^o22]

#### PeerTube {#PeerTube}

[PeerTube](https://en.wikipedia.org/wiki/PeerTube) formerly used WebTorrent but stopped because of maintaining complexity.[^o24]
