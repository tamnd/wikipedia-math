# Goertzel algorithm

::: {#o1 .subject cue=lead name="Goertzel algorithm"}

The **Goertzel algorithm** is a technique in [digital signal processing](https://en.wikipedia.org/wiki/Digital_signal_processing) (DSP) for efficient evaluation of the individual terms of the [discrete Fourier transform](wikipedia://en/8811) (DFT). It is useful in certain practical applications, such as recognition of [dual-tone multi-frequency signaling](https://en.wikipedia.org/wiki/Dual-tone_multi-frequency_signaling) (DTMF) tones produced by the push buttons of the keypad of a traditional analog [telephone](https://en.wikipedia.org/wiki/Telephone). The algorithm was [first described](https://en.wikipedia.org/wiki/Species_description) by [Gerald Goertzel](https://en.wikipedia.org/wiki/Gerald_Goertzel) in 1958.[^o2]

:::

Like the DFT, the Goertzel algorithm analyses one selectable frequency component from a [discrete signal](https://en.wikipedia.org/wiki/Discrete_signal).[^o3][^o4][^o5] Unlike direct DFT calculations, the Goertzel algorithm applies a single [real-valued](wikipedia://en/20646438) coefficient at each iteration, using real-valued arithmetic for real-valued input sequences. For covering a full spectrum (except when using for continuous stream of data where coefficients are reused for subsequent calculations, which has computational complexity equivalent of [sliding DFT](wikipedia://en/63148459)), the Goertzel algorithm has a [higher order of complexity](wikipedia://en/7543) than [fast Fourier transform](wikipedia://en/11512) (FFT) algorithms, but for computing a small number of selected frequency components, it is more numerically efficient. The simple structure of the Goertzel algorithm makes it well suited to small processors and embedded applications.

The Goertzel algorithm can also be used "in reverse" as a sinusoid synthesis function, which requires only 1 multiplication and 1 [subtraction](wikipedia://en/74141) per generated sample.[^o6]

::: {#o8 .definition kind=definition/construction cue=heading name="The algorithm"}

## The algorithm {#The_algorithm}

The main calculation in the Goertzel algorithm has the form of a [digital filter](https://en.wikipedia.org/wiki/Digital_filter), and for this reason the algorithm is often called a *Goertzel filter*. The filter operates on an input sequence $x[n]$ in a cascade of two stages with a parameter $\omega_0$, giving the frequency to be analysed, normalised to [radians](wikipedia://en/26003) per sample.

The first stage calculates an intermediate sequence, $s[n]$:

::: {#o9 .equation cue=numblk name="1"}

$$s[n] = x[n] + 2 \cos(\omega_0) s[n-1] - s[n-2]. \tag{1}$$

:::

The second stage applies the following filter to $s[n]$, producing output sequence $y[n]$:

::: {#o10 .equation cue=numblk name="2"}

$$y[n] = s[n] - e^{-j \omega_0} s[n-1]. \tag{2}$$

:::

The first filter stage can be observed to be a second-order [IIR filter](https://en.wikipedia.org/wiki/Infinite_impulse_response) with a [direct-form](https://en.wikipedia.org/wiki/Digital_filter#Direct_form_I) structure. This particular structure has the property that its internal state variables equal the past output values from that stage. Input values $x[n]$ for $n < 0$ are presumed all equal to 0. To establish the initial filter state so that evaluation can begin at sample $x[0]$, the filter states are assigned initial values $s[-2] = s[-1] = 0$. To avoid [aliasing](wikipedia://en/151474) hazards, frequency $\omega_0$ is often restricted to the range 0 to π (see [Nyquist–Shannon sampling theorem](wikipedia://en/37864)); using a value outside this range is not meaningless, but is equivalent to using an aliased frequency inside this range, since the [exponential function](wikipedia://en/9678) is periodic with a period of 2π in $\omega_0$.

The second-stage filter can be observed to be a [FIR filter](https://en.wikipedia.org/wiki/Finite_impulse_response), since its calculations do not use any of its past outputs.

[Z-transform](wikipedia://en/171589) methods can be applied to study the properties of the filter cascade. The Z transform of the first filter stage given in equation (1) is

::: {#o11 .equation cue=numblk name="3"}

$$\begin{aligned} \frac{S(z)}{X(z)} &= \frac{1}{1 - 2 \cos(\omega_0) z^{-1} + z^{-2}} \\ & = \frac{1}{(1 - e^{+j \omega_0} z^{-1})(1 - e^{-j \omega_0} z^{-1})}. \end{aligned} \tag{3}$$

:::

The Z transform of the second filter stage given in equation (2) is

::: {#o12 .equation cue=numblk name="4"}

$$\frac{Y(z)}{S(z)} = 1 - e^{-j \omega_0}z^{-1}. \tag{4}$$

:::

The combined transfer function of the cascade of the two filter stages is then

::: {#o13 .equation cue=numblk name="5"}

$$\begin{aligned} \frac{S(z)}{X(z)} \frac{Y(z)}{S(z)} = \frac{Y(z)}{X(z)} &= \frac{(1 - e^{-j \omega_0}z^{-1})}{(1 - e^{+j \omega_0} z^{-1})(1 - e^{-j \omega_0} z^{-1})} \\ &= \frac{1}{1 - e^{+j \omega_0} z^{-1}}. \end{aligned} \tag{5}$$

:::

This can be transformed back to an equivalent time-domain sequence, and the terms unrolled back to the first input term at index $n = 0$:

::: {#o14 .equation cue=numblk name="6"}

$$\begin{aligned} y[n] &= x[n] + e^{+j \omega_0} y[n-1] \\ &= \sum_{k=-\infty}^{n}x[k] e^{+j \omega_0 (n-k)} \\ &= e^{j \omega_0 n} \sum_{k=0}^{n} x[k] e^{-j \omega_0 k} \qquad \text{since }\forall k < 0, x[k] = 0. \end{aligned} \tag{6}$$

:::

:::

## Numerical stability {#Numerical_stability}

It can be observed that the [poles](https://en.wikipedia.org/wiki/Pole_%28complex_analysis%29) of the filter's [Z transform](https://en.wikipedia.org/wiki/Z_transform) are located at $e^{+j \omega_0}$ and $e^{-j \omega_0}$, on a circle of unit radius centered on the origin of the complex Z-transform plane. This property indicates that the filter process is [marginally stable](wikipedia://en/1273629) and vulnerable to [numerical-error accumulation](wikipedia://en/233807) when computed using low-precision arithmetic and long input sequences.[^o16] A numerically stable version was proposed by [Christian Reinsch](wikipedia://en/64413735).[^o17]

## DFT computations {#DFT_computations}

For the important case of computing a DFT term, the following special restrictions are applied.

- The filtering terminates at index $n = N$, where $N$ is the number of terms in the input sequence of the DFT.
- The frequencies chosen for the Goertzel analysis are restricted to the special form

::: {#o19 .equation cue=numblk name="7"}

$$\omega_0 = 2 \pi \frac{k}{N}. \tag{7}$$

:::

- The index number $k$ indicating the "frequency bin" of the DFT is selected from the set of index numbers

::: {#o20 .equation cue=numblk name="8"}

$$k \in \{ 0, 1, 2, ..., N-1 \}. \tag{8}$$

:::

Making these substitutions into equation (6) and observing that the term $e^{+j 2 \pi k} = 1$, equation (6) then takes the following form:

::: {#o21 .equation cue=numblk name="9"}

$$y[N] = \sum_{n=0}^{N} x[n]e^{-j 2 \pi \frac{n k}{N}}. \tag{9}$$

:::

We can observe that the right side of equation (9) is extremely similar to the defining formula for DFT term $X[k]$, the DFT term for index number $k$, but not exactly the same. The summation shown in equation (9) requires $N+1$ input terms, but only $N$ input terms are available when evaluating a DFT. A simple but inelegant expedient is to extend the input sequence $x[n]$ with one more artificial value $x[N] = 0$.[^o22] We can see from equation (9) that the mathematical effect on the final result is the same as removing term $x[N]$ from the summation, thus delivering the intended DFT value.

However, there is a more elegant approach that avoids the extra filter pass. From equation (1), we can note that when the extended input term $x[N] = 0$ is used in the final step,

::: {#o23 .equation cue=numblk name="10"}

$$s[N] = 2 \cos(\omega_0) s[N-1] - s[N-2]. \tag{10}$$

:::

Thus, the algorithm can be completed as follows:

- terminate the IIR filter after processing input term $x[N-1]$,
- apply equation (10) to construct $s[N]$ from the prior outputs $s[N-1]$ and $s[N-2]$,
- apply equation (2) with the calculated $s[N]$ value and with $s[N-1]$ produced by the final direct calculation of the filter.

The last two mathematical operations are simplified by combining them algebraically:

::: {#o24 .equation cue=numblk name="11"}

$$\begin{aligned} y[N] & = s[N] - e^{-j 2 \pi \frac{k}{N}} s[N-1] \\ & = (2 \cos(\omega_0) s[N-1] - s[N-2]) - e^{-j 2 \pi \frac{k}{N}} s[N-1] \\ & = e^{j 2 \pi \frac{k}{N}} s[N-1] - s[N-2]. \end{aligned} \tag{11}$$

:::

Note that stopping the filter updates at term $N-1$ and immediately applying equation (2) rather than equation (11) misses the final filter state updates, yielding a result with incorrect phase.[^o25]

The particular filtering structure chosen for the Goertzel algorithm is the key to its efficient DFT calculations. We can observe that only one output value $y[N]$ is used for calculating the DFT, so calculations for all the other output terms are omitted. Since the FIR filter is not calculated, the IIR stage calculations $s[0], s[1]$, etc. can be discarded immediately after updating the first stage's internal state.

This seems to leave a paradox: to complete the algorithm, the FIR filter stage must be evaluated once using the final two outputs from the IIR filter stage, while for computational efficiency the IIR filter iteration discards its output values. This is where the properties of the direct-form filter structure are applied. The two internal state variables of the IIR filter provide the last two values of the IIR filter output, which are the terms required to evaluate the FIR filter stage.

## Applications {#Applications}

### Power-spectrum terms {#Power-spectrum_terms}

Examining equation (6), a final IIR filter pass to calculate term $y[N]$ using a supplemental input value $x[N]=0$ applies a complex multiplier of magnitude 1 to the previous term $y[N-1]$. Consequently, $y[N]$ and $y[N-1]$ represent equivalent signal power. It is equally valid to apply equation (11) and calculate the signal power from term $y[N]$ or to apply equation (2) and calculate the signal power from term $y[N-1]$. Both cases lead to the following expression for the signal power represented by DFT term $X[k]$:

::: {#o29 .equation cue=numblk name="12"}

$$\begin{aligned} X[k] \, X'[k] & = y[N] \, y'[N] = y[N-1] \, y'[N-1] \\ & = s^2[N-1] + s^2[N-2] - 2 \cos \left(2 \pi \frac{k}{N} \right) \, s[N-1] \, s[N-2]. \end{aligned} \tag{12}$$

:::

In the [pseudocode](https://en.wikipedia.org/wiki/Pseudocode) below, the complex-valued input data is stored in the [array](https://en.wikipedia.org/wiki/Array_data_type) `x` and the variables `sprev` and `sprev2` temporarily store output history from the IIR filter. `Nterms` is the number of samples in the array, and `Kterm` corresponds to the frequency of interest, multiplied by the sampling period.

Nterms defined here Kterm selected here ω = 2 × π × Kterm / Nterms; coeff := 2 × cos(ω)

sprev := 0 sprev2 := 0 **for each** index *n* in range 0 to Nterms-1 **do** s := x\[n\] + coeff × sprev - sprev2 sprev2 := sprev sprev := s **end**

power := sprev<sup>*2*</sup> + sprev2<sup>*2*</sup> - (coeff × sprev × sprev2)

It is possible[^o30] to organise the computations so that incoming samples are delivered singly to a [software object](https://en.wikipedia.org/wiki/Object-oriented_programming) that maintains the filter state between updates, with the final power result accessed after the other processing is done.

### Single DFT term with real-valued arithmetic {#Single_DFT_term_with_real-valued_arithmetic}

The case of real-valued input data arises frequently, especially in embedded systems where the input streams result from direct measurements of physical processes. When the input data are real-valued, the filter internal state variables `sprev` and `sprev2` can be observed also to be real-valued, consequently, no complex arithmetic is required in the first IIR stage. Optimizing for real-valued arithmetic typically is as simple as applying appropriate real-valued data types for the variables.

After the calculations using input term $x[N-1]$, and filter iterations are terminated, equation (11) must be applied to evaluate the DFT term. The final calculation uses complex-valued arithmetic, but this can be converted into real-valued arithmetic by separating real and imaginary terms:

::: {#o32 .equation cue=numblk name="13"}

$$\begin{aligned} c_r &= \cos(2 \pi \tfrac{k}{N}), \\ c_i &= \sin(2 \pi \tfrac{k}{N}), \\ y[N] &= c_r s[N-1] - s[N-2] + j c_i s[N-1]. \end{aligned} \tag{13}$$

:::

Comparing to the power-spectrum application, the only difference are the calculation used to finish:

```
(Same IIR filter calculations as in the signal power implementation)
XKreal = sprev * cr - sprev2;
XKimag = sprev * ci;
```

### Phase detection {#Phase_detection}

This application requires the same evaluation of DFT term $X[k]$, as discussed in the previous section, using a real-valued or complex-valued input stream. Then the signal phase can be evaluated as

::: {#o34 .equation cue=numblk name="14"}

$$\phi = \tan^{-1}\frac{\Im(X[k])}{ \Re(X[k])}, \tag{14}$$

:::

taking appropriate precautions for singularities, quadrant, and so forth when computing the inverse tangent function.

### Complex signals in real arithmetic {#Complex_signals_in_real_arithmetic}

Since complex signals decompose linearly into real and imaginary parts, the Goertzel algorithm can be computed in real arithmetic separately over the sequence of real parts, yielding $y_\text{r}[n]$, and over the sequence of imaginary parts, yielding $y_\text{i}[n]$. After that, the two complex-valued partial results can be recombined:

::: {#o36 .equation cue=numblk name="15"}

$$y[n] = y_\text{r}[n] + j y_\text{i}[n]. \tag{15}$$

:::

:::

## Computational complexity {#Computational_complexity}

- According to [computational complexity theory](wikipedia://en/7543), computing a set of $M$ DFT terms using $M$ applications of the Goertzel algorithm on a [data set](wikipedia://en/8495) with $N$ values with a "cost per operation" of $K$ has [complexity](wikipedia://en/44578) $O(KNM)$.

To compute a single [DFT](wikipedia://en/8811) bin $X(f)$ for a complex input sequence of length $N$, the Goertzel algorithm requires $2 N$ multiplications and $4\ N$ additions/subtractions within the loop, as well as 4 multiplications and 4 final additions/subtractions, for a total of $2 N + 4$ multiplications and $4 N + 4$ additions/subtractions. This is repeated for each of the $M$ frequencies.

- In contrast, using an [FFT](wikipedia://en/11512) on a data set with $N$ values has complexity $O(KN\log_2(N))$.

This is harder to apply directly because it depends on the FFT algorithm used, but a typical example is a radix-2 FFT, which requires $2 \log_2(N)$ multiplications and $3 \log_2(N)$ additions/subtractions per [DFT](wikipedia://en/8811) bin, for each of the $N$ bins.

In the complexity order expressions, when the number of calculated terms $M$ is smaller than $\log N$, the advantage of the Goertzel algorithm is clear. But because FFT code is comparatively complex, the "cost per unit of work" factor $K$ is often larger for an FFT, and the practical advantage favours the Goertzel algorithm even for $M$ several times larger than $\log_2(N)$.

As a rule-of-thumb for determining whether a radix-2 FFT or a Goertzel algorithm is more efficient, adjust the number of terms $N$ in the data set upward to the nearest exact power of 2, calling this $N_2$, and the Goertzel algorithm is likely to be faster if

$$M \le \frac{5 N_2}{6 N} \log_2(N_2)$$

FFT implementations and processing platforms have a significant impact on the relative performance. Some FFT implementations[^o38] perform internal complex-number calculations to generate coefficients on-the-fly, significantly increasing their "cost K per unit of work." FFT and DFT algorithms can use tables of pre-computed coefficient values for better numerical efficiency, but this requires more accesses to coefficient values buffered in external memory, which can lead to increased cache contention that counters some of the numerical advantage.

Both algorithms gain approximately a factor of 2 efficiency when using real-valued rather than complex-valued input data. However, these gains are natural for the Goertzel algorithm but will not be achieved for the FFT without using certain algorithm variants specialised for [transforming real-valued data](wikipedia://en/11512).
