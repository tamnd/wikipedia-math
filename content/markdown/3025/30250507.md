# Discrete logarithm records

::: {#o1 .subject cue=lead name="Discrete logarithm records"}

**Discrete logarithm records** are the best results achieved to date in solving the [discrete logarithm problem](https://en.wikipedia.org/wiki/Discrete_logarithm_problem), which is the problem of finding solutions $x$ to the equation $g^x = h$ given elements $g$ and $h$ of a [finite](wikipedia://en/323707) [cyclic group](wikipedia://en/52327) $G$. The difficulty of this problem is the basis for the security of several [cryptographic](https://en.wikipedia.org/wiki/Cryptographic) systems, including [Diffie–Hellman](https://en.wikipedia.org/wiki/Diffie–Hellman) key agreement, [ElGamal encryption](wikipedia://en/59458), the [ElGamal signature scheme](wikipedia://en/2033473), the [Digital Signature Algorithm](wikipedia://en/59470), and the [elliptic curve cryptography](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography) analogues of these. Common choices for $G$ used in these [algorithms](wikipedia://en/775) include the multiplicative [group](wikipedia://en/19447) of [integers](wikipedia://en/14563) [modulo](wikipedia://en/20087) $p$, the multiplicative group of a [finite field](wikipedia://en/11615), and the group of points on an [elliptic curve](wikipedia://en/10225) over a finite field.

:::

## Integers modulo *p* {#Integers_modulo_p}

The current record for integers modulo [prime numbers](wikipedia://en/23666), set in December 2019, is a discrete logarithm computation modulo a prime with 240 digits. For [characteristic](wikipedia://en/1066621) 2, the current record for finite fields, set in July 2019, is a discrete logarithm over $\mathrm{GF}(2^{30750})$. When restricted to prime exponents, the current record, set in October 2014, is over $\mathrm{GF}(2^{1279})$. For characteristic 3, the current record, set in July 2016, is over $\mathrm{GF}(3^{6*509})$. For Kummer extension [fields](wikipedia://en/10603) of "moderate" characteristic, the current record, set in January 2013, is over $\mathrm{GF}(33341353^{57})$. For fields of "moderate" characteristic (which are not necessarily Kummer extensions), the current record, published in 2022, is over $\mathrm {GF} (2111023^{50})$.

Previous records for integers modulo *p* include:

- On 2 Dec 2019, Fabrice Boudot, Pierrick Gaudry, Aurore Guillevic, [Nadia Heninger](https://en.wikipedia.org/wiki/Nadia_Heninger), Emmanuel Thomé, and [Paul Zimmermann](https://en.wikipedia.org/wiki/Paul_Zimmermann_%28mathematician%29) announced the computation of a discrete logarithm modulo the 240-digit (795 bit) prime [RSA-240](https://en.wikipedia.org/wiki/RSA-240) + 49204 (the first [safe prime](https://en.wikipedia.org/wiki/Safe_prime) above RSA-240). This computation was performed simultaneously with the [factorization](wikipedia://en/15491) of RSA-240, using the Number Field Sieve algorithm and the open-source CADO-NFS software. The discrete logarithm part of the computation took approximately 3100 core-years, using Intel Xeon Gold 6130 CPUs as a reference (2.1 GHz). The researchers estimate that improvements in the algorithms and software made this computation three times faster than would be expected from previous records after accounting for improvements in hardware.[^o3][^o4]
- On 16 June 2016, Thorsten Kleinjung, Claus Diem, [Arjen K. Lenstra](https://en.wikipedia.org/wiki/Arjen_K._Lenstra), Christine Priplata, and Colin Stahlke announced the computation of a discrete logarithm modulo a 232-digit (768-bit) safe prime, using the number field sieve. The computation was started in February 2015 and took approximately 6600 core years scaled to an Intel Xeon E5-2660 at 2.2 GHz.[^o5]
- On 18 June 2005, [Antoine Joux](https://en.wikipedia.org/wiki/Antoine_Joux) and Reynald Lercier announced the computation of a discrete logarithm modulo a 130-digit (431-bit) [strong prime](wikipedia://en/3843453) in three weeks, using a 1.15 GHz 16-processor HP [AlphaServer GS1280](https://en.wikipedia.org/wiki/AlphaServer_GS1280) computer and a [number field sieve](wikipedia://en/152734) algorithm.[^o6]
- On 5 February 2007 this was superseded by the announcement by Thorsten Kleinjung of the computation of a discrete logarithm modulo a 160-digit (530-bit) safe prime, again using the number field sieve. Most of the computation was done using idle time on various PCs and on a [parallel computing](https://en.wikipedia.org/wiki/Parallel_computing) cluster.[^o7]
- On 11 June 2014, Cyril Bouvier, Pierrick Gaudry, Laurent Imbert, Hamza Jeljeli and Emmanuel Thomé announced the computation of a discrete logarithm modulo a 180 digit (596-bit) safe prime using the number field sieve algorithm.[^o8]

Also of note, in July 2016, Joshua Fried, Pierrick Gaudry, Nadia Heninger, Emmanuel Thome published their discrete logarithm computation on a 1024-bit prime.[^o9] They generated a prime susceptible to the [special number field sieve](wikipedia://en/589132), using the specialized algorithm on a comparatively small [subgroup](wikipedia://en/28011) (160-bits). While this is a small subgroup, it was the standardized subgroup size used with the 1024-bit digital signature algorithm (DSA).

## Finite fields {#Finite_fields}

The current record () in a finite field of characteristic 2 was announced by Robert Granger, Thorsten Kleinjung, Arjen Lenstra, Benjamin Wesolowski, and Jens Zumbrägel on 10 July 2019.[^o12] This team was able to compute discrete logarithms in GF(2<sup>30750</sup>) using 25,481,219 core hours on clusters based on the Intel Xeon architecture. This computation was the first large-scale example using the elimination step of the quasi-polynomial algorithm.[^o13]

Previous records in a finite field of characteristic 2 were announced by:

- Robert Granger, Thorsten Kleinjung, and Jens Zumbrägel on 31 January 2014. This team was able to compute discrete logarithms in GF(2<sup>9234</sup>) using about 400,000 core hours. New features of this computation include a modified method for obtaining the logarithms of degree two elements and a systematically optimized descent strategy.[^o14]
- Antoine Joux on 21 May 2013. His team was able to compute discrete logarithms in the field with 2<sup>6168</sup> = (2<sup>257</sup>)<sup>24</sup> elements using less than 550 CPU-hours. This computation was performed using the same [index calculus algorithm](wikipedia://en/1549595) as in the recent computation in the field with 2<sup>4080</sup> elements.[^o15]
- Robert Granger, Faruk Göloğlu, Gary McGuire, and Jens Zumbrägel on 11 Apr 2013. The new computation concerned the field with 2<sup>6120</sup> elements and took 749.5 core-hours.
- Antoine Joux on 22 March 2013. This used the same algorithm[^o16] for small characteristic fields as the previous computation in the field with 2<sup>1778</sup> elements. The new computation concerned the field with 2<sup>4080</sup> elements, represented as a degree 255 [extension](wikipedia://en/11634) of the field with 2<sup>16</sup> elements. The computation took less than 14100 core hours.[^o17]
- Robert Granger, Faruk Göloğlu, Gary McGuire, and Jens Zumbrägel on 19 Feb 2013. They used a new variant of the medium-sized base field [function field sieve](wikipedia://en/22407581), for binary fields, to compute a discrete logarithm in a field of 2<sup>1971</sup> elements. In order to use a medium-sized base field, they represented the field as a degree 73 extension of the field of 2<sup>27</sup> elements. The computation took 3132 core hours on an SGI Altix ICE 8200EX cluster using Intel (Westmere) Xeon E5650 hex-core processors.[^o18]
- Antoine Joux on 11 Feb 2013. This used a new algorithm for small characteristic fields. The computation concerned a field of 2<sup>1778</sup> elements, represented as a degree 127 extension of the field with 2<sup>14</sup> elements. The computation took less than 220 core hours.[^o19]

The current record () in a finite field of characteristic 2 of prime degree was announced by Thorsten Kleinjung on 17 October 2014. The calculation was done in a field of 2<sup>1279</sup> elements and followed essentially the path sketched for $\mathrm{GF}(2^{4 \cdot 1223})$ in [^o20] with two main exceptions in the [linear algebra](wikipedia://en/18422) computation and the descent phase. The total running time was less than four core years.[^o21] The previous record in a finite field of characteristic 2 of prime degree was announced by the CARAMEL group on 6 April 2013. They used the [function field sieve](wikipedia://en/22407581) to compute a discrete logarithm in a field of 2<sup>809</sup> elements.[^o22]

The current record () for a field of characteristic 3 was announced by Gora Adj, Isaac Canales-Martinez, Nareli Cruz-Cortés, Alfred Menezes, Thomaz Oliveira, Francisco Rodriguez-Henriquez, and Luis Rivera-Zamarripa on 18 July 2016. The calculation was done in the 4841-bit finite field with 3<sup>6 · 509</sup> elements and was performed on several computers at [CINVESTAV](https://en.wikipedia.org/wiki/CINVESTAV) and the [University of Waterloo](https://en.wikipedia.org/wiki/University_of_Waterloo). In total, about 200 core years of computing time was expended on the computation.[^o23]

Previous records in a finite field of characteristic 3 were announced:

- in the full version of the Asiacrypt 2014 paper of Joux and Pierrot (December 2014).[^o24] The DLP is solved in the field GF(3<sup>5 · 479</sup>), which is a 3796-bit field. This work did not exploit any "special" aspects of the field such as Kummer or twisted-Kummer properties. The total computation took less than 8600 CPU-hours.
- by Gora Adj, Alfred Menezes, Thomaz Oliveira, and Francisco Rodríguez-Henríquez on 26 February 2014, updating a previous announcement on 27 January 2014. The computation solve DLP in the 1551-bit field GF(3<sup>6 · 163</sup>), taking 1201 CPU hours.[^o25][^o26]
- in 2012 by a joint Fujitsu, NICT, and Kyushu University team, that computed a discrete logarithm in the field of 3<sup>6 · 97</sup> elements and a size of 923 bits,[^o27] using a variation on the [function field sieve](wikipedia://en/22407581) and beating the previous record in a field of 3<sup>6 · 71</sup> elements and size of 676 bits by a wide margin.[^o28]

Over fields of "moderate"-sized characteristic, notable computations as of 2005 included those a field of 65537<sup>25</sup> elements (401 bits) announced on 24 Oct 2005, and in a field of 370801<sup>30</sup> elements (556 bits) announced on 9 Nov 2005.[^o29] The current record (as of 2013) for a Kummer extension finite field of "moderate" characteristic was announced on 6 January 2013. The team used a new variation of the [function field sieve](wikipedia://en/22407581) for the medium prime case to compute a discrete logarithm in a Kummer extension field of 33341353<sup>57</sup> elements (a 1425-bit finite field).[^o30][^o31] The same technique had been used a few weeks earlier to compute a discrete logarithm in a Kummer extension field of 33553771<sup>47</sup> elements (an 1175-bit finite field).[^o31][^o32] The current record (as of 2022) for a finite field of "moderate" characteristic (which is not necessarily a Kummer extension) is the computation of discrete logarithm in a field of 2111023<sup>50</sup> elements (a 1051-bit finite field);[^o33] previous record[^o34] of discrete logarithm computations over such fields was over fields having 297079<sup>40</sup> elements (a 728-bit finite field) and 64373<sup>37</sup> elements (a 592-bit finite field). These computations were done using new ideas to speed up the function field sieve.

On 25 June 2014, Razvan Barbulescu, Pierrick Gaudry, Aurore Guillevic, and François Morain announced a new computation of a discrete logarithm in a finite field whose order has 160 digits and is a degree 2 extension of a prime field.[^o35] The algorithm used was the number field sieve (NFS), with various modifications. The total computing time was equivalent to 68 days on one core of CPU (sieving) and 30 hours on a GPU (linear algebra).

## Elliptic curves {#Elliptic_curves}

[Certicom](https://en.wikipedia.org/wiki/Certicom) Corp. has issued a series of [Elliptic Curve Cryptography](wikipedia://en/9966) challenges. Level I involves fields of 109-bit and 131-bit sizes. Level II includes 163, 191, 239, 359-bit sizes. All Level II challenges are currently believed to be computationally infeasible.[^o38]

The Level I challenges which have been met are:[^o39]

- ECC2K-108, involving taking a discrete logarithm on a [Koblitz curve](https://en.wikipedia.org/wiki/Koblitz_curve) over a field of 2<sup>108</sup> elements. The prize was awarded on 4 April 2000 to a group of about 1300 people represented by Robert Harley. They used a parallelized [Pollard rho method](wikipedia://en/1630817) with speedup.
- ECC2-109, involving taking a discrete logarithm on a curve over a field of 2<sup>109</sup> elements. The prize was awarded on 8 April 2004 to a group of about 2600 people represented by Chris Monico. They also used a version of a parallelized Pollard rho method, taking 17 months of calendar time.
- ECCp-109, involving taking a discrete logarithm on a curve modulo a 109-bit prime. The prize was awarded on 15 Apr 2002 to a group of about 10308 people represented by Chris Monico. Once again, they used a version of a parallelized Pollard rho method, taking 549 days of calendar time.

None of the 131-bit (or larger) challenges have been met .

In July 2009, Joppe W. Bos, Marcelo E. Kaihara, Thorsten Kleinjung, Arjen K. Lenstra and [Peter L. Montgomery](wikipedia://en/14573146) announced that they had carried out a discrete logarithm computation on an elliptic curve (known as secp112r1[^o40]) modulo a 112-bit prime. The computation was done on a cluster of over 200 [PlayStation 3](https://en.wikipedia.org/wiki/PlayStation_3) game consoles over about 6 months. They used the common parallelized version of Pollard rho method.[^o41]

In April 2014, [Erich Wenger](https://en.wikipedia.org/wiki/Erich_Wenger) and [Paul Wolfger](https://en.wikipedia.org/wiki/Paul_Wolfger) from [Graz University of Technology](https://en.wikipedia.org/wiki/Graz_University_of_Technology) solved the discrete logarithm of a 113-bit Koblitz curve in extrapolated 24 days using an 18-core [Virtex-6](https://en.wikipedia.org/wiki/Virtex-6) [FPGA](https://en.wikipedia.org/wiki/Field-programmable_gate_array) cluster.[^o42] In January 2015, the same researchers solved the discrete logarithm of an elliptic curve defined over a 113-bit binary field. The average runtime is around 82 days using a 10-core [Kintex-7](https://en.wikipedia.org/wiki/Kintex-7) [FPGA](https://en.wikipedia.org/wiki/Field-programmable_gate_array) cluster.[^o43]

On 2 December 2016, [Daniel J. Bernstein](wikipedia://en/198983), [Susanne Engels](https://en.wikipedia.org/wiki/Susanne_Engels), [Tanja Lange](https://en.wikipedia.org/wiki/Tanja_Lange), [Ruben Niederhagen](https://en.wikipedia.org/wiki/Ruben_Niederhagen), [Christof Paar](wikipedia://en/74074951), [Peter Schwabe](https://en.wikipedia.org/wiki/Peter_Schwabe), and [Ralf Zimmermann](https://en.wikipedia.org/wiki/Ralf_Zimmermann) announced the solution of a generic 117.35-bit elliptic curve discrete logarithm problem on a binary curve, using an optimized FPGA implementation of a parallel version of Pollard's rho method. The attack ran for about six months on 64 to 576 FPGAs in parallel.[^o44]

On 23 August 2017, Takuya Kusaka, Sho Joichi, Ken Ikuta, Md. Al-Amin Khandaker, Yasuyuki Nogami, Satoshi Uehara, Nariyoshi Yamai, and Sylvain Duquesne announced that they had solved a discrete logarithm problem on a 114-bit "pairing-friendly" Barreto–Naehrig (BN) curve,[^o45] using the special sextic twist property of the BN curve to efficiently carry out the [random walk](wikipedia://en/235451) of Pollard's rho method. The implementation used 2000 CPU cores and took about 6 months to solve the problem.[^o46]

On 16 June 2020, Aleksander Zieniewicz (zielar) and Jean Luc Pons ([JeanLucPons](https://github.com/JeanLucPons)) announced the solution of a 114-bit interval elliptic curve discrete logarithm problem on the secp256k1 curve by solving a 114-bit private key in Bitcoin Puzzle Transactions Challenge. To set a new record, they used their own software[^o47] based on the [Pollard Kangaroo](wikipedia://en/12928899) on 256x [NVIDIA Tesla V100](https://www.nvidia.com/en-us/data-center/v100/) GPU processor and it took them 13 days. Two weeks earlier - They used the same number of graphics cards to solve a 109-bit interval ECDLP in just 3 days.
