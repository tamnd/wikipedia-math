# Noncommutative signal-flow graph

*Image: Matrix Signal-Flow Graph.png.* A multi-input, multi-output system represented as a noncommutative matrix signal-flow graph.

::: {#o1 .subject cue=lead name="Noncommutative signal-flow graph"}

In [automata theory](wikipedia://en/103356) and [control theory](wikipedia://en/7039), branches of [mathematics](wikipedia://en/18831), [theoretical computer science](wikipedia://en/323392) and [systems engineering](https://en.wikipedia.org/wiki/Systems_engineering), a **noncommutative signal-flow graph** is a tool for modeling[^n1] interconnected systems and state machines by mapping the edges of a [directed graph](wikipedia://en/19721986) to a [ring](wikipedia://en/48404) or [semiring](wikipedia://en/371468).

:::

A single edge **weight** might represent an array of [impulse responses](wikipedia://en/545825) of a complex system (see figure to the right),[^n2] or a character from an [alphabet](https://en.wikipedia.org/wiki/Alphabet_%28computer_science%29) picked off the [input tape](https://en.wikipedia.org/wiki/Finite_state_transducer) of a finite automaton,[^n3] while the graph might represent the flow of information or state transitions.

As diverse as these applications are, they share much of the same underlying theory.[^n4][^n5]

::: {#o8 .definition cue=heading name="Definition"}

## Definition {#Definition}

*Image: Signal-Flow Graph Fragment.png.* Signal-flow graph fragment.

Consider *n* equations involving *n*+1 variables {*x*<sub>0</sub>, *x*<sub>1</sub>,...,*x*<sub>n</sub>}.

$$x_i = \sum_{j=0}^n a_{ij}x_j, \;\;\; 1\leq i \leq n,$$

with *a*<sub>ij</sub> elements in a ring or semiring *R*. The free variable *x*<sub>0</sub> corresponds to a source vertex *v*<sub>0</sub>, thus having no defining equation. Each equation corresponds to a fragment of a [directed graph](wikipedia://en/19721986) *G*=(*V*,*E*) as show in the figure.

The edge weights define a function *f* from *E* to *R*. Finally fix an output vertex *v<sub>m</sub>*. A signal-flow graph is the collection of this data *S* = (*G*=(*V*,*E*), *v<sub>0</sub>*,*v<sub>m</sub>* $\in$ *V*, *f* : *E* → *R*). The equations may not have a solution, but when they do,

$$x_m = T x_0,$$

with *T* an element of *R* called the **gain**.

:::

## Return Loop Method {#Return_Loop_Method}

There exist several[^n2] noncommutative generalizations of [Mason's rule](https://en.wikipedia.org/wiki/Mason's_rule). The most common is the **return loop method** (sometimes called the **forward return loop method (FRL)**, having a dual **backward return loop method (BRL)**). The first rigorous proof is attributed to Riegle,[^n2] so it is sometimes called **Riegle's rule**.[^n6]

As with [Mason's rule](https://en.wikipedia.org/wiki/Mason's_rule), these gain expressions combine terms in a [graph-theoretic](https://en.wikipedia.org/wiki/Graph-theoretic) manner (loop-gains, path products, etc.). They are known to hold over an arbitrary [noncommutative ring](wikipedia://en/24062516) and over the [semiring](wikipedia://en/371468) of regular expressions.[^n5]

### Formal Description {#Formal_Description}

The method starts by enumerating all paths from input to output, indexed by *j* $\in$ *J*. We use the following definitions:

- The *j*-th **path product** is (by abuse of notation) a [tuple](wikipedia://en/132729) of *k<sub>j</sub>* edge weights along it:

$$p_j = (w^{(j)}_{k_j},\ldots, w^{(j)}_2, w^{(j)}_1).$$

- To **split** a vertex *v* is to replace it with a source and sink respecting the original incidence and weights (this is the inverse of the graph morphism taking source and sink to *v*).
- The **[loop gain](https://en.wikipedia.org/wiki/Loop_gain)** of a vertex *v* w.r.t. a subgraph *H* is the gain from source to sink of the signal-flow graph split at *v* after removing all vertices not in *H*.
- Each path defines an ordering of vertices along it. The along path *j*, the *i*-th **FRL (BRL) node factor** is (1-*S<sub>i</sub><sup>(j)</sup>*)<sup>−1</sup> where *S<sub>i</sub><sup>(j)</sup>* is the loop gain of the *i*-th vertex along the *j*-th w.r.t. the subgraph obtained by removing *v*<sub>0</sub> and all vertices ahead of (behind) it.

The contribution of the *j*-th path to the gain is the product along the path, alternating between the path product weights and the node factors:

$$T_j = \prod_{i=k_j}^1 (1-S^{(j)}_i)^{-1} w^{(j)}_i,$$

so the total gain is

$$T = \sum_{j\in J} T_j.$$

### An Example {#An_Example}

*Image: FRL BRL Example.png.* A noncommutative signal-flow graph from *x* to *z*

Consider the [signal-flow graph](wikipedia://en/15175696) shown. From *x* to *z*, there are two path products: (*d*) and (*e,a*). Along (*d*), the FRL and BRL contributions coincide as both share same loop gain (whose split reappears in the upper right of the table below):

$$f+e(1-b)^{-1}c,$$

Multiplying its node factor and path weight, its gain contribution is

$$T_d = \left[1 - f - e(1-b)^{-1}c \right]^{-1}d.$$

Along path (*e,a*), FRL and BRL differ slightly, each having distinct splits of vertices *y* and *z* as shown in the following table.

*Image: Return Loop Split Table.png.*

Adding to *T<sub>d</sub>*, the alternating product of node factors and path weights, we obtain two gain expressions:

$$T^{(FRL)} = \left[1 - f - e(1-b)^{-1}c \right]^{-1}d + \left[1 - f - e(1-b)^{-1}c \right]^{-1}e(1-b)^{-1}a,$$

and

$$T^{(BRL)} = \left[1 - f - e(1-b)^{-1}c \right]^{-1}d + (1-f)^{-1}e\left[1 - b - c(1-f)^e\right]^{-1}a,$$

These values are easily seen to be the same using identities (*ab*)<sup>−1</sup> = *b*<sup>−1</sup>*a*<sup>−1</sup> and *a*(1-*ba*)<sup>−1</sup>=(1-*ab*)<sup>−1</sup>*a*.

:::

## Applications {#Applications}

### Matrix Signal-Flow Graphs {#Matrix_Signal-Flow_Graphs}

Consider equations

$$y_i=\sum_{j=1}^2 a_{ij} x_j + \sum_{j=1}^2 b_{ij}y_j$$

and

$$z_i=\sum_{j=1}^2 c_{ij} y_j,$$

This system could be modeled as scalar signal-flow graph with multiple inputs and outputs. But, the variables naturally fall into layers, which can be collected into vectors *x*=(*x*<sub>1</sub>,*x*<sub>2</sub>)<sup>*t*</sup> *y*=(*y*<sub>1</sub>,*y*<sub>2</sub>)<sup>*t*</sup> and *z*=(*z*<sub>1</sub>,*z*<sub>2</sub>)<sup>*t*</sup>. This results in much simpler **matrix signal-flow graph** as shown in the figure at the top of the article.

Applying the forward return loop method is trivial as there's a single path product (*C*,*A*) with a single loop-gain *B* at *y*. Thus as a matrix, this system has a very compact representation of its input-output map:

$$T = C(1-B)^{-1}A.$$

### Finite Automata {#Finite_Automata}

*Image: Automaton as Signal-Flow Graph.png.* Representation of a finite automaton as a (noncommutative) signal flow graph over a semiring.

An important kind of noncommutative signal-flow graph is a [finite state](wikipedia://en/10931) [automaton](https://en.wikipedia.org/wiki/Automaton) over an alphabet $\Sigma$.[^n3][^n4]

Serial connections correspond to the concatenation of words, which can be extended to subsets of the [free monoid](wikipedia://en/523166) $\Sigma^*$. For *A*, *B* $\subseteq\Sigma^*$

$$A \cdot B = \{ab \mid a\in A, b\in B\}.$$

Parallel connections correspond to [set union](https://en.wikipedia.org/wiki/Set_union), which in this context is often written *A*+*B*.

Finally, self-loops naturally correspond to the [Kleene closure](https://en.wikipedia.org/wiki/Kleene_closure)

$$A^* = \{\lambda\} + A + AA + AAA + \cdots,$$

where $\lambda$ is the [empty word](https://en.wikipedia.org/wiki/Empty_word). The similarity to the infinite geometric series

$$(1-x)^{-1} = 1 + x + x^2 + x^3 \cdots,$$

is more than superficial, as expressions of this form serve as 'inversion' in this [semiring](wikipedia://en/371468).[^n7]

In this way, the subsets of $\Sigma^*$ built of from finitely many of these three operations can be identified with the [semiring](wikipedia://en/371468) of [regular expressions](https://en.wikipedia.org/wiki/Regular_expressions). Similarly, finite graphs whose edges are weighted by subsets of $\Sigma^*$ can be identified with finite automata, though generally that theory starts with [singleton](wikipedia://en/381798) sets as in the figure.

This automaton is deterministic so we can unambiguously enumerate paths via words. Using the return loop method, path contributions are:

- path *ab*, has node factors (*c*<sup>\*</sup>, $\lambda$), yielding gain contribution

$$ac^*b,$$

- path *ada*, has node factors (*c*<sup>\*</sup>, *c*<sup>\*</sup>, $\lambda$), yielding gain contribution

$$ac^*dc^*a,$$

- path *ba*, has node factors (*c*<sup>\*</sup>, $\lambda$), yielding gain contribution

$$bc^*a.$$

Thus the [language](wikipedia://en/10939) accepted by this automaton (the gain of its signal-flow graph) is the sum of these terms

$$L = ac^*b+ac^*dc^*a+bc^*a.$$
