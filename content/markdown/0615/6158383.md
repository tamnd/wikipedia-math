# Computational hardness assumption

::: {#o1 .subject cue=lead name="Computational hardness assumption"}

In [computational complexity theory](wikipedia://en/7543), a **computational hardness assumption** is the hypothesis that a particular problem cannot be solved efficiently (where *efficiently* typically means "in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time)"). It is not known how to [prove](wikipedia://en/82285) (unconditional) hardness for essentially any useful problem. Instead, [computer scientists](https://en.wikipedia.org/wiki/Computer_scientist) rely on [reductions](wikipedia://en/848067) to formally relate the hardness of a new or complicated problem to a computational hardness assumption about a problem that is better-understood.

:::

Computational hardness assumptions are of particular importance in [cryptography](wikipedia://en/18934432). A major goal in cryptography is to create [cryptographic primitives](wikipedia://en/4928985) with [provable security](wikipedia://en/1182348). In some cases, cryptographic protocols are found to have [information theoretic security](https://en.wikipedia.org/wiki/Information_theoretic_security); the [one-time pad](wikipedia://en/22210) is a common example. However, information theoretic security cannot always be achieved; in such cases, cryptographers fall back to computational security. Roughly speaking, this means that these systems are secure *assuming that any adversaries are computationally limited*, as all adversaries are in practice.

Computational hardness assumptions are also useful for guiding [algorithm](wikipedia://en/775) designers: a simple algorithm is unlikely to refute a well-studied computational hardness assumption such as [P ≠ NP](wikipedia://en/6115).

## Comparing hardness assumptions {#Comparing_hardness_assumptions}

Computer scientists have different ways of assessing which hardness assumptions are more reliable.

### Strength of hardness assumptions {#Strength_of_hardness_assumptions}

We say that assumption $A$ is *stronger* than assumption $B$ when $A$ implies $B$ (and the [converse](wikipedia://en/155941) is false or not known). In other words, even if assumption $A$ were false, assumption $B$ may still be true, and cryptographic protocols based on assumption $B$ may still be safe to use. Thus when devising cryptographic protocols, one hopes to be able to prove security using the *weakest* possible assumptions.

### Average-case vs. worst-case assumptions {#Average-case_vs._worst-case_assumptions}

An [average-case](https://en.wikipedia.org/wiki/Average-case_complexity) assumption says that a specific problem is hard on most instances from some explicit distribution, whereas a [worst-case](https://en.wikipedia.org/wiki/Worst-case_complexity) assumption only says that the problem is hard on *some* instances. For a given problem, average-case hardness implies worst-case hardness, so an average-case hardness assumption is stronger than a worst-case hardness assumption for the same problem. Furthermore, even for incomparable problems, an assumption like the exponential time hypothesis is often considered preferable to an average-case assumption like the [planted clique conjecture](wikipedia://en/48563244).[^o5] However, for cryptographic applications, knowing that a problem has some hard instance (the problem is hard in the worst-case) is useless because it does not provide us with a way of generating hard instances.[^o6] Fortunately, many average-case assumptions used in cryptography (including RSA, discrete log, and some lattice problems) can be based on worst-case assumptions via worst-case-to-average-case reductions.[^o7]

### Falsifiability {#Falsifiability}

A desired characteristic of a computational hardness assumption is [falsifiability](wikipedia://en/11283), i.e. that if the assumption were false, then it would be possible to prove it. In particular, (Naor 2003) introduced a formal notion of cryptographic falsifiability.[^o10] Roughly, a computational hardness assumption is said to be falsifiable if it can be formulated in terms of a challenge: an interactive protocol between an adversary and an efficient verifier, where an efficient adversary can convince the verifier to accept [if and only if](wikipedia://en/14922) the assumption is false.

## Common cryptographic hardness assumptions {#Common_cryptographic_hardness_assumptions}

There are many cryptographic hardness assumptions in use. This is a list of some of the most common ones, and some cryptographic protocols that use them.

### Integer factorization {#Integer_factorization}

Given a [composite](wikipedia://en/82289) [integer](wikipedia://en/14563) $n$, and in particular one which is the product of two large [primes](wikipedia://en/23666) $n = p\cdot q$, the integer factorization problem is to find $p$ and $q$ (more generally, find primes $p_1,\dots,p_k$ such that $n = \prod_i p_i$). It is a major [open problem](wikipedia://en/1333335) to find an algorithm for integer factorization that runs in time polynomial in the size of representation ($\log n$). The security of many cryptographic protocols rely on the assumption that integer factorization is hard (i.e. cannot be solved in polynomial time). Cryptosystems whose security is equivalent to this assumption include [Rabin signature](https://en.wikipedia.org/wiki/Rabin_signature) and the [Okamoto–Uchiyama cryptosystem](wikipedia://en/7503084). Many more cryptosystems rely on stronger assumptions such as RSA, residuosity problems, and phi-hiding.

#### RSA problem {#RSA_problem}

Given a composite number $n$, exponent $e$ and number $c := m^e (\mathrm{mod}\; n)$, the RSA problem is to find $m$. The problem is [conjectured](wikipedia://en/6138) to be hard, but becomes easy given the factorization of $n$. In the [RSA cryptosystem](wikipedia://en/25385), $(n,e)$ is the [public key](wikipedia://en/24222), $c$ is the encryption of message $m$, and the factorization of $n$ is the secret key used for decryption.

#### Residuosity problems {#Residuosity_problems}

Given a composite number $n$ and integers $y,d$, the residuosity problem is to determine whether there exists (alternatively, find an) $x$ such that

$$x^d \equiv y \pmod{n}.$$

Important special cases include the [quadratic residuosity problem](wikipedia://en/1183041) and the [decisional composite residuosity problem](wikipedia://en/23702343). As in the case of RSA, this problem (and its special cases) are conjectured to be hard, but become easy given the factorization of $n$. Some cryptosystems that rely on the hardness of residuousity problems include:

- [Goldwasser–Micali cryptosystem](wikipedia://en/2461162) (quadratic residuosity problem)
- [Blum Blum Shub generator](https://en.wikipedia.org/wiki/Blum_Blum_Shub_generator) (quadratic residuosity problem)
- [Paillier cryptosystem](wikipedia://en/480685) (decisional composite residuosity problem)
- [Benaloh cryptosystem](wikipedia://en/6144390) (higher residuosity problem)
- [Naccache–Stern cryptosystem](wikipedia://en/6149634) (higher residuosity problem)

#### Phi-hiding assumption {#Phi-hiding_assumption}

For a composite number $m$, it is not known how to efficiently compute its [Euler's totient function](wikipedia://en/53452) $\phi(m)$. The phi-hiding assumption postulates that it is hard to compute $\phi(m)$, and furthermore even computing any [prime factors](https://en.wikipedia.org/wiki/Prime_factor) of $\phi(m)$ is hard. This assumption is used in the Cachin–Micali–Stadler [PIR](https://en.wikipedia.org/wiki/Private_information_retrieval) protocol.[^o16]

### Discrete log problem (DLP) {#Discrete_log_problem_(DLP)}

Given elements $a$ and $b$ from a [group](wikipedia://en/19447) $G$, the discrete log problem asks for an integer $k$ such that $a = b^k$. The discrete log problem is not known to be comparable to integer factorization, but their computational complexities [are closely related](wikipedia://en/181334#Comparison_with_integer_factorization).

Most cryptographic protocols related to the discrete log problem actually rely on the stronger [Diffie–Hellman assumption](wikipedia://en/1937391): given group elements $g, g^a, g^b$, where $g$ is a [generator](wikipedia://en/99945) and $a,b$ are random integers, it is hard to find $g^{a\cdot b}$. Examples of protocols that use this assumption include the original [Diffie–Hellman key exchange](wikipedia://en/7903), as well as the [ElGamal encryption](wikipedia://en/59458) (which relies on the yet stronger [Decisional Diffie–Hellman (DDH)](wikipedia://en/1198015) variant).

#### Multilinear maps {#Multilinear_maps}

A [multilinear map](wikipedia://en/221525) is a function $e: G_1 ,\dots,G_n \rightarrow G_T$ (where $G_1 ,\dots,G_n,G_T$ are [groups](wikipedia://en/19447)) such that for any $g_1, \dots, g_n \in G_1, \dots G_n$ and $a_1, \dots, a_n$,

$$e(g_1^{a_1},\dots,g_n^{a_n}) = e(g_1,\dots,g_n)^{a_1\cdots a_n}.$$

For cryptographic applications, one would like to construct groups $G_1,\dots,G_n,G_T$ and a map $e$ such that the map and the group operations on $G_1,\dots,G_n,G_T$ can be computed efficiently, but the discrete log problem on $G_1,\dots,G_n$ is still hard.[^o19] Some applications require stronger assumptions, e.g. multilinear analogs of Diffie-Hellman assumptions.

For the special case of $n=2$, [bilinear maps](wikipedia://en/4365) with believable security have been constructed using [Weil pairing](https://en.wikipedia.org/wiki/Weil_pairing) and [Tate pairing](wikipedia://en/34128228).[^o20] For $n>2$ many constructions have been proposed in recent years, but many of them have also been broken, and currently there is no consensus about a safe candidate.[^o21]

Some cryptosystems that rely on multilinear hardness assumptions include:

- [Boneh-Franklin scheme](https://en.wikipedia.org/wiki/Boneh-Franklin_scheme) (bilinear Diffie-Hellman)
- [Boneh–Lynn–Shacham](https://en.wikipedia.org/wiki/Boneh–Lynn–Shacham) (bilinear Diffie-Hellman)
- Garg-Gentry-Halevi-Raykova-Sahai-Waters candidate for [indistinguishability obfuscation](wikipedia://en/59961754) and [functional encryption](wikipedia://en/39080703) (multilinear jigsaw puzzles)[^o22]

### Lattice problems {#Lattice_problems}

The most fundamental computational problem on [lattices](wikipedia://en/469246) is the [shortest vector problem (SVP)](wikipedia://en/18661117#Shortest_vector_problem_%28SVP%29): given a lattice $L$, find the shortest non-zero vector $v \in L$. Most cryptosystems require stronger assumptions on variants of SVP, such as [shortest independent vectors problem (SIVP)](wikipedia://en/18661117#Shortest_independent_vectors_problem_%28SIVP%29), [GapSVP](wikipedia://en/18661117#GapSVP),[^o24] or Unique-SVP.[^o25]

The most useful lattice hardness assumption in cryptography is for the [learning with errors](wikipedia://en/23864530) (LWE) problem: Given samples to $(x,y)$, where $y = f(x)$ for some linear function $f(\cdot)$, it is easy to learn $f(\cdot)$ using [linear algebra](wikipedia://en/18422). In the LWE problem, the input to the algorithm has errors, i.e. for each pair $y\neq f(x)$ with some small [probability](wikipedia://en/22934). The errors are believed to make the problem intractable (for appropriate parameters); in particular, there are known worst-case to average-case reductions from variants of SVP.[^o26]

For [quantum computers](https://en.wikipedia.org/wiki/Quantum_computer), factoring and discrete log problems are easy, but lattice problems are conjectured to be hard.[^o27] This makes some [lattice-based cryptosystems](wikipedia://en/18657553) candidates for [post-quantum cryptography](wikipedia://en/26605226).

Some cryptosystems that rely on hardness of lattice problems include:

- [NTRU](wikipedia://en/481661) (both [NTRUEncrypt](wikipedia://en/481582) and [NTRUSign](wikipedia://en/3513327))
- Most candidates for [fully homomorphic encryption](wikipedia://en/4939073)

## Non-cryptographic hardness assumptions {#Non-cryptographic_hardness_assumptions}

As well as their cryptographic applications, hardness assumptions are used in [computational complexity theory](wikipedia://en/7543) to provide evidence for mathematical statements that are difficult to prove unconditionally. In these applications, one proves that the hardness assumption implies some desired complexity-theoretic statement, instead of proving that the statement is itself true. The best-known assumption of this type is the assumption that [P ≠ NP](wikipedia://en/6115),[^o29] but others include the [exponential time hypothesis](wikipedia://en/26434552),[^o30] the [planted clique conjecture](wikipedia://en/48563244), and the [unique games conjecture](wikipedia://en/3000842).[^o31]

### *C*-hard problems {#C-hard_problems}

Many [worst-case](https://en.wikipedia.org/wiki/Worst-case_complexity) computational problems are known to be hard or even [complete](wikipedia://en/1176530) for some [complexity class](wikipedia://en/502426) $C$, in particular [NP-hard](wikipedia://en/54681) (but often also [PSPACE-hard](wikipedia://en/9202993), [PPAD-hard](wikipedia://en/23256783), etc.). This means that they are at least as hard as any problem in the class $C$. If a problem is $C$-hard (with respect to polynomial time reductions), then it cannot be solved by a polynomial-time algorithm unless the computational hardness assumption $P \neq C$ is false.

::: {#o34 .statement kind=statement/conjecture cue=named-heading name="Exponential time hypothesis (ETH) and variants"}

### Exponential time hypothesis (ETH) and variants {#Exponential_time_hypothesis_(ETH)_and_variants}

The exponential time hypothesis (ETH) is a strengthening of $P \neq NP$ hardness assumption, which conjectures that not only does the [Boolean satisfiability problem](wikipedia://en/4715) (SAT) not have a polynomial time algorithm, it furthermore requires exponential time ($2^{\Omega(n)}$).[^o35] An even stronger assumption, known as the [strong exponential time hypothesis](wikipedia://en/26434552) (SETH) conjectures that [$k$-SAT](wikipedia://en/4715) requires $2^{(1-\varepsilon_k)n}$ time, where $\lim_{k \rightarrow \infty} \varepsilon_k = 0$. ETH, SETH, and related computational hardness assumptions allow for deducing fine-grained complexity results, e.g. results that distinguish polynomial time and [quasi-polynomial time](wikipedia://en/25269049),[^o5] or even $n^{1.99}$ versus $n^2$.[^o36] Such assumptions are also useful in [parametrized complexity](https://en.wikipedia.org/wiki/Parametrized_complexity).[^o37]

:::

### Average-case hardness assumptions {#Average-case_hardness_assumptions}

Some computational problems are assumed to be hard on average over a particular distribution of instances. For example, in the [planted clique](wikipedia://en/48563244) problem, the input is a [random graph](wikipedia://en/358477) sampled, by sampling an [Erdős–Rényi random graph](wikipedia://en/10477221) and then "planting" a random $k$-clique, i.e. connecting $k$ uniformly random nodes (where $2\log_2 n \ll k \ll \sqrt n$), and the goal is to find the planted $k$-clique (which is unique w.h.p.).[^o39] Another important example is [Feige](wikipedia://en/24734804)'s Hypothesis, which is a computational hardness assumption about random instances of [3-SAT](wikipedia://en/4715) (sampled to maintain a specific ratio of clauses to variables).[^o40] Average-case computational hardness assumptions are useful for proving average-case hardness in applications like statistics, where there is a natural distribution over inputs.[^o41] Additionally, the planted clique hardness assumption has also been used to distinguish between polynomial and quasi-polynomial worst-case time complexity of other problems,[^o42] similarly to the exponential time hypothesis.

### Unique games {#Unique_games}

The [unique label cover](wikipedia://en/3000842#Unique_label_cover) problem is a constraint satisfaction problem, where each constraint $C$ involves two variables $x,y$, and for each value of $x$ there is a *unique* value of $y$ that satisfies $C$. Determining whether all the constraints can be satisfied is easy, but the **unique game conjecture** (UGC) postulates that determining whether almost all the constraints ($(1-\varepsilon)$-fraction, for any constant $\varepsilon>0$) can be satisfied or almost none of them ($\varepsilon$-fraction) can be satisfied is NP-hard.[^o31] Approximation problems are often known to be NP-hard assuming UGC; such problems are referred to as UG-hard. In particular, assuming UGC there is a [semidefinite programming](wikipedia://en/4993539) algorithm that achieves optimal approximation guarantees for many important problems.[^o44]

#### Small set expansion {#Small_set_expansion}

Closely related to the unique label cover problem is the **small set expansion (SSE)** problem: Given a [graph](wikipedia://en/325806) $G = (V,E)$, find a small set of vertices (of size $n/\log(n)$) whose [edge expansion](wikipedia://en/9313#Edge_expansion) is minimal. It is known that if SSE is hard to approximate, then so is unique label cover. Hence, the *small set expansion hypothesis*, which postulates that SSE is hard to approximate, is a stronger (but closely related) assumption than the unique game conjecture.[^o46] Some approximation problems are known to be SSE-hard[^o47] (i.e. at least as hard as approximating SSE).

::: {#o49 .statement kind=statement/conjecture cue=named-heading name="The 3SUM conjecture"}

### The 3SUM conjecture {#The_3SUM_conjecture}

Given a set of $n$ numbers, the 3SUM problem asks whether there is a triplet of numbers whose sum is zero. There is a [quadratic-time](https://en.wikipedia.org/wiki/Quadratic_time) algorithm for 3SUM, and it has been conjectured that no algorithm can solve 3SUM in "truly sub-quadratic time": the **3SUM conjecture** is the computational hardness assumption that there are no $O(n^{2-\varepsilon})$-time algorithms for 3SUM (for any constant $\varepsilon > 0$). This conjecture is useful for proving near-quadratic lower bounds for several problems, mostly from [computational geometry](wikipedia://en/176927).[^o50]

:::
