# Naccache–Stern knapsack cryptosystem

::: {#o1 .subject cue=lead name="Naccache–Stern knapsack cryptosystem"}

The **Naccache–Stern Knapsack cryptosystem** is an atypical [public-key cryptosystem](https://en.wikipedia.org/wiki/Public-key_cryptosystem) developed by [David Naccache](wikipedia://en/9488704) and [Jacques Stern](https://en.wikipedia.org/wiki/Jacques_Stern_%28cryptographer%29) in 1997. This cryptosystem is [deterministic](wikipedia://en/2343703), and hence is not [semantically secure](wikipedia://en/960585). While unbroken to date, this system also lacks [provable security](wikipedia://en/1182348).

:::

## System overview {#System_overview}

This system is based on a type of [knapsack problem](wikipedia://en/16974). Specifically, the underlying problem is this: given integers *c*,*n*,*p* and *v*<sub>0</sub>,...,*v*<sub>*n*</sub>, find a vector $x \in \{0,1\}^n$ such that

$$c \equiv \prod_{i=0}^n v_i^{x_i} \mod p$$

The idea here is that when the *v*<sub>*i*</sub> are [relatively prime](https://en.wikipedia.org/wiki/Relatively_prime) and much smaller than the modulus *p* this problem can be solved easily. It is this observation which allows decryption.

### Key Generation {#Key_Generation}

To generate a public/private key pair

- Pick a large [prime](wikipedia://en/23666) modulus *p*.
- Pick a positive integer *n* and for *i* from 0 to *n*, set *p*<sub>*i*</sub> to be the *i*th prime, starting with *p*<sub>0</sub> = 2 and such that $\prod_{i=0}^np_i < p$.
- Pick a secret integer *s* \< *p*-1, such that gcd(*p*-1,*s*) = 1.
- Set $v_i = \sqrt[s]{p_i} \mod p$.

The public key is then *p*,*n* and *v*<sub>0</sub>,...,*v*<sub>*n*</sub>. The private key is *s*.

### Encryption {#Encryption}

To encrypt an *n*-bit long message *m*, calculate

$$c = \prod_{i=0}^n v_i^{m_i} \mod p$$

where *m*<sub>*i*</sub> is the *i*th bit of the message *m*.

### Decryption {#Decryption}

To decrypt a message *c*, calculate

$$m = \sum_{i=0}^n \frac{2^i}{p_i-1} \times \left( \gcd(p_i,c^s \mod p) -1 \right)$$

This works because the fraction

$$\frac{ \gcd(p_i,c^s \mod p) - 1 }{p_i - 1}$$

is 0 or 1 depending on whether *p*<sub>*i*</sub> divides *c*<sup>*s*</sup> mod *p*.

## Security {#Security}

The security of the trapdoor function relies on the difficulty of the following multiplicative [knapsack problem](wikipedia://en/16974): given

$$c = \prod_{i=0}^n v_i^{m_i}\pmod p,$$

recover the $m_i$. Unlike additive knapsack-based cryptosystems, such as [Merkle-Hellman](https://en.wikipedia.org/wiki/Merkle-Hellman_knapsack_cryptosystem), techniques like [Euclidean lattice reduction](https://en.wikipedia.org/wiki/LLL_algorithm) do not apply to this problem.

The best known generic attack consists of solving the [discrete logarithm problem](https://en.wikipedia.org/wiki/Discrete_logarithm_problem) to recover $s$ from $p, p_i, v_i$, which is considered difficult for a classical computer. However, the [quantum algorithm of Shor](wikipedia://en/42674) efficiently solves this problem. Furthermore, currently (2023), there is no proof that the Naccache-Stern knapsack reduces to the discrete logarithm problem.

The best known specific attack (in 2018) uses the [birthday theorem](https://en.wikipedia.org/wiki/Birthday_paradox) to partially invert the function without knowing the trapdoor, assuming that the message has a very low [Hamming weight](wikipedia://en/1127884).[^o7]
