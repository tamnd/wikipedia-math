# Hash chain

::: {#o1 .subject cue=lead name="Hash chain"}

A **hash chain** is the successive application of a [cryptographic hash function](wikipedia://en/439526) to a piece of data. In [computer security](https://en.wikipedia.org/wiki/Computer_security), a hash chain is a method used to produce many [one-time keys](wikipedia://en/1190077) from a single [key](wikipedia://en/53039) or [password](wikipedia://en/24304). For [non-repudiation](wikipedia://en/52491), a hash function can be applied successively to additional pieces of data in order to record the chronology of data's existence.

:::

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

A **hash chain** is a successive application of a [cryptographic hash function](wikipedia://en/439526) $h$ to a string $x$.

For example,

$h(h(h(h(x))))$ gives a hash chain of length 4, often denoted $h^{4}(x)$

:::

::: {#o5 .application cue=heading name="Applications"}

## Applications {#Applications}

[Leslie Lamport](https://en.wikipedia.org/wiki/Leslie_Lamport)[^o6] suggested the use of hash chains as a password protection scheme in an insecure environment. A server which needs to provide [authentication](wikipedia://en/47967) may store a hash chain rather than a [plain text](https://en.wikipedia.org/wiki/Plain_text) password and prevent theft of the password in transmission or theft from the server. For example, a server begins by storing $h^{1000}(\mathrm{password})$ which is provided by the user. When the user wishes to authenticate, they supply $h^{999}(\mathrm{password})$ to the server. The server computes $h(h^{999}(\mathrm{password})) = h^{1000}(\mathrm{password})$ and verifies this matches the hash chain it has stored. It then stores $h^{999}(\mathrm{password})$ for the next time the user wishes to authenticate.

An eavesdropper seeing $h^{999}(\mathrm{password})$ communicated to the server will be unable to re-transmit the same hash chain to the server for [authentication](wikipedia://en/47967) since the server now expects $h^{998}(\mathrm{password})$. Due to the [one-way property](wikipedia://en/363890) of [cryptographically secure hash functions](wikipedia://en/439526), it is infeasible for the eavesdropper to reverse the hash function and obtain an earlier piece of the hash chain. In this example, the user could authenticate 1000 times before the hash chain were exhausted. Each time the hash value is different, and thus cannot be duplicated by an attacker.

:::

## Binary hash chains {#Binary_hash_chains}

Binary hash chains are commonly used in association with a [hash tree](wikipedia://en/2497388). A binary hash chain takes two hash values as inputs, concatenates them and applies a hash function to the result, thereby producing a third hash value.

*Image: Hashtreehashchainjux.png.* Hash tree and hash chain

The above diagram shows a hash tree consisting of eight leaf nodes and the hash chain for the third leaf node. In addition to the hash values themselves the order of concatenation (right or left 1,0) or "order bits" are necessary to complete the hash chain.

## Winternitz chains {#Winternitz_chains}

Winternitz chain (also known as **function chains**[^n1]) are used in [hash-based cryptography](wikipedia://en/53957696). The chain is parameterized by the Winternitz parameter *w* (number of bits in a "digit" *d*) and *security parameter* *n* (number of bits in the hash value, typically double the [security strength](https://en.wikipedia.org/wiki/Security_strength),[^n2] 256 or 512). The chain consists of $2^w$ values that are results of repeated application of a [one-way "chain" function](wikipedia://en/363890) *F* to a secret key *sk*: $sk, F(sk), F(F(sk)), ..., F^{2^{w-1}}(sk)$. The chain function is typically based on a standard [cryptographic hash](https://en.wikipedia.org/wiki/Cryptographic_hash), but needs to be parameterized ("randomized"[^n3]), so it involves few invocations of the underlying hash.[^o12] In the Winternitz signature scheme a chain is used to encode one digit of the *m*-bit message, so the Winternitz signature uses approximately $mn/w$ bits, its calculation takes about $2^wm/w$ applications of the function F.[^n2] Note that some signature standards (like [Extended Merkle signature scheme](https://en.wikipedia.org/wiki/Extended_Merkle_signature_scheme), XMSS) define *w* as the number of possible values in a digit, so $w=16$ in XMSS corresponds to $w=4$ in standards (like [Leighton-Micali Signature](https://en.wikipedia.org/wiki/Leighton-Micali_Signature), LMS) that define *w* in the same way as above - as a number of bits in the digit.[^o14]

## Hash chain vs. blockchain {#Hash_chain_vs._blockchain}

A hash chain is similar to a [blockchain](wikipedia://en/44065971), as they both utilize a [cryptographic hash function](wikipedia://en/439526) for creating a link between two nodes. However, a blockchain (as used by [Bitcoin](wikipedia://en/28249265) and related systems) is generally intended to support distributed agreement around a public ledger (data), and incorporates a set of rules for encapsulation of data and associated data permissions.
