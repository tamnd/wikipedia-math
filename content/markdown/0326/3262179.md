# Cobham's thesis

::: {#o1 .subject cue=lead name="Cobham's thesis"}

Cobham's theorem **Cobham's thesis**, also known as the **Cobham–Edmonds thesis** (named after [Alan Cobham](wikipedia://en/68162815) and [Jack Edmonds](wikipedia://en/3625459)),[^o2][^o3][^o4] asserts that computational problems can be feasibly computed on some computational device only if they can be computed in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time); that is, if they lie in the [complexity class](wikipedia://en/502426) **[P](wikipedia://en/658550)**.[^o5] In modern terms, it identifies [tractable problems](https://en.wikipedia.org/wiki/Tractable_problem) with the complexity class **P**.

:::

Formally, to say that a problem can be solved in polynomial time is to say that there exists an algorithm that, given an *n*-bit instance of the problem as input, can produce a solution in time O(*n<sup>c</sup>*), using the [big-O notation](https://en.wikipedia.org/wiki/Big-O_notation) and with *c* being a constant that depends on the problem but not the particular instance of the problem.

Alan Cobham's 1965 paper entitled "The intrinsic computational difficulty of functions"[^o6] is one of the earliest mentions of the concept of the [complexity class](wikipedia://en/502426) **[P](wikipedia://en/658550)**, consisting of problems decidable in polynomial time. Cobham theorized that this complexity class was a good way to describe the set of feasibly [computable](https://en.wikipedia.org/wiki/Computability_theory_%28computer_science%29) problems.

Jack Edmonds's 1965 paper "Paths, trees, and flowers"[^o7] is also credited with identifying **P** with tractable problems.[^o8]

## Limitations {#Limitations}

*Image: KnapsackEmpComplexity.GIF.* The graph shows time of solution of problem in milliseconds (ms) vs. problem size *n* for [knapsack problems](wikipedia://en/16974) solved by a state-of-the-art specialized algorithm using a 933 MHz Pentium III computer (average of 100 instances, data from Pisinger[^o10]). The fit of the quadratic equation suggests that empirical algorithmic complexity for instances with 50–10,000 variables is O((log *n*)<sup>2</sup>) despite having exponential worst-case complexity estimate in theory.

While Cobham's thesis is an important milestone in the development of the theory of [computational complexity](wikipedia://en/7543), it has limitations as applied to practical feasibility of algorithms. The thesis essentially states that "**P**" means "easy, fast, and practical", while "not in **P**" means "hard, slow, and impractical". But this is not always true, because the thesis abstracts away some important variables that influence the runtime in practice:

- It ignores constant factors and lower-order terms.
- It ignores the size of the exponent. The [time hierarchy theorem](wikipedia://en/184120) proves the existence of problems in **P** requiring arbitrarily large exponents.
- It ignores the typical size of the input.

All three are related and are general complaints about [analysis of algorithms](wikipedia://en/2230), but they particularly apply to Cobham's thesis, since it makes an explicit claim about practicality. Under Cobham's thesis, a problem for which the best algorithm takes *n*<sup>200</sup> instructions is considered feasible, and a problem with an algorithm that takes 2<sup>\0.00001*n*</sup> instructions infeasible—even though one could never solve an instance of size *n* = 2 with the former algorithm, whereas an instance of the latter problem of size *n* = 10<sup>6</sup> could be solved without difficulty. In fields where practical problems have millions of variables (such as [operations research](wikipedia://en/43476) or [electronic design automation](https://en.wikipedia.org/wiki/Electronic_design_automation)), even O(*n*<sup>3</sup>) algorithms are often impractical.[^o11]

A separate consideration is that in many cases, one is often content with *approximate* solutions if an exact solution cannot be found. For example, the [travelling salesman problem](wikipedia://en/31248) is widely suspected to be unsolvable exactly in polynomial time (it is [NP-hard](wikipedia://en/54681)), but good solutions can be obtained in polynomial time with methods such as the [Christofides algorithm](wikipedia://en/3589536).
