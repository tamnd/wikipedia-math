# Metric k-center

::: {#o1 .subject cue=lead name="Metric k-center"}

In [graph theory](wikipedia://en/12401), the **metric $k$-center** problem or **vertex k-center problem** is a classical [combinatorial optimization](wikipedia://en/420555) problem studied in [theoretical computer science](wikipedia://en/323392) that is [NP-hard](wikipedia://en/54681). Given $n$ cities with specified distances, one wants to build $k$ warehouses in different cities and minimize the maximum distance of a city to a warehouse. In [graph theory](wikipedia://en/12401), this means finding a set of $k$ [vertices](wikipedia://en/638899) for which the largest distance of any point to its closest vertex in the $k$-set is minimum. The vertices must be in a [metric space](wikipedia://en/20018), providing a [complete graph](wikipedia://en/85816) that satisfies the [triangle inequality](wikipedia://en/53941). It has application in [facility location](wikipedia://en/10469986) and [clustering](wikipedia://en/669675).[^o2][^o3]

:::

::: {#o5 .definition cue=heading name="Formal definition"}

## Formal definition {#Formal_definition}

The problem was first proposed by Hakimi in 1964.[^o6]

Let $(X,d)$ be a [metric space](wikipedia://en/20018) where $X$ is a set and $d$ is a [metric](https://en.wikipedia.org/wiki/Metric_%28mathematics%29) A set $\mathbf{V}\subseteq\mathcal{X}$, is provided together with a parameter $k$. The goal is to find a subset $\mathcal{C}\subseteq \mathbf{V}$ with $|\mathcal{C}|=k$ such that the maximum distance of a point in $\mathbf{V}$ to the closest point in $\mathcal{C}$ is minimized. The problem can be formally defined as follows: For a metric space ($\mathcal{X}$,d),

- *Input*: a set $\mathbf{V}\subseteq\mathcal{X}$, and a parameter $k$.
- *Output*: a set $\mathcal{C}\subseteq\mathbf{V}$ of $k$ points.
- *Goal*: Minimize the cost $r^\mathcal{C}(\mathbf{V}) = \underset{v\in V}{\max}$ d(v,$\mathcal{C}$)

That is, every point in a cluster is in distance at most $r^\mathcal{C}(V)$ from its respective center. [^o7]

The k-Center Clustering problem can also be defined on a complete [undirected graph](wikipedia://en/325806) *G* = (*V*, *E*) as follows: Given a complete undirected graph *G* = (*V*, *E*) with distances *d*(*v*<sub>*i*</sub>, *v*<sub>*j*</sub>) ∈ *N* satisfying the triangle inequality, find a subset *C* ⊆ *V* with |*C*| = *k* while minimizing:

$$\max_{v \in V} \min_{c \in C} d(v,c)$$

:::

## Computational complexity {#Computational_complexity}

In a complete undirected graph *G* = (*V*, *E*), if we sort the edges in non-decreasing order of the distances: *d*(*e*<sub>1</sub>) ≤ *d*(*e*<sub>2</sub>) ≤ ... ≤ *d*(*e*<sub>m</sub>) and let *G*<sub>i</sub> = (V, *E*<sub>i</sub>), where *E*<sub>i</sub> = {*e*<sub>1</sub>, *e*<sub>2</sub>, ..., *e*<sub>i</sub>}. The *k*-center problem is equivalent to finding the smallest index *i* such that *G*<sub>i</sub> has a [dominating set](wikipedia://en/1747972) of size at most *k*. [^o9]

Although Dominating Set is [NP-complete](https://en.wikipedia.org/wiki/NP-complete), the *k*-center problem remains [NP-hard](https://en.wikipedia.org/wiki/NP-hard). This is clear, since the optimality of a given feasible solution for the *k*-center problem can be determined through the Dominating Set reduction only if we know in first place the size of the optimal solution (i.e. the smallest index *i* such that *G*<sub>i</sub> has a [dominating set](wikipedia://en/1747972) of size at most *k*), which is precisely the difficult core of the [NP-hard](https://en.wikipedia.org/wiki/NP-hard) problems. Although a [Turing reduction](wikipedia://en/1188375) can get around this issue by trying all values of *k*.

## Approximations {#Approximations}

### A simple greedy algorithm {#A_simple_greedy_algorithm}

A simple [greedy](wikipedia://en/89247) [approximation algorithm](wikipedia://en/563105) that achieves an approximation factor of 2 builds $\mathcal{C}$ using a [farthest-first traversal](https://en.wikipedia.org/wiki/Farthest-first_traversal) in *k* iterations. This algorithm simply chooses the point farthest away from the current set of centers in each iteration as the new center. It can be described as follows:

- Pick an arbitrary point $\bar{c}_1$ into $C_1$
- For every point $v\in \mathbf{V}$ compute $d_1[v]$ from $\bar{c}_1$
- Pick the point $\bar{c}_2$ with highest distance from $\bar{c}_1$.
- Add it to the set of centers and denote this expanded set of centers as $C_2$. Continue this till *k* centers are found

#### Running time {#Running_time}

- The i<sup>th</sup> iteration of choosing the i<sup>th</sup> center takes $\mathcal{O}(n)$ time.
- There are *k* such iterations.
- Thus, overall the algorithm takes $\mathcal{O}(nk)$ time.[^o13]

#### Proving the approximation factor {#Proving_the_approximation_factor}

The solution obtained using the simple greedy algorithm is a 2-approximation to the optimal solution. This section focuses on proving this approximation factor.

Given a set of *n* points $\mathbf{V}\subseteq\mathcal{X}$, belonging to a metric space ($\mathcal{X}$,d), the greedy *K*-center algorithm computes a set **K** of *k* centers, such that **K** is a 2-approximation to the optimal *k*-center clustering of **V**.

*i.e.* $r^{\mathbf{K}}(\mathbf{V})\leq 2r^{opt}(\mathbf{V},\textit{k})$ [^o7]

This theorem can be proven using two cases as follows,

Case 1: Every cluster of $\mathcal{C}_{opt}$ contains exactly one point of $\mathbf{K}$

- Consider a point $v\in \mathbf{V}$
- Let $\bar{c}$ be the center it belongs to in $\mathcal{C}_{opt}$
- Let $\bar{k}$ be the center of $\mathbf{K}$ that is in $\Pi(\mathcal{C}_{opt},\bar{c})$
- $$d(v,\bar{c})=d(v,\mathcal{C}_{opt})\leq r^{opt}(\mathbf{V},k)$$
- Similarly, $d(\bar{k},\bar{c})=d(\bar{k},\mathcal{C}_{opt})\leq r^{opt}$
- By the triangle inequality: $d(v,\bar{k})\leq d(v,\bar{c})+d(\bar{c},\bar{k})\leq 2r^{opt}$

Case 2: There are two centers $\bar{k}$ and $\bar{u}$ of $\mathbf{K}$ that are both in $\Pi(\mathcal{C}_{opt},\bar{c})$, for some $\bar{c}\in \mathcal{C}_{opt}$ (By pigeon hole principle, this is the only other possibility)

- Assume, [without loss of generality](wikipedia://en/296000), that $\bar{u}$ was added later to the center set $\mathbf{K}$ by the greedy algorithm, say in i<sup>th</sup> iteration.
- But since the greedy algorithm always chooses the point furthest away from the current set of centers, we have that $\bar{k}\in\mathcal{C}_{i-1}$and,

$\begin{aligned} r^\mathbf{K}(\mathbf{V})\leq r^{\mathcal{C}_{i-1}}(\mathbf{V})&=d(\bar{u},\mathcal{C}_{i-1})\\ &\leq d(\bar{u},\bar{k})\\ &\leq d(\bar{u},\bar{c})+d(\bar{c},\bar{k})\\ &\leq 2r^{opt} \end{aligned}$ [^o7]

### Another 2-factor approximation algorithm {#Another_2-factor_approximation_algorithm}

Another algorithm with the same approximation factor takes advantage of the fact that the *k*-Center problem is equivalent to finding the smallest index *i* such that *G*<sub>i</sub> has a dominating set of size at most *k* and computes a [maximal independent set](wikipedia://en/1793590) of *G*<sub>i</sub>, looking for the smallest index *i* that has a maximal independent set with a size of at least *k*. [^o16] It is not possible to find an approximation algorithm with an approximation factor of 2 − ε for any ε > 0, unless P = NP. [^o17] Furthermore, the distances of all edges in G must satisfy the triangle inequality if the *k*-center problem is to be approximated within any constant factor, unless P = NP. [^o18]

### Parameterized approximations {#Parameterized_approximations}

It can be shown that the *k*-Center problem is [W\[2\]-hard](wikipedia://en/603026) to approximate within a factor of 2 − ε for any ε > 0, when using *k* as the parameter.[^o20] This is also true when parameterizing by the [doubling dimension](https://en.wikipedia.org/wiki/Doubling_dimension) (in fact the dimension of a [Manhattan metric](https://en.wikipedia.org/wiki/Manhattan_metric)), unless [P=NP](wikipedia://en/6115).[^o21] When considering the combined parameter given by *k* and the [doubling dimension](https://en.wikipedia.org/wiki/Doubling_dimension), *k*-Center is still W\[1\]-hard but it is possible to obtain a [parameterized approximation scheme](wikipedia://en/72808068).[^o22] This is even possible for the variant with vertex capacities, which bound how many vertices can be assigned to an opened center of the solution.[^o23]

## Approximation algorithms {#Approximation_algorithms}

If $P \neq NP$, the vertex *k*-center problem can not be (optimally) solved in polynomial time. However, there are some polynomial time [approximation algorithms](wikipedia://en/563105) that get near-optimal solutions. Specifically, [2-approximated solutions](wikipedia://en/563105). Actually, if $P \neq NP$ the best possible solution that can be achieved by a polynomial time algorithm is a 2-approximated one.[^o25][^o26][^o27][^o28] In the context of a minimization problem, such as the vertex *k*-center problem, a 2-approximated solution is any solution $C'$ such that $r(C') \le 2 \times r(\text{OPT})$, where $r(\text{OPT})$ is the size of an optimal solution. An algorithm that guarantees to generate 2-approximated solutions is known as a 2-approximation algorithm. The main 2-approximated algorithms for the vertex *k*-center problem reported in the literature are the Sh algorithm,[^o29] the HS algorithm,[^o28] and the Gon algorithm.[^o26][^o27] Even though these algorithms are the (polynomial) best possible ones, their performance on most benchmark datasets is very deficient. Because of this, many [heuristics](wikipedia://en/14220429) and [metaheuristics](https://en.wikipedia.org/wiki/Metaheuristic) have been developed through the time. Contrary to common sense, one of the most practical (polynomial) heuristics for the vertex *k*-center problem is based on the CDS algorithm, which is a 3-approximation algorithm[^o30]

### The Sh algorithm {#The_Sh_algorithm}

Formally characterized by [David Shmoys](https://en.wikipedia.org/wiki/David_Shmoys) in 1995,[^o29] the Sh algorithm takes as input a complete undirected graph $G=(V,E)$, a positive integer $k$, and an assumption $r$ on what the optimal solution size is. The Sh algorithm works as follows: selects the first center $c_1$ at random. So far, the solution consists of only one vertex, $C=\{c_1\}$. Next, selects center $c_2$ at random from the set containing all the vertices whose distance from $C$ is greater than $2 \times r$. At this point, $C=\{c_1,c_2\}$. Finally, selects the remaining $k-2$ centers the same way $c_2$ was selected. The complexity of the Sh algorithm is $O(kn)$, where $n$ is the number of vertices.

### The HS algorithm {#The_HS_algorithm}

Proposed by [Dorit Hochbaum](https://en.wikipedia.org/wiki/Dorit_S._Hochbaum) and [David Shmoys](https://en.wikipedia.org/wiki/David_Shmoys) in 1985, the HS algorithm takes the Sh algorithm as basis.[^o28] By noticing that the value of $r(\text{OPT})$ must equals the cost of some edge in $E$, and since there are $O(n^2)$ edges in $E$, the HS algorithm basically repeats the Sh algorithm with every edge cost. The complexity of the HS algorithm is $O(n^4)$. However, by running a [binary search](https://en.wikipedia.org/wiki/Binary_search_algorithm) over the ordered set of edge costs, its complexity is reduced to $O(n^2 \log n)$.

### The Gon algorithm {#The_Gon_algorithm}

Proposed independently by [Teofilo Gonzalez](https://en.wikipedia.org/wiki/Teofilo_F._Gonzalez),[^o26] and by [Martin Dyer](https://en.wikipedia.org/wiki/Martin_Dyer) and [Alan Frieze](wikipedia://en/22466549)[^o27] in 1985, the Gon algorithm is basically a more powerful version of the Sh algorithm. While the Sh algorithm requires a guess $r$ on $r(\text{OPT})$, the Gon algorithm prescinds from such guess by noticing that if any set of vertices at distance greater than $2 \times r(\text{OPT})$ exists, then the farthest vertex must be inside such set. Therefore, instead of computing at each iteration the set of vertices at distance greater than $2 \times r$ and then selecting a random vertex, the Gon algorithm simply selects the farthest vertex from every partial solution $C'$. The complexity of the Gon algorithm is $O(kn)$, where $n$ is the number of vertices.

### The CDS algorithm {#The_CDS_algorithm}

Proposed by García Díaz et al. in 2017,[^o30] the CDS algorithm is a 3-approximation algorithm that takes ideas from the Gon algorithm (farthest point heuristic), the HS algorithm (parametric pruning), and the relationship between the vertex *k*-center problem and the [Dominating Set](wikipedia://en/1747972) problem. The CDS algorithm has a complexity of $O(n^4)$. However, by performing a binary search over the ordered set of edge costs, a more efficiente heuristic named CDSh is proposed. The CDSh algorithm complexity is $O(n^2 \log n)$. Despite the suboptimal performance of the CDS algorithm, and the heuristic performance of CDSh, both present a much better performance than the Sh, HS, and Gon algorithms.

### Parameterized approximations {#Parameterized_approximations}

It can be shown that the *k*-Center problem is [W\[2\]-hard](wikipedia://en/603026) to approximate within a factor of 2 − ε for any ε > 0, when using *k* as the parameter.[^o36] This is also true when parameterizing by the [doubling dimension](https://en.wikipedia.org/wiki/Doubling_dimension) (in fact the dimension of a [Manhattan metric](https://en.wikipedia.org/wiki/Manhattan_metric)), unless [P=NP](wikipedia://en/6115).[^o21] When considering the combined parameter given by *k* and the [doubling dimension](https://en.wikipedia.org/wiki/Doubling_dimension), *k*-Center is still W\[1\]-hard but it is possible to obtain a [parameterized approximation scheme](wikipedia://en/72808068).[^o37] This is even possible for the variant with vertex capacities, which bound how many vertices can be assigned to an opened center of the solution.[^o23]

## Polynomial heuristics {#Polynomial_heuristics}

### Greedy pure algorithm {#Greedy_pure_algorithm}

The greedy pure algorithm (or Gr) follows the core idea of [greedy algorithms](wikipedia://en/89247): to take optimal local decisions. In the case of the vertex *k*-center problem, the optimal local decision consists in selecting each center in such a way that the size of the solution (covering radius) is minimum at each iteration. In other words, the first center selected is the one that solves the [1-center problem](https://en.wikipedia.org/wiki/1-center_problem). The second center selected is the one that, along with the previous center, generates a solution with minimum covering radius. The remaining centers are selected the same way. The complexity of the Gr algorithm is $O(kn^2)$.[^o45] The empirical performance of the Gr algorithm is poor on most benchmark instances.

### Scoring algorithm {#Scoring_algorithm}

The [Scoring algorithm](wikipedia://en/9981737) (or Scr) was introduced by Jurij Mihelič and Borut Robič in 2005.[^o47] This algorithm takes advantage of the reduction from the vertex *k*-center problem to the minimum dominating set problem. The problem is solved by pruning the input graph with every possible value of the optimal solution size and then solving the minimum dominating set problem heuristically. This heuristic follows the *lazy principle,* which takes every decision as slow as possible (opposed to the greedy strategy). The complexity of the Scr algorithm is $O(n^4)$. The empirical performance of the Scr algorithm is very good on most benchmark instances. However, its running time rapidly becomes impractical as the input grows. So, it seems to be a good algorithm only for small instances.
