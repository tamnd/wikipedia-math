# Dm-crypt

::: {#o1 .subject cue=lead name="Dm-crypt"}

**dm-crypt** is a transparent [block device encryption](wikipedia://en/7066791) [subsystem](https://en.wikipedia.org/wiki/Subsystem) in [Linux kernel](https://en.wikipedia.org/wiki/Linux_kernel) versions 2.6 and later and in [DragonFly BSD](https://en.wikipedia.org/wiki/DragonFly_BSD). It is part of the [device mapper](https://en.wikipedia.org/wiki/Device_mapper) (dm) infrastructure, and uses cryptographic routines from the kernel's [Crypto API](https://en.wikipedia.org/wiki/Crypto_API_%28Linux%29). Unlike its predecessor [cryptoloop](https://en.wikipedia.org/wiki/Cryptoloop), dm-crypt was designed to support advanced modes of operation, such as [XTS](wikipedia://en/3395256#XTS), [LRW](wikipedia://en/3395256#Liskov,_Rivest,_and_Wagner_%28LRW%29) and [ESSIV](wikipedia://en/3395256#Encrypted_salt-sector_initialization_vector_%28ESSIV%29), in order to avoid [watermarking attacks](wikipedia://en/7228413).[^o2] In addition to that, dm-crypt addresses some reliability problems of cryptoloop.[^o3]

:::

dm-crypt is implemented as a device mapper target and may be stacked on top of other device mapper transformations. It can thus encrypt whole disks (including [removable media](https://en.wikipedia.org/wiki/Removable_media)), [partitions](https://en.wikipedia.org/wiki/Disk_partitioning), [software RAID](https://en.wikipedia.org/wiki/Software_RAID) volumes, [logical volumes](https://en.wikipedia.org/wiki/Logical_volume), as well as [files](https://en.wikipedia.org/wiki/Computer_file). It appears as a block device, which can be used to back [file systems](https://en.wikipedia.org/wiki/File_systems), [swap](https://en.wikipedia.org/wiki/Swap_partition) or as an [LVM](https://en.wikipedia.org/wiki/Logical_Volume_Manager_%28Linux%29) [physical volume](https://en.wikipedia.org/wiki/Physical_volume).

Some [Linux distributions](https://en.wikipedia.org/wiki/Linux_distribution) support the use of dm-crypt on the root file system. These distributions use [initrd](https://en.wikipedia.org/wiki/Initrd) to prompt the user to enter a passphrase at the console, or insert a [smart card](https://en.wikipedia.org/wiki/Smart_card) prior to the normal boot process.[^o20]

## Frontends {#Frontends}

The dm-crypt device mapper target resides entirely in kernel space, and is only concerned with encryption of the [block device](https://en.wikipedia.org/wiki/Block_device) – it does not interpret any data itself. It relies on [user space](https://en.wikipedia.org/wiki/User_space) [front-ends](https://en.wikipedia.org/wiki/Front_and_back_ends) to create and activate encrypted volumes, and manage authentication. At least two frontends are currently available: `cryptsetup` and `cryptmount`.

::: {#o6 .pointer-item cue=pointer name="Cryptsetup"}

### cryptsetup {#cryptsetup}

The `cryptsetup` command-line interface, by default, does not write any headers to the encrypted volume, and hence only provides the bare essentials: encryption settings have to be provided every time the disk is mounted (although usually employed with automated scripts), and only one [key](wikipedia://en/53039) can be used per volume; the [symmetric encryption](wikipedia://en/53042) key is directly derived from the supplied [passphrase](https://en.wikipedia.org/wiki/Passphrase).

Because it lacks a "[salt](wikipedia://en/701756)", using cryptsetup is less secure in this mode than is the case with [Linux Unified Key Setup](https://en.wikipedia.org/wiki/Linux_Unified_Key_Setup) (LUKS).[^o13] However, the simplicity of cryptsetup makes it useful when combined with third-party software, for example, with [smart card](https://en.wikipedia.org/wiki/Smart_card) authentication.

`cryptsetup` also provides commands to deal with the LUKS on-disk format. This format provides additional features such as [key management](wikipedia://en/631063) and [key stretching](wikipedia://en/4266286) (using [PBKDF2](wikipedia://en/1568244)), and remembers encrypted volume configuration across reboots.[^o20][^o14]

:::

::: {#o16 .pointer-item cue=pointer name="CryptMount"}

### cryptmount {#cryptmount}

The `cryptmount` interface is an alternative to the "cryptsetup" tool that allows any user to [mount](https://en.wikipedia.org/wiki/Mount_%28computing%29) and unmount a dm-crypt file system when needed, without needing [superuser](https://en.wikipedia.org/wiki/Superuser) privileges after the device has been configured by a superuser.

:::

## Features {#Features}

The fact that disk encryption (volume encryption) software like dm-crypt only deals with transparent encryption of abstract [block devices](https://en.wikipedia.org/wiki/Block_device) gives it a lot of flexibility. This means that it can be used for encrypting any disk-backed [file systems](https://en.wikipedia.org/wiki/File_system) supported by the [operating system](https://en.wikipedia.org/wiki/Operating_system), as well as [swap space](https://en.wikipedia.org/wiki/Swap_space); [write barriers](https://en.wikipedia.org/wiki/Write_barrier) implemented by file systems are preserved.[^o18][^o19] Encrypted volumes can be stored on [disk partitions](https://en.wikipedia.org/wiki/Disk_partition), [logical volumes](https://en.wikipedia.org/wiki/Logical_volume), whole disks as well as [file](https://en.wikipedia.org/wiki/Computer_file)-backed [disk images](https://en.wikipedia.org/wiki/Disk_image) (through the use of [loop devices](https://en.wikipedia.org/wiki/Loop_device) with the losetup utility). dm-crypt can also be configured to encrypt [RAID](https://en.wikipedia.org/wiki/RAID) volumes and [LVM](https://en.wikipedia.org/wiki/Logical_volume_management) physical volumes.

dm-crypt can also be configured to provide [pre-boot](https://en.wikipedia.org/wiki/Booting) authentication through an [initrd](https://en.wikipedia.org/wiki/Initrd), thus encrypting all the data on a computer – except the bootloader, the kernel and the initrd image itself.[^o20]

When using the [cipher block chaining](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation#Cipher_Block_Chaining_%28CBC%29) (CBC) mode of operation with predictable [initialization vectors](wikipedia://en/105971) as other disk encryption software, the disk is vulnerable to [watermarking attacks](wikipedia://en/7228413). This means that an attacker is able to detect the presence of specially crafted data on the disk. To address this problem in its predecessors, dm-crypt included provisions for more elaborate, disk encryption-specific modes of operation.[^o2] Support for [ESSIV](https://en.wikipedia.org/wiki/ESSIV) (encrypted salt-sector initialization vector) was introduced in Linux kernel version 2.6.10, [LRW](wikipedia://en/3395256#LRW) in 2.6.20 and [XTS](wikipedia://en/3395256#XTS) in 2.6.24. A [wide-block](wikipedia://en/3395256#narrow_and_wide_block) disk encryption algorithm, [Adiantum](wikipedia://en/59693398), was added in 5.0, and its AES-based cousin HCTR2 in 6.0.

The Linux Crypto API includes support for most popular [block ciphers](wikipedia://en/4594) and [hash functions](https://en.wikipedia.org/wiki/Hash_function), which are all usable with dm-crypt.

Crypted FS support include LUKS (versions 1 and 2) volumes, [loop-AES](https://en.wikipedia.org/wiki/Loop-AES), [TrueCrypt](wikipedia://en/905962)/[VeraCrypt](wikipedia://en/45345491) (since Linux kernel 3.13),[^o21][^o22][^o23] and [BitLocker](https://en.wikipedia.org/wiki/BitLocker)-encrypted NTFS (since cryptsetup 2.3.0).[^o24] TrueCrypt/VeraCrypt (TCRYPT) and BitLocker (BITLK) support require the kernel userspace crypto API.[^o25]

## Compatibility {#Compatibility}

dm-crypt and LUKS encrypted disks can be accessed and used under MS Windows using the now defunct [FreeOTFE](wikipedia://en/4954583) (formerly DoxBox, LibreCrypt), provided that the filesystem used is supported by Windows (e.g. [FAT](https://en.wikipedia.org/wiki/File_Allocation_Table)/FAT32/[NTFS](https://en.wikipedia.org/wiki/NTFS)). Encrypted [ext2](https://en.wikipedia.org/wiki/Ext2) and [ext3](https://en.wikipedia.org/wiki/Ext3) filesystems are supported by using [Ext2Fsd](https://en.wikipedia.org/wiki/Ext2Fsd) or so-called "Ext2 Installable File System for Windows";[^o27] FreeOTFE also supports them.

Cryptsetup/LUKS and the required infrastructure have also been implemented on the DragonFly BSD operating system.[^o28]
