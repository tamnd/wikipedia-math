# Indistinguishability obfuscation

::: {#o1 .subject cue=lead name="Indistinguishability obfuscation"}

In [cryptography](wikipedia://en/18934432), **indistinguishability obfuscation** (abbreviated **IO** or **iO**) is a type of [software obfuscation](https://en.wikipedia.org/wiki/Software_obfuscation) with the defining property that obfuscating any two programs that compute the same [mathematical function](https://en.wikipedia.org/wiki/Mathematical_function) results in programs that cannot be distinguished from each other. Informally, such obfuscation hides the implementation of a program while still allowing users to run it.[^o2] Formally, iO satisfies the property that obfuscations of two circuits of the same size which implement the same function are [computationally indistinguishable](https://en.wikipedia.org/wiki/Computationally_indistinguishable).[^o8]

:::

Indistinguishability obfuscation has several interesting theoretical properties. Firstly, iO is the "best-possible" obfuscation (in the sense that any secret about a program that can be hidden by any obfuscator at all can also be hidden by iO). Secondly, iO can be used to construct nearly the entire gamut of [cryptographic primitives](wikipedia://en/4928985), including both mundane ones such as [public-key cryptography](wikipedia://en/24222) and more exotic ones such as [deniable encryption](wikipedia://en/1055437) and [functional encryption](wikipedia://en/39080703) (which are types of cryptography that no-one previously knew how to construct[^o13]), but with the notable exception of collision-resistant [hash function](https://en.wikipedia.org/wiki/Hash_function) families. For this reason, it has been referred to as "crypto-complete". Lastly, unlike many other kinds of cryptography, indistinguishability obfuscation continues to exist even if [P=NP](https://en.wikipedia.org/wiki/P=NP) (though it would have to be constructed differently in this case), though this does not necessarily imply that iO exists unconditionally.

Though the idea of cryptographic software obfuscation has been around since 1996, indistinguishability obfuscation was first proposed by Barak et al. (2001), who proved that iO exists if P=NP is the case. For the P≠NP case (which is harder, but also more plausible[^o8]), progress was slower: Garg et al. (2013)[^o14] proposed a construction of iO based on a [computational hardness assumption](wikipedia://en/6158383) relating to [multilinear maps](wikipedia://en/221525), but this assumption was later disproven. A construction based on "well-founded assumptions" (hardness assumptions that have been well-studied by cryptographers, and thus widely assumed secure) had to wait until Jain, Lin, and Sahai (2020). (Even so, one of these assumptions used in the 2020 proposal is not secure against [quantum computers](https://en.wikipedia.org/wiki/Quantum_computers).)

Currently known indistinguishability obfuscation candidates are very far from being practical. As measured by a 2017 paper, even obfuscating the [toy function](wikipedia://en/701142) which outputs the [logical conjunction](wikipedia://en/18152) of its thirty-two [Boolean data type](https://en.wikipedia.org/wiki/Boolean_data_type) inputs produces a program nearly a dozen [gigabytes](https://en.wikipedia.org/wiki/Gigabyte) large.

::: {#o4 .definition cue=heading name="Formal definition"}

## Formal definition {#Formal_definition}

Computational indistinguishability Let $\mathcal{iO}$ be some uniform [probabilistic polynomial-time](https://en.wikipedia.org/wiki/Probabilistic_polynomial-time) algorithm. Then $\mathcal{iO}$ is called an *indistinguishability obfuscator* if and only if it satisfies both of the following two statements:[^o15][^o20][^o7]

- **Completeness** or **Functionality**: For any [Boolean circuit](wikipedia://en/7087423) *C* of input length *n* and input $x\in\{0, 1\}^n$, we have $$\Pr[C'(x) = C(x): C' \leftarrow\mathcal{iO}(C) ] = 1.$$
- **Indistinguishability**: For every pair of circuits $C_0, C_1$ of the same size *k* that implement the same functionality, the distributions $\{\mathcal{iO}(C_0)\}$ and $\{\mathcal{iO}(C_1)\}$ are computationally indistinguishable. In other words, for any probabilistic polynomial-time [adversary](wikipedia://en/789126) *A*, there is a negligible function $\varepsilon(k)$ (*i.e.*, a function that eventually grows slower than $1/p(k)$ for any polynomial *p*) such that, for every pair of circuits $C_0, C_1$ of the same size *k* that implement the same functionality, we have $$|\Pr[A(\mathcal{iO}(C_0))=1] - \Pr[A(\mathcal{iO}(C_1))=1]|\leq\varepsilon(k).$$

:::

## History {#History}

In 2001, Barak et al., showing that [black-box obfuscation](wikipedia://en/65807245) is impossible, also proposed the idea of an indistinguishability obfuscator, and constructed an inefficient one.[^o6][^o7][^o8] Although this notion seemed relatively weak, Goldwasser and Rothblum (2007) showed that an efficient indistinguishability obfuscator would be a best-possible obfuscator, and any best-possible obfuscator would be an indistinguishability obfuscator.[^o6][^o9] (However, for *inefficient* obfuscators, no best-possible obfuscator exists unless the [polynomial hierarchy](wikipedia://en/658651) collapses to the second level.[^o9])

An [open-source software](https://en.wikipedia.org/wiki/Open-source_software) implementation of an iO candidate was created in 2015.[^o10]

### Candidate constructions {#Candidate_constructions}

Barak et al. (2001) proved that an *inefficient* indistinguishability obfuscator exists for circuits; that is, the lexicographically first circuit that computes the same function.[^o7] If [P = NP](https://en.wikipedia.org/wiki/P_=_NP) holds, then an indistinguishability obfuscator exists, even though no other kind of cryptography based on Minicrypt assumptions would exist.[^o8]

A candidate construction of iO with [provable security](wikipedia://en/1182348) under concrete [hardness assumptions](wikipedia://en/6158383) relating to [multilinear maps](wikipedia://en/6158383#Multilinear_maps) was published by Garg et al. (2013),[^o8][^o12][^o13] but this assumption was later invalidated.[^o12][^o13] (Previously, Garg, Gentry, and Halevi (2012) had constructed a candidate version of a multilinear map based on heuristic assumptions.[^o14])

Starting from 2016, Lin began to explore constructions of iO based on less strict versions of multilinear maps, constructing a candidate based on maps of degree up to 30, and eventually a candidate based on maps of degree up to 3.[^o13] Finally, in 2020, Jain, Lin, and Sahai proposed a construction of iO based on the [symmetric external Diffie-Hellman](wikipedia://en/1937517), [learning with errors](wikipedia://en/23864530), and [learning plus noise](https://en.wikipedia.org/wiki/Parity_learning#Noisy_version_%28"Learning_Parity_with_Noise"%29) assumptions,[^o13][^o15] as well as the existence of a super-linear stretch [pseudorandom generator](wikipedia://en/1812809) in the function class [NC<sup>0</sup>](wikipedia://en/22073#NC0).[^o15] (The existence of pseudorandom generators in NC<sup>0</sup> (even with sub-linear stretch) was a long-standing open problem until 2006.[^o16]) It is possible that this construction could be broken with [quantum computing](wikipedia://en/25220), but there is an alternative construction that may be secure even against that (although the latter relies on less established security assumptions).[^o13]

### Practicality {#Practicality}

There have been attempts to implement and benchmark iO candidates.[^o8] In 2017, an obfuscation of the function $x_1\wedge x_2\wedge \dots \wedge x_{32}$ at a security level of 80 bits took 23.5 minutes to produce and measured 11.6 GB, with an evaluation time of 77 ms.[^o8] Additionally, an obfuscation of the [Advanced Encryption Standard](wikipedia://en/1260) encryption circuit at a security level of 128 bits would measure 18 PB and have an evaluation time of about 272 years.[^o8]

## Existence {#Existence}

P versus NP problem#P ≠ NP It is useful to divide the question of the existence of iO by using [Russell Impagliazzo](https://en.wikipedia.org/wiki/Russell_Impagliazzo)'s "five worlds",[^o19] which are five different hypothetical situations about [average-case complexity](https://en.wikipedia.org/wiki/Average-case_complexity):[^o20]

- *Algorithmica*: In this case [P = NP](https://en.wikipedia.org/wiki/P_=_NP), but iO exists.
- *Heuristica*: In this case NP problems are easy on average; iO does not exist.
- *Pessiland*: In this case, BPP ≠ NP, but [one-way functions](https://en.wikipedia.org/wiki/One-way_functions) do not exist; as a result, iO does not exist.
- *Minicrypt*: In this case, [one-way functions](https://en.wikipedia.org/wiki/One-way_functions) exist, but secure [public-key cryptography](wikipedia://en/24222) does not; iO does not exist (because explicit constructions of public-key cryptography from iO and one-way functions are known).
- *Cryptomania*: In this case, secure [public-key cryptography](wikipedia://en/24222) exists, but iO does not exist.
- *Obfustopia*:[^o21][^o22] In this case, iO is believed to exist.

## Potential applications {#Potential_applications}

Indistinguishability obfuscators, if they exist, could be used for an enormous range of [cryptographic](wikipedia://en/18934432) applications, so much so that it has been referred to as a "central hub" for cryptography,[^o2][^o13] the "crown jewel of cryptography",[^o13] or "crypto-complete".[^o8] Concretely, an indistinguishability obfuscator (with the additional assumption of the existence of [one-way functions](wikipedia://en/363890)[^o8]) could be used to construct the following kinds of cryptography:

- Indistinguishability obfuscation for programs in the RAM model[^o15] and for [Turing machines](wikipedia://en/30403)[^o24][^o25]
- [IND-CCA](https://en.wikipedia.org/wiki/IND-CCA)-secure [public-key cryptography](wikipedia://en/24222)[^o26]
- Short [digital signatures](wikipedia://en/59644)[^o26]
- [IND-CCA](https://en.wikipedia.org/wiki/IND-CCA)-secure [key encapsulation](https://en.wikipedia.org/wiki/Key_encapsulation) schemes[^o26]
- Perfectly zero-knowledge [non-interactive zero-knowledge proofs](wikipedia://en/11589052) and succinct non-interactive arguments[^o26]
- Constant-round concurrent zero-knowledge protocols[^o15]
- [Multilinear maps](wikipedia://en/221525) with bounded polynomial degrees[^o15]
- [Injective](wikipedia://en/45196) [trapdoor functions](wikipedia://en/206753)[^o26]
- [Fully homomorphic encryption](https://en.wikipedia.org/wiki/Fully_homomorphic_encryption)[^o15]
- [Witness encryption](https://en.wikipedia.org/wiki/Witness_encryption)[^o15][^o8]
- [Functional encryption](wikipedia://en/39080703)[^o8]
- [Secret sharing](wikipedia://en/458253) for any monotone NP language[^o15]
- Semi-honest [oblivious transfer](wikipedia://en/554716)[^o26]
- [Deniable encryption](wikipedia://en/1055437) (both sender-deniable and fully-deniable)[^o26][^o15][^o8]
- Multiparty, non-interactive [key exchange](wikipedia://en/578092)[^o15]
- Adaptively secure succinct garbled RAM[^o15]
- Correlation intractable functions[^o15]
- [Identity-based encryption](wikipedia://en/385892)[^o15]
- [Attribute-based encryption](wikipedia://en/38366406)[^o15]
- [Oblivious transfer](wikipedia://en/554716)[^o8]
- Traitor tracing[^o8]
- Graded encoding schemes[^o8]

Additionally, if iO and one-way functions exist, then problems in the [PPAD](wikipedia://en/9192019) complexity class are provably hard.[^o15][^o27]

However, indistinguishability obfuscation cannot be used to construct *every* possible cryptographic protocol: for example, no black-box construction can convert an indistinguishability obfuscator to a collision-resistant [hash function](https://en.wikipedia.org/wiki/Hash_function) family, even with a [trapdoor permutation](https://en.wikipedia.org/wiki/Trapdoor_permutation), except with an *exponential* loss of security.[^o28]
