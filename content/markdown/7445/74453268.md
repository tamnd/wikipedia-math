# Web Environment Integrity

::: {#o1 .subject cue=lead name="Web Environment Integrity"}

**Web Environment Integrity** (**WEI**) is an abandoned [API](https://en.wikipedia.org/wiki/API) proposal previously under development for [Google Chrome](https://en.wikipedia.org/wiki/Google_Chrome).[^o2] A Web Environment Integrity prototype existed in [Chromium](https://en.wikipedia.org/wiki/Chromium_%28web_browser%29)[^o3][^o4] from May[^o5] to November 2023; it was removed after extensive criticism by many tech groups.[^o6] Its purpose was to verify that interactions with websites were human and authentic as defined by third-party attesters.

:::

## Proposal {#Proposal}

*Image: Web Environment Integrity attestation - How it works.svg.* [Sequence diagram](https://en.wikipedia.org/wiki/Sequence_diagram) showing WEI attestation

The draft proposed an API for websites to get a [digitally signed](wikipedia://en/59644) token that contains the certifier's name and whether or not they deem the web client to be authentic. The stated goal was for sites to be able to restrict access to human users instead of automated programs and "allow web servers to evaluate the authenticity of the device and honest representation of the software stack and the traffic from the device". Access to this API would not be allowed in non-secure ([HTTP](https://en.wikipedia.org/wiki/HTTP)) contexts.[^o8]

## History {#History}

The proposal first showed up as a commit to [Chromium](https://en.wikipedia.org/wiki/Chromium_%28web_browser%29) in April before being announced by its developers, Google engineers, in May. It received a few concerned comments from those who followed the browser's rendering engine's development. After discussion at W3C in late April, its working draft specification was published as part of the process to develop standards for the web on July 21, 2023. As a result, users flooded the proposal's [GitHub](https://en.wikipedia.org/wiki/GitHub) repository with critical comments and [flaming](https://en.wikipedia.org/wiki/Flaming_%28Internet%29) of the proposal's authors. As a result, the Google engineers limited comment to those who have contributed to the repository and added a [code of conduct](https://en.wikipedia.org/wiki/Code_of_conduct).[^o13] On the same day, Chromium's preliminary code to implement the standard was enabled.[^o3]

On November 2, 2023, Google abandoned the proposal, removed the prototype implementation from Chromium, and proposed a replacement API named "Android WebView Media Integrity API" limited to WebViews on Android. Google tested the new API with partners in early 2024.[^o6] As of late 2024, WebView Media Integrity API is available to all developers.[^o10]

## Reception {#Reception}

The proposal received widespread criticism for limiting general purpose computing, with some comparing WEI to [digital rights management](wikipedia://en/18938226) (DRM).[^o12] Others have accused the standard of being evidence of Google abusing Chrome's near-[monopoly](https://en.wikipedia.org/wiki/Monopoly) of browser share.[^o13] Some have issued official statements on the matter in 2023:

- On July 25, [Mozilla](https://en.wikipedia.org/wiki/Mozilla) opposed it, stating "Any browser, server, or publisher that implements common standards is automatically part of [the Web](https://en.wikipedia.org/wiki/The_Web) ... Mechanisms that attempt to restrict these choices are harmful to the openness of the Web ecosystem and are not good for users."[^o14]
- On July 27, [Vivaldi](https://en.wikipedia.org/wiki/Vivaldi_Technologies) opposed it as "simply dangerous" and feared that attestation providers would not be trustworthy.[^o15]
- On July 29, the [Free Software Foundation](https://en.wikipedia.org/wiki/Free_Software_Foundation) opposed it as "an all-out attack on the free Internet" and claimed it would significantly limit the browsers that could be used.[^o16]
- On August 1, [Brave Software](https://en.wikipedia.org/wiki/Brave_%28web_browser%29) announced they will not include WEI in their [web browser](https://en.wikipedia.org/wiki/Web_browser).[^o17]
- On August 7, the [Electronic Frontier Foundation](https://en.wikipedia.org/wiki/Electronic_Frontier_Foundation) opposed it as "a bad idea that Google should not pursue" and opposed its proposal of selecting a "small percentage" of random users to simulate behavior without WEI in order to prevent websites from blocking unattested users. The EFF claimed that "\[m\]any websites will consider that 'small percentage' of users an acceptable price to pay" and feared Google would set the percentage extremely low to combat [ad fraud](https://en.wikipedia.org/wiki/Ad_fraud).[^o18]
- On August 11, the [World Wide Web Consortium](https://en.wikipedia.org/wiki/World_Wide_Web_Consortium) refrained from taking a stance as it was "not being worked on in W3C, nor has there been any submission \[for W3C\] review".[^o19]
