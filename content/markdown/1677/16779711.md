# Advanced Vector Extensions

::: {#o1 .subject cue=lead name="Advanced Vector Extensions"}

X86 Assembly/AVX, AVX2, FMA3, FMA4

**Advanced Vector Extensions** (**AVX**, also known as **Gesher New Instructions** and then **Sandy Bridge New Instructions**) are [SIMD](https://en.wikipedia.org/wiki/Single_instruction,_multiple_data) extensions to the [x86](https://en.wikipedia.org/wiki/X86) [instruction set architecture](https://en.wikipedia.org/wiki/Instruction_set_architecture) for [microprocessors](https://en.wikipedia.org/wiki/Microprocessor) from [Intel](https://en.wikipedia.org/wiki/Intel) and [Advanced Micro Devices](https://en.wikipedia.org/wiki/Advanced_Micro_Devices) (AMD). They were proposed by Intel in March 2008 and first supported by Intel with the [Sandy Bridge](https://en.wikipedia.org/wiki/Sandy_Bridge)[^o2] microarchitecture shipping in Q1 2011 and later by AMD with the [Bulldozer](https://en.wikipedia.org/wiki/Bulldozer_%28microarchitecture%29)[^o3] microarchitecture shipping in Q4 2011. AVX provides new features, new instructions, and a new coding scheme.

:::

**AVX2** (also known as **Haswell New Instructions**) expands most integer commands to 256 bits and introduces new instructions. They were first supported by Intel with the [Haswell](https://en.wikipedia.org/wiki/Haswell_%28microarchitecture%29) microarchitecture, which shipped in 2013.

[AVX-512](https://en.wikipedia.org/wiki/AVX-512) expands AVX to 512-bit support using a new [EVEX prefix](https://en.wikipedia.org/wiki/EVEX_prefix) encoding proposed by Intel in July 2013 and first supported by Intel with the [Knights Landing](https://en.wikipedia.org/wiki/Knights_Landing_%28microarchitecture%29) co-processor, which shipped in 2016.[^o4][^o5] In conventional processors, AVX-512 was introduced with [Skylake](https://en.wikipedia.org/wiki/Skylake_%28microarchitecture%29) server and HEDT processors in 2017.

::: {#o7 .pointer-item cue=pointer name="AVX-128"}

## Advanced Vector Extensions {#Advanced_Vector_Extensions}

AVX uses sixteen YMM registers to perform a single instruction on multiple pieces of data (see [SIMD](https://en.wikipedia.org/wiki/SIMD)). Each YMM register can hold and do simultaneous operations (math) on:

- eight 32-bit single-precision floating-point numbers or
- four 64-bit double-precision floating-point numbers.

The width of the SIMD registers is increased from 128 bits to 256 bits, and renamed from XMM0–XMM7 to YMM0–YMM7 (in [x86-64](https://en.wikipedia.org/wiki/X86-64) mode, from XMM0–XMM15 to YMM0–YMM15). The legacy [SSE](wikipedia://en/55365) instructions can still be utilized via the [VEX prefix](https://en.wikipedia.org/wiki/VEX_prefix) to operate on the lower 128 bits of the YMM registers.

AVX introduces a three-operand SIMD instruction format called [VEX coding scheme](https://en.wikipedia.org/wiki/VEX_coding_scheme), where the destination register is distinct from the two source operands. For example, an [SSE](wikipedia://en/55365) instruction using the conventional two-operand form *a* ← *a* + *b* can now use a non-destructive three-operand form *c* ← *a* + *b*, preserving both source operands. Originally, AVX's three-operand format was limited to the instructions with SIMD operands (YMM), and did not include instructions with general purpose registers (e.g. EAX). It was later used for coding new instructions on general purpose registers in later extensions, such as [BMI](https://en.wikipedia.org/wiki/Bit_manipulation_instruction_set). VEX coding is also used for instructions operating on the k0-k7 mask registers that were introduced with [AVX-512](https://en.wikipedia.org/wiki/AVX-512).

The [alignment](https://en.wikipedia.org/wiki/Data_structure_alignment) requirement of SIMD memory operands is relaxed.[^o9] Unlike their non-VEX coded counterparts, most VEX coded vector instructions no longer require their memory operands to be aligned to the vector size. Notably, the `VMOVDQA` instruction still requires its memory operand to be aligned.

The new [VEX coding scheme](https://en.wikipedia.org/wiki/VEX_coding_scheme) introduces a new set of code prefixes that extends the [opcode](https://en.wikipedia.org/wiki/Opcode) space, allows instructions to have more than two operands, and allows SIMD vector registers to be longer than 128 bits. The VEX prefix can also be used on the legacy SSE instructions giving them a three-operand form, and making them interact more efficiently with AVX instructions without the need for `VZEROUPPER` and `VZEROALL`.

The AVX instructions support both 128-bit and 256-bit SIMD. The 128-bit versions can be useful to improve old code without needing to widen the vectorization, and avoid the penalty of going from SSE to AVX; they are also faster on some early AMD implementations of AVX. This mode is sometimes known as AVX-128.[^o10]

Compared to SSE series, AVX further enhanced performance for [digital media](https://en.wikipedia.org/wiki/Digital_media) playback, [web browsing](https://en.wikipedia.org/wiki/Web_browsing), [asymmetric encryption](https://en.wikipedia.org/wiki/Asymmetric_encryption), and others.

### New instructions {#New_instructions}

These AVX instructions are in addition to the ones that are 256-bit extensions of the legacy 128-bit SSE instructions; most are usable on both 128-bit and 256-bit operands.

::: {#o12 .table cue=table}

| Instruction | Description |
|---|---|
| `VBROADCASTSS`, `VBROADCASTSD`, `VBROADCASTF128` | Copy a 32-bit, 64-bit or 128-bit memory operand to all elements of a XMM or YMM vector register. |
| `VINSERTF128` | Replaces either the lower half or the upper half of a 256-bit YMM register with the value of a 128-bit source operand. The other half of the destination is unchanged. |
| `VEXTRACTF128` | Extracts either the lower half or the upper half of a 256-bit YMM register and copies the value to a 128-bit destination operand. |
| `VMASKMOVPS`, `VMASKMOVPD` | Conditionally reads any number of elements from a SIMD vector memory operand into a destination register, leaving the remaining vector elements unread and setting the corresponding elements in the destination register to zero. Alternatively, conditionally writes any number of elements from a SIMD vector register operand to a vector memory operand, leaving the remaining elements of the memory operand unchanged. On the AMD Jaguar processor architecture, this instruction with a memory source operand takes more than 300 clock cycles when the mask is zero, in which case the instruction should do nothing. This appears to be a design flaw.[^o13] |
| `VPERMILPS`, `VPERMILPD` | Permute In-Lane. Shuffle the 32-bit or 64-bit vector elements of one input operand. These are in-lane 256-bit instructions, meaning that they operate on all 256 bits with two separate 128-bit shuffles, so they can not shuffle across the 128-bit lanes.[^o14] |
| `VPERM2F128` | Shuffle the four 128-bit vector elements of two 256-bit source operands into a 256-bit destination operand, with an immediate constant as selector. |
| `VTESTPS`, `VTESTPD` | Packed bit test of the packed single-precision or double-precision floating-point sign bits, setting or clearing the ZF flag based on AND and CF flag based on ANDN. |
| `VZEROALL` | Set all YMM registers to zero and tag them as unused. Used when switching between 128-bit use and 256-bit use. |
| `VZEROUPPER` | Set the upper half of all YMM registers to zero. Used when switching between 128-bit use and 256-bit use. |

:::

- Other assemblers such as [MASM](https://en.wikipedia.org/wiki/MASM) VS2010 version, [YASM](https://en.wikipedia.org/wiki/YASM),[^o23] [FASM](https://en.wikipedia.org/wiki/FASM) and [JWASM](https://en.wikipedia.org/wiki/JWASM).

### Operating system support {#Operating_system_support}

AVX adds new register-state through the 256-bit wide YMM register file, so explicit [operating system](https://en.wikipedia.org/wiki/Operating_system) support is required to properly save and restore AVX's expanded registers between [context switches](https://en.wikipedia.org/wiki/Context_switch). The following operating system versions support AVX:

- [DragonFly BSD](https://en.wikipedia.org/wiki/DragonFly_BSD): support added in early 2013.
- [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD): support added in a patch submitted on January 21, 2012,[^o25] which was included in the 9.1 stable release.[^o26]
- [Linux](https://en.wikipedia.org/wiki/Linux): supported since kernel version 2.6.30,[^o27] released on June 9, 2009.[^o28]
- [macOS](https://en.wikipedia.org/wiki/MacOS): support added in 10.6.8 ([Snow Leopard](https://en.wikipedia.org/wiki/Mac_OS_X_Snow_Leopard)) update[^o29] released on June 23, 2011. In fact, [macOS Ventura](https://en.wikipedia.org/wiki/MacOS_Ventura) does not support x86 processors without the AVX2 instruction set.[^o30]
- [OpenBSD](https://en.wikipedia.org/wiki/OpenBSD): support added on March 21, 2015.[^o31]
- [Solaris](https://en.wikipedia.org/wiki/Solaris_%28operating_system%29): supported in Solaris 10 Update 10 and Solaris 11.
- [Windows](https://en.wikipedia.org/wiki/Microsoft_Windows): supported since [Windows 7](https://en.wikipedia.org/wiki/Windows_7) SP1 and [Windows Server 2008 R2](https://en.wikipedia.org/wiki/Windows_Server_2008_R2) SP1.[^o32]
  - Windows Server 2008 R2 SP1 with Hyper-V requires a hotfix to support AMD AVX (Opteron 6200 and 4200 series) processors, [KB2568088](http://support.microsoft.com/kb/2568088)
  - [Windows XP](https://en.wikipedia.org/wiki/Windows_XP) and [Windows Server 2003](https://en.wikipedia.org/wiki/Windows_Server_2003) do not support AVX in both kernel drivers and user applications.
  - Support for [AVX-512](https://en.wikipedia.org/wiki/AVX-512) was added in [Windows 10](https://en.wikipedia.org/wiki/Windows_10) and [Windows Server 2016](https://en.wikipedia.org/wiki/Windows_Server_2016).[^o33]

## Advanced Vector Extensions 2 {#Advanced_Vector_Extensions_2}

Advanced Vector Extensions 2 (AVX2), also known as **Haswell New Instructions**,[^o36] is an expansion of the AVX instruction set introduced in Intel's [Haswell microarchitecture](https://en.wikipedia.org/wiki/Haswell_%28microarchitecture%29). AVX2 makes the following additions:

- expansion of most vector integer SSE and AVX instructions to 256 bits
- [Gather](https://en.wikipedia.org/wiki/Gather-scatter_%28vector_addressing%29) support, enabling vector elements to be loaded from non-contiguous memory locations
- [DWORD- and QWORD-granularity](https://en.wikipedia.org/wiki/Word_%28computer_architecture%29#Size_families) any-to-any permutes
- vector shifts.

Sometimes three-operand [fused multiply-accumulate](wikipedia://en/23095212) (FMA3) extension is considered part of AVX2, as it was introduced by Intel in the same processor microarchitecture. This is a separate extension using its own [CPUID](https://en.wikipedia.org/wiki/CPUID) flag, described on [its own page](wikipedia://en/23095212#FMA3_instruction_set) and not below.

## AVX-512 {#AVX-512}

*AVX-512* are 512-bit extensions to the 256-bit Advanced Vector Extensions SIMD instructions for x86 instruction set architecture proposed by [Intel](https://en.wikipedia.org/wiki/Intel_Corporation) in July 2013.[^o4]

AVX-512 instructions are encoded with the new [EVEX prefix](https://en.wikipedia.org/wiki/EVEX_prefix). It allows 4 operands, 8 new 64-bit [opmask registers](https://en.wikipedia.org/wiki/AVX-512#Opmask_registers), scalar memory mode with automatic broadcast, explicit rounding control, and compressed displacement memory [addressing mode](https://en.wikipedia.org/wiki/Addressing_mode). The width of the register file is increased to 512 bits and total register count increased to 32 (registers ZMM0-ZMM31) in x86-64 mode.

AVX-512 consists of multiple instruction subsets, not all of which are meant to be supported by all processors implementing them. The instruction set consists of the following:

- AVX-512 Foundation (F) – adds several new instructions and expands most 32- and 64-bit floating-point SSE-SSE4.1 and AVX/AVX2 instructions with [EVEX coding scheme](https://en.wikipedia.org/wiki/EVEX_prefix) to support the 512-bit registers, operation masks, parameter broadcasting, and embedded rounding and exception control
- AVX-512 Conflict Detection Instructions (CD) – efficient conflict detection to allow more loops to be vectorized, supported by Knights Landing[^o4]
- AVX-512 Exponential and Reciprocal Instructions (ER) – exponential and reciprocal operations designed to help implement transcendental operations, supported by Knights Landing[^o4]
- AVX-512 Prefetch Instructions (PF) – new prefetch capabilities, supported by Knights Landing[^o4]
- AVX-512 Vector Length Extensions (VL) – extends most AVX-512 operations to also operate on XMM (128-bit) and YMM (256-bit) registers (including XMM16-XMM31 and YMM16-YMM31 in x86-64 mode)[^o41]
- AVX-512 Byte and Word Instructions (BW) – extends AVX-512 to cover 8-bit and 16-bit integer operations[^o41]
- AVX-512 Doubleword and Quadword Instructions (DQ) – enhanced 32-bit and 64-bit integer operations[^o41]
- AVX-512 Integer [Fused Multiply Add](https://en.wikipedia.org/wiki/Fused_Multiply_Add) (IFMA) – fused multiply add for 512-bit integers.[^o42]
- AVX-512 Vector Byte Manipulation Instructions (VBMI) adds vector byte permutation instructions which are not present in AVX-512BW.
- AVX-512 Vector Neural Network Instructions Word variable precision (4VNNIW) – vector instructions for deep learning.
- AVX-512 Fused Multiply Accumulation Packed Single precision (4FMAPS) – vector instructions for deep learning.
- VPOPCNTDQ – count of bits set to 1.[^o43]
- VPCLMULQDQ – carry-less multiplication of quadwords.[^o43]
- AVX-512 Vector Neural Network Instructions (VNNI) – vector instructions for deep learning.[^o43]
- AVX-512 Galois Field New Instructions (GFNI) – vector instructions for calculating [Galois field](https://en.wikipedia.org/wiki/Galois_field).[^o43]
- AVX-512 Vector AES instructions (VAES) – vector instructions for [AES](wikipedia://en/1260) coding.[^o43]
- AVX-512 Vector Byte Manipulation Instructions 2 (VBMI2) – byte/word load, store and concatenation with shift.[^o43]
- AVX-512 Bit Algorithms (BITALG) – byte/word [bit manipulation](https://en.wikipedia.org/wiki/Bit_manipulation) instructions expanding VPOPCNTDQ.[^o43]
- AVX-512 [Bfloat16](https://en.wikipedia.org/wiki/Bfloat16_floating-point_format) Floating-Point Instructions (BF16) – vector instructions for AI acceleration.
- AVX-512 [Half-Precision](https://en.wikipedia.org/wiki/Half-precision_floating-point_format) Floating-Point Instructions (FP16) – vector instructions for operating on floating-point and complex numbers with reduced precision.
- AVX-512 Bit Manipulation Instructions (BMM) – bit matrix multiply and bit reversal instructions.

Only the core extension AVX-512F (AVX-512 Foundation) is required by all implementations, though all current implementations also support CD (conflict detection). All central processors with AVX-512 also support VL, DQ and BW. The ER, PF, 4VNNIW and 4FMAPS instruction set extensions are currently only implemented in Intel computing coprocessors.

The updated SSE/AVX instructions in AVX-512F use the same mnemonics as AVX versions; they can operate on 512-bit ZMM registers, and will also support 128/256 bit XMM/YMM registers (with AVX-512VL) and byte, word, doubleword and quadword integer operands (with AVX-512BW/DQ and VBMI).[^o42]

Discontinued subsets include:

- AVX-512 Vector Pair Intersection to a Pair of Mask Registers (VP2INTERSECT) – Compute intersection between doublewords/quadwords to a pair of mask registers. [Discontinued by Intel](https://en.wikipedia.org/wiki/List_of_discontinued_x86_instructions#VP2Intersect_instructions), but still supported by AMD.
- Xeon Phi ER, PF, 4FMAPS, 4VNNIW.

## AVX-VNNI, AVX-IFMA {#AVX-VNNI,_AVX-IFMA}

AVX-VNNI is a [VEX](https://en.wikipedia.org/wiki/VEX_prefix)-coded variant of the [AVX512-VNNI](https://en.wikipedia.org/wiki/AVX-512#VNNI) instruction set extension. Similarly, AVX-IFMA is a [VEX](https://en.wikipedia.org/wiki/VEX_prefix)-coded variant of [AVX512-IFMA](https://en.wikipedia.org/wiki/AVX-512#IFMA). These extensions provide the same sets of operations as their AVX-512 counterparts, but are limited to 256-bit vectors and do not support any additional features of [EVEX](https://en.wikipedia.org/wiki/EVEX_prefix) encoding, such as broadcasting, opmask registers or accessing more than 16 vector registers. These extensions allow for supporting VNNI and IFMA operations even when [AVX-512](https://en.wikipedia.org/wiki/AVX-512) is not implemented in the processor.

## AVX-NE-CONVERT {#AVX-NE-CONVERT}

AVX-NE-CONVERT introduces a set of instructions for converting between [Bfloat16](https://en.wikipedia.org/wiki/Bfloat16_floating-point_format) (BF16), [half-precision](https://en.wikipedia.org/wiki/Half-precision_floating-point_format) (FP16) and [single-precision](https://en.wikipedia.org/wiki/Single-precision_floating-point_format) (FP32) floating-point numbers. The new instructions are [VEX](https://en.wikipedia.org/wiki/VEX_prefix)-coded, and therefore are limited to AVX2 vector registers and lack opmask support from AVX-512. Broadcast is only supported by means of two special instructions for loading numbers from memory, it is not supported as an instruction encoding feature.

### New instructions {#New_instructions}

::: {#o78 .table cue=table}

| Instruction | Description |
|---|---|
| `VBCSTNEBF162PS` | Loads one BF16 element from memory, converts it to FP32, and broadcasts it to a vector register. |
| `VBCSTNESH2PS` | Loads one FP16 element from memory, converts it to FP32, and broadcasts it to a vector register. |
| `VCVTNEEBF162PS`, `VCVTNEOBF162PS` | Loads packed BF16 elements from memory, converts the even (for `VCVTNEEBF162PS`) or odd (for `VCVTNEOBF162PS`) elements to FP32, and writes the result to the destination vector register. |
| `VCVTNEEPH2PS`, `VCVTNEOPH2PS` | Loads packed FP16 elements from memory, converts the even (for `VCVTNEEPH2PS`) or odd (for `VCVTNEOPH2PS`) elements to FP32, and writes the result to the destination vector register. |
| `VCVTNEPS2BF16` | Loads packed FP32 elements from a vector register or memory, converts the elements to BF16, and writes the result to the destination vector register. The upper bits of the destination vector register are zeroed. |

:::

## AVX-VNNI-INT8, AVX-VNNI-INT16 {#AVX-VNNI-INT8,_AVX-VNNI-INT16}

These instruction sets further extend the [AVX-VNNI](https://en.wikipedia.org/wiki/AVX-VNNI) extension by adding support for more combinations of input data types for the `VPDP*` series of instructions. Where `VPDPBUSD(S)` instructions from [AVX-VNNI](https://en.wikipedia.org/wiki/AVX-VNNI) take a vector of unsigned bytes as the first input operand and a vector of signed bytes as the second input operand, AVX-VNNI-INT8 adds variants of these instructions that support signed and unsigned byte inputs at any position. Similarly, where `VPDPWSSD(S)` from [AVX-VNNI](https://en.wikipedia.org/wiki/AVX-VNNI) take two vectors of signed 16-bit words as input operands, AVX-VNNI-INT16 adds support for signed and unsigned 16-bit word inputs at any position.

For the instructions accepting signed and unsigned inputs, there are distinct instructions for the two possible orders of inputs (signed/unsigned and unsigned/signed) because [VEX](https://en.wikipedia.org/wiki/VEX_prefix) encoding only supports the second input operand to be a memory operand. This allows any of the supported data types to be loaded from memory by the instruction.

### New instructions in AVX-VNNI-INT8 {#New_instructions_in_AVX-VNNI-INT8}

::: {#o82 .table cue=table}

| Instruction | Description |
|---|---|
| `VPDPBSSD`, `VPDPBSSDS` | Multiply groups of 4 pairs of signed bytes in the second input with corresponding signed bytes of the first input, summing those products and adding them to the doubleword result in the output. `VPDPBSSDS` performs signed saturation of the result. |
| `VPDPBSUD`, `VPDPBSUDS` | Multiply groups of 4 pairs of unsigned bytes in the second input with corresponding signed bytes of the first input, summing those products and adding them to the doubleword result in the output. `VPDPBSUDS` performs signed saturation of the result. |
| `VPDPBUUD`, `VPDPBUUDS` | Multiply groups of 4 pairs of unsigned bytes in the second input with corresponding unsigned bytes of the first input, summing those products and adding them to the doubleword result in the output. `VPDPBUUDS` performs signed saturation of the result. |

:::

## AVX10 {#AVX10}

AVX10, announced in July 2023,[^o89] is a new, "converged" AVX instruction set. It addresses several issues of AVX-512; in particular, that it is split into too many parts[^o90] (20 feature flags). The initial technical paper also made 512-bit vectors optional to support, but as of revision 3.0, vector length enumeration is removed and 512-bit vectors are mandatory.[^o91]

AVX10 presents a simplified CPUID interface to test for instruction support, consisting of the AVX10 version number (indicating the set of instructions supported, with later versions always being a superset of an earlier one).[^o92] For example, AVX10.2 indicates that a CPU is capable of the second version of AVX10.[^o93] Initial revisions of the AVX10 technical specifications also included maximum supported vector length as part of the ISA extension name, e.g. AVX10.2/256 would mean a second version of AVX10 with vector length up to 256 bits, but later revisions made that unnecessary.

The first version of AVX10, notated AVX10.1, does *not* introduce any instructions or encoding features beyond what is already in AVX-512 (specifically, in Intel [Sapphire Rapids](https://en.wikipedia.org/wiki/Sapphire_Rapids): AVX-512F, CD, VL, DQ, BW, IFMA, VBMI, VBMI2, BITALG, VNNI, GFNI, VPOPCNTDQ, VPCLMULQDQ, VAES, BF16, FP16). For CPUs supporting AVX10 and 512-bit vectors, all legacy AVX-512 feature flags will remain set to facilitate applications supporting AVX-512 to continue using AVX-512 instructions.[^o93]

AVX10.1 was first released in Intel [Granite Rapids](https://en.wikipedia.org/wiki/Granite_Rapids)[^o93] (Q3 2024) and AVX10.2 will be available in [Diamond Rapids](https://en.wikipedia.org/wiki/Diamond_Rapids)[^o94] and [Nova Lake](https://en.wikipedia.org/wiki/Nova_Lake).[^o95]

## Downclocking {#Downclocking}

Since AVX instructions are wider, they consume more power and generate more heat. Executing heavy AVX instructions at high CPU clock frequencies may affect CPU stability due to excessive [voltage droop](https://en.wikipedia.org/wiki/Voltage_droop) during load transients. Some Intel processors have provisions to reduce the [Turbo Boost](https://en.wikipedia.org/wiki/Intel_Turbo_Boost) frequency limit when such instructions are being executed. This reduction happens even if the CPU hasn't reached its thermal and power consumption limits.

On [Skylake](https://en.wikipedia.org/wiki/Skylake_%28microarchitecture%29) and its derivatives, the throttling is divided into three levels:[^o121][^o122]

- L0 (100%): The normal turbo boost limit.
- L1 (~85%): The "AVX boost" limit. Soft-triggered by 256-bit "heavy" (floating-point unit: FP math and integer multiplication) instructions. Hard-triggered by "light" (all other) 512-bit instructions.
- L2 (~60%): The "AVX-512 boost" limit. Soft-triggered by 512-bit heavy instructions.

The frequency transition can be soft or hard. Hard transition means the frequency is reduced as soon as such an instruction is spotted; soft transition means that the frequency is reduced only after reaching a threshold number of matching instructions. The limit is per-thread.[^o121]

In [Ice Lake](https://en.wikipedia.org/wiki/Ice_Lake_%28microarchitecture%29), only two levels persist:[^o123]

- L0 (100%): The normal turbo boost limit.
- L1 (~97%): Triggered by any 512-bit instructions, but only when single-core boost is active; not triggered when multiple cores are loaded.

[Rocket Lake](https://en.wikipedia.org/wiki/Rocket_Lake) processors do not trigger frequency reduction upon executing any kind of vector instructions regardless of the vector size.[^o123] However, downclocking can still happen due to other reasons, such as reaching thermal and power limits.

Downclocking means that using AVX in a mixed workload with an Intel processor can incur a frequency penalty. Avoiding the use of wide and heavy instructions help minimize the impact in these cases. AVX-512VL allows for using 256-bit or 128-bit operands in AVX-512 instructions, making it a sensible default for mixed loads.[^o124]

On supported and unlocked variants of processors that down-clock, the clock ratio reduction offsets (typically called AVX and AVX-512 offsets) are adjustable and may be turned off entirely (set to 0x) via Intel's Overclocking / Tuning utility or in BIOS if supported there.[^o125]
