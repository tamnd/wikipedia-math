# Polynomial evaluation

::: {#o1 .subject cue=lead name="Polynomial evaluation"}

In [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), **polynomial evaluation** refers to computation of the value of a [polynomial](wikipedia://en/23000) when its [indeterminates](https://en.wikipedia.org/wiki/Indeterminate_%28variable%29) are substituted for some values. In other words, evaluating the polynomial $P(x_1, x_2) = 2x_1x_2 + x_1^3 + 4$ at $x_1=2, x_2=3$ consists of computing $P(2,3)= 2\cdot 2\cdot 3 + 2^3+4=24.$ See also Polynomial ring

:::

For evaluating the [univariate polynomial](https://en.wikipedia.org/wiki/Univariate_polynomial) $a_nx^n+a_{n-1}x^{n-1}+\cdots +a_0,$ the most naive method would use $n$ multiplications to compute $a_n x^n$, use $n-1$ multiplications to compute $a_{n-1} x^{n-1}$ and so on for a total of $\tfrac{n(n+1)}{2}$ multiplications and $n$ additions. Using better methods, such as [Horner's rule](https://en.wikipedia.org/wiki/Horner's_rule), this can be reduced to $n$ multiplications and $n$ additions. If some preprocessing is allowed, even more savings are possible.

## Background {#Background}

This problem arises frequently in practice. In [computational geometry](wikipedia://en/176927), polynomials are used to compute function approximations using [Taylor polynomials](https://en.wikipedia.org/wiki/Taylor_polynomials). In [cryptography](wikipedia://en/18934432) and [hash tables](wikipedia://en/13833), polynomials are used to compute [*k*-independent hashing](https://en.wikipedia.org/wiki/K-independent_hashing).

In the former case, polynomials are evaluated using [floating-point arithmetic](wikipedia://en/11376), which is [not exact](https://en.wikipedia.org/wiki/Floating_point_error). Thus different schemes for the evaluation will, in general, give slightly different answers. In the latter case, the polynomials are usually evaluated in a [finite field](wikipedia://en/11615), in which case the answers are always exact.

## General methods {#General_methods}

### Horner's rule {#Horner's_rule}

Horner's method evaluates a polynomial using repeated bracketing:

$$\begin{aligned} a_0 + &a_1x + a_2x^2 + a_3x^3 + \cdots + a_nx^n \\ &= a_0 + x \bigg(a_1 + x \Big(a_2 + x \big(a_3 + \cdots + x(a_{n-1} + x\,a_n) \cdots \big) \Big) \bigg). \end{aligned}$$

This method reduces the number of multiplications and additions to just $n$

Horner's method is so common that the "[multiply–accumulate operation](https://en.wikipedia.org/wiki/Multiply–accumulate_operation)" is included within the [instruction set](https://en.wikipedia.org/wiki/CPU_instruction_set) of many computer processors, which allows for the addition and multiplication operations to be performed in one combined step.

#### Multivariate {#Multivariate}

If the polynomial is multivariate, Horner's rule can be applied recursively over some ordering of the variables. E.g.

$$P(x, y) = 4 + x + 2 x y + 2 x^2 y + x^2 y^2$$

can be written as

$$\begin{aligned} P(x, y) &= 4 + x (1 + y(2) + x (y(2 + y))) \quad\text{or}\\ P(x, y) &= 4 + x + y(x(2 + x(2)) + y(x^2)). \end{aligned}$$

An efficient version of this approach was described by Carnicer and Gasca.[^o6]

#### Estrin's scheme {#Estrin's_scheme}

While it's not possible to do less computation than Horner's rule (without preprocessing), on modern computers the order of evaluation can matter a lot for the computational efficiency. A method known as [Estrin's scheme](wikipedia://en/13542806) computes a (single variate) polynomial in a tree like pattern:

$$\begin{aligned} P(x) = (a_0 + a_1 x) + (a_2 + a_3 x) x^2 + ((a_4 + a_5 x) + (a_6 + a_7 x) x^2)x^4. \end{aligned}$$

Combined by [exponentiation by squaring](wikipedia://en/10237), this allows parallelizing the computation. A similar idea[^o8] enables to involve [fast matrix multiplication algorithms](wikipedia://en/24107400) to evaluate a polynomial in a series of points.

### Evaluation with preprocessing {#Evaluation_with_preprocessing}

Arbitrary polynomials can be evaluated with fewer operations than Horner's rule requires if we first "preprocess" the coefficients $a_n, \dots, a_0$.

An example was first given by Motzkin[^o10] who noted that

$$P(x)=x^4 + a_3 x^3 + a_2 x^2 + a_1 x + a_0$$

can be written as

$$y = (x+\beta_0)x+\beta_1,\quad P(x)=(y+x+\beta_2)y+\beta_3,$$

where the values $\beta_0, \dots, \beta_3$ are computed in advance, based on $a_0, \dots, a_3$. Motzkin's method uses just 3 multiplications compared to Horner's 4.

The values for each $\beta_i$ can be easily computed by expanding $P(x)$ and equating the coefficients:

$$\begin{aligned} \beta_0&=\tfrac12(a_3-1),\quad &z&=a_2-\beta_0(\beta_0+1),\quad &\beta_1&=a_1-\beta_0 z,\\ \beta_2&=z-2\beta_1, \quad &\beta_3&=a_0-\beta_1(\beta_1+\beta_2).\end{aligned}$$

::: {#o12 .example cue=heading name="Example"}

#### Example {#Example}

To compute the [Taylor expansion](https://en.wikipedia.org/wiki/Taylor_expansion) $\exp(x) \approx 1+x+x^2/2+x^3/6+x^4/24$, we can upscale by a factor 24, apply the above steps, and scale back down. That gives us the three multiplication computation

$$y = (x+1.5)x+11.625,\quad P(x)=(y+x-15)y/24+2.63477.$$

Improving over the equivalent Horner form (that is $P(x) = 1 + x (1 + x (1/2 + x(1/6 + x/24)))$) by 1 multiplication.

Some general methods include the [Knuth–Eve algorithm](wikipedia://en/80523191) and the [Rabin–Winograd algorithm](https://en.wikipedia.org/wiki/Rabin–Winograd_algorithm). [^o13]

:::

### Multipoint evaluation {#Multipoint_evaluation}

Evaluation of a degree-n polynomial $P(x)$ at multiple points $x_1, \dots, x_m$ can be done with $mn$ multiplications by using [Horner's method](wikipedia://en/14263) $m$ times. Using the above preprocessing approach, this can be reduced by a factor of two; that is, to $mn/2$ multiplications.

However, it is possible to do better and reduce the time requirement to just $O\big((n + m) \log^2(n + m)\big)$.[^o15] The idea is to define two polynomials that are zero in respectively the first and second half of the points: $m_0(x)=(x-x_1)\cdots(x-x_{n/2})$ and $m_1(x)=(x-x_{n/2+1})\cdots(x-x_{n})$. We then compute $R_0 = P \bmod m_0$ and $R_1 = P \bmod m_1$ using the [Polynomial remainder theorem](https://en.wikipedia.org/wiki/Polynomial_division), which can be done in $O(n\log n)$ time using a [fast Fourier transform](wikipedia://en/11512). This means $P(x) = Q_0(x)m_0(x) + R_0(x)$ and $P(x) = Q_1(x)m_1(x) + R_1(x)$ by construction, where $R_0$ and $R_1$ are polynomials of degree at most $n/2$. Because of how $m_0$ and $m_1$ were defined, we have

$$\begin{aligned} R_0(x_i) &= P(x_i) \quad\text{for } i \le n/2 \quad\text{and}\\ R_1(x_i) &= P(x_i) \quad\text{for } i > n/2. \end{aligned}$$

Thus to compute $P$ on all $n$ of the $x_i$, it suffices to compute the smaller polynomials $R_0$ and $R_1$ on each half of the points. This gives us a [divide-and-conquer algorithm](wikipedia://en/201154) with $T(n) = 2T(n/2) + n\log n$, which implies $T(n)=O(n(\log n)^2)$ by the [master theorem](wikipedia://en/561585).

In the case where the points in which we wish to evaluate the polynomials have some structure, simpler methods exist. For example, Knuth[^o16] section 4.6.4 gives a method for tabulating polynomial values of the type

$$P(x_0 + h), P(x_0 + 2h), \dots.$$

### Dynamic evaluation {#Dynamic_evaluation}

In the case where $x_1, \dots, x_m$ are not known in advance, Kedlaya and Umans[^o18] gave a [data structure](wikipedia://en/8519) for evaluating polynomials over a [finite field](wikipedia://en/11615) of size $F_q$ in time $(\log n)^{O(1)}(\log_2 q)^{1+o(1)}$ per evaluation after some initial preprocessing. This was shown by [Larsen](https://en.wikipedia.org/wiki/Kasper_Green_Larsen)[^o19] to be essentially optimal.

The idea is to transform $P(x)$ of degree $n$ into a [multivariate polynomial](https://en.wikipedia.org/wiki/Multivariate_polynomial) $f(x_1, x_2, \dots, x_m)$, such that $P(x) = f(x, x^d, x^{d^2}, \dots, x^{d^m})$ and the individual degrees of $f$ is at most $d$. Since this is over $\bmod q$, the largest value $f$ can take (over $\mathbb Z$) is $M = d^m (q-1)^{dm}$. Using the [Chinese remainder theorem](wikipedia://en/7713), it suffices to evaluate $f$ modulo different primes $p_1, \dots, p_\ell$ with a product at least $M$. Each prime can be taken to be roughly $\log M = O(dm\log q)$, and the number of primes needed, $\ell$, is roughly the same. Doing this process recursively, we can get the primes as small as $\log\log q$. That means we can compute and store $f$ on all the possible values in $T = (\log\log q)^m$ time and space. If we take $d = \log q$, we get $m = \tfrac{\log n}{\log\log q}$, so the time/space requirement is $n^\frac{\log\log q}{\log\log\log q}.$

Kedlaya and Umans further show how to combine this preprocessing with fast multipoint evaluation using the fast Fourier transform. This allows optimal algorithms for many important algebraic problems, such as polynomial [modular composition](https://en.wikipedia.org/wiki/Modular_composition).

## Specific polynomials {#Specific_polynomials}

While general polynomials require $\Omega(n)$ operations to evaluate, some polynomials can be computed much faster. For example, the polynomial $P(x)=x^2+2x+1$ can be computed using just one multiplication and one addition since $P(x)=(x+1)^2$.

### Evaluation of powers {#Evaluation_of_powers}

A particularly interesting type of polynomial is powers like $x^n$. Such polynomials can always be computed in $O(\log n)$ operations. Suppose, for example, that we need to compute $x^{16}$; we could simply start with $x$ and multiply by $x$ to get $x^2$. We can then multiply that by itself to get $x^4$ and so on to get $x^8$ and $x^{16}$ in just four multiplications. Other powers like $x^5$ can similarly be computed efficiently by first computing $x^4$ by 2 multiplications and then multiplying by $x$.

The most efficient way to compute a given power $x^n$ is provided by [addition-chain exponentiation](wikipedia://en/856356). However, this requires designing a specific algorithm for each exponent, and the computation needed for designing these algorithms are difficult ([NP-complete](https://en.wikipedia.org/wiki/NP-complete)[^o22]), so exponentiation by squaring is generally preferred for effective computations.

### Polynomial families {#Polynomial_families}

Often polynomials show up in a different form than the well known $a_n x^n + \dots + a_1 x + a_0$. For polynomials in [Chebyshev form](https://en.wikipedia.org/wiki/Chebyshev_form) we can use [Clenshaw algorithm](wikipedia://en/906703). For polynomials in [Bézier form](https://en.wikipedia.org/wiki/Bézier_form) we can use [De Casteljau's algorithm](wikipedia://en/656099), and for [B-splines](wikipedia://en/21834) there is [De Boor's algorithm](wikipedia://en/475385).

### Hard polynomials {#Hard_polynomials}

The fact that some polynomials can be computed significantly faster than "general polynomials" suggests the question: Can we give an example of a simple polynomial that cannot be computed in time much smaller than its degree? [Volker Strassen](wikipedia://en/771960) has shown[^o25] that the polynomial

$$P(x)=\sum_{k=0}^n 2^{2^{kn^3}}x^k$$

cannot be evaluated with less than $\tfrac12 n - 2$ multiplications and $n - 4$ additions. At least this bound holds if only operations of those types are allowed, giving rise to a so-called "polynomial chain of length $<n^2/\log n$".

The polynomial given by Strassen has very large coefficients, but by probabilistic methods, one can show there must exist even polynomials with coefficients just 0's and 1's such that the evaluation requires at least $\Omega(n/\log n)$ multiplications.[^o26]

For other simple polynomials, the complexity is unknown. The polynomial $(x+1)(x+2)\cdots(x+n)$ is conjectured to not be computable in time $(\log n)^{c}$ for any $c$. This is supported by the fact that, if it can be computed fast, then [integer factorization](wikipedia://en/15491) can be computed in polynomial time, breaking the [RSA cryptosystem](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29).[^o27]

## Matrix polynomials {#Matrix_polynomials}

Sometimes the computational cost of scalar multiplications (like $ax$) is less than the computational cost of "non scalar" multiplications (like $x^2$). The typical example of this is matrices. If $M$ is an $m\times m$ matrix, a [scalar multiplication](wikipedia://en/244373) $aM$ takes about $m^2$ arithmetic operations, while computing $M^2$ takes about $m^3$ (or $m^{2.3}$ using [fast matrix multiplication](https://en.wikipedia.org/wiki/Fast_matrix_multiplication)).

Matrix polynomials are used, for example, for [computing matrix exponentials](wikipedia://en/672731#Computing_the_matrix_exponential).

Paterson and Stockmeyer[^o29] showed how to compute a degree $n$ polynomial using only $O(\sqrt n)$ non scalar multiplications and $O(n)$ scalar multiplications. Thus a [matrix polynomial](wikipedia://en/15663294) of degree $n$ can be evaluated in $O(m^\alpha\sqrt{n} + m^2n)$ time, where $m^\alpha$ is the time needed for multiplying two $m\times m$ matices. If $m=n$ this is $O(n^\beta),$ where $\beta=3.5$ or $\beta=3$ deprending whether usual or fast matrix multiplication is used. This is to be compared to the usual [Horner method](https://en.wikipedia.org/wiki/Horner_method), which gives $\beta=4$ or $\beta=3.3$ respectively.

This method works as follows: For a polynomial

$$P(M)=a_{n-1} M^{n-1} + \dots + a_{1}M + a_0 I,$$

let $k$ be the least integer not smaller than $\sqrt{n}.$ The powers $M, M^2, \dots, M^k$ are computed with $k$ matrix multiplications, and $M^{2k}, M^{3k}, \dots, M^{k^2-k}$ are then computed by repeated multiplication by $M^k.$ Now,

$$\begin{aligned}P(M) = &\,(a_0 I + a_1 M + \dots + a_{k-1}M^{k-1}) \\+&\,(a_k I + a_{k+1} M + \dots + a_{2k-1}M^{k-1})M^k \\+&\,\dots \\+&\,(a_{n-k} I + a_{n-k+1} M + \dots + a_{n-1}M^{k-1})M^{k^2-k}, \end{aligned},$$

where $a_i=0$ for $i \ge n$. This requires just $k$ more non-scalar multiplications.

The direct application of this method uses $2\sqrt{n}$ non-scalar multiplications, but combining it with [Evaluation with preprocessing](wikipedia://en/64691694#Evaluation_with_preprocessing), Paterson and Stockmeyer show you can reduce this to $\sqrt{2n}$.

Methods based on matrix polynomial multiplications and additions have been proposed allowing to save nonscalar matrix multiplications with respect to the Paterson-Stockmeyer method.[^o30]
