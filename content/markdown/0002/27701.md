# String (computer science)

*Image: String example.svg.* Strings are typically made up of [characters](https://en.wikipedia.org/wiki/Character_%28computing%29), and are often used to store human-readable data, such as words or sentences.

::: {#o1 .subject cue=lead name="String"}

In [computer programming](https://en.wikipedia.org/wiki/Computer_programming), a **string** is traditionally a [sequence](wikipedia://en/27838) of [characters](https://en.wikipedia.org/wiki/Character_%28computing%29), either as a [literal constant](https://en.wikipedia.org/wiki/Literal_%28computer_programming%29) or as some kind of [variable](https://en.wikipedia.org/wiki/Variable_%28computer_science%29). The latter may allow its elements to be [mutated](https://en.wikipedia.org/wiki/Immutable_object) and the length changed, or it may be fixed (after creation). A string is often implemented as an [array data structure](https://en.wikipedia.org/wiki/Array_data_structure) of [bytes](https://en.wikipedia.org/wiki/Byte) (or [words](https://en.wikipedia.org/wiki/Word_%28computer_architecture%29)) that stores a sequence of elements, typically characters, using some [character encoding](https://en.wikipedia.org/wiki/Character_encoding). More general, *string* may also denote a sequence (or [list](https://en.wikipedia.org/wiki/List_%28abstract_data_type%29)) of data other than just characters.

:::

Depending on the programming language and precise data type used, a [variable](https://en.wikipedia.org/wiki/Variable_%28programming%29) declared to be a string may either cause storage in memory to be statically allocated for a predetermined maximum length or employ [dynamic allocation](https://en.wikipedia.org/wiki/Dynamic_allocation) to allow it to hold a variable number of elements.

When a string appears literally in [source code](https://en.wikipedia.org/wiki/Source_code), it is known as a [string literal](https://en.wikipedia.org/wiki/String_literal) or an anonymous string.[^o2]

In [formal languages](wikipedia://en/10939), which are used in [mathematical logic](wikipedia://en/19636) and [theoretical computer science](wikipedia://en/323392), a string is a finite sequence of [symbols](wikipedia://en/24028642) that are chosen from a [set](wikipedia://en/26691) called an [alphabet](https://en.wikipedia.org/wiki/Alphabet_%28computer_science%29).

## Purpose {#Purpose}

A primary purpose of strings is to store human-readable text, like words and sentences. Strings are used to communicate information from a computer program to the user of the program.[^o4] A program may also accept string input from its user. Further, strings may store data expressed as characters yet not intended for human reading.

Example strings and their purposes:

- A message like "`file upload complete`" is a string that software shows to [end users](https://en.wikipedia.org/wiki/End_user). In the program's [source code](https://en.wikipedia.org/wiki/Source_code), this message would likely appear as a [string literal](https://en.wikipedia.org/wiki/String_literal).
- User-entered text, like "`I got a new job today`" as a status update on a [social media](https://en.wikipedia.org/wiki/Social_media) service. Instead of a string literal, the software would likely store this string in a [database](https://en.wikipedia.org/wiki/Database).
- Alphabetical data, like "`AGATGCCGT`" representing nucleic acid sequences of [DNA](https://en.wikipedia.org/wiki/DNA).[^o5]
- Computer settings or parameters, like "`?action=edit`" as a URL [query string](https://en.wikipedia.org/wiki/Query_string). Often these are intended to be somewhat human-readable, though their primary purpose is to communicate to computers.

The term string may also designate a sequence of data or computer records other than characters, like a "string of [bits](https://en.wikipedia.org/wiki/Bit)", but when used without qualification it refers to strings of characters.[^o11]

## History {#History}

Use of the word "string" to mean any items arranged in a line, series or succession dates back centuries.[^o7][^o8] In 19th-century typesetting, [compositors](https://en.wikipedia.org/wiki/Compositor_%28typesetting%29) used the term "string" to denote a length of type printed on paper; the string would be measured to determine the compositor's pay.[^o9][^o11][^o10]

Use of the word "string" to mean "a sequence of symbols or linguistic elements in a definite order" emerged from mathematics, [symbolic logic](https://en.wikipedia.org/wiki/Symbolic_logic), and [linguistic theory](https://en.wikipedia.org/wiki/Linguistic_theory) to speak about the [formal](wikipedia://en/396102) behavior of symbolic systems, setting aside the symbols' meaning.[^o11]

For example, logician [C. I. Lewis](wikipedia://en/433707) wrote in 1918:[^o12]

> A mathematical system is any set of strings of recognisable marks in which some of the strings are taken initially and the remainder derived from these by operations performed according to rules which are independent of any meaning assigned to the marks. That a system should consist of 'marks' instead of sounds or odours is immaterial.

According to [Jean E. Sammet](https://en.wikipedia.org/wiki/Jean_E._Sammet), "the first realistic string handling and pattern matching language" for computers was [COMIT](https://en.wikipedia.org/wiki/COMIT) in the 1950s, followed by the [SNOBOL](https://en.wikipedia.org/wiki/SNOBOL) language of the early 1960s.[^o13]

## String datatypes {#String_datatypes}

A **string datatype** is a datatype modeled on the idea of a formal string. Strings are such an important and useful datatype that they are implemented in nearly every [programming language](wikipedia://en/23015). In some languages they are available as [primitive types](https://en.wikipedia.org/wiki/Primitive_type) and in others as [composite types](https://en.wikipedia.org/wiki/Composite_type). The [syntax](https://en.wikipedia.org/wiki/Syntax_%28programming_languages%29) of most [high-level programming languages](https://en.wikipedia.org/wiki/High-level_programming_language) allows for a string, usually quoted in some way, to represent an instance of a string datatype; such a meta-string is called a *literal* or *string literal*.

### String length {#String_length}

Although formal strings can have an arbitrary finite length, the length of strings in real languages is often constrained to an artificial maximum. In general, there are two types of string datatypes: *fixed-length strings*, which have a fixed maximum length to be determined at [compile time](https://en.wikipedia.org/wiki/Compile_time) and which use the same amount of memory whether this maximum is needed or not, and *variable-length strings*, whose length is not arbitrarily fixed and which can use varying amounts of memory depending on the actual requirements at run time (see [Memory management](https://en.wikipedia.org/wiki/Memory_management)). Most strings in modern [programming languages](https://en.wikipedia.org/wiki/Programming_languages) are variable-length strings. Of course, even variable-length strings are limited in length by the amount of available memory. The string length can be stored as a separate integer (which may put another artificial limit on the length) or implicitly through a termination character, usually a character value with all bits zero such as in C programming language. See also "Null-terminated" below.

### Character encoding {#Character_encoding}

String datatypes have historically allocated one byte per character, and, although the exact character set varied by region, character encodings were similar enough that programmers could often get away with ignoring this, since characters a program treated specially (such as period and space and comma) were in the same place in all the encodings a program would encounter. These character sets were typically based on [ASCII](https://en.wikipedia.org/wiki/ASCII) or [EBCDIC](https://en.wikipedia.org/wiki/EBCDIC). If text in one encoding was displayed on a system using a different encoding, text was often [mangled](https://en.wikipedia.org/wiki/Mojibake), though often somewhat readable and some computer users learned to read the mangled text.

[Logographic](https://en.wikipedia.org/wiki/Logograph) languages such as [Chinese](https://en.wikipedia.org/wiki/Chinese_language), [Japanese](https://en.wikipedia.org/wiki/Japanese_language), and [Korean](https://en.wikipedia.org/wiki/Korean_language) (known collectively as [CJK](https://en.wikipedia.org/wiki/CJK_characters)) need far more than 256 characters (the limit of a one 8-bit byte per-character encoding) for reasonable representation. The normal solutions involved keeping single-byte representations for ASCII and using two-byte representations for CJK [ideographs](https://en.wikipedia.org/wiki/Ideographs). Use of these with existing code led to problems with matching and cutting of strings, the severity of which depended on how the character encoding was designed. Some encodings such as the [EUC](https://en.wikipedia.org/wiki/Extended_Unix_Code) family guarantee that a byte value in the ASCII range will represent only that ASCII character, making the encoding safe for systems that use those characters as field separators. Other encodings such as [ISO-2022](https://en.wikipedia.org/wiki/ISO-2022) and [Shift-JIS](https://en.wikipedia.org/wiki/Shift-JIS) do not make such guarantees, making matching on byte codes unsafe. These encodings also were not "self-synchronizing", so that locating character boundaries required backing up to the start of a string, and pasting two strings together could result in corruption of the second string.

[Unicode](https://en.wikipedia.org/wiki/Unicode) has simplified the picture somewhat. Most programming languages now have a datatype for Unicode strings. Unicode's preferred byte stream format [UTF-8](https://en.wikipedia.org/wiki/UTF-8) is designed not to have the problems described above for older multibyte encodings. UTF-8, UTF-16 and [UTF-32](https://en.wikipedia.org/wiki/UTF-32) require the programmer to know that the fixed-size code units are different from the "characters", the main difficulty currently is incorrectly designed APIs that attempt to hide this difference (UTF-32 does make *code points* fixed-sized, but these are not "characters" due to composing codes).

::: {#o18 .definition kind=definition/construction cue=heading name="Implementations"}

### Implementations {#Implementations}

Some languages, such as [C++](https://en.wikipedia.org/wiki/C++), [Perl](https://en.wikipedia.org/wiki/Perl), and [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29), normally allow the contents of a string to be changed after it has been created; these are termed *mutable* strings. In other languages, such as [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), [JavaScript](https://en.wikipedia.org/wiki/JavaScript), [Lua](https://en.wikipedia.org/wiki/Lua), [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), and [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29), the value is fixed and a new string must be created if any alteration is to be made; these are termed *immutable* strings. Some of these languages with immutable strings also provide another type that is mutable, such as Java and [.NET](https://en.wikipedia.org/wiki/.NET)'s , the thread-safe Java , and the [Cocoa](https://en.wikipedia.org/wiki/Cocoa_%28API%29) `NSMutableString`. Immutability brings advantages and disadvantages: while immutable strings may require inefficiently creating many copies, they are simpler and fully [thread-safe](https://en.wikipedia.org/wiki/Thread_safety).

Strings are typically implemented as [arrays](https://en.wikipedia.org/wiki/Array_data_type) of bytes, characters, or code units, to allow fast access to individual units or substrings, including characters when they have a fixed length. A few languages such as [Haskell](https://en.wikipedia.org/wiki/Haskell) implement them as [linked lists](https://en.wikipedia.org/wiki/Linked_list) instead.

Many high-level languages provide strings as a primitive data type, such as [JavaScript](https://en.wikipedia.org/wiki/JavaScript) and [PHP](https://en.wikipedia.org/wiki/PHP), while most others provide them as a composite data type, some with special language support in writing literals, for example, [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) and [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29).

Some languages, such as [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [Prolog](wikipedia://en/23485) and [Erlang](https://en.wikipedia.org/wiki/Erlang_%28programming_language%29), avoid implementing a dedicated string datatype at all, instead adopting the convention of representing strings as lists of character codes. Even in programming languages having a dedicated string type, strings can usually be iterated as a sequence of character codes, like lists of integers or other values.

:::

### Representations {#Representations}

Representations of strings depend heavily on the choice of character repertoire and the method of character encoding. Older string implementations were designed to work with repertoire and encoding defined by ASCII, or more recent extensions like the [ISO 8859](https://en.wikipedia.org/wiki/ISO_8859) series. Modern implementations often use the extensive repertoire defined by Unicode along with a variety of complex encodings such as UTF-8 and UTF-16.

The term *byte string* usually indicates a general-purpose string of bytes, rather than strings of only (readable) characters, strings of bits, or such. Byte strings often imply that bytes can take any value and any data can be stored as-is, meaning that there should be no value interpreted as a termination value.

Most string implementations are very similar to variable-length [arrays](https://en.wikipedia.org/wiki/Array_data_type) with the entries storing the [character codes](https://en.wikipedia.org/wiki/Character_code) of corresponding characters. The principal difference is that, with certain encodings, a single logical character may take up more than one entry in the array. This happens, for example, with UTF-8, where single codes ([UCS](https://en.wikipedia.org/wiki/Universal_Character_Set) code points) can take anywhere from one to four bytes, and single characters can take an arbitrary number of codes. In these cases, the logical length of the string (number of characters) differs from the physical length of the array (number of bytes in use). [UTF-32](https://en.wikipedia.org/wiki/UTF-32) avoids the first part of the problem.

#### Dope vectors {#Dope_vectors}

The length of a string can be stored in a [dope vector](https://en.wikipedia.org/wiki/Dope_vector), separate from the storage holding the actual characters. The IBM PL/I (F) compiler used a **string dope vector**[^o22] (SDV) for variable-length strings and for passing string parameters. The SDV contains a current length and a maximum length, and is not adjacent to the string proper. After PL/I (F), IBM dropped the SDV in favor of length-prefixed strings.

#### Null-terminated {#Null-terminated}

The length of a string can be stored implicitly by using a special terminating character; often this is the [null character](https://en.wikipedia.org/wiki/Null_character) (NUL), which has all bits zero, a convention used and perpetuated by the popular [C programming language](https://en.wikipedia.org/wiki/C_%28programming_language%29).[^o24] Hence, this representation is commonly referred to as a **C string**. This representation of an *n*-character string takes *n* + 1 space (1 for the terminator), and is thus an [implicit data structure](https://en.wikipedia.org/wiki/Implicit_data_structure).

In terminated strings, the terminating code is not an allowable character in any string. Strings with *length* field do not have this limitation and can also store arbitrary [binary data](https://en.wikipedia.org/wiki/Binary_data).

An example of a *null-terminated string* stored in a 10-byte [buffer](https://en.wikipedia.org/wiki/Buffer_%28computer_science%29), along with its [ASCII](https://en.wikipedia.org/wiki/ASCII) (or more modern [UTF-8](https://en.wikipedia.org/wiki/UTF-8)) representation as 8-bit [hexadecimal numbers](https://en.wikipedia.org/wiki/Hexadecimal_number) is:

::: {#o25 .table cue=table}

| `F` | `R` | `A` | `N` | `K` | [NUL](https://en.wikipedia.org/wiki/Null_character) | `k` | `e` | `f` | `w` |
|---|---|---|---|---|---|---|---|---|---|
| 46<sub>[16](wikipedia://en/13263#Using_0–9_and_A–F)</sub> | 52<sub>16</sub> | 41<sub>16</sub> | 4E<sub>16</sub> | 4B<sub>16</sub> | 00<sub>16</sub> | 6B<sub>16</sub> | 65<sub>16</sub> | 66<sub>16</sub> | 77<sub>16</sub> |

:::

The length of the string in the above example, "`FRANK`", is 5 characters, but it occupies 6 bytes. Characters after the terminator do not form part of the representation; they may be either part of other data or just garbage. (Strings of this form are sometimes called *ASCIZ strings*, after the original [assembly language](https://en.wikipedia.org/wiki/Assembly_language) directive used to declare them.)

#### Byte- and bit-terminated {#Byte-_and_bit-terminated}

Using a special byte other than null for terminating strings has historically appeared in both hardware and software, though sometimes with a value that was also a printing character. `$` was used by many assembler systems, `:` used by [CDC](https://en.wikipedia.org/wiki/Control_Data_Corporation) systems (this character had a value of zero), and the [ZX80](https://en.wikipedia.org/wiki/ZX80) used `"`[^o28] since this was the string delimiter in its BASIC language.

Somewhat similar, "data processing" machines like the [IBM 1401](https://en.wikipedia.org/wiki/IBM_1401) used a special [word mark](https://en.wikipedia.org/wiki/Word_mark_%28computer_hardware%29) bit to delimit strings at the left, where the operation would start at the right. This bit had to be clear in all other parts of the string. This meant that, while the IBM 1401 had a seven-bit word, almost no-one ever thought to use this as a feature, and override the assignment of the seventh bit to (for example) handle ASCII codes.

Early microcomputer software relied upon the fact that ASCII codes do not use the high-order bit, and set it to indicate the end of a string. It must be reset to 0 prior to output.[^o29]

::: {#o31 .pointer-item cue=pointer name="Length-prefixed string"}

#### Length-prefixed {#Length-prefixed}

The length of a string can also be stored explicitly, for example by prefixing the string with the length as a byte value. This convention is used in many [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29) dialects; as a consequence, some people call such a string a **Pascal string** or **P-string**. Storing the string length as byte limits the maximum string length to 255. To avoid such limitations, improved implementations of P-strings use 16-, 32-, or 64-bit [words](https://en.wikipedia.org/wiki/Word_%28data_type%29) to store the string length. When the *length* field covers the [address space](https://en.wikipedia.org/wiki/Address_space), strings are limited only by the [available memory](https://en.wikipedia.org/wiki/Dynamic_memory_allocation).

If the length is bounded, then it can be encoded in constant space, typically a machine word, thus leading to an [implicit data structure](https://en.wikipedia.org/wiki/Implicit_data_structure), taking *n* + *k* space, where *k* is the number of characters in a word (8 for 8-bit ASCII on a 64-bit machine, 1 for 32-bit UTF-32/UCS-4 on a 32-bit machine, etc.). If the length is not bounded, encoding a length *n* takes log(*n*) space (see [fixed-length code](https://en.wikipedia.org/wiki/Fixed-length_code)), so length-prefixed strings are a [succinct data structure](https://en.wikipedia.org/wiki/Succinct_data_structure), encoding a string of length *n* in log(*n*) + *n* space.

In the latter case, the length-prefix field itself does not have fixed length, therefore the actual string data needs to be moved when the string grows such that the length field needs to be increased.

Here is a Pascal string stored in a 10-byte buffer, along with its ASCII / UTF-8 representation:

::: {#o32 .table cue=table}

| length | `F` | `R` | `A` | `N` | `K` | `k` | `e` | `f` | `w` |
|---|---|---|---|---|---|---|---|---|---|
| 05<sub>16</sub> | 46<sub>16</sub> | 52<sub>16</sub> | 41<sub>16</sub> | 4E<sub>16</sub> | 4B<sub>16</sub> | 6B<sub>16</sub> | 65<sub>16</sub> | 66<sub>16</sub> | 77<sub>16</sub> |

:::

#### Strings as records {#Strings_as_records}

Many languages, including object-oriented ones, implement strings as [records](https://en.wikipedia.org/wiki/Record_%28computer_science%29) with an internal structure like:

```cpp
public final class String {
    private unsigned long length; // string length
    private UniquePointer<char[]> text; // explicit ownership
    
    // public methods...
}
```

However, since the implementation is usually [hidden](https://en.wikipedia.org/wiki/Information_hiding), the string must be accessed and modified through member functions. `text` is a pointer to a dynamically allocated memory area, which might be expanded as needed. See also [string (C++)](https://en.wikipedia.org/wiki/String_%28C++%29).

#### Other representations {#Other_representations}

Both character termination and length codes limit strings: For example, C character arrays that contain null (NUL) characters cannot be handled directly by [C string](https://en.wikipedia.org/wiki/C_string_handling) library functions: Strings using a length code are limited to the maximum value of the length code.

Both of these limitations can be overcome by clever programming.

It is possible to create data structures and functions that manipulate them that do not have the problems associated with character termination and can in principle overcome length code bounds. It is also possible to optimize the string represented using techniques from [run length encoding](wikipedia://en/26392) (replacing repeated characters by the character value and a length) and [Hamming encoding](https://en.wikipedia.org/wiki/Hamming_coding).

While these representations are common, others are possible. Using [ropes](https://en.wikipedia.org/wiki/Rope_%28data_structure%29) makes certain string operations, such as insertions, deletions, and concatenations more efficient.

The core data structure in a [text editor](https://en.wikipedia.org/wiki/Text_editor) is the one that manages the string (sequence of characters) that represents the current state of the file being edited. While that state could be stored in a single long consecutive array of characters, a typical text editor instead uses an alternative representation as its sequence data structure—a [gap buffer](https://en.wikipedia.org/wiki/Gap_buffer), a [linked list](https://en.wikipedia.org/wiki/Linked_list) of lines, a [piece table](https://en.wikipedia.org/wiki/Piece_table), or a [rope](https://en.wikipedia.org/wiki/Rope_%28data_structure%29)—which makes certain string operations, such as insertions, deletions, and undoing previous edits, more efficient.[^o35]

### Security concerns {#Security_concerns}

The differing memory layout and storage requirements of strings can affect the security of the program accessing the string data. String representations requiring a terminating character are commonly susceptible to [buffer overflow](https://en.wikipedia.org/wiki/Buffer_overflow) problems if the terminating character is not present, caused by a coding error or an [attacker](https://en.wikipedia.org/wiki/Hacker_%28computer_security%29) deliberately altering the data. String representations adopting a separate length field are also susceptible if the length can be manipulated. In such cases, program code accessing the string data requires [bounds checking](https://en.wikipedia.org/wiki/Bounds_checking) to ensure that it does not inadvertently access or change data outside of the string memory limits.

String data is frequently obtained from user input to a program. As such, it is the responsibility of the program to validate the string to ensure that it represents the expected format. Performing [limited or no validation](https://en.wikipedia.org/wiki/Improper_input_validation) of user input can cause a program to be vulnerable to [code injection](https://en.wikipedia.org/wiki/Code_injection) attacks.

## Literal strings {#Literal_strings}

Sometimes, strings need to be embedded inside a text file that is both human-readable and intended for consumption by a machine. This is needed in, for example, source code of programming languages, or in configuration files. In this case, the NUL character does not work well as a terminator since it is normally invisible (non-printable) and is difficult to input via a keyboard. Storing the string length would also be inconvenient as manual computation and tracking of the length is tedious and error-prone.

Two common representations are:

- Surrounded by [quotation marks](https://en.wikipedia.org/wiki/Quotation_mark) (ASCII [0x22](wikipedia://en/13263#Using_0–9_and_A–F) double quote `"str"` or ASCII 0x27 single quote `'str'`), used by most programming languages. To be able to include special characters such as the quotation mark itself, newline characters, or non-printable characters, [escape sequences](https://en.wikipedia.org/wiki/Escape_character) are often available, usually prefixed with the [backslash](https://en.wikipedia.org/wiki/Backslash) character (ASCII 0x5C).
- Terminated by a [newline](https://en.wikipedia.org/wiki/Newline) sequence, for example in Windows [INI files](https://en.wikipedia.org/wiki/INI_file).

## Non-text strings {#Non-text_strings}

While character strings are very common uses of strings, a string in computer science may refer generically to any sequence of homogeneously typed data. A [bit string](https://en.wikipedia.org/wiki/Bit_string) or [byte string](https://en.wikipedia.org/wiki/Byte_string), for example, may be used to represent non-textual [binary data](https://en.wikipedia.org/wiki/Binary_data) retrieved from a communications medium. This data may or may not be represented by a string-specific datatype, depending on the needs of the application, the desire of the programmer, and the capabilities of the programming language being used. If the programming language's string implementation is not [8-bit clean](https://en.wikipedia.org/wiki/8-bit_clean), data corruption may ensue.

C programmers draw a sharp distinction between a "string", aka a "string of characters", which by definition is always null terminated, vs. an "array of characters" which may be stored in the same array but is often not null terminated. Using [C string handling](https://en.wikipedia.org/wiki/C_string_handling) functions on such an array of characters often seems to work, but later leads to security problems.[^o39][^o40][^o41]

## String processing algorithms {#String_processing_algorithms}

There are many [algorithms](wikipedia://en/775) for processing strings, each with various trade-offs. Competing algorithms can be [analyzed](wikipedia://en/2230) with respect to run time, storage requirements, and so forth. The name **stringology** was coined in 1984 by computer scientist [Zvi Galil](wikipedia://en/7913127) for the theory of algorithms and data structures used for string processing.[^o44][^o45][^o46]

Some categories of algorithms include:

- [String searching algorithms](https://en.wikipedia.org/wiki/String_searching_algorithm) for finding a given substring or pattern
- [String manipulation algorithms](https://en.wikipedia.org/wiki/String_manipulation_algorithm)
- [Sorting algorithms](wikipedia://en/28442)
- [Regular expression](wikipedia://en/25717) algorithms
- [Parsing](https://en.wikipedia.org/wiki/Parser) a string
- [Sequence mining](https://en.wikipedia.org/wiki/Sequence_mining)

Advanced string algorithms often employ complex mechanisms and data structures, among them [suffix trees](https://en.wikipedia.org/wiki/Suffix_tree) and [finite-state machines](wikipedia://en/10931).

## Character string-oriented languages and utilities {#Character_string-oriented_languages_and_utilities}

Character strings are such a useful datatype that several languages have been designed in order to make string processing applications easy to write. Examples include the following languages:

- [AWK](https://en.wikipedia.org/wiki/AWK)
- [Icon](https://en.wikipedia.org/wiki/Icon_%28programming_language%29)
- [MUMPS](https://en.wikipedia.org/wiki/MUMPS)
- [Perl](https://en.wikipedia.org/wiki/Perl)
- [Rexx](https://en.wikipedia.org/wiki/Rexx)
- [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29)
- [sed](https://en.wikipedia.org/wiki/Sed)
- [SNOBOL](https://en.wikipedia.org/wiki/SNOBOL)
- [Tcl](https://en.wikipedia.org/wiki/Tcl_%28programming_language%29)
- [TTM](https://en.wikipedia.org/wiki/TTM_%28programming_language%29)

Many [Unix](https://en.wikipedia.org/wiki/Unix) utilities perform simple string manipulations and can be used to easily program some powerful string processing algorithms. Files and finite streams may be viewed as strings.

Some [APIs](https://en.wikipedia.org/wiki/Application_programming_interface) like [Multimedia Control Interface](https://en.wikipedia.org/wiki/Multimedia_Control_Interface), [embedded SQL](https://en.wikipedia.org/wiki/Embedded_SQL) or [printf](https://en.wikipedia.org/wiki/Printf) use strings to hold commands that will be interpreted.

Many [scripting programming languages](https://en.wikipedia.org/wiki/Scripting_programming_language), including Perl, [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), Ruby, and Tcl employ [regular expressions](wikipedia://en/25717) to facilitate text operations. Perl is particularly noted for its regular expression use,[^o49] and many other languages and applications implement [Perl compatible regular expressions](https://en.wikipedia.org/wiki/Perl_Compatible_Regular_Expressions).

Some languages such as Perl and Ruby support [string interpolation](https://en.wikipedia.org/wiki/String_interpolation), which permits arbitrary expressions to be evaluated and included in string literals.

## Character string functions {#Character_string_functions}

[String functions](https://en.wikipedia.org/wiki/String_function) are used to create strings or change the contents of a mutable string. They also are used to query information about a string. The set of functions and their names varies depending on the [computer programming language](wikipedia://en/23015).

The most basic example of a string function is the [string length](https://en.wikipedia.org/wiki/String_length) function – the function that returns the length of a string (not counting any terminator characters or any of the string's internal structural information) and does not modify the string. This function is often named `[[comparison of programming languages (string functions)#length |length]]`, `len`, or `size`. For example, `length("hello world")` would return 11. Another common function is [concatenation](wikipedia://en/64474), where a new string is created by appending two strings, often this is the + addition operator.

Some [microprocessor](https://en.wikipedia.org/wiki/Microprocessor)'s [instruction set architectures](https://en.wikipedia.org/wiki/Instruction_set_architecture) contain direct support for string operations, such as block copy (e.g. In [intel x86m](https://en.wikipedia.org/wiki/Intel_x86) `REPNZ MOVSB`).[^o51]

## Formal theory {#Formal_theory}

Let $\Sigma$ be a [finite set](wikipedia://en/11742) of distinct, unambiguous symbols (alternatively called characters), called the [alphabet](wikipedia://en/4292269). A **string** (or **word**[^o54] or **expression**[^o55]) over $\Sigma$ is any finite [sequence](wikipedia://en/27838) of symbols from $\Sigma$.[^o56] For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$, then $\texttt{01011}$ is a string over $\Sigma$.

The *[length](wikipedia://en/18542)* of a string $s$ is the number of symbols in $s$ (the length of the sequence) and can be any [non-negative integer](https://en.wikipedia.org/wiki/Non-negative_integer); it is often denoted as $|s|$. The *[empty string](wikipedia://en/835827)* is the unique string over $\Sigma$ of length $0$, and is denoted $\varepsilon$ or $\lambda$.[^o56][^o57]

The set of all strings over $\Sigma$ of length $n$ is denoted $\Sigma^n$. For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$, then $\Sigma^2 = \{\texttt{00}, \texttt{01}, \texttt{10}, \texttt{11}\}$. We have $\Sigma^0 = \{\varepsilon\}$ for every alphabet $\Sigma$.

The set of all strings over $\Sigma$ of any length is the [Kleene closure](wikipedia://en/16750) of $\Sigma$ and is denoted $\Sigma^*$. In terms of $\Sigma^n$,

$$\Sigma^{*} = \bigcup_{n = 0}^\infty \Sigma^{n}$$

For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$, then $\Sigma^* = \{\varepsilon, \texttt{0}, \texttt{1}, \texttt{00}, \texttt{01}, \texttt{10}, \texttt{11}, \texttt{000}, \texttt{001}, \texttt{010}, \texttt{011}, ...\}$. Although the set $\Sigma^*$ itself is [countably infinite](https://en.wikipedia.org/wiki/Countably_infinite), each element of $\Sigma^*$ is a string of finite length.

A set of strings over $\Sigma$ (i.e. any [subset](wikipedia://en/27631) of $\Sigma^*$) is called a *[formal language](wikipedia://en/10939)* over $\Sigma$. For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$, the set of strings with an even number of zeros, $\{\varepsilon, \texttt{1}, \texttt{00}, \texttt{11}, \texttt{001}, \texttt{010}, \texttt{100}, \texttt{111}, \texttt{0000}, \texttt{0011}, \texttt{0101}, \texttt{0110}, \texttt{1001}, \texttt{1010}, \texttt{1100}, \texttt{1111}, ...\}$, is a formal language over $\Sigma$.

### Concatenation and substrings {#Concatenation_and_substrings}

*[Concatenation](wikipedia://en/64474)* is an important [binary operation](wikipedia://en/3948) on $\Sigma^*$. For any two strings $s$ and $t$ in $\Sigma^*$, their concatenation is defined as the sequence of symbols in $s$ followed by the sequence of characters in $t$, and is denoted $st$. For example, if $\Sigma = \{\texttt{a}, \texttt{b}, ..., \texttt{z}\}$ (i.e. the lowercase [English alphabet](https://en.wikipedia.org/wiki/English_alphabet)), $s = \texttt{bear}$, and $t = \texttt{hug}$, then $st = \texttt{bearhug}$ and $ts = \texttt{hugbear}$.

String concatenation is an [associative](https://en.wikipedia.org/wiki/Associative), but non-[commutative](https://en.wikipedia.org/wiki/Commutative) operation. The empty string $\varepsilon$ serves as the [identity element](wikipedia://en/14962); for any string $s$, $\varepsilon s = s \varepsilon = s$. Therefore, the set $\Sigma^*$ and the concatenation operation form a [monoid](wikipedia://en/19652), the [free monoid](wikipedia://en/523166) generated by $\Sigma$. In addition, the length function defines a [monoid homomorphism](https://en.wikipedia.org/wiki/Monoid_homomorphism) from $\Sigma^*$ to the non-negative integers (that is, a function $L: \Sigma^{*} \mapsto \mathbb{N} \cup \{0\}$, such that $L(st)=L(s)+L(t)\quad \forall s,t\in\Sigma^*$).

A string $s$ is said to be a *[substring](https://en.wikipedia.org/wiki/Substring)* or *factor* of $t$ if there exist (possibly empty) strings $u$ and $v$ such that $t = usv$. The [relation](wikipedia://en/3931) "is a substring of" defines a [partial order](https://en.wikipedia.org/wiki/Partial_order) on $\Sigma^*$, the [least element](https://en.wikipedia.org/wiki/Least_element) of which is the empty string.

### Prefixes and suffixes {#Prefixes_and_suffixes}

A string $s$ is said to be a [prefix](https://en.wikipedia.org/wiki/Substring#Prefix) of $t$ if there exists a string $u$ such that $t = su$. If $u$ is nonempty, $s$ is said to be a *proper* prefix of $t$. Symmetrically, a string $s$ is said to be a [suffix](https://en.wikipedia.org/wiki/Substring#Suffix) of $t$ if there exists a string $u$ such that $t = us$. If $u$ is nonempty, $s$ is said to be a *proper* suffix of $t$. Suffixes and prefixes are substrings of $t$. Both the relations "is a prefix of" and "is a suffix of" are [prefix orders](wikipedia://en/7006917).

### Reversal {#Reversal}

The reverse of a string is a string with the same symbols but in reverse order. For example, if $s = \texttt{abc}$ (where $\texttt{a}$, $\texttt{b}$, and $\texttt{c}$ are symbols of the alphabet), then the reverse of $s$ is $\texttt{cba}$. A string that is the reverse of itself (e.g., $s = \texttt{madam}$) is called a [palindrome](https://en.wikipedia.org/wiki/Palindrome#Computation_theory), which also includes the empty string and all strings of length $1$.

### Rotations {#Rotations}

A string $s = uv$ is said to be a rotation of $t$ if $t = vu$. For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$ the string $\texttt{0011001}$ is a rotation of $\texttt{0100110}$, where $u = \texttt{00110}$ and $v = \texttt{01}$. As another example, the string $\texttt{abc}$ has three different rotations, viz. $\texttt{abc}$ itself (with $u=\texttt{abc}$, $v=\varepsilon$), $\texttt{bca}$ (with $u=\texttt{bc}, v=\texttt{a}$), and $\texttt{cab}$ (with $u=\texttt{c}, v=\texttt{ab}$).

### Lexicographical ordering {#Lexicographical_ordering}

It is often useful to define an [ordering](wikipedia://en/361924) on a set of strings. If the alphabet $\Sigma$ has a [total order](wikipedia://en/30330) (cf. [alphabetical order](https://en.wikipedia.org/wiki/Alphabetical_order)) one can define a total order on $\Sigma^*$ called [lexicographical order](https://en.wikipedia.org/wiki/Lexicographical_order). The lexicographical order is [total](wikipedia://en/30330) if the alphabetical order is, but is not [well-founded](https://en.wikipedia.org/wiki/Well-founded) for any nontrivial alphabet, even if the alphabetical order is. For example, if $\Sigma = \{\texttt{0}, \texttt{1}\}$ and $\texttt{0} < \texttt{1}$, then the lexicographical order on $\Sigma^*$ includes the relationships $\varepsilon < \texttt{0} < \texttt{00} < \texttt{000} < ... < \texttt{0001} < ... < \texttt{001} < ... < \texttt{01} < \texttt{010} < ... < \texttt{011} < \texttt{0110} < ... < \texttt{01111} < ... < \texttt{1} < \texttt{10} < \texttt{100} < ... < \texttt{101} < ... < \texttt{111} < ... < \texttt{1111} < ... < \texttt{11111} ...$ With respect to this ordering, e.g. the infinite set $\{ \texttt{1}, \texttt{01}, \texttt{001}, \texttt{0001}, \texttt{00001}, \texttt{000001}, ... \}$ has no minimal element.

See [Shortlex](https://en.wikipedia.org/wiki/Shortlex) for an alternative string ordering that preserves well-foundedness. For the example alphabet, the shortlex order is $\varepsilon < \texttt{0} < \texttt{1} < \texttt{00} < \texttt{01} < \texttt{10} < \texttt{11} < \texttt{000} < \texttt{001} < \texttt{010} < \texttt{011} < \texttt{100} < \texttt{101} < \texttt{0110} < \texttt{111} < \texttt{0000} < \texttt{0001} < \texttt{0010} < \texttt{0011} < ... < \texttt{1111} < \texttt{00000} < \texttt{00001} ...$

A number of additional operations on strings commonly occur in the formal theory. These are given in the article on [string operations](https://en.wikipedia.org/wiki/String_operations).

### Topology {#Topology}

*Image: Hamming distance 3 bit binary.svg.* (Hyper)cube of [binary strings](https://en.wikipedia.org/wiki/Binary_string) of length $3$

Strings admit the following interpretation as nodes on a graph, where $k$ is the number of symbols in $\Sigma$:

- Fixed-length strings of length $n$ can be viewed as the integer locations in an $n$-dimensional [hypercube](wikipedia://en/39783) with sides of length $k-1$.
- Variable-length strings (of finite length) can be viewed as nodes on a [perfect $k$-ary tree](https://en.wikipedia.org/wiki/K-ary_tree).
- [Infinite strings](https://en.wikipedia.org/wiki/Infinite_string) (otherwise not considered here) can be viewed as infinite paths on a $k$-node [complete graph](wikipedia://en/85816).

The natural topology on the set of fixed-length strings or variable-length strings is the discrete topology, but the natural topology on the set of infinite strings is the [limit topology](https://en.wikipedia.org/wiki/Limit_topology), viewing the set of infinite strings as the [inverse limit](wikipedia://en/15109) of the sets of finite strings. This is the construction used for the [*p*-adic numbers](https://en.wikipedia.org/wiki/P-adic) and some constructions of the [Cantor set](wikipedia://en/6172), and yields the same topology.

[Isomorphisms](wikipedia://en/14828) between string representations of topologies can be found by normalizing according to the [lexicographically minimal string rotation](https://en.wikipedia.org/wiki/Lexicographically_minimal_string_rotation).
