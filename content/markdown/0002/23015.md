# Programming language

*Image: C Hello World Program.png.* The [source code](https://en.wikipedia.org/wiki/Source_code) for a computer program in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29). The gray lines are [comments](https://en.wikipedia.org/wiki/Comment_%28computer_programming%29) that explain the program to humans. When [compiled](https://en.wikipedia.org/wiki/Compiled) and [run](https://en.wikipedia.org/wiki/Execution_%28computing%29), it will give the output "[Hello, world!](https://en.wikipedia.org/wiki/Hello,_world!)".

::: {#o1 .subject cue=lead name="Programming language"}

A **programming language** is an [engineered language](wikipedia://en/663695) for expressing [computer programs](https://en.wikipedia.org/wiki/Computer_program),[^o2] typically allowing software to be [written](https://en.wikipedia.org/wiki/Software_development) in a [human readable](https://en.wikipedia.org/wiki/Human_readable) manner.

:::

[Execution](https://en.wikipedia.org/wiki/Execution_%28computing%29) of a program requires an [implementation](https://en.wikipedia.org/wiki/Programming_language_implementation). There are two main approaches for implementing a programming language [compilation](https://en.wikipedia.org/wiki/Compiler), where programs are translated ahead-of-time to [machine code](https://en.wikipedia.org/wiki/Machine_code), and [interpretation](https://en.wikipedia.org/wiki/Interpreter_%28computing%29), where programs are directly executed. In addition to these two extremes, some implementations use hybrid approaches such as [just-in-time compilation](https://en.wikipedia.org/wiki/Just-in-time_compilation) and [bytecode](https://en.wikipedia.org/wiki/Bytecode) interpreters.[^o3]

The [design of programming languages](https://en.wikipedia.org/wiki/Programming_language_design_and_implementation) has been strongly influenced by [computer architecture](https://en.wikipedia.org/wiki/Computer_architecture), with most [imperative](https://en.wikipedia.org/wiki/Imperative_programming) languages designed around the ubiquitous [von Neumann architecture](https://en.wikipedia.org/wiki/Von_Neumann_architecture).[^o4] While early programming languages were closely tied to the [hardware](https://en.wikipedia.org/wiki/Computer_hardware), modern languages often hide hardware details via [abstraction](https://en.wikipedia.org/wiki/Abstraction_%28computer_science%29) in an effort to enable better software with less effort. These languages are known as [high-level](https://en.wikipedia.org/wiki/High-level_programming_language) languages.[^o5]

## Relation to natural languages {#Relation_to_natural_languages}

Programming languages have some similarity to [natural languages](https://en.wikipedia.org/wiki/Natural_languages) in that they can allow communication of ideas between people. Programs are generally human-readable and can express complex ideas however, the kinds of ideas that programming languages can express are ultimately limited to the domain of computation.[^o7]

The term *[computer language](https://en.wikipedia.org/wiki/Computer_language)* is sometimes used interchangeably with *programming language*[^o8] but some contend they are different concepts. Some contend that programming languages are a subset of computer languages.[^o9] Some use *computer language* to classify a language used in computing that is not considered a programming language. Some regard a programming language as a theoretical construct for programming an [abstract machine](wikipedia://en/60492), and a computer language as the subset thereof that runs on a physical computer, which has finite hardware resources.[^o10]

[John C. Reynolds](https://en.wikipedia.org/wiki/John_C._Reynolds) emphasizes that a [formal specification](https://en.wikipedia.org/wiki/Formal_specification) language is a programming language as much as any language intended for execution. He argues that textual and even graphical input formats that affect the behavior of a computer are programming languages, despite the fact they are commonly not Turing-complete, and remarks that ignorance of programming language concepts is the reason for many flaws in input formats.[^o11]

## History {#History}

### Early developments {#Early_developments}

The first programmable computers were invented during the 1940s, and with them, the first programming languages. [^o14][^n1] The earliest computers were programmed in [first-generation programming languages](https://en.wikipedia.org/wiki/First-generation_programming_language) (1GLs), [machine language](https://en.wikipedia.org/wiki/Machine_language) (simple instructions that could be directly executed by the processor). This code was very difficult to debug and was not [portable](https://en.wikipedia.org/wiki/Portability_%28computing%29) between different computer systems.[^n2] In order to improve the ease of programming, [assembly languages](https://en.wikipedia.org/wiki/Assembly_languages) (or [second-generation programming languages](https://en.wikipedia.org/wiki/Second-generation_programming_language)—2GLs) were invented, diverging from the machine language to make programs easier to understand for humans, although they did not increase portability.[^n3]

Initially, hardware resources were scarce and expensive, while [human resources](https://en.wikipedia.org/wiki/Human_resources) were cheaper. Therefore, cumbersome languages that were time-consuming to use, but were closer to the hardware for higher efficiency were favored.[^n4] The introduction of [high-level programming languages](https://en.wikipedia.org/wiki/High-level_programming_language) ([third-generation programming languages](https://en.wikipedia.org/wiki/Third-generation_programming_language)—3GLs)—revolutionized programming. These languages [abstracted](https://en.wikipedia.org/wiki/Abstraction_%28computing%29) away the details of the hardware, instead being designed to express [algorithms](wikipedia://en/775) that could be understood more easily by humans. For example, arithmetic expressions could now be written in symbolic notation and later translated into machine code that the hardware could execute.[^n3] In 1957, [Fortran](https://en.wikipedia.org/wiki/Fortran) (FORmula TRANslation) was invented. Often considered the first [compiled](https://en.wikipedia.org/wiki/Compiled) high-level programming language,[^n3][^n5] Fortran has remained in use into the twenty-first century.[^n6]

### 1960s and 1970s {#1960s_and_1970s}

*Image: IBM Electronic Data Processing Machine - GPN-2000-001881.jpg.* Two people using an [IBM 704](https://en.wikipedia.org/wiki/IBM_704) [mainframe](https://en.wikipedia.org/wiki/Mainframe)—the first hardware to support [floating-point arithmetic](wikipedia://en/11376)—in 1957. [Fortran](https://en.wikipedia.org/wiki/Fortran) was designed for this machine.[^n7][^n6]

Around 1960, the first [mainframes](https://en.wikipedia.org/wiki/Mainframes)—general purpose computers—were developed, although they could only be operated by professionals and the cost was extreme. The data and instructions were input by [punch cards](https://en.wikipedia.org/wiki/Punch_cards), meaning that no input could be added while the program was running. The languages developed at this time therefore are designed for minimal interaction.[^n8] After the invention of the [microprocessor](https://en.wikipedia.org/wiki/Microprocessor), computers in the 1970s became dramatically cheaper.[^n9] New computers also allowed more user interaction, which was supported by newer programming languages.[^n10]

[Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29), implemented in 1958, was the first [functional programming](https://en.wikipedia.org/wiki/Functional_programming) language.[^o29] Unlike Fortran, it supported [recursion](wikipedia://en/25407) and [conditional expressions](https://en.wikipedia.org/wiki/Conditional_expression),[^n11] and it also introduced [dynamic memory management](https://en.wikipedia.org/wiki/Dynamic_memory_management) on a [heap](https://en.wikipedia.org/wiki/Heap_%28computer_science%29) and automatic [garbage collection](https://en.wikipedia.org/wiki/Garbage_collection_%28computer_science%29).[^n12] For the next decades, Lisp dominated [artificial intelligence](https://en.wikipedia.org/wiki/Artificial_intelligence) applications.[^n13] In 1978, another functional language, [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29), introduced [inferred types](wikipedia://en/279690) and polymorphic [parameters](https://en.wikipedia.org/wiki/Parameter_%28computer_programming%29).[^n10][^n14]

After [ALGOL](https://en.wikipedia.org/wiki/ALGOL) (ALGOrithmic Language) was released in 1958 and 1960,[^n15] it became the standard in computing literature for describing [algorithms](wikipedia://en/775). Although its commercial success was limited, most popular imperative languages—including [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29), [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), and [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29)—are directly or indirectly descended from ALGOL 60.[^n16][^n6] Among its innovations adopted by later programming languages included greater portability and the first use of [context-free](wikipedia://en/6759), [BNF](https://en.wikipedia.org/wiki/Backus–Naur_form) grammar.[^n17] [Simula](https://en.wikipedia.org/wiki/Simula), the first language to support [object-oriented programming](https://en.wikipedia.org/wiki/Object-oriented_programming) (including [subtypes](https://en.wikipedia.org/wiki/Subtypes), [dynamic dispatch](https://en.wikipedia.org/wiki/Dynamic_dispatch), and [inheritance](https://en.wikipedia.org/wiki/Inheritance_%28computer_science%29)), also descends from ALGOL and achieved commercial success.[^n18] C, another ALGOL descendant, has sustained popularity into the twenty-first century. C allows access to lower-level machine operations than other contemporary languages. Its power and efficiency, generated in part with flexible [pointer](https://en.wikipedia.org/wiki/Pointer_%28computer_programming%29) operations, comes at the cost of making it more difficult to write correct code.[^n10]

[Prolog](wikipedia://en/23485), designed in 1972, was the first [logic programming](https://en.wikipedia.org/wiki/Logic_programming) language, communicating with a computer using [formal logic](https://en.wikipedia.org/wiki/Formal_logical_system) notation.[^n19][^n20] With logic programming, the programmer specifies a desired result and allows the [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computer_science%29) to decide how to achieve it.[^n21][^n20]

### 1980s to 2000s {#1980s_to_2000s}

*Image: Bangalore India Tech books for sale IMG 5261.jpg.* A small selection of programming language textbooks on sale in [Bangalore](https://en.wikipedia.org/wiki/Bangalore), India, 2011

During the 1980s, the invention of the [personal computer](https://en.wikipedia.org/wiki/Personal_computer) transformed the roles for which programming languages were used.[^n22] New languages introduced in the 1980s included C++, a [superset](https://en.wikipedia.org/wiki/Superset) of C that can compile C programs but also supports [classes](https://en.wikipedia.org/wiki/Class_%28programming%29) and [inheritance](https://en.wikipedia.org/wiki/Inheritance_%28object-oriented_programming%29).[^n23] [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29) and other new languages introduced support for [concurrency](https://en.wikipedia.org/wiki/Concurrency_%28computer_science%29).[^n24] The Japanese government invested heavily into the so-called [fifth-generation languages](https://en.wikipedia.org/wiki/Fifth-generation_programming_language) that added support for concurrency to logic programming constructs, but these languages were outperformed by other concurrency-supporting languages.[^n25][^n26]

Due to the rapid growth of the [Internet](https://en.wikipedia.org/wiki/Internet) and the [World Wide Web](https://en.wikipedia.org/wiki/World_Wide_Web) in the 1990s, new programming languages were introduced to support [web pages](https://en.wikipedia.org/wiki/Web_pages) and [networking](https://en.wikipedia.org/wiki/Computer_network).[^n27] [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), based on C++ and designed for increased portability across systems and security, enjoyed large-scale success because these features are essential for many Internet applications.[^n28][^n29] Another development was that of [dynamically typed](https://en.wikipedia.org/wiki/Dynamically_typed) [scripting languages](https://en.wikipedia.org/wiki/Scripting_languages)—[Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [JavaScript](https://en.wikipedia.org/wiki/JavaScript), [PHP](https://en.wikipedia.org/wiki/PHP), and [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29)—designed to quickly produce small programs that coordinate existing [applications](https://en.wikipedia.org/wiki/Application_software). Due to their integration with [HTML](https://en.wikipedia.org/wiki/HTML), they have also been used for building web pages hosted on [servers](https://en.wikipedia.org/wiki/Server_%28computing%29).[^n30][^n31]

### 2000s to present {#2000s_to_present}

During the 2000s, there was a slowdown in the development of new programming languages that achieved widespread popularity.[^n32] One innovation was [service-oriented programming](https://en.wikipedia.org/wiki/Service-oriented_programming), designed to exploit [distributed computing](https://en.wikipedia.org/wiki/Distributed_computing) systems which components are connected by a network. Services are similar to objects in object-oriented programming, but run on a separate process.[^n33] [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29) and [F#](https://en.wikipedia.org/wiki/F_Sharp_%28programming_language%29) cross-pollinated ideas between imperative and functional programming.[^n34] After 2010, several new languages—[Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29), [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29), [Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29), [Zig](https://en.wikipedia.org/wiki/Zig_%28programming_language%29), and [Carbon](https://en.wikipedia.org/wiki/Carbon_%28programming_language%29) —competed for the performance-critical software for which C had historically been used.[^n35] Most of the new programming languages use [static typing](https://en.wikipedia.org/wiki/Static_typing) while a few numbers of new languages use [dynamic typing](https://en.wikipedia.org/wiki/Dynamic_typing) like [Julia](https://en.wikipedia.org/wiki/Julia_%28programming_language%29).[^o61]

Some of the new programming languages are classified as [visual programming languages](https://en.wikipedia.org/wiki/Visual_programming_language) like [Scratch](https://en.wikipedia.org/wiki/Scratch_%28programming_language%29) and [LabVIEW](https://en.wikipedia.org/wiki/LabVIEW). Also, some of these languages mix between textual and visual programming usage like [Ballerina](https://en.wikipedia.org/wiki/Ballerina_%28programming_language%29).[^o62][^o63][^o64] Also, this trend lead to developing projects that help in developing new visual languages like [Blockly](https://en.wikipedia.org/wiki/Blockly) by [Google](https://en.wikipedia.org/wiki/Google).[^o65] Many game engines like [Unreal](https://en.wikipedia.org/wiki/Unreal_Engine) and [Unity](https://en.wikipedia.org/wiki/Unity_%28game_engine%29) support visual scripting.[^o66][^o67]

## Definition {#Definition}

A language can be defined in terms of [syntax](https://en.wikipedia.org/wiki/Syntax_%28programming_languages%29) (form) and [semantics](https://en.wikipedia.org/wiki/Semantics_%28computer_science%29) (meaning), and often is defined via a [formal language](wikipedia://en/10939) specification.

### Syntax {#Syntax}

*Image: Python add5 parse.png.* [Parse tree](https://en.wikipedia.org/wiki/Parse_tree) of [Python code](https://en.wikipedia.org/wiki/Python_code) with inset tokenization

*Image: Python add5 syntax.svg.* [Syntax highlighting](https://en.wikipedia.org/wiki/Syntax_highlighting) is often used to aid programmers in recognizing elements of source code. The language above is [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29).

A programming language's surface form is known as its [syntax](https://en.wikipedia.org/wiki/Syntax_%28programming_languages%29). Most programming languages are purely textual; they use sequences of text including words, numbers, and punctuation, much like written natural languages. In contrast, some programming languages are [graphical](https://en.wikipedia.org/wiki/Visual_programming_language), using visual relationships between symbols to specify a program.

The syntax of a language describes the possible combinations of symbols that form a syntactically correct program. The meaning given to a combination of symbols is handled by semantics (either [formal](https://en.wikipedia.org/wiki/Semantics_%28programming_languages%29) or hard-coded in a [reference implementation](https://en.wikipedia.org/wiki/Reference_implementation)). Since most languages are textual, this article discusses textual syntax.

The programming language syntax is usually defined using a combination of [regular expressions](wikipedia://en/25717) (for [lexical](https://en.wikipedia.org/wiki/Lexical_analysis) structure) and [Backus–Naur form](https://en.wikipedia.org/wiki/Backus–Naur_form) (for [grammatical](wikipedia://en/6759) structure). Below is a simple grammar, based on [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29):

```bnf
expression ::= atom | list
atom       ::= number | symbol
number     ::= [+-]?['0'-'9']+
symbol     ::= ['A'-'Z''a'-'z'].*
list       ::= '(' expression* ')'
```

This grammar specifies the following:

- an *expression* is either an *atom* or a *list*;
- an *atom* is either a *number* or a *symbol*;
- a *number* is an unbroken sequence of one or more decimal digits, optionally preceded by a plus or minus sign;
- a *symbol* is a letter followed by zero or more of any alphabetical characters (excluding whitespace); and
- a *list* is a matched pair of parentheses, with zero or more *expressions* inside it.

The following are examples of well-formed token sequences in this grammar: `12345`, `()` and `(a b c232 (1))`.

Not all syntactically correct programs are semantically correct. Many syntactically correct programs are nonetheless ill-formed, per the language's rules, and may (depending on the language specification and the soundness of the implementation) result in an error on translation or execution. In some cases, such programs may exhibit [undefined behavior](https://en.wikipedia.org/wiki/Undefined_behavior). Even when a program is well-defined within a language, it may still have a meaning that is not intended by the person who wrote it.

Using [natural language](wikipedia://en/21173) as an example, it may not be possible to assign a meaning to a grammatically correct sentence or the sentence may be false:

- "[Colorless green ideas sleep furiously](wikipedia://en/46438)," is grammatically [well-formed](https://en.wikipedia.org/wiki/Well-formedness) but has no generally accepted meaning.
- "John is a married bachelor," is grammatically well-formed but expresses a meaning that cannot be true.

The following [C language](https://en.wikipedia.org/wiki/C_language) fragment is syntactically correct, but performs operations that are not semantically defined (the operation `*p >> 4` has no meaning for a value having a complex type and `p->im` is not defined because the value of `p` is the [null pointer](https://en.wikipedia.org/wiki/Null_pointer)):

```c
complex *p = NULL;
complex abs_p = sqrt(*p >> 4 + p->im);
```

If the [type declaration](https://en.wikipedia.org/wiki/Type_declaration) on the first line were omitted, the program would trigger an error on the undefined variable `p` during compilation. However, the program would still be syntactically correct since type declarations provide only semantic information.

The grammar needed to specify a programming language can be classified by its position in the [Chomsky hierarchy](wikipedia://en/6011). The syntax of most programming languages can be specified using a Type-2 grammar, i.e., they are [context-free grammars](wikipedia://en/6759).[^o71] Some languages, including Perl and Lisp, contain constructs that allow execution during the parsing phase. Languages that have constructs that allow the programmer to alter the behavior of the parser make syntax analysis an [undecidable problem](wikipedia://en/15631055), and generally blur the distinction between parsing and execution.[^o72] In contrast to [Lisp's macro system](https://en.wikipedia.org/wiki/Lisp_macro) and Perl's `BEGIN` blocks, which may contain general computations, C [macros](https://en.wikipedia.org/wiki/Macro_%28computer_science%29) are merely string replacements and do not require code execution.[^o73]

### Semantics {#Semantics}

[*Semantics*](wikipedia://en/29107#Computer_science) refers to the meaning of content that conforms to a language's syntax.

::: {#o76 .pointer-item cue=pointer name="Static semantics"}

#### Static semantics {#Static_semantics}

Static semantics defines restrictions on the structure of valid texts that are hard or impossible to express in standard syntactic formalisms.[^o77] For compiled languages, static semantics essentially include those semantic rules that can be checked at compile time. Examples include checking that every [identifier](https://en.wikipedia.org/wiki/Identifier) is declared before it is used (in languages that require such declarations) or that the labels on the arms of a [case statement](https://en.wikipedia.org/wiki/Case_statement) are distinct.[^o78] Many important restrictions of this type, like checking that identifiers are used in the appropriate context (e.g. not adding an integer to a function name), or that [subroutine](https://en.wikipedia.org/wiki/Subroutine) calls have the appropriate number and type of arguments, can be enforced by defining them as rules in a [logic](wikipedia://en/46426065) called a [type system](wikipedia://en/199701). Other forms of [static analyses](https://en.wikipedia.org/wiki/Static_code_analysis) like [data flow analysis](https://en.wikipedia.org/wiki/Data_flow_analysis) may also be part of static semantics. Programming languages such as [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) and [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29) have [definite assignment analysis](https://en.wikipedia.org/wiki/Definite_assignment_analysis), a form of data flow analysis, as part of their respective static semantics.[^o79]

:::

::: {#o81 .pointer-item cue=pointer name="Execution semantics"}

#### Dynamic semantics {#Dynamic_semantics}

Once data has been specified, the machine must be instructed to perform operations on the data. For example, the semantics may define the [strategy](wikipedia://en/2977119) by which expressions are evaluated to values, or the manner in which [control structures](https://en.wikipedia.org/wiki/Control_structures) conditionally execute [statements](https://en.wikipedia.org/wiki/Statement_%28computer_science%29). The *[dynamic semantics](https://en.wikipedia.org/wiki/Dynamic_semantics)* (also known as *execution semantics*) of a language defines how and when the various constructs of a language should produce a program behavior. There are many ways of defining execution semantics. Natural language is often used to specify the execution semantics of languages commonly used in practice. A significant amount of academic research goes into formal [semantics of programming languages](https://en.wikipedia.org/wiki/Semantics_of_programming_languages), which allows execution semantics to be specified in a formal manner. Results from this field of research have seen limited application to programming language design and implementation outside academia.[^o79]

:::

:::

## Features {#Features}

A language provides features for a [programmer](https://en.wikipedia.org/wiki/Programmer) to develop software. Some notable features are described below.

::: {#o84 .pointer-item cue=pointer name="Typed and untyped languages"}

### Type system {#Type_system}

A [data type](https://en.wikipedia.org/wiki/Data_type) is a set of allowable values and operations that can be performed on these values.[^n36] Each programming language's [type system](wikipedia://en/199701) defines which data types exist, the type of an [expression](wikipedia://en/609125), and how [type equivalence](https://en.wikipedia.org/wiki/Type_equivalence) and [type compatibility](https://en.wikipedia.org/wiki/Structural_type_system) function in the language.[^n37]

According to [type theory](wikipedia://en/40282), a language is fully typed if the specification of every operation defines types of data to which the operation is applicable.[^o87] In contrast, an untyped language, such as most [assembly languages](https://en.wikipedia.org/wiki/Assembly_language), allows any operation to be performed on any data, generally sequences of bits of various lengths.[^o87] In practice, while few languages are fully typed, most offer a degree of typing.[^o87]

Because different types (such as [integers](wikipedia://en/14563) and [floats](wikipedia://en/11376)) represent values differently, unexpected results will occur if one type is used when another is expected. [Type checking](https://en.wikipedia.org/wiki/Type_checking) will flag this error, usually at [compile time](https://en.wikipedia.org/wiki/Compile_time) (runtime type checking is more costly).[^n38] With [strong typing](https://en.wikipedia.org/wiki/Strong_typing), [type errors](https://en.wikipedia.org/wiki/Type_error) can always be detected unless variables are explicitly [cast](https://en.wikipedia.org/wiki/Type_conversion) to a different type. [Weak typing](https://en.wikipedia.org/wiki/Weak_typing) occurs when languages allow implicit casting—for example, to enable operations between variables of different types without the programmer making an explicit type conversion. The more cases in which this [type coercion](https://en.wikipedia.org/wiki/Type_coercion) is allowed, the fewer type errors can be detected.[^n39]

#### Commonly supported types {#Commonly_supported_types}

Early programming languages often supported only built-in, numeric types such as the [integer](wikipedia://en/14563) (signed and unsigned) and [floating point](https://en.wikipedia.org/wiki/Floating_point) (to support operations on [real numbers](wikipedia://en/20646438) that are not integers). Most programming languages support multiple sizes of floats (often called [float](https://en.wikipedia.org/wiki/Single-precision_floating-point_format) and [double](https://en.wikipedia.org/wiki/Double-precision_floating-point_format)) and integers depending on the size and precision required by the programmer. Storing an integer in a type that is too small to represent it leads to [integer overflow](https://en.wikipedia.org/wiki/Integer_overflow). The most common way of representing negative numbers with signed types is [twos complement](https://en.wikipedia.org/wiki/Twos_complement), although [ones complement](https://en.wikipedia.org/wiki/Ones_complement) is also used.[^n40] Other common types include [Boolean](https://en.wikipedia.org/wiki/Boolean_data_type)—which is either true or false—and [character](https://en.wikipedia.org/wiki/Character_%28computing%29)—traditionally one [byte](https://en.wikipedia.org/wiki/Byte), sufficient to represent all [ASCII](https://en.wikipedia.org/wiki/ASCII) characters.[^n41]

[Arrays](https://en.wikipedia.org/wiki/Array_%28data_type%29) are a data type whose elements, in many languages, must consist of a single type of fixed length. Other languages define arrays as references to data stored elsewhere and support elements of varying types.[^n42] Depending on the programming language, sequences of multiple characters, called [strings](https://en.wikipedia.org/wiki/String_%28computing%29), may be supported as arrays of characters or their own [primitive type](https://en.wikipedia.org/wiki/Primitive_type).[^n43] Strings may be of fixed or variable length, which enables greater flexibility at the cost of increased storage space and more complexity.[^n44] Other data types that may be supported include [lists](https://en.wikipedia.org/wiki/List_%28computing%29),[^n45] [associative (unordered) arrays](https://en.wikipedia.org/wiki/Associative_arrays) accessed via keys,[^n46] [records](https://en.wikipedia.org/wiki/Record_%28computer_science%29) in which data is mapped to names in an ordered structure,[^n47] and [tuples](wikipedia://en/132729)—similar to records but without names for data fields.[^n48] [Pointers](https://en.wikipedia.org/wiki/Pointer_%28computer_programming%29) store memory addresses, typically referencing locations on the [heap](https://en.wikipedia.org/wiki/Heap_%28programming%29) where other data is stored.[^n49]

The simplest [user-defined type](https://en.wikipedia.org/wiki/User-defined_type) is an [ordinal type](https://en.wikipedia.org/wiki/Ordinal_data_type), often called an [enumeration](wikipedia://en/212115), whose values can be mapped onto the set of positive integers.[^n50] Since the mid-1980s, most programming languages also support [abstract data types](https://en.wikipedia.org/wiki/Abstract_data_types), in which the representation of the data and operations are [hidden from the user](https://en.wikipedia.org/wiki/Information_hiding), who can only access an [interface](https://en.wikipedia.org/wiki/Interface_%28computing%29).[^n51] The benefits of [data abstraction](https://en.wikipedia.org/wiki/Data_abstraction) can include increased reliability, reduced complexity, less potential for [name collision](https://en.wikipedia.org/wiki/Name_collision), and allowing the underlying [data structure](wikipedia://en/8519) to be changed without the client needing to alter its code.[^n52]

#### Static and dynamic typing {#Static_and_dynamic_typing}

In [static typing](https://en.wikipedia.org/wiki/Static_typing), all expressions have their types determined before a program executes, typically at compile-time.[^o87] Most widely used, statically typed programming languages require the types of variables to be specified explicitly. In some languages, types are implicit; one form of this is when the compiler can [infer](wikipedia://en/279690) types based on context. The downside of [implicit typing](https://en.wikipedia.org/wiki/Implicit_typing) is the potential for errors to go undetected.[^n53] Complete type inference has traditionally been associated with functional languages such as [Haskell](https://en.wikipedia.org/wiki/Haskell) and [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29).[^o106]

With [dynamic typing](https://en.wikipedia.org/wiki/Dynamic_typing), the type is not attached to the variable but only the value encoded in it. A single variable can be reused for a value of a different type. Although this provides more flexibility to the programmer, it is at the cost of lower reliability and less ability for the programming language to check for errors.[^n54] Some languages allow variables of a [union type](https://en.wikipedia.org/wiki/Union_type) to which any type of value can be assigned, in an exception to their usual static typing rules.[^n55]

:::

### Concurrency {#Concurrency}

In computing, multiple instructions can be executed simultaneously. Many programming languages support instruction-level and subprogram-level concurrency.[^n56] By the twenty-first century, additional processing power on computers was increasingly coming from the use of additional processors, which requires programmers to design software that makes use of multiple processors simultaneously to achieve improved performance.[^n57] [Interpreted languages](https://en.wikipedia.org/wiki/Interpreted_language) such as [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) and [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29) do not support the concurrent use of multiple processors.[^n58] Other programming languages do support managing data shared between different threads by controlling the order of execution of key instructions via the use of [semaphores](https://en.wikipedia.org/wiki/Semaphore_%28programming%29), controlling access to shared data via [monitor](https://en.wikipedia.org/wiki/Monitor_%28synchronization%29), or enabling [message passing](https://en.wikipedia.org/wiki/Message_passing) between threads.[^n59]

### Exception handling {#Exception_handling}

Many programming languages include exception handlers, a section of code triggered by [runtime errors](https://en.wikipedia.org/wiki/Runtime_error) that can deal with them in two main ways:[^n60]

- Termination: shutting down and handing over control to the [operating system](https://en.wikipedia.org/wiki/Operating_system). This option is considered the simplest.
- Resumption: resuming the program near where the exception occurred. This can trigger a repeat of the exception, unless the exception handler is able to modify values to prevent the exception from reoccurring.

Some programming languages support dedicating a block of code to run regardless of whether an exception occurs before the code is reached; this is called finalization.[^n61]

There is a tradeoff between increased ability to handle exceptions and reduced performance.[^n62] For example, even though array index errors are common[^n63] C does not check them for performance reasons.[^n62] Although programmers can write code to catch user-defined exceptions, this can clutter a program. Standard libraries in some languages, such as C, use their return values to indicate an exception.[^n64] Some languages and their compilers have the option of turning on and off error handling capability, either temporarily or permanently.[^n65]

## Design and implementation {#Design_and_implementation}

One of the most important influences on programming language design has been [computer architecture](https://en.wikipedia.org/wiki/Computer_architecture). [Imperative languages](https://en.wikipedia.org/wiki/Imperative_languages), the most commonly used type, were designed to perform well on [von Neumann architecture](https://en.wikipedia.org/wiki/Von_Neumann_architecture), the most common digital computer architecture.[^n66] In von Neumann architecture, the [memory](https://en.wikipedia.org/wiki/Computer_memory) stores both data and instructions, while the [CPU](https://en.wikipedia.org/wiki/CPU) that performs instructions on data is separate, and data must be piped back and forth to the CPU. The central elements in these languages are variables, [assignment](https://en.wikipedia.org/wiki/Assignment_%28computer_science%29), and [iteration](wikipedia://en/68833), which is more efficient than [recursion](wikipedia://en/4044867) on these machines.[^n67]

Many programming languages have been designed from scratch, altered to meet new needs, and combined with other languages. Many have eventually fallen into disuse. The birth of programming languages in the 1950s was stimulated by the desire to make a universal programming language suitable for all machines and uses, avoiding the need to write code for different computers.[^n68] By the early 1960s, the idea of a universal language was rejected due to the differing requirements of the variety of purposes for which code was written.[^n69]

### Tradeoffs {#Tradeoffs}

Desirable qualities of programming languages include readability, writability, and reliability.[^n70] These features can reduce the cost of training programmers in a language, the amount of time needed to write and maintain programs in the language, the cost of compiling the code, and increase runtime performance.[^n71]

- Although early programming languages often prioritized efficiency over readability, the latter has grown in importance since the 1970s. Having multiple operations to achieve the same result can be detrimental to readability, as is [overloading operators](https://en.wikipedia.org/wiki/Operator_overload), so that the same operator can have multiple meanings.[^n72] Another feature important to readability is [orthogonality](wikipedia://en/102221), limiting the number of constructs that a programmer has to learn.[^n73] A syntax structure that is easily understood and [special words](https://en.wikipedia.org/wiki/Reserved_word) that are immediately obvious also supports readability.[^n74]
- Writability is the ease of use for writing code to solve the desired problem. Along with the same features essential for readability,[^n75] [abstraction](https://en.wikipedia.org/wiki/Abstraction_%28computer_science%29)—interfaces that enable hiding details from the client—and [expressivity](https://en.wikipedia.org/wiki/Expressive_power_%28computer_science%29)—enabling more concise programs—additionally help the programmer write code.[^n76] The earliest programming languages were tied very closely to the underlying hardware of the computer, but over time support for abstraction has increased, allowing programmers to express ideas that are more remote from simple translation into underlying hardware instructions. Because programmers are less tied to the complexity of the computer, their programs can do more computing with less effort from the programmer.[^o135] Most programming languages come with a [standard library](https://en.wikipedia.org/wiki/Standard_library) of commonly used functions.[^o136]
- Reliability means that a program performs as specified in a wide range of circumstances.[^n77] [Type checking](https://en.wikipedia.org/wiki/Type_checking), [exception handling](https://en.wikipedia.org/wiki/Exception_handling), and restricted [aliasing](https://en.wikipedia.org/wiki/Aliasing_%28computing%29) (multiple variable names accessing the same region of memory) all can improve a program's reliability.[^n78]

Programming language design often involves tradeoffs.[^n79] For example, features to improve reliability typically come at the cost of performance.[^n80] Increased expressivity due to a large number of operators makes writing code easier but comes at the cost of readability.[^n80]

[Natural-language programming](https://en.wikipedia.org/wiki/Natural-language_programming) has been proposed as a way to eliminate the need for a specialized language for programming. However, this goal remains distant and its benefits are open to debate. [Edsger W. Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra) took the position that the use of a formal language is essential to prevent the introduction of meaningless constructs.[^o142] [Alan Perlis](https://en.wikipedia.org/wiki/Alan_Perlis) was similarly dismissive of the idea.[^o143]

### Specification {#Specification}

The specification of a programming language is an artifact that the language [users](https://en.wikipedia.org/wiki/Programmer) and the [implementors](https://en.wikipedia.org/wiki/Programming_language_implementation) can use to agree upon whether a piece of [source code](https://en.wikipedia.org/wiki/Source_code) is a valid [program](https://en.wikipedia.org/wiki/Computer_program) in that language, and if so what its behavior shall be.

A programming language specification can take several forms, including the following:

- An explicit definition of the syntax, static semantics, and execution semantics of the language. While syntax is commonly specified using a formal grammar, semantic definitions may be written in [natural language](wikipedia://en/21173) (e.g., as in the [C language](https://en.wikipedia.org/wiki/C_language)), or a [formal semantics](https://en.wikipedia.org/wiki/Semantics_%28programming_languages%29) (e.g., as in [Standard ML](https://en.wikipedia.org/wiki/Standard_ML)[^o145] and [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29)[^o146] specifications).
- A description of the behavior of a [translator](https://en.wikipedia.org/wiki/Compiler) for the language (e.g., the [C++](https://en.wikipedia.org/wiki/C++) and [Fortran](https://en.wikipedia.org/wiki/Fortran) specifications). The syntax and semantics of the language have to be inferred from this description, which may be written in natural or formal language.
- A [*reference* or *model* implementation](https://en.wikipedia.org/wiki/Reference_implementation), sometimes [written in the language being specified](https://en.wikipedia.org/wiki/Meta-circular_evaluator) (e.g., [Prolog](wikipedia://en/23485) or [ANSI REXX](https://en.wikipedia.org/wiki/REXX)[^o147]). The syntax and semantics of the language are explicit in the behavior of the reference implementation.

::: {#o149 .definition kind=definition/construction cue=heading name="Implementation"}

### Implementation {#Implementation}

An implementation of a programming language is the conversion of a program into [machine code](https://en.wikipedia.org/wiki/Machine_code) that can be executed by the hardware. The machine code then can be executed with the help of the [operating system](https://en.wikipedia.org/wiki/Operating_system).[^n81] The most common form of interpretation in [production code](https://en.wikipedia.org/wiki/Software_release_life_cycle) is by a [compiler](https://en.wikipedia.org/wiki/Compiler), which translates the source code via an intermediate-level language into machine code, known as an [executable](https://en.wikipedia.org/wiki/Executable). Once the program is compiled, it will run more quickly than with other implementation methods.[^n82] Some compilers are able to provide further [optimization](https://en.wikipedia.org/wiki/Optimization) to reduce memory or computation usage when the executable runs, but increasing compilation time.[^n83]

Another implementation method is to run the program with an [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29), which translates each line of software into machine code just before it executes. Although it can make debugging easier, the downside of interpretation is that it runs 10 to 100 times slower than a compiled executable.[^n84] Hybrid interpretation methods provide some of the benefits of compilation and some of the benefits of interpretation via partial compilation. One form this takes is [just-in-time compilation](https://en.wikipedia.org/wiki/Just-in-time_compilation), in which the software is compiled ahead of time into an intermediate language, and then into machine code immediately before execution.[^n85]

## Proprietary languages {#Proprietary_languages}

Although most of the most commonly used programming languages have fully open specifications and implementations, many programming languages exist only as proprietary programming languages with the implementation available only from a single vendor, which may claim that such a proprietary language is their intellectual property. Proprietary programming languages are commonly [domain-specific languages](https://en.wikipedia.org/wiki/Domain-specific_language) or internal [scripting languages](https://en.wikipedia.org/wiki/Scripting_language) for a single product; some proprietary languages are used only internally within a vendor, while others are available to external users.

Some programming languages exist on the border between proprietary and open; for example, [Oracle Corporation](https://en.wikipedia.org/wiki/Oracle_Corporation) asserts proprietary rights to some aspects of the [Java (programming language)](https://en.wikipedia.org/wiki/Java_%28programming_language%29) programming language,[^o157] and [Microsoft](https://en.wikipedia.org/wiki/Microsoft)'s [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29) programming language, which has open implementations of most parts of the system, also has [Common Language Runtime](https://en.wikipedia.org/wiki/Common_Language_Runtime) (CLR) as a closed environment.[^o158]

Many proprietary languages are widely used, in spite of their proprietary nature; examples include [MATLAB](wikipedia://en/20412), [VBScript](https://en.wikipedia.org/wiki/VBScript), and [Wolfram Language](https://en.wikipedia.org/wiki/Wolfram_Language). Some languages may make the transition from closed to open; for example, [Erlang](https://en.wikipedia.org/wiki/Erlang_%28programming_language%29) was originally Ericsson's internal programming language.[^o159]

[Open source programming languages](https://en.wikipedia.org/wiki/List_of_open-source_programming_languages) are particularly helpful for [open science](https://en.wikipedia.org/wiki/Open_science) applications, enhancing the capacity for [replication](https://en.wikipedia.org/wiki/Replication_crisis) and code sharing.[^o160]

## Use {#Use}

Thousands of different programming languages have been created, mainly in the computing field.[^o163] Individual software projects commonly use five programming languages or more.[^o164]

Programming languages differ from most other forms of human expression in that they require a greater degree of precision and completeness. When using a natural language to communicate with other people, human authors and speakers can be ambiguous and make small errors, and still expect their intent to be understood. However, figuratively speaking, computers "do exactly what they are told to do", and cannot "understand" what code the programmer intended to write. The combination of the language definition, a program, and the program's inputs must fully specify the external behavior that occurs when the program is executed, within the domain of control of that program. In contrast, ideas about an algorithm can be communicated to humans without the precision needed for execution by using [pseudocode](https://en.wikipedia.org/wiki/Pseudocode), which interleaves natural language with code written in a programming language.

A programming language provides a structured mechanism for defining pieces of data, and the operations or transformations that may be carried out automatically on that data. A [programmer](https://en.wikipedia.org/wiki/Programmer) uses the [abstractions](https://en.wikipedia.org/wiki/Abstraction_%28computer_science%29) present in the language to represent the concepts involved in a computation. These concepts are represented as a collection of the simplest elements available (called [primitives](https://en.wikipedia.org/wiki/Language_primitive)).[^o165] *[Programming](https://en.wikipedia.org/wiki/Computer_Programming)* is the process by which programmers combine these primitives to compose new programs, or adapt existing ones to new uses or a changing environment.

Programs for a computer might be [executed](https://en.wikipedia.org/wiki/Execution_%28computing%29) in a [batch process](https://en.wikipedia.org/wiki/Batch_processing) without any human interaction, or a user might type [commands](https://en.wikipedia.org/wiki/Command_%28computing%29) in an [interactive session](https://en.wikipedia.org/wiki/Session_%28computer_science%29) of an [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29). In this case the "commands" are simply programs, whose execution is chained together. When a language can run its commands through an interpreter (such as a [Unix shell](https://en.wikipedia.org/wiki/Unix_shell) or other [command-line interface](https://en.wikipedia.org/wiki/Command-line_interface)), without compiling, it is called a [scripting language](https://en.wikipedia.org/wiki/Scripting_language).[^o166]

### Measuring language usage {#Measuring_language_usage}

Determining which is the most widely used programming language is difficult since the definition of usage varies by context. One language may occupy the greater number of programmer hours, a different one has more lines of code, and a third may consume the most CPU time. Some languages are very popular for particular kinds of applications. For example, [COBOL](https://en.wikipedia.org/wiki/COBOL) is still strong in the corporate data center, often on large [mainframes](https://en.wikipedia.org/wiki/Mainframes);[^o168][^o169] [Fortran](https://en.wikipedia.org/wiki/Fortran) in scientific and engineering applications; [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29) in aerospace, transportation, military, real-time, and embedded applications; and [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) in embedded applications and operating systems. Other languages are regularly used to write many different kinds of applications.

Various methods of measuring language popularity, each subject to a different bias over what is measured, have been proposed:

- counting the number of job advertisements that mention the language[^o170]
- the number of books sold that teach or describe the language[^o171]
- estimates of the number of existing lines of code written in the language – which may underestimate languages not often found in public searches[^o172]
- counts of language references (i.e., to the name of the language) found using a web search engine.

Combining and averaging information from various internet sites, stackify.com reported the ten most popular programming languages (in descending order by overall popularity): [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29), [JavaScript](https://en.wikipedia.org/wiki/JavaScript), [VB .NET](https://en.wikipedia.org/wiki/VB_.NET), [R](wikipedia://en/376707), [PHP](https://en.wikipedia.org/wiki/PHP), and [MATLAB](wikipedia://en/20412).[^o173]

As of June 2024, the top five programming languages as measured by [TIOBE index](https://en.wikipedia.org/wiki/TIOBE_index) are [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) and [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29). TIOBE provides a list of the top 100 programming languages according to their index and updates this list every month.[^o174]

According to IEEE Spectrum staff, today's most popular programming languages may remain dominant because of how AI works. As a result, new languages will have a harder time gaining popularity since coders will not write many programs in them.[^o175]

## Dialects, flavors and implementations {#Dialects,_flavors_and_implementations}

A **dialect** of a programming language or a [data exchange language](https://en.wikipedia.org/wiki/Data_exchange_language) is a (relatively small) variation or extension of the language that does not change its intrinsic nature. With languages such as [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29) and [Forth](https://en.wikipedia.org/wiki/Forth_%28programming_language%29), standards may be considered insufficient, inadequate, or illegitimate by implementors, so often they will deviate from the standard, making a new [dialect](https://en.wikipedia.org/wiki/Dialect). In other cases, a dialect is created for use in a [domain-specific language](https://en.wikipedia.org/wiki/Domain-specific_language), often a subset. In the [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29) world, most languages that use basic [S-expression](https://en.wikipedia.org/wiki/S-expression) syntax and Lisp-like semantics are considered Lisp dialects, although they vary wildly as do- for example- [Racket](https://en.wikipedia.org/wiki/Racket_%28programming_language%29) and [Clojure](https://en.wikipedia.org/wiki/Clojure). As it is common for one language to have several dialects, it can become quite difficult for an inexperienced programmer to find the right documentation. The [BASIC](https://en.wikipedia.org/wiki/BASIC) language has [many dialects](https://en.wikipedia.org/wiki/List_of_BASIC_dialects).

## Classifications {#Classifications}

Programming languages can be described per the following high-level yet sometimes overlapping classifications:[^n86]

**Imperative**

An [imperative programming](https://en.wikipedia.org/wiki/Imperative_programming) language supports implementing logic encoded as a sequence of ordered operations. Most popularly used languages are classified as imperative.[^n87]

**Functional**

A [functional programming](https://en.wikipedia.org/wiki/Functional_programming) language supports successively applying functions to the given parameters. Although appreciated by many researchers for their simplicity and elegance, problems with efficiency have prevented them from being widely adopted.[^n88]

**Logic**

A [logic programming](https://en.wikipedia.org/wiki/Logic_programming) language is designed so that the software, rather than the programmer, decides what order in which the instructions are executed.[^n89]

**Object-oriented**

[Object-oriented programming](https://en.wikipedia.org/wiki/Object-oriented_programming) (OOP) is characterized by features such as [data abstraction](https://en.wikipedia.org/wiki/Data_abstraction), [inheritance](https://en.wikipedia.org/wiki/Inheritance_%28object-oriented_programming%29), and [dynamic dispatch](https://en.wikipedia.org/wiki/Dynamic_dispatch). OOP is supported by most popular imperative languages and some functional languages.[^n87]

**Markup**

Although a [markup language](https://en.wikipedia.org/wiki/Markup_language) is not a programming language per se, it might support integration with a programming language.

**Special**

There are special-purpose languages that are not easily compared to other programming languages.[^n90]
