# Pretty Good Privacy

::: {#o5 .subject cue=lead name="Pretty Good Privacy"}

**Pretty Good Privacy** (**PGP**) is an [encryption program](wikipedia://en/2285143) that provides [cryptographic](https://en.wikipedia.org/wiki/Cryptographic) [privacy](https://en.wikipedia.org/wiki/Privacy) and [authentication](wikipedia://en/47967) for [data communication](https://en.wikipedia.org/wiki/Data_communication). PGP is used for [signing](wikipedia://en/59644), encrypting, and decrypting texts, [e-mails](https://en.wikipedia.org/wiki/Email), files, directories, and whole disk partitions and to increase the [security](https://en.wikipedia.org/wiki/Security) of e-mail communications. [Phil Zimmermann](wikipedia://en/23486) developed PGP in 1991.[^o6]

:::

The PGP software follows the [OpenPGP](https://en.wikipedia.org/wiki/OpenPGP) standard in the now historical version 4880. The software has not been kept up to date with developments in OpenPGP standardization. While the product is still being sold, its development appears to have stalled sometime around 2010: The current user's guide of "PGP Encryption Desktop for Windows"[^o7] only mentions RSA and Diffie-Hellman key material, and lacks any mention of ECC cryptography (which has been introduced to OpenPGP in 2012 by 6637). The product also has no support for the updated formats in 9580.

Modern versions of PGP are [interoperable](https://en.wikipedia.org/wiki/Interoperability) with [GnuPG](https://en.wikipedia.org/wiki/GnuPG) and other OpenPGP-compliant systems[^o8], when using cryptographic algorithms that both sides of a communication can handle. This algorithmic intersection has been shrinking with time.

## Design {#Design}

Most aspects of PGP design apply more broadly to OpenPGP and are described at OpenPGP.

## Security quality {#Security_quality}

To the best of publicly available information, there is no known method which will allow a person or group to break PGP encryption by cryptographic or computational means. Indeed, in 1995, [cryptographer](https://en.wikipedia.org/wiki/Cryptographer) [Bruce Schneier](wikipedia://en/36732) characterized an early version as being "the closest you're likely to get to military-grade encryption".[^o11] Early versions of PGP have been found to have theoretical vulnerabilities and so current versions are recommended.[^o12] In addition to protecting [data in transit](https://en.wikipedia.org/wiki/Data_in_transit) over a network, PGP encryption can also be used to protect data in long-term data storage such as disk files. These long-term storage options are also known as data at rest, i.e. data stored, not in transit.

The cryptographic security of PGP encryption depends on the assumption that the algorithms used are unbreakable by direct [cryptanalysis](wikipedia://en/5715) with current equipment and techniques.

In the original version, the [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) algorithm was used to encrypt session keys. RSA's security depends upon the [one-way function](wikipedia://en/363890) nature of mathematical [integer factoring](wikipedia://en/15491).[^o13] Similarly, the symmetric key algorithm used in PGP version 2 was [IDEA](wikipedia://en/15076), which might at some point in the future be found to have previously undetected cryptanalytic flaws. Specific instances of current PGP or IDEA insecurities (if they exist) are not publicly known. As current versions of PGP have added additional encryption algorithms, their cryptographic vulnerability varies with the algorithm used. However, none of the algorithms in current use are publicly known to have cryptanalytic weaknesses.

New versions of PGP are released periodically and vulnerabilities fixed by developers as they come to light. Any agency wanting to read PGP messages would probably use easier means than standard cryptanalysis, e.g. [rubber-hose cryptanalysis](https://en.wikipedia.org/wiki/Rubber-hose_cryptanalysis) or [black-bag cryptanalysis](wikipedia://en/10418098) (e.g. installing some form of [trojan horse](https://en.wikipedia.org/wiki/Trojan_horse_%28computing%29) or [keystroke logging](https://en.wikipedia.org/wiki/Keystroke_logging) software or hardware on the target computer to capture encrypted [keyrings](https://en.wikipedia.org/wiki/Keyring_%28cryptography%29) and their passwords). The [FBI](https://en.wikipedia.org/wiki/FBI) has already used this attack against PGP[^o14][^o15] in its investigations. However, any such vulnerabilities apply not just to PGP but to any conventional encryption software.

In 2003, an incident involving seized [Psion](https://en.wikipedia.org/wiki/Psion_%28computers%29) [PDAs](https://en.wikipedia.org/wiki/Personal_digital_assistant) belonging to members of the [Red Brigade](https://en.wikipedia.org/wiki/Red_Brigades) indicated that neither the [Italian police](https://en.wikipedia.org/wiki/Italian_police) nor the FBI were able to decrypt PGP-encrypted files stored on them.[^o16]

A second incident in December 2006, (see *[In re Boucher](https://en.wikipedia.org/wiki/In_re_Boucher)*), involving [US customs agents](https://en.wikipedia.org/wiki/United_States_Customs_Service) who seized a [laptop PC](https://en.wikipedia.org/wiki/Laptop_PC) that allegedly contained [child pornography](https://en.wikipedia.org/wiki/Child_pornography), indicates that US government agencies find it "nearly impossible" to access PGP-encrypted files. Additionally, a magistrate judge ruling on the case in November 2007 has stated that forcing the suspect to reveal his PGP passphrase would violate his [Fifth Amendment](https://en.wikipedia.org/wiki/Fifth_Amendment_to_the_United_States_Constitution) rights i.e. a suspect's constitutional right not to incriminate himself.[^o17][^o18] The Fifth Amendment issue was opened again as the government appealed the case, after which a federal district judge ordered the defendant to provide the key.[^o19]

Evidence suggests that 2007, [British police](https://en.wikipedia.org/wiki/British_police) investigators are unable to break PGP,[^o20] so instead have resorted to using [RIPA](https://en.wikipedia.org/wiki/Regulation_of_Investigatory_Powers_Act_2000) legislation to demand the passwords/keys. In November 2009 a British citizen was convicted under RIPA legislation and jailed for nine months for refusing to provide police investigators with encryption keys to PGP-encrypted files.[^o21]

## History {#History}

### Early history {#Early_history}

[Phil Zimmermann](wikipedia://en/23486) created the first version of PGP encryption in 1991. The name, "Pretty Good Privacy" was inspired by the name of a [grocery](https://en.wikipedia.org/wiki/Grocery) store, "Ralph's Pretty Good Grocery", featured in radio host [Garrison Keillor](https://en.wikipedia.org/wiki/Garrison_Keillor)'s fictional town, [Lake Wobegon](https://en.wikipedia.org/wiki/Lake_Wobegon).[^o24] This first version included a [symmetric-key algorithm](wikipedia://en/53042) that Zimmermann had designed himself, named [BassOmatic](wikipedia://en/8619583) after a *[Saturday Night Live](https://en.wikipedia.org/wiki/Saturday_Night_Live)* sketch. Zimmermann had been a long-time [anti-nuclear activist](https://en.wikipedia.org/wiki/Anti-nuclear_movement), and created PGP encryption so that similarly inclined people might securely use [BBSs](https://en.wikipedia.org/wiki/Bulletin_board_system) and securely store messages and files. No license fee was required for its non-commercial use, and the complete [source code](https://en.wikipedia.org/wiki/Source_code) was included with all copies.

In a posting of June 5, 2001, entitled "PGP Marks 10th Anniversary",[^o25] Zimmermann describes the circumstances surrounding his release of PGP:

It was on this day in 1991 that I sent the first release of PGP to a couple of my friends for uploading to the Internet. First, I sent it to Allan Hoeltje, who posted it to Peacenet, an ISP that specialized in grassroots political organizations, mainly in the peace movement. Peacenet was accessible to political activists all over the world. Then, I uploaded it to Kelly Goen, who proceeded to upload it to a Usenet newsgroup that specialized in distributing source code. At my request, he marked the Usenet posting as "US only". Kelly also uploaded it to many BBS systems around the country. I don't recall if the postings to the Internet began on June 5th or 6th.

It may be surprising to some that back in 1991, I did not yet know enough about Usenet newsgroups to realize that a "US only" tag was merely an advisory tag that had little real effect on how Usenet propagated newsgroup postings. I thought it actually controlled how Usenet routed the posting. But back then, I had no clue how to post anything on a newsgroup, and didn't even have a clear idea what a newsgroup was.

PGP found its way onto the [Internet](https://en.wikipedia.org/wiki/Internet) and rapidly acquired a considerable following around the world. Users and supporters included dissidents in totalitarian countries (some affecting letters to Zimmermann have been published, some of which have been included in testimony before the US Congress), [civil libertarians](https://en.wikipedia.org/wiki/Civil_libertarians) in other parts of the world (see Zimmermann's published testimony in various hearings), and the 'free communications' activists who called themselves [cypherpunks](wikipedia://en/37314) (who provided both publicity and distribution); decades later, [CryptoParty](wikipedia://en/37121257) activists did much the same via [Twitter](https://en.wikipedia.org/wiki/Twitter).

### Criminal investigation {#Criminal_investigation}

Shortly after its release, PGP encryption found its way outside the [United States](https://en.wikipedia.org/wiki/United_States), and in February 1993 Zimmermann became the formal target of a criminal investigation by the US Government for "[munitions](https://en.wikipedia.org/wiki/United_States_Munitions_List) export without a license". At the time, cryptosystems using keys larger than [40 bits](wikipedia://en/487403) were considered munitions within the definition of the [US export regulations](https://en.wikipedia.org/wiki/Export_of_cryptography_in_the_United_States#PC_era); PGP has never used keys smaller than 128 bits, so it qualified at that time. Penalties for violation, if found guilty, were substantial. After several years, the investigation of Zimmermann was closed without filing criminal charges against him or anyone else in 1996.[^o27]

Zimmermann challenged these regulations in an imaginative way. In 1995, he published the entire [source code](https://en.wikipedia.org/wiki/Source_code) of PGP in a hardback book,[^o28] via [MIT Press](https://en.wikipedia.org/wiki/MIT_Press), which was distributed and sold widely. Anybody wishing to build their own copy of PGP could cut off the covers, separate the pages, and scan them using an [OCR](https://en.wikipedia.org/wiki/Optical_character_recognition) program (or conceivably enter it as a [type-in program](https://en.wikipedia.org/wiki/Type-in_program) if OCR software was not available), creating a set of source code text files. One could then build the application using the freely available [GNU Compiler Collection](https://en.wikipedia.org/wiki/GNU_Compiler_Collection). PGP would thus be available anywhere in the world. The claimed principle was simple: export of *munitions*—guns, bombs, planes, and software—was (and remains) restricted; but the export of *books* is protected by the [First Amendment](https://en.wikipedia.org/wiki/First_Amendment_to_the_United_States_Constitution). The question was never tested in court with respect to PGP. In cases addressing other encryption software, however, two federal appeals courts have established the rule that cryptographic software source code is speech protected by the First Amendment (the [Ninth Circuit Court of Appeals](https://en.wikipedia.org/wiki/United_States_Court_of_Appeals_for_the_Ninth_Circuit) in the [Bernstein case](wikipedia://en/340772) and the [Sixth Circuit Court of Appeals](https://en.wikipedia.org/wiki/United_States_Court_of_Appeals_for_the_Sixth_Circuit) in the [Junger case](https://en.wikipedia.org/wiki/Junger_v._Daley)).

[US export regulations](https://en.wikipedia.org/wiki/Export_of_cryptography_in_the_United_States#PC_era) regarding cryptography remain in force, but were liberalized substantially throughout the late 1990s. Since 2000, compliance with the regulations is also much easier. PGP encryption no longer meets the definition of a non-exportable weapon, and can be exported internationally except to seven specific countries and a list of named groups and individuals[^o29] (with whom substantially all US trade is prohibited under various US export controls).

### PGP 3 and founding of PGP Inc. {#PGP_3_and_founding_of_PGP_Inc.}

During this turmoil, Zimmermann's team worked on a new version of PGP encryption called PGP 3. This new version was to have considerable security improvements, including a new certificate structure that fixed small security flaws in the PGP 2.x certificates as well as permitting a certificate to include separate keys for signing and encryption. Furthermore, the experience with patent and export problems led them to eschew patents entirely. PGP 3 introduced the use of the [CAST-128](wikipedia://en/240998) (a.k.a. CAST5) symmetric key algorithm, and the [DSA](wikipedia://en/59470) and [ElGamal](https://en.wikipedia.org/wiki/ElGamal) asymmetric key algorithms, all of which were unencumbered by patents.

After the Federal criminal investigation ended in 1996, Zimmermann and his team started a company to produce new versions of PGP encryption. They merged with Viacrypt (to whom Zimmermann had sold commercial rights and who had [licensed](https://en.wikipedia.org/wiki/Licensed) RSA directly from [RSADSI](https://en.wikipedia.org/wiki/RSADSI)), which then changed its name to PGP Incorporated. The newly combined Viacrypt/PGP team started work on new versions of PGP encryption based on the PGP 3 system. Unlike PGP 2, which was an exclusively [command line](https://en.wikipedia.org/wiki/Command_line) program, PGP 3 was designed from the start as a [software library](https://en.wikipedia.org/wiki/Software_library) allowing users to work from a command line or inside a [GUI](https://en.wikipedia.org/wiki/GUI) environment. The original agreement between Viacrypt and the Zimmermann team had been that Viacrypt would have even-numbered versions and Zimmermann odd-numbered versions. Viacrypt, thus, created a new version (based on PGP 2) that they called PGP 4. To remove confusion about how it could be that PGP 3 was the successor to PGP 4, PGP 3 was renamed and released as PGP 5 in May 1997.

### Network Associates acquisition {#Network_Associates_acquisition}

In December 1997, PGP Inc. was acquired by [Network Associates, Inc.](https://en.wikipedia.org/wiki/Network_Associates,_Inc.) ("NAI"). Zimmermann and the PGP team became NAI employees. NAI was the first company to have a legal export strategy by publishing source code. Under NAI, the PGP team added disk encryption, desktop firewalls, intrusion detection, and [IPsec](https://en.wikipedia.org/wiki/IPsec) [VPNs](https://en.wikipedia.org/wiki/VPN) to the PGP family. After the export regulation liberalizations of 2000 which no longer required publishing of source, NAI stopped releasing source code.[^o32]

### Asset split {#Asset_split}

In early 2001, Zimmermann left NAI. He served as Chief Cryptographer for [Hush Communications](https://en.wikipedia.org/wiki/Hush_Communications), who provide an OpenPGP-based e-mail service, [Hushmail](https://en.wikipedia.org/wiki/Hushmail). He has also worked with Veridis and other companies. In October 2001, NAI announced that its PGP assets were for sale and that it was suspending further development of PGP encryption. The only remaining asset kept was the PGP E-Business Server (the original PGP Commandline version). In February 2002, NAI canceled all support for PGP products, with the exception of the renamed commandline product.[^o34][^o35]

#### McAfee {#McAfee}

NAI, now known as [McAfee](https://en.wikipedia.org/wiki/McAfee), continued to sell and support the commandline product under the name McAfee E-Business Server until 2013.[^o37] In 2010, [Intel Corporation](https://en.wikipedia.org/wiki/Intel_Corporation) acquired [McAfee](https://en.wikipedia.org/wiki/McAfee). In 2013, the McAfee E-Business Server was transferred to Software Diversified Services (SDS), which now sells, supports, and develops it under the name SDS E-Business Server.[^o37][^o34]

For the enterprise, Townsend Security currently offers a commercial version of PGP for the [IBM i](https://en.wikipedia.org/wiki/IBM_i) and [IBM z](https://en.wikipedia.org/wiki/Z/OS) mainframe platforms. Townsend Security partnered with Network Associates in 2000 to create a compatible version of PGP for the IBM i platform. Townsend Security again ported PGP in 2008, this time to the IBM z mainframe. This version of PGP relies on a free z/OS encryption facility, which utilizes hardware acceleration. SDS also offers a commercial version of PGP (SDS E-Business Server) for the [IBM z](https://en.wikipedia.org/wiki/Z/OS) mainframe.

#### PGP Corporation {#PGP_Corporation}

In August 2002, several ex-PGP team members formed a new company, [PGP Corporation](https://en.wikipedia.org/wiki/PGP_Corporation), and bought the PGP assets (except for the command line version) from NAI. The new company was funded by Rob Theis of Doll Capital Management (DCM) and Terry Garnett of Venrock Associates. PGP Corporation supported existing PGP users and honored NAI's support contracts. Zimmermann served as a special advisor and consultant to PGP Corporation while continuing to run his own consulting company. In 2003, PGP Corporation created a new server-based product called PGP Universal. In mid-2004, PGP Corporation shipped its own command line version called PGP Command Line, which integrated with the other PGP Encryption Platform applications. In 2005, PGP Corporation made its first acquisition: the [German](https://en.wikipedia.org/wiki/Germany) software company Glück & Kanja Technology AG,[^o39] which became PGP Deutschland AG.[^o40] In 2010, PGP Corporation acquired Hamburg-based certificate authority TC TrustCenter and its parent company, [ChosenSecurity](https://en.wikipedia.org/wiki/ChosenSecurity), to form its PGP TrustCenter[^o41] division.[^o42]

After the 2002 purchase of NAI's PGP assets, PGP Corporation offered worldwide PGP technical support from its offices in [Draper, Utah](https://en.wikipedia.org/wiki/Draper,_Utah); [Offenbach](https://en.wikipedia.org/wiki/Offenbach_am_Main), [Germany](https://en.wikipedia.org/wiki/Germany); and [Tokyo](https://en.wikipedia.org/wiki/Tokyo), Japan.

##### Symantec {#Symantec}

On April 29, 2010, [Symantec Corp.](https://en.wikipedia.org/wiki/NortonLifeLock) announced that it would acquire PGP Corporation for \$300 million with the intent of integrating it into its Enterprise Security Group.[^o44] This acquisition was finalized and announced to the public on June 7, 2010. The source code of PGP Desktop 10 is available for peer review.[^o45]

In May 2018, a bug named [EFAIL](https://en.wikipedia.org/wiki/EFAIL) was discovered in certain implementations of PGP which from 2003 could reveal the plaintext contents of emails encrypted with it.[^o46][^o47] The chosen mitigation for this vulnerability in PGP Desktop is to mandate the use [SEIP](https://en.wikipedia.org/wiki/SEIP) protected packets in the ciphertext, which can lead to old emails or other encrypted objects to be no longer decryptable after upgrading to the software version that has the mitigation.[^o48]

##### Broadcom {#Broadcom}

On August 9, 2019, [Broadcom Inc.](https://en.wikipedia.org/wiki/Broadcom_Inc.) announced they would be acquiring the Enterprise Security software division of Symantec, which includes PGP Corporation.

## PGP Corporation encryption applications {#PGP_Corporation_encryption_applications}

*This section describes commercial programs available from [PGP Corporation](https://en.wikipedia.org/wiki/PGP_Corporation). For information on other programs compatible with the OpenPGP specification, see External links below.*

While originally used primarily for encrypting the contents of e-mail messages and attachments from a desktop client, PGP products have been diversified since 2002 into a set of encryption applications that can be managed by an optional central policy server. PGP encryption applications include e-mails and attachments, digital signatures, full disk encryption, file and folder security, protection for IM sessions, batch file transfer encryption, and protection for files and folders stored on network servers and, more recently, encrypted or signed HTTP request/responses by means of a client-side (Buanzo's Enigform) and a server-side (also Buanzo's mod\_openpgp) module. There is also a WordPress plugin available, called wp-enigform-authentication, that takes advantage of the session management features of Enigform with mod\_openpgp.

The PGP Desktop 9.x family includes PGP Desktop Email, PGP Whole Disk Encryption, and PGP NetShare. Additionally, a number of Desktop bundles are also available. Depending on the application, the products feature desktop e-mail, digital signatures, IM security, whole disk encryption, file, and folder security, encrypted [self-extracting archives](https://en.wikipedia.org/wiki/Self-extracting_archive), and [secure shredding](https://en.wikipedia.org/wiki/Data_erasure) of deleted files. Capabilities are licensed in different ways depending on the features required.

The PGP Universal Server 2.x management console handles centralized deployment, security policy, policy enforcement, key management, and reporting. It is used for automated e-mail encryption in the gateway and manages PGP Desktop 9.x clients. In addition to its local [keyserver](wikipedia://en/616119), PGP Universal Server works with the PGP public keyserver—called the PGP Global Directory—to find recipient keys. It has the capability of delivering e-mail securely when no recipient key is found via a secure HTTPS browser session.

With PGP Desktop 9.x managed by PGP Universal Server 2.x, first released in 2005, all PGP encryption applications are based on a new proxy-based architecture. These newer versions of PGP software eliminate the use of e-mail plug-ins and insulate the user from changes to other desktop applications. All desktop and server operations are now based on security policies and operate in an automated fashion. The PGP Universal server automates the creation, management, and expiration of keys, sharing these keys among all PGP encryption applications.

The Symantec PGP platform has now undergone a rename. PGP Desktop is now known as Symantec Encryption Desktop (SED), and the PGP Universal Server is now known as Symantec Encryption Management Server (SEMS). The current shipping versions are Symantec Encryption Desktop 10.3.0 (Windows and macOS platforms) and Symantec Encryption Server 3.3.2.

Also available are PGP Command-Line, which enables command line-based encryption and signing of information for storage, transfer, and backup, as well as the PGP Support Package for BlackBerry which enables RIM BlackBerry devices to enjoy sender-to-recipient messaging encryption.

New versions of PGP applications use both OpenPGP and the [S/MIME](https://en.wikipedia.org/wiki/S/MIME), allowing communications with any user of a [NIST](https://en.wikipedia.org/wiki/NIST) specified standard.[^o51]
