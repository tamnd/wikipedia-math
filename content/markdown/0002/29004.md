# SQL

::: {#o3 .subject cue=lead name="SQL"}

**Structured Query Language** (**SQL**) (pronounced *S-Q-L*; or alternatively as "sequel")[^o53][^o4] is a [domain-specific language](https://en.wikipedia.org/wiki/Domain-specific_language) used to manage data, especially in a [relational database management system](https://en.wikipedia.org/wiki/Relational_database_management_system) (RDBMS). It is particularly useful in handling [structured data](wikipedia://en/82871), i.e., data incorporating relations among entities and variables.[^o5]

:::

Introduced in the 1970s, SQL offered two main advantages over older read–write [APIs](https://en.wikipedia.org/wiki/API) such as [ISAM](https://en.wikipedia.org/wiki/ISAM) or [VSAM](https://en.wikipedia.org/wiki/VSAM). Firstly, it introduced the concept of accessing many [records](https://en.wikipedia.org/wiki/Record_%28computer_science%29) with one single [command](https://en.wikipedia.org/wiki/Command-line_interface). Secondly, it eliminates the need to specify *how* to reach a record, i.e., with or without an [index](https://en.wikipedia.org/wiki/Database_index).

Originally based upon [relational algebra](wikipedia://en/175285) and [tuple relational calculus](https://en.wikipedia.org/wiki/Tuple_relational_calculus), SQL consists of many types of statements,[^o6] which may be informally classed as [sublanguages](https://en.wikipedia.org/wiki/Sublanguage), commonly: [data query language](https://en.wikipedia.org/wiki/Data_query_language) (DQL), [data definition language](https://en.wikipedia.org/wiki/Data_definition_language) (DDL), [data control language](https://en.wikipedia.org/wiki/Data_control_language) (DCL), and [data manipulation language](https://en.wikipedia.org/wiki/Data_manipulation_language) (DML).[^o7]

The scope of SQL includes data query, data manipulation (insert, update, and delete), data definition ([schema](https://en.wikipedia.org/wiki/Database_schema) creation and modification), and data access control. Although SQL is essentially a [declarative language](https://en.wikipedia.org/wiki/Declarative_programming) ([4GL](https://en.wikipedia.org/wiki/4GL)), it also includes [procedural](https://en.wikipedia.org/wiki/Procedural_programming) elements.

SQL was one of the first commercial languages to use [Edgar F. Codd](https://en.wikipedia.org/wiki/Edgar_F._Codd)'s [relational model](https://en.wikipedia.org/wiki/Relational_model). The model was described in his influential 1970 paper, "A Relational Model of Data for Large Shared Data Banks".[^o54] Despite not entirely adhering to [the relational model as described by Codd](https://en.wikipedia.org/wiki/Codd's_12_rules), SQL became the most widely used database language.[^o55][^o56]

SQL became a [standard](https://en.wikipedia.org/wiki/Technical_standard) of the [American National Standards Institute](https://en.wikipedia.org/wiki/American_National_Standards_Institute) (ANSI) in 1986 and of the [International Organization for Standardization](https://en.wikipedia.org/wiki/International_Organization_for_Standardization) (ISO) in 1987.[^o57] Since then, the standard has been revised multiple times to include a larger set of features and incorporate common extensions. Despite the existence of standards, virtually no implementations in existence adhere to it fully, and most SQL code requires at least some changes before being ported to different [database](https://en.wikipedia.org/wiki/Database) systems.

## History {#History}

SQL was initially developed at [IBM](https://en.wikipedia.org/wiki/IBM) by [Donald D. Chamberlin](https://en.wikipedia.org/wiki/Donald_D._Chamberlin) and [Raymond F. Boyce](https://en.wikipedia.org/wiki/Raymond_F._Boyce) after learning about the relational model from [Edgar F. Codd](https://en.wikipedia.org/wiki/Edgar_F._Codd)[^o13] in the early 1970s.[^o58] This version, initially called SEQUEL (Structured English Query Language), was designed to manipulate and retrieve data stored in IBM's original quasirelational database management system, [System R](https://en.wikipedia.org/wiki/IBM_System_R), which a group at [IBM San Jose Research Laboratory](https://en.wikipedia.org/wiki/IBM_Almaden_Research_Center) had developed during the 1970s.[^o58]

Chamberlin and Boyce's first attempt at a relational database language was SQUARE (Specifying Queries in A Relational Environment), but it was difficult to use due to subscript/superscript notation. After moving to the San Jose Research Laboratory in 1973, they began work on a sequel to SQUARE.[^o13] The original name SEQUEL, which is widely regarded as a pun on [QUEL](https://en.wikipedia.org/wiki/QUEL_query_languages), the query language of [Ingres](https://en.wikipedia.org/wiki/Ingres_%28database%29),[^o10] was later changed to SQL (dropping the vowels) because "SEQUEL" was a [trademark](https://en.wikipedia.org/wiki/Trademark) of the UK-based [Hawker Siddeley](https://en.wikipedia.org/wiki/Hawker_Siddeley) Dynamics Engineering Limited company.[^o59] The label SQL later became the acronym for Structured Query Language.[^o11]

After testing SQL at customer test sites to determine the usefulness and practicality of the system, IBM began developing commercial products based on their System R prototype, including [System/38](https://en.wikipedia.org/wiki/IBM_System/38), [SQL/DS](https://en.wikipedia.org/wiki/IBM_SQL/DS), and [IBM Db2](https://en.wikipedia.org/wiki/IBM_Db2), which were commercially available in 1979, 1981, and 1983, respectively.[^o60] IBM's endorsement caused the industry to move to SQL from alternatives like QUEL.[^o12]

In the late 1970s, Relational Software, Inc. (now [Oracle Corporation](https://en.wikipedia.org/wiki/Oracle_Corporation)) saw the potential of the concepts described by Codd, Chamberlin, and Boyce, and developed their own SQL-based [RDBMS](https://en.wikipedia.org/wiki/Relational_database) with aspirations of selling it to the [U.S. Navy](https://en.wikipedia.org/wiki/United_States_Navy), [Central Intelligence Agency](https://en.wikipedia.org/wiki/Central_Intelligence_Agency), and other [U.S. government](https://en.wikipedia.org/wiki/Federal_government_of_the_United_States) agencies. In June 1979, Relational Software introduced one of the first commercially available implementations of SQL, [Oracle](https://en.wikipedia.org/wiki/Oracle_Database) V2 (Version2) for [VAX](https://en.wikipedia.org/wiki/VAX) computers.

By 1986, [ANSI](https://en.wikipedia.org/wiki/American_National_Standards_Institute) and [ISO](https://en.wikipedia.org/wiki/International_Organization_for_Standardization) standard groups officially adopted the standard "Database Language SQL" language definition. [New versions of the standard](https://en.wikipedia.org/wiki/SQL_language_revisions) were published in 1989, [1992](https://en.wikipedia.org/wiki/SQL-92), 1996, 1999, 2003, 2006, 2008, 2011,[^o13] 2016 and, most recently, 2023.[^o14]

## Interoperability and standardization {#Interoperability_and_standardization}

### Overview {#Overview}

SQL implementations are incompatible between vendors and do not necessarily completely follow standards. In particular, date and time syntax, string concatenation, `NULL`s, and comparison [case sensitivity](https://en.wikipedia.org/wiki/Case_sensitivity) vary from vendor to vendor. [PostgreSQL](https://en.wikipedia.org/wiki/PostgreSQL)[^o64] and [Mimer SQL](https://en.wikipedia.org/wiki/Mimer_SQL)[^o65] strive for standards compliance, though PostgreSQL does not adhere to the standard in all cases. For example, the folding of unquoted names to lower case in PostgreSQL is incompatible with the SQL standard,[^o18] which says that unquoted names should be folded to upper case.[^o75] Thus, according to the standard, `Foo` should be equivalent to `FOO`, not `foo`.

Popular implementations of SQL commonly omit support for basic features of Standard SQL, such as the `DATE` or `TIME` data types. The most obvious such examples, and incidentally the most popular commercial and proprietary SQL DBMSs, are Oracle (whose `DATE` behaves as `DATETIME`,[^o66][^o67] and lacks a `TIME` type)[^o68] and MS SQL Server (before the 2008 version). As a result, SQL code can rarely be ported between database systems without modifications.

### Reasons for incompatibility {#Reasons_for_incompatibility}

Several reasons for the lack of portability between database systems include:

- The complexity and size of the SQL standard means that most implementers do not support the entire standard.
- The SQL standard does not specify the database behavior in some important areas (e.g., [indices](https://en.wikipedia.org/wiki/Index_%28database%29), file storage), leaving implementations to decide how to behave.
- The SQL standard defers some decisions to individual implementations, such as how to name a results column that was not named explicitly.[^o20]
- The SQL standard precisely specifies the syntax that a conforming database system must implement. However, the standard's specification of the semantics of language constructs is less well-defined, leading to ambiguity.
- Many database vendors have large existing customer bases; where the newer version of the SQL standard conflicts with the prior behavior of the vendor's database, the vendor may be unwilling to break [backward compatibility](https://en.wikipedia.org/wiki/Backward_compatibility).
- Little commercial incentive exists for vendors to make changing database suppliers easier (see [vendor lock-in](https://en.wikipedia.org/wiki/Vendor_lock-in)).
- Users evaluating database software tend to place other factors such as performance higher in their priorities than standards conformance.

### Standardization history {#Standardization_history}

SQL was adopted as a standard by the ANSI in 1986 as SQL-86[^o69] and the ISO in 1987.[^o57] It is maintained by [*ISO/IEC JTC 1, Information technology, Subcommittee SC 32, Data management and interchange*](https://en.wikipedia.org/wiki/ISO/IEC_JTC_1/SC_32).

Until 1996, the [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) (NIST) data-management standards program certified SQL DBMS compliance with the SQL standard. Vendors now self-certify the compliance of their products.[^o70]

The original standard declared that the official pronunciation for "SQL" was an [initialism](https://en.wikipedia.org/wiki/Initialism): ("ess cue el").[^o55] Regardless, many English-speaking database professionals (including Donald Chamberlin himself[^o71]) use the [acronym](https://en.wikipedia.org/wiki/Acronym)-like pronunciation of ("sequel"),[^o72] mirroring the language's prerelease development name, "SEQUEL".[^o58][^o59][^o71] The SQL standard has gone through a number of revisions:

### Current standard {#Current_standard}

The standard is commonly denoted by the pattern: *ISO/IEC 9075-n:yyyy Part n: title*, or, as a shortcut, *[ISO/IEC 9075](https://en.wikipedia.org/wiki/ISO/IEC_9075)*. Interested parties may purchase the standards documents from ISO,[^o25] IEC, or ANSI. Some old drafts are freely available.[^o75][^o76]

*[ISO/IEC 9075](https://en.wikipedia.org/wiki/ISO/IEC_9075)* is complemented by *ISO/IEC 13249: SQL Multimedia and Application Packages* and some *Technical reports*.

## Syntax {#Syntax}

The SQL language is subdivided into several language elements, including:

- *Clauses*, which are constituent components of statements and queries. (In some cases, these are optional.)[^o61]
- *Expressions*, which can produce either [scalar](https://en.wikipedia.org/wiki/Scalar_%28computing%29) values, or [tables](https://en.wikipedia.org/wiki/Table_%28database%29) consisting of [columns](https://en.wikipedia.org/wiki/Column_%28database%29) and [rows](https://en.wikipedia.org/wiki/Row_%28database%29) of data
- *Predicates*, which specify conditions that can be evaluated to SQL [three-valued logic (3VL)](wikipedia://en/249904) (true/false/unknown) or [Boolean](https://en.wikipedia.org/wiki/Boolean_logic) [truth values](wikipedia://en/161711) and are used to limit the effects of statements and queries, or to change program flow.
- *Queries*, which retrieve the data based on specific criteria. This is an important element of *SQL*.
- *Statements*, which may have a persistent effect on schemata and data, or may control [transactions](https://en.wikipedia.org/wiki/Database_transaction), program flow, connections, sessions, or diagnostics.
  - SQL statements also include the [semicolon](https://en.wikipedia.org/wiki/Semicolon) (";") statement terminator. Though not required on every platform, it is defined as a standard part of the SQL grammar.
- *[Insignificant whitespace](https://en.wikipedia.org/wiki/Whitespace_%28computer_science%29)* is generally ignored in SQL statements and queries, making it easier to format SQL code for readability.

## Procedural extensions {#Procedural_extensions}

SQL is designed for a specific purpose: to query [data](https://en.wikipedia.org/wiki/Data) contained in a [relational database](https://en.wikipedia.org/wiki/Relational_database). SQL is a [set](https://en.wikipedia.org/wiki/Set_%28computer_science%29)-based, [declarative programming language](https://en.wikipedia.org/wiki/Declarative_programming_language), not an [imperative programming language](https://en.wikipedia.org/wiki/Imperative_programming_language) like [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) or [BASIC](https://en.wikipedia.org/wiki/BASIC). However, extensions to Standard SQL add [procedural programming language](https://en.wikipedia.org/wiki/Procedural_programming_language) functionality, such as control-of-flow constructs.

In addition to the standard [SQL/PSM](https://en.wikipedia.org/wiki/SQL/PSM) extensions and proprietary SQL extensions, procedural and [object-oriented](https://en.wikipedia.org/wiki/Object-oriented_programming_language) programmability is available on many SQL platforms via DBMS integration with other languages. The SQL standard defines [SQL/JRT](https://en.wikipedia.org/wiki/SQL/JRT) extensions (SQL Routines and Types for the Java Programming Language) to support [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) code in SQL databases. [Microsoft SQL Server 2005](https://en.wikipedia.org/wiki/Microsoft_SQL_Server_2005) uses the [SQLCLR](https://en.wikipedia.org/wiki/SQLCLR) (SQL Server Common Language Runtime) to host managed [.NET](https://en.wikipedia.org/wiki/Microsoft_.NET) assemblies in the [database](https://en.wikipedia.org/wiki/Database), while prior versions of SQL Server were restricted to unmanaged extended stored procedures primarily written in C. [PostgreSQL](https://en.wikipedia.org/wiki/PostgreSQL) lets users write functions in a wide variety of languages—including [Perl](https://en.wikipedia.org/wiki/Perl), [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [Tcl](https://en.wikipedia.org/wiki/Tcl_%28programming_language%29), [JavaScript](https://en.wikipedia.org/wiki/JavaScript) (PL/V8) and C.[^o62]

## Alternatives {#Alternatives}

A distinction should be made between alternatives to SQL as a language, and alternatives to the relational model itself. Below are proposed relational alternatives to the SQL language. See [navigational database](https://en.wikipedia.org/wiki/Navigational_database) and [NoSQL](https://en.wikipedia.org/wiki/NoSQL) for alternatives to the relational model.

- [.QL](https://en.wikipedia.org/wiki/.QL): object-oriented Datalog
- [4D Query Language](https://en.wikipedia.org/wiki/4th_Dimension_%28Software%29) (4D QL)
- [Datalog](https://en.wikipedia.org/wiki/Datalog): critics suggest that [Datalog](https://en.wikipedia.org/wiki/Datalog) has two advantages over SQL: it has cleaner semantics, which facilitates program understanding and maintenance, and it is more expressive, in particular for recursive queries.[^o63]
- [HTSQL](https://en.wikipedia.org/wiki/HTSQL): URL based query method
- [IBM Business System 12](https://en.wikipedia.org/wiki/IBM_Business_System_12) (IBM BS12): one of the first fully relational database management systems, introduced in 1982
- [ISBL](https://en.wikipedia.org/wiki/ISBL)
- [jOOQ](https://en.wikipedia.org/wiki/Java_Object_Oriented_Querying): SQL implemented in Java as an [internal domain-specific language](https://en.wikipedia.org/wiki/Domain-specific_language)
- [Java Persistence Query Language](https://en.wikipedia.org/wiki/Java_Persistence_Query_Language) (JPQL): The query language used by the Java Persistence API and [Hibernate](https://en.wikipedia.org/wiki/Hibernate_%28Java%29) persistence library
- [JavaScript](https://en.wikipedia.org/wiki/JavaScript): [MongoDB](https://en.wikipedia.org/wiki/MongoDB) implements its query language in a JavaScript API.
- [LINQ](https://en.wikipedia.org/wiki/Language_Integrated_Query): Runs SQL statements written like language constructs to query collections directly from inside [.Net](https://en.wikipedia.org/wiki/.NET_Framework) code
- [Object Query Language](https://en.wikipedia.org/wiki/Object_Query_Language)
- QBE ([Query By Example](https://en.wikipedia.org/wiki/Query_By_Example)) created by Moshè Zloof, IBM 1977
- [QUEL](https://en.wikipedia.org/wiki/QUEL_query_languages) introduced in 1974 by the U.C. Berkeley Ingres project, closer to [tuple relational calculus](https://en.wikipedia.org/wiki/Tuple_relational_calculus) than SQL
- [XQuery](https://en.wikipedia.org/wiki/XQuery)

## Distributed SQL processing {#Distributed_SQL_processing}

[Distributed Relational Database Architecture](https://en.wikipedia.org/wiki/DRDA) (DRDA) was designed by a workgroup within IBM from 1988 to 1994. DRDA enables network-connected relational databases to cooperate to fulfill SQL requests.[^o33][^o34]

An interactive user or program can issue SQL statements to a local RDB and receive tables of data and status indicators in reply from remote RDBs. SQL statements can also be compiled and stored in remote RDBs as packages and then invoked by package name. This is important for the efficient operation of application programs that issue complex, high-frequency queries. It is especially important when the tables to be accessed are located in remote systems.

The messages, protocols, and structural components of DRDA are defined by the [Distributed Data Management Architecture](https://en.wikipedia.org/wiki/Distributed_Data_Management_Architecture). Distributed SQL processing ala DRDA is distinctive from contemporary [distributed SQL](https://en.wikipedia.org/wiki/Distributed_SQL) databases.

## Criticisms {#Criticisms}

### Design {#Design}

SQL deviates in several ways from its theoretical foundation, the relational model and its tuple calculus. In that model, a table is a [set](wikipedia://en/26691) of tuples, while in SQL, tables and query results are [lists](https://en.wikipedia.org/wiki/List_%28computing%29) of rows; the same row may occur multiple times, and the order of rows can be employed in queries (e.g., in the `LIMIT` clause). Critics argue that SQL should be replaced with a language that returns strictly to the original foundation: for example, see *The Third Manifesto* by Hugh Darwen and C.J. Date (2006, ).

### Orthogonality and completeness {#Orthogonality_and_completeness}

Early specifications did not support major features, such as primary keys. Result sets could not be named, and subqueries had not been defined. These were added in 1992.[^o13]

The lack of [sum types](https://en.wikipedia.org/wiki/Sum_type) has been described as a roadblock to full use of SQL's user-defined types. JSON support, for example, needed to be added by a new standard in 2016.[^o39]

### Null {#Null}

The concept of [Null](https://en.wikipedia.org/wiki/Null_%28SQL%29) is the subject of some [debate](https://en.wikipedia.org/wiki/Null_%28SQL%29#Criticisms). The Null marker indicates the absence of a value, and is distinct from a value of 0 for an integer column or an empty string for a text column. The concept of Nulls enforces the [3-valued-logic in SQL](https://en.wikipedia.org/wiki/Null_%28SQL%29#Comparisons_with_NULL_and_the_three-valued_logic_%283VL%29), which is a concrete implementation of the general [3-valued logic](wikipedia://en/249904).[^o13]

### Duplicates {#Duplicates}

Another popular criticism is that it allows duplicate rows, making integration with languages such as [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), whose data types might make accurately representing the data difficult,[^o13] in terms of parsing and by the absence of modularity. This is usually avoided by declaring a primary key, or a unique constraint, with one or more columns that uniquely identify a row in the table.

### Impedance mismatch {#Impedance_mismatch}

In a sense similar to [object–relational impedance mismatch](https://en.wikipedia.org/wiki/Object–relational_impedance_mismatch), a mismatch occurs between the declarative SQL language and the procedural languages in which SQL is typically embedded.[^o43]

## SQL data types {#SQL_data_types}

The SQL standard defines three kinds of [data types](https://en.wikipedia.org/wiki/Data_type) (chapter 4.1.1 of SQL/Foundation):

- predefined data types
- constructed types
- user-defined types.

*Constructed types* are one of `ARRAY`, `MULTISET`, `REF` (reference), or `ROW`. *User-defined types* are comparable to classes in object-oriented language with their own constructors, observers, mutators, methods, inheritance, overloading, overwriting, interfaces, and so on. *Predefined data types* are intrinsically supported by the implementation.

### Predefined data types {#Predefined_data_types}

- Character types
  - Character (`CHAR`)
  - Character varying (`VARCHAR`)
  - Character large object (`CLOB`)
- National character types
  - National character (`NCHAR`)
  - National character varying (`NCHAR VARYING`)
  - National character large object (`NCLOB`)
- Binary types
  - Binary (`BINARY`)
  - Binary varying (`VARBINARY`)
  - Binary large object (`BLOB`)
- Numeric types
  - Exact numeric types (`NUMERIC`, `DECIMAL`, `SMALLINT`, `INTEGER`, `BIGINT`)
  - Approximate numeric types (`FLOAT`, `REAL`, `DOUBLE PRECISION`)
  - Decimal floating-point type (`DECFLOAT`)
- Datetime types (`DATE`, `TIME`, `TIMESTAMP`)
- Interval type (`INTERVAL`)
- Boolean
- XML (see [SQL/XML](https://en.wikipedia.org/wiki/SQL/XML))[^o47]
- [JSON](https://en.wikipedia.org/wiki/JSON)

:::
