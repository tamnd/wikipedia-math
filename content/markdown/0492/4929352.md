# Smallest grammar problem

::: {#o1 .subject cue=lead name="Smallest grammar problem"}

In [data compression](wikipedia://en/8013) and the theory of [formal languages](wikipedia://en/10939), the **smallest grammar problem** is the problem of finding the smallest [context-free grammar](wikipedia://en/6759) that generates a given [string](wikipedia://en/27701) of characters (but no other string). The size of a grammar is defined by some authors as the number of symbols on the right side of the production rules.[^o5] Others also add the number of rules to that.[^o2] A grammar that generates only a single string, as required for the solution to this problem, is called a [straight-line grammar](https://en.wikipedia.org/wiki/Straight-line_grammar).[^o3]

:::

Every [binary string](https://en.wikipedia.org/wiki/Binary_string) of length $n$ has a grammar of length $O(n/\log n)$, as expressed using [big O notation](wikipedia://en/44578).[^o3] For binary [de Bruijn sequences](wikipedia://en/1565267), no better length is possible.[^o4]

The (decision version of the) smallest grammar problem is [NP-complete](https://en.wikipedia.org/wiki/NP-complete).[^o5] It can be approximated in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) to within a logarithmic [approximation ratio](https://en.wikipedia.org/wiki/Approximation_ratio); more precisely, the ratio is $O(\log\tfrac{n}{g})$ where $n$ is the length of the given string and $g$ is the size of its smallest grammar. It is hard to approximate to within a constant approximation ratio. An improvement of the approximation ratio to $o(\log n/\log\log n)$ would also improve certain algorithms for approximate [addition chains](wikipedia://en/578656).[^o6]
