# Skein (hash function)

::: {#o1 .subject cue=lead name="Skein"}

*Image: Skein Mix Function.png.* Threefish Mix Function

**Skein** is a [cryptographic hash function](wikipedia://en/439526) and one of five finalists in the [NIST hash function competition](wikipedia://en/20051952). Entered as a candidate to become the [SHA-3](wikipedia://en/20394543) standard, the successor of [SHA-1](wikipedia://en/26672) and [SHA-2](wikipedia://en/1638777), it ultimately lost to NIST hash candidate [Keccak](https://en.wikipedia.org/wiki/Keccak).[^o3]

:::

The name Skein refers to how the Skein function intertwines the input, similar to a skein of yarn.[^o4] Skein was designed to natively support arbitrary, variable-length outputs, so it can be considered an [extendable-output function](https://en.wikipedia.org/wiki/Extendable-output_function) (XOF).

## History {#History}

Skein was created by [Bruce Schneier](wikipedia://en/36732), [Niels Ferguson](wikipedia://en/204933), [Stefan Lucks](https://en.wikipedia.org/wiki/Stefan_Lucks), Doug Whiting, [Mihir Bellare](https://en.wikipedia.org/wiki/Mihir_Bellare), Tadayoshi Kohno, [Jon Callas](https://en.wikipedia.org/wiki/Jon_Callas) and Jesse Walker.

Skein is based on the [Threefish](wikipedia://en/20019277) [tweakable](https://en.wikipedia.org/wiki/Tweakable_block_cipher) [block cipher](wikipedia://en/4594) compressed using [Unique Block Iteration](https://en.wikipedia.org/wiki/Unique_Block_Iteration) (UBI) chaining mode, a variant of the [Matyas–Meyer–Oseas](https://en.wikipedia.org/wiki/Matyas–Meyer–Oseas) hash mode,[^o6] while leveraging an optional low-overhead argument-system for flexibility.

Skein's algorithm and a [reference implementation](https://en.wikipedia.org/wiki/Reference_implementation) was given to [public domain](https://en.wikipedia.org/wiki/Public_domain).[^o7]

## Functionality {#Functionality}

Skein supports internal state sizes of 256, 512 and 1024 bits, and arbitrary output sizes.[^o9]

The authors claim 6.1 [cycles per byte](https://en.wikipedia.org/wiki/Cycles_per_byte) for any output size on an [Intel Core 2](https://en.wikipedia.org/wiki/Intel_Core_2) Duo in 64-bit mode.[^o10]

The core of Threefish is based on a MIX function that transforms 2 64-bit words using a single addition, rotation by a constant and XOR. The UBI chaining mode combines an input chaining value with an arbitrary length input string and produces a fixed size output.

Threefish's [nonlinearity](https://en.wikipedia.org/wiki/Nonlinearity) comes entirely from the combination of addition operations and [exclusive-ORs](wikipedia://en/105979); it does not use [S-boxes](wikipedia://en/240991). The function is optimized for 64-bit processors, and the Skein paper defines optional features such as randomized [hashing](https://en.wikipedia.org/wiki/Hash_function), [parallelizable](https://en.wikipedia.org/wiki/Parallelizable) [tree hashing](wikipedia://en/2497388), a [stream cipher](wikipedia://en/49007), personalization, and a [key derivation function](wikipedia://en/449781).

## Cryptanalysis {#Cryptanalysis}

In October 2010, an attack that combines [rotational cryptanalysis](wikipedia://en/26122724) with the [rebound attack](https://en.wikipedia.org/wiki/Rebound_attack) was published. The attack finds rotational collisions for 53 of 72 rounds in Threefish-256, and 57 of 72 rounds in Threefish-512. It also affects the Skein hash function.[^o12] This is a follow-up to the earlier attack published in February, which breaks 39 and 42 rounds respectively.[^o13]

The Skein team tweaked the [key schedule](wikipedia://en/609603) constant for round 3 of the NIST hash function competition, to make this attack less effective, even though they believe the hash would still be secure without these tweaks.[^o4]
