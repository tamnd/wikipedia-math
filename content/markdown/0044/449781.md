# Key derivation function

::: {#o1 .subject cue=lead name="Key derivation function"}

*Image: KDF chain.png.* Example of a Key Derivation Function chain as used in the [Signal Protocol](wikipedia://en/50607084). The output of one KDF function is the input to the next KDF function in the chain.

In [cryptography](wikipedia://en/18934432), a **key derivation function** (**KDF**) is an [algorithm](wikipedia://en/775) that derives one or more [secret keys](wikipedia://en/53039) from a secret value, such as a master key, a [password](wikipedia://en/24304), or a [passphrase](https://en.wikipedia.org/wiki/Passphrase) using a [pseudorandom function](https://en.wikipedia.org/wiki/Pseudorandom_function) (which typically uses a [cryptographic hash function](wikipedia://en/439526) or [block cipher](wikipedia://en/4594)).[^o2]8018[^o3] KDFs can be used to stretch keys into longer keys or to obtain keys of a required format, such as converting a group element that is the result of a [Diffie–Hellman key exchange](wikipedia://en/7903) into a symmetric key for use with [AES](wikipedia://en/1260). [Keyed cryptographic hash functions](wikipedia://en/17112) are popular examples of pseudorandom functions used for key derivation.[^o4]

:::

## Key derivation {#Key_derivation}

The original use for a KDF is key derivation, the generation of keys from secret passwords or passphrases. Variations on this theme include:

- In conjunction with non-secret parameters to derive one or more keys from a common secret value (which is sometimes also referred to as "**key diversification**"). Such use may prevent an attacker who obtains a derived key from learning useful information about either the input secret value or any of the other derived keys. A KDF may also be used to ensure that derived keys have other desirable properties, such as avoiding "weak keys" in some specific encryption systems.
- As components of multiparty [key-agreement protocols](wikipedia://en/63944). Examples of such key derivation functions include KDF1, defined in [IEEE Std 1363-2000](wikipedia://en/1644154), and similar functions in ANSI X9.42.
- To derive keys from secret passwords or passphrases (a *password-based KDF*).
- To derive keys of different length from the ones provided. KDFs designed for this purpose include [HKDF](wikipedia://en/34278662) and SSKDF. These take an 'info' bit string as an additional optional 'info' parameter, which may be crucial to bind the derived key material to application- and context-specific information.[^o6]
- [Key stretching](wikipedia://en/4266286) and key strengthening.

### Key stretching and key strengthening {#Key_stretching_and_key_strengthening}

Key derivation functions are also used in applications to derive keys from secret passwords or passphrases, which typically do not have the desired properties to be used directly as cryptographic keys. In such applications, it is generally recommended that the key derivation function be made deliberately slow so as to frustrate [brute-force attack](wikipedia://en/53784) or [dictionary attack](wikipedia://en/53785) on the password or passphrase input value.

Such use may be expressed as $\operatorname{DK} = \operatorname{KDF}(\operatorname{key}, \operatorname{salt}, \operatorname{iterations})$, where $\operatorname{DK}$ is the derived key, $\operatorname{KDF}$ is the key derivation [function](https://en.wikipedia.org/wiki/Subroutine), $\operatorname{key}$ is the original key or password, $\operatorname{salt}$ is a random number which acts as [cryptographic salt](wikipedia://en/701756), and $\operatorname{iterations}$ refers to the number of [iterations](wikipedia://en/68833) of a sub-function. The derived key is used instead of the original key or password as the key to the system. The values of the salt and the number of iterations (if it is not fixed) are stored with the hashed password or sent as [cleartext](wikipedia://en/157935) (unencrypted) with an encrypted message.[^o8]

The difficulty of a brute force attack is increased with the number of iterations. A practical limit on the iteration count is the unwillingness of users to tolerate a perceptible delay in logging into a computer or seeing a decrypted message. The use of [salt](wikipedia://en/701756) prevents the attackers from precomputing a dictionary of derived keys.[^o8]

An alternative approach, called **key strengthening**, extends the key with a random salt, but then (unlike in key stretching) securely deletes the salt.[^o9] This forces both the attacker and legitimate users to perform a brute-force search for the salt value.[^o10] Although the paper that introduced key stretching[^o11] referred to this earlier technique and intentionally chose a different name, the term "key strengthening" is now often (arguably incorrectly) used to refer to key stretching.

## Deriving keys from passwords {#Deriving_keys_from_passwords}

High-throughput (keyed) cryptographic hash functions are inappropriate for generating cryptographic keys from low-entropy secrets like passwords, as if the function is quick to evaluate a small search space can quickly be exhaustively searched.

### History of password hash functions {#History_of_password_hash_functions}

The first deliberately slow (key stretching) password-based key derivation function was called "[crypt](wikipedia://en/38472580)" (or "crypt(3)" after its [man page](https://en.wikipedia.org/wiki/Manual_page_%28Unix%29)), and was invented by [Robert Morris](wikipedia://en/230338) in 1978. It would encrypt a constant (zero), using the first 8 characters of the user's password as the key, by performing 25 iterations of a modified [DES](wikipedia://en/7978) encryption algorithm (in which a 12-bit number read from the real-time computer clock is used to perturb the calculations). The resulting 64-bit number is encoded as 11 printable characters and then stored in the [Unix](https://en.wikipedia.org/wiki/Unix) password file.[^o14] While it was a great advance at the time, increases in processor speeds since the [PDP-11](https://en.wikipedia.org/wiki/PDP-11) era have made [brute-force attacks](wikipedia://en/53784) against crypt [feasible](https://en.wikipedia.org/wiki/Feasible_computability), and advances in storage have rendered the 12-bit [salt](wikipedia://en/701756) inadequate. The crypt function's design also limits the user password to 8 characters, which limits the keyspace and makes strong [passphrases](https://en.wikipedia.org/wiki/Passphrase) impossible.

Although high throughput is a desirable property in general-purpose hash functions, the opposite is true in password security applications in which defending against brute-force cracking is a primary concern. The growing use of [massively-parallel](https://en.wikipedia.org/wiki/Massively_parallel) hardware such as [GPUs](https://en.wikipedia.org/wiki/Graphics_processing_unit), [FPGAs](https://en.wikipedia.org/wiki/Field-programmable_gate_array), and even [ASICs](https://en.wikipedia.org/wiki/Application-specific_integrated_circuit) for brute-force cracking has made the selection of a suitable algorithms even more critical because the good algorithm should enforce a certain amount of computational cost not only on CPUs, but also resist the cost/performance advantages of modern massively-parallel platforms for such tasks. Various algorithms have been designed specifically for this purpose, including [bcrypt](wikipedia://en/21564294), [scrypt](https://en.wikipedia.org/wiki/Scrypt) and, more recently, [Lyra2](wikipedia://en/49892678) and [Argon2](wikipedia://en/48963187) (the latter being the winner of the [Password Hashing Competition](https://en.wikipedia.org/wiki/Password_Hashing_Competition)). The large-scale [Ashley Madison data breach](https://en.wikipedia.org/wiki/Ashley_Madison_data_breach) in which roughly 36 million passwords hashes were stolen by attackers illustrated the importance of algorithm selection in securing passwords. Although bcrypt was employed to protect the hashes (making large scale brute-force cracking expensive and time-consuming), a significant portion of the accounts in the compromised data also contained a password hash based on the fast, general-purpose, and [insecure](wikipedia://en/18826#Security) [MD5](wikipedia://en/18826) algorithm, which made it possible for over 11 million of the passwords to be cracked in a matter of weeks.[^o15]

In June 2017, The U.S. National Institute of Standards and Technology (NIST) issued a new revision of their digital authentication guidelines, NIST SP 800-63B-3,[^o16] stating that: "Verifiers SHALL store memorized secrets \[i.e. passwords\] in a form that is resistant to offline attacks. Memorized secrets SHALL be salted and hashed using a suitable one-way key derivation function. Key derivation functions take a password, a salt, and a cost factor as inputs then generate a password hash. Their purpose is to make each password guessing trial by an attacker who has obtained a password hash file expensive and therefore the cost of a guessing attack high or prohibitive."

Modern password-based key derivation functions, such as [PBKDF2](wikipedia://en/1568244),8018 are based on a recognized cryptographic hash, such as [SHA-2](wikipedia://en/1638777), use more salt (at least 64 bits and chosen randomly) and a high iteration count. NIST recommends a minimum iteration count of 10,000.[^o16] "For especially critical keys, or for very powerful systems or systems where user-perceived performance is not critical, an iteration count of 10,000,000 may be appropriate.” [^o17]

Despite their original use for key derivation, KDFs are possibly better known for their use in **password hashing** ([password verification by hash comparison](wikipedia://en/439526#Password_verification)), as used by the [passwd](https://en.wikipedia.org/wiki/Passwd) file or [shadow password](https://en.wikipedia.org/wiki/Shadow_password) file. Password hash functions should be relatively expensive to calculate in case of brute-force attacks, and KDFs are designed with this characteristic built in.[^o18] The non-secret parameters are called "[salt](wikipedia://en/701756)" in this context.

In 2013 a [Password Hashing Competition](https://en.wikipedia.org/wiki/Password_Hashing_Competition) was announced to choose a new, standard algorithm for password hashing. On 20 July 2015 the competition ended and [Argon2](wikipedia://en/48963187) was announced as the final winner. Four other algorithms received special recognition: Catena, [Lyra2](wikipedia://en/49892678), Makwa and [yescrypt](wikipedia://en/55569844).[^o19]

As of May 2023, the [Open Worldwide Application Security Project](https://en.wikipedia.org/wiki/OWASP) (OWASP) recommends the following KDFs for password hashing, listed in order of priority:[^o20]

1. [Argon2id](wikipedia://en/48963187)
1. [scrypt](https://en.wikipedia.org/wiki/Scrypt) if Argon2id is unavailable
1. [bcrypt](wikipedia://en/21564294) for legacy systems
1. [PBKDF2](wikipedia://en/1568244) if [FIPS-140](https://en.wikipedia.org/wiki/FIPS-140) compliance is required
