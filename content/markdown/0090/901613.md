# Logical framework

::: {#o1 .subject cue=lead name="Logical framework"}

In [logic](wikipedia://en/46426065), a **logical framework** provides a means to define (or present) a logic as a signature in a higher-order [type theory](wikipedia://en/40282) in such a way that [provability](wikipedia://en/618119) of a formula in the original logic reduces to a [type inhabitation](https://en.wikipedia.org/wiki/Type_inhabitation) problem in the framework type theory.[^o2][^o3] This approach has been used successfully for (interactive) [automated theorem proving](wikipedia://en/2546). The first logical framework was [Automath](https://en.wikipedia.org/wiki/Automath); however, the name of the idea comes from the more widely known Edinburgh Logical Framework, **LF**. Several more recent proof tools like [Isabelle](https://en.wikipedia.org/wiki/Isabelle_%28theorem_prover%29) are based on this idea.[^o2] Unlike a direct embedding, the logical framework approach allows many logics to be embedded in the same type system.[^o4]

:::

## Overview {#Overview}

A logical framework is based on a general treatment of syntax, rules and proofs by means of a [dependently typed lambda calculus](https://en.wikipedia.org/wiki/Dependent_type_theory). Syntax is treated in a style similar to, but more general than [Per Martin-Löf](wikipedia://en/1925764)'s system of arities.

To describe a logical framework, one must provide the following:

1. A characterization of the class of object-logics to be represented;
1. An appropriate meta-language;
1. A characterization of the mechanism by which object-logics are represented.

This is summarized by:

"*Framework = Language + Representation*."

::: {#o7 .pointer-item cue=pointer name="Edinburgh Logical Framework"}

## LF {#LF}

In the case of the **LF logical framework**, the meta-language is the [λΠ-calculus](https://en.wikipedia.org/wiki/ΛΠ-calculus). This is a system of first-order dependent function types which are related by the [propositions as types principle](https://en.wikipedia.org/wiki/Propositions_as_types_principle) to [first-order](wikipedia://en/10983) [minimal logic](wikipedia://en/26267678). The key features of the λΠ-calculus are that it consists of entities of three levels: objects, types and kinds (or type classes, or families of types). It is [predicative](wikipedia://en/1930406), all well-typed terms are [strongly normalizing](https://en.wikipedia.org/wiki/Strongly_normalizing) and [Church-Rosser](https://en.wikipedia.org/wiki/Church-Rosser) and the property of being well-typed is [decidable](wikipedia://en/913118). However, [type inference](wikipedia://en/279690) is undecidable.

A logic is represented in the **LF logical framework** by the judgements-as-types representation mechanism. This is inspired by [Per Martin-Löf](wikipedia://en/1925764)'s development of [Kant](https://en.wikipedia.org/wiki/Immanuel_Kant)'s notion of [judgement](https://en.wikipedia.org/wiki/Judgement_%28mathematical_logic%29), in the 1983 Siena Lectures. The two higher-order judgements, the hypothetical $J\vdash K$ and the general, $\Lambda x\in J. K(x)$, correspond to the ordinary and dependent function space, respectively. The methodology of judgements-as-types is that judgements are represented as the types of their proofs. A [logical system](https://en.wikipedia.org/wiki/Logical_system) ${\mathcal L}$ is represented by its signature which assigns kinds and types to a finite set of constants that represents its syntax, its judgements and its rule schemes. An object-logic's rules and proofs are seen as primitive proofs of hypothetico-general judgements $\Lambda x\in C. J(x)\vdash K$.

An implementation of the LF logical framework is provided by the [Twelf](https://en.wikipedia.org/wiki/Twelf) system at [Carnegie Mellon University](https://en.wikipedia.org/wiki/Carnegie_Mellon_University). Twelf includes

- a logic programming engine
- meta-theoretic reasoning about logic programs (termination, coverage, etc.)
- an inductive [meta-logical](https://en.wikipedia.org/wiki/Meta-logic) theorem prover
