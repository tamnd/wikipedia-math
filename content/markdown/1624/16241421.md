# Boneh–Franklin scheme

::: {#o1 .subject cue=lead name="Boneh–Franklin scheme"}

The **Boneh–Franklin scheme** is an [identity-based encryption](https://en.wikipedia.org/wiki/ID-based_encryption) system proposed by [Dan Boneh](https://en.wikipedia.org/wiki/Dan_Boneh) and [Matthew K. Franklin](https://en.wikipedia.org/wiki/Matthew_K._Franklin) in 2001.[^o2] This article refers to the protocol version called **BasicIdent**. It is an application of [pairings](wikipedia://en/1191490#Pairings_in_cryptography) ([Weil pairing](https://en.wikipedia.org/wiki/Weil_pairing)) over [elliptic curves](https://en.wikipedia.org/wiki/Elliptic_curves) and [finite fields](https://en.wikipedia.org/wiki/Finite_fields).

:::

## Groups and parameters {#Groups_and_parameters}

As the scheme is based upon [pairings](wikipedia://en/1191490#Pairings_in_cryptography), all computations are performed in two groups, $\textstyle G_1$ and $\textstyle G_2$:

For $\textstyle G_1$, let $\textstyle p$ be prime, $\textstyle p \equiv 2 \mod 3$ and consider the [elliptic curve](wikipedia://en/10225) $\textstyle E: y^2 = x^3 + 1$ over $\textstyle \mathbb{Z}/p\mathbb{Z}$. Note that this curve is not singular as $\textstyle 4a^3+27b^2 = 27 = 3^3$ only equals $\textstyle 0$ for the case $\textstyle p = 3$ which is excluded by the additional constraint.

Let $\textstyle q > 3$ be a prime factor of $\textstyle p + 1$ (which is the order of $\textstyle E$) and find a point $\textstyle P \in E$ of order $\textstyle q$. $\textstyle G_1$ is the set of points generated by $\textstyle P$: $\textstyle \left\{nP \| n \in \left\{0,\ldots,q-1\right\} \right\}$

$\textstyle G_2$ is the subgroup of order $\textstyle q$ of $\textstyle GF\left(p^2\right)^*$. We do not need to construct this group explicitly (this is done by the pairing) and thus don't have to find a generator.

$\textstyle G_1$ is considered an [additive group](wikipedia://en/332229), being a subgroup of the additive group of points of $\textstyle E$, while $\textstyle G_2$ is considered a [multiplicative group](wikipedia://en/1110742), being a subgroup of the multiplicative group of the finite field $\textstyle GF(p^2)^*$.

## Protocol description {#Protocol_description}

### Setup {#Setup}

The public key generator (PKG) chooses:

1. the public groups $\textstyle G_1$ (with generator $\textstyle P$) and $\textstyle G_2$ as stated above, with the size of $\textstyle q$ depending on security parameter $\textstyle k$,
1. the corresponding pairing $\textstyle e$,
1. a random private master-key $\textstyle K_m = s \in \mathbb{Z}_q^*$,
1. a public key $\textstyle K_{pub} = sP$,
1. a public hash function $\textstyle H_1: \left\{0,1\right\}^* \rightarrow G_1^*$,
1. a public hash function $\textstyle H_2: G_2 \rightarrow \left\{0,1\right\}^n$ for some fixed $\textstyle n$ and
1. the [message space](https://en.wikipedia.org/wiki/Message_space) and the [cipher space](https://en.wikipedia.org/wiki/Cipher_space) $\textstyle \mathcal{M} = \left\{0,1\right\}^n, \mathcal{C} = G_1^* \times \left\{0,1\right\}^n$

### Extraction {#Extraction}

To create the public key for $\textstyle ID \in \left\{0,1\right\}^*$, the PKG computes

1. $\textstyle Q_{ID} = H_1\left(ID\right)$ and
1. the private key $\textstyle d_{ID} = sQ_{ID}$ which is given to the user.

### Encryption {#Encryption}

Given $\textstyle m \in \mathcal{M}$, the ciphertext $\textstyle c$ is obtained as follows:

1. $$\textstyle Q_{ID} = H_1\left(ID\right) \in G_1^*,$$
1. choose random $\textstyle r \in \mathbb{Z}_q^*$,
1. compute $\textstyle g_{ID} = e\left(Q_{ID}, K_{pub}\right) \in G_2$ and
1. set $\textstyle c = \left(rP, m \oplus H_2\left(g_{ID}^r\right)\right)$.

Note that $\textstyle K_{pub}$ is the PKG's public key and thus independent of the recipient's ID.

### Decryption {#Decryption}

Given $\textstyle c = \left(u, v\right) \in \mathcal{C}$, the plaintext can be retrieved using the private key:

$$\textstyle m = v \oplus H_2\left(e\left(d_{ID}, u\right)\right)$$

### Correctness {#Correctness}

The primary step in both encryption and decryption is to employ the pairing and $\textstyle H_2$ to generate a mask (like a symmetric key) that is xor'ed with the plaintext. So in order to verify correctness of the protocol, one has to verify that an honest sender and recipient end up with the same values here.

The encrypting entity uses $\textstyle H_2\left(g_{ID}^r\right)$, while for decryption, $\textstyle H_2\left( e\left(d_{ID}, u\right) \right)$ is applied. Due to the properties of pairings, it follows that:

$$\begin{aligned} H_2\left( e\left(d_{ID}, u\right) \right) &= H_2\left( e\left(sQ_{ID}, rP\right) \right) \\ &= H_2\left( e\left(Q_{ID}, P\right)^{rs} \right) \\ &= H_2\left( e\left(Q_{ID}, sP\right)^r \right) \\ &= H_2\left( e\left(Q_{ID}, K_{pub}\right)^r \right) \\ &= H_2\left( g_{ID}^r \right) \\ \end{aligned}$$

## Security {#Security}

The security of the scheme depends on the hardness of the [bilinear Diffie-Hellman problem](https://en.wikipedia.org/wiki/Bilinear_Diffie_Hellman_Problem) (BDH) for the groups used. It has been proved that in a [random-oracle model](wikipedia://en/451286), the protocol is [semantically secure](https://en.wikipedia.org/wiki/Semantically_secure) under the BDH assumption.

## Improvements {#Improvements}

**BasicIdent** is not [chosen ciphertext secure](https://en.wikipedia.org/wiki/Adaptive_chosen_ciphertext_attack). However, there is a [universal transformation method](https://en.wikipedia.org/wiki/Fujisaki-Okamoto_transformation) due to [Fujisaki](https://en.wikipedia.org/wiki/Eiichiro_Fujisaki) and [Okamoto](https://en.wikipedia.org/wiki/Tatsuaki_Okamoto)[^o12] that allows for conversion to a scheme having this property called **FullIdent**.
