# Network Security Services

::: {#o2 .subject cue=lead name="Network Security Services"}

**Network Security Services** (**NSS**) is a collection of cryptographic [computer libraries](https://en.wikipedia.org/wiki/Library_%28computing%29) designed to support [cross-platform](https://en.wikipedia.org/wiki/Cross-platform) development of security-enabled client and server applications with optional support for hardware [TLS/SSL acceleration](https://en.wikipedia.org/wiki/TLS_acceleration) on the server side and hardware smart cards on the client side. NSS provides a complete [open-source](https://en.wikipedia.org/wiki/Open-source_software) implementation of cryptographic libraries supporting [Transport Layer Security](wikipedia://en/187813) (TLS) / [Secure Sockets Layer](https://en.wikipedia.org/wiki/Secure_Sockets_Layer) (SSL) and [S/MIME](https://en.wikipedia.org/wiki/S/MIME). NSS releases prior to version 3.14 are [tri-licensed](https://en.wikipedia.org/wiki/Multi-licensing) under the [Mozilla Public License](https://en.wikipedia.org/wiki/Mozilla_Public_License) 1.1, the [GNU General Public License](https://en.wikipedia.org/wiki/GNU_General_Public_License), and the [GNU Lesser General Public License](https://en.wikipedia.org/wiki/LGPL). Since release 3.14, NSS releases are licensed under GPL-compatible Mozilla Public License 2.0.

:::

## History {#History}

NSS originated from the libraries developed when [Netscape](https://en.wikipedia.org/wiki/Netscape) invented the SSL security protocol.

### FIPS 140 validation and NISCC testing {#FIPS_140_validation_and_NISCC_testing}

The NSS software crypto module has been validated five times (in 1997,[^o5] 1999, 2002,[^o6] 2007, and 2010[^o7]) for conformance to [FIPS 140](wikipedia://en/1539324) at Security Levels 1 and 2.[^o8] NSS was the first open source cryptographic library to receive FIPS 140 validation.[^o8] The NSS libraries passed the [NISCC](https://en.wikipedia.org/wiki/National_Infrastructure_Security_Co-ordination_Centre) TLS/SSL and S/MIME test suites (1.6 million test cases of invalid input data).[^o8]

## Applications that use NSS {#Applications_that_use_NSS}

[AOL](https://en.wikipedia.org/wiki/AOL), [Red Hat](https://en.wikipedia.org/wiki/Red_Hat), [Sun Microsystems](https://en.wikipedia.org/wiki/Sun_Microsystems)/[Oracle Corporation](https://en.wikipedia.org/wiki/Oracle_Corporation), [Google](https://en.wikipedia.org/wiki/Google) and other companies and individual contributors have co-developed NSS. [Mozilla](https://en.wikipedia.org/wiki/Mozilla) provides the source code repository, bug tracking system, and infrastructure for mailing lists and discussion groups. They and others named below use NSS in a variety of products, including the following:

- [Mozilla](https://en.wikipedia.org/wiki/Mozilla) client products, including [Firefox](https://en.wikipedia.org/wiki/Mozilla_Firefox), [Thunderbird](https://en.wikipedia.org/wiki/Mozilla_Thunderbird), [SeaMonkey](https://en.wikipedia.org/wiki/SeaMonkey), and [Firefox for mobile](https://en.wikipedia.org/wiki/Firefox_for_mobile).[^o10]
- [AOL Communicator](https://en.wikipedia.org/wiki/AOL_Communicator) and [AOL Instant Messenger (AIM)](https://en.wikipedia.org/wiki/AOL_Instant_Messenger)
- Open source client applications such as [Evolution](https://en.wikipedia.org/wiki/Novell_Evolution), [Pidgin](wikipedia://en/188211), and [OpenOffice.org](https://en.wikipedia.org/wiki/OpenOffice.org) 2.0 onward (and its descendants).
- Server products from [Red Hat](https://en.wikipedia.org/wiki/Red_Hat): [Red Hat Directory Server](https://en.wikipedia.org/wiki/Red_Hat_Directory_Server), Red Hat Certificate System, and the [mod nss SSL module](https://en.wikipedia.org/wiki/List_of_Apache_modules) for the [Apache web server](https://en.wikipedia.org/wiki/Apache_web_server).
- Sun server products from the [Sun Java Enterprise System](https://en.wikipedia.org/wiki/Sun_Java_System), including [Sun Java System Web Server](https://en.wikipedia.org/wiki/Sun_Java_System_Web_Server), [Sun Java System Directory Server](https://en.wikipedia.org/wiki/Sun_Java_System_Directory_Server), [Sun Java System Portal Server](https://en.wikipedia.org/wiki/Sun_Java_System_Portal_Server), [Sun Java System Messaging Server](https://en.wikipedia.org/wiki/Sun_Java_System_Messaging_Server), and [Sun Java System Application Server](https://en.wikipedia.org/wiki/Sun_Java_System_Application_Server), open source version of Directory Server [OpenDS](https://en.wikipedia.org/wiki/OpenDS).
- [Libreswan](https://en.wikipedia.org/wiki/Libreswan) IKE/IPsec requires NSS. It is a fork of Openswan which could optionally use NSS.

## Architecture {#Architecture}

NSS includes a framework to which developers and [OEMs](https://en.wikipedia.org/wiki/Original_equipment_manufacturer) can contribute patches, such as assembly code, to optimize performance on their platforms. Mozilla has certified NSS 3.x on 18 platforms.[^o12][^o13] NSS makes use of [Netscape Portable Runtime](https://en.wikipedia.org/wiki/Netscape_Portable_Runtime) (NSPR), a platform-neutral open-source API for system functions designed to facilitate cross-platform development. Like NSS, NSPR has been used heavily in multiple products.

### Software development kit {#Software_development_kit}

In addition to libraries and APIs, NSS provides security tools required for debugging, diagnostics, certificate and key management, cryptography-module management, and other development tasks. NSS comes with an extensive and growing set of documentation, including introductory material, API references, `man` pages for command-line tools, and sample code.

Programmers can utilize NSS as source and as shared (dynamic) libraries. Every NSS release is backward-compatible with previous releases, allowing NSS users to upgrade to new NSS shared libraries without recompiling or relinking their applications.

### Interoperability and open standards {#Interoperability_and_open_standards}

NSS supports a range of security standards, including the following:[^o16][^o17]

- [TLS](wikipedia://en/187813) 1.0 (RFC 2246), 1.1 (RFC 4346), 1.2 (RFC 5246), and 1.3 (RFC 8446). The Transport Layer Security (TLS) protocol from the [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) supersedes SSL v3.0 while remaining backward-compatible with SSL v3 implementations.
- [SSL](wikipedia://en/187813) 3.0. The Secure Sockets Layer (SSL) protocol allows mutual authentication between a client and server and the establishment of an authenticated and encrypted connection.
- [DTLS](wikipedia://en/1500599) 1.0 (RFC 4347) and 1.2 (RFC 6347).
- [DTLS-SRTP](https://en.wikipedia.org/wiki/DTLS-SRTP) (RFC 5764).
- The following [PKCS](wikipedia://en/616418) standards:
  - PKCS #1. RSA standard that governs implementation of public-key cryptography based on the RSA algorithm.
  - PKCS #3. RSA standard that governs implementation of Diffie–Hellman key agreement.
  - PKCS #5. RSA standard that governs password-based cryptography, for example to encrypt private keys for storage.
  - PKCS #7. RSA standard that governs the application of cryptography to data, for example digital signatures and digital envelopes.
  - PKCS #8. RSA standard that governs the storage and encryption of private keys.
  - PKCS #9. RSA standard that governs selected attribute types, including those used with PKCS #7, PKCS #8, and PKCS #10.
  - PKCS #10. RSA standard that governs the syntax for certificate requests.
  - PKCS #11. RSA standard that governs communication with cryptographic tokens (such as hardware accelerators and smart cards) and permits application independence from specific algorithms and implementations.
  - PKCS #12. RSA standard that governs the format used to store or transport private keys, certificates, and other secret material.
- [Cryptographic Message Syntax](wikipedia://en/442961), used in [S/MIME](https://en.wikipedia.org/wiki/S/MIME) (RFC 2311 and RFC 2633). IETF message specification (based on the popular Internet [MIME](https://en.wikipedia.org/wiki/MIME) standard) that provides a consistent way to send and receive signed and encrypted MIME data.
- [X.509 v3](https://en.wikipedia.org/wiki/X.509). [ITU](https://en.wikipedia.org/wiki/International_Telecommunication_Union) standard that governs the format of certificates used for authentication in public-key cryptography.
- [OCSP](https://en.wikipedia.org/wiki/Online_Certificate_Status_Protocol) (RFC 2560). The Online Certificate Status Protocol (OCSP) governs real-time confirmation of certificate validity.
- [PKIX](https://en.wikipedia.org/wiki/PKIX) Certificate and CRL Profile (RFC 3280). The first part of the four-part standard under development by the Public-Key Infrastructure (X.509) working group of the IETF (known as PKIX) for a public-key infrastructure for the Internet.
- [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29), [DSA](wikipedia://en/59470), [ECDSA](https://en.wikipedia.org/wiki/Elliptic_Curve_DSA), [Diffie–Hellman](wikipedia://en/7903), [EC Diffie–Hellman](https://en.wikipedia.org/wiki/Elliptic_curve_Diffie–Hellman), [AES](wikipedia://en/1260), [Triple DES](wikipedia://en/48375), [Camellia](wikipedia://en/532475), [IDEA](wikipedia://en/15076), [SEED](wikipedia://en/1063358), [DES](wikipedia://en/7978), [RC2](wikipedia://en/632592), [RC4](wikipedia://en/25831), [SHA-1](wikipedia://en/26672), [SHA-256, SHA-384, SHA-512](wikipedia://en/1638777), [MD2](https://en.wikipedia.org/wiki/MD2_%28cryptography%29), [MD5](wikipedia://en/18826), [HMAC](wikipedia://en/17112): Common cryptographic algorithms used in public-key and symmetric-key cryptography.
- [FIPS](https://en.wikipedia.org/wiki/Federal_Information_Processing_Standard) 186-2 [pseudorandom number generator](wikipedia://en/45524).

### Hardware support {#Hardware_support}

NSS supports the [PKCS #11](https://en.wikipedia.org/wiki/PKCS11) interface for access to cryptographic hardware like [TLS/SSL accelerators](https://en.wikipedia.org/wiki/TLS_acceleration), [hardware security modules](https://en.wikipedia.org/wiki/Hardware_security_module) and [smart cards](https://en.wikipedia.org/wiki/Smart_card). Since most hardware vendors such as [SafeNet](https://en.wikipedia.org/wiki/SafeNet), [AEP](https://en.wikipedia.org/wiki/Ultra_Electronics) and [Thales](https://en.wikipedia.org/wiki/Thales_Group) also support this interface, NSS-enabled applications can work with high-speed crypto hardware and use private keys residing on various smart cards, if vendors provide the necessary middleware. NSS version 3.13 and above support the [Advanced Encryption Standard New Instructions](wikipedia://en/23095336) (AES-NI).[^o19]

### Java support {#Java_support}

Network Security Services for [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) (JSS) consists of a Java interface to NSS. It supports most of the security standards and encryption technologies supported by NSS. JSS also provides a pure Java interface for [ASN.1](https://en.wikipedia.org/wiki/ASN.1) types and [BER](https://en.wikipedia.org/wiki/Basic_Encoding_Rules)/[DER](https://en.wikipedia.org/wiki/Distinguished_Encoding_Rules) encoding.[^o21]
