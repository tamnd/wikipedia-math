# ESTREAM

::: {#o1 .subject cue=lead name="ESTREAM"}

**eSTREAM** is a project to "identify new [stream ciphers](wikipedia://en/49007) suitable for widespread adoption",[^o2][^o3] organised by the [EU](https://en.wikipedia.org/wiki/European_Union) [ECRYPT](wikipedia://en/1635837) network. It was set up as a result of the failure of all six stream ciphers submitted to the [NESSIE](wikipedia://en/497430) project. The call for primitives was first issued in November 2004. The project was completed in April 2008. The project was divided into separate phases and the project goal was to find algorithms suitable for different application profiles.

:::

## Profiles {#Profiles}

The submissions to eSTREAM fall into either or both of two profiles:

- Profile 1: "Stream ciphers for [software](https://en.wikipedia.org/wiki/Software) applications with high [throughput](https://en.wikipedia.org/wiki/Throughput) requirements"
- Profile 2: "Stream ciphers for hardware applications with restricted resources such as limited storage, [gate count](https://en.wikipedia.org/wiki/Gate_count), or power consumption."

Both profiles contain an "A" subcategory (1A and 2A) with ciphers that also provide authentication in addition to encryption. In Phase 3 none of the ciphers providing authentication are being considered (The NLS cipher had authentication removed from it to improve its performance).

## Phases {#Phases}

### Phase 1 {#Phase_1}

Phase 1 included a general analysis of all submissions with the purpose of selecting a subset of the submitted designs for further scrutiny. The designs were scrutinized based on criteria of security, performance (with respect to the [block cipher](wikipedia://en/4594) [AES](wikipedia://en/1260)—a US Government approved standard, as well as the other candidates), simplicity and flexibility, justification and supporting analysis, and clarity and completeness of the documentation. Submissions in Profile 1 were only accepted if they demonstrated software performance superior to AES-128 in [counter mode](https://en.wikipedia.org/wiki/Counter_mode).

Activities in Phase 1 included a large amount of analysis and presentations of analysis results as well as discussion. The project also developed a framework for testing the performance of the candidates. The framework was then used to benchmark the candidates on a wide variety of systems.

On 27 March 2006, the eSTREAM project officially announced the end of Phase 1.

### Phase 2 {#Phase_2}

On 1 August 2006, Phase 2 was officially started. For each of the profiles, a number of algorithms has been selected to be Focus Phase 2 algorithms. These are designs that eSTREAM finds of particular interest and encourages more cryptanalysis and performance evaluation on these algorithms. Additionally a number of algorithms for each profile are accepted as Phase 2 algorithms, meaning that they are still valid as eSTREAM candidates. The Focus 2 candidates will be re-classified every six months.

### Phase 3 {#Phase_3}

Phase 3 started in April 2007. Candidates for Profile 1 (software) were:

- [CryptMT](wikipedia://en/6338441) (version 3)
- [Dragon](wikipedia://en/4546067)
- [HC](https://en.wikipedia.org/wiki/HC-256) (HC-128 and HC-256)
- [LEX](https://en.wikipedia.org/wiki/LEX_%28cipher%29) (LEX-128, LEX-192 and LEX-256)
- [NLS](wikipedia://en/6338866) (NLSv2, encryption only, not authentication)
- [Rabbit](wikipedia://en/4565952)
- [Salsa20](wikipedia://en/2701329)/12
- [SOSEMANUK](wikipedia://en/4546152)

Candidates for Profile 2 (hardware) were:

- [DECIM](https://en.wikipedia.org/wiki/DECIM) (DECIM v2 and DECIM-128)
- [F-FCSR](https://en.wikipedia.org/wiki/F-FCSR) (F-FCSR-H v2 and F-FCSR-16)
- [Grain](wikipedia://en/2710390) (Grain v1 and Grain-128)
- [MICKEY](https://en.wikipedia.org/wiki/MICKEY) (MICKEY 2.0 and MICKEY-128 2.0)
- [Moustique](https://en.wikipedia.org/wiki/Moustique), [Pomaranch](https://en.wikipedia.org/wiki/Pomaranch) (version 3)
- [Trivium](wikipedia://en/2620653)

Phase 3 ended on 15 April 2008, with the announcement of the candidates that had been selected for the final eSTREAM portfolio. The selected algorithms were:

- For Profile 1: HC-128, Rabbit, Salsa20/12, and SOSEMANUK.
- For Profile 2: F-FCSR-H v2, Grain v1, Mickey v2, and Trivium.
