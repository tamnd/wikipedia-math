# Dependency graph

::: {#o1 .subject cue=lead name="Dependency graph"}

In [mathematics](wikipedia://en/18831), [computer science](https://en.wikipedia.org/wiki/Computer_science) and [digital electronics](https://en.wikipedia.org/wiki/Digital_electronics), a **dependency graph** is a [directed graph](wikipedia://en/19721986) representing dependencies of several objects towards each other. It is possible to derive an evaluation order or the absence of an evaluation order that respects the given dependencies from the dependency graph.

:::

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

*Image: Dependencygraph.png.* *A* depends on *B* and *C*; *B* depends on *D*

Given a set of objects $S$ and a [transitive relation](wikipedia://en/200463) $R \subseteq S \times S$ with $(a,b) \in R$ modeling a dependency "*a* depends on *b*" ("*a* needs *b* evaluated first"), the dependency graph is a graph $G = (S, T)$ with $T \subseteq R$ the [transitive reduction](wikipedia://en/3757117) of *R*.

For example, assume a simple calculator. This calculator supports assignment of constant values to variables and assigning the sum of exactly two variables to a third variable. Given several equations like "*A* = *B*+*C*; *B* = 5+*D*; *C*=4; *D*=2;", then $S=\{A,B,C,D\}$ and $R=\{(A,B),(A,C),(B,V),(A,V)\}$. You can derive this relation directly: *A* depends on *B* and *C*, because you can add two variables [if and only if](wikipedia://en/14922) you know the values of both variables. Thus, *B* must be calculated before *A* can be calculated. Since *B* depends on *D* to be calculated, *A* must also depend on *D* to be calculated before it (hence the transitive property stated above). On the other hand, the values of *C* and *D* are known immediately, because they are number literals.

:::

## Recognizing impossible evaluations {#Recognizing_impossible_evaluations}

In a dependency graph, cycles of dependencies (also called **circular dependencies**) lead to a situation in which no valid evaluation order exists, because none of the objects in the cycle may be evaluated first. If a dependency graph does not have any circular dependencies, it forms a [directed acyclic graph](wikipedia://en/204002), and an evaluation order may be found by [topological sorting](wikipedia://en/897064). Most topological sorting algorithms are also capable of detecting cycles in their inputs; however, it may be desirable to perform [cycle detection](https://en.wikipedia.org/wiki/Cycle_detection_%28graph_theory%29) separately from topological sorting in order to provide appropriate handling for the detected cycles.

Assume the simple calculator from before. The equation system "*A*=*B*; *B*=*D*+*C*; *C*=*D*+*A*; *D*=12;" contains a [circular dependency](https://en.wikipedia.org/wiki/Circular_dependency) formed by *A*, *B* and *C*, as *B* must be evaluated before *A*, *C* must be evaluated before *B*, and *A* must be evaluated before *C*.

## Deriving an evaluation order {#Deriving_an_evaluation_order}

A **correct evaluation order** is a numbering $n : S \rightarrow \mathbb{N}$ of the objects that form the nodes of the dependency graph so that the following equation holds: $n(a) < n(b) \Rightarrow (a, b) \notin R$ with $a, b \in S$. This means, if the numbering orders two elements $a$ and $b$ so that $a$ will be evaluated before $b$, then $a$ must not depend on $b$.

There can be more than one correct evaluation order. In fact, a correct numbering is a [topological order](wikipedia://en/897064), and any topological order is a correct numbering. Thus, any algorithm that derives a correct topological order derives a correct evaluation order.

Assume the simple calculator from above once more. Given the equation system "*A* = *B*+*C*; *B* = 5+*D*; *C*=4; *D*=2;", a correct evaluation order would be (*D*, *C*, *B*, *A*). However, (*C*, *D*, *B*, *A*) is a correct evaluation order as well.

## Monoid structure {#Monoid_structure}

An acyclic dependency graph corresponds to a trace of a [trace monoid](wikipedia://en/10739141) as follows:[^o7]

- A function $\phi : S \to \Sigma$ labels each vertex with a symbol from the alphabet $\Sigma$
- There is an edge $a \to b$ or $b \to a$ if and only if $(\phi(a),\phi(b))$ is in the [dependency relation](wikipedia://en/10739341) $D$.
- Two graphs are considered to be equal if their labels and edges correspond.

Then the string consisting of the vertex labels ordered by a correct evaluation order corresponds to a string of a trace.

The [monoidal](wikipedia://en/19652) operation $(S_{12},R_{12})=(S_1,R_1)\bullet (S_2,R_2)$ takes the [disjoint union](wikipedia://en/188946) $S_{12}=S_1 \sqcup S_2$ of two graphs' vertex sets, preserves the existing edges in each graph, and draws new edges from the first to the second where the dependency relation allows,[^o7]

$$R_{12} = R_1 \sqcup R_2 \sqcup \{(a,b)\mid a\in S_1 \land b\in S_2 \land (\phi(a),\phi(b))\in D\}$$

The identity is the empty graph.

## Examples {#Examples}

Dependency graphs are used in:

- Automated software [installers](https://en.wikipedia.org/wiki/Installer): They walk the graph looking for [software packages](https://en.wikipedia.org/wiki/Software_package_%28installation%29) that are required but not yet installed. The dependency is given by the [coupling](https://en.wikipedia.org/wiki/Coupling_%28computer_science%29) of the packages.
- Software build scripts such as [Unix](https://en.wikipedia.org/wiki/Unix) [Make](https://en.wikipedia.org/wiki/Make_%28software%29), [Node](https://en.wikipedia.org/wiki/Node.js) npm install, php composer, [Twitter](https://en.wikipedia.org/wiki/Twitter) bower install, or [Apache Ant](https://en.wikipedia.org/wiki/Apache_Ant). They need to know what files have changed so only the correct files need to be recompiled.
- In [compiler](https://en.wikipedia.org/wiki/Compiler) technology and [formal language](wikipedia://en/10939) implementation:
  - [Instruction scheduling](https://en.wikipedia.org/wiki/Instruction_scheduling): Dependency graphs are computed for the operands of [assembly](https://en.wikipedia.org/wiki/Assembly_code) or intermediate instructions and used to determine an optimal order for the instructions.
  - [Dead code elimination](https://en.wikipedia.org/wiki/Dead_code_elimination): If no side effected operation depends on a variable, this variable is considered dead and can be removed.
- Dynamic graph analytics: GraphBolt[^o10] and KickStarter[^o11] capture value dependencies for [incremental computing](https://en.wikipedia.org/wiki/Incremental_computing) when graph structure changes.
- [Spreadsheet](https://en.wikipedia.org/wiki/Spreadsheet) calculators. They need to derive a correct calculation order similar to that one in the example used in this article.
- Web Forms standards such as [XForms](https://en.wikipedia.org/wiki/XForms) to know what visual elements to update if data in the model changes.
- Dependency graphs are used in alarm correlation approaches for tracing the impact or propagation of network attacks through the network. This approach exploits the spatio-temporal attributes of alarms and the dependencies between network devices, which are modeled as a network dependency graph. Given that false alarms generated by an intrusion detection system (IDS), for example, may produce incorrect dependency relationships, entropy-based measures can be applied to mitigate the uncertainty introduced by false alarms in the identification of attack impact or propagation paths.[^o12]
- Video games, especially [puzzle](https://en.wikipedia.org/wiki/Puzzle_video_game) and [adventure video games](https://en.wikipedia.org/wiki/Adventure_game), which are frequently designed as a graph of dependent relationships between in-game actions.[^o13]

Dependency graphs are one aspect of:

- [Manufacturing plant types](https://en.wikipedia.org/wiki/Theory_of_Constraints#Plant_types): Raw materials are processed into products via several dependent stages.
- [Job shop scheduling](https://en.wikipedia.org/wiki/Job_Shop_Scheduling): A collection of related theoretical problems in computer science.
