# BF-graph

*Image: BF-graph.svg.* Each blue hyperedge has all tails but one, making them **B-arcs**. Likewise, each orange edge has all heads but one, making them **F-arcs**. A **BF-graph** consists only of these two kinds of directed arcs, such as the one shown.

::: {#o1 .subject cue=lead name="BF-graph"}

In [graph theory](wikipedia://en/12401), a **BF-graph** is a type of [directed](wikipedia://en/19721986) [hypergraph](wikipedia://en/232535) where each [hyperedge](https://en.wikipedia.org/wiki/Hyperedge) is directed either to one particular [vertex](wikipedia://en/638899) or away from one particular vertex.[^o2]

:::

::: {#o4 .definition cue=heading name="Definition"}

## Definition {#Definition}

In a directed hypergraph, each hyperedge may be directed away from some of its vertices (its *tails*) and towards some others of its vertices (its *heads*). A hyperedge that is directed to a single head vertex, and away from all its other vertices, is called a *B*-arc (backward arc). Symmetrically, a hyperedge that is directed away from a single tail vertex, and towards all its other vertices, is called an *F*-arc (forward arc).[^o2]

A hypergraph with only B-arcs is a **B-graph** (or B-hypergraph) and a hypergraph with only F-arcs is a **F-graph** (or F-hypergraph). A **BF-graph** (or BF-hypergraph) is a hypergraph whose hyperarcs are either B-arcs or F-arcs.[^o2][^o5][^o6]

:::

::: {#o8 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

Any general directed hypergraph can be transformed into a BF-graph by adding a dummy node to each hyperarc that is neither a B-arc nor an F-arc, thus replacing each such hyperarc with one B-arc and one F-arc.[^o2]

The symmetric image of a B-graph is an F-graph, and vice versa. This is obtained by reversing the direction of all hyperarcs.[^o2]

:::

## Paths and connectivity {#Paths_and_connectivity}

In BF-graphs, different types of paths and connectivity can be defined:

- A **B-path** (or B-hyperpath) from node *s* to node *t* is a minimal hypergraph where every node is connected to *s* by means of a cycle-free simple path
- An **F-path** (or F-hyperpath) from *s* to *t* is a hypergraph whose symmetric image is a B-path from *t* to *s*
- A **BF-path** (or BF-hyperpath) from *s* to *t* is a hypergraph that is simultaneously both a B-path and an F-path from *s* to *t*

Correspondingly, nodes can be B-connected, F-connected, or BF-connected depending on whether the respective type of path exists between them.[^o2][^o5]

::: {#o11 .application cue=heading name="Applications"}

## Applications {#Applications}

Directed hypergraphs and their BF-graph subfamily have found applications across diverse areas of [computer science](https://en.wikipedia.org/wiki/Computer_science), including database systems, expert systems, parallel programming, scheduling, routing in dynamic networks, [data mining](wikipedia://en/42253), and [bioinformatics](wikipedia://en/4214).[^o6]

### B-graphs {#B-graphs}

B-graphs have been particularly useful in representing [Horn formulae](wikipedia://en/333824) in [propositional logic](wikipedia://en/18154), where they are sometimes called "labelled graphs". They have also been applied to analyzing [deductive databases](https://en.wikipedia.org/wiki/Deductive_database) and studying Leontiev substitution matrices and flow problems.[^o2]

### F-graphs {#F-graphs}

F-graphs have found applications in urban transit problems, particularly for modeling passenger distribution in transit systems. They have also been used in the analysis of [And-Or graphs](https://en.wikipedia.org/wiki/And-or_tree) in [artificial intelligence](https://en.wikipedia.org/wiki/Artificial_intelligence).[^o2]

### BF-graphs {#BF-graphs}

BF-graphs provide a general framework that can model concurrent systems and parallel computation programs. They are particularly useful for representing task precedence and simultaneous execution in synchronous systems.[^o5] The structure has also been applied to scheduling problems and routing in dynamic networks.[^o6]

BF-graphs are well-suited for representing [functional dependencies](https://en.wikipedia.org/wiki/Functional_dependency) in [relational databases](https://en.wikipedia.org/wiki/Relational_database), as both the domain and codomain of a functional dependency may contain multiple attributes. This property has been utilized in converting relational databases to [Resource Description Framework](https://en.wikipedia.org/wiki/Resource_Description_Framework) (RDF) representations for [semantic web](https://en.wikipedia.org/wiki/Semantic_web) applications.[^o15]

:::

## Computational complexity {#Computational_complexity}

Several path problems that are polynomial-time solvable on ordinary directed graphs become [NP-hard](https://en.wikipedia.org/wiki/NP-hard) when extended to BF-graphs. For example, finding a minimum cardinality B-path in a B-graph is NP-hard, even though the corresponding shortest path problem in ordinary graphs can be solved in polynomial time.[^o2] However, certain special cases and constrained versions of these problems remain tractable.[^o5]

In contrast, planarity testing for BF-graphs can be performed efficiently in linear time with respect to the size of the hypergraph.[^o6]
