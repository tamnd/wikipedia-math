# GBDE

::: {#o1 .subject cue=lead name="GBDE"}

**GBDE**, standing for **GEOM Based Disk Encryption**, is a [block device](https://en.wikipedia.org/wiki/Block_device)-layer [disk encryption](wikipedia://en/7066791) system written for [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD),[^o2][^o3] initially introduced in version 5.0. It is based on the [GEOM](https://en.wikipedia.org/wiki/GEOM) disk framework. GBDE was designed and implemented by [Poul-Henning Kamp](https://en.wikipedia.org/wiki/Poul-Henning_Kamp) and Network Associates Inc. (now known as [McAfee](https://en.wikipedia.org/wiki/McAfee)).[^o4]

:::

## Design decisions {#Design_decisions}

Unlike most disk encryption software, GBDE does not attempt to defeat [watermarking attacks](wikipedia://en/7228413) through the use of disk encryption-specific modes of operation (see [disk encryption theory](wikipedia://en/3395256)), but instead generates a random [key](wikipedia://en/53039) each time a [sector](https://en.wikipedia.org/wiki/Disk_sector) is written.[^o6] Unlike some alternatives, such as CBC with sector-specific [initialization vectors](wikipedia://en/105971), this approach does not reveal any information to the attacker even if they have access to snapshots of the disk image from different points in time, since encryption keys are never re-used.

The one time sector key is encrypted using a pseudorandom key. This pseudorandom key is derived from the sector number and a static 2048-bit master key with 128 bits of [salt](wikipedia://en/701756). The [pseudorandom number generator](wikipedia://en/45524) used for this purpose is called the Cherry Picker. This is not a well established PRNG, but rather one invented for GBDE. This generator may not meet the security levels of standard algorithms, and could be distinguishable from random numbers.[^o7]

## Limitations {#Limitations}

Due to this unique approach, GBDE only supports 128-bit [AES](wikipedia://en/1260). Using a different key for each write also introduces a significant CPU overhead, as most [block ciphers](wikipedia://en/4594) use key-specific precomputations, and makes disk updates non-[atomic](https://en.wikipedia.org/wiki/Atomicity_%28database_systems%29) since the keys are written separately from the data.[^o9][^o10][^o11] As a result, data loss can occur on unexpected power drops, even when used with [journaling file systems](https://en.wikipedia.org/wiki/Journaling_file_system). GBDE also has a disk space [overhead](https://en.wikipedia.org/wiki/Computational_overhead) of about 3% to store the per-sector keys.

To address these shortcomings, a more typical disk encryption solution for FreeBSD, [GELI](wikipedia://en/22725313), was written later by Pawel Jakub Dawidek.
