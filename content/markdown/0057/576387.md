# Finite field arithmetic

::: {#o1 .subject cue=lead name="Finite field arithmetic"}

In [mathematics](wikipedia://en/18831), **finite field arithmetic** is [arithmetic](wikipedia://en/3118) in a [finite field](wikipedia://en/11615) (a [field](wikipedia://en/10603) containing a finite number of [elements](https://en.wikipedia.org/wiki/Element_%28mathematics%29)) contrary to arithmetic in a field with an infinite number of elements, like the field of [rational numbers](wikipedia://en/19727024).

:::

There are infinitely many different finite fields. Their [number of elements](wikipedia://en/6174) is necessarily of the form *p<sup>n</sup>* where *p* is a [prime number](wikipedia://en/23666) and *n* is a [positive integer](https://en.wikipedia.org/wiki/Positive_integer), and two finite fields of the same size are [isomorphic](wikipedia://en/14828). The prime *p* is called the [characteristic](wikipedia://en/1066621) of the field, and the positive integer *n* is called the [dimension](wikipedia://en/38267) of the field over its [prime field](wikipedia://en/1066621#Case_of_fields).

Finite fields are used in a variety of applications, including in classical [coding theory](wikipedia://en/321869) in [linear block codes](https://en.wikipedia.org/wiki/Linear_block_code) such as [BCH codes](wikipedia://en/40779) and [Reed–Solomon error correction](wikipedia://en/45600), in [cryptography](wikipedia://en/18934432) algorithms such as the [Rijndael](wikipedia://en/1260) ([AES](wikipedia://en/1260)) encryption algorithm, in tournament scheduling, and in the [design of experiments](wikipedia://en/9541).

## Effective polynomial representation {#Effective_polynomial_representation}

The finite field with *p*<sup>*n*</sup> elements is denoted GF(*p*<sup>*n*</sup>) and is also called the **Galois field** of order *p*<sup>*n*</sup>, in honor of the founder of finite field theory, [Évariste Galois](wikipedia://en/9815). GF(*p*), where *p* is a prime number, is simply the [ring](https://en.wikipedia.org/wiki/Ring_%28algebra%29) of integers [modulo](wikipedia://en/20087) *p*. That is, one can perform operations (addition, subtraction, multiplication) using the usual operation on integers, followed by reduction modulo *p*. For instance, in GF(5), 4 + 3 = 7 is reduced to 2 modulo 5. Division is multiplication by the inverse modulo *p*, which may be computed using the [extended Euclidean algorithm](wikipedia://en/9815338#Extended_Euclidean_algorithm).

A particular case is [GF(2)](wikipedia://en/11137263), where addition is [exclusive OR](https://en.wikipedia.org/wiki/XOR_gate) (XOR) and multiplication is [AND](https://en.wikipedia.org/wiki/AND_gate). Since the only invertible element is 1, division is the [identity function](wikipedia://en/15069).

Elements of GF(*p*<sup>*n*</sup>) may be represented as [polynomials](wikipedia://en/23000) of degree strictly less than *n* over GF(*p*). Operations are then performed modulo *m(x)* where *m(x)* is an [irreducible polynomial](wikipedia://en/188725) of degree *n* over GF(*p*), for instance using [polynomial long division](wikipedia://en/314205). Addition is the usual addition of polynomials, but the coefficients are reduced modulo *p*. Multiplication is also the usual multiplication of polynomials, but with coefficients multiplied modulo *p* and polynomials multiplied modulo the polynomial *m(x)*.[^o3] This representation in terms of polynomial coefficients is called a [monomial basis](wikipedia://en/976666) (a.k.a. 'polynomial basis').

There are other representations of the elements of GF(*p*<sup>*n*</sup>); some are isomorphic to the polynomial representation above and others look quite different (for instance, using matrices). Using a [normal basis](wikipedia://en/1028589) may have advantages in some contexts.

When the prime is 2, it is conventional to express elements of GF(*p*<sup>*n*</sup>) as [binary numbers](https://en.wikipedia.org/wiki/Binary_numeral_system), with the coefficient of each term in a polynomial represented by one bit in the corresponding element's binary expression. Braces ( "{" and "}" ) or similar delimiters are commonly added to binary numbers, or to their [hexadecimal](wikipedia://en/13263) equivalents, to indicate that the value gives the coefficients of a basis of a field, thus representing an element of the field. For example, the following are equivalent representations of the same value in a characteristic 2 finite field:

::: {#o4 .table cue=table}

| Polynomial | *x*<sup>6</sup> + *x*<sup>4</sup> + *x* + 1 |
|---|---|
| Binary | {01010011} |
| Hexadecimal | {53} |

:::

## Primitive polynomials {#Primitive_polynomials}

There are many irreducible polynomials (sometimes called **reducing polynomials**) that can be used to generate a finite field, but they do not all give rise to the same representation of the field.

A [monic](wikipedia://en/314730) [irreducible polynomial](wikipedia://en/188725) of degree $n$ having coefficients in the finite field GF($q$), where $q = p^{t}$ for some prime $p$ and positive integer $t$, is called a **primitive polynomial** if all of its roots are [primitive elements](wikipedia://en/19127149) of GF($q^{n}$).[^o6][^o7] In the polynomial representation of the finite field, this implies that $x$ is a primitive element. There is at least one irreducible polynomial for which $x$ is a primitive element.[^o8] In other words, for a primitive polynomial, the powers of $x$ generate every nonzero value in the field.

In the following examples it is best not to use the polynomial representation, as the meaning of $x$ changes between the examples. The monic irreducible polynomial $x^{8} + x^{4} + x^{3} + x + 1$ over [GF(2)](wikipedia://en/11137263) is not primitive. Let $\lambda$ be a root of this polynomial (in the polynomial representation this would be $x$), that is, $\lambda^{8} + \lambda^{4} + \lambda^{3} + \lambda + 1 = 0$. Now $\lambda^{51} = 1$, so $\lambda$ is not a primitive element of GF(2<sup>8</sup>) and generates a multiplicative subgroup of order 51.[^o9] The monic irreducible polynomial $x^{8} + x^{4} + x^{3} + x^{2} + 1$ over [GF(2)](wikipedia://en/11137263) is primitive, and all 8 roots are generators of $\operatorname{GF}(2^{8})$.

All GF(2<sup>8</sup>) have a total of 128 generators (see [Number of primitive elements](wikipedia://en/19127149#Number_of_primitive_elements)), and for a primitive polynomial, 8 of them are roots of the reducing polynomial. Having $x$ as a generator for a finite field is beneficial for many computational mathematical operations.

## Addition and subtraction {#Addition_and_subtraction}

Addition and subtraction are performed by adding or subtracting two of these polynomials together, and reducing the result modulo the characteristic.

In a finite field with characteristic 2, addition modulo 2, subtraction modulo 2, and XOR are identical. Thus,

| Binary | {01010011} + {11001010} = {10011001} |
| Hexadecimal | {53} + {CA} = {99} |

## Multiplication {#Multiplication}

Multiplication in a finite field is multiplication [modulo](wikipedia://en/20087) an [irreducible](wikipedia://en/188725) reducing polynomial used to define the finite field. (I.e., it is multiplication followed by division using the reducing polynomial as the divisor—the remainder is the product.) The symbol "•" may be used to denote multiplication in a finite field.

::: {#o15 .pointer-item cue=pointer name="Rijndael Galois field"}

### Rijndael's (AES) finite field {#Rijndael's_(AES)_finite_field}

[Rijndael](https://en.wikipedia.org/wiki/Rijndael) (standardised as AES) uses the characteristic 2 finite field with 256 elements, which can also be called the Galois field GF(2<sup>8</sup>). It employs the following reducing polynomial for multiplication:

*x*<sup>8</sup> + *x*<sup>4</sup> + *x*<sup>3</sup> + *x* + 1.

(The elements {53} and {CA} are [multiplicative inverses](wikipedia://en/229940) of one another since their product is [1](https://en.wikipedia.org/wiki/1_%28number%29).)

Multiplication in this particular finite field can also be done using a modified version of the "[peasant's algorithm](wikipedia://en/57411#Russian_peasant_multiplication)". Each polynomial is represented using the same binary notation as above. Eight bits is sufficient because only degrees 0 to 7 are possible in the terms of each (reduced) polynomial.

This algorithm uses three [variables](https://en.wikipedia.org/wiki/Variable_%28programming%29) (in the [computer programming](https://en.wikipedia.org/wiki/Computer_programming) sense), each holding an eight-bit representation. **a** and **b** are initialized with the multiplicands; **p** accumulates the product and must be initialized to 0.

At the start and end of the algorithm, and the start and end of each iteration, this [invariant](https://en.wikipedia.org/wiki/Invariant_%28computer_science%29) is true: **a** **b** + **p** is the product. This is obviously true when the algorithm starts. When the algorithm terminates, **a** or **b** will be zero so **p** will contain the product.

- Run the following loop eight times (once per bit). It is OK to stop when **a** or **b** is zero before an iteration:
  1. If the rightmost bit of **b** is set, exclusive OR the product **p** by the value of **a**. This is polynomial addition.
  1. Shift **b** one bit to the right, discarding the rightmost bit, and making the leftmost bit have a value of zero. This divides the polynomial by **x**, discarding the *x*<sup>0</sup> term.
  1. Keep track of whether the leftmost bit of **a** is set to one and call this value **carry**.
  1. Shift **a** one bit to the left, discarding the leftmost bit, and making the new rightmost bit zero. This multiplies the polynomial by **x**, but we still need to take account of **carry** which represented the coefficient of *x*<sup>7</sup>.
  1. If **carry** had a value of one, exclusive or **a** with the hexadecimal number `0x1b` (00011011 in binary). `0x1b` corresponds to the irreducible polynomial with the high term eliminated. Conceptually, the high term of the irreducible polynomial and **carry** add modulo 2 to 0.
- **p** now has the product

This algorithm generalizes easily to multiplication over other fields of characteristic 2, changing the lengths of **a**, **b**, and **p** and the value `0x1b` appropriately.

:::

## Multiplicative inverse {#Multiplicative_inverse}

The [multiplicative inverse](wikipedia://en/229940) for an element **a** of a finite field can be calculated a number of different ways:

- By multiplying **a** by every number in the field until the product is one. This is a [brute-force search](https://en.wikipedia.org/wiki/Brute-force_search).
- Since the nonzero elements of GF(*p<sup>n</sup>*) form a [finite group](wikipedia://en/323707) with respect to multiplication, *a*${}^{p^{n}-1}$ = 1 (for *a* ≠ 0), thus the inverse of *a* is *a*${}^{p^{n}-2}$. This algorithm is a generalization of the [modular multiplicative inverse](wikipedia://en/9815338) based on [Fermat's little theorem](wikipedia://en/53453).
- Multiplicative inverse based on the [Fermat's little theorem](wikipedia://en/53453) can also be interpreted using the multiplicative Norm function in [finite field](wikipedia://en/11615). This new viewpoint leads to an inverse algorithm based on the additive Trace function in [finite field](wikipedia://en/11615).[^o17]
- By using the [extended Euclidean algorithm](wikipedia://en/99438).
- By making [logarithm](wikipedia://en/17860) and [exponentiation](wikipedia://en/99491) tables for the finite field, subtracting the logarithm from *p<sup>n</sup>* − 1 and exponentiating the result.
- By making a [modular multiplicative inverse](wikipedia://en/9815338) table for the finite field and doing a lookup.
- By mapping to a [composite field](wikipedia://en/576387#Composite_field) where inversion is simpler, and mapping back.
- By constructing a special integer (in case of a finite field of a prime order) or a special polynomial (in case of a finite field of a non-prime order) and dividing it by *a*.[^o18]

## Implementation tricks {#Implementation_tricks}

### Generator-based tables {#Generator-based_tables}

When developing algorithms for Galois field computation on small Galois fields, a common performance optimization approach is to find a [generator](wikipedia://en/99945#Finitely_generated_group) *g* and use the identity:

$$ab = g^{\log_g(ab)} = g^{\log_g(a) + \log_g (b)}$$

to implement multiplication as a sequence of table look ups for the log<sub>*g*</sub>(*a*) and *g*<sup>*y*</sup> functions and an integer addition operation. This exploits the property that every finite field contains generators. In the Rijndael field example, the polynomial *x* + 1 (or {03}) is one such generator. A necessary but not sufficient condition for a polynomial to be a generator is to be [irreducible](wikipedia://en/188725).

An implementation must test for the special case of *a* or *b* being zero, as the product will also be zero.

This same strategy can be used to determine the multiplicative inverse with the identity:

$$a^{-1} = g^{\log_g\left(a^{-1}\right)} = g^{-\log_g(a)} = g^{|g| - \log_g(a)}$$

Here, the [order](wikipedia://en/493527) of the generator, $\lvert g\rvert$, is the number of non-zero elements of the field. In the case of GF(2<sup>8</sup>) this is 2<sup>8</sup> − 1 = 255. That is to say, for the Rijndael example: (*x* + 1)<sup>255</sup> = 1. So this can be performed with two look up tables and an integer subtract. Using this idea for exponentiation also derives benefit:

$$a^n = g^{\log_g\left(a^n\right)} = g^{n\log_g(a)} = g^{n\log_g(a) \pmod{|g|}}$$

This requires two table look ups, an integer multiplication and an integer modulo operation. Again a test for the special case *a* = 0 must be performed.

However, in cryptographic implementations, one has to be careful with such implementations since the [cache architecture](https://en.wikipedia.org/wiki/CPU_cache) of many microprocessors leads to variable timing for memory access. This can lead to implementations that are vulnerable to a [timing attack](wikipedia://en/481813).

### Carryless multiply {#Carryless_multiply}

For binary fields GF(2<sup>*n*</sup>), field multiplication can be implemented using a carryless multiply such as [CLMUL instruction set](https://en.wikipedia.org/wiki/CLMUL_instruction_set), which is good for *n* ≤ 64. A multiplication uses one carryless multiply to produce a product (up to 2*n* − 1 bits), another carryless multiply of a pre-computed inverse of the field polynomial to produce a quotient = ⌊product / (field polynomial)⌋, a multiply of the quotient by the field polynomial, then an xor: result = product ⊕ ((field polynomial) ⌊product / (field polynomial)⌋). The last 3 steps (pclmulqdq, pclmulqdq, xor) are used in the [Barrett reduction](wikipedia://en/26812527) step for fast computation of CRC using the [x86](https://en.wikipedia.org/wiki/X86) pclmulqdq instruction.[^o22]

### Composite exponent {#Composite_exponent}

When *k* is a [composite number](wikipedia://en/82289), there will exist [isomorphisms](wikipedia://en/14828) from a binary field GF(2<sup>*k*</sup>) to an extension field of one of its subfields, that is, GF((2<sup>*m*</sup>)<sup>*n*</sup>) where *k* = *m* *n*. Utilizing one of these isomorphisms can simplify the mathematical considerations as the degree of the extension is smaller with the trade off that the elements are now represented over a larger subfield.[^o24] To reduce gate count for hardware implementations, the process may involve multiple nesting, such as mapping from GF(2<sup>8</sup>) to GF(((2<sup>2</sup>)<sup>2</sup>)<sup>2</sup>).[^o25]

## Program examples {#Program_examples}

### C programming example {#C_programming_example}

Here is some [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) code which will add and multiply numbers in the characteristic 2 finite field of order 2<sup>8</sup>, used for example by Rijndael algorithm or Reed–Solomon, using the [Russian peasant multiplication algorithm](wikipedia://en/3975814#Russian_peasant_multiplication):

```c
/* Add two numbers in the GF(2^8) finite field */
uint8_t gadd(uint8_t a, uint8_t b) {
	return a ^ b;
}

/* Multiply two numbers in the GF(2^8) finite field defined 
 * by the modulo polynomial relation x^8 + x^4 + x^3 + x + 1 = 0
 * (the other way being to do carryless multiplication followed by a modular reduction)
 */
uint8_t gmul(uint8_t a, uint8_t b) {
	uint8_t p = 0; /* accumulator for the product of the multiplication */
	while (a != 0 && b != 0) {
        if (b & 1) /* if the polynomial for b has a constant term, add the corresponding a to p */
            p ^= a; /* addition in GF(2^m) is an XOR of the polynomial coefficients */

        if (a & 0x80) /* GF modulo: if a has a nonzero term x^7, then must be reduced when it becomes x^8 */
            a = (a << 1) ^ 0x11b; /* subtract (XOR) the primitive polynomial x^8 + x^4 + x^3 + x + 1 (0b1_0001_1011) – you can change it but it must be irreducible */
        else
            a <<= 1; /* equivalent to a*x */
        b >>= 1;
	}
	return p;
}
```

This example has [cache, timing, and branch prediction side-channel](wikipedia://en/481813) leaks, and is not suitable for use in cryptography.

### D programming example {#D_programming_example}

This [D](https://en.wikipedia.org/wiki/D_%28programming_language%29) program will multiply numbers in Rijndael's finite field and generate a [PGM](https://en.wikipedia.org/wiki/Netpbm_format#PGM_example) image:

```D
/**
Multiply two numbers in the GF(2^8) finite field defined
by the polynomial x^8 + x^4 + x^3 + x + 1.
*/
ubyte gMul(ubyte a, ubyte b) pure nothrow {
    ubyte p = 0;

    foreach (immutable ubyte counter; 0 .. 8) {
        p ^= -(b & 1) & a;
        auto mask = -((a >> 7) & 1);
        // 0b1_0001_1011 is x^8 + x^4 + x^3 + x + 1.
        a = cast(ubyte)((a << 1) ^ (0b1_0001_1011 & mask));
        b >>= 1;
    }

    return p;
}

void main() {
    import std.stdio, std.conv;
    enum width = ubyte.max + 1, height = width;

    auto f = File("rijndael_finite_field_multiplication.pgm", "wb");
    f.writefln("P5\n%d %d\n255", width, height);
    foreach (immutable y; 0 .. height)
        foreach (immutable x; 0 .. width) {
            immutable char c = gMul(x.to!ubyte, y.to!ubyte);
            f.write(c);
        }
}
```

This example does not use any branches or table lookups in order to avoid side channels and is therefore suitable for use in cryptography.
