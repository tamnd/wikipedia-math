# AES instruction set

::: {#o1 .subject cue=lead name="AES instruction set"}

An **Advanced Encryption Standard instruction set** (**AES instruction set**) is a set of instructions that are specifically designed to perform [AES encryption](https://en.wikipedia.org/wiki/AES_encryption) and decryption operations efficiently. These instructions are typically found in modern processors and can greatly accelerate AES operations compared to software implementations. An AES instruction set includes instructions for [key expansion](https://en.wikipedia.org/wiki/Key_expansion), encryption, and decryption using various key sizes (128-bit, 192-bit, and 256-bit).

:::

The [instruction set](https://en.wikipedia.org/wiki/Instruction_set) is often implemented as a set of instructions that can perform a single round of AES along with a special version for the last round which has a slightly different method.

When AES is implemented as an instruction set instead of as software, it can have improved security, as its [side channel attack](https://en.wikipedia.org/wiki/Side_channel_attack) surface is reduced.[^o2]

::: {#o4 .pointer-item cue=pointer name="AES-NI"}

## x86 architecture processors {#x86_architecture_processors}

AES-NI (or the Intel **Advanced Encryption Standard New Instructions**; **AES-NI**) was the first major implementation. AES-NI is an extension to the [x86](https://en.wikipedia.org/wiki/X86) [instruction set architecture](https://en.wikipedia.org/wiki/Instruction_set_architecture) for [microprocessors](https://en.wikipedia.org/wiki/Microprocessor) from [Intel](https://en.wikipedia.org/wiki/Intel_Corporation) and [AMD](https://en.wikipedia.org/wiki/Advanced_Micro_Devices) proposed by Intel in March 2008.[^o5]

A wider version of AES-NI, *[AVX-512 Vector AES instructions (VAES)](https://en.wikipedia.org/wiki/AVX-512#VAES)*, is found in [AVX-512](https://en.wikipedia.org/wiki/AVX-512).[^o6]

### Instructions {#Instructions}

::: {#o8 .table cue=table}

| Instruction | Description[^o9] |
|---|---|
| `AESENC` | Perform one round of an AES encryption flow |
| `AESENCLAST` | Perform the last round of an AES encryption flow |
| `AESDEC` | Perform one round of an AES decryption flow |
| `AESDECLAST` | Perform the last round of an AES decryption flow |
| `AESKEYGENASSIST` | Assist in AES round key generation |
| `AESIMC` | Assist in AES decryption round key generation. Applies [Inverse Mix Columns](wikipedia://en/2105621#InverseMixColumns) to round keys. |

:::

## Hardware acceleration in other architectures {#Hardware_acceleration_in_other_architectures}

AES support with unprivileged processor instructions is also available in the latest [SPARC](https://en.wikipedia.org/wiki/SPARC) processors ([T3](https://en.wikipedia.org/wiki/SPARC_T3), [T4](https://en.wikipedia.org/wiki/SPARC_T4), [T5](https://en.wikipedia.org/wiki/SPARC_T5), M5, and forward) and in latest [ARM](https://en.wikipedia.org/wiki/ARM_architecture) processors. The [SPARC T4](https://en.wikipedia.org/wiki/SPARC_T4) processor, introduced in 2011, has user-level instructions implementing AES rounds.[^o21] These instructions are in addition to higher level encryption commands. The [ARMv8-A](https://en.wikipedia.org/wiki/ARMv8) processor architecture, announced in 2011, including the ARM Cortex-A53 and A57 (but not previous v7 processors like the Cortex A5, 7, 8, 9, 11, 15 ) also have user-level instructions which implement AES rounds.[^o22]

### x86 CPUs offering non-AES-NI acceleration interfaces {#x86_CPUs_offering_non-AES-NI_acceleration_interfaces}

[VIA x86 CPUs](https://en.wikipedia.org/wiki/VIA_PadLock) and [AMD Geode](https://en.wikipedia.org/wiki/AMD_Geode) use driver-based accelerated AES handling instead. (See [Crypto API (Linux)](https://en.wikipedia.org/wiki/Crypto_API_%28Linux%29).)

The following chips, while supporting AES hardware acceleration, do not support AES-NI:

- AMD [Geode LX](https://en.wikipedia.org/wiki/Geode_%28processor%29#Geode_LX) processors[^o24]
- [VIA](https://en.wikipedia.org/wiki/VIA_Technologies), using [VIA PadLock](https://en.wikipedia.org/wiki/VIA_PadLock)[^o25][^o26]
  - [VIA C3 Nehemiah C5P (Eden-N) processors](https://en.wikipedia.org/wiki/VIA_C3)[^o27]
  - [VIA C7 Esther C5J processors](https://en.wikipedia.org/wiki/VIA_C7)[^o28]

### RISC-V architecture {#RISC-V_architecture}

The scalar and vector cryptographic instruction set extensions for the [RISC-V](https://en.wikipedia.org/wiki/RISC-V) architecture were ratified respectively on 2022 and 2023, which allowed RISC-V processors to implement hardware acceleration for AES, [GHASH](https://en.wikipedia.org/wiki/GHASH), [SHA-256](https://en.wikipedia.org/wiki/SHA-256), [SHA-512](https://en.wikipedia.org/wiki/SHA-512), [SM3](wikipedia://en/58049400), and [SM4](wikipedia://en/4446998).

Before the AES-specific instructions were available on RISC-V, a number of RISC-V chips included integrated AES co-processors. Examples include:

- Dual-core [RISC-V](https://en.wikipedia.org/wiki/RISC-V) 64 bits Sipeed-M1 support AES and SHA256.[^o37]
- RISC-V architecture based [ESP32](https://en.wikipedia.org/wiki/ESP32)-C (as well as Xtensa-based ESP32[^o38]), support AES, SHA, RSA, RNG, HMAC, [digital signature](wikipedia://en/59644) and XTS 128 for flash.[^o39]
- Bouffalo Labs BL602/604 32-bit RISC-V supports various AES and SHA variants.[^o40]

### POWER architecture {#POWER_architecture}

Since the [Power ISA v.2.07](https://en.wikipedia.org/wiki/Power_ISA#Power_ISA_v.2.07), the instructions `vcipher` and `vcipherlast` implement one round of AES directly.[^o42]

### IBM z/Architecture {#IBM_z/Architecture}

IBM z9 or later mainframe processors support AES as single-opcode (KM, KMC) AES ECB/CBC instructions via [IBM](https://en.wikipedia.org/wiki/IBM)'s CryptoExpress hardware.[^o44] These single-instruction AES versions are therefore easier to use than Intel NI ones, but may not be extended to implement other algorithms based on AES round functions (such as the [Whirlpool](https://en.wikipedia.org/wiki/Whirlpool_%28cryptography%29) and [Grøstl](wikipedia://en/20394803) hash functions).

### Other architectures {#Other_architectures}

- [Atmel XMEGA](https://en.wikipedia.org/wiki/Atmel_AVR)[^o46] (on-chip accelerator with parallel execution, not an instruction)
- [SPARC T3](https://en.wikipedia.org/wiki/SPARC_T3) and later processors have hardware support for several cryptographic algorithms, including AES.
- Cavium Octeon MIPS[^o47] All Cavium Octeon MIPS-based processors have hardware support for several cryptographic algorithms, including AES using special coprocessor 3 instructions.

## Performance {#Performance}

In *AES-NI Performance Analyzed*, Patrick Schmid and Achim Roos found "impressive results from a handful of applications already optimized to take advantage of Intel's AES-NI capability".[^o49] A performance analysis using the [Crypto++](https://en.wikipedia.org/wiki/Crypto++) [security library](https://en.wikipedia.org/wiki/Library_%28computing%29) showed an increase in throughput from approximately 28.0 cycles per byte to 3.5 cycles per byte with [AES](wikipedia://en/1260)/[GCM](wikipedia://en/5897139) versus a [Pentium 4](https://en.wikipedia.org/wiki/Pentium_4) with no acceleration.[^o50][^o51]

## Supporting software {#Supporting_software}

Most modern compilers can emit AES instructions.

A lot of security and cryptography software supports the AES instruction set, including the following notable core infrastructure:

- [Apple's FileVault 2](wikipedia://en/466854#FileVault_2) full-disk encryption in [macOS](https://en.wikipedia.org/wiki/MacOS) 10.10+
- NonStop [SSH2](wikipedia://en/28814#Version_2), NonStop cF [SSL](https://en.wikipedia.org/wiki/Secure_Sockets_Layer) Library and BackBox [VTC Software](https://en.wikipedia.org/wiki/Virtual_Tape_Library) in [HPE Tandem NonStop OS L-series](https://en.wikipedia.org/wiki/NonStop_%28server_computers%29)[^o53][^o54][^o55]
- [Cryptography API: Next Generation (CNG)](wikipedia://en/3302413) (requires [Windows Vista SP2](https://en.wikipedia.org/wiki/Windows_Vista_SP2) or [Windows 7](https://en.wikipedia.org/wiki/Windows_7))[^o56]

## Application beyond AES {#Application_beyond_AES}

A fringe use of the AES instruction set involves using it on block ciphers with a similarly-structured [S-box](wikipedia://en/240991), using [affine transform](https://en.wikipedia.org/wiki/Affine_transform) to convert between the two. [SM4](wikipedia://en/4446998), [Camellia](wikipedia://en/532475) and [ARIA](wikipedia://en/9013560) have been accelerated using AES-NI.[^o69][^o70][^o71] The [AVX-512 Galois Field New Instructions](https://en.wikipedia.org/wiki/AVX-512#GFNI) (GFNI) allows implementing these S-boxes in a more direct way.[^o72]

New cryptographic algorithms have been constructed to specifically use parts of the AES algorithm, so that the AES instruction set can be used for speedups. The AEGIS family, which offers [authenticated encryption](wikipedia://en/2244296), runs with at least twice the speed of AES.[^o73] AEGIS is an "additional finalist for high-performance applications" in the [CAESAR Competition](wikipedia://en/70035770).[^o74]
