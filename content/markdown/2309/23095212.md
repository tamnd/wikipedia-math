# FMA instruction set

::: {#o1 .subject cue=lead name="FMA instruction set"}

X86 Assembly/AVX, AVX2, FMA3, FMA4 The **FMA instruction set** is an extension to the 128- and 256-bit [Streaming SIMD Extensions](wikipedia://en/55365) instructions in the [x86](https://en.wikipedia.org/wiki/X86) [microprocessor](https://en.wikipedia.org/wiki/Microprocessor) [instruction set](https://en.wikipedia.org/wiki/Instruction_set) to perform [fused multiply–add](https://en.wikipedia.org/wiki/Fused_multiply–add) (FMA) operations.[^o2] There are two variants:

:::

- **FMA4** is supported in [AMD](https://en.wikipedia.org/wiki/AMD) processors starting with the [Bulldozer](https://en.wikipedia.org/wiki/Bulldozer_%28microarchitecture%29) architecture. FMA4 was performed in hardware before FMA3 was. Support for FMA4 has been removed since [Zen 1](https://en.wikipedia.org/wiki/Zen_1).[^o32]
- **FMA3** is supported in AMD processors starting with the [Piledriver](https://en.wikipedia.org/wiki/Piledriver_%28microarchitecture%29) architecture and [Intel](https://en.wikipedia.org/wiki/Intel_Corporation) starting with [Haswell processors](https://en.wikipedia.org/wiki/Haswell_%28microarchitecture%29) and [Broadwell processors](https://en.wikipedia.org/wiki/Broadwell_%28microarchitecture%29) since 2014.

## Instructions {#Instructions}

FMA3 and FMA4 instructions have almost identical functionality, but are not compatible. Both contain [fused multiply–add](https://en.wikipedia.org/wiki/Fused_multiply–add) (FMA) instructions for [floating-point](https://en.wikipedia.org/wiki/Floating-point) scalar and [SIMD](https://en.wikipedia.org/wiki/Single_instruction,_multiple_data) operations, but FMA3 instructions have three operands, while FMA4 ones have four. The FMA operation has the form *d* = round(*a* · *b* + *c*), where the round function performs a [rounding](wikipedia://en/169945) to allow the result to fit within the destination register if there are too many significant bits to fit within the destination.

The four-operand form (FMA4) allows *a*, *b*, *c* and *d* to be four different registers, while the three-operand form (FMA3) requires that *d* be the same register as *a*, *b* or *c*. The three-operand form makes the code shorter and the hardware implementation slightly simpler, while the four-operand form provides more programming flexibility.

See [XOP instruction set](wikipedia://en/22701763#Compatibility_issues) for more discussion of compatibility issues between Intel and AMD.

## FMA3 instruction set {#FMA3_instruction_set}

### CPUs with FMA3 {#CPUs_with_FMA3}

- AMD
  - [Piledriver](https://en.wikipedia.org/wiki/Piledriver_%28microarchitecture%29) (2012) and newer microarchitectures[^o6]
    - 2nd gen [APUs](https://en.wikipedia.org/wiki/AMD_Accelerated_Processing_Unit), "Trinity" (32nm), May 15, 2012
    - 2nd gen "Bulldozer" (bdver2) with Piledriver cores, October 23, 2012
- Intel
  - [Haswell](https://en.wikipedia.org/wiki/Haswell_%28microarchitecture%29) (2013) and newer processors, except [Pentiums](https://en.wikipedia.org/wiki/Pentium) and [Celerons](https://en.wikipedia.org/wiki/Celeron)[^o7][^o8]

### Excerpt from FMA3 {#Excerpt_from_FMA3}

Supported commands include

::: {#o10 .table cue=table}

| Mnemonic | Operation | Mnemonic | Operation |
|---|---|---|---|
| VFM**ADD** | `result = + a · b + c` | VFM**ADDSUB** | `result = a · b + c` for i = 1, 3, ... `result = a · b − c` for i = 0, 2, ... |
| VF**N**M**ADD** | `result = − a · b + c` |  |  |
| VFM**SUB** | `result = + a · b − c` | VFM**SUBADD** | `result = a · b − c` for i = 1, 3, ... `result = a · b + c` for i = 0, 2, ... |
| VF**N**M**SUB** | `result = − a · b − c` |  |  |

:::

**Note**

- VF**N**M**ADD** is `result = − a · b + c`, not `result = − (a · b + c)`.
- VF**N**M**SUB** generates a −0 when all inputs are zero.

Explicit order of operands is included in the mnemonic using numbers "132", "213", and "231":

::: {#o11 .table cue=table}

| Postfix 1 | Operation | possible memory operand | overwrites |
|---|---|---|---|
| **132** | `a = a · c + b` | `c` (factor) | `a` (other factor) |
| **213** | `a = b · a + c` | `c` (summand) | `a` (factor) |
| **231** | `a = b · c + a` | `c` (factor) | `a` (summand) |

:::

as well as operand format (packed or scalar) and size (single or double).

::: {#o12 .table cue=table}

| Postfix 2 | precision | size | Postfix 2 | precision | size |
|---|---|---|---|---|---|
| S**S** | Single | 00× 32 bit | S**D** | Double | 0× 64 bit |
| P**S**x |  | 4× 32 bit | P**D**x |  | 2× 64 bit |
| P**S**y |  | 8× 32 bit | P**D**y |  | 4× 64 bit |
| P**S**z |  | 16× 32 bit | P**D**z |  | 8× 64 bit |

:::

### CPUs with FMA4 {#CPUs_with_FMA4}

- AMD
  - "Heavy Equipment" processors
    - [Bulldozer-based](https://en.wikipedia.org/wiki/Bulldozer_%28microarchitecture%29) processors, October 12, 2011[^o16]
    - [Piledriver-based](https://en.wikipedia.org/wiki/Piledriver_%28microarchitecture%29) processors[^o17]
    - [Steamroller-based](https://en.wikipedia.org/wiki/Steamroller_%28microarchitecture%29) processors

  - [Zen](https://en.wikipedia.org/wiki/Zen_%28microarchitecture%29): WikiChip's testing shows FMA4 still appears to work (under the conditions of the tests) despite not being officially supported and not even reported by CPUID. This has also been confirmed by Agner Fog.[^o18] But other tests gave wrong results.[^o35] AMD Official Web Site FMA4 Support Note ZEN CPUs = AMD ThreadRipper 1900x, R7 Pro 1800, 1700, R5 Pro 1600, 1500, R3 Pro 1300, 1200, R3 2200G, R5 2400G.[^o19][^o20][^o21]
- Intel
  - Intel has not released CPUs with support for FMA4.

## History {#History}

The incompatibility between Intel's FMA3 and AMD's FMA4 is due to both companies changing plans without coordinating coding details with each other. AMD changed their plans from FMA3 to FMA4 while Intel changed their plans from FMA4 to FMA3 almost at the same time. The history can be summarized as follows:

- **August 2007:** [AMD](https://en.wikipedia.org/wiki/AMD) announces the [SSE5](wikipedia://en/13016550) instruction set, which includes 3-operand FMA instructions. A new coding scheme (DREX) is introduced for allowing instructions to have three operands.[^o25]
- **April 2008:** [Intel](https://en.wikipedia.org/wiki/Intel) announces their [AVX](wikipedia://en/16779711) and FMA instruction sets, including 4-operand FMA instructions. The coding of these instructions uses the new [VEX](https://en.wikipedia.org/wiki/VEX_prefix) coding scheme,[^o26] which is more flexible than AMD's DREX scheme.
- **December 2008:** Intel changes the specification for their FMA instructions from 4-operand to 3-operand instructions. The VEX coding scheme is still used.[^o27]
- **May 2009:** AMD changes the specification of their FMA instructions from the 3-operand DREX form to the 4-operand VEX form, compatible with the April 2008 Intel specification rather than the December 2008 Intel specification.[^o28]
- **October 2011:** AMD [Bulldozer](https://en.wikipedia.org/wiki/Bulldozer_%28microarchitecture%29) processor supports FMA4.[^o29]
- **January 2012:** AMD announces FMA3 support in future processors codenamed Trinity and Vishera; they are based on the [Piledriver](https://en.wikipedia.org/wiki/Piledriver_%28microarchitecture%29) architecture.[^o30]
- **May 2012:** AMD Piledriver processor supports both FMA3 and FMA4.[^o29]
- **June 2013:** Intel [Haswell](https://en.wikipedia.org/wiki/Haswell_%28microarchitecture%29) processor supports FMA3.[^o31]
- **February 2017:** The first generation of AMD [Ryzen](https://en.wikipedia.org/wiki/AMD_Ryzen) processors officially supports FMA3, but not FMA4 according to the [CPUID](https://en.wikipedia.org/wiki/CPUID) instruction.[^o32] There has been confusion regarding whether FMA4 was implemented or not on this processor due to errata in the initial patch to the [GNU Binutils](https://en.wikipedia.org/wiki/GNU_Binutils) package that has since been rectified.[^o33][^o34] One unconfirmed report of wrong results[^o35] led to some doubt, but Mysticial (Alexander Yee, developer of y-cruncher) debunked it:[^o36] FMA4 worked for bit-exact bignum calculations on his Zen 1 system for years, and the one report on Reddit never had any followup investigation to rule out mistakes in the testing software before being widely repeated. The initial Ryzen CPUs could be crashed by a particular sequence of FMA3 instructions, but updated CPU microcode fixes the problem.[^o37]
- **July 2019:** AMD [Zen 2](https://en.wikipedia.org/wiki/Zen_2) and later Ryzen processors don't support FMA4 at all.[^o38] They continue to support FMA3. Only Zen 1 and Zen+ have unofficial FMA4 support.

## Compiler and assembler support {#Compiler_and_assembler_support}

Different compilers provide different levels of support for FMA:

- [GCC](https://en.wikipedia.org/wiki/GNU_Compiler_Collection) supports FMA4 with -mfma4 since version 4.5.0[^o40] and FMA3 with -mfma since version 4.7.0.
- [Microsoft Visual C++](https://en.wikipedia.org/wiki/Microsoft_Visual_C++) 2010 SP1 supports FMA4 instructions.[^o41]
- [Microsoft Visual C++](https://en.wikipedia.org/wiki/Microsoft_Visual_C++) 2012 supports FMA3 instructions (if the processor also supports AVX2 instruction set extension).
- [Microsoft Visual C++](https://en.wikipedia.org/wiki/Microsoft_Visual_C++) since VC 2013
- [PathScale](https://en.wikipedia.org/wiki/PathScale) supports FMA4 with -mfma.[^o42]
- [LLVM](https://en.wikipedia.org/wiki/LLVM) 3.1 adds FMA4 support,[^o43] along with preliminary FMA3 support.[^o44]
- [Open64](https://en.wikipedia.org/wiki/Open64) 5.0 adds "limited support".
- [Intel compilers](https://en.wikipedia.org/wiki/Intel_Fortran_Compiler) support only FMA3 instructions.[^o40]
- [NASM](https://en.wikipedia.org/wiki/Netwide_Assembler) supports FMA3 instructions since version 2.03 and FMA4 instructions since 2.06.
- [FASM](https://en.wikipedia.org/wiki/FASM) supports both FMA3 and FMA4 instructions.
