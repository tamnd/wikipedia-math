# BD+

::: {#o1 .subject cue=lead name="BD+"}

**BD+** is a component of the [Blu-ray](https://en.wikipedia.org/wiki/Blu-ray) [digital rights management](wikipedia://en/18938226) system designed to prevent unauthorized [copying](https://en.wikipedia.org/wiki/Ripping) or playback of Blu-ray discs.

:::

BD+ was developed by [Cryptography Research](wikipedia://en/18356058) Inc. (CRI) and is based on their [Self-Protecting Digital Content](https://en.wikipedia.org/wiki/Self-Protecting_Digital_Content) (SPDC) concept.[^o2] BD+ was adopted by the [Blu-ray Disc Association](https://en.wikipedia.org/wiki/Blu-ray_Disc_Association) for protecting Blu-ray discs.[^o2][^o3]

While BD+ has not stemmed the flow of "cracked" high-definition content, it has made it necessary for those who wish to copy Blu-ray movies to reinvest resources to break each new version of security code.[^o4]

BD+ played a pivotal role in the [format war](https://en.wikipedia.org/wiki/High-definition_optical_disc_format_war) of Blu-ray and [HD DVD](https://en.wikipedia.org/wiki/HD_DVD). Several studios cited Blu-ray Disc's adoption of the BD+ anti-copying system as the reason they supported Blu-ray Disc over HD DVD. The copy protection scheme was to take "10 years" to crack, according to Richard Doherty, an analyst with Envisioneering Group.[^o5]

## History {#History}

In November 2007, the SPDC business unit and technology was acquired by [Macrovision](https://en.wikipedia.org/wiki/Macrovision) to complement its existing [Analog Copy Protection](https://en.wikipedia.org/wiki/Analog_Copy_Protection) (ACP) and [Ripguard](https://en.wikipedia.org/wiki/RipGuard) technology.[^o7]

In 2011, Irdeto acquired SPDC and BD+ from Macrovision (then known as [Rovi Corporation](https://en.wikipedia.org/wiki/Rovi_Corporation)).[^o8][^o9]

## Capabilities {#Capabilities}

BD+ is effectively a [virtual machine](https://en.wikipedia.org/wiki/Virtual_machine) embedded in authorized players. It allows content providers to include executable programs on Blu-ray Discs. Such programs can:[^o11]

- examine the host environment, to see if the player has been tampered with. Every licensed playback device manufacturer must provide the BD+ licensing authority with [memory footprints](https://en.wikipedia.org/wiki/Memory_footprint) that identify their devices.
- verify that the player's keys have not been changed.
- execute native code, possibly to patch an otherwise insecure system.
- transform the audio and video output. Parts of the content will not be viewable without letting the BD+-program repair it.

If a playback device manufacturer finds that its devices have been hacked, it can potentially release BD+-code that detects and circumvents the vulnerability. These programs can then be included in all new disc releases.[^o12]

The specifications of the BD+ virtual machine are only officially available to licensed device manufacturers. A list of licensed adopters is available from the BD+ website.[^o13] Both SlySoft (now [RedFox](https://en.wikipedia.org/wiki/RedFox)) and members of the [Doom9](https://en.wikipedia.org/wiki/Doom9) forum have [reverse engineered](https://en.wikipedia.org/wiki/Reverse_engineering) the virtual machine specification, however.

According to the reverse-engineered specification, the virtual machine consists of a 32-bit big endian [DLX](https://en.wikipedia.org/wiki/DLX)-like processor with 4MB of RAM. It has 32 32-bit registers available for use. A [TRAP instruction](https://en.wikipedia.org/wiki/Trap_%28computing%29) is used to allow the virtual machine host to perform more complex actions as system calls.[^o14]

To prevent simple, [static disassembly](https://en.wikipedia.org/wiki/Disassembly) of the BD+ code, an instruction filter is available that can perform an [XOR](https://en.wikipedia.org/wiki/XOR) operation on an opcode before executing it. By varying the instruction filter at runtime, the compiler can force an adversary to trace through the code at runtime before they can fully disassemble it.[^o15]

## Virtual machine {#Virtual_machine}

This program which can be found inside the BDSVM directory of a BD+ protected disc is called content code.[^o14] The content code is executed on a virtual big endian [DLX-like processor](https://en.wikipedia.org/wiki/DLX) interfacing 4 MB of memory. The processor supports 59 different instructions and a register set consisting of 32 general purpose registers and three special purpose registers for the instruction filter, the clock cycle counter and the program counter. The BD+ Virtual Machine applies memory protection by masking memory access addresses to prevent them from falling outside of the designated memory areas. The execution of content code starts at address 0x1000 relative to the beginning of the payload of the first block of the file 00001.svm (located inside the BDSVM directory).

### Traps {#Traps}

While the BD+ virtual machine is extremely simple, the interface between the virtual machine and the player is somewhat more complicated.[^o14] BD+ provides the content code with 25 [system calls](https://en.wikipedia.org/wiki/System_calls) or "traps". An overview is given in the table below. Note that the bits 00–07 of the trap id uniquely identify each trap within a group. The group id itself is specified by the bits 08–16 of the trap id. The group ids seen so far are 00 (event handling), 01 (cryptography operations), 02 (arithmetic operations), 03 (memory operations), 04 (slot memory access), 05 (device access) and 80 (debugging). [src/libbdplus/bdsvm/interface.c · master · VideoLAN / libbdplus · GitLab](https://code.videolan.org/videolan/libbdplus/-/blob/master/src/libbdplus/bdsvm/interface.c)

| Group ID | Trap ID | Name | Parameters |
|---|---|---|---|
| 00 | 000010 | TRAP\_Finished | 0F |
|  | 000020 | TRAP\_ConversionTable | 2 |
| 01 | 000110 | TRAP\_Aes | 5 |
|  | 000120 | TRAP\_PrivateKey | 5 |
|  | 000130 | TRAP\_Random | 2 |
|  | 000140 | TRAP\_Sha | 4 |
| 02 | 000210 | TRAP\_AddWithCarry | 3 |
|  | 000220 | TRAP\_MultiplyWithRipple | 4 |
|  | 000230 | TRAP\_XorBlock | 3 |
| 03 | 000310 | TRAP\_Memmove | 3 |
|  | 000320 | TRAP\_MemSearch | 5 |
|  | 000330 | TRAP\_Memset | 3 |
| 04 | 000410 | TRAP\_SlotAttach | 2 |
|  | 000420 | TRAP\_SlotRead | 2 |
|  | 000430 | TRAP\_SlotWrite | 1 |
| 05 | 000510 | TRAP\_ApplicationLayer | 3 |
|  | 000520 | TRAP\_DeviceDiscovery | 4 |
|  | 000530 | TRAP\_DiscoveryRAM | 3 |
|  | 000540 | TRAP\_LoadContentCode | 5 |
|  | 000550 | TRAP\_MediaCheck | 6 |
|  | 000560 | TRAP\_RunNative | 4 |
| 80 | 008010 | TRAP\_DebugLog | 2 |

:::

Each of these system calls can be invoked by the TRAP instruction (opcode 0x39). By convention register 29 is used as the [stack pointer](https://en.wikipedia.org/wiki/Stack_pointer) holding the memory address of the parameters. After parameter validation the system call is executed and a return code is written to register 1. During its execution the content code performs a series of tests to verify it is being executed in a trusted environment. One of these tests involves asking the player for its certificate with `TRAP_Discovery`. The RSA signature of this certificate is later verified by the content code using the public key of the license administration which is (optionally in obfuscated form) also stored in the content code. Later the player is asked to sign a random message with ECDSA by calling `TRAP_PrivateKey`. The generated signature is subsequently verified using the player's public key stored in the previously verified certificate.

### Events {#Events}

The BD+ virtual machine is event-driven. Five callbacks (events) are defined by the interface which the player may invoke to notify the content code of a variety of events, including the playback of various parts of the movie, shutdown, media eject events, or player security operations. The event data is exchanged using a dedicated memory area (0x00–0x3F). `TRAP_Finished` is invoked whenever the content code has finished processing an event. The first event invoked is `EVENT_Startup` which starts the execution of the content code.

::: {#o20 .table cue=table}

| Group ID | Event ID | Name | Parameters |
|---|---|---|---|
| 00 | 000000 | EVENT\_MediaInit | 1 |
|  | 000010 | EVENT\_Shutdown | 1 |
| 01 | 000110 | EVENT\_TitleInit | 2 |
| 02 | 000210 | EVENT\_ApplicationLayer | 2 |
|  | 000220 | EVENT\_ComputeSP | 3 |

:::

### Conversion table {#Conversion_table}

Before a BD+-capable disc is mastered, random sections of the .m2ts files are overwritten by random data, effectively corrupting parts of the content. The original data is stored encrypted and obfuscated within the BD+ content code.[^o14] After the content code has verified the security of the execution environment, it sends a table with repair instructions (the "conversion table" or "fix-up table") to the player using the system call `TRAP_FixUpTableSend`. The conversion table consists of one subtable for each .m2ts file on the disc. A subtable consists of multiple, possibly empty, segments which contain the repair descriptors. Each repair descriptor then provides the raw data and the offset needed to repair a small section of a .m2ts file, replacing the corrupted part of the file with the original data.

## Reverse engineering and emulation of BD+ implementations {#Reverse_engineering_and_emulation_of_BD+_implementations}

On November 8, 2007, [SlySoft](https://en.wikipedia.org/wiki/SlySoft) announced that BD+ discs can be copied with their [AnyDVD HD](https://en.wikipedia.org/wiki/AnyDVD_HD) software.[^o23] This was possible because first generation BD+ titles did not check if [AACS](wikipedia://en/11010249) was present. This allowed a user to play a ripped disc using only a specific version of Cyberlink's [PowerDVD](https://en.wikipedia.org/wiki/PowerDVD) (3319a), but not to transcode, otherwise manipulate the content, or play it back from a burned [BD-R](https://en.wikipedia.org/wiki/Blu-ray_Disc_recordable) or BD-RE. Updated versions of BD+ security code plugged this hole.

On January 9, 2008, engadgethd.com reported that Fox has stated that BD+ has yet to be compromised.[^o24] When asked how hi-def [20th Century Fox](https://en.wikipedia.org/wiki/20th_Century_Fox) titles had become available online, the rep reported that the titles were available as [HD DVDs](https://en.wikipedia.org/wiki/HD_DVD) in Europe.

On March 3, 2008, [SlySoft](https://en.wikipedia.org/wiki/SlySoft) updated AnyDVD HD allowing the full decryption of BD+,[^o25] allowing not only the viewing of the film itself but also playing and copying discs with third-party software.

On March 19, 2008, a new version of AnyDVD HD was released (6.4.0.0) that supported the full removal of the BD+ copy protection for all titles released to date.[^o26][^o27][^o25]

In May 2008 the Blu-ray release of *[Jumper](https://en.wikipedia.org/wiki/Jumper_%282008_film%29)* introduced a modified version of BD+ security code which prevented the Slysoft AnyDVD HD software from removing BD+. This modified version was again circumvented by Slysoft several months after Jumper was initially released.

In August 2008, members of the Doom9 forum began work on an independent project to create an open-source implementation of BD+.[^o14]

In late October 2008, the same Doom9 members made the first working repaired BD+ movie with the previously developed open source tools,[^o28] and as of November 1, 2008, have created code to debug content produced for BD+'s virtual machine.[^o29]

On November 2, 2008, Doom9 forums announced that early (pre-May 2008) BD+ discs can be played back using open source software only.[^o30]

In early November 2008 multiple versions of BD+ security code were released which, according to Slysoft, may take a few months to circumvent.[^o31]

On December 29, 2008 Slysoft announced that AnyDVD HD 6.5.0.2 decrypts copy protection on all current Blu-ray movies.[^o32]

On February 13, 2009 a 4th version of BD+ security code was discovered on the movie *[Australia](https://en.wikipedia.org/wiki/Australia_%282008_film%29)*,[^o33] rendering Slysoft's existing AnyDVD HD software ineffective.

On March 19, 2009 Slysoft announced that AnyDVD HD 6.5.3.1 adds support for some new BD+ protection in movies, e.g. *[Australia](https://en.wikipedia.org/wiki/Australia_%281989_film%29)*, *[The Robe](https://en.wikipedia.org/wiki/The_Robe_%28film%29)*, and *[South Pacific](https://en.wikipedia.org/wiki/South_Pacific_%282001_film%29)*.[^o34] Some BD+ movies were not supported by Slysoft's update, e.g. *[Slumdog Millionaire](https://en.wikipedia.org/wiki/Slumdog_Millionaire)*, *[The Day the Earth Stood Still](https://en.wikipedia.org/wiki/The_Day_the_Earth_Stood_Still)*, *[Marley & Me](https://en.wikipedia.org/wiki/Marley_&_Me_%282008_film%29)*, and the *X-Men* Trilogy.[^o35] Since then, Slysoft has released several updates adding support for newer titles.

On October 7, 2009 support for BD+ was announced for MakeMKV, making it the second application capable of handling all BD+ discs released to date.[^o36]

In 2010 four other companies released software that can decrypt BD+: DVDFab Blu-ray Copy, Pavtube Blu-ray Copy, and [BlindWrite](https://en.wikipedia.org/wiki/BlindWrite).

On December 18, 2013, the [VideoLAN](https://en.wikipedia.org/wiki/VideoLAN) developers released *libbdplus*, an open-source library for BD+ decryption. As with [libdvdcss](https://en.wikipedia.org/wiki/Libdvdcss), the API allows media players to use it transparently.[^o37]
