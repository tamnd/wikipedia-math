# Bridge (graph theory)

*Image: Graph cut edges.svg.* A graph with 16 vertices and six bridges (highlighted in red)

*Image: Undirected.svg.* An undirected connected graph with no bridge edges

::: {#o1 .subject cue=lead name="Bridge"}

In [graph theory](wikipedia://en/12401), a **bridge**, **isthmus**, **cut-edge**, or **cut arc** is an [edge](wikipedia://en/325802#edge) of a [graph](wikipedia://en/325806) whose deletion increases the graph's number of [connected components](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29).[^o2] Equivalently, an edge is a bridge if and only if it is not contained in any [cycle](wikipedia://en/168609). For a connected graph, a bridge can uniquely determine a [cut](wikipedia://en/2180494). A graph is said to be **bridgeless** or **isthmus-free** if it contains no bridges.

:::

This type of bridge should be distinguished from an unrelated meaning of "bridge" in graph theory, a subgraph separated from the rest of the graph by a specified subset of vertices; see [bridge](wikipedia://en/325802#bridge) in the [Glossary of graph theory](wikipedia://en/325802).

## Trees and forests {#Trees_and_forests}

A graph with $n$ nodes can contain at most $n-1$ bridges, since adding additional edges must create a cycle. The graphs with exactly $n-1$ bridges are exactly the [trees](wikipedia://en/48560), and the graphs in which every edge is a bridge are exactly the [forests](https://en.wikipedia.org/wiki/Forest_%28graph_theory%29).

In every undirected graph, there is an [equivalence relation](wikipedia://en/9259) on the vertices according to which two vertices are related to each other whenever there are two edge-disjoint paths connecting them. (Every vertex is related to itself via two length-zero paths, which are identical but nevertheless edge-disjoint.) The equivalence classes of this relation are called **2-edge-connected components**, and the bridges of the graph are exactly the edges whose endpoints belong to different components. The **bridge-block tree** of the graph has a vertex for every nontrivial component and an edge for every bridge.[^o4]

## Relation to vertex connectivity {#Relation_to_vertex_connectivity}

Bridges are closely related to the concept of [articulation vertices](https://en.wikipedia.org/wiki/Articulation_vertex), vertices that belong to every path between some pair of other vertices. The two endpoints of a bridge are articulation vertices unless they have a degree of 1, although it may also be possible for a non-bridge edge to have two articulation vertices as endpoints. Analogously to bridgeless graphs being 2-edge-connected, graphs without articulation vertices are [2-vertex-connected](https://en.wikipedia.org/wiki/K-vertex-connected_graph).

In a [cubic graph](wikipedia://en/980508), every cut vertex is an endpoint of at least one bridge.

## Bridgeless graphs {#Bridgeless_graphs}

A **bridgeless graph** is a graph that does not have any bridges. Equivalent conditions are that each [connected component](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29) of the graph has an [open ear decomposition](wikipedia://en/32183016),[^o8] that each connected component is [2-edge-connected](https://en.wikipedia.org/wiki/K-edge-connected_graph), or (by [Robbins' theorem](wikipedia://en/36633800)) that every connected component has a [strong orientation](wikipedia://en/16678715).[^o8]

An important [open problem](wikipedia://en/1333335) involving bridges is the [cycle double cover conjecture](https://en.wikipedia.org/wiki/Cycle_double_cover_conjecture), due to [Seymour](wikipedia://en/1575708) and [Szekeres](wikipedia://en/2563194) (1978 and 1979, independently), which states that every bridgeless graph admits a multi-set of simple cycles which contains each edge exactly twice.[^o9]

:::

## Tarjan's bridge-finding algorithm {#Tarjan's_bridge-finding_algorithm}

The first [linear time](https://en.wikipedia.org/wiki/Linear_time) algorithm (linear in the number of edges) for finding the bridges in a graph was described by [Robert Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan) in 1974.[^o11] It performs the following steps:

- Find a [spanning forest](https://en.wikipedia.org/wiki/Spanning_forest) of $G$
- Create a [Rooted forest](wikipedia://en/48560#Rooted_tree) $F$ from the spanning forest
- Traverse the forest $F$ in [preorder](https://en.wikipedia.org/wiki/Tree_traversal#Pre-order,_NLR) and number the nodes. Parent nodes in the forest now have lower numbers than child nodes.
- For each node $v$ in preorder (denoting each node using its preorder number), do:
  - Compute the number of forest descendants $ND(v)$ for this node, by adding one to the sum of its children's descendants.
  - Compute $L(v)$, the lowest preorder label reachable from $v$ by a path for which all but the last edge stays within the subtree rooted at $v$. This is the minimum of the set consisting of the preorder label of $v$, of the values of $L(w)$ at child nodes of $v$ and of the preorder labels of nodes reachable from $v$ by edges that do not belong to $F$.
  - Similarly, compute $H(v)$, the highest preorder label reachable by a path for which all but the last edge stays within the subtree rooted at $v$. This is the maximum of the set consisting of the preorder label of $v$, of the values of $H(w)$ at child nodes of $v$ and of the preorder labels of nodes reachable from $v$ by edges that do not belong to $F$.
  - For each node $w$ with parent node $v$, if $L(w) = w$ and $H(w) < w + ND(w)$ then the edge from $v$ to $w$ is a bridge.

## Bridge-finding with chain decompositions {#Bridge-finding_with_chain_decompositions}

A very simple bridge-finding algorithm[^o13] uses [chain decompositions](https://en.wikipedia.org/wiki/Chain_decomposition). Chain decompositions do not only allow to compute all bridges of a graph, they also allow to *read off* every [cut vertex](https://en.wikipedia.org/wiki/Cut_vertex) of *G* (and the [block-cut tree](wikipedia://en/4842394) of *G*), giving a general framework for testing 2-edge- and 2-vertex-connectivity (which extends to linear-time 3-edge- and 3-vertex-connectivity tests).

Chain decompositions are special ear decompositions depending on a DFS-tree *T* of *G* and can be computed very simply: Let every vertex be marked as unvisited. For each vertex *v* in ascending [DFS](wikipedia://en/97034)-numbers 1...*n*, traverse every backedge (i.e. every edge not in the DFS tree) that is incident to *v* and follow the path of tree-edges back to the root of *T*, stopping at the first vertex that is marked as visited. During such a traversal, every traversed vertex is marked as visited. Thus, a traversal stops at the latest at *v* and forms either a directed path or cycle, beginning with v; we call this path or cycle a *chain*. The *i*th chain found by this procedure is referred to as *C<sub>i</sub>*. *C=C<sub>1</sub>,C<sub>2</sub>,...* is then a *[chain decomposition](https://en.wikipedia.org/wiki/Chain_decomposition)* of *G*.

The following characterizations then allow to *read off* several properties of *G* from *C* efficiently, including all bridges of *G*.[^o13] Let *C* be a chain decomposition of a simple connected graph *G=(V,E)*.

1. *G* is 2-edge-connected if and only if the chains in *C* partition *E*.
1. An edge *e* in *G* is a bridge if and only if *e* is not contained in any chain in *C*.
1. If *G* is 2-edge-connected, *C* is an [ear decomposition](wikipedia://en/32183016).
1. *G* is 2-vertex-connected if and only if *G* has minimum degree 2 and *C<sub>1</sub>* is the only cycle in *C*.
1. A vertex *v* in a 2-edge-connected graph *G* is a cut vertex if and only if *v* is the first vertex of a cycle in *C - C<sub>1</sub>*.
1. If *G* is 2-vertex-connected, *C* is an [open ear decomposition](wikipedia://en/32183016).

## Bridges and Eulerian cycles {#Bridges_and_Eulerian_cycles}

Define an **[Eulerian graph](https://en.wikipedia.org/wiki/Eulerian_graph)** as a graph with an Eulerian cycle. Every Eulerian graph is bridgeless. This is because in an Eulerian graph every edge is a part of an Eulerian cycle. Hence, if the edge is deleted, then its endpoints remain connected through the rest of the cycle. But the opposite is not true.

Define an **almost Eulerian graph** as a graph that can be made Eulerian by adding a single edge (equivalently, a graph that contains an Eulerian trail). Every almost-Eulerian graph is almost-bridgeless, but the opposite is not true.

The classes of bridgeless graphs and almost-Eulerian graphs have a non-empty intersection (the Eulerian graphs are both bridgeless and almost-Eulerian), but they do not contain each other.[^o15]
