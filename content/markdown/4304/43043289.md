# Polygon covering

::: {#o1 .subject cue=lead name="Polygon covering"}

In [geometry](wikipedia://en/18973446), a **covering** of a [polygon](wikipedia://en/23621) is a set of primitive units (e.g. squares) whose [union](wikipedia://en/47949) equals the polygon. A **polygon covering problem** is a problem of finding a covering with a smallest number of units for a given polygon. This is an important class of problems in [computational geometry](wikipedia://en/176927).

:::

There are many different polygon covering problems, depending on the type of polygon being covered. An example polygon covering problem is: given a [rectilinear polygon](wikipedia://en/8779182), find a smallest set of squares whose union equals the polygon.

In some scenarios, it is not required to cover the entire polygon but only its edges (this is called *polygon edge covering*) or its vertices (this is called *polygon vertex covering*).

A *minimal covering* is a covering that does not contain any other covering (i.e. it is a local minimum). A *minimum covering* is a covering with a smallest number of units (i.e. a global minimum). Every minimum covering is minimal, but not vice versa.

## Related problems {#Related_problems}

In a [covering problem](wikipedia://en/1045640), the units in the covering are allowed to overlap, as long as their union is exactly equal to the target polygon. This is in contrast to a [packing problem](wikipedia://en/213003), in which the units must be disjoint and their union may be smaller than the target polygon, and to a [polygon partition](wikipedia://en/48191322) problem, in which the units must be disjoint *and* their union must be equal to the target polygon.

A polygon covering problem is a special case of the [set cover problem](wikipedia://en/870399). In general, the problem of finding a smallest set covering is NP-complete, but for special classes of polygons, a smallest polygon covering can be found in polynomial time.

## Covering a rectilinear polygon with squares {#Covering_a_rectilinear_polygon_with_squares}

A [rectilinear polygon](wikipedia://en/8779182) can always be covered with a finite number of vertices of the polygon.[^o4] The algorithm uses a local optimization approach: it builds the covering by iteratively selecting maximal squares that are essential to the cover (i.e., contain uncovered points not covered by other maximal squares) and then deleting from the polygon the points that become unnecessary (i.e., unneeded to support future squares). Here is a simplified pseudo-code of the algorithm:

- While the polygon *P* is not empty:
  - Select a [continuator square](wikipedia://en/8779182#Squares_in_a_rectilinear_polygon) *s* in *P*.
  - If the [balcony](wikipedia://en/8779182#Squares_in_a_rectilinear_polygon) of *s* is not yet covered, then add *s* to the covering.
  - Remove the balcony of *s* from *P*.
  - If what remains of *s* is a one-knob continuator, then remove from *P* a certain rectangle adjacent to the knob, taking care to leave a sufficient security distance for future squares.

*Image: Removing holes from a rectilinear polygon.png.*

For polygons which may contain holes, finding a minimum such covering is [NP-hard](https://en.wikipedia.org/wiki/NP-hard).[^o5] This sharp difference between hole-free and general polygons can be intuitively explained based on the following analogy between maximal squares in a rectilinear polygon and nodes in an [undirected graph](wikipedia://en/325806):[^o4]

- Some maximal squares have a continuous intersection with the boundary of the polygon; when they are removed, the remaining polygon remains connected. Such squares are called "continuators" and are analogous to leaf nodes – nodes with a single edge – that can be removed without disconnecting the graph.
- Other maximal squares are "separators": when they are removed, the polygon splits into two disconnected polygons. They are analogous to nodes with two or more edges that, when removed, leave a disconnected remainder.

In a hole-free rectilinear polygon, all maximal squares are either continuators or separators; thus, such a polygon is analogous to a [tree graph](https://en.wikipedia.org/wiki/Tree_graph). A general polygon is analogous to a general graph. Just like the [vertex cover](wikipedia://en/562782) problem is polynomial for tree graphs but NP-hard for general graphs, the square covering problem is linear for hole-free polygons but NP-hard for general polygons.

It is possible to use the linear algorithm to get a 2-approximation; i.e., a covering with at most 2 *opt* squares, where *opt* is the number of squares in a minimum covering:[^o6]

- For each hole, find a square *s* connecting the hole to the external boundary.
- Cut *s* from the polygon, then glue back two overlapping copies of *s* (see figure). The resulting polygon is not planar, but it still 2-dimensional, and now it has no holes.
- Now use the original algorithm to find a minimum covering.

The number of squares in the resulting covering is at most *opt* + *holes*, where *holes* is the number of holes. It is possible to prove that *opt* ≥ *holes*. Hence the number of squares in the covering is at most 2 *opt*.

## Covering a rectilinear polygon with rectangles {#Covering_a_rectilinear_polygon_with_rectangles}

For general rectilinear polygons, the problem of finding a minimum rectangle covering is NP-hard, even when the target polygon is hole-free.[^o26] Several partial solutions have been suggested to this problem:

In [orthogonally convex](https://en.wikipedia.org/wiki/Orthogonally_convex) polygons, the number of rectangles in a minimum covering is equal to the number of blocks in an [anti rectangle](https://en.wikipedia.org/wiki/Anti_rectangle), and this fact can be used to build a polynomial time algorithm for finding a minimum covering by rectangles.[^o8]; Even when the target polygon is only half-orthogonally convex (i.e. only in the *y* direction), a minimum covering by rectangles can be found in time O(*n*<sup>2</sup>), where *n* is the number of vertices of the polygon.[^o9]; An approximation algorithm which gives good empirical results on real-life data is presented by.[^o10]; For rectilinear polygons which may contain holes, there is an O($\sqrt{\log n}$) factor approximation algorithm.[^o11]

## Covering a rectilinear polygon with orthogonally convex polygons {#Covering_a_rectilinear_polygon_with_orthogonally_convex_polygons}

For a [rectilinear polygon](wikipedia://en/8779182) which is half-orthogonally convex (i.e. only in the *x* direction), a minimum covering by [orthogonally convex](https://en.wikipedia.org/wiki/Orthogonally_convex) polygons can be found in time O(*n*^2), where *n* is the number of vertices of the polygon. The same is true for a covering by rectilinear [star polygons](wikipedia://en/313303).[^o13]

The number of orthogonally-convex components in a minimum covering can, in some cases, be found without finding the covering itself, in time O(*n*).[^o14]

## Covering a rectilinear polygon with star polygons {#Covering_a_rectilinear_polygon_with_star_polygons}

A rectilinear [star polygon](wikipedia://en/313303) is a polygon *P* containing a point *p*, such that for every point *q* in *P*, there is an [orthogonally convex](https://en.wikipedia.org/wiki/Orthogonally_convex) polygon containing *p* and *q*.

The problem of covering a polygon with star polygons is a variant of the [art gallery problem](wikipedia://en/1448859).

The [visibility graph](wikipedia://en/1448291) for the problem of minimally covering hole-free [rectilinear polygons](wikipedia://en/8779182) with star polygons is a [perfect graph](wikipedia://en/670531). This perfectness property implies a polynomial algorithm for finding a minimum covering of any rectilinear polygon with rectilinear star polygons.[^o16]

## Covering a polygon without acute angles with squares or rectangles {#Covering_a_polygon_without_acute_angles_with_squares_or_rectangles}

The most general class of polygons for which coverings by squares or rectangles can be found is the class of polygons without acute interior angles. This is because an acute angle cannot be covered by a finite number of rectangles. This problem is NP-hard, but several approximation algorithms exist.[^o18]

## Covering a polygon with rectangles of a finite family {#Covering_a_polygon_with_rectangles_of_a_finite_family}

In some cases, a polygon has to be covered not with arbitrary rectangles but with rectangles from a finite family.[^o20]

## Covering a polygon with triangles {#Covering_a_polygon_with_triangles}

Finding the smallest set of triangles covering a given polygon is NP-hard. It is also hard to approximate - every polynomial-time algorithm might find a covering with size (1 + 1/19151) times the minimal covering.[^o22]

If the polygon is in [general position](wikipedia://en/383736) (i.e. no two edges are collinear), then every triangle can cover at most 3 polygon edges. Hence every [polygon triangulation](wikipedia://en/679384) is a 3-approximation.

If the covering is restricted to triangles whose vertices are vertices of the polygon (i.e. [Steiner points](https://en.wikipedia.org/wiki/Steiner_point_%28computational_geometry%29) are not allowed), then the problem is NP-complete.

If Steiner points are not allowed *and* the polygon is in [general position](wikipedia://en/383736) (i.e. no two edges are collinear), then every minimal covering without Steiner points is also a minimal partitioning of the polygon to triangles (i.e., the triangles in the minimal covering to not overlap).[^o22] Hence, the minimum covering problem is identical to the polygon triangulation problem, which can be solved in time O(*n*log *n*). Note that if we drop the general position assumption, there are polygons in which the triangles in the optimal covering overlap. Think of the [Star of David](https://en.wikipedia.org/wiki/Star_of_David) for example.

The problem of covering only the boundary of a polygon with triangles is NP-complete, but there is an efficient 2-approximation.[^o22]

## Covering a polygon with convex polygons {#Covering_a_polygon_with_convex_polygons}

Covering a polygon (which may contain holes) with convex polygons is NP-hard.[^o33] It has also been shown to be $\exists\mathbb{R}$-complete. [^o24] There is an O(log *n*) [approximation algorithm](wikipedia://en/563105).[^o25]

Covering a polygon with convex polygons is NP-hard even when the target polygon is [hole-free](wikipedia://en/1059530).[^o26] It is also [APX-hard](https://en.wikipedia.org/wiki/APX-hard),[^o25] but there is a 6-approximation algorithm for the hole-free case.[^o27] The problem is NP-complete when the covering must not introduce new vertices (i.e. [Steiner points](wikipedia://en/498304) are not allowed).[^o22]

## Covering a polygon with star polygons {#Covering_a_polygon_with_star_polygons}

Covering a simple polygon with star polygons is [$\exists\mathbb{R}$-complete](https://en.wikipedia.org/wiki/Existential_theory_of_the_reals), as is the version where a point in the kernel of each star must be contained in an edge of the polygon.[^o29]

## Covering a set of points with identical squares {#Covering_a_set_of_points_with_identical_squares}

Given a set *S* of points in the plane, and a set of identical squares, the goal is to find the smallest number of squares that can cover all points in *S*.

Suppose that, for each point *p* in *S*, we put a square centered at *p*. Let *G*<sub>S</sub> be the [intersection graph](wikipedia://en/7726759) of these squares. Note that two points in *S* can be covered by a single square, [if and only if](wikipedia://en/14922) the two squares centered at them overlap. Therefore, a square-covering of the points in *S* is equivalent to a [clique cover](wikipedia://en/17113364) of *G*<sub>S</sub>. Finding a smallest square-covering of *S* is NP-hard; the proof is by reduction from [3SAT](https://en.wikipedia.org/wiki/3SAT).[^o31]

## Other combinations {#Other_combinations}

Covering a polygon (which may contain holes) with spiral polygons is NP-hard.[^o33]

Covering a polygon with [pseudotriangles](wikipedia://en/10609147) has also been studied.
