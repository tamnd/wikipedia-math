# Hamiltonian path problem

::: {#o1 .subject cue=lead name="Hamiltonian path problem"}

The **Hamiltonian path problem** is a topic discussed in the fields of [complexity theory](wikipedia://en/7543) and [graph theory](wikipedia://en/12401). It decides if a [directed](wikipedia://en/19721986) or [undirected](https://en.wikipedia.org/wiki/Undirected_graph) [graph](wikipedia://en/325806), *G*, contains a [Hamiltonian path](wikipedia://en/244437), a path that visits every vertex in the graph exactly once. The problem may specify the start and end of the path, in which case the starting vertex *s* and ending vertex *t* must be identified.[^o2]

:::

The **Hamiltonian cycle problem** is similar to the Hamiltonian path problem, except it asks if a given graph contains a [Hamiltonian cycle](https://en.wikipedia.org/wiki/Hamiltonian_cycle). This problem may also specify the start of the cycle. The Hamiltonian cycle problem is a special case of the [travelling salesman problem](wikipedia://en/31248), obtained by setting the distance between two cities to one if they are adjacent and two otherwise, and verifying that the total distance travelled is equal to *n.* If so, the route is a Hamiltonian cycle.

The Hamiltonian path problem and the Hamiltonian cycle problem belong to the class of [NP-complete](wikipedia://en/23385892) problems, as shown in [Michael Garey](https://en.wikipedia.org/wiki/Michael_Garey) and [David S. Johnson](https://en.wikipedia.org/wiki/David_S._Johnson)'s book [Computers and Intractability: A Guide to the Theory of NP-Completeness](https://en.wikipedia.org/wiki/Computers_and_Intractability) and [Richard Karp's](wikipedia://en/298763) list of [21 NP-complete problems](wikipedia://en/2012564).[^o3][^o4]

## Reductions {#Reductions}

### Reduction from the path problem to the cycle problem {#Reduction_from_the_path_problem_to_the_cycle_problem}

The problems of finding a Hamiltonian path and a Hamiltonian cycle can be related as follows:

- In one direction, the Hamiltonian path problem for graph *G* can be related to the Hamiltonian cycle problem in a graph *H* obtained from *G* by adding a new [universal vertex](wikipedia://en/51352780) *x*, connecting *x* to all vertices of *G*. Thus, finding a Hamiltonian path cannot be significantly slower (in the worst case, as a function of the number of vertices) than finding a Hamiltonian cycle.
- In the other direction, the Hamiltonian cycle problem for a graph *G* is equivalent to the Hamiltonian path problem in the graph *H* obtained by adding terminal ([degree](wikipedia://en/1374448)-one) vertices *s* and *t* attached respectively to a vertex v of G and to *v',* a [cleaved copy](wikipedia://en/3758115#Vertex_cleaving) of *v* which gives *v'*the same neighbourhood as *v*. The Hamiltonian path in *H* running through vertices $s-v-x-\cdots-y-v'-t$ corresponds to the Hamiltonian cycle in *G* running through $v-x-\cdots-y(-v)$.[^o7]

::: {#o9 .definition kind=definition/construction cue=heading name="Algorithms"}

## Algorithms {#Algorithms}

### Brute force {#Brute_force}

To decide if a graph has a Hamiltonian path, one would have to check each possible path in the input graph G. There are *n*! different sequences of vertices that *might* be Hamiltonian paths in a given *n*-vertex graph (and are, in a [complete graph](wikipedia://en/85816)), so a [brute force search](https://en.wikipedia.org/wiki/Brute_force_search) algorithm that tests all possible sequences would be very slow.

### Partial paths {#Partial_paths}

An early exact algorithm for finding a Hamiltonian cycle on a directed graph was the enumerative algorithm of Martello.[^o4] A search procedure by Frank Rubin[^o12] divides the edges of the graph into three classes: those that must be in the path, those that cannot be in the path, and undecided. As the search proceeds, a set of decision rules classifies the undecided edges, and determines whether to halt or continue the search. Edges that cannot be in the path can be eliminated, so the search gets continually smaller. The algorithm also divides the graph into components that can be solved separately, greatly reducing the search size. In practice, this algorithm is still the fastest.

### Dynamic programming {#Dynamic_programming}

Also, a [dynamic programming](wikipedia://en/125297) algorithm of [Bellman, Held, and Karp](https://en.wikipedia.org/wiki/Held-Karp_algorithm) can be used to solve the problem in time O(*n*<sup>2</sup> 2<sup>*n*</sup>). In this method, one determines, for each set *S* of vertices and each vertex *v* in *S*, whether there is a path that covers exactly the vertices in *S* and ends at *v*. For each choice of *S* and *v*, a path exists for (*S*,*v*) if and only if *v* has a neighbor *w* such that a path exists for (*S* − *v*,*w*), which can be looked up from already-computed information in the dynamic program.[^o14][^o15]

### Monte Carlo {#Monte_Carlo}

Andreas Björklund provided an alternative approach using the [inclusion–exclusion principle](wikipedia://en/342684) to reduce the problem of counting the number of Hamiltonian cycles to a simpler counting problem, of counting cycle covers, which can be solved by computing certain matrix determinants. Using this method, he showed how to solve the Hamiltonian cycle problem in arbitrary *n*-vertex graphs by a [Monte Carlo algorithm](https://en.wikipedia.org/wiki/Monte_Carlo_algorithm) in time O(1.657<sup>*n*</sup>); for [bipartite graphs](wikipedia://en/244431) this algorithm can be further improved to time [O](wikipedia://en/44578#Little-o_notation)(1.415<sup>*n*</sup>).[^o17]

### Backtracking {#Backtracking}

For graphs of maximum degree three, a careful backtracking search can find a Hamiltonian cycle (if one exists) in time O(1.251<sup>*n*</sup>).[^o19]

### Boolean satisfiability {#Boolean_satisfiability}

Hamiltonian paths can be found using a [SAT solver](https://en.wikipedia.org/wiki/SAT_solver). The Hamiltonian path is NP-Complete meaning it can be [mapping reduced](https://en.wikipedia.org/wiki/Mapping_reducibility) to the [3-SAT problem](https://en.wikipedia.org/wiki/3-SAT). As a result, finding a solution to the Hamiltonian Path problem is equivalent to finding a solution for 3-SAT.

### Unconventional methods {#Unconventional_methods}

Because of the difficulty of solving the Hamiltonian path and cycle problems on conventional computers, they have also been studied in unconventional models of computing. For instance, [Leonard Adleman](https://en.wikipedia.org/wiki/Leonard_Adleman) showed that the Hamiltonian path problem may be solved using a [DNA computer](https://en.wikipedia.org/wiki/DNA_computing). Exploiting the parallelism inherent in chemical reactions, the problem may be solved using a number of chemical reaction steps linear in the number of vertices of the graph; however, it requires a factorial number of DNA molecules to participate in the reaction.[^o22]

An optical solution to the Hamiltonian problem has been proposed as well.[^o23] The idea is to create a graph-like structure made from optical cables and beam splitters which are traversed by light in order to construct a solution for the problem. The weak point of this approach is the required amount of energy which is exponential in the number of nodes.

:::

## Complexity {#Complexity}

The problem of finding a Hamiltonian cycle or path is in [FNP](wikipedia://en/663351); the analogous [decision problem](wikipedia://en/8336) is to test whether a Hamiltonian cycle or path exists. The directed and undirected Hamiltonian cycle problems were two of [Karp's 21 NP-complete problems](wikipedia://en/2012564). They remain NP-complete even for special kinds of graphs, such as:

- [bipartite graphs](wikipedia://en/244431),[^o25]
- undirected [planar graphs](wikipedia://en/24314) of maximum degree three,[^o26]
- directed planar graphs with indegree and outdegree at most two,[^o27]
- [bridgeless](https://en.wikipedia.org/wiki/Bridgeless_graph) undirected planar 3-[regular](wikipedia://en/85821) [bipartite graphs](wikipedia://en/244431),
- 3-connected 3-regular bipartite graphs,[^o28]
- subgraphs of the [square grid graph](wikipedia://en/19635706#Square_grid_graph),[^o29]
- cubic subgraphs of the square grid graph.[^o30]

However, for some special classes of graphs, the problem can be solved in polynomial time:

- [4-connected](https://en.wikipedia.org/wiki/K-vertex-connected_graph) planar graphs are always Hamiltonian by a result due to [Tutte](wikipedia://en/52021), and the computational task of finding a Hamiltonian cycle in these graphs can be carried out in linear time[^o31] by computing a so-called [Tutte path](wikipedia://en/80543180).
- Tutte proved this result by showing that every 2-connected planar graph contains a Tutte path. Tutte paths in turn can be computed in quadratic time even for 2-connected planar graphs,[^o32] which may be used to find Hamiltonian cycles and long cycles in generalizations of planar graphs.

Putting all of these conditions together, it remains open whether 3-connected 3-regular bipartite planar graphs must always contain a Hamiltonian cycle, in which case the problem restricted to those graphs could not be NP-complete; see [Barnette's conjecture](wikipedia://en/28059825).

In graphs in which all vertices have odd degree, an argument related to the [handshaking lemma](wikipedia://en/9607933) shows that the number of Hamiltonian cycles through any fixed edge is always even, so if one Hamiltonian cycle is given, then a second one must also exist.[^o33] However, finding this second cycle does not seem to be an easy computational task. [Papadimitriou](https://en.wikipedia.org/wiki/Christos_Papadimitriou) defined the [complexity class](wikipedia://en/502426) [PPA](wikipedia://en/25494843) to encapsulate problems such as this one.[^o34]

## Polynomial time verifier {#Polynomial_time_verifier}

*Image: Hamiltonian Path Problem.jpg.* The proposed solution {s,w,v,u,t} forms a valid Hamiltonian Path in the graph G.

The Hamiltonian path problem is NP meaning a proposed solution can be verified in [polynomial time](https://en.wikipedia.org/wiki/Polynomial-time).[^o2]

A verifier [algorithm](wikipedia://en/775) for Hamiltonian path will take as input a graph G, starting vertex s, and ending vertex t. Additionally, verifiers require a potential solution known as a [certificate](wikipedia://en/14933760), c. For the Hamiltonian Path problem, c would consist of a [string](wikipedia://en/27701) of vertices where the first vertex is the start of the proposed path and the last is the end.[^o36] The algorithm will determine if c is a valid [Hamiltonian Path](wikipedia://en/244437) in G and if so, accept.

To decide this, the algorithm first verifies that all of the vertices in G appear exactly once in c. If this check passes, next, the algorithm will ensure that the first vertex in c is equal to s and the last vertex is equal to t. Lastly, to verify that c is a valid path, the algorithm must check that every edge between vertices in c is indeed an edge in G. If any of these checks fail, the algorithm will reject. Otherwise, it will accept.[^o36][^o37]

The algorithm can check in polynomial time if the vertices in G appear once in c. Additionally, it takes polynomial time to check the start and end vertices, as well as the edges between vertices. Therefore, the algorithm is a polynomial time verifier for the Hamiltonian path problem.[^o36]

## Applications {#Applications}

### Networks on chip {#Networks_on_chip}

[Networks on chip](https://en.wikipedia.org/wiki/Network_on_a_chip) (NoC) are used in computer systems and [processors](https://en.wikipedia.org/wiki/Processor_%28computing%29) serving as communication for on-chip components.[^o41] The performance of NoC is determined by the method it uses to move [packets](https://en.wikipedia.org/wiki/Network_packet) of data across a [network](https://en.wikipedia.org/wiki/Computer_network).[^o42] The Hamiltonian Path problem can be implemented as a path-based method in [multicast routing](https://en.wikipedia.org/wiki/Multicast_routing). Path-based multicast algorithms will determine if there is a Hamiltonian path from the start [node](https://en.wikipedia.org/wiki/Node_%28networking%29) to each end node and send packets across the corresponding path. Utilizing this strategy guarantees [deadlock](https://en.wikipedia.org/wiki/Deadlock_%28computer_science%29) and [livelock](https://en.wikipedia.org/wiki/Livelock) free routing, increasing the efficiency of the NoC.[^o43]

### Computer graphics {#Computer_graphics}

[Rendering](https://en.wikipedia.org/wiki/Rendering_%28computer_graphics%29) engines are a form of [software](https://en.wikipedia.org/wiki/Software) used in [computer graphics](https://en.wikipedia.org/wiki/Computer_graphics) to generate images or models from input data.[^o45] In [three dimensional](wikipedia://en/3054853) graphics rendering, a common input to the engine is a [polygon mesh](https://en.wikipedia.org/wiki/Polygon_mesh). The time it takes to render the object is dependent on the rate at which the input is received, meaning the larger the input the longer the rendering time. For triangle meshes, however, the rendering time can be decreased by up to a factor of three. This is done through "ordering the triangles so that consecutive triangles share a face."[^o46] That way, only one vertex changes between each consecutive triangle. This ordering exists if the [dual graph](wikipedia://en/2536864) of the triangular mesh contains a Hamiltonian path.
