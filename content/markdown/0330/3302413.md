# Microsoft CryptoAPI

::: {#o1 .subject cue=lead name="Microsoft CryptoAPI"}

The Microsoft Windows platform specific **Cryptographic Application Programming Interface** (also known variously as **CryptoAPI**, **Microsoft Cryptography API**, **MS-CAPI** or simply **CAPI**) is an [application programming interface](https://en.wikipedia.org/wiki/Application_programming_interface) included with [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows) [operating systems](https://en.wikipedia.org/wiki/Operating_system) that provides services to enable developers to secure Windows-based applications using [cryptography](wikipedia://en/18934432). It is a set of [dynamically linked libraries](https://en.wikipedia.org/wiki/Dynamic-link_library) that provides an [abstraction layer](https://en.wikipedia.org/wiki/Abstraction_layer) which isolates programmers from the code used to encrypt the data. The Crypto API was first introduced in [Windows 95 OSR2](https://en.wikipedia.org/wiki/Windows_95_OSR2)[^o2] and [Windows NT 4.0](https://en.wikipedia.org/wiki/Windows_NT_4.0)[^o3] and enhanced in subsequent versions.

:::

CryptoAPI supports both [public-key](wikipedia://en/24222) and [symmetric key](https://en.wikipedia.org/wiki/Symmetric_key_algorithm) cryptography, though persistent symmetric keys are not supported. It includes functionality for encrypting and decrypting data and for [authentication](wikipedia://en/47967) using [digital certificates](https://en.wikipedia.org/wiki/Digital_certificate). It also includes a [cryptographically secure pseudorandom number generator](wikipedia://en/182249) function: [CryptGenRandom](wikipedia://en/6109234).

CryptoAPI works with a number of CSPs ([Cryptographic Service Providers](wikipedia://en/3168110)) installed on the machine. CSPs are the modules that do the actual work of encoding and decoding data by performing the cryptographic functions. Vendors of [HSMs](https://en.wikipedia.org/wiki/Hardware_security_module) may supply a CSP which works with their hardware.

## Cryptography API: Next Generation {#Cryptography_API:_Next_Generation}

[Windows Vista](https://en.wikipedia.org/wiki/Windows_Vista) features an update to the Crypto API known as **Cryptography API: Next Generation** (**CNG**). It has better API factoring to allow the same functions to work using a wide range of cryptographic algorithms, and includes a number of newer algorithms that are part of the [National Security Agency](wikipedia://en/21939) (NSA) [Suite B](https://en.wikipedia.org/wiki/NSA_Suite_B_Cryptography).[^o5] It is also flexible, featuring support for plugging custom cryptographic APIs into the CNG runtime. However, CNG Key Storage Providers still do not support symmetric keys.[^o6] CNG works in both [user](https://en.wikipedia.org/wiki/User_mode) and [kernel mode](https://en.wikipedia.org/wiki/Kernel_mode), and also supports all of the algorithms from the CryptoAPI. The Microsoft provider that implements CNG is housed in Bcrypt.dll.

CNG also supports [elliptic curve cryptography](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography) which, because it uses shorter keys for the same expected [level of security](https://en.wikipedia.org/wiki/Level_of_security), is more efficient than RSA.[^o7] The CNG API integrates with the [smart card](https://en.wikipedia.org/wiki/Smart_card) subsystem by including a Base Smart Card Cryptographic Service Provider (Base CSP) module which encapsulates the smart card API. Smart card manufacturers just have to make their devices compatible with this, rather than provide a from-scratch solution.

CNG also adds support for [Dual\_EC\_DRBG](wikipedia://en/14259066),[^o8] a [pseudorandom number generator](wikipedia://en/45524) defined in [NIST SP 800-90A](wikipedia://en/40611086) that could expose the user to eavesdropping by the [National Security Agency](wikipedia://en/21939) since it contains a [kleptographic](wikipedia://en/1660818) backdoor, unless the developer remembers to generate new base points with a different cryptographically secure pseudorandom number generator or a [true random number generator](https://en.wikipedia.org/wiki/Hardware_random_number_generator) and then publish the generated seed in order to remove the NSA backdoor. It is also very slow.[^o9] It is only used when called for explicitly.

CNG also replaces the default PRNG with [CTR\_DRBG](https://en.wikipedia.org/wiki/CTR_DRBG) using AES as the block cipher, because the earlier RNG which is defined in the now superseded FIPS 186-2 is based on either [DES](wikipedia://en/7978) or [SHA-1](wikipedia://en/26672), both which have been broken.[^o10] CTR\_DRBG is one of the two algorithms in NIST SP 800-90 endorsed by [Schneier](wikipedia://en/36732), the other being Hash\_DRBG.[^o9]
