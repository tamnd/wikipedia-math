# Repetition code

::: {#o1 .subject cue=lead name="Repetition code"}

In [coding theory](wikipedia://en/321869), the **repetition code** is one of the most basic [linear](wikipedia://en/1866743) [error-correcting codes](https://en.wikipedia.org/wiki/Error-correcting_code). In order to transmit a message over a noisy [channel](wikipedia://en/156700) that may corrupt the transmission in a few places, the idea of the repetition code is to just repeat the message several times. The hope is that the channel corrupts only a minority of these repetitions. This way, the receiver will notice that a transmission error occurred since the received data stream is not the repetition of a single message, and moreover, the receiver can recover the original message by looking at the received message in the data stream that occurs most often.

:::

Because of the bad error correcting performance coupled with the low [code rate](https://en.wikipedia.org/wiki/Code_rate) (ratio between useful information symbols and actual transmitted symbols), other [error correction codes](https://en.wikipedia.org/wiki/Error_correction_codes) are preferred in most cases. The chief attraction of the repetition code is the ease of implementation.

## Code parameters {#Code_parameters}

In the case of a binary repetition code, there exist two code words - all ones and all zeros - which have a length of $n$. Therefore, the minimum [Hamming distance](wikipedia://en/41227) of the code equals its length $n$. This gives the repetition code an error correcting capacity of $\tfrac{n-1}{2}$ (i.e. it will correct up to $\tfrac{n-1}{2}$ errors in any code word).

If the length of a binary repetition code is odd, then it's a [perfect code](https://en.wikipedia.org/wiki/Perfect_code).[^o3] The binary repetition code of length *n* is equivalent to the (*n*, 1)-[Hamming code](wikipedia://en/41226). A (*n*, 1) [BCH code](wikipedia://en/40779) is also a repetition code.

::: {#o5 .example cue=heading name="Example"}

## Example {#Example}

Consider a binary repetition code of length 3. The user wants to transmit the information bits `101`. Then the encoding maps each bit either to the all ones or all zeros code word, so we get the `111 000 111`, which will be transmitted.

Let's say three errors corrupt the transmitted bits and the received sequence is `111 010 100`. Decoding is usually done by a simple [majority decision](https://en.wikipedia.org/wiki/Majority_logic_decoding) for each code word. That leads us to `100` as the decoded information bits, because in the first and second code word occurred less than two errors, so the majority of the bits are correct. But in the third code word two bits are corrupted, which results in an erroneous information bit, since two errors lie above the error correcting capacity.

:::

## Applications {#Applications}

Despite their poor performance as stand-alone codes, use in [Turbo code](wikipedia://en/497535)-like iteratively decoded [concatenated coding](https://en.wikipedia.org/wiki/Concatenated_error_correction_codes) schemes, such as [repeat-accumulate](https://en.wikipedia.org/wiki/Repeat-accumulate_code) (RA) and accumulate-repeat-accumulate (ARA) codes, allows for surprisingly good error correction performance.

Repetition codes are one of the few known codes whose [code rate](https://en.wikipedia.org/wiki/Code_rate) can be automatically adjusted to varying [channel capacity](wikipedia://en/231204), by sending more or less parity information as required to overcome the channel noise, and it is the only such code known for non-[erasure channels](wikipedia://en/6948409). Practical adaptive codes for erasure channels have been invented only recently, and are known as [fountain codes](https://en.wikipedia.org/wiki/Fountain_code).

Some [UARTs](https://en.wikipedia.org/wiki/UART), such as the ones used in the [FlexRay](https://en.wikipedia.org/wiki/FlexRay) protocol, use a majority filter to ignore brief noise spikes. This spike-rejection filter can be seen as a kind of repetition decoder.
