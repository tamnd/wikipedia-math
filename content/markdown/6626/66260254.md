# Mixed-precision arithmetic

::: {#o1 .subject cue=lead name="Mixed-precision arithmetic"}

**Mixed-precision arithmetic** is a form of [floating-point arithmetic](wikipedia://en/11376) that uses numbers with varying widths in a single operation.

:::

## Overview {#Overview}

A common usage of mixed-precision arithmetic is for operating on inaccurate numbers with a small width and expanding them to a larger, more accurate representation. For example, two [half-precision](https://en.wikipedia.org/wiki/Half-precision_floating-point_format) or [bfloat16](https://en.wikipedia.org/wiki/Bfloat16_floating-point_format) (16-bit) floating-point numbers may be multiplied together to result in a more accurate [single-precision](https://en.wikipedia.org/wiki/Single-precision_floating-point_format) (32-bit) float.[^o3] In this way, mixed-precision arithmetic approximates [arbitrary-precision arithmetic](wikipedia://en/600892), albeit with a low number of possible precisions.

[Iterative algorithms](wikipedia://en/15237) (like [gradient descent](wikipedia://en/201489)) are good candidates for mixed-precision arithmetic. In an iterative algorithm like [square root](wikipedia://en/29208), a coarse integral guess can be made and refined over many iterations until the error in precision makes it such that the smallest addition or subtraction to the guess is still too coarse to be an acceptable answer. When this happens, the precision can be increased to something more precise, which allows for smaller increments to be used for the approximation.

[Supercomputers](https://en.wikipedia.org/wiki/Supercomputer) such as [Summit](https://en.wikipedia.org/wiki/Summit_%28supercomputer%29) utilize mixed-precision arithmetic to be more efficient with regards to memory and processing time, as well as power consumption.[^o3][^o4][^o5]

## Machine learning {#Machine_learning}

Mixed-precision arithmetic is used in the field of [machine learning](wikipedia://en/233488), since [gradient descent](wikipedia://en/201489) algorithms can use coarse and efficient half-precision floats for certain tasks, but can be more accurate if they use more precise but slower single-precision floats. Some platforms, including [Nvidia](https://en.wikipedia.org/wiki/Nvidia), [Intel](https://en.wikipedia.org/wiki/Intel), and [AMD](https://en.wikipedia.org/wiki/Advanced_Micro_Devices) CPUs and GPUs, provide mixed-precision arithmetic for this purpose, using coarse floats when possible, but expanding them to higher precision when necessary.[^o3][^o4][^o14][^o15]

### Automatic mixed precision {#Automatic_mixed_precision}

[PyTorch](https://en.wikipedia.org/wiki/PyTorch) implements automatic mixed-precision (AMP), which performs autocasting, gradient scaling, and loss scaling.[^o17][^o18]

- The weights are stored in a **master copy** at a high precision, usually in FP32.
- **Autocasting** means automatically converting a floating-point number between different precisions, such as from FP32 to FP16, during training. For example, [matrix multiplications](wikipedia://en/125280) can often be performed in FP16 without loss of accuracy, even if the master copy weights are stored in FP32. Low-precision weights are used during forward pass.
- **Gradient scaling** means multiplying [gradients](wikipedia://en/12461) by a constant factor during training, typically before the [weight optimizer](wikipedia://en/1180641) update. This is done to prevent the gradients from underflowing to zero when using low-precision data types like FP16. Mathematically, if the unscaled gradient is $\mathbf{g}$, the scaled gradient is $s\mathbf{g}$ where $s$ is the scaling factor. Within the optimizer update, the scaled gradient is cast to a higher precision before it is scaled down (no longer underflowing, as it is in a higher precision) to update the weights.
- **Loss scaling** means multiplying the loss function by a constant factor during training, typically before [backpropagation](https://en.wikipedia.org/wiki/Backpropagation). This is done to prevent the gradients from underflowing to zero when using low-precision data types. If the unscaled loss is $\mathcal{L}$, the scaled loss is $k\mathcal{L}$ where $k$ is the scaling factor. Since gradient scaling and loss scaling are mathematically equivalent by $\frac{\partial(k\mathcal{L})}{\partial\mathbf{w}} = k\frac{\partial\mathcal{L}}{\partial\mathbf{w}}$, loss scaling is an implementation of gradient scaling.

PyTorch AMP uses [exponential backoff](https://en.wikipedia.org/wiki/Exponential_backoff) to automatically adjust the scale factor for loss scaling. That is, it periodically increase the scale factor. Whenever the gradients contain a [NaN](https://en.wikipedia.org/wiki/NaN) (indicating overflow), the weight update is skipped, and the scale factor is decreased.
