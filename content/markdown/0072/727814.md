# TWIRL

::: {#o1 .subject cue=lead name="TWIRL"}

In [cryptography](wikipedia://en/18934432) and [number theory](wikipedia://en/21527), **TWIRL** (**The [Weizmann Institute](https://en.wikipedia.org/wiki/Weizmann_Institute) Relation Locator**) is a hypothetical hardware device designed to speed up the sieving step of the [general number field sieve](wikipedia://en/152734) [integer factorization](wikipedia://en/15491) algorithm.[^o2] During the sieving step, the algorithm searches for numbers with a certain mathematical relationship. In distributed factoring projects, this is the step that is parallelized to a large number of processors.

:::

TWIRL is still a hypothetical device — no implementation has been publicly reported. However, its designers, [Adi Shamir](wikipedia://en/57314) and [Eran Tromer](wikipedia://en/78318716), estimate that if TWIRL were built, it would be able to factor 1024-bit numbers in one year at the cost of "a few dozen million [US dollars](https://en.wikipedia.org/wiki/US_dollar)". TWIRL could therefore have enormous repercussions in [cryptography](wikipedia://en/18934432) and [computer security](https://en.wikipedia.org/wiki/Computer_security) — many high-security systems still use 1024-bit [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) keys, which TWIRL would be able to break in a reasonable amount of time and for reasonable costs.

The security of some important cryptographic algorithms, notably [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) and the [Blum Blum Shub](wikipedia://en/39599) [pseudorandom number generator](wikipedia://en/45524), rests in the difficulty of factorizing large integers. If factorizing large integers becomes easier, users of these algorithms will have to resort to using larger keys (computationally more expensive) or to using different algorithms, whose security rests on some other computationally hard problem (like the [discrete logarithm](wikipedia://en/181334) problem).
