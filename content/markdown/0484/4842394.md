# Biconnected component

vertex cut

*Image: Graph-Biconnected-Components.svg.* Each color corresponds to a biconnected component. Multi-colored vertices are cut vertices, and thus belong to multiple biconnected components.

::: {#o1 .subject cue=lead name="Biconnected component"}

In [graph theory](wikipedia://en/12401), a **biconnected component** or **block** (sometimes known as a **2-connected component**) is a maximal [biconnected](wikipedia://en/4989397) [subgraph](wikipedia://en/325802#Subgraphs). Any [connected graph](wikipedia://en/1614492#Connected_graph) decomposes into a [tree](wikipedia://en/48560) of biconnected components called the **block-cut tree** of the graph. The blocks are attached to each other at shared [vertices](wikipedia://en/638899) called **cut vertices** or **separating vertices** or **articulation points**. Specifically, a **cut vertex** is any vertex whose removal increases the number of [connected components](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29).[^o2] A block containing at most one cut vertex is called a **leaf block**, it corresponds to a [leaf vertex](wikipedia://en/638899#Types_of_vertices) in the block-cut tree.

:::

## Algorithms {#Algorithms}

### Linear time depth-first search {#Linear_time_depth-first_search}

The classic [sequential algorithm](https://en.wikipedia.org/wiki/Sequential_algorithm) for computing biconnected components in a connected [undirected graph](https://en.wikipedia.org/wiki/Undirected_graph) is due to [John Hopcroft](https://en.wikipedia.org/wiki/John_Hopcroft) and [Robert Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan) (1973).[^o6] It runs in [linear time](wikipedia://en/405944#Linear_time), and is based on [depth-first search](wikipedia://en/97034). This algorithm is also outlined as Problem 22-2 of [Introduction to Algorithms](https://en.wikipedia.org/wiki/Introduction_to_Algorithms) (both 2nd and 3rd editions).

The idea is to run a depth-first search while maintaining the following information:

1. the depth of each vertex in the depth-first-search tree (once it gets visited), and
1. for each vertex $v$, the lowest depth of neighbors of all descendants of $v$ (including $v$ itself) in the depth-first-search tree, called the $\mathbf{lowpoint}$.

The depth is standard to maintain during a depth-first search. The lowpoint of $v$ can be computed after visiting all descendants of $v$ (i.e., just before $v$ gets popped off the depth-first-search [stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29)) as the minimum of the depth of $v$, the depth of all neighbors of $v$ (other than the parent of $v$ in the depth-first-search tree) and the lowpoint of all children of $v$ in the depth-first-search tree.

The key fact is that a nonroot vertex $v$ is a cut vertex (or articulation point) separating two biconnected components [if and only if](wikipedia://en/14922) there is a child $y$ of $v$ such that $\operatorname{lowpoint}(y) \ge \operatorname{depth}(v)$. This property can be tested once the depth-first search returned from every child of $v$ (i.e., just before $v$ gets popped off the depth-first-search stack), and if **true**, $v$ separates the graph into different biconnected components. This can be represented by computing one biconnected component out of every such $y$ (a component which contains $y$ will contain the subtree of $y$, plus $v$), and then erasing the subtree of $y$ from the tree.

The root vertex must be handled separately: it is a cut vertex if and only if it has at least two children in the DFS tree. Thus, it suffices to simply build one component out of each child subtree of the root (including the root).

#### Pseudocode {#Pseudocode}

GetArticulationPoints(i)

visited\[i\] := **true** current\_time := current\_time+1 visit\_time\[i\] := current\_time low\[i\] := current\_time childCount := 0 isArticulation := **false**

**for each** j **in** Neighborhood(i) **do** **if** **not** visited\[j\] **then** parent\[j\] := i GetArticulationPoints(j) childCount := childCount + 1 **if** low\[j\] ≥ visit\_time\[i\] **then** isArticulation := **true** low\[i\] := Min (low\[i\], low\[j\]) **else if** j ≠ parent\[i\] **then** low\[i\] := Min (low\[i\], visit\_time\[j\]) **if** (parent\[i\] ≠ **null** **and** isArticulation) **or** (parent\[i\] = **null** **and** childCount > 1) **then** **Output** i as articulation point

Main

current\_time := 0 // global variable parent\[r\] := **null** GetArticulationPoints(r) // r is an arbitrary root

Note that the terms child and parent denote the relations in the DFS tree, not the original graph.

### Other algorithms {#Other_algorithms}

A simple alternative to the above algorithm uses [chain decompositions](https://en.wikipedia.org/wiki/Chain_decomposition), which are special ear decompositions depending on [DFS](wikipedia://en/97034)-trees.[^o9] Chain decompositions can be computed in linear time by this [traversing rule](wikipedia://en/1305071#Bridge-Finding_with_Chain_Decompositions). Let $C$ be a chain decomposition of $G$. Then $G$ is 2-vertex-connected if and only if $G$ has minimum [degree](wikipedia://en/1374448) 2 and $C_{1}$ is the only [cycle](wikipedia://en/168609) in $C$. This gives immediately a linear-time 2-connectivity test and can be extended to list all cut vertices of $G$ in linear time using the following statement: A vertex $v$ in a connected graph $G$ (with minimum degree 2) is a cut vertex if and only if $v$ is incident to a [bridge](wikipedia://en/1305071) or $v$ is the first vertex of a cycle in $C - C_{1}$. The list of cut vertices can be used to create the [block-cut tree](wikipedia://en/4842394#Block-cut_tree) of $G$ in linear time.

In the [online](https://en.wikipedia.org/wiki/Online_algorithm) version of the problem, vertices and edges are added (but not removed) dynamically, and a data structure must maintain the biconnected components. [Jeffery Westbrook](https://en.wikipedia.org/wiki/Jeffery_Westbrook) and [Robert Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan) (1992) [^o10] developed an efficient data structure for this problem based on [disjoint-set data structures](https://en.wikipedia.org/wiki/Disjoint-set_data_structure). Specifically, it processes $n$ vertex additions and $m$ edge additions in $O(m \alpha(m, n))$ total time, where $\alpha$ is the [inverse Ackermann function](https://en.wikipedia.org/wiki/Inverse_Ackermann_function). This time bound is proved to be optimal.

[Uzi Vishkin](https://en.wikipedia.org/wiki/Uzi_Vishkin) and [Robert Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan) (1985) [^o11] designed a [parallel algorithm](https://en.wikipedia.org/wiki/Parallel_algorithm) on CRCW [PRAM](https://en.wikipedia.org/wiki/Parallel_random-access_machine) that runs in $O(\log n)$ time with $n + m$ processors.

Another algorithm has been provided by Harold Gabow, in his paper "Path-based depth-first search for strong and biconnected components" (2000).[^o12]

## Related structures {#Related_structures}

### Equivalence relation {#Equivalence_relation}

One can define a [binary relation](wikipedia://en/3931) on the edges of an arbitrary undirected graph, according to which two edges $e$ and $f$ are related if and only if either $e = f$ or the graph contains a [simple cycle](https://en.wikipedia.org/wiki/Simple_cycle) through both $e$ and $f$. Every edge is related to itself, and an edge $e$ is related to another edge $f$ if and only if $f$ is related in the same way to $e$. Less obviously, this is a [transitive relation](wikipedia://en/200463): if there exists a simple cycle containing edges $e$ and $f$, and another simple cycle containing edges $f$ and $g$, then one can combine these two cycles to find a simple cycle through $e$ and $g$. Therefore, this is an [equivalence relation](wikipedia://en/9259), and it can be used to partition the edges into equivalence classes, subsets of edges with the property that two edges are related to each other if and only if they belong to the same [equivalence class](wikipedia://en/9260). The subgraphs formed by the edges in each equivalence class are the biconnected components of the given graph. Thus, the biconnected components partition the edges of the graph; however, they may share vertices with each other.[^o15]

### Block graph {#Block_graph}

The **block graph** of a given graph $G$ is the [intersection graph](wikipedia://en/7726759) of its blocks. Thus, it has one vertex for each block of $G$, and an edge between two vertices whenever the corresponding two blocks share a vertex. A graph $H$ is the block graph of another graph $G$ exactly when all the blocks of $H$ are complete subgraphs. The graphs $H$ with this property are known as the [block graphs](wikipedia://en/29106883).[^o17]

::: {#o19 .pointer-item cue=pointer name="Block tree"}

### Block-cut tree {#Block-cut_tree}

A **cutpoint**, **cut vertex**, or **articulation point** of a graph $G$ is a vertex that is shared by two or more blocks. The structure of the blocks and cutpoints of a connected graph can be described by a [tree](wikipedia://en/48560) called the **block-cut tree** or **BC-tree**. This tree has a vertex for each block and for each articulation point of the given graph. There is an edge in the block-cut tree for each pair of a block and an articulation point that belongs to that block.[^o20]
