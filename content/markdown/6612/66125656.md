# Enumeration reducibility

::: {#o1 .subject cue=lead name="Enumeration reducibility"}

In [computability theory](wikipedia://en/155414), **enumeration reducibility** (or **e-reducibility** for short) is a specific type of [reducibility](wikipedia://en/9719800). Roughly speaking, *A* is enumeration-reducible to *B* if an enumeration of *B* can be algorithmically converted to an enumeration of *A*. In particular, if *B* is [computably enumerable](https://en.wikipedia.org/wiki/Computably_enumerable), then *A* also is.

:::

## Introduction {#Introduction}

In one of the possible formalizations of the concept, a [Turing reduction](wikipedia://en/1188375) from *A* to *B* is a [Turing machine](wikipedia://en/30403) augmented with a special instruction "query the [oracle](wikipedia://en/22431)". This instruction takes an integer *x* and instantly returns whether *x* belongs to *B*. The oracle machine should [decide](https://en.wikipedia.org/wiki/Decidable_problem) *A*, possibly using this special capability to decide *B*. Informally, the existence of a Turing reduction from *A* to *B* means that if it is possible to decide *B*, then this can be used to decide *A*.

Enumeration reducibility is a variant whose informal explanation is, instead, that if it is possible to enumerate *B*, then this can be used to enumerate *A*. The reduction can be defined by a Turing machine with a special oracle query instruction that takes no parameter, and either returns a new element of *B*, or returns no output. The oracle supplies the elements of *B* in any order. It can possibly return no output for some queries before resuming the enumeration. The machine should similarly enumerate the members of *A*, in any order and at any pace.[^o3] Repetitions in the enumerations of *A* and *B* may be permitted or not; the concept is equivalent in both cases. Although this could be made precise, the definition given below is more common since it is formally simpler.

Enumeration reducibility is a form of [positive reducibility](https://en.wikipedia.org/wiki/Reduction_%28recursion_theory%29#Reductions_stronger_than_Turing_reducibility), in the sense that the oracle machine receives information about which elements are in *B* (positive information), but no information about which elements are *not* in *B* (negative information). Indeed, if an element has not been listed yet, the oracle machine cannot know whether it will be listed later, or never.

The concept of enumeration reducibility was first introduced by the results of [John Myhill](wikipedia://en/2611636), which concluded that "a set is [many-one complete](wikipedia://en/362983) if and only if it is [recursively enumerable](https://en.wikipedia.org/wiki/Recursively_enumerable_set) and its [complement](wikipedia://en/54347) is productive".[^o4] This result extends to enumeration reducibility as well. Enumeration reducibility was later formally codified by [Rogers](https://en.wikipedia.org/wiki/Hartley_Rogers,_Jr.) and his collaborator [Richard M. Friedberg](https://en.wikipedia.org/wiki/Richard_M._Friedberg) in *Zeitschrift für mathematische Logik und Grundlagen der Mathematik* (the predecessor of *[Mathematical Logic Quarterly](https://en.wikipedia.org/wiki/Mathematical_Logic_Quarterly)*) in 1959.[^o5]

## Definition {#Definition}

Source:[^o8]

Let $(D_u)$ be a [standard numbering](wikipedia://en/2399097) of finite subsets of $\mathbb{N}$, and let $\langle \bullet, \bullet \rangle$ be a standard [pairing function](wikipedia://en/1145848). A set $A \subseteq \mathbb{N}$ is **enumeration reducible** to a set $B \subseteq \mathbb{N}$ if there exists a [computably enumerable set](wikipedia://en/332090) $W$ such that for all $x \in \mathbb{N}$,

$$x \in A \iff \exists u\ (D_u \subseteq B \land \langle x, D \rangle \in W)$$

When *A* is enumeration reducible to *B*, we write $A \leq_e B$. The relation $\leq_e$ is a [preorder](wikipedia://en/23582). Its associated [equivalence relation](wikipedia://en/9259) is denoted by $\equiv_e$.[^o9]

:::

::: {#o11 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

- The [supremum](https://en.wikipedia.org/wiki/Supremum) (least upper bound, join) of sets $A$ and $B$ with respect to $\leq_e$ is given by the [disjoint union](wikipedia://en/188946)

$A\oplus B=\{2n:n\in A\}\cup\{2n+1:n\in B\}.$[^o16]

- *A* is [Turing reducible](wikipedia://en/1188375) to *B* if and only if $A^+$ is enumeration reducible to $B^+$, where the plus operator is defined as $A^+ := A \oplus \overline{A}$.[^o16] Informally, this operator encodes the positive and negative information about *A* in a positive way. Likewise, *A* is computably enumerable with oracle *B* if and only if *A* is enumeration reducible to $B^+$.
- Furthermore, *A* is enumeration reducible to *B* if and only if, for all *X* such that *B* is computably enumerable with oracle *X*, it holds that *A* is also computably enumerable with oracle *X*. This is [Selman's theorem](https://en.wikipedia.org/wiki/Selman's_theorem).

:::

## Variants {#Variants}

### Strong enumeration reducibilities {#Strong_enumeration_reducibilities}

In addition to enumeration reducibility, there exist strong versions, the most important one being *s*-reducibility (named after [Robert M. Solovay](wikipedia://en/3160110)). Informally, a computably enumerable real set $A$ is *s*-reducible to another computably enumerable real set $B$ if $B$ is at least as difficult to be approximated as $A$.[^o15] This method shows similarity to *e*-reducibility in that it compares the elements of multiple sets. In addition, the structure of *s*-degrees have natural analogs in the enumeration degrees.[^o16]

The reasoning for using *s*-reducibility is summarized by Omandaze and Sorbi as a result of positive reducibility models being unable to answer certain [oracle](wikipedia://en/22431) questions (e.g. an answer to "Is $x\in A$?" is only given if $x\in A$, and is not true for the inverse.) because they inherently model computational situations where incomplete oracle information is available.[^o17] This is in contrast from the well-studied [Turing reducibility](wikipedia://en/1188375), in which information is captured in both negative and positive values. In addition, Turing reducibility uses information that is provided immediately and without delay. A strong reducibility is utilized in order to prevent problems occurring when incomplete information is supplied.

### Partial functions {#Partial_functions}

*E*-reducibility can be defined for [partial functions](wikipedia://en/23577) as well. Writing graph$(f)=\{\langle x,y\rangle$ $|$ $f(x)=y\}$, etc., we can define for partial functions $f,g$:[^o19]

$f\leq_eg\Leftrightarrow$ graph$(f)\leq_e$ graph$(g).$

[Kleene's recursion theorem](wikipedia://en/155407) introduces the notion of *relative partial recursiveness*, which, by means of systems of equations, can demonstrate equivalence through $\leq_e$ between graphs of partial functions.[^o20] *E*-reducibility relates to *relative partial recursiveness* in the same way that Turing reducibility relates to [μ-recursiveness](wikipedia://en/26469).[^o16]
