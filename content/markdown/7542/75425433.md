# Center-of-gravity method

::: {#o1 .subject cue=lead name="Center-of-gravity method"}

The **center-of-gravity method** is a theoretic algorithm for [convex optimization](wikipedia://en/1674411). It can be seen as a generalization of the [bisection method](wikipedia://en/646651) from one-dimensional functions to multi-dimensional functions.[^o2] It is theoretically important as it attains the optimal convergence rate. However, it has little practical value as each step is very computationally expensive.

:::

## Input {#Input}

Our goal is to solve a [convex optimization](wikipedia://en/1674411) problem of the form:

> **minimize *f*(*x*) s.t. *x* in *G*,**

where *f* is a [convex function](wikipedia://en/245568), and *G* is a [convex subset](wikipedia://en/6292) of a Euclidean space *R<sup>n</sup>*.

We assume that we have a "subgradient oracle": a routine that can compute a [subgradient](https://en.wikipedia.org/wiki/Subgradient) of *f* at any given point (if *f* is differentiable, then the only subgradient is the [gradient](wikipedia://en/12461) $\nabla f$; but we do not assume that *f* is differentiable).

::: {#o5 .definition kind=definition/construction cue=heading name="Method"}

## Method {#Method}

The method is [iterative](wikipedia://en/15237). At each iteration *t*, we keep a convex region *G<sub>t</sub>*, which surely contains the desired minimum. Initially we have *G*<sub>0</sub> = *G*. Then, each iteration *t* proceeds as follows.

- Let *x<sub>t</sub>* be the [center of gravity](wikipedia://en/173961) of *G*<sub>t</sub>.
- Compute a subgradient at *x<sub>t</sub>*, denoted *f*'(*x<sub>t</sub>*).
  - By definition of a subgradient, the graph of *f* is above the subgradient, so for all *x* in *G*<sub>t</sub>: *f*(*x*)−*f*(*x<sub>t</sub>*) ≥ (*x*−*x<sub>t</sub>*)<sup>T</sup>f'(*x<sub>t</sub>*).
- If *f*'(*x<sub>t</sub>*)=0, then the above implies that *x<sub>t</sub>* is an exact minimum point, so we terminate and return *x<sub>t.</sub>*
- Otherwise, let *G<sub>t</sub>*<sub>\+1</sub> := {x in G<sub>t</sub>: (*x*−*x<sub>t</sub>*)<sup>T</sup>f'(*x<sub>t</sub>*) ≤ 0}.

Note that, by the above inequality, every minimum point of *f* must be in *G<sub>t</sub>*<sub>\+1.</sub>[^o2]

:::

## Convergence {#Convergence}

It can be proved that

> $Volume(G_{t+1})\leq \left[1-\left(\frac{n}{n+1}\right)^n\right]\cdot Volume(G_t)$ .

Therefore,

> $$f(x_t) - \min_G f \leq \left[1-\left(\frac{n}{n+1}\right)^n\right]^{t/n} [\max_G f - \min_G f].$$

In other words, the method has [linear convergence](https://en.wikipedia.org/wiki/Linear_convergence) of the residual objective value, with convergence rate $\left[1-\left(\frac{n}{n+1}\right)^n\right]^{1/n} \leq (1-1/e)^{1/n}$. To get an ε-approximation to the objective value, the number of required steps is at most $2.13 n \ln(1/\epsilon) + 1$.[^o2]

## Computational complexity {#Computational_complexity}

The main problem with the method is that, in each step, we have to compute the center-of-gravity of a polytope. All the methods known so far for this problem require a number of arithmetic operations that is exponential in the dimension *n.[^o2]* Therefore, the method is not useful in practice when there are 5 or more dimensions.

## See also {#See_also}

The [ellipsoid method](wikipedia://en/4331203) can be seen as a tractable approximation to the center-of-gravity method. Instead of maintaining the feasible polytope *G<sub>t</sub>*, it maintains an ellipsoid that contains it. Computing the center-of-gravity of an ellipsoid is much easier than of a general polytope, and hence the ellipsoid method can usually be computed in polynomial time.
