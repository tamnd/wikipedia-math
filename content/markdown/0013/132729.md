# Tuple

::: {#o1 .subject cue=lead name="Tuple"}

In [mathematics](wikipedia://en/18831), a **tuple** is a finite [sequence](wikipedia://en/27838) (or ordered list) of [numbers](wikipedia://en/21690). More generally, it is a sequence of [mathematical objects](wikipedia://en/19453961), called the *elements* of the tuple. An **$n$-tuple** is a tuple of $n$ elements, where $n$ is a non-negative [integer](wikipedia://en/14563). There is only one 0-tuple, called the *empty tuple*. A 1-tuple and a 2-tuple are commonly called a [*singleton*](wikipedia://en/381798) and an *[ordered pair](wikipedia://en/22362)*, respectively. The term *"infinite tuple"* is occasionally used for *"infinite sequences"*.

:::

Tuples are usually written by listing the elements within parentheses "$( )$" and separated by commas; for example, $(2, 7, 4, 1, 7)$ denotes a 5-tuple. Other types of brackets are sometimes used, although they may have a different meaning.

An $n$-tuple can be formally defined as the [image](wikipedia://en/579311) of a [function](wikipedia://en/185427) that has the set of the first $n$ [natural numbers](wikipedia://en/21474) as its [domain](wikipedia://en/50263) ($1, 2, ..., n$). Tuples may be also defined from ordered pairs by a [recurrence](wikipedia://en/146806) starting from an ordered pair; indeed, an $n$-tuple can be identified with the ordered pair of its $(n - 1)$ first elements and its $n$th element, for example, $\left( \left( \left( 1,2 \right),3 \right),4 \right)=\left( 1,2,3,4 \right)$.

In [computer science](https://en.wikipedia.org/wiki/Computer_science), tuples come in many forms. Most typed [functional programming](https://en.wikipedia.org/wiki/Functional_programming) languages implement tuples directly as [product types](wikipedia://en/14892710),[^o2] tightly associated with [algebraic data types](https://en.wikipedia.org/wiki/Algebraic_data_type), [pattern matching](https://en.wikipedia.org/wiki/Pattern_matching), and [destructuring assignment](https://en.wikipedia.org/wiki/Assignment_%28computer_science%29#Parallel_assignment).[^o3] Many programming languages offer an alternative to tuples, known as [record types](https://en.wikipedia.org/wiki/Record_%28computer_science%29), featuring unordered elements accessed by label.[^o4] A few programming languages combine ordered tuple product types and unordered record types into a single construct, as in [C structs](https://en.wikipedia.org/wiki/Struct_%28C_programming_language%29) and Haskell records. [Relational databases](https://en.wikipedia.org/wiki/Relational_database) may formally identify their [rows](https://en.wikipedia.org/wiki/Row_%28database%29) (records) as *tuples*.

Tuples also occur in [relational algebra](wikipedia://en/175285); when programming the [semantic web](https://en.wikipedia.org/wiki/Semantic_web) with the [Resource Description Framework](https://en.wikipedia.org/wiki/Resource_Description_Framework) (RDF); in [linguistics](https://en.wikipedia.org/wiki/Linguistics);[^o5] and in [philosophy](https://en.wikipedia.org/wiki/Philosophy).[^o6]

## Etymology {#Etymology}

The term originated as an abstraction of the sequence: single, couple/double, triple, quadruple, quintuple, sextuple, septuple, octuple, ..., $n$‑tuple, ..., where the prefixes are taken from the [Latin](https://en.wikipedia.org/wiki/Latin) names of the numerals. The unique 0-tuple is called the *null tuple* or *empty tuple*. A 1‑tuple is called a *single* (or *singleton*), a 2‑tuple is called an *ordered pair* or *couple*, and a 3‑tuple is called a *triple* (or *triplet*). The number $n$ can be any nonnegative [integer](wikipedia://en/14563). For example, a [complex number](wikipedia://en/5826) can be represented as a 2‑tuple of reals, a [quaternion](wikipedia://en/51440) can be represented as a 4‑tuple, an [octonion](wikipedia://en/51436) can be represented as an 8‑tuple, and a [sedenion](wikipedia://en/51434) can be represented as a 16‑tuple.

Although these uses treat *‑tuple* as the suffix, the original suffix was *‑ple* as in "triple" (three-fold) or "decuple" (ten‑fold). This originates from [medieval Latin](https://en.wikipedia.org/wiki/Medieval_Latin) *plus* (meaning "more") related to [Greek](https://en.wikipedia.org/wiki/Greek_language) ‑πλοῦς, which replaced the classical and late antique *‑plex* (meaning "folded"), as in "duplex".[^o9]

## Properties {#Properties}

The general rule for the identity of two $n$-tuples is

$(a_1, a_2, \ldots, a_n) = (b_1, b_2, \ldots, b_n)$ [if and only if](wikipedia://en/14922) $a_1=b_1,\text{ }a_2=b_2,\text{ }\ldots,\text{ }a_n=b_n$.

Thus a tuple has properties that distinguish it from a [set](wikipedia://en/26691):

1. A tuple may contain multiple instances of the same element, so tuple $(1,2,2,3) \neq (1,2,3)$; but set $\{1,2,2,3\} = \{1,2,3\}$.
1. Tuple elements are ordered: tuple $(1,2,3) \neq (3,2,1)$, but set $\{1,2,3\} = \{3,2,1\}$.
1. A tuple has a finite number of elements, while a set or a [multiset](wikipedia://en/305303) may have an infinite number of elements.

## Definitions {#Definitions}

There are several definitions of tuples that give them the properties described in the previous section.

### Tuples as functions {#Tuples_as_functions}

The $0$-tuple may be identified as the [empty function](wikipedia://en/185427#General_properties). For $n \geq 1,$ the $n$-tuple $\left(a_1, \ldots, a_n\right)$ may be identified with the [surjective](wikipedia://en/27873) [function](wikipedia://en/185427#Definition)

$$F ~:~ \left\{ 1, \ldots, n \right\} ~\to~ \left\{ a_1, \ldots, a_n \right\}$$

with [domain](wikipedia://en/50263)

$$\operatorname{domain} F = \left\{ 1, \ldots, n \right\} = \left\{ i \in \mathbb{N} : 1 \leq i \leq n\right\}$$

and with [codomain](wikipedia://en/50264)

$$\operatorname{codomain} F = \left\{ a_1, \ldots, a_n \right\},$$

that is defined at $i \in \operatorname{domain} F = \left\{ 1, \ldots, n \right\}$ by

$$F(i) := a_i.$$

That is, $F$ is the function defined by

$$\begin{alignedat}{3} 1 \;&\mapsto&&\; a_1 \\ \;&\;\;\vdots&&\; \\ n \;&\mapsto&&\; a_n \\ \end{alignedat}$$

in which case the equality

$$\left(a_1, a_2, \dots, a_n\right) = \left(F(1), F(2), \dots, F(n)\right)$$

necessarily holds.

**Tuples as sets of ordered pairs**

Functions are commonly identified with their [graphs](wikipedia://en/87352), which is a certain set of ordered pairs. Indeed, many authors use graphs as the definition of a function. Using this definition of "function", the above function $F$ can be defined as:

$$F ~:=~ \left\{ \left(1, a_1\right), \ldots, \left(n, a_n\right) \right\}.$$

### Tuples as nested ordered pairs {#Tuples_as_nested_ordered_pairs}

Another way of modeling tuples in set theory is as nested [ordered pairs](wikipedia://en/22362). This approach assumes that the notion of ordered pair has already been defined.

1. The 0-tuple (i.e. the empty tuple) is represented by the empty set $\emptyset$.
1. An $n$-tuple, with $n > 0$, can be defined as an ordered pair of its first entry and an $(n - 1)$-tuple (which contains the remaining entries when $n > 1)$:

$$(a_1, a_2, a_3, \ldots, a_n) = (a_1, (a_2, a_3, \ldots, a_n))$$

This definition can be applied recursively to the $(n - 1)$-tuple:

$$(a_1, a_2, a_3, \ldots, a_n) = (a_1, (a_2, (a_3, (\ldots, (a_n, \emptyset)\ldots))))$$

Thus, for example:

$$\begin{aligned} (1, 2, 3) & = (1, (2, (3, \emptyset))) \\ (1, 2, 3, 4) & = (1, (2, (3, (4, \emptyset)))) \\ \end{aligned}$$

A variant of this definition starts "peeling off" elements from the other end:

1. The 0-tuple is the empty set $\emptyset$.
1. For $n > 0$:

$$(a_1, a_2, a_3, \ldots, a_n) = ((a_1, a_2, a_3, \ldots, a_{n-1}), a_n)$$

This definition can be applied recursively:

$$(a_1, a_2, a_3, \ldots, a_n) = ((\ldots(((\emptyset, a_1), a_2), a_3), \ldots), a_n)$$

Thus, for example:

$$\begin{aligned} (1, 2, 3) & = (((\emptyset, 1), 2), 3) \\ (1, 2, 3, 4) & = ((((\emptyset, 1), 2), 3), 4) \\ \end{aligned}$$

### Tuples as nested sets {#Tuples_as_nested_sets}

Using [Kuratowski's representation for an ordered pair](wikipedia://en/22362#Kuratowski's_definition), the second definition above can be reformulated in terms of pure [set theory](wikipedia://en/27553):

1. The 0-tuple (i.e. the empty tuple) is represented by the empty set $\emptyset$;
1. Let $x$ be an $n$-tuple $(a_1, a_2, \ldots, a_n)$, and let $x \rightarrow b \equiv (a_1, a_2, \ldots, a_n, b)$. Then, $x \rightarrow b \equiv \{\{x\}, \{x, b\}\}$. (The right arrow, $\rightarrow$, could be read as "adjoined with".)

In this formulation:

$$\begin{array}{lclcl} () & & &=& \emptyset \\ & & & & \\ (1) &=& () \rightarrow 1 &=& \{\{()\},\{(),1\}\} \\ & & &=& \{\{\emptyset\},\{\emptyset,1\}\} \\ & & & & \\ (1,2) &=& (1) \rightarrow 2 &=& \{\{(1)\},\{(1),2\}\} \\ & & &=& \{\{\{\{\emptyset\},\{\emptyset,1\}\}\}, \\ & & & & \{\{\{\emptyset\},\{\emptyset,1\}\},2\}\} \\ & & & & \\ (1,2,3) &=& (1,2) \rightarrow 3 &=& \{\{(1,2)\},\{(1,2),3\}\} \\ & & &=& \{\{\{\{\{\{\emptyset\},\{\emptyset,1\}\}\}, \\ & & & & \{\{\{\emptyset\},\{\emptyset,1\}\},2\}\}\}, \\ & & & & \{\{\{\{\{\emptyset\},\{\emptyset,1\}\}\}, \\ & & & & \{\{\{\emptyset\},\{\emptyset,1\}\},2\}\},3\}\} \\ \end{array}$$

## $n$-tuples of $m$-sets {#-tuples_of_-sets}

In [discrete mathematics](wikipedia://en/8492), especially [combinatorics](wikipedia://en/5170) and finite [probability theory](wikipedia://en/23542), $n$-tuples arise in the context of various counting problems and are treated more informally as ordered lists of length $n$.[^o19] $n$-tuples whose entries come from a set of $m$ elements are also called *arrangements with repetition*, *[permutations of a multiset](wikipedia://en/44027#Permutations_of_multisets)* and, in some non-English literature, *variations with repetition*. The number of $n$-tuples of an $m$-set is $m^{n}$. This follows from the combinatorial [rule of product](wikipedia://en/1594286).[^o20] If $S$ is a finite set of [cardinality](wikipedia://en/6174) $m$, this number is the cardinality of the $n$-fold [Cartesian power](wikipedia://en/24104095#n-ary_Cartesian_power) $S \times S \times \cdots \times S$. Tuples are elements of this product set.

## Type theory {#Type_theory}

In [type theory](wikipedia://en/40282), commonly used in [programming languages](wikipedia://en/23015), a tuple has a [product type](wikipedia://en/14892710); this fixes not only the length, but also the underlying types of each component. Formally:

$$(x_1, x_2, \ldots, x_n) : \mathsf{T}_1 \times \mathsf{T}_2 \times \ldots \times \mathsf{T}_n$$

and the [projections](wikipedia://en/3909097) are term constructors:

$$\pi_1(x) : \mathsf{T}_1,~\pi_2(x) : \mathsf{T}_2,~\ldots,~\pi_n(x) : \mathsf{T}_n$$

The tuple with labeled elements used in the [relational model](https://en.wikipedia.org/wiki/Relational_model) has a [record type](https://en.wikipedia.org/wiki/Record_%28computer_science%29). Both of these types can be defined as simple extensions of the [simply typed lambda calculus](wikipedia://en/1986011).[^o22]

The notion of a tuple in type theory and that in set theory are related in the following way: If we consider the natural [model](wikipedia://en/19858) of a type theory, and use the Scott brackets to indicate the semantic interpretation, then the model consists of some sets $S_1, S_2, \ldots, S_n$ (note: the use of italics here that distinguishes sets from types) such that:

$$[\![\mathsf{T}_1]\!] = S_1,~[\![\mathsf{T}_2]\!] = S_2,~\ldots,~[\![\mathsf{T}_n]\!] = S_n$$

and the interpretation of the basic terms is:

$$[\![x_1]\!] \in [\![\mathsf{T}_1]\!],~[\![x_2]\!] \in [\![\mathsf{T}_2]\!],~\ldots,~[\![x_n]\!] \in [\![\mathsf{T}_n]\!].$$

The $n$-tuple of type theory has the natural interpretation as an $n$-tuple of set theory:[^o23]

$$[\![(x_1, x_2, \ldots, x_n)]\!] = (\,[\![x_1]\!], [\![x_2]\!], \ldots, [\![x_n]\!]\,)$$

The [unit type](wikipedia://en/3646268) has as semantic interpretation the 0-tuple.

For a list of tuple types in programming languages, see [Product type#Product types in programming languages](wikipedia://en/14892710#Product_types_in_programming_languages).
