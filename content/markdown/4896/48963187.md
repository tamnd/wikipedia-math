# Argon2

::: {#o1 .subject cue=lead name="Argon2"}

**Argon2** is a [key derivation function](wikipedia://en/449781) that was selected as the winner of the 2015 [Password Hashing Competition](https://en.wikipedia.org/wiki/Password_Hashing_Competition).[^o3][^o4] It was designed by [Alex Biryukov](wikipedia://en/9189491), Daniel Dinu, and [Dmitry Khovratovich](wikipedia://en/58758465) from the [University of Luxembourg](https://en.wikipedia.org/wiki/University_of_Luxembourg).[^o5] The reference implementation of Argon2 is released under a [Creative Commons CC0](https://en.wikipedia.org/wiki/Creative_Commons_CC0) license (i.e. [public domain](https://en.wikipedia.org/wiki/Public_domain)) or the [Apache License 2.0](https://en.wikipedia.org/wiki/Apache_License).

:::

The Argon2 function uses a large, fixed-size memory region (often called the 'memory array' in documentation) to make brute-force attacks computationally expensive. The three variants differ in how they access this memory:

- Argon2d maximizes resistance to GPU [cracking attacks](wikipedia://en/477981). It accesses the memory array in a password-dependent order, which reduces the possibility of [time–memory trade-off](https://en.wikipedia.org/wiki/Time–memory_trade-off) (TMTO) attacks, but introduces possible [side-channel attacks](wikipedia://en/667678).
- Argon2i is optimized to resist side-channel attacks. It accesses the memory array in a password-independent order.
- Argon2id is a hybrid version. It follows the Argon2i approach for the first half pass over memory and the Argon2d approach for subsequent passes. 9106 recommends using Argon2id if one does not know the difference between the types or if side-channel attacks are considered to be a viable threat.[^o6]

All three modes allow specification by three parameters that control:

- execution time
- memory required
- degree of parallelism

## Cryptanalysis {#Cryptanalysis}

While there is no public [cryptanalysis](wikipedia://en/5715) applicable to Argon2d, there are two published attacks on the Argon2i function. The first attack is applicable only to the old version of Argon2i, while the second has been extended to the latest version (1.3).[^o11]

The first attack shows that it is possible to compute a single-pass Argon2i function using between a quarter and a fifth of the desired space with no time penalty, and compute a multiple-pass Argon2i using only $N$/$e$ (≈ $N$/2.72) space with no time penalty.[^o8] According to the Argon2 authors, this attack vector was fixed in version 1.3.[^o9]

The second attack shows that Argon2i can be computed by an algorithm which has complexity O($n$<sup>7/4</sup> log($n$)) for all choices of parameters $\sigma$ (space cost), $\tau$ (time cost), and thread-count such that $n$=$\sigma$∗$\tau$.[^o10] The Argon2 authors claim that this attack is not efficient if Argon2i is used with three or more passes.[^o9] However, Joël Alwen and Jeremiah Blocki improved the attack and showed that in order for the attack to fail, Argon2i v1.3 needs more than 10 passes over memory.[^o11]

To address these concerns, RFC9106 recommends using Argon2id to largely mitigate such attacks.[^o12]

### Variable-length hash function {#Variable-length_hash_function}

Argon2 makes use of a hash function capable of producing digests up to 2<sup>32</sup> bytes long. This hash function is internally built upon [Blake2](https://en.wikipedia.org/wiki/Blake2).

**Function** Hash(message, digestSize) **Inputs:** message: Bytes (0..2<sup>32</sup>-1) Message to be hashed digestSize: Integer (1..2<sup>32</sup>) Desired number of bytes to be returned Output: digest: Bytes (digestSize) The resulting generated bytes, digestSize bytes long

**Hash** is a variable-length hash function, built using Blake2b, capable of generating digests up to 2<sup>32</sup> bytes.

If the requested digestSize is 64-bytes or lower, then we use Blake2b directly **if** (digestSize \<= 64) **then** **return** Blake2b(digestSize ∥ message, digestSize) // concatenate 32-bit little endian digestSize with the message bytes

For desired hashes over 64-bytes (e.g. 1024 bytes for Argon2 blocks), we use Blake2b to generate twice the number of needed 64-byte blocks, and then only use 32-bytes from each block

Calculate the number of whole blocks (knowing we're only going to use 32-bytes from each) r ← Ceil(digestSize/32)-2;

Generate r whole blocks. Initial block is generated from message V<sub>1</sub> ← Blake2b(digestSize ∥ message, 64); Subsequent blocks are generated from previous blocks **for** i ← 2 **to** r **do** V<sub>i</sub> ← Blake2b(V<sub>i-1</sub>, 64) Generate the final (possibly partial) block partialBytesNeeded ← digestSize – 32\*r; V<sub>r+1</sub> ← Blake2b(V<sub>r</sub>, partialBytesNeeded)

Concatenate the first 32-bytes of each block V<sub>i</sub> (except the possibly partial last block, which we take the whole thing) Let A<sub>i</sub> represent the lower 32-bytes of block V<sub>i</sub> **return** A<sub>1</sub> ∥ A<sub>2</sub> ∥ ... ∥ A<sub>r</sub> ∥ V<sub>r+1</sub>

## Recommended minimum parameters {#Recommended_minimum_parameters}

The [Request for Comments](https://en.wikipedia.org/wiki/Request_for_Comments) document standardizing Argon2, which was published in September 2021, recommends:

- Memory: 2 GiB, Iterations: 1, Parallelism: 4; for "a default setting for all environments"[^o17]
- Memory: 64 MiB, Iterations: 3, Parallelism: 4; for "memory-constrained environments"[^o17]
