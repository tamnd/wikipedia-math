# SipHash

::: {#o1 .subject cue=lead name="SipHash"}

**SipHash** is an [add–rotate–xor](wikipedia://en/4594#ARX_%28add–rotate–XOR%29) (ARX) based family of [pseudorandom functions](https://en.wikipedia.org/wiki/Pseudorandom_function) created by Jean-Philippe Aumasson and [Daniel J. Bernstein](wikipedia://en/198983) in 2012,[^o2][^o3] in response to a spate of ["hash flooding"](wikipedia://en/969624#Hash_flooding) [denial-of-service attacks](https://en.wikipedia.org/wiki/Denial-of-service_attack) (HashDoS) in late 2011.[^o4]

:::

SipHash is designed as a [secure pseudorandom function](wikipedia://en/3454616) and can also be used as a secure [message authentication code](wikipedia://en/567523) (MAC). SipHash, however, is not a general purpose key-less [hash function](https://en.wikipedia.org/wiki/Hash_function) such as [Secure Hash Algorithms](wikipedia://en/897855) (SHA) and therefore must always be used with a secret key in order to be secure. That is, SHA is designed so that it is difficult for an attacker to find two messages *X* and *Y* such that SHA(*X*) = SHA(*Y*), even though anyone may compute SHA(*X*). SipHash instead guarantees that, having seen *X<sub>i</sub>* and SipHash(*X<sub>i</sub>*, *k*), an attacker who does not know the key *k* cannot find (any information about) *k* or SipHash(*Y*, *k*) for any message *Y* ∉ {*X<sub>i</sub>*} which they have not seen before.

## Overview {#Overview}

SipHash computes a [64-bit](https://en.wikipedia.org/wiki/64-bit_computing) [message authentication code](wikipedia://en/567523) from a variable-length message and 128-bit secret key. It was designed to be efficient even for short inputs, with performance comparable to non-cryptographic hash functions, such as [CityHash](https://en.wikipedia.org/wiki/CityHash);[^o6][^o3] this can be used to prevent denial-of-service attacks against [hash tables](wikipedia://en/13833) ("hash flooding"),[^o7] or to authenticate [network packets](https://en.wikipedia.org/wiki/Network_packet). A variant was later added which produces a 128-bit result.[^o10]

An unkeyed hash function such as SHA is collision-resistant only if the entire output is used. If used to generate a *small* output, such as an index into a hash table of practical size, then no algorithm can prevent collisions; an attacker need only make as many attempts as there are possible outputs.

For example, suppose a network server is designed to be able to handle up to a million requests at once. It keeps track of incoming requests in a hash table with two million entries, using a hash function to map identifying information from each request to one of the two million possible table entries. An attacker who knows the hash function need only feed it arbitrary inputs; one out of two million will have a specific hash value. If the attacker now sends a few hundred requests all chosen to have the *same* hash value to the server, that will produce a large number of hash collisions, slowing (or possibly stopping) the server with an effect similar to a [packet flood](https://en.wikipedia.org/wiki/Denial-of-service_attack#Application-layer_attacks) of many million requests.[^o8]

By using a key unknown to the attacker, a keyed hash function like SipHash prevents this sort of attack. While it is possible to add a key to an unkeyed hash function ([HMAC](wikipedia://en/17112) is a popular technique), SipHash is much more efficient.

Functions in SipHash family are specified as SipHash-*c*-*d*, where *c* is the number of rounds per message block and *d* is the number of finalization rounds. The recommended parameters are SipHash-2-4 for best performance, and SipHash-4-8 for conservative security. A few languages use SipHash-1-3 for performance at the risk of yet-unknown DoS attacks.[^o9]

The [reference implementation](https://en.wikipedia.org/wiki/Reference_implementation) was released as [public domain-like software](https://en.wikipedia.org/wiki/Public_domain_software) under the [CC0](https://en.wikipedia.org/wiki/CC0).[^o10]

## Usage {#Usage}

SipHash is used in *[hash table](wikipedia://en/13833) implementations* of various software:[^o12]

- [Programming languages](wikipedia://en/23015)
  - [JavaScript](https://en.wikipedia.org/wiki/JavaScript)
    - [Node.js](https://en.wikipedia.org/wiki/Node.js)[^o13]
      - [V8 (JavaScript engine)](https://en.wikipedia.org/wiki/V8_%28JavaScript_engine%29) (available as a compile-time option)[^o14]
  - [OCaml](https://en.wikipedia.org/wiki/OCaml)[^o15]
  - [Perl](https://en.wikipedia.org/wiki/Perl) 5 (available as a [compile time](https://en.wikipedia.org/wiki/Compile_time) option)[^o16]
  - [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) (starting in version 3.4,[^o17] SipHash 1-3 since 3.11[^o18])
  - [Raku](https://en.wikipedia.org/wiki/Raku_%28programming_language%29)[^o19]
  - [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29) (SipHash 1-3)[^o20]
  - [Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29)
  - [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29)
- [Operating systems](https://en.wikipedia.org/wiki/Operating_system)
  - [Linux](https://en.wikipedia.org/wiki/Linux)
    - [systemd](https://en.wikipedia.org/wiki/Systemd)[^o21]
  - [OpenBSD](https://en.wikipedia.org/wiki/OpenBSD)[^o22]
  - [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD)[^o23]
  - [OpenDNS](https://en.wikipedia.org/wiki/OpenDNS)
  - [WireGuard](https://en.wikipedia.org/wiki/WireGuard)[^o24]

The following programs use SipHash in other ways:

- [Bitcoin](wikipedia://en/28249265) for short transaction IDs[^o25]
- Bloomberg BDE as a [C++](https://en.wikipedia.org/wiki/C++) [object](https://en.wikipedia.org/wiki/Object_%28computer_science%29) hasher[^o26]
- [InterPlanetary File System](wikipedia://en/47785998) (IPFS) for its seven [Bloom filter](https://en.wikipedia.org/wiki/Bloom_filter) hashes[^o27]
