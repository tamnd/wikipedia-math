# Integer relation algorithm

::: {#o1 .subject cue=lead name="Integer relation algorithm"}

An **integer relation** between a set of real numbers *x*<sub>1</sub>, *x*<sub>2</sub>, ..., *x*<sub>*n*</sub> is a set of integers *a*<sub>1</sub>, *a*<sub>2</sub>, ..., *a*<sub>*n*</sub>, not all 0, such that

:::

$$a_1x_1 + a_2x_2 + \cdots + a_nx_n = 0.\,$$

An **integer relation algorithm** is an [algorithm](wikipedia://en/775) for finding integer relations. Specifically, given a set of real numbers known to a given precision, an integer relation algorithm will either find an integer relation between them, or will determine that no integer relation exists with coefficients whose magnitudes are less than a certain [upper bound](https://en.wikipedia.org/wiki/Upper_bound).[^o2]

## History {#History}

For the case *n* = 2, an extension of the [Euclidean algorithm](wikipedia://en/10377) can find any integer relation that exists between any two real numbers *x*<sub>1</sub> and *x*<sub>2</sub>. The algorithm generates successive terms of the [continued fraction](wikipedia://en/739199) expansion of *x*<sub>1</sub>/*x*<sub>2</sub>; if there is an integer relation between the numbers, then their ratio is rational and the algorithm eventually terminates.

- The Ferguson–Forcade algorithm was published in 1979 by [Helaman Ferguson](https://en.wikipedia.org/wiki/Helaman_Ferguson) and [R.W. Forcade](https://en.wikipedia.org/wiki/R.W._Forcade). Although the paper treats general *n*, it is not clear if the paper fully solves the problem because it lacks the detailed steps, proofs, and a precision bound that are crucial for a reliable implementation.
- The first algorithm with complete proofs was the **[LLL algorithm](wikipedia://en/1735228)**, developed by [Arjen Lenstra](wikipedia://en/6850292), [Hendrik Lenstra](https://en.wikipedia.org/wiki/Hendrik_Lenstra) and [László Lovász](wikipedia://en/1623938) in 1982.
- The **HJLS algorithm**, developed by [Johan Håstad](https://en.wikipedia.org/wiki/Johan_Håstad), Bettina Just, [Jeffrey Lagarias](wikipedia://en/4327781), and [Claus-Peter Schnorr](wikipedia://en/9439931) in 1986.[^o7]
- The **PSOS algorithm**, developed by Ferguson in 1988.
- The **PSLQ algorithm**, developed by Ferguson and [Bailey](wikipedia://en/184462) in 1992 and substantially simplified by Ferguson, Bailey, and Arno in 1999.[^o9][^o10][^o12] In 2000 the PSLQ algorithm was selected as one of the "Top Ten Algorithms of the Century" by [Jack Dongarra](https://en.wikipedia.org/wiki/Jack_Dongarra) and Francis Sullivan[^o13] even though it is considered essentially equivalent to HJLS.[^o14][^o15]
- The LLL algorithm has been improved by numerous authors. Modern LLL implementations can solve integer relation problems with *n* above 500.

## Applications {#Applications}

Integer relation algorithms have numerous applications. The first application is to determine whether a given real number *x* is likely to be [algebraic](wikipedia://en/1158), by searching for an integer relation between a set of powers of *x* {1, *x*, *x*<sup>2</sup>, ..., *x*<sup>*n*</sup>}. The second application is to search for an integer relation between a real number *x* and a set of mathematical constants such as *e*, $\pi$ and ln(2), which will lead to an expression for *x* as a linear combination of these constants.

A typical approach in [experimental mathematics](wikipedia://en/256363) is to use [numerical methods](wikipedia://en/1678715) and [arbitrary precision arithmetic](https://en.wikipedia.org/wiki/Arbitrary_precision_arithmetic) to find an approximate value for an [infinite series](wikipedia://en/15287), [infinite product](wikipedia://en/26382006) or an [integral](wikipedia://en/15532) to a high degree of precision (usually at least 100 significant figures), and then use an integer relation algorithm to search for an integer relation between this value and a set of mathematical constants. If an integer relation is found, this suggests a possible [closed-form expression](wikipedia://en/585143) for the original series, product or integral. This conjecture can then be validated by formal algebraic methods. The higher the precision to which the inputs to the algorithm are known, the greater the level of confidence that any integer relation that is found is not just a [numerical artifact](wikipedia://en/14041933).

A notable success of this approach was the use of the PSLQ algorithm to find the integer relation that led to the [Bailey–Borwein–Plouffe formula](wikipedia://en/22684956) for the value of [$\pi$](wikipedia://en/23601). PSLQ has also helped find new identities involving [multiple zeta functions](wikipedia://en/18037845) and their appearance in [quantum field theory](wikipedia://en/25267); and in identifying bifurcation points of the [logistic map](wikipedia://en/18137). For example, where B<sub>4</sub> is the logistic map's fourth bifurcation point, the constant α = −*B*<sub>4</sub>(*B*<sub>4</sub> − 2) is a root of a 120th-degree polynomial whose largest coefficient is 257<sup>30</sup>.[^o18][^o19] Integer relation algorithms are combined with tables of high precision mathematical constants and heuristic search methods in applications such as the [Inverse Symbolic Calculator](wikipedia://en/9087019) or [Plouffe's Inverter](https://en.wikipedia.org/wiki/Plouffe's_Inverter).

Integer relation finding can be used to [factor polynomials](wikipedia://en/3776351) of high degree.[^o20]
