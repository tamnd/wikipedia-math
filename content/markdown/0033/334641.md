# Directory service

::: {#o1 .subject cue=lead name="Directory service"}

In [computing](https://en.wikipedia.org/wiki/Computing), a **directory service** or **name service** maps the names of network resources to their respective [network addresses](https://en.wikipedia.org/wiki/Network_address). It is a shared information infrastructure for locating, managing, administering and organizing everyday items and network resources, which can include volumes, folders, files, printers, users, groups, devices, telephone numbers and other objects. A directory service is a critical component of a [network operating system](https://en.wikipedia.org/wiki/Network_operating_system). A **directory server** or [name server](https://en.wikipedia.org/wiki/Name_server) is a [server](https://en.wikipedia.org/wiki/Server_%28computing%29) which provides such a service. Each resource on the network is considered an [object](https://en.wikipedia.org/wiki/Object_%28computer_science%29) by the directory server. Information about a particular resource is stored as a collection of [attributes](https://en.wikipedia.org/wiki/Attribute_%28computing%29) associated with that resource or object.

:::

A directory service defines a [namespace](https://en.wikipedia.org/wiki/Namespace) for the network. The namespace is used to assign a *name* (unique identifier) to each of the objects. Directories typically have a set of rules determining how network resources are named and identified, which usually includes a requirement that the identifiers be [unique](https://en.wikipedia.org/wiki/Unique_identifier) and [unambiguous](https://en.wikipedia.org/wiki/Unambiguous). When using a directory service, a user does not have to remember the physical address of a network resource; providing a name locates the resource. Some directory services include [access control](https://en.wikipedia.org/wiki/Access_control) provisions, limiting the availability of directory information to [authorized users](https://en.wikipedia.org/wiki/Authorization).

## Comparison with relational databases {#Comparison_with_relational_databases}

Several things distinguish a directory service from a [relational database](https://en.wikipedia.org/wiki/Relational_database). Data can be made redundant if it aids performance (e.g. by repeating values through rows in a table instead of relating them to the contents of a different table through a key, which technique is called [denormalization](https://en.wikipedia.org/wiki/Denormalization); another technique could be the utilization of [replicas](https://en.wikipedia.org/wiki/Database_replication) for increasing actual throughput).[^o3]

Directory schemas are object classes, attributes, name bindings and knowledge (namespaces) where an object class has:

- *Must* - attributes that each instances must have
- *May* - attributes which can be defined for an instance but can be omitted, with the absence similar to NULL in a relational database

Attributes are sometimes multi-valued, allowing multiple naming attributes at one level (such as machine type and serial number [concatenation](wikipedia://en/64474), or multiple phone numbers for "work phone"). Attributes and object classes are usually standardized throughout the industry; for example, [X.500](https://en.wikipedia.org/wiki/X.500) attributes and classes are often formally registered with the [IANA](https://en.wikipedia.org/wiki/Internet_Assigned_Numbers_Authority) for their object ID. Therefore, directory applications try to reuse standard classes and attributes to maximize the benefit of existing directory-server software.

Object instances are slotted into namespaces; each object class [inherits](https://en.wikipedia.org/wiki/Inheritance_%28object-oriented_programming%29) from its parent object class (and ultimately from the root of the [hierarchy](wikipedia://en/13998)), adding attributes to the must-may list. Directory services are often central to the [security](https://en.wikipedia.org/wiki/Computer_security) design of an IT system and have a correspondingly-fine granularity of access control.

## Replication and distribution {#Replication_and_distribution}

[Replication](https://en.wikipedia.org/wiki/Replication_%28computing%29) and distribution have distinct meanings in the design and management of a directory service. Replication is used to indicate that the same directory namespace (the same objects) are copied to another directory server for redundancy and throughput reasons; the replicated namespace is governed by the same authority. Distribution is used to indicate that multiple directory servers in different namespaces are interconnected to form a distributed directory service; each namespace can be governed by a different authority.

## Implementations {#Implementations}

Directory services were part of an [Open Systems Interconnection](https://en.wikipedia.org/wiki/Open_Systems_Interconnection) (OSI) initiative for common network standards and multi-vendor interoperability. During the 1980s, the [ITU](https://en.wikipedia.org/wiki/International_Telecommunication_Union) and [ISO](https://en.wikipedia.org/wiki/International_Organization_for_Standardization) created the [X.500 set of standards](https://en.wikipedia.org/wiki/X.500) for directory services, initially to support the requirements of inter-carrier electronic messaging and network-name lookup. The [Lightweight Directory Access Protocol](https://en.wikipedia.org/wiki/Lightweight_Directory_Access_Protocol) (LDAP) is based on the X.500 directory-information services, using the [TCP/IP stack](https://en.wikipedia.org/wiki/Internet_protocol_suite) and an X.500 [Directory Access Protocol](https://en.wikipedia.org/wiki/Directory_Access_Protocol) (DAP) string-encoding scheme on the [Internet](https://en.wikipedia.org/wiki/Internet).

Systems developed before the X.500 include:

- *[Domain Name System](https://en.wikipedia.org/wiki/Domain_Name_System) (DNS):* The first directory service on the Internet,[^o7] still in use
- *[Hesiod](https://en.wikipedia.org/wiki/Hesiod_%28name_service%29):* Based on DNS and used at MIT's [Project Athena](https://en.wikipedia.org/wiki/Project_Athena)
- *[Network Information Service](https://en.wikipedia.org/wiki/Network_Information_Service) (NIS):* Originally [Yellow Pages](https://en.wikipedia.org/wiki/Yellow_Pages_%28computing%29) (YP) [Sun Microsystems](https://en.wikipedia.org/wiki/Sun_Microsystems)' implementation of a directory service for [Unix](https://en.wikipedia.org/wiki/Unix) network environments. It played a role similar to Hesiod.
- *[NetInfo](https://en.wikipedia.org/wiki/NetInfo):* Developed by NeXT during the late 1980s for [NEXTSTEP](https://en.wikipedia.org/wiki/NEXTSTEP). After its acquisition by Apple, it was released as open source and was the directory service for [Mac OS X](https://en.wikipedia.org/wiki/Mac_OS_X) before it was deprecated for the LDAP-based Open Directory. Support for NetInfo was removed with the release of 10.5 Leopard.
- *[Banyan VINES](https://en.wikipedia.org/wiki/Banyan_VINES):* First [scalable](https://en.wikipedia.org/wiki/Scalability) directory service
- *[NT Domains](https://en.wikipedia.org/wiki/Windows_domain):* Developed by Microsoft to provide directory services for Windows machines before the release of the LDAP-based Active Directory in Windows 2000. Windows Vista continues to support NT Domains after relaxing its minimum authentication protocols.

### LDAP implementations {#LDAP_implementations}

LDAP/X.500-based implementations include:

- [389 Directory Server](https://en.wikipedia.org/wiki/389_Directory_Server): Free Open Source server implementation by [Red Hat](https://en.wikipedia.org/wiki/Red_Hat), with commercial support by Red Hat and [SUSE](https://en.wikipedia.org/wiki/SUSE_S.A.).
- [Active Directory](wikipedia://en/2807): [Microsoft](https://en.wikipedia.org/wiki/Microsoft)'s directory service for [Windows](https://en.wikipedia.org/wiki/Windows), originating from the X.500 directory, created for use in [Exchange Server](https://en.wikipedia.org/wiki/Microsoft_Exchange_Server), first shipped with [Windows 2000 Server](https://en.wikipedia.org/wiki/Windows_2000_Server) and supported by successive versions of Windows
- [Apache Directory Server](https://en.wikipedia.org/wiki/Apache_Directory_Server): Directory service, written in Java, supporting LDAP, Kerberos 5 and the Change Password Protocol; LDAPv3 certified
- [Apple Open Directory](https://en.wikipedia.org/wiki/Apple_Open_Directory): [Apple](https://en.wikipedia.org/wiki/Apple_Inc.)'s directory server for [Mac OS X](https://en.wikipedia.org/wiki/MacOS), available through [Mac OS X Server](https://en.wikipedia.org/wiki/MacOS_Server)
- [eDirectory: NetIQ's](https://en.wikipedia.org/wiki/NetIQ_eDirectory) implementation of directory services supports multiple architectures, including [Windows](https://en.wikipedia.org/wiki/Microsoft_Windows), [NetWare](https://en.wikipedia.org/wiki/NetWare), [Linux](https://en.wikipedia.org/wiki/Linux) and several flavours of [Unix](https://en.wikipedia.org/wiki/Unix) and is used for user administration and configuration and software management; previously known as Novell Directory Services.
- [Red Hat Directory Server](https://en.wikipedia.org/wiki/Red_Hat_Directory_Server): [Red Hat](https://en.wikipedia.org/wiki/Red_Hat) released Red Hat Directory Server, acquired from AOL's Netscape Security Solutions unit,[^o9] as a commercial product running on top of [Red Hat Enterprise Linux](https://en.wikipedia.org/wiki/Red_Hat_Enterprise_Linux) as the community-supported [389 Directory Server](https://en.wikipedia.org/wiki/389_Directory_Server) project. Upstream open source project is called [FreeIPA](https://en.wikipedia.org/wiki/FreeIPA).
- [Oracle Internet Directory](https://en.wikipedia.org/wiki/Oracle_Internet_Directory): (OID) is [Oracle Corporation](https://en.wikipedia.org/wiki/Oracle_Corporation)'s directory service, compatible with LDAP version 3.
- [Sun Java System Directory Server](https://en.wikipedia.org/wiki/Sun_Java_System_Directory_Server): [Sun Microsystems](https://en.wikipedia.org/wiki/Sun_Microsystems)' directory service[^o10]
- [OpenDS](https://en.wikipedia.org/wiki/OpenDS): [Open-source](https://en.wikipedia.org/wiki/Open-source_model) directory service in Java, backed by [Sun Microsystems](https://en.wikipedia.org/wiki/Sun_Microsystems)[^o11]
- [Oracle Unified Directory](https://en.wikipedia.org/wiki/Oracle_Unified_Directory): (OUD) is [Oracle Corporation](https://en.wikipedia.org/wiki/Oracle_Corporation)'s next-generation unified directory solution. It integrates storage, synchronization, and proxy functionalities.
- Windows [NT Directory Services](https://en.wikipedia.org/wiki/NT_Directory_Service) (NTDS), later renamed [Active Directory](wikipedia://en/2807), replaced the former NT Domain system.
- [Critical Path Directory Server](https://en.wikipedia.org/wiki/Critical_Path,_Inc.)
- [OpenLDAP](https://en.wikipedia.org/wiki/OpenLDAP): Derived from the original University of Michigan LDAP implementation (like Netscape, Red Hat, Fedora and Sun JSDS implementations), it supports all computer architectures (including Unix and Unix derivatives, Linux, Windows, z/OS and a number of embedded-realtime systems).
- [Lotus Domino](https://en.wikipedia.org/wiki/Lotus_Domino)
- [Nexor](https://en.wikipedia.org/wiki/Nexor) Directory
- [OpenDJ](https://en.wikipedia.org/wiki/OpenDJ) - a [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29)-based LDAP server and directory client that runs in any operating environment, under license [CDDL](https://en.wikipedia.org/wiki/Common_Development_and_Distribution_License). Developed by [ForgeRock](https://en.wikipedia.org/wiki/ForgeRock), until 2016,[^o12] now maintained by [OpenDJ](https://github.com/OpenIdentityPlatform/OpenDJ) Community

Open-source tools to create directory services include OpenLDAP, the [Kerberos protocol](wikipedia://en/16947) and [Samba software](https://en.wikipedia.org/wiki/Samba_software), which can function as a Windows [domain controller](https://en.wikipedia.org/wiki/Domain_controller) with Kerberos and LDAP [back ends](https://en.wikipedia.org/wiki/Front_and_back_ends). Administration is by GOsa or Samba SWAT.

:::

## Using name services {#Using_name_services}

### Unix systems {#Unix_systems}

Name services on Unix systems are typically configured through [nsswitch.conf](https://en.wikipedia.org/wiki/Nsswitch.conf). Information from name services can be retrieved with [getent](https://en.wikipedia.org/wiki/Getent).
