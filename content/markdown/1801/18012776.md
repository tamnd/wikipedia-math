# Symmetric convolution

::: {#o1 .subject cue=lead name="Symmetric convolution"}

In [mathematics](wikipedia://en/18831), **symmetric convolution** is a special subset of [convolution](wikipedia://en/7519) operations in which the [convolution kernel](https://en.wikipedia.org/wiki/Convolution_kernel) is [symmetric](https://en.wikipedia.org/wiki/Symmetric) across its zero point. Many common convolution-based processes such as [Gaussian blur](https://en.wikipedia.org/wiki/Gaussian_blur) and taking the [derivative](wikipedia://en/7921) of a signal in [frequency-space](wikipedia://en/370346) are symmetric and this property can be exploited to make these convolutions easier to evaluate.

:::

::: {#o3 .statement kind=statement/theorem cue=named-heading name="Convolution theorem"}

## Convolution theorem {#Convolution_theorem}

The [convolution theorem](wikipedia://en/53268) states that a convolution in the real domain can be represented as a [pointwise multiplication](https://en.wikipedia.org/wiki/Pointwise_product) across the frequency domain of a [Fourier transform](https://en.wikipedia.org/wiki/Fourier_transforms). Since [sine and cosine transforms](wikipedia://en/2660978) are related transforms a modified version of the convolution theorem can be applied, in which the concept of [circular convolution](wikipedia://en/3367262) is replaced with symmetric convolution. Using these transforms to compute discrete symmetric convolutions is non-trivial since [discrete sine transforms](wikipedia://en/196095) (DSTs) and [discrete cosine transforms](wikipedia://en/59962) (DCTs) can be counter-intuitively incompatible for computing symmetric convolution, i.e. symmetric convolution can only be computed between a fixed set of compatible transforms.

:::

## Mutually compatible transforms {#Mutually_compatible_transforms}

In order to compute symmetric convolution effectively, one must know which particular [frequency domains](wikipedia://en/370346) (which are reachable by transforming real data through DSTs or DCTs) the inputs and outputs to the convolution can be and then tailor the symmetries of the transforms to the required symmetries of the convolution.

The following table documents which combinations of the domains from the main eight commonly used DST I-IV and DCT I-IV satisfy $f * g = h$ where $*$ represents the symmetric convolution [operator](wikipedia://en/22213). Convolution is a [commutative](https://en.wikipedia.org/wiki/Commutative) operator, and so $f$ and $g$ are interchangeable.

Forward transforms of $f$, $g$ and $h$, through the transforms specified should allow the symmetric convolution to be computed as a pointwise multiplication, with any excess undefined frequency amplitudes set to zero. Possibilities for symmetric convolutions involving DSTs and DCTs V-VIII derived from the [discrete Fourier transforms (DFTs)](https://en.wikipedia.org/wiki/Discrete_fourier_transform) of odd logical order can be determined by adding four to each type in the above tables.

## Advantages of symmetric convolutions {#Advantages_of_symmetric_convolutions}

There are a number of advantages to computing symmetric convolutions in DSTs and DCTs in comparison with the more common circular convolution with the Fourier transform.

Most notably the implicit symmetry of the transforms involved is such that only data unable to be inferred through symmetry is required. For instance using a DCT-II, a symmetric signal need only have the positive half DCT-II transformed, since the frequency domain will implicitly construct the mirrored data comprising the other half. This enables larger convolution kernels to be used with the same cost as smaller kernels circularly convolved on the DFT. Also the boundary conditions implicit in DSTs and DCTs create edge effects that are often more in keeping with neighbouring data than the periodic effects introduced by using the Fourier transform.
