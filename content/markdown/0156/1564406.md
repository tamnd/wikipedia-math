# Cramer–Shoup cryptosystem

::: {#o1 .subject cue=lead name="Cramer–Shoup cryptosystem"}

The **Cramer–Shoup system** is an [asymmetric](https://en.wikipedia.org/wiki/Asymmetric_cryptography) key encryption algorithm, and was the first efficient scheme proven to be secure against adaptive chosen ciphertext attack using standard cryptographic assumptions. Its security is based on the computational intractability (widely assumed, but not proved) of the [decisional Diffie–Hellman assumption](wikipedia://en/1198015). Developed by [Ronald Cramer](wikipedia://en/25494221) and [Victor Shoup](wikipedia://en/3978418) in 1998, it is an extension of the [ElGamal](https://en.wikipedia.org/wiki/ElGamal) cryptosystem. In contrast to ElGamal, which is extremely malleable, Cramer–Shoup adds other elements to ensure non-malleability even against a resourceful attacker. This non-malleability is achieved through the use of a [universal one-way hash function](wikipedia://en/3904224) and additional computations, resulting in a ciphertext which is twice as large as in ElGamal.

:::

## Adaptive chosen ciphertext attacks {#Adaptive_chosen_ciphertext_attacks}

The definition of security achieved by Cramer–Shoup is formally termed "[indistinguishability](wikipedia://en/2187252) under [adaptive chosen-ciphertext attack](wikipedia://en/426533)" ([IND-CCA2](https://en.wikipedia.org/wiki/IND-CCA2)). This security definition is currently the strongest definition known for a public key cryptosystem: it assumes that the attacker has access to a [decryption oracle](https://en.wikipedia.org/wiki/Decryption_oracle) which will decrypt any ciphertext using the scheme's secret decryption key. The "adaptive" component of the security definition means that the attacker has access to this decryption oracle both before and after he observes a specific target ciphertext to attack (though he is prohibited from using the oracle to simply decrypt this target ciphertext). The weaker notion of security against non-adaptive chosen-ciphertext attacks ([IND-CCA1](https://en.wikipedia.org/wiki/IND-CCA1)) only allows the attacker to access the decryption oracle before observing the target ciphertext.

Though it was well known that many widely used cryptosystems were insecure against such an attacker, for many years system designers considered the attack to be impractical and of largely theoretical interest. This began to change during the late 1990s, particularly when [Daniel Bleichenbacher](https://en.wikipedia.org/wiki/Daniel_Bleichenbacher) demonstrated a practical adaptive chosen ciphertext attack against [SSL](https://en.wikipedia.org/wiki/Secure_Sockets_Layer) servers using a form of [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) encryption.[^o3]

Cramer–Shoup was not the first encryption scheme to provide security against adaptive chosen ciphertext attack. Naor–Yung, Rackoff–Simon, and Dolev–Dwork–Naor proposed provably secure conversions from standard ([IND-CPA](https://en.wikipedia.org/wiki/IND-CPA)) schemes into IND-CCA1 and IND-CCA2 schemes. These techniques are secure under a standard set of cryptographic assumptions (without random oracles), however they rely on complex [zero-knowledge proof](wikipedia://en/450541) techniques, and are inefficient in terms of computational cost and ciphertext size. A variety of other approaches, including [Bellare](https://en.wikipedia.org/wiki/Mihir_Bellare)/[Rogaway](https://en.wikipedia.org/wiki/Phillip_Rogaway)'s [OAEP](https://en.wikipedia.org/wiki/Optimal_Asymmetric_Encryption_Padding) and [Fujisaki–Okamoto](https://en.wikipedia.org/wiki/Fujisaki–Okamoto) achieve efficient constructions using a mathematical abstraction known as a [random oracle](wikipedia://en/451286). Unfortunately, to implement these schemes in practice requires the substitution of some practical function (e.g., a [cryptographic hash function](wikipedia://en/439526)) in place of the random oracle. A growing body of evidence suggests the insecurity of this approach,[^o4] although no practical attacks have been demonstrated against deployed schemes.

## The cryptosystem {#The_cryptosystem}

Cramer–Shoup consists of three algorithms: the key generator, the encryption algorithm, and the decryption algorithm.

### Key generation {#Key_generation}

- [Alice](wikipedia://en/679079) generates an efficient description of a [cyclic group](wikipedia://en/52327) $G$ of order $q$ with two distinct, random [generators](wikipedia://en/99945) $g_1, g_2$.
- Alice chooses five random values $({x}_{1}, {x}_{2}, {y}_{1}, {y}_{2}, z)$ from $\{0, \ldots, q-1\}$.
- Alice computes $c = {g}_{1}^{x_1} g_{2}^{x_2}, d = {g}_{1}^{y_1} g_{2}^{y_2}, h = {g}_{1}^{z}$.
- Alice publishes $(c, d, h)$, along with the description of $G, q, g_1, g_2$, as her [public key](https://en.wikipedia.org/wiki/Public_key). Alice retains $(x_1, x_2, y_1, y_2, z)$ as her [secret key](https://en.wikipedia.org/wiki/Secret_key). The group can be shared between users of the system.

### Encryption {#Encryption}

To encrypt a message $m$ to Alice under her public key $(G,q,g_1,g_2,c,d,h)$,

- Bob converts $m$ into an element of $G$.
- Bob chooses a random $k$ from $\{0, \ldots, q-1\}$, then calculates:
  - $$u_1 = {g}_{1}^{k}, u_2 = {g}_{2}^{k}$$
  - $$e = h^k m$$
  - $\alpha = H(u_1, u_2, e)$, where *H*() is a [universal one-way hash function](wikipedia://en/3904224) (or a [collision-resistant](https://en.wikipedia.org/wiki/Collision-resistant) [cryptographic hash function](wikipedia://en/439526), which is a stronger requirement).
  - $$v = c^k d^{k\alpha}$$
- Bob sends the ciphertext $(u_1, u_2, e, v)$ to Alice.

### Decryption {#Decryption}

To decrypt a ciphertext $(u_1, u_2, e, v)$ with Alice's secret key $(x_1, x_2, y_1, y_2, z)$,

- Alice computes $\alpha = H(u_1, u_2, e) \,$ and verifies that ${u}_{1}^{x_1} u_{2}^{x_2} ({u}_{1}^{y_1} u_{2}^{y_2})^{\alpha} = v \,$. If this test fails, further decryption is aborted and the output is rejected.
- Otherwise, Alice computes the plaintext as $m = e / ({u}_{1}^{z}) \,$.

The decryption stage correctly decrypts any properly-formed ciphertext, since

${u}_{1}^{z} = {g}_{1}^{k z} = h^k \,$, and $m = e / h^k. \,$

If the space of possible messages is larger than the size of $G$, then Cramer–Shoup may be used in a [hybrid cryptosystem](wikipedia://en/11756462) to improve efficiency on long messages.
