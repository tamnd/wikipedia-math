# Bit-reversal permutation

::: {#o1 .subject cue=lead name="Bit-reversal permutation"}

*Image: Hammersley set 2D.svg.* A [Hammersley set](https://en.wikipedia.org/wiki/Hammersley_set) whose coordinates are the integers from 0 to 255 and their bit-reversals

In [applied mathematics](wikipedia://en/24295969), a **bit-reversal permutation** is a [permutation](wikipedia://en/44027) of a [sequence](wikipedia://en/27838) of $n$ items, where $n=2^k$ is a [power of two](wikipedia://en/376948). It is defined by indexing the elements of the sequence by the numbers from $0$ to $n-1$, representing each of these numbers by its [binary representation](https://en.wikipedia.org/wiki/Binary_representation) (padded to have length exactly $k$), and mapping each item to the item whose representation has the same bits in the reversed order.

:::

Repeating the same permutation twice returns to the original ordering on the items, so the bit reversal permutation is an [involution](wikipedia://en/293450).

This permutation can be applied to any sequence in [linear time](https://en.wikipedia.org/wiki/Linear_time) while performing only simple index calculations. It has applications in the generation of [low-discrepancy sequences](wikipedia://en/478601) and in the evaluation of [fast Fourier transforms](wikipedia://en/11512).

::: {#o3 .example cue=heading name="Example"}

## Example {#Example}

Consider the sequence of eight letters *abcdefgh*. Their indexes are the binary numbers 000, 001, 010, 011, 100, 101, 110, and 111, which when reversed become 000, 100, 010, 110, 001, 101, 011, and 111. Thus, the letter *a* in position 000 is mapped to the same position (000), the letter *b* in position 001 is mapped to the fifth position (the one numbered 100), etc., giving the new sequence *aecgbfdh*. Repeating the same permutation on this new sequence returns to the starting sequence.

Writing the index numbers in decimal (but, as above, starting with position 0 rather than the more conventional start of 1 for a permutation), the bit-reversal permutations on $n=2^k$ items, for $k=0,1,2, 3, \dots$, are:

::: {#o5 .table cue=table}

| $k$ | $n=2^k$ | permutation |
|---|---|---|
| 0 | 1 | 0 |
| 1 | 2 | 0 1 |
| 2 | 4 | 0 2 1 3 |
| 3 | 8 | 0 4 2 6 1 5 3 7 |
| 4 | 16 | 0 8 4 12 2 10 6 14 1 9 5 13 3 11 7 15 |

:::

Each permutation in this sequence can be generated by concatenating two sequences of numbers: the previous permutation, with its values doubled, and the same sequence with each value increased by one. Thus, for example doubling the length-4 permutation 0 2 1 3 gives 0 4 2 6, adding one gives 1 5 3 7, and concatenating these two sequences gives the length-8 permutation 0 4 2 6 1 5 3 7.[^o19]

:::

::: {#o7 .statement kind=statement/generalization cue=heading name="Generalizations"}

## Generalizations {#Generalizations}

The generalization to [radix](wikipedia://en/701207) $b$ representations, for $b > 2$, and to $n=b^k$, is a **digit-reversal permutation**, in which the base-$b$ digits of the index of each element are reversed to obtain the permuted index. The same idea can also been generalized to [mixed radix](wikipedia://en/249726) number systems. In such cases, the digit-reversal permutation should simultaneously reverse the digits of each item and the bases of the number system, so that each reversed digit remains within the range defined by its base.[^o8]

Permutations that generalize the bit-reversal permutation by reversing contiguous blocks of bits within the binary representations of their indices can be used to interleave two equal-length sequences of data in-place.[^o9]

There are two extensions of the bit-reversal permutation to sequences of arbitrary length. These extensions coincide with bit-reversal for sequences whose length is a power of 2, and their purpose is to separate adjacent items in a sequence for the efficient operation of the [Kaczmarz algorithm](wikipedia://en/2407650). The first of these extensions, called *efficient ordering*,[^o10] operates on composite numbers, and it is based on decomposing the number into its prime components.

The second extension, called EBR (extended bit-reversal), is similar in spirit to bit-reversal. Given an array of size $n$, EBR fills the array with a permutation of the numbers in the range $0\ldots n-1$ in linear time. Successive numbers are separated in the permutation by at least $\lfloor n/4\rfloor$ positions.[^o11]

:::

::: {#o13 .application cue=heading name="Applications"}

## Applications {#Applications}

Bit reversal is most important for radix-2 [Cooley–Tukey FFT algorithms](wikipedia://en/352702), where the recursive stages of the algorithm, operating [in-place](https://en.wikipedia.org/wiki/In-place), imply a bit reversal of the inputs or outputs. Similarly, mixed-radix digit reversals arise in mixed-radix Cooley–Tukey FFTs.[^o14]

The bit reversal permutation has also been used to devise [lower bounds](https://en.wikipedia.org/wiki/Lower_bound) in distributed computation.[^o15]

The [Van der Corput sequence](https://en.wikipedia.org/wiki/Van_der_Corput_sequence), a [low-discrepancy sequence](wikipedia://en/478601) of numbers in the [unit interval](wikipedia://en/49324), is formed by reinterpreting the indexes of the bit-reversal permutation as the [fixed-point binary representations](https://en.wikipedia.org/wiki/Fixed-point_arithmetic) of [dyadic rational numbers](https://en.wikipedia.org/wiki/Dyadic_rational_number).

Bit-reversal permutations are often used in finding lower bounds on dynamic [data structures](https://en.wikipedia.org/wiki/Data_structures). For example, subject to certain assumptions, the cost of looking up the integers between $0$ and $n-1$, inclusive, in any [binary search tree](wikipedia://en/4320) holding those values, is $\Omega(n \log n)$ when those numbers are queried in bit-reversed order. This bound applies even to trees like [splay trees](https://en.wikipedia.org/wiki/Splay_trees) that are allowed to rearrange their nodes between accesses.[^o16]

:::

## Algorithms {#Algorithms}

Mainly because of the importance of [fast Fourier transform](wikipedia://en/11512) algorithms, numerous efficient algorithms for applying a bit-reversal permutation to a sequence have been devised.[^o19]

Because the bit-reversal permutation is an involution, it may be performed easily [in place](https://en.wikipedia.org/wiki/In-place_algorithm) (without copying the data into another array) by swapping pairs of elements. In the [random-access machine](wikipedia://en/544227) commonly used in algorithm analysis, a simple algorithm that scans the indexes in input order and swaps whenever the scan encounters an index whose reversal is a larger number would perform a linear number of data moves.[^o21] However, computing the reversal of each index may take a non-constant number of steps. Alternative algorithms can perform a bit reversal permutation in linear time while using only simple index calculations.[^o20] Because bit-reversal permutations may be repeated multiple times as part of a calculation, it may be helpful to separate out the steps of the algorithm that calculate index data used to represent the permutation (for instance, by using the doubling and concatenation method) from the steps that use the results of this calculation to permute the data (for instance, by scanning the data indexes in order and performing a swap whenever the swapped location is greater than the current index, or by using more sophisticated [vector scatter–gather operations](https://en.wikipedia.org/wiki/Vectored_I/O)).[^o19]

Another consideration that is even more important for the performance of these algorithms is the effect of the [memory hierarchy](https://en.wikipedia.org/wiki/Memory_hierarchy) on running time. Because of this effect, more sophisticated algorithms that consider the block structure of memory can be faster than this naive scan.[^o19][^o21] An alternative to these techniques is special [computer hardware](https://en.wikipedia.org/wiki/Computer_hardware) that allows memory to be accessed both in normal and in bit-reversed order.[^o22]

Significant attention has been given to improving the performance of bit-reversal operations within the field of high-performance computing. Developing architecture-aware algorithms is crucial for enabling optimal use of hardware and system software resources such as caches, TLBs, and multicore processors.[^o23]
