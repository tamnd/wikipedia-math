# Graph edit distance

*Image: Graph edit distance.svg.* At first glance, the **GED** (graph edit distance) may appear to be 7, removing 3 edges, adding the yellow vertex, and adding edges between it and the 3 other vertices. However, the optimal set of operations would be to remove the edge between 2 colors of choice (for example, green and blue), change the third (red) to yellow, add a vertex of the now missing color (red), and connect it to the newly yellow vertex, for a GED of 4.

::: {#o1 .subject cue=lead name="Graph edit distance"}

In [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), **graph edit distance** (**GED**) is a [measure of similarity](wikipedia://en/1004743) (or dissimilarity) between two [graphs](wikipedia://en/325806). The concept of graph edit distance was first formalized mathematically by Alberto Sanfeliu and King-Sun Fu in 1983.[^o2] A major application of graph edit distance is in [inexact graph matching](https://en.wikipedia.org/wiki/Inexact_graph_matching), such as error-tolerant [pattern recognition](wikipedia://en/126706) in [machine learning](wikipedia://en/233488).[^o3]

:::

The graph edit distance between two graphs is related to the [string edit distance](wikipedia://en/406427) between [strings](https://en.wikipedia.org/wiki/String_%28computing%29). With the interpretation of strings as [connected](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29), [directed acyclic graphs](wikipedia://en/204002) of [maximum degree](wikipedia://en/1374448) one, classical definitions of edit distance such as [Levenshtein distance](https://en.wikipedia.org/wiki/Levenshtein_distance),[^o4][^o5] [Hamming distance](wikipedia://en/41227)[^o6] and [Jaro–Winkler distance](https://en.wikipedia.org/wiki/Jaro–Winkler_distance) may be interpreted as graph edit distances between suitably constrained graphs. Likewise, graph edit distance is also a generalization of **tree edit distance** between [rooted trees](wikipedia://en/48560).[^o7][^o8][^o9][^o10][^o11]

## Formal definitions and properties {#Formal_definitions_and_properties}

The mathematical definition of graph edit distance is dependent upon the definitions of the graphs over which it is defined, i.e. whether and how the vertices and edges of the graph are [labeled](wikipedia://en/1609861) and whether the edges are [directed](wikipedia://en/19721986). Generally, given a set of **graph edit operations** (also known as elementary [graph operations](wikipedia://en/9938244)), the graph edit distance between two graphs $g_{1}$ and $g_{2}$, written as $GED(g_{1},g_{2})$ can be defined as

$$GED(g_{1},g_{2}) = \min_{(e_{1},...,e_{k}) \in \mathcal{P}(g_{1},g_{2})} \sum_{i=1}^{k} c(e_{i})$$

where $\mathcal{P}(g_{1},g_{2})$ denotes the set of edit paths transforming $g_{1}$ into (a graph [isomorphic](wikipedia://en/247577) to) $g_{2}$ and $c(e) \ge 0$ is the cost of each graph edit operation $e$.

The set of elementary graph edit operators typically includes:

**vertex insertion** to introduce a single new labeled vertex to a graph.

**vertex deletion** to remove a single (often disconnected) vertex from a graph.

**vertex substitution** to change the label (or color) of a given vertex.

**edge insertion** to introduce a new colored edge between a pair of vertices.

**edge deletion** to remove a single edge between a pair of vertices.

**edge substitution** to change the label (or color) of a given edge.

Additional, but less common operators, include operations such as **edge splitting** that introduces a new vertex into an edge (also creating a new edge), and **[edge contraction](wikipedia://en/3758115)** that eliminates vertices of degree two between edges (of the same color). Although such complex edit operators can be defined in terms of more elementary transformations, their use allows finer parameterization of the cost function $c$ when the operator is cheaper than the sum of its constituents.

## Applications {#Applications}

Graph edit distance finds applications in [handwriting recognition](https://en.wikipedia.org/wiki/Handwriting_recognition),[^o24] [fingerprint recognition](https://en.wikipedia.org/wiki/Fingerprint_recognition)[^o25] and [cheminformatics](https://en.wikipedia.org/wiki/Cheminformatics).[^o26]

## Algorithms and complexity {#Algorithms_and_complexity}

Exact algorithms for computing the graph edit distance between a pair of graphs typically transform the problem into one of finding the minimum cost edit path between the two graphs. The computation of the optimal edit path is cast as a [pathfinding](https://en.wikipedia.org/wiki/Pathfinding) search or [shortest path problem](wikipedia://en/41985), often implemented as an [A\* search algorithm](wikipedia://en/100558).

In addition to exact algorithms, a number of efficient approximation algorithms are also known. Most of them have cubic computational time [^o29][^o30] [^o31] [^o32]

**[^o33] however, the runtime of at least one algorithm is linear in the number of nodes while still being cubic in the node degree.[^o34]**

Despite the above algorithms sometimes working well in practice, in general the problem of computing graph edit distance is NP-hard (for a proof that's available online, see Section 2 of [Zeng et al.](https://web.archive.org/web/20170810170852/http://www.vldb.org/pvldb/2/vldb09-568.pdf)), and is even hard to approximate (formally, it is [APX](wikipedia://en/2018925)-hard[^o35]).

## Tree Edit Distance {#Tree_Edit_Distance}

Tree Edit Distance (TED) represents the minimum cost of transforming one tree into another using three operations: insertion, deletion, and replacement. The first polynomial-time TED algorithm was proposed by Tai in 1979.[^o37] In 1989, Kaizhong Zhang and [Dennis Shasha](https://en.wikipedia.org/wiki/Dennis_Shasha) proposed the most well-known TED algorithm,[^o38] which introduced [Dynamic Programming](https://en.wikipedia.org/wiki/Dynamic_Programming) (DP) techniques to solve TED and has a worst-case time complexity of O(n<sup>4</sup>). This method employs a series of DP tables, where each table computes the edit distance between a subpart of the first input tree and a subpart of the second input tree. Since then, substantial research efforts[^o39][^o40][^o41] have focused on improving its sequential time complexity, and it has been proven that O(n<sup>3</sup>) is the lowest theoretical bound.[^o42]

### Parallelization {#Parallelization}

Despite these sequential improvements, TED remains computationally expensive for large trees, and its parallelization is highly non-trivial.[^o44] Specifically, TED computation involves both intra-table and inter-table data dependencies: entries within a DP table depend on previously computed entries, while the computation of each DP table depends on results from other tables.[^o11] These intricate dependencies hinder parallel execution. Moreover, the severe workload imbalance across DP tables further complicates scheduling and reduces parallel resource utilization.

[X-TED](https://github.com/Davis-Fan/X-TED)[^o11] is a [massively parallel](https://en.wikipedia.org/wiki/Massively_parallel) framework for TED computation that addresses these structural challenges. It employs a new preprocessing algorithm to efficiently determine dependency relationships among DP tables by analyzing only the tree structures. Based on this dependency information, X-TED groups independent DP tables into batches and processes them in parallel. To handle tables of different sizes, X-TED further adopts a dynamic parallelization strategy that allocates different levels of parallel resources according to each table's size. Extensive experiments on multicore CPUs and GPUs using real-world and synthetic trees demonstrate the effectiveness of X-TED for large-scale TED computation.[^o11]
