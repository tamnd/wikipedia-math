# Emptiness problem

::: {#o1 .subject cue=lead name="Emptiness problem"}

In [theoretical computer science](wikipedia://en/323392) and [formal language theory](https://en.wikipedia.org/wiki/Formal_language_theory), a formal language is **empty** if its set of valid sentences is the [empty set](wikipedia://en/9566). The **emptiness problem** is the question of determining whether a language is empty given some representation of it, such as a [finite-state automaton](https://en.wikipedia.org/wiki/Finite-state_automaton).[^o2] For an automaton having $n$ states, this is a [decision problem](wikipedia://en/8336) that can be solved in [$O(n^2)$ time](wikipedia://en/44578),[^o3] or in time $O(n+m)$ if the automaton has *n* states and *m* transitions. However, variants of that question, such as the emptiness problem for [non-erasing stack automata](https://en.wikipedia.org/wiki/Stack_automaton), are [PSPACE-complete](wikipedia://en/54685).[^o4] The emptiness problem in machine learning and formal languages determines if a model or automaton generates the [empty language](wikipedia://en/10939), which is undecidable for certain alternating multi-head [finite automata](wikipedia://en/10931) over single-letter alphabets.[^o5]

:::

The emptiness problem is [undecidable](wikipedia://en/15631055) for [context-sensitive grammars](wikipedia://en/6211), a fact that follows from the undecidability of the [halting problem](wikipedia://en/21391870). It is, however, decidable for [context-free grammars](wikipedia://en/6759).[^o4]
