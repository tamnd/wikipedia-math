# NL-complete

::: {#o1 .subject cue=lead name="NL-complete"}

In [computational complexity theory](wikipedia://en/7543), **NL-complete** is a [complexity class](wikipedia://en/502426) containing the languages that are [complete](wikipedia://en/1176530) for **[NL](wikipedia://en/1145955)**, the class of [decision problems](wikipedia://en/8336) that can be solved by a [nondeterministic Turing machine](wikipedia://en/21935) using [a logarithmic amount of memory space](wikipedia://en/1149999). The NL-complete languages are the most "difficult" or "expressive" problems in **NL**. If a deterministic algorithm exists for solving any one of the NL-complete problems in logarithmic memory space, then **NL** = **L**.

:::

::: {#o3 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

**NL** consists of the [decision problems](wikipedia://en/8336) that can be solved by a nondeterministic Turing machine with a read-only input tape and a separate read-write tape whose size is limited to be proportional to the logarithm of the input length. Similarly, **[L](wikipedia://en/1149999)** consists of the languages that can be solved by a deterministic Turing machine with the same assumptions about tape length. Because there are only a polynomial number of distinct configurations of these machines, both **L** and **NL** are subsets of the class **[P](wikipedia://en/658550)** of deterministic polynomial-time decision problems.

Formally, a [decision problem](wikipedia://en/8336) is NL-complete when it belongs to **NL**, and has the additional property that every other decision problem in **NL** can be [reduced](wikipedia://en/848067) to it. Unless otherwise specified, the reductions in this definition are assumed to be many-one reductions by a deterministic logarithmic-space algorithm.

:::

::: {#o5 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

If an NL-complete language *X* could belong to **L**, then so would every other language *Y* in **NL**. For, suppose (by NL-completeness) that there existed a deterministic logspace reduction *r* that maps an instance *y* of problem *Y* to an instance *x* of problem *X*, and also (by the assumption that *X* is in **L**) that there exists a deterministic logspace algorithm *A* for solving problem *X*. With these assumptions, a problem *y* in language Y could be solved in logarithmic space by an algorithm that simulates the behavior of algorithm *A* on input *r*(*y*), using the reduction algorithm to simulate each access to the read-only tape for *r*(*y*).

It follows from the [Immerman–Szelepcsényi theorem](wikipedia://en/2827371) that, if a language is co-NL-complete (that is, if its [complement](wikipedia://en/54347) is NL-complete) then the language is also NL-complete itself.

:::

::: {#o7 .example cue=heading name="Examples"}

## Examples {#Examples}

One important NL-complete problem is [ST-connectivity](https://en.wikipedia.org/wiki/ST-connectivity) (or "Reachability") (Papadimitriou 1994 Thrm. 16.2), the problem of determining whether, given a [directed graph](wikipedia://en/19721986) *G* and two nodes *s* and *t* on that graph, there is a path from *s* to *t*. ST-connectivity can be seen to be in **NL**, because we start at the node *s* and nondeterministically walk to every other reachable node. ST-connectivity can be seen to be NL-hard by considering the computation state graph of any other **NL** algorithm, and considering that the other algorithm will accept if and only if there is a (nondetermistic) path from the starting state to an accepting state.

Another important NL-complete problem is [2-satisfiability](https://en.wikipedia.org/wiki/2-satisfiability) (Papadimitriou 1994 Thrm. 16.3), the problem of determining whether a boolean formula in [conjunctive normal form](wikipedia://en/73342) with two variables per clause is satisfiable.

The problem of unique decipherability of a given [variable-length code](https://en.wikipedia.org/wiki/Variable-length_code) was shown to be co-NL-complete by (Rytter 1986); Rytter used a variant of the [Sardinas–Patterson algorithm](wikipedia://en/23632960) to show that the complementary problem, finding a string that has multiple ambiguous decodings, belongs to **NL**. Because of the Immerman–Szelepcsényi theorem, it follows that unique decipherability is also NL-complete.

Other NL-complete problems include:[^o9][^o10]

- generation of elements by an [associative](https://en.wikipedia.org/wiki/Associative) [binary operation](wikipedia://en/3948)
- solving [systems of linear equations](https://en.wikipedia.org/wiki/Systems_of_linear_equations) with two variables per equation
- equivalence of generalized sequential machines with final states
- deciding the LL(*k*) and LR(*k*) conditions for [context-free grammars](https://en.wikipedia.org/wiki/Context-free_grammars)
- determining whether a directed graph is [strongly connected](https://en.wikipedia.org/wiki/Strongly_connected)
- determining whether a directed graph contains a [directed cycle](https://en.wikipedia.org/wiki/Directed_cycle)
- acceptability problem of [nondeterministic finite automata](https://en.wikipedia.org/wiki/Nondeterministic_finite_automata)
- certain [context-free languages](https://en.wikipedia.org/wiki/Context-free_languages)

Additional NL-complete problems on [propositional logic](https://en.wikipedia.org/wiki/Propositional_calculus), algebra, linear system, graph, [finite automata](https://en.wikipedia.org/wiki/Finite_automata), [context-free grammar](wikipedia://en/6759) are listed in (Jones 1976).
