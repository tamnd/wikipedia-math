# Brzozowski derivative

*Image: Brzozowski derivative.gif.* Brzozowski derivative (on red background) of a dictionary string set with respect to the string "con"

::: {#o1 .subject cue=lead name="Brzozowski derivative"}

In [theoretical computer science](wikipedia://en/323392), particularly in [formal language theory](https://en.wikipedia.org/wiki/Formal_language_theory), the **Brzozowski derivative** $u^{-1}S$ of a [set](wikipedia://en/26691) $S$ of [strings](https://en.wikipedia.org/wiki/Word_%28formal_languages%29) and a string $u$ is the set of all strings obtainable from a string in $S$ by cutting off the [prefix](https://en.wikipedia.org/wiki/Prefix_%28computer_science%29) $u$. Formally:

:::

$$u^{-1}S = \{v \in \Sigma^* \mid uv \in S\}.$$

For example,

$$\text{c}^{-1}\{\text{cat}, \text{cow}, \text{dog}\} = \{\text{at}, \text{ow}\}.$$

The Brzozowski derivative was introduced under various different names since the late 1950s.[^o2][^o3][^o4] Today it is named after the computer scientist [Janusz Brzozowski](wikipedia://en/23616030) who investigated its properties and gave an [algorithm](wikipedia://en/775) to compute the derivative of a generalized [regular expression](wikipedia://en/25717).[^o5]

::: {#o7 .definition cue=heading name="Definition"}

## Definition {#Definition}

Even though originally studied for regular expressions, the definition applies to arbitrary formal languages. Given any [formal language](wikipedia://en/10939) $S$ over an alphabet $\Sigma$ and any string $u \in \Sigma^*$, the derivative of $S$ with respect to $u$ is defined as:[^o5]

$$u^{-1}S = \{v \in \Sigma^* \mid uv \in S\}$$

The Brzozowski derivative is a special case of [left quotient](wikipedia://en/208850) by a singleton set containing only $u$: $\ u^{-1}S = \{u\} \;\backslash\; S$.

Equivalently, for all $u,v \in \Sigma^*$:

$$v \in u^{-1}S \;\Leftrightarrow\; uv \in S.$$

From the definition, for all $u, v \in \Sigma^*$:

$$(uv)^{-1}S = v^{-1}(u^{-1}S)$$

since for all $w \in \Sigma^*$, we have $w \in (uv)^{-1}S \Leftrightarrow uvw \in S \Leftrightarrow vw \in u^{-1}S \Leftrightarrow w \in v^{-1}(u^{-1}S)$.

The derivative with respect to an arbitrary string reduces to successive derivatives over the symbols of that string, since for all $a \in \Sigma, u \in \Sigma^*$:

$$\begin{aligned} (ua)^{-1}S &= a^{-1}(u^{-1}S) \\ \varepsilon^{-1}S &= S \end{aligned}$$

A language $S \subseteq \Sigma^*$ is called *nullable* if it contains the empty string $\varepsilon$. Each language $S$ is uniquely determined by nullability of its derivatives:

$$w \in S \ \Leftrightarrow\ \varepsilon \in w^{-1}S$$

A language can be viewed as a (potentially infinite) boolean-labelled [tree](https://en.wikipedia.org/wiki/Tree_%28automata_theory%29) (see also [tree (set theory)](wikipedia://en/704160) and [infinite-tree automaton](https://en.wikipedia.org/wiki/Infinite-tree_automaton)). Each possible string $w \in \Sigma^*$ denotes a node in the tree, with label *true* when $w \in S$ and *false* otherwise. In this interpretation, the derivative with respect to a symbol $a$ corresponds to the subtree obtained by following the edge $a$ from the root. Decomposing a tree into the root and the subtrees $a^{-1}S$ corresponds to the following equality, which holds for every language $S \subseteq \Sigma^*$:

$$S = (\{\varepsilon\} \cap S) \cup \bigcup_{a \in \Sigma} a(a^{-1}S).$$

:::

## Derivatives of generalized regular expressions {#Derivatives_of_generalized_regular_expressions}

When a language is given by a regular expression, the concept of derivatives leads to an algorithm for deciding whether a given word belongs to the regular expression.

Given a finite [alphabet](https://en.wikipedia.org/wiki/Alphabet) *A* of symbols,[^o9] a **generalized regular expression** *R* denotes a possibly infinite set of finite-length strings over the alphabet *A*, called the **language** of *R*, denoted *L*(*R*).

A generalized regular expression can be one of the following (where *a* is a symbol of the alphabet *A*, and *R* and *S* are generalized regular expressions):

- "∅" denotes the [empty set](wikipedia://en/9566): *L*(∅) = {},
- "ε" denotes the singleton set containing the [empty string](wikipedia://en/835827): *L*(ε) = {ε},
- "*a*" denotes the singleton set containing the single-symbol string *a*: *L*(*a*) = {*a*},
- "*R*∨*S*" denotes the union of *R* and *S*: *L*(*R*∨*S*) = *L*(*R*) ∪ *L*(*S*),
- "*R*∧*S*" denotes the intersection of *R* and *S*: *L*(*R*∧*S*) = *L*(*R*) ∩ *L*(*S*),
- "¬*R*" denotes the complement of *R* (with respect to *A*\*, the set of all strings over *A*): *L*(¬*R*) = *A*\* \\ *L*(*R*),
- "*RS*" denotes the concatenation of *R* and *S*: *L*(*RS*) = *L*(*R*) · *L*(*S*),
- "*R*\*" denotes the [Kleene closure](https://en.wikipedia.org/wiki/Kleene_closure) of *R*: *L*(*R*\*) = *L*(*R*)\*.

In an ordinary regular expression, neither ∧ nor ¬ is allowed.

::: {#o11 .definition kind=definition/construction cue=heading name="Computation"}

### Computation {#Computation}

For any given generalized regular expression *R* and any string *u*, the derivative *u*<sup>−1</sup>*R* is again a generalized regular expression (denoting the language *u*<sup>−1</sup>*L*(*R*)).[^o12] It may be computed recursively as follows.[^o13]

| (*ua*)<sup>−1</sup>*R* | \= *a*<sup>−1</sup>(*u*<sup>−1</sup>*R*) | for a symbol *a* and a string *u* |
|---|---|---|
| *ε*<sup>−1</sup>*R* | \= *R* |  |

Using the previous two rules, the derivative with respect to an arbitrary string is explained by the derivative with respect to a single-symbol string *a*. The latter can be computed as follows:[^o14]

| *a*<sup>−1</sup>*a* | \= *ε* |  |
|---|---|---|
| *a*<sup>−1</sup>*b* | \= ∅ | for each symbol *b*≠*a* |
| *a*<sup>−1</sup>*ε* | \= ∅ |  |
| *a*<sup>−1</sup>∅ | \= ∅ |  |
| *a*<sup>−1</sup>(*R*\*) | \= (*a*<sup>−1</sup>*R*)*R*\* |  |
| *a*<sup>−1</sup>(*RS*) | \= (*a*<sup>−1</sup>*R*)*S* ∨ ν(*R*)*a*<sup>−1</sup>*S* |  |
| *a*<sup>−1</sup>(*R*∧*S*) | \= (*a*<sup>−1</sup>*R*) ∧ (*a*<sup>−1</sup>*S*) |  |
| *a*<sup>−1</sup>(*R*∨*S*) | \= (*a*<sup>−1</sup>*R*) ∨ (*a*<sup>−1</sup>*S*) |  |
| *a*<sup>−1</sup>(¬*R*) | \= ¬(*a*<sup>−1</sup>*R*) |  |

Here, $\nu(R)$ is an [auxiliary function](wikipedia://en/11826062) yielding a generalized regular expression that evaluates to the empty string *ε* if *R* language contains *ε*, and otherwise evaluates to ∅. This function can be computed by the following rules:[^o15]

| ν(*a*) | \= ∅ | for any symbol *a* |
|---|---|---|
| ν(*ε*) | \= *ε* |  |
| ν(∅) | \= ∅ |  |
| ν(*R*\*) | \= *ε* |  |
| ν(*RS*) | \= ν(*R*) ∧ ν(*S*) |  |
| ν(*R* ∧ *S*) | \= ν(*R*) ∧ ν(*S*) |  |
| ν(*R* ∨ *S*) | \= ν(*R*) ∨ ν(*S*) |  |
| ν(¬*R*) | \= *ε* | if ν(*R*) = ∅ |
| ν(¬*R*) | \= ∅ | if ν(*R*) = *ε* |

:::

::: {#o17 .statement kind=statement/fact cue=heading name="Properties"}

### Properties {#Properties}

A string *u* is a member of the string set denoted by a generalized regular expression *R* if and only if ε is a member of the string set denoted by the derivative *u*<sup>−1</sup>*R*.[^o18]

Considering all the derivatives of a fixed generalized regular expression *R* results in only finitely many different languages. If their number is denoted by *d*<sub>*R*</sub>, all these languages can be obtained as derivatives of *R* with respect to strings of length less than *d*<sub>*R*</sub>.[^o19] Furthermore, there is a complete [deterministic finite automaton](wikipedia://en/653404) with *d*<sub>*R*</sub> states that recognises the [regular language](wikipedia://en/25723) given by *R*, as stated by the [Myhill–Nerode theorem](wikipedia://en/339992).

:::

## Derivatives of context-free languages {#Derivatives_of_context-free_languages}

Derivatives are also effectively computable for recursively defined equations with regular expression operators, which are equivalent to [context-free grammars](wikipedia://en/6759). This insight was used to derive [parsing](https://en.wikipedia.org/wiki/Parsing) algorithms for [context-free languages](wikipedia://en/6867).[^o21] Implementation of such algorithms have shown to have cubic [time complexity](wikipedia://en/405944),[^o22] corresponding to the complexity of the [Earley parser](https://en.wikipedia.org/wiki/Earley_parser) on general context-free grammars.
