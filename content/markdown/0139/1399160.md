# Encrypted function

::: {#o1 .subject cue=lead name="Encrypted function"}

An **encrypted function** is an attempt to provide [mobile code](https://en.wikipedia.org/wiki/Mobile_code) privacy without providing any [tamper-resistant](https://en.wikipedia.org/wiki/Tamper-resistance) hardware. It is a method where in mobile code can carry out [cryptographic](wikipedia://en/18934432) primitives.

:::

[Polynomial](https://en.wikipedia.org/wiki/Polynomial_function) and [rational functions](wikipedia://en/361210) are [encrypted](https://en.wikipedia.org/wiki/Encrypted) such that their transformation can again be implemented, as programs consisting of [cleartext](https://en.wikipedia.org/wiki/Cleartext) instructions that a [processor](https://en.wikipedia.org/wiki/Central_processing_unit) or [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29) understands. The processor would not understand the program's function. This field of study is gaining popularity as mobile cryptography.

::: {#o3 .example cue=heading name="Example"}

## Example {#Example}

Scenario: Host A, has an [algorithm](wikipedia://en/775) which computes function f. A wants to send its [mobile agent](https://en.wikipedia.org/wiki/Mobile_agent) to B which holds input x, to compute f(x). But A doesn't want B to learn anything about f.

Scheme: Function f is encrypted in a way that results in E(f). Host A then creates another program P(E(f)), which implements E(f), and sends it to B through its agent. B then runs the agent, which computes P(E(f))(x) and returns the result to A. A then decrypts this to get f(x).

Drawbacks: Finding appropriate encryption schemes that can transform arbitrary functions is a challenge. The scheme doesn't prevent [denial of service](https://en.wikipedia.org/wiki/Denial_of_service), replay, [experimental extraction](https://en.wikipedia.org/wiki/Experimental_extraction) and others.

:::
