# Turing machine examples

::: {#o1 .subject cue=lead name="Turing machine examples"}

The following are examples to supplement the article [Turing machine](wikipedia://en/30403).

:::

## Turing's first example {#Turing's_first_example}

The following table is [Turing](https://en.wikipedia.org/wiki/Turing)'s very first example (Turing 1937):

"1. A machine can be constructed to compute the sequence 0 1 0 1 0 1..." (0 \<blank> 1 \<blank> 0...)[^n1]

::: {#o4 .table cue=table}

| Configuration |  | Behavior |  |
|---|---|---|---|
| m-configuration (state) | Tape symbol | Tape operations | Final m-configuration (state) |
| b | blank | P0, R | c |
| c | blank | R | e |
| e | blank | P1, R | f |
| f | blank | R | b |

:::

With regard to what actions the machine actually does, Turing (1936)[^n2] states the following:

"This \[example\] table (and all succeeding tables of the same kind) is to be understood to mean that for a configuration described in the first two columns the operations in the third column are carried out successively, and the machine then goes over into the m-configuration in the final column."[^n2]

He makes this very clear when he reduces the above table to a single instruction called "b",[^n3] but his instruction consists of 3 lines. Instruction "b" has three different symbol possibilities {None, 0, 1}. Each possibility is followed by a sequence of actions until we arrive at the rightmost column, where the final m-configuration is "b":

::: {#o8 .table cue=table}

| Current m-configuration (instruction) | Tape symbol | Operations on the tape | Final m-configuration (instruction) |
|---|---|---|---|
| b | None | P0 | b |
| b | 0 | R, R, P1 | b |
| b | 1 | R, R, P0 | b |

:::

As observed by a number of commentators including Turing (1937) himself, (e.g., Post (1936), Post (1947), Kleene (1952), Wang (1954)) the Turing instructions are not atomic — further simplifications of the model can be made without reducing its computational power; see more at [Post–Turing machine](wikipedia://en/3688147).

As stated in the article [Turing machine](wikipedia://en/30403), Turing proposed that his table be further atomized by allowing only a single print/erase followed by a single tape movement L/R/N. He gives us this example of the first little table converted:[^n4]

::: {#o10 .table cue=table}

| Current m-configuration (Turing state) | Tape symbol | Print-operation | Tape-motion | Final m-configuration (Turing state) |
|---|---|---|---|---|
| q<sub>1</sub> | blank | P0 | R | q<sub>2</sub> |
| q<sub>2</sub> | blank | P blank, i.e. E | R | q<sub>3</sub> |
| q<sub>3</sub> | blank | P1 | R | q<sub>4</sub> |
| q<sub>4</sub> | blank | P blank, i.e. E | R | q<sub>1</sub> |

:::

Turing's statement still implies five atomic operations. At a given instruction (m-configuration) the machine:

1. observes the tape-symbol underneath the head
1. based on the observed symbol goes to the appropriate instruction-sequence to use
1. prints symbol S<sub>j</sub> or erases or does nothing
1. moves tape left, right or not at all
1. goes to the final m-configuration for that symbol

Because a Turing machine's actions are not atomic, a simulation of the machine must atomize each 5-tuple into a sequence of simpler actions. One possibility — used in the following examples of "behaviors" of his machine — is as follows:

(q<sub>i</sub>) Test tape-symbol under head: If the symbol is S<sub>0</sub> go to q<sub>i</sub>.01, if symbol S<sub>1</sub> go to q<sub>i</sub>.11, if symbol S<sub>2</sub> go to q<sub>i</sub>.21, etc.

(q<sub>i</sub>.01) print symbol S<sub>j</sub>0 or erase or do nothing then go to q<sub>i</sub>.02

(q<sub>i</sub>.02) move tape left or right nor not at all then go to qm0

(q<sub>i</sub>.11) print symbol S<sub>j</sub>1 or erase or do nothing then go to q<sub>i</sub>.12

(q<sub>i</sub>.12) move tape left or right nor not at all then go to qm1

(q<sub>i</sub>.21) print symbol S<sub>j</sub>2 or erase or do nothing then go to q<sub>i</sub>.22

(q<sub>i</sub>.22) move tape left or right nor not at all then go to qm2

(etc — all symbols must be accounted for)

So-called "canonical" [finite-state machines](wikipedia://en/10931) do the symbol tests "in parallel"; see more at [microprogramming](https://en.wikipedia.org/wiki/Microprogramming).

In the following example of what the machine does, we will note some peculiarities of Turing's models:

The convention of writing the figures only on alternate squares is very useful: I shall always make use of it.[^n2]

Thus when printing he skips every other square. The printed-on squares are called F-squares; the blank squares in between may be used for "markers" and are called "E-squares" as in "liable to erasure." The F-squares in turn are his "Figure squares" and will only bear the symbols 1 or 0 — symbols he called "figures" (as in "binary numbers").

## A copy subroutine {#A_copy_subroutine}

This is a very important subroutine used in the "multiply" routine.

The example Turing machine handles a string of 0s and 1s, with 0 represented by the blank symbol. Its task is to double any series of 1s encountered on the tape by writing a 0 between them. For example, when the head reads "111", it will write a 0, then "111". The output will be "1110111".

In order to accomplish its task, this Turing machine will need only 5 states of operation, which are called {s<sub>1</sub>, s<sub>2</sub>, s<sub>3</sub>, s<sub>4</sub>, s<sub>5</sub>}. Each state does 4 actions:

1. Read the symbol under the head
1. Write the output symbol decided by the state
1. Move the tape to the left or to the right decided by the state
1. Switch to the following state decided by the current state

| Initial m-configuration (current instruction) | Tape symbol | Print operation | Tape motion | Final m-configuration (next instruction) |
|---|---|---|---|---|
| s<sub>1</sub> | 0 | N | N | H |
| s<sub>1</sub> | 1 | E | R | s<sub>2</sub> |
| s<sub>2</sub> | 0 | E | R | s<sub>3</sub> |
| s<sub>2</sub> | 1 | P1 | R | s<sub>2</sub> |
| s<sub>3</sub> | 0 | P1 | L | s<sub>4</sub> |
| s<sub>3</sub> | 1 | P1 | R | s<sub>3</sub> |
| s<sub>4</sub> | 0 | E | L | s<sub>5</sub> |
| s<sub>4</sub> | 1 | P1 | L | s<sub>4</sub> |
| s<sub>5</sub> | 0 | P1 | R | s<sub>1</sub> |
| s<sub>5</sub> | 1 | P1 | L | s<sub>5</sub> |

The behavior of this machine can be described as a loop: it starts out in s<sub>1</sub>, replaces the first 1 with a 0, then uses s<sub>2</sub> to move to the right, skipping over 1s and the first 0 encountered. s<sub>3</sub> then skips over the next sequence of 1s (initially there are none) and replaces the first 0 it finds with a 1. s<sub>4</sub> moves back to the left, skipping over 1s until it finds a 0 and switches to s<sub>5</sub>. s<sub>5</sub> then moves to the left, skipping over 1s until it finds the 0 that was originally written by s<sub>1</sub>.

It replaces that 0 with a 1, moves one position to the right and enters s<sub>1</sub> again for another round of the loop.

This continues until s<sub>1</sub> finds a 0 (this is the 0 in the middle of the two strings of 1s) at which time the machine halts.

### Alternative description {#Alternative_description}

Another description sees the problem as how to keep track of how many "1"s there are. We can't use one state for each possible number (a state for each of 0,1,2,3,4,5,6 etc), because then we'd need infinite states to represent all the natural numbers, and the state machine is *finite* - we'll have to track this using the tape in some way.

The basic way it works is by copying each "1" to the other side, by moving back and forth - it is intelligent enough to remember which part of the trip it is on. In more detail, it carries each "1" across to the other side, by recognizing the separating "0" in the middle, and recognizing the "0" on the other side to know it's reached the end. It comes back using the same method, detecting the middle "0", and then the "0" on the original side. This "0" on the original side is the key to the puzzle of how it keeps track of the number of 1's.

The trick is that before carrying the "1", it marks that digit as "taken" by replacing it with an "0". When it returns, it fills that "0" back in with a "1", *then moves on to the next one*, marking it with an "0" and repeating the cycle, carrying that "1" across and so on. *With each trip across and back, the marker "0" moves one step closer to the centre*. This is how it keeps track of how many "1"'s it has taken across.

When it returns, the marker "0" looks like the end of the collection of "1"s to it - any "1"s that have already been taken across are invisible to it (on the other side of the marker "0") and so it is as if it is working on an (N-1) number of "1"s - similar to a proof by [mathematical induction](wikipedia://en/18881).

## 3-state [Busy Beaver](https://en.wikipedia.org/wiki/Busy_Beaver) {#3-state_Busy_Beaver}

The following Turing table of instructions was derived from Peterson:[^n5] "a three-state busy beaver writes 6 ones before it comes to a halt". Peterson moves the head; in the following model the tape moves. 0 is the blank character: the tape starts with all cells 0.

::: {#o19 .table cue=table}

| Tape symbol | Current state **A** |  |  | Current state **B** |  |  | Current state **C** |  |  |
|---|---|---|---|---|---|---|---|---|---|
|  | Write symbol | Move tape | Next state | Write symbol | Move tape | Next state | Write symbol | Move tape | Next state |
| 0 | 1 | L | **B** | 1 | R | **A** | 1 | R | **B** |
| 1 | 1 | R | **C** | 1 | L | **B** | 1 | N | **HALT** |

:::

The "state" drawing of the 3-state busy beaver shows the internal sequences of events required to actually perform "the state". As noted above Turing (1937) makes it perfectly clear that this is the proper interpretation of the 5-tuples that describe the instruction.[^n1] For more about the atomization of Turing 5-tuples see [Post–Turing machine](wikipedia://en/3688147):
