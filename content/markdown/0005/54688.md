# NP-easy

::: {#o1 .subject cue=lead name="NP-easy"}

In [complexity theory](wikipedia://en/7543), the [complexity class](wikipedia://en/502426) **NP-easy** is the set of [function problems](wikipedia://en/663345) that are solvable in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) by a [deterministic Turing machine](https://en.wikipedia.org/wiki/Deterministic_Turing_machine) with an [oracle](wikipedia://en/22431) for some [decision problem](wikipedia://en/8336) in [NP](wikipedia://en/21562).

:::

In other words, a problem X is NP-easy [if and only if](wikipedia://en/14922) there exists some problem Y in NP such that X is [polynomial-time Turing reducible](https://en.wikipedia.org/wiki/Polynomial-time_Turing_reduction) to Y.[^o2] This means that given an [oracle](wikipedia://en/22431) for Y, there exists an algorithm that solves X in polynomial time (possibly by repeatedly using that oracle).

NP-easy is another name for FP<sup>NP</sup> (see the [function problem](wikipedia://en/663345) article) or for FΔ<sub>2</sub>P (see the [polynomial hierarchy](wikipedia://en/658651) article).

An example of an NP-easy problem is the problem of sorting a list of strings. The decision problem "is string A greater than string B" is in NP. There are algorithms such as [quicksort](wikipedia://en/3268249) that can sort the list using only a polynomial number of calls to the comparison routine, plus a polynomial amount of additional work. Therefore, sorting is NP-easy.

There are also more difficult problems that are NP-easy. See [NP-equivalent](https://en.wikipedia.org/wiki/NP-equivalent) for an example.

The definition of NP-easy uses a [Turing reduction](wikipedia://en/1188375) rather than a [many-one reduction](wikipedia://en/362983) because the answers to problem *Y* are only TRUE or FALSE, but the answers to problem *X* can be more general. Therefore, there is no general way to translate an instance of *X* to an instance of *Y* with the same answer.
