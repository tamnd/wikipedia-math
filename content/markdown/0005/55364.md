# MMX (instruction set)

::: {#o1 .subject cue=lead name="MMX"}

*Image: PentiumMMX-presslogo.jpg.* Pentium with MMX

**MMX** is a *single instruction, multiple data* ([SIMD](https://en.wikipedia.org/wiki/SIMD)) [instruction set architecture](https://en.wikipedia.org/wiki/Instruction_set_architecture) extension\* designed by [Intel](https://en.wikipedia.org/wiki/Intel), introduced on January 8, 1997[^o2][^o3] with its [Pentium](https://en.wikipedia.org/wiki/Pentium) [P5 (microarchitecture)](https://en.wikipedia.org/wiki/P5_%28microarchitecture%29) based line of [microprocessors](https://en.wikipedia.org/wiki/Microprocessor), named "Pentium with MMX Technology".[^o4] It developed out of a similar unit introduced on the [Intel i860](https://en.wikipedia.org/wiki/Intel_i860),[^o5] and earlier the [Intel i750](https://en.wikipedia.org/wiki/Intel_i750) video pixel processor. MMX is a [processor supplementary capability](https://en.wikipedia.org/wiki/Processor_supplementary_capability) that is supported on [IA-32](https://en.wikipedia.org/wiki/IA-32) processors by Intel and other vendors . AMD also added MMX instruction set in its [K6](https://en.wikipedia.org/wiki/AMD_K6) processor.

:::

*[The New York Times](https://en.wikipedia.org/wiki/The_New_York_Times)* described the initial push, including [Super Bowl](https://en.wikipedia.org/wiki/Super_Bowl) advertisements, as focused on "a new generation of glitzy multimedia products, including videophones and 3-D video games."[^o6]

MMX has subsequently been extended by several programs by Intel and others: [3DNow!](wikipedia://en/211551), [Streaming SIMD Extensions](wikipedia://en/55365) (SSE), and ongoing revisions of [Advanced Vector Extensions](wikipedia://en/16779711) (AVX).

## Overview {#Overview}

### Naming {#Naming}

MMX is officially a meaningless [initialism](https://en.wikipedia.org/wiki/Initialism)[^o9] [trademarked](https://en.wikipedia.org/wiki/Trademark) by Intel;[^o10] unofficially, the initials have been variously explained as standing for

- *MultiMedia eXtension*,[^o2] or
- *Matrix Math eXtension*.[^o11]

[Advanced Micro Devices](https://en.wikipedia.org/wiki/Advanced_Micro_Devices) (AMD), during one of its many court battles with Intel, produced marketing material from Intel indicating that MMX stood for "Matrix Math Extensions". Since an [initialism](https://en.wikipedia.org/wiki/Initialism) cannot be trademarked, this was an attempt to invalidate Intel's trademark. In 1995, Intel filed suit against AMD and Cyrix Corp. for misuse of its trademark MMX. AMD and Intel settled, with AMD acknowledging MMX as a trademark owned by Intel, and with Intel granting AMD rights to use the MMX trademark as a technology name, but not a processor name.[^o12] Also the "MMX" term is sometimes confused with the separate [MultiMedia Extensions](https://en.wikipedia.org/wiki/MultiMedia_Extensions) API on [Windows 3.x](https://en.wikipedia.org/wiki/Windows_3.x) and [Windows 9x](https://en.wikipedia.org/wiki/Windows_9x).

### Technical details {#Technical_details}

*Image: Pentium II.jpg.* Pentium II processor with MMX technology

MMX defines eight [processor registers](https://en.wikipedia.org/wiki/Processor_register), named MM0 through MM7, and operations that operate on them. Each register is 64 bits wide and can be used to hold either 64-bit [integers](wikipedia://en/14563), or multiple smaller integers in a "packed" format: one instruction can then be applied to two 32-bit integers, four 16-bit integers, or eight 8-bit integers at once.[^o15]

MMX provides only integer operations. When originally developed, for the [Intel i860](https://en.wikipedia.org/wiki/Intel_i860), the use of integer math made sense (both 2D and 3D calculations required it), but as graphics cards that did much of this became common, integer [SIMD](https://en.wikipedia.org/wiki/SIMD) in the CPU became somewhat redundant for graphical applications. Alternatively, the [saturation arithmetic](https://en.wikipedia.org/wiki/Saturation_arithmetic) operations in MMX could significantly speed up some [digital signal processing](https://en.wikipedia.org/wiki/Digital_signal_processing) applications.

To avoid compatibility problems with the [context switch](https://en.wikipedia.org/wiki/Context_switch) mechanisms in existing operating systems, the MMX registers are aliases for the existing [x87](https://en.wikipedia.org/wiki/X87) [floating-point unit](https://en.wikipedia.org/wiki/Floating-point_unit) (FPU) registers, which context switches would already save and restore. Unlike the x87 registers, which behave like a [stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29), the MMX registers are each directly addressable (random access).

Any operation involving the floating-point stack might also affect the MMX registers and vice versa, so this aliasing makes it difficult to work with floating-point and SIMD operations in the same program.[^o16] To maximize performance, software often used the processor exclusively in one mode or the other, deferring the relatively slow switch between them as long as possible.

Each 64-bit MMX register corresponds to the [mantissa](wikipedia://en/419250) part of an 80-bit x87 register. The upper 16 bits of the x87 registers thus go unused in MMX, and these bits are all set to ones, making them *Not a Number* ([NaN](https://en.wikipedia.org/wiki/NaN)) data types, or infinities in the floating-point representation. This can be used by software to decide whether a given register's content is intended as floating-point or SIMD data.

### Software support {#Software_support}

Software support for MMX developed slowly.[^o6] [Intel's C Compiler](https://en.wikipedia.org/wiki/Intel_C++_Compiler) and related development tools obtained [intrinsics](https://en.wikipedia.org/wiki/Intrinsic_function) for invoking MMX instructions and Intel released [libraries](https://en.wikipedia.org/wiki/Library_%28computing%29) of common vectorized algorithms using MMX. Both Intel and [Metrowerks](https://en.wikipedia.org/wiki/Metrowerks) attempted [automatic vectorization](https://en.wikipedia.org/wiki/Automatic_vectorization) in their compilers, but the operations in the [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) programming language mapped poorly onto the MMX instruction set and custom algorithms as of 2000 typically still had to be written in [assembly language](https://en.wikipedia.org/wiki/Assembly_language).

## Successors {#Successors}

AMD, a competing [x86](https://en.wikipedia.org/wiki/X86) microprocessor vendor, enhanced Intel's MMX with their own [3DNow!](wikipedia://en/211551) instruction set. 3DNow is best known for adding single-precision (32-bit) floating-point support to the SIMD instruction-set, among other integer and more general enhancements.

Following MMX, Intel's next major x86 extension was the [Streaming SIMD Extensions](wikipedia://en/55365) (SSE), introduced with the [Pentium III](https://en.wikipedia.org/wiki/Pentium_III) family[^o22] in 1999,[^o23] roughly a year after AMD's 3DNow! was introduced.

SSE addressed the core shortcomings of MMX (inability to mix integer-SIMD ops with any floating-point ops) by creating a new 128-bit wide register file (XMM0–XMM7) and new SIMD instructions for it. Like 3DNow!, SSE focused exclusively on single-precision floating-point operations (32-bit); integer SIMD operations were still performed using the MMX register and instruction set. However, the new XMM register-file allowed SSE SIMD-operations to be freely mixed with either MMX or x87 FPU ops.

*Streaming SIMD Extensions 2* ([SSE2](wikipedia://en/311203)), introduced with the [Pentium 4](https://en.wikipedia.org/wiki/Pentium_4), further extended the x86 SIMD instruction set with integer (8/16/32 bit) and double-precision floating-point data support for the XMM register file. SSE2 also allowed the MMX *operation codes* ([opcodes](https://en.wikipedia.org/wiki/Opcode)) to use XMM register operands, extended to even wider YMM and ZMM registers by later SSE revisions.

## MMX in embedded applications {#MMX_in_embedded_applications}

Intel's and [Marvell Technology Group](https://en.wikipedia.org/wiki/Marvell_Technology_Group)'s [XScale](https://en.wikipedia.org/wiki/XScale) microprocessor core starting with PXA270 include an [SIMD](https://en.wikipedia.org/wiki/SIMD) [instruction set architecture](https://en.wikipedia.org/wiki/Instruction_set_architecture) extension to the [ARM architecture](https://en.wikipedia.org/wiki/ARM_architecture) core named *Intel Wireless MMX Technology* (iwMMXt) which functions are similar to those of the [IA-32](https://en.wikipedia.org/wiki/IA-32) MMX extension.[^o26][^o27][^o28] It provides arithmetic and logic operations on 64-bit integer numbers, in which the software may choose to instead perform two 32-bit, four 16-bit or eight 8-bit operations in one instruction. The extension contains 16 data registers of 64-bits and eight control registers of 32-bits. All registers are accessed through standard ARM architecture coprocessor mapping mechanism. iwMMXt occupies coprocessors 0 and 1 space, and some of its opcodes clash with the opcodes of the earlier floating-point extension, FPA.

Later versions of Marvell's ARM processors support both *Wireless MMX* (WMMX) and *Wireless MMX2* (WMMX2) opcodes.
