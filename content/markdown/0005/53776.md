# Kruskal's algorithm

::: {#o1 .subject cue=lead name="Kruskal's algorithm"}

**Kruskal's algorithm**[^o3] finds a [minimum spanning forest](wikipedia://en/41795) of an undirected [edge-weighted graph](https://en.wikipedia.org/wiki/Weighted_graph). If the graph is [connected](wikipedia://en/1614492), it finds a [minimum spanning tree](wikipedia://en/41795). It is a [greedy algorithm](wikipedia://en/89247) that in each step adds to the forest the lowest-weight edge that will not form a [cycle](wikipedia://en/168609).[^o4] The key steps of the algorithm are [sorting](https://en.wikipedia.org/wiki/Sorting) and the use of a [disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure) to detect cycles. Its running time is dominated by the time to sort all of the graph edges by their weight.

:::

A minimum spanning tree of a connected weighted graph is a connected subgraph, without cycles, for which the sum of the weights of all the edges in the subgraph is minimal. For a disconnected graph, a minimum spanning forest is composed of a minimum spanning tree for each [connected component](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29).

This algorithm was first published by [Joseph Kruskal](https://en.wikipedia.org/wiki/Joseph_Kruskal) in 1956,[^o5] and was rediscovered soon afterward by (Loberman Weinberger 1957).[^o7] Other algorithms for this problem include [Prim's algorithm](wikipedia://en/53783), [Borůvka's algorithm](wikipedia://en/197253), and the [reverse-delete algorithm](wikipedia://en/9516059).

::: {#o9 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

The algorithm performs the following steps:

- Create a forest (a set of trees) initially consisting of a separate single-vertex tree for each vertex in the input graph.
- Sort the graph edges by weight.
- Loop through the edges of the graph, in ascending sorted order by their weight. For each edge:
  - Test whether adding the edge to the current forest would create a cycle.
  - If not, add the edge to the forest, combining two trees into a single tree.

At the termination of the algorithm, the forest forms a minimum spanning forest of the graph. If the graph is connected, the forest has a single component and forms a minimum spanning tree.

:::

## Pseudocode {#Pseudocode}

The following code is implemented with a [disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure). It represents the forest *F* as a set of undirected edges, and uses the disjoint-set data structure to efficiently determine whether two vertices are part of the same tree.

**function** Kruskal(*Graph G*) **is** F:= ∅ **for each** v **in** G.Vertices **do** MAKE-SET(v)

**for each** {u, v} **in** G.Edges ordered by increasing weight({u, v}) **do** **if** FIND-SET(u) ≠ FIND-SET(v) **then** F := F ∪ { {u, v} } UNION(FIND-SET(u), FIND-SET(v)) **return** F

## Complexity {#Complexity}

For a graph with $E$ edges and $V$ vertices, Kruskal's algorithm can be shown to run in time $O(E \log E)$ time, with simple data structures. This time bound is often written instead as $O(E \log V)$, which is equivalent for graphs with no isolated vertices, because for these graphs $V / 2 \le E < V^{2}$ and the logarithms of $V$ and $V^{2}$ are again within a constant factor of each other.

To achieve this bound, first sort the edges by weight using a [comparison sort](wikipedia://en/3189304) in $O(E \log E)$ time. Once sorted, it is possible to loop through the edges in sorted order in constant time per edge. Next, use a [disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure), with a set of vertices for each component, to keep track of which vertices are in which components. Creating this structure, with a separate set for each vertex, takes $V$ operations and $O(V)$ time. The final iteration through all edges performs two find operations per edge, to determine the components containing the two endpoints of the edge, and then possibly one union operation for each edge whose endpoints are in different components. Using the [disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure) for these operations takes [amortized time](https://en.wikipedia.org/wiki/Amortized_time) $O(\alpha(E,V))$ time per operation, giving worst-case total time $O(E \alpha(E,V))$ for this loop, where $\alpha$ is the extremely slowly growing [inverse Ackermann function](https://en.wikipedia.org/wiki/Inverse_Ackermann_function). This part of the time bound is much smaller than the time for the sorting step, so the total time for the algorithm can be simplified to the time for the sorting step.

In cases where the edges are already sorted, or where they have small enough integer weight to allow [integer sorting](https://en.wikipedia.org/wiki/Integer_sorting) algorithms such as [counting sort](https://en.wikipedia.org/wiki/Counting_sort) or [radix sort](https://en.wikipedia.org/wiki/Radix_sort) to sort them in linear time, the disjoint set operations are the slowest remaining part of the algorithm and the total time is $O(E \alpha(E,V))$.

## Proof of correctness {#Proof_of_correctness}

The proof consists of two parts. First, it is proved that the algorithm produces a [spanning tree](wikipedia://en/455770). Second, it is proved that the constructed spanning tree is of minimal weight.

### Spanning tree {#Spanning_tree}

Let $G$ be a connected, weighted graph and let $Y$ be the subgraph of $G$ produced by the algorithm. $Y$ cannot have a cycle, as by definition an edge is not added if it results in a cycle. $Y$ cannot be disconnected, since the first encountered edge that joins two components of $Y$ would have been added by the algorithm. Thus, $Y$ is a spanning tree of $G$.

### Minimality {#Minimality}

We show that the following proposition ***P*** is true by [induction](wikipedia://en/18881): If *F* is the set of edges chosen at any stage of the algorithm, then there is some minimum spanning tree that contains *F* and none of the edges rejected by the algorithm.

- Clearly ***P*** is true at the beginning, when *F* is empty: any minimum spanning tree will do, and there exists one because a weighted connected graph always has a minimum spanning tree.
- Now assume ***P*** is true for some non-final edge set *F* and let *T* be a minimum spanning tree that contains *F*.
  - If the next chosen edge *e* is also in *T*, then ***P*** is true for *F* + *e*.
  - Otherwise, if *e* is not in *T* then *T* + *e* has a cycle *C*. The cycle *C* contains edges which do not belong to *F* + *e*, since *e* does not form a cycle when added to *F* but does in *T*. Let *f* be an edge which is in *C* but not in *F* + *e*. Note that *f* also belongs to *T*, since *f* belongs to *T* + *e* but not *F* + *e*. By ***P***, *f* has not been considered by the algorithm. *f* must therefore have a weight at least as large as *e*. Then *T* − *f* + *e* is a tree, and it has the same or less weight as *T*. However since *T* is a minimum spanning tree then *T* − *f* + *e* has the same weight as *T*, otherwise we get a contradiction and *T* would not be a minimum spanning tree. So *T* − *f* + *e* is a minimum spanning tree containing *F* + *e* and again ***P*** holds.
- Therefore, by the principle of induction, ***P*** holds when *F* has become a spanning tree, which is only possible if *F* is a minimum spanning tree itself.

:::

## Parallel algorithm {#Parallel_algorithm}

Kruskal's algorithm is inherently sequential and hard to parallelize. It is, however, possible to perform the initial sorting of the edges in parallel or, alternatively, to use a parallel implementation of a [binary heap](https://en.wikipedia.org/wiki/Binary_heap) to extract the minimum-weight edge in every iteration.[^o20] As parallel sorting is possible in time $O(n)$ on $O(\log n)$ processors,[^o21] the runtime of Kruskal's algorithm can be reduced to *O*(*E* α(*V*)), where α again is the inverse of the single-valued [Ackermann function](wikipedia://en/2925).

A variant of Kruskal's algorithm, named Filter-Kruskal, has been described by Osipov et al.[^o22] and is better suited for parallelization. The basic idea behind Filter-Kruskal is to partition the edges in a similar way to [quicksort](wikipedia://en/3268249) and filter out edges that connect vertices of the same tree to reduce the cost of sorting. The following [pseudocode](https://en.wikipedia.org/wiki/Pseudocode) demonstrates this.

**function** filter\_kruskal(G) **is** **if** |G.E| \< kruskal\_threshold: **return** kruskal(G) pivot = choose\_random(G.E) E${}_{\le}$, E${}_{>}$ = partition(G.E, pivot) A = filter\_kruskal(E${}_{\le}$) E${}_{>}$ = filter(E${}_{>}$) A = A ∪ filter\_kruskal(E${}_{>}$) **return** A

**function** partition(E, pivot) **is** E${}_{\le}$ = ∅, E${}_{>}$ = ∅ **foreach** (u, v) in E **do** **if** weight(u, v) ≤ pivot **then** E${}_{\le}$ = E${}_{\le}$ ∪ {(u, v)} **else** E${}_{>}$ = E${}_{>}$ ∪ {(u, v)} **return** E${}_{\le}$, E${}_{>}$

**function** filter(E) **is** E${}_{f}$ = ∅ **foreach** (u, v) in E **do** **if** find\_set(u) ≠ find\_set(v) **then** E${}_{f}$ = E${}_{f}$ ∪ {(u, v)} **return** E${}_{f}$

Filter-Kruskal lends itself better to parallelization as sorting, filtering, and partitioning can easily be performed in parallel by distributing the edges between the processors.[^o22]

Finally, other variants of a parallel implementation of Kruskal's algorithm have been explored. Examples include a scheme that uses helper threads to remove edges that are definitely not part of the MST in the background,[^o23] and a variant which runs the sequential algorithm on *p* subgraphs, then merges those subgraphs until only one, the final MST, remains.[^o24]
