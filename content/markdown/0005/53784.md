# Brute-force attack

::: {#o1 .subject cue=lead name="Brute-force attack"}

In [cryptography](wikipedia://en/18934432), a **brute-force attack** or **exhaustive key search** is a [cryptanalytic attack](wikipedia://en/5715) that consists of an attacker submitting many possible [keys](wikipedia://en/53039) or [passwords](wikipedia://en/24304) with the hope of eventually guessing correctly. This strategy can theoretically be used to break any form of encryption that is not [information-theoretically secure](wikipedia://en/677968).[^n1] However, in a properly designed cryptosystem the chance of successfully guessing the key is negligible.

:::

When [cracking passwords](wikipedia://en/477981), this method is very fast when used to check all short passwords, but for longer passwords other methods such as the [dictionary attack](wikipedia://en/53785) are used because a brute-force search takes too long. Longer passwords, passphrases and keys have more possible values, making them exponentially more difficult to crack than shorter ones due to the diversity of characters.[^o3]

Brute-force attacks can be made less effective by implementing key stretching techniques making it more difficult for an attacker to recognize when the code has been cracked or by making the attacker do more work to test each guess. One of the measures of the strength of an encryption system is how long it would theoretically take an attacker to mount a successful brute-force attack against it.[^o4]

Brute-force attacks are an application of brute-force search, the general problem-solving technique of enumerating all candidates and checking each one. The word 'hammering' is sometimes used to describe a brute-force attack,[^o5] with 'anti-hammering' for countermeasures.[^o6]

## Basic concept {#Basic_concept}

Brute-force attacks work by calculating every possible combination that could make up a password and testing it to see if it is the correct password. As the password's length increases, the amount of time, on average, to find the correct password increases exponentially.[^o8]

## Theoretical limits {#Theoretical_limits}

*Image: Board300.jpg.* The 1998 [Electronic Frontier Foundation](https://en.wikipedia.org/wiki/Electronic_Frontier_Foundation)'s US\$250,000 [DES](wikipedia://en/7978) [cracking machine](wikipedia://en/839358) contained over 1,800 custom chips and could brute-force a DES key in a matter of days. The photograph shows a DES Cracker circuit board fitted with 64 Deep Crack chips using both sides.

The resources required for a brute-force attack grow [exponentially](wikipedia://en/191933) with increasing [key size](wikipedia://en/5749), not linearly. Although U.S. export regulations historically restricted key lengths to 56-bit [symmetric keys](https://en.wikipedia.org/wiki/Symmetric_key) (e.g. [Data Encryption Standard](wikipedia://en/7978)), these restrictions are no longer in place, so modern symmetric algorithms typically use computationally stronger 128- to 256-bit keys.

There is a physical argument that a 128-bit symmetric key is computationally secure against brute-force attack. The [Landauer limit](https://en.wikipedia.org/wiki/Landauer_limit) implied by the laws of physics sets a lower limit on the energy required to perform a computation of $kT \ln 2$ per bit erased in a computation, where *T* is the temperature of the computing device in [kelvins](wikipedia://en/19593121), *k* is the [Boltzmann constant](https://en.wikipedia.org/wiki/Boltzmann_constant), and the [natural logarithm](wikipedia://en/21476) of 2 is about 0.693 (0.6931471805599453). No irreversible computing device can use less energy than this, even in principle.[^n2] Thus, to simply flip through the possible values for a 128-bit symmetric key (ignoring doing the actual computing to check it) would, theoretically, require 2<sup>128</sup> − 1 bit flips on a conventional processor. If it is assumed that the calculation occurs near room temperature (≈300 K), the Von Neumann-Landauer Limit can be applied to estimate the energy required as ≈10<sup>18</sup> [joules](https://en.wikipedia.org/wiki/Joule), which is equivalent to consuming 30 [gigawatts](https://en.wikipedia.org/wiki/Orders_of_magnitude_%28power%29#gigawatt_%28109_watts%29) of power for one year. This is equal to 30×10<sup>9</sup> W×365×24×3600 s = 9.46×10<sup>17</sup> J or 262.7 TWh (about 0.1% of the [yearly world energy production](https://en.wikipedia.org/wiki/World_energy_supply_and_consumption)). The full actual computation – checking each key to see if a solution has been found – would consume many times this amount. Furthermore, this is simply the energy requirement for cycling through the key space; the actual time it takes to flip each bit is not considered, which is certainly greater than 0 (see [Bremermann's limit](https://en.wikipedia.org/wiki/Bremermann's_limit)).

However, this argument assumes that the register values are changed using conventional set and clear operations, which inevitably generate [entropy](https://en.wikipedia.org/wiki/Entropy_%28computing%29). It has been shown that computational hardware can be designed not to encounter this theoretical obstruction (see [reversible computing](https://en.wikipedia.org/wiki/Reversible_computing)), though no such computers are known to have been constructed.

*Image: ATI Radeon HD 5770 Graphics Card-oblique view.jpg.* Modern [GPUs](https://en.wikipedia.org/wiki/Graphics_processing_unit) are well-suited to the repetitive tasks associated with hardware-based password cracking.

As commercial successors of governmental [ASIC](https://en.wikipedia.org/wiki/ASIC) solutions have become available, also known as [custom hardware attacks](wikipedia://en/2174032), two emerging technologies have proven their capability in the brute-force attack of certain ciphers. One is modern [graphics processing unit](https://en.wikipedia.org/wiki/Graphics_processing_unit) (GPU) technology,[^n3] the other is the [field-programmable gate array](https://en.wikipedia.org/wiki/Field-programmable_gate_array) (FPGA) technology. GPUs benefit from their wide availability and price-performance benefit, FPGAs from their [energy efficiency](https://en.wikipedia.org/wiki/Efficient_energy_use) per cryptographic operation. Both technologies try to transport the benefits of parallel processing to brute-force attacks. In the case of GPUs some hundreds, in the case of FPGAs some thousand processing units making them much better suited to cracking passwords than conventional processors. For instance in 2022, 8 [Nvidia RTX 4090](https://en.wikipedia.org/wiki/GeForce_40_series) GPUs were linked together to test password strength by using the software [Hashcat](https://en.wikipedia.org/wiki/Hashcat) with results that showed 200 billion eight-character [NTLM](https://en.wikipedia.org/wiki/NTLM) password combinations could be cycled through in 48 minutes.[^o12][^o13]

Various publications in the fields of cryptographic analysis have proved the energy efficiency of today's FPGA technology; for example, the COPACOBANA FPGA Cluster computer consumes the same energy as a single PC (600 W), but performs like 2,500 PCs for certain algorithms. A number of firms provide hardware-based FPGA cryptographic analysis solutions from a single FPGA [PCI Express](https://en.wikipedia.org/wiki/PCI_Express) card up to dedicated FPGA computers. [WPA](wikipedia://en/422017) and [WPA2](https://en.wikipedia.org/wiki/WPA2) encryption have successfully been brute-force attacked by reducing the workload by a factor of 50 in comparison to conventional CPUs[^n4][^n5] and some hundred in case of FPGAs.

*Image: COPACOBANA FPGA BOARD.jpg.* A single COPACOBANA board boasting 6 Xilinx Spartans – a cluster is made up of 20 of these.

[Advanced Encryption Standard](wikipedia://en/1260) (AES) permits the use of 256-bit keys. Breaking a symmetric 256-bit key by brute force requires 2<sup>128</sup> times more computational power than a 128-bit key. One of the fastest supercomputers in 2019 has a speed of 100 [petaFLOPS](https://en.wikipedia.org/wiki/PetaFLOPS) which could theoretically check 100 trillion (10<sup>14</sup>) AES keys per second (assuming 1000 operations per check), but would still require 3.67×10<sup>55</sup> years to exhaust the 256-bit key space.[^o16]

An underlying assumption of a brute-force attack is that the complete key space was used to generate keys, something that relies on an effective [random number generator](wikipedia://en/2736939), and that there are no defects in the algorithm or its implementation. For example, a number of systems that were originally thought to be impossible to crack by brute-force have nevertheless been [cracked](wikipedia://en/1250124) because the [key space](https://en.wikipedia.org/wiki/Key_space_%28cryptography%29) to search through was found to be much smaller than originally thought, because of a lack of entropy in their [pseudorandom number generators](wikipedia://en/45524). These include [Netscape](https://en.wikipedia.org/wiki/Netscape)'s implementation of [Secure Sockets Layer](https://en.wikipedia.org/wiki/Secure_Sockets_Layer) (SSL) (cracked by [Ian Goldberg](wikipedia://en/829135) and [David Wagner](wikipedia://en/298253) in 1995) and a [Debian](https://en.wikipedia.org/wiki/Debian)/[Ubuntu](https://en.wikipedia.org/wiki/Ubuntu_%28operating_system%29) edition of [OpenSSL](wikipedia://en/438819) discovered in 2008 to be flawed.[^n6][^n7] A similar lack of implemented entropy led to the breaking of [Enigma's](wikipedia://en/9256) code.[^n8][^n9]

## Credential recycling {#Credential_recycling}

Credential recycling is the [hacking](https://en.wikipedia.org/wiki/Hacker_%28computer_security%29) practice of reusing username and password combinations gathered in previous brute-force attacks. A special form of credential recycling is [pass the hash](https://en.wikipedia.org/wiki/Pass_the_hash), where [unsalted](wikipedia://en/701756) hashed credentials are stolen and re-used without first being brute-forced.[^o22]

## Unbreakable codes {#Unbreakable_codes}

Certain types of encryption, by their mathematical properties, cannot be defeated by brute force. An example of this is [one-time pad](wikipedia://en/22210) cryptography, where every [cleartext](https://en.wikipedia.org/wiki/Cleartext) bit has a corresponding key from a truly random sequence of key bits. A 140-character one-time-pad-encoded string subjected to a brute-force attack would eventually reveal every 140-character string possible, including the correct answer – but of all the answers given, there would be no way of knowing which was the correct one. Defeating such a system, as was done by the [Venona project](https://en.wikipedia.org/wiki/Venona_project), generally relies not on pure cryptography, but upon mistakes in its implementation, such as the keypads not being truly random, intercepted keypads, or operators making mistakes.[^n10]

## Countermeasures {#Countermeasures}

In case of an *offline* attack where the attacker has gained access to the encrypted material, one can try key combinations without the risk of discovery or interference. In case of *online* attacks, database and directory administrators can deploy countermeasures such as limiting the number of attempts that a password can be tried, introducing time delays between successive attempts, increasing the answer's complexity (e.g., requiring a [CAPTCHA](https://en.wikipedia.org/wiki/CAPTCHA) answer or employing [multi-factor authentication](https://en.wikipedia.org/wiki/Multi-factor_authentication)), and/or locking accounts out after unsuccessful login attempts.[^n11] Website administrators may prevent a particular IP address from trying more than a predetermined number of password attempts against any account on the site.[^n12] Additionally, the MITRE D3FEND framework provides structured recommendations for defending against brute-force attacks by implementing strategies such as network traffic filtering, deploying decoy credentials, and invalidating authentication caches.[^o28]

## Reverse brute-force attack {#Reverse_brute-force_attack}

In a reverse brute-force attack (also called password spraying), a single (usually common) password is tested against multiple usernames or encrypted files.[^o30] The process may be repeated for a select few passwords. In such a strategy, the attacker is not targeting a specific user.
