# Dictionary attack

::: {#o1 .subject cue=lead name="Dictionary attack"}

In [cryptanalysis](wikipedia://en/5715) and [computer security](https://en.wikipedia.org/wiki/Computer_security), a **dictionary attack** is an attack using a restricted subset of a keyspace to defeat a [cipher](wikipedia://en/5244) or authentication mechanism by trying to determine its decryption key or [passphrase](https://en.wikipedia.org/wiki/Passphrase), sometimes trying thousands or millions of likely possibilities[^o2] often obtained from lists of past security breaches.

:::

## Technique {#Technique}

A dictionary attack is based on trying all the strings in a pre-arranged listing. Such attacks originally used words found in a dictionary (hence the phrase *dictionary attack*);[^o4] however, now there are much larger lists available on the open Internet containing hundreds of millions of passwords recovered from past data breaches.[^o5] There is also cracking software that can use such lists and produce common variations, such as [substituting numbers for similar-looking letters](https://en.wikipedia.org/wiki/Leet). A dictionary attack tries only those possibilities which are deemed most likely to succeed. Dictionary attacks often succeed because many people have a tendency to choose short passwords that are ordinary words or common passwords; or variants obtained, for example, by appending a digit or punctuation character, which are easily covered by modern cracking software pattern generation. A safer approach. is to randomly generate a long password (15 letters or more) or a multiword [passphrase](https://en.wikipedia.org/wiki/Passphrase), using a [password manager](wikipedia://en/4696394) program or manually typing a password.

Dictionary attacks can be deterred by the server administrator by using a more computationally expensive hashing algorithm. [Bcrypt](wikipedia://en/21564294), [scrypt](https://en.wikipedia.org/wiki/Scrypt), and [Argon2](wikipedia://en/48963187) are examples of such resource intensive functions that require significant computational power to process,[^o6] allowing for large improvements in security against dictionary attacks. While other hashing functions, such as [SHA](wikipedia://en/897855) and [MD5](wikipedia://en/18826), are much faster and less expensive to compute, they can still be strengthened by being applied multiple times to an input string through a process called [key stretching](wikipedia://en/4266286). An attacker would have to know approximately how many times the function was applied for a dictionary attack to be feasible.

::: {#o8 .pointer-item cue=pointer name="Pre-computed dictionary attack"}

## Pre-computed dictionary attack/Rainbow table attack {#Pre-computed_dictionary_attack/Rainbow_table_attack}

It is possible to achieve a [time–space tradeoff](https://en.wikipedia.org/wiki/Time–space_tradeoff) by [pre-computing](https://en.wikipedia.org/wiki/Pre-computing) a list of [hashes](wikipedia://en/439526) of dictionary words and storing these in a database using the hash as the [key](https://en.wikipedia.org/wiki/Unique_key). This requires a considerable amount of preparation time, but this allows the actual attack to be executed faster. The storage requirements for the pre-computed tables were once a major cost, but now they are less of an issue because of the low cost of [disk storage](https://en.wikipedia.org/wiki/Disk_storage). Pre-computed dictionary attacks are particularly effective when a large number of passwords are to be cracked. The pre-computed dictionary needs be generated only once, and when it is completed, password hashes can be looked up almost instantly at any time to find the corresponding password. A more refined approach involves the use of [rainbow tables](wikipedia://en/2403284), which reduce storage requirements at the cost of slightly longer lookup-times. *See* [LM hash](https://en.wikipedia.org/wiki/LM_hash) for an example of an [authentication system](https://en.wikipedia.org/wiki/Authentication_protocol) compromised by such an attack.

Pre-computed dictionary attacks, or "rainbow table attacks", can be thwarted by the use of [salt](wikipedia://en/701756), a technique that forces the hash dictionary to be recomputed for each password sought, making [precomputation](wikipedia://en/30208842) infeasible, provided that the number of possible salt values is large enough.[^o9]

:::
