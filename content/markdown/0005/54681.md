# NP-hardness

::: {#o1 .subject cue=lead name="NP-hardness"}

*Image: P np np-complete np-hard.svg.* [Euler diagram](wikipedia://en/2427526) for [P](wikipedia://en/658550), [NP](wikipedia://en/21562), NP-complete, and NP-hard set of problems. The left side is valid under the assumption that [P≠NP](wikipedia://en/6115), while the right side is valid under the assumption that P=NP (except that the empty language and its complement are never NP-complete).

In [computational complexity theory](wikipedia://en/7543), a computational problem *H* is called **NP-hard** if, for every problem *L* which can be solved in [non-deterministic polynomial-time](wikipedia://en/21562), there is a [polynomial-time reduction](https://en.wikipedia.org/wiki/Polynomial_time_reduction) from *L* to *H*. That is, assuming a solution for *H* takes 1 unit time, *H*'s solution can be used to solve *L* in polynomial time.[^o2][^o3] As a consequence, finding a polynomial time algorithm to solve a single NP-hard problem would give polynomial time algorithms for all the problems in the complexity class [NP](wikipedia://en/21562). As it is suspected, but unproven, that [P≠NP](wikipedia://en/6115), it is unlikely that any polynomial-time algorithms for NP-hard problems exist.[^o4][^o5]

:::

A simple example of an NP-hard problem is the [subset sum problem](wikipedia://en/36811).

Informally, if *H* is NP-hard, then it is at least as difficult to solve as the problems in [NP](wikipedia://en/21562). However, the opposite direction is not true: some problems are [undecidable](wikipedia://en/15631055), and therefore even more difficult to solve than all problems in NP, but they are probably not NP-hard (unless P=NP).[^o6]

::: {#o8 .definition cue=heading name="Definition"}

## Definition {#Definition}

A [decision problem](wikipedia://en/8336) *H* is NP-hard when for every problem *L* in NP, there is a [polynomial-time many-one reduction](wikipedia://en/362983) from *L* to *H*.[^o2]

Another definition is to require that there be a polynomial-time reduction from an [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem *G* to *H*.[^o2] As any problem *L* in NP reduces in polynomial time to *G*, *L* reduces in turn to *H* in polynomial time so this new definition implies the previous one. It does not restrict the class NP-hard to decision problems, and it also includes [search problems](wikipedia://en/1471816) or [optimization problems](wikipedia://en/1126536).

:::

## Consequences {#Consequences}

If P ≠ NP, then NP-hard problems could not be solved in polynomial time.

Some NP-hard optimization problems can be polynomial-time [approximated](wikipedia://en/563105) up to some constant approximation ratio (in particular, those in [APX](wikipedia://en/2018925)) or even up to any approximation ratio (those in [PTAS](wikipedia://en/666431#As_a_complexity_class) or [FPTAS](wikipedia://en/666431#Deterministic)). There are many classes of approximability, each one enabling approximation up to a different level.[^o10]

## Examples {#Examples}

All [NP-complete](wikipedia://en/23385892) problems are also NP-hard (see [List of NP-complete problems](wikipedia://en/1707754)). For example, the optimization problem of finding the least-cost cyclic route through all nodes of a weighted graph—commonly known as the [travelling salesman problem](wikipedia://en/31248)—is NP-hard.[^o13] The [subset sum problem](wikipedia://en/36811) is another example: given a set of integers, does any non-empty subset of them add up to zero? That is a [decision problem](wikipedia://en/8336) and happens to be NP-complete.

There are decision problems that are *NP-hard* but not *NP-complete* such as the [halting problem](wikipedia://en/21391870). That is the problem which asks "given a program and its input, will it run forever?" That is a *yes*/*no* question and so is a decision problem. It is easy to prove that the halting problem is NP-hard but not NP-complete. For example, the [Boolean satisfiability problem](wikipedia://en/4715) can be reduced to the halting problem by transforming it to the description of a [Turing machine](wikipedia://en/30403) that tries all [truth value](wikipedia://en/161711) assignments and when it finds one that satisfies the formula it halts and otherwise it goes into an infinite loop. It is also easy to see that the halting problem is not in *NP* since all problems in NP are decidable in a finite number of operations, but the halting problem, in general, is [undecidable](wikipedia://en/15631055). There are also NP-hard problems that are neither *NP-complete* nor *Undecidable*. For instance, the language of [true quantified Boolean formulas](wikipedia://en/20768715) is decidable in [polynomial space](wikipedia://en/39351), but not in non-deterministic polynomial time (unless NP = [PSPACE](wikipedia://en/39351)).[^o14]

:::

## NP-naming convention {#NP-naming_convention}

NP-hard problems do not have to be elements of the complexity class NP. As NP plays a central role in [computational complexity](wikipedia://en/7543), it is used as the basis of several classes:

**[NP](wikipedia://en/21562)**

Class of computational decision problems for which any given *yes*-solution can be verified as a solution in polynomial time by a deterministic Turing machine (or *solvable* by a *non-deterministic* Turing machine in polynomial time).

**NP-hard**

Class of problems which are at least as hard as the hardest problems in NP. Problems that are NP-hard do not have to be elements of NP; indeed, they may not even be decidable.

**[NP-complete](https://en.wikipedia.org/wiki/NP-complete)**

Class of decision problems which contains the hardest problems in NP. Each NP-complete problem has to be in NP.

**[NP-easy](wikipedia://en/54688)**

At most as hard as NP, but not necessarily in NP.

**[NP-equivalent](https://en.wikipedia.org/wiki/NP-equivalent)**

Decision problems that are both NP-hard and NP-easy, but not necessarily in NP.

**[NP-intermediate](wikipedia://en/4637081)**

If P and NP are different, then there exist decision problems in the region of NP that fall between P and the NP-complete problems. (If P and NP are the same class, then NP-intermediate problems do not exist because in this case every NP-complete problem would fall in P, and by definition, every problem in NP can be reduced to an NP-complete problem.)

## Application areas {#Application_areas}

NP-hard problems are often tackled with rules-based languages in areas including:

- [Approximate computing](https://en.wikipedia.org/wiki/Approximate_computing)
- [Configuration](https://en.wikipedia.org/wiki/Configuration_management)
- [Cryptography](wikipedia://en/18934432)
- [Data mining](wikipedia://en/42253)
- [Decision support](https://en.wikipedia.org/wiki/Decision_support_system)
- [Phylogenetics](https://en.wikipedia.org/wiki/Phylogenetics)
- [Planning](https://en.wikipedia.org/wiki/Planning)
- Process monitoring and control
- Rosters or schedules
- Routing/vehicle routing
- [Scheduling](https://en.wikipedia.org/wiki/Schedule)

## NP-hard problems {#NP-hard_problems}

Problems that are decidable but not [NP-complete](wikipedia://en/23385892), often are optimization problems:

- [Knapsack optimization problems](wikipedia://en/16974)
- [Integer programming](wikipedia://en/411215)
- [Travelling salesman optimization problem](wikipedia://en/31248)
- [Maximum clique](wikipedia://en/249254)
- [Longest simple path](wikipedia://en/149646)
- [Graph coloring](wikipedia://en/426743); an application: register allocation in compilers
