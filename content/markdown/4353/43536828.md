# Set constraint

::: {#o1 .subject cue=lead name="Set constraint"}

*Image: SetConstraintsAbstractInterpretation svg.svg.* Set constraints obtained from [abstract interpretation](https://en.wikipedia.org/wiki/Abstract_interpretation) of the [Collatz](wikipedia://en/37895) algorithm

In [mathematics](wikipedia://en/18831) and [theoretical computer science](wikipedia://en/323392), a **set constraint** is an equation or an inequation between sets of [terms](wikipedia://en/24885593#Formal_definition). Similar to systems of ([in](wikipedia://en/89486#Solving_inequations))[equations](wikipedia://en/537048) between numbers, methods are studied for solving systems of set constraints. Different approaches admit different operators (like "∪", "∩", "\\", and function application)[^o2] on sets and different (in)equation relations (like "=", "⊆", and "⊈") between set expressions.

:::

Systems of set constraints are useful to describe (in particular infinite) sets of [ground terms](https://en.wikipedia.org/wiki/Ground_term).[^o3] They arise in program analysis, [abstract interpretation](https://en.wikipedia.org/wiki/Abstract_interpretation), and [type inference](wikipedia://en/279690).

## Relation to regular tree grammars {#Relation_to_regular_tree_grammars}

Each [regular tree grammar](wikipedia://en/5078522) can be systematically transformed into a system of set inclusions such that its minimal solution corresponds to the tree language of the grammar.

For example, the grammar (terminal and nonterminal symbols indicated by lower and upper case initials, respectively) with the rules

{|

\|- | *Bool*<sub>G</sub> || → *false* |- | *Bool*<sub>G</sub> || → *true* |- | *BList*<sub>G</sub> || → *nil* |- | *BList*<sub>G</sub> || → *cons*(*Bool*<sub>G</sub>,*BList*<sub>G</sub>) |- | *BList1*<sub>G</sub> || → *cons*(*true*,*BList*<sub>G</sub>) |- | *BList1*<sub>G</sub> || → *cons*(*false*,*BList1*<sub>G</sub>) |} is transformed to the set inclusion system (constants and variables indicated by lower and upper case initials, respectively):

{|

\|- | *Bool*<sub>S</sub> || ⊇ *false* |- | *Bool*<sub>S</sub> || ⊇ *true* |- | *BList*<sub>S</sub> || ⊇ *nil* |- | *BList*<sub>S</sub> || ⊇ *cons*(*Bool*<sub>S</sub>,*BList*<sub>S</sub>) |- | *BList1*<sub>S</sub> || ⊇ *cons*(*true*,*BList*<sub>S</sub>) |- | *BList1*<sub>S</sub> || ⊇ *cons*(*false*,*BList1*<sub>S</sub>) |} This system has a minimal solution, viz. ("*L*(*N*)" denoting the tree language corresponding to the nonterminal *N* in the above tree grammar):

{|

\|- | *Bool*<sub>S</sub> || = *L*(*Bool*<sub>G</sub>) || = { *false*, *true* } |- | *BList*<sub>S</sub> || = *L*(*BList*<sub>G</sub>) || = { *nil*, *cons*(*false*,*nil*), *cons*(*true*,*nil*), *cons*(*false*,*cons*(*false*,*nil*)), ... } |- | *BList1*<sub>S</sub> || = *L*(*BList1*<sub>G</sub>) || = { *nil*, *cons*(*true*,*nil*), *cons*(*true*,*cons*(*false*,*nil*)),... } |} The maximal solution of the system is trivial; it assigns the set of all terms to every variable.

## Notes {#Notes}

[^o2]: If *f* is an *n*-ary function symbol admitted in a term, then "*f*(*E*<sub>1</sub>,...,*E*<sub>*n*</sub>)" is a set expression denoting the set { *f*(*t*<sub>1</sub>,...,*t*<sub>*n*</sub>) : *t*<sub>1</sub>∈*E*<sub>1</sub> and ... and *t*<sub>*n*</sub>∈*E*<sub>*n*</sub> }, where *E*<sub>1</sub>,...,*E*<sub>*n*</sub> are set expressions in turn.
[^o3]: This is similar to describing e.g. a [rational number](wikipedia://en/19727024) as a solution to an equation *a*⋅*x* + *b* = 0, with [integer](wikipedia://en/14563) coefficients *a*, *b*.
