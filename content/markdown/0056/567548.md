# One-key MAC

::: {#o1 .subject cue=lead name="One-key MAC"}

**One-key MAC** (**OMAC**) is a family of [message authentication codes](wikipedia://en/567523) constructed from a [block cipher](wikipedia://en/4594) much like the [CBC-MAC](wikipedia://en/2840574) algorithm. It may be used to provide assurance of the authenticity and, hence, the integrity of data. Two versions are defined:

:::

- The original OMAC of February 2003, which is rarely used.[^o7] The preferred name is now "OMAC2".[^o8]
- The OMAC1 refinement,[^o8] which became an [NIST](https://en.wikipedia.org/wiki/NIST) recommendation in May 2005 under the name **CMAC**.[^o2]

OMAC is free for all uses: it is not covered by any patents.[^o3]

## History {#History}

The core of the CMAC algorithm is a variation of [CBC-MAC](wikipedia://en/2840574) that [Black](https://en.wikipedia.org/wiki/John_Black_%28cryptographer%29) and [Rogaway](https://en.wikipedia.org/wiki/Phillip_Rogaway) proposed and analyzed under the name "XCBC"[^o5] and submitted to [NIST](https://en.wikipedia.org/wiki/NIST).[^o6] The XCBC algorithm efficiently addresses the security deficiencies of CBC-MAC, but requires three keys.

Iwata and Kurosawa proposed an improvement of XCBC that requires less key material (just one key) and named the resulting algorithm *One-Key CBC-MAC* (OMAC) in their papers.[^o7] They later submitted the OMAC1 (= CMAC),[^o8] a refinement of OMAC, and additional security analysis.[^o9]

## Algorithm {#Algorithm}

*Image: CMAC - Cipher-based Message Authentication Code.pdf.*

To generate an $\ell$-bit CMAC tag (*t*) of a message (*m*) using a *b*-bit block cipher (*E*) and a secret key (*k*), one first generates two *b*-bit sub-keys (*k*<sub>1</sub> and *k*<sub>2</sub>) using the following algorithm (this is equivalent to multiplication by *x* and *x*<sup>2</sup> in a [finite field](wikipedia://en/11615) GF(2<sup>*b*</sup>)). Let ≪ denote the standard left-shift operator and ⊕ denote bit-wise [exclusive or](wikipedia://en/105979#Computer_science):

1. Calculate a temporary value *k*<sub>0</sub> = *E<sub>k</sub>*(0).
1. If msb(*k*<sub>0</sub>) = 0, then *k*<sub>1</sub> = *k*<sub>0</sub> ≪ 1, else *k*<sub>1</sub> = (*k*<sub>0</sub> ≪ 1) ⊕ *C*; where *C* is a certain constant that depends only on *b*. (Specifically, *C* is the non-leading coefficients of the lexicographically first irreducible degree-*b* binary polynomial with the minimal number of ones: 0x1B for 64-bit, 0x87 for 128-bit, and 0x425 for 256-bit blocks.)
1. If $\operatorname{msb}(k_{1}) = 0$, then $k_{2} = k_{1} \ll 1$, else $k_{2} = (k_{1} \ll 1) \oplus C$.
1. Return keys (*k*<sub>1</sub>, *k*<sub>2</sub>) for the MAC generation process.

As a small example, suppose $b = 4$, $C = 0011_{2}$, and $k_{0} = E_{k}(0) = 0101_{2}$. Then $k_{1} = 1010_{2}$ and $k_{2} = 0100 \oplus 0011 = 0111_{2}$.

The CMAC tag generation process is as follows:

1. Divide message into *b*-bit blocks $m = m_{1} \parallel ... \parallel m_{n-1} \parallel m_{n}$, where *m*<sub>1</sub>, ..., *m*<sub>*n*−1</sub> are complete blocks. (The empty message is treated as one incomplete block.)
1. If *m<sub>n</sub>* is a complete block then $m_{n}' = k_{1} \oplus m_{n}$ else $m_{n}' = k_{2} \oplus (m_{n} \parallel 10...0_{2})$.
1. Let $c_{0} = 00...0_{2}$.
1. For $i = 1, ..., n - 1$, calculate $c_{i} = E_{k}(c_{i-1} \oplus m_{i})$.
1. $$c_{n} = E_{k}(c_{n-1} \oplus m_{n}')$$
1. Output $t = \operatorname{msb}_{\ell}(c_{n})$.

The verification process is as follows:

1. Use the above algorithm to generate the tag.
1. Check that the generated tag is equal to the received tag.

:::

## Variants {#Variants}

CMAC-C1[^o14] is a variant of CMAC that provides additional [commitment and context-discovery security](wikipedia://en/567523#Security) guarantees.
