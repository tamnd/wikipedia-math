# Baby-step giant-step

::: {#o1 .subject cue=lead name="Baby-step giant-step"}

In [group theory](wikipedia://en/41890), a branch of mathematics, the **baby-step giant-step** is a [meet-in-the-middle](wikipedia://en/423418) [algorithm](wikipedia://en/775) for computing the [discrete logarithm](wikipedia://en/181334) or [order](wikipedia://en/493527) of an element in a [finite](wikipedia://en/323707) [abelian group](wikipedia://en/2974) by [Daniel Shanks](wikipedia://en/18171362).[^o2] The discrete log problem is of fundamental importance to the area of [public key cryptography](https://en.wikipedia.org/wiki/Public_key_cryptography).

:::

Many of the most commonly used cryptography systems are based on the assumption that the discrete log is extremely difficult to compute; the more difficult it is, the more security it provides a data transfer. One way to increase the difficulty of the discrete log problem is to base the cryptosystem on a larger group.

## Theory {#Theory}

The algorithm is based on a [space–time tradeoff](https://en.wikipedia.org/wiki/Space–time_tradeoff). It is a fairly simple modification of trial multiplication, the naive method of finding discrete logarithms.

Given a [cyclic group](wikipedia://en/52327) $G$ of order $n$, a [generator](wikipedia://en/99945) $\alpha$ of the group and a group element $\beta$, the problem is to find an integer $x$ such that

$$\alpha^x = \beta\,.$$

The baby-step giant-step algorithm is based on rewriting $x$:

$$x = im + j$$

$$m = \left\lceil \sqrt{n} \right\rceil$$

$$0 \leq i < m$$

$$0 \leq j < m$$

Therefore, we have:

$$\alpha^x = \beta\,$$

$$\alpha^{im + j} = \beta\,$$

$$\alpha^j = \beta\left(\alpha^{-m}\right)^i\,$$

The algorithm precomputes $\alpha^j$ for several values of $j$. Then it fixes an $m$ and tries values of $i$ in the right-hand side of the congruence above, in the manner of trial multiplication. It tests to see if the congruence is satisfied for any value of $j$, using the precomputed values of $\alpha^j$.

::: {#o5 .definition kind=definition/construction cue=heading name="The algorithm"}

## The algorithm {#The_algorithm}

**Input**: A cyclic group *G* of order *n*, having a generator *α* and an element *β*.

**Output**: A value *x* satisfying $\alpha^x = \beta$.

1. *m* ← Ceiling($\sqrt{n}$)
1. For all *j* where 0 ≤ *j* \< *m*:
   1. Compute *α*<sup>*j*</sup> and store the pair (*j*, *α*<sup>*j*</sup>) in a table. (See )
1. Compute *α*<sup>−*m*</sup>.
1. *γ* ← *β*. (set *γ* = *β*)
1. For all *i* where 0 ≤ *i* \< *m*:
   1. Check to see if γ is the second component (*α*<sup>*j*</sup>) of any pair in the table.
   1. If so, return *im* + *j*.
   1. If not, *γ* ← *γ* • *α*<sup>−*m*</sup>.

:::

## In practice {#In_practice}

The best way to speed up the baby-step giant-step algorithm is to use an efficient table lookup scheme. The best in this case is a [hash table](wikipedia://en/13833). The hashing is done on the second component, and to perform the check in step 1 of the main loop, γ is hashed and the resulting memory address checked. Since hash tables can retrieve and add elements in [$O(1)$](wikipedia://en/44578) time (constant time), this does not slow down the overall baby-step giant-step algorithm.

The space complexity of the algorithm is $O(\sqrt n)$, while the time complexity of the algorithm is $O(\sqrt n)$. This running time is better than the $O(n)$ running time of the naive brute force calculation.

The baby-step giant-step algorithm could be used by an eavesdropper to derive the private key generated in the [Diffie Hellman key exchange](wikipedia://en/7903), when the modulus is a prime number that is not too large. If the modulus is not prime, the [Pohlig–Hellman algorithm](wikipedia://en/1995624) has a smaller algorithmic complexity, and potentially solves the same problem.[^o7]

## Notes {#Notes}

- The baby-step giant-step algorithm is a generic algorithm. It works for every finite cyclic group.
- It is not necessary to know the exact order of the group *G* in advance. The algorithm still works if *n* is merely an upper bound on the group order.
- Usually the baby-step giant-step algorithm is used for groups whose order is prime. If the order of the group is composite then the [Pohlig–Hellman algorithm](wikipedia://en/1995624) is more efficient.
- The algorithm requires $O(m)$ memory. It is possible to use less memory by choosing a smaller *m* in the first step of the algorithm. Doing so increases the running time, which then is $O(n/m)$. Alternatively one can use [Pollard's rho algorithm for logarithms](wikipedia://en/1630817), which has about the same running time as the baby-step giant-step algorithm, but only a small memory requirement.
- While this algorithm is credited to Daniel Shanks, who published the 1971 paper in which it first appears, a 1994 paper by Nechaev[^o9] states that it was known to [Gelfond](wikipedia://en/4542389) in 1962.
- There exist optimized versions of the original algorithm, such as using collision-free truncated lookup tables[^o10] or negation maps and Montgomery's simultaneous modular inversion.[^o11]
