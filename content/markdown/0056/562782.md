# Vertex cover

*Image: Couverture de sommets.svg.* Example graph that has a vertex cover comprising 2 vertices (bottom), but none with fewer

::: {#o1 .subject cue=lead name="Vertex cover"}

In [graph theory](wikipedia://en/12401), a **vertex cover** (sometimes **node cover**) of a [graph](wikipedia://en/325806) is a set of [vertices](wikipedia://en/638899) that includes at least one endpoint of every [edge](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) of the graph.

:::

In [computer science](https://en.wikipedia.org/wiki/Computer_science), the problem of finding a **minimum vertex cover** is a classical [optimization problem](wikipedia://en/1126536). It is [NP-hard](https://en.wikipedia.org/wiki/NP-hard), so it cannot be solved by a [polynomial-time algorithm](https://en.wikipedia.org/wiki/Polynomial-time_algorithm) if [P ≠ NP](https://en.wikipedia.org/wiki/P_≠_NP). Moreover, it is [hard to approximate](https://en.wikipedia.org/wiki/Hard_to_approximate) – it cannot be approximated up to a factor smaller than 2 if the [unique games conjecture](wikipedia://en/3000842) is true. On the other hand, it has several simple 2-factor approximations. It is a typical example of an NP-hard optimization problem that has an [approximation algorithm](wikipedia://en/563105). Its [decision version](wikipedia://en/8336), the **vertex cover problem**, was one of [Karp's 21 NP-complete problems](wikipedia://en/2012564) and is therefore a classical [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem in [computational complexity theory](wikipedia://en/7543). Furthermore, the vertex cover problem is [fixed-parameter tractable](https://en.wikipedia.org/wiki/Fixed-parameter_tractable) and a central problem in [parameterized complexity theory](wikipedia://en/603026).

The minimum vertex cover problem can be formulated as a [half-integral](wikipedia://en/1568608), [linear program](https://en.wikipedia.org/wiki/Linear_program) whose [dual linear program](wikipedia://en/15772894) is the [maximum matching problem](https://en.wikipedia.org/wiki/Maximum_matching_problem).

Vertex cover problems have been generalized to [hypergraphs](wikipedia://en/232535), see *[Vertex cover in hypergraphs](wikipedia://en/64318108)*.

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

*Image: Vertex-cover.svg.* Examples of vertex covers

*Image: Minimum-vertex-cover.svg.* Examples of minimum vertex covers

Formally, a vertex cover $V'$ of an undirected graph $G=(V, E)$ is a subset of $V$ such that $(uv \in E) \Rightarrow (u \in V' \lor v \in V')$, that is to say it is a set of vertices $V'$ where every edge has at least one endpoint in the vertex cover $V'$. Such a set is said to *cover* the edges of $G$. The upper figure shows two examples of vertex covers, with some vertex cover $V'$ marked in red.

A *minimum vertex cover* is a vertex cover of smallest possible size. The vertex cover number $\tau$ is the size of a minimum vertex cover, i.e. $\tau = |V'|$. The lower figure shows examples of minimum vertex covers in the previous graphs.

::: {#o5 .example cue=heading name="Examples"}

### Examples {#Examples}

- The set of all vertices is a vertex cover.
- The endpoints of any [maximal matching](https://en.wikipedia.org/wiki/Maximal_matching) form a vertex cover.
- The [complete bipartite graph](wikipedia://en/525320) $K_{m,n}$ has a minimum vertex cover of size $\tau(K_{m,n})=\min\{\,m,n\,\}$.

:::

::: {#o7 .statement kind=statement/fact cue=heading name="Properties"}

### Properties {#Properties}

- A set of vertices is a vertex cover if and only if its [complement](wikipedia://en/54347) is an [independent set](wikipedia://en/524501).
- Consequently, the number of vertices of a graph is equal to its minimum vertex cover number plus the size of a maximum independent set.[^n1]

:::

:::

## Computational problem {#Computational_problem}

The **minimum vertex cover problem** is the [optimization problem](wikipedia://en/1126536) of finding a smallest vertex cover in a given graph.

INSTANCE: Graph $G$

OUTPUT: Smallest number $k$ such that $G$ has a vertex cover of size $k$.

If the problem is stated as a [decision problem](wikipedia://en/8336), it is called the **vertex cover problem**:

INSTANCE: Graph $G$ and positive integer $k$.

QUESTION: Does $G$ have a vertex cover of size at most $k$?

They are equivalent under [polynomial-time reduction](wikipedia://en/159695) by using [binary search](wikipedia://en/4266). The vertex cover problem is an [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem: it was one of [Karp's 21 NP-complete problems](wikipedia://en/2012564). It is often used in [computational complexity theory](wikipedia://en/7543) as a starting point for [NP-hardness](https://en.wikipedia.org/wiki/NP-hard) proofs.

### ILP formulation {#ILP_formulation}

Assume that every vertex has an associated cost of $c(v)\geq 0$. The (weighted) minimum vertex cover problem can be formulated as the following [integer linear program](https://en.wikipedia.org/wiki/Integer_linear_program) (ILP).[^o11]

{|

\| minimize | colspan="2" | $\textstyle\sum_{v \in V} c(v) x_v$ | | (minimize the total cost) |- | subject to | $x_u+x_v\geq 1$ | for all $\{u,v\} \in E$ | | (cover every edge of the graph), |- | | $x_v\in\{0,1\}$ | for all $v\in V$. | | (every vertex is either in the vertex cover or not) |} This ILP belongs to the more general class of ILPs for [covering problems](wikipedia://en/1045640). The [integrality gap](wikipedia://en/6368430#Approximation_and_integrality_gap) of this ILP is $2$, so its [relaxation](wikipedia://en/6368430) (allowing each variable to be in the interval from 0 to 1, rather than requiring the variables to be only 0 or 1) gives a factor-$2$ [approximation algorithm](wikipedia://en/563105) for the minimum vertex cover problem. Furthermore, the linear programming relaxation of that ILP is *half-integral*, that is, there exists an optimal solution for which each entry $x_v$ is either 0, 1/2, or 1. A 2-approximate vertex cover can be obtained from this fractional solution by selecting the subset of vertices whose variables are nonzero.

### Exact evaluation {#Exact_evaluation}

The [decision](wikipedia://en/8336) variant of the vertex cover problem is [NP-complete](https://en.wikipedia.org/wiki/NP-complete), which means it is unlikely that there is an [efficient algorithm](https://en.wikipedia.org/wiki/Efficient_algorithm) to solve it exactly for arbitrary graphs. NP-completeness can be proven by reduction from [3-satisfiability](wikipedia://en/4715) or, as Karp did, by reduction from the [clique problem](wikipedia://en/249254). Vertex cover remains NP-complete even in [cubic graphs](wikipedia://en/980508)[^o13] and even in [planar graphs](wikipedia://en/24314) of degree at most 3.[^o14]

For [bipartite graphs](wikipedia://en/244431), the equivalence between vertex cover and maximum matching described by [Kőnig's theorem](wikipedia://en/5465118) allows the bipartite vertex cover problem to be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time).

For [tree graphs](https://en.wikipedia.org/wiki/Tree_graph), an algorithm finds a minimal vertex cover in polynomial time by finding the first leaf in the tree and adding its parent to the minimal vertex cover, then deleting the leaf and parent and all associated edges and continuing repeatedly until no edges remain in the tree.

#### Fixed-parameter tractability {#Fixed-parameter_tractability}

An [exhaustive search](https://en.wikipedia.org/wiki/Brute-force_search) algorithm can solve the problem in time 2<sup>*k*</sup>*n*<sup>*O*(1)</sup>, where *k* is the size of the vertex cover. Vertex cover is therefore [fixed-parameter tractable](https://en.wikipedia.org/wiki/Fixed-parameter_tractable), and if we are only interested in small *k*, we can solve the problem in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time). One algorithmic technique that works here is called *bounded search tree algorithm*, and its idea is to repeatedly choose some vertex and recursively branch, with two cases at each step: place either the current vertex or all its neighbours into the vertex cover. The algorithm for solving vertex cover that achieves the best asymptotic dependence on the parameter runs in time $O(1.2738^k+(k\cdot n))$.[^o16] The [klam value](https://en.wikipedia.org/wiki/Klam_value) of this time bound (an estimate for the largest parameter value that could be solved in a reasonable amount of time) is approximately 190. That is, unless additional algorithmic improvements can be found, this algorithm is suitable only for instances whose vertex cover number is 190 or less. Under reasonable complexity-theoretic assumptions, namely the [exponential time hypothesis](wikipedia://en/26434552), the running time cannot be improved to 2<sup>*o*(*k*)</sup>, even when $n$ is $O(k)$.

However, for [planar graphs](wikipedia://en/24314), and more generally, for graphs excluding some fixed graph as a minor, a vertex cover of size *k* can be found in time *$2^{O(\sqrt{k})} n^{O(1)}$*, i.e., the problem is subexponential [fixed-parameter tractable](https://en.wikipedia.org/wiki/Fixed-parameter_tractable).[^o17] This algorithm is again optimal, in the sense that, under the [exponential time hypothesis](wikipedia://en/26434552), no algorithm can solve vertex cover on planar graphs in time *$2^{o(\sqrt{k})} n^{O(1)}$*.[^o18]

### Approximate evaluation {#Approximate_evaluation}

One can find a factor-2 [approximation](wikipedia://en/563105) by repeatedly taking *both* endpoints of an edge into the vertex cover, then removing them from the graph. Put otherwise, we find a [maximal matching](https://en.wikipedia.org/wiki/Maximal_matching) *M* with a greedy algorithm and construct a vertex cover *C* that consists of all endpoints of the edges in *M*. In the following figure, a maximal matching *M* is marked with red, and the vertex cover *C* is marked with blue.

*Image: Vertex-cover-from-maximal-matching.svg.*

The set *C* constructed this way is a vertex cover: suppose that an edge *e* is not covered by *C*; then *M* ∪ {*e*} is a matching and *e* ∉ *M*, which is a contradiction with the assumption that *M* is maximal. Furthermore, if *e* = {*u*, *v*} ∈ *M*, then any vertex cover – including an optimal vertex cover – must contain *u* or *v* (or both); otherwise the edge *e* is not covered. That is, an optimal cover contains at least *one* endpoint of each edge in *M*; in total, the set *C* is at most 2 times as large as the optimal vertex cover.

This simple algorithm was discovered independently by Fanica Gavril and [Mihalis Yannakakis](https://en.wikipedia.org/wiki/Mihalis_Yannakakis).[^o20]

More involved techniques show that there are approximation algorithms with a slightly better approximation factor. For example, an approximation algorithm with an approximation factor of $2 - \Theta \left( 1 / \sqrt{\log |V|} \right)$ is known.[^o21] The problem can be approximated with an approximation factor $2/(1 + \delta)$ in $\delta$ - dense graphs.[^o22]

#### Inapproximability {#Inapproximability}

No better [constant-factor approximation algorithm](https://en.wikipedia.org/wiki/Constant-factor_approximation_algorithm) than the above one is known. The minimum vertex cover problem is [APX-complete](wikipedia://en/2018925), that is, it cannot be approximated arbitrarily well unless [**P** = **NP**](https://en.wikipedia.org/wiki/P_=_NP_problem). Using techniques from the [PCP theorem](wikipedia://en/3001241), [Dinur](https://en.wikipedia.org/wiki/Irit_Dinur) and [Safra](https://en.wikipedia.org/wiki/Shmuel_Safra) proved in 2005 that minimum vertex cover cannot be approximated within a factor of 1.3606 for any sufficiently large vertex degree unless **P** = **NP**.[^o24] Later, the factor was improved to $\sqrt{2} - \epsilon$ for any $\epsilon > 0$.[^o25] Moreover, if the [unique games conjecture](wikipedia://en/3000842) is true then minimum vertex cover cannot be approximated within any constant factor better than 2.[^o26]

Although finding the minimum-size vertex cover is equivalent to finding the maximum-size independent set, as described above, the two problems are not equivalent in an approximation-preserving way: The Independent Set problem has *no* constant-factor approximation unless **P** = **NP**.

#### Pseudocode {#Pseudocode}

Approximation algorithm:[^o29]

```c
APPROXIMATION-VERTEX-COVER(G)
C = ∅
E'= G.E

while E' ≠ ∅:
    let (u, v) be an arbitrary edge of E'
    C = C ∪ {u, v}
    remove from E' every edge incident on either u or v

return C
```
