# BLS digital signature

::: {#o1 .subject cue=lead name="BLS digital signature"}

A **BLS digital signature,** also known as **Boneh–Lynn–Shacham**[^o4] (BLS), is a [cryptographic](wikipedia://en/18934432) [signature scheme](https://en.wikipedia.org/wiki/Signature_scheme) which allows a user to verify that a signer is *authentic*.

:::

The scheme uses a [bilinear pairing](wikipedia://en/1191490#Pairings_in_cryptography) $e: G_1\times G_2\to G_T$, where $G_1, G_2,$ and $G_T$ are [elliptic curve](wikipedia://en/10225) groups of prime order $q$, and a hash function $H$ from the message space into $G_1$. Signature are elements of $G_1$, public keys are elements of $G_2$, and the secret key is an integer in $[0,q-1]$. Working in an elliptic curve group provides some defense against [index calculus](https://en.wikipedia.org/wiki/Index_calculus) attacks (with the caveat that such attacks are still possible in the target group $G_T$ of the pairing), allowing shorter signatures than [FDH](wikipedia://en/2493181) signatures for a similar [level of security](https://en.wikipedia.org/wiki/Level_of_security).

Signatures produced by the BLS signature scheme are often referred to as *short signatures*, *BLS short signatures*, or simply ***BLS signatures***.[^o2] The signature scheme is [provably secure](https://en.wikipedia.org/wiki/Provably_secure) (the scheme is [existentially unforgeable](https://en.wikipedia.org/wiki/Existential_forgery) under [adaptive chosen-message attacks](https://en.wikipedia.org/wiki/Adaptive_chosen-message_attack)) in the [random oracle](wikipedia://en/451286) model assuming the intractability of the [computational Diffie–Hellman problem](https://en.wikipedia.org/wiki/Computational_Diffie–Hellman_problem) in a gap Diffie–Hellman group.[^o4]

## BLS signature scheme {#BLS_signature_scheme}

A [signature scheme](https://en.wikipedia.org/wiki/Signature_scheme) consists of three functions: *generate*, *sign*, and *verify*.[^o4]

**Key generation**

The key generation algorithm selects the private key by picking a random integer $x\in [0,q-1]$. The holder of the private key publishes the public key, $g_2^x$, where $g_2$ is a generator of $G_2$.

**Signing**

Given the private key $x$, and some message $m$, we compute the signature by hashing the bitstring $m$, as $h=H(m)$, and we output the signature $\sigma=h^x$.

**Verification**

Given a signature $\sigma$ for message $m$ and public key $g_2^x$, we verify that $e(\sigma, g_2 )=e(H(m), g_2^x)$.

::: {#o6 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

- Unique and deterministic: for a given key and message, there is only one valid signature (like RSA PKCS1 v1.5, RSA-FDH and unlike RSA-PSS, DSA, ECDSA, Schnorr and [ML-DSA](https://en.wikipedia.org/wiki/ML-DSA)).[^o7]
- Signature Aggregation: Multiple signatures generated under multiple public keys for multiple messages can be aggregated into a single signature.[^o8]
- Simple [Threshold Signatures](wikipedia://en/6866642)[^o9] and multisignatures.[^o10]

:::

## Curves {#Curves}

::: {#o13 .pointer-item cue=pointer name="BLS12-381"}

### BLS12-381 {#BLS12-381}

BLS12-381 is part of a family of elliptic curves named after Barreto, Lynn, and Scott[^o14] (a different BLS trio, except for the L). It was designed by Sean Bowe in early 2017 as the foundation for an upgrade to the [Zcash](wikipedia://en/51849458) protocol. It is both pairing-friendly, making it efficient for digital signatures, and effective for constructing [zkSnarks](https://en.wikipedia.org/wiki/ZkSNARK).[^o15] The usage of BLS12-381 curve for BLS signatures is detailed in the June 2022 [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) internet draft.[^o16]

:::

## Implementations {#Implementations}

- [Chia network](https://en.wikipedia.org/wiki/Chia_%28cryptocurrency%29) has used BLS signatures.[^o19][^o20]
- By 2021, BLS signatures were used in Proof-of-Stake [Ethereum](https://en.wikipedia.org/wiki/Ethereum)'s consensus layer to aggregate signatures from all validators. Every validator participates in attesting to the validity of a single slot (i.e. block) per 6.4 minute epoch.[^o21] The use of BLS signatures in Ethereum is considered a solution to the verification bottleneck only for the medium term, as BLS signatures are not [quantum secure](wikipedia://en/26605226). Over the longer term—say, 2025–2030—[STARK aggregation](wikipedia://en/11589052) is expected to be a drop-in replacement for BLS aggregation.[^o16][^o22]
- Skale cryptocurrency uses BLS signature algorithm.[^o23]
- drand uses the BLS12-381 curve as a threshold scheme.[^o24]

:::
