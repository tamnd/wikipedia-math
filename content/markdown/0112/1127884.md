# Hamming weight

::: {#o1 .subject cue=lead name="Hamming weight"}

The **Hamming weight** of a [string](wikipedia://en/27701) is the number of symbols that are different from the zero-symbol of the [alphabet](https://en.wikipedia.org/wiki/Alphabet) used. It is thus equivalent to the [Hamming distance](wikipedia://en/41227) from the all-zero string of the same length. For the most typical case, a given set of [bits](https://en.wikipedia.org/wiki/Bit), this is the number of bits set to 1, or the [digit sum](wikipedia://en/1598868) of the [binary representation](https://en.wikipedia.org/wiki/Binary_numeral_system) of a given number and the [*ℓ*₁ norm](wikipedia://en/408354) of a bit vector. In this binary case, it is also called the **population count**,[^o21] **popcount**, **sideways sum**,[^o20] or **bit summation**.[^o34]

:::

*Examples*

::: {#o2 .table cue=table name="Examples"}

| String | Hamming weight |
|---|---|
| **111**0**1** | 4 |
| **111**0**1**000 | 4 |
| 00000000 | 0 |
| **678**0**1234**0**567** | 10 |

## History and usage {#History_and_usage}

The Hamming weight is named after the American mathematician [Richard Hamming](wikipedia://en/99326), although he did not originate the notion.[^o28] The Hamming weight of binary numbers was already used in 1899 by [James W. L. Glaisher](https://en.wikipedia.org/wiki/James_Whitbread_Lee_Glaisher) to give a formula for [the number of odd binomial coefficients](wikipedia://en/51516730) in a single row of [Pascal's triangle](wikipedia://en/49497).[^o27] [Irving S. Reed](https://en.wikipedia.org/wiki/Irving_S._Reed) introduced a concept, equivalent to Hamming weight in the binary case, in 1954.[^o29]

Hamming weight is used in several disciplines including [information theory](wikipedia://en/14773), [coding theory](wikipedia://en/321869), and [cryptography](wikipedia://en/18934432). Examples of applications of the Hamming weight include:

- In modular [exponentiation by squaring](wikipedia://en/10237), the number of modular multiplications required for an exponent *e* is log<sub>2</sub> *e* + weight(*e*). This is the reason that the public key value *e* used in [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) is typically chosen to be a number of low Hamming weight.[^o19]
- The Hamming weight determines path lengths between nodes in [Chord distributed hash tables](https://en.wikipedia.org/wiki/Chord_%28distributed_hash_table%29).[^o22]
- [IrisCode](https://en.wikipedia.org/wiki/IrisCode) lookups in biometric databases are typically implemented by calculating the [Hamming distance](wikipedia://en/41227) to each stored record.[^o5]
- In [computer chess](https://en.wikipedia.org/wiki/Computer_chess) programs using a [bitboard](https://en.wikipedia.org/wiki/Bitboard) representation, the Hamming weight of a bitboard gives the number of pieces of a given type remaining in the game, or the number of squares of the board controlled by one player's pieces, and is therefore an important contributing term to the value of a position.[^o6]
- Hamming weight can be used to efficiently compute [find first set](https://en.wikipedia.org/wiki/Find_first_set) using the identity ffs(x) = pop(x ^ (x - 1)). This is useful on platforms such as [SPARC](https://en.wikipedia.org/wiki/SPARC) that have hardware Hamming weight instructions but no hardware find first set instruction.[^o33][^o21]
- The Hamming weight operation can be interpreted as a conversion from the [unary numeral system](wikipedia://en/32316) to [binary numbers](wikipedia://en/238686).[^o23]

## Efficient implementation {#Efficient_implementation}

The population count of a [bitstring](https://en.wikipedia.org/wiki/Bit_array) is often needed in cryptography and other applications. The [Hamming distance](wikipedia://en/41227) of two words *A* and *B* can be calculated as the Hamming weight of *A* [xor](https://en.wikipedia.org/wiki/Xor) *B*.[^o21]

The problem of how to implement it efficiently has been widely studied. A single operation for the calculation, or parallel operations on bit vectors are available on some processors. For processors lacking those features, the best solutions known are based on adding counts in a tree pattern. For example, to count the number of 1 bits in the 16-bit binary number a = 0110 1100 1011 1010, these operations can be done:

::: {#o8 .table cue=table}

| Expression | Binary |  |  |  |  |  |  |  | Decimal | Comment |
|---|---|---|---|---|---|---|---|---|---|---|
| `a` | 01 | 10 | 11 | 00 | 10 | 11 | 10 | 10 | style="text-align:left;" 27834 | The original number |
| `b0 = (a >> 0) & 01 01 01 01 01 01 01 01` | 01 | 00 | 01 | 00 | 00 | 01 | 00 | 00 | 1, 0, 1, 0, 0, 1, 0, 0 | Every other bit from a |
| `b1 = (a >> 1) & 01 01 01 01 01 01 01 01` | 00 | 01 | 01 | 00 | 01 | 01 | 01 | 01 | 0, 1, 1, 0, 1, 1, 1, 1 | The remaining bits from a |
| `c = b0 + b1` | 01 | 01 | 10 | 00 | 01 | 10 | 01 | 01 | 1, 1, 2, 0, 1, 2, 1, 1 | Count of 1s in each 2-bit slice of a |
| `d0 = (c >> 0) & 0011 0011 0011 0011` | 0001 |  | 0000 |  | 0010 |  | 0001 |  | 1, 0, 2, 1 | Every other count from c |
| `d2 = (c >> 2) & 0011 0011 0011 0011` | 0001 |  | 0010 |  | 0001 |  | 0001 |  | 1, 2, 1, 1 | The remaining counts from c |
| `e = d0 + d2` | 0010 |  | 0010 |  | 0011 |  | 0010 |  | 2, 2, 3, 2 | Count of 1s in each 4-bit slice of a |
| `f0 = (e >> 0) & 00001111 00001111` | 00000010 |  |  |  | 00000010 |  |  |  | 2, 2 | Every other count from e |
| `f4 = (e >> 4) & 00001111 00001111` | 00000010 |  |  |  | 00000011 |  |  |  | 2, 3 | The remaining counts from e |
| `g = f0 + f4` | 00000100 |  |  |  | 00000101 |  |  |  | 4, 5 | Count of 1s in each 8-bit slice of a |
| `h0 = (g >> 0) & 0000000011111111` | 0000000000000101 |  |  |  |  |  |  |  | 5 | Every other count from g |
| `h8 = (g >> 8) & 0000000011111111` | 0000000000000100 |  |  |  |  |  |  |  | 4 | The remaining counts from g |
| `i = h0 + h8` | 0000000000001001 |  |  |  |  |  |  |  | 9 | Count of 1s in entire 16-bit word |

:::

Here, the operations are as in [C programming language](https://en.wikipedia.org/wiki/C_%28programming_language%29), so X >> Y means to shift X right by Y bits, X & Y means the bitwise AND of X and Y, and + is ordinary addition. The best algorithms known for this problem are based on the concept illustrated above and are given here:[^o21]

```c
//types and constants used in the functions below
//uint64_t is an unsigned 64-bit integer variable type (defined in C99 version of C language)
const uint64_t m1  = 0x5555555555555555; //binary: 0101...
const uint64_t m2  = 0x3333333333333333; //binary: 00110011..
const uint64_t m4  = 0x0f0f0f0f0f0f0f0f; //binary:  4 zeros,  4 ones ...
const uint64_t m8  = 0x00ff00ff00ff00ff; //binary:  8 zeros,  8 ones ...
const uint64_t m16 = 0x0000ffff0000ffff; //binary: 16 zeros, 16 ones ...
const uint64_t m32 = 0x00000000ffffffff; //binary: 32 zeros, 32 ones
const uint64_t h01 = 0x0101010101010101; //the sum of 256 to the power of 0,1,2,3...

//This is a naive implementation, shown for comparison,
//and to help in understanding the better functions.
//This algorithm uses 24 arithmetic operations (shift, add, and).
int popcount64a(uint64_t x)
{
    x = (x & m1 ) + ((x >>  1) & m1 ); //put count of each  2 bits into those  2 bits 
    x = (x & m2 ) + ((x >>  2) & m2 ); //put count of each  4 bits into those  4 bits 
    x = (x & m4 ) + ((x >>  4) & m4 ); //put count of each  8 bits into those  8 bits 
    x = (x & m8 ) + ((x >>  8) & m8 ); //put count of each 16 bits into those 16 bits 
    x = (x & m16) + ((x >> 16) & m16); //put count of each 32 bits into those 32 bits 
    x = (x & m32) + ((x >> 32) & m32); //put count of each 64 bits into those 64 bits 
    return x;
}

//This uses fewer arithmetic operations than any other known  
//implementation on machines with slow multiplication.
//This algorithm uses 17 arithmetic operations.
int popcount64b(uint64_t x)
{
    x -= (x >> 1) & m1;             //put count of each 2 bits into those 2 bits
    x = (x & m2) + ((x >> 2) & m2); //put count of each 4 bits into those 4 bits 
    x = (x + (x >> 4)) & m4;        //put count of each 8 bits into those 8 bits 
    x += x >>  8;  //put count of each 16 bits into their lowest 8 bits
    x += x >> 16;  //put count of each 32 bits into their lowest 8 bits
    x += x >> 32;  //put count of each 64 bits into their lowest 8 bits
    return x & 0x7f;
}

//This uses fewer arithmetic operations than any other known  
//implementation on machines with fast multiplication.
//This algorithm uses 12 arithmetic operations, one of which is a multiply.
int popcount64c(uint64_t x)
{
    x -= (x >> 1) & m1;             //put count of each 2 bits into those 2 bits
    x = (x & m2) + ((x >> 2) & m2); //put count of each 4 bits into those 4 bits 
    x = (x + (x >> 4)) & m4;        //put count of each 8 bits into those 8 bits 
    return (x * h01) >> 56;  //returns left 8 bits of x + (x<<8) + (x<<16) + (x<<24) + ... 
}
```

The above implementations have the best worst-case behavior of any known algorithm. However, when a value is expected to have few nonzero bits, it may instead be more efficient to use algorithms that count these bits one at a time. As Wegner described in 1960,[^o24] the [bitwise AND](https://en.wikipedia.org/wiki/Bitwise_AND) of *x* with *x* − 1 differs from *x* only in zeroing out the least significant nonzero bit: subtracting 1 changes the rightmost string of 0s to 1s, and changes the rightmost 1 to a 0. If *x* originally had *n* bits that were 1, then after only *n* iterations of this operation, *x* will be reduced to zero. The following implementation is based on this principle.

```c
//This is better when most bits in x are 0
//This algorithm works the same for all data sizes.
//This algorithm uses 3 arithmetic operations and 1 comparison/branch per "1" bit in x.
int popcount64d(uint64_t x)
{
    int count;
    for (count=0; x; count++)
        x &= x - 1;
    return count;
}
```

Of interest here is the [close relationship](https://en.wikipedia.org/wiki/Find_first_set#Properties_and_relations) between Popcount, FFS and CLZ.

If greater memory usage is allowed, we can calculate the Hamming weight faster than the above methods. With unlimited memory, we could simply create a large lookup table of the Hamming weight of every 64 bit integer. If we can store a lookup table of the hamming function of every 16 bit integer, we can do the following to compute the Hamming weight of every 32 bit integer.

```c
static uint8_t wordbits[65536] = { /* bitcounts of integers 0 through 65535, inclusive */ };
//This algorithm uses 3 arithmetic operations and 2 memory reads.
int popcount32e(uint32_t x)
{
    return wordbits[x & 0xFFFF] + wordbits[x >> 16];
}
```

```c
//Optionally, the wordbits[] table could be filled using this function
int popcount32e_init(void)
{
    uint32_t i;
    uint16_t x;
    int count;
    for (i=0; i <= 0xFFFF; i++)
    {
        x = i;
        for (count=0; x; count++) // borrowed from popcount64d() above
            x &= x - 1;
        wordbits[i] = count;
    }
}
```

A recursive algorithm is given in Donovan & Kernighan[^o36]

```c
/* The weight of i can differ from the weight of i / 2
only in the least significant bit of i */
int popcount32e_init (void)
{
    int i;
    for (i = 1; sizeof wordbits / sizeof *wordbits > i; ++i)
        wordbits [i] = wordbits [i >> 1] + (1 & i);
}
```

Muła et al.[^o37] have shown that a vectorized version of popcount64b can run faster than dedicated instructions (e.g., popcnt on x64 processors).

The Harley–Seal algorithm[^o9] is one of the fastest that also only needs integer operations.[^o10]

## Minimum weight {#Minimum_weight}

In [error-correcting coding](https://en.wikipedia.org/wiki/Error-correcting_code), the minimum Hamming weight, commonly referred to as the **minimum weight** *w*<sub>min</sub> of a code is the weight of the lowest-weight non-zero code word. The weight *w* of a code word is the number of 1s in the word. For example, the word 11001010 has a weight of 4.

In a [linear block code](https://en.wikipedia.org/wiki/Linear_block_code) the minimum weight is also the [minimum Hamming distance](https://en.wikipedia.org/wiki/Minimum_Hamming_distance) (*d*<sub>min</sub>) and defines the error correction capability of the code. If *w*<sub>min</sub> = *n*, then *d*<sub>min</sub> = *n* and the code will correct up to *d*<sub>min</sub>/2 errors.[^o13]

:::

## Language support {#Language_support}

Some C compilers provide intrinsic functions that provide bit counting facilities. For example, [GCC](https://en.wikipedia.org/wiki/GNU_Compiler_Collection) (since version 3.4 in April 2004) includes a builtin function `__builtin_popcount` that will use a processor instruction if available or an efficient library implementation otherwise.[^o25] [LLVM-GCC](https://en.wikipedia.org/wiki/LLVM) has included this function since version 1.5 in June 2005.[^o26]

In the [C++ Standard Library](https://en.wikipedia.org/wiki/C++_Standard_Library), the bit-array data structure `bitset` has a `count()` method that counts the number of bits that are set. In [C++20](https://en.wikipedia.org/wiki/C++20), a new header `<bit>` was added, containing functions `std::popcount` and `std::has_single_bit`, taking arguments of unsigned integer types.

In Java, the growable bit-array data structure has a method that counts the number of bits that are set. In addition, there are and functions to count bits in primitive 32-bit and 64-bit integers, respectively. Also, the arbitrary-precision integer class also has a method that counts bits.

In [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), the `int` type has a `bit_count()` method to count the number of bits set. This functionality was introduced in Python 3.10, released in October 2021.[^o15]

In [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp), the function `logcount`, given a non-negative integer, returns the number of 1 bits. (For negative integers it returns the number of 0 bits in 2's complement notation.) In either case the integer can be a [bignum](wikipedia://en/600892).

Starting in [GHC](https://en.wikipedia.org/wiki/Glasgow_Haskell_Compiler) 7.4, the [Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29) base package has a `popCount` function available on all types that are instances of the `Bits` class (available from the `Data.Bits` module).[^o30]

[MySQL](https://en.wikipedia.org/wiki/MySQL) version of [SQL](wikipedia://en/29004) language provides `BIT_COUNT()` as a standard function.[^o31]

[Fortran 2008](https://en.wikipedia.org/wiki/Fortran_2008) has the standard, intrinsic, elemental function `popcnt` returning the number of nonzero bits within an integer (or integer array).[^o32]

Some programmable scientific pocket calculators feature special commands to calculate the number of set bits, e.g. `#B` on the [HP-16C](https://en.wikipedia.org/wiki/HP-16C).[^o34]

[FreePascal](https://en.wikipedia.org/wiki/FreePascal) implements popcnt since version 3.0.[^o38]

## Processor support {#Processor_support}

- The [IBM STRETCH](https://en.wikipedia.org/wiki/IBM_STRETCH) computer in the 1960s calculated the number of set bits as well as the [number of leading zeros](https://en.wikipedia.org/wiki/Number_of_leading_zeros) as a by-product of all logical operations.[^o21]
- [Cray](https://en.wikipedia.org/wiki/Cray) supercomputers early on featured a population count [machine instruction](https://en.wikipedia.org/wiki/Machine_instruction), rumoured to have been specifically requested by the U.S. government [National Security Agency](wikipedia://en/21939) for [cryptanalysis](wikipedia://en/5715) applications.[^o21]
- [Control Data Corporation](https://en.wikipedia.org/wiki/Control_Data_Corporation)'s (CDC) [6000](https://en.wikipedia.org/wiki/CDC_6000_series) and [Cyber 70/170](https://en.wikipedia.org/wiki/CDC_Cyber) series machines included a population count instruction; in [COMPASS](https://en.wikipedia.org/wiki/COMPASS#COMPASS_for_60-bit_machines), this instruction was coded as `CXi`.
- The 64-bit [SPARC](https://en.wikipedia.org/wiki/SPARC) version 9 architecture defines a `POPC` instruction,[^o33][^o21] but most implementations do not implement it, requiring it be emulated by the operating system.[^o39]
- [Donald Knuth](wikipedia://en/8095)'s model computer [MMIX](https://en.wikipedia.org/wiki/MMIX) that is going to replace [MIX](https://en.wikipedia.org/wiki/MIX_%28abstract_machine%29) in his book [The Art of Computer Programming](https://en.wikipedia.org/wiki/The_Art_of_Computer_Programming) has an `SADD` instruction since 1999. `SADD a,b,c` counts all bits that are 1 in b and 0 in c and writes the result to a.
- [Compaq](https://en.wikipedia.org/wiki/Compaq)'s [Alpha 21264A](https://en.wikipedia.org/wiki/Alpha_21264A), released in 1999, was the first Alpha series CPU design that had the count extension (`CIX`).
- [Analog Devices](https://en.wikipedia.org/wiki/Analog_Devices)' [Blackfin](https://en.wikipedia.org/wiki/Blackfin) processors feature the `ONES` instruction to perform a 32-bit population count.[^o35]
- [AMD](https://en.wikipedia.org/wiki/AMD)'s [Barcelona](https://en.wikipedia.org/wiki/AMD_K10) architecture introduced the advanced bit manipulation (ABM) [ISA](https://en.wikipedia.org/wiki/Instruction_set) introducing the `POPCNT` instruction as part of the [SSE4a](https://en.wikipedia.org/wiki/SSE4a) extensions in 2007.
- [Intel Core](https://en.wikipedia.org/wiki/Intel_Core) processors introduced a `POPCNT` instruction with the [SSE4.2](https://en.wikipedia.org/wiki/SSE4.2) [instruction set](https://en.wikipedia.org/wiki/Instruction_set) extension, first available in a [Nehalem](https://en.wikipedia.org/wiki/Nehalem_%28microarchitecture%29)-based [Core i7](https://en.wikipedia.org/wiki/Core_i7) processor, released in November 2008.
- The [ARM architecture](https://en.wikipedia.org/wiki/ARM_architecture) introduced the `VCNT` instruction as part of the [Advanced SIMD](https://en.wikipedia.org/wiki/ARM_Advanced_SIMD) ([NEON](https://en.wikipedia.org/wiki/NEON_%28instruction_set%29)) extensions.
- The [RISC-V](https://en.wikipedia.org/wiki/RISC-V) architecture introduced the `CPOP` instruction as part of the Bit Manipulation (B) extension.[^o40]
