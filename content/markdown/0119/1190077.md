# One-time password

::: {#o1 .subject cue=lead name="One-time password"}

*Image: Mastercard Identity Check with BCA Debit Mastercard.webp.* Mastercard Identity Check uses OTP to confirm a user's identity during online transaction ([3-D Secure](wikipedia://en/3708321))

A **one-time password** (**OTP**), also known as a **one-time PIN**, **one-time passcode**, **one-time authorization code** (**OTAC**) or **dynamic password**, is a password that is valid for only one login session or transaction, on a computer system or other digital device. OTPs avoid several shortcomings that are associated with traditional (static) password-based authentication; a number of implementations also incorporate [two-factor authentication](https://en.wikipedia.org/wiki/Two-factor_authentication) by ensuring that the one-time password requires access to *something a person has* (such as a small keyring fob device with the OTP calculator built into it, or a smartcard or specific cellphone) as well as *something a person knows* (such as a PIN).

:::

OTP generation algorithms typically make use of [pseudorandomness](wikipedia://en/23210) or [randomness](wikipedia://en/19196523) to generate a shared key or seed, and [cryptographic hash functions](wikipedia://en/439526), which can be used to derive a value but are hard to reverse and therefore difficult for an attacker to obtain the data that was used for the hash. This is necessary because otherwise, it would be easy to predict future OTPs by observing previous ones.

OTPs have been discussed as a possible replacement for, as well as an enhancer to, traditional passwords. On the downside, OTPs can be intercepted or rerouted, and hard tokens can get lost, damaged, or stolen. Many systems that use OTPs do not securely implement them, and attackers can still learn the password through [phishing attacks](https://en.wikipedia.org/wiki/Phishing_attack) to impersonate the authorized user.[^o3]

## Characteristics {#Characteristics}

The most important advantage addressed by OTPs is that, in contrast to static passwords, they are not vulnerable to [replay attacks](wikipedia://en/614094). This means that a potential intruder who manages to record an OTP that was already used to log into a service or to conduct a transaction will not be able to use it, since it will no longer be valid.[^o3] A second major advantage is that a user who uses the same (or similar) password for multiple systems, is not made vulnerable on all of them, if the password for one of these is gained by an attacker. A number of OTP systems also aim to ensure that a session cannot easily be intercepted or impersonated without knowledge of unpredictable data created during the *previous* session, thus reducing the [attack surface](https://en.wikipedia.org/wiki/Attack_surface) further.

There are also different ways to make the user aware of the next OTP to use. Some systems use special electronic [security tokens](https://en.wikipedia.org/wiki/Security_token) that the user carries and that generate OTPs and show them using a small display. Other systems consist of software that runs on the user's [mobile phone](https://en.wikipedia.org/wiki/Mobile_phone). Yet other systems generate OTPs on the server-side and send them to the user using an [out-of-band](https://en.wikipedia.org/wiki/Out-of-band_data) channel such as [SMS](https://en.wikipedia.org/wiki/SMS) messaging. Finally, in some systems, OTPs are printed on paper that the user is required to carry.

A one-time password is the only communication required in some cryptographic schemes for a user to safely send a static encryption key to a server. This lowers the possibility of interception by enabling the server to determine or unlock the static key without the user having to send it directly. An illustration of this method is the Encrypted One-Time Pad (EOTP) system, which shows how a one-time password can enable safe key transfer across an unprotected channel.[^o4]

## Generation {#Generation}

Concrete OTP algorithms vary greatly in their details. Various approaches for the generation of OTPs include:

- Based on time-synchronization between the authentication server and the client providing the password (OTPs are valid only for a short period of time)
- Using a mathematical algorithm to generate a new password based on the previous password (OTPs are effectively a chain and must be used in a predefined order).
- Using a mathematical algorithm where the new password is based on a challenge (e.g., a random number chosen by the authentication server or transaction details) and/or a counter.

::: {#o7 .pointer-item cue=pointer name="Time-synchronized one-time passwords"}

### Time-synchronized {#Time-synchronized}

A time-synchronized OTP is usually related to a piece of hardware called a [security token](https://en.wikipedia.org/wiki/Security_token) (e.g., each user is given a personal token that generates a one-time password). It might look like a small calculator or a keychain charm, with an LCD that shows a number that changes occasionally. Inside the token is an accurate clock that has been synchronized with the clock on the authentication [server](https://en.wikipedia.org/wiki/Server_%28computing%29). In these OTP systems, time is an important part of the password algorithm, since the generation of new passwords is based on the current time rather than, or in addition to, the previous password or a [secret key](https://en.wikipedia.org/wiki/Secret_key). This token may be a [proprietary](https://en.wikipedia.org/wiki/Proprietary_hardware) device, or a [mobile phone](https://en.wikipedia.org/wiki/Mobile_phone) or similar [mobile device](https://en.wikipedia.org/wiki/Mobile_device) which runs [software](https://en.wikipedia.org/wiki/Software) that is proprietary, [freeware](https://en.wikipedia.org/wiki/Freeware), or [open-source](https://en.wikipedia.org/wiki/Open-source_license). An example of a time-synchronized OTP standard is [time-based one-time password](https://en.wikipedia.org/wiki/Time-based_one-time_password) (TOTP). Some applications can be used to keep time-synchronized OTP, like [Google Authenticator](https://en.wikipedia.org/wiki/Google_Authenticator) or a [password manager](wikipedia://en/4696394).

:::

### Hash chains {#Hash_chains}

Each new OTP may be created from the past OTPs used. An example of this type of algorithm, credited to [Leslie Lamport](https://en.wikipedia.org/wiki/Leslie_Lamport), uses a [one-way function](wikipedia://en/363890) (call it $f$). This one-time password system works as follows:

1. A [seed](https://en.wikipedia.org/wiki/Random_seed) (starting value) $s$ is chosen.
1. A [hash function](https://en.wikipedia.org/wiki/Hash_function) $f(s)$ is applied repeatedly (for example, 1000 times) to the seed, giving a value of: $f(f(f(\ldots f(s) \ldots )))$. This value, which we will call $f^{1000}(s)$ is stored on the target system.
1. The user's first login uses a password $p$ derived by applying $f$ 999 times to the seed, that is, $f^{999}(s)$. The target system can authenticate that this is the correct password, because $f(p)$ is $f^{1000}(s)$, which is the value stored. The value stored is then replaced by $p$ and the user is allowed to log in.
1. The next login, must be accompanied by $f^{998}(s)$. Again, this can be validated because hashing it gives $f^{999}(s)$ which is $p$, the value stored after the previous login. Again, the new value replaces $p$ and the user is authenticated.
1. This can be repeated another 997 times, each time the password will be $f$ applied one fewer time, and is validated by checking that when hashed, it gives the value stored during the previous login. Hash functions are designed to be extremely hard to reverse, therefore an attacker would need to know the initial seed $s$ to calculate the possible passwords, while the computer system can confirm the password on any given occasion is valid by checking that, when hashed, it gives the value previously used for login. If an indefinite series of passwords is wanted, a new seed value can be chosen after the set for $s$ is exhausted.
1. Although the server's counter value is only incremented after a successful OTP authentication, the counter on the token is incremented every time a new password is requested by the user. Because of this, the counter values on the server and on the token might be out of synchronization. It is recommended to set a look-ahead parameter $x$ on the server, which defines the size of the look-ahead window. In case of an accidental password generation by the user, the server will still authenticate the client, because it can recalculate the next $x$ OTP-server values, and check them against the received password from the client.[^o9]

To get the next password in the series from the previous passwords, one needs to find a way of calculating the [inverse function](wikipedia://en/14907) $f^{-1}$. Since $f$ was chosen to be one-way, this is extremely difficult to do. If $f$ is a [cryptographic hash function](wikipedia://en/439526), which is generally the case, it is assumed to be a [computationally intractable](https://en.wikipedia.org/wiki/Computationally_intractable) task. An intruder who happens to see a one-time password may have access for one time period or login, but it becomes useless once that period expires. The [S/KEY](https://en.wikipedia.org/wiki/S/KEY) one-time password system and its derivative OTP are based on Lamport's scheme.

### Challenge–response {#Challenge–response}

The use of [challenge–response](https://en.wikipedia.org/wiki/Challenge–response) one-time passwords requires a user to provide a response to a challenge. For example, this can be done by inputting the value that the token has generated into the token itself. To avoid duplicates, an additional counter is usually involved, so if one happens to get the same challenge twice, this still results in different one-time passwords. However, the computation does not usually involve the previous one-time password; that is, usually, this or another algorithm is used, rather than using both algorithms.

## Implementations {#Implementations}

### SMS {#SMS}

A common technology used for the delivery of OTPs is [text messaging](https://en.wikipedia.org/wiki/Text_messaging). Because text messaging is a ubiquitous communication channel, being directly available in nearly all mobile handsets and, through text-to-speech conversion, to any mobile or landline telephone, text messaging has a great potential to reach all consumers with a low total cost to implement. OTP over text messaging may be encrypted using an [A5/x](wikipedia://en/294149#Security) standard, which several hacking groups report can be successfully [decrypted](wikipedia://en/5715) within minutes or seconds.[^o14][^o15][^o16][^o17] Additionally, security flaws in the [SS7](https://en.wikipedia.org/wiki/Signalling_System_No._7) routing protocol can and have been used to redirect the associated text messages to attackers; in 2017, several [O2](https://en.wikipedia.org/wiki/Telefónica_Germany) customers in Germany were breached in this manner in order to gain access to their [mobile banking](https://en.wikipedia.org/wiki/Mobile_banking) accounts. In July 2016, the U.S. [NIST](https://en.wikipedia.org/wiki/NIST) issued a draft of a special publication with guidance on authentication practices, which discourages the use of SMS as a method of implementing out-of-band two-factor authentication, due to the ability for SMS to be [intercepted](wikipedia://en/144676) at scale.[^o18][^o19][^o26] Text messages are also vulnerable to [SIM swap scams](https://en.wikipedia.org/wiki/SIM_swap_scam)—in which an attacker fraudulently transfers a victim's phone number to their own [SIM card](https://en.wikipedia.org/wiki/SIM_card), which can then be used to gain access to messages being sent to it.[^o20][^o21]

### Hardware tokens {#Hardware_tokens}

*Image: RSA-SecurID-Tokens.jpg.* RSA SecurID [security tokens](https://en.wikipedia.org/wiki/Security_token).

[RSA Security](wikipedia://en/301240)'s [SecurID](https://en.wikipedia.org/wiki/SecurID) is one example of a time-synchronization type of token, along with [HID Global](https://en.wikipedia.org/wiki/HID_Global)'s solutions. Like all tokens, these may be lost, damaged, or stolen; additionally, there is an inconvenience as batteries die, especially for tokens without a recharging facility or with a non-replaceable battery. A variant of the proprietary token was proposed by RSA in 2006 and was described as "ubiquitous authentication", in which RSA would partner with manufacturers to add physical [SecurID](https://en.wikipedia.org/wiki/SecurID) chips to devices such as mobile phones.

Recently, it has become possible to take the electronic components associated with regular keyfob OTP tokens and embed them in a credit card form factor. However, the thinness of the cards, at 0.79mm to 0.84mm thick, prevents standard components or batteries from being used. Special [polymer-based batteries](https://en.wikipedia.org/wiki/Lithium-ion_polymer_battery) must be used which have a much lower battery life than [coin (button) cells](https://en.wikipedia.org/wiki/Coin_cell). Semiconductor components must not only be very flat but must minimise the power used in standby and when operating.

[Yubico](https://en.wikipedia.org/wiki/Yubico) offers a small USB token with an embedded chip that creates an OTP when a key is pressed and simulates a keyboard to facilitate easily entering a long password.[^o23] Since it is a USB device it avoids the inconvenience of battery replacement.

A new version of this technology has been developed that embeds a keypad into a [payment card](https://en.wikipedia.org/wiki/Payment_card) of standard size and thickness. The card has an embedded keypad, display, microprocessor and proximity chip.

### Soft tokens {#Soft_tokens}

*Image: Aegis Authenticator 3.2 TOTP screenshot.png.* Example of [soft token](https://en.wikipedia.org/wiki/Software_token).

On smartphones, one-time passwords can also be delivered directly through [mobile apps](https://en.wikipedia.org/wiki/Mobile_app), including dedicated authentication apps such as [Authy](https://en.wikipedia.org/wiki/Authy) and [Google Authenticator](https://en.wikipedia.org/wiki/Google_Authenticator), or within a service's existing app, such as in the case of [Steam](https://en.wikipedia.org/wiki/Steam_%28service%29). These systems do not share the same security vulnerabilities as SMS, and do not necessarily require a connection to a mobile network to use.[^o25][^o26][^o27]

### Hard copies {#Hard_copies}

*Image: Internet banking code card 20180728.jpg.* Paper-based OTP.

In some countries' online banking, the bank sends to the user a numbered list of OTPs that is printed on paper. Other banks send plastic cards with actual OTPs obscured by a layer that the user has to scratch off to reveal a numbered OTP. For every online transaction, the user is required to enter a specific OTP from that list. Some systems ask for the numbered OTPs sequentially, others pseudorandomly choose an OTP to be entered.

:::

## Security {#Security}

When correctly implemented, OTPs are no longer useful to an attacker within a short time of their initial use. This differs from passwords, which may remain useful to attackers years after the fact.

As with passwords, OTPs are vulnerable to [social engineering](https://en.wikipedia.org/wiki/Social_engineering_%28security%29) attacks in which [phishers](https://en.wikipedia.org/wiki/Phisher) steal OTPs by tricking customers into providing them with their OTPs. Also like passwords, OTPs can be vulnerable to [man-in-the-middle attacks](wikipedia://en/144676), making it important to communicate them via a secure channel, for example [Transport Layer Security](wikipedia://en/187813).

The fact that both passwords and OTP are vulnerable to similar kinds of attacks was a key motivation for [Universal 2nd Factor](https://en.wikipedia.org/wiki/Universal_2nd_Factor), which is designed to be more resistant to phishing attacks.

OTPs which don't involve a time-synchronization or challenge–response component will necessarily have a longer window of vulnerability if compromised before their use. In late 2005 customers of a Swedish bank were tricked into giving up their pre-supplied one-time passwords.[^o30] In 2006 this type of attack was used on customers of a US bank.[^o31]

## Standardization {#Standardization}

Many OTP technologies are patented. This makes standardization in this area more difficult, as each company tries to push its own technology. Standards do, however, exist – for example, RFC 1760 ([S/KEY](https://en.wikipedia.org/wiki/S/KEY)), RFC 2289 (OTP), RFC 4226 ([HOTP](https://en.wikipedia.org/wiki/HOTP)) and RFC 6238 ([TOTP](https://en.wikipedia.org/wiki/Time-based_One-time_Password_Algorithm)).

## Use {#Use}

### Mobile phone {#Mobile_phone}

A [mobile phone](https://en.wikipedia.org/wiki/Mobile_phone) itself can be a hand-held [authentication token](https://en.wikipedia.org/wiki/Authentication_token).[^o36] Mobile text messaging is one of the ways of receiving an OTAC through a mobile phone. In this way, a service provider sends a text message that includes an OTAC enciphered by [a digital certificate](https://en.wikipedia.org/wiki/Digital_certificate) to a user for authentication. According to a report, mobile text messaging provides high security when it uses [public key infrastructure (PKI)](wikipedia://en/194112) to provide bidirectional authentication and non-repudiation, in accordance with theoretical analysis.[^o37]

[SMS](https://en.wikipedia.org/wiki/SMS) as a method of receiving OTACs is broadly used in our daily lives for purposes such as banking, credit/debit cards, and security.[^o38][^o39][^o40]

### Telephone {#Telephone}

There are two methods of using a [telephone](https://en.wikipedia.org/wiki/Telephone) to verify a user's authentication.

With the first method, a service provider shows an OTAC on the computer or smartphone screen and then makes an automatic telephone call to a number that has already been authenticated. Then the user enters the OTAC that appears on their screen into the telephone keypad.[^o42]

With the second method, which is used to authenticate and activate [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows), the user call a number that is provided by the service provider and enters the OTAC that the phone system gives the user.[^o43]

### Computer {#Computer}

In the field of [computer technology](https://en.wikipedia.org/wiki/Computer_technology), it is known that using one-time authorization code (OTAC) through [email](https://en.wikipedia.org/wiki/Email), in a broad sense, and using one-time authorization code (OTAC) through [web-application](https://en.wikipedia.org/wiki/Web-application), in a professional sense.

- An [email](https://en.wikipedia.org/wiki/Email) is one of the common ways of using OTACs. There are two main methods used. With the first method, a service provider sends a personalised one time [URL](https://en.wikipedia.org/wiki/URL) to an authenticated email address e.g. @ucl.ac.uk; when the user clicks the URL, the server authenticates the user.[^o45] With the second method, a service provider sends a personalised OTAC (e.g. an enciphered token) to an authenticated email address; when the user types the OTAC into the website, the server authenticates the user.
- A [web application](https://en.wikipedia.org/wiki/Web_application) can generate a unique [personal identification number](https://en.wikipedia.org/wiki/Personal_identification_number) (PIN) that the user can input into the desktop client, the desktop client, in turn, uses that code to authenticate itself to the [web application](https://en.wikipedia.org/wiki/Web_application). This form of authentication is particularly useful in web applications that do not have an internal username/password store but instead use [SAML](https://en.wikipedia.org/wiki/Security_Assertion_Markup_Language) for authentication. Since [SAML](https://en.wikipedia.org/wiki/SAML) only works within the browser, a desktop-based [web application](https://en.wikipedia.org/wiki/Web_application) client cannot successfully authenticate using [SAML](https://en.wikipedia.org/wiki/SAML). Instead, the client application can use the one-time authorization code (OTAC) to authenticate itself to the [web application](https://en.wikipedia.org/wiki/Web_application). In addition, it is possible to use the [OAuth](https://en.wikipedia.org/wiki/OAuth) authorization framework when a third-party application needs to obtain limited access to an HTTP service.[^o46]

### Post {#Post}

It is possible to send OTACs to a user via post or [registered mail](https://en.wikipedia.org/wiki/Registered_mail). When a user requests an OTAC, the service provider sends it via post or registered mail and then the user can use it for authentication. For example, in the UK, some banks send their OTAC for Internet banking authorization via post or [registered mail](https://en.wikipedia.org/wiki/Registered_mail).[^o48]

:::

## Expansion {#Expansion}

[Quantum cryptography](wikipedia://en/28676005), which is based on the [uncertainty principle](wikipedia://en/31883) is one of the ideal methods to produce an OTAC.[^o50]

Moreover, it has been discussed and used not only using an enciphered code for authentication but also using graphical one time PIN authentication[^o51] such as [QR code](https://en.wikipedia.org/wiki/QR_code) which provides decentralized access control technique with anonymous authentication.[^o52][^o53]
