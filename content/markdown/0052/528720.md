# Tiny Encryption Algorithm

the Tiny Encryption Algorithm

::: {#o4 .subject cue=lead name="Tiny Encryption Algorithm"}

In [cryptography](wikipedia://en/18934432), the **Tiny Encryption Algorithm** (**TEA**) is a [block cipher](wikipedia://en/4594) notable for its simplicity of description and [implementation](https://en.wikipedia.org/wiki/Implementation), typically a few lines of code. It was designed by [David Wheeler](wikipedia://en/532495) and [Roger Needham](https://en.wikipedia.org/wiki/Roger_Needham) of the [Cambridge Computer Laboratory](https://en.wikipedia.org/wiki/Cambridge_University_Computer_Laboratory); it was first presented at the [Fast Software Encryption](https://en.wikipedia.org/wiki/Fast_Software_Encryption) workshop in [Leuven](https://en.wikipedia.org/wiki/Leuven) in 1994, and first published in the proceedings of that workshop.[^o5]

:::

The cipher is not subject to any [patents](https://en.wikipedia.org/wiki/Patent).

::: {#o7 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

TEA operates on two 32-bit [unsigned integers](https://en.wikipedia.org/wiki/Unsigned_integers) (could be derived from a 64-bit data [block](wikipedia://en/294065)) and uses a 128-bit [key](wikipedia://en/53039). It has a [Feistel structure](https://en.wikipedia.org/wiki/Feistel_network) with a suggested 64 rounds, typically implemented in pairs termed *cycles*. It has an extremely simple [key schedule](wikipedia://en/609603), mixing all of the key material in exactly the same way for each cycle. Different multiples of a [magic constant](https://en.wikipedia.org/wiki/Magic_number_%28programming%29) are used to prevent simple attacks based on the [symmetry](wikipedia://en/53741) of the rounds. The magic constant, 2654435769 or 0x9E3779B9 is chosen to be $\lfloor2^{32}\rfloor$, where is the [golden ratio](wikipedia://en/12386) (as a [nothing-up-my-sleeve number](wikipedia://en/1249296)).[^o5]

TEA has a few weaknesses. Most notably, it suffers from equivalent keys—each key is equivalent to three others, which means that the effective [key size](wikipedia://en/5749) is only 126 [bits](https://en.wikipedia.org/wiki/Bit).[^o8] As a result, TEA is especially bad as a [cryptographic hash function](wikipedia://en/439526). This weakness led to a method for [hacking](https://en.wikipedia.org/wiki/Hacker_%28hobbyist%29) [Microsoft](https://en.wikipedia.org/wiki/Microsoft)'s [Xbox](https://en.wikipedia.org/wiki/Xbox_%28console%29) [game console](https://en.wikipedia.org/wiki/Game_console), where the cipher was used as a hash function.[^o9] TEA is also susceptible to a [related-key attack](wikipedia://en/1516144) which requires 2<sup>23</sup> [chosen plaintexts](https://en.wikipedia.org/wiki/Chosen_plaintext) under a related-key pair, with 2<sup>32</sup> time complexity.[^o10] Because of these weaknesses, the [XTEA](wikipedia://en/530334) cipher was designed.

:::

## Versions {#Versions}

The first published version of TEA was supplemented by a second version that incorporated extensions to make it more secure. *Block TEA* (which was specified along with [XTEA](wikipedia://en/530334)) operates on arbitrary-size blocks in place of the 64-bit blocks of the original.

A third version ([XXTEA](wikipedia://en/10919454)), published in 1998, described further improvements for enhancing the security of the Block TEA algorithm.

## Reference code {#Reference_code}

Following is an adaptation of the reference encryption and decryption routines in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), released into the public domain by David Wheeler and Roger Needham:[^o5]

```C
#include <stdint.h>

void encrypt (uint32_t v[2], const uint32_t k[4]) {
    uint32_t v0=v[0], v1=v[1], sum=0, i;           /* set up */
    uint32_t delta=0x9E3779B9;                     /* a key schedule constant */
    uint32_t k0=k[0], k1=k[1], k2=k[2], k3=k[3];   /* cache key */
    for (i=0; i<32; i++) {                         /* basic cycle start */
        sum += delta;
        v0 += ((v1<<4) + k0) ^ (v1 + sum) ^ ((v1>>5) + k1);
        v1 += ((v0<<4) + k2) ^ (v0 + sum) ^ ((v0>>5) + k3);
    }                                              /* end cycle */
    v[0]=v0; v[1]=v1;
}

void decrypt (uint32_t v[2], const uint32_t k[4]) {
    uint32_t v0=v[0], v1=v[1], sum=0xC6EF3720, i;  /* set up; sum is (delta << 5) & 0xFFFFFFFF */
    uint32_t delta=0x9E3779B9;                     /* a key schedule constant */
    uint32_t k0=k[0], k1=k[1], k2=k[2], k3=k[3];   /* cache key */
    for (i=0; i<32; i++) {                         /* basic cycle start */
        v1 -= ((v0<<4) + k2) ^ (v0 + sum) ^ ((v0>>5) + k3);
        v0 -= ((v1<<4) + k0) ^ (v1 + sum) ^ ((v1>>5) + k1);
        sum -= delta;
    }                                              /* end cycle */
    v[0]=v0; v[1]=v1;
}
```

Note that the reference implementation acts on multi-byte numeric values. The original paper does not specify how to derive the numbers it acts on from binary or other content.
