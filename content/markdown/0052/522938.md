# Ciphertext-only attack

::: {#o1 .subject cue=lead name="Ciphertext-only attack"}

In [cryptography](wikipedia://en/18934432), a **ciphertext-only attack** (**COA**) or **known ciphertext attack** is an [attack model](wikipedia://en/3201589) for [cryptanalysis](wikipedia://en/5715) where the attacker is assumed to have access only to a set of [ciphertexts](wikipedia://en/175560). While the attacker has no channel providing access to the plaintext prior to encryption, in all practical ciphertext-only attacks, the attacker still has some knowledge of the plaintext. For instance, the attacker might know the language in which the plaintext is written or the expected statistical distribution of characters in the plaintext. Standard protocol data and messages are commonly part of the plaintext in many deployed systems, and can usually be guessed or known efficiently as part of a ciphertext-only attack on these systems.

:::

## Attack {#Attack}

The attack is completely successful if the corresponding [plaintexts](wikipedia://en/157935) can be deduced, or even better, the [key](wikipedia://en/53039). The ability to obtain any information at all about the underlying plaintext beyond what was pre-known to the attacker is still considered a success. For example, if an adversary is sending ciphertext continuously to maintain [traffic-flow security](https://en.wikipedia.org/wiki/Traffic-flow_security), it would be very useful to be able to distinguish real messages from nulls. Even making an informed guess of the existence of real messages would facilitate [traffic analysis](https://en.wikipedia.org/wiki/Traffic_analysis).

In the [history of cryptography](wikipedia://en/520066), early ciphers, implemented using pen-and-paper, were routinely broken using ciphertexts alone. Cryptographers developed statistical techniques for attacking ciphertext, such as [frequency analysis](https://en.wikipedia.org/wiki/Frequency_analysis_%28cryptanalysis%29). Mechanical encryption devices such as [Enigma](https://en.wikipedia.org/wiki/Enigma_%28machine%29) made these attacks much more difficult (although, historically, Polish cryptographers were able to mount a successful ciphertext-only [cryptanalysis of the Enigma](wikipedia://en/872175) by exploiting an insecure protocol for indicating the message settings). More advanced ciphertext-only attacks on the Enigma were mounted in [Bletchley Park](wikipedia://en/4037) during [World War II](https://en.wikipedia.org/wiki/World_War_II), by intelligently guessing plaintexts corresponding to intercepted ciphertexts.

## Modern {#Modern}

Every modern [cipher](wikipedia://en/5244) attempts to provide protection against ciphertext-only attacks. The vetting process for a new cipher design standard usually takes many years and includes exhaustive testing of large quantities of ciphertext for any statistical departure from random noise. *See:* [Advanced Encryption Standard process](wikipedia://en/99431). Also, the field of [steganography](wikipedia://en/28733) evolved, in part, to develop methods like [mimic functions](https://en.wikipedia.org/wiki/Mimic_function) that allow one piece of data to adopt the statistical profile of another. Nonetheless, poor cipher usage or reliance on home-grown proprietary algorithms that have not been subject to thorough scrutiny has resulted in many computer-age encryption systems that are still subject to ciphertext-only attack. ### Examples {#Examples}

- Early versions of [Microsoft](https://en.wikipedia.org/wiki/Microsoft)'s [PPTP](https://en.wikipedia.org/wiki/Point-to-point_tunneling_protocol) [virtual private network](wikipedia://en/147130) software used the same [RC4](wikipedia://en/25831) key for the sender and the receiver (later versions had other problems). In any case where a stream cipher like RC4 is used twice with the same key, it is open to ciphertext-only attack. *See:* [stream cipher attack](https://en.wikipedia.org/wiki/Stream_cipher_attack)
- [Wired Equivalent Privacy](wikipedia://en/422014) (WEP), the first security protocol for [Wi-Fi](https://en.wikipedia.org/wiki/Wi-Fi), proved vulnerable to several attacks, most of them ciphertext-only.
- GSM's [A5/1](wikipedia://en/294149) and [A5/2](wikipedia://en/543816)
- Some modern cipher designs have later been shown to be vulnerable to ciphertext-only attacks. For example, [Akelarre](wikipedia://en/1488264).
- A cipher whose key space is too small is subject to [brute force attack](https://en.wikipedia.org/wiki/Brute_force_attack) with access to nothing but ciphertext by simply trying all possible keys. All that is needed is some way to distinguish valid plaintext from random noise, which is easily done for natural languages when the ciphertext is longer than the [unicity distance](wikipedia://en/71630). One example is [DES](wikipedia://en/7978), which only has 56-bit keys. All too common current examples are commercial security products that derive keys for otherwise impregnable ciphers like [AES](wikipedia://en/1260) from a user-selected [password](wikipedia://en/24304). Since users rarely employ passwords with anything close to the [entropy](https://en.wikipedia.org/wiki/Information_entropy) of the cipher's key space, such systems are often quite easy to break in practice using only ciphertext. The 40-bit [CSS](wikipedia://en/18935238) cipher used to encrypt [DVD](https://en.wikipedia.org/wiki/DVD) video discs can always be broken with this method, as all that is needed is to look for [MPEG-2](https://en.wikipedia.org/wiki/MPEG-2) video data.

:::
