# Blinding (cryptography)

::: {#o1 .subject cue=lead name="Blinding"}

In [cryptography](wikipedia://en/18934432), **blinding** first became known in the context of [blind signatures](wikipedia://en/428273), where the message author *blinds* the message with a random *blinding factor*, the signer then signs it and the message author "*unblinds"* it*;* signer and message author are different parties.

:::

Since the late 1990s, **blinding** mostly refers to countermeasures against [side-channel attacks](https://en.wikipedia.org/wiki/Side-channel_attacks) on encryption devices,[^o2] where the random *blinding* and the "*unblinding"* happen on the encryption devices. The techniques used for blinding signatures were adapted to prevent attackers from knowing the input to the [modular exponentiation](wikipedia://en/903032) function for [Diffie-Hellman](https://en.wikipedia.org/wiki/Diffie-Hellman) or [RSA](wikipedia://en/25385).

Blinding must be applied with care, for example [Rabin–Williams signatures](https://en.wikipedia.org/wiki/Rabin_signature). If blinding is applied to the formatted message but the random value does not honor Jacobi requirements on *p* and *q*, then it could lead to private key recovery. A demonstration of the recovery can be seen in [CVE](https://en.wikipedia.org/wiki/Common_Vulnerabilities_and_Exposures)-2015-2141[^o3] discovered by Evgeny Sidorov.

Side-channel attacks allow an adversary to recover information about the input to a cryptographic operation within an [asymmetric encryption scheme](https://en.wikipedia.org/wiki/Asymmetric_key_encryption_algorithm), by measuring something other than the algorithm's result, e.g., power consumption, computation time, or radio-frequency emanations by a device. Typically these attacks depend on the attacker knowing the characteristics of the algorithm, as well as (some) inputs. In this setting, blinding serves to alter the algorithm's input into some unpredictable state. Depending on the characteristics of the blinding function, this can prevent some or all leakage of useful information. Note that security depends also on the resistance of the blinding functions themselves to side-channel attacks.

## Examples {#Examples}

- In [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) blinding involves computing the blinding operation *E*(*x*) = *(xr)<sup>e</sup>* mod *N*, where *r* is a random integer between 1 and *N* and [relatively prime](https://en.wikipedia.org/wiki/Relatively_prime) to *N* (i.e. gcd(*r*, *N*) = 1), *x* is the [plaintext](wikipedia://en/157935), *e* is the public RSA exponent and *N* is the RSA modulus. As usual, the decryption function *f*(*z*) = *z<sup>d</sup>* mod *N* is applied thus giving *f*(*E*(*x*)) = *(xr)<sup>ed</sup>* mod *N* = *xr* mod *N*. Finally it is unblinded using the function *D*(*z*) = *zr*<sup>−1</sup> mod *N*. Multiplying *xr* mod *N* by *r<sup>−1</sup>* mod *N* yields *x*, as desired. When decrypting in this manner, an adversary who is able to measure time taken by this operation would not be able to make use of this information (by applying timing attacks RSA is known to be vulnerable to) as they does not know the constant *r* and hence has no knowledge of the real input fed to the RSA primitives.
- [Blinding in GPG 1.x](http://git.gnupg.org/cgi-bin/gitweb.cgi?p=gnupg.git;a=commit;h=93a96e3c0c33370248f6570d8285c4e811d305d4)

:::
