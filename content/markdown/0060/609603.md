# Key schedule

*Image: DES key schedule.svg.* The key schedule of DES ("\<\<\<" denotes a left rotation), showing the calculation of each round key ("Subkey").

::: {#o1 .subject cue=lead name="Key schedule"}

In [cryptography](wikipedia://en/18934432), the so-called [product ciphers](wikipedia://en/598557) are a certain kind of cipher, where the (de-)ciphering of data is typically done as an iteration of *[rounds](wikipedia://en/73297602)*. The setup for each round is generally the same, except for round-specific fixed values called a [round constant](https://en.wikipedia.org/wiki/Round_constant), and round-specific data derived from the [cipher key](wikipedia://en/53039) called a **round key**. A **key schedule** is an algorithm that calculates all the round keys from the key.

:::

## Some types of key schedules {#Some_types_of_key_schedules}

- Some ciphers have simple key schedules. For example, the block cipher [TEA](wikipedia://en/528720) splits the 128-bit key into four 32-bit pieces and uses them repeatedly in successive rounds.
- [DES](wikipedia://en/7978) has a key schedule in which the 56-bit key is divided into two 28-bit halves; each half is thereafter treated separately. In successive rounds, both halves are rotated left by one or two bits (specified for each round), and then 48 round key bits are selected by [Permuted Choice 2](wikipedia://en/876721#Permuted_choice_2_.28PC-2.29) (PC-2) – 24 bits from the left half and 24 from the right. The rotations have the effect that a different set of bits is used in each round key; each bit is used in approximately 14 out of the 16 round keys.
- To avoid simple relationships between the cipher key and the round keys, in order to resist such forms of [cryptanalysis](wikipedia://en/5715) as [related-key attacks](wikipedia://en/1516144) and [slide attacks](wikipedia://en/1821327), many modern ciphers use more elaborate key schedules to generate an "expanded key" from which round keys are drawn. Some ciphers, such as [Rijndael (AES)](https://en.wikipedia.org/wiki/Rijndael_key_schedule) and [Blowfish](wikipedia://en/3940), use the same operations as those used in the data path of the cipher algorithm for their key expansion, sometimes initialized with some "[nothing-up-my-sleeve numbers](wikipedia://en/1249296)". Other ciphers, such as [RC5](wikipedia://en/102600), expand keys with functions that are somewhat or completely different from the encryption functions.

## Notes {#Notes}

[Knudsen](https://en.wikipedia.org/wiki/Lars_Ramkilde_Knudsen) and Mathiassen (2004) give some experimental evidence that indicate that the key schedule plays a part in providing strength against [linear](wikipedia://en/59469) and [differential cryptanalysis](wikipedia://en/8536). For toy [Feistel ciphers](wikipedia://en/352709), it was observed that those with complex and well-designed key schedules can reach a uniform distribution for the probabilities of [differentials](wikipedia://en/8536) and [linear hulls](wikipedia://en/59469) faster than those with poorly designed key schedules.
