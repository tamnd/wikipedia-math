# Sponge function

::: {#o1 .subject cue=lead name="Sponge function"}

*Image: SpongeConstruction.svg.* The sponge construction for hash functions. *P<sub>i</sub>* are blocks of the input string, *Z<sub>i</sub>* are hashed output blocks.

In [cryptography](wikipedia://en/18934432), a **sponge function** or **sponge construction** is any of a class of [algorithms](wikipedia://en/775) with finite [internal state](https://en.wikipedia.org/wiki/State_%28computer_science%29) that take an input [bit stream](https://en.wikipedia.org/wiki/Bit_stream) of any length and produce an output bit stream of any desired length. Sponge functions have both theoretical and practical uses. They can be used to model or implement many [cryptographic primitives](wikipedia://en/4928985), including [cryptographic hashes](https://en.wikipedia.org/wiki/Cryptographic_hash), [message authentication codes](https://en.wikipedia.org/wiki/Message_authentication_codes), [mask generation functions](wikipedia://en/53230626), [stream ciphers](wikipedia://en/49007), [pseudo-random number generators](https://en.wikipedia.org/wiki/Pseudo-random_number_generator), and [authenticated encryption](wikipedia://en/2244296).[^o2]

:::

::: {#o4 .definition kind=definition/construction cue=heading name="Construction"}

## Construction {#Construction}

A sponge function is built from three components:[^o5]

- a state memory, *S*, containing *b* bits,
- a function $f: \{0,1\}^b \rightarrow \{0,1\}^b$
- a padding function *P*

*S* is divided into two sections: one of size *r* (the bitrate) and the remaining part of size *c* (the capacity). These sections are denoted *R* and *C* respectively.

*f* produces a [pseudorandom permutation](wikipedia://en/4681949) of the $2^b$ states from *S*.

*P* appends enough bits to the input string so that the length of the padded input is a whole multiple of the bitrate, *r*. This means the input is segmented into blocks of *r* bits.

### Operation {#Operation}

The sponge function "absorbs" (in the [sponge](https://en.wikipedia.org/wiki/Sponge_%28material%29) metaphor) all blocks of a padded input string as follows:

- *S* is initialized to zero
- for each *r*-bit block *B* of *P*(string)
  - *R* is replaced with *R* XOR *B* (using bitwise [XOR](wikipedia://en/105979))
  - *S* is replaced by *f*(*S*)

The sponge function output is now ready to be produced ("squeezed out") as follows:

- repeat until output is full
  - output the *R* portion of *S*
  - *S* is replaced by *f*(*S*)

If less than *r* bits remain to be output, then *R* will be truncated (only part of *R* will be output).

Another metaphor describes the state memory as an "[entropy pool](https://en.wikipedia.org/wiki/Entropy_pool)", with input "poured into" the pool, and the transformation function referred to as "stirring the entropy pool".[^o7]

Note that input bits are never XORed into the *C* portion of the state memory, nor are any bits of *C* ever output directly. The extent to which *C* is altered by the input depends entirely on the transformation function *f.* In hash applications, resistance to [collision](wikipedia://en/969624) or [preimage attacks](wikipedia://en/969477) depends on *C*, and its size (the "capacity" *c*) is typically twice the desired resistance level.

### Duplex construction {#Duplex_construction}

It is also possible to absorb and squeeze in an alternating fashion.[^o2] This operation is called the duplex construction or duplexing. It can be the basis of a single pass authenticated encryption system. This have also been used as an efficient variant of the [Fiat-Shamir transformation](https://en.wikipedia.org/wiki/Fiat–Shamir_heuristic) for some protocols.[^o9]

- The state *S* is initialized to zero
- for each *r*-bit block *B* of the input
  - *R* is XORed with *B*
  - *S* is replaced by *f*(*S*)
  - *R* is now an output block of size *r* bits.

### Overwrite mode {#Overwrite_mode}

It is possible to omit the XOR operations during absorption, while still maintaining the chosen [security level](wikipedia://en/52729212).[^o2] In this mode, in the absorbing phase, the next block of the input overwrites the *R* part of the state. This allows keeping a smaller state between the steps. Since the *R* part will be overwritten anyway, it can be discarded in advance, only the *C* part must be kept.

## Applications {#Applications}

Sponge functions have both theoretical and practical uses. In theoretical cryptanalysis, a **random sponge function** is a sponge construction where *f* is a random permutation or transformation, as appropriate. Random sponge functions capture more of the practical limitations of cryptographic primitives than does the widely used [random oracle](wikipedia://en/451286) model, in particular the finite internal state.[^o13]

The sponge construction can also be used to build practical cryptographic primitives. For example, the [Keccak](https://en.wikipedia.org/wiki/Keccak) cryptographic sponge with a 1600-bit state has been selected by [NIST](https://en.wikipedia.org/wiki/NIST) as the winner in the [SHA-3 competition](https://en.wikipedia.org/wiki/SHA-3_competition). The strength of Keccak derives from the intricate, multi-round permutation *f* that its authors developed.[^o14] The [RC4](wikipedia://en/25831)-redesign called [Spritz](https://en.wikipedia.org/wiki/Spritz_%28cipher%29) refers to the sponge-construct to define the algorithm.

For other examples, a sponge function can be used to build [authenticated encryption](wikipedia://en/2244296) with associated data (AEAD),[^o7] as well as [password hashing](https://en.wikipedia.org/wiki/Password_hashing) schemes.[^o15]
