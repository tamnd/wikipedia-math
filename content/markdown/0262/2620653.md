# Trivium (cipher)

*Image: Trivium (cipher).png.* Structure of Trivium

::: {#o1 .subject cue=lead name="Trivium"}

**Trivium** is a synchronous [stream cipher](wikipedia://en/49007) designed to provide a flexible trade-off between speed and [gate count](https://en.wikipedia.org/wiki/Gate_count) in hardware, and reasonably efficient software implementation.

:::

Trivium was submitted to the Profile II (hardware) of the [eSTREAM](wikipedia://en/2287686) competition by its authors, Christophe De Cannière and [Bart Preneel](wikipedia://en/1520490), and has been selected as part of the portfolio for low area hardware ciphers (Profile 2) by the eSTREAM project. It is not patented and has been specified as an International Standard under ISO/IEC 29192-3.[^o2]

It generates up to 2<sup>64</sup> [bits](https://en.wikipedia.org/wiki/Bit) of output from an 80-bit [key](https://en.wikipedia.org/wiki/Key_length) and an 80-bit [IV](wikipedia://en/105971). It is the simplest eSTREAM entrant; while it shows remarkable resistance to cryptanalysis for its simplicity and performance, recent attacks leave the security margin looking rather slim.

## Description {#Description}

Trivium's 288-bit internal state consists of three [shift registers](https://en.wikipedia.org/wiki/Shift_register) of different lengths. At each round, a bit is shifted into each of the three shift registers using a non-linear combination of taps from that and one other register; one bit of output is produced. To initialize the cipher, the key and IV are written into two of the shift registers, with the remaining bits starting in a fixed pattern; the cipher state is then updated 4 × 288 = 1152 times, so that every bit of the internal state depends on every bit of the key and of the IV in a complex nonlinear way.

No taps appear on the first 65 bits of each shift register, so each novel state bit is not used until at least 65 rounds after it is generated. This is the key to Trivium's software performance and flexibility in hardware.

## Specification {#Specification}

Trivium may be specified very concisely using three recursive equations.[^o5] Each variable is an element of [GF](wikipedia://en/11615)(2); they can be represented as [bits](https://en.wikipedia.org/wiki/Bit), with "+" being [XOR](wikipedia://en/105979) and "•" being [AND](https://en.wikipedia.org/wiki/Binary_and).

- *a*<sub>*i*</sub> = *c*<sub>*i*−66</sub> + *c*<sub>*i*−111</sub> + *c*<sub>*i*−110</sub> • *c*<sub>*i*−109</sub> + *a*<sub>*i*−69</sub>
- *b*<sub>*i*</sub> = *a*<sub>*i*−66</sub> + *a*<sub>*i*−93</sub> + *a*<sub>*i*−92</sub> • *a*<sub>*i*−91</sub> + *b*<sub>*i*−78</sub>
- *c*<sub>*i*</sub> = *b*<sub>*i*−69</sub> + *b*<sub>*i*−84</sub> + *b*<sub>*i*−83</sub> • *b*<sub>*i*−82</sub> + *c*<sub>*i*−87</sub>

The output bits *r*<sub>0</sub> ... *r*<sub>2<sup>64</sup>−1</sub> are then generated by

- *r*<sub>*i*</sub> = *c*<sub>*i*−66</sub> + *c*<sub>*i*−111</sub> + *a*<sub>*i*−66</sub> + *a*<sub>*i*−93</sub> + *b*<sub>*i*−69</sub> + *b*<sub>*i*−84</sub>

Given an 80-bit key *k*<sub>0</sub> ... *k*<sub>79</sub> and an *l*-bit IV *v*<sub>0</sub> ... *v*<sub>*l*−1</sub> (where 0 ≤ *l* \< 80), Trivium is initialized as follows:

- (*a*<sub>−1245</sub> ... *a*<sub>−1153</sub>) = (0, 0 ... 0, *k*<sub>0</sub> ... *k*<sub>79</sub>)
- (*b*<sub>−1236</sub> ... *b*<sub>−1153</sub>) = (0, 0 ... 0, *v*<sub>0</sub> ... *v*<sub>*l*−1</sub>)
- (*c*<sub>−1263</sub> ... *c*<sub>−1153</sub>) = (1, 1, 1, 0, 0 ... 0)

The large negative indices on the initial values reflect the 1152 steps that must take place before output is produced.

To map a stream of bits *r* to a stream of bytes *R*, we use the [LSb-first](https://en.wikipedia.org/wiki/Bit_numbering) mapping *R*<sub>*i*</sub> = Σ<sub>*j*=0, ..., 7</sub> 2<sup>j</sup> *r*<sub>8*i*+j</sub>.

## Performance {#Performance}

A straightforward hardware implementation of Trivium would use 3488 [logic gates](https://en.wikipedia.org/wiki/Logic_gate) and produce one bit per clock cycle. However, because each state bit is not used for at least 64 rounds, 64 state bits can be generated in parallel at a higher hardware cost of 5504 gates. Different tradeoffs between speed and area are also possible.

The same property allows an efficient bitslice implementation in software; performance testing by [eSTREAM](wikipedia://en/2287686) give bulk encryption speeds of around 4 [cycles/byte](https://en.wikipedia.org/wiki/Cycles_per_byte) on some [x86](https://en.wikipedia.org/wiki/X86) platforms, which compares well to the 19 cycles/byte of the [AES](wikipedia://en/1260) reference implementation on the same platform.

## Security {#Security}

\[Trivium\] was designed as an exercise in exploring how far a stream cipher can be simplified without sacrificing its security, speed or flexibility. While simple designs are more likely to be vulnerable to simple, and possibly devastating, attacks (which is why we strongly discourage the use of Trivium at this stage), they certainly inspire more confidence than complex schemes, if they survive a long period of public scrutiny despite their simplicity.[^o8]

, no cryptanalytic attacks better than [brute-force attack](wikipedia://en/53784) are known, but several attacks come close. The best published practical [cube attacks](wikipedia://en/18982200) recover the key of reduced-round Trivium with up to 832 of its 1,152 initialization rounds, with a reported time complexity not exceeding (2^{50}).[^n1] Attacks reaching 978 rounds for key recovery and 1,108 rounds for distinguishing apply only in a [weak-key](wikipedia://en/719388) setting; no comparable attack is known against the full cipher.[^n2]

Previous cube attacks required 2<sup>68</sup> steps to break a variant of Trivium where the number of initialization rounds is reduced to 799.[^o11] Other authors speculated that these techniques could lead to a break for 1100 initialisation rounds, or "maybe even the original cipher".[^o12] This builds on an attack due to Michael Vielhaber that breaks 576 initialization rounds in only 2<sup>\12.3</sup> steps.[^o13]

Another attack recovers the internal state (and thus the key) of the full cipher in around 2<sup>\89.5</sup> steps (where each step is roughly the cost of a single trial in exhaustive search).[^o14] Reduced variants of Trivium using the same design principles have been broken using an equation-solving technique.[^o15] These attacks improve on the well-known time-space tradeoff attack on stream ciphers, which with Trivium's 288-bit internal state would take 2<sup>144</sup> steps, and show that a variant on Trivium which made no change except to increase the key length beyond the 80 bits mandated by eSTREAM Profile 2 would not be secure. Using optimised solving strategy, it is further possible to reduce the state-recovery complexity to 2<sup>132</sup> steps.[^o16]

A detailed justification of the design of Trivium is given in a paper "A Stream Cipher Construction Inspired by Block Cipher Design Principles".[^o17]
