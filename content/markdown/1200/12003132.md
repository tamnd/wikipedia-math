# Visibility polygon

*Image: Visibility polygon.svg.* Visibility polygon shown in yellow. Four obstacles are shown in blue.

::: {#o1 .subject cue=lead name="Visibility polygon"}

In [computational geometry](wikipedia://en/176927), the **visibility polygon** or **visibility region** for a point $p$ in the plane among obstacles is the possibly unbounded [polygonal region](https://en.wikipedia.org/wiki/Polygonal_region) of all points of the plane [visible](https://en.wikipedia.org/wiki/Visible_%28geometry%29) from $p$. The visibility polygon can also be defined for visibility from a segment, or a polygon. Visibility polygons are useful in [robotics](https://en.wikipedia.org/wiki/Robotics), [video games](https://en.wikipedia.org/wiki/Video_games), and in various optimization problems such as the [facility location problem](wikipedia://en/10469986) and the [art gallery problem](wikipedia://en/1448859).

:::

If the visibility region is bounded then it is a [star-shaped polygon](wikipedia://en/12002655). A visibility polygon is bounded if all [rays](wikipedia://en/946975#Ray) shooting from the point eventually terminate in some obstacle. This is the case, e.g., if the obstacles are the edges of a [simple polygon](wikipedia://en/1059530) and $p$ is inside the polygon. In the latter case the visibility polygon may be found in [linear time](https://en.wikipedia.org/wiki/Linear_time).[^o2][^o3][^o4][^o5]

::: {#o7 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

Formally, we can define the planar visibility polygon problem as such. Let $S$ be a set of obstacles (either segments, or polygons) in $\mathbb{R}^2$. Let $p$ be a point in $\mathbb{R}^2$ that is not within an obstacle. Then, the *point visibility polygon* $V$ is the set of points in $\mathbb{R}^2$, such that for every point $q$ in $V$, the segment $pq$ does not intersect any obstacle in $S$.

Likewise, the *segment visibility polygon* or *edge visibility polygon* is the portion visible to any point along a [line segment](wikipedia://en/22634860).

:::

::: {#o9 .application cue=heading name="Applications"}

## Applications {#Applications}

Visibility polygons are useful in [robotics](https://en.wikipedia.org/wiki/Robotics). For example, in [robot localization](https://en.wikipedia.org/wiki/Robot_localization), a robot using sensors such as a [lidar](https://en.wikipedia.org/wiki/Lidar) will detect obstacles that it can see, which is similar to a visibility polygon.[^o10]

They are also useful in [video games](https://en.wikipedia.org/wiki/Video_games), with numerous online tutorials explaining simple algorithms for implementing it.[^o11][^o12]

:::

## Algorithms for point visibility polygons {#Algorithms_for_point_visibility_polygons}

### Optimal algorithms for a point in a simple polygon {#Optimal_algorithms_for_a_point_in_a_simple_polygon}

*Image: Visibility polygon for a point in a simple polygon 2.svg.* A visibility polygon for a point in the center (shown in white) inside a simple polygon, outlined in black.

Given a simple polygon $\mathcal{P}$ and a point $p$, a [linear time](https://en.wikipedia.org/wiki/Linear_time) algorithm is optimal for computing the region in $\mathcal{P}$ that is visible from $p$. Such an algorithm was first proposed in 1981.[^o3] However, it is quite complicated. In 1983, a conceptually simpler algorithm was proposed,[^o4] which had a minor error that was corrected in 1987.[^o5]

The latter algorithm will be briefly explained here. It simply walks around the boundary of the polygon $\mathcal{P}$, processing the vertices in the order in which they appear, while maintaining a [stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29) of vertices $\mathcal{S}=s_0, s_1,\cdots, s_t$ where $s_t$ is the top of the stack. The stack constitutes the vertices encountered so far which are visible to $p$. If, later during the execution of the algorithm, some new vertices are encountered that obscure part of $\mathcal{S}$, then the obscured vertices in $\mathcal{S}$ will be popped from the stack. By the time the algorithm terminates, $\mathcal{S}$ will consist of all the visible vertices, i.e. the desired visibility polygon. An efficient implementation was published in 2014.[^o24]

### Optimal algorithms for a point in a polygon with holes {#Optimal_algorithms_for_a_point_in_a_polygon_with_holes}

For a point in a polygon with $h$ holes and $n$ vertices in total, it can be shown that in the worst case, a $\Theta(n + h\log h)$ algorithm is optimal. Such an algorithm was proposed in 1995 together with its proof of optimality.[^o16] However, it relies on the linear time [polygon triangulation](wikipedia://en/679384) algorithm by Chazelle, which is extremely complex.

### Optimal algorithms for a point among segments {#Optimal_algorithms_for_a_point_among_segments}

#### Segments that do not intersect except at their endpoints {#Segments_that_do_not_intersect_except_at_their_endpoints}

*Image: Visibility polygon for a point among segments.svg.* A visibility polygon for a point in the center (shown in white) amongst a set of arbitrary line segments in the plane, allowed to intersect only at their endpoints, acting as obstacles (shown in black).

For a point among a set of $n$ segments that do not intersect except at their endpoints, it can be shown that in the worst case, a $\Theta(n\log n)$ algorithm is optimal. This is because a visibility polygon algorithm must output the vertices of the visibility polygon in sorted order, hence the problem of [sorting](wikipedia://en/28442) can be reduced to computing a visibility polygon.[^o19]

Notice that any algorithm that computes a visibility polygon for a point among segments can be used to compute a visibility polygon for all other kinds of polygonal obstacles, since any polygon can be decomposed into segments.

##### Divide and conquer {#Divide_and_conquer}

A [divide-and-conquer algorithm](wikipedia://en/201154) to compute the visibility polygon was proposed in 1987.[^o21]

##### Angular sweep {#Angular_sweep}

An *angular sweep*, i.e. rotational [plane sweep](wikipedia://en/8700856) algorithm to compute the visibility polygon was proposed in 1985[^o23] and 1986.[^o19] The idea is to first sort all the segment endpoints by polar angle, and then iterate over them in that order. During the iteration, the event line is maintained as a [heap](wikipedia://en/13996). An efficient implementation was published in 2014.[^o24]

#### Generally intersecting segments {#Generally_intersecting_segments}

For a point among generally intersecting segments, the visibility polygon problem is reducible, in linear time, to the [lower envelope](wikipedia://en/67739924) problem. By the [Davenport–Schinzel argument](wikipedia://en/20232529#Application_to_lower_envelopes), the lower envelope in the worst case has $\Theta(n\alpha(n))$ number of vertices, where $\alpha(n)$ is the [inverse Ackermann function](https://en.wikipedia.org/wiki/Inverse_Ackermann_function). A worst case optimal divide-and-conquer algorithm running in $\Theta(n\log n)$ time was created by [John Hershberger](https://en.wikipedia.org/wiki/John_Hershberger) in 1989.[^o26]
