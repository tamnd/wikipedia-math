# Logic redundancy

::: {#o1 .subject cue=lead name="Logic redundancy"}

**Logic redundancy** occurs in a [logic gate](https://en.wikipedia.org/wiki/Logic_gate) network containing circuitry that does not affect the static logic function. There are several reasons why logic redundancy may exist. One reason is that it may have been added deliberately to suppress transient glitches (thus causing a [race condition](https://en.wikipedia.org/wiki/Race_condition)) in the output signals by having two or more product terms overlap with a third one.

:::

Consider the following equation:

$$Y = A B + \overline{A} C + B C.$$

The third [product term](wikipedia://en/2139702) $BC$ is a redundant [consensus term](wikipedia://en/8325288). If $A$ switches from 1 to 0 while $B = 1$ and $C = 1$, $Y$ remains 1. During the transition of signal $A$ in logic gates, both the first and second term may be 0 momentarily. The third term prevents a glitch since its value of 1 in this case is not affected by the transition of signal $A$.

Another reason for logic redundancy is poor design practices which unintentionally result in logically redundant terms. This causes an unnecessary increase in network complexity, and possibly hampering the ability to test manufactured designs using traditional test methods (single [stuck-at fault](https://en.wikipedia.org/wiki/Stuck-at_fault) models). Testing might be possible using [IDDQ](https://en.wikipedia.org/wiki/Iddq_testing) models.

## Removing logic redundancy {#Removing_logic_redundancy}

Logic redundancy is, in general, not desired. [Redundancy](https://en.wikipedia.org/wiki/Redundancy_%28engineering%29), by definition, requires extra parts (in this case: logical terms) which raises the cost of implementation (either actual cost of physical parts or [CPU time](https://en.wikipedia.org/wiki/CPU_time) to process). Logic redundancy can be removed by several well-known techniques, such as [Karnaugh maps](wikipedia://en/10854684), the [Quine–McCluskey algorithm](wikipedia://en/317263), and the [heuristic computer method](https://en.wikipedia.org/wiki/Espresso_heuristic_logic_minimizer).

## Adding logic redundancy {#Adding_logic_redundancy}

*Image: K-map 6,8,9,10,11,12,13,14\_1only.svg.* K-map to obtain minimal circuitery for function *f*

*Image: K-map 6,8,9,10,11,12,13,14 anti-race\_1only.svg.* Above k-map with the $A\overline{D}$ term added to avoid race hazards

In some cases it may be desirable to *add* logic redundancy. One of those cases is to avoid [race conditions](https://en.wikipedia.org/wiki/Race_condition) whereby an output can fluctuate because different terms are "racing" to turn off and on. To explain this in more concrete terms the [Karnaugh map](wikipedia://en/10854684) to the right shows the minterms for the following function:

$$f(A, B, C, D) = E(6, 8, 9, 10, 11, 12, 13, 14).\$$

The boxes represent the minimal AND/OR terms needed to implement this function:

$$f = A\overline{C} + A\overline{B} + BC\overline{D}.$$

The k-map visually shows where [race conditions](https://en.wikipedia.org/wiki/Race_condition) occur in the minimal expression by having gaps between minterms, for example, the gap between the blue and green rectangles. If the input were to change from $1110$[^o4] to $1010$ then a race will occur between $BC\overline{D}$ turning off and $A\overline{B}$ turning on. If the blue term switches off before the green turns on then the output will fluctuate and may register as 0. Another race condition is between the blue and the red for transition from $1110$ to $1100$.

The race condition is removed by adding in logic redundancy. Both minterm race conditions are covered by addition of the yellow term $A\overline{D}$.

In this case, the addition of logic redundancy has stabilized the output to avoid output fluctuations because terms are racing each other to change state.

## Notes {#Notes}

[^o4]: this is usual short notation for $A=1$, $B=1$, $C=1$, and $D=0$
