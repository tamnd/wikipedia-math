# Naor–Reingold pseudorandom function

::: {#o1 .subject cue=lead name="Naor–Reingold pseudorandom function"}

In 1997, [Moni Naor](https://en.wikipedia.org/wiki/Moni_Naor) and [Omer Reingold](https://en.wikipedia.org/wiki/Omer_Reingold) described efficient constructions for various [cryptographic primitives](wikipedia://en/4928985) in private key as well as [public-key cryptography](wikipedia://en/24222). Their result is the construction of an efficient [pseudorandom function](wikipedia://en/3454616). Let *p* and *l* be [prime numbers](wikipedia://en/23666) with *l* | *p* − 1, and select an element $g \in \mathbb{F}_p^*$ of [multiplicative order](wikipedia://en/344542) *l*. Then for each (*n*+1)-dimensional [vector](wikipedia://en/879358) $a = (a_0, a_1, \ldots, a_n) \in \mathbb{F}_l^{n+1},$ they define the function

$$f_{a}(x) = g^{a_0\cdot a_1^{x_1} a_2^{x_2} \cdots a_n^{x_n}} \in \mathbb F_p,$$

where *x* = *x*<sub>1</sub>…*x*<sub>*n*</sub> is the [bit representation](https://en.wikipedia.org/wiki/Binary_numeral_system#Representation) of the integer *x*, 0 ≤ *x* ≤ 2<sup>*n*−1</sup>, with some extra leading zeros if necessary.[^o13]

:::

::: {#o3 .example cue=heading name="Example"}

## Example {#Example}

Let *p* = 7 and *l* = 3; then *l* | *p* − 1. Select $g=4\in\mathbb{F}_7^*$ of multiplicative order 3 (since 4<sup>3</sup> = 64 ≡ 1 (mod 7)). For *n* = 3, *a* = (1,1,2,1) and *x* = 5 (the bit representation of 5 is 101), we can compute *f*<sub>*a*</sub>(5) as follows:

$$f_a(5) = 4^{1\cdot 1^1 2^0 1^1} = 4^1 = 4 \in \mathbb{F}_7.$$

:::

## Efficiency {#Efficiency}

The evaluation of function *f*<sub>*a*</sub>(5) in the Naor–Reingold construction can be done very efficiently: at any given point, it is comparable with one [modular exponentiation](wikipedia://en/903032) and *n* modular multiplications. This function can be computed in parallel by threshold circuits of bounded depth and polynomial size.

The Naor–Reingold function can be used as the basis of many [cryptographic](wikipedia://en/18934432) schemes including [symmetric encryption](wikipedia://en/53042), [authentication](https://en.wikipedia.org/wiki/Authentication_protocol), and [digital signatures](wikipedia://en/59644).

## Security of the function {#Security_of_the_function}

Assume that an attacker sees several outputs of the function, such as $f_a(1) = g^{a_1},$ $f_a(2) = g^{a_2},$ $f_a(3) = g^{a_1 a_2}, \ldots,$ $f_a(k) = g^{a_1^{x_1} a_2^{x_2}...a_n^{x_n}},$ and wants to compute $f_{a}(k + 1)$. Assume for simplicity that $x_1=0$; then the attacker needs to solve the [computational Diffie–Hellman (CDH) problem](wikipedia://en/1937391) between $f_a (1)= g^{a_{1}}$ and $f_{a}(k) = g^{a_{2}^{x_{2}} ...a_{n}^{x_{n}}}$ to get $f_{a}(k+1) = g^{a_{1}a_{2}^{x_{2}} \dots a_{n}^{x_{n}}}$. In general, moving from $k$ to $k+1$ changes the bit pattern, and unless $k+1$ is a power of 2, one can split the exponent in $f_{a}(k + 1)$ so that the computation corresponds to computing the [Diffie–Hellman](wikipedia://en/3237741) key between two of the earlier results. This attacker wants to predict the next sequence element. Such an attack would be very bad—but it is also possible to fight it off by working in [groups](wikipedia://en/19447) with a hard Diffie–Hellman problem (DHP).

::: {#o7 .example cue=heading name="Example"}

### Example {#Example}

An attacker sees several outputs of the function, such as $f_{a}(5) = 4^{1^{1} 2^{0} 1^{1}} = 4^{1} = 4$, as in the previous example, and $f_{a}(1) = 4^{1^{0} 2^{0} 1^{1}} = 4^{1} = 4$. Then, the attacker wants to predict the next sequence element of this function, $f_{a}(6)$. However, the attacker cannot predict the outcome of $f_{a}(6)$ from knowing $f_{a}(1)$ and $f_{a}(5)$.

Other attacks could also be very bad for a [pseudorandom number generator](wikipedia://en/45524): the user expects to get random numbers from the output, so of course the stream should not be predictable, but even more, it should be indistinguishable from a random string. Let $\mathcal{A}^f$ denote the algorithm $\mathcal{A}$ with access to an oracle for evaluating the function $f_{a}(x)$. Suppose that the [decisional Diffie–Hellman assumption](wikipedia://en/1198015) holds for $\mathbb F_p$; then Naor and Reingold show that for every [probabilistic polynomial time](wikipedia://en/659322) algorithm $\mathcal{A}$ and sufficiently large *n*,

$$\text{Pr }[\mathcal{A}^{f_{a}(x)}(p,g) \to 1] - \text{Pr }[\mathcal{A}^{R} (p,g)\to 1]$$

is [negligible](wikipedia://en/8426019).

The first probability is taken over the choice of the seed $s=(p,g,a)$, and the second probability is taken over the random distribution induced on $p,g$ by $\mathcal{I}\mathcal{G} (n)$, instance generator, and the random choice of the function $R_{a}(x)$ among the set of all $\{0,1\}^{n} \to \mathbb F_p$ functions.[^o17]

:::

## Linear complexity {#Linear_complexity}

One natural measure of how useful a sequence may be for [cryptographic](wikipedia://en/18934432) purposes is the size of its linear complexity. The linear complexity of an *n*-element sequence $W(x)$ over a ring $\mathcal{R}$ with $x=0,1,2,\ldots, n-1$ is the length $l$ of the shortest linear [recurrence relation](wikipedia://en/146806) $W(x+l)=A_{l-1} W(x+l-1) + \cdots A_0 W(x),$ where $x=0,1,2, \ldots, n-l-1$ with $A_0,\ldots,A_{l-1}\in\mathcal{R}$, which is satisfied by this sequence.

For some $\gamma > 0$ and $n \geq (1+\gamma) \log(l)$, for any $\delta > 0$ and sufficiently large *l*, the linear complexity of the sequence $f_{a}(x)_{x=0}^{2^{n-1}}$, denoted by $L_a$ satisfies

$$L_{a} \geqslant \begin{cases} l^{1-\delta} &\text{if } \gamma \geq 2\\ l^{\left(\tfrac{\gamma}{2-\delta}\right)} &\text{if } \gamma < 2 \end{cases}$$

for all except possibly at most $3(l - 1)^{n - \delta}$ vectors $a \in (\mathbb{F}_l)^n$.[^o14] The bound of this work has disadvantages; namely, it does not apply to the very interesting case $\log(p) \approx \log(n) \approx n.$

## Uniformity of distribution {#Uniformity_of_distribution}

The statistical distribution of $f_{a}(x)$ is exponentially close to [uniform](https://en.wikipedia.org/wiki/Uniform_distribution_%28discrete%29) for almost all vectors $a \in (\mathbb{F}_l)^n$.

Let ${\mathbf D}_a$ be the [discrepancy](wikipedia://en/1544750) of the set $\{f_a (x)| 0 \leq x \leq 2^{n-1}\}$. Thus, if $n=\lceil\log(p)\rceil$ is the bit length of $p$, then for all vectors $a \in (\mathbb{F}_l)^n$, the bound ${\mathbf D}_a\leq \Delta (l,p)$ holds, where

$$\Delta (l,p) = \begin{cases} p^{\left (\tfrac{1-\ \gamma\,\!}{2}\right )}l^{\left (\tfrac{-1}{2}\right )}\log^{2}p &\text{ if } l \geqslant p^{\gamma\,\!}\\ p^{\left (\tfrac{1}{2}\right )}l^{-1}\log^{2}p &\text{ if } p^{\gamma\,\!} > l \geqslant p^{\left (\tfrac{2}{3}\right )} \\ p^{\left (\tfrac{1}{4}\right )}l^{\left (\tfrac{-5}{8}\right )}\log^{2}p &\text{ if } p^{\left (\tfrac{2}{3}\right )} > l \geqslant p^{\left (\tfrac{1}{2}\right )} \\ p^{\left (\tfrac{1}{8}\right )}l^{\left (\tfrac{-3}{8}\right )}\log^{2}p &\text{ if } p^{\left (\tfrac{1}{2}\right )} > l \geqslant p^{\left (\tfrac{1}{3}\right )} \\ \end{cases}$$

and

$$\gamma = 2.5 - \log 3 = 0.9150\ldots.$$

Although this property does not seem to have any immediate cryptographic implications, the inverse fact, namely non-uniform distribution, if true would have disastrous consequences for applications of this function.[^o15]

## Sequences in elliptic curves {#Sequences_in_elliptic_curves}

The [elliptic-curve](wikipedia://en/10225) version of this function is also of interest. In particular, it may help to improve the cryptographic security of the corresponding system. Let $p>3$ be prime and let $E$ be an elliptic curve; then each vector $\mathbf{a}$ defines a finite sequence in the [subgroup](wikipedia://en/28011) $\langle G\rangle$ as

$$F_{a}(x) = (a_{1}^{x_{1}} a_{2}^{x_{2}}\dots a_{n}^{x_{n}})G,$$

where $x = x_1 \cdots x_n$ is the bit representation of integer $x, 0 \leq x \leq 2^{n-1}$. The Naor–Reingold elliptic curve sequence is defined as[^o16]

$$u_{k} = X (f_{a}(k)),$$

where $X(P)$ is the [abscissa](wikipedia://en/60487) of $P \in E(\mathbb{F}_p)$.

If the [decisional Diffie–Hellman assumption](wikipedia://en/1198015) holds, then index $k$ is not enough to compute $u_k$ in polynomial time, even if an attacker performs polynomially-many queries to a [random oracle](wikipedia://en/451286).
