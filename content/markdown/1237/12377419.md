# Path-based strong component algorithm

::: {#o1 .subject cue=lead name="Path-based strong component algorithm"}

In [graph theory](wikipedia://en/12401), the [strongly connected components](wikipedia://en/684680) of a [directed graph](wikipedia://en/19721986) may be found using an algorithm that uses [depth-first search](wikipedia://en/97034) in combination with two [stacks](https://en.wikipedia.org/wiki/Stack_%28data_structure%29), one to keep track of the vertices in the current component and the second to keep track of the current search path.[^o2] Versions of this algorithm have been proposed by (Purdom 1970), (Munro 1971), (Dijkstra 1976), (Cheriyan Mehlhorn 1996), and (Gabow 2000); of these, Dijkstra's version was the first to achieve [linear time](https://en.wikipedia.org/wiki/Linear_time).[^o8]

:::

## Description {#Description}

The algorithm performs a depth-first search of the given graph *G*, maintaining as it does two stacks *S* and *P* (in addition to the normal call stack for a recursive function). Stack *S* contains all the vertices that have not yet been assigned to a strongly connected component, in the order in which the depth-first search reaches the vertices. Stack *P* contains vertices that have not yet been determined to belong to different strongly connected components from each other. It also uses a counter *C* of the number of vertices reached so far, which it uses to compute the preorder numbers of the vertices.

When the depth-first search reaches a vertex *v*, the algorithm performs the following steps:

1. Set the preorder number of *v* to *C*, and increment *C*.
1. Push *v* onto *S* and also onto *P*.
1. For each edge from *v* to a neighboring vertex *w*:
   - If the preorder number of *w* has not yet been assigned (the edge is a [tree edge](wikipedia://en/97034#Output_of_a_depth-first_search)), recursively search *w*;
   - Otherwise, if *w* has not yet been assigned to a strongly connected component (the edge is a forward/back/cross edge):
     - Repeatedly pop vertices from *P* until the top element of *P* has a preorder number less than or equal to the preorder number of *w*.
1. If *v* is the top element of *P*:
   - Pop vertices from *S* until *v* has been popped, and assign the popped vertices to a new component.
   - Pop *v* from *P*.

The overall algorithm consists of a loop through the vertices of the graph, calling this recursive search on each vertex that does not yet have a preorder number assigned to it.

## History and development {#History_and_development}

The path-based algorithm family for finding strongly connected components was developed from several key historical contributions. The earliest version was proposed as Paul Purdom's 1970 transitive closure algorithm, which utilized naive cycle contraction.[^o11][^o8] This was optimized by J. Ian Munro in 1971 using a set-merging approach, running in *O*(*m* + *n* log *n*) time.[^o12][^o8] [Edsger W. Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra), in his 1976 book, introduced the first linear-time *O*(*m* + *n*) non-recursive implementation of the algorithm using three main arrays: *rank*, *knar* (the backwards spelled *rank* array mapping rank to vertex), and *cc* (used to track component boundaries).[^o13][^o8] In 1976, Dijkstra also derived the path-based algorithm using these three arrays—*rank*, *knar*, and *cc*—to track component boundaries and achieve *O*(*m* + *n*) time.[^o14] Later formulations and refinements to the path-based strongly connected components algorithm were proposed by Cheriyan and Mehlhorn in 1996[^o15] and by Gabow in 2000.[^o16]

## Related algorithms {#Related_algorithms}

Like this algorithm, [Tarjan's strongly connected components algorithm](wikipedia://en/8244667) also uses depth first search together with a stack to keep track of vertices that have not yet been assigned to a component, and moves these vertices into a new component when it finishes expanding the final vertex of its component. However, in place of the stack *P*, Tarjan's algorithm uses a vertex-indexed [array](https://en.wikipedia.org/wiki/Array_%28data_type%29) of preorder numbers, assigned in the order that vertices are first visited in the [depth-first search](wikipedia://en/97034). The preorder array is used to keep track of when to form a new component.
