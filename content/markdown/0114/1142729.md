# FROG

::: {#o1 .subject cue=lead name="FROG"}

In [cryptography](wikipedia://en/18934432), **FROG** is a [block cipher](wikipedia://en/4594) authored by Georgoudis, Leroux and Chaves. The algorithm can work with any block size between 8 and 128 [bytes](https://en.wikipedia.org/wiki/Byte), and supports key sizes between 5 and 125 bytes. The algorithm consists of 8 rounds and has a very complicated [key schedule](wikipedia://en/609603).

:::

It was submitted in 1998 by TecApro, a Costa Rican software company, to the [AES competition](https://en.wikipedia.org/wiki/AES_competition) as a candidate to become the [Advanced Encryption Standard](wikipedia://en/1260). Wagner et al. (1999) found a number of [weak key](wikipedia://en/719388) classes for FROG. Other problems included very slow key setup and relatively slow encryption. FROG was not selected as a finalist.

## Design philosophy {#Design_philosophy}

Normally a block cipher applies a fixed sequence of primitive mathematical or logical operators (such as additions, [XORs](https://en.wikipedia.org/wiki/XOR), etc.) on the [plaintext](wikipedia://en/157935) and [secret key](https://en.wikipedia.org/wiki/Secret_key) in order to produce the [ciphertext](wikipedia://en/175560). An attacker uses this knowledge to search for weaknesses in the cipher which may allow the recovery of the plaintext.

FROG's design philosophy is to hide the exact sequence of primitive operations even though the cipher itself is known. While other ciphers use the secret key only as data (which are combined with the plain text to produce the cipher text), FROG uses the key both as data and as instructions on how to combine these data. In effect an expanded version of the key is used by FROG as a program. FROG itself operates as an interpreter that applies this key-dependent program on the plain text to produce the cipher text. Decryption works by applying the same program in reverse on the cipher text.

## Description {#Description}

*Image: High level view of FROG.PNG.* High level view of FROG

The FROG key schedule (or internal key) is 2304 bytes long. It is produced recursively by iteratively applying FROG to an empty plain text. The resulting block is processed to produce a well formatted internal key with 8 records. FROG has 8 rounds, the operations of each round codified by one record in the internal key. All operations are byte-wide and consist of [XORs](https://en.wikipedia.org/wiki/XOR) and substitutions.[^o5]

FROG is very easy to implement (the reference C version has only about 150 lines of code). Much of the code needed to implement FROG is used to generate the secret internal key; the internal cipher itself is a very short piece of code. It is possible to write an assembly routine of just 22 machine instructions that does full FROG encryption and decryption. The implementation will run well on 8 [bit](https://en.wikipedia.org/wiki/Bit) processors because it uses only byte-level instructions. No bit-specific operations are used. Once the internal key has been computed, the algorithm is fairly fast: a version implemented using 8086 assembler achieves processing speeds of over 2.2 [megabytes](https://en.wikipedia.org/wiki/Megabyte) per second when run on a 200 MHz Pentium PC.

## Security {#Security}

FROG's design philosophy is meant to defend against unforeseen/unknown types of attacks. Nevertheless, the very fact that the key is used as the encryption program means that some keys may correspond to [weak encryption](https://en.wikipedia.org/wiki/Weak_encryption) programs. David Wagner et al. found that 2<sup>−33</sup> of the keys are weak and that in these cases the key can be broken with 2<sup>58</sup> [chosen plaintexts](https://en.wikipedia.org/wiki/Chosen_plaintext).

Another flaw of FROG is that the decryption function has a much slower diffusion than the encryption function. Here 2<sup>−29</sup> of keys are weak and can be broken using 2<sup>36</sup> chosen ciphertexts.
