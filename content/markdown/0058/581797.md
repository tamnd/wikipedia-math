# Matching (graph theory)

::: {#o1 .subject cue=lead name="Matching"}

In the mathematical discipline of [graph theory](wikipedia://en/12401), a **matching** or **independent edge set** in an undirected [graph](wikipedia://en/325806) is a set of [edges](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) without common [vertices](wikipedia://en/638899).[^o2] In other words, a subset of the edges is a matching if each vertex appears in at most one edge of that matching.

:::

Finding a [largest matching](wikipedia://en/5989592) in a [bipartite graph](wikipedia://en/244431) can be treated as a [network flow](wikipedia://en/645676) problem. Finding a largest matching in a general graph is much more difficult; it can be done using [Edmonds'](wikipedia://en/3625459) [blossom algorithm](wikipedia://en/24277294).

::: {#o4 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

Given a [graph](wikipedia://en/325806) $G = (V,\,E),$ a **matching** *M* in *G* is a set of pairwise [non-adjacent](https://en.wikipedia.org/wiki/Non-adjacent) edges, none of which are [loops](wikipedia://en/1449083); that is, no two edges share common vertices.

$M$ is a matching *of* $U \subseteq V$ if every vertex in $U$ is incident with an edge in $M$.[^o5]

*Image: Bipartite\_matching.svg.* An example of a matching on a bipartite graph.

A vertex is **matched** (or **saturated**) if it is an endpoint of one of the edges in the matching. Otherwise the vertex is **unmatched** (or **unsaturated**).

A **maximal matching** is a matching *M* of a graph *G* that is not a subset of any other matching. A matching *M* of a graph *G* is maximal if every edge in *G* has a non-empty intersection with at least one edge in *M*. The following figure shows examples of maximal matchings (red) in three graphs.

*Image: Maximal-matching.svg.*

A **maximum matching** (also known as [maximum-cardinality matching](wikipedia://en/5989592)[^o6]) is a matching that contains the largest possible number of edges. There may be many maximum matchings. The **matching number** $\nu(G)$ of a graph $G$ is the size of a maximum matching. Every maximum matching is maximal, but not every maximal matching is a maximum matching. The following figure shows examples of maximum matchings in the same three graphs.

*Image: Maximum-matching-labels.svg.*

A **[perfect matching](wikipedia://en/44031)** is a matching that matches all vertices of the graph. That is, a matching is perfect if every vertex of the graph is [incident](wikipedia://en/387224) to an edge of the matching. A matching is perfect if $|M|=|V|/2$. Every perfect matching is maximum and hence maximal. In some literature, the term **complete matching** is used. In the above figure, only part (b) shows a perfect matching. A perfect matching is also a minimum-size [edge cover](wikipedia://en/4577392). Thus, the size of a maximum matching is no larger than the size of a minimum edge cover: $\nu(G) \le \rho(G)$. A graph can only contain a perfect matching when the graph has an even number of vertices.

A **near-perfect matching** is one in which exactly one vertex is unmatched. Clearly, a graph can only contain a near-perfect matching when the graph has an [odd number](https://en.wikipedia.org/wiki/Odd_number) of vertices, and near-perfect matchings are maximum matchings. In the above figure, part (c) shows a near-perfect matching. If every vertex is unmatched by some near-perfect matching, then the graph is called [factor-critical](wikipedia://en/7684634).

An **[induced matching](https://en.wikipedia.org/wiki/Induced_matching)** is a matching that is the edge set of an [induced subgraph](wikipedia://en/1655188).[^o7]

:::

## Alternating and augmenting paths {#Alternating_and_augmenting_paths}

Given a matching *M*, an **alternating path** is a path that begins with an unmatched vertex[^o9] and whose edges belong alternately to the matching and not to the matching. An **augmenting path** is an alternating path that starts from and ends on free (unmatched) vertices. [Berge's lemma](https://en.wikipedia.org/wiki/Berge's_lemma) states that a matching *M* is maximum if and only if there is no augmenting path with respect to $M$*.* Using Berge's lemma, we can start from any matching $M$ and repeatedly apply augmenting paths until no more augmenting paths are found. This reduces the problem of finding a large matching to finding augmented paths.[^o5]

::: {#o11 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

In any graph without isolated vertices, the sum of the matching number and the [edge covering number](https://en.wikipedia.org/wiki/Edge_covering_number) equals the number of vertices.[^o12] If there is a perfect matching, then both the matching number and the edge cover number are $|V | / 2$.

::: {#o14 .statement kind=statement/fact cue=heading name="Characterizations"}

### Characterizations {#Characterizations}

[Kőnig's theorem](wikipedia://en/5465118) states that, in bipartite graphs, the maximum matching is equal in size to the minimum [vertex cover](wikipedia://en/562782). Via this result, the minimum vertex cover, [maximum independent set](https://en.wikipedia.org/wiki/Maximum_independent_set), and [maximum vertex biclique](https://en.wikipedia.org/wiki/Maximum_vertex_biclique) problems may be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) for bipartite graphs.

[Hall's marriage theorem](wikipedia://en/186969) provides a characterization of bipartite graphs which have a perfect matching and [Tutte's theorem on perfect matchings](wikipedia://en/1655060) provides a characterization for arbitrary graphs.

A spectral characterization of the matching number of a graph is given by Hassani Monfared and Mallik as follows: Let $G$ be a [graph](wikipedia://en/325806) on $n$ vertices, and $\lambda_1 > \lambda_2 > \ldots > \lambda_k>0$ be $k$ distinct nonzero [purely imaginary numbers](wikipedia://en/14554) where $2k \leq n$. Then the [matching number](https://en.wikipedia.org/wiki/Matching_number) of $G$ is $k$ if and only if (a) there is a real [skew-symmetric matrix](wikipedia://en/174055) $A$ with graph $G$ and [eigenvalues](https://en.wikipedia.org/wiki/Eigenvalues) $\pm \lambda_1, \pm\lambda_2,\ldots,\pm\lambda_k$ and $n-2k$ zeros, and (b) all real skew-symmetric matrices with graph $G$ have at most $2k$ nonzero [eigenvalues](https://en.wikipedia.org/wiki/Eigenvalues).[^o15] Note that the (simple) graph of a real symmetric or skew-symmetric matrix $A$ of order $n$ has $n$ vertices and edges given by the nonozero off-diagonal entries of $A$.

:::

### Maximum vs. maximal matchings {#Maximum_vs._maximal_matchings}

If $A$ and $B$ are two maximal matchings, then $|A| \le 2|B|$ and $|B| \le 2|A|$. To see this, observe that each edge in $B \backslash A$ can be adjacent to at most two edges in $A \backslash B$ because $A$ is a matching; moreover each edge in $A \backslash B$ is adjacent to an edge in $B \backslash A$ by maximality of $B$, hence

$$|A \setminus B| \le 2|B \setminus A |.$$

Further we deduce that

$$|A| = |A \cap B| + |A \setminus B| \le 2|B \cap A| + 2|B \setminus A| = 2|B|.$$

In particular, this shows that any maximal matching is a 2-approximation of a maximum matching and also a 2-approximation of a minimum maximal matching. This inequality is tight: for example, if $G$ is a path with 3 edges and 4 vertices, the size of a minimum maximal matching is 1 and the size of a maximum matching is 2.

:::

## Matching polynomials {#Matching_polynomials}

A [generating function](wikipedia://en/160993) of the number of *k*-edge matchings in a graph is called a matching polynomial. Let *G* be a graph and *m<sub>k</sub>* be the number of *k*-edge matchings. One matching polynomial of *G* is

$$\sum_{k\geq0} m_k x^k.$$

Another definition gives the matching polynomial as

$$\sum_{k\geq0} (-1)^k m_k x^{n-2k},$$

where *n* is the number of vertices in the graph. Each type has its uses; for more information see the article on matching polynomials.

## Algorithms and computational complexity {#Algorithms_and_computational_complexity}

### Maximum-cardinality matching {#Maximum-cardinality_matching}

A fundamental problem in [combinatorial optimization](wikipedia://en/420555) is finding a *maximum matching*. This problem has various algorithms for different classes of graphs.

In an *unweighted bipartite graph*, the optimization problem is to find a [maximum cardinality matching](https://en.wikipedia.org/wiki/Maximum_cardinality_matching). The problem is solved by the [Hopcroft-Karp algorithm](https://en.wikipedia.org/wiki/Hopcroft-Karp_algorithm) in time $O(VE)$ time, and there are more efficient [randomized algorithms](wikipedia://en/495383), [approximation algorithms](wikipedia://en/563105), and algorithms for special classes of graphs such as bipartite [planar graphs](wikipedia://en/24314), as described in the main article.

### Maximum-weight matching {#Maximum-weight_matching}

In a [*weighted*](https://en.wikipedia.org/wiki/Weighted_graph) *bipartite graph,* the optimization problem is to find a maximum-weight matching; a dual problem is to find a minimum-weight matching. This problem is often called **maximum weighted bipartite matching**, or the **[assignment problem](wikipedia://en/140592)**. The [Hungarian algorithm](wikipedia://en/2609001) solves the assignment problem and it was one of the beginnings of combinatorial optimization algorithms. It uses a modified [shortest path](https://en.wikipedia.org/wiki/Shortest_path) search in the augmenting path algorithm. If the [Bellman–Ford algorithm](wikipedia://en/221244) is used for this step, the running time of the Hungarian algorithm becomes $O(V^2 E)$, or the edge cost can be shifted with a potential to achieve $O(V^2 \log{V} + V E)$ running time with the [Dijkstra algorithm](https://en.wikipedia.org/wiki/Dijkstra_algorithm) and [Fibonacci heap](https://en.wikipedia.org/wiki/Fibonacci_heap).[^o21]

In a *non-bipartite weighted graph*, the problem of **[maximum weight matching](https://en.wikipedia.org/wiki/Maximum_weight_matching)** can be solved in time $O(V^{2}E)$ using [Edmonds' blossom algorithm](https://en.wikipedia.org/wiki/Edmonds's_matching_algorithm).

### Maximal matchings {#Maximal_matchings}

A maximal matching can be found with a simple [greedy algorithm](wikipedia://en/89247). A maximum matching is also a maximal matching, and hence it is possible to find a *largest* maximal matching in polynomial time. It is also possible to find a maximum matching with the use of [fast matrix multiplication algorithms](wikipedia://en/24107400) in the time $O({n^\omega })$ for $~2.37 \le \omega < 3$[^o23]. However, no polynomial-time algorithm is known for finding a **minimum maximal matching**, that is, a maximal matching that contains the *smallest* possible number of edges.

A maximal matching with *k* edges is an [edge dominating set](wikipedia://en/21689422) with *k* edges. Conversely, if we are given a minimum edge dominating set with *k* edges, we can construct a maximal matching with *k* edges in polynomial time. Therefore, the problem of finding a minimum maximal matching is essentially equal to the problem of finding a minimum edge dominating set.[^o24] Both of these two optimization problems are known to be [NP-hard](https://en.wikipedia.org/wiki/NP-hard); the decision versions of these problems are classical examples of [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problems.[^o25] Both problems can be [approximated](wikipedia://en/563105) within factor 2 in polynomial time: simply find an arbitrary maximal matching *M*.[^o26]

### Counting problems {#Counting_problems}

The number of matchings in a graph is known as the [Hosoya index](wikipedia://en/14221581) of the graph. It is [\#P-complete](https://en.wikipedia.org/wiki/Sharp-P-complete) to compute this quantity, even for bipartite graphs.[^o28] It is also #P-complete to count [perfect matchings](wikipedia://en/44031), even in [bipartite graphs](wikipedia://en/244431), because computing the [permanent](wikipedia://en/215889) of an arbitrary 0–1 matrix (another #P-complete problem) is the same as computing the number of perfect matchings in the bipartite graph having the given matrix as its [biadjacency matrix](https://en.wikipedia.org/wiki/Biadjacency_matrix). However, there exists a fully polynomial time randomized approximation scheme for counting the number of bipartite matchings.[^o29] A remarkable theorem of [Kasteleyn](https://en.wikipedia.org/wiki/Pieter_Kasteleyn) states that the number of perfect matchings in a [planar graph](wikipedia://en/24314) can be computed exactly in polynomial time via the [FKT algorithm](wikipedia://en/30159370).

The number of perfect matchings in a [complete graph](wikipedia://en/85816) *K*<sub>*n*</sub> (with *n* even) is given by the [double factorial](wikipedia://en/507208) (*n* − 1)!!.[^o30] The numbers of matchings in complete graphs, without constraining the matchings to be perfect, are given by the [telephone numbers](wikipedia://en/35258497).[^o31]

The number of perfect matchings in a graph is also known as the [hafnian](wikipedia://en/49270505) of its [adjacency matrix](wikipedia://en/244463).

### Finding all maximally matchable edges {#Finding_all_maximally_matchable_edges}

One of the basic problems in matching theory is to find in a given graph all edges that may be extended to a maximum matching in the graph (such edges are called [maximally matchable edges](wikipedia://en/61936551), or **allowed** edges). Algorithms for this problem include:

- For general graphs, a deterministic algorithm in time $O(VE)$ and a randomized algorithm in time $\tilde{O}(V^{2.376})$.[^o33][^o34]
- For bipartite graphs, if a single maximum matching is found, a deterministic algorithm runs in time $O(V+E)$.[^o35]

::: {#o37 .pointer-item cue=pointer name="Online bipartite matching"}

### Online bipartite matching {#Online_bipartite_matching}

The problem of developing an [online algorithm](https://en.wikipedia.org/wiki/Online_algorithm) for matching was first considered by [Richard M. Karp](wikipedia://en/298763), [Umesh Vazirani](https://en.wikipedia.org/wiki/Umesh_Vazirani), and [Vijay Vazirani](https://en.wikipedia.org/wiki/Vijay_Vazirani) in 1990.[^o38]

In the online setting, nodes on one side of the bipartite graph ("clients") arrive one at a time and must either be immediately matched to the other side of the graph ("servers") or discarded. This is a natural generalization of the [secretary problem](wikipedia://en/1971750) and has applications to online ad auctions. A simple greedy algorithm is 1/2-[competitive](wikipedia://en/8198743). For the unweighted maximization case with a random arrival model, Karp, Vazirani and Vazirani gave a randomized algorithm that attains a [competitive ratio](wikipedia://en/8198743) of $0.632$. The bound was later improved to $0.696$.[^o39] The problem was also studied in a model where clients may switch servers in order to improve the matching, and the goal is to economize on the number of switches while achieving a maximum matching.[^o40]

:::

## Applications {#Applications}

### Matching in general graphs {#Matching_in_general_graphs}

- A **Kekulé structure** of an [aromatic compound](https://en.wikipedia.org/wiki/Aromaticity) consists of a perfect matching of its [carbon skeleton](https://en.wikipedia.org/wiki/Skeletal_formula), showing the locations of [double bonds](https://en.wikipedia.org/wiki/Double_bond) in the [chemical structure](https://en.wikipedia.org/wiki/Chemical_structure). These structures are named after [Friedrich August Kekulé von Stradonitz](https://en.wikipedia.org/wiki/Friedrich_August_Kekulé_von_Stradonitz), who showed that [benzene](https://en.wikipedia.org/wiki/Benzene) (in graph theoretical terms, a 6-vertex cycle) can be given such a structure.[^o44]
- The [Hosoya index](wikipedia://en/14221581) is the number of non-empty matchings plus one; it is used in [computational chemistry](https://en.wikipedia.org/wiki/Computational_chemistry) and [mathematical chemistry](wikipedia://en/1570072) investigations for organic compounds.
- The [Chinese postman problem](wikipedia://en/172564) involves finding a minimum-weight perfect matching as a subproblem.

### Matching in bipartite graphs {#Matching_in_bipartite_graphs}

- The [graduation problem](https://web.archive.org/web/20240301015223/https://community.topcoder.com/stat?c=problem_statement&pm=2852&rd=5075) is about choosing minimum set of classes from given requirements for graduation.
- The [Hitchcock transport problem](wikipedia://en/6631661) involves bipartite matching as a sub-problem.
- The [subtree isomorphism](wikipedia://en/450062) problem involves bipartite matching as a sub-problem.

:::
