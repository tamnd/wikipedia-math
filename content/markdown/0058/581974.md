# Rocq

::: {#o2 .subject cue=lead name="Rocq"}

The **Rocq Prover** (formerly named **Coq**) is an [interactive theorem prover](wikipedia://en/1258607) first released in 1989. It allows the expression of mathematical assertions, mechanical checking of proofs of these assertions, assists in finding [formal proofs](wikipedia://en/1197184) using proof automation routines and extraction of a certified program from the [constructive proof](wikipedia://en/360113) of its [formal specification](https://en.wikipedia.org/wiki/Formal_specification).

:::

Rocq works within the theory of the calculus of inductive constructions, a derivative of the [calculus of constructions](wikipedia://en/613557). Rocq is not an [automated theorem prover](https://en.wikipedia.org/wiki/Automated_theorem_prover) but includes automatic theorem proving tactics ([procedures](https://en.wikipedia.org/wiki/Subroutine)) and various [decision](wikipedia://en/913118) procedures.

The [Association for Computing Machinery](https://en.wikipedia.org/wiki/Association_for_Computing_Machinery) awarded [Thierry Coquand](wikipedia://en/31842262), [Gérard Huet](https://en.wikipedia.org/wiki/Gérard_Huet), [Christine Paulin-Mohring](https://en.wikipedia.org/wiki/Christine_Paulin-Mohring), Bruno Barras, Jean-Christophe Filliâtre, Hugo Herbelin, Chetan Murthy, Yves Bertot, and Pierre Castéran with the 2013 [ACM Software System Award](https://en.wikipedia.org/wiki/ACM_Software_System_Award) for Rocq (when it was named Coq).

## Overview {#Overview}

When viewed as a [programming language](wikipedia://en/23015), Rocq implements a [dependently typed](wikipedia://en/1949487) [functional programming](https://en.wikipedia.org/wiki/Functional_programming) model;[^o4] when viewed as a logical system, it implements a [higher-order](wikipedia://en/562883) [type theory](wikipedia://en/40282). The development of Rocq has been supported since 1984 by [French Institute for Research in Computer Science and Automation](wikipedia://en/318413) (INRIA), in collaboration with many other French and international research institutions. The development of Rocq was initiated by Gérard Huet and Thierry Coquand, and more than 200 people,[^o5] mainly researchers, have contributed features to the core system since its inception. The implementation team has successively been coordinated by Gérard Huet, Christine Paulin-Mohring, Hugo Herbelin, and Matthieu Sozeau. Rocq is mainly implemented in [OCaml](https://en.wikipedia.org/wiki/OCaml) with a bit of [C](https://en.wikipedia.org/wiki/C_%28programming_language%29). The core system can be extended by way of a [plug-in](https://en.wikipedia.org/wiki/Plug-in_%28computing%29) mechanism.[^o6]

Rocq provides a specification language named Gallina.[^o7] Programs written in Gallina have the [weak normalization](https://en.wikipedia.org/wiki/Normalization_property_%28abstract_rewriting%29) property, implying that they always terminate. This is a distinctive property of the language, since infinite loops (non-terminating programs) are common in other programming languages.[^o8]

As an example of a proof written in Rocq, consider a proof of a lemma which states that taking the successor of a natural number flips its parity. The fold-unfold tactic introduced by Danvy[^o9] is used to help keep the proof simple.

```coq
From Stdlib Require Import Arith Nat Bool.

Fixpoint is_even (n : nat) : bool :=
  match n with
  | 0 => true
  | S n' => negb (is_even n')
  end.

Lemma is_even_0 :
  is_even 0 = true.
Proof. reflexivity. Qed.

Lemma is_even_S n :
  is_even (S n) = negb (is_even n).
Proof. reflexivity. Qed.

Lemma successor_flips_evenness n :
  is_even n = negb (is_even (S n)).
Proof.
  rewrite is_even_S.
  destruct (is_even n).
  * simpl. reflexivity.
  * simpl. reflexivity.
Qed.
```

This proof firsts import the definition of booleans and natural numbers from the standard library, and then defines a `is_even` which is a function returning whether a number is even. Then, three lemmas are proven about this function. The first just restate the defining equations of `is_even`, and since Rocq knows the equations their proof is very short. The last lemma is proven with a case distinction after first applying the second lemma; the star `*` demarks that a new sub-case starts there.

## Notable uses {#Notable_uses}

::: {#o12 .statement kind=statement/theorem cue=named-heading name="Four color theorem and SSReflect extension"}

### Four color theorem and SSReflect extension {#Four_color_theorem_and_SSReflect_extension}

[Georges Gonthier](wikipedia://en/38594995) of [Microsoft Research](https://en.wikipedia.org/wiki/Microsoft_Research) in [Cambridge](https://en.wikipedia.org/wiki/Cambridge), [England](https://en.wikipedia.org/wiki/England) and Benjamin Werner of [INRIA](wikipedia://en/318413) used Rocq to create a [surveyable proof](wikipedia://en/48740815) of the [four color theorem](wikipedia://en/10949), which was completed in 2002.[^o13] Their work led to the development of the SSReflect ("Small Scale Reflection") package, which was a significant extension to Rocq.[^o14] Despite its name, most of the features added to Rocq by SSReflect are general-purpose features and are not limited to the computational [reflective programming](https://en.wikipedia.org/wiki/Reflective_programming) style of proof. These features include:

- Added convenient notations for irrefutable and refutable [pattern matching](https://en.wikipedia.org/wiki/Pattern_matching), on [inductive types](wikipedia://en/22778065) with one or two constructors
- Implicit arguments for functions applied to zero arguments, which is useful when programming with [higher-order functions](https://en.wikipedia.org/wiki/Higher-order_function)
- Concise anonymous arguments
- An improved `set` tactic with more powerful matching
- Support for reflection

SSReflect is distributed as part of the main Rocq distribution since Coq 8.7.[^o15]

:::

## Other applications {#Other_applications}

- [CompCert](https://en.wikipedia.org/wiki/CompCert): an optimizing compiler for almost all of the [C programming language](https://en.wikipedia.org/wiki/C_%28programming_language%29) which is largely programmed and proven correct in Rocq.
- [Disjoint-set data structure](https://en.wikipedia.org/wiki/Disjoint-set_data_structure#History): correctness proof in Rocq was published in 2007.[^o17]
- [Feit–Thompson theorem](wikipedia://en/1656473): formal proof using Rocq was completed in September 2012.[^o18]
- [Busy beaver](wikipedia://en/67911): The value of the 5-state winning busy beaver was discovered by Heiner Marxen and Jürgen Buntrock in 1989, but only proved to be the winning fifth busy beaver — stylized as **BB(5)** — in 2024 using a proof in Rocq.[^o19][^o20]

## Tactic language {#Tactic_language}

In addition to constructing Gallina terms explicitly, Rocq supports the use of *tactics* written in the built-in language Ltac or in OCaml. These tactics automate the construction of proofs, carrying out trivial or obvious steps in proofs.[^o22] Several tactics implement decision procedures for various theories. For example, the "ring" tactic decides the theory of equality modulo [ring](wikipedia://en/48404) or [semiring](wikipedia://en/371468) axioms via [associative](wikipedia://en/1335)-[commutative](wikipedia://en/294390) rewriting.[^o23] For example, the following proof establishes a complex equality in the ring of [integers](wikipedia://en/14563) in just one line of proof:[^o24]

```coq
Require Import ZArith.
Open Scope Z_scope.
Goal forall a b c:Z,
    (a + b + c) ^ 2 =
     a * a + b ^ 2 + c * c + 2 * a * b + 2 * a * c + 2 * b * c.
  intros; ring.
Qed.
```

Built-in decision procedures are also available for the [empty theory](https://en.wikipedia.org/wiki/Empty_theory) ("congruence"), propositional logic ("tauto"), quantifier-free linear integer arithmetic ("lia"), and linear rational/real arithmetic ("lra").[^o25][^o26] Further decision procedures have been developed as libraries, including one for [Kleene algebras](wikipedia://en/155430)[^o27] and another for certain [geometric](wikipedia://en/18973446) goals.[^o28]

## Name {#Name}

*Image: Coq logo.png.* Former logo

The old name *Coq* means '[rooster](https://en.wikipedia.org/wiki/Rooster)' in [French](https://en.wikipedia.org/wiki/French_language) and is a wordplay on the name of Thierry Coquand, *calculus of constructions* or *CoC*, and stems from a French tradition of naming research development tools after animals.[^o30] Until 1991, Coquand was implementing a language named the *[calculus of constructions](wikipedia://en/613557)* and it was simply called *CoC* then. In 1991, a new implementation based on the extended *calculus of inductive constructions* was begun and the name changed from *CoC* to *Coq* in an indirect reference to Coquand, who developed the *calculus of constructions* along with Gérard Huet and contributed to the *calculus of inductive constructions* with Christine Paulin-Mohring.[^o31] On October 11, 2023, the development team announced that *Coq* would be renamed *The Rocq Prover* in coming months, and began updating the code base, website, and related tools.[^o32] The official renaming happened with the release of Rocq 9.0 in March 2025.[^o33] The new name refers to [Inria Rocquencourt](wikipedia://en/318413), where the system was developed first, and is related to the mythical bird [Roc](https://en.wikipedia.org/wiki/Roc_%28mythology%29), which allows keeping the bird references from the prior name.[^o34]
