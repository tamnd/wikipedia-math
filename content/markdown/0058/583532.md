# Function type

::: {#o1 .subject cue=lead name="Function type"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science) and [mathematical logic](wikipedia://en/19636), a **function type** (or **arrow type** or **exponential**) is the type of a [variable](https://en.wikipedia.org/wiki/Variable_%28computer_science%29) or [parameter](https://en.wikipedia.org/wiki/Parameter_%28computer_science%29) to which a [function](https://en.wikipedia.org/wiki/Function_%28computer_science%29) has or can be assigned, or an argument or result type of a [higher-order function](https://en.wikipedia.org/wiki/Higher-order_function) taking or returning a function.

:::

A function type depends on the type of the parameters and the result type of the function (it, or more accurately the unapplied [type constructor](wikipedia://en/24047271) `{{nowrap|· → ·}}`, is a [higher-kinded type](https://en.wikipedia.org/wiki/Higher-kinded_type)). In theoretical settings and [programming languages](wikipedia://en/23015) where functions are defined in [curried form](https://en.wikipedia.org/wiki/Curried_form), such as the [simply typed lambda calculus](wikipedia://en/1986011), a function type depends on exactly two types, the [domain](wikipedia://en/50263) *A* and the [range](wikipedia://en/275991) *B*. Here a function type is often denoted $A \to B$, following mathematical convention, or $B^{A}$, based on there existing exactly $B^{A}$ (exponentially many) [set-theoretic functions](wikipedia://en/340630) mappings *A* to *B* in the [category of sets](wikipedia://en/26829). The class of such maps or functions is called the [exponential object](wikipedia://en/2237858). The act of [currying](wikipedia://en/6600) makes the function type [adjoint](https://en.wikipedia.org/wiki/Adjoint_functor) to the [product type](wikipedia://en/14892710); this is explored in detail in the article on currying.

The function type can be considered to be a special case of the [dependent product type](wikipedia://en/1949487#Formal_definition), which among other properties, encompasses the idea of a [polymorphic function](https://en.wikipedia.org/wiki/Polymorphism_%28computer_science%29).

## Programming languages {#Programming_languages}

The syntax used for function types in several programming languages can be summarized, including an example type signature for the higher-order [function composition](https://en.wikipedia.org/wiki/Function_composition_%28computer_science%29) function:

When looking at the example type signature of, for example C#, the type of the function compose is actually `Func<Func<A,B>,Func<B,C>,Func<A,C>>`.

Due to [type erasure](https://en.wikipedia.org/wiki/Type_erasure) in C++11's `std::function`, it is more common to use [templates](https://en.wikipedia.org/wiki/Template_%28C++%29) for [higher order function](https://en.wikipedia.org/wiki/Higher_order_function) parameters and [type inference](wikipedia://en/279690) (`auto`) for [closures](https://en.wikipedia.org/wiki/Closure_%28computer_programming%29).

## Denotational semantics {#Denotational_semantics}

The function type in programming languages does not correspond to the space of all set-theoretic functions. Given the [countably infinite](https://en.wikipedia.org/wiki/Countably_infinite) type of [natural numbers](wikipedia://en/21474) as the domain and the Booleans as range, then there are an [uncountably infinite](https://en.wikipedia.org/wiki/Uncountably_infinite) number (2<sup>ℵ<sub>0</sub></sup> = [c](wikipedia://en/1574901)) of set-theoretic functions between them. Clearly this space of functions is larger than the number of functions that can be defined in any programming language, as there exist only countably many programs (a program being a finite sequence of a finite number of symbols) and one of the set-theoretic functions effectively solves the [halting problem](wikipedia://en/21391870).

[Denotational semantics](wikipedia://en/55275) concerns itself with finding more appropriate models (called [domains](wikipedia://en/325077)) to model programming language concepts such as function types. It turns out that restricting expression to the set of [computable functions](wikipedia://en/1139338) is not sufficient either if the programming language allows writing [non-terminating computations](https://en.wikipedia.org/wiki/Non-terminating_computation) (which is the case if the programming language is [Turing complete](https://en.wikipedia.org/wiki/Turing_complete)). Expression must be restricted to the so-called *[continuous functions](https://en.wikipedia.org/wiki/Continuous_functions#Continuous_functions_between_partially_ordered_sets)* (corresponding to continuity in the [Scott topology](https://en.wikipedia.org/wiki/Scott_topology), not continuity in the real analytical sense). Even then, the set of continuous function contains the *parallel-or* function, which cannot be correctly defined in all programming languages.
