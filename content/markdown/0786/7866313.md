# Crab (cipher)

::: {#o2 .subject cue=lead name="Crab"}

In [cryptography](wikipedia://en/18934432), **Crab** is a [block cipher](wikipedia://en/4594) proposed by [Burt Kaliski](wikipedia://en/9371879) and [Matt Robshaw](wikipedia://en/9213927) at the first [Fast Software Encryption](https://en.wikipedia.org/wiki/Fast_Software_Encryption) workshop in 1993. Not really intended for use, Crab was developed to demonstrate how ideas from [hash functions](wikipedia://en/439526) could be used to create a fast cipher.

:::

Crab has an unusually large [block size](wikipedia://en/294065) of 8192 bits. Its creators suggested using an 80-bit key, but the cipher could use any [key size](wikipedia://en/5749). The authors didn't specify an actual [key schedule](wikipedia://en/609603), only that the key is used to generate two large sets of [subkeys](wikipedia://en/609603): a permutation of the numbers 0 through 255, and an array of 2048 32-bit numbers. The block is divided into 256 32-bit subblocks, which are permuted at the beginning. Then the algorithm makes four passes over the data, each time applying one of four transformations adapted from [MD5](wikipedia://en/18826).

A brief note on the [cryptanalysis](wikipedia://en/5715) of Crab is included in Markku-Juhani Saarinen's paper on block ciphers based on [SHA-1](wikipedia://en/26672) and MD5, published at FSE 2003. The author demonstrates a weakness in Crab that permits a [distinguisher](wikipedia://en/11563117) using no more than a dozen [chosen plaintexts](https://en.wikipedia.org/wiki/Chosen_plaintext_attack), and speculates that this can be converted into a full key-recovery attack using no more than 2<sup>16</sup> chosen plaintexts. Such an attack would depend on the key schedule used.
