# Standard model (cryptography)

::: {#o1 .subject cue=lead name="Standard model"}

In [cryptography](wikipedia://en/18934432) the **standard model** is the model of computation in which the [adversary](wikipedia://en/789126) is only limited by the amount of time and computational power available. Other names used are **bare model** and **plain model**.

:::

Cryptographic schemes are usually based on [complexity assumptions](wikipedia://en/7543), which state that some problems, such as [factorization](wikipedia://en/82341), cannot be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time). Schemes that can be [proven secure](wikipedia://en/1182348) using only complexity assumptions are said to be secure in the standard model. Security proofs are notoriously difficult to achieve in the standard model, so in many proofs, cryptographic primitives are replaced by idealized versions. The most common example of this technique, known as the [random oracle model](https://en.wikipedia.org/wiki/Random_oracle_model),[^o2][^o3] involves replacing a [cryptographic hash function](wikipedia://en/439526) with a genuinely random function. Another example is the [generic group model](https://en.wikipedia.org/wiki/Generic_group_model),[^o4][^o5] where the adversary is given access to a randomly chosen encoding of a [group](wikipedia://en/19447), instead of the [finite field](wikipedia://en/11615) or [elliptic curve groups](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography) used in practice.

Other models used invoke trusted third parties to perform some task without cheating; for example, the [public key infrastructure](wikipedia://en/194112) (PKI) model requires a [certificate authority](wikipedia://en/296370), which if it were dishonest, could produce fake certificates and use them to forge signatures, or mount a [man in the middle attack](https://en.wikipedia.org/wiki/Man_in_the_middle_attack) to read encrypted messages. Other examples of this type are the [common random string model](https://en.wikipedia.org/wiki/Common_random_string_model), where it is assumed that all parties have access to some string chosen uniformly at random, and its generalization, the [common reference string model](wikipedia://en/12022206), where a string is chosen according to some other probability distribution.[^o6] These models are often used for [non-interactive zero-knowledge proofs](wikipedia://en/11589052) (NIZK). In some applications, such as the Dolev–Dwork–Naor encryption scheme,[^o7] it makes sense for a particular party to generate the common reference string, while in other applications, the common reference string must be generated by a trusted third party. Collectively, these models are referred to as models with special setup assumptions.
