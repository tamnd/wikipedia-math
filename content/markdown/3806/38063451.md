# Hash calendar

::: {#o1 .subject cue=lead name="Hash calendar"}

A **hash calendar** is a data structure that is used to measure the passage of time by adding hash values to an append-only database with one hash value per elapsed second. It can be thought of special kind of [Merkle or hash tree](wikipedia://en/2497388), with the property that at any given moment, the tree contains a leaf node for each second since 1970‑01‑01 00:00:00 UTC.

:::

*Image: A hash tree with 8 leaf nodes and a hash calendar after 7 seconds.jpg.* A hash tree with 8 leaf nodes and a hash calendar after 7 seconds

*Image: Hash calendar after 31 seconds.jpg.* Hash calendar after 31 seconds

The leaves are numbered left to right starting from zero and new leaves are always added to the right. By periodically publishing the root of the hash-tree is it possible to use a hash calendar as the basis of a [hash-linking based digital timestamping scheme](https://en.wikipedia.org/wiki/Linked_Timestamping).

## History {#History}

The hash calendar construct was invented by Estonian cryptographers [Ahto Buldas](wikipedia://en/37408676) and Mart Saarepera based on their research on the security properties of [cryptographic hash functions](wikipedia://en/439526) and hash-linking based digital timestamping.[^o3] Their design goal was to remove the need for a trusted third party i.e. that the time of the timestamp should be verifiable independently from the issuer of the timestamp.[^o4]

::: {#o6 .definition kind=definition/construction cue=heading name="Construction of a hash calendar"}

## Construction of a hash calendar {#Construction_of_a_hash_calendar}

There are different algorithms that can be used to build a hash calendar and extract a relevant [hash chain](wikipedia://en/7386159#Binary_hash_chains) per second. The easiest is to imagine the calendar being built in two phases. In the first phase, the leaves are collected into complete binary trees, starting from left, and making each tree as large as possible.

*Image: Sparse hash calendar with 11 10 = 1011 2 leaves.jpg.* Sparse hash calendar with 11<sub>10</sub> = 1011<sub>2</sub> leaves

In the second phase, the multiple unconnected trees are turned into a single tree by merging the roots of the initial trees, but this time starting from the right and adding new parent nodes as needed (red nodes).

*Image: Compact hash calendar with 11 10 = 1011 2 leaves.jpg.* Compact hash calendar with 11<sub>10</sub> = 1011<sub>2</sub> leaves.

The hash chains can then be extracted as from any hash tree. Since the hash calendar is built in a deterministic manner, the shape of the tree for any moment can be reconstructed knowing just the number of leaf nodes in the tree at that moment, which is one more than the number of seconds from 1970‑01‑01 00:00:00 UTC to that moment. Therefore, given the time when the calendar tree was created and a hash chain extracted from it, the time value corresponding to each leaf node can be computed.

:::

## Distributed hash calendar {#Distributed_hash_calendar}

The Distributed hash calendar is a distributed network of hash calendar nodes. In order to ensure a high availability service, it is possible to have multiple calendars in different physical locations all of which communicate with each other to ensure that each calendar contains identical hash values. Ensuring that the calendars remain in agreement is a form of [Byzantine fault tolerance](https://en.wikipedia.org/wiki/Byzantine_generals)

To the right a 5 node calendar cluster is shown where each node communicates with every other node in the cluster, and there is no single point of failure. Although each node has a clock, the clock is not used for setting the time directly but as a metronome to ensure that the nodes “beat” at the same time.

::: {#o9 .application cue=heading name="Applications"}

## Applications {#Applications}

A five node hash calendar cluster is a component of Keyless Signature Infrastructure (KSI), each leaf in the hash calendar being the aggregate hash value of a globally distributed hash tree.
