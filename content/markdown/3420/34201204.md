# Alias method

::: {#o1 .subject cue=lead name="Alias method"}

*Image: Alias Table.png.* A diagram of an alias table that represents the probability distribution〈0.25, 0.3, 0.1, 0.2, 0.15〉

In [computing](https://en.wikipedia.org/wiki/Computing), the **alias method** is a family of efficient [algorithms](wikipedia://en/775) for [sampling from a discrete probability distribution](wikipedia://en/31693124), published in 1974 by Alastair J. Walker.[^o2][^o3] That is, it returns integer values $1 \le i \le n$ according to some arbitrary [discrete probability distribution](https://en.wikipedia.org/wiki/Discrete_probability_distribution) $p_{i}$. The algorithms typically use $O(n \log n)$ or $O(n)$ preprocessing time, after which random values can be drawn from the distribution in $O(1)$ time.[^o4]

:::

## Operation {#Operation}

Internally, the algorithm consults two tables, a *[probability](wikipedia://en/22934) [table](https://en.wikipedia.org/wiki/Table_%28information%29)* $U_{i}$ and an *alias table* $K_{i}$ (for $1 \le i \le n$). To generate a random outcome, a fair [die](https://en.wikipedia.org/wiki/Dice) is rolled to determine an index $i$ into the two tables. A [biased coin](https://en.wikipedia.org/wiki/Biased_coin) is then flipped, choosing a result of $i$ with probability $U_{i}$, or $K_{i}$ otherwise (probability $1 - U_{i}$).[^o6]

More concretely, the algorithm operates as follows:

1. Generate a [uniform](https://en.wikipedia.org/wiki/Uniform_distribution_%28continuous%29) [random variate](https://en.wikipedia.org/wiki/Random_variate) $0 \le x < 1$.
1. Let $i = \lfloor nx\rfloor + 1$ and $y = nx + 1 - i$. (This makes $i$ uniformly distributed on $\{1, 2, ..., n\}$ and $y$ uniformly distributed on $[0, 1)$.)
1. If $y < U_{i}$, return $i$. This is the biased coin flip.
1. Otherwise, return $K_{i}$.

An alternative formulation of the probability table, proposed by Marsaglia et al.[^o7] as the **square histogram method**, avoids the computation of $y$ by instead checking the condition $x < V_{i} = (U_{i} + i - 1)/n$ in the third step.

## Table generation {#Table_generation}

The distribution may be padded with additional probabilities $p_{i} = 0$ to increase $n$ to a convenient value, such as a [power of two](wikipedia://en/376948).

To generate the two tables, first initialize $U_{i} = np_{i}$. While doing this, divide the table entries into three categories:

- The "overfull" group, where $U_{i} > 1$,
- The "underfull" group, where $U_{i} < 1$ and $K_{i}$ has not been initialized, and
- The "exactly full" group, where $U_{i} = 1$ or $K_{i}$ *has* been initialized.

If $U_{i} = 1$, the corresponding value $K_{i}$ will never be consulted and is unimportant, but a value of $K_{i} = i$ is sensible. This also avoids problems if the probabilities are represented as [fixed-point numbers](https://en.wikipedia.org/wiki/Fixed-point_number) which cannot represent $U_{i} = 1$ exactly.

As long as not all table entries are exactly full, repeat the following steps:

1. Arbitrarily choose an overfull entry $U_{i} > 1$ and an underfull entry $j$ with $1 - U_{j} \le U_{i} - 1$. (If one of these exists, the other must, as well.)
1. Allocate all unused space in entry $j$ to outcome $i$, by setting $K_{j} \leftarrow i$.
1. Remove the allocated space from entry $i$ by changing $U_{i} \leftarrow U_{i} - (1 - U_{j}) = U_{i} + U_{j} - 1$.
1. Entry $j$ is now exactly full.
1. Assign entry $i$ to the appropriate category based on the new value of $U_{i}$.

Each iteration moves at least one entry to the "exactly full" category (and the last moves two), so the procedure is guaranteed to terminate after at most $n\,-1$ iterations. Each iteration can be done in $O(1)$ time, so the table can be set up in $O(n)$ time.

Vose[^o4] points out that floating-point rounding errors may cause the guarantee referred to in step 1 to be violated. If one category empties before the other, the remaining entries may have $U_{i}$ set to 1 with negligible error. The solution accounting for floating point is sometimes called the **Walker-Vose method** or the **Vose alias method**.

Because of the arbitrary choice in step 1, the alias structure is not unique.

As the lookup procedure is slightly faster if $y < U_{i}$ (because $K_{i}$ does not need to be consulted), one goal during table generation is to maximize the sum of the $U_{i}$. Doing this optimally turns out to be [NP hard](https://en.wikipedia.org/wiki/NP_hard),[^o7] but a [greedy algorithm](wikipedia://en/89247) comes reasonably close: rob from the richest and give to the poorest. That is, at each step choose the largest $U_{i}$ and the smallest $U_{j}$. Because this requires sorting the $U_{i}$, it requires $O(n \log n)$ time.

## Efficiency {#Efficiency}

Although the alias method is very efficient if generating a uniform deviate is itself fast, there are cases where it is far from optimal in terms of random bit usage. This is because it uses a full-precision random variate $x$ each time, even when only a few random bits are needed.

One case arises when the probabilities are particularly well balanced, so many $U_{i} = 1$. For these values of $i$, $K_{i}$ is not needed and generating $y$ is a waste of time. For example if $p_{1} = p_{2} = \tfrac{1}{2}$, then a 32-bit random variate $x$ could be used to generate 32 outputs, but the alias method will only generate one.

Another case arises when the probabilities are strongly unbalanced, so many $U_{i} \approx 0$. For example if $p_{1} = 0.999$ and $p_{2} = 0.001$, then the great majority of the time, only a few random bits are required to determine that case 1 applies. In such cases, the table method described by Marsaglia et al.p. 1–4 is more efficient. If we make many choices with the same probability we can on average require much less than one unbiased random bit. Using [arithmetic coding](wikipedia://en/62545) techniques arithmetic we can approach the limit given by the [binary entropy function](wikipedia://en/5275277).
