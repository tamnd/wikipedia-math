# Estrin's scheme

::: {#o1 .subject cue=lead name="Estrin's scheme"}

In [numerical analysis](wikipedia://en/21506), **Estrin's scheme** (after [Gerald Estrin](https://en.wikipedia.org/wiki/Gerald_Estrin)), also known as **Estrin's method**, is an [algorithm](wikipedia://en/775) for numerical [evaluation of polynomials](wikipedia://en/64691694).

:::

[Horner's method](wikipedia://en/14263) for evaluation of polynomials is one of the most commonly used algorithms for this purpose, and unlike Estrin's scheme it is optimal in the sense that it minimizes the number of multiplications and additions required to evaluate an arbitrary polynomial. However, each operation depends on the previous one, so it cannot take advantage of modern processors' ability to perform multiple independent operations in parallel. Estrin's scheme is one method which attempts to overcome this serialization while still being reasonably close to optimal.

## Description of the algorithm {#Description_of_the_algorithm}

Estrin's scheme operates [recursively](wikipedia://en/4044867), converting a degree-*n* polynomial in *x* (for *n*≥2) to a degree-$\lfloor n/2\rfloor$ polynomial in *x*<sup>2</sup> using $\lceil n/2\rceil$ independent operations (plus one to compute *x*<sup>2</sup>).

Given an arbitrary polynomial *P*(*x*) = *C*<sub>0</sub> + *C*<sub>1</sub>*x* + *C*<sub>2</sub>*x*<sup>2</sup> + *C*<sub>3</sub>*x*<sup>3</sup> + ⋯ + *C<sub>n</sub>x<sup>n</sup>*, one can group adjacent terms into sub-expressions of the form (*A* + *Bx*) and rewrite it as a polynomial in *x*<sup>2</sup>: *P*(*x*) = (*C*<sub>0</sub> + *C*<sub>1</sub>*x*) + (*C*<sub>2</sub> + *C*<sub>3</sub>*x*)*x*<sup>2</sup> + (*C*<sub>4</sub> + *C*<sub>5</sub>*x*)*x*<sup>4</sup> + ⋯ = *Q*(*x*<sup>2</sup>).

Each of these sub-expressions, and *x*<sup>2</sup>, may be computed in parallel. They may also be evaluated using a native [multiply–accumulate](https://en.wikipedia.org/wiki/Multiply–accumulate) instruction on some architectures, an advantage that is shared with Horner's method.

This grouping can then be repeated to get a polynomial in *x*<sup>4</sup>: *P*(*x*) = *Q*(*x*<sup>2</sup>) = ((*C*<sub>0</sub> + *C*<sub>1</sub>*x*) + (*C*<sub>2</sub> + *C*<sub>3</sub>*x*)*x*<sup>2</sup>) + ((*C*<sub>4</sub> + *C*<sub>5</sub>*x*) + (*C*<sub>6</sub> + *C*<sub>7</sub>*x*)*x*<sup>2</sup>)*x*<sup>4</sup> + ⋯ = *R*(*x*<sup>4</sup>).

Repeating this $\lfloor \log_{2}n\rfloor$+1 times, one arrives at Estrin's scheme for parallel evaluation of a polynomial:

1. Compute *D<sub>i</sub>* = *C*<sub>2*i*</sub> + *C*<sub>2*i*+1</sub>*x* for all 0 ≤ *i* ≤ $\lfloor n/2\rfloor$. (If *n* is even, then *C*<sub>*n*+1</sub> = 0 and *D*<sub>*n*/2</sub> = *C<sub>n</sub>*.)
1. If *n* ≤ 1, the computation is complete and *D*<sub>0</sub> is the final answer.
1. Otherwise, compute *y* = *x*<sup>2</sup> (in parallel with the computation of *D<sub>i</sub>*).
1. Evaluate *Q*(*y*) = *D*<sub>0</sub> + *D*<sub>1</sub>*y* + *D*<sub>2</sub>*y*<sup>2</sup> + ⋯ + *D*<sub>$\lfloor n/2\rfloor$</sub>*y*<sup>$\lfloor n/2\rfloor$</sup> using Estrin's scheme.

This performs a total of *n* multiply-accumulate operations (the same as Horner's method) in line 1, and an additional $\lfloor \log_{2}n\rfloor$ squarings in line 3. In exchange for those extra squarings, all of the operations in each level of the scheme are independent and may be computed in parallel; the longest dependency path is $\lfloor \log_{2}n\rfloor$+1 operations long. A similar idea[^o3] enables a [fast matrix multiplication algorithm](wikipedia://en/24107400) to evaluate a polynomial at a series of points.

### In combination with Horner's method {#In_combination_with_Horner's_method}

Estrin's full scheme uses a very large number of [multiply–accumulate operations](https://en.wikipedia.org/wiki/Multiply–accumulate_operation) in the first step. While this is useful to fully exploit modern [superscalar processors](https://en.wikipedia.org/wiki/Superscalar_processor), it will eventually exceed the available computing resources, at which point it may be useful to use Estrin's scheme to a limited depth, and then Horner's method on the residual.

For example, if a computer can perform four multiply-accumulate operations before the result of the first operation is available, then two levels of Estrin's scheme will keep its [instruction pipeline](https://en.wikipedia.org/wiki/Instruction_pipeline) full. Each iteration, it can perform the following operations in parallel:

**Level 1:** (Estrin) Compute *D*<sub>2*i*</sub> = *C*<sub>4*i*</sub> + *C*<sub>4*i*+1</sub>*x* and *D*<sub>2*i*+1</sub> = *C*<sub>4*i*+2</sub> + *C*<sub>4*i*+3</sub>*x*

**Level 2:** (Estrin) Compute *E*<sub>*i*+1</sub> = *D*<sub>2*i*+2</sub> + *D*<sub>2*i*+3</sub>*x*<sup>2</sup>

**Level 3:** (Horner) Compute *F*<sub>*i*+2</sub> = *E*<sub>*i*+2</sub> + *F*<sub>*i*+3</sub>*x*<sup>4</sup>

The final result is *F*<sub>0</sub>.

A more capable processor may be able to have four 4-operand [SIMD](https://en.wikipedia.org/wiki/SIMD) operations in progress at once, in which case four levels of Estrin's scheme could be used to evaluate a sufficiently high-degree polynomial.
