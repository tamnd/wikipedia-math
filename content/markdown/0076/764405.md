# Turing degree

::: {#o1 .subject cue=lead name="Turing degree"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science) and [mathematical logic](wikipedia://en/19636) the **Turing degree** (named after [Alan Turing](wikipedia://en/1208)) or **degree of unsolvability** of a set of [natural numbers](wikipedia://en/21474) measures the level of algorithmic unsolvability of the set.

:::

## Overview {#Overview}

The concept of Turing degree is fundamental in [computability theory](wikipedia://en/155414), where sets of natural numbers are often regarded as [decision problems](wikipedia://en/8336). The Turing degree of a set is a measure of how difficult it is to solve the decision problem associated with the set, that is, to determine whether an arbitrary number is in the given set.

Two sets are **Turing equivalent** if they have the same level of unsolvability; each Turing degree is a collection of Turing equivalent sets, so that two sets are in different Turing degrees exactly when they are not Turing equivalent. Furthermore, the Turing degrees are [partially ordered](https://en.wikipedia.org/wiki/Partial_order), so that if the Turing degree of a set *X* is less than the Turing degree of a set *Y*, then any (possibly noncomputable) procedure that correctly decides whether numbers are in *Y* can be effectively converted to a procedure that correctly decides whether numbers are in *X*. It is in this sense that the Turing degree of a set corresponds to its level of algorithmic unsolvability.

The Turing degrees were introduced by (Post 1944) and many fundamental results were established by (Kleene Post 1954). The Turing degrees have been an area of intense research since then. Many proofs in the area make use of a proof technique known as the **priority method**.

## Turing equivalence {#Turing_equivalence}

For the rest of this article, the word *set* will refer to a set of natural numbers. A set *X* is said to be **[Turing reducible](https://en.wikipedia.org/wiki/Turing_reducible)** to a set *Y* if there is an [oracle Turing machine](https://en.wikipedia.org/wiki/Oracle_Turing_machine) that decides membership in *X* when given an oracle for membership in *Y*. The notation *X* ≤<sub>T</sub> *Y* indicates that *X* is Turing reducible to *Y*.

Two sets *X* and *Y* are defined to be **Turing equivalent** if *X* is Turing reducible to *Y* and *Y* is Turing reducible to *X*. The notation *X* ≡<sub>T</sub> *Y* indicates that *X* and *Y* are Turing equivalent. The relation ≡<sub>T</sub> can be seen to be an [equivalence relation](wikipedia://en/9259), which means that for all sets *X*, *Y*, and *Z*:

- *X* ≡<sub>T</sub> *X*
- *X* ≡<sub>T</sub> *Y* implies *Y* ≡<sub>T</sub> *X*
- If *X* ≡<sub>T</sub> *Y* and *Y* ≡<sub>T</sub> *Z* then *X* ≡<sub>T</sub> *Z*.

A **Turing degree** is an [equivalence class](wikipedia://en/9260) of the relation ≡<sub>T</sub>. The notation \[*X*\] denotes the equivalence class containing a set *X*. The entire collection of Turing degrees is denoted $\mathcal{D}$.

The Turing degrees have a [partial order](https://en.wikipedia.org/wiki/Partial_order) ≤ defined so that \[*X*\] ≤ \[*Y*\] [if and only if](wikipedia://en/14922) *X* ≤<sub>T</sub> *Y*. There is a unique Turing degree containing all the [computable sets](wikipedia://en/332264), and this degree is less than every other degree. It is denoted **0** (zero) because it is the least element of the poset $\mathcal{D}$. (It is common to use boldface notation for Turing degrees, in order to distinguish them from sets. When no confusion can occur, such as with \[*X*\], the boldface is not necessary.)

For any sets *X* and *Y*, the set *X* **join** *Y*, written *X* ⊕ *Y*, is defined to be the union of the sets {2*n* : *n* ∈ *X* } and {2*m*+1 : *m* ∈ *Y*}. The Turing degree of *X* ⊕ *Y* is the [least upper bound](https://en.wikipedia.org/wiki/Join_%28mathematics%29) of the degrees of *X* and *Y*. Thus $\mathcal{D}$ is a [join-semilattice](https://en.wikipedia.org/wiki/Join-semilattice). The least upper bound of degrees **a** and **b** is denoted **a** ∪ **b**. It is known that $\mathcal{D}$ is not a [lattice](wikipedia://en/469304), as there are pairs of degrees with no greatest lower bound.

For any set *X* the notation *X*′ denotes the set of [indices](https://en.wikipedia.org/wiki/Admissible_numbering) of oracle machines that halt (when given their index as input) when using *X* as an oracle. The set *X*′ is called the **[Turing jump](wikipedia://en/1681091)** of *X*. The Turing jump of a degree \[*X*\] is defined to be the degree \[*X*′\]; this is a valid definition because *X*′ ≡<sub>T</sub> *Y*′ whenever *X* ≡<sub>T</sub> *Y*. A key example is **0**′, the degree of the [halting problem](wikipedia://en/21391870).

## Basic properties of the Turing degrees {#Basic_properties_of_the_Turing_degrees}

- Every Turing degree is [countably infinite](https://en.wikipedia.org/wiki/Countably_infinite), that is, it contains exactly $\aleph_0$ sets.
- There are $2^{\aleph_0}$ distinct Turing degrees.
- For each degree **a** the strict inequality **a** \< **a**′ holds.
- For each degree **a**, the set of degrees below **a** is [countable](wikipedia://en/6026). The set of degrees greater than **a** has size $2^{\aleph_0}$.

## Structure of the Turing degrees {#Structure_of_the_Turing_degrees}

A great deal of research has been conducted into the structure of the Turing degrees. The following survey lists only some of the many known results. One general conclusion that can be drawn from the research is that the structure of the Turing degrees is extremely complicated.

### Order properties {#Order_properties}

- There are **minimal degrees**. A degree **a** is *minimal* if **a** is nonzero and there is no degree between **0** and **a**. Thus the order relation on the degrees is not a [dense order](wikipedia://en/6320997).
- The Turing degrees are not linearly ordered by ≤<sub>T</sub>.[^n1]
- In fact, for every nonzero degree **a** there is a degree **b** incomparable with **a**.
- There is a set of $2^{\aleph_0}$ pairwise incomparable Turing degrees.
- There are pairs of degrees with no greatest lower bound. Thus $\mathcal{D}$ is not a [lattice](wikipedia://en/469304).
- Every countable partially ordered set can be [embedded](wikipedia://en/762203) in the Turing degrees.
- An infinite strictly increasing sequence **a**<sub>1</sub>, **a**<sub>2</sub>, ... of Turing degrees cannot have a least upper bound, but it always has an *exact pair* **c**, **d** such that $\forall\mathbf{e} (\mathbf{e}<\mathbf{c}\land\mathbf{e}<\mathbf{d} \Leftrightarrow \exists i \mathbf{e}\le\mathbf{a}_{i})$ (and thus it has upper bounds).
- Assuming the [axiom of constructibility](wikipedia://en/696472), it can be shown there is a maximal [chain](https://en.wikipedia.org/wiki/Chain_%28order_theory%29) of degrees of order type $\omega_1$.[^n2]

### Properties involving the jump {#Properties_involving_the_jump}

- For every degree **a** there is a degree strictly between **a** and **a**′. In fact, there is a countably infinite family of pairwise incomparable degrees between **a** and **a**′.
- Jump inversion: a degree **a** is of the form **b**′ if and only if **0**′ ≤ **a**.
- For any degree **a** there is a degree **b** such that **a** \< **b** and **b**′ = **a**′; such a degree **b** is called *low* relative to **a**.
- There is an infinite sequence **a**<sub>*i*</sub> of degrees such that **a**′<sub>*i*+1</sub> ≤ **a**<sub>*i*</sub> for each *i*.
- [Post's theorem](wikipedia://en/764468) establishes a close correspondence between the [arithmetical hierarchy](wikipedia://en/186475) and finitely iterated Turing jumps of the [empty set](wikipedia://en/9566).

### Logical properties {#Logical_properties}

- (Simpson 1977b) showed that the [first-order theory](https://en.wikipedia.org/wiki/First-order_theory) of $\mathcal{D}$ in the language ⟨ ≤, = ⟩ or ⟨ ≤, ′, = ⟩ is [many-one equivalent](wikipedia://en/362983) to the theory of [true second-order arithmetic](wikipedia://en/22156658#True_theory_of_second-order_arithmetic). This indicates that the structure of $\mathcal{D}$ is extremely complicated.
- (Shore Slaman 1999) showed that the jump operator is definable in the first-order structure of $\mathcal{D}$ with the language ⟨ ≤, = ⟩.

## Recursively enumerable Turing degrees {#Recursively_enumerable_Turing_degrees}

*Image: Rehasse.png.* A finite lattice that can't be embedded in the r.e. degrees.

A degree is called *recursively enumerable* (r.e.) or *computably enumerable* (c.e.) if it contains a [recursively enumerable set](https://en.wikipedia.org/wiki/Recursively_enumerable_set). Every r.e. degree is below **0**′, but not every degree below **0**′ is r.e.. However, a set $A$ is many-one reducible to **0**′ if and only if $A$ is r.e..[^n3]

- (Sacks 1964): The r.e. degrees are dense; between any two r.e. degrees there is a third r.e. degree.
- (Lachlan 1966a) and (Yates 1966): There are two r.e. degrees with no greatest lower bound in the r.e. degrees.
- (Lachlan 1966a) and (Yates 1966): There is a pair of nonzero r.e. degrees whose greatest lower bound is **0**.
- (Lachlan 1966b): There is no pair of r.e. degrees whose greatest lower bound is **0** and whose least upper bound is **0**′. This result is informally called the *nondiamond theorem*.
- (Thomason 1971): Every finite [distributive lattice](wikipedia://en/310883) can be embedded into the r.e. degrees. In fact, the countable [atomless](wikipedia://en/998824) [Boolean algebra](wikipedia://en/54476844) can be embedded in a manner that preserves [suprema and infima](wikipedia://en/39382).
- (Lachlan Soare 1980): Not all finite [lattices](wikipedia://en/469304) can be embedded in the r.e. degrees (via an embedding that preserves suprema and infima). A particular example is shown to the right.
- [L. A. Harrington](wikipedia://en/5693354) and [T. A. Slaman](wikipedia://en/5693320) (see (Nies Shore Slaman 1998)): The first-order theory of the r.e. degrees in the language ⟨ **0**, ≤, = ⟩ is many-one equivalent to the theory of [true first-order arithmetic](wikipedia://en/22156658).

Additionally, there is Shoenfield's limit lemma, a set *A* satisfies $[A]\leq_T \emptyset'$ if and only if there is a "recursive approximation" to its characteristic function: a function *g* such that for sufficiently large *s*, $g(s)=\chi_A(s)$.[^n4]

A set *A* is called *n*-r e. if there is a family of functions $(A_s)_{s\in\mathbb N}$ such that:[^n4]

- *A*<sub>*s*</sub> is a recursive approximation of *A*: for some *t*, for any *s*≥*t* we have *A*<sub>*s*</sub>(*x*) = *A*(*x*), in particular conflating *A* with its characteristic function. *(Removing this condition yields a definition of* A *being* "weakly *n*-r.e."*)*
- *A*<sub>*s*</sub> is an "*n*-trial predicate": for all *x*, *A*<sub>0</sub>(*x*)=0 and the cardinality of $\{s\mid A_s(x)\neq A_{s+1}(x)\}$ is ≤*n*.

Properties of *n*-r.e. degrees:[^n4]

- The class of sets of *n*-r.e. degree is a strict subclass of the class of sets of (*n*+1)-r.e. degree.
- For all *n*>1 there are two (*n*+1)-r.e. degrees **a**, **b** with $\mathbf a\leq_T\mathbf b$, such that the segment $\{\mathbf c\mid\mathbf a\leq_T\mathbf c\leq_T\mathbf b\}$ contains no *n*-r.e. degrees.
- $A$ and $\overline A$ are (*n*+1)-r.e. if and only if both sets are weakly-*n*-r.e.

## Post's problem and the priority method {#Post's_problem_and_the_priority_method}

[Emil Post](https://en.wikipedia.org/wiki/Emil_Post) studied the r.e. Turing degrees and asked whether there is any r.e. degree strictly between **0** and **0**′. The problem of constructing such a degree (or showing that none exist) became known as **Post's problem**. This problem was solved independently by [Friedberg](https://en.wikipedia.org/wiki/Richard_M._Friedberg) and [Muchnik](wikipedia://en/22647091) in the 1950s, who showed that these intermediate r.e. degrees do exist ([Friedberg–Muchnik theorem](wikipedia://en/61969687)). Their proofs each developed the same new method for constructing r.e. degrees, which came to be known as the **priority method**. The priority method is now the main technique for establishing results about r.e. sets.

The idea of the priority method for constructing an r.e. set *X* is to list a countable sequence of *requirements* that *X* must satisfy. For example, to construct an r.e. set *X* between **0** and **0**′ it is enough to satisfy the requirements *A<sub>e</sub>* and *B<sub>e</sub>* for each natural number *e*, where *A<sub>e</sub>* requires that the oracle machine with index *e* does not compute 0′ from *X* and *B<sub>e</sub>* requires that the Turing machine with index *e* (and no oracle) does not compute *X*. These requirements are put into a *priority ordering*, which is an explicit [bijection](wikipedia://en/3942) of the requirements and the natural numbers. The proof proceeds inductively with one stage for each natural number; these stages can be thought of as steps of time during which the set *X* is enumerated. At each stage, numbers may be put into *X* or forever (if not injured) prevented from entering *X* in an attempt to *satisfy* requirements (that is, force them to hold once all of *X* has been enumerated). Sometimes, a number can be enumerated into *X* to satisfy one requirement but doing this would cause a previously satisfied requirement to become unsatisfied (that is, to be *injured*). The priority order on requirements is used to determine which requirement to satisfy in this case. The informal idea is that if a requirement is injured then it will eventually stop being injured after all higher priority requirements have stopped being injured, although not every priority argument has this property. An argument must be made that the overall set *X* is r.e. and satisfies all the requirements. Priority arguments can be used to prove many facts about r.e. sets; the requirements used and the manner in which they are satisfied must be carefully chosen to produce the required result.

For example, a [simple](wikipedia://en/2451294) (and hence noncomputable r.e.) [low](wikipedia://en/9767106) *X* (low means *X*′=0′) can be constructed in infinitely many stages as follows. At the start of stage *n*, let *T*<sub>*n*</sub> be the output (binary) tape, identified with the set of cell indices where we placed 1 so far (so $X=\cup_{n} T_{n}; T_{0}=\emptyset)$; and let *P*<sub>*n*</sub>(*m*) be the priority for not outputting 1 at location *m*; $P_{0}(m)=\infty$. At stage *n*, if possible (otherwise do nothing in the stage), pick the least *i*\<*n* such that $\forall m P_{n}(m)\ne i$ and Turing machine *i* halts in \<*n* steps on some input $S\supseteq T_{n}$ with $\forall m\in S\backslash T_{n} P_{n}(m)\ge i$. Choose any such (finite) *S*, set *T*<sub>*n*+1</sub>=*S*, and for every cell *m* visited by machine *i* on *S*, set *P*<sub>*n*+1</sub>(*m*) = min(*i*, *P*<sub>*n*</sub>(*m*)), and set all priorities >*i* to ∞, and then set one priority ∞ cell (any will do) not in *S* to priority *i*. Essentially, we make machine *i* halt if we can do so without upsetting priorities \<*i*, and then set priorities to prevent machines >*i* from disrupting the halt; all priorities are eventually constant.

To see that *X* is low, machine *i* halts on *X* if and only if it halts in \<*n* steps on some *T*<sub>*n*</sub> such that machines \<*i* that halt on *X* do so \<*n*−*i* steps (by recursion, this is uniformly computable from 0′). *X* is noncomputable since otherwise a Turing machine could halt on *Y* if and only if $Y\backslash X$ is nonempty, contradicting the construction since *X* excludes some priority *i* cells for arbitrarily large *i*; and *X* is simple because for each *i* the number of priority *i* cells is finite.
