# System F

::: {#o1 .subject cue=lead name="System F"}

**System F** (also **polymorphic lambda calculus** or **second-order lambda calculus**) is a [typed lambda calculus](wikipedia://en/366208) that introduces, to [simply typed lambda calculus](wikipedia://en/1986011), a mechanism of [universal quantification](wikipedia://en/76174) over types. System F formalizes [parametric polymorphism](https://en.wikipedia.org/wiki/Parametric_polymorphism) in [programming languages](wikipedia://en/23015), thus forming a theoretical basis for languages such as [Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29) and [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29). It was discovered independently by [logician](https://en.wikipedia.org/wiki/Logician) [Jean-Yves Girard](wikipedia://en/579673) (1972) and [computer scientist](https://en.wikipedia.org/wiki/Computer_scientist) [John C. Reynolds](https://en.wikipedia.org/wiki/John_C._Reynolds).

:::

Whereas [simply typed lambda calculus](wikipedia://en/1986011) has variables ranging over terms, and binders for them, System F additionally has variables ranging over *types*, and binders for them. As an example, the fact that the [identity function](wikipedia://en/15069) can have any type of the form *A* → *A* would be formalized in System F as the statement

$$\vdash \Lambda\alpha. \lambda x^\alpha.x: \forall\alpha.\alpha \to \alpha$$

where $\alpha$ is a [type variable](https://en.wikipedia.org/wiki/Type_variable). The upper-case $\Lambda$ is traditionally used to denote type-level functions, as opposed to the lower-case $\lambda$ which is used for value-level functions. (The superscripted $\alpha$ means that the bound variable *x* is of type $\alpha$; the expression after the colon is the type of the lambda expression preceding it.)

As a [term rewriting system](https://en.wikipedia.org/wiki/Term_rewriting_system), System F is [strongly normalizing](https://en.wikipedia.org/wiki/Normalization_property_%28lambda-calculus%29). However, [type inference](wikipedia://en/279690) in System F (without explicit type annotations) is [undecidable](wikipedia://en/15631055). Under the [Curry–Howard isomorphism](https://en.wikipedia.org/wiki/Curry–Howard_isomorphism), System F corresponds to [second-order propositional intuitionistic logic](wikipedia://en/23454734). System F can be seen as part of the [lambda cube](wikipedia://en/901593), together with even more expressive typed lambda calculi, including those with [dependent types](https://en.wikipedia.org/wiki/Dependent_types).

According to Girard, the "F" in *System F* was picked by chance.[^o2]

## Typing rules {#Typing_rules}

The typing rules of System F are those of simply typed lambda calculus with the addition of the following:

| ${\frac{\Gamma\vdash M : \forall\alpha.\sigma}{\Gamma\vdash M\tau : \sigma[\tau/\alpha]} }$ (1) | ${\frac{\Gamma,\alpha~\text{type}\vdash M : \sigma}{\Gamma\vdash\Lambda\alpha.M : \forall\alpha.\sigma}}$ (2) |
|---|---|

where $\sigma, \tau$ are types, $\alpha$ is a type variable, and $\alpha~\text{type}$ in the context indicates that $\alpha$ is bound. The first rule is that of application, and the second is that of abstraction.[^o4][^o5]

## Logic and predicates {#Logic_and_predicates}

The $\mathsf{Boolean}$ type is defined as: $\forall\alpha.\alpha \to \alpha \to \alpha$, where $\alpha$ is a [type variable](https://en.wikipedia.org/wiki/Type_variable). This means: $\mathsf{Boolean}$ is the type of all functions which take as input a type α and two expressions of type α, and produce as output an expression of type α (note that we consider $\to$ to be [right-associative](https://en.wikipedia.org/wiki/Right-associative).)

The following two definitions for the Boolean values $\mathbf{T}$ and $\mathbf{F}$ are used, extending the definition of [Church Booleans](wikipedia://en/2989409#Church_Booleans):

$$\mathbf{T} = \Lambda\alpha{.}\lambda x^{\alpha} \lambda y^\alpha{.}x$$

$$\mathbf{F} = \Lambda\alpha{.}\lambda x^{\alpha} \lambda y^{\alpha}{.}y$$

(Note that the above two functions require *three* — not two — arguments. The latter two should be lambda expressions, but the first one should be a type. This fact is reflected in the fact that the type of these expressions is $\forall\alpha.\alpha \to \alpha \to \alpha$; the universal quantifier binding the α corresponds to the Λ binding the alpha in the lambda expression itself. Also, note that $\mathsf{Boolean}$ is a convenient shorthand for $\forall\alpha.\alpha \to \alpha \to \alpha$, but it is not a symbol of System F itself, but rather a "meta-symbol". Likewise, $\mathbf{T}$ and $\mathbf{F}$ are also "meta-symbols", convenient shorthands, of System F "assemblies" (in the [Bourbaki sense](https://books.google.com/books?id=IL-SI67hjI4C&q=Nicolas+Bourbaki)); otherwise, if such functions could be named (within System F), then there would be no need for the lambda-expressive apparatus capable of defining functions anonymously and for the [fixed-point combinator](wikipedia://en/150287), which works around that restriction.)

Then, with these two $\lambda$-terms, we can define some logic operators (which are of type $\mathsf{Boolean} \rightarrow \mathsf{Boolean} \rightarrow \mathsf{Boolean}$):

$$\begin{aligned} \mathrm{AND} &= \lambda x^{\mathsf{Boolean}} \lambda y^{\mathsf{Boolean}}{.} x \, \mathsf{Boolean} \, y\, \mathbf{F}\\ \mathrm{OR} &= \lambda x^{\mathsf{Boolean}} \lambda y^{\mathsf{Boolean}}{.} x \, \mathsf{Boolean} \, \mathbf{T}\, y\\ \mathrm{NOT} &= \lambda x^{\mathsf{Boolean}}{.} x \, \mathsf{Boolean} \, \mathbf{F}\, \mathbf{T} \end{aligned}$$

Note that in the definitions above, $\mathsf{Boolean}$ is a type argument to $x$, specifying that the other two parameters that are given to $x$ are of type $\mathsf{Boolean}$. As in Church encodings, there is no need for an IFTHENELSE function as one can just use raw $\mathsf{Boolean}$-typed terms as decision functions. However, if one is requested:

$$\mathrm{IFTHENELSE} = \Lambda \alpha.\lambda x^{\mathsf{Boolean}}\lambda y^{\alpha}\lambda z^{\alpha}. x \alpha y z$$

will do. A *predicate* is a function which returns a $\mathsf{Boolean}$-typed value. The most fundamental predicate is ISZERO which returns $\mathbf{T}$ if and only if its argument is the [Church numeral](wikipedia://en/2989409#Church_numerals) 0:

$$\mathrm{ISZERO} = \lambda n^{\forall \alpha. (\alpha \rightarrow \alpha) \rightarrow \alpha \rightarrow \alpha}{.}n \, \mathsf{Boolean} \, (\lambda x^{\mathsf{Boolean}}{.}\mathbf{F})\, \mathbf{T}$$

Furthermore, the [existential quantifier](https://en.wikipedia.org/wiki/Existential_quantifier) (and therefore existential types) can be implemented in system F by the following:[^o7][^o8]

$$\exists X. A = \forall Y. (\forall X. A \rightarrow Y) \rightarrow Y$$

## System F structures {#System_F_structures}

System F allows recursive constructions to be embedded in a natural manner, related to that in [Martin-Löf's type theory](https://en.wikipedia.org/wiki/Martin-Löf's_type_theory). Abstract structures ($S$) are created using *constructors*. These are functions typed as:

$$K_1\rightarrow K_2\rightarrow\dots\rightarrow S.$$

Recursivity is manifested when $S$ itself appears within one of the types $K_i$. If you have $m$ of these constructors, you can define the type of $S$ as:

$$\forall \alpha.(K_1^1[\alpha/S]\rightarrow\dots\rightarrow \alpha)\dots\rightarrow(K_1^m[\alpha/S]\rightarrow\dots\rightarrow \alpha)\rightarrow \alpha$$

For instance, the natural numbers can be defined as an inductive datatype $N$ with constructors

$$\begin{aligned} \mathit{zero} &: \mathrm{N}\\ \mathit{succ} &: \mathrm{N} \rightarrow \mathrm{N} \end{aligned}$$

The System F type corresponding to this structure is $\forall \alpha. \alpha \to (\alpha \to \alpha) \to \alpha$. The terms of this type comprise a typed version of the [Church numerals](https://en.wikipedia.org/wiki/Church_numeral), the first few of which are:

$$\begin{aligned} 0 &:= \Lambda \alpha . \lambda x^\alpha . \lambda f^{\alpha\to\alpha} . x\\ 1 &:= \Lambda \alpha . \lambda x^\alpha . \lambda f^{\alpha\to\alpha} . f x\\ 2 &:= \Lambda \alpha . \lambda x^\alpha . \lambda f^{\alpha\to\alpha} . f (f x)\\ 3 &:= \Lambda \alpha . \lambda x^\alpha . \lambda f^{\alpha\to\alpha} . f (f (f x)) \end{aligned}$$

If we reverse the order of the curried arguments (*i.e.,* $\forall \alpha. (\alpha \rightarrow \alpha) \rightarrow \alpha \rightarrow \alpha$), then the Church numeral for $n$ is a function that takes a function $f$ as argument and returns the $n$<sup>th</sup> power of $f$. That is to say, a Church numeral is a [higher-order function](https://en.wikipedia.org/wiki/Higher-order_function) – it takes a single-argument function $f$, and returns another single-argument function.

## Use in programming languages {#Use_in_programming_languages}

The version of System F used in this article is as an explicitly typed, or Church-style, calculus. The typing information contained in λ-terms makes [type-checking](https://en.wikipedia.org/wiki/Type-checking) straightforward. [Joe Wells](https://en.wikipedia.org/wiki/Joe_Wells) (1994) settled an "embarrassing open problem" by proving that type checking is [undecidable](wikipedia://en/8336) for a Curry-style variant of System F, that is, one that lacks explicit typing annotations.[^o11][^o12]

Wells's result implies that [type inference](wikipedia://en/279690) for System F is impossible. A restriction of System F known as "[Hindley–Milner](https://en.wikipedia.org/wiki/Hindley–Milner)", or simply "HM", does have an easy type inference algorithm and is used for many [statically typed](https://en.wikipedia.org/wiki/Statically_typed) [functional programming languages](https://en.wikipedia.org/wiki/Functional_programming_languages) such as [Haskell 98](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29) and the [ML](https://en.wikipedia.org/wiki/ML_programming_language) family. Over time, as the restrictions of HM-style type systems have become apparent, languages have steadily moved to more expressive logics for their type systems. [GHC](https://en.wikipedia.org/wiki/Glasgow_Haskell_Compiler), a Haskell compiler, goes beyond HM (as of 2008) and uses System F extended with non-syntactic type equality;[^o13] non-HM features in [OCaml](https://en.wikipedia.org/wiki/OCaml)'s type system include [GADT](https://en.wikipedia.org/wiki/Generalized_algebraic_data_types).[^o14][^o15]

## The Girard–Reynolds isomorphism {#The_Girard–Reynolds_isomorphism}

In second-order [intuitionistic logic](wikipedia://en/169262), the second-order polymorphic lambda calculus (F2) was discovered by Girard (1972) and independently by Reynolds (1974).[^o17] Girard proved the *representation theorem*: that in second-order intuitionistic predicate logic (P2), functions from the natural numbers to the natural numbers that can be proved total, form a projection from P2 into F2.[^o17] Reynolds proved the *abstraction theorem*: that every term in F2 satisfies a logical relation, which can be embedded into the logical relations P2.[^o17] Reynolds proved that a Girard projection followed by a Reynolds embedding form the identity, i.e., the **Girard–Reynolds isomorphism**.[^o17]

## System F<sub>ω</sub> {#System_Fω}

While System F corresponds to the first axis of [Barendregt's](wikipedia://en/1651213) [lambda cube](wikipedia://en/901593), **System F<sub>ω</sub>** or the **higher-order polymorphic lambda calculus** combines the first axis (polymorphism) with the second axis ([type operators](https://en.wikipedia.org/wiki/Type_operator)); it is a different, more complex system.

System F<sub>ω</sub> can be defined inductively on a family of systems, where induction is based on the [kinds](wikipedia://en/20627460) permitted in each system:

- $F_n$ permits kinds:
  - $\star$ (the kind of types) and
  - $J\Rightarrow K$ where $J\in F_{n-1}$ and $K\in F_n$ (the kind of functions from types to types, where the argument type is of a lower order)

In the limit, we can define system $F_\omega$ to be

- $$F_\omega = \underset{1 \leq i}{\bigcup} F_i$$

That is, F<sub>ω</sub> is the system which allows functions from types to types where the argument (and result) may be of any order.

Note that although F<sub>ω</sub> places no restrictions on the *order* of the arguments in these mappings, it does restrict the *universe* of the arguments for these mappings: they must be types rather than values. System F<sub>ω</sub> does not permit mappings from values to types ([dependent types](https://en.wikipedia.org/wiki/Dependent_types)), though it does permit mappings from values to values ($\lambda$ abstraction), mappings from types to values ($\Lambda$ abstraction), and mappings from types to types ($\lambda$ abstraction at the level of types).

## System F<sub>\<:</sub> {#System_F<:}

**System F<sub>\<:</sub>**, pronounced "F-sub", is an extension of system F with [subtyping](wikipedia://en/213508). System F<sub>\<:</sub> has been of central importance to [programming language theory](https://en.wikipedia.org/wiki/Programming_language_theory) since the 1980s because the core of [functional programming languages](https://en.wikipedia.org/wiki/Functional_programming_languages), like those in the [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) family, support both [parametric polymorphism](https://en.wikipedia.org/wiki/Parametric_polymorphism) and [record](https://en.wikipedia.org/wiki/Record_%28computer_science%29) subtyping, which can be expressed in **System F<sub>\<:</sub>**.[^o22][^o23]
