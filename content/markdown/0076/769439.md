# Avalanche effect

::: {#o1 .subject cue=lead name="Avalanche effect"}

In [cryptography](wikipedia://en/18934432), the **avalanche effect** is the desirable property of cryptographic [algorithms](wikipedia://en/775), typically block ciphers[^o2] and [cryptographic hash functions](wikipedia://en/439526), wherein if an input is changed slightly (for example, flipping a single bit), the output changes significantly (e.g., half the output bits flip). In the case of high-quality block ciphers, such a small change in either the [key](wikipedia://en/53039) or the [plaintext](wikipedia://en/157935) should cause a drastic change in the [ciphertext](wikipedia://en/175560). The actual term was first used by [Horst Feistel](wikipedia://en/530509),[^o2] although the concept dates back to at least [Shannon](wikipedia://en/5693)'s *[diffusion](https://en.wikipedia.org/wiki/Diffusion_%28cryptography%29)*.

:::

*Image: Avalanche effect.svg.* The [SHA-1](wikipedia://en/26672) hash function exhibits good avalanche effect. When a single bit is changed the hash sum becomes completely different.

If a block cipher or cryptographic hash function does not exhibit the avalanche effect to a significant degree, then it has poor randomization, and thus a [cryptanalyst](https://en.wikipedia.org/wiki/Cryptanalyst) can make predictions about the input, being given only the output. This may be sufficient to partially or completely break the algorithm. Thus, the avalanche effect is a desirable condition from the point of view of the designer of the cryptographic algorithm or device. Failure to incorporate this characteristic leads to the hash function being exposed to attacks including [collision attacks](wikipedia://en/969624), [length extension attacks](wikipedia://en/36667216), and [preimage attacks](wikipedia://en/969477).[^o3]

Constructing a cipher or hash to exhibit a substantial avalanche effect is one of the primary design objectives, and mathematically the construction takes advantage of the [butterfly effect](wikipedia://en/4024).[^o4] This is why most block ciphers are [product ciphers](wikipedia://en/598557). It is also why hash functions have large data blocks. Both of these features allow small changes to propagate rapidly through iterations of the algorithm.

::: {#o6 .statement cue=named-heading name="Strict avalanche criterion"}

## Strict avalanche criterion {#Strict_avalanche_criterion}

The **strict avalanche criterion** (**SAC**) is a formalization of the avalanche effect. It is satisfied if, whenever a single input bit is flipped, each of the output bits changes with a 50% probability. More precisely, it is satisfied if, for all bit positions *i* and *j*, when a random input *X* is selected, there is a 50% chance that *f*(*X*) and *f*(*X*<sub>i</sub>) differ at position *j*, where *X*<sub>*i*</sub> is *X* with the bit at position *i* flipped.[^o7] The SAC builds on the concepts of [completeness](wikipedia://en/4296490) and avalanche and was introduced by Webster and Tavares in 1985.[^o8]

At least one alternative definition of the strict avalanche criterion exists in the literature. Vaughn and Borowczak define the criterion as being satisfied if, when two random inputs *X* and *Y* are selected which differ in exactly one position, the [Hamming distance](wikipedia://en/41227) between *f*(*X*) and *f*(*Y*) is distributed according to the [binomial distribution](wikipedia://en/3876) B(*n*, 1/2), where *n* is the number of bits in *X* or *Y*.[^o9]

Higher-order generalizations of SAC involve multiple input bits. Boolean functions which satisfy the highest order SAC are always [bent functions](wikipedia://en/24465207), also called maximally nonlinear functions, also called "perfect nonlinear" functions.[^o10]

:::

::: {#o12 .statement cue=named-heading name="Bit independence criterion"}

## Bit independence criterion {#Bit_independence_criterion}

The **bit independence criterion** (**BIC**) states that output bits *j* and *k* should change independently when any single input bit *i* is inverted, for all *i*, *j* and *k*.[^o13]
