# Collision resistance

::: {#o1 .subject cue=lead name="Collision resistance"}

In [cryptography](wikipedia://en/18934432), **collision resistance** is a property of [cryptographic hash functions](https://en.wikipedia.org/wiki/Cryptographic_hash_functions) (CHFs): a hash function *H* is collision-resistant if it is hard to find two inputs that hash to the same output; that is, two inputs *a* and *b* where *a* ≠ *b* but *H*(*a*) = *H*(*b*).[^o2] The [pigeonhole principle](wikipedia://en/54217) means that any hash function with more inputs than outputs will necessarily have such collisions;[^o2] the harder they are to find, the more cryptographically secure the hash function is.

:::

The "[birthday paradox](https://en.wikipedia.org/wiki/Birthday_paradox)" places an upper bound on collision resistance: if a hash function produces *N* bits of output, an attacker who computes only 2<sup>*N*/2</sup> (or $\scriptstyle \sqrt{ 2^N}$) hash operations on random input is likely to find two matching outputs. If there is an easier method to do this than [brute-force attack](wikipedia://en/53784), it is typically considered a flaw in the hash function.[^o3]

[Cryptographic hash functions](wikipedia://en/439526) are usually designed to be collision resistant. However, many hash functions that were once thought to be collision resistant were later broken. [MD5](wikipedia://en/18826) and [SHA-1](wikipedia://en/26672) in particular both have published techniques more efficient than brute force for finding collisions.[^o4][^o5] However, some hash functions have a proof that finding collisions is at least as difficult as some hard mathematical problem (such as [integer factorization](wikipedia://en/15491) or [discrete logarithm](wikipedia://en/181334)). Those functions are called [provably secure](https://en.wikipedia.org/wiki/Provably_secure_cryptographic_hash_function).[^o3]

## Definition {#Definition}

A family of functions {*h*<sub>*k*</sub> : {0, 1}<sup>*m*(*k*)</sup> → {0, 1}<sup>*l*(*k*)</sup>} generated by some algorithm *G* is a family of collision-resistant hash functions, if |*m*(*k*)| > |*l*(*k*)| for any *k*, i.e., *h*<sub>*k*</sub> compresses the input string, and every *h*<sub>*k*</sub> can be computed within [polynomial time](wikipedia://en/405944) given *k*, but for any probabilistic polynomial algorithm *A*, we have

Pr \[*k* ← *G*(1<sup>*n*</sup>), (*x*<sub>1</sub>, *x*<sub>2</sub>) ← *A*(*k*, 1<sup>*n*</sup>) s.t. *x*<sub>1</sub> ≠ *x*<sub>2</sub> but *h*<sub>*k*</sub>(*x*<sub>1</sub>) = *h*<sub>*k*</sub>(*x*<sub>2</sub>)\] \< negl(*n*),

where negl(·) denotes some [negligible function](wikipedia://en/8426019), and *n* is the [security parameter](wikipedia://en/2290431).[^o8]

:::

## Weak and strong collision resistance {#Weak_and_strong_collision_resistance}

There are two different types of collision resistance.

A hash function has weak collision resistance when, given a hashing function H and an x, no other x' can be found such that H(x)=H(x'). In words, when given an x, it is not possible to find another x' such that the hashing function would create a collision.

A hash function has strong collision resistance when, given a hashing function H, no arbitrary x and x' can be found where H(x)=H(x'). In words, no two x's can be found where the hashing function would create a collision.

## Rationale {#Rationale}

Collision resistance is desirable for several reasons.

- In some [digital signature](wikipedia://en/59644) systems, a party attests to a document by publishing a [public key](https://en.wikipedia.org/wiki/Public_key) signature on a hash of the document. If it is possible to produce two documents with the same hash, an attacker could get a party to attest to one, and then claim that the party had attested to the other.
- In some distributed content systems, parties compare cryptographic hashes of files in order to make sure they have the same version. An attacker who could produce two files with the same hash could trick users into believing they had the same version of a file when they in fact did not.

## Pseudo-collisions {#Pseudo-collisions}

During the evaluation of CHFs, one approach is to study attacks on similar, slightly modified, algorithms. Usually, a free choice of hash initialization value (IV in [Merkle–Damgård construction](wikipedia://en/4076217)) is allowed. If the same hash value is observed for two different (input value, IV) [tuples](https://en.wikipedia.org/wiki/Tuples), the result is called a **pseudo-collision**. Pseudo-collisions are not directly affecting the security of the algorithm – as the IV is fixed in a practical hash design – but they are treated as suspicious while considering new [cryptography standards](wikipedia://en/788203).[^n1]
