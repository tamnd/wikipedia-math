# Feistel cipher

::: {#o1 .subject cue=lead name="Feistel cipher"}

*Image: Feistel cipher diagram en.svg.*

In [cryptography](wikipedia://en/18934432), a **Feistel cipher** (also known as **Luby–Rackoff block cipher**) is a [symmetric structure](wikipedia://en/53042) used in the construction of [block ciphers](wikipedia://en/4594), named after the [German](https://en.wikipedia.org/wiki/Germany)-born [physicist](https://en.wikipedia.org/wiki/Physicist) and cryptographer [Horst Feistel](wikipedia://en/530509), who did pioneering research while working for [IBM](https://en.wikipedia.org/wiki/IBM); it is also commonly known as a **Feistel network**. A large number of [block ciphers](wikipedia://en/4594) use the scheme, including the US [Data Encryption Standard](wikipedia://en/7978), the Soviet/Russian [GOST (aka Magma)](wikipedia://en/487471) and the more recent [Blowfish](wikipedia://en/3940) and [Twofish](wikipedia://en/26508356) ciphers. In a Feistel cipher, encryption and decryption are very similar operations, and both consist of iteratively running a function called a "[round function](wikipedia://en/73297602)" a fixed number of times.

:::

## History {#History}

Many modern symmetric block ciphers are based on Feistel networks. Feistel networks were first seen commercially in IBM's [Lucifer](wikipedia://en/364242) cipher, designed by [Horst Feistel](wikipedia://en/530509) and [Don Coppersmith](wikipedia://en/540090) in 1973. Feistel networks gained respectability when the U.S. Federal Government adopted the [DES](wikipedia://en/7978) (a cipher based on Lucifer, with changes made by the [NSA](wikipedia://en/21939)) in 1976. Like other components of the DES, the iterative nature of the Feistel construction makes implementing the cryptosystem in hardware easier (particularly on the hardware available at the time of DES's design).

## Design {#Design}

A Feistel network uses a *round function*, a function which takes two inputs – a data block and a subkey – and returns one output of the same size as the data block.[^o4] In each round, the round function is run on half of the data to be encrypted, and its output is XORed with the other half of the data. This is repeated a fixed number of times, and the final output is the encrypted data. An important advantage of Feistel networks compared to other cipher designs such as [substitution–permutation networks](https://en.wikipedia.org/wiki/Substitution–permutation_network) (SP-networks) is that the entire operation is guaranteed to be invertible (that is, encrypted data can be decrypted), even if the round function is not itself invertible. The round function can be made arbitrarily complicated, since it does not need to be designed to be invertible.[^o5] [^o6] Furthermore, the [encryption](wikipedia://en/10294) and [decryption](https://en.wikipedia.org/wiki/Decryption) operations are very similar, even identical in some cases, requiring only a reversal of the [key schedule](wikipedia://en/609603). Therefore, the size of the code or circuitry required to implement such a cipher is nearly halved. Unlike SP-networks, Feistel networks also do not depend on a substitution box that could cause timing side-channels in software implementations.

## Theoretical work {#Theoretical_work}

The structure and properties of Feistel ciphers have been extensively analyzed by [cryptographers](https://en.wikipedia.org/wiki/Cryptographer).

[Michael Luby](wikipedia://en/9552275) and [Charles Rackoff](https://en.wikipedia.org/wiki/Charles_Rackoff) analyzed the Feistel cipher construction and proved that if the round function is a cryptographically secure [pseudorandom function](https://en.wikipedia.org/wiki/Pseudorandom_function), with *K<sub>i</sub>* used as the seed, then 3 rounds are sufficient to make the block cipher a [pseudorandom permutation](wikipedia://en/4681949), while 4 rounds are sufficient to make it a "strong" pseudorandom permutation (which means that it remains pseudorandom even to an adversary who gets [oracle](wikipedia://en/22431) access to its inverse permutation).[^o8] Because of this very important result of Luby and Rackoff, Feistel ciphers are sometimes called Luby–Rackoff block ciphers.

Further theoretical work has generalized the construction somewhat and given more precise bounds for security.[^o9][^o10]

## Construction details {#Construction_details}

Let $\mathrm{F}$ be the round function and let $K_0, K_1, \ldots, K_n$ be the sub-keys for the rounds $0, 1, \ldots, n$ respectively.

Then the basic operation is as follows:

Split the plaintext block into two equal pieces: ($L_0$, $R_0$).

For each round $i = 0, 1, \dots, n$, compute

$$L_{i+1} = R_i,$$

$$R_{i+1}= L_i \oplus \mathrm{F}(R_i, K_i),$$

where $\oplus$ means [XOR](https://en.wikipedia.org/wiki/XOR). Then the ciphertext is $(R_{n+1}, L_{n+1})$.

Decryption of a ciphertext $(R_{n+1}, L_{n+1})$ is accomplished by computing for $i = n, n - 1, \ldots, 0$

$$R_{i} = L_{i+1},$$

$$L_{i} = R_{i+1} \oplus \operatorname{F}(L_{i+1}, K_i).$$

Then $(L_0, R_0)$ is the plaintext again.

The diagram illustrates both encryption and decryption. Note the reversal of the subkey order for decryption; this is the only difference between encryption and decryption.

### Unbalanced Feistel cipher {#Unbalanced_Feistel_cipher}

Unbalanced Feistel ciphers use a modified structure where $L_0$ and $R_0$ are not of equal lengths.[^o13] The [Skipjack](wikipedia://en/474702) cipher is an example of such a cipher. The [Texas Instruments](https://en.wikipedia.org/wiki/Texas_Instruments) [digital signature transponder](https://en.wikipedia.org/wiki/Digital_signature_transponder) uses a proprietary unbalanced Feistel cipher to perform [challenge–response authentication](wikipedia://en/412627).[^o14]

The [Thorp shuffle](https://en.wikipedia.org/wiki/Thorp_shuffle) is an extreme case of an unbalanced Feistel cipher in which one side is a single bit. This has better provable security than a balanced Feistel cipher but requires more rounds.[^o15]

There exists Type-1, Type-2, and Type-3 Feistel networks, where the Feistel function is one fourth the size of the block but operates a varying number of times within one round.[^o16]

### Other uses {#Other_uses}

The Feistel construction is also used in cryptographic algorithms other than block ciphers. For example, the [optimal asymmetric encryption padding](wikipedia://en/1579249) (OAEP) scheme uses a simple Feistel network to randomize ciphertexts in certain [asymmetric-key encryption](wikipedia://en/24222) schemes.

A generalized Feistel algorithm can be used to create strong permutations on small domains of size not a power of two (see [format-preserving encryption](wikipedia://en/23271188)).[^o15]

### Feistel networks as a design component {#Feistel_networks_as_a_design_component}

Whether the entire cipher is a Feistel cipher or not, Feistel-like networks can be used as a component of a cipher's design. For example, [MISTY1](https://en.wikipedia.org/wiki/MISTY1) is a Feistel cipher using a three-round Feistel network in its round function, [Skipjack](wikipedia://en/474702) is a modified Feistel cipher using a Feistel network in its G permutation, and [Threefish](wikipedia://en/20019277) (part of [Skein](wikipedia://en/20007592)) is a non-Feistel block cipher that uses a Feistel-like MIX function.
