# CAcert.org

::: {#o2 .subject cue=lead name="CAcert.org"}

**CAcert.org** is a community-driven [certificate authority](wikipedia://en/296370) that issues free [X.509](https://en.wikipedia.org/wiki/X.509) [public key certificates](wikipedia://en/223796).[^o3] CAcert.org relies heavily on automation and therefore issues only [Domain-validated certificates](https://en.wikipedia.org/wiki/Domain-validated_certificate) (and not [Extended validation](https://en.wikipedia.org/wiki/Extended_Validation_Certificate) or [Organization Validation](https://en.wikipedia.org/wiki/Organization_Validation_Certificate) certificates).

:::

These certificates can be used to [digitally sign](wikipedia://en/59644) and [encrypt](https://en.wikipedia.org/wiki/Encrypt) [email](https://en.wikipedia.org/wiki/Email_encryption); encrypt [code](wikipedia://en/3768009) and documents; and to authenticate and authorize user connections to websites via [TLS/SSL](wikipedia://en/187813).

## CAcert Inc. Association {#CAcert_Inc._Association}

On 24 July 2003, Duane Groth incorporated **CAcert Inc.** as a non-profit association registered[^o5] in [New South Wales](https://en.wikipedia.org/wiki/New_South_Wales), [Australia](https://en.wikipedia.org/wiki/Australia) and after, in September 2024, moved to Europe in Geneva, [Switzerland](https://en.wikipedia.org/wiki/Switzerland). CAcert Inc runs **CAcert.org**—a community-driven certificate authority.

In 2004, the Dutch Internet pioneer [Teus Hagen](https://en.wikipedia.org/wiki/Teus_Hagen) became involved. He served as board member and, in 2008, as a president.[^o6]

## Certificate Trust status {#Certificate_Trust_status}

CAcert.org's [root certificates](wikipedia://en/296362) are not included in the most widely deployed certificate stores[^o8] and has to be added by its customers.[^o9] As of 2021, most [browsers](https://en.wikipedia.org/wiki/Web_browser), [email clients](https://en.wikipedia.org/wiki/Email_client), and [operating systems](https://en.wikipedia.org/wiki/Operating_system) do not automatically trust certificates issued by CAcert. Thus, users receive an "untrusted certificate" warning upon trying to view a website providing [X.509](https://en.wikipedia.org/wiki/X.509) certificate issued by CAcert, or view emails authenticated with CAcert certificates in [Microsoft Outlook](https://en.wikipedia.org/wiki/Microsoft_Outlook), [Mozilla Thunderbird](https://en.wikipedia.org/wiki/Mozilla_Thunderbird), etc. CAcert uses its own certificate on its website.

### Web browsers {#Web_browsers}

Discussion for inclusion of CAcert root certificate in [Mozilla Application Suite](https://en.wikipedia.org/wiki/Mozilla_Application_Suite) and [Mozilla Firefox](https://en.wikipedia.org/wiki/Mozilla_Firefox) started in 2004. [Mozilla](https://en.wikipedia.org/wiki/Mozilla) had no [CA](wikipedia://en/296370) certificate policy at the time. Eventually, Mozilla developed a policy which required CAcert to improve their management system and conduct [audits](https://en.wikipedia.org/wiki/Audit). In April 2007, CAcert formally withdrew its application for inclusion in the Mozilla root program.[^o11] At the same time, the [CA/Browser Forum](https://en.wikipedia.org/wiki/CA/Browser_Forum) was established to facilitate communication among browser vendors and Certificate Authorities. Mozilla's advice was incorporated into "baseline requirements" used by most major browser vendors. Progress towards meeting these requirements can hardly be expected in the near future.[^o11]

### Operating systems {#Operating_systems}

[FreeBSD](https://en.wikipedia.org/wiki/FreeBSD) included CAcert's root certificate but removed it in 2008, following [Mozilla](https://en.wikipedia.org/wiki/Mozilla)'s policy.[^o13] In 2014, CAcert was removed from [Ubuntu](https://en.wikipedia.org/wiki/Ubuntu),[^o14] [Debian](https://en.wikipedia.org/wiki/Debian),[^o15] and [OpenBSD](https://en.wikipedia.org/wiki/OpenBSD)[^o16] root stores. In 2018, CAcert was removed from [Arch Linux](https://en.wikipedia.org/wiki/Arch_Linux).[^o17]

As of Feb 2022, the following operating systems or distributions include the CAcert root certificate by default:[^o18]

- [FreeWRT](https://en.wikipedia.org/wiki/FreeWRT)
- [GRML](https://en.wikipedia.org/wiki/Grml)
- [Knoppix](https://en.wikipedia.org/wiki/Knoppix)
- [Mandriva Linux](https://en.wikipedia.org/wiki/Mandriva_Linux)
- [MirOS BSD](https://en.wikipedia.org/wiki/MirOS_BSD)
- [Openfire](https://en.wikipedia.org/wiki/Openfire)
- Privatix
- [Replicant](https://en.wikipedia.org/wiki/Replicant_%28operating_system%29) (Android)

As of 2021, the following operating systems or distributions have an optional package with the CAcert root certificate:[^o18]

- [Arch Linux](https://en.wikipedia.org/wiki/Arch_Linux)
- [Debian](https://en.wikipedia.org/wiki/Debian)[^o19]
- [Gentoo](https://en.wikipedia.org/wiki/Gentoo_Linux) (app-misc/ca-certificates only when USE flag cacert is set, defaults OFF from version 20161102.3.27.2-r2 )
- [openSUSE](https://en.wikipedia.org/wiki/OpenSUSE)

## Web of trust {#Web_of_trust}

To create higher-trust certificates, users can participate in a web of trust system whereby users physically meet and verify each other's identities.[^o21][^o22] CAcert maintains the number of **assurance points** for each account. Assurance points can be gained through various means, primarily by having one's identity physically verified by users classified as "Assurers".

Having more assurance points allows users more privileges such as writing a name in the certificate and longer expiration times on certificates. A user with at least 100 assurance points is a Prospective Assurer, and may—after passing an Assurer Challenge[^o23]—verify other users; more assurance points allow the Assurer to assign more assurance points to others.

CAcert sponsors [key signing parties](wikipedia://en/424764), especially at big events such as [CeBIT](https://en.wikipedia.org/wiki/CeBIT) and [FOSDEM](https://en.wikipedia.org/wiki/FOSDEM).

As of 2021, CAcert's web of trust has over 380,000 verified users.[^o24]

## Root certificate descriptions {#Root_certificate_descriptions}

Since October 2005, CAcert offers Class 1 and Class 3 root certificates. Class 3 is a high-security subset of Class 1.[^o26]
