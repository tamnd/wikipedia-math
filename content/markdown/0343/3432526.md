# Anubis (cipher)

::: {#o2 .subject cue=lead name="Anubis"}

**Anubis** is a [block cipher](wikipedia://en/4594) designed by [Vincent Rijmen](https://en.wikipedia.org/wiki/Vincent_Rijmen) and [Paulo S. L. M. Barreto](https://en.wikipedia.org/wiki/Paulo_S._L._M._Barreto) as an entrant in the [NESSIE](wikipedia://en/497430) project, a former research program initiated by the [European Commission](https://en.wikipedia.org/wiki/European_Commission) in 2000 for the identification of new [cryptographic](wikipedia://en/18934432) algorithms.[^o4] Although the cipher has not been included in the final NESSIE portfolio, its design is considered very strong, and no attacks have been found by 2004 after the project had been concluded.[^o6] The cipher is not patented and has been released by the designers for free public use.[^o5]

:::

Anubis operates on data blocks of 128 bits, accepting keys of length 32*N* bits (*N* = 4, ..., 10). It is designed as a [substitution–permutation network](https://en.wikipedia.org/wiki/Substitution–permutation_network), which bears large similarity to [Rijndael](wikipedia://en/1260).[^o6] Like [KHAZAD](wikipedia://en/615967), designed by the same authors and also submitted to NESSIE, it uses [involutions](wikipedia://en/293450) for the various operations.[^o6] An involution is an operation whose inverse is the same as the forward operation. In other words, when an involution is run twice, it is the same as performing no operation. This allows low-cost hardware and compact software implementations to use the same operations for both encryption and decryption. Both the [S-box](https://en.wikipedia.org/wiki/Substitution_box) and the mix columns operations are involutions.[^o4] Although many involutional components can make a cipher more susceptible to [distinguishing attacks](wikipedia://en/11563117) exploiting the cycle structure of permutations within the cipher, no attack strategy for the Anubis cipher has been presented.[^o7]

There are two versions of the Anubis cipher; the original implementation uses a pseudo-random S-box. Subsequently, the S-box was modified to be more efficient to implement in hardware; the newer version of Anubis is called the "tweaked" version.[^o6]

The authors claim the algorithm to be secure against a number of attacks, including four-round [differential](wikipedia://en/8536) and [linear analysis](wikipedia://en/59469), as well as [related-key](wikipedia://en/1516144), [interpolation](wikipedia://en/3329538), [boomerang](wikipedia://en/2137332), [truncated differential](wikipedia://en/9506236), [impossible differential](https://en.wikipedia.org/wiki/Impossible_differential_attack), and saturation attacks.[^o4] Nonetheless, because of the cipher's similarity with Rijndael it was not considered to offer any convincing advantages and thus was not included in the second evaluation phase of the NESSIE project.

Anubis is named after the [Egyptian god](https://en.wikipedia.org/wiki/Anubis) of entombing and embalming, which the designers interpreted to include [encryption](wikipedia://en/10294). They claim that violators of the cipher will be [cursed](https://en.wikipedia.org/wiki/Curse).[^o4]
