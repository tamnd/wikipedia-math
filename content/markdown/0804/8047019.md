# Weak NP-completeness

::: {#o1 .subject cue=lead name="Weak NP-completeness"}

In [computational complexity](wikipedia://en/2230), an [NP-complete](https://en.wikipedia.org/wiki/NP-complete) (or [NP-hard](https://en.wikipedia.org/wiki/NP-hard)) problem is **weakly NP-complete** (or weakly NP-hard) if there is an [algorithm](wikipedia://en/775) for the problem whose running time is [polynomial](wikipedia://en/23000) in the dimension of the problem and the magnitudes of the data involved (provided these are given as [integers](wikipedia://en/14563)), rather than the [base-two logarithms](wikipedia://en/249992) of their magnitudes. Such algorithms have running times that are [exponential](wikipedia://en/9678) functions of their input size and are therefore not considered [polynomial](wikipedia://en/23000)[^o2]

:::

For example, the NP-hard [knapsack problem](wikipedia://en/16974) can be solved by a [dynamic programming](wikipedia://en/125297) algorithm requiring a number of steps polynomial in the size of the knapsack and the number of items (assuming that all data are scaled to be integers); however, the runtime of this algorithm is [exponential time](https://en.wikipedia.org/wiki/Exponential_time) since the input sizes of the objects and knapsack are logarithmic in their magnitudes. However, as Garey and Johnson (1979) observed, “A [pseudo-polynomial-time](wikipedia://en/3149636) algorithm … will display 'exponential behavior' only when confronted with instances containing 'exponentially large' numbers, \[which\] might be rare for the application we are interested in. If so, this type of algorithm might serve our purposes almost as well as a polynomial time algorithm.” Another example for a weakly NP-complete problem is the [subset sum problem](wikipedia://en/36811).

The related term [strongly NP-complete](https://en.wikipedia.org/wiki/Strongly_NP-complete) (or unary NP-complete) refers to those problems that remain NP-complete even if the data are encoded in [unary](wikipedia://en/32316), that is, if the data are "small" relative to the overall input size.[^o3]
