# Tahoe-LAFS

::: {#o6 .subject cue=lead name="Tahoe-LAFS"}

**Tahoe-LAFS** (**Tahoe Least-Authority File Store**[^o7]) is a [free and open](https://en.wikipedia.org/wiki/Free_software), secure, [decentralized](https://en.wikipedia.org/wiki/Decentralized), fault-tolerant, [distributed data store](https://en.wikipedia.org/wiki/Distributed_data_store) and [distributed file system](https://en.wikipedia.org/wiki/Clustered_file_system#Distributed_file_systems).[^o8][^o9] It can be used as an [online backup](https://en.wikipedia.org/wiki/Remote_backup_service) system, or to serve as a file or Web host similar to [Freenet](https://en.wikipedia.org/wiki/Freenet), depending on the [front-end](https://en.wikipedia.org/wiki/Front_and_back_ends) used to insert and access files in the Tahoe system. Tahoe can also be used in a [RAID](https://en.wikipedia.org/wiki/RAID)-like fashion using multiple disks to make a single large [Redundant Array of Inexpensive Nodes](https://en.wikipedia.org/wiki/Redundant_Array_of_Inexpensive_Servers) (RAIN) pool of reliable data storage.

:::

The system is designed and implemented around the "[principle of least authority](https://en.wikipedia.org/wiki/Principle_of_least_privilege)" (POLA), described by Brian Warner (one of the project's original founders) as the idea "that any component of the system should have as little power of authority as it needs to get its job done".[^o10] Strict adherence to this convention is enabled by the use of [cryptographic](wikipedia://en/18934432) capabilities that provide the minimum set of [privileges](https://en.wikipedia.org/wiki/Privilege_%28computing%29) necessary to perform a given task by asking agents. A RAIN array acts as a storage volume; these servers do not need to be trusted by confidentiality or integrity of the stored data.

## History {#History}

**Tahoe-LAFS** was started in 2006 at online backup services company *All My Data*[^o10] and has been actively developed since 2007.[^o12] In 2008, Brian Warner and [Zooko Wilcox-O'Hearn](https://en.wikipedia.org/wiki/Zooko_Wilcox-O'Hearn) published a paper on Tahoe at the 4th [ACM](https://en.wikipedia.org/wiki/Association_for_Computing_Machinery) international workshop on Storage security and survivability.[^o13]

When *All My Data* closed in 2009, Tahoe-LAFS became a free software project under the [GNU General Public License](https://en.wikipedia.org/wiki/GNU_General_Public_License) or *The Transitive Grace License*, which allows owners of the code twelve months to profit from their work before releasing it. In 2010, Tahoe-LAFS was mentioned as a tool against censorship by the [Electronic Frontier Foundation](https://en.wikipedia.org/wiki/Electronic_Frontier_Foundation).[^o14] In 2013, it was one of the hackathon projects at the [GNU](https://en.wikipedia.org/wiki/GNU_Project) 30th anniversary.[^o15]

## Functionality {#Functionality}

*Image: Tahoe-LAFS.png.* Overview of Tahoe-LAFS

The Tahoe-LAFS Client sends an unencrypted file via a web API to the HTTPS Server. The HTTPS Server passes the file off to the Tahoe-LAFS Storage client which encrypts the file and then uses [erasure coding](https://en.wikipedia.org/wiki/Erasure_coding) to store fragments of the file on multiple storage drives.[^o17]

Tahoe-LAFS features "provider-independent security", in that the integrity and confidentiality of the files are guaranteed by the algorithms used on the client, independent of the storage servers, which may fail or may be operated by untrusted entities. Files are encrypted using [AES](wikipedia://en/1260), then split up using [erasure coding](https://en.wikipedia.org/wiki/Erasure_code), such that only a subset K of the original N servers storing the file chunks need to be available in order to recreate the original file.[^o18][^o19] The default parameters are K=3, N=10, so each file is shared across 10 different servers, accessing it requires the correct function of any 3 of those servers.[^o13]

Tahoe provides very little control over on which nodes data is stored.[^o20]

## Fork {#Fork}

A patched version of Tahoe-LAFS exists from 2011, and was made to run on anonymous networks such as [I2P](wikipedia://en/538434), with support for multiple introducers. There is also a version for Microsoft Windows.[^o22] It is distributed from a site within the I2P network. In contrast to normal Tahoe-LAFS operation, when I2P and Tahoe-LAFS are used together the location of the nodes are disguised. This allows for anonymous distributed grids to be formed.
