# Transaction logic

::: {#o1 .subject cue=lead name="Transaction logic"}

**Transaction Logic** is an extension of [predicate logic](https://en.wikipedia.org/wiki/Predicate_logic) that accounts in a clean and declarative way for the phenomenon of state changes in [logic programs](https://en.wikipedia.org/wiki/Logic_program) and [databases](https://en.wikipedia.org/wiki/Database). This extension adds connectives specifically designed for combining simple actions into complex transactions and for providing control over their execution. The logic has a natural [model theory](wikipedia://en/19858) and a sound and complete [proof theory](wikipedia://en/183478). Transaction Logic has a [Horn clause](wikipedia://en/333824) subset, which has a procedural as well as a declarative semantics. The important features of the logic include hypothetical and committed updates, dynamic constraints on transaction execution, non-determinism, and bulk updates. In this way, Transaction Logic is able to declaratively capture a number of non-logical phenomena, including [procedural knowledge](https://en.wikipedia.org/wiki/Procedural_knowledge) in [artificial intelligence](https://en.wikipedia.org/wiki/Artificial_intelligence), [active databases](https://en.wikipedia.org/wiki/Active_database), and methods with side effects in [object databases](https://en.wikipedia.org/wiki/Object_database).

:::

Transaction Logic was originally proposed in 1993 by [Anthony Bonner](http://www.cs.toronto.edu/~bonner/) and [Michael Kifer](http://www.cs.stonybrook.edu/~kifer/)[^o2] and later described in more detail in *An Overview of Transaction Logic*[^o3] and *Logic Programming for Database Transactions*.[^o4] The most comprehensive description appears in Bonner & Kifer's technical report from 1995.[^o5]

In later years, Transaction Logic was extended in various ways, including [concurrency](https://en.wikipedia.org/wiki/Concurrency_%28computer_science%29),[^o6] [defeasible reasoning](wikipedia://en/2628057),[^o7] partially defined actions,[^o8] and other features.[^o9][^o10]

In 2013, the original paper on Transaction Logic has [won](https://www.cs.stonybrook.edu/about-us/News/ALP-Presents-Prof-Kifer-20-year-Test-Time-Award) the [20-year Test of Time Award](https://www.cs.nmsu.edu/ALP/the-association-for-logic-programming/alp-awards/) of the [Association for Logic Programming](https://en.wikipedia.org/wiki/Association_for_Logic_Programming) as the most influential paper from the proceedings of [ICLP 1993 conference](http://www.informatik.uni-trier.de/~ley/db/conf/iclp/iclp93.html) in the preceding 20 years.

## Examples {#Examples}

### Graph coloring {#Graph_coloring}

Here tinsert denotes the elementary update operation of *transactional insert*. The connective ⊗ is called *serial conjunction*.

```text
colorNode <-  // color one node correctly
    node(N) ⊗ ¬ colored(N,_) ⊗ color(C)
    ⊗ ¬(adjacent(N,N2) ∧ colored(N2,C))
    ⊗ tinsert(colored(N,C)).
colorGraph <- ¬uncoloredNodesLeft.
colorGraph <- colorNode ⊗ colorGraph.
```

### Pyramid stacking {#Pyramid_stacking}

The elementary update tdelete represents the *transactional delete* operation.

```text
stack(N,X) <- N>0 ⊗ move(Y,X) ⊗ stack(N-1,Y).
stack(0,X).
move(X,Y) <- pickup(X) ⊗ putdown(X,Y).
pickup(X) <- clear(X) ⊗ on(X,Y) ⊗
             ⊗ tdelete(on(X,Y)) ⊗ tinsert(clear(Y)).
putdown(X,Y) <-  wider(Y,X) ⊗ clear(Y) 
                 ⊗ tinsert(on(X,Y)) ⊗ tdelete(clear(Y)).
```

### Hypothetical execution {#Hypothetical_execution}

Here \<> is the [modal operator](wikipedia://en/3832714) of possibility: If both action1 and action2 are possible, execute action1. Otherwise, if only action2 is possible, then execute it.

```text
execute <- <>action1 ⊗ <>action2 ⊗ action1.
execute <- ¬<>action1 ⊗ <>action2 ⊗ action2.
```

### Dining philosophers {#Dining_philosophers}

Here | is the [logical connective](wikipedia://en/18153) of parallel conjunction of Concurrent Transaction Logic.[^o6]

```text
diningPhilosophers <- phil(1) | phil(2) | phil(3) | phil(4).
```

## Implementations {#Implementations}

A number of implementations of Transaction Logic exist:

- The original implementation.[^o19]
- An implementation of Concurrent Transaction Logic.[^o20]
- Transaction Logic enhanced with [tabling](https://en.wikipedia.org/wiki/Tabling). An implementation of Transaction Logic has also been incorporated as part of the [Flora-2](https://en.wikipedia.org/wiki/Flora-2) knowledge representation and reasoning system.[^o21]

All these implementations are [open source](https://en.wikipedia.org/wiki/Open_source).

:::
