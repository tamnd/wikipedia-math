# Algebraic-group factorization algorithm

::: {#o1 .subject cue=lead name="Algebraic-group factorization algorithm"}

**Algebraic-group factorization algorithms** are algorithms for [factoring an integer](wikipedia://en/15491) *N* by working in an [algebraic group](wikipedia://en/247924) defined [modulo](wikipedia://en/20087) *N* whose group structure is the direct sum of the 'reduced groups' obtained by performing the equations defining the group arithmetic modulo the unknown prime factors *p*<sub>1</sub>, *p*<sub>2</sub>, ... By the [Chinese remainder theorem](wikipedia://en/7713), arithmetic modulo *N* corresponds to arithmetic in all the reduced groups simultaneously.

:::

The aim is to find an element which is not the identity of the group modulo *N*, but is the identity modulo one of the factors, so a method for recognising such *one-sided identities* is required. In general, one finds them by performing operations that move elements around and leave the identities in the reduced groups unchanged. Once the algorithm finds a one-sided identity all future terms will also be one-sided identities, so checking periodically suffices.

::: {#o3 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

Computation proceeds by picking an arbitrary element *x* of the group modulo *N* and computing a large and [smooth](wikipedia://en/1035039) multiple *Ax* of it; if the order of at least one but not all of the reduced groups is a divisor of A, this yields a factorisation. It need not be a prime factorisation, as the element might be an identity in more than one of the reduced groups.

Generally, A is taken as a product of all the prime powers below some limit B<sub>1</sub>, and *Ax* is computed by successive multiplication of *x* by these primes; after each multiplication, or every few multiplications, the check is made for a one-sided identity. (A less efficient naive version would use a product of all integers below the limit B<sub>1</sub>.)[^o4]

### The two-step procedure {#The_two-step_procedure}

It is often possible to multiply a group element by several small integers more quickly than by their product, generally by difference-based methods: one calculates differences between consecutive primes and adds consecutively by the $d_i r$. This means that a two-step procedure becomes sensible, first computing *Ax* by multiplying *x* by all the primes below a limit B<sub>1</sub>, and then examining *p Ax* for all the primes between B<sub>1</sub> and a larger limit B<sub>2</sub>. This would relax the smoothness requirement for the group order from being B<sub>1</sub>-powersmooth to being the product of a prime between B<sub>1</sub> and B<sub>2</sub> and a B<sub>1</sub>-powersmooth number.

The difference-based method is the basic "stage 2" method. There exist modifications such as [Montgomery](wikipedia://en/14573146)'s prime pairing (1978) and the Brent-Suyama extension.[^o6]

A more efficient "stage 2" method uses polynomial multiplication implemented via [fast Fourier transform](wikipedia://en/11512). This method was originally demonstrated for Lenstra's ECM by Montgomery in 1992,[^o7] but has since been adapted for *p*-1 and *p*+1.[^o8]

:::

## Methods corresponding to particular algebraic groups {#Methods_corresponding_to_particular_algebraic_groups}

### Practical methods {#Practical_methods}

If the algebraic group is the [multiplicative group](wikipedia://en/1110742) mod *N*, the one-sided identities are recognised by computing [greatest common divisors](wikipedia://en/12354) with *N*, and the result is the [*p* − 1 method](https://en.wikipedia.org/wiki/Pollard's_p-1_algorithm).

If the algebraic group is the multiplicative group of a quadratic extension of *N*, the result is the [*p* + 1 method](https://en.wikipedia.org/wiki/Williams'_p_+_1_algorithm); the calculation involves pairs of numbers modulo *N*. It is not possible to tell whether $\mathbb Z/N\mathbb Z [ \sqrt t]$ is actually a quadratic extension of $\mathbb Z/N\mathbb Z$ without knowing the factorisation of *N*. This requires knowing whether *t* is a [quadratic residue](wikipedia://en/200091) modulo *N*, and there are no known methods for doing this without knowledge of the factorisation. However, provided *N* does not have a very large number of factors, in which case another method should be used first, picking random *t* (or rather picking *A* with *t* = *A*<sup>2</sup> − 4) will accidentally hit a quadratic non-residue fairly quickly. If *t* is a quadratic residue, the p+1 method degenerates to a slower form of the *p* − 1 method.

If the algebraic group is an [elliptic curve](wikipedia://en/10225), the one-sided identities can be recognised by failure of [inversion](wikipedia://en/14907) in the elliptic-curve point addition procedure, and the result is the [elliptic curve method](https://en.wikipedia.org/wiki/Elliptic_curve_method); [Hasse's theorem](wikipedia://en/1108758) states that the number of points on an elliptic curve modulo *p* is always within $2 \sqrt p$ of *p*.

All three of the above algebraic groups are used by the GMP-ECM package,[^o11] which includes efficient implementations of the two-stage procedure, and an implementation of the PRAC group-exponentiation algorithm which is rather more efficient than the standard [binary exponentiation](https://en.wikipedia.org/wiki/Binary_exponentiation) approach.

### Other groups {#Other_groups}

The use of other algebraic groups—higher-order extensions of *N* or groups corresponding to algebraic curves of higher genus—is occasionally proposed, but almost always impractical. For example, one can use the [Jacobian variety](wikipedia://en/489734) of a [hyperelliptic curve](wikipedia://en/499361), which has an efficient group law. These methods end up with smoothness constraints on numbers of the order of *p*<sup>*d*</sup> for some *d* > 1, which are much less likely to be smooth than numbers of the order of *p*.

## Practical considerations {#Practical_considerations}

### Complexity {#Complexity}

The naive first stage uses $O(B_1 \log (B_1) M(\log (N)))$ bit operations, while the prime-powers-only first stage takes $O(B_1 M(\log (N)))$, with *N* being the number-to-be-factored and $M(x)$ denoting the cost of multiplying two *x*-bit integers (practically $M(\log (N)) = O(N \log (N) \log \log (N))$ using FFT-based methods).[^o4]

The standard (difference-based) second stage uses $O((B_2 - B_1) M (\log (N)) )$ bit operations.[^o4] The polynomial-based second stage uses $O(\sqrt{B_2- B_1} \log (B_2- B_1) M(\log (N)))$ bit operations (the $B_1$ term can be discarded assuming $B_2 >> B_1$, which is often the case). Varying the size of the convolution gives a trade-off between memory and space: for each doubling of memory usage, double the amount of advancement in $B_2$ can be made for the same amount of computation.[^o8]
