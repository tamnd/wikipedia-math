# Embarrassingly parallel

::: {#o1 .subject cue=lead name="Embarrassingly parallel"}

In [parallel computing](https://en.wikipedia.org/wiki/Parallel_computing), an **embarrassingly parallel** workload or problem (also called **embarrassingly parallelizable**, **perfectly parallel**, **delightfully parallel** or **pleasingly parallel**) is one where little or no effort is needed to split the problem into a number of parallel tasks.[^o2] This is due to minimal or no dependency upon communication between the parallel tasks, or for results between them.[^o3]

:::

These differ from [distributed computing](https://en.wikipedia.org/wiki/Distributed_computing) problems, which need communication between tasks, especially communication of intermediate results. They are easier to perform on [server farms](https://en.wikipedia.org/wiki/Server_farm) which lack the special infrastructure used in a true [supercomputer](https://en.wikipedia.org/wiki/Supercomputer) cluster. They are well-suited to large, Internet-based [volunteer computing](https://en.wikipedia.org/wiki/Volunteer_computing) platforms such as [BOINC](https://en.wikipedia.org/wiki/BOINC), and suffer less from [parallel slowdown](https://en.wikipedia.org/wiki/Parallel_slowdown). The opposite of embarrassingly parallel problems are [inherently serial problems](https://en.wikipedia.org/wiki/Inherently_serial_problem), which cannot be parallelized at all.

A common example of an embarrassingly parallel problem is 3D video rendering handled by a [graphics processing unit](https://en.wikipedia.org/wiki/Graphics_processing_unit), where each frame (forward method) or pixel ([ray tracing](https://en.wikipedia.org/wiki/Ray_tracing_%28graphics%29) method) can be handled with no interdependency.[^o4] Some forms of [password cracking](wikipedia://en/477981) are another embarrassingly parallel task that is easily distributed on [central processing units](https://en.wikipedia.org/wiki/Central_processing_unit), [CPU cores](https://en.wikipedia.org/wiki/CPU_core), or clusters.

## Etymology {#Etymology}

"Embarrassingly" is used here to refer to parallelization problems which are "embarrassingly easy".[^o6] The term may imply embarrassment on the part of developers or compilers: "Because so many important problems remain unsolved mainly due to their intrinsic computational complexity, it would be embarrassing not to develop parallel implementations of polynomial [homotopy](wikipedia://en/212250) continuation methods."[^o7] The term is first found in the literature in a 1986 book on multiprocessors by [MATLAB](wikipedia://en/20412)'s creator [Cleve Moler](wikipedia://en/562706),[^o8] who claims to have invented the term.[^o9]

An alternative term, *pleasingly parallel*, has gained some use, perhaps to avoid the negative connotations of embarrassment in favor of a positive reflection on the parallelizability of the problems: "Of course, there is nothing embarrassing about these programs at all."[^o10]

## Examples {#Examples}

A trivial example involves serving static data. It would take very little effort to have many processing units produce the same set of bits. Indeed, the famous [Hello World](https://en.wikipedia.org/wiki/"Hello,_World!"_program) problem could easily be parallelized with few programming considerations or computational costs.

Some examples of embarrassingly parallel problems include:

- [Monte Carlo method](wikipedia://en/56098)[^o13]
- Distributed relational database queries using [distributed set processing](http://www.mysqlperformanceblog.com/2011/05/14/distributed-set-processing-with-shard-query/).
- [Numerical integration](wikipedia://en/170089)[^o14]
- Bulk processing of unrelated files of similar nature in general, such as photo gallery resizing and conversion.
- The [Mandelbrot set](wikipedia://en/19562), [Perlin noise](https://en.wikipedia.org/wiki/Perlin_noise) and similar images, where each point is calculated independently.
- [Rendering](https://en.wikipedia.org/wiki/Rendering_%28computer_graphics%29) of [computer graphics](https://en.wikipedia.org/wiki/Computer_graphics). In [computer animation](https://en.wikipedia.org/wiki/Computer_animation), each [frame](https://en.wikipedia.org/wiki/Video_frame) or pixel may be rendered independently (see: [Parallel rendering](https://en.wikipedia.org/wiki/Parallel_rendering)).
- Some [brute-force searches](https://en.wikipedia.org/wiki/Brute-force_search) in [cryptography](wikipedia://en/18934432).[^o15] Notable real-world examples include [distributed.net](wikipedia://en/337011) and [proof-of-work](https://en.wikipedia.org/wiki/Proof-of-work) systems used in [cryptocurrency](wikipedia://en/36662188).
- [BLAST](https://en.wikipedia.org/wiki/BLAST_%28biotechnology%29) searches in [bioinformatics](wikipedia://en/4214) with split databases.[^o16]
- Large scale [facial recognition systems](https://en.wikipedia.org/wiki/Facial_recognition_system) that compare thousands of arbitrary acquired faces (e.g., a security or surveillance video via [closed-circuit television](https://en.wikipedia.org/wiki/Closed-circuit_television)) with similarly large number of previously stored faces (e.g., a *[rogues gallery](https://en.wikipedia.org/wiki/Rogues_gallery)* or similar [watch list](https://en.wikipedia.org/wiki/No_Fly_List)).[^o17]
- Computer simulations comparing many independent scenarios.
- [Genetic algorithms](https://en.wikipedia.org/wiki/Genetic_algorithm).[^o18]
- [Ensemble calculations](https://en.wikipedia.org/wiki/Statistical_ensemble_%28mathematical_physics%29) of [numerical weather prediction](wikipedia://en/1505381).
- Event simulation and reconstruction in [particle physics](https://en.wikipedia.org/wiki/Particle_physics).
- The [marching squares](https://en.wikipedia.org/wiki/Marching_squares) algorithm.
- Sieving step of the [quadratic sieve](wikipedia://en/582340) and the [number field sieve](wikipedia://en/152734).
- Tree growth step of the [random forest](wikipedia://en/1363880) machine learning technique.
- [Discrete Fourier transform](wikipedia://en/8811) where each harmonic is independently calculated.
- [Convolutional neural networks](https://en.wikipedia.org/wiki/Convolutional_neural_network) running on [GPUs](https://en.wikipedia.org/wiki/GPU).
- Parallel search in [constraint programming](https://en.wikipedia.org/wiki/Constraint_programming)[^o19]

## Implementations {#Implementations}

- In [R (programming language)](wikipedia://en/376707) – The Simple Network of Workstations (SNOW) package implements a simple mechanism for using a set of workstations or a [Beowulf cluster](https://en.wikipedia.org/wiki/Beowulf_cluster) for embarrassingly parallel computations.[^o22] Similar R packages include "future", "parallel" and others.
