# Computer experiment

::: {#o1 .subject cue=lead name="Computer experiment"}

A **computer experiment** or **simulation experiment** is an experiment used to study a computer simulation, also referred to as an [in silico](https://en.wikipedia.org/wiki/In_silico) system. This area includes [computational physics](https://en.wikipedia.org/wiki/Computational_physics), [computational chemistry](https://en.wikipedia.org/wiki/Computational_chemistry), [computational biology](https://en.wikipedia.org/wiki/Computational_biology) and other similar disciplines.

:::

## Background {#Background}

[Computer simulations](https://en.wikipedia.org/wiki/Computer_simulation) are constructed to emulate a physical system. Because these are meant to replicate some aspect of a system in detail, they often do not yield an analytic solution. Therefore, methods such as [discrete event simulation](https://en.wikipedia.org/wiki/Discrete_event_simulation) or [finite element](https://en.wikipedia.org/wiki/Finite_element) solvers are used. A [computer model](https://en.wikipedia.org/wiki/Computer_model) is used to make inferences about the system it replicates. For example, [climate models](https://en.wikipedia.org/wiki/Climate_models) are often used because experimentation on an earth sized object is impossible.

## Objectives {#Objectives}

Computer experiments have been employed with many purposes in mind. Some of those include:

- [Uncertainty quantification](wikipedia://en/5987648): Characterize the uncertainty present in a computer simulation arising from unknowns during the computer simulation's construction.
- [Inverse problems](wikipedia://en/203956): Discover the underlying properties of the system from the physical data.
- Bias correction: Use physical data to correct for bias in the simulation.
- [Data assimilation](wikipedia://en/2458875): Combine multiple simulations and physical data sources into a complete predictive model.
- [Systems design](https://en.wikipedia.org/wiki/Systems_design): Find inputs that result in optimal system performance measures.

## Computer simulation modeling {#Computer_simulation_modeling}

Modeling of computer experiments typically uses a Bayesian framework. [Bayesian statistics](wikipedia://en/404412) is an interpretation of the field of [statistics](wikipedia://en/26685) where all evidence about the true state of the world is explicitly expressed in the form of [probabilities](https://en.wikipedia.org/wiki/Probabilities). In the realm of computer experiments, the Bayesian interpretation would imply we must form a [prior distribution](https://en.wikipedia.org/wiki/Prior_distribution) that represents our prior belief on the structure of the computer model. The use of this philosophy for computer experiments started in the 1980s and is nicely summarized by Sacks et al. (1989) <https://web.archive.org/web/20170918022130/https://projecteuclid.org/DPubS?service=UI&version=1.0&verb=Display&handle=euclid.ss%2F1177012413>. While the Bayesian approach is widely used, [frequentist](https://en.wikipedia.org/wiki/Frequentist) approaches have been recently discussed <https://www2.isye.gatech.edu/~jeffwu/publications/calibration-may1.pdf>.

The basic idea of this framework is to model the computer simulation as an unknown function of a set of inputs. The computer simulation is implemented as a piece of computer code that can be evaluated to produce a collection of outputs. Examples of inputs to these simulations are coefficients in the underlying model, [initial conditions](https://en.wikipedia.org/wiki/Initial_conditions) and [forcing functions](wikipedia://en/21452055). It is natural to see the simulation as a deterministic function that maps these *inputs* into a collection of *outputs*. On the basis of seeing our simulator this way, it is common to refer to the collection of inputs as $x$, the computer simulation itself as $f$, and the resulting output as $f(x)$. Both $x$ and $f(x)$ are vector quantities, and they can be very large collections of values, often indexed by space, or by time, or by both space and time.

Although $f(\cdot)$ is known in principle, in practice this is not the case. Many simulators comprise tens of thousands of lines of high-level computer code, which is not accessible to intuition. For some simulations, such as climate models, evaluation of the output for a single set of inputs can require millions of computer hours <http://amstat.tandfonline.com/doi/abs/10.1198/TECH.2009.0015#.UbixC_nFWHQ>.

### Gaussian process prior {#Gaussian_process_prior}

The typical model for a computer code output is a Gaussian process. For notational simplicity, assume $f(x)$ is a scalar. Owing to the Bayesian framework, we fix our belief that the function $f$ follows a [Gaussian process](wikipedia://en/302944), $f \sim \operatorname{GP}(m(\cdot),C(\cdot,\cdot)),$ where $m$ is the mean function and $C$ is the covariance function. Popular mean functions are low order polynomials and a popular [covariance function](wikipedia://en/9793263) is [Matern covariance](https://en.wikipedia.org/wiki/Matern_covariance), which includes both the exponential ($\nu = 1/2$) and Gaussian covariances (as $\nu \rightarrow \infty$).

## Design of computer experiments {#Design_of_computer_experiments}

The design of computer experiments has considerable differences from [design of experiments](wikipedia://en/9541) for parametric models. Since a Gaussian process prior has an infinite dimensional representation, the concepts of A and D criteria (see [Optimal design](https://en.wikipedia.org/wiki/Optimal_design)), which focus on reducing the error in the parameters, cannot be used. Replications would also be wasteful in cases when the computer simulation has no error. Criteria that are used to determine a good experimental design include integrated mean squared prediction error <https://web.archive.org/web/20170918022130/https://projecteuclid.org/DPubS?service=UI&version=1.0&verb=Display&handle=euclid.ss%2F1177012413> and distance based criteria <http://www.sciencedirect.com/science/article/pii/037837589090122B>.

Popular strategies for design include [latin hypercube sampling](wikipedia://en/710164) and [low discrepancy sequences](https://en.wikipedia.org/wiki/Low_discrepancy_sequences).

### Problems with massive sample sizes {#Problems_with_massive_sample_sizes}

Unlike physical experiments, it is common for computer experiments to have thousands of different input combinations. Because the standard inference requires [matrix inversion](wikipedia://en/217122) of a square matrix of the size of the number of samples ($n$), the cost grows on the $\mathcal{O} (n^3)$. Matrix inversion of large, dense matrices can also cause numerical inaccuracies. Currently, this problem is solved by greedy decision tree techniques, allowing effective computations for unlimited dimensionality and sample size [patent WO2013055257A1](https://patents.google.com/patent/WO2013055257A1/en), or avoided by using approximation methods, e.g. <https://wayback.archive-it.org/all/20120130182750/http://www.stat.wisc.edu/~zhiguang/Multistep_AOS.pdf>.
