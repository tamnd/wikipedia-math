# Iterated logarithm

::: {#o1 .subject cue=lead name="Iterated logarithm"}

*Image: Iterated logarithm.png.* **Figure 1.** Demonstrating log\* 4 = 2 for the base-e iterated logarithm. The value of the iterated logarithm can be found by "zig-zagging" on the curve y = log<sub>b</sub>(x) from the input n, to the interval \[0,1\]. In this case, b = e. The zig-zagging entails starting from the point (n, 0) and iteratively moving to (n, log<sub>b</sub>(n) ), to (0, log<sub>b</sub>(n) ), to (log<sub>b</sub>(n), 0 ).

In [computer science](https://en.wikipedia.org/wiki/Computer_science), the **iterated logarithm** of $n$, written $n$ (usually read "**log [star](https://en.wikipedia.org/wiki/Star_%28punctuation%29)**"), is the number of times the [logarithm](wikipedia://en/17860) function must be [iteratively](wikipedia://en/68833) applied before the result is less than or equal to $1$.[^o2] The simplest formal definition is the result of this [recurrence relation](wikipedia://en/146806):

:::

$$\log^* n := \begin{cases} 0 & \mbox{if } n \le 1; \\ 1 + \log^*(\log n) & \mbox{if } n > 1 \end{cases}$$

In computer science, is often used to indicate the **binary iterated logarithm**, which iterates the [binary logarithm](wikipedia://en/249992) (with base $2$) instead of the natural logarithm (with base *e*). Mathematically, the iterated logarithm is well defined for any base greater than $e^{1/e} \approx 1.444667$, not only for base $2$ and base *e*. The "super-logarithm" function $\mathrm {slog}_b(n)$ is "essentially equivalent" to the base $b$ iterated logarithm (although differing in minor details of [rounding](wikipedia://en/169945)) and forms an inverse to the operation of [tetration](wikipedia://en/482379).[^o3]

## Analysis of algorithms {#Analysis_of_algorithms}

The iterated logarithm is useful in [analysis of algorithms](wikipedia://en/2230) and [computational complexity](wikipedia://en/7543), appearing in the time and space complexity bounds of some algorithms such as:

- Finding the [Delaunay triangulation](wikipedia://en/8864) of a set of points knowing the [Euclidean minimum spanning tree](wikipedia://en/1040597): randomized [O](https://en.wikipedia.org/wiki/Big-O_notation)(*n* *n*) time.[^o5]
- [Fürer's algorithm](https://en.wikipedia.org/wiki/Fürer's_algorithm) for integer multiplication: O(*n* log *n* 2<sup>*O*(lg *n*)</sup>).
- Finding an approximate maximum (element at least as large as the median): lg *n* − 1 ± 3 parallel operations.[^o6]
- Richard Cole and [Uzi Vishkin](https://en.wikipedia.org/wiki/Uzi_Vishkin)'s [distributed algorithm for 3-coloring an *n*-cycle](wikipedia://en/426743#Parallel_and_distributed_algorithms): *O*( *n*) synchronous communication rounds.[^o7]

The iterated logarithm grows at an extremely slow rate, much slower than the logarithm itself, or repeats of it. This is because the tetration grows much faster than iterated exponential:

$${^{y}b} = \underbrace{b^{b^{\cdot^{\cdot^{b}}}}}_y \gg \underbrace{b^{b^{\cdot^{\cdot^{b^{y}}}}}}_n$$

the inverse grows much slower: $\log_b^* x \ll \log_b^n x$.

For all values of *n* relevant to counting the running times of algorithms implemented in practice (i.e., *n* ≤ 2<sup>65536</sup>, which is far more than the estimated number of atoms in the known universe), the iterated logarithm with base 2 has a value no more than 5.

*The base-2 iterated logarithm*

::: {#o8 .table cue=table name="The base-2 iterated logarithm"}

| *x* | *x* |
|---|---|
| −∞, 1 | 0 |
| 1, 2 | 1 |
| 2, 4 | 2 |
| 4, 16 | 3 |
| 16, 65536 | 4 |
| 65536, 2<sup>65536</sup> | 5 |

:::

Higher bases give smaller iterated logarithms.

## Other applications {#Other_applications}

The iterated logarithm is closely related to the [generalized logarithm function](https://en.wikipedia.org/wiki/Generalized_logarithm_function) used in [symmetric level-index arithmetic](https://en.wikipedia.org/wiki/Symmetric_level-index_arithmetic). The additive [persistence of a number](wikipedia://en/624708), the number of times someone must replace the number by the sum of its digits before reaching its [digital root](wikipedia://en/8286632), is $O(\log^* n)$.

In [computational complexity theory](wikipedia://en/7543), Santhanam[^o10] shows that the [computational resources](wikipedia://en/4628222) [DTIME](wikipedia://en/658538) — [computation time](wikipedia://en/405944) for a [deterministic Turing machine](wikipedia://en/30403) — and [NTIME](wikipedia://en/658539) — computation time for a [non-deterministic Turing machine](https://en.wikipedia.org/wiki/Non-deterministic_Turing_machine) — are distinct up to $n\sqrt{\log^*n}.$

[Gijswijt's sequence](wikipedia://en/50359643) is known to be bounded above by $O(\log^*n)$. (The lower bound is $O(1)$, since every natural number has positive [natural density](wikipedia://en/1819983) in this sequence.)[^o11]
