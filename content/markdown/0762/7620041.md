# PKCS 11

::: {#o1 .subject cue=lead name="PKCS 11"}

In [cryptography](wikipedia://en/18934432), **PKCS #11** is a [Public-Key Cryptography Standard](https://en.wikipedia.org/wiki/Public-Key_Cryptography_Standards) that defines a C programming interface to create and manipulate [cryptographic tokens](https://en.wikipedia.org/wiki/Cryptographic_tokens) that may contain secret [cryptographic keys](https://en.wikipedia.org/wiki/Cryptographic_key). It is often used to communicate with a [Hardware Security Module](https://en.wikipedia.org/wiki/Hardware_Security_Module) or [smart cards](https://en.wikipedia.org/wiki/Smart_cards).

:::

The PKCS #11 standard is managed by [OASIS](https://en.wikipedia.org/wiki/OASIS_%28organization%29)[^o2] with the current version being 3.1 [^o3] PKCS #11 is sometimes referred to as "Cryptoki" (from "cryptographic token interface" and pronounced as "crypto-key").

The API defines most commonly used cryptographic object types ([RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) keys, [X.509](https://en.wikipedia.org/wiki/X.509) certificates, [DES](wikipedia://en/7978)/[Triple DES](wikipedia://en/48375) keys, etc.) and all the functions needed to use, create/generate, modify and delete those objects.

## Usage {#Usage}

Most commercial [certificate authority](wikipedia://en/296370) (CA) software uses PKCS #11 to access the CA signing key or to enroll user certificates. Cross-platform software that needs to use [smart cards](https://en.wikipedia.org/wiki/Smart_cards) uses PKCS #11, such as [Mozilla Firefox](https://en.wikipedia.org/wiki/Mozilla_Firefox) and [OpenSSL](wikipedia://en/438819) (using an extension). It is also used to access smart cards and [HSMs](https://en.wikipedia.org/wiki/Hardware_security_module). Software written for [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows) may use the platform specific [MS-CAPI](https://en.wikipedia.org/wiki/Cryptographic_Application_Programming_Interface) API instead. Both [Oracle Solaris](https://en.wikipedia.org/wiki/Solaris_%28operating_system%29) and [Red Hat Enterprise Linux](https://en.wikipedia.org/wiki/Red_Hat_Enterprise_Linux) contain implementations for use by applications, as well.

## Relationship to KMIP {#Relationship_to_KMIP}

The [Key Management Interoperability Protocol](https://en.wikipedia.org/wiki/Key_Management_Interoperability_Protocol) (KMIP) defines a wire protocol that has similar functionality to the PKCS #11 API.

The two standards were originally developed independently but are now both governed by an [OASIS](https://en.wikipedia.org/wiki/OASIS_%28organization%29) technical committee. It is the stated objective of both the PKCS #11 and KMIP committees to align the standards where practicable. KMIP also has special operations that provide a complete standards based wire protocol for PKCS #11.

There is considerable overlap between members of the two technical committees.

## History {#History}

The PKCS #11 standard originated from [RSA Security](wikipedia://en/301240) along with its other [PKCS standards](wikipedia://en/616418) in 1994. In 2013, RSA contributed the latest draft revision of the standard (PKCS #11 2.30) to [OASIS](https://en.wikipedia.org/wiki/OASIS_%28organization%29) to continue the work on the standard within the newly created OASIS PKCS11 Technical Committee.[^o7] The following list contains significant revision information:

- 01/1994: project launched
- 04/1995: v1.0 published
- 12/1997: v2.01 published
- 12/1999: v2.10 published
- 01/2001: v2.11 published[^o8]
- 06/2004: v2.20 published[^o2]
- 12/2005: amendments 1 & 2 ([one-time password](wikipedia://en/1190077) tokens, CT-KIP [^o9])
- 01/2007: amendment 3 (additional mechanisms)
- 09/2009: v2.30 draft published for review, but final version never published
- 12/2012: RSA announce that PKCS #11 management is being transitioned to [OASIS](https://en.wikipedia.org/wiki/OASIS_%28organization%29)[^o10]
- 03/2013: OASIS PKCS #11 Technical Committee Inaugural meetings, works starts on v2.40 [^o11]
- 04/2015: OASIS PKCS #11 v2.40 specifications become approved OASIS standards [^o12]
- 05/2016: OASIS PKCS #11 v2.40 Errata 01 specifications become approved OASIS errata [^o13]
- 07/2020: OASIS PKCS #11 v3.0 specifications become approved OASIS standards [^o14]
- 07/2023: OASIS PKCS #11 v3.1 specifications become approved OASIS standards [^o3]
