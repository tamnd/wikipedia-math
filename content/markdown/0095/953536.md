# GiNaC

::: {#o3 .subject cue=lead name="GiNaC"}

**GiNaC** is a [free](https://en.wikipedia.org/wiki/Free_software) [computer algebra system](wikipedia://en/54427) released under the [GNU General Public License](https://en.wikipedia.org/wiki/GNU_General_Public_License). The name is a [recursive acronym](https://en.wikipedia.org/wiki/Recursive_acronym) for "GiNaC is Not a CAS" ([Computer Algebra System](https://en.wikipedia.org/wiki/Computer_Algebra_System)). This is similar to the [GNU](https://en.wikipedia.org/wiki/GNU) acronym "GNU's not Unix".[^o4]

:::

What distinguishes GiNaC from most other computer algebra systems is that it does not provide a high-level interface for user interaction. Rather, it encourages its users to write [symbolic](https://en.wikipedia.org/wiki/Symbolic_computation) [algorithms](wikipedia://en/775) directly in [C++](https://en.wikipedia.org/wiki/C++), which is GiNaC's implementation [programming language](wikipedia://en/23015). The algebraic syntax is achieved in C++ through the use of [operator overloading](https://en.wikipedia.org/wiki/Operator_overloading). The name GiNaC is also explained by its developers' perception that most "computer algebra systems" put too much emphasis on a high-level interface and too little on interoperability.

GiNaC uses the [CLN](https://en.wikipedia.org/wiki/Class_Library_for_Numbers) library for implementing [arbitrary-precision arithmetic](wikipedia://en/600892). Symbolically, it can do multivariate polynomial arithmetic, [factor polynomials](https://en.wikipedia.org/wiki/Polynomial_factorization), compute [GCDs](wikipedia://en/12354), expand [series](wikipedia://en/61213), and compute with [matrices](wikipedia://en/20556859). It is equipped to handle certain [noncommutative algebras](wikipedia://en/24062516) which are extensively used in [theoretical](wikipedia://en/19594028) [high energy physics](https://en.wikipedia.org/wiki/Particle_physics)—[Clifford algebras](https://en.wikipedia.org/wiki/Clifford_Algebra), [SU(3)](wikipedia://en/173997#The_group_SU%283%29) [Lie algebras](wikipedia://en/17944), and [Lorentz tensors](wikipedia://en/1912367)—and can evaluate a wide range of [multiple polylogarithms](wikipedia://en/482471). Due to this, it is extensively used in [dimensional regularization](wikipedia://en/1934335) computations – but it is not restricted to physics.

GiNaC is the symbolic foundation in several [open-source](https://en.wikipedia.org/wiki/Open-source_software) projects: there is a symbolic extension for [GNU Octave](wikipedia://en/48707),[^o5] a simulator for [magnetic resonance imaging](https://en.wikipedia.org/wiki/Magnetic_resonance_imaging),[^o6] and since May 2009, [Pynac](http://pynac.org/), a [fork](https://en.wikipedia.org/wiki/Fork_%28software_development%29) of GiNaC, provides the backend for symbolic expressions in [SageMath](https://en.wikipedia.org/wiki/SageMath).[^o7]
