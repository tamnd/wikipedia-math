# Longest path problem

*Image: Longest path in a graph.svg.* A longest path in the [complete bipartite graph](wikipedia://en/525320) $K_{m,n}$ colored red

::: {#o1 .subject cue=lead name="Longest path problem"}

In [graph theory](wikipedia://en/12401) and [theoretical computer science](wikipedia://en/323392), the **longest path problem** is the problem of finding a simple [path](wikipedia://en/638889) of maximum length in a given [graph](wikipedia://en/325806). A path is called *simple* if it does not have any repeated [vertices](wikipedia://en/638899); the length of a path may either be measured by its number of edges, or (in [weighted graphs](https://en.wikipedia.org/wiki/Weighted_graph)) by the sum of the weights of its edges. In contrast to the [shortest path problem](wikipedia://en/41985), which can be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) in graphs without negative-weight cycles, the longest path problem is [NP-hard](https://en.wikipedia.org/wiki/NP-hard) and the decision version of the problem, which asks whether a path exists of at least some given length, is [NP-complete](https://en.wikipedia.org/wiki/NP-complete). This means that the decision problem cannot be solved in polynomial time for arbitrary graphs unless [P = NP](https://en.wikipedia.org/wiki/P_=_NP). Stronger hardness results are also known showing that it is difficult to [approximate](wikipedia://en/563105). However, it has a [linear time](https://en.wikipedia.org/wiki/Linear_time) solution for [directed acyclic graphs](wikipedia://en/204002), which has important applications in finding the [critical path](wikipedia://en/203646) in scheduling problems.

:::

## NP-hardness {#NP-hardness}

The NP-hardness of the unweighted longest path problem can be shown using a reduction from the [Hamiltonian path problem](wikipedia://en/149646): a graph *G* has a Hamiltonian path if and only if its longest path has length *n* − 1, where *n* is the number of vertices in *G*. Because the Hamiltonian path problem is NP-complete, this reduction shows that the [decision version](wikipedia://en/8336) of the longest path problem is also NP-complete. In this decision problem, the input is a graph *G* and a number *k*; the desired output is *yes* if *G* contains a path of *k* or more edges, and *no* otherwise.[^o3]

If the longest path problem could be solved in polynomial time, it could be used to solve this decision problem, by finding a longest path and then comparing its length to the number *k*. Therefore, the longest path problem is NP-hard. The question "does there exist a simple path in a given graph with at least *k* edges" is NP-complete.[^o4]

In weighted [complete graphs](wikipedia://en/85816) with non-negative edge weights, the weighted longest path problem is the same as the [Travelling salesman path problem](wikipedia://en/31248), because the longest path always includes all vertices.[^o5]

## Acyclic graphs {#Acyclic_graphs}

A longest path between two given vertices *s* and *t* in a weighted graph *G* is the same thing as a shortest path in a graph −*G* derived from *G* by changing every weight to its negation. Therefore, if shortest paths can be found in −*G*, then longest paths can also be found in *G*.[^o7]

For most graphs, this transformation is not useful because it creates cycles of negative length in −*G*. But if *G* is a [directed acyclic graph](wikipedia://en/204002) (DAG), then no negative cycles can be created, and a longest path in *G* can be found in [linear time](https://en.wikipedia.org/wiki/Linear_time) by applying a linear time algorithm for shortest paths in −*G*, which is also a directed acyclic graph.[^o7] For a DAG, the longest path from a source vertex to all other vertices can be obtained by [running the shortest-path algorithm](wikipedia://en/897064#Application_to_shortest_path_finding) on −*G*.

Similarly, for each vertex *v* in a given DAG, the length of the longest path ending at *v* may be obtained by the following steps:

1. Find a [topological ordering](https://en.wikipedia.org/wiki/Topological_ordering) of the given DAG.
1. For each vertex *v* of the DAG, in the topological ordering, compute the length of the longest path ending at *v* by looking at its incoming neighbors and adding one to the maximum length recorded for those neighbors. If *v* has no incoming neighbors, set the length of the longest path ending at *v* to zero. In either case, record this number so that later steps of the algorithm can access it.

Once this has been done, the longest path in the whole DAG may be obtained by starting at the vertex *v* with the largest recorded value, then repeatedly stepping backwards to its incoming neighbor with the largest recorded value, and reversing the sequence of vertices found in this way.

This is equivalent to running the shortest-path algorithm on −*G*.

### Critical paths {#Critical_paths}

The [critical path method](wikipedia://en/203646) for scheduling a set of activities involves the construction of a directed acyclic graph in which the vertices represent project milestones and the edges represent activities that must be performed after one milestone and before another; each edge is weighted by an estimate of the amount of time the corresponding activity will take to complete. In such a graph, the longest path from the first milestone to the last one is the critical path, which describes the total time for completing the project.[^o7]

Longest paths of directed acyclic graphs may also be applied in [layered graph drawing](wikipedia://en/33211287): assigning each vertex *v* of a directed acyclic graph *G* to the layer whose number is the length of the longest path ending at *v* results in a layer assignment for *G* with the minimum possible number of layers.[^o9]

## Approximation {#Approximation}

(Björklund Husfeldt Khanna 2004) write that the longest path problem in unweighted undirected graphs "is notorious for the difficulty of understanding its approximation hardness".[^o13] The best polynomial time approximation algorithm known for this case achieves only a very weak approximation ratio, $n/\exp(\Omega(\sqrt{\log n}))$.[^o14] For all $\epsilon>0$, it is not possible to approximate the longest path to within a factor of $2^{(\log n)^{1-\epsilon}}$ unless NP is contained within [quasi-polynomial deterministic time](wikipedia://en/405944); however, there is a big gap between this inapproximability result and the known approximation algorithms for this problem.[^o15]

In the case of unweighted but directed graphs, strong inapproximability results are known. For every $\epsilon>0$ the problem cannot be approximated to within a factor of $n^{1-\epsilon}$ unless P = NP, and with stronger complexity-theoretic assumptions it cannot be approximated to within a factor of $n/\log^{2+\epsilon} n$.[^o13] The [color-coding](wikipedia://en/22469695) technique can be used to find paths of logarithmic length, if they exist, but this gives an approximation ratio of only $O(n/\log n)$.[^o16]

:::

## Parameterized complexity {#Parameterized_complexity}

The longest path problem is [fixed-parameter tractable](wikipedia://en/603026) when parameterized by the length of the path. For instance, it can be solved in time linear in the size of the input graph (but exponential in the length of the path), by an algorithm that performs the following steps:

1. Perform a [depth-first search](wikipedia://en/97034) of the graph. Let $d$ be the height of the resulting [depth-first search tree](wikipedia://en/30247317).
1. Use the sequence of root-to-leaf paths of the depth-first search tree, in the order in which they were traversed by the search, to construct a [path decomposition](https://en.wikipedia.org/wiki/Path_decomposition) of the graph, with pathwidth $d$.
1. Apply [dynamic programming](wikipedia://en/125297) to this path decomposition to find a longest path in time $O(d!2^dn)$, where $n$ is the number of vertices in the graph.

Since the output path has length at least as large as $d$, the running time is also bounded by $O(\ell!2^\ell n)$, where $\ell$ is the length of the longest path.[^o18] Using color-coding, the dependence on path length can be reduced to singly exponential.[^o16][^o19][^o20][^o21] A similar dynamic programming technique shows that the longest path problem is also fixed-parameter tractable when parameterized by the [treewidth](wikipedia://en/3987086) of the graph.

For graphs of bounded [clique-width](wikipedia://en/16795502), the longest path can also be solved by a polynomial time dynamic programming algorithm. However, the exponent of the polynomial depends on the clique-width of the graph, so this algorithms is not fixed-parameter tractable. The longest path problem, parameterized by clique-width, is hard for the [parameterized complexity](wikipedia://en/603026) class $W[1]$, showing that a fixed-parameter tractable algorithm is unlikely to exist.[^o22]

## Special classes of graphs {#Special_classes_of_graphs}

A linear-time algorithm for finding a longest path in a [tree](wikipedia://en/48560) was proposed by [Edsger Dijkstra](https://en.wikipedia.org/wiki/Edsger_W._Dijkstra) around 1960, while a formal proof of this algorithm was published in 2002.[^o24] Furthermore, a longest path can be computed in polynomial time on weighted trees, on [block graphs](wikipedia://en/29106883), on [cacti](wikipedia://en/9944209),[^o25] on [bipartite](wikipedia://en/244431) [permutation graphs](wikipedia://en/17625375),[^o26] and on [Ptolemaic graphs](wikipedia://en/50730814).[^o27]

For the class of [interval graphs](wikipedia://en/363423), an $O(n^4)$-time algorithm is known, which uses a dynamic programming approach.[^o28] This dynamic programming approach has been exploited to obtain polynomial-time algorithms on the greater classes of [circular-arc graphs](https://en.wikipedia.org/wiki/Circular-arc_graph)[^o29] and of co-comparability graphs (i.e. of the [complements](wikipedia://en/1175649) of [comparability graphs](wikipedia://en/6978672), which also contain [permutation graphs](wikipedia://en/17625375)),[^o30] both having the same running time $O(n^4)$. The latter algorithm is based on special properties of the lexicographic depth first search (LDFS) vertex ordering[^o31] of co-comparability graphs. For co-comparability graphs also an alternative polynomial-time algorithm with higher running time $O(n^7)$ is known, which is based on the [Hasse diagram](wikipedia://en/338199) of the [partially ordered set](wikipedia://en/23572) defined by the [complement](wikipedia://en/1175649) of the input co-comparability graph.[^o32]

Furthermore, the longest path problem is solvable in polynomial time on any class of graphs with bounded treewidth or bounded clique-width, such as the [distance-hereditary graphs](wikipedia://en/17315337). Finally, it is clearly NP-hard on all graph classes on which the Hamiltonian path problem is NP-hard, such as on [split graphs](wikipedia://en/9928681), [circle graphs](wikipedia://en/1399873), and [planar graphs](wikipedia://en/24314).

A simple model of a directed acyclic graph is the [Price model](https://en.wikipedia.org/wiki/Price's_model), developed by [Derek J. de Solla Price](https://en.wikipedia.org/wiki/Derek_J._de_Solla_Price) to represent [citation networks](https://en.wikipedia.org/wiki/Citation_graph). This is simple enough to allow for analytic results to be found for some properties. For instance, the length of the longest path, from the n-th node added to the network to the first node in the network, scales as[^o33] $\ln(n)$.
