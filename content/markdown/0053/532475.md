# Camellia (cipher)

::: {#o4 .subject cue=lead name="Camellia"}

In [cryptography](wikipedia://en/18934432), **Camellia** is a [symmetric key](wikipedia://en/53042) [block cipher](wikipedia://en/4594) with a [block size](wikipedia://en/294065) of 128 [bits](https://en.wikipedia.org/wiki/Bit) and [key sizes](wikipedia://en/5749) of 128, 192 and 256 bits. It was jointly developed by [Mitsubishi Electric](https://en.wikipedia.org/wiki/Mitsubishi_Electric_Corporation) and [NTT](https://en.wikipedia.org/wiki/Nippon_Telegraph_and_Telephone) of [Japan](https://en.wikipedia.org/wiki/Japan). The cipher has been approved for use by the [ISO/IEC](https://en.wikipedia.org/wiki/International_Organization_for_Standardization), the [European Union](https://en.wikipedia.org/wiki/European_Union)'s [NESSIE](wikipedia://en/497430) project and the [Japanese](https://en.wikipedia.org/wiki/Japan) [CRYPTREC](wikipedia://en/549159) project. The [cipher](wikipedia://en/4594) has security levels and processing abilities comparable to the [Advanced Encryption Standard](wikipedia://en/1260).[^o5]

:::

The [cipher](wikipedia://en/4594) was designed to be suitable for both software and hardware implementations, from low-cost smart cards to high-speed network systems. It is part of the [Transport Layer Security](wikipedia://en/187813) (TLS)5932 [cryptographic protocol](wikipedia://en/591994) designed to provide [communications security](wikipedia://en/40922) over a [computer network](https://en.wikipedia.org/wiki/Computer_network) such as the [Internet](https://en.wikipedia.org/wiki/Internet).

The cipher was named for the flower *[Camellia japonica](https://en.wikipedia.org/wiki/Camellia_japonica)*, which is known for being long-lived as well as because the cipher was developed in Japan.

## Design {#Design}

Camellia is a [Feistel cipher](wikipedia://en/352709) with either 18 rounds (when using 128-bit keys) or 24 rounds (when using 192- or 256-bit keys). Every six rounds, a logical transformation layer is applied: the so-called "FL-function" or its inverse. Camellia uses four 8×8-bit [S-boxes](https://en.wikipedia.org/wiki/S-boxes) with input and output [affine transformations](https://en.wikipedia.org/wiki/Affine_transformations) and logical operations. The cipher also uses input and output [key whitening](wikipedia://en/2990178). The [diffusion](https://en.wikipedia.org/wiki/Diffusion_%28cryptography%29) layer uses a [linear transformation](https://en.wikipedia.org/wiki/Linear_transformation) based on a [matrix](wikipedia://en/20556859) with a [branch number](wikipedia://en/73558859) of 5.

## Security analysis {#Security_analysis}

Camellia is considered a modern, safe cipher. Even using the smaller key size option (128 bits), it's considered infeasible to break it by [brute-force attack](wikipedia://en/53784) on the keys with current technology. There are no known successful attacks that weaken the cipher considerably. The cipher has been approved for use by the [ISO/IEC](https://en.wikipedia.org/wiki/International_Organization_for_Standardization), the [European Union](https://en.wikipedia.org/wiki/European_Union)'s [NESSIE](wikipedia://en/497430) project and the [Japanese](https://en.wikipedia.org/wiki/Japan) [CRYPTREC](wikipedia://en/549159) project. The Japanese [cipher](wikipedia://en/4594) has security levels and processing abilities comparable to the [AES/Rijndael](wikipedia://en/1260) cipher.[^o5]

- The Camellia (as well as [AES](wikipedia://en/1260)) [S-boxes](https://en.wikipedia.org/wiki/S-boxes) can be described by a system of 23 quadratic equations in 80 terms.[^o9]
- The [key schedule](wikipedia://en/609603) can be described by 1120 equations in 768 variables using 3328 linear and quadratic terms.[^o8]
- The entire block cipher can be described by 5104 equations in 2816 variables using 14592 linear and quadratic terms.[^o8]
- In total, 6224 equations in 3584 variables using 17920 linear and quadratic terms are required.[^o8]
- The number of [free terms](https://en.wikipedia.org/wiki/Free_variable) is 11696, which is approximately the same number as for [AES](wikipedia://en/1260).

Theoretically, such properties might make it possible to break Camellia (and [AES](wikipedia://en/1260)) using an algebraic attack, such as [extended sparse linearisation](wikipedia://en/660941), in the future, provided that the attack becomes feasible.

## Patent status {#Patent_status}

Although Camellia is patented, it is available under a royalty-free license.[^o11] This has allowed the Camellia cipher to become part of the [OpenSSL](wikipedia://en/438819) Project, under an [open-source license](https://en.wikipedia.org/wiki/Open-source_license), since November 2006.[^o12] It has also allowed it to become part of the Mozilla's [NSS](wikipedia://en/5137674) (Network Security Services) module.[^o14]

## Adoption {#Adoption}

Support for Camellia was added to the final release of [Mozilla Firefox](https://en.wikipedia.org/wiki/Mozilla_Firefox) 3 in 2008[^o14] (disabled by default as of Firefox 33 in 2014[^o15] in spirit of the "Proposal to Change the Default TLS Ciphersuites Offered by Browsers",[^o16] and has been dropped from version 37 in 2015[^o17]). [Pale Moon](https://en.wikipedia.org/wiki/Pale_Moon_%28web_browser%29), a fork of Mozilla/Firefox, continues to offer Camellia and had extended its support to include [Galois/Counter mode (GCM)](wikipedia://en/5897139) suites with the cipher,[^o18] but has removed the GCM modes again with release 27.2.0, citing the apparent lack of interest in them.

Later in 2008, the [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD) Release Engineering Team announced that the cipher had also been included in the [FreeBSD](https://en.wikipedia.org/wiki/FreeBSD) 6.4-RELEASE. Also, support for the Camellia cipher was added to the disk encryption storage class [geli](wikipedia://en/22725313) of FreeBSD by Yoshisato Yanagisawa.[^o19]

In September 2009, [GNU Privacy Guard](wikipedia://en/38809) added support for Camellia in version 1.4.10.[^o20]

[VeraCrypt](wikipedia://en/45345491) (a fork of [TrueCrypt](wikipedia://en/905962)) included Camellia as one of its supported encryption algorithms.[^o21]

Moreover, various popular [security libraries](https://en.wikipedia.org/wiki/Library_%28computing%29), such as [Crypto++](https://en.wikipedia.org/wiki/Crypto++), [GnuTLS](wikipedia://en/949758), [mbed TLS](https://en.wikipedia.org/wiki/Mbed_TLS) and [OpenSSL](wikipedia://en/438819) also include support for Camellia.

[Thales](https://en.wikipedia.org/wiki/Thales_Group) and [Bloombase](https://en.wikipedia.org/wiki/Bloombase) support Camellia encryption cipher with their data cryptography offerings.[^o22]

On March 26, 2013, Camellia was announced as having been selected again for adoption in Japan's new e-Government Recommended Ciphers List as the only 128-bit block cipher encryption algorithm developed in Japan. This coincides with the CRYPTREC list being updated for the first time in 10 years. The selection was based on Camellia's high reputation for ease of procurement, and security and performance features comparable to those of the Advanced Encryption Standard (AES). Camellia remains unbroken in its full implementation.[^o23] An impossible differential attack on 12-round Camellia without FL/FL<sup>−1</sup> layers does exist.[^o24]

## Performance {#Performance}

The S-boxes used by Camellia share a similar structure to AES's S-box. As a result, it is possible to accelerate Camellia software implementations using CPU instruction sets designed for AES, such as x86 [AES-NI](wikipedia://en/23095336) or x86 [GFNI](https://en.wikipedia.org/wiki/AVX-512#GFNI), by [affine isomorphism](wikipedia://en/298834).[^o26][^o27]
