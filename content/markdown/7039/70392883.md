# Fuzzy hashing

::: {#o1 .subject cue=lead name="Fuzzy hashing"}

**Fuzzy hashing**, also known as **similarity hashing**,[^o8] is a technique for [detecting data that is similar](https://en.wikipedia.org/wiki/Content_similarity_detection), but not exactly the same, as other data. This is in contrast to [cryptographic hash functions](wikipedia://en/439526), which are designed to have significantly different hashes for even minor differences. Fuzzy hashing has been used to identify malware[^o15][^o17] and has potential for other applications, like [data loss prevention](https://en.wikipedia.org/wiki/Data_loss_prevention) and detecting multiple versions of code.[^o9][^o11]

:::

## Background {#Background}

A [hash function](https://en.wikipedia.org/wiki/Hash_function) is a mathematical algorithm which maps arbitrary-sized data to a fixed size output. Many solutions use [cryptographic hash functions](https://en.wikipedia.org/wiki/Cryptographic_hash_functions) like [SHA-256](https://en.wikipedia.org/wiki/SHA-256) to detect duplicates or check for known files within large collection of files.[^o9] However, cryptographic hash functions cannot be used for determining if a file is *similar* to a known file, because one of the requirements of a cryptographic hash function is that a small change to the input should change the hash value so extensively that the new hash value appears uncorrelated with the old hash value ([avalanche effect](wikipedia://en/769439)).[^o16]

Fuzzy hashing exists to solve this problem of detecting data that is similar, but not exactly the same, as other data. Fuzzy hashing algorithms specifically use algorithms in which two similar inputs will generate two similar hash values. This property is the exact opposite of the avalanche effect desired in cryptographic hash functions.

Fuzzy hashing can also be used to detect when one object is contained within another.[^o8]

## Approaches {#Approaches}

There are a few approaches used for building fuzzy hash algorithms:[^o12][^o11]

- Context-triggered piecewise hashing (CTPH), which constructs a hash by splitting the input into multiple pieces, calculating traditional hashes for each piece, and then combining those traditional hashes into a single string.[^o19]
- [Locality-sensitive hashing](https://en.wikipedia.org/wiki/Locality-sensitive_hashing) places similar input items into the same "buckets", which can be used for [data clustering](wikipedia://en/669675) and [nearest neighbor searches](https://en.wikipedia.org/wiki/Nearest_neighbor_search).

## Notable tools and algorithms {#Notable_tools_and_algorithms}

- *spamsum* is a tool written by [Andrew Tridgell](https://en.wikipedia.org/wiki/Andrew_Tridgell) that uses fuzzy hashing to determine whether an email is similar to known spam. It operates by generating a fuzzy hash for an email that it compares against the fuzzy hashes from known spam emails to generate a match result between 0 (complete mismatch) to 100 (perfect match). If the match result is high enough, the email is classified as spam.[^o13][^o14]
- *[Nilsimsa Hash](https://en.wikipedia.org/wiki/Nilsimsa_Hash)* is an anti-spam–focused [locality-sensitive hashing](https://en.wikipedia.org/wiki/Locality-sensitive_hashing) algorithm.
- *ssdeep* is a fuzzy hashing tool based on context-triggered piecewise hashing to compare files.[^o9]
- *sdhash* is a fuzzy hashing tool based on using [Bloom filters](https://en.wikipedia.org/wiki/Bloom_filter) to determine whether one file is contained within another or how similar two files are to each other.[^o10]
- *TLSH* is a locality-sensitive hashing scheme for comparing whether files are similar to each other. It has been used for malware clustering.[^o18]
- *[Rspamd](https://en.wikipedia.org/wiki/Rspamd)* uses fuzzy hashing to detect spam emails, using the *shingles algorithm* for this purpose.[^o20][^o21]
