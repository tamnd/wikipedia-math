# Full entropy

::: {#o1 .subject cue=lead name="Full entropy"}

In cryptography, **full entropy** is a property of an output of a [random number generator](https://en.wikipedia.org/wiki/Random_number_generator). The output has full entropy if it cannot practically be distinguished from an output of a theoretical perfect random number source (has almost $n$ bits of entropy for an $n$-bit output).[^n1]

:::

The term is extensively used in the [NIST](https://en.wikipedia.org/wiki/NIST) random generator standards [NIST SP 800-90A](wikipedia://en/40611086) and [NIST SP 800-90B](wikipedia://en/62117026). With full entropy, the per-bit entropy in the output of the random number generator is close to one: $1-\epsilon$, where per NIST a practical $\epsilon<2^{-32}$.[^n1]

Some sources use the term to define the ideal random bit string (one bit of entropy per bit of output). In this sense, "getting to 100% full entropy is impossible" in the real world.[^n2]

::: {#o6 .definition cue=heading name="Definition"}

## Definition {#Definition}

The mathematical definition relies on a "distinguishing game": an adversary with unlimited computing power is provided with two sets of random numbers, each containing $W$ elements of length $n$. One set is *ideal*, it contains bit strings from the theoretically perfect random number generator, the other set is *real* and includes bit strings from the practical random number source after a [randomness extractor](wikipedia://en/18362292). The full entropy for particular values of $W$ and positive parameter $\delta$ is achieved if an adversary cannot guess the real set with probability higher than $\frac 1 2 + \delta$.[^n3]

:::

## Additional entropy {#Additional_entropy}

The practical way to achieve the full entropy is to obtain from an entropy source bit strings longer than $n$ bits, apply to them a high-quality randomness extractor that produces the $n$-bit result, and build the real set from these results. The ideal elements by nature have an entropy value of $n$. The inputs of the conditioning function will need to have a higher [min-entropy](wikipedia://en/41299452) value $H$ to satisfy the full-entropy definition. The number of additional bits of entropy $H-n$ depends on $W$ and $\delta$; the following table contains few representative values:[^n4]

*Minimum value of additional entropy $H-n$*

::: {#o10 .table cue=table name="Minimum value of additional entropy H-n"}

| $W$ | $\delta = 2^{-20}$ | $\delta = 2^{-10}$ |
|---|---|---|
| $2^{32}$ | \67.3 | \47.3 |
| $2^{48}$ | \83.3 | \63.3 |
| $2^{56}$ | \91.3 | \71.3 |

:::

## Randomness extractor requirements {#Randomness_extractor_requirements}

Not every [randomness extractor](wikipedia://en/18362292) will produce the desired results. For example, the [Von Neumann extractor](https://en.wikipedia.org/wiki/Von_Neumann_extractor), while providing an unbiased output, does not decorrelate groups of bits, so for serially correlated inputs (typical for many [entropy sources](https://en.wikipedia.org/wiki/Entropy_source)) the output bits will not be [independent](wikipedia://en/30876902).[^n5] NIST therefore defines the "vetted conditioning components" in its [NIST SP 800-90B](wikipedia://en/62117026) standard, including [AES](https://en.wikipedia.org/wiki/Rijndael)-[CBC-MAC](wikipedia://en/2840574).[^n5]
