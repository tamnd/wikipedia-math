# Rabin signature algorithm

::: {#o1 .subject cue=lead name="Rabin signature algorithm"}

In [cryptography](wikipedia://en/18934432), the **Rabin signature algorithm** is a method of [digital signature](wikipedia://en/59644) originally published by [Michael O. Rabin](wikipedia://en/298404) in 1979.[^o2][^o3]

:::

The Rabin signature algorithm was one of the first digital signature schemes proposed. By using a [trapdoor function](wikipedia://en/206753) with a [hash](wikipedia://en/439526) of the message rather than with the message itself, in contrast to earlier proposals of one-time hash-based signatures or trapdoor-based signatures without hashing,[^o4][^o5] Rabin's was the first published design to meet what is now the modern standard of security for digital signatures for more than one message, [existential unforgeability under chosen-message attack](wikipedia://en/8754928).[^o6]

Rabin signatures resemble [RSA signatures](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29) with exponent $e=2$, but this leads to qualitative differences that enable more efficient implementation[^o6] and a security guarantee relative to the difficulty of [integer factorization](wikipedia://en/15491),[^o2][^o3][^o7] which [has not been proven for RSA](wikipedia://en/1544741). However, Rabin signatures have seen relatively little use or standardization outside [IEEE P1363](wikipedia://en/1644154)[^o19] in comparison to RSA signature schemes such as [RSASSA-PKCS1-v1\_5](wikipedia://en/16706008) and [RSASSA-PSS](wikipedia://en/53823229).

::: {#o9 .definition cue=heading name="Definition"}

## Definition {#Definition}

The Rabin signature scheme is parametrized by a randomized [hash function](wikipedia://en/439526) $H(m, u)$ of a message $m$ and $k$-bit randomization string $u$.

**Public key**

A public key is a pair of integers $(n, b)$ with $0 \leq b < n$ and $n$ odd. $b$ is chosen arbitrarily and may be a fixed constant.

**Signature**

A signature on a message $m$ is a pair $(u, x)$ of a $k$-bit string $u$ and an integer $x$ such that

$$x (x + b) \equiv H(m, u) \pmod n.$$

**Private key**

The private key for a public key $(n, b)$ is the secret odd prime factorization $p\cdot q$ of $n$, chosen uniformly at random from some large space of primes.

**Signing a message**

To make a signature on a message $m$ using the private key, the signer starts by picking a $k$-bit string $u$ uniformly at random, and computes $c := H(m, u)$. Let $d = (b/2) \bmod n$. If $c + d^2$ is a [quadratic nonresidue](https://en.wikipedia.org/wiki/Quadratic_nonresidue) modulo $n$, the signer starts over with an independent random $u$.[^o2] Otherwise, the signer computes

$$\begin{aligned} x_p &:= \Bigl(-d \pm \sqrt{c + d^2}\Bigr) \bmod p, \\ x_q &:= \Bigl(-d \pm \sqrt{c + d^2}\Bigr) \bmod q, \end{aligned}$$

using a [standard algorithm for computing square roots modulo a prime](wikipedia://en/200091#Prime_or_prime_power_modulus)—picking $p \equiv q \equiv 3 \pmod 4$ makes it easiest. Square roots are not unique, and different variants of the signature scheme make different choices of square root;[^o6] in any case, the signer must ensure not to reveal two different roots for the same hash $c$. $x_p$ and $x_q$ satisfy the equations

$$\begin{aligned} x_p (x_p + b) &\equiv H(m,u) \pmod p, \\ x_q (x_q + b) &\equiv H(m,u) \pmod q. \end{aligned}$$

The signer then uses the [Chinese remainder theorem](wikipedia://en/7713) to solve the system

$$\begin{aligned} x &\equiv x_p \pmod p, \\ x &\equiv x_q \pmod q, \end{aligned}$$

for $x$, so that $x$ satisfies

$$x (x + b) \equiv H(m,u) \pmod n$$

as required. The signer reveals $(u, x)$ as a signature on $m$.

The number of trials for $u$ before $x (x + b) \equiv H(m,u) \pmod n$ can be solved for $x$ is geometrically distributed with an average around 4 trials, because about 1/4 of all integers are quadratic residues modulo $n$.

:::

## Security {#Security}

Security against any adversary defined generically in terms of a hash function $H$ (i.e., security in the [random oracle model](https://en.wikipedia.org/wiki/Random_oracle_model)) follows from the difficulty of factoring $n$: Any such adversary with high probability of success at forgery can, with nearly as high probability, find two distinct square roots $x_1$ and $x_2$ of a random integer $c$ modulo $n$. If $x_1 \pm x_2 \not\equiv 0 \pmod n$ then $\gcd(x_1 \pm x_2, n)$ is a nontrivial factor of $n$, since ${x_1}^2 \equiv {x_2}^2 \equiv c \pmod n$ so $n \mid {x_1}^2 - {x_2}^2 = (x_1 + x_2) (x_1 - x_2)$ but $n \nmid x_1 \pm x_2$.[^o3] Formalizing the security in modern terms requires filling in some additional details, such as the [codomain](wikipedia://en/50264) of $H$; if we set a standard size $K$ for the prime factors, $2^{K - 1} < p < q < 2^K$, then we might specify $H\colon \{0,1\}^* \times \{0,1\}^k \to \{0,1\}^K$.[^o7]

Randomization of the hash function was introduced to allow the signer to find a quadratic residue, but randomized hashing for signatures later became relevant in its own right for tighter security theorems[^o3] and resilience to collision attacks on fixed hash functions.[^o11][^o12][^o13]

## Variants {#Variants}

### Removing $b$ {#Removing}

The quantity $b$ in the public key adds no security, since any algorithm to solve congruences $x (x + b) \equiv c \pmod n$ for $x$ given $b$ and $c$ can be trivially used as a subroutine in an algorithm to compute square roots modulo $n$ and vice versa, so implementations can safely set $b = 0$ for simplicity; $b$ was discarded altogether in treatments after the initial proposal.[^o18][^o3][^o19][^o6] After removing $b$, the equations for $x_p$ and $x_q$ in the signing algorithm become:

$$\begin{aligned} x_p &:= \pm \sqrt{c} \bmod p, \\ x_q &:= \pm \sqrt{c} \bmod q. \end{aligned}$$

### Rabin-Williams {#Rabin-Williams}

The Rabin signature scheme was later tweaked by [Williams](https://en.wikipedia.org/wiki/Hugh_C._Williams) in 1980[^o18] to choose $p \equiv 3 \pmod 8$ and $q \equiv 7 \pmod 8$, and replace a square root $x$ by a tweaked square root $(e, f, x)$, with $e = \pm1$ and $f \in \{1,2\}$, so that a signature instead satisfies

$$e f x^2 \equiv H(m, u) \pmod n,$$

which allows the signer to create a signature in a single trial without sacrificing security. This variant is known as **Rabin–Williams**.[^o6][^o19]

### Others {#Others}

Further variants allow tradeoffs between signature size and verification speed, partial message recovery, signature compression (down to one-half size), and public key compression (down to one-third size), still without sacrificing security.[^o6]

Variants without the hash function have been published in textbooks,[^o21][^o22] crediting Rabin for exponent 2 but not for the use of a hash function. These variants are trivially broken—for example, the signature $x = 2$ can be forged by anyone as a valid signature on the message $m = 4$ if the signature verification equation is $x^2 \equiv m \pmod n$ instead of $x^2 \equiv H(m, u) \pmod n$.

In the original paper,[^o2] the hash function $H(m, u)$ was written with the notation $C(MU)$, with *C* for *compression*, and using juxtaposition to denote concatenation of $M$ and $U$ as bit strings:

> By convention, when wishing to sign a given message, $M$, \[the signer\] $P$ adds as suffix a word $U$ of an agreed upon length $k$. The choice of $U$ is randomized each time a message is to be signed. The signer now compresses $M_1 = MU$ by a hashing function to a word $C(M_1) = c$, so that as a binary number $c \leq n$…

This notation has led to some confusion among some authors later who ignored the $C$ part and misunderstood $MU$ to mean multiplication, giving the misapprehension of a trivially broken signature scheme.[^o23]
