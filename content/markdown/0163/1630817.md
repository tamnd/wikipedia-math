# Pollard's rho algorithm for logarithms

::: {#o1 .subject cue=lead name="Pollard's rho algorithm for logarithms"}

**Pollard's rho algorithm for logarithms** is an algorithm introduced by [John Pollard](wikipedia://en/1068500) in 1978 to solve the [discrete logarithm](wikipedia://en/181334) problem, analogous to [Pollard's rho algorithm](wikipedia://en/580668) to solve the [integer factorization](wikipedia://en/15491) problem.

:::

The goal is to compute $\gamma$ such that $\alpha ^ \gamma = \beta$, where $\beta$ belongs to a [cyclic group](wikipedia://en/52327) $G$ generated by $\alpha$. The algorithm computes [integers](wikipedia://en/14563) $a$, $b$, $A$, and $B$ such that $\alpha^a \beta^b = \alpha^A \beta^B$. If the underlying [group](wikipedia://en/19447) is cyclic of [order](https://en.wikipedia.org/wiki/Order_of_a_group) $n$, by substituting $\beta$ as ${\alpha}^{\gamma}$ and noting that two powers are equal [if and only if](wikipedia://en/14922) the exponents are equivalent modulo the order of the base, in this case modulo $n$, we get that $\gamma$ is one of the solutions of the equation $(B-b) \gamma = (a-A) \pmod n$. Solutions to this equation are easily obtained using the [extended Euclidean algorithm](wikipedia://en/99438).

To find the needed $a$, $b$, $A$, and $B$ the algorithm uses [Floyd's cycle-finding algorithm](https://en.wikipedia.org/wiki/Floyd's_cycle-finding_algorithm) to find a cycle in the sequence $x_i = \alpha^{a_i} \beta^{b_i}$, where the [function](wikipedia://en/185427) $f: x_i \mapsto x_{i+1}$ is assumed to be random-looking and thus is likely to enter into a loop of approximate length $\sqrt{\frac{\pi n}{8}}$ after $\sqrt{\frac{\pi n}{8}}$ steps. One way to define such a function is to use the following rules: [Partition](wikipedia://en/340240) $G$ into three [disjoint subsets](https://en.wikipedia.org/wiki/Disjoint_subset) $S_0$, $S_1$, and $S_2$ of approximately equal size using a [hash function](https://en.wikipedia.org/wiki/Hash_function). If $x_i$ is in $S_0$ then double both $a$ and $b$; if $x_i \in S_1$ then increment $a$, if $x_i \in S_2$ then increment $b$.

::: {#o3 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

Let $G$ be a [cyclic group](wikipedia://en/52327) of order $n$, and given $\alpha, \beta\in G$, and a partition $G = S_0\cup S_1\cup S_2$, let $f:G\to G$ be the map

$$f(x) = \begin{cases} \beta x & x\in S_0\\ x^2 & x\in S_1\\ \alpha x & x\in S_2 \end{cases}.$$

If this map is applied to $x = \alpha^a \beta^b \in G$, then we can define maps $g:G\times\mathbb{Z}\to\mathbb{Z}$ and $h:G\times\mathbb{Z}\to\mathbb{Z}$ to track the indices of $\alpha$ and $\beta$ of the result. These maps would be given by

$$\begin{aligned} g(x,k) &= \begin{cases} k & x\in S_0\\ 2k \pmod {n} & x\in S_1\\ k+1 \pmod {n} & x\in S_2 \end{cases}, \qquad \mbox{and} \\ h(x,k) &= \begin{cases} k+1 \pmod {n} & x\in S_0\\ 2k \pmod {n} & x\in S_1\\ k & x\in S_2 \end{cases}. \end{aligned}$$

**input:** *a*: a generator of *G* *b*: an element of *G* **output:** An integer *x* such that *a<sup>x</sup>* = *b*, or failure

Initialise *i* ← 0, *a*<sub>0</sub> ← 0, *b*<sub>0</sub> ← 0, *x*<sub>0</sub> ← 1 ∈ *G*

**loop** *i* ← *i* + 1

*x<sub>i</sub>* ← *f*(*x*<sub>*i*−1</sub>), *a<sub>i</sub>* ← *g*(*x*<sub>*i*−1</sub>, *a*<sub>*i*−1</sub>), *b<sub>i</sub>* ← *h*(*x*<sub>*i*−1</sub>, *b*<sub>*i*−1</sub>)

*x*<sub>2*i*−1</sub> ← *f*(*x*<sub>2*i*−2</sub>), *a*<sub>2*i*−1</sub> ← *g*(*x*<sub>2*i*−2</sub>, *a*<sub>2*i*−2</sub>), *b*<sub>2*i*−1</sub> ← *h*(*x*<sub>2*i*−2</sub>, *b*<sub>2*i*−2</sub>) *x*<sub>2*i*</sub> ← *f*(*x*<sub>2*i*−1</sub>), *a*<sub>2*i*</sub> ← *g*(*x*<sub>2*i*−1</sub>, *a*<sub>2*i*−1</sub>), *b*<sub>2*i*</sub> ← *h*(*x*<sub>2*i*−1</sub>, *b*<sub>2*i*−1</sub>) **while** *x<sub>i</sub>* ≠ *x*<sub>2*i*</sub>

*r* ← *b<sub>i</sub>* − *b*<sub>2*i*</sub> **if** r = 0 **return failure** **return** *r*<sup>−1</sup>(*a*<sub>2*i*</sub> − *a<sub>i</sub>*) mod *n*

:::

## Example {#Example}

Consider, for example, the group generated by 2 modulo $N=1019$ (the order of the group is $n=1018$, 2 generates the group of units modulo 1019). The algorithm is implemented by the following [C++](https://en.wikipedia.org/wiki/C++) program:

```cpp
#include <stdio.h>

const int n = 1018, N = n + 1;  /* N = 1019 -- prime     */
const int alpha = 2;            /* generator             */
const int beta = 5;             /* 2^{10} = 1024 = 5 (N) */

void new_xab(int& x, int& a, int& b) {
  switch (x % 3) {
  case 0: x = x * x     % N;  a =  a*2  % n;  b =  b*2  % n;  break;
  case 1: x = x * alpha % N;  a = (a+1) % n;                  break;
  case 2: x = x * beta  % N;                  b = (b+1) % n;  break;
  }
}

int main(void) {
  int x = 1, a = 0, b = 0;
  int X = x, A = a, B = b;
  for (int i = 1; i < n; ++i) {
    new_xab(x, a, b);
    new_xab(X, A, B);
    new_xab(X, A, B);
    printf("%3d  %4d %3d %3d  %4d %3d %3d\n", i, x, a, b, X, A, B);
    if (x == X) break;
  }
  return 0;
}
```

The results are as follows (edited):

i x a b X A B ------------------------------ 1 2 1 0 10 1 1 2 10 1 1 100 2 2 3 20 2 1 1000 3 3 4 100 2 2 425 8 6 5 200 3 2 436 16 14 6 1000 3 3 284 17 15 7 981 4 3 986 17 17 8 425 8 6 194 17 19 .............................. 48 224 680 376 86 299 412 49 101 680 377 860 300 413 50 505 680 378 101 300 415 51 1010 681 378 1010 301 416

That is $2^{681} 5^{378} = 1010 = 2^{301} 5^{416} \pmod{1019}$ and so $(416-378)\gamma = 681-301 \pmod{1018}$, for which $\gamma_1=10$ is a solution as expected. As $n=1018$ is not [prime](wikipedia://en/23666), there is another solution $\gamma_2=519$, for which $2^{519} = 1014 = -5\pmod{1019}$ holds.

:::

## Complexity {#Complexity}

The running time is approximately $\mathcal{O}(\sqrt{n})$. If used together with the [Pohlig–Hellman algorithm](wikipedia://en/1995624), the running time of the combined algorithm is $\mathcal{O}(\sqrt{p})$, where $p$ is the largest prime [factor](wikipedia://en/49492) of $n$.
