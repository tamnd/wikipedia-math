# Iterative refinement

::: {#o1 .subject cue=lead name="Iterative refinement"}

Iterative method

**Iterative refinement** is an [iterative method](wikipedia://en/15237) proposed by [James H. Wilkinson](wikipedia://en/301380) to improve the accuracy of numerical solutions to [systems of linear equations](https://en.wikipedia.org/wiki/Systems_of_linear_equations).[^o2][^o3]

:::

When solving a linear system $A \mathbf{x} = \mathbf{b} \,,$ due to the compounded accumulation of [rounding errors](wikipedia://en/432450), the computed solution $\hat{\mathbf{x}}$ may sometimes deviate from the exact solution $\mathbf{x}_\star\,.$ Starting with $\mathbf{x}_1 = \hat{\mathbf{x}}\,,$ iterative refinement computes a sequence $\{\mathbf{x}_1,\, \mathbf{x}_2,\, \mathbf{x}_3,\dots\}$ which converges to $\mathbf{x}_\star\,,$ when certain assumptions are met.

## Description {#Description}

For $m = 1, 2, 3, \dots\,,$ the $m$th iteration of iterative refinement consists of three steps: Compute the residual error $\mathbf{r}_{m}$ $\mathbf{r}_m = \mathbf{b} - A \mathbf{x}_m\,.$; Solve the system for the correction, $\mathbf{c}_{m}$, that removes the residual error $A \mathbf{c}_m = \mathbf{r}_m\,.$; Add the correction to get the revised next solution $\mathbf{x}_{m+1}$ $\mathbf{x}_{m+1} = \mathbf{x}_m + \mathbf{c}_m\,.$

The crucial reasoning for the refinement algorithm is that although the solution for $\mathbf{c}_{m}$ in step (ii) may indeed be troubled by similar errors as the first solution, $\hat\mathbf{x}$, the calculation of the residual $\mathbf{r}_{m}$ in step (i), in comparison, is numerically nearly exact: You may not know the right answer very well, but you know quite accurately just how far the solution you have in hand is from producing the correct outcome ($\mathbf{b}$). If the residual is small in some sense, then the correction must also be small, and should at the very least steer the current estimate of the answer, $\mathbf{x}_{m}$, closer to the desired one, $\mathbf{x}_\star\,.$

The iterations will stop on their own when the residual $\mathbf{r}_{m}$ is zero, or close enough to zero that the corresponding correction $\mathbf{c}_{m}$ is too small to change the solution $\mathbf{x}_{m}$ which produced it; alternatively, the algorithm stops when $\mathbf{r}_{m}$ is too small to convince the linear algebraist monitoring the progress that it is worth continuing with any further refinements.

Note that the matrix equation solved in step (ii) uses the same matrix $A$ for each iteration. If the matrix equation is solved using a direct method, such as [Cholesky](wikipedia://en/134433) or [LU](wikipedia://en/6243993) [decomposition](wikipedia://en/253873), the numerically expensive factorization of $A$ is done once and is reused for the relatively inexpensive [forward](https://en.wikipedia.org/wiki/Forward_substitution) and [back substitution](https://en.wikipedia.org/wiki/Back_substitution) to solve for $\mathbf{c}_{m}$ at each iteration.[^o3]

## Error analysis {#Error_analysis}

As a rule of thumb, iterative refinement for [Gaussian elimination](wikipedia://en/13035) produces a solution correct to working precision if double the working precision is used in the computation of $\mathbf{r}$, e.g. by using [quad](https://en.wikipedia.org/wiki/Quadruple-precision_floating-point_format) or [double extended](https://en.wikipedia.org/wiki/Extended_precision) precision [IEEE 754](wikipedia://en/405039) [floating point](https://en.wikipedia.org/wiki/Floating_point), and if $A$ is not too ill-conditioned (and the iteration and the rate of convergence are determined by the condition number of $A$).[^o6]

More formally, assuming that each step (ii) can be solved reasonably accurately, i.e., in mathematical terms, for every $m$, we have

$$A \left( I + F_m \right) \mathbf{c}_m = \mathbf{r}_m$$

where $\|F_{m}\|_{\infty} < 1$, the [relative error](wikipedia://en/640422) in the $m$-th iterate of iterative refinement satisfies

$$\frac{ \lVert \mathbf{x}_m - \mathbf{x}_\star \rVert_\infty }{ \lVert \mathbf{x}_\star \rVert_\infty} \leq \bigl( \sigma\,\kappa(A)\,\varepsilon_1\bigr)^m + \mu_1\, \varepsilon_1 + n\, \kappa(A)\, \mu_2\, \varepsilon_2$$

where

- $\|\cdot\|_{\infty}$ denotes the [$\infty$-norm](wikipedia://en/349755) of a vector,
- $\kappa(A)$ is the $\infty$-[condition number](wikipedia://en/6934) of $A$,
- $n$ is the order of $A$,
- $\varepsilon$${}_{1}$ and $\varepsilon$${}_{2}$ are [unit round-offs](wikipedia://en/3076863) of [floating-point arithmetic](wikipedia://en/11376) operations,
- $\sigma$, $\mu$${}_{1}$ and $\mu$${}_{2}$ are constants that depend on $A$, $\varepsilon$${}_{1}$ and $\varepsilon$${}_{2}$

if $A$ is "not too badly conditioned", which in this context means

and implies that $\mu$${}_{1}$ and $\mu$${}_{2}$ are of order unity.

The distinction of $\varepsilon$${}_{1}$ and $\varepsilon$${}_{2}$ is intended to allow mixed-precision evaluation of $\mathbf{r}_{m}$ where intermediate results are computed with unit round-off $\varepsilon$${}_{2}$ before the final result is rounded (or truncated) with unit round-off $\varepsilon$${}_{1}$. All other computations are assumed to be carried out with unit round-off $\varepsilon$${}_{1}$.
