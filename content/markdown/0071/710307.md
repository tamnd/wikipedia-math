# Linear temporal logic

::: {#o1 .subject cue=lead name="Linear temporal logic"}

In [logic](wikipedia://en/46426065), **linear temporal logic** or **linear-time temporal logic**[^o2][^o3] (**LTL**) is a [modal](wikipedia://en/333365) [temporal logic](wikipedia://en/321481) with modalities referring to time. In LTL, one can encode [formulae](https://en.wikipedia.org/wiki/Formula_%28logic%29) about the future of [paths](wikipedia://en/638889), e.g., a condition will eventually be true, a condition will be true until another fact becomes true, etc. It is a fragment of the more complex [CTL\*](https://en.wikipedia.org/wiki/CTL*), which additionally allows branching time and [quantifiers](wikipedia://en/43507260). LTL is sometimes called **propositional temporal logic** (**PTL**).[^o4] In terms of [expressive power](https://en.wikipedia.org/wiki/Expressive_power_%28computer_science%29), LTL is a fragment of [first-order logic](wikipedia://en/10983).[^o5][^o6]

:::

LTL was first proposed for the [formal verification](https://en.wikipedia.org/wiki/Formal_verification) of computer programs by [Amir Pnueli](https://en.wikipedia.org/wiki/Amir_Pnueli) in 1977.[^o7]

## Syntax {#Syntax}

LTL is built up from the set of [propositional variables](wikipedia://en/1557562) *AP*, the [logical operators](wikipedia://en/18153) ¬ and ∨, and the [temporal](wikipedia://en/321481) [modal operators](wikipedia://en/3832714) **X** (some literature uses **O** or **N**) and **U**. Formally, the set of LTL formulas over *AP* is inductively defined as follows:

- if $p \in AP$ then *p* is an LTL formula;
- if $\psi$ and $\varphi$ are LTL formulas then $\neg\psi, \varphi \lor \psi, \mathbf{X} \psi$, and $\varphi \mathbf{U} \psi$ are LTL formulas.[^o9]

**X** is read as ne**x**t and **U** is read as **u**ntil. Other than these fundamental operators, there are additional logical and temporal operators defined in terms of the fundamental operators, in order to write LTL formulas succinctly. The additional logical operators are ∧, →, ↔, **true**, and **false**. Following are the additional temporal operators.

- **G** for always (**g**lobally)
- **F** for **f**inally
- **R** for **r**elease
- **W** for **w**eak until
- **M** for **m**ighty release

The context-free grammar of LTL is as follows: $\varphi ::= \top | \perp | p | (\neg\varphi) | (\varphi \land \varphi) | (\varphi \lor \varphi) | (\varphi \to \varphi) | (\mathbf{X} \varphi) | (\mathbf{G} \varphi) | (\mathbf{F} \varphi) | (\varphi \mathbf{U} \varphi) | (\varphi \mathbf{W} \varphi) | (\varphi \mathbf{R} \varphi) | (\varphi \mathbf{M} \varphi)$

## Semantics {#Semantics}

An LTL formula can be *[satisfied](wikipedia://en/23401166)* by an infinite sequence of truth valuations of variables in *AP*. These sequences can be viewed as a word on a path of a [Kripke structure](https://en.wikipedia.org/wiki/Kripke_structure) (an [ω-word](https://en.wikipedia.org/wiki/Ω-language) over [alphabet](wikipedia://en/4292269) 2<sup>*AP*</sup>). Let *w* = a<sub>0</sub>,a<sub>1</sub>,a<sub>2</sub>,... be such an ω-word. Let *w*(*i*) = *a<sub>i</sub>*. Let *w*<sup>i</sup> = *a<sub>i</sub>*,*a*<sub>*i*+1</sub>,..., which is a suffix of *w*. Formally, the satisfaction relation ⊨ between a word and an LTL formula is defined as follows:

- *w* ⊨ *p* if *p* ∈ *w*(0)
- *w* ⊨ ¬$\psi$ if *w* ⊭ $\psi$
- *w* ⊨ $\varphi$ ∨ $\psi$ if *w* ⊨ $\varphi$ or *w* ⊨ $\psi$
- $w \models \mathbf{X} \psi$ if *w*<sup>1</sup> ⊨ $\psi$ (in the ne**x**t time step $\psi$ must be true)
- $w \models \varphi \mathbf{U} \psi$ if there exists *i* ≥ 0 such that *w*<sup>*i*</sup> ⊨ $\psi$ and for all 0 ≤ *k* \< i, *w*<sup>*k*</sup> ⊨ $\varphi$ ($\varphi$ must remain true **u**ntil $\psi$ becomes true)

We say an ω-word *w* satisfies an LTL formula $\psi$ when *w* ⊨ $\psi$. The [ω-language](https://en.wikipedia.org/wiki/Ω-language) *L*($\psi$) defined by $\psi$ is {*w* | *w* ⊨ $\psi$}, which is the set of ω-words that satisfy $\psi$. A formula $\psi$ is *satisfiable* if there exist an ω-word *w* such that *w* ⊨ $\psi$. A formula $\psi$ is *valid* if for each ω-word *w* over alphabet 2<sup>*AP*</sup>, we have *w* ⊨ $\psi$.

The additional logical operators are defined as follows:

- $\varphi$ ∧ $\psi$ ≡ ¬(¬$\varphi$ ∨ ¬$\psi$)
- $\varphi$ → $\psi$ ≡ ¬$\varphi$ ∨ $\psi$
- $\varphi$ ↔ $\psi$ ≡ ($\varphi$ → $\psi$) ∧ ( $\psi$ → $\varphi$)
- **true** ≡ *p* ∨ ¬*p*, where *p* ∈ *AP*
- **false** ≡ ¬**true**

The additional temporal operators **R**, **F**, and **G** are defined as follows:

- $\psi$ **R** $\varphi$ ≡ ¬(¬$\psi$ **U** ¬$\varphi$) ( $\varphi$ remains true until and including once $\psi$ becomes true. If $\psi$ never becomes true, $\varphi$ must remain true forever. $\psi$ **r**eleases $\varphi$.)
- $\mathbf{F} \psi \equiv \mathbf{true} \mathbf{U} \psi$ (eventually $\psi$ becomes true)
- **G** $\psi$ ≡ **false** **R** $\psi$ ≡ ¬**F** ¬$\psi$ ($\psi$ always remains true)

### Weak until and strong release {#Weak_until_and_strong_release}

Some authors also define a *weak until* binary operator, denoted **W**, with semantics similar to that of the until operator but the stop condition is not required to occur (similar to release).[^o12] It is sometimes useful since both **U** and **R** can be defined in terms of the weak until:

- $$\psi \mathbf{W} \varphi \equiv (\psi \mathbf{U} \varphi) \lor \mathbf{G} \psi \equiv \psi \mathbf{U} (\varphi \lor \mathbf{G} \psi) \equiv \varphi \mathbf{R} (\varphi \lor \psi)$$
- $$\psi \mathbf{U} \varphi \equiv \mathbf{F}\varphi \land (\psi \mathbf{W} \varphi)$$
- $$\psi \mathbf{R} \varphi \equiv \varphi \mathbf{W} (\varphi \land \psi)$$

The *strong release* binary operator, denoted **M**, is the dual of weak until. It is defined similar to the until operator, so that the release condition has to hold at some point. Therefore, it is stronger than the release operator.

- $$\psi \mathbf{M} \varphi \equiv \neg(\neg\psi \mathbf{W} \neg\varphi) \equiv (\psi \mathbf{R} \varphi) \land \mathbf{F} \psi \equiv \psi \mathbf{R} (\varphi \land \mathbf{F} \psi) \equiv \varphi \mathbf{U} (\psi \land \varphi)$$

## Negation normal form {#Negation_normal_form}

All the formulas of LTL can be transformed into *negation normal form*, where

- all negations appear only in front of the atomic propositions,
- only the logical operators **true**, **false**, ∧, and ∨ can appear, and
- only the temporal operators **X**, **U**, and **R** can appear.

Using the above equivalences for negation propagation, it is possible to derive the normal form. This normal form allows **R**, **true**, **false**, and ∧ to appear in the formula, which are not fundamental operators of LTL. Note that the transformation to the negation normal form does not blow up the length of the formula. This normal form is useful in [translation from an LTL formula to a Büchi automaton](wikipedia://en/31670156).

## Relations with other logics {#Relations_with_other_logics}

LTL can be shown to be equivalent to the [monadic first-order logic of order](https://en.wikipedia.org/wiki/Monadic_first-order_logic_of_order), FO\[\<\]—a result known as [Kamp's theorem](wikipedia://en/83795911)—[^o22] or equivalently to [star-free languages](wikipedia://en/4922792).[^o23]

[Computation tree logic](wikipedia://en/840894) (CTL) and linear temporal logic (LTL) are both a subset of [CTL\*](https://en.wikipedia.org/wiki/CTL*), but are incomparable. For example,

- No formula in CTL can define the language that is defined by the LTL formula **F**(**G** p).
- No formula in LTL can define the language that is defined by the CTL formulas **AG**( p → (**EX**q ∧ **EX**¬q) ) or **AG**(**EF**(p)).

## Computational problems {#Computational_problems}

[Model checking](wikipedia://en/321157) and satisfiability against an LTL formula are [PSPACE-complete](wikipedia://en/54685) problems. LTL synthesis and the problem of verification of games against an LTL winning condition is [2EXPTIME-complete](wikipedia://en/11387202).[^o25]

## Applications {#Applications}

**Automata-theoretic linear temporal logic model checking**

LTL formulas are commonly used to express constraints, specifications, or processes that a system should follow. The field of model checking aims to formally verify whether a system meets a given specification. In the case of automata-theoretic model checking, both the system of interest and a specification are expressed as separate [finite-state machines](https://en.wikipedia.org/wiki/Finite-state_machines), or automata, and then compared to evaluate whether the system is guaranteed to have the specified property. In computer science, this type of model checking is often used to verify that an algorithm is structured correctly.

To check LTL specifications on infinite system runs, a common technique is to obtain a [Büchi automaton](wikipedia://en/344912) that is equivalent to the model (accepts an ω-word precisely if it is the model) and another one that is equivalent to the negation of the property (accepts an ω-word precisely it satisfies the negated property) (cf. [Linear temporal logic to Büchi automaton](wikipedia://en/31670156)). In this case, if there is an overlap in the set of ω-words accepted by the two automata, it implies that the model accepts some behaviors which violate the desired property. If there is no overlap, there are no property-violating behaviors which are accepted by the model. Formally, the intersection of the two non-deterministic Büchi automata is empty if and only if the model satisfies the specified property.[^o28]

**Expressing important properties in formal verification**

There are two main types of properties that can be expressed using linear temporal logic: **[safety](https://en.wikipedia.org/wiki/Safety_property)** properties usually state that *something bad never happens* (**G**¬*ϕ*), while **[liveness](https://en.wikipedia.org/wiki/Liveness)** properties state that *something good keeps happening* (**GF***ψ* or **G**(*ϕ* →**F***ψ*)).[^o29] For example, a safety property may require that an autonomous rover never drives over a cliff, or that a software product never allows a successful login with an incorrect password. A liveness property may require that the rover always continues to collect data samples, or that a software product repeatedly sends telemetry data.

More generally, safety properties are those for which every [counterexample](wikipedia://en/143151) has a finite prefix such that, however it is extended to an infinite path, it is still a counterexample. For liveness properties, on the other hand, every finite path can be extended to an infinite path that satisfies the formula.

**Specification language**

One of the applications of linear temporal logic is the specification of [preferences](https://en.wikipedia.org/wiki/Preference) in the [Planning Domain Definition Language](https://en.wikipedia.org/wiki/Planning_Domain_Definition_Language) for the purpose of [preference-based planning](https://en.wikipedia.org/wiki/Preference-based_planning).
