# Generic-case complexity

::: {#o1 .subject cue=lead name="Generic-case complexity"}

**Generic-case complexity** is a subfield of [computational complexity theory](wikipedia://en/7543) that studies the complexity of computational problems on "most inputs".

:::

Generic-case complexity is a way of measuring the complexity of a [computational problem](https://en.wikipedia.org/wiki/Computational_problem) by neglecting a small set of unrepresentative inputs and considering [worst-case complexity](https://en.wikipedia.org/wiki/Worst-case_complexity) on the rest. Small is defined in terms of asymptotic density. The apparent efficacy of generic case complexity is because for a wide variety of concrete computational problems, the most difficult instances seem to be rare. Typical instances are relatively easy.

This approach to complexity originated in [combinatorial group theory](wikipedia://en/979834), which has a computational tradition going back to the beginning of the last century. The notion of generic complexity was introduced in a 2003 paper,[^o2] where authors showed that for a large class of [finitely generated groups](wikipedia://en/963042) the generic time complexity of some classical [decision problems](https://en.wikipedia.org/wiki/Decision_problems) from combinatorial group theory, namely the [word problem](wikipedia://en/33563), [conjugacy problem](wikipedia://en/4942384) and [membership problem](https://en.wikipedia.org/wiki/Membership_problem), are linear.

A detailed introduction of generic case complexity can be found in the surveys.[^o3][^o4]

## Basic definitions {#Basic_definitions}

### Asymptotic density {#Asymptotic_density}

Let *I* be an [infinite set](wikipedia://en/142679) of inputs for a computational problem.

::: {#o7 .definition cue=inline-head name="Definition 1"}

**Definition 1.** A [size function](wikipedia://en/16637535) on *I* is a map $\sigma:I\to \mathbb{N}$ with infinite range. The ball of radius *n* is $B_n=\{x\in I \mid \sigma(x)\le n \}$.

If the inputs are coded as strings over a finite alphabet, size might be the string length.

Let $\{\mu_n\}$ be an ensemble of [probability distributions](https://en.wikipedia.org/wiki/Probability_distributions) where $\mu_n$ is a [probability distribution](wikipedia://en/23543) on $B_n$. If the balls $B_n$ are finite, then each $\mu_n$ can be taken to be the equiprobable distribution which is the most common case. Notice that only finitely many $B_n$'s can be empty or have $\mu_n(B_n) = 0$; we ignore them.

:::

::: {#o8 .definition cue=inline-head name="Definition 2"}

**Definition 2.** The asymptotic density of a subset $X \subset I$ is $\rho(X) = \lim_{n \to \infty}\mu_n(X \cap B_n)$ when this limit exists.

When the balls $B_n$ are finite and $\mu_n$ is the equiprobable measure,

$$\rho(X)=\lim \frac{|X\cap B_n|}{|B_n|}.$$

In this case it is often convenient to use spheres $I_n=\{x\in I\mid \sigma(x)=n\}$ instead of balls and define $\rho'(X)=\lim \frac{|X\cap I_n|}{|I_n|}$. An argument using [Stolz theorem](https://en.wikipedia.org/wiki/Stolz_theorem) shows that $\rho(X)$ exists if $\rho'(X)$ does, and in that case they are equal.

:::

::: {#o9 .definition cue=inline-head name="Definition 3"}

**Definition 3** $X\subseteq I$ is generic if $\rho(X)=1$ and negligible if $\rho(X)=0$. *X* is exponentially (superpolynomially) generic if the convergence to the limit in Definition 2 is exponentially (superpolynomially) fast, etc.

A generic subset *X* is asymptotically large. Whether *X* appears large in practice depends on how fast $\mu_n(X\cap B_n)$ converges to 1. Superpolynomial convergence seems to be fast enough.

:::

### Generic complexity classes {#Generic_complexity_classes}

::: {#o11 .definition cue=inline-head name="Definition 4"}

**Definition 4** An [algorithm](wikipedia://en/775) is in *GenP* (generically polynomial time) if it never gives incorrect answers and if it gives correct answers in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) on a generic set of inputs. A problem is in *GenP* if it admits an algorithm in *GenP*. Likewise for *GenL* (generically [linear time](https://en.wikipedia.org/wiki/Linear_time)), *GenE* (generically [exponential time](https://en.wikipedia.org/wiki/Exponential_time) with a linear exponent) *GenExp* (generically exponential time), etc. *ExpGenP* is the subclass of *GenP* for which the relevant generic set is exponentially generic.

More generally for any $f : \mathbb{N} \to \mathbb{N}$ we can define the class *Gen(f)* corresponding to [time complexity](wikipedia://en/405944) *O*(*f*) on a generic set of input.

:::

::: {#o12 .definition cue=inline-head name="Definition 5"}

**Definition 5.** An algorithm solves a problem generically if it never gives incorrect answers and if it gives correct answers on a generic set of inputs. A problem is generically solvable if it is solved generically by some algorithm.

:::

## Theory and applications {#Theory_and_applications}

### Combinatorial group theory problems {#Combinatorial_group_theory_problems}

- The famous [undecidable problems](wikipedia://en/15631055): under suitable hypotheses, the word, conjugacy and membership decision problems are in generically polynomial.[^o2]
- The word and conjugacy [search problems](wikipedia://en/1471816) are in *GenP* for all fixed finitely presented groups.[^o15]
- The well known [coset enumeration](https://en.wikipedia.org/wiki/Coset_enumeration) procedure admits a computable upper bound on a generic set of inputs.[^o16]
- The Whitehead algorithm for testing whether or not one element of a free group is mapped to another by an automorphism has an exponential worst case upper bound but runs well in practice. The algorithm is shown to be in *GenL*.[^o17]
- The conjugacy problem in [HNN extensions](wikipedia://en/2823319) can be unsolvable even for [free groups](wikipedia://en/59735). However, it is generically cubic time.[^o18]

### The halting problem and the Post correspondence problem {#The_halting_problem_and_the_Post_correspondence_problem}

- The [halting problem](wikipedia://en/21391870) for [Turing machine](wikipedia://en/30403) with one-sided tape is easily decidable most of the time; it is in *GenP*[^o20]

The situation for two-sided tape is unknown. However, there is a kind of lower bound for machines of both types. The halting problem is not in *ExpGenP* for any model of Turing machine,[^o21][^o22]

- The [Post correspondence problem](wikipedia://en/64685) is in *ExpGenP*.[^o3]

### Presburger arithmetic {#Presburger_arithmetic}

The [decision problem](wikipedia://en/8336) for [Presburger arithmetic](wikipedia://en/23756) admits a double exponential worst case lower bound[^o24] and a triple exponential worst case upper bound. The generic complexity is not known, but it is known that the problem is not in *ExpGenP*.[^o25]

### NP complete problems {#NP_complete_problems}

As it is well known that [NP-complete problems](https://en.wikipedia.org/wiki/NP-complete_problems) can be easy on average, it is not a surprise that several of them are generically easy too.

- The three [satisfiability problem](https://en.wikipedia.org/wiki/Satisfiability_problem) is in *ExpGenP*.[^o27]
- The [subset sum problem](wikipedia://en/36811) is in *GenP*.[^o3]

### One way functions {#One_way_functions}

There is a generic complexity version of a [one-way function](wikipedia://en/363890)[^o29] which yields the same class of functions but allows one to consider different security assumptions than usual.

### Public-key cryptography {#Public-key_cryptography}

A series of articles[^o31][^o32][^o33] is devoted to [cryptanalysis](wikipedia://en/5715) of the [Anshel–Anshel–Goldfeld key exchange](wikipedia://en/24708948) protocol, whose security is based on assumptions about the [braid group](wikipedia://en/550138). This series culminates in Miasnikov and Ushakov (2008)[^o34] which applies techniques from generic case complexity to obtain a complete analysis of the [length based attack](https://en.wikipedia.org/wiki/Length_based_attack) and the conditions under which it works. The [generic point](wikipedia://en/3043978) of view also suggests a kind of new attack called the quotient attack, and a more secure version of the Anshel–Anshel–Goldfeld protocol.

### List of general theoretical results {#List_of_general_theoretical_results}

- A famous [Rice's theorem](wikipedia://en/25852) states that if *F* is a subset of the set of partial computable functions from $\mathbb{N}$ to $\{0,1\}$, then unless *F* or its complement is empty, the problem of deciding whether or not a particular [Turing machine](wikipedia://en/30403) computes a function in *F* is undecidable. The following theorem gives a generic version.

::: {#o36 .statement kind=statement/theorem cue=inline-head name="Theorem 1"}

**Theorem 1**[^o37] Let *I* be the set of all Turing machines. If *F* is a subset of the set of all partial [computable function](wikipedia://en/1139338) from $\mathbb{N}$ to itself such that *F* and its complement are both non-empty, then the problem of deciding whether or not a given Turing machine computes a function from *F* is not decidable on any exponentially generic subset of *I*.

- The following theorems are from:[^o2]

:::

::: {#o38 .statement kind=statement/theorem cue=inline-head name="Theorem 2"}

**Theorem 2** The set of [formal languages](https://en.wikipedia.org/wiki/Formal_languages) which are generically computable has measure zero.

:::

::: {#o39 .statement kind=statement/theorem cue=inline-head name="Theorem 3"}

**Theorem 3** There is an infinite hierarchy of generic complexity classes. More precisely for a proper complexity function *f*, $Gen(f) \subsetneq Gen(f^3)$.

The next theorem shows that just as there are [average case complete problems](https://en.wikipedia.org/wiki/Average_case_complete_problems) within distributional NP problems, there are also generic case complete problems. The arguments in the generic case are similar to those in the average case, and the generic case complete problem is also average case complete. It is the distributional [bounded halting problem](https://en.wikipedia.org/wiki/Bounded_halting_problem).

:::

::: {#o40 .statement kind=statement/theorem cue=inline-head name="Theorem 4"}

**Theorem 4**[^o3] There is a notion of generic-polynomial-time reduction with respect to which the distributional bounded halting problem is complete within class of distributional NP problems.

:::

## Comparisons with previous work {#Comparisons_with_previous_work}

### Almost polynomial time {#Almost_polynomial_time}

Meyer and Paterson[^o43] define an algorithm to be almost polynomial time, or APT, if it halts within *p(n)* steps on all but *p(n)* inputs of size *n*. Clearly, APT algorithms are included in our class *GenP*. We have seen several [NP complete](https://en.wikipedia.org/wiki/NP_complete) problems in *GenP*, but Meyer and Paterson show that this is not the case for APT. They prove that an NP complete problem is reducible to a problem in APT if and only if [P = NP](https://en.wikipedia.org/wiki/P_=_NP). Thus APT seems much more restrictive than *GenP*.

### Average-case complexity {#Average-case_complexity}

Generic case complexity is similar to [average-case complexity](https://en.wikipedia.org/wiki/Average-case_complexity). However, there are some significant differences. Generic case complexity is a direct measure of the performance of an algorithm on most inputs while average case complexity gives a measure of the balance between easy and difficult instances. In addition Generic-case complexity naturally applies to [undecidable problems](wikipedia://en/15631055).

Suppose $\mathcal{A}$ is an algorithm whose [time complexity](wikipedia://en/405944), $T:I\to \mathbb{N}$ is polynomial on $\mu$ average. What can we infer about the behavior of $\mathcal{A}$ on typical inputs?

::: {#o45 .example cue=inline-head name="Example 1"}

**Example 1** Let *I* be the set of all words over $\{0,1\}$ and define the size $\sigma(w)$ to be word length, $|w|$. Define $I_n$ to be the set of words of length *n*, and assume that each $\mu_n$ is the equiprobable measure. Suppose that *T(w)=n* for all but one word in each $I_n$, and $T(w)=2^{2^n}$ on the exceptional words.

In this example *T* is certainly polynomial on typical inputs, but *T* is not polynomial on average. *T* is in *GenP*.

:::

::: {#o46 .example cue=inline-head name="Example 2"}

**Example 2** Keep *I* and $\sigma(w) = |w|$ as before, but define $\mu(w)= 2^{-2|w|-1}$ and $T(w) = 2^{|w|}$. *T* is polynomial on average even though it is exponential on typical inputs. *T* is not in *GenP*.

In these two examples the generic complexity is more closely related to behavior on typical inputs than average case complexity. Average case complexity measures something else: the balance between the frequency of difficult instances and the degree of difficulty.[^o47][^o48] Roughly speaking an algorithm which is polynomial time on average can have only a subpolynomial fraction of inputs that require superpolynomial time to compute.

Nevertheless, in some cases generic and average case complexity are quite close to each other. A function $f:I\rightarrow\mathbb{R}^+$ is polynomial on $\mu$-average on spheres if there exists $k \geq 1$ such that $\sum_{w\in I_n} f^{1/k}(w) \mu_n(w) = O(n)$ where $\{\mu_n\}$ is the ensemble induced by $\mu$. If *f* is polynomial on $\mu$-average on spheres, the *f* is polynomial on $\mu$-average, and for many distributions the converse holds [^o49]

:::

::: {#o50 .statement kind=statement/theorem cue=inline-head name="Theorem"}

**Theorem** 5[^o3] If a function $f:I\rightarrow \mathbb{R}^+$ is polynomial on $\mu$-average on spheres then *f* is generically polynomial relative to the spherical asymptotic density $\rho'$.

:::

::: {#o51 .statement kind=statement/theorem cue=inline-head name="Theorem"}

**Theorem** 6[^o3] Suppose a complete algorithm $\mathcal{A}$ has subexponential time bound *T* and a partial algorithm $\mathcal{B}$ for the same problem is in *ExpGenP* with respect to the ensemble $\{\mu_n\}$ corresponding to a probability measure $\mu$ on the inputs *I* for $\mathcal{A}$. Then there is a complete algorithm which is $\mu$-average time complexity.

:::

### Errorless heuristic algorithms {#Errorless_heuristic_algorithms}

In a 2006 paper, Bogdanov and Trevisan came close to defining generic case complexity.[^o53] Instead of partial algorithms, they consider so-called errorless heuristic algorithms. These are complete algorithms which may fail by halting with output "?". The class *AvgnegP* is defined to consist of all errorless heuristic algorithms *A* which run in polynomial time and for which the probability of failure on $I_n$ is negligible, i.e., converges superpolynomially fast to 0. *AvgnegP* is a subset of *GenP*. Errorless heuristic algorithms are essentially the same as the algorithms with benign faults defined by Impagliazzo where polynomial time on average algorithms are characterized in terms of so-called benign algorithm schemes.
