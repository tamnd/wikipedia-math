# Criss-cross algorithm

::: {#o1 .subject cue=lead name="Criss-cross algorithm"}

*Image: Unitcube.svg.* The criss-cross algorithm visits all 8 corners of the [Klee–Minty cube](wikipedia://en/31302509) in the worst case. It visits 3 additional corners on average. The Klee–Minty cube is a perturbation of the cube shown here.

In [mathematical optimization](https://en.wikipedia.org/wiki/Optimization_%28mathematics%29), the **criss-cross algorithm** is any of a family of [algorithms](wikipedia://en/775) for [linear programming](wikipedia://en/43730). Variants of the criss-cross algorithm also solve more general problems with [linear inequality constraints](wikipedia://en/43730) and [nonlinear](wikipedia://en/679709) [objective functions](https://en.wikipedia.org/wiki/Optimization_%28mathematics%29); there are criss-cross algorithms for [linear-fractional programming](wikipedia://en/22989094) problems,[^o2][^o3] [quadratic-programming](wikipedia://en/40324) problems, and [linear complementarity problems](wikipedia://en/1470767).[^o4]

:::

Like the [simplex algorithm](wikipedia://en/349458) of [George B. Dantzig](wikipedia://en/13111), the criss-cross algorithm is not a [polynomial-time algorithm](wikipedia://en/405944) for linear programming. Both algorithms visit all 2<sup>*D*</sup> corners of a (perturbed) [cube](wikipedia://en/407763) in dimension *D*, the [Klee–Minty cube](wikipedia://en/31302509) (after [Victor Klee](https://en.wikipedia.org/wiki/Victor_Klee) and [George J. Minty](wikipedia://en/67693763)), in the [worst case](https://en.wikipedia.org/wiki/Worst-case_complexity).[^o5][^o18] However, when it is started at a random corner, the criss-cross algorithm [on average](https://en.wikipedia.org/wiki/Average-case_complexity) visits only *D* additional corners.[^o19][^o20][^o6] Thus, for the three-dimensional cube, the algorithm visits all 8 corners in the worst case and exactly 3 additional corners on average.

::: {#o8 .pointer-item cue=pointer name="Zhe-Min Wang"}

## History {#History}

The criss-cross algorithm was published independently by [Tamas Terlaky](https://en.wikipedia.org/wiki/Tamas_Terlaky)[^o9] and by Zhe-Min Wang;[^o10] related algorithms appeared in unpublished reports by other authors.[^o4]

:::

## Comparison with the simplex algorithm for linear optimization {#Comparison_with_the_simplex_algorithm_for_linear_optimization}

*Image: Simplex description.png.* In its second phase, the *simplex algorithm* crawls along the edges of the polytope until it finally reaches an optimum [vertex](wikipedia://en/11308417). The *criss-cross algorithm* considers bases that are not associated with vertices, so that some iterates can be in the *interior*of the feasible region, like interior-point algorithms; the criss-cross algorithm can also have *infeasible* iterates *outside* the feasible region.

In linear programming, the criss-cross algorithm pivots between a sequence of bases but differs from the [simplex algorithm](wikipedia://en/349458). The simplex algorithm first finds a (primal-) feasible basis by solving a "*phase-one* problem"; in "phase two", the simplex algorithm pivots between a sequence of basic *feasible*solutions so that the objective function is non-decreasing with each pivot, terminating with an optimal solution (also finally finding a "dual feasible" solution).[^o4][^o12]

The criss-cross algorithm is simpler than the simplex algorithm, because the criss-cross algorithm only has one phase. Its pivoting rules are similar to the [least-index pivoting rule of Bland](https://en.wikipedia.org/wiki/Bland's_rule).[^o13] Bland's rule selects an entering variables by comparing values of reduced costs, using the real-number ordering of the eligible pivots.[^o13][^o14] Unlike Bland's rule, the criss-cross algorithm is "purely combinatorial", selecting an entering variable and a leaving variable by considering only the signs of coefficients rather than their real-number ordering.[^o4][^o12] The criss-cross algorithm has been applied to furnish constructive proofs of basic results in [linear algebra](wikipedia://en/18422), such as the [lemma of Farkas](https://en.wikipedia.org/wiki/Farkas_lemma).[^o15]

While most simplex variants are monotonic in the objective (strictly in the non-degenerate case), most variants of the criss-cross algorithm lack a monotone merit function which can be a disadvantage in practice.

## Description {#Description}

The criss-cross algorithm works on a standard pivot tableau (or on-the-fly calculated parts of a tableau, if implemented like the revised simplex method). In a general step, if the tableau is primal or dual infeasible, it selects one of the infeasible rows / columns as the pivot row / column using an index selection rule. An important property is that the selection is made on the union of the infeasible indices and the standard version of the algorithm does not distinguish column and row indices (that is, the column indices basic in the rows). If a row is selected then the algorithm uses the index selection rule to identify a position to a dual type pivot, while if a column is selected then it uses the index selection rule to find a row position and carries out a primal type pivot.

## Computational complexity: Worst and average cases {#Computational_complexity:_Worst_and_average_cases}

The [time complexity](wikipedia://en/405944) of an [algorithm](wikipedia://en/775) counts the number of [arithmetic operations](https://en.wikipedia.org/wiki/Arithmetic_operation) sufficient for the algorithm to solve the problem. For example, [Gaussian elimination](wikipedia://en/13035) requires on the [order of](https://en.wikipedia.org/wiki/Big_oh)*D*<sup>3</sup> operations, and so it is said to have polynomial time-complexity, because its complexity is bounded by a [cubic polynomial](https://en.wikipedia.org/wiki/Cubic_polynomial). There are examples of algorithms that do not have polynomial-time complexity. For example, a generalization of Gaussian elimination called [Buchberger's algorithm](wikipedia://en/696317) has for its complexity an exponential function of the problem data (the [degree of the polynomials](wikipedia://en/5930652) and the number of variables of the [multivariate polynomials](https://en.wikipedia.org/wiki/Multivariate_polynomial)). Because exponential functions eventually grow much faster than polynomial functions, an exponential complexity implies that an algorithm has slow performance on large problems.

Several algorithms for linear programming—[Khachiyan](https://en.wikipedia.org/wiki/Khachiyan)'s [ellipsoidal algorithm](https://en.wikipedia.org/wiki/Ellipsoidal_algorithm), [Karmarkar](https://en.wikipedia.org/wiki/Karmarkar)'s [projective algorithm](wikipedia://en/3736667), and [central-path algorithms](wikipedia://en/1622862)—have polynomial time-complexity (in the [worst case](https://en.wikipedia.org/wiki/Worst_case_complexity) and thus [on average](https://en.wikipedia.org/wiki/Average_case_complexity)). The ellipsoidal and projective algorithms were published before the criss-cross algorithm.

However, like the simplex algorithm of Dantzig, the criss-cross algorithm is *not* a polynomial-time algorithm for linear programming. Terlaky's criss-cross algorithm visits all the 2<sup>*D*</sup> corners of a (perturbed) cube in dimension *D*, according to a paper of Roos; Roos's paper modifies the [Klee](https://en.wikipedia.org/wiki/Victor_Klee)–Minty construction of a [cube](wikipedia://en/407763) on which the simplex algorithm takes 2<sup>*D*</sup> steps.[^o4][^o5][^o18] Like the simplex algorithm, the criss-cross algorithm visits all 8 corners of the three-dimensional cube in the worst case.

When it is initialized at a random corner of the cube, the criss-cross algorithm visits only *D* additional corners, however, according to a 1994 paper by [Fukuda](wikipedia://en/67628503) and Namiki.[^o19][^o20] Trivially, the simplex algorithm takes on average *D* steps for a cube.[^o6][^o21] Like the simplex algorithm, the criss-cross algorithm visits exactly 3 additional corners of the three-dimensional cube on average.

## Variants {#Variants}

The criss-cross algorithm has been extended to solve more general problems than linear programming problems.

### Other optimization problems with linear constraints {#Other_optimization_problems_with_linear_constraints}

There are variants of the criss-cross algorithm for linear programming, for [quadratic programming](wikipedia://en/40324), and for the [linear-complementarity problem](wikipedia://en/1470767) with "sufficient matrices";[^o4][^o19][^o25][^o26][^o27][^o28] conversely, for linear complementarity problems, the criss-cross algorithm terminates finitely only if the matrix is a sufficient matrix.[^o27][^o28] A [sufficient&nbsp;matrix](https://en.wikipedia.org/wiki/Sufficient&nbsp;matrix) is a generalization both of a [positive-definite matrix](https://en.wikipedia.org/wiki/Positive-definite_matrix) and of a [P-matrix](wikipedia://en/7632450), whose [principal&nbsp;minors](https://en.wikipedia.org/wiki/Principal&nbsp;minor) are each positive.[^o27][^o28][^o29] The criss-cross algorithm has been adapted also for [linear-fractional programming](wikipedia://en/22989094).[^o2][^o3]

### Vertex enumeration {#Vertex_enumeration}

The criss-cross algorithm was used in an algorithm for [enumerating all the vertices of a polytope](wikipedia://en/19558316), which was published by [David Avis](https://en.wikipedia.org/wiki/David_Avis) and [Komei Fukuda](wikipedia://en/67628503) in 1992.[^o31] Avis and Fukuda presented an algorithm which finds the *v* vertices of a [polyhedron](wikipedia://en/23470) defined by a nondegenerate system of *n* [linear inequalities](wikipedia://en/19575563) in *D* [dimensions](wikipedia://en/38267) (or, dually, the *v* [facets](https://en.wikipedia.org/wiki/Facet) of the [convex hull](wikipedia://en/40634) of *n* points in *D* dimensions, where each facet contains exactly *D* given points) in time [O](https://en.wikipedia.org/wiki/Big_Oh_notation)(*nDv*) and O(*nD*) [space](wikipedia://en/338946).[^o32]

### Oriented matroids {#Oriented_matroids}

*Image: max-flow min-cut example.svg.* The [max-flow min-cut theorem](wikipedia://en/78130) states that the maximum flow through a network is exactly the capacity of its minimum cut. This theorem can be proved using the criss-cross algorithm for oriented matroids.

The criss-cross algorithm is often studied using the theory of [oriented matroids](wikipedia://en/24338041) (OMs), which is a [combinatorial](wikipedia://en/5170) abstraction of linear-optimization theory.[^o26][^o34] Indeed, Bland's pivoting rule was based on his previous papers on oriented-matroid theory. However, Bland's rule exhibits cycling on some oriented-matroid linear-programming problems.[^o26] The first purely combinatorial algorithm for linear programming was devised by [Michael J. Todd](https://en.wikipedia.org/wiki/Michael_J._Todd_%28mathematician%29).[^o26][^o35] Todd's algorithm was developed not only for linear-programming in the setting of oriented matroids, but also for [quadratic-programming problems](wikipedia://en/40324) and [linear-complementarity problems](wikipedia://en/1470767).[^o26][^o35] Todd's algorithm is complicated even to state, unfortunately, and its finite-convergence proofs are somewhat complicated.[^o26]

The criss-cross algorithm and its proof of finite termination can be simply stated and readily extend the setting of oriented matroids. The algorithm can be further simplified for *linear feasibility problems*, that is for [linear systems](wikipedia://en/722503) with [nonnegative variables](wikipedia://en/19575563); these problems can be formulated for oriented matroids.[^o15] The criss-cross algorithm has been adapted for problems that are more complicated than linear programming: There are oriented-matroid variants also for the quadratic-programming problem and for the linear-complementarity problem.[^o4][^o25][^o26]

:::

## Summary {#Summary}

The criss-cross algorithm is a simply stated algorithm for linear programming. It was the second fully combinatorial algorithm for linear programming. The partially combinatorial simplex algorithm of Bland cycles on some (nonrealizable) oriented matroids. The first fully combinatorial algorithm was published by Todd, and it is also like the simplex algorithm in that it preserves feasibility after the first feasible basis is generated; however, Todd's rule is complicated. The criss-cross algorithm is not a simplex-like algorithm, because it need not maintain feasibility. The criss-cross algorithm does not have polynomial time-complexity, however.

Researchers have extended the criss-cross algorithm for many optimization-problems, including linear-fractional programming. The criss-cross algorithm can solve quadratic programming problems and linear complementarity problems, even in the setting of oriented matroids. Even when generalized, the criss-cross algorithm remains simply stated.
