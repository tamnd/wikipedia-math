# Isabelle (proof assistant)

::: {#o3 .subject cue=lead name="Isabelle"}

The **Isabelle** [automated theorem prover](https://en.wikipedia.org/wiki/Automated_theorem_prover) is a [higher-order logic (HOL) theorem prover](https://en.wikipedia.org/wiki/HOL_%28proof_assistant%29), written in [Standard ML](https://en.wikipedia.org/wiki/Standard_ML) and [Scala](wikipedia://en/3254510). As a [Logic for Computable Functions](wikipedia://en/161900) (LCF) style theorem prover, it is based on a small logical core (kernel) to increase the trustworthiness of proofs without requiring, yet supporting, explicit proof objects.

:::

Isabelle is available inside a flexible system framework allowing for logically safe extensions, which comprise both theories and implementations for code-generating, documenting, and specific support for a variety of [formal methods](https://en.wikipedia.org/wiki/Formal_methods). It can be seen as an [integrated development environment](https://en.wikipedia.org/wiki/Integrated_development_environment) (IDE) for formal methods. In recent years, a substantial number of theories and system extensions have been collected in the Isabelle *Archive of Formal Proofs* (**Isabelle AFP**).[^o4]

Isabelle was named by [Lawrence Paulson](https://en.wikipedia.org/wiki/Lawrence_Paulson) after [Gérard Huet](https://en.wikipedia.org/wiki/Gérard_Huet)'s daughter.[^o5]

The Isabelle theorem prover is [free software](https://en.wikipedia.org/wiki/Free_software), released under the revised [BSD license](https://en.wikipedia.org/wiki/BSD_license).

::: {#o7 .pointer-item cue=pointer name="Intelligible semi-automated reasoning"}

## Features {#Features}

Isabelle is generic: it provides a [meta-logic](https://en.wikipedia.org/wiki/Meta-logic) (a weak [type theory](wikipedia://en/40282)), which is used to encode object logics like [first-order logic](wikipedia://en/10983) (FOL), [higher-order logic](wikipedia://en/562883) (HOL) or [Zermelo–Fraenkel set theory](wikipedia://en/152214) (ZFC). The most widely used object logic is Isabelle/HOL, although significant set theory developments were completed in Isabelle/ZF. Isabelle's main proof method is a higher-order version of [resolution](https://en.wikipedia.org/wiki/First-order_resolution), based on higher-order [unification](https://en.wikipedia.org/wiki/Unification_%28computing%29).

Though interactive, Isabelle features efficient automatic reasoning tools, such as a [term rewriting](https://en.wikipedia.org/wiki/Term_rewriting) engine and a [tableaux prover](wikipedia://en/1027229), various decision procedures, and, through the **Sledgehammer** proof-automation interface, external [satisfiability modulo theories](https://en.wikipedia.org/wiki/Satisfiability_modulo_theories) (SMT) solvers (including [CVC4](https://en.wikipedia.org/wiki/CVC4)) and [resolution](wikipedia://en/2724082)-based [automated theorem provers](https://en.wikipedia.org/wiki/Automated_theorem_prover) (ATPs), including [E](https://en.wikipedia.org/wiki/E_%28theorem_prover%29), [SPASS](https://en.wikipedia.org/wiki/SPASS), and [Vampire](https://en.wikipedia.org/wiki/Vampire_%28theorem_prover%29) (the **Metis** proof method reconstructs resolution proofs generated by these ATPs).[^o8] It also features two [model](wikipedia://en/19858) finders ([counterexample](wikipedia://en/143151) generators): **Nitpick**[^o9] and **Nunchaku**.[^o10]

Isabelle features **locales** which are modules that structure large proofs. A locale fixes types, constants, and assumptions within a specified scope[^o9] so that they do not have to be repeated for every [lemma](wikipedia://en/18634).

**Isar** ("**intelligible semi-automated reasoning**") is Isabelle's formal proof language. It is inspired by the [Mizar system](wikipedia://en/209074).[^o9]

:::

## Example proof {#Example_proof}

Isabelle allows proofs to be written in two different styles, the [procedural](https://en.wikipedia.org/wiki/Procedural_programming) and the [declarative](https://en.wikipedia.org/wiki/Declarative_programming). Procedural proofs specify a series of [tactics](https://en.wikipedia.org/wiki/Tactic_%28computer_science%29) (theorem proving [functions/procedures](https://en.wikipedia.org/wiki/Subroutine)) to apply. While reflecting the procedure that a human mathematician might apply to proving a result, they are typically hard to read as they do not describe the outcome of these steps. This style is "considered harmful" in the Isabelle documentation.[^o12]

On the other hand, declarative proofs (supported by Isabelle's proof language, Isar) specify the actual mathematical operations to be performed, and are therefore more easily read and checked by humans.

For example, a declarative [proof by contradiction](https://en.wikipedia.org/wiki/Proof_by_contradiction) in Isar that [the square root of two is not rational](wikipedia://en/341682#Proof_by_infinite_descent) can be written as follows.

## Applications {#Applications}

Isabelle has been used to aid [formal methods](https://en.wikipedia.org/wiki/Formal_methods) for the specification, development and [verification](https://en.wikipedia.org/wiki/Formal_verification) of software and hardware systems.

Isabelle has been used to formalize numerous theorems from [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), like [Gödel's completeness theorem](wikipedia://en/12450), Gödel's theorem about the consistency of the [axiom of choice](wikipedia://en/840), the [prime number theorem](wikipedia://en/23692), correctness of [security protocols](https://en.wikipedia.org/wiki/Security_protocol), and properties of [programming language semantics](https://en.wikipedia.org/wiki/Formal_semantics_of_programming_languages). Many of the formal proofs are, as mentioned, maintained in the Archive of Formal Proofs, which contains (as of 2019) at least 500 articles with over 2 million lines of proof in total.[^o15]

- In 2009, the L4.verified project at [NICTA](https://en.wikipedia.org/wiki/NICTA) produced the first formal proof of functional correctness of a general-purpose operating system kernel:[^o16] the [seL4](https://en.wikipedia.org/wiki/SeL4) (secure embedded [L4](https://en.wikipedia.org/wiki/L4_microkernel_family)) [microkernel](https://en.wikipedia.org/wiki/Microkernel). The proof is constructed and checked in Isabelle/HOL and comprises over 200,000 lines of proof script to verify 7,500 lines of C. The verification covers code, design, and implementation, and the main theorem states that the C code correctly implements the formal specification of the kernel. The proof uncovered 144 bugs in an early version of the C code of the seL4 kernel, and about 150 issues in each of design and specification.
- The definition of the programming language [Lightweight Java](https://en.wikipedia.org/wiki/Lightweight_Java) was proven [type-sound](https://en.wikipedia.org/wiki/Type_soundness) in Isabelle.[^o17]

## Alternatives {#Alternatives}

Several languages and systems provide similar functions:

- [Agda](https://en.wikipedia.org/wiki/Agda_%28programming_language%29), written in [Haskell](https://en.wikipedia.org/wiki/Haskell)
- [Rocq](wikipedia://en/581974) (formerly named *Coq*), written in [OCaml](https://en.wikipedia.org/wiki/OCaml)
- [Lean](wikipedia://en/62889984), written in Lean and [C++](https://en.wikipedia.org/wiki/C++)
- [LEGO](https://en.wikipedia.org/wiki/LEGO_%28proof_assistant%29), written in [Standard ML of New Jersey](https://en.wikipedia.org/wiki/Standard_ML_of_New_Jersey)
- [Mizar system](wikipedia://en/209074), written in [Free Pascal](https://en.wikipedia.org/wiki/Free_Pascal)
- [Metamath](wikipedia://en/6023946), written in [ANSI C](https://en.wikipedia.org/wiki/ANSI_C)
- [Prover9](https://en.wikipedia.org/wiki/Prover9), written in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), with a GUI written in [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29)
- [Twelf](https://en.wikipedia.org/wiki/Twelf), written in [Standard ML](https://en.wikipedia.org/wiki/Standard_ML)
