# Sum-check protocol

::: {#o1 .subject cue=lead name="Sum-check protocol"}

A **sum-check protocol** is a [cryptographic protocol](wikipedia://en/591994) for the construction of [interactive proof systems](wikipedia://en/160255),[^o2] used widely in [zero-knowledge protocols](wikipedia://en/450541).[^o3]

:::

## History {#History}

The sum-check protocol was created by [Carsten Lund](https://en.wikipedia.org/wiki/Carsten_Lund), [Lance Fortnow](wikipedia://en/25303350), [Howard Karloff](https://en.wikipedia.org/wiki/Howard_Karloff), and [Noam Nisan](https://en.wikipedia.org/wiki/Noam_Nisan) and formalized in 1990.[^o5][^o2]

## Concept {#Concept}

In an [interactive proof](wikipedia://en/160255), the goal is for a verifier V to offload an expensive computation to an untrusted prover P.[^o7] The sum-check protocol allows the prover to convince the verifier that the sum of a [multivariate polynomial](https://en.wikipedia.org/wiki/Multivariate_polynomial) is equal to a known value.[^o3] The goals of the sum-check protocol are to make the verifier run in time linear to the input size, to keep the proof logarithmically small, and to keep the prover efficient.[^o7]

For a *v*-variate polynomial *g* defined over a finite field $\mathbb{F}$, the prover provides the verifier with the following sum:[^o8]

$$H := \sum_{b_1 \in \{0,1\}} \sum_{b_2 \in \{0,1\}} \cdots \sum_{b_v \in \{0,1\}} g(b_1, \ldots, b_v).$$

Without a prover, the verifier has to perform $2^{n}$ evaluations of *g* to verify the statement, which is a very large runtime. With the sumcheck protocol, the verifier's runtime is$O(v + \text{[the cost to evaluate } g \text{ at a single input in } \mathbf{F}^v ])$.[^o7]

## Limitations {#Limitations}

::: {#o11 .proof cue=heading name="Proof size"}

### Proof size {#Proof_size}

The sum-check protocol leads to proofs that are of at least logarithmic length.[^o7]

:::

### Zero-knowledge and succinctness {#Zero-knowledge_and_succinctness}

The protocol is not [zero-knowledge](wikipedia://en/450541) by itself, and like all interactive proofs, it is not succinct for NP statements.[^o7]

[zk-SNARK](https://en.wikipedia.org/wiki/Zk-SNARK) proofs combine the sum-check protocol with [commitment schemes](wikipedia://en/439489) to obtain zero-knwoledge and succinct arguments.[^o7][^o13]
