# Lambda-mu calculus

::: {#o1 .subject cue=lead name="Lambda-mu calculus"}

In [mathematical logic](wikipedia://en/19636) and [computer science](https://en.wikipedia.org/wiki/Computer_science), the **lambda-mu calculus** is an extension of the [lambda calculus](wikipedia://en/18203) introduced by Michel Parigot.[^o2] It introduces two new operators: the μ operator (which is completely different both from the [μ operator](https://en.wikipedia.org/wiki/Μ_operator) found in [computability theory](wikipedia://en/155414) and from the μ operator of [modal μ-calculus](wikipedia://en/6158953)) and the bracket operator. [Proof-theoretically](wikipedia://en/183478), it provides a well-behaved formulation of [classical natural deduction](wikipedia://en/51072#Classical_and_modal_logics).

:::

One of the main goals of this extended calculus is to be able to describe expressions corresponding to theorems in [classical logic](wikipedia://en/55868). According to the [Curry&ndash;Howard isomorphism](https://en.wikipedia.org/wiki/Curry&ndash;Howard_isomorphism), lambda calculus on its own can express theorems in [intuitionistic logic](wikipedia://en/169262) only, and several classical logical theorems can't be written at all. However with these new operators one is able to write terms that have, for example, the type of [Peirce's law](wikipedia://en/47261948).

According to de Groote, the μ operator corresponds to [Felleisen](https://en.wikipedia.org/wiki/Matthias_Felleisen)'s undelimited control operator C and bracket corresponds to calling a captured [continuation](https://en.wikipedia.org/wiki/Continuation).[^o3]

::: {#o5 .definition cue=heading name="Formal definition"}

## Formal definition {#Formal_definition}

The three forms of expressions in [lambda calculus](wikipedia://en/18203) are as follows:

1. A *variable* x.
1. An *abstraction* λx. M, where *x* is any variable and *M* is any lambda expression.
1. An *application* (M N), where *M* and *N* are any lambda expressions.

In addition to the traditional λ-variables, the lambda-mu calculus includes a distinct set of μ-variables, which can be understood as continuation variables. The set of terms is divided into *unnamed* (all traditional lambda expressions are of this kind) and *named* terms. The terms that are added by the lambda-mu calculus are of the form:

1. \[α\]M is a named term, where *α* is a μ-variable and *M* is an unnamed term.
1. (μ α. t) is an unnamed term, where *α* is a μ-variable and *t* is a named term.

:::

## Reduction {#Reduction}

The basic reduction rules used in the lambda-mu calculus are the following:

**beta reduction**

$$(\lambda x.M)N \to M[N/x]$$

**structural reduction**

$(\mu \alpha.t)M \to \mu \alpha. t \left [ [\alpha](N M)/[\alpha] N \right ]$, where the substitutions are to be made for all subterms of $t$ of the form $[\alpha]N$.

**renaming**

$$[\alpha] \mu \beta. t \to t [\alpha / \beta]$$

**μη-reduction**

$\mu \alpha.[\alpha]M \to M$, if *α* does not occur freely in *M*

These rules cause the calculus to be [confluent](https://en.wikipedia.org/wiki/Confluence_%28term_rewriting%29).

## Typed lambda-mu calculus {#Typed_lambda-mu_calculus}

The lambda-mu calculus can be typed. The basic theory of the typed lambda-mu calculus is to classical propositional logic as the [simply typed lambda calculus](wikipedia://en/1986011) is to intuitionistic propositional logic.[^o8]

Typed lambda-mu calculus can be presented in [sequent calculus](wikipedia://en/252329):[^o8]

$$\begin{aligned} \Gamma, x\mathbin{:}\tau &\vdash x \mathbin{:} \tau \\ \\ \frac{\Gamma, x \mathbin{:} \sigma\vdash M\mathbin{:} \tau}{\Gamma \vdash (\lambda x \mathbin{:} \sigma. M) \mathbin{:} \sigma \to \tau} &\quad \frac{\Gamma, \vdash M\mathbin{:} \sigma \to \tau \quad \Gamma \vdash N\mathbin{:}\sigma}{\Gamma \vdash (MN)\mathbin{:} \tau} \\ \\ \frac{\Gamma, \alpha \mathbin{:} \neg\sigma \vdash M \mathbin{:} \bot}{\Gamma \vdash (\mu \alpha\mathbin{:} \neg \sigma. M) \mathbin{:} \sigma}& \quad \frac{\Gamma, \alpha\mathbin{:}\neg\sigma \vdash M\mathbin{:} \sigma}{\Gamma, \alpha\mathbin{:}\neg\sigma \vdash ([\alpha] M)\mathbin{:} \bot} \end{aligned}$$

The first 3 rules are the same as simply typed lambda calculus. The next 2 are new to the lambda-mu calculus.

### Curry–Howard correspondence {#Curry–Howard_correspondence}

Simply typed lambda calculus, by the [Curry–Howard correspondence](wikipedia://en/254299), corresponds to [purely functional programs](https://en.wikipedia.org/wiki/Purely_functional_programming) that can only redirect their inputs.

A sequent $\Gamma \vdash t:\tau$ states that, within a program context $\Gamma$, one can construct an object $t$ of type $\tau$.

The rule $\Gamma, x\mathbin{:}\tau \vdash x \mathbin{:} \tau$ states that, within a context that includes some $x:\tau$, one can construct an object $x$ with type $\tau$. This is obvious, by simply taking that same $x:\tau$.

The lambda-introduction rule $\frac{\Gamma, x \mathbin{:} \sigma\vdash M\mathbin{:} \tau}{\Gamma \vdash (\lambda x \mathbin{:} \sigma. M) \mathbin{:} \sigma \to \tau}$ states that, if one can construct $M: \tau$ within a context of $\Gamma, x\mathbin{:}\tau$, then one can construct $(\lambda x:\sigma. M): \sigma \to \tau$ within a context of $\Gamma$. This object $(\lambda x:\sigma. M)$ is a function-object defined within the context of $\Gamma$. It takes an object $x:\sigma$ as input, and internally reproduces the context of $\Gamma, x\mathbin{:}\tau$, in which one then constructs $M:\tau$. This is a form of [closure](https://en.wikipedia.org/wiki/Closure_%28computer_programming%29).

The lambda-reduction rule $\frac{\Gamma, \vdash M\mathbin{:} \sigma \to \tau \quad \Gamma \vdash N\mathbin{:}\sigma}{\Gamma \vdash (MN)\mathbin{:} \tau}$ is a reverse of the previous rule.

The typed lambda-mu calculus is similar to the simply typed lambda calculus, but it allows redirecing both the inputs and the outputs. The redirection of input is by lambda abstraction, or closure. The redirection of output is by mu abstraction, or [call/cc](https://en.wikipedia.org/wiki/Call-with-current-continuation), jumps, or control operators.

The negation symbol $\neg$ denotes duality. Whereas $x:\sigma$ in the program context denotes an input from which an object with type $\sigma$ appears, $\alpha:\neg\sigma$ denotes an output for an object with type $\sigma$ goes to.

$M:\bot$ denotes a computational process that does not return any value, because its value would be returned to an output in context.

The address abstraction rule $\frac{\Gamma, \alpha \mathbin{:} \neg\sigma \vdash M \mathbin{:} \bot}{\Gamma \vdash (\mu \alpha\mathbin{:} \neg \sigma. M) \mathbin{:} \sigma}$ closes an output from context. This corresponds to `catch` in call/cc.

The address application rule $\frac{\Gamma, \alpha\mathbin{:}\neg\sigma \vdash M\mathbin{:} \sigma}{\Gamma, \alpha\mathbin{:}\neg\sigma \vdash ([\alpha] M)\mathbin{:} \bot}$ redirects the output of a process $M:\sigma$ to the output $\alpha$ in context. This corresponds to `throw` in call/cc.

The $\mu$ is a channel device. The address $\alpha:\neg p$ is a channel that values of type $p$ can be transmitted along, and $[\alpha] M$ represents transmittal of $M$ to $\alpha$, provided that $M$ is of type $p$.[^o8]

### Examples {#Examples}

[Peirce's law](wikipedia://en/47261948) $((p \to q) \to p) \to p$ is the type of the following term:

$$\lambda x^{(p \to q) \to p}. \mu \alpha^{\neg p}. [\alpha] x (\lambda y^p. \mu \beta^{\neg q}. [\alpha] y)$$

where we write $x^\tau$ for $x:\tau$, in order to save space.

Intuitively, one can understand this construction as follows. The program opens an input context $x:(p\to q) \to p$, and an output context $\alpha:\neg p$. One way to satisfy the output requirement of $\alpha:\neg p$ is to construct something of type $p\to q$, and give it to $x$. That something is $\lambda y^p. \mu \beta^{\neg q}. [\alpha] y: p \to q$. If $x$ takes this object without trying to use it, then it will return an object of type $p$, which can then be given to $\alpha$. Alternatively, $x$ might attempt to use it by providing it with an object $y:p$, which can then be given to $\alpha$ without ever replying an object of type $q$ to $x$.

The [Łukasiewicz](wikipedia://en/305064) axiom is the type of the following term:

$$\lambda x^{(p\to q) \to r} \lambda y^{r\to p}. \lambda z^s. \mu\alpha^{\neg p}. [\alpha] y(\mu\beta^{\neg r}.[\beta] x(\lambda u^p. \mu \gamma^{\neg q}.[\alpha] u))$$

The [double-negation translation](wikipedia://en/14662815) corresponds to [continuation-passing style](https://en.wikipedia.org/wiki/Continuation-passing_style). That is, the double-negation translation turns every formula provable in classical propositional logic into a provable formula in intuitionistic propositional logic. This corresponds to converting a program with catch/throw into a purely functional program that uses continuation-passing.[^o8]

For example, the double-negation translation of Peirce's law $((\neg\neg p \to \neg\neg q) \to \neg\neg p ) \to \neg\neg p$ is the type of the following term:

$$\lambda x^{(\neg\neg p \to \neg\neg q) \to \neg\neg p}. \lambda \alpha^{\neg p} x (\lambda y^{\neg\neg p}. \lambda \beta^{\neg q}. y \alpha) \alpha$$

Compare these two, in parallel:

$$\begin{aligned} &\lambda x^{(p \to q) \to p}. &\mu \alpha^{\neg p}. [\alpha] &x (\lambda y^p. &\mu \beta^{\neg q}. [\alpha] &y) \\ &\lambda x^{(\neg\neg p \to \neg\neg q) \to \neg\neg p}. &\lambda \alpha^{\neg p}. \quad\; &x (\lambda y^{\neg\neg p}. &\lambda \beta^{\neg q}. y\alpha) \alpha \end{aligned}$$

The "jump to a different output" control behavior, as defined by $\mu\alpha \cdots [\alpha]$, is translated into a pure lambda expression $\lambda \alpha \cdots \alpha$. Instead of allowing a jump to the address $\alpha : \neg p$, one encodes the entire "the rest of the computation after the jumping to $\alpha: \neg p$" as a single object, called the continuation object. This continuation object can then be called for as many times as one wants, as long as that continuation object remains in context.

:::

## Variations {#Variations}

### Call-by-value lambda-mu calculus {#Call-by-value_lambda-mu_calculus}

To obtain call-by-value semantics, one must refine the beta reduction rule and add another form of structural reduction:[^o15]

**call-by-value beta reduction**

$(\lambda x.M) V \to M[V/x]$, where *V* is a value

**right structural reduction**

$V (\mu \alpha.t) \to \mu \alpha. t \left [ [\alpha](V N)/[\alpha] N \right ]$, where *V* is a value

This addition corresponds to the addition of an additional [evaluation context](wikipedia://en/270062) former when moving from call-by-name to call-by-value evaluation.

### De Groote's unstratified syntax {#De_Groote's_unstratified_syntax}

For a closer correspondence with conventional formalizations of control operators, the distinction between named and unnamed terms can be abolished, meaning that \[α\]M is of the same sort as other lambda-expressions and the body of μ-abstraction can also be any expression.[^o3] Another variant in this vein is the Λμ-calculus.[^o17]

### Symmetric lambda-mu calculus {#Symmetric_lambda-mu_calculus}

One can consider a structural reduction rule symmetric to the original one:[^o2]

$$M(\mu \alpha.t) \to \mu \alpha. t \left [ [\alpha](MN)/[\alpha] N \right ]$$

This, however, breaks [confluence](wikipedia://en/3755377) and the correspondence to control operators.

:::
