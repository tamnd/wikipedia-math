# Probabilistic encryption

::: {#o1 .subject cue=lead name="Probabilistic encryption"}

**Probabilistic encryption** is the use of [randomness](wikipedia://en/19196523) in an [encryption](wikipedia://en/10294) algorithm, so that when encrypting the same message several times it will, in general, yield different [ciphertexts](wikipedia://en/175560). The term "probabilistic encryption" is typically used in reference to [public key](https://en.wikipedia.org/wiki/Public_key_cryptography) encryption algorithms; however various [symmetric key encryption](https://en.wikipedia.org/wiki/Symmetric_key_encryption) algorithms achieve a similar property (e.g., [block ciphers](https://en.wikipedia.org/wiki/Block_ciphers) when used in a chaining mode such as [CBC](https://en.wikipedia.org/wiki/Cipher_block_chaining)), and stream ciphers such as Freestyle[^o2] which are inherently random. To be [semantically secure](wikipedia://en/960585), that is, to hide even partial information about the [plaintext](wikipedia://en/157935), an encryption algorithm must be [probabilistic](wikipedia://en/495383).

:::

## History {#History}

The first provably-secure probabilistic public-key encryption scheme was proposed by [Shafi Goldwasser](wikipedia://en/842178) and [Silvio Micali](https://en.wikipedia.org/wiki/Silvio_Micali), based on the hardness of the [quadratic residuosity problem](wikipedia://en/1183041) and had a message expansion factor equal to the public key size. More efficient probabilistic encryption algorithms include [Elgamal](wikipedia://en/59458), [Paillier](https://en.wikipedia.org/wiki/Paillier), and various constructions under the [random oracle model](https://en.wikipedia.org/wiki/Random_oracle_model), including [optimal asymmetric encryption padding](wikipedia://en/1579249) (OAEP).

## Security {#Security}

Probabilistic encryption is particularly important when using [public key cryptography](https://en.wikipedia.org/wiki/Public_key_cryptography). Suppose that the [adversary](wikipedia://en/789126) observes a ciphertext, and suspects that the plaintext is either "YES" or "NO", or has a hunch that the plaintext might be "ATTACK AT CALAIS". When a [deterministic encryption](wikipedia://en/2343703) algorithm is used, the adversary can simply try encrypting each of their guesses under the recipient's public key, and compare each result to the target ciphertext. To combat this attack, public key encryption schemes must incorporate an element of randomness, ensuring that each plaintext maps into one of a large number of possible ciphertexts.

An intuitive approach to converting a deterministic encryption scheme into a probabilistic one is to simply pad the plaintext with a random string before encrypting with the [deterministic algorithm](https://en.wikipedia.org/wiki/Deterministic_algorithm). Conversely, decryption involves applying a deterministic algorithm and ignoring the random padding. However, early schemes which applied this naive approach were broken due to limitations in some deterministic encryption schemes. Techniques such as [optimal asymmetric encryption padding](https://en.wikipedia.org/wiki/Optimal_Asymmetric_Encryption_Padding) (OAEP) integrate random padding in a manner that is secure using any [trapdoor permutation](https://en.wikipedia.org/wiki/Trapdoor_permutation).

## Examples {#Examples}

Example of probabilistic encryption using any trapdoor permutation:

- *x* - *single bit* plaintext
- *f* - trapdoor permutation (deterministic encryption algorithm)
- *b* - [hard core predicate](https://en.wikipedia.org/wiki/Hard_core_predicate) of *f*
- *r* - random string

$${\rm Enc}(x) = (f(r), x \oplus b(r))$$

$${\rm Dec}(y, z) = b(f^{-1}(y)) \oplus z$$

This is inefficient because only a single bit is encrypted. In other words, the message expansion factor is equal to the public key size.

Example of probabilistic encryption in the random oracle model:

- *x* - plaintext
- *f* - trapdoor permutation (deterministic encryption algorithm)
- *h* - [random oracle](wikipedia://en/451286) (typically implemented using a publicly specified [hash function](wikipedia://en/439526))
- *r* - random string

$${\rm Enc}(x) = (f(r), x \oplus h(r))$$

$${\rm Dec}(y, z) = h(f^{-1}(y)) \oplus z$$
