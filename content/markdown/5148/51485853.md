# Token Binding

::: {#o1 .subject cue=lead name="Token Binding"}

**Token Binding** is a proposed standard for a [Transport Layer Security (TLS)](wikipedia://en/187813) [extension](wikipedia://en/187813#Extensions) that aims to increase TLS security by using [cryptographic](wikipedia://en/18934432) [certificates](wikipedia://en/187813#Digital_certificates) on both ends of the TLS connection. Current practice often depends on bearer tokens,[^o2] which may be lost or stolen. Bearer tokens are also vulnerable to [man-in-the-middle attacks](https://en.wikipedia.org/wiki/Man-in-the-middle_attacks) or [replay attacks](https://en.wikipedia.org/wiki/Replay_attacks). In contrast, bound tokens are established by a [user agent](https://en.wikipedia.org/wiki/User_agent) that generates a [private-public key pair](wikipedia://en/24222) per target server, providing the public key to the server, and thereafter proving possession of the corresponding private key on every TLS connection to the server.

:::

Token Binding is an evolution of the [Transport Layer Security Channel ID](wikipedia://en/35076082) (previously known as Transport Layer Security – Origin Bound Certificates (TLS-OBC)) extension.

Industry participation is widespread with standards contributors including [Microsoft](https://en.wikipedia.org/wiki/Microsoft),[^o3] [Google](https://en.wikipedia.org/wiki/Google),[^o4] [PayPal](https://en.wikipedia.org/wiki/PayPal), [Ping Identity](https://en.wikipedia.org/wiki/Ping_Identity), and [Yubico](https://en.wikipedia.org/wiki/Yubico). Browser support remains limited, however. Only the older version of [Microsoft Edge](https://en.wikipedia.org/wiki/Microsoft_Edge) using the Blink engine had support for Token Binding.[^o5] [Chromium](https://en.wikipedia.org/wiki/Chromium_%28web_browser%29) removed support for Token Binding in version 70.[^o6]

## IETF standards {#IETF_standards}

The following group of [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) [RFCs](https://en.wikipedia.org/wiki/Request_for_Comments) and [Internet Drafts](https://en.wikipedia.org/wiki/Internet_Draft) comprise a set of interrelated specifications for implementing different aspects of the Token Binding standard.

- *The Token Binding Protocol Version 1.0*.[^o8] Allows client/server applications to create long-lived, uniquely identifiable TLS bindings spanning multiple TLS sessions and connections. Applications are then enabled to cryptographically bind security tokens to the TLS layer, preventing token export and replay attacks. To protect privacy, the Token Binding identifiers are only conveyed over TLS and can be reset by the user at any time.
- *Transport Layer Security (TLS) Extension for Token Binding Protocol Negotiation*.[^o9] Extension for the negotiation of Token Binding protocol version and key parameters.
- *Token Binding over HTTP*.[^o10] A collection of mechanisms that allow HTTP servers to cryptographically bind security tokens (such as cookies and OAuth tokens) to TLS connections.
- *Token Binding for Transport Layer Security (TLS) Version 1.3 Connections*.[^o11] This companion document defines a [backwards compatible](https://en.wikipedia.org/wiki/Backward_compatibility) way to negotiate Token Binding on TLS 1.3 connections.
- *HTTPS Token Binding with TLS Terminating Reverse Proxies*.[^o12] Defines [HTTP header](https://en.wikipedia.org/wiki/HTTP_header) fields that enable a TLS terminating [reverse proxy](https://en.wikipedia.org/wiki/Reverse_proxy) to convey information to a backend server about the validated Token Binding Message received from a client, which enables that backend server to bind, or verify the binding of, cookies and other security tokens to the client's Token Binding key. This facilitates the reverse proxy and backend server functioning together as though they are a single logical server side deployment of HTTPS Token Binding.

Related IETF draft standard:

- *OAuth 2.0 Token Binding*.[^o13] Enables OAuth 2.0 implementations to apply Token Binding to Access Tokens, Authorization Codes, Refresh Tokens, JWT Authorization Grants, and JWT Client Authentication. This cryptographically binds these tokens to a client's Token Binding key pair, possession of which is proven on the TLS connections over which the tokens are intended to be used. This use of Token Binding protects these tokens from man-in-the-middle and token export and replay attacks.

## Related standards {#Related_standards}

The use of TLS Token Binding allows for more robust web authentication. Several web authentication standards developed by standards bodies outside of IETF are adopting the draft standards.

- *Draft [OpenID](https://en.wikipedia.org/wiki/OpenID) [Connect](https://en.wikipedia.org/wiki/OpenID_Connect) Token Bound Authentication 1.0*.[^o15] OpenID Connect (OIDC) is a simple identity layer on top of the [OAuth 2.0](https://en.wikipedia.org/wiki/OAuth#OAuth_2.0) protocol. OIDC enables Clients to verify the identity of the End-User based on the authentication performed by an Authorization Server, as well as to obtain basic profile information about the End-User in an interoperable, REST-like manner. The OIDC Token Bound Authentication specification enables OIDC implementations to apply Token Binding to the OIDC ID Token. This cryptographically binds the ID Token to the TLS connection over which the authentication occurred. This use of Token Binding protects the authentication flow from man-in-the-middle and token export and replay attacks.
- *[W3C](https://en.wikipedia.org/wiki/World_Wide_Web_Consortium) Recommendation for Web Authentication: An API for accessing Public Key Credentials*.[^o16] Web Authentication ([WebAuthn](https://en.wikipedia.org/wiki/WebAuthn)), an interface for public-key authentication of users to web-based applications and services, removed support for Token Binding in version L3.[^o17]
