# Compositional game theory

::: {#o1 .subject cue=lead name="Compositional game theory"}

**Compositional game theory** is a branch of [game theory](wikipedia://en/11924) and [computer science](https://en.wikipedia.org/wiki/Computer_science), which aims to present large complex games as a composition of simple small games.[^o2][^o3][^o4]

:::

## Motivation {#Motivation}

A major theme in [computer science](https://en.wikipedia.org/wiki/Computer_science) is the ability to construct simple building-blocks (e.g. functions or procedures in a [programming language](wikipedia://en/23015)), and compose them into larger structures (e.g. more complex functions or programs). This principle is also called [modularity](https://en.wikipedia.org/wiki/Modularity).

In contrast, in classic [game theory](wikipedia://en/11924), even complex games are treated as single, monolithic objects. This makes the analysis of games hard to scale.

**Compositional game theory** **(CGT)** aims to apply the modularity principle to game theory. The main motivation is to make it easier to analyze large games using software tools.

## Higher-order game {#Higher-order_game}

A **higher-order simultaneous game**[^o7] is a generalization of a [Simultaneous game](wikipedia://en/23992863) in which players are defined by *selection functions* rather than by [utility functions](https://en.wikipedia.org/wiki/Utility_function). Formally, a higher-order simultaneous game for *n* players contains the following elements:

- A set R of *outcomes*.
- For each player *i*, a set *X<sub>i</sub>* of *choices* (possible actions).
  - We define *Σ* as the Cartesian product of all *X<sub>i</sub>*, and call it the set of *strategy profiles*.
- An *outcome function*, from *Σ* to *R*. This function determines, for each combination of actions of the players, what the outcome will be.
- For each player *i*, there is a *selection function* denoted *d<sub>i</sub>*. The selection function takes as input a *context*, which is a function from *X<sub>i</sub>* to *R*; and returns a set of *best-responses*, which is a subset of *X<sub>i</sub>*.

The term "higher-order" comes from the latter element. The best-response correspondence of each player is a [higher-order function](https://en.wikipedia.org/wiki/Higher-order_function), as is input is itself a function. Every strategy-profile s<sub>1</sub> in *Σ*, defines for each player *i* a function from *X<sub>i</sub>* to *R*: the function maps each possible action *x<sub>i</sub>* in *X<sub>i</sub>* to the outcome that would result if all players except i play as in s<sub>1</sub>, whereas player *i* switches his action to *x<sub>i</sub>*. In other words, s<sub>1</sub> defines the *context* in which player *i* operates.

Given two strategy-tuples s<sub>1</sub> and s<sub>2</sub> in *Σ*, we say that s<sub>2</sub> is a *best-response* to s<sub>1</sub> if, for each player *i*, s<sub>2,i</sub> is contained in the output of *d<sub>i</sub>* on the context generated by s<sub>1</sub>. The *best-response relation* is a [binary relation](wikipedia://en/3931) contained in *Σ x Σ*, denoted by *B*.

In a standard game, instead of the selection function, there is a *utility function* *u<sub>i</sub>* for each player *i.* A utility function takes as input an outcome from *R*, and returns a [real number](wikipedia://en/20646438). Such a game can be represented as a higher-order game as follows. For each player *i*, the selection function returns the set of actions from *X<sub>i</sub>* that maximize the utility of agent *i*, given the context.

## Open games {#Open_games}

The main object of study in CGT is the **open game**. An open game has the following elements:

- A set *X* of *observations*;
- A set *Y* of *outcomes;*
- A set *Σ* of *strategy profiles*.
- A *play function* *P*, which is a function from *Σ* x *X* to *Y*;
- A *coplay function* *C*, which is a function from *Σ x* X x R to S;
- A *best-response function* B, which is a function from X x (Y -> R) to a relation in *Σ x Σ.*

It is an abstraction of a higher-order game.

Open games can be decomposed in two ways:[^o3]

- In sequence - yielding a [sequential game](https://en.wikipedia.org/wiki/Sequential_game);
- In parallel - yielding a [simultaneous game](wikipedia://en/23992863).
