# ROCA vulnerability

::: {#o2 .subject cue=lead name="ROCA vulnerability"}

The **ROCA vulnerability** is a [cryptographic](wikipedia://en/18934432) weakness that allows the private key of a [key pair](wikipedia://en/24222) to be recovered from the public key in keys generated by devices with the vulnerability. "ROCA" is an acronym for "Return of [Coppersmith's attack](wikipedia://en/30639009)".[^o3] The vulnerability has been given the identifier 2017-15361.

:::

The vulnerability arises from an approach to [RSA](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29) [key generation](https://en.wikipedia.org/wiki/Key_generation) used in vulnerable versions of the [software library](https://en.wikipedia.org/wiki/Library_%28computing%29) *RSALib* provided by [Infineon Technologies](https://en.wikipedia.org/wiki/Infineon_Technologies) and incorporated into many [smart cards](https://en.wikipedia.org/wiki/Smart_card), [Trusted Platform Modules](wikipedia://en/2936835) (TPM), and [Hardware Security Modules](https://en.wikipedia.org/wiki/Hardware_Security_Module) (HSM), including [YubiKey](https://en.wikipedia.org/wiki/YubiKey) 4 tokens when used to generate RSA keys on-chip for [OpenPGP](wikipedia://en/23080) or [PIV](https://en.wikipedia.org/wiki/FIPS_201).[^o4] RSA keys of lengths 512, 1024, and 2048 bits generated using these versions of the Infineon library are vulnerable to a practical ROCA attack.[^o8][^o5] The research team that discovered the attack (all with [Masaryk University](https://en.wikipedia.org/wiki/Masaryk_University) and led by Matúš Nemec and Marek Sýs)[^o8] estimate that it affected around one-quarter of all current TPM devices globally.[^o6] Millions of [smart cards](https://en.wikipedia.org/wiki/Smart_card) are believed to be affected.[^o3]

The team informed Infineon of the *RSALib* problem in February 2017, but withheld public notice until mid-October, citing [responsible disclosure](https://en.wikipedia.org/wiki/Responsible_disclosure). At that time they announced the attack and provided a tool to test public keys for vulnerability. They published the details of the attack in November.[^o8]

## Technical details {#Technical_details}

Generating an RSA key involves selecting two large [randomly-generated](wikipedia://en/2736939) [prime numbers](wikipedia://en/23666), a process that can be time-consuming, particularly on small devices, such as smart cards. In addition to being primes, the numbers should have certain other properties for best security. The vulnerable *RSALib* selection process quickly creates primes of the desired type by only considering numbers of the form

$$k \times M + (65537^a \bmod M),$$

where $M$ is the product of the first *n* successive primes (2, 3, 5, 7, 11, 13, ...), and *n* is a constant that only depends on the desired key size. The security is based on the secret constants $k$ and $a$. The ROCA attack exploits this particular format for primes using a variation of the [Coppersmith method](wikipedia://en/25974284). In addition, public keys generated this way have a distinctive fingerprint that can be quickly recognized by attempting to compute the [discrete logarithm](wikipedia://en/181334) of the public key mod $M$ to base [65537](https://en.wikipedia.org/wiki/65537). Computing discrete logarithms in a large group is usually extremely difficult, but in this case it can be done efficiently using the [Pohlig–Hellman algorithm](wikipedia://en/1995624) because $M$ is a [smooth number](wikipedia://en/1035039). A test site is available on the Internet.[^o8][^o9][^o10][^o11] In short, keys that fit this format have significantly lower entropy and can be attacked relatively efficiently (weeks to months), and the format can be confirmed ("fingerprinted") by the attacker very quickly (microseconds). Multiple implementations of the attack are publicly available.[^o12][^o13][^o14]

## Mitigation {#Mitigation}

The ROCA authors consider public keys of length 512, 1024 and 2048-bits generated by *RSALib* to be vulnerable. Because the details of key generation differ for different key lengths, shorter keys are not necessarily more vulnerable than longer keys. For example, a 1952-bit RSAlib key is stronger than a 2048-bit key and a 4096-bit key is weaker than a 3072-bit key.

The best mitigation, according to the authors, is to generate RSA keys using a stronger method, such as by [OpenSSL](wikipedia://en/438819). If that is not possible, the ROCA authors suggest using key lengths that are less susceptible to ROCA such as 3936-bit, 3072-bit or, if there is a 2048-bit key size maximum, 1952-bits.[^o8]

Infineon has released firmware updates for its [Trusted Platform Modules](wikipedia://en/2936835) to manufacturers who have used its TPMs.[^o16]

## Implications {#Implications}

The vulnerability highlighted several [shortcomings of the Common Criteria certification scheme](https://en.wikipedia.org/wiki/Common_Criteria#Criticisms) as the vulnerability was present in a list of Common Criteria certified smart card products. Namely, the approval of homegrown cryptographic algorithms; the lack of transparency in certification reports, inability to revoke Common Criteria certificates for known vulnerable products and distribute this information to the users of the certified products.p. Sec 6.7.5

In Estonia, the discovery of the vulnerability resulted in a state-level cyber crisis as the vulnerable smart card chip was deployed on more than 750,000 [Estonian identity cards](https://en.wikipedia.org/wiki/Estonian_identity_card) that are used daily by Estonian residents and e-residents to securely authenticate online and create digital signatures.[^o18]
