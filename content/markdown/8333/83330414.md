# Min-max optimization

::: {#o1 .subject cue=lead name="Min-max optimization"}

A **min-max optimization (MMO)** problem is a [mathematical optimization](wikipedia://en/52033) problem of the following form:

:::

$$\min_{\mathbf{x}\in \mathbb{R}^{d_x}} \max_{\mathbf{y}\in \mathbb{R}^{d_y}} f(\mathbf{x}, \mathbf{y}) ~~~\text{ such that } ~~~ g(\mathbf{x}, \mathbf{y})\leq 0,$$

where *f* is a bounded function and *g* is a [convex function](wikipedia://en/245568). MMO problems play a central role in [game theory](wikipedia://en/11924), [convex optimization](wikipedia://en/1674411) and [online machine learning](https://en.wikipedia.org/wiki/Online_machine_learning).[^o2] The solution of an MMO problem involves finding a feasible pair of vectors (**x\***,**y\***) that is a [saddle point](wikipedia://en/640249), that is, it satisfies the following two conditions simultaneously:

- f(x\*,y\*) ≤ f(x,y\*) for all **x** with g(**x**,**y\***) ≤ 0;
- f(x\*,y\*) ≥ f(x\*,y) for all **y** with g(**x\***,**y**) ≤ 0.

Note that the optimization is *not* done sequentially (maximize f(x,y) over y for every fixed x, then maximize the resulting function over x). It is done *simultaneously*: the solution should both be minimum over **x** for the given **y\***, and maximum over **y** for the given **x\***.

The solution to an MMO problem is a Nash equilibrium in a two-player [zero-sum game](wikipedia://en/34417), where the payoff of the **y** player is f(**x**,**y**) (and the payoff of the **x** player is -f(**x**,**y**)). Thus, solving an MMO problem is a special case of [Nash equilibrium computation](wikipedia://en/80546223).

## Convex-concave objective {#Convex-concave_objective}

The function *f* is called *convex-concave* if it is a [convex function](wikipedia://en/245568) of **x** for any fixed **y**, and a [concave function](wikipedia://en/263321) of **y** for any fixed **x**. When *f* is continuous and convex-concave, and the constraint set is a convex [compact space](wikipedia://en/6042), MMO always has a solution, which can be computed efficiently using [convex programming](https://en.wikipedia.org/wiki/Convex_programming). This was proved by Rosen in 1965[^o4] and was used to prove the existence of Nash equilibria in [concave games](https://en.wikipedia.org/wiki/Concave_game).

[Sion's minimax theorem](https://en.wikipedia.org/wiki/Sion's_minimax_theorem) (1958) proves an even more general statement: if *f* is a [quasiconvex function](wikipedia://en/5781226) of **x** for any fixed **y**, and a [quasiconcave function](https://en.wikipedia.org/wiki/Quasiconcave_function) of **y** for any fixed **x**, and the constraint set is a convex [compact space](wikipedia://en/6042), MMO always has a solution, which can be computed by sequentially computing the maximum and then the minimum, or the minimum and then the maximum (the two sequential computations lead to identical outcomes in this case).

If *f* is L-smooth, the problem can be solved using [first-order methods](https://en.wikipedia.org/wiki/First-order_method), achieving an approximation error polynomial in *L* and 1/*T* in T iterations.[^o5][^o2]

If *f* is also *strongly* convex-concave, [linear convergence rate](https://en.wikipedia.org/wiki/Linear_convergence) is possible.[^o6]

## Non convex-concave objective {#Non_convex-concave_objective}

In [deep learning](https://en.wikipedia.org/wiki/Deep_learning_in_photoacoustic_imaging), it is often required to solve MMO with objectives that are not convex-concave. This is particularly useful for testing the robustness of deep learning systems against adversaries, as we want to compute the minimum (over all attack strategies) of the maximum (over all defense strategies) of our payoff.

In non convex-concave MMO, a solution might not exist even when the feasible set is compact (this is in contrast to standard minimization or maximization problems, where a solution always exists even when the objective is neither convex nor concave). An example is when *f*(*x*,*y*) = (*x*-*y*)<sup>2</sup> and the feasible set is the [unit cube](wikipedia://en/407763) \[0,1\]x\[0,1\]. Here, for every fixed *x*, the maximum over *y* is attained at either *y*=0 (if x>0.5) or *y*=1 (if x\<0.5). However, for every fixed *y*, the minimum over x is attained at *x*=*y*. Hence, no point is simultaneously maximum over *y* and minimum over *x*.

Checking whether a given MMO problem has a solution is [NP-hard](https://en.wikipedia.org/wiki/NP-hard). It remains NP-hard even in the special case in which the feasible region is a box \[0,1\]<sup>d</sup>, the function *f* is G-Lipschitz and L-smooth, and only an epsilon-approximate solution is allowed (where 1/epsilon, G and L are polynomial in the dimension d).[^o2] [First order methods](https://en.wikipedia.org/wiki/First_order_method) to not work well for such problems.

Daskalakis, Skoutakis and Zampetakis[^o2] study such MMO with linear constraints (the feasible set is a [polytope](wikipedia://en/23471)). They analyze the run-time complexity of computing approximatre local min-max equilibria as a function of the approximation parameters, the smoothness and the Lipschitz constant of the objective function.

## See also {#See_also}

- [Lexicographic max-min optimization](wikipedia://en/73030801) - a different kind of optimization problem (multi-objective rather than single objective).
- [Folk theorem (game theory)](wikipedia://en/3013390) - a theorem in which minmax payments are important. They are known as "punishment points" or "threat points", since a player cannot be punished beyond that.
- [Cooperative bargaining](wikipedia://en/17237395) - another field in which minmax payments are important. Here, they are better known as "disagreement points" or "status quo points".
- [Minimax theorem](wikipedia://en/645602) - gives conditions on games, guaranteeing that the minimax value equals the maximin value.
