# SSH File Transfer Protocol

::: {#o1 .subject cue=lead name="SSH File Transfer Protocol"}

SFTP protocol

In [computing](https://en.wikipedia.org/wiki/Computing), the **SSH File Transfer Protocol**, also known as **Secure File Transfer Protocol** (**SFTP**), is a [network protocol](https://en.wikipedia.org/wiki/Network_protocol) that provides [file access](https://en.wikipedia.org/wiki/File_access), [file transfer](https://en.wikipedia.org/wiki/File_transfer), and [file management](https://en.wikipedia.org/wiki/File_management) over any reliable [data stream](https://en.wikipedia.org/wiki/Data_stream). It was designed by the [Internet Engineering Task Force](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) (IETF) as an extension of the [Secure Shell](wikipedia://en/28814) protocol (SSH) version 2.0 to provide secure file transfer capabilities, and is seen as a replacement of [File Transfer Protocol](https://en.wikipedia.org/wiki/File_Transfer_Protocol) (FTP) due to superior security.[^o3] The [IETF Internet Draft](https://en.wikipedia.org/wiki/IETF_Internet_Draft) states that, even though this protocol is described in the context of the SSH-2 protocol, it could be used in a number of different applications, such as secure file transfer over [Transport Layer Security](wikipedia://en/187813) (TLS) and transfer of management information in [VPN](https://en.wikipedia.org/wiki/VPN) applications.

:::

This protocol assumes that it is run over a [secure channel](wikipedia://en/592935), such as SSH, that the server has already authenticated the client, and that the identity of the client user is available to the protocol.

The official URI scheme is `sftp`.[^o4]

## Capabilities {#Capabilities}

Compared to the [SCP](https://en.wikipedia.org/wiki/Secure_copy) protocol, which only allows file transfers, the SFTP protocol allows for a range of operations on remote files which make it more like a remote [file system](https://en.wikipedia.org/wiki/File_system) protocol.[^o6] An SFTP [client](https://en.wikipedia.org/wiki/Client_%28computing%29)'s extra capabilities include resuming interrupted transfers, directory listings, and remote file removal.[^o7] There is also support for all UNIX file types, including symbolic links.[^o8]

SFTP attempts to be more platform-independent than SCP; with SCP, for instance, the expansion of [wildcards](https://en.wikipedia.org/wiki/Wildcard_character) specified by the client is up to the server, whereas SFTP's design avoids this problem. While SCP is most frequently implemented on [Unix](https://en.wikipedia.org/wiki/Unix) platforms, SFTP servers are commonly available on most platforms. In SFTP, the file transfer can be easily terminated without terminating a session like other mechanisms do.

SFTP is not [FTP](https://en.wikipedia.org/wiki/File_Transfer_Protocol) run over [SSH](wikipedia://en/28814), but rather a new protocol designed from the ground up by the [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) SECSH [working group](https://en.wikipedia.org/wiki/Working_group). It is sometimes confused with [Simple File Transfer Protocol](https://en.wikipedia.org/wiki/Simple_File_Transfer_Protocol).[^o9]

The protocol itself does not provide authentication and security; it expects the underlying protocol to secure this. SFTP is most often used as subsystem of [SSH](https://en.wikipedia.org/wiki/Secure_shell) protocol version 2 implementations, having been designed by the same working group. It is possible, however, to run it over SSH-1 (and some implementations support this), or other data streams. However, running an SFTP server over SSH-1 is not platform-independent, as SSH-1 does not support the concept of subsystems. An SFTP client connecting to an SSH-1 server must be aware of the path to the SFTP server binary on the server side.

Uploaded files may be associated with their basic attributes, such as time stamps. This is an advantage over the common [FTP](https://en.wikipedia.org/wiki/File_Transfer_Protocol) protocol.

## History and development {#History_and_development}

The Internet Engineering Task Force (IETF) working group "Secsh" that was responsible for the development of the [Secure Shell](wikipedia://en/28814) version 2 protocol (RFC 4251) also attempted to draft an extension of that standard for secure file transfer functionality. [Internet Drafts](https://en.wikipedia.org/wiki/Internet_Draft) were created that successively revised the protocol into new versions.[^o11] The software industry began to implement various versions of the protocol before the drafts were standardized. As development work progressed, the scope of the Secsh File Transfer project expanded to include [file access](https://en.wikipedia.org/wiki/File_access) and [file management](https://en.wikipedia.org/wiki/File_management). Eventually, development stalled as some committee members began to view SFTP as a [file system](https://en.wikipedia.org/wiki/File_system) protocol, not just a [file access](https://en.wikipedia.org/wiki/File_access) or [file transfer](https://en.wikipedia.org/wiki/File_transfer) protocol, which places it beyond the purview of the working group.[^o12] After a seven-year hiatus, in 2013 an attempt was made to restart work on SFTP using the version 3 draft as the baseline.[^o13]

### Versions 0–2 {#Versions_0–2}

Prior to the IETF's involvement, SFTP was a proprietary protocol of [SSH Communications Security](https://en.wikipedia.org/wiki/SSH_Communications_Security), designed by Tatu Ylönen with assistance from Sami Lehtinen in 1997.[^o15] Differences between versions 0–2 and version 3 are enumerated upon in [section 10 of draft-ietf-secsh-filexfer-02](https://tools.ietf.org/html/draft-ietf-secsh-filexfer-02#section-10).

### Version 3 {#Version_3}

At the outset of the IETF Secure Shell File Transfer project, the Secsh group stated that its objective of SSH File Transfer Protocol was to provide a secure file transfer functionality over any reliable data stream, and to be the standard file transfer protocol for use with the SSH-2 protocol.

Drafts 00–02 of the IETF Internet Draft define successive revisions of version 3 of the SFTP protocol.

- [SSH File Transfer Protocol, Draft 00, January 2001](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-00)
- [SSH File Transfer Protocol, Draft 01, March 2001](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-01)
- [SSH File Transfer Protocol, Draft 02, October 2001](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02)

### Version 4 {#Version_4}

Drafts 03–04 of the IETF Internet Draft define version 4 of the protocol.

- [SSH File Transfer Protocol, Draft 03, October 2002](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-03)
- [SSH File Transfer Protocol, Draft 04, December 2002](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-04)

### Version 5 {#Version_5}

Draft 05 of the IETF Internet Draft defines version 5 of the protocol.

- [SSH File Transfer Protocol, Draft 05, January 2004](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-05)

### Version 6 {#Version_6}

Drafts 06–13 of the IETF Internet Draft define successive revisions of version 6 of the protocol.

- [SSH File Transfer Protocol, Draft 06, October 2004](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-06)
- [SSH File Transfer Protocol, Draft 07, March 2005](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-07)
- [SSH File Transfer Protocol, Draft 08, April 2005](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-08)
- [SSH File Transfer Protocol, Draft 09, June 2005](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-09) – Added byte-range locks. ACL changes. Rearranged SSH\_FXP\_REALPATH request parameters.
- [SSH File Transfer Protocol, Draft 10, June 2005](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-10) – Extensions "vendor-id", "md5-hash", "space-available", "home-directory" removed. ACL changes.
- [SSH File Transfer Protocol, Draft 11, January 2006](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-11) – ACL transfer fully specified. Editorial changes.
- [SSH File Transfer Protocol, Draft 12, January 2006](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-12) – Added "IANA considerations". A size parameter is now allowed for file creation as an advisory signal.
- [SSH File Transfer Protocol, Draft 13, July 2006](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-13) – editorial changes

### Extensions {#Extensions}

The SFTP protocol supports a generic way of indicating extended commands, along with a method of including them in version negotiation. An IANA registry is requested, but since the protocol never became an official standard, no such registry has been created.[^o8]

- Draft 13 specifies text-seek, supported2, acl-supported, newline, versions, version-select, filename-charset, filename-translation-control.[^o8]
- OpenSSH, the most widespread implementation, defines constants to convert ST\_NOSUID and ST\_RDONLY values across the protocol, using the statvfs@openssh.com version identifier. It only implements version 3 from draft 1.[^o22]

:::

## Software {#Software}

### SFTP client {#SFTP_client}

The term **SFTP** can also refer to [Secure file transfer program](wikipedia://en/1034826), a [command-line program](https://en.wikipedia.org/wiki/Command-line_program) that implements the [client](https://en.wikipedia.org/wiki/Client_%28computing%29) part of this protocol. As an example, the sftp program supplied with [OpenSSH](wikipedia://en/25490426) implements this.[^o25]

Some implementations of the `[[Secure copy#SCP program|scp]]` *program* support both the SFTP and SCP protocols to perform file transfers, depending on what the server supports. The scp program supplied with OpenSSH 9.0 and higher defaults to using SFTP.[^o26]

### SFTP server {#SFTP_server}

Some FTP server implementations implement the SFTP protocol; however, outside of dedicated file servers, SFTP protocol support is usually provided by an [SSH server implementation](https://en.wikipedia.org/wiki/Comparison_of_SSH_servers), as it shares the default port of 22 with other SSH services. SFTP implementations may include an SSH protocol implementation to leverage integration of SSH connection details with preexisting FTP server access controls, where an alternative SSH server is tolerable or where alternative ports may be used. An SSH-2 server which supports subsystems may be leveraged to keep a uniform SSH implementation while enhancing access controls with third party software, at the cost of fine-grained integration with connection details, and SSH-1 compatibility.

### SFTP proxy {#SFTP_proxy}

It is difficult to control SFTP transfers on security devices at the network perimeter. There are standard tools for logging [FTP](https://en.wikipedia.org/wiki/FTP) transactions, like TIS [gdev](https://en.wikipedia.org/wiki/Gdev) or SUSE FTP proxy, but SFTP is encrypted, rendering traditional proxies ineffective for controlling SFTP traffic.

There are some tools that implement man-in-the-middle for SSH which also feature SFTP control. Examples of such a tool are Shell Control Box from Balabit[^o29] and CryptoAuditor from [SSH Communications Security](https://en.wikipedia.org/wiki/SSH_Communications_Security)[^o30] (the original developer of the Secure Shell protocol) which provides functions such as SFTP transaction logging and logging of the actual data transmitted on the wire.
