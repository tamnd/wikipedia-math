# Combinatorial optimization

*Image: Minimum spanning tree.svg.* A [minimum spanning tree](wikipedia://en/41795) of a weighted [planar graph](wikipedia://en/24314). Finding a minimum spanning tree is a common problem involving combinatorial optimization.

::: {#o1 .subject cue=lead name="Combinatorial optimization"}

**Combinatorial optimization** is a subfield of [mathematical optimization](wikipedia://en/52033) that consists of finding an optimal object from a [finite set](wikipedia://en/11742) of objects,[^o2] where the set of [feasible solutions](https://en.wikipedia.org/wiki/Candidate_solution) is [discrete](https://en.wikipedia.org/wiki/Discrete_set) or can be reduced to a discrete set. Typical combinatorial optimization problems are the [travelling salesman problem](wikipedia://en/31248) ("TSP"), the [minimum spanning tree problem](wikipedia://en/41795) ("MST"), and the [knapsack problem](wikipedia://en/16974). In many such problems, such as the ones previously mentioned, [exhaustive search](https://en.wikipedia.org/wiki/Exhaustive_search) is not tractable, and so specialized algorithms that quickly rule out large parts of the search space or [approximation algorithms](wikipedia://en/563105) must be resorted to instead.

:::

Combinatorial optimization is related to [operations research](wikipedia://en/43476), [algorithm theory](wikipedia://en/775), and [computational complexity theory](wikipedia://en/7543). It has important applications in several fields, including [artificial intelligence](https://en.wikipedia.org/wiki/Artificial_intelligence), [machine learning](wikipedia://en/233488), [auction theory](wikipedia://en/5827247), [software engineering](https://en.wikipedia.org/wiki/Software_engineering), [VLSI](https://en.wikipedia.org/wiki/VLSI), [applied mathematics](wikipedia://en/24295969) and [theoretical computer science](wikipedia://en/323392).

::: {#o4 .application cue=heading name="Applications"}

## Applications {#Applications}

Basic applications of combinatorial optimization include, but are not limited to:

- [Logistics](https://en.wikipedia.org/wiki/Logistics)[^o5]
- [Supply chain optimization](https://en.wikipedia.org/wiki/Supply_chain_optimization)[^o6]
- Developing the best airline network of spokes and destinations
- Deciding which taxis in a fleet to route to pick up fares
- Determining the optimal way to deliver packages
- Allocating jobs to people optimally
- Designing water distribution networks
- [Earth science](https://en.wikipedia.org/wiki/Earth_science) problems (e.g. [reservoir](https://en.wikipedia.org/wiki/Reservoir) flow-rates)[^o7]

## Methods {#Methods}

There is a large amount of literature on [polynomial-time algorithms](https://en.wikipedia.org/wiki/Polynomial-time_algorithm) for certain special classes of discrete optimization. A considerable amount of it is unified by the theory of [linear programming](wikipedia://en/43730). Some examples of combinatorial optimization problems that are covered by this framework are [shortest paths](https://en.wikipedia.org/wiki/Shortest_path) and [shortest-path trees](wikipedia://en/9521209), [flows and circulations](wikipedia://en/645676), [spanning trees](wikipedia://en/455770), [matching](wikipedia://en/581797), and [matroid](wikipedia://en/244321) problems.

For [NP-complete](https://en.wikipedia.org/wiki/NP-complete) discrete optimization problems, current research literature includes the following topics:

- polynomial-time exactly solvable special cases of the problem at hand (e.g. [fixed-parameter tractable](https://en.wikipedia.org/wiki/Fixed-parameter_tractable) problems)
- algorithms that perform well on "random" instances (e.g. for the [traveling salesman problem](https://en.wikipedia.org/wiki/Traveling_salesman_problem#Path_length_for_random_sets_of_points_in_a_square))
- [approximation algorithms](wikipedia://en/563105) that run in polynomial time and find a solution that is close to optimal
- [parameterized approximation algorithms](wikipedia://en/72808068) that run in [FPT](https://en.wikipedia.org/wiki/Fixed-parameter_tractability) time and find a solution close to the optimum
- solving real-world instances that arise in practice and do not necessarily exhibit the worst-case behavior of in NP-complete problems (e.g. real-world TSP instances with tens of thousands of nodes[^o10]).

Combinatorial optimization problems can be viewed as searching for the best element of some set of discrete items; therefore, in principle, any sort of [search algorithm](https://en.wikipedia.org/wiki/Search_algorithm) or [metaheuristic](https://en.wikipedia.org/wiki/Metaheuristic) can be used to solve them. Widely applicable approaches include [branch-and-bound](wikipedia://en/456580) (an exact algorithm which can be stopped at any point in time to serve as heuristic), [branch-and-cut](wikipedia://en/3237914) (uses linear optimisation to generate bounds), [dynamic programming](wikipedia://en/125297) (a recursive solution construction with limited search window) and [tabu search](https://en.wikipedia.org/wiki/Tabu_search) (a greedy-type swapping algorithm). However, generic search algorithms are not guaranteed to find an optimal solution first, nor are they guaranteed to run quickly (in polynomial time). Since some discrete optimization problems are [NP-complete](https://en.wikipedia.org/wiki/NP-complete), such as the traveling salesman (decision) problem,[^o11] this is expected unless [P=NP](https://en.wikipedia.org/wiki/P=NP).

For each combinatorial optimization problem, there is a corresponding [decision problem](wikipedia://en/8336) that asks whether there is a feasible solution for some particular measure $m_0$. For example, if there is a [graph](wikipedia://en/325806) $G$ which contains vertices $u$ and $v$, an optimization problem might be "find a path from $u$ to $v$ that uses the fewest edges". This problem might have an answer of, say, 4. A corresponding decision problem would be "is there a path from $u$ to $v$ that uses 10 or fewer edges?" This problem can be answered with a simple 'yes' or 'no'.

The field of [approximation algorithms](wikipedia://en/563105) deals with algorithms to find near-optimal solutions to hard problems. The usual decision version is then an inadequate definition of the problem since it only specifies acceptable solutions. Even though we could introduce suitable decision problems, the problem is then more naturally characterized as an optimization problem.[^o12]

## NP optimization problem {#NP_optimization_problem}

An *NP-optimization problem* (NPO) is a combinatorial optimization problem with the following additional conditions.[^o15] Note that the below referred [polynomials](wikipedia://en/23000) are functions of the size of the respective functions' inputs, not the size of some implicit set of input instances.

- the size of every feasible solution $y\in f(x)$, where $f(x)$ denotes the set of feasible solutions to instance $x$, is polynomially [bounded](wikipedia://en/48258) in the size of the given instance $x$,
- the languages of valid instances $\{\,x\,\mid\, x \in I \,\}$ and of valid instance–solution pairs $\{\,(x,y)\, \mid\, y \in f(x) \,\}$ can be [recognized](https://en.wikipedia.org/wiki/Decidable_language) in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time), and
- The measure $m(x,y)$ of a solution $y$ to problem $x$ is [polynomial-time computable](https://en.wikipedia.org/wiki/Polynomial_time).

This implies that the corresponding decision problem is in [NP](wikipedia://en/21562). In computer science, interesting optimization problems usually have the above properties and are therefore NPO problems. A problem is additionally called a P-optimization (PO) problem, if there exists an algorithm which finds optimal solutions in polynomial time. Often, when dealing with the class NPO, one is interested in optimization problems for which the decision versions are [NP-complete](wikipedia://en/23385892). Note that hardness relations are always with respect to some reduction. Due to the connection between approximation algorithms and computational optimization problems, reductions which preserve approximation in some respect are for this subject preferred than the usual [Turing](wikipedia://en/1188375) and [Karp reductions](https://en.wikipedia.org/wiki/Karp_reduction). An example of such a reduction would be [L-reduction](wikipedia://en/4073116). For this reason, optimization problems with NP-complete decision versions are not necessarily called NPO-complete.[^o16]

NPO is divided into the following subclasses according to their approximability:[^o15]

- *NPO(I)*: Equals [FPTAS](https://en.wikipedia.org/wiki/FPTAS). Contains the [Knapsack problem](wikipedia://en/16974).
- *NPO(II)*: Equals [PTAS](wikipedia://en/666431). Contains the [Makespan](wikipedia://en/31501520) scheduling problem.
- *NPO(III)*: The class of NPO problems that have polynomial-time algorithms which computes solutions with a cost at most *c* times the optimal cost (for minimization problems) or a cost at least $1/c$ of the optimal cost (for maximization problems). In [Hromkovič](https://en.wikipedia.org/wiki/Juraj_Hromkovič)'s book *Algorithms for Hard Problems*, excluded from this class are all NPO(II)-problems save if P=NP.[^o15] Without the exclusion, equals APX. Contains [MAX-SAT](https://en.wikipedia.org/wiki/MAX-SAT) and metric [TSP](wikipedia://en/31248).
- *NPO(IV)*: The class of NPO problems with polynomial-time algorithms approximating the optimal solution by a ratio that is polynomial in a logarithm of the size of the input. In Hromkovič's book, all NPO(III)-problems are excluded from this class unless P=NP. Contains the [set cover](https://en.wikipedia.org/wiki/Set_cover) problem.
- *NPO(V)*: The class of NPO problems with polynomial-time algorithms approximating the optimal solution by a ratio bounded by some function on n. In Hromkovic's book, all NPO(IV)-problems are excluded from this class unless P=NP. Contains the [TSP](wikipedia://en/31248) and [clique problem](wikipedia://en/249254).

An NPO problem is called *polynomially bounded* (PB) if, for every instance $x$ and for every solution $y\in f(x)$, the measure $m(x, y)$ is bounded by a polynomial function of the size of $x$. The class NPOPB is the class of NPO problems that are polynomially-bounded.
