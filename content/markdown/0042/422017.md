# Wi-Fi Protected Access

::: {#o1 .subject cue=lead name="Wi-Fi Protected Access"}

**Wi-Fi Protected Access** (**WPA**), **Wi-Fi Protected Access 2** (**WPA2**), and **Wi-Fi Protected Access 3** (**WPA3**) are the three security certification programs developed after 2000 by the [Wi-Fi Alliance](https://en.wikipedia.org/wiki/Wi-Fi_Alliance) to secure wireless computer networks. The Alliance defined these in response to serious weaknesses researchers had found in the previous system, [Wired Equivalent Privacy](wikipedia://en/422014) (WEP).[^o2]

:::

WPA (sometimes referred to as the TKIP standard) became available in 2003. The Wi-Fi Alliance intended it as an intermediate measure in anticipation of the availability of the more secure and complex WPA2, which became available in 2004 and is a common shorthand for the full IEEE 802.11i (or [IEEE 802.11i-2004](wikipedia://en/783135)) standard.

In January 2018, the Wi-Fi Alliance announced the release of WPA3, which has several security improvements over WPA2.[^o3]

As of 2023, most computers that connect to a wireless network have support for using WPA, WPA2, or WPA3.

## Versions {#Versions}

### WEP {#WEP}

[WEP](wikipedia://en/422014) (Wired Equivalent Privacy) is an early encryption protocol for wireless networks, designed to secure WLAN connections. It supports 64-bit and 128-bit keys, combining user-configurable and factory-set bits. WEP uses the [RC4](wikipedia://en/25831) algorithm for encrypting data, creating a unique key for each packet by combining a new Initialization Vector (IV) with a shared key (it has 40 bits of vectored key and 24 bits of random numbers). Decryption involves reversing this process, using the IV and the shared key to generate a key stream and decrypt the payload. WEP was once widely used, but its significant vulnerabilities led to the adoption of more secure protocols.[^o6]

### WPA {#WPA}

The Wi-Fi Alliance intended WPA as an intermediate measure to take the place of [WEP](wikipedia://en/422014) pending the availability of the full [IEEE 802.11](https://en.wikipedia.org/wiki/IEEE_802.11) standard. WPA could be implemented through [firmware upgrades](https://en.wikipedia.org/wiki/Firmware_upgrade) on [wireless network interface cards](https://en.wikipedia.org/wiki/Wireless_network_interface_card) designed for WEP that began shipping as far back as 1999. However, since the changes required in the [wireless access points](https://en.wikipedia.org/wiki/Wireless_access_point) (APs) were more extensive than those needed on the network cards, most pre-2003 APs were not upgradable by vendor-provided methods to support WPA.

The WPA protocol implements the [Temporal Key Integrity Protocol](wikipedia://en/969136) (TKIP). WEP uses a 64-bit or 128-bit encryption key that must be manually entered on wireless access points and devices and does not change. TKIP employs a per-packet key, meaning that it dynamically generates a new 128-bit key for each packet and thus prevents the types of attacks that compromise WEP.[^o8]

WPA also includes a Message Integrity Check, which is designed to prevent an attacker from altering and resending data packets. This replaces the [cyclic redundancy check](wikipedia://en/38838) (CRC) that was used by the WEP standard. CRC's main flaw is that it does not provide a sufficiently strong [data integrity](https://en.wikipedia.org/wiki/Data_integrity) guarantee for the packets it handles.[^o9] Well-tested [message authentication codes](wikipedia://en/567523) existed to solve these problems, but they require too much computation to be used on old network cards. Researchers have since discovered a flaw in WPA that relied on older weaknesses in WEP and the limitations of the message integrity code hash function, named *Michael*, to retrieve the key-stream from short packets to use for re-injection and [spoofing](https://en.wikipedia.org/wiki/Protocol_spoofing).[^o10][^o11]

::: {#o13 .pointer-item cue=pointer name="WPA2"}

### WPA2 {#WPA2}

Ratified in 2004, WPA2 replaced WPA. WPA2, which requires testing and certification by the Wi-Fi Alliance, implements the mandatory elements of IEEE 802.11i. In particular, it includes support for [CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29), an [AES](wikipedia://en/1260)-based encryption mode.[^o14][^o15][^o16] Certification began in September, 2004. From March 13, 2006, to June 30, 2020, WPA2 certification was mandatory for all new devices to bear the Wi-Fi trademark.[^o17] In WPA2-protected WLANs, secure communication is established through a multi-step process. Initially, devices associate with the Access Point (AP) via an association request. This is followed by a 4-way handshake, a crucial step for ensuring both the client and AP have the correct [Pre-Shared Key](wikipedia://en/4934057) (PSK) without actually transmitting it. During this handshake, a [Pairwise Transient Key](https://en.wikipedia.org/wiki/Pairwise_Transient_Key) (PTK) is generated for secure data exchange.

WPA2 employs the Advanced Encryption Standard ([AES](wikipedia://en/1260)) with a 128-bit key, enhancing security through the Counter-Mode/CBC-Mac Protocol [CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29). This protocol ensures robust encryption and data integrity, using different Initialization Vectors (IVs) for encryption and authentication purposes.[^o18]

The 4-way handshake involves:

- The AP sending a random number (ANonce) to the client.
- The client responding with its random number (SNonce).
- The AP calculating the PTK from these numbers and sending an encrypted message to the client.
- The client decrypting this message with the PTK, confirming successful authentication.[^o19]

Post-handshake, the established PTK is used for encrypting unicast traffic, and the [Group Temporal Key](https://en.wikipedia.org/wiki/Group_Temporal_Key) (GTK) is used for broadcast traffic. This authentication and encryption mechanism is considered robust and defines the WPA2 security standard for wireless networks.[^o19]

:::

::: {#o21 .pointer-item cue=pointer name="WPA3"}

### WPA3 {#WPA3}

In January 2018, the Wi-Fi Alliance announced WPA3 as a replacement to WPA2.[^o22][^o23] Certification began in June 2018,[^o24] and WPA3 support has been mandatory for devices which bear the "Wi-Fi CERTIFIED™" logo since July 2020.[^o25]

The new standard uses an equivalent 192-bit cryptographic strength in WPA3-Enterprise mode[^o26] ([AES-256](https://en.wikipedia.org/wiki/AES-256) in [GCM mode](wikipedia://en/5897139) with [SHA-384](https://en.wikipedia.org/wiki/SHA-384) as [HMAC](wikipedia://en/17112)), and still mandates the use of [CCMP-128](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29) ([AES-128](https://en.wikipedia.org/wiki/AES-128) in [CCM mode](wikipedia://en/2244043)) as the minimum encryption algorithm in WPA3-Personal mode. [TKIP](wikipedia://en/969136) is not allowed in WPA3.

The WPA3 standard also replaces the [pre-shared key](wikipedia://en/4934057) (PSK) exchange with [Simultaneous Authentication of Equals](wikipedia://en/59714120) (SAE) exchange, a method originally introduced with [IEEE 802.11s](https://en.wikipedia.org/wiki/IEEE_802.11s), resulting in a more secure initial key exchange in personal mode[^o27][^o28] and [forward secrecy](wikipedia://en/2191130).[^o29] The Wi-Fi Alliance also says that WPA3 will mitigate security issues posed by weak passwords and simplify the process of setting up devices with no display interface.[^o3][^o30] WPA3 also supports [Opportunistic Wireless Encryption (OWE)](wikipedia://en/59823154) for open Wi-Fi networks that do not have passwords. The Wi-Fi Alliance calls OWE "Wi-Fi CERTIFIED Enhanced Open"; Wi-Fi manufacturers often refer to it as "Enhanced Open" rather than OWE.[^o31]

Protection of management frames as specified in the [IEEE 802.11w](https://en.wikipedia.org/wiki/IEEE_802.11w-2009) amendment is also enforced by the WPA3 specifications.

:::

## Hardware support {#Hardware_support}

WPA has been designed specifically to work with wireless hardware produced prior to the introduction of the WPA protocol,[^o33] which provide inadequate security through [WEP](wikipedia://en/422014). Some of these devices support WPA only after applying firmware upgrades, which are not available for some legacy devices.[^o33]

Wi-Fi devices certified since 2006 support both the WPA and WPA2 security protocols. WPA3 is required since July 1, 2020.[^o25]

## WPA terminology {#WPA_terminology}

Different WPA versions and protection mechanisms can be distinguished based on the target end-user (such as WEP, WPA, WPA2, WPA3) and the method of authentication key distribution, as well as the encryption protocol used. As of July 2020, WPA3 is the latest iteration of the WPA standard, bringing enhanced security features and addressing vulnerabilities found in WPA2. WPA3 improves authentication methods and employs stronger encryption protocols, making it the recommended choice for securing Wi-Fi networks.[^o30]

### Target users (authentication key distribution) {#Target_users_(authentication_key_distribution)}

#### WPA-Personal {#WPA-Personal}

Also referred to as *WPA-PSK* ([pre-shared key](wikipedia://en/4934057)) mode, this is designed for home, small office and basic uses and does not require an authentication server.[^o37] Each wireless network device encrypts the network traffic by using its 128-bit encryption key obtained during the [Temporal Key Integrity Protocol](wikipedia://en/969136) keys derivation from a 256-bit shared key. This key may be entered either as a string of 64 [hexadecimal](wikipedia://en/13263) digits, or as a [passphrase](https://en.wikipedia.org/wiki/Passphrase) of 8 to 63 [printable ASCII characters](https://en.wikipedia.org/wiki/ASCII_printable_characters).[^o38] This pass-phrase-to-PSK mapping is nevertheless not binding, as Annex J is informative in the latest 802.11 standard.[^o39] If ASCII characters are used, the 256-bit key is calculated by applying the [PBKDF2](wikipedia://en/1568244) [key derivation function](wikipedia://en/449781) to the passphrase, using the [SSID](https://en.wikipedia.org/wiki/SSID#Service_set_identification_%28SSID%29) as the [salt](wikipedia://en/701756) and 4096 iterations of [HMAC](wikipedia://en/17112)-[SHA1](https://en.wikipedia.org/wiki/SHA1).[^o40] WPA-Personal mode is available on all three WPA versions.

::: {#o42 .pointer-item cue=pointer name="Enterprise key"}

#### WPA-Enterprise {#WPA-Enterprise}

This enterprise mode uses an [802.1X](https://en.wikipedia.org/wiki/802.1X) server for authentication, offering higher security control by replacing the vulnerable WEP with the more advanced TKIP encryption. TKIP ensures continuous renewal of encryption keys, reducing security risks. Authentication is conducted through a [RADIUS](https://en.wikipedia.org/wiki/RADIUS) server, providing robust security, especially vital in corporate settings. This setup allows integration with Windows login processes and supports various authentication methods like [Extensible Authentication Protocol](https://en.wikipedia.org/wiki/Extensible_Authentication_Protocol), which uses certificates for secure authentication, and PEAP, creating a protected environment for authentication without requiring client certificates.[^o43]

:::

### Encryption protocol {#Encryption_protocol}

**[TKIP](wikipedia://en/969136) (Temporal Key Integrity Protocol)**

The [RC4](wikipedia://en/25831) stream cipher is used with a 128-bit per-packet key, meaning that it dynamically generates a new key for each packet. This is used by WPA.

**[CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29) ([CTR mode](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation#Counter_%28CTR%29) with [CBC-MAC](wikipedia://en/2840574) Protocol)**

The protocol used by WPA2, based on the [Advanced Encryption Standard](wikipedia://en/1260) (AES) cipher along with strong [message authenticity and integrity checking](wikipedia://en/567523) is significantly stronger in protection for both privacy and integrity than the [RC4](wikipedia://en/25831)-based TKIP that is used by WPA. Among informal names are *AES* and *AES-CCMP*. According to the 802.11n specification, this encryption protocol must be used to achieve fast [\802.11n high bitrate schemes](https://en.wikipedia.org/wiki/IEEE_802.11n-2009#Data_rates), though not all implementations enforce this.[^o45] Otherwise, the data rate will not exceed 54 Mbit/s.

## EAP extensions under WPA and WPA2 Enterprise {#EAP_extensions_under_WPA_and_WPA2_Enterprise}

Originally, only EAP-TLS ([Extensible Authentication Protocol](https://en.wikipedia.org/wiki/Extensible_Authentication_Protocol) - [Transport Layer Security](wikipedia://en/187813)) was certified by the Wi-Fi alliance. In April 2010, the [Wi-Fi Alliance](https://en.wikipedia.org/wiki/Wi-Fi_Alliance) announced the inclusion of additional EAP[^o47] types to its WPA- and WPA2-Enterprise certification programs.[^o48] This was to ensure that WPA-Enterprise certified products can interoperate with one another.

the certification program includes the following EAP types:

- [EAP-TLS](https://en.wikipedia.org/wiki/EAP-TLS) (previously tested)
- [EAP-TTLS](https://en.wikipedia.org/wiki/EAP-TTLS)/MSCHAPv2 (April 2005)
- [PEAP](https://en.wikipedia.org/wiki/Protected_Extensible_Authentication_Protocol)v0/EAP-MSCHAPv2 (April 2005)
- PEAPv1/EAP-GTC (April 2005)
- PEAP-TLS
- [EAP-SIM](https://en.wikipedia.org/wiki/EAP-SIM) (April 2005)
- [EAP-AKA](https://en.wikipedia.org/wiki/EAP-AKA) (April 2009[^o49])
- [EAP-FAST](https://en.wikipedia.org/wiki/EAP-FAST) (April 2009)

\802.1X clients and servers developed by specific firms may support other EAP types. This certification is an attempt for popular EAP types to interoperate; their failure to do so is one of the major issues preventing rollout of 802.1X on heterogeneous networks.

Commercial 802.1X servers include Microsoft [Network Policy Server](https://en.wikipedia.org/wiki/Network_Policy_Server) and [Juniper Networks](https://en.wikipedia.org/wiki/Juniper_Networks) Steelbelted RADIUS as well as Aradial Radius server.[^o50] [FreeRADIUS](https://en.wikipedia.org/wiki/FreeRADIUS) is an open source 802.1X server.

## Security issues {#Security_issues}

### Weak password {#Weak_password}

WPA-Personal and WPA2-Personal remain vulnerable to [password cracking](wikipedia://en/477981) attacks if users rely on a [weak password or passphrase](wikipedia://en/4459886). WPA passphrase hashes are seeded from the SSID name and its length; [rainbow tables](wikipedia://en/2403284) exist for the top 1,000 network SSIDs and a multitude of common passwords, requiring only a quick lookup to speed up cracking WPA-PSK.[^o53]

Brute forcing of simple passwords can be attempted using the [Aircrack Suite](https://en.wikipedia.org/wiki/Aircrack-ng) starting from the four-way authentication handshake exchanged during association or periodic re-authentication.[^o54][^o55][^o56][^o57][^o58]

WPA3 replaces cryptographic protocols susceptible to off-line analysis with protocols that require interaction with the infrastructure for each guessed password, supposedly placing temporal limits on the number of guesses.[^o22] However, design flaws in WPA3 enable attackers to plausibly launch brute-force attacks .

### Lack of forward secrecy {#Lack_of_forward_secrecy}

WPA and WPA2 do not provide [forward secrecy](wikipedia://en/2191130), meaning that once an adverse person discovers the pre-shared key, they can potentially decrypt all packets encrypted using that PSK transmitted in the future and even past, which could be passively and silently collected by the attacker. This also means an attacker can silently capture and decrypt others' packets if a WPA-protected access point is provided free of charge at a public place, because its password is usually shared to anyone in that place. In other words, WPA only protects from attackers who do not have access to the password. Because of that, it's safer to use [Transport Layer Security](wikipedia://en/187813) (TLS) or similar on top of that for the transfer of any sensitive data. However starting from WPA3, this issue has been addressed.[^o29]

::: {#o61 .pointer-item cue=pointer name="WPA packet spoofing"}

### WPA packet spoofing and decryption {#WPA_packet_spoofing_and_decryption}

In 2013, Mathy Vanhoef and Frank Piessens[^o62] significantly improved upon the [WPA-TKIP](wikipedia://en/969136) attacks of Erik Tews and Martin Beck.[^o63][^o64] They demonstrated how to inject an arbitrary number of packets, with each packet containing at most 112 bytes of payload. This was demonstrated by implementing a [port scanner](https://en.wikipedia.org/wiki/Port_scanner), which can be executed against any client using [WPA-TKIP](wikipedia://en/969136). Additionally, they showed how to decrypt arbitrary packets sent to a client. They mentioned this can be used to hijack a [TCP connection](https://en.wikipedia.org/wiki/Transmission_Control_Protocol), allowing an attacker to inject malicious [JavaScript](https://en.wikipedia.org/wiki/JavaScript) when the victim visits a website. In contrast, the Beck-Tews attack could only decrypt short packets with mostly known content, such as [ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol) messages, and only allowed injection of 3 to 7 packets of at most 28 bytes. The Beck-Tews attack also requires [quality of service](https://en.wikipedia.org/wiki/Quality_of_service) (as defined in [802.11e](https://en.wikipedia.org/wiki/802.11e)) to be enabled, while the Vanhoef-Piessens attack does not. Neither attack leads to recovery of the shared session key between the client and [Access Point](https://en.wikipedia.org/wiki/Wireless_access_point). The authors say using a short rekeying interval can prevent some attacks but not all, and strongly recommend switching from [TKIP](wikipedia://en/969136) to AES-based [CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29).

Halvorsen and others show how to modify the Beck-Tews attack to allow injection of 3 to 7 packets having a size of at most 596 bytes.[^o65] The downside is that their attack requires substantially more time to execute: approximately 18 minutes and 25 seconds. In other work Vanhoef and Piessens showed that, when WPA is used to encrypt broadcast packets, their original attack can also be executed.[^o66] This is an important extension, as substantially more networks use WPA to protect [broadcast packets](https://en.wikipedia.org/wiki/Broadcasting_%28networking%29), than to protect [unicast packets](https://en.wikipedia.org/wiki/Unicast). The execution time of this attack is on average around 7 minutes, compared to the 14 minutes of the original Vanhoef-Piessens and Beck-Tews attack.

The vulnerabilities of TKIP are significant because WPA-TKIP had been held before to be an extremely safe combination; indeed, WPA-TKIP is still a configuration option upon a wide variety of wireless routing devices provided by many hardware vendors. A survey in 2013 showed that 71% still allow usage of TKIP, and 19% exclusively support TKIP.[^o62]

:::

### WPS PIN recovery {#WPS_PIN_recovery}

A more serious security flaw, revealed in December 2011 by Stefan Viehböck, is the production that affects wireless routers with the [Wi-Fi Protected Setup](https://en.wikipedia.org/wiki/Wi-Fi_Protected_Setup) (WPS) feature, regardless of which encryption method they use. Most recent models have this feature and enable it by default. Many consumer Wi-Fi device manufacturers had taken steps to eliminate the potential of weak passphrase choices by promoting alternative methods of automatically generating and distributing strong keys when users add a new wireless adapter or appliance to a network. These methods include pushing buttons on the devices or entering an 8-digit [PIN](https://en.wikipedia.org/wiki/Personal_identification_number).

The Wi-Fi Alliance standardized these methods as Wi-Fi Protected Setup; however, the PIN feature as widely implemented introduced a major new security flaw. The flaw allows a remote attacker to recover the WPS PIN and, with it, the router's WPA/WPA2 password in a few hours.[^o68] Users have been urged to turn off the WPS feature,[^o69] although this may not be possible on some router models. Also, the PIN is written on a label on most Wi-Fi routers with WPS, which cannot be changed if compromised.

In 2018, the Wi-Fi Alliance introduced Wi-Fi Easy Connect[^o70] as a new alternative for the configuration of devices that lack sufficient user interface capabilities by allowing nearby devices to serve as an adequate UI for network provisioning purposes, thus mitigating the need for WPS.[^o71]

### MS-CHAPv2 and lack of AAA server CN validation {#MS-CHAPv2_and_lack_of_AAA_server_CN_validation}

Several weaknesses have been found in [MS-CHAPv](wikipedia://en/2356452)2, some of which severely reduce the complexity of brute-force attacks, making them feasible with modern hardware. In 2012 the complexity of breaking MS-CHAPv2 was reduced to that of breaking a single [DES](wikipedia://en/7978) key (work by [Moxie Marlinspike](https://en.wikipedia.org/wiki/Moxie_Marlinspike) and Marsh Ray). Moxie advised: "Enterprises who are depending on the mutual authentication properties of MS-CHAPv2 for connection to their WPA2 Radius servers should immediately start migrating to something else."[^o73]

Tunneled EAP methods using TTLS or PEAP which encrypt the MSCHAPv2 exchange are widely deployed to protect against exploitation of this vulnerability. However, prevalent WPA2 client implementations during the early 2000s were prone to misconfiguration by end users, or in some cases (e.g. [Android](https://en.wikipedia.org/wiki/Android_%28operating_system%29)), lacked any user-accessible way to properly configure validation of AAA server certificate CNs. This extended the relevance of the original weakness in MSCHAPv2 within [MiTM](wikipedia://en/144676) attack scenarios.[^o74] Under stricter compliance tests for WPA2 announced alongside WPA3, certified client software will be required to conform to certain behaviors surrounding AAA certificate validation.[^o22]

### Hole196 {#Hole196}

Hole196 is a vulnerability in the WPA2 protocol that abuses the shared Group Temporal Key (GTK). It can be used to conduct man-in-the-middle and [denial-of-service](https://en.wikipedia.org/wiki/Denial-of-service_attack) attacks. However, it assumes that the attacker is already authenticated against Access Point and thus in possession of the GTK.[^o76][^o77]

### Predictable Group Temporal Key (GTK) {#Predictable_Group_Temporal_Key_(GTK)}

In 2016 it was shown that the WPA and WPA2 standards contain a proposed example [random number generator](https://en.wikipedia.org/wiki/Random_number_generator) (RNG) that is insecure.[^o79] Researchers showed that, if vendors implement the proposed RNG, an attacker is able to predict the group key (GTK) that is supposed to be randomly generated by the [access point](https://en.wikipedia.org/wiki/Wireless_access_point) (AP). Additionally, they showed that possession of the GTK enables the attacker to inject any traffic into the network, and allowed the attacker to decrypt unicast internet traffic transmitted over the wireless network. They demonstrated their attack against an [Asus](https://en.wikipedia.org/wiki/Asus) RT-AC51U router that uses the [MediaTek](https://en.wikipedia.org/wiki/MediaTek) out-of-tree drivers, which generate the GTK themselves, and showed the GTK can be recovered within two minutes or less. Similarly, they demonstrated the keys generated by Broadcom access daemons running on VxWorks 5 and later can be recovered in four minutes or less, which affects, for example, certain versions of Linksys WRT54G and certain Apple AirPort Extreme models. Vendors can defend against this attack by using a secure RNG. By doing so, [Hostapd](https://en.wikipedia.org/wiki/Hostapd) running on Linux kernels is not vulnerable against this attack and thus routers running typical [OpenWrt](https://en.wikipedia.org/wiki/OpenWrt) or [LEDE](https://en.wikipedia.org/wiki/LEDE) installations do not exhibit this issue.[^o79]

### KRACK attack {#KRACK_attack}

In October 2017, details of the [KRACK](https://en.wikipedia.org/wiki/KRACK) (Key Reinstallation Attack) attack on WPA2 were published.[^o81][^o82] The KRACK attack is believed to affect all variants of WPA and WPA2; however, the security implications vary between implementations, depending upon how individual developers interpreted a poorly specified part of the standard. Software patches can resolve the vulnerability but are not available for all devices.[^o83] KRACK exploits a weakness in the WPA2 4-Way Handshake, a critical process for generating encryption keys. Attackers can force multiple handshakes, manipulating key resets. By intercepting the handshake, they could decrypt network traffic without cracking encryption directly. This poses a risk, especially with sensitive data transmission.[^o84]

Manufacturers have released patches in response, but not all devices have received updates. Users are advised to keep their devices updated to mitigate such security risks. Regular updates are crucial for maintaining network security against evolving threats.[^o84]

::: {#o86 .pointer-item cue=pointer name="Dragonblood"}

### Dragonblood {#Dragonblood}

In April 2019, the Dragonblood attacks exposed significant vulnerabilities in the Dragonfly handshake protocol used in WPA3 and EAP-pwd.[^o87] These included side-channel attacks potentially revealing sensitive user information and implementation weaknesses in EAP-pwd and SAE. Concerns were also raised about the inadequate security in transitional modes supporting both WPA2 and WPA3. In response, security updates and protocol changes are being integrated into WPA3 and EAP-pwd to address these vulnerabilities and enhance overall Wi-Fi security.[^o88]

:::

### FragAttacks {#FragAttacks}

In May 2021 [FragAttacks](https://en.wikipedia.org/wiki/FragAttacks), a set of new security vulnerabilities, were revealed, affecting Wi-Fi devices and enabling attackers within range to steal information or target devices. These include design flaws in the Wi-Fi standard, affecting most devices, and programming errors in Wi-Fi products, making almost all Wi-Fi products vulnerable. The vulnerabilities impact all Wi-Fi security protocols, including WPA3 and WEP. Exploiting these flaws is complex but programming errors in Wi-Fi products are easier to exploit. Despite improvements in Wi-Fi security, these findings highlight the need for continuous security analysis and updates. In response, security patches were developed, and users are advised to use HTTPS and install available updates for protection.
