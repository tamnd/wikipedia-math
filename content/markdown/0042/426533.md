# Adaptive chosen-ciphertext attack

::: {#o1 .subject cue=lead name="Adaptive chosen-ciphertext attack"}

An **adaptive chosen-ciphertext attack** (abbreviated as **CCA2**) is an interactive form of [chosen-ciphertext attack](wikipedia://en/103586) in which an attacker first sends a number of [ciphertexts](https://en.wikipedia.org/wiki/Ciphertexts) to be decrypted chosen adaptively and then uses the results to distinguish a target ciphertext without consulting the [oracle](wikipedia://en/22431) on the challenge ciphertext. In an adaptive attack, the attacker is further allowed adaptive queries to be asked after the target is revealed (but the target query is disallowed). It is extending the [indifferent (non-adaptive) chosen-ciphertext attack](wikipedia://en/103586) (CCA1), where the second stage of adaptive queries is not allowed.

:::

[Charles Rackoff](https://en.wikipedia.org/wiki/Charles_Rackoff) and Dan Simon defined CCA2 and suggested a system building on the non-adaptive CCA1 definition and system of [Moni Naor](https://en.wikipedia.org/wiki/Moni_Naor) and [Moti Yung](https://en.wikipedia.org/wiki/Moti_Yung), which was the first treatment of chosen ciphertext attack immunity of public key systems.

In certain practical settings, the goal of the attack is gradually revealing information about an encrypted message or about the decryption key itself. For [public-key systems](wikipedia://en/24222), adaptive-chosen-ciphertexts are generally applicable only when they have the property of [ciphertext malleability](wikipedia://en/87027), when a ciphertext can be modified in specific ways that will have a predictable effect on the decryption of that message.

::: {#o3 .pointer-item cue=pointer name="Bleichenbacher’s attack"}

## Practical attacks {#Practical_attacks}

Adaptive-chosen-ciphertext attacks were perhaps considered to be a theoretical concern but not to have been be manifested in practice until 1998, when [Daniel Bleichenbacher](https://en.wikipedia.org/wiki/Daniel_Bleichenbacher) (then of [Bell Laboratories](https://en.wikipedia.org/wiki/Bell_Laboratories)) demonstrated a practical attack against systems using RSA encryption in concert with the [PKCS#1 v1.5](wikipedia://en/16706008) encoding function, including a version of the [Secure Sockets Layer](https://en.wikipedia.org/wiki/Secure_Sockets_Layer) (SSL) protocol that was used by thousands of [web servers](https://en.wikipedia.org/wiki/Web_servers) at the time.[^o4]

The Bleichenbacher attacks, also known as the million message attack, took advantage of flaws within the PKCS #1 v1.5 padding function to gradually reveal the content of an RSA encrypted message. Under this padding function, padded plaintexts have a fixed format that it should follow. If the decryption device (e.g. SSL-equipped web server) somehow reveals whether the padding is valid, it also serves as an "oracle" that reveals information on the secret key. Finding the whole key requires sending several million test ciphertexts to the target.[^o5] In practical terms, this means that an SSL session key can be exposed in a reasonable amount of time, perhaps a day or less.

With slight variations, the vulnerability was still exploitable in many servers in 2018, under the new name "Return Of Bleichenbacher's Oracle Threat" (ROBOT),[^o6] and again in 2023, as the Marvin Attack[^o7].

:::

## Preventing attacks {#Preventing_attacks}

To prevent adaptive-chosen-ciphertext attacks, it is necessary to use an encryption or encoding scheme that limits ciphertext [malleability](wikipedia://en/87027) and a proof of security of the system. After the theoretical and foundation level development of CCA secure systems, a number of systems have been proposed in the Random Oracle model: the most common standard for RSA encryption is [Optimal Asymmetric Encryption Padding](https://en.wikipedia.org/wiki/Optimal_Asymmetric_Encryption_Padding) (OAEP).

Unlike improvised schemes such as the padding used in the early versions of PKCS#1, OAEP has been proven secure in the [random oracle](wikipedia://en/451286) model,[^o9] OAEP was incorporated into PKCS#1 as of version 2.0 published in 1998 as the now-recommended encoding scheme, with the older scheme still supported but not recommended for new applications.[^o10] However, the golden standard for security is to show the system secure without relying on the Random Oracle idealization.[^o11]

## Mathematical model {#Mathematical_model}

In complexity-theoretic cryptography, security against adaptive chosen-ciphertext attacks is commonly modeled using [ciphertext indistinguishability](wikipedia://en/2187252) (IND-CCA2).
