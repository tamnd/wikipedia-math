# Security level

::: {#o1 .subject cue=lead name="Security level"}

In cryptography, **security level** is a measure of the strength that a [cryptographic primitive](wikipedia://en/4928985) — such as a [cipher](wikipedia://en/5244) or [hash function](https://en.wikipedia.org/wiki/Hash_function) — achieves. Security level is usually expressed as a number of "[bits](https://en.wikipedia.org/wiki/Bit) of security" (also **security strength**),[^o2] where *n*-bit security means that the attacker would have to perform 2<sup>*n*</sup> operations to break it,[^o3] but other methods have been proposed that more closely model the costs for an attacker.[^o4] This allows for convenient comparison between algorithms and is useful when combining multiple primitives in a [hybrid cryptosystem](wikipedia://en/11756462), so there is no clear weakest link. For example, [AES](wikipedia://en/1260)-128 ([key size](wikipedia://en/5749) 128 bits) is designed to offer a 128-bit security level, which is considered roughly equivalent to a [RSA](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29) using 3072-bit key.

:::

In this context, **security claim** or **target security level** is the security level that a primitive was initially designed to achieve, although "security level" is also sometimes used in those contexts. When attacks are found that have lower cost than the security claim, the primitive is considered **broken**.[^o5][^o6]

## In symmetric cryptography {#In_symmetric_cryptography}

Symmetric algorithms usually have a strictly defined security claim. For [symmetric ciphers](https://en.wikipedia.org/wiki/Symmetric_cipher), it is typically equal to the [key size](wikipedia://en/5749) of the cipher — equivalent to the [complexity](https://en.wikipedia.org/wiki/Complexity) of a [brute-force attack](wikipedia://en/53784).[^o6][^o8] [Cryptographic hash functions](wikipedia://en/439526) with output size of *n* bits usually have a [collision resistance](wikipedia://en/2982326) security level *n*/2 and a [preimage resistance](https://en.wikipedia.org/wiki/Preimage_resistance) level *n*. This is because the general [birthday attack](wikipedia://en/189369) can always find collisions in 2<sup>*n/2*</sup> steps.[^o9] For example, [SHA-256](wikipedia://en/1638777) offers 128-bit collision resistance and 256-bit preimage resistance.

However, there are some exceptions to this. The [Phelix](wikipedia://en/883596) and Helix are 256-bit ciphers offering a 128-bit security level.[^o6][^o10] The SHAKE variants of [SHA-3](wikipedia://en/20394543) are also different: for a 256-bit output size, SHAKE-128 provides 128-bit security level for both collision and preimage resistance.[^o11]

## In asymmetric cryptography {#In_asymmetric_cryptography}

The design of most asymmetric algorithms (i.e. [public-key cryptography](wikipedia://en/24222)) relies on neat [mathematical problems](wikipedia://en/256700) that are efficient to compute in one direction, but inefficient to reverse by the attacker. However, attacks against current public-key systems are always faster than [brute-force search](https://en.wikipedia.org/wiki/Brute-force_search) of the key space. Their security level isn't set at design time, but represents a [computational hardness assumption](wikipedia://en/6158383), which is adjusted to match the best currently known attack.[^o8]

Various recommendations have been published that estimate the security level of asymmetric algorithms, which differ slightly due to different methodologies.

- For the [RSA cryptosystem](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29) at 128-bit security level, [NIST](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) and [ENISA](https://en.wikipedia.org/wiki/European_Union_Agency_for_Network_and_Information_Security) recommend using 3072-bit keys[^o13][^o14] and [IETF](https://en.wikipedia.org/wiki/Internet_Engineering_Task_Force) 3253 bits.[^o15][^o16] The conversion from key length to a security level estimate is based on the complexity of the [GNFS](wikipedia://en/152734).[^o17]
- [Diffie–Hellman key exchange](wikipedia://en/7903) and DSA are similar to RSA in terms of the conversion from key length to a security level estimate.[^o17]
- [Elliptic curve cryptography](https://en.wikipedia.org/wiki/Elliptic_curve_cryptography) requires shorter keys, so the recommendations for 128-bit are 256-383 (NIST), 256 (ENISA) and 242 bits (IETF). The conversion from key size *f* to security level is approximately *f* / 2: this is because the method to break the Elliptic Curve [Discrete Logarithm](wikipedia://en/181334) Problem, the rho method, finishes in 0.886 sqrt(2<sup>*f*</sup>) additions.[^o18]

## Typical levels {#Typical_levels}

### NIST Comparable Algorithm Strengths {#NIST_Comparable_Algorithm_Strengths}

The following table are examples of typical security levels for types of algorithms as found in s5.6.1.1 of the US NIST SP-800-57 Recommendation for [Key Management](wikipedia://en/631063).[^o21]

*Comparable Algorithm Strengths*

::: {#o22 .table cue=table name="Comparable Algorithm Strengths"}

| Security Bits | Symmetric Key | Finite Field/Discrete Logarithm (DSA, DH, MQV) | Integer Factorization (RSA) | Elliptic Curve (ECDSA, EdDSA, ECDH, ECMQV) |
|---|---|---|---|---|
| 80 | 2TDEA | *L* = 1024, *N* = 160 | *k* = 1024 | 160 ≤ *f* ≤ 223 |
| 112 | 3TDEA | *L* = 2048, *N* =224 | *k* = 2048 | 224 ≤ *f* ≤ 255 |
| 128 | AES-128 | *L* = 3072, *N* = 256 | *k* = 3072 | 256 ≤ *f* ≤ 383 |
| 192 | AES-192 | *L* = 7680, *N* = 384 | *k* = 7680 | 384 ≤ *f* ≤ 511 |
| 256 | AES-256 | *L* = 15360, *N* = 512 | *k* = 15360 | *f* ≥ 512 |

:::

Under NIST recommendation, a key of a given security level should only be transported under protection using an algorithm of equivalent or higher security level.[^o17]

The security level is given for the cost of breaking one target, not the amortized cost for group of targets. It takes 2<sup>128</sup> operations to find a AES-128 key, yet the same number of amortized operations is required for any number *m* of keys. On the other hand, breaking *m* ECC keys using the rho method require sqrt(*m*) times the base cost.[^o18][^o23]

### NIST Security Categories {#NIST_Security_Categories}

As part of the [NIST Post-Quantum Cryptography Standardization](wikipedia://en/56162225) process, NIST introduce a new set of security categories, defined [^o25] in comparison with the resources required to attack block ciphers or hashes with particular key or output sizes:

*NIST Security Categories*

::: {#o26 .table cue=table name="NIST Security Categories"}

| Category | Equivalent Resources Required to Attack | Examples |
|---|---|---|
| 1 | Key search on a block cipher with a 128-bit key | AES-128, ML-KEM-512 |
| 2 | Collision search on a 256-bit hash function | SHA-256, ML-DSA-44 |
| 3 | Key search on a block cipher with a 192-bit key | AES-192, ML-KEM-768 |
| 4 | Collision search on a 384-bit hash function | SHA-384 |
| 5 | Key search on a block cipher with a 256-bit key | AES-256, ML-KEM-1024 |

:::

## Meaning of "broken" {#Meaning_of_"broken"}

A cryptographic primitive is considered broken when an attack is found to have less than its advertised level of security. However, not all such attacks are practical: most currently demonstrated attacks take fewer than 2<sup>40</sup> operations, which translates to a few hours on an average PC. The costliest demonstrated attack on hash functions is the 2<sup>\61.2</sup> attack on [SHA-1](wikipedia://en/26672), which took 2 months on 900 [GTX 1060](https://en.wikipedia.org/wiki/GTX_1060) GPUs, and cost US\$75,000 (although the researchers estimate only \$11,000 was needed to find a collision).[^o28]

Aumasson draws the line between practical and impractical attacks at 2<sup>80</sup> operations. He proposes a new terminology:[^o29]

- A *broken* primitive has an attack taking ≤ 2<sup>80</sup> operations. An attack can be plausibly carried out.
- A *wounded* primitive has an attack taking between 2<sup>80</sup> and around 2<sup>100</sup> operations. An attack is not possible right now, but future improvements are likely to make it possible.
- An *attacked* primitive has an attack that is cheaper than the security claim, but much costlier than 2<sup>100</sup>. Such an attack is too far from being practical.
- Finally, an *analyzed* primitive is one with no attacks cheaper than its security claim.

## Quantum attacks {#Quantum_attacks}

The field of [post-quantum cryptography](wikipedia://en/26605226) considers the security level of cryptographic algorithms in the face of a hypothetical attacker possessing a [quantum computer](https://en.wikipedia.org/wiki/Quantum_computer).

- Most quantum attacks on symmetric ciphers provide a square-root speedup to their classical counterpart, thereby halving the security level provided. (The exception is the [slide attack](wikipedia://en/1821327) with [Simon's algorithm](https://en.wikipedia.org/wiki/Simon's_algorithm), though it has not proved useful in attacking AES.) For example, AES-256 would provide 128 bits of quantum security, which is still considered plenty.[^o31][^o32]
- [Shor's algorithm](wikipedia://en/42674) promises a massive speedup in solving the factoring problem, the discrete logarithm problem, and the period-finding problem, so long as a sufficiently large quantum computer on the order of millions of qubits is available. This would spell the end of RSA, DSA, DH, MQV, ECDSA, EdDSA, ECDH, and ECMQV in their current forms.[^o33]

Even though quantum computers capable of these operations have yet to appear, adversaries of today may choose to "[harvest now, decrypt later](wikipedia://en/73504338)": to store intercepted ciphertexts so that they can be decrypted when sufficiently powerful quantum computers become available. As a result, governments and businesses have already begun work on moving to quantum-resistant algorithms. Examples of these effort include Google and Cloudflare's tests of hybrid post-quantum TLS on the Internet and[^o34] NSA's release of [Commercial National Security Algorithm Suite](https://en.wikipedia.org/wiki/Commercial_National_Security_Algorithm_Suite) 2.0 in 2022.
