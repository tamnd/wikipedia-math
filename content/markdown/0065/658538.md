# DTIME

::: {#o1 .subject cue=lead name="DTIME"}

In [computational complexity theory](wikipedia://en/7543), **DTIME** (or **TIME**) is the [computational resource](wikipedia://en/4628222) of [computation time](https://en.wikipedia.org/wiki/Computation_time) for a [deterministic Turing machine](https://en.wikipedia.org/wiki/Deterministic_Turing_machine). It represents the amount of time (or number of computation steps) that a "normal" physical computer would take to solve a certain [computational problem](https://en.wikipedia.org/wiki/Computational_problem) using a certain [algorithm](wikipedia://en/775). It is one of the most well-studied complexity resources, because it corresponds so closely to an important real-world resource (the amount of time it takes a computer to solve a problem).

:::

The resource **DTIME** is used to define [complexity classes](wikipedia://en/502426), sets of all of the [decision problems](wikipedia://en/8336) that can be solved using a certain amount of computation time. If problem instances of input size *n* can be solved in $O(f(n))$, the problem is in the complexity class $\mathsf{DTIME}(f(n))$ (or $\mathsf{TIME}(f(n))$). There is no restriction on the amount of [memory space](https://en.wikipedia.org/wiki/Memory_space_%28computational_resource%29) used, but there may be restrictions on some other complexity resources (like [alternation](https://en.wikipedia.org/wiki/Alternation_%28complexity%29)).

## Complexity classes in DTIME {#Complexity_classes_in_DTIME}

Many important complexity classes are defined in terms of **DTIME**, containing all of the problems that can be solved in a certain amount of deterministic time. Any [proper complexity function](https://en.wikipedia.org/wiki/Proper_complexity_function) can be used to define a complexity class, but only certain classes are useful to study. In general, we desire our complexity classes to be robust against changes in the computational model, and to be closed under composition of subroutines.

DTIME satisfies the [time hierarchy theorem](wikipedia://en/184120), meaning that [asymptotically](wikipedia://en/641995) larger amounts of time always create strictly larger sets of problems.

The well-known complexity class **[P](wikipedia://en/658550)** comprises all of the problems that can be solved in a polynomial amount of **DTIME**. It can be defined formally as:

$$\mathsf{P} = \bigcup_{k\in\mathbb{N}} \mathsf{DTIME}(n^k)$$

**P** is the smallest robust class that includes linear-time problems $\mathsf{DTIME}\left(n\right)$ (AMS 2004, Lecture 2.2, pg. 20). **P** is one of the largest complexity classes considered "computationally feasible".

A much larger class using deterministic time is [EXPTIME](wikipedia://en/54694), which contains all of the problems solvable using a deterministic machine in [exponential time](https://en.wikipedia.org/wiki/Exponential_time). Formally, we have

$$\mathsf{EXPTIME} = \bigcup_{k \in \mathbb{N} } \mathsf{DTIME} \left( 2^{ n^k } \right) .$$

Larger complexity classes can be defined similarly. Because of the time hierarchy theorem, these classes form a strict hierarchy; we know that $\mathsf{P} \subsetneq \mathsf{EXPTIME}$, and on up.

## Machine model {#Machine_model}

For robust classes, such as P, the exact machine model used to define DTIME can vary without affecting the power of the resource. The computational complexity literature often defines DTIME based on [multitape Turing machines](wikipedia://en/4631387), particularly when discussing very small time classes. A multitape deterministic Turing machine can never provide more than a quadratic time speedup over a singletape machine.[^n1]

Due to the [linear speedup theorem](wikipedia://en/663023) for Turing machines, multiplicative constants in the time bound do not affect the extent of DTIME classes; a constant multiplicative speedup can always be obtained by increasing the number of states in the finite state control and the size of the tape alphabet. In the statement of Papadimitriou,[^n2] for a language $L$,

Let $L \in \mathsf{DTIME}(f(n))$. Then, for any $\epsilon > 0$, $L \in \mathsf{DTIME}(f'(n))$, where $f'(n) = \epsilon f(n) + n + 2$.

## Generalizations {#Generalizations}

Using a model other than a deterministic Turing machine, there are various generalizations and restrictions of DTIME. For example, if we use a [nondeterministic Turing machine](wikipedia://en/21935), we have the resource [NTIME](wikipedia://en/658539). The relationship between the expressive powers of DTIME and other computational resources are very poorly understood. One of the few known results[^n3] is

$\mathsf{DTIME}(O(n)) \neq \mathsf{NTIME}(O(n))$ for multitape machines. This was extended to

$\mathsf{DTIME}(O(n\sqrt{\log^*n})) \neq \mathsf{NTIME}(O(n\sqrt{\log^*n}))$ by Santhanam,[^n4] where $\log^*n$ is the [iterated logarithm](wikipedia://en/1038048).

If we use an [alternating Turing machine](https://en.wikipedia.org/wiki/Alternation_%28complexity%29), we have the resource ATIME.
