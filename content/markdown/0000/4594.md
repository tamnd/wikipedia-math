# Block cipher

::: {#o1 .subject cue=lead name="Block cipher"}

In [cryptography](wikipedia://en/18934432), a **block cipher** is a [deterministic algorithm](https://en.wikipedia.org/wiki/Deterministic_algorithm) that operates on fixed-length groups of [bits](https://en.wikipedia.org/wiki/Bit), called *blocks*. Block ciphers are the elementary [building blocks](wikipedia://en/4928985) of many [cryptographic protocols](wikipedia://en/591994). They are ubiquitous in the storage and exchange of data, where such data is secured and authenticated via [encryption](wikipedia://en/10294).

:::

A block cipher uses blocks as an unvarying transformation. Even a secure block cipher is suitable for the encryption of only a single block of data at a time, using a fixed key. A multitude of [modes of operation](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation) have been designed to allow their repeated use in a secure way to achieve the other security goals of confidentiality and [authenticity](wikipedia://en/47967). However, block ciphers may also feature as building blocks in other cryptographic protocols, such as [universal hash functions](https://en.wikipedia.org/wiki/Universal_hash_function) and [pseudorandom number generators](wikipedia://en/45524).

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

*Image: Block Cipher-en.svg.* Block diagram of cipher block showing its inputs, outputs and components

A block cipher consists of two paired [algorithms](wikipedia://en/775), one for encryption, E, and the other for decryption, D.[^o4] Both algorithms accept two inputs: an input block of size n bits and a [key](wikipedia://en/53039) of size k bits; and both yield an n-bit output block. The decryption algorithm D is defined to be the [inverse function](wikipedia://en/14907) of encryption, i.e., $D = E^{-1}$. More formally,[^o5][^o6] a block cipher is specified by an encryption function

$$E_K(P) := E(K,P): \{0,1\}^k \times \{0,1\}^n \rightarrow \{0,1\}^n,$$

which takes as input a key K, of bit length k (called the *key size*), and a bit string P, of length n (called the *block size*), and returns a string C of n bits. P is called the [plaintext](wikipedia://en/157935), and C is termed the [ciphertext](wikipedia://en/175560). For each K, the function E<sub>K</sub>(P) is required to be an invertible mapping on $\{0,1\}^{n}$. The inverse for E is defined as a function

$$E_K^{-1}(C) := D_K(C) = D(K,C): \{0,1\}^k \times \{0,1\}^n \rightarrow \{0,1\}^n,$$

taking a key K and a ciphertext C to return a plaintext value P, such that

$$\forall P: D_K(E_K(P)) = P.$$

For example, a block cipher encryption algorithm might take a 128-bit block of plaintext as input, and output a corresponding 128-bit block of ciphertext. The exact transformation is controlled using a second input – the secret key. Decryption is similar: the decryption algorithm takes, in this example, a 128-bit block of ciphertext together with the secret key, and yields the original 128-bit block of plain text.[^o7]

For each key *K*, *E<sub>K</sub>* is a [permutation](wikipedia://en/44027) (a [bijective](https://en.wikipedia.org/wiki/Bijective) mapping) over the set of input blocks. Each key selects one permutation from the set of $(2^n)!$ possible permutations.[^n1]

:::

## History {#History}

The modern design of block ciphers is based on the concept of an iterated [product cipher](wikipedia://en/598557). In his seminal 1949 publication, *[Communication Theory of Secrecy Systems](wikipedia://en/452085)*, [Claude Shannon](wikipedia://en/5693) analyzed product ciphers and suggested them as a means of effectively improving security by combining simple operations such as [substitutions](wikipedia://en/48356) and [permutations](wikipedia://en/48358).[^o10] Iterated product ciphers carry out encryption in multiple [rounds](wikipedia://en/73297602), each of which uses a different subkey derived from the original key. One widespread implementation of such ciphers named a [Feistel network](https://en.wikipedia.org/wiki/Feistel_network) after [Horst Feistel](wikipedia://en/530509) is notably implemented in the [DES](wikipedia://en/7978) cipher.[^o11] Many other realizations of block ciphers, such as the [AES](wikipedia://en/1260), are classified as [substitution–permutation networks](https://en.wikipedia.org/wiki/Substitution–permutation_network).[^n2]

The publication of the DES cipher by the United States National Bureau of Standards (subsequently the U.S. [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology), NIST) in 1977 was fundamental in the public understanding of modern block cipher design. It also influenced the academic development of [cryptanalytic attacks](wikipedia://en/5715). Both [differential](wikipedia://en/8536) and [linear cryptanalysis](wikipedia://en/59469) arose out of studies on DES design. , there is a palette of attack techniques against which a block cipher must be secure, in addition to being robust against [brute-force attacks](wikipedia://en/53784).

## Design {#Design}

### Iterated block ciphers {#Iterated_block_ciphers}

Most block cipher algorithms are classified as *iterated block ciphers* which means that they transform fixed-size blocks of [plaintext](wikipedia://en/157935) into identically sized blocks of [ciphertext](wikipedia://en/175560), via the repeated application of an invertible transformation known as the *round function*, with each iteration referred to as a *round*.[^o15]

Usually, the round function *R* takes different *round keys* *K<sub>i</sub>* as a second input, which is derived from the original key:[^o16]

$$M_i = R_{K_i}(M_{i-1})$$

where $M_0$ is the plaintext and $M_r$ the ciphertext, with *r* being the number of rounds.

Frequently, [key whitening](wikipedia://en/2990178) is used in addition to this. At the beginning and the end, the data is modified with key material (often with [XOR](wikipedia://en/105979)):

$$M_0 = M \oplus K_0$$

$$M_i = R_{K_i}(M_{i-1})\; ; \; i = 1 \dots r$$

$$C = M_r \oplus K_{r+1}$$

Given one of the standard iterated block cipher design schemes, it is fairly easy to construct a block cipher that is cryptographically secure, simply by using a large number of rounds. However, this will make the cipher inefficient. Thus, efficiency is the most important additional design criterion for professional ciphers. Further, a good block cipher is designed to avoid side-channel attacks, such as branch prediction and input-dependent memory accesses that might leak secret data via the cache state or the execution time. In addition, the cipher should be concise, for small hardware and software implementations.

### Substitution–permutation networks {#Substitution–permutation_networks}

*Image: SubstitutionPermutationNetwork-en.svg.* A sketch of a substitution–permutation network with 3 rounds, encrypting a plaintext block of 16 bits into a ciphertext block of 16 bits. The S-boxes are the *S<sub>i</sub>*, the P-boxes are the same *P*, and the round keys are the *K<sub>i</sub>*.

One important type of iterated block cipher known as a *[substitution–permutation network](https://en.wikipedia.org/wiki/Substitution–permutation_network) (SPN)* takes a block of the plaintext and the key as inputs and applies several alternating rounds consisting of a [substitution stage](https://en.wikipedia.org/wiki/Substitution_box) followed by a [permutation stage](wikipedia://en/19958773)—to produce each block of ciphertext output.[^o18] The non-linear substitution stage mixes the key bits with those of the plaintext, creating Shannon's *[confusion](https://en.wikipedia.org/wiki/Confusion_%28cryptography%29)*. The linear permutation stage then dissipates redundancies, creating *[diffusion](https://en.wikipedia.org/wiki/Diffusion_%28cryptography%29)*.[^o19][^o20]

A *[substitution box](https://en.wikipedia.org/wiki/Substitution_box) (S-box)* substitutes a small block of input bits with another block of output bits. This substitution must be [one-to-one](wikipedia://en/3942), to ensure invertibility (hence decryption). A secure S-box will have the property that changing one input bit will change about half of the output bits on average, exhibiting what is known as the [avalanche effect](wikipedia://en/769439)—i.e. it has the property that each output bit will depend on every input bit.[^o21]

A *[permutation box](wikipedia://en/19958773) (P-box)* is a [permutation](wikipedia://en/44027) of all the bits: it takes the outputs of all the S-boxes of one round, permutes the bits, and feeds them into the S-boxes of the next round. A good P-box has the property that the output bits of any S-box are distributed to as many S-box inputs as possible.[^o22]

At each round, the round key (obtained from the key with some simple operations, for instance, using S-boxes and P-boxes) is combined using some group operation, typically [XOR](https://en.wikipedia.org/wiki/XOR).

[Decryption](https://en.wikipedia.org/wiki/Decryption) is done by simply reversing the process (using the inverses of the S-boxes and P-boxes and applying the round keys in reversed order).[^o23]

### Feistel ciphers {#Feistel_ciphers}

*Image: Feistel cipher diagram en.svg.* Many block ciphers, such as DES and Blowfish utilize structures known as *Feistel ciphers*.

In a *Feistel cipher*, the block of plain text to be encrypted is split into two equal-sized halves. The round function is applied to one half, using a subkey, and then the output is XORed with the other half. The two halves are then swapped.[^n3]

Let ${\rm F}$ be the round function and let $K_0,K_1,\ldots,K_{n}$ be the sub-keys for the rounds $0,1,\ldots,n$ respectively.

Then the basic operation is as follows:[^n3]

Split the plaintext block into two equal pieces, ($L_0$, $R_0$)

For each round $i =0,1,\dots,n$, compute

$$L_{i+1} = R_i\,$$

$$R_{i+1}= L_i \oplus {\rm F}(R_i, K_i).$$

Then the ciphertext is $(R_{n+1}, L_{n+1})$.

The decryption of a ciphertext $(R_{n+1}, L_{n+1})$ is accomplished by computing for $i=n,n-1,\ldots,0$

$$R_{i} = L_{i+1}\,$$

$$L_{i} = R_{i+1} \oplus {\rm F}(L_{i+1}, K_{i}).$$

Then $(L_0,R_0)$ is the plaintext again.

One advantage of the Feistel model compared to a [substitution–permutation network](https://en.wikipedia.org/wiki/Substitution–permutation_network) is that the round function ${\rm F}$ does not have to be invertible.[^n4]

### Lai–Massey ciphers {#Lai–Massey_ciphers}

*Image: Lai Massey scheme diagram en.svg.* The Lai–Massey scheme. The archetypical cipher utilizing it is [IDEA](wikipedia://en/15076).

The Lai–Massey scheme offers security properties similar to those of the [Feistel structure](https://en.wikipedia.org/wiki/Feistel_structure). It also shares the advantage that the round function $\mathrm F$ does not have to be invertible. Another similarity is that it also splits the input block into two equal pieces. However, the round function is applied to the difference between the two, and the result is then added to both half blocks.

Let $\mathrm F$ be the round function and $\mathrm H$ a half-round function and let $K_0,K_1,\ldots,K_n$ be the sub-keys for the rounds $0,1,\ldots,n$ respectively.

Then the basic operation is as follows:

Split the plaintext block into two equal pieces, ($L_0$, $R_0$)

For each round $i =0,1,\dots,n$, compute

$$(L_{i+1}',R_{i+1}') = \mathrm H(L_i' + T_i,R_i' + T_i),$$

where $T_i = \mathrm F(L_i' - R_i', K_i)$ and $(L_0',R_0') = \mathrm H(L_0,R_0)$

Then the ciphertext is $(L_{n+1}, R_{n+1}) = (L_{n+1}',R_{n+1}')$.

The decryption of a ciphertext $(L_{n+1}, R_{n+1})$ is accomplished by computing for $i=n,n-1,\ldots,0$

$$(L_i',R_i') = \mathrm H^{-1}(L_{i+1}' - T_i, R_{i+1}' - T_i)$$

where $T_i = \mathrm F(L_{i+1}' - R_{i+1}',K_i)$ and $(L_{n+1}',R_{n+1}')=\mathrm H^{-1}(L_{n+1},R_{n+1})$

Then $(L_0,R_0) = (L_0',R_0')$ is the plaintext again.

### Operations {#Operations}

#### ARX (add–rotate–XOR) {#ARX_(add–rotate–XOR)}

Many modern block ciphers and hashes are **ARX** algorithms—their round function involves only three operations: (A) modular addition, (R) [rotation](wikipedia://en/1917276) with fixed rotation amounts, and (X) [XOR](wikipedia://en/105979). Examples include [ChaCha20](https://en.wikipedia.org/wiki/ChaCha20), [Speck](wikipedia://en/39994293), [XXTEA](wikipedia://en/10919454), and [BLAKE](wikipedia://en/30054589). Many authors draw an ARX network, a kind of [data flow diagram](https://en.wikipedia.org/wiki/Data_flow_diagram), to illustrate such a round function.[^o32]

These ARX operations are popular because they are relatively fast and cheap in hardware and software, their implementation can be made extremely simple, and also because they run in constant time, and therefore are immune to [timing attacks](wikipedia://en/481813). The [rotational cryptanalysis](wikipedia://en/26122724) technique attempts to attack such round functions.

:::

#### Other operations {#Other_operations}

Other operations often used in block ciphers include data-dependent rotations as in [RC5](wikipedia://en/102600) and [RC6](wikipedia://en/160216), a [substitution box](https://en.wikipedia.org/wiki/Substitution_box) implemented as a [lookup table](https://en.wikipedia.org/wiki/Lookup_table) as in [Data Encryption Standard](wikipedia://en/7978) and [Advanced Encryption Standard](wikipedia://en/1260), a [permutation box](wikipedia://en/19958773), and multiplication as in [IDEA](https://en.wikipedia.org/wiki/IDEA_%28cipher%29).

## Modes of operation {#Modes_of_operation}

*Image: Tux ecb.jpg.* Insecure encryption of an image (depicting [Tux](https://en.wikipedia.org/wiki/Tux_%28mascot%29)) as a result of [electronic codebook](https://en.wikipedia.org/wiki/Electronic_codebook) (ECB) mode encoding

A block cipher by itself allows encryption only of a single data block of the cipher's block length. For a variable-length message, the data must first be partitioned into separate cipher blocks. In the simplest case, known as [electronic codebook](https://en.wikipedia.org/wiki/Electronic_codebook) (ECB) mode, a message is first split into separate blocks of the cipher's block size (possibly extending the last block with [padding](wikipedia://en/592505) bits), and then each block is encrypted and decrypted independently. However, such a naive method is generally insecure because equal plaintext blocks will always generate equal ciphertext blocks (for the same key), so patterns in the plaintext message become evident in the ciphertext output.[^n5]

To overcome this limitation, several so-called [block cipher modes of operation](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation) have been designed[^o36][^n6] and specified in national recommendations such as NIST 800-38A[^o38] and [BSI](https://en.wikipedia.org/wiki/Bundesamt_für_Sicherheit_in_der_Informationstechnik) TR-02102[^o39] and international standards such as [ISO/IEC 10116](https://en.wikipedia.org/wiki/ISO/IEC_10116).[^o40] The general concept is to use [randomization](wikipedia://en/65462) of the plaintext data based on an additional input value, frequently called an [initialization vector](wikipedia://en/105971), to create what is termed [probabilistic encryption](wikipedia://en/1051442).[^n7] In the popular [cipher block chaining](https://en.wikipedia.org/wiki/Cipher_block_chaining) (CBC) mode, for encryption to be [secure](wikipedia://en/960585) the initialization vector passed along with the plaintext message must be a random or [pseudo-random](https://en.wikipedia.org/wiki/Pseudo-random) value, which is added in an [exclusive-or](wikipedia://en/105979) manner to the first plaintext block before it is encrypted. The resultant ciphertext block is then used as the new initialization vector for the next plaintext block. In the [cipher feedback](https://en.wikipedia.org/wiki/Cipher_feedback) (CFB) mode, which emulates a [self-synchronizing stream cipher](wikipedia://en/49007#Self-synchronizing_stream_ciphers), the initialization vector is first encrypted and then added to the plaintext block. The [output feedback](https://en.wikipedia.org/wiki/Output_feedback) (OFB) mode repeatedly encrypts the initialization vector to create a [key stream](https://en.wikipedia.org/wiki/Key_stream) for the emulation of a [synchronous stream cipher](wikipedia://en/49007#Synchronous_stream_ciphers). The newer [counter](https://en.wikipedia.org/wiki/Counter_mode) (CTR) mode similarly creates a key stream, but has the advantage of only needing unique and not (pseudo-)random values as initialization vectors; the needed randomness is derived internally by using the initialization vector as a block counter and encrypting this counter for each block.[^o38]

From a [security-theoretic](wikipedia://en/1182348) point of view, modes of operation must provide what is known as [semantic security](wikipedia://en/960585).[^n8] Informally, it means that given some ciphertext under an unknown key one cannot practically derive any information from the ciphertext (other than the length of the message) over what one would have known without seeing the ciphertext. It has been shown that all of the modes discussed above, with the exception of the ECB mode, provide this property under so-called [chosen plaintext attacks](https://en.wikipedia.org/wiki/Chosen_plaintext_attack).

## Padding {#Padding}

Some modes such as the CBC mode only operate on complete plaintext blocks. Simply extending the last block of a message with zero bits is insufficient since it does not allow a receiver to easily distinguish messages that differ only in the number of padding bits. More importantly, such a simple solution gives rise to very efficient [padding oracle attacks](wikipedia://en/29157021).[^o44] A suitable [padding scheme](wikipedia://en/592505) is therefore needed to extend the last plaintext block to the cipher's block size. While many popular schemes described in standards and in the literature have been shown to be vulnerable to padding oracle attacks,[^o44][^o45] a solution that adds a one-bit and then extends the last block with zero-bits, standardized as "padding method 2" in ISO/IEC 9797-1,[^o46] has been proven secure against these attacks.[^o45]

## Cryptanalysis {#Cryptanalysis}

Cryptanalysis is the technique in which ciphers are decrypted without knowledge of the used key. Different attacks can be employed based on the information available to the cryptanalyst, these [attack models](wikipedia://en/3201589) are:

- *[Ciphertext-only](wikipedia://en/522938)*: the cryptanalyst has access only to a collection of [ciphertexts](wikipedia://en/175560) or [codetexts](https://en.wikipedia.org/wiki/Codetext).
- *[Known-plaintext](wikipedia://en/517019)*: the attacker has a set of ciphertexts to which they know the corresponding [plaintext](wikipedia://en/157935).
- *[Chosen-plaintext](https://en.wikipedia.org/wiki/Chosen_plaintext_attack)* (*[chosen-ciphertext](wikipedia://en/103586)*): the attacker can obtain the ciphertexts (plaintexts) corresponding to an arbitrary set of plaintexts (ciphertexts) of their own choosing.
- *[Adaptive chosen-plaintext](https://en.wikipedia.org/wiki/Adaptive_chosen_plaintext_attack)*: like a chosen-plaintext attack, except the attacker can choose subsequent plaintexts based on information learned from previous encryptions, similarly to the *[Adaptive chosen ciphertext attack](https://en.wikipedia.org/wiki/Adaptive_chosen_ciphertext_attack)*.
- *[Related-key attack](wikipedia://en/1516144)*: Like a chosen-plaintext attack, except the attacker can obtain ciphertexts encrypted under two different keys. The keys are unknown, but the relationship between them is known; for example, two keys that differ in the one bit.

### Linear cryptanalysis {#Linear_cryptanalysis}

A *linear cryptanalysis* is a form of cryptanalysis based on finding [affine](wikipedia://en/38449) approximations to the action of a [cipher](wikipedia://en/5244). Linear cryptanalysis is one of the two most widely used attacks on block ciphers; the other being [differential cryptanalysis](wikipedia://en/8536).[^o53]

The discovery is attributed to [Mitsuru Matsui](https://en.wikipedia.org/wiki/Mitsuru_Matsui), who first applied the technique to the [FEAL](wikipedia://en/592532) cipher (Matsui and Yamagishi, 1992).[^o54]

### Integral cryptanalysis {#Integral_cryptanalysis}

*Integral cryptanalysis* is a cryptanalytic attack that is particularly applicable to block ciphers based on substitution–permutation networks. Unlike differential cryptanalysis, which uses pairs of chosen plaintexts with a fixed XOR difference, integral cryptanalysis uses sets or even multisets of chosen plaintexts of which part is held constant and another part varies through all possibilities. For example, an attack might use 256 chosen plaintexts that have all but 8 of their bits the same, but all differ in those 8 bits. Such a set necessarily has an XOR sum of 0, and the XOR sums of the corresponding sets of ciphertexts provide information about the cipher's operation. This contrast between the differences between pairs of texts and the sums of larger sets of texts inspired the name "integral cryptanalysis", borrowing the terminology of calculus.

### Other techniques {#Other_techniques}

*Image: Attaque boomerang.png.* The development of the [boomerang attack](wikipedia://en/2137332) enabled [differential cryptanalysis](wikipedia://en/8536) techniques to be applied to many ciphers that had previously been deemed secure against differential attacks.

In addition to linear and differential cryptanalysis, there is a growing catalog of attacks: [truncated differential cryptanalysis](wikipedia://en/9506236), partial differential cryptanalysis, [integral cryptanalysis](wikipedia://en/7210758), which encompasses square and integral attacks, [slide attacks](wikipedia://en/1821327), [boomerang attacks](wikipedia://en/2137332), the [XSL attack](wikipedia://en/660941), [impossible differential cryptanalysis](wikipedia://en/3329225), and algebraic attacks. For a new block cipher design to have any credibility, it must demonstrate evidence of security against known attacks.[^o57]

## Provable security {#Provable_security}

When a block cipher is used in a given [mode of operation](wikipedia://en/160202), the resulting algorithm should ideally be about as secure as the block cipher itself. ECB (discussed above) emphatically lacks this property: regardless of how secure the underlying block cipher is, ECB mode can easily be attacked. On the other hand, CBC mode can be proven to be secure under the assumption that the underlying block cipher is likewise secure. Note, however, that making statements like this requires formal mathematical definitions for what it means for an encryption algorithm or a block cipher to "be secure". This section describes two common notions for what properties a block cipher should have. Each corresponds to a mathematical model that can be used to prove properties of higher-level algorithms, such as CBC.

This general approach to cryptography – proving higher-level algorithms (such as CBC) are secure under explicitly stated assumptions regarding their components (such as a block cipher) – is known as *provable security*.

### Standard model {#Standard_model}

Informally, a block cipher is secure in the standard model if an attacker cannot tell the difference between the block cipher (equipped with a random key) and a random permutation.

To be a bit more precise, let *E* be an *n*-bit block cipher. We imagine the following game:

1. The person running the game flips a coin.
   - If the coin lands on heads, he chooses a random key *K* and defines the function *f* = *E*<sub>*K*</sub>.
   - If the coin lands on tails, he chooses a random permutation $\pi$ on the set of *n*-bit strings and defines the function *f* = $\pi$.
1. The attacker chooses an *n*-bit string *X*, and the person running the game tells him the value of *f*(*X*).
1. Step 2 is repeated a total of *q* times. (Each of these *q* interactions is a *query*.)
1. The attacker guesses how the coin landed. He wins if his guess is correct.

The attacker, which we can model as an algorithm, is called an *[adversary](wikipedia://en/789126)*. The function *f* (which the adversary was able to query) is called an *[oracle](wikipedia://en/22431)*.

Note that an adversary can trivially ensure a 50% chance of winning simply by guessing at random (or even by, for example, always guessing "heads"). Therefore, let *P*<sub>*E*</sub>(*A*) denote the probability that adversary *A* wins this game against *E*, and define the *advantage* of *A* as 2(*P*<sub>*E*</sub>(*A*) − 1/2). It follows that if *A* guesses randomly, its advantage will be 0; on the other hand, if *A* always wins, then its advantage is 1. The block cipher *E* is a *pseudo-random permutation* (PRP) if no adversary has an advantage significantly greater than 0, given specified restrictions on *q* and the adversary's running time. If in Step 2 above adversaries have the option of learning *f*<sup>−1</sup>(*X*) instead of *f*(*X*) (but still have only small advantages) then *E* is a *strong* PRP (SPRP). An adversary is *non-adaptive* if it chooses all *q* values for *X* before the game begins (that is, it does not use any information gleaned from previous queries to choose each *X* as it goes).

These definitions have proven useful for analyzing various modes of operation. For example, one can define a similar game for measuring the security of a block cipher-based encryption algorithm, and then try to show (through a [reduction argument](wikipedia://en/848067)) that the probability of an adversary winning this new game is not much more than *P*<sub>*E*</sub>(*A*) for some *A*. (The reduction typically provides limits on *q* and the running time of *A*.) Equivalently, if *P*<sub>*E*</sub>(*A*) is small for all relevant *A*, then no attacker has a significant probability of winning the new game. This formalizes the idea that the higher-level algorithm inherits the block cipher's security.

## Practical evaluation {#Practical_evaluation}

Block ciphers may be evaluated according to multiple criteria in practice. Common factors include:[^n9][^o63]

- Key parameters, such as its key size and block size, both of which provide an upper bound on the security of the cipher.
- The *estimated security level*, which is based on the confidence gained in the block cipher design after it has largely withstood major efforts in cryptanalysis over time, the design's mathematical soundness, and the existence of practical or certificational[^o64] attacks.
- The cipher's *complexity* and its suitability for implementation in [hardware](https://en.wikipedia.org/wiki/Electronic_hardware) or [software](https://en.wikipedia.org/wiki/Software). Hardware implementations may measure the complexity in terms of [gate count](https://en.wikipedia.org/wiki/Gate_count) or energy consumption, which are important parameters for resource-constrained devices.
- The cipher's *performance* in terms of processing [throughput](https://en.wikipedia.org/wiki/Throughput) on various platforms, including its [memory](https://en.wikipedia.org/wiki/Computer_memory) requirements.
- The *cost* of the cipher refers to licensing requirements that may apply due to [intellectual property rights](https://en.wikipedia.org/wiki/Intellectual_property_right).
- The *flexibility* of the cipher includes its ability to support multiple key sizes and block lengths.

## Notable block ciphers {#Notable_block_ciphers}

### Lucifer / DES {#Lucifer_/_DES}

[Lucifer](wikipedia://en/364242) is generally considered to be the first civilian block cipher, developed at [IBM](https://en.wikipedia.org/wiki/IBM) in the 1970s based on work done by [Horst Feistel](wikipedia://en/530509). A revised version of the algorithm was adopted as a U.S. government [Federal Information Processing Standard](https://en.wikipedia.org/wiki/Federal_Information_Processing_Standard): FIPS PUB 46 [Data Encryption Standard](wikipedia://en/7978) (DES).[^o67] It was chosen by the U.S. National Bureau of Standards (NBS) after a public invitation for submissions and some internal changes by [NBS](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) (and, potentially, the [NSA](https://en.wikipedia.org/wiki/NSA)). DES was publicly released in 1976 and has been widely used.

DES was designed to, among other things, resist a certain cryptanalytic attack known to the NSA and rediscovered by IBM, though unknown publicly until rediscovered again and published by [Eli Biham](wikipedia://en/348920) and [Adi Shamir](wikipedia://en/57314) in the late 1980s. The technique is called [differential cryptanalysis](wikipedia://en/8536) and remains one of the few general attacks against block ciphers; [linear cryptanalysis](wikipedia://en/59469) is another but may have been unknown even to the NSA, prior to its publication by [Mitsuru Matsui](https://en.wikipedia.org/wiki/Mitsuru_Matsui). DES prompted a large amount of other work and publications in cryptography and [cryptanalysis](wikipedia://en/5715) in the open community and it inspired many new cipher designs.

DES has a block size of 64 bits and a [key size](wikipedia://en/5749) of 56 bits. 64-bit blocks became common in block cipher designs after DES. Key length depended on several factors, including government regulation. Many observers in the 1970s commented that the 56-bit key length used for DES was too short. As time went on, its inadequacy became apparent, especially after a [special-purpose machine designed to break DES](wikipedia://en/839358) was demonstrated in 1998 by the [Electronic Frontier Foundation](https://en.wikipedia.org/wiki/Electronic_Frontier_Foundation). An extension to DES, [Triple DES](wikipedia://en/48375), triple-encrypts each block with either two independent keys (112-bit key and 80-bit security) or three independent keys (168-bit key and 112-bit security). It was widely adopted as a replacement. As of 2011, the three-key version is still considered secure, though the [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) (NIST) standards no longer permit the use of the two-key version in new applications, due to its 80-bit security level.[^o68]

### IDEA {#IDEA}

The *[International Data Encryption Algorithm](wikipedia://en/15076)* (*IDEA*) is a block cipher designed by [James Massey](wikipedia://en/9543907) of [ETH Zurich](https://en.wikipedia.org/wiki/ETH_Zurich) and [Xuejia Lai](wikipedia://en/10016061); it was first described in 1991, as an intended replacement for DES.

IDEA operates on 64-bit [blocks](wikipedia://en/294065) using a 128-bit key and consists of a series of eight identical transformations (a *round*) and an output transformation (the *half-round*). The processes for encryption and decryption are similar. IDEA derives much of its security by interleaving operations from different [groups](wikipedia://en/19447) – [modular](wikipedia://en/20087) addition and multiplication, and bitwise *[exclusive or](wikipedia://en/105979) (XOR)* – which are algebraically "incompatible" in some sense.

The designers analysed IDEA to measure its strength against [differential cryptanalysis](wikipedia://en/8536) and concluded that it is immune under certain assumptions. No successful [linear](wikipedia://en/59469) or algebraic weaknesses have been reported. , the best attack which applies to all keys can break a full 8.5-round IDEA using a narrow-bicliques attack about four times faster than brute force.

### RC5 {#RC5}

*Image: RC5 InfoBox Diagram.svg.* One round (two half-rounds) of the RC5 block cipher

RC5 is a block cipher designed by [Ronald Rivest](https://en.wikipedia.org/wiki/Ron_Rivest) in 1994 which, unlike many other ciphers, has a variable block size (32, 64, or 128 bits), key size (0 to 2040 bits), and a number of rounds (0 to 255). The original suggested choice of parameters was a block size of 64 bits, a 128-bit key, and 12 rounds.

A key feature of RC5 is the use of data-dependent rotations; one of the goals of RC5 was to prompt the study and evaluation of such operations as a cryptographic primitive. RC5 also consists of a number of [modular](wikipedia://en/20087) additions and XORs. The general structure of the algorithm is a [Feistel](wikipedia://en/352709)-like a network. The encryption and decryption routines can be specified in a few lines of code. The key schedule, however, is more complex, expanding the key using an essentially [one-way function](wikipedia://en/363890) with the binary expansions of both [e](wikipedia://en/9633) and the [golden ratio](wikipedia://en/12386) as sources of "[nothing up my sleeve numbers](https://en.wikipedia.org/wiki/Nothing_up_my_sleeve_number)". The tantalizing simplicity of the algorithm together with the novelty of the data-dependent rotations has made RC5 an attractive object of study for cryptanalysts.

12-round RC5 (with 64-bit blocks) is susceptible to a [differential attack](wikipedia://en/8536) using 2<sup>44</sup> chosen plaintexts.[^o71] 18–20 rounds are suggested as sufficient protection.

### Rijndael / AES {#Rijndael_/_AES}

The *Rijndael* cipher developed by Belgian cryptographers, [Joan Daemen](https://en.wikipedia.org/wiki/Joan_Daemen) and [Vincent Rijmen](https://en.wikipedia.org/wiki/Vincent_Rijmen) was one of the competing designs to replace DES. It won the [5-year public competition](wikipedia://en/99431) to become the AES (Advanced Encryption Standard).

Adopted by NIST in 2001, AES has a fixed block size of 128 bits and a key size of 128, 192, or 256 bits, whereas Rijndael can be specified with block and key sizes in any multiple of 32 bits, with a minimum of 128 bits. The block size has a maximum of 256 bits, but the key size has no theoretical maximum. AES operates on a 4×4 [column-major order](https://en.wikipedia.org/wiki/Column-major_order) matrix of bytes, termed the *state* (versions of Rijndael with a larger block size have additional columns in the state).

### Blowfish {#Blowfish}

*[Blowfish](wikipedia://en/3940)* is a block cipher, designed in 1993 by [Bruce Schneier](wikipedia://en/36732) and included in a large number of cipher suites and encryption products. Blowfish has a 64-bit block size and a variable [key length](https://en.wikipedia.org/wiki/Key_length) from 1 bit up to 448 bits.[^o74] It is a 16-round [Feistel cipher](wikipedia://en/352709) and uses large key-dependent [S-boxes](https://en.wikipedia.org/wiki/Substitution_box). Notable features of the design include the key-dependent [S-boxes](wikipedia://en/240991) and a highly complex [key schedule](wikipedia://en/609603).

It was designed as a general-purpose algorithm, intended as an alternative to the aging DES and free of the problems and constraints associated with other algorithms. At the time Blowfish was released, many other designs were proprietary, encumbered by [patents](https://en.wikipedia.org/wiki/Patent), or were commercial/government secrets. Schneier has stated that "Blowfish is unpatented, and will remain so in all countries. The algorithm is hereby placed in the [public domain](https://en.wikipedia.org/wiki/Public_domain), and can be freely used by anyone." The same applies to [Twofish](wikipedia://en/26508356), a successor algorithm from Schneier.

### Tweakable block ciphers {#Tweakable_block_ciphers}

M. Liskov, R. Rivest, and D. Wagner have described a generalized version of block ciphers called "tweakable" block ciphers.[^o80] A tweakable block cipher accepts a second input called the *tweak* along with its usual plaintext or ciphertext input. The tweak, along with the key, selects the permutation computed by the cipher. If changing tweaks is sufficiently lightweight (compared with a usually fairly expensive key setup operation), then some interesting new operation modes become possible. The [disk encryption theory](wikipedia://en/3395256) article describes some of these modes.

:::

### Format-preserving encryption {#Format-preserving_encryption}

Block ciphers traditionally work over a binary [alphabet](https://en.wikipedia.org/wiki/Alphabet_%28computer_science%29). That is, both the input and the output are binary strings, consisting of *n* zeroes and ones. In some situations, however, one may wish to have a block cipher that works over some other alphabet; for example, encrypting 16-digit credit card numbers in such a way that the ciphertext is also a 16-digit number might facilitate adding an encryption layer to legacy software. This is an example of *format-preserving encryption*. More generally, format-preserving encryption requires a keyed permutation on some finite [language](wikipedia://en/10939). This makes format-preserving encryption schemes a natural generalization of (tweakable) block ciphers. In contrast, traditional encryption schemes, such as CBC, are not permutations because the same plaintext can encrypt multiple different ciphertexts, even when using a fixed key.

:::

## Relation to other cryptographic primitives {#Relation_to_other_cryptographic_primitives}

Block ciphers can be used to build other cryptographic primitives, such as those below. For these other primitives to be cryptographically secure, care has to be taken to build them the right way.

- [Stream ciphers](wikipedia://en/49007) can be built using block ciphers. OFB mode and CTR mode are block modes that turn a block cipher into a stream cipher.
- [Cryptographic hash functions](wikipedia://en/439526) can be built using block ciphers.[^o83][^n10] See the [one-way compression function](wikipedia://en/3851622) for descriptions of several such methods. The methods resemble the block cipher modes of operation usually used for encryption.
- [Cryptographically secure pseudorandom number generators](wikipedia://en/182249) (CSPRNGs) can be built using block ciphers.[^o85][^n11]
- Secure [pseudorandom permutations](wikipedia://en/4681949) of arbitrarily sized finite sets can be constructed with block ciphers; see [Format-Preserving Encryption](https://en.wikipedia.org/wiki/Format-Preserving_Encryption).
- A publicly known [unpredictable permutation](https://en.wikipedia.org/wiki/Unpredictable_permutation) combined with key whitening is enough to construct a block cipher -- such as the single-key [Even–Mansour cipher](https://en.wikipedia.org/wiki/Even–Mansour_cipher), perhaps the simplest possible provably secure block cipher.[^o87]
- [Message authentication codes](wikipedia://en/567523) (MACs) are often built from block ciphers. [CBC-MAC](wikipedia://en/2840574), [OMAC](wikipedia://en/567548), and [PMAC](wikipedia://en/8667910) are such MACs.
- [Authenticated encryption](wikipedia://en/2244296) is also built from block ciphers. It means to both encrypt and MAC at the same time. That is to both provide [confidentiality](wikipedia://en/353859) and [authentication](wikipedia://en/47967). [CCM](wikipedia://en/2244043), [EAX](wikipedia://en/4260161), [GCM](wikipedia://en/5897139), and [OCB](wikipedia://en/2233546) are such authenticated encryption modes.

Just as block ciphers can be used to build hash functions, like SHA-1 and SHA-2 are based on block ciphers which are also used independently as [SHACAL](wikipedia://en/877495), hash functions can be used to build block ciphers. Examples of such block ciphers are [BEAR and LION](wikipedia://en/13653678).
