# Digital data

*Image: Radiocontrolledclock.jpg.* [Digital clock](https://en.wikipedia.org/wiki/Digital_clock). The time shown by the digits on the face at any instant is digital data. The actual precise time is analog data.

::: {#o1 .subject cue=lead name="Digital data"}

**Digital data** or **digital information**, in [information theory](wikipedia://en/14773) and [information systems](https://en.wikipedia.org/wiki/Information_systems), is [data](https://en.wikipedia.org/wiki/Data) or [information](wikipedia://en/18985062) represented as a string of [discrete](wikipedia://en/8492) symbols, each of which can take on one of only a finite number of values from some [alphabet](wikipedia://en/4292269), such as letters or digits. An example is a [text document](https://en.wikipedia.org/wiki/Text_document), which consists of a string of [alphanumeric characters](https://en.wikipedia.org/wiki/Alphanumeric_character). The most common form of digital data in modern information systems is *[binary data](https://en.wikipedia.org/wiki/Binary_data)*, which is represented by a string of [binary digits](https://en.wikipedia.org/wiki/Binary_digit) (bits) each of which can have one of two values, either 0 or 1.

:::

Digital data can be contrasted with *analog data*, which is represented by a value from a [continuous](https://en.wikipedia.org/wiki/Continuous_variable) range of [real numbers](wikipedia://en/20646438). Analog data is transmitted by an [analog signal](https://en.wikipedia.org/wiki/Analog_signal), which not only takes on continuous values but can vary continuously with time, a continuous [real-valued function](wikipedia://en/22284647) of time. An example is the air pressure variation in a [sound wave](https://en.wikipedia.org/wiki/Sound_wave).

Data requires [interpretation](wikipedia://en/14511671) to become [information](wikipedia://en/18985062). In modern (post-1960) computer systems, all data is digital. Digital data also serves as the main input for [data science](wikipedia://en/35458904), where data is [collected](wikipedia://en/11501746), [processed](https://en.wikipedia.org/wiki/Data_processing), [analyzed](wikipedia://en/2720954), and [modeled](https://en.wikipedia.org/wiki/Data_modeling) using methods from [statistics](wikipedia://en/26685), [computer science](https://en.wikipedia.org/wiki/Computer_science) and [machine learning](wikipedia://en/233488) for [pattern recognition](wikipedia://en/126706) and support [decision-making](https://en.wikipedia.org/wiki/Decision-making).

The word *digital* comes from the same source as the words [digit](https://en.wikipedia.org/wiki/Digit_%28anatomy%29) and *digitus* (the [Latin](https://en.wikipedia.org/wiki/Latin) word for *finger*), as fingers are often used for counting. Mathematician [George Stibitz](https://en.wikipedia.org/wiki/George_Stibitz) of [Bell Telephone Laboratories](https://en.wikipedia.org/wiki/Bell_Telephone_Laboratories) used the word *digital* in reference to the fast electrical pulses emitted by a device designed to aim and fire anti-aircraft guns in 1942.[^o2] The term is most commonly used in [computing](https://en.wikipedia.org/wiki/Computing) and [electronics](https://en.wikipedia.org/wiki/Electronics), especially where real-world information is converted to [binary](https://en.wikipedia.org/wiki/Binary_numeral_system) numeric form as in [digital audio](https://en.wikipedia.org/wiki/Digital_audio) and [digital photography](https://en.wikipedia.org/wiki/Digital_photography).

## Symbol to digital conversion {#Symbol_to_digital_conversion}

Since symbols (for example, [alphanumeric](https://en.wikipedia.org/wiki/Alphanumeric) [characters](https://en.wikipedia.org/wiki/Character_%28computing%29)) are not continuous, representing symbols digitally is rather simpler than conversion of continuous or analog information to digital. Instead of [sampling](https://en.wikipedia.org/wiki/Sampling_%28signal_processing%29) and [quantization](wikipedia://en/317018) as in [analog-to-digital conversion](https://en.wikipedia.org/wiki/Analog-to-digital_conversion), such techniques as [polling](https://en.wikipedia.org/wiki/Polling_%28computer_science%29) and [encoding](https://en.wikipedia.org/wiki/Character_encoding) are used.

A symbol input device usually consists of a group of switches that are polled at regular intervals to see which switches are switched. Data will be lost if, within a single polling interval, two switches are pressed, or a switch is pressed, released, and pressed again. This polling can be done by a specialized processor in the device to prevent burdening the main [CPU](https://en.wikipedia.org/wiki/CPU).[^o4] When a new symbol has been entered, the device typically sends an [interrupt](https://en.wikipedia.org/wiki/Interrupt), in a specialized format, so that the CPU can read it.

For devices with only a few switches (such as the buttons on a [joystick](https://en.wikipedia.org/wiki/Joystick)), the status of each can be encoded as bits (usually 0 for released and 1 for pressed) in a single word. This is useful when combinations of key presses are meaningful, and is sometimes used for passing the status of modifier keys on a keyboard (such as shift and control). But it does not scale to support more keys than the number of bits in a single byte or word.

Devices with many switches (such as a [computer keyboard](https://en.wikipedia.org/wiki/Computer_keyboard)) usually arrange these switches in a scan matrix, with the individual switches on the intersections of x and y lines. When a switch is pressed, it connects the corresponding x and y lines together. Polling (often called scanning in this case) is done by activating each x line in sequence and detecting which y lines then have a [signal](https://en.wikipedia.org/wiki/Digital_signal), thus which keys are pressed. When the keyboard processor detects that a key has changed state, it sends a signal to the CPU indicating the scan code of the key and its new state. The symbol is then [encoded](https://en.wikipedia.org/wiki/Encoded) or converted into a number based on the status of modifier keys and the desired [character encoding](https://en.wikipedia.org/wiki/Character_encoding).

A custom [encoding](https://en.wikipedia.org/wiki/Character_encoding) can be used for a specific application with no loss of data. However, using a standard encoding such as [ASCII](https://en.wikipedia.org/wiki/ASCII) is problematic if a symbol such as 'ß' needs to be converted but is not in the standard.

It is estimated that in the year 1986, less than 1% of the world's technological capacity to store information was digital and in 2007 it was already 94%.[^o5] The year 2002 is assumed to be the year when humankind was able to store more information in digital than in analog format (the "beginning of the [digital age](https://en.wikipedia.org/wiki/Digital_age)").[^o6][^o61]

## States {#States}

*Image: 3 states of data.jpg.* The 3 states of data.

Digital data come in these three states: [data at rest](https://en.wikipedia.org/wiki/Data_at_rest), [data in transit](https://en.wikipedia.org/wiki/Data_in_transit), and [data in use](https://en.wikipedia.org/wiki/Data_in_use).[^o8][^o9] The [confidentiality, integrity, and availability](https://en.wikipedia.org/wiki/CIA_Triad) have to be managed during the entire lifecycle from 'birth' to the destruction of the data.[^o10]

::: {#o12 .pointer-item cue=pointer name="DARP"}

### Data at rest {#Data_at_rest}

*Image: DAR v DIU.JPG.* Data at Rest vs Data in Use.

**Data at rest** in [information technology](https://en.wikipedia.org/wiki/Information_technology) means data that is housed physically on [computer data storage](https://en.wikipedia.org/wiki/Computer_data_storage) in any digital form (e.g. [cloud storage](https://en.wikipedia.org/wiki/Cloud_storage), [file hosting services](https://en.wikipedia.org/wiki/File_hosting_service), [databases](https://en.wikipedia.org/wiki/Database), [data warehouses](https://en.wikipedia.org/wiki/Data_warehouse), [spreadsheets](https://en.wikipedia.org/wiki/Spreadsheet), archives, tapes, off-site or cloud backups, [mobile devices](https://en.wikipedia.org/wiki/Mobile_device) etc.). Data at rest includes both structured and [unstructured data](https://en.wikipedia.org/wiki/Unstructured_data).[^o13] This type of data is subject to threats from hackers and other malicious threats to gain access to the data digitally or physical theft of the data storage media. To prevent this data from being accessed, modified or stolen, organizations will often employ security protection measures such as password protection, data encryption, or a combination of both. The security options used for this type of data are broadly referred to as **data-at-rest protection** (**DARP**).[^o14]

Definitions include:

> "...all data in computer storage while excluding data that is traversing a network or temporarily residing in computer memory to be read or updated."[^o15]

> "...all data in storage but excludes any data that frequently traverses the network or that which resides in temporary memory. Data at rest includes but is not limited to archived data, data which is not accessed or changed frequently, files stored on hard drives, USB thumb drives, files stored on backup tape and disks, and also files stored off-site or on a [storage area network](https://en.wikipedia.org/wiki/Storage_area_network) (SAN)."[^o16]

While it is generally accepted that archive data (i.e., which never changes), regardless of its storage medium, is data at rest and active data subject to constant or frequent change is data in use. “Inactive data” could be taken to mean data which may change, but infrequently. The imprecise nature of terms such as “constant” and “frequent” means that some stored data cannot be comprehensively defined as either data at rest or in use. These definitions could be taken to assume that Data at Rest is a superset of data in use; however, data in use, subject to frequent change, has distinct processing requirements from data at rest, whether completely static or subject to occasional change.

#### Security {#Security}

Because of its nature data at rest is of increasing concern to businesses, government agencies and other institutions.[^o15] Mobile devices are often subject to specific security protocols to protect data at rest from unauthorized access when lost or stolen[^o18] and there is an increasing recognition that database management systems and file servers should also be considered as at risk;[^o19] the longer data is left unused in storage, the more likely it might be retrieved by unauthorized individuals outside the network.

[Data encryption](https://en.wikipedia.org/wiki/Data_encryption), which prevents data visibility in the event of its unauthorized access or theft, is commonly used to protect data in motion and increasingly promoted for protecting data at rest.[^o20] The encryption of data at rest should only include strong encryption methods such as [AES](wikipedia://en/1260) or [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29). Encrypted data should remain encrypted when access controls such as usernames and passwords fail. Increasing encryption on multiple levels is recommended. [Cryptography](wikipedia://en/18934432) can be implemented on the database housing the data and on the physical storage where the databases are stored. Data encryption keys should be updated on a regular basis. Encryption keys should be stored separately from the data. Encryption also enables [crypto-shredding](wikipedia://en/53764660) at the end of the data or hardware lifecycle. Periodic auditing of sensitive data should be part of policy and should occur on scheduled occurrences. Finally, only store the minimum possible amount of sensitive data.[^o21]

[Tokenization](https://en.wikipedia.org/wiki/Tokenization_%28data_security%29) is a non-mathematical approach to protecting data at rest that replaces sensitive data with non-sensitive substitutes, referred to as tokens, which have no extrinsic or exploitable meaning or value. This process does not alter the type or length of data, which means it can be processed by legacy systems such as databases that may be sensitive to data length and type. Tokens require significantly less computational resources to process and less storage space in databases than traditionally encrypted data. This is achieved by keeping specific data fully or partially visible for processing and analytics while sensitive information is kept hidden. Lower processing and storage requirements make tokenization an ideal method of securing data at rest in systems that manage large volumes of data.

A further method of preventing unwanted access to data at rest is the use of data federation[^o22] especially when data is distributed globally (e.g., in offshore archives). An example of this would be a European organisation which stores its archived data off-site in the US. Under the terms of the [USA PATRIOT Act](https://en.wikipedia.org/wiki/USA_PATRIOT_Act)[^o23] the American authorities can demand access to all data physically stored within its boundaries, even if it includes personal information on European citizens with no connections to the US. Data encryption alone cannot be used to prevent this as the authorities have the right to demand decrypted information. A data federation policy which retains personal citizen information with no foreign connections within its country of origin (separate from information which is either not personal or is relevant to offshore authorities) is one option to address this concern. However, data stored in foreign countries can be accessed using legislation in the [CLOUD Act](https://en.wikipedia.org/wiki/CLOUD_Act).

:::

### Data in use {#Data_in_use}

**Data in use** is an [information technology](https://en.wikipedia.org/wiki/Information_technology) term referring to active [data](https://en.wikipedia.org/wiki/Data) which is stored in a non-persistent digital state or [volatile memory](https://en.wikipedia.org/wiki/Volatile_memory), typically in computer [random-access memory](https://en.wikipedia.org/wiki/Random-access_memory) (RAM), [CPU caches](https://en.wikipedia.org/wiki/CPU_cache), or [CPU registers](https://en.wikipedia.org/wiki/CPU_register).[^o30]

*Data in use* has also been taken to mean “active data” in the context of being in a database or being manipulated by an application. For example, some [enterprise encryption gateway](https://en.wikipedia.org/wiki/Enterprise_encryption_gateway) solutions for the cloud claim to encrypt data at rest, [data in transit](https://en.wikipedia.org/wiki/Data_in_transit) and [data in use](https://en.wikipedia.org/wiki/Data_in_use).[^o26]

Some cloud [software as a service](https://en.wikipedia.org/wiki/Software_as_a_service) (SaaS) providers refer to data in use as any data currently being processed by applications, as the CPU and memory are utilized.[^o27]

#### Security {#Security}

Because of its nature, data in use is of increasing concern to businesses, government agencies and other institutions. Data in use, or memory, can contain sensitive data including digital certificates, encryption keys, intellectual property (software algorithms, design data), and [personally identifiable information](https://en.wikipedia.org/wiki/Personally_identifiable_information). Compromising data in use enables access to encrypted data at rest and data in motion. For example, someone with access to random access memory can parse that memory to locate the encryption key for data at rest. Once they have obtained that encryption key, they can decrypt encrypted data at rest. Threats to data in use can come in the form of [cold boot attacks](wikipedia://en/15893148), malicious hardware devices, [rootkits](https://en.wikipedia.org/wiki/Rootkit) and bootkits.

Encryption, which prevents data visibility in the event of its unauthorized access or theft, is commonly used to protect Data in Motion and Data at Rest and increasingly recognized as an optimal method for protecting Data in Use. There have been multiple projects to encrypt memory. Microsoft [Xbox](https://en.wikipedia.org/wiki/Xbox) systems are designed to provide memory encryption and the company [PrivateCore](https://en.wikipedia.org/wiki/PrivateCore) presently has a commercial software product vCage to provide attestation along with full memory encryption for x86 servers.[^o29] Several papers have been published highlighting the availability of security-enhanced x86 and ARM commodity processors.[^o30][^o31] In that work, an [ARM Cortex-A8](https://en.wikipedia.org/wiki/ARM_Cortex-A8) processor is used as the substrate on which a full memory encryption solution is built. Process segments (for example, stack, code or heap) can be encrypted individually or in composition. This work marks the first full memory encryption implementation on a mobile general-purpose commodity processor. The system provides both confidentiality and integrity protections of code and data, which are encrypted everywhere outside the CPU boundary.

For x86 systems, AMD has a Secure Memory Encryption (SME) feature introduced in 2017 with [Epyc](https://en.wikipedia.org/wiki/Epyc).[^o32] Intel has promised to deliver its Total Memory Encryption (TME) feature in an upcoming CPU.[^o33][^o34]

Operating system kernel patches such as [TRESOR](wikipedia://en/33994571) and Loop-Amnesia modify the operating system so that CPU registers can be used to store encryption keys and avoid holding encryption keys in RAM. While this approach is not general purpose and does not protect all data in use, it does protect against cold boot attacks. Encryption keys are held inside the CPU rather than in RAM so that data at rest encryption keys are protected against attacks that might compromise encryption keys in memory.

Enclaves enable an “enclave” to be secured with encryption in RAM so that enclave data is encrypted while in RAM but available as clear text inside the CPU and CPU cache. Intel Corporation has introduced the concept of “enclaves” as part of its [Software Guard Extensions](https://en.wikipedia.org/wiki/Software_Guard_Extensions). Intel revealed an architecture combining software and CPU hardware in technical papers published in 2013.[^o35]

Several cryptographic tools, including [secure multi-party computation](wikipedia://en/646233) and [homomorphic encryption](wikipedia://en/4939073), allow for the private computation of data on untrusted systems. Data in use could be operated upon while encrypted and never exposed to the system doing the processing.

:::

### Data in transit {#Data_in_transit}

**Data in transit**, also referred to as **data in motion**[^o38] and **data in flight**,[^o39] is data en route between source and destination, typically on a [computer network](https://en.wikipedia.org/wiki/Computer_network).

Data in transit can be separated into two categories: information that flows over the public or untrusted network such as the Internet and data that flows in the confines of a private network such as a corporate or enterprise [local area network](https://en.wikipedia.org/wiki/Local_area_network) (LAN).[^o40]

## In computing {#In_computing}

Data within a computer, in most cases, [moves as parallel data](https://en.wikipedia.org/wiki/Parallel_communication). Data moving to or from a computer, in most cases, [moves as serial data](https://en.wikipedia.org/wiki/Serial_communication). Data sourced from an analog device, such as a temperature sensor, may be converted to digital using an [analog-to-digital converter](https://en.wikipedia.org/wiki/Analog-to-digital_converter). Data representing [quantities](https://en.wikipedia.org/wiki/Quantities), characters, or symbols on which operations are performed by a [computer](https://en.wikipedia.org/wiki/Computer) are [stored](wikipedia://en/28174) and [recorded](https://en.wikipedia.org/wiki/Record_%28computer_science%29) on [magnetic](https://en.wikipedia.org/wiki/Magnetic_tape_data_storage), [optical](https://en.wikipedia.org/wiki/Optical_storage), electronic, or mechanical recording media, and [transmitted](https://en.wikipedia.org/wiki/Data_communication) in the form of digital electrical or optical signals.[^o43] Data pass in and out of computers via [peripheral devices](https://en.wikipedia.org/wiki/Peripheral_device).

Physical [computer memory](https://en.wikipedia.org/wiki/Computer_memory) elements consist of an address and a byte/word of data storage. Digital data are often stored in [relational databases](https://en.wikipedia.org/wiki/Relational_database#RDBMS), like [tables](https://en.wikipedia.org/wiki/Table_%28database%29) or SQL databases, and can generally be represented as abstract key/value pairs. Data can be organized in many different types of [data structures](wikipedia://en/8519), including arrays, [graphs](wikipedia://en/557931), and [objects](https://en.wikipedia.org/wiki/Object_%28computer_science%29). Data structures can store data of many different [types](https://en.wikipedia.org/wiki/Data_type), including [numbers](wikipedia://en/11376), [strings](wikipedia://en/27701) and even other [data structures](https://en.wikipedia.org/wiki/Recursive_data_type).

### Characteristics {#Characteristics}

[Metadata](https://en.wikipedia.org/wiki/Metadata) helps translate data to information. Metadata is data about the data. Metadata may be implied, specified or given.

Data relating to physical events or processes will have a temporal component. This temporal component may be implied. This is the case when a device such as a temperature logger receives data from a temperature [sensor](https://en.wikipedia.org/wiki/Sensor). When the temperature is received, it is assumed that the data has a temporal reference of *now*. So the device records the date, time and temperature together. When the data logger communicates temperatures, it must also report the date and time as metadata for each temperature reading.

Fundamentally, computers follow a sequence of instructions they are given in the form of data. A set of instructions to perform a given task (or tasks) is called a *[program](https://en.wikipedia.org/wiki/Computer_program)*. A program is data in the form of coded instructions to control the operation of a computer or other machine.[^o45] In the nominal case, the program, as [executed](https://en.wikipedia.org/wiki/Execution_%28computing%29) by the computer, will consist of [machine code](https://en.wikipedia.org/wiki/Machine_code). The elements of [storage](https://en.wikipedia.org/wiki/Computer_data_storage) manipulated by the program, but not actually executed by the [central processing unit](https://en.wikipedia.org/wiki/Central_processing_unit) (CPU), are also data. At its most essential, a single datum is a [value](https://en.wikipedia.org/wiki/Value_%28computer_science%29) stored at a specific location. Therefore, it is possible for computer programs to operate on other computer programs by manipulating their programmatic data.

To store data [bytes](https://en.wikipedia.org/wiki/Byte) in a file, they have to be [serialized](https://en.wikipedia.org/wiki/Serialization) in a [file format](https://en.wikipedia.org/wiki/File_format). Typically, programs are stored in special file types, different from those used for other data. [Executable files](https://en.wikipedia.org/wiki/Executable_file) contain programs; all other files are also [data files](https://en.wikipedia.org/wiki/Data_file). However, executable files may also contain data used by the program, which is built into the program. In particular, some executable files have a [data segment](https://en.wikipedia.org/wiki/Data_segment), which nominally contains constants and initial values for variables, both of which can be considered data.

The line between program and data can become blurry. An [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29), for example, is a program. The input data to an interpreter is itself a program, just not one expressed in native [machine language](https://en.wikipedia.org/wiki/Machine_language). In many cases, the interpreted program will be a human-readable [text file](https://en.wikipedia.org/wiki/Text_file), which is manipulated with a [text editor](https://en.wikipedia.org/wiki/Text_editor) program. [Metaprogramming](https://en.wikipedia.org/wiki/Metaprogramming) similarly involves programs manipulating other programs as data. Programs like [compilers](https://en.wikipedia.org/wiki/Compiler), [linkers](https://en.wikipedia.org/wiki/Linker_%28computing%29), [debuggers](https://en.wikipedia.org/wiki/Debugger), program updaters, [virus scanners](https://en.wikipedia.org/wiki/Virus_scanner) and such use other programs as their data.

For example, a [user](https://en.wikipedia.org/wiki/User_%28computing%29) might first instruct the [operating system](https://en.wikipedia.org/wiki/Operating_system) to load a [word processor](https://en.wikipedia.org/wiki/Word_processor) program from one file, and then use the running program to open and edit a [document](https://en.wikipedia.org/wiki/Document_file_format) stored in another file. In this example, the document would be considered data. If the word processor also features a [spell checker](https://en.wikipedia.org/wiki/Spell_checker), then the dictionary (word list) for the spell checker would also be considered data. The [algorithms](wikipedia://en/775) used by the spell checker to suggest corrections would be either [machine code](https://en.wikipedia.org/wiki/Machine_code) data or text in some interpretable [programming language](wikipedia://en/23015).

In an alternate usage, [binary files](https://en.wikipedia.org/wiki/Binary_file) (which are not [human-readable](https://en.wikipedia.org/wiki/Human-readable)) are sometimes called *data* as distinguished from human-readable *[text](https://en.wikipedia.org/wiki/Text_file)*.[^o46]

The total amount of digital data in 2007 was estimated to be 281 billion [gigabytes](https://en.wikipedia.org/wiki/Gigabyte) (281 [exabytes](https://en.wikipedia.org/wiki/Exabyte)).[^o47][^o48]

### Data keys and values, structures and persistence {#Data_keys_and_values,_structures_and_persistence}

Keys in data provide the context for values. Regardless of the structure of data, there is always a key component present. Keys in data and data-structures are essential for giving meaning to data values. Without a key that is directly or indirectly associated with a value, or collection of values in a structure, the values become meaningless and cease to be data. That is to say, there has to be a key component linked to a value component in order for it to be considered data.[^o50]

Data can be represented in computers in multiple ways, as per the following examples:

#### RAM {#RAM}

[Random access memory](https://en.wikipedia.org/wiki/Random_access_memory) (RAM) holds data that the CPU has direct access to. A CPU may only manipulate data within its [processor registers](https://en.wikipedia.org/wiki/Processor_register) or memory. This is as opposed to data storage, where the CPU must direct the transfer of data between the storage device (disk, tape...) and memory. RAM is an array of linear contiguous locations that a processor may read or write by providing an address for the read or write operation. The processor may operate on any location in memory at any time in any order. In RAM, the smallest element of data is the binary [bit](https://en.wikipedia.org/wiki/Bit). The capabilities and limitations of accessing RAM are processor specific. In general [main memory](https://en.wikipedia.org/wiki/Computer_data_storage) is arranged as an array of [locations](https://en.wikipedia.org/wiki/Memory_address) beginning at address 0 ([hexadecimal](wikipedia://en/13263) 0). Each location can usually store 8 or 32 bits depending on the [computer architecture](https://en.wikipedia.org/wiki/Computer_architecture).

#### Keys {#Keys}

Data keys need not be a direct hardware address in memory. [Indirect](https://en.wikipedia.org/wiki/Indirection), abstract and logical keys codes can be stored in association with values to form a [data structure](wikipedia://en/8519). Data structures have predetermined [offsets](https://en.wikipedia.org/wiki/Offset_%28computer_science%29) (or links or paths) from the start of the structure, in which data values are stored. Therefore, the data key consists of the key to the structure plus the offset (or links or paths) into the structure. When such a structure is repeated, storing variations of the data values and the data keys within the same repeating structure, the result can be considered to resemble a [table](https://en.wikipedia.org/wiki/Table_%28information%29), in which each element of the repeating structure is considered to be a column and each repetition of the structure is considered as a row of the table. In such an organization of data, the data key is usually a value in one (or a composite of the values in several) of the columns.

#### Organised recurring data structures {#Organised_recurring_data_structures}

The [tabular](https://en.wikipedia.org/wiki/Table_%28information%29) view of repeating data structures is only one of many possibilities. Repeating data structures can be organised [hierarchically](https://en.wikipedia.org/wiki/Hierarchically), such that nodes are linked to each other in a cascade of parent-child relationships. Values and potentially more complex data-structures are linked to the nodes. Thus the nodal hierarchy provides the key for addressing the data structures associated with the nodes. This representation can be thought of as an [inverted tree](https://en.wikipedia.org/wiki/Inverted_tree). Modern computer operating system [file systems](https://en.wikipedia.org/wiki/File_system) are a common example; and [XML](https://en.wikipedia.org/wiki/XML) is another.

#### Sorted or ordered data {#Sorted_or_ordered_data}

Data has some inherent features when it is [sorted on a key](https://en.wikipedia.org/wiki/Collation). All the values for subsets of the key appear together. When passing sequentially through groups of the data with the same key, or a subset of the key changes, this is referred to in data processing circles as a break, or a [control break](https://en.wikipedia.org/wiki/Control_break). It particularly facilitates the aggregation of data values on subsets of a key.

#### Peripheral storage {#Peripheral_storage}

Until the advent of bulk [non-volatile memory](https://en.wikipedia.org/wiki/Non-volatile_memory) like [flash](https://en.wikipedia.org/wiki/Flash_memory), persistent data storage was traditionally achieved by writing the data to [external block devices like magnetic tape and disk drives](https://en.wikipedia.org/wiki/Peripheral). These devices typically seek to a location on the magnetic media and then read or write [blocks of data](https://en.wikipedia.org/wiki/Block_%28data_storage%29) of a predetermined size. In this case, the seek location on the media is the data key and the blocks are the data values. Early used *raw disk* data file-systems or disc operating systems reserved [contiguous](https://en.wikipedia.org/wiki/Fragmentation_%28computing%29) blocks on the disc drive for [data files](https://en.wikipedia.org/wiki/Data_file). In those systems, the files could be filled up, running out of data space before all the data had been written to them. Thus, much unused data space was reserved unproductively to ensure adequate free space for each file. Later file systems introduced [partitions](https://en.wikipedia.org/wiki/Partition_type). They reserved blocks of disc data space for partitions and used the allocated blocks more economically, by dynamically assigning blocks of a partition to a file as needed. To achieve this, the file system had to keep track of which blocks were used or unused by data files in a catalog or file allocation table. Though this made better use of the disc data space, it resulted in fragmentation of files across the disc, and a concomitant performance overhead due to additional seek time to read the data. Modern file systems reorganize fragmented files dynamically to optimize file access times. Further developments in file systems resulted in [virtualization](https://en.wikipedia.org/wiki/Virtualization) of disc drives i.e. where a logical drive can be defined as partitions from a number of physical drives.

#### Indexed data {#Indexed_data}

Retrieving a small subset of data from a much larger set may imply inefficiently searching through the data sequentially. **[Indexes](https://en.wikipedia.org/wiki/Database_index)** are a way to copy out keys and location addresses from data structures in files, tables and data sets, then organize them using [inverted tree structures](https://en.wikipedia.org/wiki/Tree_%28data_structure%29) to reduce the time taken to retrieve a subset of the original data. In order to do this, the key of the subset of data to be retrieved must be known before retrieval begins. The most popular indexes are the [B-tree](https://en.wikipedia.org/wiki/B-tree) and the dynamic [hash](https://en.wikipedia.org/wiki/Hash_function) key indexing methods. Indexing is overhead for filing and retrieving data. There are other ways of organizing indexes, e.g., sorting the keys and using a [binary search algorithm](https://en.wikipedia.org/wiki/Binary_search_algorithm).

#### Abstraction and indirection {#Abstraction_and_indirection}

[Object-oriented programming](https://en.wikipedia.org/wiki/Object-oriented_programming) uses two basic concepts for understanding data and software:

1. The taxonomic rank-structure of *[classes](https://en.wikipedia.org/wiki/Class_%28programming%29)*, which is an example of a hierarchical data structure; and
1. at run time, the creation of references to in-memory data structures of objects that have been [instantiated](https://en.wikipedia.org/wiki/Instance_%28computer_science%29) from a [class library](https://en.wikipedia.org/wiki/Class_library).

It is only after instantiation that an object of a specified class exists. After an object's reference is cleared, the object also ceases to exist. The memory locations where the object's data was stored are [garbage](https://en.wikipedia.org/wiki/Garbage_collection_%28computer_science%29) and are reclassified as unused memory available for reuse.

#### Database data {#Database_data}

The advent of [databases](https://en.wikipedia.org/wiki/Database) introduced a further [layer of abstraction](https://en.wikipedia.org/wiki/Layer_of_abstraction) for persistent data storage. Databases use [metadata](https://en.wikipedia.org/wiki/Metadata), and a [structured query language](https://en.wikipedia.org/wiki/Structured_query_language) protocol between [client and server](https://en.wikipedia.org/wiki/Client–server_model) systems, communicating over a [computer network](https://en.wikipedia.org/wiki/Computer_network), using a [two-phase commit](https://en.wikipedia.org/wiki/Two-phase_commit) logging system to ensure [transactional](https://en.wikipedia.org/wiki/Database_transaction) completeness when saving data.

#### Parallel distributed data processing {#Parallel_distributed_data_processing}

Modern scalable and high-performance data persistence technologies, such as [Apache Hadoop](https://en.wikipedia.org/wiki/Apache_Hadoop), rely on massively parallel distributed data processing across many commodity computers on a high bandwidth network. In such systems, the data is distributed across multiple computers and therefore any particular computer in the system must be represented in the key of the data, either directly or indirectly. This enables the differentiation between two identical sets of data, each being processed on a different computer at the same time.

## Properties of digital information {#Properties_of_digital_information}

All digital information possesses common properties that distinguish it from analog data with respect to communications:

- **Synchronization:** Since digital information is conveyed by the sequence in which symbols are ordered, all digital schemes have some method for determining the beginning of a sequence. In written or spoken human languages, synchronization is typically provided by [pauses](https://en.wikipedia.org/wiki/Pausa) (spaces), [capitalization](https://en.wikipedia.org/wiki/Capitalization), and [punctuation](https://en.wikipedia.org/wiki/Punctuation). Machine communications typically use special [synchronization sequences](https://en.wikipedia.org/wiki/Synchronization_sequence).
- **Language:** All digital communications require a *[formal language](wikipedia://en/10939)*, which in this context consists of all the information that the sender and receiver of the digital communication must both possess, in advance, for the communication to be successful. Languages are generally arbitrary and specify the meaning to be assigned to particular symbol sequences, the allowed range of values, methods to be used for synchronization, etc.
- **Errors:** Disturbances ([noise](https://en.wikipedia.org/wiki/Noise_%28signal_processing%29)) in analog communications invariably introduce some, generally small deviation or error between the intended and actual communication. Disturbances in digital communication only result in errors when the disturbance is so large as to result in a symbol being misinterpreted as another symbol or disturbing the sequence of symbols. It is generally possible to have near-error-free digital communication. Further, techniques such as check codes may be used to [detect errors and correct them](wikipedia://en/10375) through redundancy or re-transmission. Errors in digital communications can take the form of *substitution errors,* in which a symbol is replaced by another symbol, or *insertion/deletion* errors, in which an extra incorrect symbol is inserted into or deleted from a digital message. Uncorrected errors in digital communications have an unpredictable and generally large impact on the information content of the communication.
- **[Copying](https://en.wikipedia.org/wiki/Data_transmission):** Because of the inevitable presence of noise, making many successive copies of an analog communication is infeasible because each generation increases the noise. Because digital communications are generally error-free, copies of copies can be made indefinitely.
- **[Granularity](https://en.wikipedia.org/wiki/Granularity):** The digital representation of a continuously variable analog value typically involves a selection of the number of symbols to be assigned to that value. The number of symbols determines the precision or resolution of the resulting datum. The difference between the actual analog value and the digital representation is known as *[quantization error](https://en.wikipedia.org/wiki/Quantization_error)*. For example, if the actual temperature is 23.234456544453 degrees, but only two digits (23) are assigned to this parameter in a particular digital representation, the quantizing error is 0.234456544453. This property of digital communication is known as *granularity*.
- **[Compressible](wikipedia://en/8013):** According to Miller, "Uncompressed digital data is very large, and in its raw form, it would actually produce a larger signal (therefore be more difficult to transfer) than analog data. However, digital data can be compressed. Compression reduces the amount of bandwidth space needed to send information. Data can be compressed, sent, and then decompressed at the site of consumption. This makes it possible to send much more information and results in, for example, [digital television](https://en.wikipedia.org/wiki/Digital_television) signals offering more room on the airwave spectrum for more television channels."[^o61]

## Historical digital systems {#Historical_digital_systems}

Even though digital signals are generally associated with the binary electronic digital systems used in modern electronics and computing, digital systems are actually ancient, and need not be binary or electronic.

- [DNA](https://en.wikipedia.org/wiki/DNA) [genetic code](https://en.wikipedia.org/wiki/Genetic_code) is a naturally occurring form of digital data storage.
- Written text (due to the limited character set and the use of discrete symbols – the alphabet in most cases)
- The *[abacus](wikipedia://en/655)* was created sometime between 1000 BC and 500 BC; it later became a form of calculation frequency. Nowadays it can be used as a very advanced, yet basic digital calculator that uses beads on rows to represent numbers. Beads only have meaning in discrete up and down states, not in analog in-between states.
- A *[beacon](https://en.wikipedia.org/wiki/Beacon)* is perhaps the simplest non-electronic digital signal, with just two states (on and off). In particular, *[smoke signals](https://en.wikipedia.org/wiki/Smoke_signal)* are one of the oldest examples of a digital signal, where an analog "carrier" (smoke) is [modulated](https://en.wikipedia.org/wiki/Modulated) with a blanket to generate a digital signal (puffs) that conveys information.
- [Morse code](https://en.wikipedia.org/wiki/Morse_code) uses six digital states—dot, dash, intra-character gap (between each dot or dash), short gap (between each letter), medium gap (between words), and long gap (between sentences)—to send messages via a variety of potential carriers such as electricity or light, for example using an [electrical telegraph](https://en.wikipedia.org/wiki/Electrical_telegraph) or a flashing light.
- The [Braille](https://en.wikipedia.org/wiki/Braille) uses a six-bit code rendered as dot patterns.
- [Flag semaphore](https://en.wikipedia.org/wiki/Flag_semaphore) uses rods or flags held in particular positions to send messages to the receiver watching them some distance away.
- [International maritime signal flags](https://en.wikipedia.org/wiki/International_maritime_signal_flags) have distinctive markings that represent letters of the alphabet to allow ships to send messages to each other.
- More recently invented, a [modem](https://en.wikipedia.org/wiki/Modem) modulates an analog carrier signal (such as sound) to encode binary digital information, as a series of binary digital sound pulses. A slightly earlier, surprisingly reliable version of the same concept was to bundle a sequence of audio digital signal and no signal information (i.e., sound and silence) on [magnetic cassette tape](https://en.wikipedia.org/wiki/Compact_audio_cassette) for use with early [home computers](https://en.wikipedia.org/wiki/Home_computer).
