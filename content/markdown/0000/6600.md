# Currying

::: {#o1 .subject cue=lead name="Currying"}

In [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), **currying** (named after [Haskell Curry](wikipedia://en/42182)) is the technique of translating a [function](wikipedia://en/185427) that takes multiple [arguments](https://en.wikipedia.org/wiki/Parameter_%28computer_programming%29) into a sequence of families of functions, each taking a single argument.

:::

In the prototypical example, one begins with a function $f:(X\times Y)\to Z$ that takes two arguments, one from $X$ and one from $Y,$ and produces objects in $Z.$ The curried form of this function treats the first argument as a parameter, so as to create a family of functions $f_x :Y\to Z.$ The family is arranged so that for each object $x$ in $X,$ there is exactly one function $f_x$, such that for any $y$ in $Y$, $f_x(y) = f(x,y)$.

In this example, $\mbox{curry}$ itself becomes a function that takes $f$ as an argument, and returns a function that maps each $x$ to $f_x.$ The proper notation for expressing this is verbose. The function $f$ belongs to the set of functions $(X\times Y)\to Z.$ Meanwhile, $f_x$ belongs to the set of functions $Y\to Z.$ Thus, something that maps $x$ to $f_x$ will be of the type $X\to [Y\to Z].$ With this notation, $\mbox{curry}$ is a function that takes objects from the first set, and returns objects in the second set, and so one writes $\mbox{curry}:[(X\times Y)\to Z]\to (X\to [Y\to Z]).$ This is a somewhat informal example; more precise definitions of what is meant by "object" and "function" are given below. These definitions vary from context to context, and take different forms, depending on the theory that one is working in.

Currying is related to, but not the same as, [partial application](https://en.wikipedia.org/wiki/Partial_application).[^o2][^o39] The example above can be used to illustrate partial application; it is quite similar. Partial application is the function $\mbox{apply}$ that takes the pair $f$ and $x$ together as arguments, and returns $f_x.$ Using the same notation as above, partial application has the signature $\mbox{apply}:([(X\times Y)\to Z] \times X) \to [Y\to Z].$ Written this way, application can be seen to be adjoint to currying.

The currying of a function with more than two arguments can be defined by induction.

Currying is useful in both practical and theoretical settings. In [functional programming](https://en.wikipedia.org/wiki/Functional_programming) [languages](wikipedia://en/23015), and many others, it provides a way of automatically managing how arguments are passed to functions and [exceptions](https://en.wikipedia.org/wiki/Exception_handling). In [theoretical computer science](wikipedia://en/323392), it provides a way to study functions with multiple arguments in simpler theoretical models which provide only one argument. The most general setting for the strict notion of currying and uncurrying is in the [closed monoidal categories](wikipedia://en/1396924), which underpins a vast generalization of the [Curry–Howard correspondence](wikipedia://en/254299) of proofs and programs to a correspondence with many other structures, including [quantum mechanics](wikipedia://en/25202), [cobordisms](wikipedia://en/391832), and [string theory](wikipedia://en/28305).[^o37]

The concept of currying was introduced by [Gottlob Frege](wikipedia://en/48416),[^o3][^o4] developed by [Moses Schönfinkel](wikipedia://en/767234),[^o5][^o4][^o6][^o7][^o8][^o16][^o9] and further developed by [Haskell Curry](wikipedia://en/42182).[^o7][^o16][^o10][^o11]

**Uncurrying** is the [dual](wikipedia://en/609737) transformation to currying, and can be seen as a form of [defunctionalization](https://en.wikipedia.org/wiki/Defunctionalization). It takes a function $f$ whose return value is another function $g$, and yields a new function $f'$ that takes as parameters the arguments for both $f$ and $g$, and returns, as a result, the application of $f$ and subsequently, $g$, to those arguments. The process can be iterated.

## Motivation {#Motivation}

Currying provides a way for working with functions that take multiple arguments, and using them in frameworks where functions might take only one argument. For example, some analytical techniques can only be applied to [functions](wikipedia://en/185427) with a single argument. Practical functions frequently take more arguments than this. [Frege](wikipedia://en/48416) showed that it was sufficient to provide solutions for the single argument case, as it was possible to transform a function with multiple arguments into a chain of single-argument functions instead. This transformation is the process now known as currying.[^o13] All "ordinary" functions that might typically be encountered in [mathematical analysis](wikipedia://en/48396) or in [computer programming](https://en.wikipedia.org/wiki/Computer_programming) can be curried. However, there are categories in which currying is not possible; the most general categories which allow currying are the [closed monoidal categories](wikipedia://en/1396924).

Some [programming languages](wikipedia://en/23015) almost always use curried functions to achieve multiple arguments; notable examples are [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) and [Haskell](https://en.wikipedia.org/wiki/Haskell), where in both cases all functions have exactly one argument. This property is inherited from [lambda calculus](wikipedia://en/18203), where multi-argument functions are usually represented in curried form.

Currying is related to, but not the same as [partial application](https://en.wikipedia.org/wiki/Partial_application).[^o2][^o39] In practice, the programming technique of [closures](https://en.wikipedia.org/wiki/Closure_%28computer_programming%29) can be used to perform partial application and a kind of currying, by hiding arguments in an environment that travels with the curried function.

## History {#History}

The "Curry" in "Currying" is a reference to logician [Haskell Curry](wikipedia://en/42182), who used the concept extensively, but [Moses Schönfinkel](wikipedia://en/767234) had the idea six years before Curry.[^o16] The alternative name "Schönfinkelisation" has been proposed.[^o17] In the mathematical context, the principle can be traced back to work in 1893 by [Frege](wikipedia://en/48416).[^o3][^o4]

The originator of the word "currying" is not clear. [David Turner](https://en.wikipedia.org/wiki/David_Turner_%28computer_scientist%29) says the word was coined by [Christopher Strachey](https://en.wikipedia.org/wiki/Christopher_Strachey) in his 1967 lecture notes [Fundamental Concepts in Programming Languages](https://en.wikipedia.org/wiki/Fundamental_Concepts_in_Programming_Languages),[^o18] but that source introduces the concept as "a device originated by Schönfinkel", and the term "currying" is not used, while Curry is mentioned later in the context of higher-order functions.[^o6] [John C. Reynolds](https://en.wikipedia.org/wiki/John_C._Reynolds) defined "currying" in a 1972 paper, but did not claim to have coined the term.[^o7]

## Definition {#Definition}

Currying is most easily understood by starting with an informal definition, which can then be molded to fit many different domains. First, there is some notation to be established. The notation $X \to Y$ denotes all [functions](wikipedia://en/185427) from $X$ to $Y$. If $f$ is such a function, we write $f \colon X \to Y$. Let $X \times Y$ denote the [ordered pairs](wikipedia://en/22362) of the elements of $X$ and $Y$ respectively, that is, the [Cartesian product](wikipedia://en/24104095) of $X$ and $Y$. Here, $X$ and $Y$ may be sets, or they may be types, or they may be other kinds of objects, as explored below.

Given a function

$$f \colon (X \times Y) \to Z,$$

**currying** constructs a new function

$$g \colon X \to (Y \to Z).$$

That is, $g$ takes an argument of type $X$ and returns a function of type $Y\to Z$. It is defined by

$$g(x)(y)=f(x,y)$$

for $x$ of type $X$ and $y$ of type $Y$. We then also write

$$\text{curry}(f)=g.$$

**Uncurrying** is the reverse transformation, and is most easily understood in terms of its right adjoint, the [function $\operatorname{apply}.$](https://en.wikipedia.org/wiki/Apply)

### Set theory {#Set_theory}

In [set theory](wikipedia://en/27553), the notation $Y^X$ is used to denote the [set](wikipedia://en/26691) of functions from the set $X$ to the set $Y$. Currying is the [natural bijection](https://en.wikipedia.org/wiki/Natural_equivalence) between the set $A^{B\times C}$ of functions from $B\times C$ to $A$, and the set $(A^C)^B$ of functions from $B$ to the set of functions from $C$ to $A$. In symbols:

$$A^{B\times C}\cong (A^C)^B$$

Indeed, it is this natural bijection that justifies the [exponential notation](https://en.wikipedia.org/wiki/Exponential_notation) for the set of functions. As is the case in all instances of currying, the formula above describes an [adjoint pair of functors](wikipedia://en/53991): for every fixed set $C$, the functor $B\mapsto B\times C$ is left adjoint to the functor $A \mapsto A^C$.

In the [category of sets](wikipedia://en/26829), the [object](wikipedia://en/19453961) $Y^X$ is called the [exponential object](wikipedia://en/2237858).

### Function spaces {#Function_spaces}

In the theory of [function spaces](wikipedia://en/340630), such as in [functional analysis](wikipedia://en/11180) or [homotopy theory](wikipedia://en/61994831), one is commonly interested in [continuous functions](wikipedia://en/6122) between [topological spaces](wikipedia://en/30450). One writes $\text{Hom}(X,Y)$ (the [Hom functor](wikipedia://en/2741037)) for the set of *all* functions from $X$ to $Y$, and uses the notation $Y^X$ to denote the subset of continuous functions. Here, $\text{curry}$ is the [bijection](wikipedia://en/3942)

$$\text{curry}:\text{Hom}(X\times Y, Z) \to \text{Hom}(X, \text{Hom}(Y,Z)) ,$$

while uncurrying is the inverse map. If the set $Y^X$ of continuous functions from $X$ to $Y$ is given the [compact-open topology](wikipedia://en/726335), and if the space $Y$ is [locally compact Hausdorff](https://en.wikipedia.org/wiki/Locally_compact_Hausdorff), then

$$\text{curry} : Z^{X\times Y}\to (Z^Y)^X$$

is a [homeomorphism](wikipedia://en/13660). This is also the case when $X$, $Y$ and $Y^X$ are [compactly generated](wikipedia://en/899382),[^o23][^o24] although there are more cases.[^o25][^o26]

One useful corollary is that a function is continuous [if and only if](wikipedia://en/14922) its curried form is continuous. Another important result is that the [application map](https://en.wikipedia.org/wiki/Apply), usually called "evaluation" in this context, is continuous (note that [eval](https://en.wikipedia.org/wiki/Eval) is a strictly different concept in computer science.) That is,

$$\begin{aligned} &&\text{eval}:Y^X \times X \to Y \\ && (f,x) \mapsto f(x) \end{aligned}$$

is continuous when $Y^X$ is compact-open and $Y$ locally compact Hausdorff.[^o27] These two results are central for establishing the continuity of [homotopy](wikipedia://en/212250), i.e. when $X$ is the unit interval $I$, so that $Z^{I\times Y} \cong (Z^Y)^I$ can be thought of as either a homotopy of two functions from $Y$ to $Z$, or, equivalently, a single (continuous) path in $Z^Y$.

### Algebraic topology {#Algebraic_topology}

In [algebraic topology](wikipedia://en/38801), currying serves as an example of [Eckmann–Hilton duality](wikipedia://en/23191477), and, as such, plays an important role in a variety of different settings. For example, [loop space](wikipedia://en/2174332) is adjoint to [reduced suspensions](https://en.wikipedia.org/wiki/Reduced_suspension); this is commonly written as

$$[\Sigma X,Z] \approxeq [X, \Omega Z]$$

where $[A,B]$ is the set of [homotopy classes](https://en.wikipedia.org/wiki/Homotopy_class) of maps $A \rightarrow B$, and $\Sigma A$ is the [suspension](wikipedia://en/1251702) of *A*, and $\Omega A$ is the [loop space](wikipedia://en/2174332) of *A*. In essence, the suspension $\Sigma X$ can be seen as the cartesian product of $X$ with the unit interval, modulo an equivalence relation to turn the interval into a loop. The curried form then maps the space $X$ to the space of functions from loops into $Z$, that is, from $X$ into $\Omega Z$.[^o27] Then $\text{curry}$ is the [adjoint functor](https://en.wikipedia.org/wiki/Adjoint_functor) that maps suspensions to loop spaces, and uncurrying is the dual.[^o27]

The duality between the [mapping cone](wikipedia://en/1707756) and the mapping fiber ([cofibration](wikipedia://en/1697216) and [fibration](wikipedia://en/316826))[^o23] can be understood as a form of currying, which in turn leads to the duality of the [long exact](https://en.wikipedia.org/wiki/Long_exact_sequence) and coexact [Puppe sequences](wikipedia://en/4734210).

In [homological algebra](wikipedia://en/139410), the relationship between currying and uncurrying is known as [tensor-hom adjunction](https://en.wikipedia.org/wiki/Tensor-hom_adjunction). Here, an interesting twist arises: the [Hom functor](wikipedia://en/2741037) and the [tensor product](wikipedia://en/30844) functor might not [lift](wikipedia://en/10504570) to an [exact sequence](wikipedia://en/138215); this leads to the definition of the [Ext functor](wikipedia://en/840758) and the [Tor functor](wikipedia://en/856347).

### Domain theory {#Domain_theory}

In [order theory](wikipedia://en/361924), the theory of [lattices](wikipedia://en/469304) of [partially ordered sets](wikipedia://en/23572), $\text{curry}$ is a [continuous function](wikipedia://en/6122) when the lattice is given the [Scott topology](https://en.wikipedia.org/wiki/Scott_topology).[^o30] Scott-continuous functions were first investigated in the attempt to provide a semantics for [lambda calculus](wikipedia://en/18203) (as ordinary set theory is inadequate to do this). More generally, Scott-continuous functions are now studied in [domain theory](wikipedia://en/325077), which encompasses the study of [denotational semantics](wikipedia://en/55275) of computer algorithms. Note that the Scott topology is quite different than many common topologies one might encounter in the [category of topological spaces](wikipedia://en/435051); the Scott topology is typically [finer](wikipedia://en/1819736), and is not [sober](wikipedia://en/602490).

The notion of continuity makes its appearance in [homotopy type theory](wikipedia://en/33974223), where, roughly speaking, two computer programs can be considered to be homotopic, i.e. compute the same results, if they can be "continuously" [refactored](https://en.wikipedia.org/wiki/Code_refactoring) from one to the other.

### Lambda calculi {#Lambda_calculi}

In [theoretical computer science](wikipedia://en/323392), currying provides a way to study functions with multiple arguments in very simple theoretical models, such as the [lambda calculus](wikipedia://en/18203), in which functions only take a single argument. Consider a function $f(x,y)$ taking two arguments, and having the type $(X \times Y)\to Z$, which should be understood to mean that *x* must have the type $X$, *y* must have the type $Y$, and the function itself returns the type $Z$. The curried form of *f* is defined as

$$\text{curry}(f) = \lambda x.(\lambda y.(f(x,y)))$$

where $\lambda$ is the abstractor of lambda calculus. Since curry takes, as input, functions with the type $(X\times Y)\to Z$, one concludes that the type of curry itself is

$$\text{curry}:((X \times Y)\to Z) \to (X \to (Y \to Z))$$

The → operator is often considered [right-associative](https://en.wikipedia.org/wiki/Right-associative), so the curried function type $X \to (Y \to Z)$ is often written as $X \to Y \to Z$. Conversely, [function application](wikipedia://en/20576545) is considered to be [left-associative](https://en.wikipedia.org/wiki/Operator_associativity), so that $f(x, y)$ is equivalent to

$$((\text{curry}(f) \; x) \;y) = \text{curry}(f) \; x \;y.$$

That is, the parenthesis are not required to disambiguate the order of the application.

Curried functions may be used in any [programming language](wikipedia://en/23015) that supports [closures](https://en.wikipedia.org/wiki/Closure_%28computer_programming%29); however, uncurried functions are generally preferred for efficiency reasons, since the overhead of partial application and closure creation can then be avoided for most function calls.

### Type theory {#Type_theory}

In [type theory](wikipedia://en/40282), the general idea of a [type system](wikipedia://en/199701) in computer science is formalized into a specific algebra of types. For example, when writing $f \colon X \to Y$, the intent is that $X$ and $Y$ are [types](wikipedia://en/199701), while the arrow $\to$ is a [type constructor](wikipedia://en/24047271), specifically, the [function type](wikipedia://en/583532) or arrow type. Similarly, the Cartesian product $X \times Y$ of types is constructed by the [product type](wikipedia://en/14892710) constructor $\times$.

The type-theoretical approach is expressed in programming languages such as [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) and the languages derived from and inspired by it: [Caml](https://en.wikipedia.org/wiki/Caml), [Haskell](https://en.wikipedia.org/wiki/Haskell), and [F#](https://en.wikipedia.org/wiki/F_Sharp_%28programming_language%29).

The type-theoretical approach provides a natural complement to the language of [category theory](wikipedia://en/5869), as discussed below. This is because categories, and specifically, [monoidal categories](https://en.wikipedia.org/wiki/Monoidal_categories), have an [internal language](https://en.wikipedia.org/wiki/Internal_language), with [simply typed lambda calculus](wikipedia://en/1986011) being the most prominent example of such a language. It is important in this context, because it can be built from a single type constructor, the arrow type. Currying then endows the language with a natural product type. The correspondence between objects in categories and types then allows programming languages to be re-interpreted as logics (via [Curry–Howard correspondence](wikipedia://en/254299)), and as other types of mathematical systems, as explored further, below.

### Logic {#Logic}

Under the [Curry–Howard correspondence](wikipedia://en/254299), the existence of currying and uncurrying is equivalent to the logical theorem $((A \land B) \to C) \Leftrightarrow (A \to (B \to C))$ (also known as [exportation](wikipedia://en/34769960)), as [tuples](wikipedia://en/132729) ([product type](wikipedia://en/14892710)) corresponds to conjunction in logic, and function type corresponds to implication.

The [exponential object](wikipedia://en/2237858) $Q^P$ in the category of [Heyting algebras](wikipedia://en/309343) is normally written as [material implication](wikipedia://en/658808) $P\to Q$. Distributive Heyting algebras are [Boolean algebras](wikipedia://en/54476844), and the exponential object has the explicit form $\neg P \lor Q$, thus making it clear that the exponential object really is [material implication](wikipedia://en/244516).[^o34]

### Category theory {#Category_theory}

The above notions of currying and uncurrying find their most general, abstract statement in [category theory](wikipedia://en/5869). Currying is a [universal property](wikipedia://en/32245) of an [exponential object](wikipedia://en/2237858), and gives rise to an [adjunction](https://en.wikipedia.org/wiki/Adjunction_%28category_theory%29) in [cartesian closed categories](wikipedia://en/237037). That is, there is a [natural](wikipedia://en/45022) [isomorphism](wikipedia://en/14828) between the [morphisms](https://en.wikipedia.org/wiki/Morphism_%28category_theory%29) from a [binary product](wikipedia://en/237868) $f \colon (X \times Y) \to Z$ and the morphisms to an exponential object $g \colon X \to Z^Y$.

This generalizes to a broader result in [closed monoidal categories](wikipedia://en/1396924): Currying is the statement that the [tensor product](wikipedia://en/330604) and the [internal Hom](https://en.wikipedia.org/wiki/Internal_Hom) are [adjoint functors](wikipedia://en/53991); that is, for every object $B$ there is a [natural isomorphism](wikipedia://en/45022):

$$\mathrm{Hom}(A\otimes B, C) \cong \mathrm{Hom}(A, B\Rightarrow C) .$$

Here, *Hom* denotes the (external) Hom-functor of all morphisms in the category, while $B\Rightarrow C$ denotes the internal hom functor in the closed monoidal category. For the [category of sets](wikipedia://en/26829), the two are the same. When the product is the cartesian product, then the internal hom $B\Rightarrow C$ becomes the exponential object $C^B$.

Currying can break down in one of two ways. One is if a category is not [closed](wikipedia://en/1397197), and thus lacks an internal hom functor (possibly because there is more than one choice for such a functor). Another way is if it is not [monoidal](wikipedia://en/330604), and thus lacks a product (that is, lacks a way of writing down pairs of objects). Categories that do have both products and internal homs are exactly the closed monoidal categories.

The setting of cartesian closed categories is sufficient for the discussion of [classical logic](wikipedia://en/55868); the more general setting of closed monoidal categories is suitable for [quantum computation](https://en.wikipedia.org/wiki/Quantum_computation).[^o36]

The difference between these two is that the [product](wikipedia://en/24977) for cartesian categories (such as the [category of sets](wikipedia://en/26829), [complete partial orders](wikipedia://en/572352) or [Heyting algebras](wikipedia://en/309343)) is just the [Cartesian product](wikipedia://en/24104095); it is interpreted as an [ordered pair](wikipedia://en/22362) of items (or a list). [Simply typed lambda calculus](wikipedia://en/1986011) is the [internal language](https://en.wikipedia.org/wiki/Internal_language) of cartesian closed categories; and it is for this reason that pairs and lists are the primary [types](wikipedia://en/199701) in the [type theory](wikipedia://en/40282) of [LISP](https://en.wikipedia.org/wiki/LISP), [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29) and many [functional programming languages](https://en.wikipedia.org/wiki/Functional_programming_language).

By contrast, the product for [monoidal categories](wikipedia://en/330604) (such as [Hilbert space](wikipedia://en/20598932) and the [vector spaces](wikipedia://en/32370) of [functional analysis](wikipedia://en/11180)) is the [tensor product](wikipedia://en/30844). The internal language of such categories is [linear logic](wikipedia://en/579675), a form of [quantum logic](wikipedia://en/663426); the corresponding [type system](wikipedia://en/199701) is the [linear type system](https://en.wikipedia.org/wiki/Linear_type_system). Such categories are suitable for describing [entangled quantum states](https://en.wikipedia.org/wiki/Entangled_quantum_states), and, more generally, allow a vast generalization of the [Curry–Howard correspondence](wikipedia://en/254299) to [quantum mechanics](wikipedia://en/25202), to [cobordisms](wikipedia://en/391832) in [algebraic topology](wikipedia://en/38801), and to [string theory](wikipedia://en/28305).[^o37] The [linear type system](https://en.wikipedia.org/wiki/Linear_type_system), and [linear logic](wikipedia://en/579675) are useful for describing [synchronization primitives](https://en.wikipedia.org/wiki/Synchronization_primitive), such as mutual exclusion locks, and the operation of vending machines.

## Contrast with partial function application {#Contrast_with_partial_function_application}

Currying and partial function application are often conflated.[^o2][^o39] One of the significant differences between the two is that a call to a partially applied function returns the result right away, not another function down the currying chain; this distinction can be illustrated clearly for functions whose [arity](wikipedia://en/42301) is greater than two.[^o40]

Given a function of type $f \colon (X \times Y \times Z) \to N$, currying produces $\text{curry}(f) \colon X \to (Y \to (Z \to N))$. That is, while an evaluation of the first function might be represented as $f(1, 2, 3)$, evaluation of the curried function would be represented as $f_\text{curried}(1)(2)(3)$, applying each argument in turn to a single-argument function returned by the previous invocation. Note that after calling $f_\text{curried}(1)$, we are left with a function that takes a single argument and returns another function, not a function that takes two arguments.

In contrast, **partial function application** refers to the process of fixing a number of arguments to a function, producing another function of smaller arity. Given the definition of $f$ above, we might fix (or 'bind') the first argument, producing a function of type $\text{partial}(f) \colon (Y \times Z) \to N$. Evaluation of this function might be represented as $f_\text{partial}(2, 3)$. Note that the result of partial function application in this case is a function that takes two arguments.

Intuitively, partial function application says "if you fix the first [argument](https://en.wikipedia.org/wiki/Parameter_%28computer_programming%29) of the function, you get a function of the remaining arguments". For example, if function *div* stands for the division operation *x*/*y*, then *div* with the parameter *x* fixed at 1 (i.e., *div* 1) is another function: the same as the function *inv* that returns the multiplicative inverse of its argument, defined by *inv*(*y*) = 1/*y*.

The practical motivation for partial application is that very often the functions obtained by supplying some but not all of the arguments to a function are useful; for example, many languages have a function or operator similar to `plus_one`. Partial application makes it easy to define these functions, for example by creating a function that represents the addition operator with 1 bound as its first argument.

Partial application can be seen as evaluating a curried function at a fixed point, e.g. given $f \colon (X \times Y \times Z) \to N$ and $a \in X$ then $\text{curry}(\text{partial}(f)_a)(y)(z) = \text{curry}(f)(a)(y)(z)$ or simply $\text{partial}(f)_a = \text{curry}_1(f)(a)$ where $\text{curry}_1$ curries f's first parameter.

Thus, partial application is reduced to a curried function at a fixed point. Further, a curried function at a fixed point is (trivially), a partial application. For further evidence, note that, given any function $f(x,y)$, a function $g(y,x)$ may be defined such that $g(y,x) = f(x,y)$. Thus, any partial application may be reduced to a single curry operation. As such, curry is more suitably defined as an operation which, in many theoretical cases, is often applied recursively, but which is theoretically indistinguishable (when considered as an operation) from a partial application.

So, a partial application can be defined as the objective result of a single application of the curry operator on some ordering of the inputs of some function.
