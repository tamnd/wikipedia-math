# Co-NP

::: {#o1 .subject cue=lead name="Co-NP"}

In [computational complexity theory](wikipedia://en/7543), **co-NP** is a [complexity class](wikipedia://en/502426). A [decision problem](wikipedia://en/8336) X is a member of co-NP if and only if its [complement](wikipedia://en/1929955) $\overline{X}$ is in the complexity class [NP](wikipedia://en/21562). The class can be defined as follows: a decision problem is in co-NP if and only if for every *no*-instance we have a polynomial-length "[certificate](wikipedia://en/14933760)" and there is a polynomial-time algorithm that can be used to verify any purported certificate.

:::

That is, co-NP is the set of decision problems where there exists a polynomial $p(n)$ and a polynomial-time bounded [Turing machine](wikipedia://en/30403) *M* such that for every instance *x*, *x* is a *no*-instance if and only if: for some possible certificate *c* of length bounded by $p(n)$, the Turing machine *M* accepts the pair $(x, c)$.[^o2]

## Complementary problems {#Complementary_problems}

While an NP problem asks whether a given instance is a *yes*-instance, its *complement* asks whether an instance is a *no*-instance, which means the complement is in co-NP. Any *yes*-instance for the original NP problem becomes a *no*-instance for its complement, and vice versa.

### Unsatisfiability {#Unsatisfiability}

An example of an [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem is the [Boolean satisfiability problem](wikipedia://en/4715): given a Boolean formula, is it *satisfiable* (is there a possible input for which the formula outputs true)? The complementary problem asks: "given a Boolean formula, is it *unsatisfiable* (do all possible inputs to the formula output false)?". Since this is the *complement* of the satisfiability problem, a certificate for a *no*-instance is the same as for a *yes*-instance from the original NP problem: a set of Boolean variable assignments which make the formula true. On the other hand, a certificate of a *yes*-instance for the complementary problem (whatever form it might take) would be equally as complex as for the *no*-instance of the original NP satisfiability problem.

## co-NP-completeness {#co-NP-completeness}

A problem *L* is [co-NP-complete](wikipedia://en/54680) if and only if *L* is in co-NP and for any problem in co-NP, there exists a [polynomial-time reduction](wikipedia://en/159695) from that problem to *L*.

### Tautology reduction {#Tautology_reduction}

Determining if a formula in [propositional logic](wikipedia://en/18154) is a [tautology](wikipedia://en/4495335) is co-NP-complete: that is, if the formula evaluates to true under every possible assignment to its variables.[^o2]

## Relationship to other classes {#Relationship_to_other_classes}

::: {#o8 .problem cue=unsolved}

$$\textsf{NP}\ \overset{?}{=}\ \textsf{co-NP}$$

:::

*Image: Complexity-classes-polynomial.svg.* Inclusions of complexity classes including [P](wikipedia://en/658550), [NP](wikipedia://en/21562), co-NP, [BPP](wikipedia://en/4079), [P/poly](wikipedia://en/2052415), [PH](https://en.wikipedia.org/wiki/PH_%28complexity%29), and [PSPACE](wikipedia://en/39351)

[P](wikipedia://en/658550), the class of polynomial time solvable problems, is a subset of both NP and co-NP. P is thought to be a strict subset in both cases. Because P is closed under complementation, and NP and co-NP are complementary, it cannot be strict in one case and not strict in the other: if P equals NP, it must also equal co-NP, and vice versa.[^o9]

NP and co-NP are also thought to be unequal,[^o10] and their equality would imply the collapse of the [polynomial hierarchy](wikipedia://en/658651) PH to NP. If they are unequal, then no NP-complete problem can be in co-NP and no [co-NP-complete](wikipedia://en/54680) problem can be in NP.[^o11] This can be shown as follows. Suppose for the sake of contradiction there exists an NP-complete problem X that is in co-NP. Since all problems in NP can be reduced to X, it follows that for every problem in NP, we can construct a [non-deterministic Turing machine](https://en.wikipedia.org/wiki/Non-deterministic_Turing_machine) that decides its complement in polynomial time; i.e., $\textsf{NP} \subseteq \textsf{co-NP}$. From this, it follows that the set of complements of the problems in NP is a subset of the set of complements of the problems in co-NP; i.e., $\textsf{co-NP} \subseteq \textsf{NP}$. Thus $\textsf{co-NP} = \textsf{NP}$. The proof that no co-NP-complete problem can be in NP if $\textsf{NP} \neq \textsf{co-NP}$ is symmetrical.

co-NP is a subset of [PH](https://en.wikipedia.org/wiki/PH_%28complexity%29), which itself is a subset of [PSPACE](wikipedia://en/39351).

### Integer factorization {#Integer_factorization}

An example of a problem that is known to belong to both NP and co-NP (but not known to be in P) is [Integer factorization](wikipedia://en/15491): given positive integers *m* and *n*, determine if *m* has a factor less than *n* and greater than one. Membership in NP is clear; if *m* does have such a factor, then the factor itself is a certificate. Membership in co-NP is also straightforward: one can just list the prime factors of *m*, all greater or equal to *n*, which the verifier can confirm to be valid by multiplication and the [AKS primality test](https://en.wikipedia.org/wiki/AKS_primality_test). It is presently not known whether there is a polynomial-time algorithm for factorization, equivalently that integer factorization is in P, and hence this example is interesting as one of the most natural problems known to be in NP and co-NP but not known to be in P.[^o13]
