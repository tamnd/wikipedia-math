# Data compression

::: {#o1 .subject cue=lead name="Data compression"}

In [information theory](wikipedia://en/14773), **data compression**, **source coding**,[^o80] or **bit-rate reduction** is the process of encoding [information](wikipedia://en/18985062) using fewer [bits](https://en.wikipedia.org/wiki/Bit) than the original representation.[^o81] Any particular compression is either [lossy](https://en.wikipedia.org/wiki/Lossy) or [lossless](https://en.wikipedia.org/wiki/Lossless). Lossless compression reduces bits by identifying and eliminating [statistical redundancy](https://en.wikipedia.org/wiki/Redundancy_%28information_theory%29). No information is lost in lossless compression. Lossy compression reduces bits by removing unnecessary or less important information.[^o82] Typically, a device that performs data compression is referred to as an encoder, and one that performs the reversal of the process (decompression) as a decoder.

:::

The process of reducing the size of a [data file](https://en.wikipedia.org/wiki/Data_file) is often referred to as data compression. In the context of [data transmission](https://en.wikipedia.org/wiki/Data_transmission), it is called source coding: encoding is done at the source of the data before it is stored or transmitted.[^o83] Source coding should not be confused with [channel coding](https://en.wikipedia.org/wiki/Channel_coding), for error detection and correction or [line coding](https://en.wikipedia.org/wiki/Line_coding), the means for mapping data onto a signal.

Data compression algorithms present a [space–time complexity trade-off](https://en.wikipedia.org/wiki/Space–time_tradeoff) between the bytes needed to store or transmit information, and the [computational resources](wikipedia://en/4628222) needed to perform the encoding and decoding. The design of data compression schemes involves balancing the degree of compression, the amount of distortion introduced (when using [lossy data compression](https://en.wikipedia.org/wiki/Lossy_data_compression)), and the computational resources or time required to compress and decompress the data.[^o84]

::: {#o3 .pointer-item cue=pointer name="Algorithms for lossless data compression"}

## Lossless {#Lossless}

Lossless data compression [algorithms](wikipedia://en/775) usually exploit [statistical redundancy](https://en.wikipedia.org/wiki/Redundancy_%28information_theory%29) to represent data without losing any [information](https://en.wikipedia.org/wiki/Self-information), so that the process is reversible. Lossless compression is possible because most real-world data exhibits statistical redundancy. For example, an image may have areas of color that do not change over several pixels; instead of coding "red pixel, red pixel, ..." the data may be encoded as "279 red pixels". This is a basic example of [run-length encoding](wikipedia://en/26392); there are many schemes to reduce file size by eliminating redundancy.

The [Lempel–Ziv](https://en.wikipedia.org/wiki/Lempel–Ziv) (LZ) compression methods are among the most popular algorithms for lossless storage.[^o85] [DEFLATE](https://en.wikipedia.org/wiki/DEFLATE) is a variation on LZ optimized for decompression speed and compression ratio,[^o4] but compression can be slow. In the mid-1980s, following work by [Terry Welch](https://en.wikipedia.org/wiki/Terry_Welch), the [Lempel–Ziv–Welch](https://en.wikipedia.org/wiki/Lempel–Ziv–Welch) (LZW) algorithm rapidly became the method of choice for most general-purpose compression systems. LZW is used in [GIF](https://en.wikipedia.org/wiki/GIF) images, programs such as [PKZIP](https://en.wikipedia.org/wiki/PKZIP), and hardware devices such as modems.[^o5] LZ methods use a table-based compression model where table entries are substituted for repeated strings of data. For most LZ methods, this table is generated dynamically from earlier data in the input. The table itself is often [Huffman encoded](wikipedia://en/13883). [Grammar-based codes](https://en.wikipedia.org/wiki/Grammar-based_codes) like this can compress highly repetitive input extremely effectively, for instance, a biological [data collection](wikipedia://en/11501746) of the same or closely related species, a huge versioned document collection, internet archival, etc. The basic task of grammar-based codes is constructing a context-free grammar deriving a single string. Other practical grammar compression algorithms include [Sequitur](https://en.wikipedia.org/wiki/Sequitur_algorithm) and [Re-Pair](https://en.wikipedia.org/wiki/Re-Pair).

The strongest modern lossless compressors use [probabilistic](wikipedia://en/495383) models, such as [prediction by partial matching](wikipedia://en/527918). The [Burrows–Wheeler transform](https://en.wikipedia.org/wiki/Burrows–Wheeler_transform) can also be viewed as an indirect form of statistical modelling. In a further refinement of the direct use of [probabilistic modelling](https://en.wikipedia.org/wiki/Probabilistic_model), statistical estimates can be coupled to an algorithm called [arithmetic coding](wikipedia://en/62545). Arithmetic coding is a more modern coding technique that uses the mathematical calculations of a [finite-state machine](wikipedia://en/10931) to produce a string of encoded bits from a series of input data symbols. It can achieve superior compression compared to other techniques, such as the better-known Huffman algorithm. It uses an internal memory state to avoid the need to perform a one-to-one mapping of individual input symbols to distinct representations that use an integer number of bits, and it clears out the internal memory only after encoding the entire string of data symbols. Arithmetic coding applies especially well to adaptive data compression tasks where the statistics vary and are context-dependent, as it can be easily coupled with an adaptive model of the [probability distribution](wikipedia://en/23543) of the input data. An early example of the use of arithmetic coding was in an optional (but not widely used) feature of the [JPEG](https://en.wikipedia.org/wiki/JPEG) image coding standard.[^o87] It has since been applied in various other designs including [H.263](https://en.wikipedia.org/wiki/H.263), [H.264/MPEG-4 AVC](https://en.wikipedia.org/wiki/H.264/MPEG-4_AVC) and [HEVC](https://en.wikipedia.org/wiki/HEVC) for video coding.[^o88]

Archive software typically has the ability to adjust the "dictionary size", where a larger size demands more [random-access memory](https://en.wikipedia.org/wiki/Random-access_memory) during compression and decompression, but compresses more strongly, especially on repeating patterns in files' content.[^o6][^o7]

## Lossy {#Lossy}

*Image: Comparison of JPEG and PNG.png.* Composite image showing JPG and PNG image compression. Left side of the image is from a JPEG image, showing lossy artifacts; the right side is from a PNG image.

In the late 1980s, digital images became more common, and standards for lossless [image compression](https://en.wikipedia.org/wiki/Image_compression) emerged. In the early 1990s, lossy compression methods began to be widely used.[^o86] In these schemes, some loss of information is accepted as dropping nonessential detail can save storage space. There is a corresponding [trade-off](https://en.wikipedia.org/wiki/Trade-off) between preserving information and reducing size. Lossy data compression schemes are designed based on research on how people perceive the data in question. For example, the human eye is more sensitive to subtle variations in [luminance](https://en.wikipedia.org/wiki/Luminance) than it is to the variations in color. [JPEG](https://en.wikipedia.org/wiki/JPEG) image compression works in part by rounding off nonessential bits of information.[^o89] A number of popular compression formats exploit these perceptual differences, including [psychoacoustics](https://en.wikipedia.org/wiki/Psychoacoustics) for sound, and [psychovisuals](https://en.wikipedia.org/wiki/Psychovisual) for images and video.

Most forms of lossy compression are based on [transform coding](https://en.wikipedia.org/wiki/Transform_coding), especially the [discrete cosine transform](wikipedia://en/59962) (DCT). It was first proposed in 1972 by [Nasir Ahmed](https://en.wikipedia.org/wiki/N._Ahmed), who then developed a working algorithm with T. Natarajan and [K. R. Rao](https://en.wikipedia.org/wiki/K._R._Rao) in 1973, before introducing it in January 1974.[^o9][^o105] DCT is the most widely used lossy compression method, and is used in multimedia formats for images (such as JPEG and [HEIF](https://en.wikipedia.org/wiki/HEIF)),[^o109] [video](https://en.wikipedia.org/wiki/Video_compression) (such as [MPEG](https://en.wikipedia.org/wiki/MPEG), [AVC](https://en.wikipedia.org/wiki/H.264/AVC) and HEVC) and audio (such as [MP3](https://en.wikipedia.org/wiki/MP3), [AAC](https://en.wikipedia.org/wiki/Advanced_Audio_Coding) and [Vorbis](https://en.wikipedia.org/wiki/Vorbis)).

Lossy image compression is used in [digital cameras](https://en.wikipedia.org/wiki/Digital_camera), to increase storage capacities. Similarly, [DVDs](https://en.wikipedia.org/wiki/DVD), [Blu-ray](https://en.wikipedia.org/wiki/Blu-ray) and [streaming video](https://en.wikipedia.org/wiki/Streaming_video) use lossy [video coding formats](https://en.wikipedia.org/wiki/Video_coding_format). Lossy compression is extensively used in video.

In lossy audio compression, methods of psychoacoustics are used to remove non-audible (or less audible) components of the [audio signal](https://en.wikipedia.org/wiki/Audio_signal). Compression of human speech is often performed with even more specialized techniques; [speech coding](https://en.wikipedia.org/wiki/Speech_coding) is distinguished as a separate discipline from general-purpose audio compression. Speech coding is used in [internet telephony](https://en.wikipedia.org/wiki/Internet_telephony), for example, audio compression is used for CD ripping and is decoded by the audio players.

Lossy compression can cause [generation loss](https://en.wikipedia.org/wiki/Generation_loss).

## Theory {#Theory}

The theoretical basis for compression is provided by [information theory](wikipedia://en/14773) and, more specifically, [Shannon's source coding theorem](wikipedia://en/1208872); domain-specific theories include [algorithmic information theory](https://en.wikipedia.org/wiki/Algorithmic_information_theory) for lossless compression and [rate–distortion theory](wikipedia://en/192842) for lossy compression. These areas of study were essentially created by [Claude Shannon](wikipedia://en/5693), who published fundamental papers on the topic in the late 1940s and early 1950s. Other topics associated with compression include [coding theory](wikipedia://en/321869) and [statistical inference](wikipedia://en/27577).[^o90]

### Machine learning {#Machine_learning}

There is a close connection between [machine learning](wikipedia://en/233488) and compression. A system that predicts the [posterior probabilities](https://en.wikipedia.org/wiki/Posterior_probabilities) of a sequence given its entire history can be used for optimal data compression (by using [arithmetic coding](wikipedia://en/62545) on the output distribution). Conversely, an optimal compressor can be used for prediction (by finding the symbol that compresses best, given the previous history). This equivalence has been used as a justification for using data compression as a benchmark for "general intelligence".[^o91][^o92][^o93]

An alternative view can show compression algorithms implicitly map strings into implicit [feature space vectors](https://en.wikipedia.org/wiki/Feature_space_vector), and compression-based similarity measures compute similarity within these feature spaces. For each compressor C(.) we define an associated vector space ℵ, such that C(.) maps an input string x, corresponding to the vector norm ||~x||. An exhaustive examination of the feature spaces underlying all compression algorithms is precluded by space; instead, feature vectors chooses to examine three representative lossless compression methods, LZW, LZ77, and PPM.[^o94]

According to [AIXI](wikipedia://en/30511763) theory, a connection more directly explained in [Hutter Prize](https://en.wikipedia.org/wiki/Hutter_Prize), the best possible compression of x is the smallest possible software that generates x. For example, in that model, a zip file's compressed size includes both the zip file and the unzipping software, since you can not unzip it without both, but there may be an even smaller combined form.

Examples of AI-powered audio/video compression software include [NVIDIA Maxine](https://en.wikipedia.org/wiki/NVIDIA_Maxine), AIVC.[^o13] Examples of software that can perform AI-powered image compression include [OpenCV](https://en.wikipedia.org/wiki/OpenCV), [TensorFlow](https://en.wikipedia.org/wiki/TensorFlow), [MATLAB](wikipedia://en/20412)'s Image Processing Toolbox (IPT) and High-Fidelity Generative Image Compression.[^o14]

In [unsupervised machine learning](https://en.wikipedia.org/wiki/Unsupervised_machine_learning), [k-means clustering](wikipedia://en/1860407) can be utilized to compress data by grouping similar data points into clusters. This technique simplifies handling extensive datasets that lack predefined labels and finds widespread use in fields such as [image compression](https://en.wikipedia.org/wiki/Image_compression).[^o15]

Data compression aims to reduce the size of data files, enhancing storage efficiency and speeding up data transmission. K-means clustering, an unsupervised machine learning algorithm, is employed to partition a dataset into a specified number of clusters, k, each represented by the [centroid](wikipedia://en/187926) of its points. This process condenses extensive datasets into a more compact set of representative points. Particularly beneficial in [image](https://en.wikipedia.org/wiki/Image_processing) and [signal processing](wikipedia://en/29324), k-means clustering aids in data reduction by replacing groups of data points with their centroids, thereby preserving the core information of the original data while significantly decreasing the required storage space.[^o16]

[Large language models](https://en.wikipedia.org/wiki/Large_language_model) (LLMs) are also efficient lossless data compressors on some data sets, as demonstrated by [DeepMind](https://en.wikipedia.org/wiki/DeepMind)'s research with the Chinchilla 70B model. Developed by DeepMind, Chinchilla 70B effectively compressed data, outperforming conventional methods such as [Portable Network Graphics](https://en.wikipedia.org/wiki/Portable_Network_Graphics) (PNG) for images and [Free Lossless Audio Codec](https://en.wikipedia.org/wiki/Free_Lossless_Audio_Codec) (FLAC) for audio. It achieved compression of image and audio data to 43.4% and 16.4% of their original sizes, respectively. There is, however, some reason to be concerned that the data set used for testing overlaps the LLM training data set, making it possible that the Chinchilla 70B model is only an efficient compression tool on data it has already been trained on.[^o17][^o18]

### Data differencing {#Data_differencing}

*Image: Nubio Diff Screenshot3.png.* [Comparison](https://en.wikipedia.org/wiki/File_comparison) of two revisions of a file

Data compression can be viewed as a special case of [data differencing](https://en.wikipedia.org/wiki/Data_differencing).[^o95][^o96] Data differencing consists of producing a *difference* given a *source* and a *target,* with patching reproducing the *target* given a *source* and a *difference.* Since there is no separate source and target in data compression, one can consider data compression as data differencing with empty source data, the compressed file corresponding to a difference from nothing. This is the same as considering absolute [entropy](wikipedia://en/15445) (corresponding to data compression) as a special case of [relative entropy](https://en.wikipedia.org/wiki/Relative_entropy) (corresponding to data differencing) with no initial data.

The term *differential compression* is used to emphasize the data differencing connection.

## Uses {#Uses}

### Image {#Image}

[Entropy coding](wikipedia://en/46680) originated in the 1940s with the introduction of [Shannon–Fano coding](wikipedia://en/62544),[^o107] the basis for [Huffman coding](wikipedia://en/13883) which was developed in 1950.[^o108] [Transform coding](https://en.wikipedia.org/wiki/Transform_coding) dates back to the late 1960s, with the introduction of [fast Fourier transform](wikipedia://en/11512) (FFT) coding in 1968 and the [Hadamard transform](wikipedia://en/634765) in 1969.[^o110]

An important image compression technique is the [discrete cosine transform](wikipedia://en/59962) (DCT), a technique developed in the early 1970s.[^o9] DCT is the basis for JPEG, a [lossy compression](https://en.wikipedia.org/wiki/Lossy_compression) format which was introduced by the [Joint Photographic Experts Group](https://en.wikipedia.org/wiki/Joint_Photographic_Experts_Group) (JPEG) in 1992.[^o111] JPEG greatly reduces the amount of data required to represent an image at the cost of a relatively small reduction in image quality and has become the most widely used [image file format](https://en.wikipedia.org/wiki/Image_file_format).[^o23][^o24] Its highly efficient DCT-based compression algorithm was largely responsible for the wide proliferation of [digital images](https://en.wikipedia.org/wiki/Digital_image) and [digital photos](https://en.wikipedia.org/wiki/Digital_photo).[^o25]

[Lempel–Ziv–Welch](https://en.wikipedia.org/wiki/Lempel–Ziv–Welch) (LZW) is a [lossless compression](wikipedia://en/18209) algorithm developed in 1984. It is used in the [GIF](https://en.wikipedia.org/wiki/GIF) format, introduced in 1987.[^o26] [DEFLATE](https://en.wikipedia.org/wiki/DEFLATE), a lossless compression algorithm specified in 1996, is used in the [Portable Network Graphics](https://en.wikipedia.org/wiki/Portable_Network_Graphics) (PNG) format.[^o27]

[Wavelet compression](https://en.wikipedia.org/wiki/Wavelet_compression), the use of [wavelets](wikipedia://en/50903) in image compression, began after the development of DCT coding.[^o118] The [JPEG 2000](https://en.wikipedia.org/wiki/JPEG_2000) standard was introduced in 2000.[^o28] In contrast to the DCT algorithm used by the original JPEG format, JPEG 2000 instead uses [discrete wavelet transform](wikipedia://en/857564) (DWT) algorithms.[^o119][^o29][^o30] JPEG 2000 technology, which includes the [Motion JPEG 2000](https://en.wikipedia.org/wiki/Motion_JPEG_2000) extension, was selected as the [video coding standard](https://en.wikipedia.org/wiki/Video_coding_standard) for [digital cinema](https://en.wikipedia.org/wiki/Digital_cinema) in 2004.[^o31]

### Audio {#Audio}

Audio data compression, not to be confused with [dynamic range compression](https://en.wikipedia.org/wiki/Dynamic_range_compression), has the potential to reduce the transmission [bandwidth](https://en.wikipedia.org/wiki/Bandwidth_%28computing%29) and storage requirements of audio data. [Audio compression formats compression algorithms](https://en.wikipedia.org/wiki/List_of_codecs#Audio_compression_formats) are implemented in [software](https://en.wikipedia.org/wiki/Software) as audio [codecs](https://en.wikipedia.org/wiki/Codec). In both lossy and lossless compression, [information redundancy](https://en.wikipedia.org/wiki/Redundancy_%28information_theory%29) is reduced, using methods such as [coding](wikipedia://en/321869), [quantization](wikipedia://en/317018), DCT and [linear prediction](wikipedia://en/18572) to reduce the amount of information used to represent the uncompressed data.

Lossy audio compression algorithms provide higher compression and are used in numerous audio applications including [Vorbis](https://en.wikipedia.org/wiki/Vorbis) and [MP3](https://en.wikipedia.org/wiki/MP3). These algorithms almost all rely on [psychoacoustics](https://en.wikipedia.org/wiki/Psychoacoustics) to eliminate or reduce fidelity of less audible sounds, thereby reducing the space required to store or transmit them.[^o81][^o34]

The acceptable trade-off between loss of audio quality and transmission or storage size depends upon the application. For example, one 640 MB [compact disc](https://en.wikipedia.org/wiki/Compact_disc) (CD) holds approximately one hour of uncompressed [high fidelity](https://en.wikipedia.org/wiki/High_fidelity) music, less than 2 hours of music compressed losslessly, or 7 hours of music compressed in the [MP3](https://en.wikipedia.org/wiki/MP3) format at a medium [bit rate](https://en.wikipedia.org/wiki/Bit_rate). A digital sound recorder can typically store around 200 hours of clearly intelligible speech in 640 MB.[^o97]

Lossless audio compression produces a representation of digital data that can be decoded to an exact digital duplicate of the original. Compression ratios are around 50–60% of the original size,[^o98] which is similar to those for generic lossless data compression. Lossless codecs use [curve fitting](wikipedia://en/555425) or linear prediction as a basis for estimating the signal. Parameters describing the estimation and the difference between the estimation and the actual signal are coded separately.[^o99]

A number of lossless audio compression formats exist. See [list of lossless codecs](https://en.wikipedia.org/wiki/List_of_codecs#Lossless_compression) for a listing. Some formats are associated with a distinct system, such as [Direct Stream Transfer](https://en.wikipedia.org/wiki/Direct_Stream_Transfer), used in [Super Audio CD](https://en.wikipedia.org/wiki/Super_Audio_CD) and [Meridian Lossless Packing](https://en.wikipedia.org/wiki/Meridian_Lossless_Packing), used in [DVD-Audio](https://en.wikipedia.org/wiki/DVD-Audio), [Dolby TrueHD](https://en.wikipedia.org/wiki/Dolby_TrueHD), [Blu-ray](https://en.wikipedia.org/wiki/Blu-ray) and [HD DVD](https://en.wikipedia.org/wiki/HD_DVD).

Some [audio file formats](https://en.wikipedia.org/wiki/Audio_file_format) feature a combination of a lossy format and a lossless correction; this allows stripping the correction to easily obtain a lossy file. Such formats include [MPEG-4 SLS](https://en.wikipedia.org/wiki/MPEG-4_SLS) (Scalable to Lossless), [WavPack](https://en.wikipedia.org/wiki/WavPack), and [OptimFROG DualStream](https://en.wikipedia.org/wiki/OptimFROG_DualStream).

When audio files are to be processed, either by further compression or for [editing](https://en.wikipedia.org/wiki/Audio_editing), it is desirable to work from an unchanged original (uncompressed or losslessly compressed). Processing of a lossily compressed file for some purpose usually produces a final result inferior to the creation of the same compressed file from an uncompressed original. In addition to sound editing or mixing, lossless audio compression is often used for archival storage, or as master copies.

#### Lossy audio compression {#Lossy_audio_compression}

*Image: AudiodatenkompressionManowarThePowerOfThySword.jpg.* Comparison of [spectrograms](wikipedia://en/263317) of audio in an uncompressed format and several lossy formats. The lossy spectrograms show [bandlimiting](wikipedia://en/561949) of higher frequencies, a common technique associated with lossy audio compression.

Lossy audio compression is used in a wide range of applications. In addition to standalone audio-only applications of file playback in MP3 players or computers, digitally compressed audio streams are used in most video DVDs, digital television, streaming media on the [Internet](https://en.wikipedia.org/wiki/Internet), satellite and cable radio, and increasingly in terrestrial radio broadcasts. Lossy compression typically achieves far greater compression than lossless compression, by discarding less-critical data based on [psychoacoustic](https://en.wikipedia.org/wiki/Psychoacoustic) optimizations.[^o100]

Psychoacoustics recognizes that not all data in an audio stream can be perceived by the human [auditory system](https://en.wikipedia.org/wiki/Auditory_system). Most lossy compression reduces redundancy by first identifying perceptually irrelevant sounds, that is, sounds that are very hard to hear. Typical examples include high frequencies or sounds that occur at the same time as louder sounds. Those irrelevant sounds are coded with decreased accuracy or not at all.

Due to the nature of lossy algorithms, [audio quality](https://en.wikipedia.org/wiki/Audio_quality) suffers a [digital generation loss](https://en.wikipedia.org/wiki/Digital_generation_loss) when a file is decompressed and recompressed. This makes lossy compression unsuitable for storing the intermediate results in professional audio engineering applications, such as sound editing and multitrack recording. However, lossy formats such as [MP3](https://en.wikipedia.org/wiki/MP3) are very popular with end-users as the file size is reduced to 5-20% of the original size and a megabyte can store about a minute's worth of music at adequate quality.

Several proprietary lossy compression algorithms have been developed that provide higher quality audio performance by using a combination of lossless and lossy algorithms with adaptive bit rates and lower compression ratios. Examples include [aptX](https://en.wikipedia.org/wiki/AptX), [LDAC](https://en.wikipedia.org/wiki/LDAC_%28codec%29), [LHDC](https://en.wikipedia.org/wiki/LHDC_%28codec%29), [MQA](https://en.wikipedia.org/wiki/Master_Quality_Authenticated#Codec_description) and [SCL6](https://en.wikipedia.org/wiki/SCL6_%28codec%29).

##### Coding methods {#Coding_methods}

To determine what information in an audio signal is perceptually irrelevant, most lossy compression algorithms use transforms such as the [modified discrete cosine transform](https://en.wikipedia.org/wiki/Modified_discrete_cosine_transform) (MDCT) to convert [time domain](wikipedia://en/173419) sampled waveforms into a transform domain, typically the [frequency domain](wikipedia://en/370346). Once transformed, component frequencies can be prioritized according to how audible they are. Audibility of spectral components is assessed using the [absolute threshold of hearing](https://en.wikipedia.org/wiki/Absolute_threshold_of_hearing) and the principles of [simultaneous masking](https://en.wikipedia.org/wiki/Simultaneous_masking)—the phenomenon wherein a signal is masked by another signal separated by frequency—and, in some cases, [temporal masking](https://en.wikipedia.org/wiki/Temporal_masking)—where a signal is masked by another signal separated by time. [Equal-loudness contours](https://en.wikipedia.org/wiki/Equal-loudness_contour) may also be used to weigh the perceptual importance of components. Models of the human ear-brain combination incorporating such effects are often called [psychoacoustic models](https://en.wikipedia.org/wiki/Psychoacoustic_model).[^o101]

Other types of lossy compressors, such as the [linear predictive coding](https://en.wikipedia.org/wiki/Linear_predictive_coding) (LPC) used with speech, are source-based coders. LPC uses a model of the human vocal tract to analyze speech sounds and infer the parameters used by the model to produce them moment to moment. These changing parameters are transmitted or stored and used to drive another model in the decoder, which reproduces the sound.

Lossy formats are often used for the distribution of streaming audio or interactive communication (such as in cell phone networks). In such applications, the data must be decompressed as the data flows, rather than after the entire data stream has been transmitted. Not all audio codecs can be used for streaming applications.[^o100]

[Latency](https://en.wikipedia.org/wiki/Latency_%28engineering%29) is introduced by the methods used to encode and decode the data. Some codecs will analyze a longer segment, called a *frame*, of the data to optimize efficiency, and then code it in a manner that requires a larger segment of data at one time to decode. The inherent latency of the coding algorithm can be critical; for example, when there is a two-way transmission of data, such as with a telephone conversation, significant delays may seriously degrade the perceived quality.

In contrast to the speed of compression, which is proportional to the number of operations required by the algorithm, here latency refers to the number of samples that must be analyzed before a block of audio is processed. In the minimum case, latency is zero samples (e.g., if the coder/decoder simply reduces the number of bits used to quantize the signal). Time domain algorithms such as LPC also often have low latencies, hence their popularity in speech coding for telephony. In algorithms such as MP3, however, a large number of samples have to be analyzed to implement a psychoacoustic model in the frequency domain, and latency is on the order of 23 ms.

##### Speech encoding {#Speech_encoding}

[Speech encoding](https://en.wikipedia.org/wiki/Speech_encoding) is an important category of audio data compression. The perceptual models used to estimate what aspects of speech a human ear can hear are generally somewhat different from those used for music. The range of frequencies needed to convey the sounds of a human voice is normally far narrower than that needed for music, and the sound is normally less complex. As a result, speech can be encoded at high quality using a relatively low bit rate.

This is accomplished, in general, by some combination of two approaches:

- Only encoding sounds that could be made by a single human voice.
- Throwing away more of the data in the signal—keeping just enough to reconstruct an "intelligible" voice rather than the full frequency range of human [hearing](https://en.wikipedia.org/wiki/Hearing).

The earliest algorithms used in speech encoding (and audio data compression in general) were the [A-law algorithm](https://en.wikipedia.org/wiki/A-law_algorithm) and the [μ-law algorithm](https://en.wikipedia.org/wiki/Μ-law_algorithm).

#### History {#History}

*Image: Placa-audioPC-925.jpg.* Solidyne 922: The world's first commercial audio bit compression [sound card](https://en.wikipedia.org/wiki/Sound_card) for PC, 1990

Early audio research was conducted at [Bell Labs](https://en.wikipedia.org/wiki/Bell_Labs). There, in 1950, [C. Chapin Cutler](https://en.wikipedia.org/wiki/C._Chapin_Cutler) filed the patent on [differential pulse-code modulation](https://en.wikipedia.org/wiki/Differential_pulse-code_modulation) (DPCM).[^o106] In 1973, [Adaptive DPCM](https://en.wikipedia.org/wiki/Adaptive_DPCM) (ADPCM) was introduced by P. Cummiskey, [Nikil S. Jayant](https://en.wikipedia.org/wiki/Nikil_Jayant) and [James L. Flanagan](https://en.wikipedia.org/wiki/James_L._Flanagan).[^o41][^o42]

[Perceptual coding](https://en.wikipedia.org/wiki/Perceptual_coding) was first used for [speech coding](https://en.wikipedia.org/wiki/Speech_coding) compression, with [linear predictive coding](https://en.wikipedia.org/wiki/Linear_predictive_coding) (LPC).[^o43] Initial concepts for LPC date back to the work of [Fumitada Itakura](https://en.wikipedia.org/wiki/Fumitada_Itakura) ([Nagoya University](https://en.wikipedia.org/wiki/Nagoya_University)) and Shuzo Saito ([Nippon Telegraph and Telephone](https://en.wikipedia.org/wiki/Nippon_Telegraph_and_Telephone)) in 1966.[^o44] During the 1970s, [Bishnu S. Atal](https://en.wikipedia.org/wiki/Bishnu_S._Atal) and [Manfred R. Schroeder](https://en.wikipedia.org/wiki/Manfred_R._Schroeder) at [Bell Labs](https://en.wikipedia.org/wiki/Bell_Labs) developed a form of LPC called [adaptive predictive coding](https://en.wikipedia.org/wiki/Adaptive_predictive_coding) (APC), a perceptual coding algorithm that exploited the masking properties of the human ear, followed in the early 1980s with the [code-excited linear prediction](https://en.wikipedia.org/wiki/Code-excited_linear_prediction) (CELP) algorithm which achieved a significant [compression ratio](https://en.wikipedia.org/wiki/Data_compression_ratio) for its time.[^o43] Perceptual coding is used by modern audio compression formats such as [MP3](https://en.wikipedia.org/wiki/MP3)[^o43] and [AAC](https://en.wikipedia.org/wiki/Advanced_Audio_Codec).

[Discrete cosine transform](wikipedia://en/59962) (DCT), developed by [Nasir Ahmed](https://en.wikipedia.org/wiki/N._Ahmed), T. Natarajan and [K. R. Rao](https://en.wikipedia.org/wiki/K._R._Rao) in 1974,[^o105] provided the basis for the [modified discrete cosine transform](https://en.wikipedia.org/wiki/Modified_discrete_cosine_transform) (MDCT) used by modern audio compression formats such as MP3,[^o45] [Dolby Digital](https://en.wikipedia.org/wiki/Dolby_Digital),[^o46][^o47] and AAC.[^o48] MDCT was proposed by J. P. Princen, A. W. Johnson and A. B. Bradley in 1987,[^o49] following earlier work by Princen and Bradley in 1986.[^o50]

The world's first commercial [broadcast automation](https://en.wikipedia.org/wiki/Broadcast_automation) audio compression system was developed by Oscar Bonello, an engineering professor at the [University of Buenos Aires](https://en.wikipedia.org/wiki/University_of_Buenos_Aires). [^o51] This broadcast automation system was launched in 1987 under the name [Audicom](https://en.wikipedia.org/wiki/Audicom). [^o52] [^o53]

A literature compendium for a large variety of audio coding systems was published in the IEEE's *Journal on Selected Areas in Communications* (*JSAC*), in February 1988. While there were some papers from before that time, this collection documented an entire variety of finished, working audio coders, nearly all of them using perceptual techniques and some kind of frequency analysis and back-end noiseless coding.[^o102]

### Video {#Video}

[Uncompressed video](https://en.wikipedia.org/wiki/Uncompressed_video) requires a very high [data rate](https://en.wikipedia.org/wiki/Uncompressed_video#Storage_and_Data_Rates_for_Uncompressed_Video). Although [lossless video compression](https://en.wikipedia.org/wiki/List_of_codecs#Lossless_video_compression) codecs perform at a compression factor of 5 to 12, a typical [H.264](https://en.wikipedia.org/wiki/H.264) lossy compression video has a compression factor between 20 and 200.[^o104]

The two key video compression techniques used in [video coding standards](https://en.wikipedia.org/wiki/Video_coding_standards) are the DCT and [motion compensation](https://en.wikipedia.org/wiki/Motion_compensation) (MC). Most video coding standards, such as the [H.26x](https://en.wikipedia.org/wiki/H.26x) and [MPEG](https://en.wikipedia.org/wiki/MPEG) formats, typically use motion-compensated DCT video coding (block motion compensation).[^o56][^o57]

Most video codecs are used alongside audio compression techniques to store the separate but complementary data streams as one combined package using so-called *[container formats](https://en.wikipedia.org/wiki/Container_format)*.[^o103]

#### Encoding theory {#Encoding_theory}

Video data may be represented as a series of still image frames. Such data usually contains abundant amounts of spatial and temporal [redundancy](https://en.wikipedia.org/wiki/Redundancy_%28information_theory%29). Video compression algorithms attempt to reduce redundancy and store information more compactly.

Most [video compression formats](https://en.wikipedia.org/wiki/Video_compression_formats) and [codecs](https://en.wikipedia.org/wiki/Video_codec) exploit both spatial and temporal redundancy (e.g., through difference coding with [motion compensation](https://en.wikipedia.org/wiki/Motion_compensation)). Similarities can be encoded by only storing differences between e.g., temporally adjacent frames (inter-frame coding) or spatially adjacent pixels (intra-frame coding). [Inter-frame](https://en.wikipedia.org/wiki/Inter-frame) compression (a temporal [delta encoding](https://en.wikipedia.org/wiki/Delta_encoding)) (re)uses data from one or more earlier or later frames in a sequence to describe the current frame. [Intra-frame coding](https://en.wikipedia.org/wiki/Intra-frame_coding), on the other hand, uses only data from within the current frame, effectively being still-image compression.[^o101]

The [intra-frame video coding formats](https://en.wikipedia.org/wiki/Video_coding_format#Intra-frame_video_coding_formats) used in camcorders and video editing employ simpler compression that uses only intra-frame prediction. This simplifies video editing software, as it prevents a situation in which a compressed frame refers to data that the editor has deleted.

Usually, video compression additionally employs [lossy compression](https://en.wikipedia.org/wiki/Lossy_compression) techniques like [quantization](https://en.wikipedia.org/wiki/Quantization_%28image_processing%29) that reduce aspects of the source data that are (more or less) irrelevant to the human visual perception by exploiting perceptual features of human vision. For example, small differences in color are more difficult to perceive than are changes in brightness. Compression algorithms can average a color across these similar areas in a manner similar to those used in JPEG image compression.[^o87] As in all lossy compression, there is a [trade-off](https://en.wikipedia.org/wiki/Trade-off) between [video quality](https://en.wikipedia.org/wiki/Video_quality) and [bit rate](https://en.wikipedia.org/wiki/Bit_rate), cost of processing the compression and decompression, and system requirements. Highly compressed video may present visible or distracting [artifacts](https://en.wikipedia.org/wiki/Compression_artifact).

Other methods other than the prevalent DCT-based transform formats, such as [fractal compression](wikipedia://en/60022), [matching pursuit](wikipedia://en/5534001) and the use of a [discrete wavelet transform](wikipedia://en/857564) (DWT), have been the subject of some research, but are typically not used in practical products. [Wavelet compression](https://en.wikipedia.org/wiki/Wavelet_compression) is used in still-image coders and video coders without motion compensation. Interest in fractal compression seems to be waning, due to recent theoretical analysis showing a comparative lack of effectiveness of such methods.[^o101]

##### Inter-frame coding {#Inter-frame_coding}

In inter-frame coding, individual frames of a video sequence are compared from one frame to the next, and the [video compression codec](https://en.wikipedia.org/wiki/Video_codec) records the [differences](https://en.wikipedia.org/wiki/Residual_frame) to the reference frame. If the frame contains areas where nothing has moved, the system can simply issue a short command that copies that part of the previous frame into the next one. If sections of the frame move in a simple manner, the compressor can emit a (slightly longer) command that tells the decompressor to shift, rotate, lighten, or darken the copy. This longer command still remains much shorter than data generated by intra-frame compression. Usually, the encoder will also transmit a residue signal which describes the remaining, more subtle differences to the reference imagery. Using entropy coding, these residue signals have a more compact representation than the full signal. In areas of video with more motion, the compression must encode more data to keep up with the larger number of pixels that are changing. Commonly, the high-frequency detail of explosions, flames, flocks of animals, and some panning shots will lead to decreases in quality or increases in the [variable bitrate](https://en.wikipedia.org/wiki/Variable_bitrate).

#### Hybrid block-based transform formats {#Hybrid_block-based_transform_formats}

*Image: Hybrid video encoder processing stages.svg.* Processing stages of a typical video encoder

Many commonly used video compression methods (e.g., those in standards approved by the [ITU-T](https://en.wikipedia.org/wiki/ITU-T) or [ISO](https://en.wikipedia.org/wiki/ISO)) share the same basic architecture that dates back to [H.261](https://en.wikipedia.org/wiki/H.261), which was standardized in 1988 by the ITU-T. They mostly rely on the DCT, applied to rectangular blocks of neighboring pixels, and temporal prediction using [motion vectors](https://en.wikipedia.org/wiki/Motion_vector), as well as nowadays also an in-loop filtering step.

In the prediction stage, various [deduplication](https://en.wikipedia.org/wiki/Data_deduplication) and difference-coding techniques are applied that help decorrelate data and describe new data based on already transmitted data.

Then, rectangular blocks of remaining [pixel](https://en.wikipedia.org/wiki/Pixel) data are transformed to the frequency domain. In the main lossy processing stage, frequency domain data gets quantized in order to reduce information that is irrelevant to human visual perception.

In the last stage, statistical redundancy gets largely eliminated by an [entropy coder](https://en.wikipedia.org/wiki/Entropy_coder), which often applies some form of arithmetic coding.

In an additional in-loop filtering stage, various filters can be applied to the reconstructed image signal. By computing these filters also inside the encoding loop, they can help compression because they can be applied to reference material before it gets used in the prediction process and they can be guided using the original signal. The most popular example are [deblocking filters](https://en.wikipedia.org/wiki/Deblocking_filter) that blur out blocking artifacts from quantization discontinuities at transform block boundaries.

#### History {#History}

In 1967, A.H. Robinson and C. Cherry proposed a [run-length encoding](wikipedia://en/26392) bandwidth compression scheme for the transmission of analog television signals.[^o62] The DCT, which is fundamental to modern video compression,[^o64] was introduced by [Nasir Ahmed](https://en.wikipedia.org/wiki/N._Ahmed), T. Natarajan and [K. R. Rao](https://en.wikipedia.org/wiki/K._R._Rao) in 1974.[^o105][^o112]

[H.261](https://en.wikipedia.org/wiki/H.261), which debuted in 1988, commercially introduced the prevalent basic architecture of video compression technology.[^o63] It was the first [video coding format](https://en.wikipedia.org/wiki/Video_coding_format) based on DCT compression.[^o64] H.261 was developed by a number of companies, including [Hitachi](https://en.wikipedia.org/wiki/Hitachi), [PictureTel](https://en.wikipedia.org/wiki/PictureTel), [NTT](https://en.wikipedia.org/wiki/Nippon_Telegraph_and_Telephone), [BT](https://en.wikipedia.org/wiki/BT_plc) and [Toshiba](https://en.wikipedia.org/wiki/Toshiba).[^o65]

The most popular [video coding standards](https://en.wikipedia.org/wiki/Video_coding_standard) used for codecs have been the [MPEG](https://en.wikipedia.org/wiki/MPEG) standards. [MPEG-1](https://en.wikipedia.org/wiki/MPEG-1) was developed by the [Motion Picture Experts Group](https://en.wikipedia.org/wiki/Motion_Picture_Experts_Group) (MPEG) in 1991, and it was designed to compress [VHS](https://en.wikipedia.org/wiki/VHS)-quality video. It was succeeded in 1994 by [MPEG-2](https://en.wikipedia.org/wiki/MPEG-2)/[H.262](https://en.wikipedia.org/wiki/H.262),[^o63] which was developed by a number of companies, primarily [Sony](https://en.wikipedia.org/wiki/Sony), [Thomson](https://en.wikipedia.org/wiki/Technicolor_SA) and [Mitsubishi Electric](https://en.wikipedia.org/wiki/Mitsubishi_Electric).[^o66] MPEG-2 became the standard video format for [DVD](https://en.wikipedia.org/wiki/DVD) and [SD digital television](https://en.wikipedia.org/wiki/SD_digital_television).[^o63] In 1999, it was followed by [MPEG-4](https://en.wikipedia.org/wiki/MPEG-4_Visual)/[H.263](https://en.wikipedia.org/wiki/H.263).[^o63] It was also developed by a number of companies, primarily Mitsubishi Electric, [Hitachi](https://en.wikipedia.org/wiki/Hitachi) and [Panasonic](https://en.wikipedia.org/wiki/Panasonic).[^o67]

[H.264/MPEG-4 AVC](https://en.wikipedia.org/wiki/H.264/MPEG-4_AVC) was developed in 2003 by a number of organizations, primarily Panasonic, [Godo Kaisha IP Bridge](https://en.wikipedia.org/wiki/Godo_kaisha) and [LG Electronics](https://en.wikipedia.org/wiki/LG_Electronics).[^o68] AVC commercially introduced the modern [context-adaptive binary arithmetic coding](https://en.wikipedia.org/wiki/Context-adaptive_binary_arithmetic_coding) (CABAC) and [context-adaptive variable-length coding](https://en.wikipedia.org/wiki/Context-adaptive_variable-length_coding) (CAVLC) algorithms. AVC is the main video encoding standard for [Blu-ray Discs](https://en.wikipedia.org/wiki/Blu-ray_Disc), and is widely used by video sharing websites and streaming internet services such as [YouTube](https://en.wikipedia.org/wiki/YouTube), [Netflix](https://en.wikipedia.org/wiki/Netflix), [Vimeo](https://en.wikipedia.org/wiki/Vimeo), and [iTunes Store](https://en.wikipedia.org/wiki/ITunes_Store), web software such as [Adobe Flash Player](https://en.wikipedia.org/wiki/Adobe_Flash_Player) and [Microsoft Silverlight](https://en.wikipedia.org/wiki/Microsoft_Silverlight), and various [HDTV](https://en.wikipedia.org/wiki/HDTV) broadcasts over terrestrial and satellite television.[^o69]

### Genetics {#Genetics}

[Genetics compression algorithms](https://en.wikipedia.org/wiki/Genetics_compression_algorithms) are the latest generation of lossless algorithms that compress data (typically sequences of nucleotides) using both conventional compression algorithms and genetic algorithms adapted to the specific datatype. In 2012, a team of scientists from Johns Hopkins University published a genetic compression algorithm that does not use a reference genome for compression. HAPZIPPER was tailored for [HapMap](https://en.wikipedia.org/wiki/HapMap) data and achieves over 20-fold compression (95% reduction in file size), providing 2- to 4-fold better compression and is less computationally intensive than the leading general-purpose compression utilities. For this, Chanda, Elhaik, and Bader introduced MAF-based encoding (MAFE), which reduces the heterogeneity of the dataset by sorting SNPs by their minor allele frequency, thus homogenizing the dataset.[^o113] Other algorithms developed in 2009 and 2013 (DNAZip and GenomeZip) have compression ratios of up to 1200-fold—allowing 6 billion basepair diploid human genomes to be stored in 2.5 megabytes (relative to a reference genome or averaged over many genomes).[^o114][^o115] For a benchmark in genetics/genomics data compressors, see [^o116]

## Outlook and currently unused potential {#Outlook_and_currently_unused_potential}

It is estimated that the total amount of data that is stored on the world's storage devices could be further compressed with existing compression algorithms by a remaining average factor of 4.5:1.[^o73] It is estimated that the combined technological capacity of the world to store information provides 1,300 [exabytes](https://en.wikipedia.org/wiki/Exabytes) of hardware digits in 2007, but when the corresponding content is optimally compressed, this only represents 295 exabytes of [Shannon information](https://en.wikipedia.org/wiki/Shannon_information).[^o117]
