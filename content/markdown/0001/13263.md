# Hexadecimal

::: {#o1 .subject cue=lead name="Hexadecimal"}

3

**Hexadecimal** (**hex** for short) is a [positional numeral system](wikipedia://en/21170#Positional_systems_in_detail) for representing a numeric value as [base](wikipedia://en/701207) 16. For the most common convention, a digit is represented as "0" to "9" like for [decimal](wikipedia://en/8214) and as a letter of the alphabet from "A" to "F" (either upper or lower case) for the digits with decimal value 10 to 15.

:::

As typical [computer hardware](https://en.wikipedia.org/wiki/Computer_hardware) is [binary](wikipedia://en/238686) in nature and that hex is [power of 2](https://en.wikipedia.org/wiki/Power_of_2), the hex representation is often used in [computing](https://en.wikipedia.org/wiki/Computing) as a dense representation of [binary information](https://en.wikipedia.org/wiki/Binary_code). A hex digit represents 4 contiguous [bits](https://en.wikipedia.org/wiki/Bit) –known as a [nibble](https://en.wikipedia.org/wiki/Nibble).[^o2] An 8-bit [byte](https://en.wikipedia.org/wiki/Byte) is two hex digits, such as 2C.

Special notation is often used to indicate that a number is hex. In [mathematics](wikipedia://en/18831), a subscript is typically used to specify the base. For example, the decimal value 491 would be expressed in hex as 491. In [computer programming](https://en.wikipedia.org/wiki/Computer_programming), various notations are used. In [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) and many related languages, the prefix `0x` is used. For example, `0x{{hexadecimal|491|no}}`.

## Written representation {#Written_representation}

### Common convention {#Common_convention}

Typically, a hex representation convention allows either lower or upper case letters and treats the letter the same regardless of its case.

Often when rendering non-textual data, a value stored in memory is displayed as a sequence of hex digits with spaces between values. For instance, in the following [hex dump](https://en.wikipedia.org/wiki/Hex_dump), each 8-bit [byte](https://en.wikipedia.org/wiki/Byte) is a 2-digit hex number, with spaces between them, while the 32-bit offset at the start is an 8-digit hex number.

```hexdump
00000000  57 69 6B 69 70 65 64 69  61 2C 20 74 68 65 20 66
00000010  72 65 65 20 65 6E 63 79  63 6C 6F 70 65 64 69 61
00000020  20 74 68 61 74 20 61 6E  79 6F 6E 65 20 63 61 6E
00000030  20 65 64 69 74 2C 20 69  6E 63 6C 75 64 69 6E 67
00000040  20 79 6F 75 20 28 61 6E  64 20 6D 65 29 21
```

### Identification {#Identification}

There are several conventions for expressing that a number is represented as hex.

- A decimal subscript can give the base explicitly. For example 159<sub>10</sub> indicates decimal 159, 159<sub>16</sub> indicates hex 159. Some prefer a text subscript, such as 159<sub>decimal</sub> and 159<sub>hex</sub>, or 159<sub>d</sub> and 159<sub>h</sub>
- In C and many languages influenced by it, the prefix `0x` indicates that the numeric literal after it is in hex, a character of a string or character literal can be expressed as hex with the prefix `\x` (for example `'\x1B'` represents the [Esc](https://en.wikipedia.org/wiki/Escape_character) control character) and to output an integer as hex via [printf](https://en.wikipedia.org/wiki/Printf)-like function, the format conversion code `%X` or `%x` is used
- In [URIs](https://en.wikipedia.org/wiki/URI) (including [URLs](https://en.wikipedia.org/wiki/URL)), [character codes](https://en.wikipedia.org/wiki/Character_encoding) are written as hex pairs prefixed with %: http://www.example.com/name%20with%20spaces where %20 is the code for the [space (blank)](https://en.wikipedia.org/wiki/Space_%28punctuation%29#Space_characters_and_digital_typography) character, [ASCII](https://en.wikipedia.org/wiki/ASCII) code point 20 in hex, 32 in decimal.
- In [XML](https://en.wikipedia.org/wiki/XML) and [XHTML](https://en.wikipedia.org/wiki/XHTML), a character can be expressed as a hex [numeric character reference](https://en.wikipedia.org/wiki/Numeric_character_reference) using the notation `&#x''code'';`, for instance `&#x0054;` represents the character U+0054 (the uppercase letter "T"). If there is no x the number is decimal (thus `&#0084;` is the same character).[^o6]
- In Intel-derived [assembly languages](https://en.wikipedia.org/wiki/Assembly_language) and Modula-2,[^o7] hex is denoted with a suffixed H or h: `FFh` or `05A3H`. Some implementations require a leading zero when the first hex digit character is not a decimal digit, so one would write `0FFh` instead of `FFh`. Some other implementations (such as NASM) allow C-style numbers (`0x42`)
- Other assembly languages ([6502](https://en.wikipedia.org/wiki/MOS_Technology_6502), [Motorola](https://en.wikipedia.org/wiki/Motorola)), [Pascal](https://en.wikipedia.org/wiki/Pascal_%28programming_language%29), [Delphi](https://en.wikipedia.org/wiki/Delphi_%28programming_language%29), some versions of [BASIC](https://en.wikipedia.org/wiki/BASIC) ([Commodore](https://en.wikipedia.org/wiki/Commodore_BASIC)), [GameMaker Language](https://en.wikipedia.org/wiki/GameMaker_Studio), [Godot](https://en.wikipedia.org/wiki/Godot_%28game_engine%29) and [Forth](https://en.wikipedia.org/wiki/Forth_%28programming_language%29) use `$` as a prefix: `$5A3`, `$C1F27ED`
- Some assembly languages (Microchip) use the notation `H'ABCD'` (for ABCD<sub>16</sub>); similarly, [Fortran 95](https://en.wikipedia.org/wiki/Fortran_95_language_features) uses Z'ABCD'
- [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29) and [VHDL](https://en.wikipedia.org/wiki/VHDL) enclose hex numerals in based "numeric quotes": `16#5A3#`, `16#C1F27ED#`. For bit vector constants [VHDL](https://en.wikipedia.org/wiki/VHDL) uses the notation `x"5A3"`, `x"C1F27ED"`.[^o8]
- [Verilog](https://en.wikipedia.org/wiki/Verilog) represents hex constants in the form `8'hFF`, where 8 is the number of bits in the value and FF is the hex constant
- The [Icon](https://en.wikipedia.org/wiki/Icon_%28programming_language%29) and [Smalltalk](https://en.wikipedia.org/wiki/Smalltalk) languages use the prefix `16r`: `16r5A3`
- [PostScript](https://en.wikipedia.org/wiki/PostScript) and the [Bourne shell](https://en.wikipedia.org/wiki/Bourne_shell) and its derivatives denote hex with prefix `16#`: `16#5A3`, `16#C1F27ED`
- [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp) uses the prefixes `#x` and `#16r`. Setting the variables \*read-base\*[^o9] and \*print-base\*[^o10] to 16 can also be used to switch the reader and printer of a Common Lisp system to hex representation for reading and printing numbers. Thus hex numbers can be represented without the #x or #16r prefix code, when the input or output base has been changed to 16.
- [MSX BASIC](https://en.wikipedia.org/wiki/MSX_BASIC),[^o11] [QuickBASIC](https://en.wikipedia.org/wiki/QuickBASIC), [FreeBASIC](https://en.wikipedia.org/wiki/FreeBASIC) and [Visual Basic](https://en.wikipedia.org/wiki/Visual_Basic) prefix hex numbers with `&H`: `&H5A3`
- [BBC BASIC](https://en.wikipedia.org/wiki/BBC_BASIC) and [Locomotive BASIC](https://en.wikipedia.org/wiki/Locomotive_BASIC) use `&` for hex[^o12]
- [TI-89](https://en.wikipedia.org/wiki/TI-89) and 92 series uses a `0h` prefix: `0h5A3`, `0hC1F27ED`
- [ALGOL 68](https://en.wikipedia.org/wiki/ALGOL_68) uses the prefix `16r` to denote hex numbers: `16r5a3`, `16rC1F27ED`. Binary, quaternary (base-4), and octal numbers can be specified similarly.
- The most common format for hex on IBM mainframes ([zSeries](https://en.wikipedia.org/wiki/ZSeries)) and midrange computers ([IBM i](https://en.wikipedia.org/wiki/IBM_i)) running the traditional OS's ([zOS](https://en.wikipedia.org/wiki/Z/OS), [zVSE](https://en.wikipedia.org/wiki/VSE_%28operating_system%29), [zVM](https://en.wikipedia.org/wiki/Z/VM), [TPF](https://en.wikipedia.org/wiki/Transaction_Processing_Facility), [IBM i](https://en.wikipedia.org/wiki/IBM_i)) is `X'5A3'` or `X'C1F27ED'`, and is used in Assembler, [PL/I](https://en.wikipedia.org/wiki/PL/I), [COBOL](https://en.wikipedia.org/wiki/COBOL), [JCL](https://en.wikipedia.org/wiki/Job_Control_Language), scripts, commands and other places. This format was common on other (and now obsolete) IBM systems as well. Occasionally quotation marks were used instead of apostrophes.
- [Donald Knuth](wikipedia://en/8095) used a [typewriter typeface](https://en.wikipedia.org/wiki/Monospaced_font) to represent hex in his book *The TeXbook*,[^o13] like: 5A3, C1F27ED

### Implicit {#Implicit}

In some contexts, a number is always written as hex, and therefore, needs no identification notation.

- In the [Unicode](https://en.wikipedia.org/wiki/Unicode) standard, a character value is represented with U+ followed by the hex value, e.g. U+00A1 is the [inverted exclamation point](https://en.wikipedia.org/wiki/Inverted_exclamation_point) (¡).
- [Color references](https://en.wikipedia.org/wiki/Web_colors) in HTML, [CSS](https://en.wikipedia.org/wiki/Cascading_Style_Sheets) and [X Window](https://en.wikipedia.org/wiki/X_window_system) can be expressed with six hex digits (two each for the red, green and blue components, in that order) prefixed with #: magenta, for example, is represented as #FF00FF.[^o15] CSS also allows 3-hexdigit abbreviations with one hexdigit per component: #FA3 abbreviates #FFAA33, a golden orange.
- In [MIME](https://en.wikipedia.org/wiki/MIME) (e-mail extensions) [quoted-printable](https://en.wikipedia.org/wiki/Quoted-printable) encoding, character codes are written as hex pairs prefixed with =: Espa=F1a is "España" (F1${}_{\operatorname{hex}}$ is the code for *ñ* in the ISO/IEC 8859-1 character set).[^o16])
- PostScript binary data (such as image [pixels](https://en.wikipedia.org/wiki/Pixel)) can be expressed as unprefixed consecutive hex pairs: AA213FD51B3801043FBC ...
- Any [IPv6 address](https://en.wikipedia.org/wiki/IPv6_address) can be written as eight groups of four hex digits (sometimes called [hextets](https://en.wikipedia.org/wiki/Hextet_%28computing%29)), where each group is separated by a colon (:). This, for example, is a valid IPv6 address: 2001:0db8:85a3:0000:0000:8a2e:0370:7334 or abbreviated by removing leading zeros as 2001:db8:85a3::8a2e:370:7334 ([IPv4 addresses](https://en.wikipedia.org/wiki/IPv4_address) are usually written in decimal).
- [Globally unique identifiers](https://en.wikipedia.org/wiki/Globally_unique_identifier) are written as thirty-two hex digits, often in unequal hyphen-separated groupings, for example 3F2504E0-4F89-41D3-9A0C-0305E82C3301.

### Alternative symbols {#Alternative_symbols}

*Image: Bruce Martin hexadecimal notation proposal.svg.* Bruce Alan Martin's hex notation proposal[^o19]

*Image: Base-16 digits.svg.* Ronald O. Whitaker's hex notation proposal.[^o20][^o21]

Notable other hexadecimal representations that use symbols other than letters "A" through "F" to represent the digits above 9 include:

- During the 1950s, some installations, such as Bendix-14, favored using the digits 0 through 5 with an [overline](wikipedia://en/4780165) to denote the values 10–15 as $\overline{0}$, $\overline{1}$, $\overline{2}$, $\overline{3}$, $\overline{4}$ and $\overline{5}$.
- The [SWAC](https://en.wikipedia.org/wiki/SWAC_%28computer%29) (1950)[^o78] and [Bendix G-15](https://en.wikipedia.org/wiki/Bendix_G-15) (1956)[^o79][^o78] computers used the lowercase letters *u*, *v*, *w*, *x*, *y* and *z* for the values 10 to 15.
- The [ORDVAC](https://en.wikipedia.org/wiki/ORDVAC) and [ILLIAC I](https://en.wikipedia.org/wiki/ILLIAC_I) (1952) computers (and some derived designs, e.g. [BRLESC](https://en.wikipedia.org/wiki/BRLESC)) used the uppercase letters *K*, *S*, *N*, *J*, *F* and *L* for the values 10 to 15.[^o80][^o78]
- The Librascope [LGP-30](https://en.wikipedia.org/wiki/LGP-30) (1956) used the letters *F*, *G*, *J*, *K*, *Q* and *W* for the values 10 to 15.[^o81][^o78]
- On the [PERM](https://en.wikipedia.org/wiki/PERM_%28computer%29) (1956) computer, hex numbers were written as letters *O* for zero, *A* to *N* and *P* for 1 to 15. Many machine instructions had mnemonic hex-codes (*A*=add, *M*=multiply, *L*=load, *F*=fixed-point etc.); programs were written without instruction names.[^o82]
- The [Honeywell](https://en.wikipedia.org/wiki/Honeywell) [Datamatic D-1000](https://en.wikipedia.org/wiki/Datamatic_D-1000) (1957) used the lowercase letters *b*, *c*, *d*, *e*, *f*, and *g* whereas the [Elbit](https://en.wikipedia.org/wiki/Elbit) 100 (1967) used the uppercase letters *B*, *C*, *D*, *E*, *F* and *G* for the values 10 to 15.[^o78]
- The [Monrobot XI](https://en.wikipedia.org/wiki/Monrobot_XI) (1960) used the letters *S*, *T*, *U*, *V*, *W* and *X* for the values 10 to 15.[^o78]
- The [NEC](https://en.wikipedia.org/wiki/NEC) [parametron](https://en.wikipedia.org/wiki/Parametron) computer NEAC 1103 (1960) used the letters *D*, *G*, *H*, *J*, *K* (and possibly *V*) for values 10–15.[^o18]
- The [Pacific Data Systems](https://en.wikipedia.org/wiki/Pacific_Data_Systems) 1020 (1964) used the letters *L*, *C*, *A*, *S*, *M* and *D* for the values 10 to 15.[^o78]
- New numeric symbols and names were introduced in the [Bibi-binary](wikipedia://en/52016575) notation by [Boby Lapointe](https://en.wikipedia.org/wiki/Boby_Lapointe) in 1968.
- Bruce Alan Martin of [Brookhaven National Laboratory](https://en.wikipedia.org/wiki/Brookhaven_National_Laboratory) considered the choice of A–F "ridiculous". In a 1968 letter to the editor of the [CACM](https://en.wikipedia.org/wiki/Communications_of_the_ACM), he proposed an entirely new set of symbols based on the bit locations.[^o19]
- In 1972, Ronald O. Whitaker of Rowco Engineering Co. proposed a triangular font that allows "direct binary reading" to "permit both input and output from computers without respect to encoding matrices".[^o20][^o21]
- Some [seven-segment display](https://en.wikipedia.org/wiki/Seven-segment_display) decoder chips (i.e., 74LS47) show unexpected output due to logic designed only to produce 0–9 correctly.[^o22]

### Sign {#Sign}

The hex system can express negative numbers the same way as in decimal, by putting a minus sign (−) before the number to indicate that it is negative.

### Bit pattern {#Bit_pattern}

Hex can express the bit pattern in a [processor](https://en.wikipedia.org/wiki/Central_processing_unit), so a sequence of hex digits may represent a [signed](https://en.wikipedia.org/wiki/Signedness) or even a [floating-point](wikipedia://en/11376) value. This way, the negative number −42<sub>10</sub> can be written as FFFF FFD6 in a 32-bit [CPU register](https://en.wikipedia.org/wiki/Processor_register) (in [two's complement](https://en.wikipedia.org/wiki/Two's_complement)), as C228 0000 in a 32-bit [FPU](https://en.wikipedia.org/wiki/Floating-point_unit) register or C045 0000 0000 0000 in a 64-bit FPU register (in the [IEEE floating-point standard](https://en.wikipedia.org/wiki/IEEE_floating-point_standard)).

### Exponential notation {#Exponential_notation}

Just as decimal numbers can be represented in [exponential notation](https://en.wikipedia.org/wiki/Exponential_notation), so too can hex numbers. [P notation](https://en.wikipedia.org/wiki/P_notation) uses the letter *P* (or *p*, for "power"), whereas *E* (or *e*) serves a similar purpose in decimal [E notation](https://en.wikipedia.org/wiki/E_notation). The number after the *P* is *decimal* and represents the *binary* exponent. Increasing the exponent by 1 multiplies by 2, not 16: 20p0 = 10p1 = 8p2 = 4p3 = 2p4 = 1p5. Usually, the number is normalized so that the hex digits start with 1. (zero is usually 0 with no *P*).

Example: 1.3DEp42 represents $1.3\operatorname{DE}_{16}\,\times\,2^{42_{10}}$.

P notation is required by the [IEEE 754-2008](https://en.wikipedia.org/wiki/IEEE_754-2008) binary floating-point standard and can be used for floating-point literals in the [C99](https://en.wikipedia.org/wiki/C99) edition of the [C programming language](https://en.wikipedia.org/wiki/C_%28programming_language%29).[^o26] Using the *%a* or *%A* conversion specifiers, this notation can be produced by implementations of the *[printf](https://en.wikipedia.org/wiki/Printf)* family of functions following the C99 specification[^o27] and [Single Unix Specification](https://en.wikipedia.org/wiki/Single_UNIX_Specification) (IEEE Std 1003.1) [POSIX](https://en.wikipedia.org/wiki/POSIX) standard.[^o28]

## Verbal representation {#Verbal_representation}

*Image: Hexadecimal-counting.jpg.* Hex finger-counting scheme

Most European languages lack non-decimal-based words for some of the numerals eleven to fifteen. Some people read hex numbers digit by digit, like a phone number, or using the [NATO phonetic alphabet](https://en.wikipedia.org/wiki/ICAO_spelling_alphabet), the [Joint Army/Navy Phonetic Alphabet](https://en.wikipedia.org/wiki/Joint_Army/Navy_Phonetic_Alphabet), or a similar [ad hoc](https://en.wikipedia.org/wiki/Ad_hoc) system. In the wake of the adoption of hex among [IBM System/360](https://en.wikipedia.org/wiki/IBM_System/360) programmers, Magnuson (1968)[^o30] suggested a pronunciation guide that gave short names to the letters of hex – for instance, "A" was pronounced "ann", B "bet", C "chris", etc.[^o30] Another naming-system was published online by Rogers (2007)[^o31] that tries to make the verbal representation distinguishable in any case, even when the actual number does not contain numbers A–F. Examples are listed in the tables below. Yet another naming system was elaborated by Babb (2015), based on a joke in *[Silicon Valley](https://en.wikipedia.org/wiki/Silicon_Valley_%28TV_series%29)*.[^o32]

Others have proposed using the verbal [Morse code](https://en.wikipedia.org/wiki/Morse_code) conventions to express four-bit hex digits, with "dit" and "dah" representing zero and one, respectively, so that "0000" is voiced as "dit-dit-dit-dit" (....), "dah-dit-dit-dah" (-..-) voices the digit with a value of nine, and "dah-dah-dah-dah" (----) voices the hex digit for decimal 15.

Systems of counting on [digits](https://en.wikipedia.org/wiki/Digit_%28anatomy%29) have been devised for both binary and hex. [Arthur C. Clarke](https://en.wikipedia.org/wiki/Arthur_C._Clarke) suggested using each finger as an on/off bit, allowing finger counting from zero to 1023<sub>10</sub> on ten fingers.[^o33] Another system for counting up to FF<sub>16</sub> (255<sub>10</sub>) is illustrated on the right.

## Conversion {#Conversion}

### Binary conversion {#Binary_conversion}

*Image: Hewlett-Packard Model HP-16C Programmable RPN Calculator, HP's First and Only Calculator esp. for Programmers, built 1982-1989 (edited to rectangular, V2).jpg.* The programmable [RPN](wikipedia://en/26513)-calculator [HP-16C Computer Scientist](https://en.wikipedia.org/wiki/HP-16C) from 1982 was designed for programmers. One of its key features was the conversion between different numeral systems (note hex number in display).

Most computers manipulate binary data, but it is difficult for humans to work with a large number of digits for even a relatively small binary number. Although most humans are familiar with the base 10 system, it is much easier to map binary to hex than to decimal because each hex digit maps to a whole number of bits (4<sub>10</sub>). This example converts 1111<sub>2</sub> to base ten. Since each [position](wikipedia://en/437052) in a binary numeral can contain either a 1 or a 0, its value may be easily determined by its position from the right:

- 0001<sub>2</sub> = 1<sub>10</sub>
- 0010<sub>2</sub> = 2<sub>10</sub>
- 0100<sub>2</sub> = 4<sub>10</sub>
- 1000<sub>2</sub> = 8<sub>10</sub>

Therefore:

| 1111<sub>2</sub> | \= 8<sub>10</sub> + 4<sub>10</sub> + 2<sub>10</sub> + 1<sub>10</sub> |
|---|---|
|  | \= 15<sub>10</sub> |

With little practice, mapping 1111<sub>2</sub> to F<sub>16</sub> in one step becomes easy. The advantage of using hex rather than decimal increases rapidly with the size of the number. When the number becomes large, conversion to decimal is very tedious. However, when mapping to hex, it is trivial to regard the binary string as 4-digit groups and map each to a single hex digit.[^o39]

This example shows the conversion of a binary number to decimal, mapping each digit to the decimal value, and adding the results.

| (1001011100)<sub>2</sub> | \= 512<sub>10</sub> + 64<sub>10</sub> + 16<sub>10</sub> + 8<sub>10</sub> + 4<sub>10</sub> |
|---|---|
|  | \= 604<sub>10</sub> |

Compare this to the conversion to hex, where each group of four digits can be considered independently and converted directly:

| (1001011100)<sub>2</sub> | \= | 0010 | 0101 | 1100<sub>2</sub> |  |  |
|---|---|---|---|---|---|---|
|  | \= | 2 | 5 | C<sub>16</sub> |  |  |
|  | \= | 25C<sub>16</sub> |  |  |  |  |

The conversion from hex to binary is equally direct.[^o39]

### Other simple conversions {#Other_simple_conversions}

Although [quaternary](wikipedia://en/357685) (base 4) is little used, it can easily be converted to and from hex or binary. Each hex digit corresponds to a pair of quaternary digits, and each quaternary digit corresponds to a pair of binary digits. In the above example 2 5 C<sub>16</sub> = 02 11 30<sub>4</sub>.

The [octal](wikipedia://en/22330) (base 8) system can also be converted with relative ease, although not quite as trivially as with bases 2 and 4. Each octal digit corresponds to three binary digits, rather than four. Therefore, we can convert between octal and hex via an intermediate conversion to binary followed by regrouping the binary digits in groups of either three or four.

### Division-remainder in source base {#Division-remainder_in_source_base}

As with all bases there is a simple [algorithm](wikipedia://en/775) for converting a representation of a number to hex by doing integer division and remainder operations in the source base. In theory, this is possible from any base, but for most humans, only decimal and for most computers, only binary (which can be converted by far more efficient methods) can be easily handled with this method.

Let d be the number to represent in hex, and the series h<sub>i</sub>h<sub>i−1</sub>...h<sub>2</sub>h<sub>1</sub> be the hex digits representing the number.

1. i ← 1
1. h<sub>i</sub> ← d mod 16
1. d ← (d − h<sub>i</sub>) / 16
1. If d = 0 (return series h<sub>i</sub>) else increment i and go to step 2

"16" may be replaced with any other base that may be desired.

The following is a [JavaScript](https://en.wikipedia.org/wiki/JavaScript) implementation of the above algorithm for converting any number to a hex in String representation. Its purpose is to illustrate the above algorithm. To work with data seriously, however, it is much more advisable to work with [bitwise operators](https://en.wikipedia.org/wiki/Bitwise_operators).

```javascript
function toHex(d) {
  var r = d % 16;
  if (d - r == 0) {
    return toChar(r);
  }
  return toHex((d - r) / 16) + toChar(r);
}

function toChar(n) {
  const alpha = "0123456789ABCDEF";
  return alpha.charAt(n);
}
```

### Conversion through addition and multiplication {#Conversion_through_addition_and_multiplication}

*Image: Hexadecimal multiplication table.svg.* A hex [multiplication table](wikipedia://en/57122)

It is also possible to make the conversion by assigning each place in the source base the hex representation of its place value –before carrying out multiplication and addition to get the final representation. For example, to convert the number B3AD to decimal, one can split the hex number into its digits: B (11<sub>10</sub>), 3 (3<sub>10</sub>), A (10<sub>10</sub>) and D (13<sub>10</sub>), and then get the final result by multiplying each decimal representation by 16<sup>*p*</sup> (*p* being the corresponding hex digit position, counting from right to left, beginning with 0). In this case, we have that:

$$B3\operatorname{AD} = (11\,\times\,16^{3}) + (3\,\times\,16^{2}) + (10\,\times\,16^{1}) + (13\,\times\,16^{0})$$

which is 45997 in base 10.

## Elementary arithmetic {#Elementary_arithmetic}

Elementary operations such as division can be carried out indirectly through conversion to an alternate [numeral system](wikipedia://en/21170), such as the commonly used decimal system or the binary system where each hex digit corresponds to four binary digits.

Alternatively, one can also perform elementary operations directly within the hex system itself –by relying on its addition/multiplication tables and its corresponding standard algorithms such as [long division](wikipedia://en/313384) and the traditional subtraction algorithm.

## Real numbers {#Real_numbers}

### Rational numbers {#Rational_numbers}

As with other numeral systems, the hex system can be used to represent [rational numbers](wikipedia://en/19727024), although [repeating expansions](wikipedia://en/13612447) are common since sixteen (10<sub>16</sub>) has only a single prime factor: two.

For any base, 0.1 (or "1/10") is always equivalent to one divided by the representation of that base value in its own number system. Thus, whether dividing one by two for [binary](https://en.wikipedia.org/wiki/Binary_numeral_system) or dividing one by sixteen for hex, both of these fractions are written as `0.1`. Because the radix 16 is a [perfect square](wikipedia://en/213919) (4<sup>2</sup>), fractions expressed in hex have an odd period much more often than decimal ones, and there are no [cyclic numbers](wikipedia://en/1672489) (other than trivial single digits). Recurring digits are exhibited when the denominator in lowest terms has a [prime factor](https://en.wikipedia.org/wiki/Prime_factor) not found in the radix; thus, when using hex notation, all fractions with denominators that are not a [power of two](wikipedia://en/376948) result in an infinite string of recurring digits (such as thirds and fifths). This makes hex (and binary) less convenient than [decimal](wikipedia://en/8214) for representing rational numbers since a larger proportion lies outside its range of finite representation.

All rational numbers finitely representable in hex are also finitely representable in decimal, [duodecimal](wikipedia://en/8400) and [sexagesimal](wikipedia://en/135316): that is, any hex number with a finite number of digits also has a finite number of digits when expressed in those other bases. Conversely, only a fraction of those finitely representable in the latter bases are finitely representable in hex. For example, decimal 0.1 corresponds to the infinite recurring representation 0.1$\overline{9}$ in hex. However, hex is more efficient than duodecimal and sexagesimal for representing fractions with powers of two in the denominator. For example, 0.0625<sub>10</sub> (one-sixteenth) is equivalent to 0.1<sub>16</sub>, 0.09<sub>12</sub>, and 0;3,45<sub>60</sub>.

## Cultural history {#Cultural_history}

The traditional [Chinese units of measurement](https://en.wikipedia.org/wiki/Chinese_units_of_measurement) were base-16. For example, one jīn (斤) in the old system equals sixteen [taels](https://en.wikipedia.org/wiki/Tael). The [suanpan](wikipedia://en/956258) (Chinese [abacus](wikipedia://en/655)) can be used to perform hex calculations such as additions and subtractions.[^o61]

As with the [duodecimal](wikipedia://en/8400) system, there have been occasional attempts to promote hex as the preferred numeral system. These attempts often propose specific pronunciation and symbols for the individual numerals.[^o62] Some proposals unify standard measures so that they are multiples of 16.[^o63][^o64] An early such proposal was put forward by [John W. Nystrom](https://en.wikipedia.org/wiki/John_W._Nystrom) in *Project of a New System of Arithmetic, Weight, Measure and Coins: Proposed to be called the Tonal System, with Sixteen to the Base*, published in 1862.[^o65] Nystrom among other things suggested [hexadecimal time](https://en.wikipedia.org/wiki/Hexadecimal_time), which subdivides a day by 16, so that there are 16 "hours" (or "10 *tims*", pronounced *tontim*) in a day.[^o66]

The word *hexadecimal* is first recorded in 1952.[^o67] It is [macaronic](https://en.wikipedia.org/wiki/Macaronic) in the sense that it combines [Greek](https://en.wikipedia.org/wiki/Greek_language) ἕξ (hex) "six" with [Latinate](https://en.wikipedia.org/wiki/Latin) *\-decimal*. The all-Latin alternative *sexadecimal* (compare the word *[sexagesimal](wikipedia://en/135316)* for base 60) is older, and sees at least occasional use from the late 19th century.[^o68] It is still in use in the 1950s in [Bendix](https://en.wikipedia.org/wiki/Bendix_Corporation) documentation. Schwartzman (1994) argues that use of *sexadecimal* may have been avoided because of its suggestive abbreviation to *sex*.[^o69] Many western languages since the 1960s have adopted terms equivalent in formation to *hexadecimal* (e.g. French *hexadécimal*, Italian *esadecimale*, Romanian *hexazecimal*, Serbian *хексадецимални*, etc.) but others have introduced terms which substitute native words for "sixteen" (e.g. Greek δεκαεξαδικός, Icelandic *sextándakerfi*, Russian *шестнадцатеричной* etc.)

Terminology and notation did not become settled until the end of the 1960s. In 1969, [Donald Knuth](wikipedia://en/8095) argued that the etymologically correct term would be *senidenary*, or possibly *sedenary*, a Latinate term intended to convey "grouped by 16" modelled on *binary*, *ternary*, *quaternary*, etc. According to Knuth's argument, the correct terms for *decimal* and *octal* arithmetic would be *denary* and *octonary*, respectively.[^o70] Alfred B. Taylor used *senidenary* in his mid-1800s work on alternative number bases, although he rejected base 16 because of its "incommodious number of digits".[^o71][^o72]

The now-current notation using the letters A to F establishes itself as the de facto standard beginning in 1966, in the wake of the publication of the [Fortran IV](https://en.wikipedia.org/wiki/Fortran_IV) manual for [IBM System/360](https://en.wikipedia.org/wiki/IBM_System/360), which (unlike earlier variants of Fortran) recognizes a standard for entering hexadecimal constants.[^o73] As noted above, alternative notations were used by [NEC](https://en.wikipedia.org/wiki/NEC) (1960) and The Pacific Data Systems 1020 (1964). The standard adopted by IBM seems to have become widely adopted by 1968, when Bruce Alan Martin in his letter to the editor of the [CACM](https://en.wikipedia.org/wiki/Communications_of_the_ACM) complains that With the ridiculous choice of letters A, B, C, D, E, F as hexadecimal number symbols adding to already troublesome problems of distinguishing octal (or hex) numbers from decimal numbers (or variable names), the time is overripe for reconsideration of our number symbols. This should have been done before poor choices gelled into a de facto standard! Martin's argument was that use of numerals 0 to 9 in nondecimal numbers "imply to us a base-ten place-value scheme": "Why not use entirely new symbols (and names) for the seven or fifteen nonzero digits needed in octal or hex. Even use of the letters A through P would be an improvement, but entirely new symbols could reflect the binary nature of the system".[^o19] He also argued that "re-using alphabetic letters for numerical digits represents a gigantic backward step from the invention of distinct, non-alphabetic glyphs for numerals sixteen centuries ago" (as [Brahmi numerals](wikipedia://en/1903587), and later in a [Hindu–Arabic numeral system](wikipedia://en/3393371)), and that the recent [ASCII](https://en.wikipedia.org/wiki/ASCII) standards (ASA X3.4-1963 and USAS X3.4-1968) "should have preserved six code table positions following the ten decimal digits -- rather than needlessly filling these with punctuation characters" (":;\<=>?") that might have been placed elsewhere among the 128 available positions.

::: {#o75 .pointer-item cue=pointer name="Base16"}

## Base16 {#Base16}

**Base16** is a [binary to text encoding](https://en.wikipedia.org/wiki/Binary_to_text_encoding) in the family that also contains [Base32](https://en.wikipedia.org/wiki/Base32), [Base58](https://en.wikipedia.org/wiki/Base58), and [Base64](https://en.wikipedia.org/wiki/Base64). Data is broken into 4-bit sequences, and each value (0-15) is encoded as a character. Although any 16 characters could be used, in practice, the [ASCII](https://en.wikipedia.org/wiki/ASCII) digits "0"–"9" and letters "A"–"F" (or "a"–"f") are used to align with the typical notation for hex numbers.

Support for Base16 encoding is ubiquitous in modern computing. It is the basis for the [W3C](https://en.wikipedia.org/wiki/World_Wide_Web_Consortium) standard for [URL percent encoding](https://en.wikipedia.org/wiki/Percent-encoding), where a character is replaced with a percent sign "%" and its Base16-encoded form. Most modern programming languages directly include support for formatting and parsing Base16-encoded numbers.

Advantages of Base16 encoding include:

- Most programming languages have facilities to parse ASCII-encoded hex
- Being exactly half a byte, 4-bits is easier to process than the 5 or 6 bits of Base32 and Base64, respectively
- The notation is well-known and easily understood without needing a symbol lookup table
- Many CPU architectures have dedicated instructions that allow access to a half-byte (aka nibble), making it more efficient in hardware than Base32 and Base64

Disadvantages include:

- Space efficiency is only 50%, since each 4-bit value from the original data will be encoded as an 8-bit byte; in contrast, Base32 and Base64 encodings have a space efficiency of 63% and 75% respectively
- Complexity of accepting both upper and lower case letters
