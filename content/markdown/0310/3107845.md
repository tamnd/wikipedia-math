# Klee's measure problem

::: {#o1 .subject cue=lead name="Klee's measure problem"}

*Image: Set a rectangles (Klee's Trevis).svg.* A set of rectangular ranges ('trellis') whose area has to be measured.

In [computational geometry](wikipedia://en/176927), **Klee's measure problem** is the problem of determining how efficiently the [measure](wikipedia://en/19873) of a [union](wikipedia://en/47949) of ([multidimensional](wikipedia://en/8398)) rectangular ranges can be computed. Here, a *d*-dimensional rectangular range is defined to be a [Cartesian product](wikipedia://en/24104095) of *d* [intervals](wikipedia://en/49172) of [real numbers](wikipedia://en/20646438), which is a [subset](wikipedia://en/27631) of **R**<sup>*d*</sup>.

:::

The problem is named after [Victor Klee](https://en.wikipedia.org/wiki/Victor_Klee), who gave an algorithm for computing the length of a union of intervals (the case *d* = 1) which was later shown to be optimally efficient in the sense of [computational complexity theory](wikipedia://en/7543). The computational complexity of computing the area of a union of 2-dimensional rectangular ranges is now also known, but the case *d* ≥ 3 remains an [open problem](wikipedia://en/1333335).

## History and algorithms {#History_and_algorithms}

In 1977, [Victor Klee](https://en.wikipedia.org/wiki/Victor_Klee) considered the following problem: given a collection of *n* [intervals](wikipedia://en/49172) in the [real line](https://en.wikipedia.org/wiki/Real_line), compute the length of their union. He then presented an [algorithm](wikipedia://en/775) to solve this problem with [computational complexity](wikipedia://en/2230) (or "running time") $O(n \log n)$ — see [Big O notation](wikipedia://en/44578) for the meaning of this statement. This algorithm, based on [sorting](https://en.wikipedia.org/wiki/Sorting) the intervals, was later shown by [Michael Fredman](https://en.wikipedia.org/wiki/Michael_Fredman) and Bruce Weide (1978) to be optimal.

Later in 1977, [Jon Bentley](https://en.wikipedia.org/wiki/Jon_Bentley_%28computer_scientist%29) considered a 2-dimensional analogue of this problem: given a collection of *n* [rectangles](wikipedia://en/70048), find the [area](https://en.wikipedia.org/wiki/Area_%28geometry%29) of their union. He also obtained a complexity $O(n \log n)$ algorithm, now known as **Bentley's algorithm**, based on reducing the problem to *n* *1*-dimensional problems: this is done by sweeping a vertical line across the area. Using this method, the area of the union can be computed without explicitly constructing the union itself. Bentley's algorithm is now also known to be optimal (in the 2-dimensional case), and is used in [computer graphics](https://en.wikipedia.org/wiki/Computer_graphics), among other areas.

These two problems are the 1- and 2-dimensional cases of a more general question: given a collection of *n* *d*-dimensional rectangular ranges, compute the measure of their union. This general problem is Klee's measure problem.

When generalized to the *d*-dimensional case, Bentley's algorithm has a running time of $O(n^{d-1} \log n)$. This turns out *not* to be optimal, because it only decomposes the *d*-dimensional problem into *n* (*d-1*)-dimensional problems, and does not further decompose those subproblems. In 1981, [Jan van Leeuwen](https://en.wikipedia.org/wiki/Jan_van_Leeuwen) and Derek Wood improved the running time of this algorithm to $O(n^{d-1})$ for *d* ≥ 3 by using dynamic [quadtrees](https://en.wikipedia.org/wiki/Quadtree).

In 1988, [Mark Overmars](https://en.wikipedia.org/wiki/Mark_Overmars) and Chee Yap proposed an $O(n^{d/2} \log n)$ algorithm for *d* ≥ 3. Their algorithm uses a particular [data structure](wikipedia://en/8519) similar to a [kd-tree](https://en.wikipedia.org/wiki/Kd-tree) to decompose the problem into 2-dimensional components and aggregate those components efficiently; the 2-dimensional problems themselves are solved efficiently using a [trellis](https://en.wikipedia.org/wiki/Trellis_%28graph%29) structure. Although asymptotically faster than Bentley's algorithm, its data structures use significantly more space, so it is only used in problems where either *n* or *d* is large. In 1998, Bogdan Chlebus proposed a simpler algorithm with the same asymptotic running time for the common special cases where *d* is 3 or 4.

In 2013, [Timothy M. Chan](https://en.wikipedia.org/wiki/Timothy_M._Chan) developed a simpler algorithm that avoids the need for dynamic data structures and eliminates the logarithmic factor, lowering the best known running time for d ≥ 3 to $O(n^{d/2})$.

## Known bounds {#Known_bounds}

The only known [lower bound](https://en.wikipedia.org/wiki/Lower_bound) for any *d* is $\Omega(n \log n)$, and optimal algorithms with this running time are known for *d*=1 and *d*=2. The Chan algorithm provides an upper bound of $O(n^{d/2})$ for *d* ≥ 3, so for *d* ≥ 3, it remains an open question whether faster algorithms are possible, or alternatively whether tighter lower bounds can be proven. In particular, it remains open whether the algorithm's running time must depend on *d*. In addition, the question of whether there are faster algorithms that can deal with special cases (for example, when the input coordinates are integers within a bounded range) remains open.

The 1D Klee's measure problem (union of intervals) can be solved in $O(n \log p)$ where *p* denotes the number of piercing points required to [stab](https://en.wikipedia.org/wiki/Stabbing_set) all intervals[^o4] (the union of intervals pierced by a common point can be calculated in linear time by computing the extrema). Parameter *p* is an adaptive parameter that depends on the input configuration, and the piercing algorithm[^o5] yields an [adaptive algorithm](https://en.wikipedia.org/wiki/Adaptive_algorithm) for Klee's measure problem.
