# DNS over HTTPS

::: {#o1 .subject cue=lead name="DNS over HTTPS"}

**DNS over HTTPS** (**DoH**) is a protocol for performing remote Domain Name System (DNS) resolution via the [HTTPS](wikipedia://en/13586) protocol. A goal of the method is to increase user privacy and security by preventing eavesdropping and manipulation of DNS data by [man-in-the-middle attacks](https://en.wikipedia.org/wiki/Man-in-the-middle_attacks)[^o3] by using the HTTPS protocol to [encrypt](https://en.wikipedia.org/wiki/Encrypt) the data between the DoH client and the DoH-based [DNS resolver](https://en.wikipedia.org/wiki/DNS_resolver).[^o4] By March 2018, [Google](https://en.wikipedia.org/wiki/Google) and the [Mozilla Foundation](https://en.wikipedia.org/wiki/Mozilla_Foundation) had started testing versions of DNS over HTTPS.[^o5][^o6] In February 2020, [Firefox](https://en.wikipedia.org/wiki/Firefox) switched to DNS over HTTPS by default for users in the United States.[^o7] In May 2020, [Chrome](https://en.wikipedia.org/wiki/Google_Chrome) switched to DNS over HTTPS by default.[^o8]

:::

An alternative to DoH is the [DNS over TLS](https://en.wikipedia.org/wiki/DNS_over_TLS) (DoT) protocol, a similar standard for encrypting [DNS](https://en.wikipedia.org/wiki/DNS) queries, differing only in the methods used for encryption and delivery. Based on privacy and security, whether either protocol is superior is a matter of debate, while others argue that the merits of either depend on the specific use case.[^o9]

## Technical details {#Technical_details}

DoH is a proposed standard, published as 8484 (October 2018) by the [IETF](https://en.wikipedia.org/wiki/IETF). It uses [HTTPS](wikipedia://en/13586), and supports the *wire format* DNS response data, as returned in existing UDP responses, in an HTTPS payload with the [MIME type](https://en.wikipedia.org/wiki/MIME_type) *application/dns-message*.[^o3][^o11] The underlying HTTP layer can be any version of HTTP, though [HTTP/2](https://en.wikipedia.org/wiki/HTTP/2) is the *recommended* minimum.[^o11] If HTTP/2 is used, the server may also use [HTTP/2 server push](https://en.wikipedia.org/wiki/HTTP/2_server_push) to send values that it anticipates the client may find useful in advance.[^o11]

DoH is a work in progress. Even though the IETF has published RFC 8484 as a proposed standard and companies are experimenting with it,[^o12][^o13] the IETF has yet to determine how it should best be implemented. The IETF is evaluating a number of approaches for how best to deploy DoH and has established a working group, [Adaptive DNS Discovery (ADD)](https://datatracker.ietf.org/wg/add/about/), to do this work and develop a consensus.

Since DoH cannot be used under some circumstances, like [captive portals](https://en.wikipedia.org/wiki/Captive_portals), web browsers like Firefox can be configured to fall back to insecure DNS.[^o14]

The de facto DoH URL is *https://host\_name/dns-query*.

::: {#o16 .pointer-item cue=pointer name="ODoH"}

## Oblivious DNS over HTTPS {#Oblivious_DNS_over_HTTPS}

Oblivious DNS over HTTPS (ODoH) is an experimental standard, published as 9230 (June 2022) by the [IETF](https://en.wikipedia.org/wiki/IETF), proposing a protocol extension to ensure no single DoH server is aware of both the client's IP address and the content of their DNS queries and responses.[^o17] This is an application of a security principle called decoupling or privacy partitioning.[^o18][^o19] A different protocol with the same name (Oblivious DoH) was originally developed as Oblivious DNS (ODNS) by researchers at [Princeton University](https://en.wikipedia.org/wiki/Princeton_University) and the [University of Chicago](https://en.wikipedia.org/wiki/University_of_Chicago) as an extension to unencrypted DNS,[^o20] before DoH itself was standardized and widely deployed. [Apple](https://en.wikipedia.org/wiki/Apple_Inc.) and [Cloudflare](https://en.wikipedia.org/wiki/Cloudflare) subsequently deployed the technology in the context of DoH, as Oblivious DoH (ODoH).[^o21][^o24]

In ODoH and ODNS, all DNS requests and responses are routed via a proxy, hiding the client's address from the resolver. Requests and responses are encrypted to hide their contents from the proxy, and only the resolver can decrypt the requests, and the client the responses. Thus, the proxy knows the client address and resolver but not the request, and the resolver knows the proxy and request but not the client address, preventing the client address being linked to the query, unless both the proxy and resolver servers collude.[^o22][^o23][^o24] Another protocol, [Oblivious HTTP](wikipedia://en/79378523), uses similar architectural principles for [HTTP](https://en.wikipedia.org/wiki/HTTP) requests.[^o19]

:::

## Deployment scenarios {#Deployment_scenarios}

DoH is used for recursive DNS resolution by [DNS resolvers](https://en.wikipedia.org/wiki/Recursive_DNS_resolver). Resolvers (*DoH clients*) must have access to a DoH server hosting a query endpoint.[^o26]

Three usage scenarios are common:

- Using a DoH implementation within an application: Some browsers have a built-in DoH implementation and can thus perform queries by bypassing the operating system's DNS functionality. A drawback is that an application may not inform the user if it skips DoH querying, either by misconfiguration or lack of support for DoH.
- Installing a DoH proxy on the name server in the local network: In this scenario client systems continue to use traditional (port 53 or 853) DNS to query the name server in the local network, which will then gather the necessary replies via DoH by reaching DoH-servers in the Internet. This method is transparent to the end user.
- Installing a DoH proxy on a local system: In this scenario, operating systems are configured to query a locally running DoH proxy. In contrast to the previously mentioned method, the proxy needs to be installed on each system wishing to use DoH, which might require a lot of effort in larger environments.

## Software support {#Software_support}

### Operating systems {#Operating_systems}

#### Apple {#Apple}

[Apple's](https://en.wikipedia.org/wiki/Apple_Inc.) [iOS 14](https://en.wikipedia.org/wiki/IOS_14) and [macOS 11](https://en.wikipedia.org/wiki/MacOS_11) released in late 2020 support both DoH and [DoT](https://en.wikipedia.org/wiki/DNS_over_TLS) protocols.[^o30][^o31] In iOS, the protocols can be used via configuration profiles.

#### Windows {#Windows}

In November 2019, [Microsoft](https://en.wikipedia.org/wiki/Microsoft) announced plans to implement support for encrypted DNS protocols in [Microsoft Windows](https://en.wikipedia.org/wiki/Microsoft_Windows), beginning with DoH.[^o33] In May 2020, Microsoft released Windows 10 Insider Preview Build 19628 that included initial support for DoH[^o34] along with instructions on how to enable it via [registry](https://en.wikipedia.org/wiki/Windows_Registry) and [command line interface](https://en.wikipedia.org/wiki/Command-line_interface).[^o35] Windows 10 Insider Preview Build 20185 added a graphical user interface for specifying a DoH resolver.[^o36] DoH support is not included in Windows 10 21H2.[^o37]

[Windows 11](https://en.wikipedia.org/wiki/Windows_11) has DoH support.[^o38]

#### Android {#Android}

Android 11 onwards supports DNS over [HTTP/3](https://en.wikipedia.org/wiki/HTTP/3) (DoH3) if a July 2022 system update is installed.[^o40]

### Recursive DNS resolvers {#Recursive_DNS_resolvers}

#### BIND {#BIND}

[BIND 9](https://en.wikipedia.org/wiki/BIND), an open source DNS resolver from [Internet Systems Consortium](https://en.wikipedia.org/wiki/Internet_Systems_Consortium) added native support for DoH in version 9.17.10.[^o43]

#### PowerDNS {#PowerDNS}

DNSdist, an open source DNS proxy/load balancer from [PowerDNS](https://en.wikipedia.org/wiki/PowerDNS), added native support for DoH in version 1.4.0 in April 2019.[^o45]

#### Unbound {#Unbound}

Unbound, an [open source](https://en.wikipedia.org/wiki/Open_source) DNS resolver created by [NLnet Labs](https://en.wikipedia.org/wiki/NLnet_Labs), has supported DoH since version 1.12.0, released in October 2020.[^o47][^o48] It first implemented support for [DNS](https://en.wikipedia.org/wiki/DNS) encryption using the alternative [DoT](https://en.wikipedia.org/wiki/DNS_over_TLS) protocol much earlier, starting with version 1.4.14, released in December 2011.[^o49][^o50] [Unbound](https://en.wikipedia.org/wiki/Unbound_%28DNS_server%29) runs on most [operating systems](https://en.wikipedia.org/wiki/Operating_system), including distributions of [Linux](https://en.wikipedia.org/wiki/Linux), [BSD](https://en.wikipedia.org/wiki/BSD), [MacOS](https://en.wikipedia.org/wiki/MacOS), and [Windows](https://en.wikipedia.org/wiki/Microsoft_Windows).

### Web browsers {#Web_browsers}

#### Google Chrome {#Google_Chrome}

DNS over HTTPS is available in [Google Chrome](https://en.wikipedia.org/wiki/Google_Chrome) 83 or later for Windows, Linux, and macOS, configurable via the settings page. When enabled, and the operating system is configured with a supported DNS server, Chrome will upgrade DNS queries to be encrypted.[^o53] It is also possible to manually specify a preset or custom DoH server to use within the user interface.[^o54]

In September 2020, Google Chrome for Android began staged rollout of DNS over HTTPS. Users can configure a custom resolver or disable DNS over HTTPS in settings.[^o55]

Google Chrome has five DNS-over-HTTPS providers pre-configured, which are [Google Public DNS](https://en.wikipedia.org/wiki/Google_Public_DNS), Cloudflare's [1.1.1.1](https://en.wikipedia.org/wiki/1.1.1.1), Quad9's [\9.9.9.9](https://en.wikipedia.org/wiki/Quad9), [NextDNS](https://en.wikipedia.org/wiki/NextDNS), and [CleanBrowsing](https://en.wikipedia.org/wiki/CleanBrowsing).[^o56]

#### Microsoft Edge {#Microsoft_Edge}

[Microsoft Edge](https://en.wikipedia.org/wiki/Microsoft_Edge) supports DNS over HTTPS, configurable via the settings page. When enabled, and the operating system is configured with a supported DNS server, Edge will upgrade DNS queries to be encrypted. It is also possible to manually specify a preset or custom DoH server to use within the user interface.[^o58]

#### Mozilla Firefox {#Mozilla_Firefox}

*Image: DNS over HTTPS information on Firefox 89 screenshot.png.* An example of DNS over HTTPS usage on Firefox 89

In 2018, [Mozilla](https://en.wikipedia.org/wiki/Mozilla) partnered with [Cloudflare](https://en.wikipedia.org/wiki/Cloudflare) to deliver DoH for [Firefox](https://en.wikipedia.org/wiki/Firefox) users that enable it (known as Trusted Recursive Resolver).[^o60] On February 25, 2020, Firefox started enabling DNS over HTTPS for all US-based users, relying on Cloudflare's resolver by default.[^o61]

#### Opera {#Opera}

[Opera](https://en.wikipedia.org/wiki/Opera_%28web_browser%29) supports DoH, configurable via the browser settings page.[^o63] By default, DNS queries are sent to Cloudflare servers.[^o64]

#### Brave {#Brave}

[Brave](https://en.wikipedia.org/wiki/Brave_%28web_browser%29) implemented DNS over HTTPS (DoH) by default for its desktop browser in version 1.4, released in April 2020, as part of its broader privacy-focused features to encrypt DNS queries and prevent third-party eavesdropping or manipulation. [^o66][^o67]

### Public DNS servers {#Public_DNS_servers}

DNS over HTTPS server implementations are already available free of charge by some public DNS providers.

## Implementation considerations {#Implementation_considerations}

Many issues with how to properly deploy DoH are still being resolved by the internet community including, but not limited to:

- Stopping third parties from analyzing DNS traffic for security purposes
- Disruption of [DNS](https://en.wikipedia.org/wiki/DNS)-level parental controls and content filters
- Split DNS in enterprise networks[^o70][^o71][^o72][^o73][^o74]
- CDN localization

### Analysis of DNS traffic for security purposes {#Analysis_of_DNS_traffic_for_security_purposes}

DoH can impede analysis and monitoring of DNS traffic for cybersecurity purposes; the 2019 [DDoS](https://en.wikipedia.org/wiki/Denial-of-service_attack) worm Godlua used DoH to mask connections to its command-and-control server.[^o76][^o77]

In January 2021, [NSA](wikipedia://en/21939) warned enterprises against using external DoH resolvers because they prevent DNS query filtering, inspection, and audit. Instead, NSA recommends configuring enterprise-owned DoH resolvers and blocking all known external DoH resolvers.[^o78]

### Disruption of content filters {#Disruption_of_content_filters}

DoH has been used to bypass [parental controls](https://en.wikipedia.org/wiki/Parental_controls) which operate at the (unencrypted) standard DNS level; however, there are DNS providers that offer filtering and parental controls along with support for DoH by operating DoH servers.[^o80]

The [Internet Service Providers Association](https://en.wikipedia.org/wiki/Internet_Service_Providers_Association_%28United_Kingdom%29) (ISPA)—a trade association representing British ISPs—and the also British body [Internet Watch Foundation](https://en.wikipedia.org/wiki/Internet_Watch_Foundation) have criticized [Mozilla](https://en.wikipedia.org/wiki/Mozilla), developer of the [Firefox](https://en.wikipedia.org/wiki/Firefox) [web browser](https://en.wikipedia.org/wiki/Web_browser), for supporting DoH, as they believe that it will undermine [web blocking](https://en.wikipedia.org/wiki/Web_blocking_in_the_United_Kingdom) programs in the country, including ISP default filtering of adult content, and mandatory court-ordered filtering of copyright violations. The ISPA nominated Mozilla for its "Internet Villain" award for 2019 (alongside the EU [Directive on Copyright in the Digital Single Market](https://en.wikipedia.org/wiki/Directive_on_Copyright_in_the_Digital_Single_Market), and [Donald Trump](https://en.wikipedia.org/wiki/Donald_Trump)), "for their proposed approach to introduce DNS-over-HTTPS in such a way as to bypass UK filtering obligations and parental controls, undermining internet safety standards in the UK." Mozilla responded to the allegations by the ISPA, arguing that it would not prevent filtering, and that they were "surprised and disappointed that an industry association for ISPs decided to misrepresent an improvement to decades-old internet infrastructure".[^o81][^o82] In response to the criticism, the ISPA apologized and withdrew the nomination.[^o83][^o84] Mozilla subsequently stated that DoH will not be used by default in the British market until further discussion with relevant stakeholders, but stated that it "would offer real security benefits to UK citizens".[^o85]
