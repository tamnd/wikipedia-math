# Offline private key protocol

::: {#o1 .subject cue=lead name="Offline private key protocol"}

The **Offline Private Key Protocol** (**OPKP**) is a [cryptographic protocol](wikipedia://en/591994) to prevent unauthorized access to [back up](https://en.wikipedia.org/wiki/Backup) or [archive](https://en.wikipedia.org/wiki/Archive) data. The protocol results in a [public key](https://en.wikipedia.org/wiki/Public_key) that can be used to encrypt data and an [offline private key](https://en.wikipedia.org/wiki/Offline_private_key) that can later be used to decrypt that data.

:::

The protocol is based on three rules regarding the key. An offline private key should:

- not be stored with the encrypted data (obviously)
- not be kept by the organization that physically stores the encrypted data, to ensure privacy
- not be stored at the same system as the original data, to avoid the possibility that theft of only the private key would give access to all data at the storage provider; and to avoid that when the key would be needed to restore a backup, the key would be lost together with the data loss that made the restore necessary in the first place

To comply with these rules, the offline private key protocol uses a method of asymmetric [key wrapping](https://en.wikipedia.org/wiki/Key_Wrap).

## Security {#Security}

As the protocol does not provide rules on the strength of the encryption methods and keys to be used, the security of the protocol depends on the actual cryptographic implementation. When used in combination with [strong encryption](https://en.wikipedia.org/wiki/Strong_encryption) methods, the protocol can provide extreme security.

## Operation {#Operation}

Initially:

1. a client program (program) on a system (local system) with data to back up or archive generates a random private key PRIV
1. program creates a public key PUB based on PRIV
1. program stores PUB on the local system
1. program presents PRIV to user who can store the key, e.g. printed as a [trusted paper key](https://en.wikipedia.org/wiki/Trusted_paper_key), or on a memory card
1. program destroys PRIV on the local system

When archiving or creating a backup, for each session or file:

1. program generates a one-time random key OTRK
1. program encrypts data using OTRK and a [symmetric encryption](https://en.wikipedia.org/wiki/Symmetric_encryption) method
1. program encrypts the (optionally [padded](wikipedia://en/592505)) key OTRK using PUB to OTRKCR
1. program stores the OTRKCR and the encrypted data to a server
1. program destroys OTRK on the local system
1. program destroys OTRKCR on the local system
1. the server stores OTRKCR and stores the encrypted data

To restore backed up or archived data:

1. user feeds PRIV into program
1. program downloads data with the respective OTRKCR
1. program decrypts OTRKCR using PRIV, giving OTRK
1. program can destroys PRIV on the local system
1. program decrypts data using OTRK
