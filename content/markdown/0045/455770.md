# Spanning tree

::: {#o1 .subject cue=lead name="Spanning tree"}

*Image: 4x4 grid spanning tree.svg.* A spanning tree (blue heavy edges) of a [grid graph](https://en.wikipedia.org/wiki/Grid_graph)

In the [mathematical](wikipedia://en/18831) field of [graph theory](wikipedia://en/12401), a **spanning tree** *T* of an [undirected graph](https://en.wikipedia.org/wiki/Undirected_graph) *G* is a subgraph that is a [tree](wikipedia://en/48560) which includes all of the [vertices](wikipedia://en/638899) of *G*.[^o2] In general, a graph may have several spanning trees, but a graph that is not [connected](https://en.wikipedia.org/wiki/Connected_graph) will not contain a spanning tree (see about spanning forests below). If all of the [edges](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) of *G* are also edges of a spanning tree *T* of *G*, then *G* is a tree and is identical to *T* (that is, a tree has a unique spanning tree and it is itself).

:::

::: {#o4 .application cue=heading name="Applications"}

## Applications {#Applications}

Several [pathfinding](https://en.wikipedia.org/wiki/Pathfinding) algorithms, including [Dijkstra's algorithm](wikipedia://en/45809) and the [A\* search algorithm](wikipedia://en/100558), internally build a spanning tree as an intermediate step in solving the problem.

In order to minimize the cost of power networks, wiring connections, piping, automatic speech recognition, etc., people often use algorithms that gradually build a spanning tree (or many such trees) as intermediate steps in the process of finding the [minimum spanning tree](wikipedia://en/41795).[^o5]

The Internet and many other [telecommunications networks](https://en.wikipedia.org/wiki/Telecommunications_network) have transmission links that connect nodes together in a [mesh topology](https://en.wikipedia.org/wiki/Mesh_topology) that includes some loops. In order to avoid [bridge loops](https://en.wikipedia.org/wiki/Bridge_loop) and [routing loops](https://en.wikipedia.org/wiki/Routing_loop), many routing protocols designed for such networks—including the [Spanning Tree Protocol](https://en.wikipedia.org/wiki/Spanning_Tree_Protocol), [Open Shortest Path First](https://en.wikipedia.org/wiki/Open_Shortest_Path_First), [Link-state routing protocol](https://en.wikipedia.org/wiki/Link-state_routing_protocol), [Augmented tree-based routing](https://en.wikipedia.org/wiki/Augmented_tree-based_routing), etc.—require each router to remember a spanning tree.[^o6]

A special kind of spanning tree, the [Xuong tree](wikipedia://en/56061994), is used in [topological graph theory](wikipedia://en/1631772) to find [graph embeddings](wikipedia://en/8149170) with maximum [genus](wikipedia://en/61891). A Xuong tree is a spanning tree such that, in the remaining graph, the number of connected components with an odd number of edges is as small as possible. A Xuong tree and an associated maximum-genus embedding can be found in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time).[^o7]

:::

## Definitions {#Definitions}

A tree is a [connected](https://en.wikipedia.org/wiki/Connected_graph) [undirected graph](https://en.wikipedia.org/wiki/Undirected_graph) with no [cycles](wikipedia://en/168609). It is a spanning tree of a graph *G* if it spans *G* (that is, it includes every vertex of *G*) and is a subgraph of *G* (every edge in the tree belongs to *G*). A spanning tree of a connected graph *G* can also be defined as a maximal set of edges of *G* that contains no cycle, or as a minimal set of edges that connect all vertices.

### Fundamental cycles {#Fundamental_cycles}

Adding just one edge to a spanning tree will create a cycle; such a cycle is called a **fundamental cycle** with respect to that tree. There is a distinct fundamental cycle for each edge not in the spanning tree; thus, there is a one-to-one correspondence between fundamental cycles and edges not in the spanning tree. For a connected graph with *V* vertices, any spanning tree will have *V* − 1 edges, and thus, a graph of *E* edges and one of its spanning trees will have *E* − *V* + 1 fundamental cycles (The number of edges subtracted by number of edges included in a spanning tree; giving the number of edges not included in the spanning tree). For any given spanning tree the set of all *E* − *V* + 1 fundamental cycles forms a [cycle basis](wikipedia://en/24778911), i.e., a basis for the [cycle space](wikipedia://en/262243).[^o11]

### Fundamental cutsets {#Fundamental_cutsets}

Dual to the notion of a fundamental cycle is the notion of a **fundamental cutset** with respect to a given spanning tree. By deleting just one edge of the spanning tree, the vertices are partitioned into two disjoint sets. The fundamental cutset is defined as the set of edges that must be removed from the graph *G* to accomplish the same partition. Thus, each spanning tree defines a set of *V* − 1 fundamental cutsets, one for each edge of the spanning tree.[^o13]

The duality between fundamental cutsets and fundamental cycles is established by noting that cycle edges not in the spanning tree can only appear in the cutsets of the other edges in the cycle; and *vice versa*: edges in a cutset can only appear in those cycles containing the edge corresponding to the cutset. This duality can also be expressed using the theory of [matroids](wikipedia://en/244321), according to which a spanning tree is a base of the [graphic matroid](wikipedia://en/745714), a fundamental cycle is the unique circuit within the set formed by adding one element to the base, and fundamental cutsets are defined in the same way from the [dual matroid](wikipedia://en/23515837).[^o14]

::: {#o16 .pointer-item cue=pointer name="Spanning forest"}

### Spanning forests {#Spanning_forests}

A collection of disjoint (unconnected) trees is described as a *[forest](https://en.wikipedia.org/wiki/Forest_%28graph_theory%29)*. A *spanning forest* in a graph is a subgraph that is a forest with an additional requirement. There are two incompatible requirements in use, of which one is relatively rare.

- Almost all graph theory books and articles define a spanning forest as a forest that spans all of the vertices, meaning only that each vertex of the graph is a vertex in the forest. A connected graph may have a disconnected spanning forest, such as the forest with no edges, in which each vertex forms a single-vertex tree.[^o17][^o18]
- A few graph theory authors define a spanning forest to be a maximal acyclic subgraph of the given graph, or equivalently a subgraph consisting of a spanning tree in each [connected component](https://en.wikipedia.org/wiki/Connected_component_%28graph_theory%29) of the graph.[^o19]

To avoid confusion between these two definitions, (Gross Yellen 2005) suggest the term "full spanning forest" for a spanning forest with the same number of components as the given graph (i.e., a maximal forest), while (Bondy Murty 2008) instead call this kind of forest a "maximal spanning forest" (which is redundant, as a maximal forest necessarily contains every vertex).[^o22]

## Counting spanning trees {#Counting_spanning_trees}

*Image: Cayley's formula 2-4.svg.* [Cayley's formula](wikipedia://en/1266713) counts the number of spanning trees on a complete graph. There are $2^{2-2}=1$ trees in $K_2$, $3^{3-2}=3$ trees in $K_3$, and $4^{4-2}=16$ trees in $K_4$.

The number *t*(*G*) of spanning trees of a connected graph is a well-studied [invariant](wikipedia://en/1126638).

### In specific graphs {#In_specific_graphs}

In some cases, it is easy to calculate *t*(*G*) directly:

- If *G* is itself a tree, then $t(G) = 1$.
- When *G* is the [cycle graph](wikipedia://en/878962) *C<sub>n</sub>* with *n* vertices, then $t(G) = n$.
- For a [complete graph](wikipedia://en/85816) with *n* vertices, [Cayley's formula](wikipedia://en/1266713)[^o25] gives the number of spanning trees as $n^{n - 2}$.
- If *G* is the [complete bipartite graph](wikipedia://en/525320) $K_{p,q}$,then $t(G)=p^{q-1}q^{p-1}$.[^o17]
- For the *n*-dimensional [hypercube graph](wikipedia://en/6706815) $Q_n$,[^o26] the number of spanning trees is $t(G)=2^{2^n-n-1}\prod_{k=2}^n k^{{n\choose k}}$.

### In arbitrary graphs {#In_arbitrary_graphs}

More generally, for any graph *G*, the number *t*(*G*) can be calculated in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) as the [determinant](wikipedia://en/8468) of a [matrix](wikipedia://en/20556859) derived from the graph, using [Kirchhoff's matrix-tree theorem](wikipedia://en/1270691).[^o28]

Specifically, to compute *t*(*G*), one constructs the [Laplacian matrix](wikipedia://en/1448472) of the graph, a square matrix in which the rows and columns are both indexed by the vertices of *G*. The entry in row *i* and column *j* is one of three values:

- The degree of vertex *i*, if *i* = *j*,
- −1, if vertices *i* and *j* are adjacent, or
- 0, if vertices *i* and *j* are different from each other but not adjacent.

The resulting matrix is [singular](wikipedia://en/245528), so its determinant is zero. However, deleting the row and column for an arbitrarily chosen vertex leads to a smaller matrix whose determinant is exactly *t*(*G*).

### Deletion-contraction {#Deletion-contraction}

If *G* is a graph or [multigraph](wikipedia://en/1774970) and *e* is an arbitrary edge of *G*, then the number *t*(*G*) of spanning trees of *G* satisfies the *deletion-contraction recurrence* *t*(*G*) = *t*(*G* − *e*) + *t*(*G*/*e*), where *G* − *e* is the multigraph obtained by deleting *e* and *G*/*e* is the [contraction](wikipedia://en/3758115) of *G* by *e*.[^o30] The term *t*(*G* − *e*) in this formula counts the spanning trees of *G* that do not use edge *e*, and the term *t*(*G*/*e*) counts the spanning trees of *G* that use *e*.

In this formula, if the given graph *G* is a [multigraph](wikipedia://en/1774970), or if a contraction causes two vertices to be connected to each other by multiple edges, then the redundant edges should not be removed, as that would lead to the wrong total. For instance a [bond graph](https://en.wikipedia.org/wiki/Bond_graph) connecting two vertices by *k* edges has *k* different spanning trees, each consisting of a single one of these edges.

### Tutte polynomial {#Tutte_polynomial}

The [Tutte polynomial](wikipedia://en/3892303) of a graph can be defined as a sum, over the spanning trees of the graph, of terms computed from the "internal activity" and "external activity" of the tree. Its value at the arguments (1,1) is the number of spanning trees or, in a disconnected graph, the number of maximal spanning forests.[^o32]

The Tutte polynomial can also be computed using a deletion-contraction recurrence, but its [computational complexity](wikipedia://en/7543) is high: for many values of its arguments, computing it exactly is [\#P-complete](https://en.wikipedia.org/wiki/Sharp-P-complete), and it is also hard to approximate with a guaranteed [approximation ratio](https://en.wikipedia.org/wiki/Approximation_ratio). The point (1,1), at which it can be evaluated using Kirchhoff's theorem, is one of the few exceptions.[^o33]

## Algorithms {#Algorithms}

::: {#o37 .definition kind=definition/construction cue=heading name="Construction"}

### Construction {#Construction}

A single spanning tree of a graph can be found in [linear time](https://en.wikipedia.org/wiki/Linear_time) by either [depth-first search](wikipedia://en/97034) or [breadth-first search](wikipedia://en/97026). Both of these algorithms explore the given graph, starting from an arbitrary vertex *v*, by looping through the neighbors of the vertices they discover and adding each unexplored neighbor to a data structure to be explored later. They differ in whether this data structure is a [stack](https://en.wikipedia.org/wiki/Stack_%28abstract_data_type%29) (in the case of depth-first search) or a [queue](https://en.wikipedia.org/wiki/Queue_%28abstract_data_type%29) (in the case of breadth-first search). In either case, one can form a spanning tree by connecting each vertex, other than the root vertex *v*, to the vertex from which it was discovered. This tree is known as a depth-first search tree or a breadth-first search tree according to the graph exploration algorithm used to construct it.[^o38] Depth-first search trees are a special case of a class of spanning trees called [Trémaux trees](wikipedia://en/30247317), named after the 19th-century discoverer of depth-first search.[^o39]

Spanning trees are important in parallel and distributed computing, as a way of maintaining communications between a set of processors; see for instance the [Spanning Tree Protocol](https://en.wikipedia.org/wiki/Spanning_Tree_Protocol) used by [OSI link layer](https://en.wikipedia.org/wiki/Data_link_layer) devices or the Shout (protocol) for distributed computing. However, the depth-first and breadth-first methods for constructing spanning trees on sequential computers are not well suited for parallel and distributed computers.[^o40] Instead, researchers have devised several more specialized algorithms for finding spanning trees in these models of computation.[^o41]

:::

### Optimization {#Optimization}

In certain fields of graph theory it is often useful to find a [minimum spanning tree](wikipedia://en/41795) of a [weighted graph](https://en.wikipedia.org/wiki/Weighted_graph). Other optimization problems on spanning trees have also been studied, including the maximum spanning tree, the minimum tree that spans at least k vertices, the [spanning tree with the fewest edges per vertex](wikipedia://en/2624629), the [spanning tree with the largest number of leaves](https://en.wikipedia.org/wiki/Maximum_leaf_spanning_tree), the spanning tree with the fewest leaves (closely related to the [Hamiltonian path problem](wikipedia://en/149646)), the [minimum-diameter spanning tree](https://en.wikipedia.org/wiki/Minimum-diameter_spanning_tree), and the minimum dilation spanning tree.[^o43][^o44]

Optimal spanning tree problems have also been studied for finite sets of points in a geometric space such as the [Euclidean plane](wikipedia://en/15575410). For such an input, a spanning tree is again a tree that has as its vertices the given points. The quality of the tree is measured in the same way as in a graph, using the [Euclidean distance](wikipedia://en/53932) between pairs of points as the weight for each edge. Thus, for instance, a [Euclidean minimum spanning tree](wikipedia://en/1040597) is the same as a graph minimum spanning tree in a [complete graph](wikipedia://en/85816) with Euclidean edge weights. However, it is not necessary to construct this graph in order to solve the optimization problem; the Euclidean minimum spanning tree problem, for instance, can be solved more efficiently in *O*(*n* log *n*) time by constructing the [Delaunay triangulation](wikipedia://en/8864) and then applying a linear time [planar graph](wikipedia://en/24314) minimum spanning tree algorithm to the resulting triangulation.[^o43]

### Randomization {#Randomization}

A spanning tree chosen [randomly](https://en.wikipedia.org/wiki/Random) from among all the spanning trees with equal probability is called a [uniform spanning tree](https://en.wikipedia.org/wiki/Uniform_spanning_tree). Wilson's algorithm can be used to generate uniform spanning trees in polynomial time by a process of taking a random walk on the given graph and erasing the cycles created by this walk.[^o46]

An alternative model for generating spanning trees randomly but not uniformly is the [random minimal spanning tree](https://en.wikipedia.org/wiki/Random_minimal_spanning_tree). In this model, the edges of the graph are assigned random weights and then the [minimum spanning tree](wikipedia://en/41795) of the weighted graph is constructed.[^o47]

::: {#o49 .definition kind=definition/construction cue=heading name="Enumeration"}

### Enumeration {#Enumeration}

Because a graph may have exponentially many spanning trees, it is not possible to list them all in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time). However, algorithms are known for listing all spanning trees in polynomial time per tree.[^o50]

:::

:::

## In infinite graphs {#In_infinite_graphs}

Every finite connected graph has a spanning tree. However, for infinite connected graphs, the existence of spanning trees is equivalent to the [axiom of choice](wikipedia://en/840). An infinite graph is connected if each pair of its vertices forms the pair of endpoints of a finite path. As with finite graphs, a tree is a connected graph with no finite cycles, and a spanning tree can be defined either as a maximal acyclic set of edges or as a tree that contains every vertex.[^o52]

The trees within a graph may be partially ordered by their subgraph relation, and any infinite chain in this partial order has an upper bound (the union of the trees in the chain). [Zorn's lemma](wikipedia://en/51442), one of many equivalent statements to the axiom of choice, requires that a partial order in which all chains are upper bounded have a maximal element; in the partial order on the trees of the graph, this maximal element must be a spanning tree. Therefore, if Zorn's lemma is assumed, every infinite connected graph has a spanning tree.[^o52]

In the other direction, given a [family of sets](wikipedia://en/723043), it is possible to construct an infinite connected graph such that every spanning tree of the graph corresponds to a [choice function](wikipedia://en/1432664) of the family of sets. Therefore, if every infinite connected graph has a spanning tree, then the axiom of choice is true.[^o53]

## In directed multigraphs {#In_directed_multigraphs}

The idea of a spanning tree can be generalized to directed multigraphs.[^o55] Given a vertex *v* on a directed multigraph *G*, an *oriented spanning tree* *T* rooted at *v* is an acyclic subgraph of *G* in which every vertex other than *v* has outdegree 1. This definition is only satisfied when the "branches" of *T* point towards *v*.
