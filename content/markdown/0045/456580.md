# Branch and bound

::: {#o1 .subject cue=lead name="Branch and bound"}

**Branch-and-bound** (**BB**, **B&B**, or **BnB**) is a method for solving optimization problems by breaking them down into smaller subproblems and using a bounding function to eliminate subproblems that cannot contain the optimal solution.

:::

It is an [algorithm](wikipedia://en/775) [design paradigm](https://en.wikipedia.org/wiki/Algorithmic_paradigm) for [discrete](wikipedia://en/420567) and [combinatorial optimization](wikipedia://en/420555) problems, as well as [mathematical optimization](wikipedia://en/52033). A branch-and-bound algorithm consists of a systematic enumeration of candidate solutions by means of [state-space search](https://en.wikipedia.org/wiki/State_space_search): the set of candidate solutions is thought of as forming a [rooted tree](wikipedia://en/48560) with the full set at the root.

The algorithm explores *branches* of this tree, which represent subsets of the solution set. Before enumerating the candidate solutions of a branch, the branch is checked against upper and lower estimated *bounds* on the optimal solution, and is discarded if it cannot produce a better solution than the best one found so far by the algorithm.

The algorithm depends on efficient estimation of the lower and upper bounds of regions/branches of the search space. If no bounds are available, then the algorithm degenerates to an exhaustive search.

The method was first proposed by [Ailsa Land](wikipedia://en/58693284) and [Alison Doig](wikipedia://en/58692342) whilst carrying out research at the [London School of Economics](https://en.wikipedia.org/wiki/London_School_of_Economics) sponsored by [British Petroleum](https://en.wikipedia.org/wiki/BP) in 1960 for [discrete programming](wikipedia://en/420567),[^o2][^o3] and has become the most commonly used tool for solving [NP-hard](https://en.wikipedia.org/wiki/NP-hard) optimization problems.[^o8] The name "branch and bound" first occurred in the work of Little *et al.* on the [traveling salesman problem](https://en.wikipedia.org/wiki/Traveling_salesman_problem).[^o16][^o4]

## Overview {#Overview}

The goal of a branch-and-bound algorithm is to find a value $x$ that maximizes or minimizes the value of a [real-valued function](wikipedia://en/22284647) $f(x)$, called an [objective function](wikipedia://en/442137), among some set $S$ of admissible or [candidate solutions](https://en.wikipedia.org/wiki/Candidate_solution). The set $S$ is called the search space, or [feasible region](wikipedia://en/9157119). The rest of this section assumes that minimization of $f(x)$ is desired; this assumption comes [without loss of generality](wikipedia://en/296000), since one can find the maximum value of $f(x)$ by finding the minimum of $g(x) = -f(x)$. A B&B algorithm operates according to two principles:

- It [recursively](wikipedia://en/25407) splits the search space into smaller spaces, then minimizes $f(x)$ on these smaller spaces; the splitting is called *branching*.
- Branching alone would amount to [brute-force](https://en.wikipedia.org/wiki/Brute-force_search) enumeration of candidate solutions and testing them all. To improve on the performance of brute-force search, a B&B algorithm keeps track of *bounds* on the minimum that it is trying to find, and uses these bounds to "[prune](https://en.wikipedia.org/wiki/Pruning_%28decision_trees%29)" the search space, eliminating candidate solutions that it can prove will not contain an optimal solution.

Turning these principles into a concrete algorithm for a specific optimization problem requires some kind of [data structure](wikipedia://en/8519) that represents sets of candidate solutions. Such a representation is called an *[instance](https://en.wikipedia.org/wiki/Instance_%28computer_science%29)* of the problem. Denote the set of candidate solutions of an instance $I$ by $S_{I}$. The instance representation has to come with three operations:

- $\operatorname{branch}(I)$ produces two or more instances that each represent a subset of $S_{I}$. (Typically, the subsets are [disjoint](wikipedia://en/39359) to prevent the algorithm from visiting the same candidate solution twice, but this is not required. However, an optimal solution among $S_{I}$ must be contained in at least one of the subsets.[^o6])
- $\operatorname{bound}(I)$ computes a lower bound on the value of any candidate solution in the space represented by $I$, that is, $\operatorname{bound}(I) \le f(x)$ for all $x$ in $S_{I}$.
- $\operatorname{solution}(I)$ determines whether $I$ represents a single candidate solution. (Optionally, if it does not, then the operation may choose to return some feasible solution from among $S_{I}$.) If $\operatorname{solution}(I)$ returns a solution, then $f(\operatorname{solution}(I))$ provides an upper bound for the optimal objective value over the whole space of feasible solutions.

Using these operations, a B&B algorithm performs a top-down recursive search through the [tree](https://en.wikipedia.org/wiki/Search_tree) of instances formed by the branch operation. Upon visiting an instance $I$, it checks whether $\operatorname{bound}(I)$ is equal to or greater than the current upper bound; if so, $I$ may be safely discarded from the search and the recursion stops. This pruning step is usually implemented by maintaining a [global variable](https://en.wikipedia.org/wiki/Global_variable) that records the minimum upper bound seen among all instances examined so far.

### Generic version {#Generic_version}

The following is the skeleton of a generic branch-and-bound algorithm for minimizing an arbitrary objective function $f$.[^o8] To obtain an actual algorithm from this, one requires a bounding function $\operatorname{bound}$, that computes lower bounds of $f$ on nodes of the [search tree](https://en.wikipedia.org/wiki/Search_tree), as well as a problem-specific branching rule.

1. Using a [heuristic](https://en.wikipedia.org/wiki/Heuristic), find a solution $x_{h}$ to the optimization problem. Store its value, $B = f(x_{h})$. (If no heuristic is available, set $B$ to infinity.) $B$ will denote the best solution found so far, and will be used as an upper bound on candidate solutions.
1. Initialize a queue to hold a partial solution with none of the variables of the problem assigned.
1. Loop until the queue is empty:
   1. Take a [node](https://en.wikipedia.org/wiki/Node_%28computer_science%29) $N$ off the queue.
   1. If $N$ represents a single candidate solution $x$ and $f(x) < B$, then $x$ is the best solution so far. Record it and set $B \leftarrow f(x)$. The same can be done with a [heuristic](https://en.wikipedia.org/wiki/Heuristic) whenever the node does not identify a unique solution.
   1. Else, *branch* on $N$ to produce new nodes $N_{i}$. Add all feasible nodes for which $\operatorname{bound}(N_{i}) < B$ to the queue. The remaining nodes, having a lower bound greater than or equal to the upper bound of the problem, will never lead to the optimal solution and are discarded.

Several different [queue](https://en.wikipedia.org/wiki/Queue_%28abstract_data_type%29) [data structures](wikipedia://en/8519) can be used. A [stack](https://en.wikipedia.org/wiki/Stack_%28data_structure%29) (LIFO queue) will yield a [depth-first](wikipedia://en/97034) algorithm. A [best-first](https://en.wikipedia.org/wiki/Best-first_search) branch-and-bound algorithm can be obtained by using a [priority queue](https://en.wikipedia.org/wiki/Priority_queue) that sorts nodes on their lower bounds.[^o8] The depth-first variant is recommended when no good heuristic is available for producing an initial solution, because it quickly produces full solutions, and therefore upper bounds.[^o9]

### Improvements {#Improvements}

When $\mathbf{x}$ is a vector of $\mathbb{R}^n$, branch-and-bound algorithms can be combined with [interval analysis](wikipedia://en/2176160)[^o11] and [contractor](wikipedia://en/39293339) techniques to provide guaranteed enclosures of the global minimum.[^o12][^o13]

## Applications {#Applications}

section This approach is used for a number of [NP-hard](https://en.wikipedia.org/wiki/NP-hard) problems:

- [Integer programming](wikipedia://en/411215)
- [Nonlinear programming](wikipedia://en/679709)
- [Travelling salesman problem](wikipedia://en/31248) (TSP)[^o16][^o17]
- [Quadratic assignment problem](wikipedia://en/1636520) (QAP)
- [Maximum satisfiability problem](https://en.wikipedia.org/wiki/Maximum_satisfiability_problem) (MAX-SAT)
- [Nearest neighbor search](https://en.wikipedia.org/wiki/Nearest_neighbor_search)[^o18] (by [Keinosuke Fukunaga](https://en.wikipedia.org/wiki/Keinosuke_Fukunaga))
- [Flow shop scheduling](https://en.wikipedia.org/wiki/Flow_shop_scheduling)
- [Cutting stock problem](wikipedia://en/826868)
- [Computational phylogenetics](wikipedia://en/3986130)
- [Set inversion](wikipedia://en/39157279)
- [Parameter estimation](wikipedia://en/39284847)
- [0/1 knapsack problem](https://en.wikipedia.org/wiki/0/1_knapsack_problem)
- [Set cover problem](wikipedia://en/870399)
- [Feature selection](wikipedia://en/1179950) in [machine learning](wikipedia://en/233488)[^o19][^o20]
- [Structured prediction](https://en.wikipedia.org/wiki/Structured_prediction) in [computer vision](https://en.wikipedia.org/wiki/Computer_vision)[^o21]
- [Arc routing problem](https://en.wikipedia.org/wiki/Arc_routing_problem), including the Chinese Postman problem
- [Talent Scheduling](https://en.wikipedia.org/wiki/Talent_Scheduling), scenes-shooting arrangement problem

Branch-and-bound may also be a base of various [heuristics](https://en.wikipedia.org/wiki/Heuristic). For example, one may wish to stop branching when the gap between the upper and lower bounds becomes smaller than a certain threshold. This is used when the solution is "good enough for practical purposes" and can greatly reduce the computations required. This type of solution is particularly applicable when the cost function used is [*noisy*](https://en.wikipedia.org/wiki/Noise) or is the result of [statistical estimates](wikipedia://en/26685) and so is not known precisely but rather only known to lie within a range of values with a specific [probability](wikipedia://en/22934).

## Relation to other algorithms {#Relation_to_other_algorithms}

Nau *et al.* present a generalization of branch and bound that also subsumes the [A\*](wikipedia://en/100558), [B\*](wikipedia://en/14993828) and [alpha-beta](wikipedia://en/159501) search algorithms.[^o23]

## Optimization example {#Optimization_example}

Branch-and-bound can be used to maximize $Z=5x_1+6x_2$ with the constraints

> $$x_1+x_2\leq 50$$
>
> $$4x_1+7x_2\leq280$$
>
> $$x_1, x_2\geq0$$
>
> $x_1$ and $x_2$ are integers.

The first step is to relax the integer constraint. We have two extreme points for the first equation that form a line: $\begin{bmatrix} x_1 \\ x_2 \end{bmatrix}=\begin{bmatrix}50 \\0\end{bmatrix}$ and $\begin{bmatrix}0 \\50\end{bmatrix}$. We can form the second line with the vector points $\begin{bmatrix}0\\40\end{bmatrix}$ and $\begin{bmatrix} 70\\0\end{bmatrix}$.

*Image: Branch and Bound optimization example with linear constraints in BricsCad Ultimate Academic Edition.png.* the two lines.

The third point is $\begin{bmatrix}0\\0\end{bmatrix}$. This is a [convex hull region](wikipedia://en/40634), so the solution lies on one of the vertices of the region. We can find the intersection using row reduction, which is $\begin{bmatrix}70/3\\80/3\end{bmatrix}$ with a value of 276 + 2/3. We test the other endpoints by sweeping the line over the region and find this is the maximum over the reals.

We choose the variable with the maximum fractional part, in this case $x_2$ becomes the parameter for the branch and bound method. We branch to $x_2\leq26$ and obtain 276 at $\langle 24,26\rangle$. We have reached an integer solution so we move to the other branch $x_2\geq27$. We obtain 275.75 at $\langle 22.75, 27\rangle$. We have a decimal, so we branch $x_1$ to $x_1\leq22$ and we find 274.571 at $\langle 22,27.4286\rangle$. We try the other branch $x_1\geq23$ and there are no feasible solutions. Therefore, the maximum is 276 with $x_1 = 24$ and $x_2 = 26$.
