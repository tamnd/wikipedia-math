# Random oracle

::: {#o1 .subject cue=lead name="Random oracle"}

In [cryptography](wikipedia://en/18934432), a **random oracle** is an [oracle](wikipedia://en/22431) (a theoretical [black box](https://en.wikipedia.org/wiki/Black_box_%28systems%29)) that responds to every *unique query* with a (truly) [random](https://en.wikipedia.org/wiki/Random) response chosen [uniformly](https://en.wikipedia.org/wiki/Uniform_distribution_%28discrete%29) from its output domain. If a query is repeated, it responds the [same way](https://en.wikipedia.org/wiki/Deterministic_algorithm) every time that query is submitted.

:::

Stated differently, a random oracle is a [mathematical function](https://en.wikipedia.org/wiki/Mathematical_function) chosen uniformly at random, that is, a function mapping each possible query to a (fixed) random response from its output domain.

Random oracles first appeared in the context of complexity theory, in which they were used to argue that complexity class separations may face relativization barriers, with the most prominent case being the [P vs NP problem](https://en.wikipedia.org/wiki/P_vs_NP_problem), two classes shown in 1981 to be distinct relative to a random oracle [almost surely](wikipedia://en/351908).[^o2] They made their way into cryptography by the publication of [Mihir Bellare](https://en.wikipedia.org/wiki/Mihir_Bellare) and [Phillip Rogaway](https://en.wikipedia.org/wiki/Phillip_Rogaway) in 1993, which introduced them as a formal cryptographic model to be used in reduction proofs.[^o3]

They are typically used when the proof cannot be carried out using weaker assumptions on the [cryptographic hash function](wikipedia://en/439526). A system that is proven secure when every hash function is replaced by a random oracle is described as being secure in the **random oracle model**, a differentiation from being secure in the [standard model of cryptography](wikipedia://en/4488342).

::: {#o5 .application cue=heading name="Applications"}

## Applications {#Applications}

Random oracles are typically used as an [idealised](https://en.wikipedia.org/wiki/Platonic_ideal) replacement for [cryptographic hash functions](wikipedia://en/439526) in schemes where strong randomness assumptions are needed of the hash function's output. Such a proof often shows that a system or a protocol is secure by showing that an attacker must require impossible behavior from the oracle, or solve some mathematical problem believed [hard](wikipedia://en/54681) in order to break it. However, it only proves such properties in the random oracle model, making sure no major design flaws are present. It is in general not true that such a proof implies the same properties in the standard model. Still, a proof in the random oracle model is considered better than no formal security proof at all.[^o6]

Not all uses of cryptographic hash functions require random oracles: schemes that require only one or more properties having a definition in the [standard model](wikipedia://en/4488342) (such as [collision resistance](wikipedia://en/2982326), [preimage resistance](https://en.wikipedia.org/wiki/Preimage_resistance), [second preimage resistance](https://en.wikipedia.org/wiki/Second_preimage_resistance), etc.) can often be proven secure in the standard model (e.g., the [Cramer–Shoup cryptosystem](wikipedia://en/1564406)).

Random oracles have long been considered in [computational complexity theory](wikipedia://en/7543),[^o7] and many schemes have been proven secure in the random oracle model, for example [Optimal Asymmetric Encryption Padding](https://en.wikipedia.org/wiki/Optimal_Asymmetric_Encryption_Padding), [RSA-FDH](wikipedia://en/2493181) and [PSS](wikipedia://en/53823229). In 1986, [Amos Fiat](https://en.wikipedia.org/wiki/Amos_Fiat) and [Adi Shamir](wikipedia://en/57314)[^o8] showed a major application of random oracles – the removal of interaction from protocols for the creation of signatures.

In 1989, [Russell Impagliazzo](https://en.wikipedia.org/wiki/Russell_Impagliazzo) and [Steven Rudich](https://en.wikipedia.org/wiki/Steven_Rudich)[^o9] used random oracles to show an [oracle separation](https://en.wikipedia.org/wiki/Oracle_separation) between one-way functions and secret-key exchange, by exhibiting an oracle relative to which one-way functions exists but secret-key exchange — and thus also public-key encryption — does not exist. Their result show that there is no [black-box construction](https://en.wikipedia.org/wiki/Black-box) of public-key encryption from one-way functions, thus suggesting that one-way functions are a *weaker* assumption than public-key encryption.

In 1993, [Mihir Bellare](https://en.wikipedia.org/wiki/Mihir_Bellare) and [Phillip Rogaway](https://en.wikipedia.org/wiki/Phillip_Rogaway)[^o3] were the first to advocate their use in cryptographic constructions. In their definition, the random oracle produces a bit-string of [infinite](wikipedia://en/20110824) length which can be truncated to the length desired.

When a random oracle is used within a security proof, it is made available to all players, including the adversary or adversaries.

:::

## Domain separation {#Domain_separation}

A single oracle may be treated as multiple oracles by pre-pending a fixed bit-string to the beginning of each query (e.g., queries formatted as "1||x" or "0||x" can be considered as calls to two separate random oracles, similarly "00||x", "01||x", "10||x" and "11||x" can be used to represent calls to four separate random oracles). This practice is usually called [domain separation](wikipedia://en/75916379). *Oracle cloning* is the re-use of the once-constructed random oracle within the same proof (this in practice corresponds to the multiple uses of the same [cryptographic hash](https://en.wikipedia.org/wiki/Cryptographic_hash) within one algorithm for different purposes).[^n1] Oracle cloning with improper domain separation breaks security proofs and can lead to successful attacks.[^n2]

## Limitations {#Limitations}

According to the [Church–Turing thesis](wikipedia://en/6854), no function [computable](wikipedia://en/1139338) by a finite algorithm can implement a true random oracle (which by definition requires an infinite description because it has infinitely many possible inputs, and its outputs are all independent from each other and need to be individually specified by any description).

In fact, certain contrived signature and encryption schemes are known which are proven secure in the random oracle model, but which are trivially insecure when any real function is substituted for the random oracle.[^o14][^o15] Nonetheless, for any more natural protocol a proof of security in the random oracle model gives very strong evidence of the *practical* security of the protocol.[^o16]

In general, if a protocol is proven secure, attacks to that protocol must either be outside what was proven, or break one of the assumptions in the proof; for instance if the proof relies on the hardness of [integer factorization](wikipedia://en/15491), to break this assumption one must discover a fast integer factorization algorithm. Instead, to break the random oracle assumption, one must discover some unknown and undesirable property of the actual hash function; for good hash functions where such properties are believed unlikely, the considered protocol can be considered secure.

## Random oracle hypothesis {#Random_oracle_hypothesis}

Although the Baker–Gill–Solovay theorem[^o19] showed that there exists an oracle A such that P<sup>A</sup> = NP<sup>A</sup>, subsequent work by Bennett and Gill,[^o20] showed that for a *random oracle* B (a function from {0,1}<sup>n</sup> to {0,1} such that each input element maps to each of 0 or 1 with probability 1/2, independently of the mapping of all other inputs), P<sup>B</sup> ⊊ NP<sup>B</sup> with probability 1. Similar separations, as well as the fact that random oracles separate classes with probability 0 or 1 (as a consequence of the [Kolmogorov's zero–one law](wikipedia://en/191797)), led to the creation of the **Random Oracle Hypothesis**, that two "acceptable" complexity classes C<sub>1</sub> and C<sub>2</sub> are equal if and only if they are equal (with probability 1) under a random oracle (the acceptability of a complexity class is defined in BG81[^o20]). This hypothesis was later shown to be false, as the two acceptable complexity classes [IP](wikipedia://en/2197070) and [PSPACE](wikipedia://en/39351) were shown to be equal[^o21] despite IP<sup>A</sup> ⊊ PSPACE<sup>A</sup> for a random oracle A with probability 1.[^o22]

:::

## Ideal cipher {#Ideal_cipher}

An ***ideal*** cipher is a [random permutation](https://en.wikipedia.org/wiki/Random_permutation) oracle that is used to model an idealized block cipher. A random permutation decrypts each ciphertext block into one and only one plaintext block and vice versa, so there is a [one-to-one correspondence](https://en.wikipedia.org/wiki/One-to-one_correspondence). Some cryptographic proofs make not only the "forward" permutation available to all players, but also the "reverse" permutation.

Recent works showed that an ideal cipher can be constructed from a random oracle using 10-round[^o24] or even 8-round[^o25] [Feistel networks](https://en.wikipedia.org/wiki/Feistel_network).

## Ideal permutation {#Ideal_permutation}

An ideal permutation is an idealized object sometimes used in cryptography to model the behaviour of a permutation whose outputs are indistinguishable from those of a random permutation. In the ideal permutation model, an additional oracle access is given to the ideal permutation and its inverse. The ideal permutation model can be seen as a special case of the ideal cipher model where access is given to only a single permutation, instead of a family of permutations as in the case of the ideal cipher model.

## Quantum-accessible random oracles {#Quantum-accessible_random_oracles}

[Post-quantum cryptography](wikipedia://en/26605226) studies quantum attacks on classical cryptographic schemes. As a random oracle is an abstraction of a [hash function](https://en.wikipedia.org/wiki/Hash_function), it makes sense to assume that a quantum attacker can access the random oracle in [quantum superposition](wikipedia://en/82728).[^o28] Many of the classical security proofs break down in that quantum random oracle model and need to be revised.
