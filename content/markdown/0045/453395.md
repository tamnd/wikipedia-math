# Tagged union

::: {#o1 .subject cue=lead name="Tagged union"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science), a **tagged union**, also called a **variant**, **variant record**, **choice type**, **discriminated union**, **[disjoint union](wikipedia://en/188946)**, **sum type**, or **[coproduct](wikipedia://en/310889)**, is a [data structure](wikipedia://en/8519) used to hold a value that could take on several different, but fixed, types. Only one of the types can be in use at any one time, and a **tag** field explicitly indicates which type is in use. It can be thought of as a type that has several "cases", each of which should be handled correctly when that type is manipulated. This is critical in defining recursive datatypes, in which some component of a value may have the same type as that value, for example in defining a type for representing [trees](https://en.wikipedia.org/wiki/Tree_%28data_structure%29), where it is necessary to distinguish multi-node subtrees and leaves. Like ordinary [unions](https://en.wikipedia.org/wiki/Union_type), tagged unions can save storage by overlapping storage areas for each type, since only one is in use at a time.

:::

## Description {#Description}

Tagged unions are most important in [functional programming](https://en.wikipedia.org/wiki/Functional_programming) languages such as [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) and [Haskell](https://en.wikipedia.org/wiki/Haskell), where they are called *datatypes* (see [algebraic data type](https://en.wikipedia.org/wiki/Algebraic_data_type)) and the [compiler](https://en.wikipedia.org/wiki/Compiler) can verify that all cases of a tagged union are always handled, avoiding many types of errors. Compile-time checked sum types are also extensively used in [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29), where they are called *enum*. They can, however, be constructed in nearly any [programming language](wikipedia://en/23015), and are much safer than untagged unions, often simply called unions, which are similar but do not explicitly track which member of a union is currently in use.

Tagged unions are often accompanied by the concept of a [constructor](https://en.wikipedia.org/wiki/Algebraic_data_type), which is similar but not the same as a [constructor](https://en.wikipedia.org/wiki/Constructor_%28object-oriented_programming%29) for a [class](https://en.wikipedia.org/wiki/Class_%28programming%29). A constructor is a function or an expression that produces a value of the tagged union type, given a tag and a value of the corresponding type.

Mathematically, tagged unions correspond to *[disjoint](wikipedia://en/188946)* or *discriminated unions*, usually written using +. Given an element of a disjoint union $A + B$, it is possible to determine whether it came from $A$ or $B$. If an element lies in both, there will be two effectively distinct copies of the value in $A + B$, one from $A$ and one from $B$.

In [type theory](wikipedia://en/40282), a tagged union is called a *sum type*. Sum types are the [dual](https://en.wikipedia.org/wiki/Dual_%28mathematics%29) of [product types](wikipedia://en/14892710). Notations vary, but usually the sum type $A + B$ comes with two introduction forms ([injections](https://en.wikipedia.org/wiki/Injection_%28mathematics%29)) $\texttt{inj}_1: A \mapsto A + B$ and $\texttt{inj}_2: B \mapsto A + B$. The elimination form is case analysis, known as [pattern matching](https://en.wikipedia.org/wiki/Pattern_matching) in [ML-style](https://en.wikipedia.org/wiki/ML_%28programming_language%29) languages: if $e$ has type $A + B$ and $e_1$ and $e_2$ have type $\tau$ under the assumptions $x: A$ and $y: B$ respectively, then the term $\mathsf{case}\ e\ \mathsf{of}\ x \Rightarrow e_1 \mid y \Rightarrow e_2$ has type $\tau$. The sum type corresponds to [intuitionistic](wikipedia://en/169262) [logical disjunction](wikipedia://en/7962) under the [Curry–Howard correspondence](wikipedia://en/254299).

An [enumerated type](https://en.wikipedia.org/wiki/Enumerated_type) can be seen as a degenerate case: a tagged union of [unit types](wikipedia://en/3646268). It corresponds to a set of nullary constructors and may be implemented as a simple tag variable, since it holds no additional data besides the value of the tag.

Many programming techniques and data structures, including [rope](https://en.wikipedia.org/wiki/Rope_%28data_structure%29), [lazy evaluation](https://en.wikipedia.org/wiki/Lazy_evaluation), [class hierarchy](https://en.wikipedia.org/wiki/Class_hierarchy) (see below), [arbitrary-precision arithmetic](wikipedia://en/600892), [CDR coding](https://en.wikipedia.org/wiki/CDR_coding), the [indirection bit](https://en.wikipedia.org/wiki/Indirection_bit), and other kinds of [tagged pointers](https://en.wikipedia.org/wiki/Tagged_pointer), are usually implemented using some sort of tagged union.

A tagged union can be seen as the simplest kind of [self-describing](https://en.wikipedia.org/wiki/Self-describing) [data format](https://en.wikipedia.org/wiki/Comparison_of_data_serialization_formats). The tag of the tagged union can be seen as the simplest kind of [metadata](https://en.wikipedia.org/wiki/Metadata).

In languages with [flow-sensitive typing](https://en.wikipedia.org/wiki/Flow-sensitive_typing), tagged unions can be implemented by a combination of [union types](https://en.wikipedia.org/wiki/Union_type) and [record types](https://en.wikipedia.org/wiki/Row_polymorphism).[^o3]

## Advantages and disadvantages {#Advantages_and_disadvantages}

The primary advantage of a tagged union over an untagged union is that all accesses are safe, and the compiler can even check that all cases are handled. Untagged unions depend on program logic to correctly identify the currently active field, which may result in strange behavior and hard-to-find bugs if that logic fails.

The primary advantage of a tagged union over a simple [record](https://en.wikipedia.org/wiki/Record_%28computer_science%29) containing a field for each type is that it saves storage by overlapping storage for all the types. Some implementations reserve enough storage for the largest type, while others dynamically adjust the size of a tagged union value as needed. When the value is [immutable](https://en.wikipedia.org/wiki/Immutable_object), it is simple to allocate just as much storage as is needed.

The main disadvantage of tagged unions is that the tag occupies space. Since there are usually a small number of alternatives, the tag can often be squeezed into 2 or 3 bits wherever space can be found, but sometimes even these bits are not available. In this case, a helpful alternative may be **folded**, **computed** or **encoded tags**, where the tag value is dynamically computed from the contents of the union field. Common examples are the use of *reserved values*, where, for example, a function returning a positive number may return -1 to indicate failure, and [sentinel values](https://en.wikipedia.org/wiki/Sentinel_value), most often used in [tagged pointers](https://en.wikipedia.org/wiki/Tagged_pointer).

Sometimes, untagged unions are used to perform bit-level conversions between types, or [type punning](https://en.wikipedia.org/wiki/Type_punning). Tagged unions are not intended for this purpose; typically a new value is assigned whenever the tag is changed.

Many languages support, to some extent, a [universal data type](https://en.wikipedia.org/wiki/Top_type), which is a type that includes every value of every other type, and often a way is provided to test the actual type of a value of the universal type. These are sometimes referred to as *variants*. While universal data types are comparable to tagged unions in their formal definition, typical tagged unions include a relatively small number of cases, and these cases form different ways of expressing a single coherent concept, such as a data structure node or instruction. Also, there is an expectation that every possible case of a tagged union will be dealt with when it is used. The values of a universal data type are not related and there is no feasible way to deal with them all.

Like [option types](https://en.wikipedia.org/wiki/Option_type) and [exception handling](https://en.wikipedia.org/wiki/Exception_handling), tagged unions are sometimes used to handle the occurrence of exceptional results. Often these tags are folded into the type as *reserved values*, and their occurrence is not consistently checked: this is a fairly common source of programming errors. This use of tagged unions can be formalized as a [monad](wikipedia://en/579061) with the following functions:

$$\texttt{return}\colon A \to \left( A + E \right) = a \mapsto \text{value} \, a$$

$$\texttt{bind}\colon \left( A + E \right) \to \left(A \to \left(B + E \right) \right) \to \left( B + E \right) = a \mapsto f \mapsto \begin{cases} \text{err} \, e & \text{if} \ a = \text{err} \, e\\ f \, a' & \text{if} \ a = \text{value} \, a' \end{cases}$$

where $\text{value}$ and $\text{err}$ are the constructors of the union type, $A$ and $B$ are valid [result types](https://en.wikipedia.org/wiki/Result_type) and $E$ is the type of error conditions. Alternately, the same monad may be described by $\texttt{return}$ and two additional functions, $\texttt{fmap}$ and $\texttt{join}$:

$$\texttt{fmap} \colon (A \to B) \to \left( \left( A + E \right) \to \left( B + E \right) \right) = f \mapsto a \mapsto \begin{cases} \text{err} \, e & \text{if} \ a = \text{err} \, e \\ \text{value} \, \text{(} \, f \, a' \, \text{)} & \text{if} \ a = \text{value} \, a' \end{cases}$$

$$\texttt{join} \colon ((A + E ) + E) \to (A + E) = a \mapsto \begin{cases} \text{err} \, e & \mbox{if} \ a = \text{err} \, e\\ \text{err} \, e & \text{if} \ a = \text{value} \, \text{(err} \, e \, \text{)} \\ \text{value} \, a' & \text{if} \ a = \text{value} \, \text{(value} \, a' \, \text{)} \end{cases}$$

## Examples {#Examples}

A [binary tree](wikipedia://en/4321) of integers in [ML](https://en.wikipedia.org/wiki/ML_%28programming_language%29) can be expressed using a [data type](https://en.wikipedia.org/wiki/Data_type) similar to the following:

```sml
datatype tree = Leaf
              | Node of (int * tree * tree)
```

This is a tagged union with two cases: one, the leaf, is used to terminate a path of the tree, and functions much like a null value would in imperative languages. The other branch holds a node, which contains an integer and a left and right subtree. Leaf and Node are the constructors, which are used to create a given tree, such as:

```sml
Node(5, Node(1, Leaf, Leaf), Node(3, Leaf, Node(4, Leaf, Leaf)))
```

which corresponds to this tree:

*Image: tagged union tree.svg.* The tree produced by the above constructors

It then becomes trivial to write a type-safe function that, for example, counts the number of nodes in the tree:

```sml
fun countNodes(Leaf) = 0
  | countNodes(Node(int, left, right)) =
      1 + countNodes(left) + countNodes(right)
```

## Language support {#Language_support}

### ALGOL 68 {#ALGOL_68}

In [ALGOL 68](https://en.wikipedia.org/wiki/ALGOL_68), tagged unions are called *united modes*, the tag is implicit, and the `'''case'''` construct is used to determine which field is tagged:

`'''mode''' '''node''' = '''union''' ('''real''', '''int''', '''compl''', '''string''');`

Usage example for `'''union'''` `'''case'''` of `'''node'''`:

**node** n := "1234"; **case** n **in** (**real** r): print(("real:", r)), (**int** i): print(("int:", i)), (**compl** c): print(("compl:", c)), (**string** s): print(("string:", s)) **out** print(("?:", n)) **esac**

In ALGOL 68, a union can be automatically coerced into a wider union, for example if all its constituents can be handled by the union parameter of **print**, a union can simply be passed to print as in the **out** case above.

### Ada {#Ada}

In [Ada](https://en.wikipedia.org/wiki/Ada_%28programming_language%29), these are called "discriminated types".

```ada
type Shape_Kind is (Square, Rectangle, Circle);
type Shape (Kind : Shape_Kind) is record
   Center_X : Integer;
   Center_Y : Integer;
   case Kind is
      when Square =>
         Side : Integer;
      when Rectangle =>
         Width, Height : Integer;
      when Circle =>
         Radius : Integer;
   end case;
end record;

-- Any attempt to access a member which existence depends
-- on a certain value of the discriminant, while the
-- discriminant is not the expected one, raises an error.
```

### C++ {#C++}

While [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) only provides

```c
union
```

, an untagged union type, [C++](https://en.wikipedia.org/wiki/C++) offers a class

```cpp
std::variant<Ts...>
```

(since [C++17](https://en.wikipedia.org/wiki/C++17)), but rather than being a core language feature like

```c
union
```

, it is a [standard library](https://en.wikipedia.org/wiki/C++_Standard_Library) class.

```cpp
import std;

using std::string;
using std::variant;

struct Cat {
    string name;
};

struct Dog {
    string name;
};

struct Bird {
    string name;
};

using Pet = variant<Cat, Dog, Bird>;

Pet p1 = Cat("Whiskers");
Pet p2 = Dog("Rex");
```

The "overload pattern" is a common [design pattern](https://en.wikipedia.org/wiki/Software_design_pattern) that implements algebraic pattern matching using [variadic template](https://en.wikipedia.org/wiki/Variadic_template) inheritance.[^o11]

```cpp
// Helper type for visitor
template <typename... Ts>
struct Overload : public Ts... {
    using Ts::operator()...;
}

// Deduction guide
template <typename... Ts>
Overload(Ts...) -> Overload<Ts...>;
```

Then, the `std::visit()` function may be used to call each respective case, with each case handled by a [lambda](https://en.wikipedia.org/wiki/Anonymous_function):[^o12]

```cpp
using Value = variant<int, double, string>;

Value v = 3.14;

// prints "double: 3.14"
std::visit(
    Overload {
        [](int i) -> void { std::println("int: {}", i); },
        [](double d) -> void { std::println("double: {}", d); },
        [](const string& s) -> void { std::println("string: {}", s); }
    },
    v
);
```

Additionally, `std::visit()` may be made to return a type:

```cpp
Pet p = Bird("Polly");

string name = std::visit(
    Overload {
        [](const Cat& c) -> string { return c.name; },
        [](const Dog& d) -> string { return d.name; },
        [](const Bird& b) -> string { return b.name; }
    },
    p
);

// Prints "Pet name: Polly"
std::println("Pet name: {}", name);
```

Since [C++26](https://en.wikipedia.org/wiki/C++26), `visit()` may be used as method of

```cpp
std::variant<Ts...>
```

:

```cpp
Pet p = Bird("Polly");

Overload visitor(
    [](const Cat& c) -> string { return c.name; },
    [](const Dog& d) -> string { return d.name; },
    [](const Bird& b) -> string { return b.name; }
);

// Prints "Pet name: Polly"
std::println("Pet name: {}", p.visit(visitor));
```

The result type for error handling (like

```rust
std::result::Result<T, E>
```

in Rust), was introduced to [C++23](https://en.wikipedia.org/wiki/C++23) as

```cpp
std::expected<T, E>
```

.

### C# {#C#}

[C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29) traditionally did not have tagged unions. The closest way to approximate these was through pattern matching over

```csharp
record
```

types. With C# 15, tagged unions were introduced with the keyword

```csharp
union
```

.[^o14]

```csharp
record class Car(string Model);
record class Bicycle(string Model);
record class Bus(string Model);

union Vehicle(Car, Bicycle, Bus);

Vehicle car = new Car("Tesla Model 3");
Console.WriteLine(car.Value); // Car { Model = Tesla Model 3 }

Vehicle bike = new Bicycle("Giant Escape 3");
Console.WriteLine(bike.Value); // Bicycle { Model = Giant Escape 3 }

Vehicle bus = new Bus("Volvo 9700");
Console.WriteLine(bus.Value); // Bus { Model = Volvo 9700 }

Vehicle v = /* some vehicle here */;
string model = v switch
{
    Car c => c.Model,
    Bicycle bk => b.Model,
    Bus bs => bs.Model,
};
```

The

```csharp
default
```

value of a union is

```csharp
null
```

, but if all types in the union are non-[nullable](https://en.wikipedia.org/wiki/Nullable_type), then a

```csharp
switch
```

expression need not check for

```csharp
null
```

.

### Cyclone {#Cyclone}

[Cyclone](https://en.wikipedia.org/wiki/Cyclone_%28programming_language%29), a dialect of C with safety enhancements, offers tagged unions.[^o16] These were declared with a

```d
@tagged
```

qualifier.

```d
@tagged union Foo {
    int i;
    double d;
    char* @fat s;
};

void printFoo(union Foo x) {
    // A missed case would be warned by the compiler
    switch (x) {
        case { .i = i }:
            printf("%d", i);
            break;
        case { .d = d }:
            printf("%g", d);
            break;
        case { .s = s }:
            printf("%s", s); 
            break;
    }
}
```

### D {#D}

[D](https://en.wikipedia.org/wiki/D_%28programming_language%29) provides the `std.variant` module, with types like

```d
Variant
```

(representing an [any type](wikipedia://en/3893409)), and

```d
std.variant.Algebraic!(T...)
```

(representing an algebraic data type).[^o18]

```d
import std.variant;

Algebraic!(int, string) v = 10;

int result = v.visit!(
    (string s) => cast(int) s.length,
    (int i) => i,
    () => -1
)();
writeln(result); // 10
```

### F# {#F#}

[F#](https://en.wikipedia.org/wiki/F_Sharp_%28programming_language%29) has discriminated unions:

```fsharp
type Tree =
  | Leaf
  | Node of value: int * left: Tree * right: Tree

let tree = Node(5, Node(1, Leaf, Leaf), Node(3, Leaf, Node(4, Leaf, Leaf)))
```

Because the defined cases are exhaustive, the compiler can check that all cases are handled in a pattern match:

```fsharp
match tree with
| Node (x, _, _) -> printfn "top level node value: %i" x
| Leaf           -> printfn "top level node is a leaf"
```

### Haxe {#Haxe}

[Haxe](https://en.wikipedia.org/wiki/Haxe)'s enums also work as tagged unions:[^o21]

```haxe
enum Color {
  Red;
  Green;
  Blue;
  Rgb(r:Int, g:Int, b:Int);
}
```

These can be matched using a switch expression:

```haxe
switch (color) {
  case Red: trace("Color was red");
  case Green: trace("Color was green");
  case Blue: trace("Color was blue");
  case Rgb(r, g, b): trace("Color had a red value of " +r);
}
```

### Java {#Java}

In [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), the closest way to implement a tagged union is through a [sealed class](https://en.wikipedia.org/wiki/Sealed_class), which directly constrains what types may inherit the class. Pattern matching itself may be done over

```java
switch
```

expressions.[^o23]

```java
sealed interface Shape permits Circle, Rectangle, Triangle {}
record Circle(double radius) implements Shape {}
record Rectangle(double width, double height) implements Shape {}
record Triangle(double base, double height) implements Shape {}

double area(Shape s) {
    return switch (s) {
        case Circle(double r) -> Math.PI * r * r;
        case Rectangle(double w, double h) -> w * h;
        case Triangle(double b, double h) -> 0.5 * b * h;
    };
}
```

### Standard ML {#Standard_ML}

In [Standard ML](https://en.wikipedia.org/wiki/Standard_ML), a tagged union is an "algebraic data type" or a "sum type".

```sml
datatype shape = Circle of real
    | Rectangle of real * real
    | Point

fun area s =
    case s of
        Circle r => 3.1415926535 * r * r
      | Rectangle (w, h) => w * h
      | Point => 0.0
```

### Nim {#Nim}

[Nim](https://en.wikipedia.org/wiki/Nim_%28programming_language%29) has object variants[^o26] similar in declaration to those in Pascal and Ada:

```nim
type
  ShapeKind = enum
    skSquare, skRectangle, skCircle
  Shape = object
    centerX, centerY: int
    case kind: ShapeKind
    of skSquare:
      side: int
    of skRectangle:
      length, height: int
    of skCircle:
      radius: int
```

[Macros](https://en.wikipedia.org/wiki/Macro_%28computer_science%29) can be used to emulate pattern matching or to create syntactic sugar for declaring object variants, seen here as implemented by the package [patty](https://github.com/andreaferretti/patty):

```nim
import patty

proc `~`[A](a: A): ref A =
  new(result)
  result[] = a

variant List[A]:
  Nil
  Cons(x: A, xs: ref List[A])

proc listHelper[A](xs: seq[A]): List[A] =
  if xs.len == 0: Nil[A]()
  else: Cons(xs[0], ~listHelper(xs[1 .. xs.high]))

proc list[A](xs: varargs[A]): List[A] = listHelper(@xs)

proc sum(xs: List[int]): int = (block:
  match xs:
    Nil: 0
    Cons(y, ys): y + sum(ys[])
)

echo sum(list(1, 2, 3, 4, 5))
```

### Rust {#Rust}

The [Rust language](https://en.wikipedia.org/wiki/Rust_%28programming_language%29) has extensive support for tagged unions, called enums.[^o32] For example:

```rust
enum Tree {
    Leaf,
    Node(i64, Box<Tree>, Box<Tree>)
}
```

It also allows matching on unions:

```rust
let tree: Tree = Tree::Node(
    2,
    Box::new(Tree::Node(0, Box::new(Tree::Leaf), Box::new(Tree::Leaf))),
    Box::new(Tree::Node(3, Box::new(Tree::Leaf),
        Box::new(Tree::Node(4, Box::new(Tree::Leaf), Box::new(Tree::Leaf)))))
);

fn add_values(tree: Tree) -> i64 {
    match tree {
        Tree::Node(v, a, b) => v + add_values(*a) + add_values(*b),
        Tree::Leaf => 0
    }
}

fn main() {
    assert_eq!(add_values(tree), 9);
}
```

Rust's error handling model relies extensively on these tagged unions, especially the

```rust
std::option::Option<T>
```

type, which is either `None` or `Some(T)`, and the

```rust
std::result::Result<T, E>
```

type, which is either `Ok(T)` or `Err(E)`.[^o33]

### Scala {#Scala}

[Scala](wikipedia://en/3254510) has case classes:

```scala
sealed abstract class Tree
case object Leaf extends Tree
case class Node(value: Int, left: Tree, right: Tree) extends Tree

val tree = Node(5, Node(1, Leaf, Leaf), Node(3, Leaf, Node(4, Leaf, Leaf)))
```

Because the class hierarchy is sealed, the compiler can check that all cases are handled in a pattern match:

```scala
tree match {
  case Node(x, _, _) => println("top level node value: " + x)
  case Leaf          => println("top level node is a leaf")
}
```

Scala's case classes also permit reuse through subtyping:

```scala
sealed abstract class Shape(centerX: Int, centerY: Int)
case class Square(side: Int, centerX: Int, centerY: Int) extends Shape(centerX, centerY)
case class Rectangle(length: Int, height: Int, centerX: Int, centerY: Int) extends Shape(centerX, centerY)
case class Circle(radius: Int, centerX: Int, centerY: Int) extends Shape(centerX, centerY)
```

Enums are added in Scala 3,[^o35] allowing us to rewrite the earlier Scala examples more concisely:

```scala
enum Tree[+T]:
  case Leaf
  case Node(x: Int, left: Tree[T], right: Tree[T])

enum Shape(centerX: Int, centerY: Int):
  case Square(side: Int, centerX: Int, centerY: Int) extends Shape(centerY, centerX)
  case Rectangle(length: Int, height: Int, centerX: Int, centerY: Int) extends Shape(centerX, centerY)
  case Circle(radius: Int, centerX: Int, centerY: Int) extends Shape(centerX, centerY)
```

### Swift {#Swift}

[Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29) also has substantial support for tagged unions via enumerations.[^o37] For example:

```swift
enum Tree {
    case leaf
    indirect case node(Int, Tree, Tree)
}

let tree = Tree.node(
    2,
    .node(0, .leaf, .leaf),
    .node(3, .leaf, .node(4, .leaf, .leaf))
)

func add_values(_ tree: Tree) -> Int {
    switch tree {
    case let .node(v, a, b):
        return v + add_values(a) + add_values(b)

    case .leaf:
        return 0
    }
}

assert(add_values(tree) == 9)
```

### TypeScript {#TypeScript}

With [TypeScript](https://en.wikipedia.org/wiki/TypeScript) it is also possible to create tagged unions. For example:

```typescript
interface Leaf {
    kind: "leaf";
}

interface Node {
    kind: "node";
    value: number;
    left: Tree;
    right: Tree;
}

type Tree = Leaf | Node;

const root: Tree = {
    kind: "node",
    value: 5,
    left: {
        kind: "node",
        value: 1,
        left: { kind: "leaf" },
        right: { kind: "leaf" }
    },
    right: {
        kind: "node",
        value: 3,
        left: { kind: "leaf" },
        right: {
            kind: "node",
            value: 4,
            left: { kind: "leaf" },
            right: { kind: "leaf" }
        }
    }
};

function visit(tree: Tree): void {
    switch (tree.kind) {
        case "leaf":
            break;
        case "node":
            console.log(tree.value);
            visit(tree.left);
            visit(tree.right);
            break;
    } 
}
```

## Class hierarchies as tagged unions {#Class_hierarchies_as_tagged_unions}

In a typical [class hierarchy](https://en.wikipedia.org/wiki/Class_hierarchy) in [object-oriented programming](https://en.wikipedia.org/wiki/Object-oriented_programming), each subclass can encapsulate data unique to that class. The metadata used to perform [virtual method](https://en.wikipedia.org/wiki/Virtual_method) lookup (for example, the object's [vtable](https://en.wikipedia.org/wiki/Virtual_method_table) pointer in most C++ implementations) identifies the subclass and so effectively acts as a tag identifying the data stored by the instance (see [RTTI](https://en.wikipedia.org/wiki/RTTI)). An object's [constructor](https://en.wikipedia.org/wiki/Constructor_%28object-oriented_programming%29) sets this tag, and it remains constant throughout the object's lifetime.

Nevertheless, a class hierarchy involves true [subtype polymorphism](https://en.wikipedia.org/wiki/Subtype_polymorphism). It can be extended by creating further subclasses of the same base type, which could not be handled correctly under a tag/dispatch model. Hence, it is usually not possible to do case analysis or dispatch on a subobject's 'tag' as one would for tagged unions. Some languages such as [Scala](wikipedia://en/3254510) allow base classes to be "sealed", and unify tagged unions with sealed base classes.
