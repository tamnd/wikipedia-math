# Time complexity

*Image: comparison computational complexity.svg.* Graphs of functions commonly used in the [analysis of algorithms](wikipedia://en/2230), showing the number of operations $N$ as the result of input size $n$ for each function

::: {#o1 .subject cue=lead name="Time complexity"}

In [theoretical computer science](wikipedia://en/323392), the **time complexity** is the [computational complexity](wikipedia://en/6511) that describes the amount of computer time it takes to run an [algorithm](wikipedia://en/775). Time complexity is commonly estimated by counting the number of elementary operations performed by the algorithm, supposing that each elementary operation takes a fixed amount of time to perform. Thus, the amount of time taken and the number of elementary operations performed by the algorithm are taken to be related by a [constant factor](https://en.wikipedia.org/wiki/Constant_factor).

:::

Since an algorithm's running time may vary among different inputs of the same size, one commonly considers the [worst-case time complexity](https://en.wikipedia.org/wiki/Worst-case_complexity), which is the maximum amount of time required for inputs of a given size. Less common, and usually specified explicitly, is the [average-case complexity](https://en.wikipedia.org/wiki/Average-case_complexity), which is the average of the time taken on inputs of a given size (this makes sense because there are only a finite number of possible inputs of a given size). In both cases, the time complexity is generally expressed as a [function](wikipedia://en/185427) of the size of the input.[^o30] Since this function is generally difficult to compute exactly, and the running time for small inputs is usually not consequential, one commonly focuses on the behavior of the complexity when the input size increases—that is, the [asymptotic behavior](wikipedia://en/641995) of the complexity. Therefore, the time complexity is commonly expressed using [big O notation](wikipedia://en/44578), typically $O(n)$, $O(n\log n)$, $O(n^\alpha)$, $O(2^n)$, etc., where $n$ is the size in units of [bits](https://en.wikipedia.org/wiki/Bit) needed to represent the input.

Algorithmic complexities are classified according to the type of function appearing in the big O notation. For example, an algorithm with time complexity $O(n)$ is a *linear time algorithm* and an algorithm with time complexity $O(n^\alpha)$ for some constant $\alpha > 0$ is a *polynomial time algorithm*.

An algorithm is termed **constant time** (often represented as $O(1)$ time) when its complexity function $T(n)$ is bounded by a value that does not change with the size of the input. This implies that the execution time remains consistent regardless of how much data is processed. For instance, accessing a specific element in an [array](https://en.wikipedia.org/wiki/Array_data_structure) is a constant-time operation, as it requires only a single operation to locate that element.

In contrast, determining the minimum value in an unordered array is not constant time; it requires examining each [element](https://en.wikipedia.org/wiki/Element_%28math%29), resulting in linear time complexity, or $O(n)$. However, if the number of elements is known and fixed, certain tasks can still be considered constant time.

Importantly, the term "constant time" does not mean the running time must be entirely independent of the problem size; rather, it should have a consistent upper bound irrespective of input size. For example, a task that involves swapping the values of $a$ and $b$ to ensure $a \le b$ is classified as constant time, even if the execution time may vary depending on whether the condition is already met. The key is that there exists a constant $t$ such that the time taken will never exceed $t$, regardless of the input values.

Constant-time algorithms are especially significant in contexts like cryptography, where timing attacks can exploit variations in execution time. By designing algorithms that run in constant time, developers can enhance security and ensure performance predictability, making it a fundamental consideration in software engineering.

## Logarithmic time {#Logarithmic_time}

An algorithm is said to take **logarithmic time** when $T(n) = O(\log n)$. Since $\log_a n$ and $\log_b n$ are related by a [constant multiplier](https://en.wikipedia.org/wiki/Logarithmic_identities#Changing_the_base), and such a [multiplier is irrelevant](wikipedia://en/44578#Multiplication_by_a_constant) to big O classification, the standard usage for logarithmic-time algorithms is $O(\log n)$ regardless of the base of the logarithm appearing in the expression of $T$.

Algorithms taking logarithmic time are commonly found in operations on [binary trees](wikipedia://en/4321) or when using [binary search](wikipedia://en/4266).

An $O(\log n)$ algorithm is considered highly efficient, as the ratio of the number of operations to the size of the input decreases and tends to zero when $n$ increases. An algorithm that must access all elements of its input cannot take logarithmic time, as the time taken for reading an input of size $n$ is of the order of $n$.

An example of logarithmic time is given by dictionary search. Consider a [dictionary](https://en.wikipedia.org/wiki/Dictionary_%28data_structure%29) $D$ which contains $n$ entries, sorted in [alphabetical order](https://en.wikipedia.org/wiki/Alphabetical_order). We suppose that, for $1 \le k \le n$, one may access the $k$-th entry of the dictionary in a constant time. Let $D(k)$ denote this $k$-th entry. Under these hypotheses, the test to see if a word $w$ is in the dictionary may be done in logarithmic time: consider $D\left(\left\lfloor \frac{n}{2} \right\rfloor\right)$, where $\lfloor\;\rfloor$ denotes the [floor function](https://en.wikipedia.org/wiki/Floor_function). If $w = D\left(\left\lfloor \frac{n}{2} \right\rfloor\right)$--that is to say, the word $w$ is exactly in the middle of the dictionary--then we are done. Else, if $w < D\left(\left\lfloor \frac{n}{2} \right\rfloor\right)$--i.e., if the word $w$ comes earlier in alphabetical order than the middle word of the whole dictionary--we continue the search in the same way in the left (i.e. earlier) half of the dictionary, and then again repeatedly until the correct word is found. Otherwise, if it comes after the middle word, continue similarly with the right half of the dictionary. This algorithm is similar to the method often used to find an entry in a paper dictionary. As a result, the search space within the dictionary decreases as the algorithm gets closer to the target word.

:::

## Polylogarithmic time {#Polylogarithmic_time}

An algorithm is said to run in **[polylogarithmic](wikipedia://en/445957) time** if its time $T(n)$ is $O\bigl((\log n)^k\bigr)$ for some constant $k$. Another way to write this is $O(\log^kn)$.

For example, [matrix chain ordering](wikipedia://en/1538007) can be solved in polylogarithmic time on a [parallel random-access machine](https://en.wikipedia.org/wiki/Parallel_random-access_machine),[^o14] and [a graph](wikipedia://en/325806) can be [determined to be planar](wikipedia://en/15972636) in a [fully dynamic](https://en.wikipedia.org/wiki/Dynamic_connectivity) way in $O(\log^3n)$ time per insert/delete operation.[^o15]

:::

::: {#o17 .pointer-item cue=pointer name="Sub-linear time"}

## Sub-linear time {#Sub-linear_time}

An algorithm is said to run in **sub-linear time** (often spelled **sublinear time**) if $T(n)=o(n)$. In particular this includes algorithms with the time complexities defined above.

The specific term *sublinear time algorithm* commonly refers to randomized algorithms that sample a small fraction of their inputs and process them efficiently to [approximately](wikipedia://en/563105) infer properties of the entire instance.[^o18] This type of sublinear time algorithm is closely related to [property testing](wikipedia://en/20506304) and [statistics](wikipedia://en/26685).

Other settings where algorithms can run in sublinear time include:

- [Parallel algorithms](https://en.wikipedia.org/wiki/Parallel_algorithm) that have linear or greater total [work](https://en.wikipedia.org/wiki/Analysis_of_parallel_algorithms#Definitions) (allowing them to read the entire input), but sub-linear [depth](https://en.wikipedia.org/wiki/Analysis_of_parallel_algorithms#Definitions).
- Algorithms that have [guaranteed assumptions](wikipedia://en/1471429) on the input structure. An important example are operations on [data structures](https://en.wikipedia.org/wiki/Data_structures), e.g. [binary search](https://en.wikipedia.org/wiki/Binary_search_algorithm) in a sorted array.
- Algorithms that search for local structure in the input, for example finding a local minimum in a 1-D array (can be solved in $O(\log(n))$ time using a variant of binary search). A closely related notion is that of [Local Computation Algorithms (LCA)](https://en.wikipedia.org/wiki/Local_Computation_Algorithms_%28LCA%29) where the algorithm receives a large input and queries to local information about some valid large output.[^o19]

:::

::: {#o21 .pointer-item cue=pointer name="Linear time"}

## Linear time {#Linear_time}

An algorithm is said to take **linear time**, or $O(n)$ time, if its time complexity is $O(n)$. Informally, this means that the running time increases at most linearly with the size of the input. More precisely, this means that there is a constant $c$ such that the running time is at most $cn$ for every input of size $n$. For example, a procedure that adds up all elements of a list requires time proportional to the length of the list, if the adding time is constant, or, at least, bounded by a constant.

Linear time is the best possible time complexity in situations where the algorithm has to sequentially read its entire input. Therefore, much research has been invested into discovering algorithms exhibiting linear time or, at least, nearly linear time. This research includes both software and hardware methods. There are several hardware technologies which exploit [parallelism](https://en.wikipedia.org/wiki/Parallel_computing) to provide this. An example is [content-addressable memory](https://en.wikipedia.org/wiki/Content-addressable_memory). This concept of linear time is used in string matching algorithms such as the [Boyer–Moore string-search algorithm](https://en.wikipedia.org/wiki/Boyer–Moore_string-search_algorithm) and [Ukkonen's algorithm](https://en.wikipedia.org/wiki/Ukkonen's_algorithm).

:::

::: {#o23 .pointer-item cue=pointer name="Linearithm"}

## Quasilinear time {#Quasilinear_time}

An algorithm is said to run in **quasilinear time** (also referred to as **log-linear time**) if $T(n)=O(n\log^kn)$ for some positive constant $k$;[^o24] **linearithmic time** is the case $k=1$.[^o25] Using [soft O notation](https://en.wikipedia.org/wiki/Soft_O_notation) these algorithms are $\tilde{O}(n)$. Quasilinear time algorithms are also $O(n^{1+\varepsilon })$ for every constant $\varepsilon >0$ and thus run faster than any polynomial time algorithm whose time bound includes a term $n^c$ for any $c>1$.

Algorithms which run in quasilinear time include:

- [In-place merge sort](https://en.wikipedia.org/wiki/In-place_merge_sort), $O(n\log^2n)$
- [Quicksort](wikipedia://en/3268249), $O(n\log n)$, in its randomized version, has a running time that is $O(n\log n)$ in expectation on the worst-case input. Its non-randomized version has an $O(n\log n)$ running time only when considering average case complexity.
- [Heapsort](https://en.wikipedia.org/wiki/Heapsort), $O(n\log n)$, [merge sort](wikipedia://en/20039), [introsort](https://en.wikipedia.org/wiki/Introsort), binary tree sort, [smoothsort](https://en.wikipedia.org/wiki/Smoothsort), [patience sorting](https://en.wikipedia.org/wiki/Patience_sorting), etc. in the worst case
- [Fast Fourier transforms](wikipedia://en/11512), $O(n\log n)$
- [Monge array](https://en.wikipedia.org/wiki/Monge_array) calculation, $O(n\log n)$
- [Schönhage–Strassen algorithm](https://en.wikipedia.org/wiki/Schönhage–Strassen_algorithm) for [multiplication](wikipedia://en/57411), $O(n\log n\log \log n)$

In many cases, the $O(n\log n)$ running time is simply the result of performing a $\Theta (\log n)$ operation $n$ times (for the notation, see Big O notation). For example, [binary tree sort](https://en.wikipedia.org/wiki/Binary_tree_sort) creates a [binary tree](wikipedia://en/4321) by inserting each element of the $n$-sized array one by one. Since the insert operation on a [self-balancing binary search tree](https://en.wikipedia.org/wiki/Self-balancing_binary_search_tree) takes $O(\log n)$ time, the entire algorithm takes $O(n\log n)$ time.

[Comparison sorts](wikipedia://en/3189304) require at least $\Omega (n\log n)$ comparisons in the worst case because $\log (n!)=\Theta (n\log n)$, by [Stirling's approximation](wikipedia://en/151783). They also frequently arise from the [recurrence relation](wikipedia://en/146806) $T(n) = 2T\left(\frac{n}{2}\right)+O(n)$.

:::

::: {#o27 .pointer-item cue=pointer name="Subquadratic time"}

## Sub-quadratic time {#Sub-quadratic_time}

An [algorithm](wikipedia://en/775) is said to be **subquadratic time** if $T(n)=o(n^2)$.

For example, simple, comparison-based [sorting algorithms](wikipedia://en/28442) are quadratic (e.g. [insertion sort](wikipedia://en/15205)), but more advanced algorithms can be found that are subquadratic (e.g. [shell sort](https://en.wikipedia.org/wiki/Shell_sort)). No general-purpose sorts run in linear time, but the change from quadratic to sub-quadratic is of great practical importance.

:::

::: {#o29 .pointer-item cue=pointer name="Polynomial complexity"}

## Polynomial time {#Polynomial_time}

An algorithm is said to be of **polynomial time** if its running time is [upper bounded](https://en.wikipedia.org/wiki/Upper_bound) by a [polynomial](wikipedia://en/23000) expression in the size of the input for the algorithm, that is, $1=T(n) = O(n^k)$ for some positive constant $k$.[^o30][^o31] [Problems](wikipedia://en/8336) for which a deterministic polynomial-time algorithm exists belong to the [complexity class](wikipedia://en/502426) **[P](wikipedia://en/658550)**, which is central in the field of [computational complexity theory](wikipedia://en/7543). [Cobham's thesis](wikipedia://en/3262179) states that polynomial time is a synonym for "tractable", "feasible", "efficient", or "fast".[^o32]

Some examples of polynomial-time algorithms:

- The [selection sort](https://en.wikipedia.org/wiki/Selection_sort) sorting algorithm on $n$ integers performs $An^2$ operations for some constant $A$. Thus it runs in time $O(n^2)$ and is a polynomial-time algorithm.
- All the basic arithmetic operations (addition, subtraction, multiplication, division, and comparison) can be done in polynomial time.
- [Maximum matchings](https://en.wikipedia.org/wiki/Maximum_matching) in [graphs](wikipedia://en/325806) can be found in polynomial time. In some contexts, especially in [optimization](https://en.wikipedia.org/wiki/Optimization_%28mathematics%29), one differentiates between **[strongly polynomial time](https://en.wikipedia.org/wiki/Strongly-polynomial_time)** and **weakly polynomial time** algorithms.

These two concepts are only relevant if the inputs to the algorithms consist of integers.

### Complexity classes {#Complexity_classes}

The concept of polynomial time leads to several complexity classes in computational complexity theory. Some important classes defined using polynomial time are the following.

- **[P](wikipedia://en/658550)**: The [complexity class](wikipedia://en/502426) of [decision problems](wikipedia://en/8336) that can be solved on a [deterministic Turing machine](https://en.wikipedia.org/wiki/Deterministic_Turing_machine) in polynomial time
- **[NP](wikipedia://en/21562)**: The complexity class of decision problems that can be solved on a [non-deterministic Turing machine](https://en.wikipedia.org/wiki/Non-deterministic_Turing_machine) in polynomial time
- **[ZPP](wikipedia://en/54772)**: The complexity class of decision problems that can be solved with zero error on a [probabilistic Turing machine](wikipedia://en/197812) in polynomial time
- **[RP](wikipedia://en/54771)**: The complexity class of decision problems that can be solved with 1-sided error on a probabilistic Turing machine in polynomial time.
- **[BPP](wikipedia://en/4079)**: The complexity class of decision problems that can be solved with 2-sided error on a probabilistic Turing machine in polynomial time
- **[BQP](wikipedia://en/4080)**: The complexity class of decision problems that can be solved with 2-sided error on a [quantum Turing machine](wikipedia://en/4786555) in polynomial time

P is the smallest time-complexity class on a deterministic machine which is [robust](https://en.wikipedia.org/wiki/Robustness_%28computer_science%29) in terms of machine model changes. (For example, a change from a single-tape Turing machine to a multi-tape machine can lead to a quadratic speedup, but any algorithm that runs in polynomial time under one model also does so on the other.) Any given [abstract machine](wikipedia://en/60492) will have a complexity class corresponding to the problems which can be solved in polynomial time on that machine.

:::

## Superpolynomial time {#Superpolynomial_time}

An algorithm is defined to take **superpolynomial time** if $T(n)$ is not bounded above by any polynomial; that is, if $T(n) \not \in O(n^c)$ for every positive integer $c$.

For example, an algorithm that runs for $2^n$ steps on an input of size $n$ requires superpolynomial time (more specifically, exponential time).

An algorithm that uses exponential resources is clearly superpolynomial, but some algorithms are only very weakly superpolynomial. For example, the [Adleman–Pomerance–Rumely primality test](wikipedia://en/8198761) runs for $n^{O(\log \log n)}$ time on $n$-bit inputs; this grows faster than any polynomial for large enough $n$, but the input size must become impractically large before it cannot be dominated by a polynomial with small degree.

An algorithm that requires superpolynomial time lies outside the [complexity class](wikipedia://en/502426) **[P](wikipedia://en/658550)**. [Cobham's thesis](wikipedia://en/3262179) posits that these algorithms are impractical, and in many cases they are. Since the [P versus NP problem](wikipedia://en/6115) is unresolved, it is unknown whether [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problems require superpolynomial time.

:::

## Quasi-polynomial time {#Quasi-polynomial_time}

**Quasi-polynomial time** algorithms are algorithms whose running time exhibits [quasi-polynomial growth](wikipedia://en/75468672), a type of behavior that may be slower than polynomial time but yet is significantly faster than [exponential time](https://en.wikipedia.org/wiki/Exponential_time). The worst case running time of a quasi-polynomial time algorithm is $2^{O(\log^c n)}$ for some fixed $c > 0$. When $c=1$ this gives polynomial time, and for $c < 1$ it gives sub-linear time.

There are some problems for which we know quasi-polynomial time algorithms, but no polynomial time algorithm is known. Such problems arise in approximation algorithms; a famous example is the directed [Steiner tree problem](wikipedia://en/498304), for which there is a quasi-polynomial time approximation algorithm achieving an approximation factor of $O(\log^3 n)$ ($n$ being the number of vertices), but showing the existence of such a polynomial time algorithm is an open problem.

Other computational problems with quasi-polynomial time solutions but no known polynomial time solution include the [planted clique](wikipedia://en/48563244) problem in which the goal is to [find a large clique](wikipedia://en/249254) in the union of a clique and a [random graph](wikipedia://en/358477). Although quasi-polynomially solvable, it has been conjectured that the planted clique problem has no polynomial time solution; this planted clique conjecture has been used as a [computational hardness assumption](wikipedia://en/6158383) to prove the difficulty of several other problems in computational [game theory](wikipedia://en/11924), [property testing](wikipedia://en/20506304), and [machine learning](wikipedia://en/233488).[^o37]

The complexity class **QP** consists of all problems that have quasi-polynomial time algorithms. It can be defined in terms of [DTIME](wikipedia://en/658538) as follows.[^o38]

$$\mbox{QP} = \bigcup_{c \in \mathbb{N}} \mbox{DTIME} \left(2^{\log^c n}\right)$$

### Relation to NP-complete problems {#Relation_to_NP-complete_problems}

In complexity theory, the unsolved [P versus NP](https://en.wikipedia.org/wiki/P_versus_NP) problem asks if all problems in NP have polynomial-time algorithms. All the best-known algorithms for [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problems like 3SAT etc. take exponential time. Indeed, it is conjectured for many natural NP-complete problems that they do not have sub-exponential time algorithms. Here "sub-exponential time" is taken to mean the second definition presented below. (On the other hand, many graph problems represented in the natural way by adjacency matrices are solvable in subexponential time simply because the size of the input is the square of the number of vertices.) This conjecture (for the k-SAT problem) is known as the [exponential time hypothesis](wikipedia://en/26434552).[^o40] Since it is conjectured that NP-complete problems do not have quasi-polynomial time algorithms, some inapproximability results in the field of [approximation algorithms](https://en.wikipedia.org/wiki/Approximation_algorithms) make the assumption that NP-complete problems do not have quasi-polynomial time algorithms. For example, see the known inapproximability results for the [set cover](https://en.wikipedia.org/wiki/Set_cover) problem.

## Sub-exponential time {#Sub-exponential_time}

The term **sub-exponential time** is used to express that the running time of some algorithm may grow faster than any polynomial but is still significantly smaller than an exponential. In this sense, problems that have sub-exponential time algorithms are somewhat more tractable than those that only have exponential algorithms. The precise definition of "sub-exponential" is not generally agreed upon,[^o42] however the two most widely used are below.

::: {#o44 .pointer-item cue=pointer name="SUBEXP"}

### First definition {#First_definition}

A problem is said to be sub-exponential time solvable if it can be solved in running times whose logarithms grow smaller than any given polynomial. More precisely, a problem is in sub-exponential time if for every $\epsilon > 0$ there exists an algorithm which solves the problem in time $O(2^{n^\epsilon})$. The set of all such problems is the complexity class **SUBEXP** which can be defined in terms of [DTIME](wikipedia://en/658538) as follows.[^o45][^o46][^o47][^o48]

$$\textsf{SUBEXP}=\bigcap_{\varepsilon>0} \textsf{DTIME}\left(2^{n^\varepsilon}\right)$$

This notion of sub-exponential is non-uniform in terms of $\epsilon$ in the sense that $\epsilon$ is not part of the input and each ε may have its own algorithm for the problem.

:::

### Second definition {#Second_definition}

Some authors define sub-exponential time as running times in $2^{o(n)}$.[^o40][^o50][^o51] This definition allows larger running times than the first definition of sub-exponential time. An example of such a sub-exponential time algorithm is the best-known classical algorithm for integer factorization, the [general number field sieve](wikipedia://en/152734), which runs in time about $2^{{O}(n^{1/3} (\log n)^{2/3})}$, where the length of the input is $n$. Another example was the [graph isomorphism problem](wikipedia://en/1950766), which the best known algorithm from 1982 to 2016 solved in $2^{O\left(\sqrt{n \log n}\right)}$. However, at [STOC](https://en.wikipedia.org/wiki/Symposium_on_Theory_of_Computing) 2016 a quasi-polynomial time algorithm was presented.[^o52]

It makes a difference whether the algorithm is allowed to be sub-exponential in the size of the instance, the number of vertices, or the number of edges. In [parameterized complexity](wikipedia://en/603026), this difference is made explicit by considering pairs $(L,k)$ of [decision problems](wikipedia://en/8336) and parameters $k$. **SUBEPT** is the class of all parameterized problems that run in time sub-exponential in $k$ and polynomial in the input size $n$:[^o53]

$$\textsf{SUBEPT}=\textsf{DTIME}\left(2^{o(k)} \cdot \text{poly}(n)\right).$$

More precisely, SUBEPT is the class of all parameterized problems $(L,k)$ for which there is a [computable function](wikipedia://en/1139338) $f : \mathbb{N} \to \mathbb{N}$ with $f \in o(k)$ and an algorithm that decides $L$ in time $2^{f(k)} \cdot \text{poly}(n)$.

::: {#o55 .statement kind=statement/conjecture cue=named-heading name="Exponential time hypothesis"}

#### Exponential time hypothesis {#Exponential_time_hypothesis}

The **exponential time hypothesis** (**ETH**) is that [3SAT](https://en.wikipedia.org/wiki/3SAT), the satisfiability problem of Boolean formulas in [conjunctive normal form](wikipedia://en/73342) with at most three literals per clause and with $n$ variables, cannot be solved in time $2^{o(n)}$. More precisely, the hypothesis is that there is some absolute constant $c > 0$ such that 3SAT cannot be decided in time $2^{cn}$ by any deterministic Turing machine. With $m$ denoting the number of clauses, ETH is equivalent to the hypothesis that $k$-SAT cannot be solved in time $2^{o(m)}$ for any integer $k \ge 3$.[^o56] The exponential time hypothesis implies [P ≠ NP](https://en.wikipedia.org/wiki/P_≠_NP).

:::

::: {#o58 .pointer-item cue=pointer name="Exponential algorithm"}

## Exponential time {#Exponential_time}

An algorithm is said to be **exponential time**, if $T(n)$ is upper bounded by $2^{\text{poly}(n)}$, where $\text{poly}(n)$ is some polynomial in $n$. More formally, an algorithm is exponential time if $T(n)$ is bounded by $O(2^{n^k})$ for some constant $k$. Problems which admit exponential time algorithms on a deterministic Turing machine form the complexity class known as **[EXP](https://en.wikipedia.org/wiki/EXP)**.

$$\textsf{EXP} = \bigcup_{c \in \mathbb{R_+}} \textsf{DTIME}\left(2^{n^c}\right)$$

Sometimes, exponential time is used to refer to algorithms that have $T(n) = 2^{O(n)}$, where the exponent is at most a linear function of $n$. This gives rise to the complexity class **[E](wikipedia://en/663674)**.

$$\textsf{E} = \bigcup_{c \in \mathbb{N}} \textsf{DTIME}\left(2^{cn}\right)$$

:::

## Factorial time {#Factorial_time}

An algorithm is said to be **factorial time** if $T(n)$ is upper bounded by the [factorial function](https://en.wikipedia.org/wiki/Factorial_function) $n!$. Factorial time is a subset of exponential time (EXP) because $n! \leq n^n = 2^{n \log n}= O \left(2^{n^{1 + \epsilon}} \right)$ for all $\epsilon > 0$. However, it is not a subset of E.

An example of an algorithm that runs in factorial time is [bogosort](https://en.wikipedia.org/wiki/Bogosort), a notoriously inefficient sorting algorithm based on [trial and error](https://en.wikipedia.org/wiki/Trial_and_error). Bogosort sorts a list of $n$ items by repeatedly [shuffling](https://en.wikipedia.org/wiki/Shuffling) the list until it is found to be sorted. In the average case, each pass through the bogosort algorithm will examine one of the $n!$ orderings of the $n$ items. If the items are distinct, only one such ordering is sorted. Bogosort shares patrimony with the [infinite monkey theorem](wikipedia://en/42515).

::: {#o61 .pointer-item cue=pointer name="Double exponential time"}

## Double exponential time {#Double_exponential_time}

An algorithm is said to be [double exponential](wikipedia://en/8541166) time if $T(n)$ is upper bounded by $2^{2^{\text{poly}(n)}}$, where $\text{poly}(n)$ is some polynomial in $n$. Such algorithms belong to the complexity class [2-EXPTIME](wikipedia://en/11387202).

$$\textsf{2-EXPTIME} = \bigcup_{c \in \mathbb{N}} \textsf{DTIME}\left( 2^{2^{n^c}}\right)$$

Well-known double exponential time algorithms include:

- Decision procedures for [Presburger arithmetic](wikipedia://en/23756)
- Computing a [Gröbner basis](wikipedia://en/357328) (in the worst case[^o62])
- [Quantifier elimination](wikipedia://en/2150441) on [real closed fields](wikipedia://en/1066093) takes at least double exponential time,[^o63] and can be done in this time.[^o64]

:::
