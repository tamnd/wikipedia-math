# Domain separation

::: {#o1 .subject cue=lead name="Domain separation"}

In [cryptography](wikipedia://en/18934432), **domain separation** is a construct used to implement multiple different functions using only one underlying template in an efficient way.[^n1] The domain separation can be defined as partitioning of the [domain of a function](wikipedia://en/50263) to assign separate subdomains to different applications of the same function.[^n2]

:::

For example, [cryptographic protocols](https://en.wikipedia.org/wiki/Cryptographic_protocols) typically rely on [random oracles](wikipedia://en/451286) (ROs, functions that return a value fully determined by their input yet otherwise random). The security proofs for these protocols are based on the assumption that the random oracle is unique to the protocol: if two protocols share the same RO, the assumptions of the proof are not met anymore. Since creating a new [cryptographic primitive](wikipedia://en/4928985) from scratch each time an RO is needed is impractical, multiple ROs (say, RO1 and RO2) are produced by prepending unique **domain separation tags** (DSTs, also known as *domain separators*) to the input of a base oracle RO:

RO1(x) := RO("RO1" || x)

RO2(x) := RO("RO2" || x)

where "RO1" and "RO2" are the strings representing the unique DSTs and || is a [concatenation operator](https://en.wikipedia.org/wiki/Concatenation_operator).[^n3] If the underlying RO function is secure (say, it is a [cryptographic hash](https://en.wikipedia.org/wiki/Cryptographic_hash)), RO1 and RO2 are [statistically independent](https://en.wikipedia.org/wiki/Statistical_independence).[^n1] The technique was originally proposed[^n4] by [Bellare](https://en.wikipedia.org/wiki/Mihir_Bellare) & [Rogaway](https://en.wikipedia.org/wiki/Phillip_Rogaway) in 1993.[^n5]

::: {#o9 .application cue=heading name="Uses"}

## Uses {#Uses}

The domain separation construct can be used for multiple purposes:

- providing independent ROs for protocols;[^n6]
- extending the output size of an RO (for example, by using the RO multiple times (numbered from 1 to L), each time using a representation of oracle number as a DST. This technique is called "counter mode" due to its similarity to the [counter mode](https://en.wikipedia.org/wiki/Counter_mode) of a [block cipher](wikipedia://en/4594);[^n7]
- "keying" the oracle by using an encryption key as a DST.[^n8]

In the practical sense, the domain separation can provide "customization", an equivalent of the [strong typing](https://en.wikipedia.org/wiki/Strong_typing) in programming: it enforces the use of independent calculations for different tasks, so an attacker that had learned a result of one calculation will get no information about another one.[^n9]

:::

## Kinds of functions {#Kinds_of_functions}

Domain separation can be used with functions implementing different [cryptographic primitives](wikipedia://en/4928985).

### Hash functions {#Hash_functions}

Domain separation is most commonly used with hash functions. The input domain of a hash function is practically unlimited, it is easy to partition it among any number of derived functions, for example, by prepending or appending of a DST to the message.[^o16][^n1]

Domain separation is used within the implementation of some hash functions to produce multiple different functions from the same design.[^o18] For example, in [SHA-3](wikipedia://en/20394543) the domain separation makes sure that the differently named functions (like [SHA3-512](https://en.wikipedia.org/wiki/SHA3-512) or [SHAKE128](https://en.wikipedia.org/wiki/SHAKE128)) are independent.[^n9]

### Symmetric ciphers and MACs {#Symmetric_ciphers_and_MACs}

The security of [symmetric ciphers](https://en.wikipedia.org/wiki/Symmetric_cipher) and [MACs](wikipedia://en/567523) critically depends on the key not being used for other purposes. If an application needs multiple keys but has only one source of [keying material](https://en.wikipedia.org/wiki/Keying_material), it would typically employ a [key derivation function](wikipedia://en/449781) to produce the keys. KDFs can usually produce output of arbitrary length, so they can be used to generate any number of keys.[^o21]

Also, just like hash functions, some symmetric ciphers and MACs use domain separation internally.[^o22]

### Signatures {#Signatures}

In many cases, it is desirable to use a single signing key to produce [digital signatures](wikipedia://en/59644) for different purposes. If this is done, it is important to make sure that signed messages intended for one purpose cannot be used for the other. A simple way to achieve this is to add to each message an identifier specifying the purpose, and to reject a message if the identifier doesn't match.[^o24]
