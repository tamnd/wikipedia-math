# Merkle tree

*Image: Hash Tree.svg.* An example of a binary hash tree. Hashes 0-0 and 0-1 are the hash values of data blocks L1 and L2, respectively, and hash 0 is the hash of the concatenation of hashes 0-0 and 0-1.

::: {#o1 .subject cue=lead name="Merkle tree"}

In [cryptography](wikipedia://en/18934432) and [computer science](https://en.wikipedia.org/wiki/Computer_science), a **hash tree** or **Merkle tree** is a [tree](https://en.wikipedia.org/wiki/Tree_%28data_structure%29) in which every "leaf" [node](https://en.wikipedia.org/wiki/Tree_%28data_structure%29#Terminology) is labelled with the [cryptographic hash](wikipedia://en/439526) of a data block, and every node that is not a leaf (called a *branch*, *inner node*, or *inode*) is labelled with the cryptographic hash of the labels of its child nodes. A hash tree allows efficient and secure verification of the contents of a large [data structure](wikipedia://en/8519). A hash tree is a generalization of a [hash list](wikipedia://en/2497149) and a [hash chain](wikipedia://en/7386159).

:::

Demonstrating that a leaf node is a part of a given binary hash tree requires computing a number of hashes proportional to the [logarithm](wikipedia://en/17860) of the number of leaf nodes in the tree.[^o2] Conversely, in a hash list, the number is proportional to the number of leaf nodes itself. A Merkle tree is therefore an efficient example of a [cryptographic commitment scheme](https://en.wikipedia.org/wiki/Cryptographic_commitment#Partial_reveal), in which the root of the tree is seen as a commitment and leaf nodes may be revealed and proven to be part of the original commitment.[^o3]

The concept of a hash tree is named after [Ralph Merkle](wikipedia://en/25849), who patented it in 1979.[^o4][^o5]

::: {#o7 .application cue=heading name="Uses"}

## Uses {#Uses}

Hash trees can be used to verify any kind of data stored, handled and transferred in and between computers. They can help ensure that data [blocks](wikipedia://en/44065971) received from other peers in a [peer-to-peer network](https://en.wikipedia.org/wiki/Peer-to-peer) are received undamaged and unaltered, and even to check that the other peers do not lie and send fake blocks.

Hash trees are used in:

- [hash-based cryptography](wikipedia://en/53957696).
- [InterPlanetary File System](wikipedia://en/47785998) (IPFS),
- [BitTorrent](https://en.wikipedia.org/wiki/BitTorrent)
- hashtree[^o8]
- [ZFS](https://en.wikipedia.org/wiki/ZFS) file system[^o9] (to counter [data degradation](https://en.wikipedia.org/wiki/Data_degradation)[^o10]);
- [Dat](https://en.wikipedia.org/wiki/Dat_%28software%29) protocol;
- [Apache Wave](https://en.wikipedia.org/wiki/Apache_Wave) protocol;[^o11]
- [Git](https://en.wikipedia.org/wiki/Git_%28software%29) and [Mercurial](https://en.wikipedia.org/wiki/Mercurial) distributed revision control systems (although, strictly speaking, they use [directed acyclic graphs](wikipedia://en/204002), not trees);
- the [Tahoe-LAFS](wikipedia://en/24447073) backup system;
- [Zeronet](https://en.wikipedia.org/wiki/Zeronet);
- [OpenZFS](https://en.wikipedia.org/wiki/OpenZFS)[^o12]
- the [Bitcoin](wikipedia://en/28249265) and [Ethereum](https://en.wikipedia.org/wiki/Ethereum) peer-to-peer networks;[^o13]
- the [Certificate Transparency](wikipedia://en/41061790) framework;
- Merkle Tree Certificates;[^o14]
- the [Nix package manager](https://en.wikipedia.org/wiki/Nix_package_manager) and descendants like [GNU Guix](https://en.wikipedia.org/wiki/GNU_Guix);[^o15]
- a number of [NoSQL](https://en.wikipedia.org/wiki/NoSQL) systems such as [Apache Cassandra](https://en.wikipedia.org/wiki/Apache_Cassandra), [Riak](https://en.wikipedia.org/wiki/Riak), and [Dynamo](https://en.wikipedia.org/wiki/Dynamo_%28storage_system%29).[^o16]

Suggestions have been made to use hash trees in [trusted computing](https://en.wikipedia.org/wiki/Trusted_computing) systems.[^o17]

:::

## Overview {#Overview}

A hash tree is a [tree](wikipedia://en/4321) of [hashes](https://en.wikipedia.org/wiki/Hash_function) in which the leaves (i.e., leaf nodes, sometimes also called "leafs") are hashes of data [blocks](wikipedia://en/44065971) in, for instance, a file or set of files. Nodes farther up in the tree are the hashes of their respective children. For example, in the above picture *hash 0* is the result of hashing the [concatenation](wikipedia://en/64474) of *hash 0-0* and *hash 0-1*. That is, *hash 0* = *hash*( *hash 0-0* + *hash 0-1* ) where "+" denotes concatenation.

Most hash tree implementations are binary (two child nodes under each node) but they can just as well use many more child nodes under each node.

Usually, a [cryptographic hash function](wikipedia://en/439526) such as [SHA-2](wikipedia://en/1638777) is used for the hashing. If the hash tree only needs to protect against unintentional damage, non-cryptographic [checksums](https://en.wikipedia.org/wiki/Checksum) such as [CRCs](wikipedia://en/38838) can be used.

In the top of a hash tree there is a *top hash* (or *root hash* or *master hash*). Before downloading a file on a [P2P network](https://en.wikipedia.org/wiki/P2P_network), in most cases the top hash is acquired from a trusted source, for instance a friend or a web site that is known to have good recommendations of files to download. When the top hash is available, the hash tree can be received from any non-trusted source, like any peer in the P2P network. Then, the received hash tree is checked against the trusted top hash, and if the hash tree is damaged or fake, another hash tree from another source will be tried until the program finds one that matches the top hash.[^o19]

The main difference from a [hash list](wikipedia://en/2497149) is that one branch of the hash tree can be downloaded at a time and the integrity of each branch can be checked immediately, even though the whole tree is not available yet. For example, in the picture, the integrity of *data block L2* can be verified immediately if the tree already contains *hash 0-0* and *hash 1* by hashing the data block and iteratively combining the result with *hash 0-0* and then *hash 1* and finally comparing the result with the *top hash*. Similarly, the integrity of *data block L3* can be verified if the tree already has *hash 1-1* and *hash 0*. This can be an advantage since it is efficient to split files up in very small data blocks so that only small blocks have to be re-downloaded if they get damaged. If the hashed file is big, such a hash list or hash chain becomes fairly big. But if it is a tree, one small branch can be downloaded quickly, the integrity of the branch can be checked, and then the downloading of data blocks can start.

### Second preimage attack {#Second_preimage_attack}

The Merkle hash root does not indicate the tree depth, enabling a [second-preimage attack](https://en.wikipedia.org/wiki/Second-preimage_attack) in which an attacker creates a document other than the original that has the same Merkle hash root. For the example above, an attacker can create a new document containing two data blocks, where the first is *hash 0-0* + *hash 0-1*, and the second is *hash 1-0* + *hash 1-1*.[^o21][^o22]

One simple fix is defined in [Certificate Transparency](wikipedia://en/41061790): when computing leaf node hashes, a 0x00 byte is prepended to the hash data, while 0x01 is prepended when computing internal node hashes.[^o19] Limiting the hash tree size is a prerequisite of some [formal security proofs](https://en.wikipedia.org/wiki/Linked_timestamping#Provable_security), and helps in making some proofs tighter. Some implementations limit the tree depth using hash tree depth prefixes before hashes, so any extracted hash chain is defined to be valid only if the prefix decreases at each step and is still positive when the leaf is reached.

### Tiger tree hash {#Tiger_tree_hash}

The Tiger tree hash is a widely used form of hash tree. It uses a binary hash tree (two child nodes under each node), usually has a data block size of 1024 [bytes](https://en.wikipedia.org/wiki/Byte) and uses the [Tiger hash](wikipedia://en/511596).[^o25]

Tiger tree hashes are used in [Gnutella](https://en.wikipedia.org/wiki/Gnutella),[^o26] [Gnutella2](https://en.wikipedia.org/wiki/Gnutella2), and [Direct Connect](https://en.wikipedia.org/wiki/Direct_Connect_%28file_sharing%29) [P2P](https://en.wikipedia.org/wiki/Peer-to-peer) file sharing protocols[^o27] and in [file sharing](https://en.wikipedia.org/wiki/File_sharing) applications such as [Phex](https://en.wikipedia.org/wiki/Phex),[^o28] [BearShare](https://en.wikipedia.org/wiki/BearShare), [LimeWire](https://en.wikipedia.org/wiki/LimeWire), [Shareaza](https://en.wikipedia.org/wiki/Shareaza), [DC++](https://en.wikipedia.org/wiki/DCPlusPlus)[^o29] and [gtk-gnutella](https://en.wikipedia.org/wiki/Gtk-gnutella).[^o30]
