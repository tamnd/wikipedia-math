# Batcher odd–even mergesort

::: {#o2 .subject cue=lead name="Batcher odd–even mergesort"}

**Batcher's odd–even mergesort**[^o3] is a generic construction devised by [Ken Batcher](https://en.wikipedia.org/wiki/Ken_Batcher) for [sorting networks](wikipedia://en/562061) of size O(*n* (log *n*)<sup>2</sup>) and depth O((log *n*)<sup>2</sup>), where *n* is the number of items to be sorted. Although it is not asymptotically optimal, [Knuth](wikipedia://en/8095) concluded in 1998, with respect to the [AKS network](wikipedia://en/562061#Optimal_sorting_networks) that "Batcher's method is much better, unless *n* exceeds the total memory capacity of all computers on earth!"[^o4]

:::

It is popularized by the second *[GPU Gems](https://en.wikipedia.org/wiki/GPU_Gems)* book,[^o5] as an easy way of doing reasonably efficient sorts on graphics-processing hardware.

## Pseudocode {#Pseudocode}

Various recursive and iterative schemes are possible to calculate the indices of the elements to be compared and sorted. This is one iterative technique to generate the indices for sorting n elements:

```text
# note: the input sequence is indexed from 0 to (n-1)
for p = 1, 2, 4, 8, ... # as long as p < n
  for k = p, p/2, p/4, p/8, ... # as long as k >= 1
    for j = mod(k,p) to (n-1-k) with a step size of 2k
      for i = 0 to min(k-1, n-j-k-1) with a step size of 1
        if floor((i+j) / (p*2)) == floor((i+j+k) / (p*2))
          compare and sort elements (i+j) and (i+j+k)
```

Non-recursive calculation of the partner node index is also possible.[^o7]
