# Planarity testing

::: {#o1 .subject cue=lead name="Planarity testing"}

In [graph theory](wikipedia://en/12401), the **planarity testing** problem is the [algorithmic](wikipedia://en/775) problem of testing whether a given graph is a [planar graph](wikipedia://en/24314) (that is, whether it can be drawn in the plane without edge intersections). This is a well-studied problem in [computer science](https://en.wikipedia.org/wiki/Computer_science) for which many practical [algorithms](wikipedia://en/775) have emerged, many taking advantage of novel [data structures](wikipedia://en/8519). Most of these methods operate in [O](wikipedia://en/44578)(*n*) time (linear time), where *n* is the number of edges (or vertices) in the graph, which is [asymptotically optimal](https://en.wikipedia.org/wiki/Asymptotically_optimal). Rather than just being a single Boolean value, the output of a planarity testing algorithm may be a planar [graph embedding](wikipedia://en/8149170), if the graph is planar, or an obstacle to planarity such as a [Kuratowski subgraph](wikipedia://en/54493) if it is not.

:::

## Planarity criteria {#Planarity_criteria}

Planarity testing algorithms typically take advantage of theorems in graph theory that characterize the set of planar graphs in terms that are independent of graph drawings. These include

- [Kuratowski's theorem](wikipedia://en/54493) that a graph is planar if and only if it does not contain a [subgraph](wikipedia://en/325802#subgraph) that is a [subdivision](https://en.wikipedia.org/wiki/Subdivision_%28graph_theory%29) of *K*<sub>5</sub> (the [complete graph](wikipedia://en/85816) on five [vertices](wikipedia://en/638899)) or *K*<sub>3,3</sub> (the [utility graph](https://en.wikipedia.org/wiki/Utility_graph), a [complete bipartite graph](wikipedia://en/525320) on six vertices, three of which connect to each of the other three).
- [Wagner's theorem](wikipedia://en/3126130) that a graph is planar if and only if it does not contain a [minor](https://en.wikipedia.org/wiki/Minor_%28graph_theory%29) (subgraph of a contraction) that is [isomorphic](wikipedia://en/247577) to *K*<sub>5</sub> or *K*<sub>3,3</sub>.
- The [Fraysseix–Rosenstiehl planarity criterion](https://en.wikipedia.org/wiki/Fraysseix–Rosenstiehl_planarity_criterion), characterizing planar graphs in terms of a left-right ordering of the edges in a [depth-first search](wikipedia://en/97034) tree.

The Fraysseix–Rosenstiehl planarity criterion can be used directly as part of algorithms for planarity testing, while Kuratowski's and Wagner's theorems have indirect applications: if an algorithm can find a copy of *K*<sub>5</sub> or *K*<sub>3,3</sub> within a given graph, it can be sure that the input graph is not planar and return without additional computation.

Other planarity criteria, that characterize planar graphs mathematically but are less central to planarity testing algorithms, include:

- [Whitney's planarity criterion](wikipedia://en/3126156) that a graph is planar if and only if its [graphic matroid](wikipedia://en/745714) is also cographic,
- [Mac Lane's planarity criterion](wikipedia://en/781806) characterizing planar graphs by the bases of their [cycle spaces](wikipedia://en/262243),
- [Schnyder's theorem](wikipedia://en/3122052) characterizing planar graphs by the [order dimension](wikipedia://en/3121852) of an associated [partial order](https://en.wikipedia.org/wiki/Partial_order), and
- [Colin de Verdière's planarity criterion](https://en.wikipedia.org/wiki/Colin_de_Verdière_graph_invariant) using [spectral graph theory](wikipedia://en/534914).

## Algorithms {#Algorithms}

### Path addition method {#Path_addition_method}

The classic *path addition* method of [Hopcroft](https://en.wikipedia.org/wiki/John_Hopcroft) and [Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan)[^o6] was the first published linear-time planarity testing algorithm in 1974. An implementation of [Hopcroft](https://en.wikipedia.org/wiki/John_Hopcroft) and [Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan)'s algorithm is provided in the [Library of Efficient Data types and Algorithms](https://en.wikipedia.org/wiki/Library_of_Efficient_Data_types_and_Algorithms) by [Mehlhorn](https://en.wikipedia.org/wiki/Kurt_Mehlhorn), [Mutzel](https://en.wikipedia.org/wiki/Petra_Mutzel) and [Näher](https://en.wikipedia.org/wiki/Stefan_Näher).[^o7][^o8][^o9] In 2012, Taylor[^o10] extended this algorithm to generate all permutations of cyclic edge-order for planar embeddings of biconnected components.

### Vertex addition method {#Vertex_addition_method}

Vertex addition methods work by maintaining a data structure representing the possible embeddings of an [induced subgraph](wikipedia://en/1655188) of the given graph, and adding vertices one at a time to this data structure. These methods began with an inefficient O(*n*<sup>2</sup>) method conceived by [Lempel](https://en.wikipedia.org/wiki/Abraham_Lempel), [Even](https://en.wikipedia.org/wiki/Shimon_Even) and Cederbaum in 1967.[^o12] It was improved by Even and Tarjan, who found a linear-time solution for the *s*,*t*-numbering step,[^o13] and by [Booth](https://en.wikipedia.org/wiki/Kellogg_S._Booth) and [Lueker](https://en.wikipedia.org/wiki/George_S._Lueker), who developed the [PQ tree](wikipedia://en/597568) data structure. With these improvements it is linear-time and outperforms the path addition method in practice.[^o14] This method was also extended to allow a planar embedding (drawing) to be efficiently computed for a planar graph.[^o15] In 1999, Shih and Hsu simplified these methods using the PC tree (an unrooted variant of the PQ tree) and a [postorder traversal](https://en.wikipedia.org/wiki/Postorder_traversal) of the [depth-first search](wikipedia://en/97034) tree of the vertices.[^o16]

### Edge addition method {#Edge_addition_method}

In 2004, John Boyer and [Wendy Myrvold](wikipedia://en/61886633)[^o18] developed a simplified O(*n*) algorithm, originally inspired by the PQ tree method, which gets rid of the PQ tree and uses edge additions to compute a planar embedding, if possible. Otherwise, a Kuratowski subdivision (of either *K*<sub>5</sub> or *K*<sub>3,3</sub>) is computed. This is one of the two current state-of-the-art algorithms today (the other one is the planarity testing algorithm of de Fraysseix, Ossona de Mendez and Rosenstiehl[^o19][^o20]). See [^o21] for an experimental comparison with a preliminary version of the Boyer and Myrvold planarity test. Furthermore, the Boyer–Myrvold test was extended to extract multiple Kuratowski subdivisions of a non-planar input graph in a running time linearly dependent on the output size.[^o22] The source code for the planarity test and the extraction of multiple Kuratowski subdivisions is publicly available.[^o23] Algorithms that locate a Kuratowski subgraph in linear time in vertices were developed by Williamson in the 1980s.[^o24]

### Construction sequence method {#Construction_sequence_method}

A different method uses an inductive construction of 3-connected graphs to incrementally build planar embeddings of every 3-connected component of *G* (and hence a planar embedding of *G* itself).[^o26] The construction starts with *K<sub>4</sub>* and is defined in such a way that every intermediate graph on the way to the full component is again 3-connected. Since such graphs have a unique embedding (up to flipping and the choice of the external face), the next bigger graph, if still planar, must be a refinement of the former graph. This allows to reduce the planarity test to just testing for each step whether the next added edge has both ends in the external face of the current embedding. While this is conceptually very simple (and gives linear running time), the method itself suffers from the complexity of finding the construction sequence.

### Dynamic algorithms {#Dynamic_algorithms}

Planarity testing has been studied in the [Dynamic Algorithms](https://en.wikipedia.org/wiki/Dynamic_problem_%28algorithms%29) model, in which one maintains an answer to a problem (in this case planarity) as the graph undergoes local updates, typically in the form of insertion/deletion of edges. In the edge-arrival case, there is an asympotically tight inverse-[Ackermann function](wikipedia://en/2925) update-time algorithm due to [La Poutré](https://en.wikipedia.org/wiki/Han_La_Poutré_%28computer_scientist%29),[^o28] improving upon algorithms by Di Battista, Tamassia, and Westbrook.[^o29][^o30][^o31] In the fully-dynamic case where edges are both inserted and deleted, there is a logarithmic update-time lower bound by [Pătrașcu](https://en.wikipedia.org/wiki/Mihai_Pătrașcu_%28computer_scientist%29) and [Demaine](https://en.wikipedia.org/wiki/Erik_Demaine),[^o32] and a polylogarithmic update-time algorithm by [Holm](https://en.wikipedia.org/wiki/Jacob_Holm_%28computer_scientist%29) and [Rotenberg](https://en.wikipedia.org/wiki/Eva_Rotenberg_%28computer_scientist%29),[^o33] improving on sub-linear update-time algorithms by [Eppstein](wikipedia://en/4015871), [Galil](wikipedia://en/7913127), [Italiano](https://en.wikipedia.org/wiki/Giuseppe_F._Italiano), Sarnak, and Spencer.[^o34][^o35]
