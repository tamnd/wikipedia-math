# OMDoc

::: {#o2 .subject cue=lead name="OMDoc"}

**OMDoc** (Open Mathematical Documents) is a [semantic](wikipedia://en/29107) markup format for [mathematical](wikipedia://en/18831) documents. While [MathML](wikipedia://en/52313) only covers mathematical formulae and the related [OpenMath](wikipedia://en/746751) standard only supports formulae and “content dictionaries” containing definitions of the symbols used in formulae, OMDoc covers the whole range of written mathematics.

:::

## Coverage {#Coverage}

OMDoc allows for mathematical expressions on three levels:

**Object level**

Formulae, written in Content [MathML](wikipedia://en/52313) (the non-presentational subset of MathML), [OpenMath](wikipedia://en/746751) or languages for [mathematical logic](wikipedia://en/19636).

**Statement level**

Definitions, theorems, proofs, examples and the relations between them (e.g. “this proof proves that theorem”).

**Theory level**

A theory is a set of contextually related statements. Theories may import each other, thereby forming a [graph](https://en.wikipedia.org/wiki/Graph_%28data_structure%29). Seen as collections of symbol definitions, OMDoc theories are compatible to OpenMath content dictionaries.

On each level, formal syntax and informal natural language can be used, depending on the application.

## Semantics and Presentation {#Semantics_and_Presentation}

OMDoc is a semantic markup language that allows writing down the *meaning* of texts about mathematics. In contrast to [LaTeX](https://en.wikipedia.org/wiki/LaTeX), for example, it is not primarily presentation-oriented. An OMDoc document need not specify what its contents should look like. A conversion to LaTeX and [XHTML](https://en.wikipedia.org/wiki/XHTML) (with Presentation [MathML](wikipedia://en/52313) for the formulae) is possible, though. To this end, the presentation of each symbol can be defined.

::: {#o6 .application cue=heading name="Applications"}

## Applications {#Applications}

Today, OMDoc is used in the following settings:

**[E-learning](https://en.wikipedia.org/wiki/E-learning)**

Creation of customized textbooks.

**Data exchange**

OMDoc import and export modules are available for many [automated theorem provers](wikipedia://en/2546) and [computer algebra systems](wikipedia://en/54427). OMDoc is intended to be used for communication between mathematical [web services](https://en.wikipedia.org/wiki/Web_service).

**Document preparation**

Documents about mathematics can be prepared in OMDoc and later exported to a presentation-oriented format like LaTeX or XHTML+MathML.

:::

## History {#History}

OMDoc has been developed by the German mathematician and computer scientist [Michael Kohlhase](https://en.wikipedia.org/wiki/Michael_Kohlhase) since 1998. So far, there have been the following releases:

- \1.0 (November 2000)
- \1.1 (December 2001)
- \1.2 (July 2006)

## Future developments {#Future_developments}

It is planned to create the infrastructure for a “[semantic web](https://en.wikipedia.org/wiki/Semantic_web) for technology and science” based on OMDoc. To this end, OMDoc is being extended towards sciences other than mathematics. The first result is [PhysML](https://en.wikipedia.org/wiki/PhysML), an OMDoc variant extended towards [physics](wikipedia://en/22939).

For a better integration with other Semantic Web applications, an [OWL](https://en.wikipedia.org/wiki/Web_Ontology_Language) ontology of OMDoc is under development, as well as an export facility to [RDF](https://en.wikipedia.org/wiki/Resource_Description_Framework).
