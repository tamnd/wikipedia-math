# Convex layers

::: {#o1 .subject cue=lead name="Convex layers"}

*Image: Convex layers halfspace.svg.* The convex layers of a point set and their intersection with a halfplane

In [computational geometry](wikipedia://en/176927), the **convex layers** of a set of points in the [Euclidean plane](wikipedia://en/15575410) are a sequence of nested [convex polygons](wikipedia://en/660019) having the points as their vertices. The outermost one is the [convex hull](wikipedia://en/40634) of the points and the rest are formed in the same way [recursively](wikipedia://en/25407). The innermost layer may be degenerate, consisting only of one or two points.[^o2] The problem of constructing convex layers has also been called **onion peeling** or **onion decomposition**.[^o3]

:::

Although constructing the convex layers by repeatedly finding convex hulls would be slower, it is possible to partition any set of $n$ points into its convex layers in time $O(n\log n)$.[^o2] Furthermore, the first $k$ convex layers can be computed in output-sensitive time $O(n\log H_k)$[^o4] where $H_k$ denotes the number of points on the first $k$ convex layers.

An early application of the convex layers was in [robust statistics](wikipedia://en/2885691), as a way of identifying [outliers](wikipedia://en/160951) and measuring the [central tendency](https://en.wikipedia.org/wiki/Central_tendency) of a set of sample points.[^o5][^o6] In this context, the number of convex layers surrounding a given point is called its **convex hull peeling depth**, and the convex layers themselves are the depth contours for this notion of data depth.[^o7]

Convex layers may be used as part of an efficient [range reporting](https://en.wikipedia.org/wiki/Range_reporting) data structure for listing all of the points in a query [half-plane](https://en.wikipedia.org/wiki/Half-plane). The points in the half-plane from each successive layer may be found by a binary search to find the most [extreme point](wikipedia://en/454968) in the direction of the half-plane, and then searching sequentially from there. [Fractional cascading](https://en.wikipedia.org/wiki/Fractional_cascading) can be used to speed up the binary searches, giving total query time $O(\log n+k)$ to find $k$ points out of a set of $n$.[^o8]

The points of an $n\times n$ grid have $\Theta(n^{4/3})$ convex layers,[^o9] as do the same number of uniformly random points within any convex shape.[^o10]
