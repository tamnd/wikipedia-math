# Pure type system

::: {#o1 .subject cue=lead name="Pure type system"}

::: {#o2 .problem cue=unsolved}

Is every weakly normalizing pure type system also strongly normalizing?

:::

In the branches of [mathematical logic](wikipedia://en/19636) known as [proof theory](wikipedia://en/183478) and [type theory](wikipedia://en/40282), a **pure type system** (**PTS**), previously known as a **generalized type system** (**GTS**), is a form of [typed lambda calculus](wikipedia://en/366208) that allows an arbitrary number of [sorts](wikipedia://en/4055928#Many-sorted_structures) and dependencies between any of these. The framework can be seen as a generalisation of [Barendregt](wikipedia://en/1651213)'s [lambda cube](wikipedia://en/901593), in the sense that all corners of the cube can be represented as instances of a PTS with just two sorts.[^o3][^o4] In fact, Barendregt (1991) framed his cube in this setting.[^o5] Pure type systems may obscure the distinction between *types* and *terms* and collapse the [type hierarchy](https://en.wikipedia.org/wiki/Type_hierarchy), as is the case with the [calculus of constructions](wikipedia://en/613557), but this is not generally the case, e.g. the [simply typed lambda calculus](wikipedia://en/1986011) allows only terms to depend on terms.

:::

Pure type systems were independently introduced by Stefano Berardi (1988) and Jan Terlouw (1989).[^o3][^o4] Barendregt discussed them at length in his subsequent papers.[^o6] In his PhD thesis,[^o7] Berardi defined a cube of [constructive logics](https://en.wikipedia.org/wiki/Constructive_logic) akin to the lambda cube (these specifications are non-dependent). A modification of this cube was later called the L-cube by Herman Geuvers, who in his PhD thesis extended the [Curry–Howard correspondence](wikipedia://en/254299) to this setting.[^o8] Based on these ideas, G. Barthe and others defined *classical pure type systems* (CPTS) by adding a [double negation](wikipedia://en/379833) operator.[^o9] Similarly, in 1998, Tijn Borghuis introduced *modal pure type systems* (MPTS).[^o10] Roorda has discussed the application of pure type systems to [functional programming](https://en.wikipedia.org/wiki/Functional_programming); and Roorda and Jeuring have proposed a [programming language](wikipedia://en/23015) based on pure type systems.[^o11]

The systems from the lambda cube are all known to be [strongly normalizing](https://en.wikipedia.org/wiki/Strongly_normalizing). Pure type systems in general need not be, for example [System U](wikipedia://en/49481270) from **Girard's paradox** is not. (Roughly speaking, [Girard](wikipedia://en/579673) found pure systems in which one can express the sentence "the types form a type".) Furthermore, all known examples of pure type systems that are not strongly normalizing are not even (weakly) [normalizing](https://en.wikipedia.org/wiki/Normalization_property_%28abstract_rewriting%29): they contain expressions that do not have [normal forms](wikipedia://en/5085531), just like the [untyped lambda calculus](https://en.wikipedia.org/wiki/Untyped_lambda_calculus). It is a major open problem in the field whether this is always the case, i.e. whether a (weakly) normalizing PTS always has the strong normalization property. This is known as the Barendregt–Geuvers–Klop conjecture (named after [Henk Barendregt](wikipedia://en/1651213), [Herman Geuvers](https://en.wikipedia.org/wiki/Herman_Geuvers), and [Jan Willem Klop](https://en.wikipedia.org/wiki/Jan_Willem_Klop)).[^o12]

::: {#o14 .definition cue=heading name="Definition"}

## Definition {#Definition}

A pure type system is defined by a triple $(\mathcal{S}, \mathcal{A}, \mathcal{R})$ where $\mathcal{S}$ is the [set](wikipedia://en/26691) of sorts, $\mathcal{A} \subseteq \mathcal{S}^2$ is the set of axioms, and $\mathcal{R} \subseteq \mathcal{S}^3$ is the set of rules. Typing in pure type systems is determined by the following rules, where $s$ is any sort:[^o6]

$$\frac{(s_1, s_2) \in \mathcal{A}}{\vdash s_1 : s_2}\quad \text{(axiom)}$$

$$\frac{\Gamma \vdash A : s \quad x \notin \text{dom}(\Gamma)}{\Gamma, x : A \vdash x : A }\quad \text{(start)}$$

$$\frac{\Gamma \vdash A : B \quad \Gamma \vdash C : s \quad x \notin \text{dom}(\Gamma)}{\Gamma, x : C \vdash A : B}\quad \text{(weakening)}$$

$$\frac{\Gamma \vdash A : s_1 \quad \Gamma, x : A \vdash B : s_2 \quad (s_1, s_2, s_3) \in \mathcal{R}}{\Gamma \vdash \Pi x : A. B : s_3}\quad\text{(product)}$$

$$\frac{\Gamma \vdash C : \Pi x : A. B \quad \Gamma \vdash a : A}{\Gamma \vdash Ca : B[x := a]}\quad\text{(application)}$$

$$\frac{\Gamma, x : A \vdash b : B \quad \Gamma \vdash \Pi x : A. B : s}{\Gamma \vdash \lambda x : A. b : \Pi x : A. B}\quad\text{(abstraction)}$$

$$\frac{\Gamma \vdash A : B \quad B =_{\beta} B' \quad \Gamma \vdash B' : s}{\Gamma \vdash A : B'}\quad\text{(conversion)}$$

:::

## Implementations {#Implementations}

The following programming languages have pure type systems:

- SAGE[^o17]
- Yarrow[^o18]
- Henk 2000[^o19]
- [Haskell](https://en.wikipedia.org/wiki/Haskell) since GHC version 8.[^o20][^o21]
