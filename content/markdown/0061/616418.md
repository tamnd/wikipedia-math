# PKCS

::: {#o1 .subject cue=lead name="PKCS"}

**Public Key Cryptography Standards** (**PKCS**) are a group of [public-key cryptography](wikipedia://en/24222) intervendor standards first developed by [RSA Security](wikipedia://en/301240), with involvement from [Apple](https://en.wikipedia.org/wiki/Apple_Inc.), [Digital](https://en.wikipedia.org/wiki/Digital_Equipment_Corporation), [Lotus Development](https://en.wikipedia.org/wiki/Lotus_Development), [Microsoft](https://en.wikipedia.org/wiki/Microsoft), [MIT](https://en.wikipedia.org/wiki/Massachusetts_Institute_of_Technology), [Northern Telecom](https://en.wikipedia.org/wiki/Nortel), and [Sun Microsystems](https://en.wikipedia.org/wiki/Sun_Microsystems), first published in June 1991.[^o2]

:::

The PKCS series of standards began development internally at RSA Laboratories in March 1991 with the "broad design goals" of maintaining compatibility with existing [Privacy-Enhanced Mail](wikipedia://en/552878) (PEM) protocol certificates, allow handling of arbitrary data, adding richer information in certificate attributes, supporting [Diffie-Hellman key exchange](https://en.wikipedia.org/wiki/Diffie-Hellman_key_exchange), and creating protocols to be some day incorporated into [International Telecommunication Union](https://en.wikipedia.org/wiki/International_Telecommunication_Union) X.200 standards by basing it on existing ITU-T standards such as [ASN.1](https://en.wikipedia.org/wiki/ASN.1) and [BER](https://en.wikipedia.org/wiki/Basic_Encoding_Rules). [^o3] PKCS then taken by RSA to the US [National Institute of Standards and Technology](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology)'s Open Systems Interconnection Workshop, an organization created in 1983 by NIST at the request of industry to provide a forum for industry co-operation in computer interconnection protocols. Development of the PKCS protocols was undertaken in the 1991 sessions of the OSI Workshop under the Security Special Interest Group chaired by [Trusted Information Systems](https://en.wikipedia.org/wiki/Trusted_Information_Systems). However, PKCS did not appear in the final OSI Workshop yearly publication [^o4] [^o5] and was instead published as an OSI working document, the first publicly available version of the protocols.[^o3] Though not [industry standards](https://en.wikipedia.org/wiki/List_of_computer_standards) because the company retained control over them, some of the standards have moved into the "[standards track](https://en.wikipedia.org/wiki/Standards_track)" processes of relevant [standards organizations](https://en.wikipedia.org/wiki/Standards_organization) since May 1997,[^o6] such as the [IETF](https://en.wikipedia.org/wiki/IETF) and the [PKIX](https://en.wikipedia.org/wiki/PKIX) working group.

**Key Updates (2023–2025):**

- Integration of [PKCS #7](wikipedia://en/64431194) and [PKCS #12](wikipedia://en/12545362) into broader standards like S/MIME and TLS.
- Evolution of [PKCS #11](wikipedia://en/7620041) to support newer hardware and cloud services; support for NIST's [ML-DSA](https://en.wikipedia.org/wiki/ML-DSA) and [ML-KEM](https://en.wikipedia.org/wiki/ML-KEM).
- Involvement of PKCS standards in post-quantum cryptography efforts, with NIST's ongoing standardization.
- Growing adoption of PKCS standards in the context of blockchain and digital assets.

*PKCS Standards Summary*

::: {#o7 .table cue=table name="PKCS Standards Summary"}

|  | Version | Name | Comments |
|---|---|---|---|
| [PKCS #1](wikipedia://en/16706008) | \2.2 | RSA Cryptography Standard[^o9] | See 8017. Defines the mathematical properties and format of RSA public and private keys ([ASN.1](https://en.wikipedia.org/wiki/ASN.1)-encoded in clear-text), and the basic algorithms and encoding/[padding](wikipedia://en/592505) schemes for performing RSA encryption, decryption, and producing and verifying signatures. |
| PKCS #2 | \- | *Withdrawn* | No longer active. Covered RSA encryption of message digests; subsequently merged into PKCS #1 by PKCS#1 v1.5 in 1993. |
| PKCS #3 | \1.4 | [Diffie–Hellman Key Agreement](wikipedia://en/7903) Standard[^o10] | A cryptographic protocol that allows two parties that have no prior knowledge of each other to jointly establish a shared secret key over an insecure communications channel. |
| PKCS #4 | \- | *Withdrawn* | No longer active. Covered RSA key syntax; subsequently merged into PKCS #1 by PKCS#1 v1.5 in 1993. |
| PKCS #5 | \2.1 | Password-based Encryption Standard[^o11][^o12] | See 8018 and [PBKDF2](wikipedia://en/1568244). |
| PKCS #6 | \1.5 | Extended-Certificate Syntax Standard[^o13] | Defines extensions to the old v1 [X.509](https://en.wikipedia.org/wiki/X.509) certificate specification. Obsoleted by v3 of the same. |
| [PKCS #7](wikipedia://en/64431194) | \1.5 | [Cryptographic Message Syntax](wikipedia://en/442961) Standard[^o15] | See 2315. Used to sign and/or encrypt messages under a [PKI](wikipedia://en/194112). Used also for certificate dissemination (for instance as a response to a PKCS #10 message). Formed the basis for [S/MIME](https://en.wikipedia.org/wiki/S/MIME), which is based on 5652, an updated [Cryptographic Message Syntax Standard](wikipedia://en/442961) (CMS). Often used for [single sign-on](https://en.wikipedia.org/wiki/Single_sign-on). |
| [PKCS #8](wikipedia://en/40387096) | \2.0 | Private-Key Information Syntax Standard[^o17] | See 5958. Used to carry private and public keys (encrypted or unencrypted). |
| PKCS #9 | \2.0 | Selected Attribute Types[^o18] | See 2985. Defines selected attribute types for use in PKCS #6 extended certificates, PKCS #7 digitally signed messages, PKCS #8 private-key information, and PKCS #10 certificate-signing requests. |
| [PKCS #10](https://en.wikipedia.org/wiki/PKCS_10) | \1.7 | Certification Request Standard[^o20] | See 2986. Format of messages sent to a [certification authority](https://en.wikipedia.org/wiki/Certification_authority) to request certification of a public key. See [certificate signing request](wikipedia://en/1124588). |
| [PKCS #11](wikipedia://en/7620041) | \3.2 | Cryptographic Token Interface[^o22] | Also known as "Cryptoki". An [API](https://en.wikipedia.org/wiki/API) defining a generic interface to [cryptographic tokens](https://en.wikipedia.org/wiki/Cryptographic_token) (see also [hardware security module](https://en.wikipedia.org/wiki/Hardware_security_module)). Often used in [single sign-on](https://en.wikipedia.org/wiki/Single_sign-on), [public-key cryptography](wikipedia://en/24222) and [disk encryption](wikipedia://en/7066791)[^o23] systems. RSA Security has turned over further development of the PKCS #11 standard to the [OASIS PKCS 11 Technical Committee](https://www.oasis-open.org/committees/pkcs11/). |
| [PKCS #12](wikipedia://en/12545362) | \1.1 | Personal Information Exchange Syntax Standard[^o25] | See 7292. Defines a file format commonly used to store [private keys](https://en.wikipedia.org/wiki/Private_key) with accompanying [public key certificates](wikipedia://en/223796), protected with a password-based [symmetric key](https://en.wikipedia.org/wiki/Symmetric_key). PFX is a predecessor to PKCS #12. This container format can contain multiple embedded objects, such as multiple certificates. Usually protected/encrypted with a password. Usable as a format for the [Java KeyStore](https://en.wikipedia.org/wiki/Java_KeyStore) and to establish client authentication certificates in Mozilla Firefox. Usable by [Apache Tomcat](https://en.wikipedia.org/wiki/Apache_Tomcat). |
| PKCS #13 | – | [Elliptic-curve cryptography](wikipedia://en/9966) Standard | *(Apparently abandoned, only reference is a proposal from 1998.)* |
| PKCS #14 | – | [Pseudo-random Number Generation](wikipedia://en/45524) | *(Apparently abandoned, no documents exist.)* |
| PKCS #15 | \1.1 | Cryptographic Token Information Format Standard[^o26] | Defines a standard allowing users of [cryptographic tokens](https://en.wikipedia.org/wiki/Cryptographic_token) to identify themselves to applications, independent of the application's Cryptoki implementation (PKCS #11) or other [API](https://en.wikipedia.org/wiki/API). RSA has relinquished IC-card-related parts of this standard to [ISO/IEC 7816](https://en.wikipedia.org/wiki/ISO/IEC_7816)-15.[^o27] |

:::
