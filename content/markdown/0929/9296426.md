# Randomness test

::: {#o1 .subject cue=lead name="Randomness test"}

A **randomness test** (or **test for randomness**), in data evaluation, is a test used to analyze the distribution of a set of data to see whether it can be described as [random](https://en.wikipedia.org/wiki/Random) (patternless). In [stochastic modeling](https://en.wikipedia.org/wiki/Stochastic_modeling), as in some [computer simulations](https://en.wikipedia.org/wiki/Computer_simulation), the hoped-for randomness of potential input data can be verified, by a formal test for randomness, to show that the data are valid for use in simulation runs. In some cases, data reveals an obvious non-random pattern, as with so-called "runs in the data" (such as expecting random 0–9 but finding "4 3 2 1 0 4 3 2 1..." and rarely going above 4). If a selected set of data fails the tests, then parameters can be changed or other randomized data can be used which does pass the tests for randomness.

:::

## Background {#Background}

The issue of randomness is an important philosophical and theoretical question. Tests for randomness can be used to determine whether a data set has a recognisable pattern, which would indicate that the process that generated it is significantly non-random. For the most part, statistical analysis has, in practice, been much more concerned with finding regularities in data as opposed to testing for randomness. Many "random number generators" in use today are defined by algorithms, and so are actually *[pseudo-random](https://en.wikipedia.org/wiki/Pseudo-random)* number generators. The sequences they produce are called pseudo-random sequences. These generators do not always generate sequences which are sufficiently random, but instead can produce sequences which contain patterns. For example, the infamous [RANDU](https://en.wikipedia.org/wiki/RANDU) routine fails many randomness tests dramatically, including the [spectral test](https://en.wikipedia.org/wiki/Spectral_test).

[Stephen Wolfram](wikipedia://en/52469) used randomness tests on the output of [Rule 30](https://en.wikipedia.org/wiki/Rule_30) to examine its potential for generating random numbers,[^o3] though it was shown to have an effective key size far smaller than its actual size[^o4] and to perform poorly on a [chi-squared test](wikipedia://en/226680).[^o5] The use of an ill-conceived random number generator can put the validity of an experiment in doubt by violating statistical assumptions. Though there are commonly used statistical testing techniques such as NIST standards, Yongge Wang showed that NIST standards are not sufficient. Furthermore, Yongge Wang[^o6] designed statistical–distance–based and law–of–the–iterated–logarithm–based testing techniques. Using this technique, Yongge Wang and Tony Nicol[^o7] detected the weakness in commonly used pseudorandom generators such as the well known [Debian version of OpenSSL pseudorandom generator](wikipedia://en/1250124#Debian_OpenSSL) which was fixed in 2008.

## Specific tests for randomness {#Specific_tests_for_randomness}

There have been a fairly small number of different types of (pseudo-)random number generators used in practice. They can be found in the [list of random number generators](wikipedia://en/4160163), and have included:

- [Linear congruential generator](wikipedia://en/45527) and [Linear-feedback shift register](wikipedia://en/58992)
- Generalized Fibonacci generator
- Cryptographic generators
- Quadratic congruential generator
- Cellular automaton generators
- [Pseudorandom binary sequence](https://en.wikipedia.org/wiki/Pseudorandom_binary_sequence)

These different generators have varying degrees of success in passing the accepted test suites. Several widely used generators fail the tests more or less badly, while other 'better' and prior generators (in the sense that they passed all current batteries of tests and they already existed) have been largely ignored.

There are many practical measures of [randomness](wikipedia://en/19196523) for a [binary sequence](https://en.wikipedia.org/wiki/Binary_sequence). These include measures based on [statistical tests](https://en.wikipedia.org/wiki/Statistical_tests), [transforms](wikipedia://en/634765), and [complexity](https://en.wikipedia.org/wiki/Complexity) or a mixture of these. A well-known and widely used collection of tests was [the Diehard Battery of Tests](wikipedia://en/2167005), introduced by Marsaglia; this was extended to the [TestU01](https://en.wikipedia.org/wiki/TestU01) suite by L'Ecuyer and Simard. The use of [Hadamard transform](wikipedia://en/634765) to measure randomness was proposed by [S. Kak](https://en.wikipedia.org/wiki/Subhash_Kak) and developed further by Phillips, Yuen, Hopkins, Beth and Dai, Mund, and [Marsaglia](https://en.wikipedia.org/wiki/George_Marsaglia) and Zaman.[^o9]

Several of these tests, which are of linear complexity, provide spectral measures of randomness. T. Beth and Z-D. Dai purported to show that [Kolmogorov complexity](wikipedia://en/1635) and linear complexity are practically the same,[^o10] although Y. Wang later showed their claims are incorrect.[^o11] Nevertheless, Wang also demonstrated that for [Martin-Löf random](https://en.wikipedia.org/wiki/Martin-Löf_random) sequences, the Kolmogorov complexity is essentially the same as linear complexity.

These practical tests make it possible to compare the randomness of [strings](wikipedia://en/27701). On probabilistic grounds, all strings of a given length have the same randomness. However different strings have a different Kolmogorov complexity. For example, consider the following two strings.

String 1: `0101010101010101010101010101010101010101010101010101010101010101`

String 2: `1100100001100001110111101110110011111010010000100101011110010110`

String 1 admits a short linguistic description: "32 repetitions of '01'". This description has 22 characters, and it can be efficiently constructed out of some basis sequences. String 2 has no obvious simple description other than writing down the string itself, which has 64 characters, and it has no comparably efficient [basis function](wikipedia://en/50909) representation. Using linear Hadamard spectral tests (see [Hadamard transform](wikipedia://en/634765)), the first of these sequences will be found to be much less random than the second one, which agrees with intuition.
