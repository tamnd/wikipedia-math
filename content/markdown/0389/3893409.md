# Any type

::: {#o1 .subject cue=lead name="Any type"}

In [type theory](wikipedia://en/40282) and [computer science](https://en.wikipedia.org/wiki/Computer_science), [type systems](wikipedia://en/199701) include a ***top*, *universal*,** or ***any* type** (often represented with the [down tack](https://en.wikipedia.org/wiki/Down_tack) (**⊤**) symbol), which includes all other types as subtypes. The top type is sometimes called also ***universal* type**, or **universal supertype** as all other types in the type system of interest are [subtypes](wikipedia://en/213508) of it. In [object-oriented](https://en.wikipedia.org/wiki/Object-oriented_programming) languages, it is often called **Object**, as it represents all possible objects.

:::

The top type contrasts with the [bottom type](https://en.wikipedia.org/wiki/Bottom_type), or the *universal subtype*, which every other type is the supertype of. The bottom type is a type that contains no subtypes at all.

## Support in programming languages {#Support_in_programming_languages}

Several typed [programming languages](wikipedia://en/23015) provide explicit support for the top type.

In [statically-typed](wikipedia://en/199701#Static_type_checking) languages, there are two different, often confused, concepts when discussing the top type.

1. A *universal base [class](https://en.wikipedia.org/wiki/Class_%28programming%29)* or other item at the top of a [runtime](https://en.wikipedia.org/wiki/Execution_%28computing%29#Runtime) *class hierarchy* (often relevant in [object-oriented programming](https://en.wikipedia.org/wiki/Object-oriented_programming)) or *type hierarchy*; it is often possible to create objects with this (runtime) type, or it could be found when one examines the type hierarchy programmatically, in languages that support it
1. A ([compile time](https://en.wikipedia.org/wiki/Compile_time)) *static type* in the code whose variables can be assigned any value (or a subset thereof, like any object pointer value), similar to [dynamic typing](wikipedia://en/199701#Dynamic_type_checking_and_runtime_type_information)

The first concept often implies the second, i.e., if a universal base class exists, then a variable that can point to an object of this class can also point to an object of any class. However, several languages have types in the second regard above (e.g., `void*` in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), `id` in [Objective-C](https://en.wikipedia.org/wiki/Objective-C), `interface {}` in [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29)), static types which variables can accept any object value, but which do not reflect real runtime types that an object can have in the type system, so are not top types in the first regard.

In dynamically-typed languages, the second concept does not exist (any value can be assigned to any variable anyway), so only the first (class hierarchy) is discussed. This article tries to stay with the first concept when discussing top types, but also mention the second concept in languages where it is significant.

The following object-oriented languages have no universal base class:

- C++ and Rust have no universal class like `Object`.
- [Objective-C](https://en.wikipedia.org/wiki/Objective-C). It is possible to create a new base class by not specifying a parent class for a class, although this is highly unusual. `Object` is conventionally used as the base class in the original Objective-C runtimes. In the [OpenStep](https://en.wikipedia.org/wiki/OpenStep) and [Cocoa](https://en.wikipedia.org/wiki/Cocoa_%28API%29) Objective-C [libraries](https://en.wikipedia.org/wiki/Library_%28computing%29), `NSObject` is conventionally the universal base class. The top type for pointers to objects is `id`.
- [Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29). It is possible to create a new base class by not specifying a parent class for a class. The protocol `Any` can accept any type.

### Other languages {#Other_languages}

Languages that are not object-oriented usually have no universal supertype, or subtype [polymorphism](https://en.wikipedia.org/wiki/Polymorphism_%28computer_science%29) support.

While [Haskell](https://en.wikipedia.org/wiki/Haskell) purposefully lacks subtyping, it has several other forms of polymorphism including [parametric polymorphism](https://en.wikipedia.org/wiki/Parametric_polymorphism). The most generic type class parameter is an unconstrained parameter `a` (without a [type class](https://en.wikipedia.org/wiki/Type_class) constraint). In [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29),

```rust
<T: ?Sized>
```

is the most generic parameter (`<T>` is not, as it implies the `Sized` trait by default).

`std::any` (in C++) and `std::any::Any` (in Rust) are not actually top types in the type-system, but rather type-erased containers, from which the data is obtained through [downcasting](https://en.wikipedia.org/wiki/Downcasting) (or *type refinement*).

`std.variant.Variant` in D behaves like an any type, but rather than being a root of an inheritance tree, it is a [tagged union](wikipedia://en/453395) of all types.

The top type is used as a *generic* type, more so in languages without [parametric polymorphism](https://en.wikipedia.org/wiki/Parametric_polymorphism). For example, before the introduction of generics to [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) in Java 5, collection classes in the [Java standard library](https://en.wikipedia.org/wiki/Java_Class_Library) (excluding Java arrays) held references of type `java.lang.Object`. In this way, any non-intrinsic type could be inserted into a collection. The top type is also often used to hold objects of unknown type. Java supports "[wildcard](https://en.wikipedia.org/wiki/Wildcard_%28Java%29) type parameters", represented by `?`. For instance, `List<?>` denotes a list that can hold any type (but not [null](https://en.wikipedia.org/wiki/Null_pointer)). Wildcards can be bounded,

```java
List<? extends T>
```

and

```java
List<? super T>
```

denote a list that can hold any type that inherits from/is an ancestor class of (respectively) type `T` (including `T` itself). Wildcards however cannot simultaneously have both upper and lower bounds.

The top type may also be seen as the implied type of non-statically typed languages. Languages with runtime typing often provide downcasting to allow discovering a more specific type for an object at runtime.

In [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) and [C++](https://en.wikipedia.org/wiki/C++), the *void pointer* type (`void*`) can accept any non-function pointer, even though the [void type](https://en.wikipedia.org/wiki/Void_type) is not the universal type but the [unit type](wikipedia://en/3646268). In C++, downcasting from `void*` cannot be done in a *safe* way, where failed downcasts are detected by the language runtime.

In languages with a [structural type system](https://en.wikipedia.org/wiki/Structural_type_system), the empty structure serves as a top type. For example, objects in [OCaml](https://en.wikipedia.org/wiki/OCaml) are structurally typed; the empty object type (the type of objects with no methods), `< >`, is the top type of object types. Any OCaml object can be explicitly upcasted to this type, although the result would be of no use. [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29) also uses structural typing; and all types implement the empty interface: `interface {}`, which has no methods, but may still be downcast back to a more specific type.

In [Kotlin](https://en.wikipedia.org/wiki/Kotlin_%28programming_language%29), the top type is `kotlin.Any?`, a nullable form of `kotlin.Any` (the top type that disallows `null`). Although `kotlin.Any` maps to `java.lang.Object` in the [JVM](https://en.wikipedia.org/wiki/Java_Virtual_Machine), Kotlin enforces nullability while Java does not.

## In logic {#In_logic}

The notion of *top* is also found in [propositional calculus](https://en.wikipedia.org/wiki/Propositional_calculus), linking to a formula which is true in every possible interpretation. It has a similar meaning in [predicate calculus](https://en.wikipedia.org/wiki/Predicate_calculus). In [description logic](wikipedia://en/183503), top is used to refer to the set of all concepts. This is intuitively like the use of the top type in programming languages. For example, in the [Web Ontology Language](https://en.wikipedia.org/wiki/Web_Ontology_Language) (OWL), which supports several description logics, top corresponds to the class `owl:Thing`, where all classes are subclasses of `owl:Thing`. (the bottom type or empty set corresponds to `owl:Nothing`).
