# Hopcroft's problem

::: {#o1 .subject cue=lead name="Hopcroft's problem"}

In [computational geometry](wikipedia://en/176927), **Hopcroft's problem** is the problem of testing, for a given system of points and lines in the [Euclidean plane](wikipedia://en/15575410), whether at least one of the points lies on at least one of the lines. More generally, one may ask for the number of point–line incidences. Both versions of the problem can be solved in time $O(n^{4/3})$, where $n$ is the total number of points and lines. This time bound matches the bound of $O(n^{4/3})$ on the total number of point-line incidences given by the [Szemerédi–Trotter theorem](wikipedia://en/1051627). Hopcroft's problem is named after [John Hopcroft](https://en.wikipedia.org/wiki/John_Hopcroft), who posed it in the early 1980s. Its [computational complexity](wikipedia://en/6511) is closely connected to the complexity of several other problems in computational geometry, including that of three-dimensional [Euclidean minimum spanning trees](wikipedia://en/1040597).

:::

## Algorithms {#Algorithms}

One way of solving the problem involves a geometric [divide-and-conquer algorithm](wikipedia://en/201154). For a given system of points and lines, it is possible to use the theory of [epsilon-nets](wikipedia://en/28807941) to subdivide the plane, for a given parameter $r$ into $O(r)$ triangular subproblems each crossed by a $1/r^2$ fraction of the lines and each containing a $1/r$ fraction of the points. Alternatively, applying the same technique to the [projective dual](https://en.wikipedia.org/wiki/Projective_dual) system of dual lines and dual points, one can obtain subproblems each involving a $1/r$ fraction of the input lines and a $1/r^2$ fraction of the points. Doing this once each way, for $r=n^{1/3}$, would reduce the problem to subproblems of constant size, which can be solved directly. This idea (with a more careful choice of the parameter $r$) leads to a time bound of $O(n^{4/3}\log^{1/3} n)$. Here, the extra logarithmic factor comes from the overhead of assigning points and lines to the subproblems that are generated in this way.

The same two-step subdivision process, with a choice of $r$ that is smaller by a logarithmic factor, can reduce the given problem to subproblems whose size is a [polylogarithmic function](wikipedia://en/445957) of $n$, in time $O(n^{4/3})$. Repeating this process [recursively](wikipedia://en/4044867) until the input is reduced to subproblems of constant size, would lead to a time bound of the form $n^{4/3}2^{O(\log^* n)}$. Here $\log^* n$ denotes the [iterated logarithm](wikipedia://en/1038048).

In a 2024 paper, Chan and Zheng showed that there exist [algebraic decision trees](https://en.wikipedia.org/wiki/Algebraic_decision_tree) for Hopcroft's problem whose depth is $O(n^{4/3})$. These cannot be used directly to solve Hopcroft's problem, because they have exponential size and cannot be constructed efficiently; however they can be used in combination with the divide-and-conquer methods. Following a suggestion credited to [David Eppstein](wikipedia://en/4015871) by [Jiří Matoušek](wikipedia://en/20938051), Chan and Zheng describe an algorithm that performs a constant number of levels of the recursive algorithm, reducing the problem to many subproblems whose size is an iterated logarithm of the original input size. This is small enough for an optimal decision tree to be constructed by a [brute-force search](https://en.wikipedia.org/wiki/Brute-force_search), and then used to solve each subproblem. The result is an algorithm for Hopcroft's problem with total time $O(n^{4/3})$.

In a 2024 preprint, Andrejevs, Belovs, and Vihrovs have announced a [quantum algorithm](https://en.wikipedia.org/wiki/Quantum_algorithm) for Hopcroft's problem that runs in time $\tilde O(n^{5/6})$, where the $\tilde O$ notation hides logarithmic factors. This is substantially below the best known time bound for a classical algorithm.

:::

## Lower bounds {#Lower_bounds}

A natural limitation on Hopcroft's algorithm is the number of point–line incidences, which could be $\Theta(n^{4/3})$ by the [Szemerédi–Trotter theorem](wikipedia://en/1051627). This would also provide a lower bound on algorithms for listing all point–line incidences, but not for detecting whether there is an incidence or counting the incidences.

The divide-and-conquer algorithms for Hopcroft's algorithm operate purely by subdividing the plane in which the input points and lines are given and its dual projective plane. Jeff Erickson proved a [lower bound](https://en.wikipedia.org/wiki/Lower_bound), according to which algorithms that operate in this way must take time $\Omega(n^{4/3})$. However, methods based on algebraic decision trees do not fit this model, and Erickson's lower bound does not apply to algebraic decision trees. If there exist algebraic decision trees for the problem with depth $o(n^{4/3})$, they could be used in the same way to solve Hopcroft's problem in time $o(n^{4/3})$.
