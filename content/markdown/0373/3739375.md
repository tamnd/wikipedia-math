# Q-systems

::: {#o1 .subject cue=lead name="Q-systems"}

**Q-systems** are a method of [directed graph](wikipedia://en/19721986) transformations according to given [grammar](wikipedia://en/12569) rules, developed at the [Université de Montréal](https://en.wikipedia.org/wiki/Université_de_Montréal) by [Alain Colmerauer](https://en.wikipedia.org/wiki/Alain_Colmerauer) in 1967–70 for use in [natural language processing](https://en.wikipedia.org/wiki/Natural_language_processing). The Université de Montréal's [machine translation](https://en.wikipedia.org/wiki/Machine_translation) system, [TAUM-73](https://en.wikipedia.org/wiki/TAUM_system), used the Q-Systems as its language formalism.

:::

The data structure manipulated by a Q-system is a [Q-graph](https://en.wikipedia.org/wiki/Q-graph), which is a directed acyclic graph with one entry node and one exit node, where each arc bears a [labelled ordered tree](https://en.wikipedia.org/wiki/Labelled_ordered_tree). An input sentence is usually represented by a linear Q-graph where each arc bears a word (tree reduced to one node labelled by this word). After analysis, the Q-graph is usually a bundle of 1-arc paths, each arc bearing a possible analysis tree. After generation, the goal is usually to produce as many paths as desired outputs, with again one word per arc.

A Q-System consists of a sequence of [Q-treatments](https://en.wikipedia.org/wiki/Q-treatments), each being a set of [Q-rules](https://en.wikipedia.org/wiki/Q-rules), of the form \<matched\_path> == \<added\_path> \[\<condition>\]. The Q-treatments are applied in sequence, unless one of them produces the empty Q-graph, in which case the result is the last Q-graph obtained. The three parts of a rule can contain variables for labels, trees, and forests. All variables after "==" must appear in the \<matched\_path> part. Variables are local to rules.

A Q-treatment works in two steps, addition and cleaning. It first applies all its rules exhaustively, using [instantiation](https://en.wikipedia.org/wiki/Instance_%28computer_science%29) (one-way unification), thereby adding new paths to the current Q-graph (added arcs and their trees can be used to produce new paths). If and when this addition process halts, all arcs used in some successful rule application are erased, as well as all unused arcs that are no more on any path from the entry node to the exit node. Hence, the result, if any (if the addition step terminates), is again a Q-graph. That allows several Q-Systems to be chained, each of them performing a specialized task, together forming a complex system. For example, TAUM 73 consisted of fifteen chained Q-Systems.

An extension of the basic idea of the Q-Systems, namely to replace instantiation by [unification](wikipedia://en/54432) (to put it simply, allow "new" variables in the right hand side part of a rule, and replace parametrized labelled trees by logical terms) led to [Prolog](wikipedia://en/23485), designed by [Alain Colmerauer](https://en.wikipedia.org/wiki/Alain_Colmerauer) and [Philippe Roussel](https://en.wikipedia.org/wiki/Philippe_Roussel) in 1972. Refinements in the other direction (reducing non-determinism and introducing typed labels) by [John Chandioux](https://en.wikipedia.org/wiki/John_Chandioux) led to [GramR](https://en.wikipedia.org/wiki/GramR), used for programming [METEO](https://en.wikipedia.org/wiki/METEO_System) from 1985 onward.

In 2009, Hong Thai Nguyen of GETALP,[^o2] Laboratoire d'Informatique de Grenoble[^o3] reimplemented the Q-language in C, using ANTLR to compile the Q-systems and the Q-graphs, and an algorithm proposed by Christian Boitet (as none had been published and sources of the previous [Fortran](https://en.wikipedia.org/wiki/Fortran) implementation had been lost). That implementation was corrected, completed and extended (to labels using Unicode characters and not only the printable characters of the CDC6600 of the historical version) by David Cattanéo in 2010-11.
