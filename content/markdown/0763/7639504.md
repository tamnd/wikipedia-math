# BIT predicate

::: {#o1 .subject cue=lead name="BIT predicate"}

In [mathematics](wikipedia://en/18831) and [computer science](https://en.wikipedia.org/wiki/Computer_science), the **BIT predicate**, sometimes written $\text{BIT}(i,j)$, is a [predicate](https://en.wikipedia.org/wiki/Predicate_%28mathematical_logic%29) that tests whether the $j$th [bit](https://en.wikipedia.org/wiki/Bit) of the number $i$ (starting from the [least significant bit](https://en.wikipedia.org/wiki/Least_significant_bit)) is 1, when $i$ is written as a [binary number](wikipedia://en/238686). Its mathematical applications include modeling the membership relation of [hereditarily finite sets](wikipedia://en/332621), and defining the adjacency relation of the [Rado graph](wikipedia://en/7785594). In computer science, it is used for efficient representations of set [data structures](wikipedia://en/8519) using [bit vectors](https://en.wikipedia.org/wiki/Bit_vector), in defining the [private information retrieval](https://en.wikipedia.org/wiki/Private_information_retrieval) problem from [communication complexity](wikipedia://en/50329), and in [descriptive complexity theory](wikipedia://en/1212009) to formulate logical descriptions of [complexity classes](wikipedia://en/502426).

:::

## History {#History}

The BIT predicate was first introduced in 1937 by [Wilhelm Ackermann](wikipedia://en/62727) to define the [Ackermann coding](https://en.wikipedia.org/wiki/Ackermann_coding), which encodes [hereditarily finite sets](wikipedia://en/332621) as [natural numbers](wikipedia://en/21474). The BIT predicate can be used to perform membership tests for the encoded sets: $\text{BIT}(i,j)$ is true if and only if the set encoded by $j$ is a member of the set encoded by $i$.

Ackermann denoted the predicate $\text{BIT}(i,j)$ as $\mathfrak{El}(j,i)$, using a [Fraktur](https://en.wikipedia.org/wiki/Fraktur) font to distinguish it from the notation $\mathrm{El}(j,i)$ that he used for set membership (short for "$j$ is an element of $i$" in German). The notation $\text{BIT}(i,j)$, and the name "the BIT predicate", come from the work of [Ronald Fagin](https://en.wikipedia.org/wiki/Ronald_Fagin) and [Neil Immerman](https://en.wikipedia.org/wiki/Neil_Immerman), who applied this predicate in [computational complexity theory](wikipedia://en/7543) as a way to encode and decode information in the late 1980s and early 1990s.

## Description and implementation {#Description_and_implementation}

The [binary representation](https://en.wikipedia.org/wiki/Binary_representation) of a number $i$ is an expression for $i$ as a sum of distinct [powers of two](wikipedia://en/376948),

$$i = \cdots b_3 2^3 + b_2 2^2 + b_1 2^1 + b_0 2^0$$

where each [bit](https://en.wikipedia.org/wiki/Bit) $b_j$ in this expression is either 0 or 1. It is commonly written in binary notation as just the sequence of these bits, $\cdots b_3b_2b_1b_0$. Given this expansion for $i$, the BIT predicate $\text{BIT}(i,j)$ is defined to equal $b_j$. It can be calculated from the formula

$$\text{BIT}(i,j) = \left\lfloor \frac{i}{2^j} \right\rfloor \bmod 2,$$

where $\lfloor \cdot \rfloor$ is the [floor function](https://en.wikipedia.org/wiki/Floor_function) and mod is the [modulo function](https://en.wikipedia.org/wiki/Modulo_function). The BIT predicate is a [primitive recursive function](wikipedia://en/24829). As a [binary relation](wikipedia://en/3931) (producing true and false values rather than 1 and 0 respectively), the BIT predicate is [asymmetric](wikipedia://en/1229368): there do not exist two numbers $i$ and $j$ for which both $\text{BIT}(i,j)$ and $\text{BIT}(j,i)$ are true.

In programming languages such as [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), or [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) that provide a [right shift operator](wikipedia://en/264399#Bit_shifts) `>>` and a [bitwise Boolean and operator](wikipedia://en/264399) `&`, the BIT predicate $\text{BIT}(i,j)$ can be implemented by the expression `(i>>j)&1`. The subexpression `i>>j` shifts the bits in the binary representation of $i$ so that bit $b_j$ is shifted to position 0, and the subexpression `&1` [masks off](https://en.wikipedia.org/wiki/Mask_%28computing%29) the remaining bits, leaving only the bit in position 0. As with the modular arithmetic formula above, the value of the expression is 1 or 0, respectively as the value of $\text{BIT}(i,j)$ is true or false.

## Applications {#Applications}

### Set data structures {#Set_data_structures}

For a set represented as a [bit array](https://en.wikipedia.org/wiki/Bit_array), the BIT predicate can be used to test set membership. For instance, subsets of the non-negative integers $\{0, 1, \ldots\}$ may be represented by a bit array with a one in position $i$ when $i$ is a member of the subset, and a zero in that position when it is not a member. When such a bit array is interpreted as a binary number, the set $\{i,j,k,\dots\}$ for distinct $i,j,k,\dots$ is represented as the binary number $2^i+2^j+2^k+\cdots$. If $S$ is a set, represented in this way, and $i$ is a number that may or may not be an element of $S$, then $\text{BIT}(S,i)$ returns a nonzero value when $i$ is a member and zero when it is not.

The same technique may be used to test membership in subsets of any sequence $x_0,x_1,\dots$ of distinct values, encoded using powers of two whose exponents are the positions of the elements in this sequence, rather than their values. For instance, in the [Java collections framework](https://en.wikipedia.org/wiki/Java_collections_framework), `java.util.EnumSet` uses this technique to implement a set data structure for [enumerated types](https://en.wikipedia.org/wiki/Enumerated_type). Ackermann's encoding of the hereditarily finite sets is an example of this technique, for the recursively-generated sequence of hereditarily finite sets.

### Private information retrieval {#Private_information_retrieval}

In the mathematical study of [computer security](https://en.wikipedia.org/wiki/Computer_security), the [private information retrieval](https://en.wikipedia.org/wiki/Private_information_retrieval) problem can be modeled as one in which a client, communicating with a collection of servers that store a binary number $i$, wishes to determine the result of a BIT predicate $\text{BIT}(i,j)$ without divulging the value of $j$ to the servers. (Chor Kushilevitz Goldreich Sudan 1998) describe a method for replicating $i$ across two servers in such a way that the client can solve the private information retrieval problem using a substantially smaller amount of communication than would be necessary to recover the complete value of $i$.

### Complexity and logic {#Complexity_and_logic}

The BIT predicate is often examined in the context of [first-order logic](wikipedia://en/10983), where systems of logic result from adding the BIT predicate to first-order logic. In [descriptive complexity](https://en.wikipedia.org/wiki/Descriptive_complexity), the [complexity class](wikipedia://en/502426) FO describes the class of [formal languages](wikipedia://en/10939) that can be described by a formula in first-order logic with a comparison operation on [totally ordered](wikipedia://en/30330) variables (interpreted as the indexes of characters in a [string](wikipedia://en/27701)) and with predicates that test whether this string has a given character at a given numerical index. A formula in this logic defines a language consisting of its [finite models](wikipedia://en/1773596). However, with these operations, only a very restricted class of languages, the [star-free regular languages](wikipedia://en/4922792), can be described. Adding the BIT predicate to the repertoire of operations used in these logical formulas results in a more robust complexity class, FO\[BIT\], meaning that it is less sensitive to minor variations in its definition.

The class FO\[BIT\] is the same as the class FO\[+,×\], of first-order logic with addition and multiplication predicates. It is also the same as the [circuit complexity](wikipedia://en/7641969) class [DLOGTIME](wikipedia://en/7404967)-[uniform](https://en.wikipedia.org/wiki/Uniformity_%28complexity%29) [AC<sup>0</sup>](wikipedia://en/7400698). Here, AC<sup>0</sup> describes the problems that can be computed by circuits of [AND gates](https://en.wikipedia.org/wiki/AND_gate) and [OR gates](https://en.wikipedia.org/wiki/OR_gate) with polynomial size, bounded height, and unbounded fanout. "Uniform" means that the circuits of all problem sizes must be described by a single algorithm. More specifically, it must be possible to index the gates of each circuit by numbers in such a way that the type of each gate and the adjacency between any two gates can be computed by a [deterministic algorithm](https://en.wikipedia.org/wiki/Deterministic_algorithm) whose time is logarithmic in the size of the circuit (DLOGTIME).

### Construction of the Rado graph {#Construction_of_the_Rado_graph}

*Image: Rado graph.svg.* The Rado graph, constructed from the BIT predicate. For instance, an edge connects 0 to 3 because the 0th bit of 3 is nonzero.

In 1964, German–British mathematician [Richard Rado](wikipedia://en/614984) used the BIT predicate to construct the infinite [Rado graph](wikipedia://en/7785594). Rado's construction is just the [symmetrization](wikipedia://en/8227451) of Ackermann's 1937 construction of the hereditary finite sets from the BIT predicate: two vertices numbered $i$ and $j$ are adjacent in the Rado graph when either $\text{BIT}(i,j)$ or $\text{BIT}(j,i)$ is nonzero.

The resulting graph has many important properties: it contains every finite undirected graph as an [induced subgraph](wikipedia://en/1655188), and any [isomorphism](wikipedia://en/247577) of its induced subgraphs can be extended to a symmetry of the whole graph.
