# Tiger (hash function)

::: {#o1 .subject cue=lead name="Tiger"}

In [cryptography](wikipedia://en/18934432), **Tiger**[^o3] is a [cryptographic hash function](wikipedia://en/439526) designed by [Ross Anderson](wikipedia://en/61571) and [Eli Biham](wikipedia://en/348920) in 1995 for efficiency on [64-bit](https://en.wikipedia.org/wiki/64-bit_computing) platforms. The size of a Tiger hash value is 192 bits. Truncated versions (known as Tiger/128 and Tiger/160) can be used for compatibility with protocols assuming a particular hash size. Unlike the [SHA-2](wikipedia://en/1638777) family, no distinguishing initialization values are defined; they are simply prefixes of the full Tiger/192 hash value.

:::

**Tiger2**[^o4] is a variant where the message is padded by first appending a byte with the hexadecimal value of 0x80 as in [MD4](wikipedia://en/578106), [MD5](wikipedia://en/18826) and [SHA](https://en.wikipedia.org/wiki/Secure_Hash_Algorithm), rather than with the hexadecimal value of 0x01 as in the case of Tiger. The two variants are otherwise identical.

::: {#o6 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

Tiger is based on [Merkle–Damgård construction](wikipedia://en/4076217). The [one-way compression function](wikipedia://en/3851622) operates on 64-bit words, maintaining 3 words of state and processing 8 words of data. There are 24 rounds, using a combination of operation mixing with XOR and addition/subtraction, rotations, and S-box lookups, along with a fairly intricate key scheduling algorithm for deriving 24 round keys from the 8 input words.

Although fast in software, Tiger's large S-boxes (four S-boxes, each with 256 64-bit entries totaling 8 [KiB](https://en.wikipedia.org/wiki/KiB)) make implementations in hardware or [microcontrollers](https://en.wikipedia.org/wiki/Microcontroller) difficult.

:::

## Usage {#Usage}

Tiger is frequently used in [Merkle hash tree](wikipedia://en/2497388) form, where it is referred to as TTH ([Tiger Tree Hash](wikipedia://en/2497388#Tiger_tree_hash)). TTH is used by many clients on the [Direct Connect](https://en.wikipedia.org/wiki/Direct_Connect_%28protocol%29) and [Gnutella](https://en.wikipedia.org/wiki/Gnutella) file sharing networks, and can optionally be included in the [BitTorrent](https://en.wikipedia.org/wiki/BitTorrent) metafile [^o8] for better content availability.

Tiger was considered for inclusion in the [OpenPGP](https://en.wikipedia.org/wiki/OpenPGP) standard, but was abandoned in favor of [RIPEMD](wikipedia://en/26363)-160.[^o9][^o10]

## OID {#OID}

2440 refers to TIGER as having no [OID](https://en.wikipedia.org/wiki/Object_identifier), whereas the [GNU Coding Standards](https://en.wikipedia.org/wiki/GNU_Coding_Standards) list TIGER/192 as having OID `1.3.6.1.4.1.11591.12.2`, an allocation under the GNU organization subtree.[^o12]

In the [IPsec](https://en.wikipedia.org/wiki/IPsec) subtree, HMAC-TIGER is assigned OID `1.3.6.1.5.5.8.1.3`.[^o13]

No OID for TTH has been announced yet.

## Byte order {#Byte_order}

The specification of Tiger does not define the way its output should be printed but only defines the result to be three ordered 64-bit integers. The "testtiger" program at the author's homepage was intended to allow easy testing of the test source code, rather than to define any particular print order. The protocols [Direct Connect](https://en.wikipedia.org/wiki/Direct_Connect_%28protocol%29) and [ADC](https://en.wikipedia.org/wiki/Advanced_Direct_Connect) as well as the program `tthsum` use little-endian byte order, which is also preferred by one of the authors.[^o15]

## Examples {#Examples}

In the example below, the 192-bit (24-byte) Tiger hashes are represented as 48 [hexadecimal](wikipedia://en/13263) digits in [little-endian](https://en.wikipedia.org/wiki/Little-endian) byte order. The following demonstrates a 43-byte [ASCII](https://en.wikipedia.org/wiki/ASCII) input and the corresponding Tiger hashes:

Tiger("The quick brown fox jumps over the lazy #87CEEBog") = 6d12a41e72e644f017b6f0e2f7b44c6285f06dd5d2c5b075

Tiger2("The quick brown fox jumps over the lazy #87CEEBog") = 976abff8062a2e9dcea3a1ace966ed9c19cb85558b4976d8

Even a small change in the message will (with very high probability) result in a completely different hash, e.g. changing d to c:

Tiger("The quick brown fox jumps over the lazy #87CEEBog") = a8f04b0f7201a0d728101c9d26525b31764a3493fcd8458f

Tiger2("The quick brown fox jumps over the lazy #87CEEBog") = 09c11330283a27efb51930aa7dc1ec624ff738a8d9bdd3df

The hash of the zero-length string is:

Tiger("") = 3293ac630c13f0245f92bbb1766e16167a4e58492dde73f3

Tiger2("") = 4441be75f6018773c206c22745374b924aa8313fef919f41

:::

## Cryptanalysis {#Cryptanalysis}

Unlike MD5 or SHA-0/1, there are no known effective attacks on the full 24-round Tiger[^o20] except for pseudo-near collision.[^o19] While MD5 processes its state with 64 simple 32-bit operations per 512-bit block and SHA-1 with 80, Tiger updates its state with a total of 144 such operations per 512-bit block, additionally strengthened by large S-box look-ups.

[John Kelsey](https://en.wikipedia.org/wiki/John_Kelsey_%28cryptanalyst%29) and [Stefan Lucks](https://en.wikipedia.org/wiki/Stefan_Lucks) have found a collision-finding attack on 16-round Tiger with a time complexity equivalent to about 2<sup>44</sup> compression function invocations and another attack that finds pseudo-near collisions in 20-round Tiger with work less than that of 2<sup>48</sup> compression function invocations.[^o20] Florian Mendel et al. have improved upon these attacks by describing a collision attack spanning 19 rounds of Tiger, and a 22-round pseudo-near-collision attack. These attacks require a work effort equivalent to about 2<sup>62</sup> and 2<sup>44</sup> evaluations of the Tiger compression function, respectively.[^o21]
