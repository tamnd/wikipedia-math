# Abstract model checking

::: {#o1 .subject cue=lead name="Abstract model checking"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science) and in [mathematics](wikipedia://en/18831), **abstraction model checking** is a form of [model checking](wikipedia://en/321157) for systems where an actual representation is too complex in developing the model alone. So, the design undergoes a kind of translation to scaled down "abstract" version.

:::

The set of [variables](wikipedia://en/3728109) are partitioned into visible and invisible depending on their change of values. The real [state space](https://en.wikipedia.org/wiki/State_space) is summarized into a smaller set of the visible ones.

## Galois connected {#Galois_connected}

The real and the abstract state spaces are [Galois connected](wikipedia://en/156411). This means that if we take an element from the abstract space, concretize it and abstract the concretized version, the result will be equal to the original. On the other hand, if you pick an element from the real space, abstract it and concretize the abstract version, the final result will be a super set of the original.

That is,

$\eta$($\theta$(abstract)) = abstract $\theta$($\eta$(real)) $\supseteq$ real
