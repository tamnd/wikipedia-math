# Examples of anonymous functions

Anonymous function

## Examples of anonymous functions {#Examples_of_anonymous_functions}

Numerous languages support [anonymous functions](https://en.wikipedia.org/wiki/Anonymous_functions), or something similar.

### APL {#APL}

Only some dialects support anonymous functions, either as [dfns](https://en.wikipedia.org/wiki/Direct_function), in the tacit style or a combination of both.

```apl
      f←{⍵×⍵} As a dfn
      f 1 2 3
1 4 9     
      g←⊢×⊢   As a tacit 3-train (fork)
      g 1 2 3
1 4 9
      h←×⍨    As a derived tacit function
      h 1 2 3
1 4 9
```

### C (non-standard extension) {#C_(non-standard_extension)}

The anonymous function is not supported by standard [C programming language](https://en.wikipedia.org/wiki/C_%28programming_language%29), but supported by some C dialects, such as *GCC*[^o4] and *Clang*.

#### GCC {#GCC}

The [GNU Compiler Collection](https://en.wikipedia.org/wiki/GNU_Compiler_Collection) (GCC) supports anonymous functions, mixed by [nested functions](https://en.wikipedia.org/wiki/Nested_function) and statement expressions. It has the form:

```c
( { return_type anonymous_functions_name (parameters) { function_body } anonymous_functions_name; } )
```

The following example works only with GCC. Because of how macros are expanded, the `l_body` cannot contain any commas outside of parentheses; GCC treats the comma as a [delimiter](https://en.wikipedia.org/wiki/Delimiter) between macro arguments. The argument `l_ret_type` can be removed if `__typeof__` is available; in the example below using `__typeof__` on array would return `testtype *`, which can be dereferenced for the actual value if needed.

```c
#include <stdio.h>

// this is the definition of the anonymous function
#define lambda(l_ret_type, l_arguments, l_body) \
  ({ \
   l_ret_type l_anonymous_functions_name l_arguments \
   l_body \
   &l_anonymous_functions_name; \
   })

#define FOR_EACH_IN_ARRAY(fe_arrType, fe_arr, fe_fn_body) \
{ \
    for (int i = 0; i < sizeof(fe_arr) / sizeof(fe_arrType); i++) { \
        fe_arr[i] = fe_fn_body(&fe_arr[i]); \
    } \
}

typedef struct {
    int a;
    int b;
} IntegerPair;

void printElements(const IntegerPair arr[], size_t n) {
    for (int i = 0; i < n; ++i) {
        printf("%d %d\n", arr[i].a, arr[i].b);
    }
}

int main(int argc, char* argv[]) {
    IntegerPair pairArray[] = { 
        {0, 1}, 
        {2, 3}, 
        {4, 5} 
    };

    printElements(a, 3);
    // the anonymous function is given as function for the foreach
    FOR_EACH_IN_ARRAY(IntegerPair, pairArray,
        lambda (IntegerPair, (void* item),
            {
                int temp = (*(IntegerPair*) item).a;
                (*(IntegerPair*) item).a = (*(IntegerPair*) item).b;
                (*(IntegerPair*) item).b = temp;
                return (*(IntegerPair*) item);
            }
        )
    );
    printElements(pairArray, 3);
    return 0;
}
```

#### Clang (C, C++, Objective-C, Objective-C++) {#Clang_(C,_C++,_Objective-C,_Objective-C++)}

[Clang](https://en.wikipedia.org/wiki/Clang) supports anonymous functions, called [blocks](https://en.wikipedia.org/wiki/Blocks_%28C_language_extension%29),[^o7] which have the form:

```c
^T (params) { body }
```

The type of the blocks above is `T (^)(params)`.

Using the aforementioned *blocks* extension and [Grand Central Dispatch](https://en.wikipedia.org/wiki/Grand_Central_Dispatch) (libdispatch), the code could look simpler:

```c
#include <stdio.h>
#include <dispatch/dispatch.h>

int main(int argc, char* argv[]) {
    void (^count_loop)() = ^{
        for (int i = 0; i < 100; i++) {
            printf("%d\n", i);
        }
        printf("ah ah ah\n");
    };

    // Pass as a parameter to another function
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), count_loop);

    // Invoke directly
    count_loop();

    return 0;
}
```

The code with blocks should be compiled with `-fblocks` and linked with `-lBlocksRuntime`

### C++ {#C++}

[C++](https://en.wikipedia.org/wiki/C++) (since [C++11](https://en.wikipedia.org/wiki/C++11)) supports anonymous functions (technically [function objects](https://en.wikipedia.org/wiki/Function_object)), called *lambda expressions*,[^o9] which have the form `[''captures''] <nowiki>[[</nowiki>''front-annotations''<nowiki>]]</nowiki> <''template-parameters''> <nowiki>[[</nowiki>''annotations''<nowiki>]]</nowiki> (''params'') ''specs'' ''requires ﻿(...)'' -> ''returns'' ''contract-specs'' { ''body'' }`; each of these components is optional". If it is absent, the return type is deduced from `return` statements as if for a function with declared return type `auto`.

As of [C++20](https://en.wikipedia.org/wiki/C++20), template parameters can also be declared explicitly in the `<''template-parameters''>` area.

This is an example lambda expression, with a

```cpp
[[nodiscard]]
```

[attribute](https://en.wikipedia.org/wiki/Attribute_%28programming%29):

```cpp
auto f = [](int x, int y) [[nodiscard]] -> int { 
    return x + y; 
};
```

C++ also supports [closures](https://en.wikipedia.org/wiki/Closure_%28computer_science%29), here called captures. Captures are defined between square brackets `[`and `]` in the declaration of lambda expression. The mechanism allows these variables to be captured by value or by reference. The following table demonstrates this:

```cpp
// No captures, the lambda is implicitly convertible to a function pointer.
auto a = [] -> void {};
// x is captured by value and y is captured by reference.
auto b = [x, &y] -> void {};
// Any external variable is implicitly captured by reference if used
auto c = [&] -> void {};
// Any external variable is implicitly captured by value if used.
auto d = [=] -> void {};
// x is captured by value. Other variables will be captured by reference.
auto e = [&, x] -> void {};
// z is captured by reference. Other variables will be captured by value.
auto f = [=, &z] -> void {};
```

Variables captured by value are constant by default. Adding `mutable` after the parameter list makes them non-constant.

[C++14](https://en.wikipedia.org/wiki/C++14) and newer versions support init-capture, for example:

```cpp
using std::unique_ptr;

unique_ptr<int> ptr = std::make_unique<int>(42);

// copy assignment is deleted for a unique pointer
auto a = [ptr] -> void { 
    // ...
};

// OK
auto b = [ptr = std::move(ptr)] -> void { 
    // ... 
};

// mutable is required to modify 'i'
auto counter = [i = 0]() mutable -> int { 
    return i++; 
};

counter(); // 0
counter(); // 1
counter(); // 2
```

The following two examples demonstrate use of a lambda expression:

```cpp
using std::vector;

vector<int> someList{1, 2, 3, 4, 5};
int total = 0;
std::ranges::for_each(
    someList, 
    [&total](int x) -> void { 
        total += x; 
    }
);
// Note that std::ranges::fold_left is a preferable alternative here
```

This computes the total of all elements in the list. The variable `total` is stored as a part of the lambda function's closure. Since it is a reference to the stack variable `total`, it can change its value.

```cpp
using std::vector;

vector<int> someList{1, 2, 3, 4, 5};
int total = 0;
int value = 5;
std::ranges::for_each(
    someList, 
    [&total, value, this](int x) -> void {
        total += x * value * this->someFunc(); 
    }
);
```

This will cause `total` to be stored as a reference, but `value` will be stored as a copy.

The capture of `this` is special. It can only be captured by value, not by reference. However in [C++17](https://en.wikipedia.org/wiki/C++17), the current object can be captured by value (denoted by `*this`), or can be captured by reference (denoted by `this`). `this` can only be captured if the closest enclosing function is a non-static member function. The lambda will have the same access as the member that created it, in terms of protected/private members.

If `this` is captured, either explicitly or implicitly, then the scope of the enclosed class members is also tested. Accessing members of `this` does not need explicit use of `this->` syntax.

The specific internal implementation can vary, but the expectation is that a lambda function that captures everything by reference will store the actual stack pointer of the function it is created in, rather than individual references to stack variables. However, because most lambda functions are small and local in scope, they are likely candidates for [inlining](https://en.wikipedia.org/wiki/Inline_expansion), and thus need no added storage for references.

If a closure object containing references to local variables is invoked after the innermost block scope of its creation, the behaviour is [undefined](https://en.wikipedia.org/wiki/Undefined_behaviour).

Lambda functions are function objects of an implementation-dependent type; this type's name is only available to the compiler, thus lambdas can be seen as compiler-generated types which implement a `operator()`. Because the type of a lambda is compiler-specified, it is usually stored in `auto` for [type deduction](https://en.wikipedia.org/wiki/Type_deduction). Lambdas may also be stored in std::function\<R(Ts...)>, but this uses [type erasure](https://en.wikipedia.org/wiki/Type_erasure), while storing in a [function pointer](https://en.wikipedia.org/wiki/Function_pointer) disallows captures in the lambda. If the user wishes to take a lambda function as a parameter, the parameter type must be a template type, or they must create a `std::function` or a similar object to capture the lambda value. The use of the `auto` keyword can help store the lambda function,

```cpp
auto myLambdaFunc = [&](int x) -> void { 
    // ...
};

auto myHeapLambdaFunc = new auto([=](int x) -> void { 
    // ...
});
```

Here is an example of storing anonymous functions in variables, vectors, and arrays; and passing them as named parameters:

```cpp
import std;

using std::function;
using std::vector;

double eval(function<double(double)> f, double x = 2.0) {
    return f(x);
}

int main(int argc, char* argv[]) {
    function<double(double)> f0 = [](double x) -> double { 
         return 1.0f; 
    };

    auto f1 = [](double x) -> double { 
        return x; 
    };

    decltype(f0) fa[3] = {f0, f1, [](double x) -> double { return x * x; }};

    vector<decltype(f0)> fv = {f0, f1};
    fv.push_back([](double x) -> double { return x * x; });

    for (size_t i = 0; i < fv.size(); ++i) {
        std::println("{}", fv[i](2.0));
    }

    for (size_t i = 0; i < 3; ++i) {
        std::println("{}", fa[i](2.0));
    }

    for (decltype(f0)& f : fv) {
        std::println("{}", f(2.0));
    }

    for (decltype(f0)& f : fa) {
        std::println("{}", f(2.0));
    }

    std::println("{}", f(2.0));
    std::println("{}", eval(f0));
    std::println("{}", eval(f1));
    std::println("{}", eval([](double x) -> double { return x * x; }));
}
```

A lambda expression with an empty capture specification (`[]`) can be implicitly converted into a [function pointer](https://en.wikipedia.org/wiki/Function_pointer) with the same type as the lambda was declared with. So this is legal:

```cpp
auto aLambdaFunc = [](int x) -> void { 
    // ...
};
void (*funcPtr)(int) = aLambdaFunc;
funcPtr(4); // calls the lambda.
```

Since [C++14](https://en.wikipedia.org/wiki/C++14), the function parameters of a lambda can be declared with `auto`. The resulting lambda is called a *generic lambda* and is essentially an anonymous function template since the rules for type deduction of the auto parameters are the rules of template argument deduction.

Since [C++17](https://en.wikipedia.org/wiki/C++17), a lambda can be declared `[[constexpr]]`, and since [C++20](https://en.wikipedia.org/wiki/C++20), `[[consteval]]` with the usual semantics. These specifiers go after the parameter list, like `mutable`. Starting from [C++23](https://en.wikipedia.org/wiki/C++23), the lambda can also be `[[static member function|static]]` if it has no captures. The `static` and `mutable` specifiers are not allowed to be combined.

Since C++23, a lambda expression can be recursive through explicit `this` as first parameter:

```cpp
auto fibonacci = [](this auto self, int n) -> void { 
    return n <= 1 ? n : self(n - 1) + self(n - 2); 
};
fibonacci(7); // 13
```

In addition to that, C++23 modified the syntax so that the parentheses can be omitted in the case of a lambda that takes no arguments even if the lambda has a specifier. It also made it so that an attribute specifier sequence that appears before the parameter list, lambda specifiers, or noexcept specifier (there must be one of them) applies to the function call operator or operator template of the closure type. Otherwise, it applies to the type of the function call operator or operator template. Previously, such a sequence always applied to the type of the function call operator or operator template of the closure type making e.g the

```cpp
[[noreturn]]
```

attribute impossible to use with lambdas.

### C# {#C#}

In [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29), support for anonymous functions has deepened through the various versions of the language compiler. The language v3.0, released in November 2007 with [.NET Framework](https://en.wikipedia.org/wiki/.NET_Framework) v3.5, has full support of anonymous functions.[^o11][^o12] C# names them *lambda expressions*, following the original version of anonymous functions, the [lambda calculus](wikipedia://en/18203).[^o13][^o11][^o12]

```csharp
using System;

// the first int is the x' type
// the second int is the return type
// <see href="http://msdn.microsoft.com/en-us/library/bb549151.aspx" />
Func<int, int> foo = x => x * x;
Console.WriteLine(foo(7));
```

While the function is anonymous, it cannot be assigned to an implicitly typed variable, because the lambda syntax may be used for denoting an anonymous function or an expression tree, and the choice cannot automatically be decided by the compiler.[^o11] E.g., this does not work:

```csharp
using System;

// will NOT compile!
Func<int, int> foo = (int x) => x * x;
```

However, a lambda expression can take part in [type inference](wikipedia://en/279690) and can be used as a [method argument](https://en.wikipedia.org/wiki/Parameter_%28computer_science%29), e.g. to use anonymous functions with the Map capability available with `System.Collections.Generic.List` (in the `ConvertAll()` method):

```csharp
using System.Collections.Generic;

// Initialize the list:
List<int> values = new(7, 13, 4, 9, 3);
// Map the anonymous function over all elements in the list, return the new list
List<int> foo = values.ConvertAll(d => d * d); 
// the result of the foo variable is of type System.Collections.Generic.List<Int32>
```

Prior versions of C# had more limited support for anonymous functions. C# v1.0, introduced in February 2002 with the .NET Framework v1.0, provided partial anonymous function support through the use of [delegates](https://en.wikipedia.org/wiki/Delegate_%28CLI%29).[^o11] C# names them *lambda expressions*, following the original version of anonymous functions, the [lambda calculus](wikipedia://en/18203).[^o11] This construct is somewhat similar to PHP delegates. In C# 1.0, delegates are like function pointers that refer to an explicitly named method within a class. (But unlike PHP, the name is unneeded at the time the delegate is used.) C# v2.0, released in November 2005 with the .NET Framework v2.0, introduced the concept of anonymous methods as a way to write unnamed inline statement blocks that can be executed in a delegate invocation.[^o11] C# 3.0 continues to support these constructs, but also supports the lambda expression construct.

This example will compile in C# 3.0, and exhibits the three forms:

```csharp
namespace Wikipedia.Examples;

using System;

public class TestDriver
{
    delegate int SquareDelegate(int d);
    static int Square(int d)
    {
        return d * d;
    }
 
    static void Main(string[] args)
    {
        // C# 1.0: Original delegate syntax needed 
        // initializing with a named method.
        SquareDelegate A = new(Square);
        Console.WriteLine(A(3));
 
        // C# 2.0: A delegate can be initialized with
        // inline code, called an "anonymous method". This
        // method takes an int as an input parameter.
        SquareDelegate B = delegate(int d) { return d * d; };
        Console.WriteLine(B(5));
 
        // C# 3.0. A delegate can be initialized with
        // a lambda expression. The lambda takes an int, and returns an int. 
        // The type of x is inferred by the compiler.
        SquareDelegate C = x => x * x;
        Console.WriteLine(C(7));
 
        // C# 3.0. A delegate that accepts one input and
        // returns one output can also be implicitly declared with the Func<> type.
        System.Func<int, int> D = x => x * x;
        Console.WriteLine(D(9));
    } 
}
```

In the case of the C# 2.0 version, the C# compiler takes the code block of the anonymous function and creates a static private function. Internally, the function gets a generated name, of course; this generated name is based on the name of the method in which the Delegate is declared. But the name is not exposed to application code except by using [reflection](https://en.wikipedia.org/wiki/Reflection_%28computer_science%29).[^o11] In the case of the C# 3.0 version, the same mechanism applies.

### ColdFusion Markup Language (CFML) {#ColdFusion_Markup_Language_(CFML)}

Using the function keyword:

```CFC
fn = function(){
  // statements
};
```

Or using an arrow function:

```CFC
fn = () => {
  // statements
};

fn = () => singleExpression // singleExpression is implicitly returned. There is no need for the braces or the return keyword

fn = singleParam => { // if the arrow function has only one parameter, there's no need for parentheses
    // statements
}

fn = (x, y) => { // if the arrow function has zero or multiple parameters, one needs to use parentheses
    // statements
}
```

CFML supports any statements within the function's definition, not simply expressions.

CFML supports recursive anonymous functions:

```CFC
factorial = function(n){
    return n > 1 ? n * factorial(n-1) : 1;
};
```

CFML anonymous functions implement closure.

### D {#D}

D uses inline [delegates](https://en.wikipedia.org/wiki/Delegation_%28programming%29) to implement anonymous functions. The full syntax for an inline delegate is

```d
ReturnType delegate(Args args) {
    // body
}
```

If unambiguous, the return type and the keyword *delegate* can be omitted.

```d
(x) { return x * x; }
delegate (x) { return x * x; } // if more verbosity is needed
(int x) { return x * x; } // if parameter type cannot be inferred
delegate (int x) { return x * x; } // ditto
delegate double(int x) { return x * x; } // if return type must be forced manually
```

Since version 2.0, [D](https://en.wikipedia.org/wiki/D_programming_language) allocates closures on the heap unless the compiler can prove it is unnecessary; the `scope` keyword can be used for forcing stack allocation. Since version 2.058, it is possible to use shorthand notation:

```d
x => x * x;
(int x) => x * x;
(x, y) => x * y;
(int x, int y) => x * y;
```

An anonymous function can be assigned to a variable and used like this:

```d
auto sqr = (double x) { return x * x; };
double y = sqr(4);
```

### Haskell {#Haskell}

[Haskell](https://en.wikipedia.org/wiki/Haskell_%28programming_language%29) uses a concise syntax for anonymous functions (lambda expressions). The [backslash](https://en.wikipedia.org/wiki/Backslash) is supposed to resemble λ.

```haskell
\x -> x * x
```

Lambda expressions are fully integrated with the type [inference engine](https://en.wikipedia.org/wiki/Inference_engine), and support all the syntax and features of "ordinary" functions (except for the use of multiple definitions for pattern-matching, since the argument list is only specified once).

```haskell
map (\x -> x * x) [1..5] -- returns [1, 4, 9, 16, 25]
```

The following are all equivalent:

```haskell
f x y = x + y
f x = \y -> x + y
f = \x y -> x + y
```

### Haxe {#Haxe}

In [Haxe](https://en.wikipedia.org/wiki/Haxe), anonymous functions are called lambda, and use the syntax `function(argument-list) expression;` .

```actionscript
var f = function(x) return x*x;
f(8); // 64

(function(x,y) return x+y)(5,6); // 11
```

### Java {#Java}

[Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29) supports anonymous functions, named *Lambda Expressions*, starting with [JDK 8](https://en.wikipedia.org/wiki/Java_8).[^o29]

A lambda expression consists of a comma separated list of the formal parameters enclosed in parentheses, an arrow token (`->`), and a body. Data types of the parameters can always be omitted, as can the parentheses if there is only one parameter. The body can consist of one statement or a statement block.[^o31]

```java
import java.util.Optional;
import java.util.function.BiFunction;
import java.util.function.BinaryOperator;
import java.util.function.Function;

// With no parameter
Runnable r = () -> System.out.println("Hello, world!");

// With one parameter (this example is an identity function).
Function<Object, Object> identity = a -> a;

// With one expression
BinaryOperator<Integer> add = (a, b) -> a + b;

// With explicit type information, and a code block
BiFunction<Long, String, String> formatter = (long id, String name) -> {
    String.format("id: %f, name: %s", id, name);
}

// With multiple statements in the lambda body. It needs a code block.
// This example also includes two nested lambda expressions (the first one is also a closure).
BiFunction<Long, Double, Double> getPriceOrDefault = (double id, double defaultPrice) -> {
    Optional<Product> product = productList
        .stream()
        .filter(p -> p.getId() == id)
        .findFirst();

    return product
        .map(Product::getPrice())
        .orElse(defaultPrice);
}
```

Lambdas cannot specify `throws` clauses. Lambdas themselves are not complete expressions of concrete types, but rather poly expressions, whose type are influenced by their surrounding target type rather than entirely by their own content.

```java
import java.util.function.Function;

// Invalid, as lambda expressions themselves have no standalone type
var f = (int x) -> x + 1;
// Should instead be:
Function<Integer, Integer> f = x -> x + 1;
```

Lambdas implement some target functional interface (such as `java.lang.Runnable`, etc.), which are is any interface that defines only one method (excluding those which are inherited from `java.lang.Object`); it can additionally be annotated with

```java
@FunctionalInterface
```

to have the compiler enforce that an interface is actually a functional interface.[^o30][^o31]

```java
public class Calculator {
    interface IntegerMath {
        int operation(int a, int b);

        default IntegerMath swap() {
            return (a, b) -> operation(b, a);
        }
    }

    private static int apply(int a, int b, IntegerMath op) {
        return op.operation(a, b);
    }

    public static void main(String[] args) {
        IntegerMath addition = (a, b) -> a + b;
        IntegerMath subtraction = (a, b) -> a - b;
        System.out.printf("40 + 2 = %d%n", apply(40, 2, addition));
        System.out.printf("20 - 10 = %d%n", apply(20, 10, subtraction));
        System.out.printf("10 - 20 = %d%n", apply(20, 10, subtraction.swap()));    
    }
}
```

In this example, a functional interface called `IntegerMath` is declared. Lambda expressions that implement `IntegerMath` are passed to the `apply()` method to be executed. Default methods like `swap` define methods on functions.

Java 8 introduced another mechanism named method reference (the `::` operator) to create a lambda on an existing method. A method reference does not indicate the number or types of arguments because those are extracted from the abstract method of the functional interface.

```java
IntBinaryOperator sum = Integer::sum;
```

In the example above, the functional interface `IntBinaryOperator` declares an abstract method `int applyAsInt(int, int)`, so the compiler looks for a method `int sum(int, int)` in the class `java.lang.Integer`.

#### Differences compared to Anonymous Classes {#Differences_compared_to_Anonymous_Classes}

[Anonymous classes](https://docs.oracle.com/javase/tutorial/java/javaOO/anonymousclasses.html) of lambda-compatible interfaces are similar, but not exactly equivalent, to lambda expressions. To illustrate, in the following example, anonymousClass and lambdaExpression are both instances of IntegerMath that add their two parameters:

```java
IntegerMath anonymousClass = new IntegerMath() {
    @Override
    public int operation(int a, int b) {
        return a + b;
    }
};

IntegerMath lambdaExpression = (a, b) -> a + b;
```

The main difference here is that the lambda expression does not necessarily need to allocate a new instance for the IntegerMath, and can return the same instance every time this code is run.[^o33] Additionally, in the [OpenJDK](https://en.wikipedia.org/wiki/OpenJDK) implementation at least, lambdas are compiled to invokedynamic instructions, with the lambda body inserted as a static method into the surrounding class,[^o34] rather than generating a new class file entirely.

If a lambda implements a functional interface which extends `java.lang.Serializable`, then when the lambda is serialized, it becomes a `java.lang.invoke.SerializedLambda`[^o35], capturing information about the lambda itself, called its "serialized form".[^o36] This is necessary, because lambda implementation classes are synthetic and JVM-specific, and must therefore be reconstructed exactly in another JVM invocation. Much like in C++, lambda type names are synthetic and compiler-generated with unspecified implementation details.

```java
Runnable r = () -> System.out.println("Hello");

// Could print something like:
// class org.wikipedia.examples.Main$$Lambda$1/0x0000000800b00440
System.out.println(r.getClass());
```

Lambdas do not generate [class files](https://en.wikipedia.org/wiki/Java_class_file), but rather emit an `invokedynamic` instruction on the JVM, which the runtime uses to create a suitable implementation class.

Capturing lambdas are typically distinct objects, due to requiring stored captured state, however non-capturing lambdas may potentially be [singleton](https://en.wikipedia.org/wiki/Singleton_pattern).

```java
Runnable r1 = () -> {};
Runnable r2 = () -> {};

System.out.println(r1 == r2); // May print true or false; determined by the JVM
```

However, unlike C++, lambda types are not part of the [language model](wikipedia://en/1911810); nothing about its runtime class may be depended upon, whereas in C++ the lambda type may still be extracted with [`decltype`](https://en.wikipedia.org/wiki/Decltype) to obtain a real unique closure type; a lambda's `java.lang.Class<?>` cannot be referenced in code.

#### Java limitations {#Java_limitations}

Java 8 lambdas have the following limitations:

- Lambdas can throw checked exceptions, but such lambdas will not work with the interfaces used by the Collection API.
- Variables that are in-scope where the lambda is declared may only be accessed inside the lambda if they are effectively final, i.e. if the variable is not mutated inside or outside of the lambda scope.

### JavaScript {#JavaScript}

[JavaScript](https://en.wikipedia.org/wiki/JavaScript)/[ECMAScript](https://en.wikipedia.org/wiki/ECMAScript) supports anonymous functions.

```javascript
alert((function (x) {
  return x * x;
})(10));
```

[ES6](https://en.wikipedia.org/wiki/ES6) supports "arrow function" syntax, where a **\=>** symbol separates the anonymous function's parameter list from the body:

```javascript
alert((x => x * x)(10));
```

This construct is often used in [Bookmarklets](https://en.wikipedia.org/wiki/Bookmarklet). For example, to change the title of the current document (visible in its window's [title bar](https://en.wikipedia.org/wiki/Title_bar)) to its [URL](https://en.wikipedia.org/wiki/URL), the following bookmarklet may seem to work.

```javascript
document.title=location.href;
```

However, as the assignment statement returns a value (the URL itself), many browsers actually create a new page to display this value.

Instead, an anonymous function, that does not return a value, can be used:

```javascript
(function () {
  document.title=location.href;
})();
```

The function statement in the first (outer) pair of parentheses declares an anonymous function, which is then executed when used with the last pair of parentheses. This is almost equivalent to the following, which populates the environment with `f` unlike an anonymous function.

```javascript
var f = function () {
  document.title=location.href;
};
f();
```

Use [void()](https://en.wikipedia.org/wiki/Bookmarklets#History) to avoid new pages for arbitrary anonymous functions:

```javascript
void(function () {
  return document.title=location.href;
}());
```

or just:

```javascript
void(document.title=location.href);
```

JavaScript has syntactic subtleties for the semantics of defining, invoking and evaluating anonymous functions. These subliminal nuances are a direct consequence of the evaluation of parenthetical expressions. The following constructs which are called [immediately-invoked function expression](https://en.wikipedia.org/wiki/Immediately-invoked_function_expression) illustrate this:

```javascript
(function () { /* ... */ }())
```

and

```javascript
(function () { /* ... */ })()
```

Representing "`function () { /* ... */ }`" by `f`, the form of the constructs are a parenthetical within a parenthetical `(f())` and a parenthetical applied to a parenthetical `(f)()`.

Note the general syntactic ambiguity of a parenthetical expression, parenthesized arguments to a function and the parentheses around the formal parameters in a function definition. In particular, JavaScript defines a `,` (comma) operator in the context of a parenthetical expression. It is no mere coincidence that the syntactic forms coincide for an expression and a function's arguments (ignoring the function formal parameter syntax)! If `f` is not identified in the constructs above, they become `(())` and `()()`. The first provides no syntactic hint of any resident function but the second MUST evaluate the first parenthetical as a function to be legal JavaScript. (Aside: for instance, the `()`'s could be (\[\], {}, 42, "abc", function () {}) as long as the expression evaluates to a function.)

Also, a function is an Object instance (likewise objects are Function instances) and the object literal notation brackets, `{}` for braced code, are used when defining a function this way (as opposed to using `new Function(...)`). In a very broad non-rigorous sense (especially since global bindings are compromised), an arbitrary sequence of braced JavaScript statements, `{stuff}`, can be considered to be a [fixed point](wikipedia://en/449738) of

```javascript
(function () {
  (function () {
    ( ... {(function () {
      /* stuff */
    }() )} ... )
  }() )
}() )
```

More correctly but with caveats,

```javascript
(function () { /* stuff */ }() ) ~= fixedPointOf(function () {
  return function () {
    return ... {
      return function () {
        /* stuff */
      }()
    } ...
  }()
}())
```

Note the implications of the anonymous function in the JavaScript fragments that follow:

- `function () { /* ... */ }()` without surrounding `()`'s is generally not legal
- `(f = function () { /* ... */ })` does not "forget" `f` globally unlike `(function f () { /* ... */ })`

Performance [metrics](https://en.wikipedia.org/wiki/Software_metric) to analyze the [space](https://en.wikipedia.org/wiki/Space_complexity_theory) and [time](wikipedia://en/405944) [complexities](wikipedia://en/7543) of function calls, [call stack](https://en.wikipedia.org/wiki/Call_stack), etc. in a JavaScript [interpreter](https://en.wikipedia.org/wiki/Interpreter_%28computing%29) [engine](https://en.wikipedia.org/wiki/Software_engine) implement easily with these last anonymous function constructs. From the implications of the results, it is possible to deduce some of an engine's recursive versus iterative implementation details, especially [tail-recursion](https://en.wikipedia.org/wiki/Tail-recursion).

### Lisp {#Lisp}

[Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29) and [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29) support anonymous functions using the "lambda" construct, which is a reference to [lambda calculus](wikipedia://en/18203). [Clojure](https://en.wikipedia.org/wiki/Clojure) supports anonymous functions with the "fn" special form and #() reader syntax.

```lisp
(lambda (arg) (* arg arg))
```

#### Common Lisp {#Common_Lisp}

[Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp) has the concept of lambda expressions. A lambda expression is written as a list with the symbol "lambda" as its first element. The list then contains the argument list, documentation or declarations and a function body. Lambda expressions can be used inside lambda forms and with the special operator "function".

```lisp
(function (lambda (arg) (do-something arg)))
```

"function" can be abbreviated as #'. Also, macro *lambda* exists, which expands into a function form:

```lisp
; using sharp quote
#'(lambda (arg) (do-something arg))
; using the lambda macro:
(lambda (arg) (do-something arg))
```

One typical use of anonymous functions in Common Lisp is to pass them to higher-order functions like *mapcar*, which applies a function to each element of a list and returns a list of the results.

```lisp
(mapcar #'(lambda (x) (* x x))
        '(1 2 3 4))
; -> (1 4 9 16)
```

The *lambda form* in Common Lisp allows a *lambda expression* to be written in a function call:

```lisp
((lambda (x y)
   (+ (sqrt x) (sqrt y)))
 10.0
 12.0)
```

Anonymous functions in Common Lisp can also later be given global names:

```lisp
(setf (symbol-function 'sqr)
      (lambda (x) (* x x)))
; which allows us to call it using the name SQR:
(sqr 10.0)
```

#### Scheme {#Scheme}

[Scheme's](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29) *named functions* is simply [syntactic sugar](https://en.wikipedia.org/wiki/Syntactic_sugar) for anonymous functions bound to names:

```scheme
(define (somename arg)
  (do-something arg))
```

expands (and is equivalent) to

```scheme
(define somename
  (lambda (arg)
    (do-something arg)))
```

#### Clojure {#Clojure}

[Clojure](https://en.wikipedia.org/wiki/Clojure) supports anonymous functions through the "fn" special form:

```clojure
(fn [x] (+ x 3))
```

There is also a reader syntax to define a lambda:

```clojure
#(+ % %2%3) ; Defines an anonymous function that takes three arguments and sums them.
```

Like Scheme, Clojure's "named functions" are simply syntactic sugar for lambdas bound to names:

```clojure
(defn func [arg] (+ 3 arg))
```

expands to:

```clojure
(def func (fn [arg] (+ 3 arg)))
```

### Lua {#Lua}

In [Lua](https://en.wikipedia.org/wiki/Lua_%28programming_language%29) (much as in Scheme) all functions are anonymous. A *named function* in Lua is simply a variable holding a reference to a function object.[^o46]

Thus, in Lua

```lua

```

is just syntactical sugar for

### Wolfram Language, Mathematica {#Wolfram_Language,_Mathematica}

The [Wolfram Language](https://en.wikipedia.org/wiki/Wolfram_Language) is the programming language of [Mathematica](https://en.wikipedia.org/wiki/Mathematica). Anonymous functions are important in programming the latter. There are several ways to create them. Below are a few anonymous functions that increment a number. The first is the most common. `#1` refers to the first argument and `&` marks the end of the anonymous function.

```mathematica
     #1+1&
     Function[x,x+1]
     x \[Function] x+1
```

So, for instance:

```mathematica
    f:= #1^2&;f[8]
     64
    #1+#2&[5,6]
     11
```

Also, Mathematica has an added construct to make recursive anonymous functions. The symbol '#0' refers to the [entire function](wikipedia://en/10372). The following function calculates the factorial of its input:

```mathematica
     If[#1 == 1, 1, #1 * #0[#1-1]]&
```

For example, 6 factorial would be:

```mathematica
     If[#1 == 1, 1, #1 * #0[#1-1]]&[6]
720
```

### Perl {#Perl}

#### Perl 5 {#Perl_5}

[Perl 5](https://en.wikipedia.org/wiki/Perl_5) supports anonymous functions,[^o60] as follows:

```perl

my $squarer = sub { my $x = shift; $x * $x }; # 2. assigned to a variable

sub curry {
    my ($sub, @args) = @_;

```

Other constructs take *bare blocks* as arguments, which serve a function similar to lambda functions of one parameter, but do not have the same parameter-passing convention as functions -- @\_ is not set.

```perl
my @bad_example = map { print for @_ } 1..10; # values not passed like normal Perl function
```

### PHP {#PHP}

Before 4.0.1, [PHP](https://en.wikipedia.org/wiki/PHP) had no anonymous function support.[^o62]

#### PHP 4.0.1 to 5.3 {#PHP_4.0.1_to_5.3}

PHP 4.0.1 introduced the `create_function` which was the initial anonymous function support. This function call makes a new randomly named function and returns its name (as a string)

```php
$foo = create_function('$x', 'return $x*$x;');
$bar = create_function("\$x", "return \$x*\$x;");
echo $foo(10);
```

The argument list and function body must be in single quotes, or the dollar signs must be escaped. Otherwise, PHP assumes "`$x`" means the variable `$x` and will substitute it into the string (despite possibly not existing) instead of leaving "`$x`" in the string. For functions with quotes or functions with many variables, it can get quite tedious to ensure the intended function body is what PHP interprets.

Each invocation of `create_function` makes a new function, which exists for the rest of the program, and cannot be *[garbage collected](https://en.wikipedia.org/wiki/Garbage_collection_%28computer_science%29)*, using memory in the program irreversibly. If this is used to create anonymous functions many times, e.g., in a loop, it can cause problems such as memory bloat.

#### PHP 5.3 {#PHP_5.3}

PHP 5.3 added a new class called `Closure` and magic method `__invoke()` that makes a class instance invocable.[^o65]

```php
$x = 3;
$func = function($z) { return $z * 2; };
echo $func($x); // prints 6
```

In this example, `$func` is an instance of `Closure` and `echo $func($x)` is equivalent to `echo $func->__invoke($x)`. PHP 5.3 mimics anonymous functions but it does not support true anonymous functions because PHP functions are still not first-class objects.

PHP 5.3 does support closures but the variables must be explicitly indicated as such:

```php
$x = 3;
$func = function() use(&$x) { $x *= 2; };
$func();
echo $x; // prints 6
```

The variable `$x` is bound by reference so the invocation of `$func` modifies it and the changes are visible outside of the function.

#### PHP 7.4 {#PHP_7.4}

Arrow functions were introduced in PHP 7.4

```php
$x = 3;
$func = fn($z) => $z * 2;
echo $func($x); // prints 6
```

### Python {#Python}

[Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) supports simple anonymous functions through the lambda form.[^o72] The executable body of the lambda must be an expression and can't be a statement, which is a restriction that limits its utility. The value returned by the lambda is the value of the contained expression. Lambda forms can be used anywhere ordinary functions can. However these restrictions make it a very limited version of a normal function. Here is an example:

```python
from typing import Callable

foo: Callable[[int], int] = lambda x: x * x
print(foo(10))
# prints 100
```

In general, the Python convention encourages the use of named functions defined in the same scope as one might typically use an anonymous function in other languages. This is acceptable as locally defined functions implement the full power of [closures](https://en.wikipedia.org/wiki/Closure_%28computer_science%29) and are almost as efficient as the use of a lambda in Python. In this example, the built-in power function can be said to have been [curried](wikipedia://en/6600):

```python
def make_pow(n: int) -> Callable[[int], int]:
    def fixed_exponent_pow(x: int) -> int:
        return pow(x, n)
    return fixed_exponent_pow

square: Callable[[int], int] = make_pow(2)
print(square(10))
# prints 100
cube: Callable[[int], int] = make_pow(3)
print(cube(10))
# prints 1000
```

### Rust {#Rust}

In [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29), anonymous functions are called closures.[^o78] They are defined using the following syntax:

```rust
|<parameter-name>: <type>| -> <return-type> { <body> };
```

For example:

```rust
let f = |x: i32| -> i32 { x * 2 };
```

With type inference, however, the compiler is able to infer the type of each parameter and the return type, so the above form can be written as:

```rust
let f = |x| { x * 2 };
```

With closures with a single expression (i.e. a body with one line) and implicit return type, the curly braces may be omitted:

```rust
let f = |x| x * 2;
```

Closures with no input parameter are written like so:

```rust
let f = || println!("Hello, world!");
```

Closures may be passed as input parameters of functions that expect a function pointer:

```rust
// A function which takes a function pointer as an argument and calls it with
// the value '5'.
fn apply(f: fn(i32) -> i32) -> i32 {
    // No semicolon, to indicate an implicit return
    f(5)
}

fn main() {
    // Defining the closure
    let f = |x| x * 2;

    println!("{}", apply(f));  // 10
    println!("{}", f(5));      // 10
}
```

However, one may need complex rules to describe how values in the body of the closure are captured. They are implemented using the `Fn`, `FnMut`, and `FnOnce` traits:[^o79]

- `Fn`: the closure captures by reference (`&T`). They are used for functions that can still be called if they only have reference access (with `&`) to their environment.
- `FnMut`: the closure captures by mutable reference (`&mut T`). They are used for functions that can be called if they have mutable reference access (with `&mut`) to their environment.
- `FnOnce`: the closure captures by value (`T`). They are used for functions that are only called once.

With these traits, the compiler will capture variables in the least restrictive manner possible.[^o79] They help govern how values are moved around between scopes, which is largely important since Rust follows a lifetime construct to ensure values are "borrowed" and moved in a predictable and explicit manner.[^o80]

The following demonstrates how one may pass a closure as an input parameter using the `Fn` trait:

```rust
// A function that takes a value of type F (which is defined as
// a generic type that implements the 'Fn' trait, e.g. a closure)
// and calls it with the value '5'.
fn apply_by_ref<F>(f: F) -> i32
    where F: Fn(i32) -> i32
{
    f(5)
}

fn main() {
    let f = |x| {
        println!("I got the value: {}", x);
        x * 2
    };
    
    // Applies the function before printing its return value
    println!("5 * 2 = {}", apply_by_ref(f));
}

// ~~ Program output ~~
// I got the value: 5
// 5 * 2 = 10
```

The previous function definition can also be shortened for convenience as follows:

```rust
fn apply_by_ref(f: impl Fn(i32) -> i32) -> i32 {
    f(5)
}
```

### Scala {#Scala}

In [Scala](wikipedia://en/3254510), anonymous functions use the following syntax:[^o82]

```scala
(x: Int, y: Int) => x + y
```

In certain contexts, like when an anonymous function is a parameter being passed to another function, the compiler can infer the types of the parameters of the anonymous function and they can be omitted in the syntax. In such contexts, it is also possible to use a shorthand for anonymous functions using the underscore character to introduce unnamed parameters.

```scala
val list = List(1, 2, 3, 4)
list.reduceLeft( (x, y) => x + y ) 
// Here, the compiler can infer that the types of x and y are both Int. 
// Thus, it needs no type annotations on the parameters of the anonymous function.

list.reduceLeft( _ + _ )   
// Each underscore stands for a new unnamed parameter in the anonymous function. 
// This results in an even shorter equivalent to the anonymous function above.
```

### Smalltalk {#Smalltalk}

In [Smalltalk](https://en.wikipedia.org/wiki/Smalltalk) anonymous functions are called [blocks](https://en.wikipedia.org/wiki/Smalltalk#Code_blocks) and they are invoked (called) by sending them a "value" message. If several arguments are to be passed, a "value:...value:" message with a corresponding number of value arguments must be used.

For example, in [GNU Smalltalk](https://en.wikipedia.org/wiki/GNU_Smalltalk),

```smalltalk
st> f:=[:x|x*x]. f value: 8 .
64
st> [:x :y|x+y] value: 5 value: 6 .
11
```

Smalltalk blocks are technically closures, allowing them to outlive their defining scope and still refer to the variables declared therein.

```smalltalk
st> f := [:a|[:n|a+n]] value: 100 .
a BlockClosure
"returns the inner block, which adds 100 (captured in "a" variable) to its argument."
st> f value: 1 .
101
st> f value: 2 .
102
```

### Swift {#Swift}

In [Swift](https://en.wikipedia.org/wiki/Swift_%28programming_language%29), anonymous functions are called closures.[^o85] The syntax has following form:

```objc
{ (parameters) -> returnType in
  statement
}
```

For example:

```objc
{ (s1: String, s2: String) -> Bool in
  return s1 > s2
}
```

For sake of brevity and expressiveness, the parameter types and return type can be omitted if these can be inferred:

```objc
{ s1, s2 in return s1 > s2 }
```

Similarly, Swift also supports implicit return statements for one-statement closures:

```objc
{ s1, s2 in s1 > s2 }
```

Finally, the parameter names can be omitted as well; when omitted, the parameters are referenced using shorthand argument names, consisting of the \$ symbol followed by their position (e.g. \$0, \$1, \$2, etc.):

```objc
{ $0 > $1 }
```

### Tcl {#Tcl}

In [Tcl](https://en.wikipedia.org/wiki/Tcl_%28programming_language%29), applying the anonymous squaring function to 2 looks as follows:[^o87]

```tcl
apply {x {expr {$x*$x}}} 2
# returns 4
```

This example involves two candidates for what it means to be a *function* in Tcl. The most generic is usually called a *command prefix*, and if the variable *f* holds such a function, then the way to perform the [function application](wikipedia://en/20576545) *f*(*x*) would be

```tcl
{*}$f $x
```

where `{*}` is the expansion prefix (new in Tcl 8.5). The command prefix in the above example is apply `{x {expr {$x*$x}}}` Command names can be bound to command prefixes by means of the `interp alias` command. Command prefixes support [currying](wikipedia://en/6600). Command prefixes are very common in Tcl [APIs](https://en.wikipedia.org/wiki/Application_programming_interface).

The other candidate for "function" in Tcl is usually called a *lambda*, and appears as the `{x {expr {$x*$x}}}` part of the above example. This is the part which caches the compiled form of the anonymous function, but it can only be invoked by being passed to the `apply` command. Lambdas do not support currying, unless paired with an `apply` to form a command prefix. Lambdas are rare in Tcl APIs.

### Vala {#Vala}

In [Vala](https://en.wikipedia.org/wiki/Vala_%28programming_language%29), anonymous functions are supported as lambda expressions.[^o89]

```vala
delegate int IntOp (int x, int y);

void main () {
	IntOp foo = (x, y) => x * y;
	stdout.printf("%d\n", foo(10,5));
}
```

### Visual Basic .NET {#Visual_Basic_.NET}

[Visual Basic .NET](https://en.wikipedia.org/wiki/Visual_Basic_.NET) 2008 introduced anonymous functions through the lambda form. Combined with implicit typing, VB provides an economical syntax for anonymous functions. As with Python, in VB.NET, anonymous functions must be defined on one line; they cannot be compound statements. Further, an anonymous function in VB.NET must truly be a VB.NET `Function` - it must return a value.

```vbnet
Dim foo = Function(x) x * x
Console.WriteLine(foo(10))
```

Visual Basic.NET 2010 added support for multiline lambda expressions and anonymous functions without a return value. For example, a function for use in a Thread.

```vbnet
Dim t As New System.Threading.Thread(Sub ()
                                         For n As Integer = 0 To 10   'Count to 10
                                             Console.WriteLine(n)     'Print each number
                                         Next
                                     End Sub
                                     )
t.Start()
```
