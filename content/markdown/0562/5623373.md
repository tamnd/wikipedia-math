# Optimal radix choice

::: {#o1 .subject cue=lead name="Optimal radix choice"}

In mathematics and computer science, **optimal radix choice** is the problem of choosing the base, or [radix](wikipedia://en/701207), that is best suited for representing numbers. Various proposals have been made to quantify the relative costs of using different radices in representing numbers, especially in computer systems. One formula is the number of [digits](https://en.wikipedia.org/wiki/Digit_%28math%29) needed to express it in that base, multiplied by the base (the number of possible values each digit could have). This expression also arises in questions regarding organizational structure, networking, and other fields.

:::

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

The cost of representing a number *N* in a given base *b* can be defined as

$$E(b,N) = b \lfloor \log_b (N) +1 \rfloor \,$$

where we use the [floor function $\lfloor \rfloor$](wikipedia://en/54267) and the base-b [logarithm](wikipedia://en/17860) $\log_{b}$.

If both *b* and *N* are positive integers, then the quantity $E(b,N)$ is equal to the number of [digits](https://en.wikipedia.org/wiki/Digit_%28math%29) needed to express the number *N* in base *b*, multiplied by base *b*.[^o4] This quantity thus measures the cost of storing or processing the number *N* in base *b* if the cost of each "digit" is proportional to *b*. A base with a lower average $E(b,N)$ is therefore, in some senses, more efficient than a base with a higher average value.

For example, [100](https://en.wikipedia.org/wiki/100_%28number%29) in [decimal](wikipedia://en/8214) has three digits, so its cost of representation is 10×3 = 30, while its binary representation has seven digits (1100100<sub>2</sub>), so the analogous calculation gives 2×7 = 14. Likewise, in [base 3](https://en.wikipedia.org/wiki/Base_3) its representation has five digits (10201<sub>3</sub>), for a value of 3×5 = 15, and in base 36 (2S<sub>36</sub>) one finds 36×2 = 72.

If the number is imagined to be represented by a [combination lock](https://en.wikipedia.org/wiki/Combination_lock) or a [tally counter](https://en.wikipedia.org/wiki/Tally_counter), in which each wheel has *b* digit faces, from $0, 1, ..., b-1$ and having $\lfloor \log_b (N) +1 \rfloor$ wheels, then $E(b,N)$ is the total number of digit faces needed to inclusively represent any integer from 0 to *N*.

:::

## Asymptotic behavior {#Asymptotic_behavior}

The quantity $E(b,N)$ for large *N* can be approximated as follows:

$$E(b,N) = b \lfloor \log_b (N) +1 \rfloor \sim b\ \log_b (N) = {b \over \ln(b)} \ln(N) .$$

$${E(b,N) \over \ln(N)} \sim {b \over \ln(b)} .$$

The asymptotically best value is obtained for base 3, since $b \over \ln(b)$ attains a minimum for $b = 3$ in the positive integers:

$${2 \over \ln(2)} \approx 2.88539\,,$$

$${3 \over \ln(3)} \approx 2.73072\,,$$

$${4 \over \ln(4)} \approx 2.88539\,.$$

For base 10, we have:

$${10 \over \ln(10)} \approx 4.34294\,.$$

### Steiner's calculus problem {#Steiner's_calculus_problem}

The closely related [continuous optimization](wikipedia://en/420577) problem of finding the maximum of the function

$$f(x)=x^{1/x},$$

or equivalently, on taking logs and inverting, minimizing $\tfrac{x}{\ln x}$ for continuous rather than integer values of $x$, was posed and solved by [Jakob Steiner](wikipedia://en/567445) in 1850.[^o8] The solution is [Euler's number](https://en.wikipedia.org/wiki/Euler's_number) $e\approx 2.71828$, the base of the [natural logarithm](wikipedia://en/21476), for which

$$\frac{e}{\ln e}=e\approx 2.71828\,.$$

Translating this solution back to Steiner's formulation, $e^{1/e}\approx 1.44467$ is the unique maximum of $f(x)=x^{1/x}$.

This analysis has sometimes been used to argue that, in some sense, "base $e$ is the most economical base for the representation and storage of numbers", despite the difficulty in understanding what that might mean in practice.[^o10]

This topic appears in [Underwood Dudley](wikipedia://en/176420)'s *[Mathematical Cranks](wikipedia://en/22363306).* One of the eccentrics discussed in the book argues that $e$ is the best base, based on a muddled understanding of Steiner's calculus problem, and with a greatly exaggerated sense of how important the choice of radix is.[^o11]

:::

## Comparing different bases {#Comparing_different_bases}

The values of $E(b,N)$ of bases *b*<sub>1</sub> and *b*<sub>2</sub> may be compared for a large value of *N*:

$${{E(b_1,N)} \over {E(b_2,N)}} \approx {{b_1 {\log_{b_1} (N)}} \over {b_2 {\log_{b_2} (N)}}} = {\left( \dfrac{b_1 \ln (N)} {\ln (b_1)} \right) \over \left( \dfrac{b_2 \ln (N)} {\ln (b_2)} \right)} = {{b_1 \ln (b_2)} \over {b_2 \ln (b_1)}} \, .$$

Choosing $e$ for $b_2$ gives

$${{E(b)} \over {E(e)}} \approx {{b \ln (e)} \over {e \ln (b)}} = {{b} \over {e \ln(b)}} \, .$$

## Ternary tree efficiency {#Ternary_tree_efficiency}

One result of the relative economy of base 3 is that [ternary search trees](https://en.wikipedia.org/wiki/Ternary_search_tree) offer an efficient strategy for retrieving elements of a database.[^o15] A similar analysis suggests that the optimum design of a large [telephone menu system](https://en.wikipedia.org/wiki/Interactive_voice_response) to minimise the number of menu choices that the average customer must listen to (i.e. the product of the number of choices per menu and the number of menu levels) is to have three choices per menu.[^o4]

In a [$d$-ary heap](https://en.wikipedia.org/wiki/D-ary_heap), a [priority queue](https://en.wikipedia.org/wiki/Priority_queue) data structure based on $d$-ary trees, the worst-case number of comparisons per operation in a heap containing $n$ elements is $d\log_d n$ (up to lower-order terms), the same formula used above. It has been suggested that choosing $d=3$ or $d=4$ may offer optimal performance in practice.[^o16]

[Brian Hayes](https://en.wikipedia.org/wiki/Brian_Hayes_%28scientist%29) suggests that $E(b,N)$ may be the appropriate measure for the complexity of an [Interactive voice response](https://en.wikipedia.org/wiki/Interactive_voice_response) menu: in a tree-structured phone menu with $n$ outcomes and $r$ choices per step, the time to traverse the menu is proportional to the product of $r$ (the time to present the choices at each step) with $\log_r n$ (the number of choices that need to be made to determine the outcome). From this analysis, the optimal number of choices per step in such a menu is three.[^o4]

:::

## Computer hardware efficiencies {#Computer_hardware_efficiencies}

The 1950 reference *High-Speed Computing Devices* describes a particular situation using contemporary technology. Each digit of a number would be stored as the state of a [ring counter](https://en.wikipedia.org/wiki/Ring_counter) composed of several [triodes](https://en.wikipedia.org/wiki/Triode). Whether [vacuum tubes](https://en.wikipedia.org/wiki/Vacuum_tube) or [thyratrons](https://en.wikipedia.org/wiki/Thyratron), the triodes were the most expensive part of a counter. For small radices *r* less than about 7, a single digit required *r* triodes.[^o18] (Larger radices required 2*r* triodes arranged as *r* [flip-flops](https://en.wikipedia.org/wiki/Flip-flop_%28electronics%29), as in [ENIAC](https://en.wikipedia.org/wiki/ENIAC)'s decimal counters.)[^o19]

So the number of triodes in a numerical register with *n* digits was *rn*. In order to represent numbers up to 10<sup>6</sup>, the following numbers of tubes were needed:

The authors conclude, Under these assumptions, the radix 3, on the average, is the most economical choice, closely followed by radices 2 and 4. These assumptions are, of course, only approximately valid, and the choice of 2 as a radix is frequently justified on more complete analysis. Even with the optimistic assumption that 10 triodes will yield a decimal ring, radix 10 leads to about one and one-half times the complexity of radix 2, 3, or 4. This is probably significant despite the shallow nature of the argument used here.[^o20]
