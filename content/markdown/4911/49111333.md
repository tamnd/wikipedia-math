# Double Ratchet Algorithm

*Image: Double Ratchet Algorithm.png.* Full ratchet step in the double ratchet algorithm. The Key Derivation Function (KDF) provides the ratcheting mechanism. The first "ratchet" is applied to the symmetric root key, the second ratchet to the asymmetric Diffie–Hellman (DH) key.[^o1]

::: {#o2 .subject cue=lead name="Double Ratchet Algorithm"}

In [cryptography](wikipedia://en/18934432), the **Double Ratchet Algorithm** (previously referred to as the **Axolotl Ratchet**[^o3][^o4]) is a [key](wikipedia://en/53039) management [algorithm](wikipedia://en/775) that was developed by [Trevor Perrin](https://en.wikipedia.org/wiki/Trevor_Perrin) and [Moxie Marlinspike](https://en.wikipedia.org/wiki/Moxie_Marlinspike) in 2013. It can be used as part of a [cryptographic protocol](wikipedia://en/591994) to provide [end-to-end encryption](wikipedia://en/1065362) for [instant messaging](https://en.wikipedia.org/wiki/Instant_messaging). After an initial [key exchange](wikipedia://en/63944) it manages the ongoing renewal and maintenance of short-lived session keys. It combines a cryptographic so-called "ratchet" based on the [Diffie–Hellman key exchange](wikipedia://en/7903) (DH) and a ratchet based on a [key derivation function](wikipedia://en/449781) (KDF), such as a [hash function](https://en.wikipedia.org/wiki/Hash_function), and is therefore called a double ratchet.

:::

The algorithm provides forward secrecy for messages, and implicit renegotiation of forward keys; properties for which the protocol is named.[^o5]

This has been extended as of October 2025 to the [Sparse Post Quantum Ratchet](https://en.wikipedia.org/wiki/Sparse_Post_Quantum_Ratchet) (SPQR) with a [CRYSTALS-Kyber](https://en.wikipedia.org/wiki/CRYSTALS-Kyber) quantum ratchet to provide post-quantum Forward Secrecy and Post-Compromise Security guarantees in what the Signal authors call a **Triple Ratchet**.[^o6]

## History {#History}

The Double Ratchet Algorithm was developed by Trevor Perrin and Moxie Marlinspike ([Open Whisper Systems](wikipedia://en/42081298)) in 2013 and introduced as part of the [Signal Protocol](wikipedia://en/50607084) in February 2014. The Double Ratchet Algorithm's design is based on the DH ratchet that was introduced by [Off-the-Record Messaging](https://en.wikipedia.org/wiki/Off-the-Record_Messaging) (OTR) and combines it with a symmetric-key ratchet modeled after the [Silent Circle Instant Messaging Protocol](https://en.wikipedia.org/wiki/Silent_Circle_Instant_Messaging_Protocol) (SCIMP). The ratchet was initially named after the critically endangered aquatic salamander [axolotl](https://en.wikipedia.org/wiki/Axolotl), which has extraordinary self-healing capabilities.[^o8] In March 2016, the developers renamed the Axolotl Ratchet as the Double Ratchet Algorithm to better differentiate between the ratchet and the full protocol,[^o4] because some had used the name Axolotl when referring to the Signal Protocol.[^o9][^o4]

## Overview {#Overview}

*Image: Ratchet example.gif.* A mechanical ratchet

The Double Ratchet Algorithm features properties that have been commonly available in end-to-end encryption systems for a long time: encryption of contents on the entire way of transport as well as [authentication](wikipedia://en/47967) of the remote peer and protection against manipulation of messages. As a hybrid of [DH](wikipedia://en/7903) and [KDF](wikipedia://en/449781) ratchets, it combines several desired features of both principles. From [OTR](https://en.wikipedia.org/wiki/Off-the-Record_Messaging) messaging it takes the properties of [forward secrecy](wikipedia://en/2191130) and automatically reestablishing secrecy in case of compromise of a session key, forward secrecy with a compromise of the secret persistent main key, and [plausible deniability](wikipedia://en/1055437) for the authorship of messages. Additionally, it enables session key renewal without interaction with the remote peer by using secondary KDF ratchets. An additional key-derivation step is taken to enable retaining session keys for out-of-order messages without endangering the following keys.

It is said to detect reordering, deletion, and replay of sent messages, and improve forward secrecy properties against passive eavesdropping in comparison to OTR messaging.

Combined with [public key infrastructure](wikipedia://en/194112) for the retention of pregenerated one-time keys (prekeys), it allows for the initialization of messaging sessions without the presence of the remote peer ([asynchronous communication](https://en.wikipedia.org/wiki/Asynchronous_communication)). The usage of [triple Diffie–Hellman key exchange (3-DH)](wikipedia://en/7903#Triple_Diffie-Hellman_%283-DH%29) as initial key exchange method improves the deniability properties. An example of this is the Signal Protocol, which combines the Double Ratchet Algorithm, prekeys, and a 3-DH handshake.[^o11] The protocol provides confidentiality, integrity, authentication, participant consistency, destination validation, forward secrecy, backward secrecy (aka future secrecy), causality preservation, message unlinkability, message repudiation, participation repudiation, and asynchronicity.[^o12] It does not provide anonymity preservation, and requires servers for the relaying of messages and storing of public key material.[^o12]

## Functioning {#Functioning}

A client attempts to renew session key material interactively with the remote peer using a Diffie-Hellman (DH) ratchet. If this is impossible, the clients renew the session key independently using a hash ratchet. With every message, a client advances one of two hash ratchets—one for sending and one for receiving. These two hash ratchets get seeded with a common secret from a DH ratchet. At the same time it tries to use every opportunity to provide the remote peer with a new public DH value and advance the DH ratchet whenever a new DH value from the remote peer arrives. As soon as a new common secret is established, a new hash ratchet gets initialized.

As cryptographic primitives, the Double Ratchet Algorithm uses

**for the DH ratchet**

Elliptic curve Diffie-Hellman (ECDH) with [Curve25519](wikipedia://en/17935444),

**for [message authentication codes](wikipedia://en/567523) (MAC, authentication)**

[Keyed-hash message authentication code](https://en.wikipedia.org/wiki/Hash-based_message_authentication_code) (HMAC) based on [SHA-256](https://en.wikipedia.org/wiki/SHA-256),

**for symmetric encryption**

the [Advanced Encryption Standard](wikipedia://en/1260) (AES), partially in cipher block chaining [mode](wikipedia://en/160202) (CBC) with [padding](wikipedia://en/592505) as per [PKCS](wikipedia://en/616418) #5 and partially in counter mode (CTR) without padding,

**for the hash ratchet**

HMAC.[^o14]

## Applications {#Applications}

The following is a list of applications that use the Double Ratchet Algorithm or a custom implementation of it.

### Federated networks {#Federated_networks}

- Any client for the [Matrix](wikipedia://en/46246817) network: [Element](https://en.wikipedia.org/wiki/Element_%28software%29),[^o18] [GNOME Fractal](https://en.wikipedia.org/wiki/Fractal_%28software%29)
- Any client for the [XMPP](https://en.wikipedia.org/wiki/XMPP) network with [OMEMO](wikipedia://en/48005845) support: [ChatSecure](wikipedia://en/41518933), [Conversations](https://en.wikipedia.org/wiki/Conversations_%28software%29), [Cryptocat](wikipedia://en/33741859)[^o19] (discontinued), [Gajim](https://en.wikipedia.org/wiki/Gajim), [Movim](https://en.wikipedia.org/wiki/Movim), [Psi](https://en.wikipedia.org/wiki/Psi_%28instant_messaging_client%29) via official plugin,[^o39] [Psi+](https://en.wikipedia.org/wiki/Psi_%28instant_messaging_client%29#History) via official plugin,[^o39] [libpurple](https://en.wikipedia.org/wiki/Libpurple) clients such as [Pidgin](wikipedia://en/188211) or Finch via experimental plugin,[^o36] [Adium](https://en.wikipedia.org/wiki/Adium) via an Xtra based on the libpurple plugin,[^o37] [Profanity](https://en.wikipedia.org/wiki/Profanity_%28instant_messaging_client%29) via experimental plugin.[^o38]

### Centralized networks {#Centralized_networks}

The Double Ratchet Algorithm does not attempt to solve the inherent vulnerability of centralized networks to [backdoors](https://en.wikipedia.org/wiki/Backdoor_%28computing%29) that introduce flaws in the algorithm implementation, the cryptographical protocol (which the algorithm is part of) or implementation thereof, or unrelated parts of the official application. It has been implemented nonetheless in a number of official clients for various centralized networks:

- [Facebook Messenger](https://en.wikipedia.org/wiki/Facebook_Messenger)[^o21]
- [G Data](https://en.wikipedia.org/wiki/G_Data_CyberDefense) Secure Chat[^o35][^o22]
- [Google Allo](https://en.wikipedia.org/wiki/Google_Allo)[^o23]
- [Google Messages](https://en.wikipedia.org/wiki/Google_Messages)[^o24]
- [Haven](https://en.wikipedia.org/wiki/Haven_%28software%29)[^o25][^o26]
- Pond[^o34]
- [Signal](https://en.wikipedia.org/wiki/Signal_%28messaging_app%29)
- [Silent Phone](wikipedia://en/38503539)[^o27]
- [Skype](https://en.wikipedia.org/wiki/Skype)[^o28]
- [Viber](https://en.wikipedia.org/wiki/Viber)[^o29]
- [WhatsApp](wikipedia://en/32058867)[^o30]
- [Wire](https://en.wikipedia.org/wiki/Wire_%28software%29)[^o31]
