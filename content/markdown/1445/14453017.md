# TLS-PSK

::: {#o1 .subject cue=lead name="TLS-PSK"}

**Transport Layer Security pre-shared key ciphersuites** (**TLS-PSK**) is a set of [cryptographic protocols](wikipedia://en/591994) that provide [secure](https://en.wikipedia.org/wiki/Security) communication based on [pre-shared keys](wikipedia://en/4934057) (PSKs). These pre-shared keys are [symmetric keys](https://en.wikipedia.org/wiki/Symmetric_key) shared in advance among the communicating parties.

:::

There are several cipher suites: The first set of ciphersuites use only [symmetric key](https://en.wikipedia.org/wiki/Symmetric_key) operations for [authentication](wikipedia://en/47967). The second set use a [Diffie–Hellman](wikipedia://en/7903) [key exchange](wikipedia://en/578092) authenticated with a pre-shared key. The third set combine [public key](https://en.wikipedia.org/wiki/Public_key) authentication of the server with pre-shared key authentication of the client.

Usually, [Transport Layer Security](wikipedia://en/187813) (TLS) uses [public key certificates](wikipedia://en/223796) or [Kerberos](wikipedia://en/16947) for authentication. TLS-PSK uses symmetric keys, shared in advance among the communicating parties, to establish a TLS connection. There are several reasons to use PSKs:

- Using pre-shared keys can, depending on the ciphersuite, avoid the need for public key operations. This is useful if TLS is used in performance-constrained environments with limited CPU power.
- Pre-shared keys may be more convenient from a key management point of view. For instance, in closed environments where the connections are mostly configured manually in advance, it may be easier to configure a PSK than to use certificates. Another case is when the parties already have a mechanism for setting up a shared secret key, and that mechanism could be used to “bootstrap” a key for authenticating a TLS connection.
