# Set packing

::: {#o1 .subject cue=lead name="Set packing"}

**Set packing** is a classical [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem in [computational complexity theory](wikipedia://en/7543) and [combinatorics](wikipedia://en/5170), and was one of [Karp's 21 NP-complete problems](wikipedia://en/2012564). Suppose one has a [finite set](wikipedia://en/11742) *S* and a list of [subsets](wikipedia://en/27631) of *S*. Then, the set packing problem asks if some *k* subsets in the list are pairwise [disjoint](wikipedia://en/39359) (in other words, no two of them share an element).

:::

More formally, given a universe $\mathcal{U}$ and a family $\mathcal{S}$ of subsets of $\mathcal{U}$, a *packing* is a subfamily $\mathcal{C}\subseteq\mathcal{S}$ of sets such that all sets in $\mathcal{C}$ are pairwise disjoint. The size of the packing is $|\mathcal{C}|$. In the set packing [decision problem](wikipedia://en/8336), the input is a pair $(\mathcal{U},\mathcal{S})$ and an integer $t$; the question is whether there is a set packing of size $t$ or more. In the set packing [optimization problem](wikipedia://en/1126536), the input is a pair $(\mathcal{U},\mathcal{S})$, and the task is to find a set packing that uses the most sets.

The problem is clearly in [NP](wikipedia://en/21562) since, given $t$ subsets, we can easily verify that they are pairwise disjoint in [polynomial time](wikipedia://en/658550).

The [optimization version](wikipedia://en/1126536) of the problem, **maximum set packing**, asks for the maximum number of pairwise disjoint sets in the list. It is a maximization problem that can be formulated naturally as an [integer linear program](https://en.wikipedia.org/wiki/Integer_linear_program), belonging to the class of [packing problems](wikipedia://en/213003).

## Integer linear program formulation {#Integer_linear_program_formulation}

The maximum set packing problem can be formulated as the following [integer linear program](https://en.wikipedia.org/wiki/Integer_linear_program).

| maximize | $\sum_{S \in \mathcal S} x_S$ |  | (maximize the total number of subsets) |
|---|---|---|---|
| subject to | $\sum_{S\colon e \in S} x_S \leqslant 1$ | for all $e\in \mathcal U$ | (selected sets have to be pairwise disjoint) |
|  | $x_S \in \{0,1\}$ | for all $S\in \mathcal S$. | (every set is either in the set packing or not) |

## Complexity {#Complexity}

The set packing problem is not only NP-complete, but its optimization version (general maximum set packing problem) has been proven as difficult to approximate as the [maximum clique problem](https://en.wikipedia.org/wiki/Maximum_clique_problem); in particular, it cannot be approximated within any constant factor.[^o4] The best known algorithm approximates it within a factor of $O(\sqrt{|\mathcal{U}|})$.[^o5] The weighted variant can also be approximated.[^o6]

## Packing sets with a bounded size {#Packing_sets_with_a_bounded_size}

The problem does have a variant which is more tractable. Given any positive integer *k*≥3, the ***k*-set packing problem** is a variant of set packing in which each set contains at most *k* elements.

When *k*=1, the problem is trivial. When *k*=2, the problem is equivalent to finding a [maximum cardinality matching](https://en.wikipedia.org/wiki/Maximum_cardinality_matching), which can be solved in polynomial time.

For any *k*≥3, the problem is NP-hard, as it is more general than [3-dimensional matching](wikipedia://en/22261908). However, there are [constant-factor approximation algorithms](https://en.wikipedia.org/wiki/Constant-factor_approximation_algorithms):

- Cygan[^o8] presented an algorithm that, for any ε>0, attains a (*k*+1+ε)/3 approximation. The run-time is polynomial in the number of sets and elements, but doubly-exponential in 1/ε.
- Furer and Yu[^o9] presented an algorithm that attains the same approximation, but with run-time singly-exponential in 1/ε.

## Packing sets with a bounded degree {#Packing_sets_with_a_bounded_degree}

In another more tractable variant, if no element occurs in more than *d* of the subsets, the answer can be approximated within a factor of *d*. This is also true for the weighted version.

## Related problems {#Related_problems}

### Equivalent problems {#Equivalent_problems}

**[Hypergraph matching](https://en.wikipedia.org/wiki/Hypergraph_matching)** is equivalent to set packing: the sets correspond to the hyperedges.

The **[independent set](wikipedia://en/524501) problem** is also equivalent to set packing – there is a one-to-one polynomial-time reduction between them:

- Given a set packing problem on a collection $\mathcal{S}$, build a graph where for each set $S \in \mathcal{S}$ there is a vertex $v_S$, and there is an edge between $v_S$ and $v_T$ iff $S \cap T \neq \varnothing$. Every independent set of vertices in the generated graph corresponds to a set packing in $\mathcal{S}$.
- Given an independent vertex set problem on a graph $G(V,E)$, build a collection of sets where for each vertex $v$ there is a set $S_v$ containing all edges adjacent to $v$. Every set packing in the generated collection corresponds to an independent vertex set in $G(V,E)$.

This is also a bidirectional [PTAS reduction](wikipedia://en/9010084), and it shows that the two problems are equally difficult to approximate.

In the special case when each set contains at most *k* elements (the *k-set packing problem*), the intersection graph is (*k*+1)-[claw-free](wikipedia://en/12415907). This is because, if a set intersects some *k*+1 sets, then at least two of these sets intersect, so there cannot be a (*k*+1)-claw. So Maximum Independent Set in claw-free graphs[^o13] can be seen as a generalization of Maximum *k*-Set Packing.

::: {#o15 .statement kind=statement/generalization cue=heading name="Special cases"}

### Special cases {#Special_cases}

[**Graph matching**](wikipedia://en/581797) is a special case of set packing in which the size of all sets is 2 (the sets correspond to the edges). In this special case, a maximum-size matching can be found in polynomial time.

**[3-dimensional matching](wikipedia://en/22261908)** is a special case in which the size of all sets is 3, and in addition, the elements are partitioned into 3 colors and each set contains exactly one element of each color. This special case is still NP-hard, though it has better constant-factor approximation algorithms than the general case.

:::

### Other related problems {#Other_related_problems}

In the **[set cover problem](wikipedia://en/870399)**, we are given a family $\mathcal{S}$ of subsets of a universe $\mathcal{U}$, and the goal is to determine whether we can choose *t* sets that together contain every element of $\mathcal{U}$. These sets may overlap. The optimization version finds the minimum number of such sets. The maximum set packing need not cover every possible element.

In the **[exact cover](https://en.wikipedia.org/wiki/Exact_cover)** problem, every element of $\mathcal{U}$ should be contained in *exactly one* of the subsets. Finding such an exact cover is an [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem, even in the special case in which the size of all sets is 3 (this special case is called **exact 3 cover** or **X3C**). However, if we create a [singleton set](https://en.wikipedia.org/wiki/Singleton_set) for each element of *S* and add these to the list, the resulting problem is about as easy as set packing.

Karp originally showed set packing NP-complete via a reduction from the **[clique problem](wikipedia://en/249254)**.
