# Pseudonymous remailer

::: {#o1 .subject cue=lead name="Pseudonymous remailer"}

A **pseudonymous remailer** or **nym server**, as opposed to an [anonymous remailer](wikipedia://en/54666), is an [Internet](https://en.wikipedia.org/wiki/Internet) software program designed to allow people to write [pseudonymous](https://en.wikipedia.org/wiki/Pseudonym) messages on [Usenet](https://en.wikipedia.org/wiki/Usenet) newsgroups and send pseudonymous [email](https://en.wikipedia.org/wiki/Email). Unlike purely anonymous remailers, it assigns its users a user name, and it keeps a database of instructions on how to return messages to the real user. These instructions usually involve the anonymous remailer network itself, thus protecting the true identity of the user.

:::

Primordial pseudonymous remailers once recorded enough information to trace the identity of the real user, making it possible for someone to obtain the identity of the real user through legal or illegal means. This form of pseudonymous remailer is no longer common.

[David Chaum](wikipedia://en/239365) wrote an article in 1981 that described many of the features present in modern pseudonymous remailers.[^o2]

The [Penet remailer](https://en.wikipedia.org/wiki/Penet_remailer), which lasted from 1993 to 1996, was a popular pseudonymous remailer.

## Contemporary nym servers {#Contemporary_nym_servers}

A **nym server** (short for "[pseudonym](https://en.wikipedia.org/wiki/Pseudonymity) server") is a [server](https://en.wikipedia.org/wiki/Server_%28computing%29) that provides an untraceable e-mail address, such that neither the nym server operator nor the operators of the remailers involved can discover which nym corresponds to which real identity.

To set up a nym, one creates a [PGP](wikipedia://en/23080) keypair and submits it to the nym server, along with instructions (called a *reply block*) to [anonymous remailers](wikipedia://en/54666) (such as [Cypherpunk](https://en.wikipedia.org/wiki/Cypherpunk_anonymous_remailer) or [Mixmaster](https://en.wikipedia.org/wiki/Mixmaster_anonymous_remailer)) on how to send a message to one's real address. The nym server returns a confirmation through this reply block. One then sends a message to the address in the confirmation.

To send a message through the nym server so that the *From* address is the nym, one adds a few headers, signs the message with one's nym key, encrypts it with the nym server key, and sends the message to the nym server, optionally routing it through some anonymous remailers. When the nym server receives the message it decrypts it and sends it on to the intended recipient, with the *From* address indicating one's nym.

When the nym server gets a message addressed *to* the nym, it appends it to the nym's reply block and sends it to the first remailer in the chain, which sends it to the next and so on until it reaches your real address. It is considered good practice to include instructions to encrypt it on the way, so that someone (or some organization) doing in/out [traffic analysis](https://en.wikipedia.org/wiki/Traffic_analysis) on the nym server cannot easily match the message received by you to the one sent by the nym server.

Existing "multi-use reply block" nym servers were shown to be susceptible to passive traffic analysis with one month's worth of incoming [spam](https://en.wikipedia.org/wiki/Spam_%28electronic%29) (based on 2005 figures) in a paper by [Bram Cohen](https://en.wikipedia.org/wiki/Bram_Cohen), [Len Sassaman](wikipedia://en/92210), and [Nick Mathewson](https://en.wikipedia.org/wiki/Nick_Mathewson).[^o4]
