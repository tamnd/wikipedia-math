# Directed acyclic graph

::: {#o1 .subject cue=lead name="Directed acyclic graph"}

*Image: Tred-G.svg.* Example of a directed acyclic graph

In [mathematics](wikipedia://en/18831), particularly [graph theory](wikipedia://en/12401), and [computer science](https://en.wikipedia.org/wiki/Computer_science), a **directed acyclic graph** (**DAG**) is a [directed graph](wikipedia://en/19721986) with no [directed cycles](wikipedia://en/878962#Directed_cycle_graph). That is, it consists of [vertices](wikipedia://en/638899) and [edges](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) (also called *arcs*), with each edge directed from one vertex to another, such that following those directions will never form a closed loop. A directed graph is a DAG if and only if it can be [topologically ordered](https://en.wikipedia.org/wiki/Topological_ordering), by arranging the vertices as a linear ordering that is consistent with all edge directions. DAGs have numerous scientific and computational applications, ranging from biology (evolution, family trees, epidemiology) to information science ([citation networks](https://en.wikipedia.org/wiki/Citation_graph)) to computation ([scheduling](https://en.wikipedia.org/wiki/Scheduling_%28computing%29)).

:::

Directed acyclic graphs are also called **acyclic directed graphs**[^o4] or **acyclic digraphs**.[^o5]

::: {#o3 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

A [graph](wikipedia://en/325806) is formed by [vertices](wikipedia://en/638899) and by [edges](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) connecting pairs of vertices, where the vertices can be any kind of object that is connected in pairs by edges. In the case of a [directed graph](wikipedia://en/19721986), each edge has an orientation, from one vertex to another vertex. A [walk](https://en.wikipedia.org/wiki/Walk_%28graph_theory%29) in a directed graph is a (finite or infinite) sequence $(v_1,v_2,\dotsc)$ of vertices such that each consecutive pair $(v_i,v_{i+1})$ is connected by a directed edge. A [path](wikipedia://en/638889) is a walk where all vertices are distinct. A [cycle](wikipedia://en/168609) is a walk $(v_1,v_2,\dotsc,v_n)$ where the only repeated vertex is $v_n=v_1$, meaning the last vertex equals the first vertex. A directed acyclic graph is a directed graph that has no cycles.[^o4][^o5][^o6]

:::

## Mathematical properties {#Mathematical_properties}

### Reachability relation, transitive closure, and transitive reduction {#Reachability_relation,_transitive_closure,_and_transitive_reduction}

The [reachability relation](wikipedia://en/2833097) of a DAG can be formalized as a [partial order](https://en.wikipedia.org/wiki/Partial_order) $\le$ on the vertices of the DAG. In this partial order, two vertices $u$ and $v$ are ordered as $u \le v$ exactly when there exists a directed path from $u$ to $v$ in the DAG; that is, when $u$ can reach $v$ (or $v$ is reachable from $u$).[^o9] However, different DAGs may give rise to the same reachability relation and the same partial order.[^o10] For example, a DAG with two edges $u \to v$ and $v \to w$ has the same reachability relation as the DAG with three edges $u \to v$, $v \to w$, and $u \to w$. Both of these DAGs produce the same partial order, in which the vertices are ordered as $u \le v \le w$.

The [transitive closure](wikipedia://en/292239) of a DAG is the graph with the most edges that has the same reachability relation as the DAG. It has an edge $u \to v$ for every pair of vertices ($u$, $v$) in the reachability relation $\le$ of the DAG, and may therefore be thought of as a direct translation of the reachability relation $\le$ into graph-theoretic terms. The same method of translating partial orders into DAGs works more generally: for every finite partially ordered set $(S, \le)$, the graph that has a vertex for every element of $S$ and an edge for every pair of elements in $\le$ is automatically a transitively closed DAG, and has $(S, \le)$ as its reachability relation. In this way, every finite partially ordered set can be represented as a DAG.

*Image: Hasse diagram of powerset of 3.svg.* A [Hasse diagram](wikipedia://en/338199) representing the partial order of set inclusion (⊆) among the subsets of a three-element set

The [transitive reduction](wikipedia://en/3757117) of a DAG is the graph with the fewest edges that has the same reachability relation as the DAG. It has an edge $u \to v$ for every pair of vertices ($u$, $v$) in the [covering relation](wikipedia://en/14835049) of the reachability relation $\le$ of the DAG. It is a subgraph of the DAG, formed by discarding the edges $u \to v$ for which the DAG also contains a longer directed path from $u$ to $v$. Like the transitive closure, the transitive reduction is uniquely defined for DAGs. In contrast, for a directed graph that is not acyclic, there can be more than one minimal subgraph with the same reachability relation.[^o11] Transitive reductions are useful in visualizing the partial orders they represent, because they have fewer edges than other graphs representing the same orders and therefore lead to simpler [graph drawings](wikipedia://en/325813). A [Hasse diagram](wikipedia://en/338199) of a partial order is a drawing of the transitive reduction in which the orientation of every edge is shown by placing the starting vertex of the edge in a lower position than its ending vertex.[^o12]

### Topological ordering {#Topological_ordering}

A [topological ordering](https://en.wikipedia.org/wiki/Topological_ordering) of a directed graph is an ordering of its vertices into a sequence, such that for every edge the start vertex of the edge occurs earlier in the sequence than the ending vertex of the edge. A graph that has a topological ordering cannot have any cycles, because the edge into the earliest vertex of a cycle would have to be oriented the wrong way. Therefore, every graph with a topological ordering is acyclic. Conversely, every directed acyclic graph has at least one topological ordering. The existence of a topological ordering can therefore be used as an equivalent definition of a directed acyclic graphs: they are exactly the graphs that have topological orderings.[^o5] In general, this ordering is not unique; a DAG has a unique topological ordering if and only if it has a directed path containing all the vertices, in which case the ordering is the same as the order in which the vertices appear in the path.[^o14]

The family of topological orderings of a DAG is the same as the family of [linear extensions](wikipedia://en/11726298) of the reachability relation for the DAG,[^o15] so any two graphs representing the same partial order have the same set of topological orders.

### Combinatorial enumeration {#Combinatorial_enumeration}

The [graph enumeration](wikipedia://en/9982439) problem of counting directed acyclic graphs was studied by (Robinson 1973).[^o18] The number of DAGs on $n$ labeled vertices, for $n = 0, 1, 2, 3, \ldots$ (without restrictions on the order in which these numbers appear in a topological ordering of the DAG) is

1, 1, 3, 25, 543, 29281, 3781503, … .

These numbers may be computed by the [recurrence relation](wikipedia://en/146806)

$a_n = \sum_{k=1}^n (-1)^{k-1} {n\choose k}2^{k(n-k)} a_{n-k}.$[^o18]

[Eric W. Weisstein](wikipedia://en/836189) conjectured, and (McKay Royle Wanless Oggier 2004) proved, that the same numbers count the [(0,1) matrices](wikipedia://en/4109196) for which all [eigenvalues](https://en.wikipedia.org/wiki/Eigenvalue) are positive [real numbers](wikipedia://en/20646438). The proof is [bijective](wikipedia://en/917006): a matrix $A$ is an [adjacency matrix](wikipedia://en/244463) of a DAG if and only if $A + I$ is a (0,1) matrix with all eigenvalues positive, where $I$ denotes the [identity matrix](wikipedia://en/59718). Because a DAG cannot have [self-loops](wikipedia://en/1449083), its adjacency matrix must have a zero diagonal, so adding $I$ preserves the property that all matrix coefficients are 0 or 1.[^o21]

### Related families of graphs {#Related_families_of_graphs}

A *[multitree](wikipedia://en/27131455)* (also called a *strongly unambiguous graph* or a *mangrove*) is a DAG in which there is at most one directed path between any two vertices. Equivalently, it is a DAG in which the subgraph reachable from any vertex induces an [undirected tree](wikipedia://en/48560).[^o23]

A *[polytree](wikipedia://en/1731488)* (also called a *directed tree*) is a multitree formed by orienting the edges of an undirected tree.[^o24]

An *[arborescence](wikipedia://en/13251077)* is a polytree formed by [orienting](wikipedia://en/36619818) the edges of an undirected tree away from a particular vertex, called the *root* of the arborescence.

## Computational problems {#Computational_problems}

### Topological sorting and recognition {#Topological_sorting_and_recognition}

[Topological sorting](wikipedia://en/897064) is the algorithmic problem of finding a topological ordering of a given DAG. It can be solved in [linear time](https://en.wikipedia.org/wiki/Linear_time).[^o27] Kahn's algorithm for topological sorting builds the vertex ordering directly. It maintains a list of vertices that have no incoming edges from other vertices that have not already been included in the partially constructed topological ordering; initially this list consists of the vertices with no incoming edges at all. Then, it repeatedly adds one vertex from this list to the end of the partially constructed topological ordering, and checks whether its neighbors should be added to the list. The algorithm terminates when all vertices have been processed in this way.[^o29] Alternatively, a topological ordering may be constructed by reversing a [postorder](https://en.wikipedia.org/wiki/Postorder) numbering of a [depth-first search](wikipedia://en/97034) graph traversal.[^o27]

It is also possible to check whether a given directed graph is a DAG in linear time, either by attempting to find a topological ordering and then testing for each edge whether the resulting ordering is valid[^o28] or alternatively, for some topological sorting algorithms, by verifying that the algorithm successfully orders all the vertices without meeting an error condition.[^o29]

### Construction from cyclic graphs {#Construction_from_cyclic_graphs}

Any undirected graph may be made into a DAG by choosing a [total order](wikipedia://en/30330) for its vertices and directing every edge from the earlier endpoint in the order to the later endpoint. The resulting [orientation](wikipedia://en/36619818) of the edges is called an [acyclic orientation](wikipedia://en/36619881). Different total orders may lead to the same acyclic orientation, so an $n$-vertex graph can have fewer than $n!$ acyclic orientations. The number of acyclic orientations is equal to $|\chi(-1)|$, where $\chi$ is the [chromatic polynomial](wikipedia://en/1460126) of the given graph.[^o31]

*Image: Graph Condensation.svg.* The yellow directed acyclic graph is the [condensation](https://en.wikipedia.org/wiki/Condensation_%28graph_theory%29) of the blue directed graph. It is formed by [contracting](wikipedia://en/3758115) each [strongly connected component](wikipedia://en/684680) of the blue graph into a single yellow vertex.

Any directed graph may be made into a DAG by removing a [feedback vertex set](wikipedia://en/1860368) or a [feedback arc set](wikipedia://en/1860374), a set of vertices or edges (respectively) that touches all cycles. However, the smallest such set is [NP-hard](https://en.wikipedia.org/wiki/NP-hard) to find.[^o32] An arbitrary directed graph may also be transformed into a DAG, called its [condensation](https://en.wikipedia.org/wiki/Condensation_%28graph_theory%29), by [contracting](wikipedia://en/3758115) each of its [strongly connected components](wikipedia://en/684680) into a single supervertex.[^o33] When the graph is already acyclic, its smallest feedback vertex sets and feedback arc sets are [empty](wikipedia://en/9566), and its condensation is the graph itself.

### Transitive closure and transitive reduction {#Transitive_closure_and_transitive_reduction}

The transitive closure of a given DAG, with $n$ vertices and $m$ edges, may be constructed in time $O(mn)$ by using either [breadth-first search](wikipedia://en/97026) or [depth-first search](wikipedia://en/97034) to test reachability from each vertex.[^o35] Alternatively, it can be solved in time $O(n^{\omega})$ where $\omega < 2.373$ is the [exponent for matrix multiplication algorithms](wikipedia://en/24107400#Matrix_multiplication_exponent); this is a theoretical improvement over the $O(mn)$ bound for [dense graphs](wikipedia://en/2777098).[^o36]

In all of these transitive closure algorithms, it is possible to distinguish pairs of vertices that are reachable by at least one path of length two or more from pairs that can only be connected by a length-one path. The transitive reduction consists of the edges that form length-one paths that are the only paths connecting their endpoints. Therefore, the transitive reduction can be constructed in the same asymptotic time bounds as the transitive closure.[^o37]

### Closure problem {#Closure_problem}

The [closure problem](https://en.wikipedia.org/wiki/Closure_problem) takes as input a vertex-weighted directed acyclic graph and seeks the minimum (or maximum) weight of a closure – a set of vertices *C*, such that no edges leave *C*. The problem may be formulated for directed graphs without the assumption of acyclicity, but with no greater generality, because in this case it is equivalent to the same problem on the condensation of the graph. It may be solved in polynomial time using a reduction to the [maximum flow problem](wikipedia://en/403165).[^o39]

### Path algorithms {#Path_algorithms}

Some algorithms become simpler when used on DAGs instead of general graphs, based on the principle of topological ordering. For example, it is possible to find [shortest paths](https://en.wikipedia.org/wiki/Shortest_path) and [longest paths](wikipedia://en/18757567) from a given starting vertex in DAGs in linear time by [processing the vertices in a topological order](wikipedia://en/897064#Application_to_shortest_path_finding), and calculating the path length for each vertex to be the minimum or maximum length obtained via any of its incoming edges.[^o41] In contrast, for arbitrary graphs the shortest path may require slower algorithms such as [Dijkstra's algorithm](wikipedia://en/45809) or the [Bellman–Ford algorithm](wikipedia://en/221244),[^o42] and longest paths in arbitrary graphs are [NP-hard](https://en.wikipedia.org/wiki/NP-hard) to find.[^o43]

## Applications {#Applications}

### Scheduling {#Scheduling}

Directed acyclic graph representations of partial orderings have many applications in [scheduling](https://en.wikipedia.org/wiki/Schedule) for systems of tasks with ordering constraints.[^o47] An important class of problems of this type concern collections of objects that need to be updated, such as the cells of a [spreadsheet](https://en.wikipedia.org/wiki/Spreadsheet) after one of the cells has been changed, or the [object files](https://en.wikipedia.org/wiki/Object_file) of a piece of computer software after its [source code](https://en.wikipedia.org/wiki/Source_code) has been changed. In this context, a [dependency graph](wikipedia://en/5021549) is a graph that has a vertex for each object to be updated, and an edge connecting two objects whenever one of them needs to be updated earlier than the other. A cycle in this graph is called a [circular dependency](https://en.wikipedia.org/wiki/Circular_dependency), and is generally not allowed, because there would be no way to consistently schedule the tasks involved in the cycle. Dependency graphs without circular dependencies form DAGs.[^o48]

For instance, when one cell of a [spreadsheet](https://en.wikipedia.org/wiki/Spreadsheet) changes, it is necessary to recalculate the values of other cells that depend directly or indirectly on the changed cell. For this problem, the tasks to be scheduled are the recalculations of the values of individual cells of the spreadsheet. Dependencies arise when an expression in one cell uses a value from another cell. In such a case, the value that is used must be recalculated earlier than the expression that uses it. Topologically ordering the dependency graph, and using this topological order to schedule the cell updates, allows the whole spreadsheet to be updated with only a single evaluation per cell.[^o49] Similar problems of task ordering arise in [makefiles](https://en.wikipedia.org/wiki/Makefile) for program compilation[^o49] and [instruction scheduling](https://en.wikipedia.org/wiki/Instruction_scheduling) for low-level computer program optimization.[^o50]

*Image: Pert chart colored.svg.* PERT chart for a project with five milestones (labeled 10–50) and six tasks (labeled A–F). There are two critical paths, ADF and BC.

A somewhat different DAG-based formulation of scheduling constraints is used by the [program evaluation and review technique](https://en.wikipedia.org/wiki/Program_evaluation_and_review_technique) (PERT), a method for management of large human projects that was one of the first applications of DAGs. In this method, the vertices of a DAG represent [milestones](https://en.wikipedia.org/wiki/Milestone_%28project_management%29) of a project rather than specific tasks to be performed. Instead, a task or activity is represented by an edge of a DAG, connecting two milestones that mark the beginning and completion of the task. Each such edge is labeled with an estimate for the amount of time that it will take a team of workers to perform the task. The [longest path](wikipedia://en/18757567) in this DAG represents the [critical path](wikipedia://en/203646) of the project, the one that controls the total time for the project. Individual milestones can be scheduled according to the lengths of the longest paths ending at their vertices.[^o51]

### Data processing networks {#Data_processing_networks}

A directed acyclic graph may be used to represent a network of processing elements. In this representation, data enters a processing element through its incoming edges and leaves the element through its outgoing edges.

For instance, in electronic circuit design, static [combinational logic](wikipedia://en/89371) blocks can be represented as an acyclic system of [logic gates](https://en.wikipedia.org/wiki/Logic_gate) that computes a function of an input, where the input and output of the function are represented as individual [bits](https://en.wikipedia.org/wiki/Bit). In general, the output of these blocks cannot be used as the input unless it is captured by a register or state element which maintains its acyclic properties.[^o53] Electronic circuit schematics either on paper or in a database are a form of directed acyclic graphs using instances or components to form a directed reference to a lower level component. Electronic circuits themselves are not necessarily acyclic or directed.

[Dataflow programming](https://en.wikipedia.org/wiki/Dataflow_programming) languages describe systems of operations on [data streams](https://en.wikipedia.org/wiki/Data_stream), and the connections between the outputs of some operations and the inputs of others. These languages can be convenient for describing repetitive data processing tasks, in which the same acyclically-connected collection of operations is applied to many data items. They can be executed as a [parallel algorithm](https://en.wikipedia.org/wiki/Parallel_algorithm) in which each operation is performed by a parallel process as soon as another set of inputs becomes available to it.[^o54]

In [compilers](https://en.wikipedia.org/wiki/Compiler), straight line code (that is, sequences of statements without loops or conditional branches) may be represented by a DAG describing the inputs and outputs of each of the arithmetic operations performed within the code. This representation allows the compiler to perform [common subexpression elimination](https://en.wikipedia.org/wiki/Common_subexpression_elimination) efficiently.[^o55] At a higher level of code organization, the [acyclic dependencies principle](https://en.wikipedia.org/wiki/Acyclic_dependencies_principle) states that the dependencies between modules or components of a large software system should form a directed acyclic graph.[^o56]

[Feedforward neural networks](https://en.wikipedia.org/wiki/Feedforward_neural_network) are another example.

### Causal structures {#Causal_structures}

Graphs in which vertices represent events occurring at a definite time, and where the edges always point from an earlier time vertex to a later time vertex, are necessarily directed and acyclic. The lack of a cycle follows because the time associated with a vertex always increases as you follow any directed [path](wikipedia://en/638889) in the graph, so you can never return to a vertex on a path. This reflects our natural intuition that causality means events can only affect the future, they never affect the past, and thus we have no [causal loops](https://en.wikipedia.org/wiki/Causal_loop). An example of this type of directed acyclic graph are those encountered in the [causal set approach to quantum gravity](wikipedia://en/10066673) though in this case the graphs considered are transitively complete. In the version history example below, each version of the software is associated with a unique time, typically the time the version was saved, committed or released. In the citation graph examples below, the documents are published at one time and can only refer to older documents.

Sometimes events are not associated with a specific physical time. Provided that pairs of events have a purely causal relationship, that is edges represent [causal relations](https://en.wikipedia.org/wiki/Causality) between the events, we will have a directed acyclic graph.[^o58] For instance, a [Bayesian network](wikipedia://en/203996) represents a system of probabilistic events as vertices in a directed acyclic graph, in which the likelihood of an event may be calculated from the likelihoods of its predecessors in the DAG.[^o59] In this context, the [moral graph](wikipedia://en/4855451) of a DAG is the undirected graph created by adding an (undirected) edge between all parents of the same vertex (sometimes called *marrying*), and then replacing all directed edges by undirected edges.[^o60] Another type of graph with a similar causal structure is an [influence diagram](wikipedia://en/1194259), the vertices of which represent either decisions to be made or unknown information, and the edges of which represent causal influences from one vertex to another.[^o61] In [epidemiology](wikipedia://en/66997), for instance, these diagrams are often used to estimate the expected value of different choices for intervention.[^o62][^o63]

The converse is also true. That is in any application represented by a directed acyclic graph there is a causal structure, either an explicit order or time in the example or an order which can be derived from graph structure. This follows because all directed acyclic graphs have a topological ordering, i.e. there is at least one way to put the vertices in an order such that all edges point in the same direction along that order.

### Genealogy and version history {#Genealogy_and_version_history}

*Image: EgyptianPtolemies2.jpg.* Family tree of the [Ptolemaic dynasty](https://en.wikipedia.org/wiki/Ptolemaic_dynasty), with many marriages between [close relatives](https://en.wikipedia.org/wiki/Consanguinity) causing [pedigree collapse](https://en.wikipedia.org/wiki/Pedigree_collapse)

[Family trees](https://en.wikipedia.org/wiki/Family_tree) may be seen as directed acyclic graphs, with a vertex for each family member and an edge for each parent-child relationship.[^o65] Despite the name, these graphs are not necessarily trees because of the possibility of marriages between relatives (so a child has a common ancestor on both the mother's and father's side) causing [pedigree collapse](https://en.wikipedia.org/wiki/Pedigree_collapse).[^o66] The graphs of [matrilineal](https://en.wikipedia.org/wiki/Matrilineal) descent (mother-daughter relationships) and [patrilineal](https://en.wikipedia.org/wiki/Patrilineal) descent (father-son relationships) are trees within this graph. Because no one can become their own ancestor, family trees are acyclic.[^o67]

The version history of a [distributed revision control](https://en.wikipedia.org/wiki/Distributed_revision_control) system, such as [Git](https://en.wikipedia.org/wiki/Git), generally has the structure of a directed acyclic graph, in which there is a vertex for each revision and an edge connecting pairs of revisions that were directly derived from each other. These are not trees in general due to merges.[^o68]

In many [randomized](wikipedia://en/65462) [algorithms](wikipedia://en/775) in [computational geometry](wikipedia://en/176927), the algorithm maintains a *history DAG* representing the version history of a geometric structure over the course of a sequence of changes to the structure. For instance in a [randomized incremental](wikipedia://en/495383#Randomized_incremental_constructions_in_geometry) algorithm for [Delaunay triangulation](wikipedia://en/8864), the triangulation changes by replacing one triangle by three smaller triangles when each point is added, and by "flip" operations that replace pairs of triangles by a different pair of triangles. The history DAG for this algorithm has a vertex for each triangle constructed as part of the algorithm, and edges from each triangle to the two or three other triangles that replace it. This structure allows [point location](https://en.wikipedia.org/wiki/Point_location) queries to be answered efficiently: to find the location of a query point $q$ in the Delaunay triangulation, follow a path in the history DAG, at each step moving to the replacement triangle that contains $q$. The final triangle reached in this path must be the Delaunay triangle that contains $q$.[^o69]

### Citation graphs {#Citation_graphs}

In a [citation graph](https://en.wikipedia.org/wiki/Citation_graph) the vertices are documents with a single publication date. The edges represent the citations from the bibliography of one document to other necessarily earlier documents. The classic example comes from the citations between academic papers as pointed out in the 1965 article "Networks of Scientific Papers"[^o71] by [Derek J. de Solla Price](https://en.wikipedia.org/wiki/Derek_J._de_Solla_Price) who went on to produce the first model of a citation network, the [Price model](https://en.wikipedia.org/wiki/Price's_model).[^o72] In this case the [citation count](https://en.wikipedia.org/wiki/Citation_impact) of a paper is just the in-degree of the corresponding vertex of the citation network. This is an important measure in [citation analysis](https://en.wikipedia.org/wiki/Citation_analysis). [Court judgements](https://en.wikipedia.org/wiki/Judgment_%28law%29) provide another example as judges support their conclusions in one case by recalling other earlier decisions made in previous cases. A final example is provided by patents which must refer to earlier [prior art](https://en.wikipedia.org/wiki/Prior_art), earlier patents which are relevant to the current patent claim. By taking the special properties of directed acyclic graphs into account, one can analyse citation networks with techniques not available when analysing the general graphs considered in many studies using [network analysis](https://en.wikipedia.org/wiki/Network_Science). For instance transitive reduction gives new insights into the citation distributions found in different applications highlighting clear differences in the mechanisms creating citations networks in different contexts.[^o73] Another technique is [main path analysis](https://en.wikipedia.org/wiki/Main_path_analysis), which traces the citation links and suggests the most significant citation chains in a given [citation graph](https://en.wikipedia.org/wiki/Citation_graph).

The [Price model](https://en.wikipedia.org/wiki/Price's_model) is too simple to be a realistic model of a [citation network](https://en.wikipedia.org/wiki/Citation_graph) but it is simple enough to allow for analytic solutions for some of its properties. Many of these can be found by using results derived from the undirected version of the [Price model](https://en.wikipedia.org/wiki/Price's_model), the [Barabási–Albert model](wikipedia://en/8286726). However, since [Price's model](https://en.wikipedia.org/wiki/Price's_model) gives a directed acyclic graph, it is a useful model when looking for analytic calculations of properties unique to directed acyclic graphs. For instance, the length of the longest path, from the n-th node added to the network to the first node in the network, scales as[^o74] $\ln(n)$.

### Data compression {#Data_compression}

Directed acyclic graphs may also be used as a [compact representation](wikipedia://en/8013) of a collection of sequences. In this type of application, one finds a DAG in which the paths form the given sequences. When many of the sequences share the same subsequences, these shared subsequences can be represented by a shared part of the DAG, allowing the representation to use less space than it would take to list out all of the sequences separately. For example, the [directed acyclic word graph](https://en.wikipedia.org/wiki/Deterministic_acyclic_finite_state_automaton) is a [data structure](wikipedia://en/8519) in computer science formed by a directed acyclic graph with a single source and with edges labeled by letters or symbols; the paths from the source to the sinks in this graph represent a set of [strings](wikipedia://en/27701), such as English words.[^o76] Any set of sequences can be represented as paths in a tree, by forming a tree vertex for every prefix of a sequence and making the parent of one of these vertices represent the sequence with one fewer element; the tree formed in this way for a set of strings is called a [trie](https://en.wikipedia.org/wiki/Trie).

Similarly, a [binary search tree](wikipedia://en/4320) can be viewed as a rooted DAG where paths represent sorted orderings of keys, though it lacks the path-merging compression found in more complex DAGs.[^o77] A directed acyclic word graph saves space over a trie by allowing paths to diverge and rejoin, so that a set of words with the same possible suffixes can be represented by a single tree vertex.[^o78]

The same idea of using a DAG to represent a family of paths occurs in the [binary decision diagram](wikipedia://en/576855),[^o79][^o80] a DAG-based data structure for representing binary functions. In a binary decision diagram, each non-sink vertex is labeled by the name of a binary variable, and each sink and each edge is labeled by a 0 or 1. The function value for any [truth assignment](https://en.wikipedia.org/wiki/Truth_assignment) to the variables is the value at the sink found by following a path, starting from the single source vertex, that at each non-sink vertex follows the outgoing edge labeled with the value of that vertex's variable. Just as directed acyclic word graphs can be viewed as a compressed form of tries, binary decision diagrams can be viewed as compressed forms of [decision trees](wikipedia://en/232602) that save space by allowing paths to rejoin when they agree on the results of all remaining decisions.[^o81]
