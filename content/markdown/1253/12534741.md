# KWallet

::: {#o2 .subject cue=lead name="KWallet"}

**KDE Wallet Manager** is free and [open-source](https://en.wikipedia.org/wiki/Open-source_software) [password management](wikipedia://en/4696394) software and [framework](https://en.wikipedia.org/wiki/Software_framework) written in [C++](https://en.wikipedia.org/wiki/C++) for [UNIX](https://en.wikipedia.org/wiki/Unix)-style operating systems. It includes the **KWallet** framework, the **KWalletManager** [GUI](https://en.wikipedia.org/wiki/Graphical_user_interface) application, the **kwalletd** [daemon](https://en.wikipedia.org/wiki/Daemon_%28computing%29) which exposes the framework [API](https://en.wikipedia.org/wiki/API), and the **ksecretd** daemon which exposes the Secret Service [D-Bus](https://en.wikipedia.org/wiki/D-Bus) API. KDE Wallet Manager runs on a [Linux](https://en.wikipedia.org/wiki/Linux)-based OS and its main feature is storing encrypted [passwords](wikipedia://en/24304) in KDE Wallets.[^o3] Its main feature is to collect user's credentials such as passwords or IDs and [encrypt](wikipedia://en/10294) them through [Blowfish](wikipedia://en/3940) symmetric [block cipher](wikipedia://en/4594) algorithm or [GNU Privacy Guard](wikipedia://en/38809) encryption.

:::

## Installation {#Installation}

KDE Wallet Manager (KWallet) requires a Linux-based OS and the [KDE Software Compilation](https://en.wikipedia.org/wiki/KDE_Software_Compilation) [desktop environment](https://en.wikipedia.org/wiki/Desktop_environment) such as [Kubuntu](https://en.wikipedia.org/wiki/Kubuntu).[^o5]

## Browser extensions {#Browser_extensions}

KDE Wallet manager (KWallet) can be integrated with various web browsers including [Chrome](https://en.wikipedia.org/wiki/Google_Chrome), [Opera](https://en.wikipedia.org/wiki/Opera_%28web_browser%29), and [Edge](https://en.wikipedia.org/wiki/Microsoft_Edge).

To use KDE Wallet manager (KWallet) integration on Chrome or any other [Chromium](https://en.wikipedia.org/wiki/Chromium_%28web_browser%29) based browsers, user needs to run the browser with argument `--password-store=kwallet5` or `--password-store=detect` .[^o7]

Historically, there was a standalone add-on available for [Firefox](https://en.wikipedia.org/wiki/Firefox). This addon allows users to store passwords internally through KDE Wallet manager (KWallet) instead of the default Firefox password manager.

Since the release of Firefox v57 and the migration from [XUL](https://en.wikipedia.org/wiki/XUL) based extension to [WebExtensions](https://en.wikipedia.org/wiki/WebExtensions), there has been no attempt to make a new add-on to support the new Firefox.

KDE web browsers [Konqueror](https://en.wikipedia.org/wiki/Konqueror) and [Falkon](https://en.wikipedia.org/wiki/Falkon) use KDE Wallet manager (KWallet) to store sensitive passwords encrypted.

## API {#API}

KDE Wallet Manager’s [APIs](https://en.wikipedia.org/wiki/API) trigger authentication events when the application makes a request through Desktop Communications protocol (DCOP), which is KDE’s primary [interprocess communication (IPC)](https://en.wikipedia.org/wiki/Inter-process_communication) mechanism, which causes a password dialog box to be displayed for the application. This causes the password dialog box to be launched by the KDE [daemon](https://en.wikipedia.org/wiki/Daemon_%28computing%29) process. Users can choose either to cancel the dialog box which will terminate the application or to fill the password box in. If the password box is filled, the Wallet will automatically open. KDE Wallet Manager’s Desktop communications protocol (DCOP) can only be accessed locally because it is an interprocess communication (IPC) protocol that is processed over UNIX [local sockets](https://en.wikipedia.org/wiki/Unix_domain_socket).[^o9]

## GUI {#GUI}

On KDE Wallet Manager’s [GUI](https://en.wikipedia.org/wiki/Graphical_user_interface), users can manage every wallet and password assigned to them.

KDE Wallet Manager allows users to save or delete Wallets and users can identify which wallet applications should look in when attempting to access a stored password.[^o9]

These are the lists of actions that users can take on the GUI of KDE Wallet manager (KWallet):

- Create new Wallet
- Change the default Wallet
- Lock the Wallet
- Store passwords to a Wallet
- Unlock the password of the Wallet
- Update the information on a Wallet
- View stored passwords in the Wallet[^o9]

## Wallets {#Wallets}

*Image: KWallet Interface.PNG.* Managing Wallets in KWallet.

The Wallet is a term for password storage used in KDE Wallet Manager software. Wallets can be created manually by the user or It is offered by dialogue when the user enters in a password on any KDE desktop environment or website. Once created, Wallet can store various passwords and It is controlled by one master password. This way users do not have to remember various passwords, instead, they can just manage them by memorizing one master password for the wallet. The default Wallet is named “kdewallet” and users can create more of their own if needed.

### Managing wallets {#Managing_wallets}

Users can manage wallets on their own KDE Wallet Manager window. Packaging or combining wallets can be done by dragging and dropping. If the user wants to export information to other locations such as [flash drives](https://en.wikipedia.org/wiki/Flash_drive), the window allows for the user to choose whether to export data encrypted or not. Providing the master password, the user can similarly import the data encrypted.

Setting preference of wallets is also possible, user can set certain wallets to be the default wallet. The close wallet setting enables the user to close the wallet after:

- Close when unused for
- Close when the screensaver starts
- Close when the application stops using it

## Encryption of the password {#Encryption_of_the_password}

The data stored by the KDE Wallet manager can be encrypted in two major ways. The GNU Privacy Guard (GnuPG or GPG) algorithm is used if GnuPG Made Easy library is installed on the user’s Linux-based OS. If not, Blowfish symmetric block cipher algorithm is used.[^o14]

*Image: Method.PNG.* The encryption methods of KWallet.

### Blowfish symmetric block cipher algorithm {#Blowfish_symmetric_block_cipher_algorithm}

KDE Wallet manager encrypts the data stored in the wallet using the Blowfish symmetric block cipher algorithm in CBC mode. To protect the user’s information, blowfish encrypted data is authenticated with the SHA-1 hashing algorithm.

KDE Wallet manager’s blowfish encryption provides faster encryption compared to Khufu, RC5, DES, IDEA, and Trip-DES. Blowfish encrypts at a rate of 18 clock cycles per byte in 32-bit microprocessors.

KDE Wallet manager’s Blowfish algorithm can be executed in memory within 5k, and a simple structure is easy to implement and easy to determine the strength of the algorithm. The algorithm is variable in key length, which can be long as 448 bites and it allows basic word addition and bit XOR operations.[^o16]

### GNU Privacy Guard encryption {#GNU_Privacy_Guard_encryption}

Users can create a GNU Privacy Guard (GnuPG or GPG) based wallet to store extra-sensitive passwords. This requires users to install GnuPG Made Easy library. If the library is installed and once the software found GNU Privacy Guard (GnuPG or GPG), users will be asked to choose a key to use for a new wallet.[^o14] Users still can encrypt passwords with the Blowfish symmetric block cipher algorithm, since the GNU Privacy Guard encryption library includes the DSA/Blowfish symmetric block cipher algorithm.[^o18]

## Security {#Security}

Using KDE Wallet manager (KWallet) may ease password management, but it does not provide greater security guarantees to the user's system. Instead of getting the user's other passwords, an attacker may get the master password for the user's wallets through the user's PC.

Since the directory of encrypted files of KDE wallet manager (KWallet) is located in a predictable path, it might be vulnerable to viruses or worms programmed to target the password management system itself.[^o9]

## Known vulnerabilities in past versions {#Known_vulnerabilities_in_past_versions}

### kwallet submodule {#kwallet_submodule}

- "kwallet-pam in KDE KWallet before 5.12.6 allows local users to obtain ownership of arbitrary files via a symlink attack."
- "fishProtocol::establishConnection in fish/fish.cpp in KDE kio-extras through 20.04.0 makes a cacheAuthentication call even if the user had not set the keepPassword option. This may lead to unintended KWallet storage of a password."
- "kwalletd in KWallet before KDE Applications 14.12.0 uses Blowfish with ECB mode instead of CBC mode when encrypting the password store, which makes it easier for attackers to guess passwords via a codebook attack."

### Use of SHA-1 {#Use_of_SHA-1}

- The [SHA-1 hash](wikipedia://en/26672) function that is used in KDE Wallet manager (KWallet) is cryptographically broken. [Google](https://en.wikipedia.org/wiki/Google) and [CWI Amsterdam](wikipedia://en/506063) have proved that two identical SHA-1 digest displays two different [PDF](https://en.wikipedia.org/wiki/PDF) content. Various companies, including [Microsoft](https://en.wikipedia.org/wiki/Microsoft), has discontinued SHA-1 supports; however, KDE Wallet manager (KWallet) uses [SHA-512](wikipedia://en/1638777) in versions higher than 4.13 or with Pluggable authentication module or it uses SHA-1 hash function.
- "SHA-1 is not collision resistant, which makes it easier for context-dependent attackers to conduct spoofing attacks, as demonstrated by attacks on the use of SHA-1 in [TLS](wikipedia://en/187813) 1.2. NOTE: this [CVE](https://en.wikipedia.org/wiki/Common_Vulnerabilities_and_Exposures) exists to provide a common identifier for referencing this SHA-1 issue; the existence of an identifier is not, by itself, a technology recommendation."[^o23]
- "A flaw was found in the way certificate [signatures](wikipedia://en/59644) could be forged using collisions found in the SHA-1 algorithm. An attacker could use this weakness to create forged certificate signatures. This issue affects GnuPG versions before 2.2.18."[^o24]

### GnuPG-related {#GnuPG-related}

- "The mixing functions in the [random number generator](wikipedia://en/2736939) in [Libgcrypt](wikipedia://en/29870579) before 1.5.6, 1.6.x before 1.6.6, and 1.7.x before 1.7.3 and GnuPG before 1.4.21 make it easier for attackers to obtain the values of 160 bits by leveraging knowledge of the previous 4640 bits."[^o26]
- "GnuPG 2.2.21 and 2.2.22 (and Gpg4win 3.1.12) has an [array overflow](https://en.wikipedia.org/wiki/Buffer_overflow), leading to a [crash](https://en.wikipedia.org/wiki/Crash_%28computing%29) or possibly unspecified other impact, when a victim imports an attacker's [OpenPGP](wikipedia://en/23080) key, and this key has [AEAD](wikipedia://en/2244296) preferences. The overflow is caused by a g10/key-check.c error. NOTE: GnuPG 2.3.x is unaffected. GnuPG 2.2.23 is a fixed version."[^o27]
- "GnuPG 1.x before 1.4.16 generates [RSA](wikipedia://en/25385) keys using sequences of introductions with certain patterns that introduce a [side channel](wikipedia://en/667678), which allows physically proximate attackers to extract RSA keys via a [chosen-ciphertext attack](wikipedia://en/103586) and [acoustic cryptanalysis](wikipedia://en/1561321) during decryption. NOTE: applications are not typically expected to protect themselves from acoustic side-channel attacks, since this is arguably the responsibility of the physical device. Accordingly, issues of this type would not normally receive a CVE identifier. However, for this issue, the developer has specified a security policy in which GnuPG should offer side-channel resistance, and developer-specified security-policy violations are within the scope of CVE."[^o28]
- "Integer underflow in the ksba\_oid\_to\_str function in Libksba before 1.3.2, as used in GnuPG, allows remote attackers to cause a [denial of service](https://en.wikipedia.org/wiki/Denial-of-service_attack) (crash) via a crafted OID in a (1) [S/MIME](https://en.wikipedia.org/wiki/S/MIME) message or (2) [ECC](wikipedia://en/9966) based OpenPGP data, which triggers a buffer overflow."[^o29]
- "[Use-after-free vulnerability](https://en.wikipedia.org/wiki/Dangling_pointer) in kbx/keybox-blob.c in GPGSM in GnuPG 2.x through 2.0.16 allows remote attackers to cause a denial of service (crash) and possibly execute arbitrary code via a certificate with a large number of [Subject Alternate Names](https://en.wikipedia.org/wiki/Subject_alternate_name), which is not properly handled in a [realloc](https://en.wikipedia.org/wiki/Realloc) operation when importing the certificate or verifying its signature."[^o30]
- "mainproc.c in GnuPG before 2.2.8 mishandles the original filename during decryption and verification actions, which allows remote attackers to spoof the output that GnuPG sends on file descriptor 2 to other programs that use the "—status-fd 2" option. For example, the OpenPGP data might represent an original filename that contains line feed characters in conjunction with GOODSIG or VALIDSIG status codes."[^o31]
- "The integrity check feature in OpenPGP, when handling a message that was encrypted using [cipher feedback (CFB) mode](https://en.wikipedia.org/wiki/Cipher_feedback_mode), allows remote attackers to recover part of the plaintext via a chosen-ciphertext attack when the first 2 bytes of a message block are known, and an oracle or other mechanism is available to determine whether an integrity check failed."[^o32]
- "[Heap](wikipedia://en/13996)-based buffer overflow in the ask\_outfile\_name function in openfile.c for GnuPG (gpg) 1.4 and 2.0, when running interactively, might allow attackers to execute arbitrary code via messages with "C-escape" expansions, which cause the make\_printable\_string function to return a longer string than expected while constructing a prompt."[^o33]
- "GnuPG 1.4.6 and earlier and GPGME before 1.1.4, when run from the command line, does not visually distinguish signed and unsigned portions of OpenPGP messages with multiple components, which might allow remote attackers to forge the contents of a message without detection."[^o34]
- "mainproc.c in GnuPG before 2.2.8 mishandles the original filename during decryption and verification actions, which allows remote attackers to spoof the output that GnuPG sends on file descriptor 2 to other programs that use the "—status-fd 2" option. For example, the OpenPGP data might represent an original filename that contains line feed characters in conjunction with GOODSIG or VALIDSIG status codes."[^o35]
- "kbx/keybox-search.c in GnuPG before 1.4.19, 2.0.x before 2.0.27, and 2.1.x before 2.1.2 does not properly handle [bitwise](wikipedia://en/264399) left-shifts, which allows remote attackers to cause a denial of service (invalid read operation) via a crafted keyring file, related to sign extensions and "[memcpy](https://en.wikipedia.org/wiki/Memcpy) with overlapping ranges."[^o36]

### In 3rd Party Software {#In_3rd_Party_Software}

- "An issue was discovered in password-store.sh in pass in Simple Password Store 1.7.x before 1.7.2. The signature verification routine parses the output of GnuPG with an incomplete [regular expression](wikipedia://en/25717), which allows remote attackers to spoof file signatures on configuration files and extension scripts. Modifying the configuration file allows the attacker to inject additional encryption keys under their control, thereby disclosing passwords to the attacker. Modifying the extension scripts allows the attacker arbitrary code execution."[^o38]
