# Collision attack

::: {#o1 .subject cue=lead name="Collision attack"}

In [cryptography](wikipedia://en/18934432), a **collision attack** on a [cryptographic hash](https://en.wikipedia.org/wiki/Cryptographic_hash) tries to find two inputs producing the same hash value, i.e. a [hash collision](https://en.wikipedia.org/wiki/Hash_collision). This is in contrast to a [preimage attack](wikipedia://en/969477) where a specific target hash value is specified.

:::

There are roughly two types of collision attacks:

**Classical collision attack**

Find two different messages *m*<sub>1</sub> and *m*<sub>2</sub> such that *hash*(*m*<sub>1</sub>) = *hash*(*m*<sub>2</sub>).

More generally:

**Chosen-prefix collision attack**

Given two different prefixes *p*<sub>1</sub> and *p*<sub>2</sub>, find two suffixes *s*<sub>1</sub> and *s*<sub>2</sub> such that *hash*(*p*<sub>1</sub> ∥ *s*<sub>1</sub>) = *hash*(*p*<sub>2</sub> ∥ *s*<sub>2</sub>), where ∥ denotes the [concatenation](wikipedia://en/64474) operation.

## Classical collision attack {#Classical_collision_attack}

Much like [symmetric-key ciphers](https://en.wikipedia.org/wiki/Symmetric-key_cipher) are vulnerable to [brute force attacks](https://en.wikipedia.org/wiki/Brute_force_attack), every [cryptographic hash function](wikipedia://en/439526) is inherently vulnerable to collisions using a [birthday attack](wikipedia://en/189369). Due to the [birthday problem](wikipedia://en/73242), these attacks are much faster than a brute force would be. A hash of *n* bits can be broken in 2<sup>*n*/2</sup> time steps (evaluations of the hash function).

Mathematically stated, a collision attack finds two different messages $m_1$ and $m_2$, such that $hash(m_1) = hash(m_2)$. In a classical collision attack, the attacker has no control over the content of either message, but they are arbitrarily chosen by the algorithm.

More efficient attacks are possible by employing [cryptanalysis](wikipedia://en/5715) to specific hash functions. When a collision attack is discovered and is found to be faster than a birthday attack, a hash function is often denounced as "broken". The [NIST hash function competition](wikipedia://en/20051952) was largely induced by published collision attacks against two very commonly used hash functions, [MD5](wikipedia://en/18826)[^o3] and [SHA-1](wikipedia://en/26672). The collision attacks against MD5 have improved so much that, as of 2007, it takes just a few seconds on a regular computer.[^o4] Hash collisions created this way are usually constant length and largely unstructured, so cannot directly be applied to attack widespread document formats or protocols.

However, workarounds are possible by abusing dynamic constructs present in many formats. In this way, two documents would be created which are as similar as possible in order to have the same hash value. One document would be shown to an authority to be signed, and then the signature could be copied to the other file. Such a malicious document would contain two different messages in the same document, but conditionally display one or the other through subtle changes to the file:

- Some document formats like [PostScript](https://en.wikipedia.org/wiki/PostScript), or [macros](https://en.wikipedia.org/wiki/Macro_%28computer_science%29) in [Microsoft Word](https://en.wikipedia.org/wiki/Microsoft_Word), have conditional constructs.[^o5][^o6] (if-then-else) that allow testing whether a location in the file has one value or another in order to control what is displayed.
- [TIFF](https://en.wikipedia.org/wiki/TIFF) files can contain cropped images, with a different part of an image being displayed without affecting the hash value.[^o6]
- [PDF](https://en.wikipedia.org/wiki/PDF) files are vulnerable to collision attacks by using color value (such that text of one message is displayed with a white color that blends into the background, and text of the other message is displayed with a dark color) which can then be altered to change the signed document's content.[^o6]

## Chosen-prefix collision attack {#Chosen-prefix_collision_attack}

An extension of the collision attack is the chosen-prefix collision attack, which is specific to [Merkle–Damgård hash functions](wikipedia://en/4076217). In this case, the attacker can choose two arbitrarily different documents, and then append different calculated values that result in the whole documents having an equal hash value. This attack is normally harder, a hash of n bits can be broken in 2<sup>(n/2)+1</sup> time steps, but is much more powerful than a classical collision attack.

Mathematically stated, given two different prefixes *p*<sub>1</sub>, *p*<sub>2</sub>, the attack finds two suffixes *s*<sub>1</sub> and *s*<sub>2</sub> such that *hash*(*p*<sub>1</sub> ∥ *s*<sub>1</sub>) = *hash*(*p*<sub>2</sub> ∥ *s*<sub>2</sub>) (where ∥ is the [concatenation](wikipedia://en/64474) operation).

More efficient attacks are also possible by employing [cryptanalysis](wikipedia://en/5715) to specific hash functions. In 2007, a chosen-prefix collision attack was found against MD5, requiring roughly 2<sup>50</sup> evaluations of the MD5 function. The paper also demonstrates two [X.509](https://en.wikipedia.org/wiki/X.509) certificates for different domain names, with colliding hash values. This means that a [certificate authority](wikipedia://en/296370) could be asked to sign a certificate for one domain, and then that certificate (specially its signature) could be used to create a new rogue certificate to impersonate another domain.[^o9]

A real-world collision attack was published in December 2008 when a group of security researchers published a forged [X.509](https://en.wikipedia.org/wiki/X.509) signing certificate that could be used to impersonate a [certificate authority](wikipedia://en/296370), taking advantage of a prefix collision attack against the MD5 hash function. This meant that an attacker could impersonate any [SSL](wikipedia://en/187813)-secured website as a [man-in-the-middle](https://en.wikipedia.org/wiki/Man-in-the-middle), thereby subverting the certificate validation built in every [web browser](https://en.wikipedia.org/wiki/Web_browser) to protect [electronic commerce](https://en.wikipedia.org/wiki/Electronic_commerce). The rogue certificate may not be revokable by real authorities, and could also have an arbitrary forged expiry time. Even though MD5 was known to be very weak in 2004,[^o3] certificate authorities were still willing to sign MD5-verified certificates in December 2008,[^o10] and at least one Microsoft code-signing certificate was still using MD5 in May 2012.

The [Flame](https://en.wikipedia.org/wiki/Flame_%28malware%29) malware successfully used a new variation of a chosen-prefix collision attack to spoof [code signing](wikipedia://en/3768009) of its components by a Microsoft root certificate that still used the compromised MD5 algorithm.[^o11][^o12]

In 2019, researchers found a chosen-prefix collision attack against [SHA-1](wikipedia://en/26672) with computing complexity between 2<sup>\66.9</sup> and 2<sup>\69.4</sup> and cost less than 100,000 US dollars. [^o13][^o14] In 2020, researchers reduced the complexity of a chosen-prefix collision attack against SHA-1 to 2<sup>\63.4</sup>. [^o15]

:::

## Attack scenarios {#Attack_scenarios}

Many applications of cryptographic hash functions do not rely on [collision resistance](wikipedia://en/2982326), thus collision attacks do not affect their security. For example, [HMACs](wikipedia://en/17112) are not vulnerable.[^o17] For the attack to be useful, the attacker must be in control of the input to the hash function.

### Digital signatures {#Digital_signatures}

Because [digital signature](wikipedia://en/59644) algorithms cannot sign a large amount of data efficiently, most implementations use a hash function to reduce ("compress") the amount of data that needs to be signed down to a constant size. Digital signature schemes often become vulnerable to hash collisions as soon as the underlying hash function is practically broken; techniques like randomized (salted) hashing will buy extra time by requiring the harder [preimage attack](wikipedia://en/969477).[^o19]

The usual attack scenario goes like this:

1. Mallory creates two different documents A and B that have an identical hash value, i.e., a collision. Mallory seeks to deceive Bob into accepting document B, ostensibly from Alice.
1. Mallory **sends document A to Alice**, who agrees to what the document says, signs its hash, and sends the signature to Mallory.
1. Mallory attaches the signature from document A to document B.
1. Mallory then **sends the signature and document B to Bob**, claiming that Alice signed B. Because the digital signature matches document B's hash, Bob's software is unable to detect the substitution.

In 2008, researchers used a chosen-prefix collision attack against [MD5](wikipedia://en/18826) using this scenario, to produce a rogue [certificate authority](wikipedia://en/296370) certificate. They created two versions of a [TLS](wikipedia://en/187813) [public key certificate](wikipedia://en/223796), one of which appeared legitimate and was submitted for signing by the RapidSSL certificate authority. The second version, which had the same MD5 hash, contained flags which signal web browsers to accept it as a legitimate authority for issuing arbitrary other certificates.[^o20]

::: {#o22 .pointer-item cue=pointer name="Hash flooding"}

### Hash flooding {#Hash_flooding}

**Hash flooding** (also known as **HashDoS**[^o23]) is a [denial of service](https://en.wikipedia.org/wiki/Denial_of_service) attack that uses hash collisions to exploit the worst-case (linear probe) runtime of [hash table](wikipedia://en/13833) lookups.[^o24] It was originally described in 2003 as an example of an algorithmic complexity attack.[^o25] To execute such an attack, the attacker sends the server multiple pieces of data that hash to the same value and then tries to get the server to perform slow lookups. As the main focus of hash functions used in hash tables was speed instead of security, most major programming languages were affected,[^o25] with new vulnerabilities of this class still showing up a decade after the original presentation.[^o24]

To prevent hash flooding without making the hash function overly complex, newer [keyed hash functions](https://en.wikipedia.org/wiki/Keyed_hash_function) are introduced, with the security objective that collisions are hard to find as long as the key is unknown. They may be slower than previous hashes, but are still much easier to compute than cryptographic hashes. As of 2021, Jean-Philippe Aumasson and [Daniel J. Bernstein](wikipedia://en/198983)'s [SipHash](wikipedia://en/37927149) (2012) is the most widely used hash function in this class.[^o26] (Non-keyed "simple" hashes remain safe to use as long as the application's hash table is not controllable from the outside.)

It is possible to perform an analogous attack to fill up [Bloom filters](https://en.wikipedia.org/wiki/Bloom_filter) using a (partial) preimage attack.[^o27]

:::
