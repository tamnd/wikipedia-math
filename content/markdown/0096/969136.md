# Temporal Key Integrity Protocol

::: {#o2 .subject cue=lead name="Temporal Key Integrity Protocol"}

**Temporal Key Integrity Protocol** (**TKIP** ) is a [security protocol](https://en.wikipedia.org/wiki/Security_protocol) used in the [IEEE 802.11](https://en.wikipedia.org/wiki/IEEE_802.11) wireless networking standard. TKIP was designed by the [IEEE 802.11i](https://en.wikipedia.org/wiki/IEEE_802.11i) task group and the [Wi-Fi Alliance](https://en.wikipedia.org/wiki/Wi-Fi_Alliance) as an interim solution to replace [Wired Equivalent Privacy](wikipedia://en/422014) (WEP) without requiring the replacement of legacy hardware. This was necessary because the breaking of WEP had left Wi-Fi networks without viable [link-layer](https://en.wikipedia.org/wiki/Data_link_layer#Logical_link_control_sublayer) security, and a solution was required for already deployed hardware. However, TKIP itself is no longer considered secure, and was deprecated in the 2012 revision of the 802.11 standard.[^o7]

:::

## Background {#Background}

On October 31, 2002, the Wi-Fi Alliance endorsed TKIP under the name [Wi-Fi Protected Access (WPA)](wikipedia://en/422017).[^o4] The IEEE endorsed the final version of TKIP, along with more robust solutions such as [802.1X](https://en.wikipedia.org/wiki/802.1X) and the [AES](wikipedia://en/1260) based [CCMP](https://en.wikipedia.org/wiki/CCMP_%28cryptography%29), when they published IEEE 802.11i-2004 on 23 July 2004.[^o5] The Wi-Fi Alliance soon afterwards adopted the full specification under the marketing name [WPA2](https://en.wikipedia.org/wiki/WPA2).[^o6]

TKIP was resolved to be deprecated by the IEEE in January 2009.[^o7]

## Technical details {#Technical_details}

TKIP and the related WPA standard implement three new security features to address security problems encountered in WEP protected networks. First, TKIP implements a key mixing function that combines the secret root key with the [initialization vector](wikipedia://en/105971) before passing it to the [RC4 cipher](wikipedia://en/25831) initialization. WEP, in comparison, merely concatenated the initialization vector to the root key, and passed this value to the RC4 routine. This permitted the vast majority of the RC4 based WEP [related key attacks](https://en.wikipedia.org/wiki/Related_key_attack).[^o9] Second, WPA implements a sequence counter to protect against replay attacks. Packets received out of order will be rejected by the access point. Finally, TKIP implements a 64-bit [Message Integrity Check (MIC)](https://en.wikipedia.org/wiki/Message_Integrity_Code#Message_integrity_codes) and re-initializes the sequence number each time when a new key (Temporal Key) is used.[^o10]

To be able to run on legacy WEP hardware with minor upgrades, TKIP uses [RC4](wikipedia://en/25831) as its cipher. TKIP also provides a [rekeying](wikipedia://en/55500399) mechanism. TKIP ensures that every data [packet](https://en.wikipedia.org/wiki/Packet_%28information_technology%29) is sent with a unique [encryption key](https://en.wikipedia.org/wiki/Encryption_key) (Interim Key/Temporal Key + Packet Sequence Counter).

Key mixing increases the complexity of decoding the keys by giving an attacker substantially less data that has been encrypted using any one key. WPA2 also implements a new message integrity code, MIC. The message integrity check prevents forged packets from being accepted. Under WEP it was possible to alter a packet whose content was known even if it had not been decrypted.

## Security {#Security}

TKIP uses the same underlying mechanism as WEP, and consequently is vulnerable to a number of similar attacks. The message integrity check, per-packet key [hashing](https://en.wikipedia.org/wiki/Hash_function), broadcast key rotation, and a sequence counter discourage many attacks. The key mixing function also eliminates the WEP key recovery attacks.

Notwithstanding these changes, the weakness of some of these additions have allowed for new, although narrower, attacks.

### Packet spoofing and decryption {#Packet_spoofing_and_decryption}

TKIP is vulnerable to a [MIC key](https://en.wikipedia.org/wiki/Message_Integrity_Code#Message_integrity_codes) recovery attack that, if successfully executed, permits an attacker to transmit and decrypt arbitrary packets on the network being attacked.[^o13] The current publicly available TKIP-specific attacks do not reveal the Pairwise Master Key or the Pairwise Temporal Keys. On November 8, 2008, Martin Beck and Erik Tews released a paper detailing how to recover the MIC key and transmit a few packets.[^o14] This attack was improved by Mathy Vanhoef and Frank Piessens in 2013, where they increase the amount of packets an attacker can transmit, and show how an attacker can also decrypt arbitrary packets.[^o13]

The basis of the attack is an extension of the [WEP](wikipedia://en/422014) [chop-chop attack](https://en.wikipedia.org/wiki/Chop-chop_attack). Because WEP uses a cryptographically insecure checksum mechanism ([CRC-32](https://en.wikipedia.org/wiki/CRC-32)), an attacker can guess individual bytes of a packet, and the [wireless access point](https://en.wikipedia.org/wiki/Wireless_access_point) will confirm or deny whether or not the guess is correct. If the guess is correct, the attacker will be able to detect the guess is correct and continue to guess other bytes of the packet. However, unlike the chop-chop attack against a WEP network, the attacker must wait for at least 60 seconds after an incorrect guess (a successful circumvention of the CRC-32 mechanism) before continuing the attack. This is because although TKIP continues to use the CRC-32 checksum mechanism, it implements an additional [MIC code](https://en.wikipedia.org/wiki/MIC_code) named Michael. If two incorrect Michael MIC codes are received within 60 seconds, the access point will implement countermeasures, meaning it will rekey the TKIP [session key](wikipedia://en/63941), thus changing future keystreams. Accordingly, attacks on TKIP will wait an appropriate amount of time to avoid these countermeasures. Because [ARP](https://en.wikipedia.org/wiki/Address_resolution_protocol) packets are easily identified by their size, and the vast majority of the contents of this packet would be known to an attacker, the number of bytes an attacker must guess using the above method is rather small (approximately 14 bytes). Beck and Tews estimate recovery of 12 bytes is possible in about 12 minutes on a typical network, which would allow an attacker to transmit 3–7 packets of at most 28 bytes.[^o14] Vanhoef and Piessens improved this technique by relying on [fragmentation](https://en.wikipedia.org/wiki/Fragmented_distribution_attack), allowing an attacker to transmit arbitrarily many packets, each at most 112 bytes in size.[^o13] The Vanhoef–Piessens attacks also can be used to decrypt arbitrary packets of the attack's choice.

An attacker already has access to the entire ciphertext packet. Upon retrieving the entire plaintext of the same packet, the attacker has access to the keystream of the packet, as well as the MIC code of the session. Using this information the attacker can construct a new packet and transmit it on the network. To circumvent the WPA implemented replay protection, the attacks use [QoS](https://en.wikipedia.org/wiki/Quality_of_service) channels to transmit these newly constructed packets. An attacker able to transmit these packets may be able to implement any number of attacks, including [ARP poisoning](https://en.wikipedia.org/wiki/ARP_poisoning) attacks, denial of service, and other similar attacks, with no need of being associated with the network.

### Royal Holloway attack {#Royal_Holloway_attack}

A group of security researchers at the Information Security Group at [Royal Holloway, University of London](https://en.wikipedia.org/wiki/Royal_Holloway,_University_of_London) reported a theoretical attack on TKIP which exploits the underlying [RC4](wikipedia://en/25831) encryption mechanism. TKIP uses a similar key structure to WEP with the low 16-bit value of a sequence counter (used to prevent replay attacks) being expanded into the 24-bit "IV", and this sequence counter always increments on every new packet. An attacker can use this key structure to improve existing attacks on RC4. In particular, if the same data is encrypted multiple times, an attacker can learn this information from only 2<sup>24</sup> connections.[^o16][^o17][^o18] While they claim that this attack is on the verge of practicality, only simulations were performed, and the attack has not been demonstrated in practice.

### NOMORE attack {#NOMORE_attack}

In 2015, security researchers from KU Leuven presented new attacks against RC4 in both TLS and WPA-TKIP. Dubbed the Numerous Occurrence MOnitoring & Recovery Exploit (NOMORE) attack, it is the first attack of its kind that was demonstrated in practice. The attack against WPA-TKIP can be completed within an hour, and allows an attacker to decrypt and inject arbitrary packets.[^o20]

## Legacy {#Legacy}

[ZDNet](https://en.wikipedia.org/wiki/ZDNET) reported on June 18, 2010, that WEP & TKIP would soon be disallowed on Wi-Fi devices by the Wi-Fi alliance.[^o22] However, a survey in 2013 showed that it was still in widespread use.[^o13]

The IEEE 802.11n standard prohibits the data rate exceed 54 Mbps if TKIP is used as the Wi-Fi cipher.[^o23]
