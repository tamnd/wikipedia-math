# Wilkinson's Grammar of Graphics

::: {#o1 .subject cue=lead name="Wilkinson's Grammar of Graphics"}

The **Grammar of Graphics** (GoG) is a [grammar](wikipedia://en/12569)-based system for representing graphics to provide [grammatical constraints](https://en.wikipedia.org/wiki/Constraint_grammar) on the [composition](https://en.wikipedia.org/wiki/Semiotics) of [data and information visualizations](wikipedia://en/3461736). A graphical grammar differs from a [graphics pipeline](https://en.wikipedia.org/wiki/Graphics_pipeline) as it focuses on semantic components such as scales and guides, statistical functions, coordinate systems, marks and aesthetic attributes.[^o7][^o32] For example, a [bar chart](wikipedia://en/393311) can be converted into a [pie chart](wikipedia://en/728487) by specifying a [polar coordinate system](wikipedia://en/25120) without any other change in graphical specification.[^o7][^o2]

:::

The grammar of graphics concept was launched by [Leland Wilkinson](https://en.wikipedia.org/wiki/Leland_Wilkinson) in 2001 (Wilkinson et al., 2001; Wilkinson, 2005) and graphical grammars have since been written in a variety of languages with various [parameterisations](https://en.wikipedia.org/wiki/Parse_tree) and extensions.[^o7] The major implementations of graphical grammars are nViZn created by a team at [SPSS](wikipedia://en/179088)/[IBM](https://en.wikipedia.org/wiki/IBM), followed by Polaris focusing on multidimensional [relational databases](https://en.wikipedia.org/wiki/Relational_database) which is commercialised as [Tableau](wikipedia://en/19547325), a revised Layered Grammar of Graphics by [Hadley Wickham](wikipedia://en/41916270) in [ggplot2](wikipedia://en/32380922) for the [R package](wikipedia://en/65740838), and [Vega-Lite](https://en.wikipedia.org/wiki/Vega_and_Vega-Lite_visualisation_grammars) which is a visualisation grammar with added interactivity.[^o3][^o4] The grammar of graphics continues to evolve with alternate parameterisations, extensions, or new specifications.

## Wilkinson's Grammar of Graphics {#Wilkinson's_Grammar_of_Graphics}

### Theory {#Theory}

Wilkinson conceived the seven elements of a graphics to be[^o2][^o7]

- **Variables**: mapping of objects to values represented in a graphic
- **Algebra**: operations to combine variables and specify dimensions of graphs
- **Geometry**: creation of geometric graphs from variables
- **Aesthetics**: sensory attributes
- **Statistics**: functions to change the appearance and representation of graphs
- **Scales**: represent variables on measured dimensions
- **Coordinates**: mapping to coordinate systems

With these, Wilkinson hypothesised that[^o2][^o7][^o8]

1. These seven constructs are orthogonal and virtually all known statistical charts can be generated relatively parsimoniously
1. This computational system is not a taxonomy of charts and rather it describes the meaning of what we do when we construct statistical graphics.

::: {#o10 .definition kind=definition/construction cue=heading name="Implementations"}

### Implementations {#Implementations}

Wilkinson wrote [SYSTAT](wikipedia://en/2197220), a statistical software package, in the early 1980s. This program was noted for its comprehensive graphics,[^o11] including the first software implementation of the [heatmap](https://en.wikipedia.org/wiki/Heatmap) display now widely used among biologists. After his company grew to 50 employees, he sold it to [SPSS](wikipedia://en/179088) in 1995. At SPSS, he assembled a team of graphics programmers who developed the nViZn platform [^o12] that produces the visualizations in [SPSS](wikipedia://en/179088), [Clementine](wikipedia://en/20588127), and other analytics products.

While at Stanford, Tableau founders Hanrahan and Stolte, as well as Diane Tang, created the predecessor to Tableau, named Polaris.[^o13] Polaris was a data visualization software tool, built with the support of a [United States Department of Energy](https://en.wikipedia.org/wiki/United_States_Department_of_Energy) defense program, the Accelerated Strategic Computing Initiative (ASCI).[^o14][^o15] The main differences between Wilkinson's system and Polaris are the use of [SQL](wikipedia://en/29004) relational algebra for database services and using shelves instead of cross and nest operators.[^o13]

:::

## Wickham's Layered Grammar of Graphics {#Wickham's_Layered_Grammar_of_Graphics}

### Theory {#Theory}

[Hadley Wickham](wikipedia://en/41916270) conceived an alternate parameterisation of the syntax Wilkinson had derived, creating a layered grammar of graphics which he implemented as [ggplot2](wikipedia://en/32380922) for [R (programming language)](wikipedia://en/376707) users.[^o18][^o19] This added a hierarchy of defaults based around the idea of building up a graphic from multiple layers.[^o20][^o21] Wickham conceived these elements to be:

- **Defaults**: consists of data and mapping
  - **Data**: dataset
  - **Mapping**: aesthetic mappings
- **Layer**: consists of data, mapping, geom, stat, and position
  - **Data**: dataset, or inherit from defaults
  - **Mapping**: aesthetic mappings, or inherit from defaults
  - **Geom**: geometric object
  - **Stat**: statistical transformation
  - **Position**: position adjustment
- **Scale**: mapping of data to aesthetic attributes
- **Coord**: mapping of data to the plane of the plot
- **Facet**: split up the data

### Reception {#Reception}

Wilkinson is generally positive on Wickham's parameterisation and implementation of ggplot2,[^o3] praising its elegance and expressivity whilst claiming that his original Grammar of Graphics is capable of representing a wider range of statistical graphics.[^o8][^o23]

::: {#o25 .definition kind=definition/construction cue=heading name="Implementations"}

### Implementations {#Implementations}

[ggplot2](wikipedia://en/32380922) is the first implementation of a layered grammar of graphics in R and implementations in other [programming languages](wikipedia://en/23015) have ensued. These include direct [ports](https://en.wikipedia.org/wiki/Porting) plotnine for [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), gramm for [MATLAB](wikipedia://en/20412), Lets-Plot for [Kotlin](https://en.wikipedia.org/wiki/Kotlin_%28programming_language%29) and gadfly for [Julia](https://en.wikipedia.org/wiki/Julia_%28programming_language%29). Projects inspired by elements of Wickham's grammar include Vega-Lite which specifies plots in [JSON](https://en.wikipedia.org/wiki/JSON) and uses a [JavaScript](https://en.wikipedia.org/wiki/JavaScript) engine. Implementations for Python include Vega-Altair (built on top of Vega-Lite).

:::

## Vega-Lite: A Grammar of Interactive Graphics {#Vega-Lite:_A_Grammar_of_Interactive_Graphics}

### Theory {#Theory}

[Vega-Lite](https://en.wikipedia.org/wiki/Vega_and_Vega-Lite_visualisation_grammars) combines ideas from Wilkinson's Grammar of Graphics and Wickham's Layered Grammar of Graphics with a composition algebra for layered and multi-view displays with a grammar of interaction. The Vega-Lite specification is instantiated in [JSON](https://en.wikipedia.org/wiki/JSON) and rendered by the lower-level Vega.[^o28] The graphical grammar implemented by Vega-Lite is composed of the following:

- **Unit**: consists of data, transforms, mark-type and encoding
  - **Data**: relational table consisting of records (rows) and named attributes (columns)
  - **Transforms**: data transformations
  - **Mark-type:** geometric object for visual encoding
  - **Encodings:** mapping of data attributes to visual marks properties where each encoding consists of:
    - **Channel:** e.g. colour, shape, size, or text
    - **Field:** data attribute
    - **Data-type:** e.g. nominal, ordinal, quantitative, or temporal
    - **Value:** use a literal instead of a data-type
    - **Functions:** e.g. binning, aggregation, and sorting
    - **Scale:** maps from data domain to visual range
    - **Guide:** axis or legend for visualising scale
- **Composite Views:** compose views from multiple unit specifications with operators:
  - **Layer**: charts plotted on top of each other
  - **Hconcat/Vconcat**: place views side-by-side
  - **Facet**: subset data to produce a trellis plot
  - **Repeat**: multiple plots similar to facet but with full data replication in each cell
- **Interaction**: selections identify the set of points a user is interested in manipulating, with components:
  - **Selection**: get the minimal number of backing points
    - **Name**: reference
    - **Type**: how many backing values are stored
    - **Predicate**: determine the set of selected points e.g. single, list, interval
    - **Domain|Range**: store data domain or visual range
    - **Event**: e.g. mouseover, mousedown, mouseup,
    - **Init**: initialise with specific backing points
    - **Transforms**: e.g. project, toggle, translate, zoom, and nearest
    - **Resolve**: resolve selections to union or intersect

::: {#o30 .definition kind=definition/construction cue=heading name="Implementations"}

#### Implementations {#Implementations}

Whilst Vega-Lite is the sole implementation of this graphics grammar specification with [compilation](https://en.wikipedia.org/wiki/Compiler) to Vega, other implementations do create JSON files which can be interpreted by Vega-Lite.

:::

## Related projects {#Related_projects}

- [ggplot2](wikipedia://en/32380922)[^o32] is an R package for plotting
- [Tableau Software](wikipedia://en/19547325)[^o13] (originally known as Polaris) is a commercial software built using the Grammar of Graphics
- nViZn[^o33] built by Wilkinson.
- [SYSTAT (statistics package)](wikipedia://en/2197220)[^o34] built by Wilkinson
- ggpy, ggplot for Python,[^o35] but has not been updated since 20 November 2016
- plotnine[^o36] started as an effort to improve the scalability of ggplot for [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) and is largely compatible with ggplot2 syntax.
- Plotly - Interactive, online ggplot2 graphs[^o37]
- gramm, a plotting class for [MATLAB](wikipedia://en/20412) inspired by ggplot2[^o38]
- gadfly, a system for plotting and visualization written in [Julia](https://en.wikipedia.org/wiki/Julia_%28programming_language%29), based largely on ggplot2[^o39]
- Chart::GGPlot - ggplot2 port in [Perl](https://en.wikipedia.org/wiki/Perl),[^o40] but has not been updated since 16 March 2023
- The Lets-Plot for Python library includes a native backend and a Python [API](https://en.wikipedia.org/wiki/API), which was mostly based on the ggplot2 package.[^o41]
- Lets-Plot Kotlin API is an open-source plotting library for statistical data implemented using the [Kotlin programming language](https://en.wikipedia.org/wiki/Kotlin_%28programming_language%29), and is built on the principles of layered graphics first described in the Leland Wilkinson's work *The Grammar of Graphics*.[^o42]
- ggplotnim, plotting library using the [Nim](https://en.wikipedia.org/wiki/Nim_%28programming_language%29) programming language inspired by ggplot2.[^o43]
- [Vega and Vega-Lite](https://en.wikipedia.org/wiki/Vega_and_Vega-Lite_visualisation_grammars) are plotting libraries that use JSON to specify plots.
- [Vega-Altair](https://altair-viz.github.io/), a Python library built on top of Vega-Lite
- chart-parts - React-friendly Grammar of Graphics,[^o44][^o45] but has not been updated since 10 Dec 2021
- g2[^o46] - a JavaScript library
