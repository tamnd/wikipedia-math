# Riffle (anonymity network)

::: {#o2 .subject cue=lead name="Riffle"}

**Riffle** is an [anonymity network](https://en.wikipedia.org/wiki/Anonymity_network) developed by researchers at [MIT](https://en.wikipedia.org/wiki/Massachusetts_Institute_of_Technology) and [EPFL](https://en.wikipedia.org/wiki/École_Polytechnique_Fédérale_de_Lausanne) as a response to the problems of the [Tor network](https://en.wikipedia.org/wiki/Tor_%28anonymity_network%29).

:::

## Overview {#Overview}

Riffle employs a [privacy](https://en.wikipedia.org/wiki/Privacy)-enhancing [protocol](https://en.wikipedia.org/wiki/Communication_protocol) that provides strong [anonymity](https://en.wikipedia.org/wiki/Anonymity) for secure and anonymous communication within groups. The protocol is designed using the anytrust model, which ensures that even if colluding [servers](https://en.wikipedia.org/wiki/Server_%28computing%29) attempt to compromise the privacy of the group, they cannot do so if at least one server in the group is honest.[^o4]

Like Tor, it utilizes [onion routing](https://en.wikipedia.org/wiki/Onion_routing).[^o5] According to MIT's Larry Hardesty, researchers at MIT and the [Qatar Computing Research Institute](https://en.wikipedia.org/wiki/Qatar_Computing_Research_Institute) demonstrated a vulnerability in Tor's design.[^o6]

## Technical design {#Technical_design}

To achieve its goals, Riffle implements two distinct protocols: the Hybrid Shuffle protocol for sending and [Private Information Retrieval](https://en.wikipedia.org/wiki/Private_Information_Retrieval) (PIR) for receiving.[^o8]

For sending information, Riffle uses a hybrid shuffle, consisted of a verifiable shuffle and a [symmetric-key algorithm](wikipedia://en/53042). The Hybrid Shuffle protocol consists of a setup phase and a transmission phase. During the setup phase, a slow verifiable shuffle based on [public key cryptography](wikipedia://en/24222) is used, while an efficient shuffle based on [symmetric key cryptography](https://en.wikipedia.org/wiki/Symmetric-key_cryptography) is used during the transmission phase.[^o8] Messages sent over Riffle are not forwarded if they have been altered by a compromised server. The server has to attach [proof](wikipedia://en/450541) in order to forward the message. If a server encounters [unauthenticated](https://en.wikipedia.org/wiki/Authentication_protocol) messages or different permutations, it exposes the [signed](wikipedia://en/59644) message of the previous server and runs the accusation protocol to ensure [verifiability](wikipedia://en/47967) without requiring computationally intensive protocols during transmission phases.[^o8]

For receiving information it utilizes multi-server [Private Information Retrieval](https://en.wikipedia.org/wiki/Private_information_retrieval). All servers in the system share a [replicated database](https://en.wikipedia.org/wiki/Replicated_database), and when a [client](https://en.wikipedia.org/wiki/Client–server_model) requests an entry from the [database](https://en.wikipedia.org/wiki/Database), they can cooperatively access it without knowing which entry they are accessing.[^o8]

## Use cases {#Use_cases}

The main intended [use-case](https://en.wikipedia.org/wiki/Use_case) is anonymous [file sharing](https://en.wikipedia.org/wiki/File_sharing). According to the lead project researcher, Riffle is intended to be complementary to Tor, not a replacement.[^o10]
