# Feature engineering

::: {#o1 .subject cue=lead name="Feature engineering"}

Problems In [supervised machine learning](https://en.wikipedia.org/wiki/Supervised_machine_learning) and [statistical modeling](https://en.wikipedia.org/wiki/Statistical_modeling), **feature engineering** is a preprocessing step[^o2] which transforms raw data into a more effective set of inputs. Each input comprises several attributes, known as [features](https://en.wikipedia.org/wiki/Feature_%28machine_learning%29). By providing models with relevant information, feature engineering significantly enhances their predictive accuracy and decision-making capability.[^o3][^o4][^o5]

:::

Beyond machine learning, the principles of feature engineering are applied in various scientific fields, including physics. For example, physicists construct [dimensionless numbers](https://en.wikipedia.org/wiki/Dimensionless_quantity) such as the [Reynolds number](wikipedia://en/23868856) in [fluid dynamics](wikipedia://en/11034), the [Nusselt number](wikipedia://en/58285) in [heat transfer](wikipedia://en/184726), and the [Archimedes number](https://en.wikipedia.org/wiki/Archimedes_number) in [sedimentation](https://en.wikipedia.org/wiki/Sedimentation). They also develop first approximations of solutions, such as analytical solutions for the [strength of materials](https://en.wikipedia.org/wiki/Strength_of_materials) in mechanics.[^o6]

## Clustering {#Clustering}

One of the applications of feature engineering has been clustering of feature-objects or sample-objects in a dataset. Especially, feature engineering based on [matrix decomposition](wikipedia://en/253873) has been extensively used for data clustering under non-negativity constraints on the feature coefficients. These include *Non-Negative Matrix Factorization* (NMF),[^o8] *Non-Negative Matrix-Tri Factorization* (NMTF),[^o9] *Non-Negative Tensor Decomposition/Factorization* (NTF/NTD),[^o10] etc. The non-negativity constraints on coefficients of the feature vectors mined by the above-stated algorithms yields a part-based representation, and different factor matrices exhibit natural clustering properties. Several extensions of the above-stated feature engineering methods have been reported in literature, including *orthogonality-constrained factorization* for hard clustering, and *manifold learning* to overcome inherent issues with these algorithms.

Other classes of feature engineering algorithms include leveraging a common hidden structure across multiple inter-related datasets to obtain a consensus (common) clustering scheme. An example is *Multi-view Classification based on Consensus Matrix Decomposition* (MCMD),[^o3] which mines a common clustering scheme across multiple datasets. MCMD is designed to output two types of class labels (scale-variant and scale-invariant clustering), and:

- is [computationally robust](https://en.wikipedia.org/wiki/Robustness_%28computer_science%29) to missing information,
- can obtain shape- and scale-based outliers,
- and can handle high-dimensional data effectively.

Coupled matrix and tensor decompositions are popular in multi-view feature engineering.[^o11]

## Predictive modelling {#Predictive_modelling}

Feature engineering in [machine learning](wikipedia://en/233488) and [statistical modeling](https://en.wikipedia.org/wiki/Statistical_modeling) involves selecting, creating, transforming, and extracting data features. Key components include feature creation from existing data, transforming and imputing missing or invalid features, reducing data dimensionality through methods like [Principal Components Analysis](wikipedia://en/76340) (PCA), [Independent Component Analysis](wikipedia://en/598031) (ICA), and [Linear Discriminant Analysis](wikipedia://en/1470657) (LDA), and selecting the most relevant features for model training based on importance scores and [correlation matrices](https://en.wikipedia.org/wiki/Correlation_matrices).[^o13]

Features vary in significance.[^o14] Even relatively insignificant features may contribute to a model. [Feature selection](wikipedia://en/1179950) can reduce the number of features to prevent a model from becoming too specific to the training data set (overfitting).[^o15]

Feature explosion occurs when the number of identified features is too large for effective model estimation or optimization. Common causes include:

- Feature templates - implementing feature templates instead of coding new features
- Feature combinations - combinations that cannot be represented by a linear system

Feature explosion can be limited via techniques such as [regularization](wikipedia://en/2009061), [kernel methods](wikipedia://en/3424576), and [feature selection](wikipedia://en/1179950).[^o16]

## Feature template {#Feature_template}

**Feature templates** (abstract specifications of features) are used to automatically populate the set of features from every instance in the training and test set. Feature templates allow us to automatically generate large numbers of specific features from a training set.

## Automation {#Automation}

Automation of feature engineering is a research topic that dates back to the 1990s.[^o19] Machine learning software that incorporates [automated feature engineering](https://en.wikipedia.org/wiki/Automated_feature_engineering) has been commercially available since 2016.[^o20] Related academic literature can be roughly separated into two types:

- Multi-relational Decision Tree Learning (MRDTL) uses a supervised algorithm that is similar to a [decision tree](wikipedia://en/232602).
- Deep Feature Synthesis uses simpler methods.

### Multi-relational Decision Tree Learning (MRDTL) {#Multi-relational_Decision_Tree_Learning_(MRDTL)}

Multi-relational Decision Tree Learning (MRDTL) extends traditional decision tree methods to [relational databases](https://en.wikipedia.org/wiki/Relational_database), handling complex data relationships across tables. It innovatively uses selection graphs as [decision nodes](https://en.wikipedia.org/wiki/Decision_node), refined systematically until a specific termination criterion is reached.[^o19]

Most MRDTL studies base implementations on relational databases, which results in many redundant operations. These redundancies can be reduced by using techniques such as tuple id propagation.[^o22][^o23]

### Open-source implementations {#Open-source_implementations}

There are a number of open-source libraries and tools that automate feature engineering on relational data and time series:

- **featuretools** is a [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) library for transforming time series and relational data into feature matrices for machine learning.[^o25][^o26][^o27]
- **MCMD:** An open-source feature engineering algorithm for joint clustering of multiple datasets.[^o28][^o3]
- **OneBM** or One-Button Machine combines feature transformations and feature selection on relational data with feature selection techniques.[^o29]
- **getML community** is an open source tool for automated feature engineering on time series and relational data.[^o30][^o31] It is implemented in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29)/[C++](https://en.wikipedia.org/wiki/C++) with a Python interface.[^o31] It has been shown to be at least 60 times faster than tsflex, tsfresh, tsfel, featuretools or kats.[^o31]
- **tsfresh** is a Python library for feature extraction on time series data.[^o32] It evaluates the quality of the features using hypothesis testing.[^o33]
- **tsflex** is an open source Python library for extracting features from time series data.[^o34] Despite being 100% written in Python, it has been shown to be faster and more memory efficient than tsfresh, seglearn or tsfel.[^o35]
- **seglearn** is an extension for multivariate, sequential time series data to the [scikit-learn](https://en.wikipedia.org/wiki/Scikit-learn) Python library.[^o36]
- **tsfel** is a Python package for feature extraction on time series data.[^o37]
- **kats** is a Python toolkit for analyzing time series data.[^o38]

### Deep feature synthesis {#Deep_feature_synthesis}

The deep feature synthesis (DFS) algorithm beat 615 of 906 human teams in a competition.[^o40][^o41]

## Feature stores {#Feature_stores}

The [feature store](https://en.wikipedia.org/wiki/Feature_store) is where the features are stored and organized for the explicit purpose of being used to either train models (by data scientists) or make predictions (by applications that have a trained model). It is a central location where you can either create or update groups of features created from multiple different data sources, or create and update new datasets from those feature groups for training models or for use in applications that do not want to compute the features but just retrieve them when it needs them to make predictions.[^o43]

A feature store includes the ability to store code used to generate features, apply the code to raw data, and serve those features to models upon request. Useful capabilities include feature versioning and policies governing the circumstances under which features can be used.[^o44]

Feature stores can be standalone software tools or built into machine learning platforms.

## Alternatives {#Alternatives}

Feature engineering can be a time-consuming and error-prone process, as it requires domain expertise and often involves trial and error.[^o46][^o47] [Deep learning algorithms](https://en.wikipedia.org/wiki/Deep_learning) may be used to process a large raw dataset without having to resort to feature engineering.[^o48] However, deep learning algorithms still require careful preprocessing and cleaning of the input data.[^o49] In addition, choosing the right architecture, hyperparameters, and optimization algorithm for a deep neural network can be a challenging and iterative process.[^o50]
