# 4D vector

::: {#o1 .subject cue=lead name="4D vector"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science), a **4D vector** is a 4-component [vector](https://en.wikipedia.org/wiki/Vector_%28mathematics%29) [data type](https://en.wikipedia.org/wiki/Data_type). Uses include [homogeneous coordinates](wikipedia://en/243316) for [3-dimensional space](https://en.wikipedia.org/wiki/3-dimensional_space) in [computer graphics](https://en.wikipedia.org/wiki/Computer_graphics), and *red green blue alpha* ([RGBA](https://en.wikipedia.org/wiki/RGBA)) values for [bitmap](https://en.wikipedia.org/wiki/Bitmap) images with a color and [alpha channel](https://en.wikipedia.org/wiki/Alpha_channel) (as such they are widely used in computer graphics). They may also represent [quaternions](wikipedia://en/51440) (useful for rotations) although the algebra they define is different.

:::

## Computer hardware support {#Computer_hardware_support}

Some [microprocessors](https://en.wikipedia.org/wiki/Microprocessor) have hardware support for 4D vectors with instructions dealing with 4 [lane](https://en.wikipedia.org/wiki/SIMD_lane) *single instruction, multiple data* ([SIMD](https://en.wikipedia.org/wiki/SIMD)) instructions, usually with a [128-bit](https://en.wikipedia.org/wiki/128-bit) data path and [32-bit floating point](https://en.wikipedia.org/wiki/32-bit_floating_point) fields.[^o3]

Specific instructions (e.g., 4 element [dot product](wikipedia://en/157093)) may facilitate the use of one 128-bit register to represent a 4D vector. For example, in chronological order: [Hitachi SH4](https://en.wikipedia.org/wiki/Hitachi_SH4), [PowerPC](https://en.wikipedia.org/wiki/PowerPC) VMX128 extension,[^o4] and Intel [x86](https://en.wikipedia.org/wiki/X86) SSE4.[^o5]

Some 4-element vector engines (e.g., the [PS2 vector units](https://en.wikipedia.org/wiki/PS2_vector_unit)) went further with the ability to broadcast components as multiply sources, and [cross product](wikipedia://en/157092) support.[^o6][^o7] Earlier generations of [graphics processing unit](https://en.wikipedia.org/wiki/Graphics_processing_unit) (GPU) shader pipelines used *[very long instruction word](https://en.wikipedia.org/wiki/Very_long_instruction_word)* (VLIW) [instruction sets](https://en.wikipedia.org/wiki/Instruction_set) tailored for similar operations.

## Software support {#Software_support}

SIMD use for 4D vectors can be conveniently wrapped in a *[vector maths library](https://en.wikipedia.org/wiki/Vector_maths_library)* (commonly implemented in [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) or [C++](https://en.wikipedia.org/wiki/C++))[^o9][^o10][^o11] commonly used in [video game development](https://en.wikipedia.org/wiki/Video_game_development), along with [4×4 matrix](https://en.wikipedia.org/wiki/4×4_matrix) support. These are distinct from more general [linear algebra libraries](https://en.wikipedia.org/wiki/Linear_algebra_libraries) in other domains focussing on [matrices](wikipedia://en/20556859) of arbitrary size. Such libraries sometimes support 3D vectors padded to 4D or loading 3D data into 4D registers, with arithmetic mapped efficiently to SIMD operations by per platform [intrinsic function](https://en.wikipedia.org/wiki/Intrinsic_function) implementations. There is choice between [AOS and SOA](https://en.wikipedia.org/wiki/AOS_and_SOA) approaches given the availability of 4 element registers, versus SIMD instructions that are usually tailored toward homogenous data.

[Shading languages](https://en.wikipedia.org/wiki/Shading_language) for [graphics processing unit](https://en.wikipedia.org/wiki/Graphics_processing_unit) (GPU) programming usually have a 4D datatypes (along with 2D, 3D) with x-y-z-w accessors including *[permutes](wikipedia://en/44027)* or *swizzle* access, e.g., allowing easy swapping of RGBA or ARGB formats, accessing two 2D vectors packed into one 4D vector, etc.[^o12] Modern GPUs have since moved to scalar [single instruction, multiple threads](https://en.wikipedia.org/wiki/Single_instruction,_multiple_threads) (SIMT) pipelines (for more efficiency in *[general-purpose computing on graphics processing units](https://en.wikipedia.org/wiki/General-purpose_computing_on_graphics_processing_units)* (GPGPU)) but still support this programming model.[^o13]
