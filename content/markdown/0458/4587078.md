# Longest increasing subsequence

::: {#o1 .subject cue=lead name="Longest increasing subsequence"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science), the **longest increasing subsequence** problem aims to find a [subsequence](wikipedia://en/236098) of a given [sequence](wikipedia://en/27838) in which the subsequence's elements are sorted in an ascending order and in which the subsequence is as long as possible. This subsequence is not necessarily contiguous or unique. The longest increasing subsequences are studied in the context of various disciplines related to [mathematics](wikipedia://en/18831), including [algorithmics](https://en.wikipedia.org/wiki/Algorithmics), [random matrix theory](https://en.wikipedia.org/wiki/Random_matrix_theory), [representation theory](wikipedia://en/19378200), and [physics](wikipedia://en/22939).[^o2][^o3] The longest increasing subsequence problem is solvable in time $O(n \log n),$ where $n$ denotes the length of the input sequence.[^o9]

:::

::: {#o5 .example cue=heading name="Example"}

## Example {#Example}

In the first 16 terms of the binary [Van der Corput sequence](https://en.wikipedia.org/wiki/Van_der_Corput_sequence)

0, 8, 4, 12, 2, 10, 6, 14, 1, 9, 5, 13, 3, 11, 7, 15

one of the longest increasing subsequences is

0, 2, 6, 9, 11, 15.

This subsequence has length six; the input sequence has no seven-member increasing subsequences. The longest increasing subsequence in this example is not the only solution: for instance,

0, 4, 6, 9, 11, 15

0, 2, 6, 9, 13, 15

0, 4, 6, 9, 13, 15

are other increasing subsequences of equal length in the same input sequence.

:::

## Relations to other algorithmic problems {#Relations_to_other_algorithmic_problems}

The longest increasing subsequence problem is closely related to the [longest common subsequence problem](https://en.wikipedia.org/wiki/Longest_common_subsequence_problem), which has a quadratic time [dynamic programming](wikipedia://en/125297) solution: the longest increasing subsequence of a sequence $S$ is the longest common subsequence of $S$ and $T,$ where $T$ is the result of [sorting](https://en.wikipedia.org/wiki/Sorting) $S.$ However, for the special case in which the input is a permutation of the integers $1, 2, \ldots, n,$ this approach can be made much more efficient, leading to time bounds of the form $O(n \log \log n).$[^o7]

The largest [clique](wikipedia://en/524466) in a [permutation graph](wikipedia://en/17625375) corresponds to the longest decreasing subsequence of the permutation that defines the graph (assuming the original non-permuted sequence is sorted from lowest value to highest). Similarly, the maximum [independent set](wikipedia://en/524501) in a permutation graph corresponds to the longest non-decreasing subsequence. Therefore, longest increasing subsequence algorithms can be used to solve the [clique problem](wikipedia://en/249254) efficiently in permutation graphs.[^o8]

In the [Robinson–Schensted correspondence](wikipedia://en/1901026) between [permutations](wikipedia://en/44027) and [Young tableaux](wikipedia://en/683368), the length of the first row of the tableau corresponding to a permutation equals the length of the longest increasing subsequence of the permutation, and the length of the first column equals the length of the longest decreasing subsequence.[^o9]

## Efficient algorithms {#Efficient_algorithms}

The algorithm outlined below solves the longest increasing subsequence problem efficiently with arrays and [binary searching](wikipedia://en/4266). It processes the sequence elements in order, maintaining the longest increasing subsequence found so far. Denote the sequence values as $X[0], X[1], \ldots,$ etc. Then, after processing $X[i],$ the algorithm will have stored an integer $L$ and values in two arrays:

- $L$ — stores the length of the longest increasing subsequence found so far.
- $M[l]$ — stores the index $k$ of the smallest value $X[k]$ such that there is an increasing subsequence of length $l$ ending at $X[k]$ in the range $k \leq i.$ Explicitly, suppose that $K_{i,l}$ denotes the set of all indices $j$ such that $j \leq i$ and there exists an increasing subsequence of length $l$ ending at $X[j].$ Then $k = M[l]$ is the index in $K_{i,l}$ for which $X[M[l]]$ is minimized; meaning that $M[l] \in K_{i,l}$ and $X[M[l]] = \min_{j \in K_{i,l}} X[j]$ (or equivalently, $M[l] \in K_{i,l}$ and for every $j \in K_{i,l},$ $X[M[l]] \leq X[j]$); if multiple indices satisfy this condition then $M[l]$ is the largest one.
  - To clarify, "there exists an increasing subsequence of length $l$ ending at $X[k]$" means that there exist $l$ indices $i_1 < i_2 < \cdots < i_l = k$ ending at $k$ such that $X\left[i_1\right] < X\left[i_2\right] < \cdots < X[k].$
  - Note that $1 \leq l \leq i + 1,$ because $l \geq 1$ represents the length of the increasing subsequence, and $k \geq 0$ represents the index of its termination.
  - The length of $M$ is $1$ more than the length of $X$ but it is possible that not all elements in this array are used by the algorithm (in fact, if the longest increasing sequence has length $L$ then only $M[1], \ldots, M[L]$ are used by the algorithm). If however $M[l]$ is used/defined then $l - 1 \leq M[l]$ (and moreover, at iteration $i,$ $M[l] \leq i$ will also hold). $M[0]$ is undefined since sequences of length $0$ have no ending index ($M[0]$ can be any value).
- $P[k]$ — stores the index of the predecessor of $X[k]$ in the longest increasing subsequence ending at $X[k].$
  - The length of $P$ is equal to that of $X,$
  - If $k > 0$ then $P[k] < k$ while $P[0]$ is undefined since $X[0]$ has no predecessor ($P[0]$ can be any value).

Because the algorithm below uses [zero-based numbering](wikipedia://en/34541), for clarity $M$ is padded with $M[0],$ which goes unused so that $M[l]$ corresponds to a subsequence of length $l.$ A real implementation can skip $M[0]$ and adjust the indices accordingly.

Note that, at any point in the algorithm, the sequence

$$X[M[1]], X[M[2]], \ldots, X[M[L]]$$

is increasing. For, if there is an increasing subsequence of length $l \geq 2$ ending at $X[M[l]],$ then there is also a subsequence of length $l - 1$ ending at a smaller value: namely the one ending at $X[P[M[l]]].$ Thus, we may do binary searches in this sequence in logarithmic time.

The algorithm, then, proceeds as follows:

*Image: LISDemo.gif.* A demo of the code.

P = array of length N M = array of length N + 1 M\[0\] = -1 // undefined so can be set to any value

L = 0 **for** i **in range** 0 **to** N-1: //N-1 included // Binary search for the smallest positive l ≤ L // such that X\[M\[l\]\] >= X\[i\] lo = 1 hi = L + 1 **while** lo \< hi: mid = lo + floor((hi-lo)/2) // lo \<= mid \< hi **if** X\[M\[mid\]\] >= X\[i\] hi = mid **else**: // if X\[M\[mid\]\] \< X\[i\] lo = mid + 1

// After searching, lo == hi is 1 greater than the // length of the longest prefix of X\[i\] newL = lo

// The predecessor of X\[i\] is the last index of // the subsequence of length newL-1 P\[i\] = M\[newL-1\] M\[newL\] = i

**if** newL > L: // If we found a subsequence longer than any we've // found yet, update L L = newL

// Reconstruct the longest increasing subsequence // It consists of the values of X at the L indices: // ..., P\[P\[M\[L\]\]\], P\[M\[L\]\], M\[L\] S = array of length L k = M\[L\] **for** j **in range** L-1 **to** 0: //0 included S\[j\] = X\[k\] k = P\[k\]

**return** S

Because the algorithm performs a single binary search per sequence element, its total time can be expressed using [Big O notation](wikipedia://en/44578) as $O(n \log n).$ (Fredman 1975) discusses a variant of this algorithm, which he credits to [Donald Knuth](wikipedia://en/8095); in the variant that he studies, the algorithm tests whether each value $X[i]$ can be used to extend the current longest increasing sequence, in constant time, prior to doing the binary search. With this modification, the algorithm uses at most $n \log_2 n - n \log_2 \log_2 n + O(n)$ comparisons in the worst case, which is optimal for a comparison-based algorithm up to the constant factor in the $O(n)$ term.[^o12]

## Length bounds {#Length_bounds}

According to the [Erdős–Szekeres theorem](wikipedia://en/3115543), any sequence of $n^2 + 1$ distinct integers has an increasing or a decreasing subsequence of length $n + 1.$ [^o16][^o17] For inputs in which each permutation of the input is equally likely, the expected length of the longest increasing subsequence is approximately $2 \sqrt{n}.$ [^o18][^o3]

In the limit as $n$ approaches infinity, the [Baik-Deift-Johansson theorem](https://en.wikipedia.org/wiki/Baik-Deift-Johansson_theorem) says, that the length of the longest increasing subsequence of a randomly permuted sequence of $n$ items has a distribution approaching the [Tracy–Widom distribution](wikipedia://en/21754732), the distribution of the largest [eigenvalue](wikipedia://en/2161429) of a random matrix in the [Gaussian unitary ensemble](https://en.wikipedia.org/wiki/Gaussian_unitary_ensemble).[^o19]

## Online algorithms {#Online_algorithms}

The longest increasing subsequence has also been studied in the setting of [online algorithms](https://en.wikipedia.org/wiki/Online_algorithm), in which the elements of a sequence of [independent random variables](wikipedia://en/27593) with continuous distribution $F$ – or alternatively the elements of a [random permutation](https://en.wikipedia.org/wiki/Random_permutation) – are presented one at a time to an algorithm that must decide whether to include or exclude each element, without knowledge of the later elements. In this variant of the problem, which allows for interesting applications in several contexts, it is possible to devise an optimal selection procedure that, given a random sample of size $n$ as input, will generate an increasing sequence with maximal expected length of size approximately $\sqrt{2 n}.$ [^o21] The length of the increasing subsequence selected by this optimal procedure has variance approximately equal to $\sqrt{2 n} / 3,$ and its limiting distribution is asymptotically [normal](wikipedia://en/21462) after the usual centering and scaling.[^o22] The same asymptotic results hold with more precise bounds for the corresponding problem in the setting of a [Poisson arrival process](wikipedia://en/41597450).[^o23] A further refinement in the Poisson process setting is given through the proof of a [central limit theorem](wikipedia://en/39406) for the optimal selection process which holds, with a suitable normalization, in a more complete sense than one would expect. The proof yields not only the "correct" functional limit theorem but also the (singular) [covariance matrix](wikipedia://en/191752) of the three-dimensional process summarizing all interacting processes. [^o24]
