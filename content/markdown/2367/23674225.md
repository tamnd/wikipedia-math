# Convex bipartite graph

::: {#o1 .subject cue=lead name="Convex bipartite graph"}

*Image: Convex bipartite graphs.svg.* Both graphs are convex bipartite graphs, because at least one side has edges with consecutive vertices on the other side (when properly ordered). The first is also **biconvex**, because *both* sides have this property with the same vertex ordering, while the second is only convex for one side and cannot be made convex for both sides simultaneously (with any vertex ordering), making it **singly convex**.

In the [mathematical](https://en.wikipedia.org/wiki/Mathematical) field of [graph theory](wikipedia://en/12401), a **convex bipartite graph** is a [bipartite graph](wikipedia://en/244431) with specific properties. A bipartite graph $(U \cup V, E)$ is said to be **convex over** the vertex set $U$ if $U$ can be [enumerated](wikipedia://en/212115) such that for all $v \in V$, the vertices adjacent to $v$ are consecutive in the enumeration. Convexity over $V$ is defined analogously. A bipartite graph $(U \cup V, E)$ that is convex over both $U$ and $V$ is said to be **biconvex** or **doubly convex**.

:::

## Properties {#Properties}

For a biconvex graph with labelings $U = {u_1, \ldots, u_m}$ and $V = {v_1, \ldots, v_n}$, let $\overline{u_i}$ denote the set of neighbors of vertex $u_i$. A biconvex graph is called **forward-convex** if there exists a labeling such that $V$ is convex and the labeling has the **forward property**: for every pair of vertices $u_i, u_j \in U$ with $i < j$, it holds that $\overline{u_i} \supseteq \overline{u_j}$ (where $\supseteq$ means that $\overline{u_i}$ contains $\overline{u_j}$ as a consecutive segment).

It has been proven that forward-convex graphs are equivalent to [permutation graphs](wikipedia://en/17625375). A biconvex graph is forward-convex (and hence a bipartite permutation graph) if and only if it contains no [induced subgraph](wikipedia://en/1655188) isomorphic to certain forbidden configurations.

Every biconvex graph is a [4-polygon graph](https://en.wikipedia.org/wiki/Polygon_graph), that is, its vertices can be represented as chords inside a convex 4-sided polygon such that two vertices are adjacent if and only if their corresponding chords intersect. Furthermore, every biconvex graph has a **biconvex S-ordering** (straight ordering), which is a biconvex ordering that generalizes the strong ordering of bipartite permutation graphs and prohibits certain crossing patterns between edges.

### Strongly biconvex graphs {#Strongly_biconvex_graphs}

A **strongly biconvex graph** is a bipartite graph $H = (X, Y)$ with labelings $X = {x_q, x_{q+1}, \ldots, x_f}$ and $Y = {y_{q'}, y_{q'+1}, \ldots, y_g}$ such that if ${x_i, y_j}$ is an edge, then $i < j$

For any $r$ with $i < r < j$ and edge ${x_i, y_j}$: if $x_r \in X$ then ${x_r, y_j}$ is an edge, and if $y_r \in Y$ then ${x_i, y_r}$ is an edge. Every strongly biconvex graph is biconvex and [weakly chordal](https://en.wikipedia.org/wiki/Weakly_chordal_graph).

## Algorithms {#Algorithms}

### Maximum matching {#Maximum_matching}

Finding a [maximum matching](https://en.wikipedia.org/wiki/Maximum_matching) in a convex bipartite graph can be done efficiently. Glover showed that a maximum matching can be found using a [greedy algorithm](wikipedia://en/89247) that processes vertices in order. Subsequent improvements by various researchers culminated in a linear-time algorithm.

For the dynamic version of the problem, where the graph is modified by vertex and edge insertions and deletions, it is impossible to maintain an explicit representation of a maximum matching in sub-linear time per operation, even in the amortized sense, because a single update can change $\Theta(|V|)$ edges in the matching. However, it is possible to efficiently maintain which vertices are matched: there exists a [data structure](wikipedia://en/8519) that maintains the set of matched vertices in $O(\log^2 |V|)$ amortized time per update operation, answers whether a given vertex is matched in $O(1)$ worst-case time, and can identify the mate of a matched vertex in $O(\sqrt{|V|} \log^2 |V|)$ amortized time.

### Maximum edge biclique {#Maximum_edge_biclique}

A [biclique](https://en.wikipedia.org/wiki/Biclique) is a [complete bipartite subgraph](wikipedia://en/525320). The **maximum edge biclique problem** asks for a biclique with the maximum number of edges. In general bipartite graphs, this problem is [NP-complete](https://en.wikipedia.org/wiki/NP-complete), but for convex bipartite graphs it can be solved in polynomial time. Given a convex bipartite graph $G = (A \cup B, E)$ with $|A| = n$, a maximum edge biclique can be found in $O(n \log^3 n \log \log n)$ time and $O(n)$ space. For the special cases of biconvex graphs and bipartite permutation graphs, the problem can be solved even more efficiently in $O(n\alpha(n))$ and $O(n)$ time respectively, where $\alpha(n)$ is the inverse [Ackermann function](wikipedia://en/2925).

The maximum edge biclique problem has applications in analyzing [DNA microarray](https://en.wikipedia.org/wiki/DNA_microarray) data, where it corresponds to finding [biclusters](wikipedia://en/1810201)—subsets of genes that exhibit coherent expression patterns across subsets of experimental conditions.

### Maximum induced matching {#Maximum_induced_matching}

An [induced matching](https://en.wikipedia.org/wiki/Induced_matching) is a set of edges that are pairwise at distance at least 3. Finding a maximum induced matching is NP-hard for general bipartite graphs, but can be solved efficiently for certain subclasses. For strongly biconvex graphs, a maximum induced matching can be computed in linear time using a greedy algorithm. Indeed, even a maximum-weight induced matching can be computed in linear-time for any convex bipartite graph using [dynamic programming](wikipedia://en/125297).

### Vertex ranking {#Vertex_ranking}

The [vertex ranking problem](wikipedia://en/426743#Other_colorings) asks for a coloring of vertices with the property that every path between two vertices of the same color must contain a vertex of higher color, using the minimum number of colors. While this problem is [NP-complete](https://en.wikipedia.org/wiki/NP-complete) for general bipartite graphs, it can be solved in polynomial time for biconvex graphs in $O(n^4(n + m))$ time, where $n$ is the number of vertices and $m$ is the number of edges.
