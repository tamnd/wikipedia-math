# Generic Security Service Algorithm for Secret Key Transaction

::: {#o1 .subject cue=lead name="Generic Security Service Algorithm for Secret Key Transaction"}

**GSS-TSIG (Generic Security Service Algorithm for Secret Key Transaction)** is an extension to the [TSIG](https://en.wikipedia.org/wiki/TSIG) DNS [authentication protocol](https://en.wikipedia.org/wiki/Authentication_protocol) for secure key exchange. It is a GSS-API algorithm which uses [Kerberos](wikipedia://en/16947) for passing security tokens to provide authentication, integrity and confidentiality.

:::

GSS-TSIG (RFC 3645) uses a mechanism like [SPNEGO](https://en.wikipedia.org/wiki/SPNEGO) with [Kerberos](wikipedia://en/16947) or [NTLM](https://en.wikipedia.org/wiki/NTLM). In Windows, this implementation is called *Secure Dynamic Update*.[^o2]

GSS-TSIG uses [TKEY records](https://en.wikipedia.org/wiki/TKEY_record) for key exchange between the DNS client and server in GSS-TSIG mode. For authentication between the DNS client and [Active Directory](wikipedia://en/2807), the AS-REQ, AS-REP, TGS-REQ, TGS-REP exchanges must take place for granting of ticket and establishing a security context. The security context has a limited lifetime during which dynamic updates to the DNS server can take place.
