# Intersection non-emptiness problem

::: {#o1 .subject cue=lead name="Intersection non-emptiness problem"}

The **intersection non-emptiness problem**, also known as **finite automaton intersection problem**[^o2] or the **non-emptiness of intersection problem**, is a [PSPACE-complete](wikipedia://en/54685) decision problem from the field of [automata theory](wikipedia://en/103356). The problem asks if a list of [deterministic finite automata](wikipedia://en/653404) has nonempty intersection.

:::

::: {#o4 .definition cue=heading name="Definitions"}

## Definitions {#Definitions}

A [non-emptiness decision problem](wikipedia://en/57342784) is defined (for a particular type of automaton) as follows: given an automaton as input, the goal is to determine whether or not the automaton's language is non-empty, i.e., if there exists a string that is accepted by the automaton. Non-emptiness problems have been studied in the field of [automata theory](wikipedia://en/103356) for many years. Several common non-emptiness problems have been shown to be complete for complexity classes ranging from [Deterministic Logspace](wikipedia://en/1149999) up to [PSPACE](wikipedia://en/39351).[^o5]

The intersection non-emptiness [decision problem](wikipedia://en/8336) is similar, but defined on a list of automata, instead of just one. In particular, for the purposes of this article: given a list of [deterministic finite automata](wikipedia://en/653404) as input, determine whether or not their associated regular languages have a non-empty intersection; i.e., determine if there exists a string that is accepted by every automaton in the list.

:::

::: {#o7 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

There is an [exponential time](wikipedia://en/405944#Exponential_time) algorithm that solves the intersection non-emptiness problem based on the [Cartesian product](wikipedia://en/24104095) construction introduced by [Michael O. Rabin](wikipedia://en/298404) and [Dana Scott](wikipedia://en/161875).[^o8] The idea is that all of the automata together form a "product automaton" whose states consist of tuples of states in the list of automata; a string is accepted by the product automaton if and only if it is accepted by every automaton in the list. Therefore, a [breadth-first search](wikipedia://en/97026) (or [depth-first search](wikipedia://en/97034)) within the product automaton's state space will determine whether there exists a path from the product start state to one of the product final states. Whether or not such a path exists is equivalent to determining if any string is accepted by every automaton in the list.

For this construction, the product automaton does not need to be explicitly constructed; the automata provide sufficient information so that transitions can be determined as needed.

:::

## Hardness {#Hardness}

The intersection non-emptiness problem was shown to be [PSPACE-complete](wikipedia://en/54685) by [Dexter Kozen](https://en.wikipedia.org/wiki/Dexter_Kozen) in 1977.[^o2] It is an open problem whether any faster algorithms exist.[^o10]
