# Very smooth hash

::: {#o1 .subject cue=lead name="Very smooth hash"}

In [cryptography](wikipedia://en/18934432), **Very Smooth Hash** (**VSH**) is a provably secure [cryptographic hash function](wikipedia://en/439526) invented in 2005 by Scott Contini, [Arjen Lenstra](wikipedia://en/6850292), and Ron Steinfeld.[^o3] [*Provably secure*](https://en.wikipedia.org/wiki/Provably_secure_cryptographic_hash_function) means that finding collisions is as difficult as some mathematical problem that is known to be hard. Unlike other provably secure [collision-resistant](wikipedia://en/2982326) hashes, VSH is efficient and usable in practice. [Asymptotically](wikipedia://en/44578), it only requires a single multiplication per $\log(n)$ message-bits and uses [RSA](wikipedia://en/25385)-type arithmetic. Therefore, VSH can be useful in embedded environments where code space is limited.

:::

Two major variants of VSH were proposed. For one, finding a [collision](wikipedia://en/2982326) is provably as difficult as finding a nontrivial [modular square root](https://en.wikipedia.org/wiki/Modular_square_root) of a very [smooth number](wikipedia://en/1035039) modulo $n$. The other one uses a prime modulus $p$ (with no [trapdoor](wikipedia://en/206753)), and its security proof relies on the hardness of finding [discrete logarithms](wikipedia://en/181334) of very smooth numbers modulo $p$. Both versions have similar efficiency.

VSH is not suitable as a substitute for a [random oracle](wikipedia://en/451286), but can be used to build a provably secure randomized trapdoor hash function. This function can replace the [trapdoor function](wikipedia://en/206753) used in the [Cramer–Shoup signature scheme](wikipedia://en/1564406), maintaining its provable security while speeding up verification time by about 50%.

## VSN and VSSR {#VSN_and_VSSR}

Not all cryptographic hash functions that are now widely used are based on hard mathematical problems. Those few functions that are constructed on hard mathematical problems are called [*provably secure*](https://en.wikipedia.org/wiki/Provably_secure_cryptographic_hash_function). [Finding collisions](wikipedia://en/2982326) is then known to be as hard as solving the hard mathematical problem. For the basic version of Very Smooth Hash, this hard problem is to find [modular square roots](https://en.wikipedia.org/wiki/Modular_square_root) (VSSR) of certain special numbers (VSN).[^o3] This is assumed to be as hard as [factoring integers](wikipedia://en/15491).

For fixed constants $c$ and $n$, an integer $m$ is a *Very Smooth Number* (VSN) if the largest prime factor of $m$ is at most $\log(n)^{c}$.

An integer $b$ is a *Very Smooth Quadratic Residue modulo* $n$ if the largest prime in $b$'s factorization is at most $\log(n)^{c}$ and there exists an integer $x$ such that $b \equiv x^{2}\pmod{n}$. The integer $x$ is then said to be a [modular square root](wikipedia://en/200091) of $b$.

We are interested only in non-trivial square roots, those where $x^{2} \ge n$. If $x^{2} < n$, then the root can be easily computed using algorithms from fields of [characteristic](wikipedia://en/1066621) 0, such as [the real field](wikipedia://en/20646438). Therefore, they are not suitable in cryptographic primitives.

*Very Smooth Number Nontrivial Modular Square Root* (VSSR) is the following problem: Let $n$ be the product of two unknown primes of approximately the same size, let $k \le (\log(n))^{c}$, and let $(p_{1},p_{2},p_{3},\ldots) = (2,3,5,\ldots)$ be the sequence of primes. Given $n$, find an integer $x$ [coprime](wikipedia://en/6556) to $n$ such that $\textstyle x^2 \equiv \prod_{i=0}^k p_i^{e_i} \pmod{n}$ and at least one of $e_{0},\ldots,e_{k}$ is odd.

The *VSSR assumption* is that there is no [probabilistic polynomial](wikipedia://en/659322) (in $\log(n)$) time algorithm which solves VSSR with [non-negligible](wikipedia://en/8426019) probability. This is considered a useless assumption in practice because it does not tell for what size of moduli VSSR is computationally hard. Instead the *computational VSSR assumption* is used. It says that solving VSSR is assumed to be as hard as [factoring](wikipedia://en/15491) a hard-to-factor $s$-bit modulus, where $s$ is somewhat smaller than the size of $n$.

### Examples of VSN and VSSR {#Examples_of_VSN_and_VSSR}

Let the parameters be fixed as $c = 5$ and $n = 31$.

Then $m_{1} = 35 = 5\cdot7$ is a Very Smooth Number with respect to these parameters because $\log(31)^{5} \approx 7.37$ is greater than all of $m_{1}$'s prime factors. On the other hand, $m_{2} = 55 = 5\cdot11$ is not a VSN under these parameters.

The integer $9$ is a Very Smooth Quadratic Residue modulo $n$ because it is a Very Smooth Number (under $c,n$), and $3^{2} \equiv 9\pmod{n}$. This is a trivial modular square root, because $9 < n$ and so the modulus is not involved when squaring.

The integer $b_{2} = 15$ is also a Very Smooth Quadratic Residue modulo $n$. All prime factors are smaller than 7.37 and the Modular Square Root is $x_{2} = 20$ since $20^{2} = 400 \equiv 15\pmod{n}$. This is thus a non-trivial root. The VSSR problem is to find $x_{2}$ given $b_{2}$ and $n$. This is believed to be computationally as hard as factoring $n$.

## VSH algorithm, basic versions {#VSH_algorithm,_basic_versions}

Let $n$ be a large RSA composite and let $(p_{1},p_{2},p_{3},\ldots) = (2,3,5,\ldots)$ be the sequence of primes. Let $k$, the block length, be the largest integer such that $\textstyle \prod_{i = 1}^k p_i < n$. Let $m$ be an $\ell$-bit message to be hashed consisting of bits $(m_{1},\ldots,m_{\ell})$ and assume that $\ell < 2^{k}$. To compute the hash of $m$:

1. Set $x_{0} = 1$.
1. Let $L$, the smallest integer greater than or equal to $\ell/k$, be the number of blocks.
1. Let $m_{i} = 0$ for $\ell < i < Lk$ (padding).
1. Let $\textstyle \ell = \sum_{i=1}^k l_i 2^{i-1}$ with $\ell_{i} \in \{0,1\}$ be the binary representation of the message length $\ell$ and define $m_{Lk+i} = \ell_{i}$ for $1 \le i \le k$.
1. For $j = 0, 1, \ldots, L$ in succession, compute $\textstyle x_{j+1} = x_j^2 \prod_{i=1}^k p_i^{m_{jk+i}} \pmod{n}$
1. Return $x_{L+1}$.

The function in step 5 is called the compression function.

## Properties of VSH {#Properties_of_VSH}

- The message length does not need to be known in advance.
- Finding a collision in VSH is as hard as solving VSSR. Thus VSH is (strongly) [collision-resistant](https://en.wikipedia.org/wiki/Collision-resistant), which also implies second preimage resistance. VSH has not been proven to be preimage-resistant.
- The compression function is not collision-resistant. Nonetheless, the hash function VSH is collision-resistant based on the VSSR assumption. An altered version of VSH, called VSH\*, uses a collision-resistant compression function and is about 5 times quicker when hashing short messages.
- Since the output length of VSH is the length of a secure [RSA modulus](wikipedia://en/511379), VSH seems quite suitable in practice for constructing "hash-then-sign" RSA signatures for arbitrarily long messages. However, such a signature must be designed carefully to ensure its security. The naïve approach could be easily broken under a [chosen-plaintext attack](wikipedia://en/2187252).
- The cost of each iteration is less than the cost of 3 modular multiplications. The basic version of VSH altogether requires one multiplication per $\Omega(\log(n) / \log(\log(n)))$ message bits.

## Variants of VSH {#Variants_of_VSH}

Several improvements, speedups, and more efficient variants of VSH have been proposed.[^o3] None of them changes the underlying concept of the function. These improvements are called:

- Cubing VSH (instead of squaring)
- VSH with increased number of small primes
- VSH with precomputed products of primes
- Fast VSH
- Fast VSH with increased block length

## VSDL and VSH-DL variant {#VSDL_and_VSH-DL_variant}

The VSH-DL is a discrete logarithm variant of VSH that has no [trapdoor](wikipedia://en/206753); its security depends on the difficulty of finding discrete logarithms modulo a prime $p$.[^o3]

*Very Smooth Number Discrete Logarithm* (VSDL) is a problem where, given a very smooth number, the task is to find its [discrete logarithm](wikipedia://en/181334) modulo some number $n$.

As in previous section, $p_{i}$ denotes the $i$th prime. Let furthermore $c$ be a fixed constant, let $p,q$ be [primes with $p = 2q + 1$](wikipedia://en/89244), and let $k \le (\log p)^{c}$. VSDL is the following problem: given $p$, find integers $e_{1},\ldots,e_{k}$ such that $\textstyle 2^{e_1} \equiv \prod_{i=2}^k p_i^{e_i} \pmod{p}$ with $\lvert e_{i}\rvert < q$ for $i = 1, \ldots, k$ and at least one of $e_{1},\ldots,e_{k}$ is non-zero.

The *VSDL assumption* is that there is no [probabilistic polynomial](wikipedia://en/659322) (in $\log(p)$) time algorithm which solves VSDL with [non-negligible](wikipedia://en/8426019) probability. There is a strong connection between the hardness of VSDL and the hardness of computing discrete logarithms modulo $p$, which is reminiscent of, but somewhat weaker than, the connection between VSSR and [integer factorization](wikipedia://en/15491).

## Security of VSH {#Security_of_VSH}

Strong [collision resistance](wikipedia://en/2982326) is the only property proven for VSH. This does not imply preimage-resistance or other important hash-function properties, and the authors state that "VSH should not be used to model [random oracles](wikipedia://en/451286)," and cannot be substituted into constructions that depend upon them ([RSA signatures](https://en.wikipedia.org/wiki/RSA_%28algorithm%29), some [MACs](wikipedia://en/567523)).[^o3] VSH should not be considered a general-purpose hash function as usually understood in [security engineering](https://en.wikipedia.org/wiki/Security_engineering).

### Multiplicative property {#Multiplicative_property}

VSH is multiplicative: Let $x$, $y$, and $z$ be three bitstrings of equal length, where $z$ consists only of zero bits and the strings satisfy $x \operatorname{AND} y = z$. Then $H(z)H(x \operatorname{OR} y) \equiv H(x)H(y)\pmod{n}$. As a result, VSH succumbs to a classical time-memory trade-off attack that applies to multiplicative and additive hashes.

This fact can be used to construct a preimage attack against VSH of $\ell$ bits which has $2^{\ell/2}$ complexity rather than $2^{\ell}$ as expected.

### Attack against truncated version {#Attack_against_truncated_version}

VSH produces a very long hash (typically 1024 bits). There are no indications that a truncated VSH hash offers security that is commensurate with the hash length.

There exists a partial collision attack on VSH truncated to $\ell$ least significant bits.[^o13]

The complexity of this attack against VSH is:

- Pre-computing the table offline: $2^{\ell/3}$ time and space.
- Finding collisions: $2^{\ell/3}$ iterations.
- Total cost: roughly $2^{\ell/3}$, rather than $2^{\ell/2}$ as expected from a hash function with good [pseudorandomness](wikipedia://en/23210) properties.

This probably rules out the applicability of VSH in digital signature schemes which produce signatures shorter than the VSH hash result, such as [elliptic-curve signature schemes](wikipedia://en/9966).
