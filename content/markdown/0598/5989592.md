# Maximum-cardinality matching

*Image: Maximum cardinality matching.svg.* The graph on the right has maximum cardinality matching one less than the graph on the left, despite the fact that they both have the same number of vertices.

::: {#o1 .subject cue=lead name="Maximum-cardinality matching"}

In [graph theory](wikipedia://en/12401), a **maximum-cardinality matching** is a special kind of subgraph useful in many computational contexts. Given a [graph](https://en.wikipedia.org/wiki/Graph_%28graph_theory%29) $G$, a [matching](wikipedia://en/581797) is a subgraph where no two edges share a vertex. The [cardinality](wikipedia://en/6174) of the matching is the number of edges in the subgraph, and the maximum cardinality is the largest number of edges a matching can contain. A matching for a given graph is a **maximum-cardinality matching** if its cardinality is this maximum cardinality. If we think of each edge as "covering" the vertices it connects exactly once, then a maximal matching is also the largest non-overlapping cover of the graph. If all the vertices are covered, we call it a [perfect matching](wikipedia://en/44031). For finite graphs, a maximum-cardinality matching always exists, but is not usually unique. The cardinality of the matching is never more than half the number of vertices and also never more than the number of edges.

:::

An important [special case](wikipedia://en/31308010) of the maximum-cardinality matching problem is when $G$ is a [bipartite graph](wikipedia://en/244431) representing a [binary relation](wikipedia://en/3931), whose vertices $V$ are partitioned between left vertices in $X$ and right vertices in $Y$, and edges in $E$ always connect a left vertex to a right vertex. In this case, the problem can be efficiently solved with simpler algorithms than in the general case.

The calculation of a **maximum matching** for a given graph is a fundamental task in computational [graph theory](wikipedia://en/12401).[^o2] There are nonconstructive [characterization theorems](wikipedia://en/581797#Characterizations) for the size of a maximum matching. This article is about computation of maximum matchings.

## Algorithms for bipartite graphs {#Algorithms_for_bipartite_graphs}

### Flow-based algorithm {#Flow-based_algorithm}

The simplest way to compute a maximum-cardinality matching is to follow the [Ford–Fulkerson algorithm](wikipedia://en/53777). This algorithm solves the more general problem of [computing the maximum flow](wikipedia://en/403165). A bipartite graph $(X + Y, E)$ can be converted to a [flow network](wikipedia://en/645676) as follows.

- Add a source vertex $s$; add an edge from $s$ to each vertex in $X$.
- Add a sink vertex $t$; add an edge from each vertex in $Y$ to $t$.
- Assign a capacity of 1 to each edge.

Since each edge in the network has integral capacity, there exists a maximum flow where all flows are integers; these integers must be either 0 or 1 since the all capacities are 1. Each integral flow defines a matching in which an edge is in the matching [if and only if](wikipedia://en/14922) its flow is 1. It is a matching because:

- The incoming flow into each vertex in $X$ is at most 1, so the outgoing flow is at most 1 too, so at most one edge adjacent to each vertex in $X$ is present.
- The outgoing flow from each vertex in $Y$ is at most 1, so the incoming flow is at most 1 too, so at most one edge adjacent to each vertex in $Y$ is present.

The Ford–Fulkerson algorithm proceeds by repeatedly finding an augmenting path from some $x \in X$ to some $y \in Y$ and updating the matching $M$ by taking the [symmetric difference](wikipedia://en/262288) of that path with $M$ (assuming such a path exists). As each path can be found in $O(E)$ time, the running time is $O(VE)$, and the maximum matching consists of the edges of $E$ that carry flow from $X$ to $Y$.

### Advanced algorithms {#Advanced_algorithms}

An improvement to this algorithm is given by the more elaborate [Hopcroft–Karp algorithm](wikipedia://en/5944391), which searches for multiple augmenting paths simultaneously. This algorithm runs in $O(\sqrt{V}E)$ time.

The algorithm of Chandran and Hochbaum[^o13] for bipartite graphs runs in time that depends on the size of the maximum matching $k$, which for $\lvert X\rvert < \lvert Y\rvert$ is

$$O\left(\min\{|X|k,E\}+ \sqrt{k} \min \{k^2,E\}\right).$$

Using Boolean operations on words of size $\lambda$ the complexity is further improved to[^o13]

$$O\left(\min \left\{|X|k, \frac{|X||Y|}{\lambda}, E\right\} + k^2 + \frac{k^{2.5}}{\lambda}\right).$$

More efficient algorithms exist for special kinds of bipartite graphs:

- For [sparse](https://en.wikipedia.org/wiki/Sparse_graph) bipartite graphs, the maximum matching problem can be solved in $\tilde{O}(E^{10/7})$ with Madry's algorithm based on electric flows.[^o6]
- For [planar](https://en.wikipedia.org/wiki/Planar_graphs) bipartite graphs, the problem can be solved in time $O(n \log^{3} n)$ where $n$ is the number of vertices, by reducing the problem to [maximum flow](https://en.wikipedia.org/wiki/Maximum_flow) with multiple sources and sinks.[^o7]

## Algorithms for arbitrary graphs {#Algorithms_for_arbitrary_graphs}

The [blossom algorithm](wikipedia://en/24277294) finds a maximum-cardinality matching in general (not necessarily bipartite) graphs. It runs in time $O(|V|^2 \cdot |E|)$. A better performance of $O(VE)$ for general graphs, matching the performance of the [Hopcroft–Karp algorithm](wikipedia://en/5944391) on bipartite graphs, can be achieved with the much more complicated algorithm of Micali and Vazirani.[^o9] The same bound was achieved by an algorithm by Norbert Blum (computer scientist)[^o10] and an algorithm by [Gabow](wikipedia://en/68166303) and [Tarjan](https://en.wikipedia.org/wiki/Robert_Tarjan).[^o11]

An alternative approach uses [randomization](wikipedia://en/495383) and is based on the fast [matrix multiplication](wikipedia://en/125280) algorithm. This gives a randomized algorithm for general graphs with complexity $O(V^{2.372})$.[^o12] This is better in theory for sufficiently [dense graphs](wikipedia://en/2777098), but in practice the algorithm is slower.[^o13]

Other algorithms for the task are reviewed by Duan and Pettie[^o14] (see Table I). In terms of [approximation algorithms](wikipedia://en/563105), they also point out that the [blossom algorithm](wikipedia://en/24277294) and the algorithms by Micali and Vazirani can be seen as [approximation algorithms](wikipedia://en/563105) running in linear time for any fixed error bound.

## Applications and generalizations {#Applications_and_generalizations}

- By finding a maximum-cardinality matching, it is possible to decide whether there exists a [perfect matching](wikipedia://en/44031).
- The problem of finding a matching with maximum weight in a **[weighted graph](https://en.wikipedia.org/wiki/Weighted_graph)** is called the [maximum-weight matching problem](https://en.wikipedia.org/wiki/Maximum-weight_matching), and its restriction to bipartite graphs is called the [assignment problem](wikipedia://en/140592). If each vertex can be matched to several vertices at once, then this is a [generalized assignment problem](https://en.wikipedia.org/wiki/Generalized_assignment_problem).
- A [priority matching](wikipedia://en/65198326) is a particular maximum-cardinality matching in which prioritized vertices are matched first.
- The problem of finding a maximum-cardinality [matching in hypergraphs](wikipedia://en/63030703) is NP-complete even for 3-uniform hypergraphs.[^o16]
