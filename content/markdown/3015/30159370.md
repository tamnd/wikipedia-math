# FKT algorithm

::: {#o1 .subject cue=lead name="FKT algorithm"}

The **Fisher–Kasteleyn–Temperley** (**FKT**) **algorithm**, named after [Michael Fisher](https://en.wikipedia.org/wiki/Michael_Fisher), [Pieter Kasteleyn](https://en.wikipedia.org/wiki/Pieter_Kasteleyn), and [Neville Temperley](https://en.wikipedia.org/wiki/Harold_Neville_Vazeille_Temperley), counts the number of [perfect matchings](wikipedia://en/44031) in a [planar](wikipedia://en/24314) graph in polynomial time. This same task is [\#P-complete](https://en.wikipedia.org/wiki/Sharp-P-complete) for general graphs. For [matchings](wikipedia://en/581797) that are not required to be perfect, counting them remains #P-complete even for planar graphs. The key idea of the FKT algorithm is to convert the problem into a [Pfaffian](wikipedia://en/530060) computation of a [skew-symmetric matrix](wikipedia://en/174055) derived from a planar embedding of the graph. The Pfaffian of this matrix is then computed efficiently using standard [determinant algorithms](wikipedia://en/8468#Algorithmic_implementation).

:::

## History {#History}

The problem of counting planar perfect matchings has its roots in [statistical mechanics](wikipedia://en/28481) and [chemistry](https://en.wikipedia.org/wiki/Chemistry), where the original question was: If [diatomic molecules](https://en.wikipedia.org/wiki/Diatomic_molecule) are adsorbed on a surface, forming a single layer, how many ways can they be arranged?[^o3] The [partition function](wikipedia://en/312252) is an important quantity that encodes the statistical properties of a system at equilibrium and can be used to answer the previous question. However, trying to compute the partition function from its definition is not practical. Thus to exactly solve a physical system is to find an alternate form of the partition function for that particular physical system that is sufficiently simple to calculate exactly.[^o4] In the early 1960s, the definition of *exactly solvable* was not rigorous.[^o5] Computer science provided a rigorous definition with the introduction of [polynomial time](wikipedia://en/658550), which dates to 1965. Similarly, the notation of not *exactly solvable*, for a [counting problem](https://en.wikipedia.org/wiki/Counting_problem_%28complexity%29) such as this one, should correspond to [\#P-hardness](https://en.wikipedia.org/wiki/Sharp-P-complete), which was defined in 1979.

Another type of physical system to consider is composed of [dimers](https://en.wikipedia.org/wiki/Dimer_%28chemistry%29), which is a polymer with two atoms. The dimer model counts the number of dimer coverings of a graph.[^o6] Another physical system to consider is the bonding of [H<sub>2</sub>O](https://en.wikipedia.org/wiki/H2O) molecules in the form of ice. This can be modelled as a directed, 3-[regular](wikipedia://en/85821) graph where the orientation of the edges at each vertex cannot all be the same. How many edge orientations does this model have?

Motivated by physical systems involving dimers, in 1961, Pieter Kasteleyn[^o7] and Neville Temperley and Michael Fisher[^o8] independently found the number of [domino tilings](wikipedia://en/10565476#Counting_tilings_of_regions) for the *m*-by-*n* rectangle. This is equivalent to counting the number of perfect matchings for the *m*-by-*n* [lattice graph](wikipedia://en/19635706). By 1967, Kasteleyn had generalized this result to all planar graphs.[^o9][^o10]

## Algorithm {#Algorithm}

### Explanation {#Explanation}

The main insight is that every non-zero term in the [Pfaffian](wikipedia://en/530060) of the [adjacency matrix](wikipedia://en/244463) of a graph *G* corresponds to a perfect matching. Thus, if one can find an [orientation](wikipedia://en/36619818) of *G* to align all signs of the terms in [Pfaffian](wikipedia://en/530060) (no matter *\+* or *\-* ), then the absolute value of the [Pfaffian](wikipedia://en/530060) is just the number of perfect matchings in *G*. The FKT algorithm does such a task for a planar graph *G*. The orientation it finds is called a [Pfaffian orientation](wikipedia://en/56281176).

Let *G* = (*V*, *E*) be an undirected graph with [adjacency matrix](wikipedia://en/244463) *A*. Define *PM*(*n*) to be the set of partitions of *n* elements into pairs, then the number of perfect matchings in *G* is

$$\operatorname{PerfMatch}(G) = \sum_{M \in PM(|V|)} \prod_{(i,j) \in M} A_{i j}.$$

Closely related to this is the [Pfaffian](wikipedia://en/530060) for an *n* by *n* matrix *A*

$$\operatorname{pf}(A) = \sum_{M \in PM(n)} \operatorname{sgn}(M) \prod_{(i,j) \in M} A_{i j},$$

where sgn(*M*) is the [sign of the permutation](wikipedia://en/49727) *M*. A Pfaffian orientation of *G* is a directed graph *H* with [adjacency matrix](wikipedia://en/244463#Directed_graphs) *B* such that pf(*B*) = PerfMatch(*G*).[^o14] In 1967, Kasteleyn proved that planar graphs have an efficiently computable Pfaffian orientation. Specifically, for a planar graph *G*, let *H* be a directed version of *G* where an odd number of edges are oriented clockwise for every face in a planar embedding of *G*. Then *H* is a Pfaffian orientation of *G*.

Finally, for any [skew-symmetric matrix](wikipedia://en/174055) *A*,

$$\operatorname{pf}(A)^2 = \det(A),$$

where det(*A*) is the [determinant](wikipedia://en/8468) of *A*. This result is due to [Arthur Cayley](wikipedia://en/311034).[^o15] Since [determinants](wikipedia://en/8468#Algorithmic_implementation) are efficiently computable, so is PerfMatch(*G*).

### High-level description {#High-level_description}

*Image: Pfaffian orientation via FKT algorithm example.gif.* An example showing how the FKT algorithm finds a Pfaffian orientation.

1. Compute a planar [embedding](wikipedia://en/8149170) of *G*.
1. Compute a [spanning tree](wikipedia://en/455770) *T*<sub>1</sub> of the input graph *G*.
1. Give an arbitrary orientation to each edge in *G* that is also in *T*<sub>1</sub>.
1. Use the planar embedding to create an (undirected) graph *T*<sub>2</sub> with the same vertex set as the [dual graph](wikipedia://en/2536864) of *G*.
1. Create an edge in *T*<sub>2</sub> between two vertices if their corresponding faces in *G* share an edge in *G* that is not in *T*<sub>1</sub>. (Note that *T*<sub>2</sub> is a tree.)
1. For each leaf *v* in *T*<sub>2</sub> (that is not also the root):
   1. Let *e* be the lone edge of *G* in the face corresponding to *v* that does not yet have an orientation.
   1. Give *e* an orientation such that the number of edges oriented clock-wise is odd.
   1. Remove *v* from *T*<sub>2</sub>.
1. Return the absolute value of the [Pfaffian](wikipedia://en/530060) of the [adjacency matrix](wikipedia://en/244463#Directed_graphs) of *G*, which is the square root of the determinant.

## Generalizations {#Generalizations}

The sum of weighted perfect matchings can also be computed by using the [Tutte matrix](wikipedia://en/18305460) for the adjacency matrix in the last step.

[Kuratowski's theorem](wikipedia://en/54493) states that

a [finite graph](https://en.wikipedia.org/wiki/Finite_graph) is planar [if and only if](wikipedia://en/14922) it contains no [subgraph](wikipedia://en/325802#Subgraphs) [homeomorphic](wikipedia://en/353021) to *K*<sub>5</sub> ([complete graph](wikipedia://en/85816) on five vertices) or *K*<sub>3,3</sub> ([complete bipartite graph](wikipedia://en/525320) on two partitions of size three).

[Vijay Vazirani](https://en.wikipedia.org/wiki/Vijay_Vazirani) generalized the FKT algorithm to graphs that do not contain a subgraph homeomorphic to *K*<sub>3,3</sub>.[^o19] More generally the complexity of counting perfect matchings has been completely characterized for families of graphs that are closed under [graph minors](wikipedia://en/353042). There exists a family of graphs, the *shallow vortex grids*, such that for a minor-closed family that does not include all shallow vortex grids, this counting problem is polynomially solvable. But for a minor-closed family that includes all shallow vortex grids, such as the $K_8$-minor-free graphs, the problem of counting perfect matchings is [\#P-complete](https://en.wikipedia.org/wiki/Sharp-P-complete).[^o20] Since counting the number of perfect matchings in a general graph is also #P-complete, some restriction on the input graph is required unless [FP](wikipedia://en/663347), the function version of [P](wikipedia://en/658550), is equal to [\#P](https://en.wikipedia.org/wiki/Sharp-P). Counting matchings, which is known as the [Hosoya index](wikipedia://en/14221581), is also #P-complete even for planar graphs.[^o21]

## Applications {#Applications}

The FKT algorithm has seen extensive use in [holographic algorithms](https://en.wikipedia.org/wiki/Holographic_algorithm) on planar graphs via [matchgates](https://en.wikipedia.org/wiki/Matchgates).[^o5] For example, consider the planar version of the ice model mentioned above, which has the technical name #[PL](wikipedia://en/24314)-3-NAE-[SAT](wikipedia://en/4715) (where NAE stands for "not all equal"). Valiant found a polynomial time algorithm for this problem which uses matchgates.[^o24]
