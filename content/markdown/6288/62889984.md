# Lean (proof assistant)

::: {#o2 .subject cue=lead name="Lean"}

**Lean** is a [proof assistant](wikipedia://en/1258607) and a [functional](https://en.wikipedia.org/wiki/Functional_programming) [programming language](wikipedia://en/23015).[^o3] It is based on the [calculus of constructions](wikipedia://en/613557) with [inductive types](wikipedia://en/22778065) (specifically, the Calculus of Inductive Constructions), the foundational type theory developed with the [Coq](wikipedia://en/581974) theorem prover,[^o4] which was renamed to [Rocq](wikipedia://en/581974) in 2024.[^o5] It is a [free and open-source software](https://en.wikipedia.org/wiki/Free_and_open-source_software) project hosted on [GitHub](https://en.wikipedia.org/wiki/GitHub). Development is currently supported by the [nonprofit](https://en.wikipedia.org/wiki/Nonprofit_organization) Lean [Focused Research Organization](https://en.wikipedia.org/wiki/Convergent_Research) (FRO).

:::

## History {#History}

Lean was developed primarily by Brazilian computer scientist [Leonardo de Moura](https://en.wikipedia.org/wiki/Leonardo_de_Moura) while employed by [Microsoft Research](https://en.wikipedia.org/wiki/Microsoft_Research) and now [Amazon Web Services](https://en.wikipedia.org/wiki/Amazon_Web_Services) and has had significant contributions from other coauthors and collaborators during its history.[^o7]

Launched in 2013,[^o8] initial versions of the language, later known as Lean 1 and 2, were experimental and contained features such as support for [homotopy type theory](wikipedia://en/33974223)-based foundations that were later dropped.

Lean 3 (first released Jan 20, 2017) was the first moderately stable version of Lean. It was implemented primarily in [C++](https://en.wikipedia.org/wiki/C++) with some features written in Lean itself. After version 3.4.2, Lean 3 was officially end-of-lifed while development of Lean 4 began. In this interim period members of the Lean community developed and released unofficial versions up to 3.51.1.[^o9]

In 2021, Lean 4 was released, which was a reimplementation of the Lean theorem prover capable of producing [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) code which is then compiled, enabling the development of efficient domain-specific automation.[^o10] Lean 4 also contains a [hygienic macro](https://en.wikipedia.org/wiki/Hygienic_macro) system and improved [type class](https://en.wikipedia.org/wiki/Type_class) synthesis and memory management procedures over the previous version.[^o11] Another benefit compared to Lean 3 is the ability to avoid touching C++ code in order to modify the frontend and other key parts of the core system, as they are now all implemented in Lean and available to the end user to be overridden as needed.[^o3]

Lean 4 is not [backwards-compatible](https://en.wikipedia.org/wiki/Backward_compatibility) with Lean 3.[^o12] It uses the [C++17](https://en.wikipedia.org/wiki/C++17) version of C++.[^o3]

In 2023, the Lean FRO (Focused Research Organization) was formed, with the goals of improving the language's scalability and usability, and implementing [proof automation](https://en.wikipedia.org/wiki/Proof_automation).[^o13]

In 2025, [ACM](https://en.wikipedia.org/wiki/Association_for_Computing_Machinery) [SIGPLAN Programming Languages Software Award](https://en.wikipedia.org/wiki/SIGPLAN#Programming_Languages_Software_Award) was awarded to Gabriel Ebner, Soonho Kong, [Leo de Moura](https://en.wikipedia.org/wiki/Leonardo_de_Moura) and Sebastian Ullrich for Lean, cited for its "significant impact on mathematics, hardware and software verification, and AI".[^o14]

In 2026, the *mathlib* library was awarded the Demailly prize for [open science](https://en.wikipedia.org/wiki/Open_science).[^o15]

## Overview {#Overview}

Lean includes many features useful for functional programming and theorem proving, such as [dependent types](https://en.wikipedia.org/wiki/Dependent_types), [type classes](https://en.wikipedia.org/wiki/Type_classes), multi-threading, an expressive tactic language, and a module system.[^o17]

::: {#o19 .pointer-item cue=pointer name="MathLib"}

### Libraries {#Libraries}

The official Lean [standard library](https://en.wikipedia.org/wiki/Standard_library) is called *Std* and contains common [data structures](wikipedia://en/8519) and functions useful for programming, such as tree maps, hash maps, datetime functions, and concurrency primitives.[^o20] The standard library is complemented by the community-maintained *batteries*, which implements additional data structures that may be used for both mathematical research and more conventional software development.[^o21]

In 2017, a community-maintained project to develop a Lean library *mathlib* began, with the goal to digitize as much of [pure mathematics](wikipedia://en/457210) as possible in one large cohesive library, up to research level mathematics.[^o22][^o23] As of May 2025, mathlib had formalized over 210,000 theorems and 100,000 definitions in Lean.[^o24]

Other libraries include *CSLib* which is a theoretical computer science library,[^o25] *SciLean* which is a library for scientific computing in Lean,[^o26] and *PhysLib*, whose goal is to digitize physics using Lean.[^o27]

:::

### Editor integration {#Editor_integration}

Lean integrates with [Visual Studio Code](https://en.wikipedia.org/wiki/Visual_Studio_Code) .[^o29] Interfacing is done via a client-extension and [Language Server Protocol](https://en.wikipedia.org/wiki/Language_Server_Protocol) server. In these editors, [Unicode](https://en.wikipedia.org/wiki/Unicode) symbols can be typed using [LaTeX](https://en.wikipedia.org/wiki/LaTeX)-like sequences, such as \\times for "×".

## Examples (Lean 4) {#Examples_(Lean_4)}

The [natural numbers](https://en.wikipedia.org/wiki/Natural_numbers) can be defined as an [inductive type](wikipedia://en/22778065). This definition is based on the [Peano axioms](wikipedia://en/25005) and states that every natural number is either zero or the [successor](wikipedia://en/325637) of some other natural number.

```lean4
inductive Nat : Type
  | zero : Nat
  | succ : Nat → Nat
```

Addition of natural numbers can be [defined recursively](wikipedia://en/1047605), using [pattern matching](https://en.wikipedia.org/wiki/Pattern_matching).

```lean4
def Nat.add : Nat → Nat → Nat
  | n, Nat.zero   => n                      -- n + 0 = n  
  | n, Nat.succ m => Nat.succ (Nat.add n m) -- n + succ(m) = succ(n + m)
```

This is a simple proof of $(P \wedge Q) \implies (Q \wedge P)$ for two [propositions](wikipedia://en/81094) $P$ and $Q$ (where is the [conjunction](wikipedia://en/18152) and $\implies$ the [implication](wikipedia://en/658808)) in Lean using tactic mode:

```lean4
theorem and_swap (p q : Prop) : p ∧ q → q ∧ p := by
  intro h            -- assume p ∧ q with proof h, the goal is q ∧ p
  apply And.intro    -- the goal is split into two subgoals, one is q and the other is p
  · exact h.right    -- the first subgoal is exactly the right part of h : p ∧ q
  · exact h.left     -- the second subgoal is exactly the left part of h : p ∧ q
```

This same proof in term mode:

```lean4
theorem and_swap (p q : Prop) : p ∧ q → q ∧ p :=
  fun ⟨hp, hq⟩ => ⟨hq, hp⟩
```

The theorem can also be proved using the grind tactic, which uses techniques from SMT solvers to automatically construct proofs:

```lean4
theorem and_swap (p q : Prop) : p ∧ q → q ∧ p := by
  grind
```

## Usage {#Usage}

### Mathematics {#Mathematics}

Lean has received attention from mathematicians such as [Thomas Hales](wikipedia://en/2388356),[^o33] [Kevin Buzzard](wikipedia://en/9277730),[^o67] [Terence Tao](wikipedia://en/1118498),[^o34] and Heather Macbeth.[^o35] Hales is using it for his project, Formal Abstracts.[^o36] Buzzard uses it for the Xena project.[^o37] One of the Xena Project's goals is to rewrite every theorem and proof in the undergraduate maths curriculum of [Imperial College London](https://en.wikipedia.org/wiki/Imperial_College_London) in Lean. Tao released a Lean companion to his [real analysis](https://en.wikipedia.org/wiki/Real_Analysis) textbook *Analysis I*, consisting of a formalization of selected sections of the mathematical text.[^o38] Macbeth is using Lean to teach students the fundamentals of mathematical proof with instant feedback.[^o39]

#### Noteworthy formalizations {#Noteworthy_formalizations}

In 2021, a team of researchers used Lean to verify the correctness of a proof by [Peter Scholze](wikipedia://en/39409306) in the area of [condensed mathematics](wikipedia://en/68011960). The project garnered attention for formalizing a result at the cutting edge of mathematical research.[^o41] In 2023, Terence Tao used Lean to formalize a proof of the [Polynomial Freiman-Ruzsa](wikipedia://en/2240299) (PFR) conjecture, a result published by Tao and collaborators in the same year.[^o42] In 2026, [Erdős Problems](wikipedia://en/336815) 728,[^o43] 347,[^o44] and 369[^o45] were solved using AI assistance and formally verified with Lean.

### Physics {#Physics}

Physlib[^o47] aspires to be the definitive library for physics in Lean, akin to Mathlib for mathematics. It aims to be a comprehensive repository containing fundamental definitions, theorems, and calculations from physics. [Kevin Buzzard](wikipedia://en/9277730) at [Imperial College London](https://en.wikipedia.org/wiki/Imperial_College_London) says[^o48] that formalization is having a big impact on mathematics, and that there is no reason that theoretical physics can not be treated in the same way.

> “Ideally, we need a million lines of physics, and that might be hard work to get. If the machines aren’t pretty good at doing physics initially, then there’ll be manual work at the beginning, and then eventually the machines will hopefully take over”

#### Noteworthy formalizations {#Noteworthy_formalizations}

In 2025, Joseph Tooby-Smith used Lean to discover an error[^o48] in a paper[^o50] published in 2006 on the stability of the [Two-Higgs-doublet model](https://en.wikipedia.org/wiki/Two-Higgs-doublet_model) (2HDM) potential.

### Artificial intelligence {#Artificial_intelligence}

In 2022, [OpenAI](https://en.wikipedia.org/wiki/OpenAI) and [Meta AI](https://en.wikipedia.org/wiki/Meta_AI) independently created AI models to generate proofs of various high-school-level olympiad problems in Lean.[^o52] Meta AI's model is available for public use with the Lean environment.[^o53]

In 2023, [Vlad Tenev](https://en.wikipedia.org/wiki/Vlad_Tenev) and Tudor Achim co-founded startup Harmonic, which aims to reduce [AI hallucinations](https://en.wikipedia.org/wiki/Hallucination_%28artificial_intelligence%29) by generating and checking Lean code.[^o54]

In 2024, [Google DeepMind](https://en.wikipedia.org/wiki/Google_DeepMind) created [AlphaProof](https://en.wikipedia.org/wiki/Google_DeepMind#AlphaProof)[^o55] which proves mathematical statements in Lean at the level of a silver medalist at the [International Mathematical Olympiad](wikipedia://en/82208). This was the first AI system that achieved a medal-worthy performance on a math olympiad's problems.[^o56]

In April 2025, [DeepSeek](wikipedia://en/78452842) introduced DeepSeek-Prover-V2, an AI model designed for theorem proving in Lean 4, built on top of DeepSeek-V3.[^o57]

In 2026, AIs designed to spot bugs in software were directed at Lean, and found several loopholes which were then fixed. Perhaps related to this effort, a purported disproof of the [Collatz conjecture](wikipedia://en/37895) was announced as verified in Lean. However, this proof was soon determined to rely on a bug in Lean, and once the bug was fixed the proof was found invalid.[^o58][^o59][^o60]

In September 2026, [Anthropic](https://en.wikipedia.org/wiki/Anthropic) reported that agents running an internal research model comparable to [Claude](https://en.wikipedia.org/wiki/Claude_%28AI%29) Fable 5.1 had produced a complete, machine-checked formalization of [Fermat's Last Theorem](wikipedia://en/19021953) in Lean 4 in eleven days.[^o61][^o62] The proof followed the 1995 exposition by Darmon, Diamond and Taylor of [Wiles's proof](wikipedia://en/21950759), comprised about 13 million lines of Lean code and roughly 30,000 intermediate theorems, and relied only on Lean's three standard axioms; the agents coordinated through Prove2Me, a platform for collaborative formalization developed by Anthropic researcher Tianyi Peng and collaborators at [Columbia University](https://en.wikipedia.org/wiki/Columbia_University).[^o61][^o63] [Kevin Buzzard](wikipedia://en/9277730), who leads a separate [Imperial College London](https://en.wikipedia.org/wiki/Imperial_College_London) project to formalize the theorem in Lean, compiled and checked the code and confirmed the result, while noting that it "adds nothing" mathematically to Wiles's proof and that the code could not be merged into Mathlib.[^o62][^o64] Buzzard said the Imperial project would continue.[^o64]
