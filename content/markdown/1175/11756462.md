# Hybrid cryptosystem

::: {#o1 .subject cue=lead name="Hybrid cryptosystem"}

In [cryptography](wikipedia://en/18934432), a **hybrid cryptosystem** is one which combines the convenience of a [public-key cryptosystem](https://en.wikipedia.org/wiki/Public-key_cryptosystem) with the efficiency of a [symmetric-key cryptosystem](https://en.wikipedia.org/wiki/Symmetric-key_cryptography).[^o2] Public-key cryptosystems are convenient in that they do not require the sender and receiver to share a [common secret](wikipedia://en/7111246) in order to communicate securely.[^o3] However, they often rely on complicated mathematical computations and are thus generally much more inefficient than comparable symmetric-key cryptosystems. In many applications, the high cost of encrypting long messages in a public-key cryptosystem can be prohibitive. This is addressed by hybrid systems by using a combination of both.[^o4]

:::

A hybrid cryptosystem can be constructed using any two separate cryptosystems:

- a [key encapsulation mechanism](wikipedia://en/8597625), which is a public-key cryptosystem
- a [data encapsulation scheme](wikipedia://en/53042), which is a symmetric-key cryptosystem

The hybrid cryptosystem is itself a public-key system, whose public and private keys are the same as in the key encapsulation scheme.[^o17]

Note that for very long messages the bulk of the work in encryption/decryption is done by the more efficient symmetric-key scheme, while the inefficient public-key scheme is used only to encrypt/decrypt a short key value.[^o4]

## Implementations and standards {#Implementations_and_standards}

All practical implementations of public key cryptography today employ a hybrid system. Examples include the [TLS](wikipedia://en/187813) protocol [^o6] and the [SSH](wikipedia://en/28814) protocol,[^o7] that use a public-key mechanism for key exchange (such as [Diffie-Hellman](wikipedia://en/7903)) and a symmetric-key mechanism for data encapsulation (such as [AES](wikipedia://en/1260)). The [OpenPGP](https://en.wikipedia.org/wiki/OpenPGP)[^o8] [file format](https://en.wikipedia.org/wiki/File_format) and the [PKCS#7](wikipedia://en/616418#7)[^o9] file format are other examples.

Hybrid Public Key Encryption (HPKE, published as [RFC 9180](https://datatracker.ietf.org/doc/rfc9180/)) is a modern standard for generic hybrid encryption. HPKE is used within multiple IETF protocols, including [Messaging Layer Security (MLS)](https://en.wikipedia.org/wiki/Messaging_Layer_Security), [Oblivious DNS over HTTPS](https://en.wikipedia.org/wiki/Oblivious_DNS_over_HTTPS), [Oblivious HTTP](wikipedia://en/79378523), [Privacy Preserving Measurement](https://en.wikipedia.org/wiki/Privacy_Preserving_Measurement), and TLS [Encrypted Client Hello](https://en.wikipedia.org/wiki/Encrypted_Client_Hello).[^o10]

Envelope encryption is an example of a usage of hybrid cryptosystems in [cloud computing](https://en.wikipedia.org/wiki/Cloud_computing). In a cloud context, hybrid cryptosystems also enable centralized [key management](wikipedia://en/631063).[^o11][^o12]

::: {#o14 .example cue=heading name="Example"}

## Example {#Example}

To encrypt a message addressed to Alice in a hybrid cryptosystem, Bob does the following:

1. Obtains Alice's public key.
1. Generates a fresh symmetric key for the data encapsulation scheme.
1. Encrypts the message under the data encapsulation scheme, using the symmetric key just generated.
1. Encrypts the symmetric key under the key encapsulation scheme, using Alice's public key.
1. Sends both of these [ciphertexts](https://en.wikipedia.org/wiki/Ciphertexts) to Alice.

To decrypt this hybrid ciphertext, Alice does the following:

1. Uses her private key to decrypt the symmetric key contained in the key encapsulation segment.
1. Uses this symmetric key to decrypt the message contained in the data encapsulation segment.[^o15][^o2]

:::

## Security {#Security}

If both the key encapsulation and data encapsulation schemes in a hybrid cryptosystem are secure against [adaptive chosen ciphertext attacks](https://en.wikipedia.org/wiki/Adaptive_chosen_ciphertext_attack), then the hybrid scheme inherits that property as well.[^o17] However, it is possible to construct a hybrid scheme secure against adaptive chosen ciphertext attacks even if the key encapsulation has a slightly weakened security definition (though the security of the data encapsulation must be slightly stronger).[^o18]

## Envelope encryption {#Envelope_encryption}

Envelope encryption is term used for encrypting with a hybrid cryptosystem used by all major [cloud service providers](https://en.wikipedia.org/wiki/Cloud_service_provider),[^o11] often as part of a centralized [key management](wikipedia://en/631063) system in cloud computing.[^o21]

Envelope encryption gives names to the keys used in hybrid encryption: Data Encryption Keys (abbreviated DEK, and used to encrypt data) and Key Encryption Keys (abbreviated KEK, and used to encrypt the DEKs). In a cloud environment, encryption with envelope encryption involves generating a DEK locally, encrypting one's data using the DEK, and then issuing a request to wrap (encrypt) the DEK with a KEK stored in a potentially more secure [service](https://en.wikipedia.org/wiki/Service_%28computer_science%29). Then, this wrapped DEK and encrypted message constitute a [ciphertext](wikipedia://en/175560) for the scheme. To decrypt a ciphertext, the wrapped DEK is unwrapped (decrypted) via a call to a service, and then the unwrapped DEK is used to decrypt the encrypted message.[^o12] In addition to the normal advantages of a hybrid cryptosystem, using asymmetric encryption for the KEK in a cloud context provides easier key management and separation of roles, but can be slower.[^o21]

In cloud systems, such as [Google Cloud Platform](https://en.wikipedia.org/wiki/Google_Cloud_Platform) and [Amazon Web Services](https://en.wikipedia.org/wiki/Amazon_Web_Services), a key management system (KMS) can be available as a service.[^o21][^o12][^o22] In some cases, the key management system will store keys in [hardware security modules](https://en.wikipedia.org/wiki/Hardware_security_modules), which are hardware systems that protect keys with hardware features like intrusion resistance.[^o23] This means that KEKs can also be more secure because they are stored on secure specialized hardware.[^o21] Envelope encryption makes centralized key management easier because a centralized key management system only needs to store KEKs, which occupy less space, and requests to the KMS only involve sending wrapped and unwrapped DEKs, which use less bandwidth than transmitting entire messages. Since one KEK can be used to encrypt many DEKs, this also allows for less storage space to be used in the KMS. This also allows for centralized auditing and [access control](https://en.wikipedia.org/wiki/Access_control) at one point of access.[^o12]
