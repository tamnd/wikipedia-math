# Fixed-point combinator

::: {#o1 .subject cue=lead name="Fixed-point combinator"}

In [combinatory logic](wikipedia://en/149848) for [computer science](https://en.wikipedia.org/wiki/Computer_science), a **fixed-point combinator** (or **fixpoint combinator**)[^o2] is a [higher-order function](https://en.wikipedia.org/wiki/Higher-order_function) (i.e., a [function](wikipedia://en/185427) that takes a function as [argument](wikipedia://en/32842052)) that returns some *[fixed point](wikipedia://en/449738)* (a value that is mapped to itself) of its argument function, if one exists.

:::

Formally, if $\mathrm{fix}$ is a fixed-point combinator and the function $f$ has one or more fixed points, then $\mathrm{fix}\ f$ is one of these fixed points, i.e.,

$$\mathrm{fix}\ f\ = f\ (\mathrm{fix}\ f) .$$

Fixed-point combinators can be defined in the [lambda calculus](wikipedia://en/18203) and in [functional programming](https://en.wikipedia.org/wiki/Functional_programming) languages, and provide a means to allow for [recursive definitions](wikipedia://en/4044867).

## Introduction {#Introduction}

Applied to a non-constant function of one variable that treats its argument as a piece of data (such as e.g. the sine function), the Y combinator usually does not terminate. Y really is meant to be used with codata, e.g. a colist constructor that places the first element there and expects "the rest of elements" as an argument, that will be fleshed out later; or a higher-order function that expects to be supplied as its first argument with a function "to compute the rest," which it might or might not call, as needed.

Applied to such "one step functional," Y arranges for the creation of that "rest of computation" function, consisting of that same step it was given and the "rest of computation" again, which really means just the original step repeated as many times as needed, calling "the rest" function as and if needed, but not always. The resulting function behaves like a *while* or a *for* loop. Used in this way, the Y combinator implements general [recursion](wikipedia://en/4044867).

The lambda calculus does not have global names, for a function to refer to itself by name inside its own definition, as is possible in many [programming languages](wikipedia://en/23015). But it has local names, i.e. parameters in lambda abstractions. An abstraction term can receive another term as an argument, and refer to that argument by the parameter name inside the function's body.

The Y combinator may also be used in implementing [Curry's paradox](wikipedia://en/154163). The heart of Curry's paradox is that untyped lambda calculus is unsound as a deductive system, and the Y combinator demonstrates this by allowing an anonymous expression to represent zero, or even many values. This is inconsistent in [mathematical logic](wikipedia://en/19636).

### Y combinator in lambda calculus {#Y_combinator_in_lambda_calculus}

In the classical untyped [lambda calculus](wikipedia://en/18203), every function has a fixed point. A particular implementation of $\mathrm{fix}$ is [Haskell Curry](wikipedia://en/42182)'s paradoxical combinator Y, given by[^o5][^o6][^o7]

$$\mathrm Y = \lambda f. \ (\lambda x.f\ (x\ x))\ (\lambda x.f\ (x\ x))$$

(Here using the standard notations and conventions of lambda calculus: Y is a function that takes one argument *f* and returns the entire expression following the first period; the expression $\lambda x.f\ (x\ x)$ denotes a function that takes one argument *x*, thought of as a function, and returns the expression $f\ (x\ x)$, where $(x\ x)$ denotes *x* applied to itself. Juxtaposition of expressions denotes [function application](wikipedia://en/20576545), is left-associative, and has higher precedence than the period.)

### Verification {#Verification}

The following calculation verifies that $\mathrm Y g$ is indeed a fixed point of the function $g$:

{| cellpadding="0"

\| $\mathrm Y\ g\$ | $\triangleq (\lambda f.(\lambda x.f\ (x\ x))\ (\lambda x.f\ (x\ x)))\ g\ \ \$ | by the definition of $\mathrm Y$ |- | | $=_{_{\beta}} (\lambda x.g\ (x\ x))\ (\lambda x.g\ (x\ x))\$ | by [β-reduction](https://en.wikipedia.org/wiki/Β-reduction): replacing the formal argument *f* of Y with the actual argument *g* |- | | $=_{_{\beta}} g\ ((\lambda x.g\ (x\ x))\ (\lambda x.g\ (x\ x)))\$ | by β-reduction: replacing the formal argument *x* of the first function with the actual argument $(\lambda x.g\ (x\ x))$ |- | | $\equiv g\ (\mathrm Y\ g)$ | by second equality, above |}

The lambda term $g\ (\mathrm Y\ g)$ may not, in general, [β-reduce](https://en.wikipedia.org/wiki/Β-reduction) to the term $\mathrm Y\ g$. However, both terms β-reduce to the same term, as shown.

### Example implementations {#Example_implementations}

An example implementation of Y in the language [R](wikipedia://en/376707) is presented below:

```r
Y <- \(f) {
  g <- \(x) f(x(x))
  g(g)
}
```

This can then be used to implement factorial as follows:

```r
fact <- \(f) \(n)
  if (n == 0) 1 else n * f(n - 1)
  
Y(fact)(5) # yields 5! = 120
```

Y is only needed when function names are absent. Substituting all the definitions into one line so that function names are not required gives:

```r
(\(f) (\(x) f(x(x)))(\(x) f(x(x)))) (\(f) \(n) if (n == 0) 1 else n * f(n - 1)) (5)
```

This works because R uses [lazy evaluation](https://en.wikipedia.org/wiki/Lazy_evaluation).

Languages that use [strict evaluation](https://en.wikipedia.org/wiki/Strict_evaluation), such as [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29), [C++](https://en.wikipedia.org/wiki/C++), and other [strict programming languages](https://en.wikipedia.org/wiki/Strict_programming_language), can often express Y; however, any implementation is useless in practice since it [loops indefinitely](https://en.wikipedia.org/wiki/Infinite_loop) until terminating via a [stack overflow](https://en.wikipedia.org/wiki/Stack_overflow).

## Fixed-point combinator {#Fixed-point_combinator}

The Y combinator is an implementation of a fixed-point combinator in lambda calculus. Fixed-point combinators may also be easily defined in other functional and imperative languages. The implementation in lambda calculus is more difficult due to limitations in lambda calculus. The fixed-point combinator may be used in a number of different areas:

- General [mathematics](wikipedia://en/18831)
- Untyped [lambda calculus](wikipedia://en/18203)
- [Typed lambda calculus](wikipedia://en/366208)
- [Functional programming](https://en.wikipedia.org/wiki/Functional_programming)
- [Imperative programming](https://en.wikipedia.org/wiki/Imperative_programming)

Fixed-point combinators may be applied to a range of different functions, but normally will not terminate unless there is an extra parameter. When the function to be fixed refers to its parameter, another call to the function is invoked, so the calculation never gets started. Instead, the extra parameter is used to trigger the start of the calculation.

The type of the fixed point is the return type of the function being fixed. This may be a real or a function or any other type.

In the untyped lambda calculus, the function to apply the fixed-point combinator to may be expressed using an encoding, like [Church encoding](wikipedia://en/2989409). In this case particular lambda terms (which define functions) are considered as values. "Running" (beta reducing) the fixed-point combinator on the encoding gives a lambda term for the result, which may then be interpreted as fixed-point value.

Alternately, a function may be considered as a lambda term defined purely in lambda calculus.

These different approaches affect how a mathematician and a programmer may regard a fixed-point combinator. A mathematician may see the Y combinator applied to a function as being an expression satisfying the fixed-point equation, and therefore a solution.

In contrast, a person only wanting to apply a fixed-point combinator to some general programming task may see it only as a means of implementing recursion.

### Values and domains {#Values_and_domains}

Many functions do not have any fixed points, for instance $f : \mathbb{N} \to \mathbb{N}$ with $f(n)=n+1$. Using [Church encoding](wikipedia://en/2989409), natural numbers can be represented in lambda calculus, and this function *f* can be defined in lambda calculus. However, its [domain](wikipedia://en/50263) will now contain *all* lambda expressions, not just those representing natural numbers. The Y combinator, applied to *f*, will yield a fixed-point for *f*, but this fixed-point won't represent a [natural number](wikipedia://en/21474). If trying to compute Y *f* in an actual programming language, an infinite loop will occur.

### Function versus implementation {#Function_versus_implementation}

The fixed-point combinator may be defined in mathematics and then implemented in other languages. General mathematics defines a function based on its [extensional](wikipedia://en/294056) properties.[^o13] That is, two functions are equal if they perform the same mapping. Lambda calculus and programming languages regard function identity as an [intensional](https://en.wikipedia.org/wiki/Intensional_definition) property. A function's identity is based on its implementation.

A lambda calculus function (or term) is an implementation of a mathematical function. In the lambda calculus there are a number of combinators (implementations) that satisfy the mathematical definition of a fixed-point combinator.

### Definition of the term "combinator" {#Definition_of_the_term_"combinator"}

[Combinatory logic](wikipedia://en/149848) is a [higher-order functions](https://en.wikipedia.org/wiki/Higher-order_function) theory. A [combinator](https://en.wikipedia.org/wiki/Combinator) is a *closed* lambda expression, meaning that it has no [free variables](wikipedia://en/147460). The combinators may be combined to direct values to their correct places in the expression without ever naming them as variables.

## Recursive definitions and fixed-point combinators {#Recursive_definitions_and_fixed-point_combinators}

Fixed-point combinators can be used to implement [recursive definition](wikipedia://en/1047605) of functions. However, they are rarely used in practical programming.[^o16] [Strongly normalizing](https://en.wikipedia.org/wiki/Strongly_normalizing) [type systems](wikipedia://en/199701) such as the [simply typed lambda calculus](wikipedia://en/1986011) disallow non-termination and hence fixed-point combinators often cannot be assigned a type or require complex type system features. Furthermore, fixed-point combinators are often inefficient compared to other strategies for implementing recursion, as they require more function reductions and construct and take apart a tuple for each group of mutually recursive definitions.[^o2]

### The factorial function {#The_factorial_function}

The [factorial function](wikipedia://en/10606) provides a good example of how a fixed-point combinator may be used to define recursive functions. The standard recursive definition of the factorial function in mathematics can be written as

$$\operatorname{fact}\ n = \begin{cases} 1 & \text{if} ~ n = 0 \\ n \times \operatorname{fact}(n - 1) & \text{otherwise.} \end{cases}$$

where *n* is a non-negative [integer](wikipedia://en/14563).

This poses a problem, though, as $\operatorname{fact}$ inside the definition of $\operatorname{fact}$ cannot possibly signify the inclusion of the definition as a whole inside itself. Instead, as it normally goes almost unnoticed, it is the reference to the definition by its *name*. This presupposes the existence of a global registry of names, so called "environment". And the lambda calculus lacks this entirely.

Still, name references do exist in lambda calculus – local names, names of parameters of a given function. And thus the above can be re-written as

$$\begin{aligned} &\operatorname{fact}(n) = \operatorname{f} (\operatorname{f},n) \\ &\quad \text{where} \\ &\quad \operatorname{f} (s,n) = \begin{cases} 1 & \text{if} ~ n = 0 \\ n \times s(s,n - 1) & \text{otherwise} \end{cases} \end{aligned}$$

Splitting off a separate copy of $\operatorname{f}$ and passing it as an argument to itself makes it available to itself to be called, as and if needed, inside itself. In such a call it must again be passed along as an argument so it will be available to the next invocation, and so on, as the chain of invocations progresses. The definition of $\operatorname{f}$ is *open recursive*, and calling $\operatorname{f}$ with itself as an argument at the top closes the circle.

Implementing this in lambda calculus is now trivial, and directly leads to the definition of the Y combinator, one instance of a fixed-point combinator, such that $\operatorname{fix} f = f\,(\operatorname{fix} f)$. Or directly, define a function *F* of two arguments *f* and *n*:

$$F\ f\ n = (\operatorname{IsZero}\ n)\ 1\ (\operatorname{multiply}\ n\ (f\ (\operatorname{pred}\ n)))$$

(Here $(\operatorname{IsZero}\ n)$ is a function that takes two arguments and returns its first argument if *n*=0, and its second argument otherwise; $\operatorname{pred}\ n$ evaluates to *n*–1.)

Now define $\operatorname{fact}=\textsf{fix}\ F = F\ (\textsf{fix}\ F)$. Then $\operatorname{fact}$ is a fixed-point of *F*, which gives

$$\begin{aligned} \operatorname{fact} n &= F\ \operatorname{fact}\ n \\ &= (\operatorname{IsZero}\ n)\ 1\ (\operatorname{multiply}\ n\ (\operatorname{fact}\ (\operatorname{pred}\ n)))\ \end{aligned}$$

as desired.

## Fixed-point combinators in lambda calculus {#Fixed-point_combinators_in_lambda_calculus}

The Y combinator, discovered by [Haskell Curry](wikipedia://en/42182), is defined as

$$Y = \lambda f.(\lambda x.f\ (x\ x)) \ (\lambda x.f\ (x\ x))$$

### Other fixed-point combinators {#Other_fixed-point_combinators}

In untyped lambda calculus fixed-point combinators are not especially rare. In fact there are infinitely many of them.[^o20] In 2005 Mayer Goldberg showed that the set of fixed-point combinators of untyped lambda calculus is [recursively enumerable](https://en.wikipedia.org/wiki/Recursively_enumerable).[^o21]

The Y combinator can be expressed in the [SKI-calculus](wikipedia://en/1232841#Self-application_and_recursion) as

$$\mathsf{Y = S (K (S I I)) (S (S (K S) K) (K (S I I))) = S S (S (S (K S) K)) (K (S I I))}$$

Additional combinators ([B, C, K, W system](wikipedia://en/550740)) allow for much shorter encodings. With $\mathsf{U = SII}$ the self-application combinator, since $\mathsf S(\mathsf Kx)yz = x(yz) = \mathsf Bxyz$ and $\mathsf Sx(\mathsf Ky)z = xzy = \mathsf Cxyz$, the above becomes

$$\mathsf{Y = S (K U) (S B (K U)) = B U (C B U)} \ \ \ ; \ \ \mathsf{Y = S S I (B W B)}$$

The shortest fixed-point combinator in the SK-calculus using S and K combinators only, found by [John Tromp](https://en.wikipedia.org/wiki/John_Tromp), is

$$\mathsf{Y' = S S K (S (K (S S (S (S S K)))) K) = W C (S B (C (W C)))}$$

although note that it is not in normal form, which is longer. This combinator corresponds to the lambda expression

$$\mathsf Y' = (\lambda x y. x y x) (\lambda y x. y (x y x))$$

The following fixed-point combinator is simpler than the Y combinator, and β-reduces into the Y combinator; it is sometimes cited as the Y combinator itself:

$$\mathsf X = \lambda f.(\lambda x.x x) (\lambda x.f (x x)) \ \ \ ; \ \ \mathsf{X f = U (B f U)}$$

Another common fixed-point combinator is the Turing fixed-point combinator (named after its discoverer, [Alan Turing](wikipedia://en/1208)):[^o22][^o5]

$$\Theta = (\lambda x y. y (x x y))\ (\lambda x y. y (x x y)) = \mathsf{S I I (S (K (S I)) (S I I)) = U (B (S I) U)}$$

Its advantage over $\mathsf Y$ is that $\Theta\ f$ beta-reduces to $f\ (\Theta f)$,[^o23] whereas $\mathsf Y\ f$ and $f\ (\mathsf Y f)$ only beta-reduce to a common term.

$\Theta$ also has a simple [call-by-value](https://en.wikipedia.org/wiki/Call-by-value) form:

$$\Theta_{v} = (\lambda x y. y (\lambda z. x x y z))\ (\lambda x y. y (\lambda z. x x y z))$$

The analog for [mutual recursion](https://en.wikipedia.org/wiki/Mutual_recursion) is a *polyvariadic fix-point combinator*,[^o24][^o25][^o26] which may be denoted Y\*.

### Strict fixed-point combinator {#Strict_fixed-point_combinator}

In a [strict programming language](https://en.wikipedia.org/wiki/Strict_programming_language) the Y combinator will expand until [stack overflow](https://en.wikipedia.org/wiki/Stack_overflow), or never halt in case of [tail call optimization](https://en.wikipedia.org/wiki/Tail_call_optimization).[^o28] The Z combinator will work in [strict languages](https://en.wikipedia.org/wiki/Strict_programming_language) (also called eager languages, where applicative evaluation order is applied). The Z combinator has the next argument defined explicitly, preventing the expansion of $Z g$ in the right-hand side of the definition:[^o29]

$$Z g v = g (Z g) v\ .$$

and in lambda calculus it is an [eta-expansion](https://en.wikipedia.org/wiki/Eta_expansion) of the Y combinator:

$$Z = \lambda f.(\lambda x.f (\lambda v.x x v)) \ (\lambda x.f (\lambda v.x x v))\ .$$

### Non-standard fixed-point combinators {#Non-standard_fixed-point_combinators}

If F is a fixed-point combinator in untyped lambda calculus, then there is:

$$\mathsf F=\lambda x. F x = \lambda x. x (F x)= \lambda x. x (x (F x)) = \cdots$$

Terms that have the same [Böhm tree](wikipedia://en/27453243) as a fixed-point combinator, i.e., have the same infinite extension $\lambda x.x (x (x \cdots ))$, are called *non-standard fixed-point combinators*. Any fixed-point combinator is also a non-standard one, but not all non-standard fixed-point combinators are fixed-point combinators because some of them fail to satisfy the fixed-point equation that defines the "standard" ones. These combinators are called *strictly non-standard fixed-point combinators*; an example is the following combinator:

$$\mathsf{N = B U (B (B U) B)}$$

where

$$\mathsf B = \lambda x y z.x (y z)$$

$$\mathsf U = \lambda x.x x\$$

since

$$\mathsf N=\lambda x. N x = \lambda x. x (N_2 x)= \lambda x. x (x (x (N_3 x))) = \lambda x. x (x (x (x (x (x (N_4 x)))))) = \cdots$$

where $\mathsf N_i$ are modifications of $\mathsf N$ created on the fly which add $i$ instances of $x$ at once into the chain while being replaced with $\mathsf N_{i+1}$.

The set of non-standard fixed-point combinators is not [recursively enumerable](https://en.wikipedia.org/wiki/Recursively_enumerable).[^o21]

## Implementation in other languages {#Implementation_in_other_languages}

The Y combinator is a particular implementation of a fixed-point combinator in lambda calculus. Its structure is determined by the limitations of lambda calculus. It is not necessary or helpful to use this structure in implementing the fixed-point combinator in other languages.

Simple examples of fixed-point combinators implemented in some [programming paradigms](https://en.wikipedia.org/wiki/Programming_paradigm) are given below.

### Lazy functional implementation {#Lazy_functional_implementation}

In a language that supports [lazy evaluation](https://en.wikipedia.org/wiki/Lazy_evaluation), as in [Haskell](https://en.wikipedia.org/wiki/Haskell), it is possible to define a fixed-point combinator using the defining equation of the fixed-point combinator which is conventionally named `fix`. Since Haskell has lazy [data types](https://en.wikipedia.org/wiki/Data_type), this combinator can also be used to define fixed points of data constructors (and not only to implement recursive functions). The definition is given here, followed by some usage examples. In Hackage, the original sample is:[^o33]

```haskell
fix, fix' :: (a -> a) -> a
fix f = let x = f x in x         -- Lambda dropped. Sharing.
                                 -- Original definition in Data.Function.
-- alternative:
fix' f = f (fix' f)              -- Lambda lifted. Non-sharing.

fix (\x -> 9)                    -- this evaluates to 9

fix (\x -> 3:x)                  -- evaluates to the lazy infinite list [3,3,3,...]

fact = fix fac                   -- evaluates to the factorial function
  where fac f 0 = 1
        fac f x = x * f (x-1)

fact 5                           -- evaluates to 120
```

### Strict functional implementation {#Strict_functional_implementation}

In a strict functional language, as illustrated below with [OCaml](https://en.wikipedia.org/wiki/OCaml), the argument to *f* is expanded beforehand, yielding an infinite call sequence,

$$f\ (f ... (f\ (\mathsf{fix}\ f))... )\ x.$$

This may be resolved by defining fix with an extra parameter.

```ocaml
let rec fix f x = f (fix f) x (* note the extra x; hence fix f = \x-> f (fix f) x *)

let factabs fact = function   (* factabs has extra level of lambda abstraction *)
   0 -> 1
 | x -> x * fact (x-1)

let _ = (fix factabs) 5       (* evaluates to "120" *)
```

In a multi-paradigm functional language (one decorated with imperative features), such as [Lisp](https://en.wikipedia.org/wiki/Lisp_%28programming_language%29), [Peter Landin](https://en.wikipedia.org/wiki/Peter_Landin) suggested the use of a variable assignment to create a fixed-point combinator,[^o35] as in the below example using [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29):

```scheme
(define Y!
  (lambda (f)
    ((lambda (g)                       
       (set! g (f (lambda (x) (g x)))) ;; (set! g expr) assigns g the value of expr,
       g)                              ;; replacing g's initial value of #f, creating 
     #f)))                             ;; thus the truly self-referential value in g
```

Using a lambda calculus with axioms for assignment statements, it can be shown that `Y!` satisfies the same fixed-point law as the call-by-value Y combinator:[^o36][^o37]

$$(Y_!\ \lambda x.e) e' = (\lambda x.e)\ (Y_!\ \lambda x.e) e'$$

In more idiomatic modern Scheme usage, this would typically be handled via a `letrec` expression, as [lexical scope](https://en.wikipedia.org/wiki/Lexical_scope) was introduced to Lisp in the 1970s:

```scheme
(define Y*
  (lambda (f)
    (letrec                           ;; (letrec ((g expr)) ...) locally defines g 
         ((g                          ;; as expr recursively: g in expr refers to 
            (f (lambda (x) (g x)))))  ;; that same g being defined, g = f (λx. g x)
	   g)))                           ;; ((Y* f) ...) = (g ...) = ((f (λx. g x)) ...)
```

Or without the internal label:

```scheme
(define Y*
  (lambda (f)
    ((lambda (i) (i i))
     (lambda (i)
       (f (lambda x
	        (apply (i i) x)))))))
```

### Imperative language implementation {#Imperative_language_implementation}

This example is a slightly interpretive implementation of a fixed-point combinator. A class is used to contain the `fix()` function, called `FixedPointCombinator`, using [CRTP](https://en.wikipedia.org/wiki/Curiously_recurring_template_pattern). The function to be fixed is contained in a class that inherits from fixer. The `fix()` function accesses the function to be fixed using a [concept](https://en.wikipedia.org/wiki/Concepts_%28C++%29) to call `apply()`. As for the strict functional definition, `fix()` is explicitly given an extra parameter `x`, which means that lazy evaluation is not needed.

```cpp
using std::same_as;

template <typename R, typename T, typename Self>
concept FixedPointApplicable = requires (T x) {
    { Self::apply(x) } -> same_as<R>;
};

template <typename R, typename T, FixedPointApplicable<R, T> Self>
class FixedPointCombinator {
protected:
    FixedPointCombinator() = default;
public:
    static R fix(T x) noexcept {
        return Self::apply(x);
    }
};

class Factorial : public FixedPointCombinator<long, long, Factorial> {
private:
    Factorial() = default;
public:
    static long apply(long x) noexcept {
        if (x == 0) {
            return 1;
        }
        return x * fix(x - 1);
    }
};

long result = Factorial::fix(5);
```

Using only lambdas, one can create a fixed-point combinator like so:

```cpp
auto fix = [](auto f) {
    return [f](auto&&... args) -> decltype(auto) {
        return f(f, std::forward<decltype(args)>(args)...);
    };
};

auto factorial = fix([](auto self, long n) -> long {
    return n == 0 ? 1 : n * self(self, n - 1);
});

std::println("5! = {}", factorial(5)); // prints 120
```

Another example can be shown to demonstrate [SKI combinator calculus](wikipedia://en/1232841) (with given bird name from [combinatory logic](wikipedia://en/149848)) being used to build up Z combinator to achieve [tail call](https://en.wikipedia.org/wiki/Tail_call)-like behavior through trampolining:

```typescript
// Combinators
const K = <A, B>(a: A) => (_b: B) => a; // Kestrel
const S = <A, B, C>(a: (x: C) => (y: B) => A) => (b: (x: C) => B) => (c: C) => a(c)(b(c)); // Starling

// Derived combinators
const I = S(K)(K); // Identity
const B = S(K(S))(K); // Bluebird
const C = S(B(B)(S))(K(K)); // Cardinal
const W = C(S)(I); // Warbler
const T = C(I); // Thrush
const V = B(C)(T); // Vireo
const I1 = C(C(I)); // Identity Bird Once Removed; same as C(B(B)(I))(I)
const C1 = B(C); // Cardinal Once Removed
const R1 = C1(C1); // Robin Once Removed
const V1 = B(R1)(C1); // Vireo Once Removed
const I2 = R1(V); // Identity Bird Twice Removed

// Z combinators
const Z = B(W(I1))(V1(B)(W(I2)));

const Z2 = S(K(S(S(K(S(S(K)(K))(S(K)(K))))(S(K(S(K(S))(K)))(S(K(S(S(K)(K))))(K))))(K(S(S(K))))))(S(S(K(S(S(K(S(K(S))(K)))(S))(K(K))))(S(K(S(S(K(S(K(S))(K)))(S))(K(K))))(S(K(S))(K))))(K(S(S(K(S(S(K)(K))(S(K)(K))))(S(K(S(K(S))(K)))(S(K(S(S(K)(K))))(K))))(K(S(K(S(S(K(S(S(K(S(K(S))(K)))(S))(K(K))))(S(K(S(S(K(S(K(S))(K)))(S))(K(K))))(S(K(S(S(K)(K))))(K))))))(K))))));
	// Alternative fully expanded form.

const Z3 = S(S(K(S(S)(K(S(S(K)(K))(S(K)(K))))))(K))(S(S(K(S))(K))(K(S(S(K(S))(S(K(S(K(S(K(S(K(S(S)(K(K))))(K)))(S)))(S(S(K)(K)))))(K)))(K(K(S(S(K)(K))(S(K)(K))))))));
	// Another shorter version.

const trampoline = <T>(fn: T | (() => T)): T => {
	let ctx = fn;
	while (typeof ctx === "function") {
		ctx = (ctx as () => T)();
    }
	return ctx;
};

const countFn = (self: (n: number) => any) => (n: number): any =>
	n === 0
		? (console.log(n), n)
		: () => self(n - 1); // Return thunk "() => self(n - 1)" instead.

// Examples
trampoline(Z(countFn)(10));
trampoline(Z2(countFn)(10));
trampoline(Z3(countFn)(10));
```

## Typing {#Typing}

In [System F](wikipedia://en/767637) ([polymorphic](https://en.wikipedia.org/wiki/Polymorphism_%28computer_science%29) lambda calculus) a polymorphic fixed-point combinator has type[^o40]

∀a.(a → a) → a

where $a$ is a [type variable](https://en.wikipedia.org/wiki/Type_variable). That is, if the type of $\mathrm{fix}\ f$ fulfilling the equation $\mathrm{fix}\ f\ =\ f\ (\mathrm{fix}\ f)$ is $a$—the most general type—then the type of $f$ is $a \to a$. So then, $\mathrm{fix}$ takes a function that maps $a$ to $a$ and uses it to return a value of type $a$.

In the simply typed lambda calculus extended with [recursive data types](https://en.wikipedia.org/wiki/Recursive_data_type), fixed-point operators can be written, but the type of a "useful" fixed-point operator (one whose application always returns) may be restricted.

In the [simply typed lambda calculus](wikipedia://en/1986011), the fixed-point combinator Y cannot be assigned a type[^o41] because at some point it would deal with the self-application sub-term $x~x$ by the application rule:

$${\Gamma\vdash x\!:\!t_1 \to t_2\quad\Gamma\vdash x\!:\!t_1}\over{\Gamma\vdash x~x\!:\!t_2}$$

where $x$ has the infinite type $t_1 = t_1\to t_2$. No fixed-point combinator can in fact be typed; in those systems, any support for recursion must be explicitly added to the language.

### Type for the Y combinator {#Type_for_the_Y_combinator}

In programming languages that support named [recursive data types](https://en.wikipedia.org/wiki/Recursive_data_type), the unbounded recursion in $t := t\to a$, which creates the would-be infinite type $t$, is broken by naming the type $t$ explicitly, as e.g. type $R\ a$ which is defined so as to be isomorphic to (or just to be a synonym of) the type $R\ a \to a$. Thus $R\ a := R\ a \to a$ is recognized as a recursive type. A datum (value) of the type $R\ a$ is created by simply tagging a value that is a function that has the type $R\ a \to a$, by the data constructor tag for the type $R\ a$.

For example, in the following Haskell code, let `Rec` be that tag name, and thus `Rec` and `app` be the names of the two directions of the isomorphism, with types:[^o43][^o44]

```haskell
Rec :: (R a -> a) -> R a
app :: R a -> (R a -> a)
```

(where $::$ means "has type"). This lets us write:

```haskell
newtype R a = Rec { app :: R a -> a }
-- app (Rec g) = g    -- g :: R a -> a
--      Rec g      :: R a
-- app             :: R a -> (R a -> a)

y :: (a -> a) -> a
y f = (\ x -> f (app x x)) (Rec (\ x -> f (app x x)))
--       x :: R a
--   app x :: R a -> a
-- app x x ::        a
```

The usual lambda-calculus definition $\operatorname{Y} f = \operatorname{U} (\lambda x. f\ (\operatorname{U} x))$ (where $\operatorname{U} x = x\ x$, and thus the term $\operatorname{U} (\lambda x. f\ (\operatorname{U} x))$ witnesses the equivalence $x\ x = f\ (x\ x)$) contains at its core the self-application $x\ x$, which is untypeable in the statically typed programming languages. But the expression `app x x` above *is* typeable. Equivalently, we can redefine the self-application combinator $\operatorname{U}$ and use it as

```haskell
U' g = g (Rec g)
y f = U' (\ Rec g -> f (U' g))
--     g (Rec g)  =  f (g (Rec g))

U'' x = app x x
y f = U'' (Rec (\ x -> f (U'' x)))
--        app x x  =  f (app x x)
```

Or in OCaml:

```ocaml
type 'a recc = In of ('a recc -> 'a)
let out (In x) = x

let y f = (fun x a -> f (out x x) a) (In (fun x a -> f (out x x) a))
```

Alternatively:

```ocaml
let y f = (fun x -> f (fun z -> out x x z)) (In (fun x -> f (fun z -> out x x z)))
```

Some languages allow for explicitly marking general types as being recursive even without naming them. Doing that also allows for defining the $\operatorname{Y}$ combinator in such languages.

## General information {#General_information}

Because fixed-point combinators can be used to implement recursion, it is possible to use them to describe specific types of recursive computations, such as those in [fixed-point iteration](wikipedia://en/7344320), [iterative methods](wikipedia://en/15237), [recursive join](https://en.wikipedia.org/wiki/Recursive_join) in [relational databases](https://en.wikipedia.org/wiki/Relational_database), [data-flow analysis](https://en.wikipedia.org/wiki/Data-flow_analysis), FIRST and FOLLOW sets of non-terminals in a [context-free grammar](wikipedia://en/6759), [transitive closure](wikipedia://en/292239), and other types of [closure](wikipedia://en/293802) operations.

A function for which *every* input is a fixed point is called an [identity function](wikipedia://en/15069). Formally:

$$\forall x (f\ x = x)$$

In contrast to [universal quantification](wikipedia://en/76174) over all $x$, a fixed-point combinator constructs *one* value that is a fixed point of $f$. The remarkable property of a fixed-point combinator is that it constructs a fixed point for an *arbitrary given* function $f$.

Other functions have the special property that, after being applied once, further applications don't have any effect. More formally:

$$\forall x (f\ (f\ x) = f\ x)$$

Such functions are called [idempotent](https://en.wikipedia.org/wiki/Idempotent) (see also [Projection (mathematics)](wikipedia://en/3909097)). An example of such a function is the function that returns 0 for all even integers, and 1 for all odd integers.

In [lambda calculus](wikipedia://en/18203), from a computational point of view, applying a fixed-point combinator to an identity function or an idempotent function typically results in non-terminating computation. For example, obtaining

$$(\mathrm Y \ \lambda x.x) = (\lambda x.(\lambda x.x)(x\ x)) \ (\lambda x.(\lambda x.x)(x\ x))$$

where the resulting term can only reduce to itself and represents an infinite loop.

Fixed-point combinators do not necessarily exist in more restrictive models of computation. For instance, they do not exist in [simply typed lambda calculus](wikipedia://en/1986011).

The Y combinator allows [recursion](wikipedia://en/4044867) to be defined as a set of [rewrite rules](https://en.wikipedia.org/wiki/Production_%28computer_science%29),[^o46] without requiring native recursion support in the language.[^o47]

In programming languages that support [anonymous functions](https://en.wikipedia.org/wiki/Anonymous_function), fixed-point combinators allow the definition and use of anonymous [recursive](wikipedia://en/25407) functions, i.e., without having to [bind](https://en.wikipedia.org/wiki/Name_binding) such functions to [identifiers](https://en.wikipedia.org/wiki/Identifier). In this setting, the use of fixed-point combinators is sometimes called *[anonymous recursion](https://en.wikipedia.org/wiki/Anonymous_recursion)*.[^o48][^o49]
