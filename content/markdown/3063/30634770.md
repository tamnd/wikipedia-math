# MMH-Badger MAC

::: {#o1 .subject cue=lead name="MMH-Badger MAC"}

**Badger** is a [message authentication code](wikipedia://en/567523) (MAC) based on the idea of [universal hashing](wikipedia://en/4024666) and was developed by Boesgaard, Scavenius, Pedersen, Christensen, and Zenner.[^o2] It is constructed by strengthening the ∆-universal hash family MMH using an ϵ-almost strongly universal (ASU) hash function family after the application of ENH (see below), where the value of ϵ is $1/(2^{32}-5)$.[^o3] Since Badger is a MAC function based on the [universal hash](https://en.wikipedia.org/wiki/Universal_hash) function approach, the conditions needed for the security of Badger are the same as those for other universal hash functions such as [UMAC](wikipedia://en/2005331).

:::

## Introduction {#Introduction}

The Badger MAC processes a message of length up to $2^{64}-1$ bits and returns an [authentication tag](https://en.wikipedia.org/wiki/Authentication_tag) of length $u\cdot32$ bits, where $1\le u \le 5$. According to the [security](https://en.wikipedia.org/wiki/Security) needs, user can choose the value of $u$, that is the number of parallel [hash trees](wikipedia://en/2497388) in Badger. One can choose larger values of *u*, but those values do not influence further the security of MAC. The [algorithm](wikipedia://en/775) uses a 128-bit key and the limited message length to be processed under this key is $2^{64}$.[^o5]

The key setup has to be run only once per key in order to run the Badger [algorithm](wikipedia://en/775) under a given key, since the resulting internal state of the MAC can be saved to be used with any other message that will be processed later.

## ENH {#ENH}

Hash families can be combined in order to obtain new hash families. For the ϵ-AU, ϵ-A∆U, and ϵ-ASU families, the latter are contained in the former. For instance, an A∆U family is also an AU family, an ASU is also an A∆U family, and so forth. On the other hand, a stronger family can be reduced to a weaker one, as long as a performance gain can be reached. A method to reduce ∆-universal hash function to [universal hash](https://en.wikipedia.org/wiki/Universal_hash) functions will be described in the following.

::: {#o7 .statement kind=statement/theorem cue=inline-head name="Theorem 2"}

**Theorem 2[^o2]**

Let $H^\triangle$ be an ϵ-AΔU hash family from a set *A* to a set *B*. Consider a message $(m, m_b) \in A \times B$. Then the family *H* consisting of the functions $h(m,m_b) = H^\triangle (m) + m_b$ is ϵ-AU.

If $m \ne m'$, then the [probability](wikipedia://en/22934) that $h(m,m_b) =h(m',m'_b)$ is at most ϵ, since $H^\triangle$ is an ϵ-A∆U family. If $m = m'$ but $m_b\ne m_b'$, then the [probability](wikipedia://en/22934) is trivially 0. The proof for Theorem 2 was described in [^o2]

The ENH-family is constructed based on the [universal hash](https://en.wikipedia.org/wiki/Universal_hash) family NH (which is also used in [UMAC](wikipedia://en/2005331)):

$$NH_K (M)= \sum_{i=1}^ \frac{\ell}{2} (k_{(2i-1)} +_w m_{(2i-1)})\times (k_{2i} +_w m_{2i} ) \mod 2^{2w}$$

Where '$+_w$' means 'addition modulo $2^w$', and $m_i,k_i \in \big\{0,\ldots, 2^w-1\big\}$. It is a $2^{-w}$-A∆U hash family.

:::

::: {#o8 .statement kind=statement/lemma cue=inline-head name="Lemma 1"}

**Lemma 1[^o2]**

The following version of NH is $2^{-w}$-A∆U:

$$NH_K (M)=(k_1 +_w m_1 )\times(k_2 +_w m_2 ) \mod 2^{2w}$$

Choosing w=32 and applying Theorem 1, one can obtain the $2^{-32}$-AU function family ENH, which will be the basic building block of the badger MAC:

$$ENH_{k_1,k_2} (m_1,m_2,m_3,m_4 )=(m_1 +_{32} k_1)(m_2 +_{32} k_2) +_{64} m_3 +_{64} 2^{32} m_4$$

where all arguments are 32-bits long and the output has 64-bits.

:::

::: {#o10 .definition kind=definition/construction cue=heading name="Construction"}

## Construction {#Construction}

Badger is constructed using the strongly universality hash family and can be described as

$\mathcal{H}=H^* \times F,$[^o2]

where an $\epsilon_{H^*}$-AU universal function family *H\** is used to hash messages of any size onto a fixed size and an $\epsilon_{F}$-ASU function family *F* is used to guarantee the strong universality of the overall construction. *NH* and *ENH* are used to construct *H\**. The maximum input size of the function family *H\** is $2^{64}-1$ and the output size is 128 bits, split into 64 bits each for the message and the hash. The collision probability for the *H\**-function ranges from $2^{-32}$ to $2^{-26.14}$. To construct the strongly universal function family *F*, the ∆-universal hash family MMH\* is transformed into a strongly universal hash family by adding another key.

:::

## Two steps on Badger {#Two_steps_on_Badger}

There are two steps that have to be executed for every message: processing phase and finalize phase.[^o5]

### Processing phase {#Processing_phase}

In this phase, the data is hashed to a 64-bit string. A core function $h$ : $\left\{0,1\right\}^{64}\times \left\{0,1\right\}^{128} \to \left\{0,1\right\}^{64}$ is used in this processing phase, that hashes a 128-bit string $m_2 \parallel m_1$ to a 64-bit string $h( k, m_2, m_1 )$ as follows:

$$h(k, m_2, m_1 )= (L(m_1 ) +_{32} L(k) )\cdot(U(m_1) +_{32} U(k) ) +_{64} m_2 \,$$

for any *n*, $+_n$ means addition modulo $2^n$. Given a $2n$-bit string *x*, $L(x)$ means least significant *n* bits, and $U(x)$ means most significant *n* bits.

A message can be processed by using this function. Denote level\_key\[j\]\[i\] by $k_j^i$.

Pseudo-code of the processing phase is as follow.

*L* = |*M*| **if** *L* = 0

$$M^1 = \cdots = M^u = 0$$

Go to finalization *r* = *L* mod 64 **if** *r* ≠ 0:

$$M = 0^{64-r} \parallel M$$

**for** *i* = 1 **to** *u*:

$M^i = M$ $v' = \max\{ 1, \lceil\log_2 L\rceil - 6 \}$

**for** *j* = 1 **to** *v*′: divide $M^i$ into 64-bit blocks, $M^i = m_t^i \parallel \cdots \parallel m_1^i$ **if** *t* **is** even:

$$M^i = h(k_j^i, m_t^i, m_{t-1}^i) \parallel \cdots \parallel h(k_j^i, m_2^i, m_1^i)$$

**else**

$$M^i = m_t^i \parallel h(k_j^i, m_{t-1}^i, m_{t-2}^i) \parallel \cdots \parallel h(k_j^i, m_2^i, m_1^i)$$

### Finalize phase {#Finalize_phase}

In this phase, the 64-string resulting from the processing phase is transformed into the desired MAC tag. This finalization phase uses the [Rabbit](wikipedia://en/4565952) [stream cipher](wikipedia://en/49007) and uses both key setup and IV setup by taking the finalization key final\_key\[j\]\[i\] as $k_j^i$.

Pseudo-code of the finalization phase

RabbitKeySetup(K) RabbitIVSetup(N) **for** *i* = 1 **to** *u*:

$$Q^i =0^7 \parallel L \parallel M^i$$

divide $Q^i$ into 27-bit blocks, $Q^i=q_5^i \parallel \cdots \parallel q_1^i$

$S^i =(\sum_{j=1}^5 (q_j^i K_j^i))+K_6^i \bmod p$ $S = S^u \parallel \cdots \parallel S^1$

*S* = *S* ⨁ RabbitNextbit(*u*∙32) **return** S

::: {#o15 .definition kind=definition/notation cue=heading name="Notation"}

### Notation {#Notation}

From the [pseudocode](https://en.wikipedia.org/wiki/Pseudocode) above, *k* denotes the key in the Rabbit Key Setup(K) which initializes Rabbit with the 128-bit key *k*. *M* denotes the message to be hashed and |*M*| denotes the length of the message in bits. $q_i$ denotes a message *M* that is divided into *i* blocks. For the given $2n$-bit string *x* then $L(x)$ and $U(x)$ respectively denoted its least significant n bits and most significant *n* bits.

:::

## MMH (Multilinear Modular Hashing) {#MMH_(Multilinear_Modular_Hashing)}

The name MMH stands for Multilinear-Modular-Hashing. Applications in [Multimedia](https://en.wikipedia.org/wiki/Multimedia) are for example to verify the [integrity](https://en.wikipedia.org/wiki/Integrity) of an on-line multimedia title. The performance of MMH is based on the improved support of integer [scalar products](https://en.wikipedia.org/wiki/Scalar_product) in modern microprocessors.

MMH uses single precision scalar products as its most basic operation. It consists of a (modified) [inner product](https://en.wikipedia.org/wiki/Inner_product) between the message and a key [modulo](wikipedia://en/20087) a [prime](wikipedia://en/23666) $p$. The construction of MMH works in the [finite field](wikipedia://en/11615) $F_p$ for some prime integer $p$.

### MMH\* {#MMH*}

MMH\* involves a construction of a family of [hash functions](https://en.wikipedia.org/wiki/Hash_functions) consisting of [multilinear](wikipedia://en/221525) functions on $F_p^k$ for some positive integer $k$. The family MMH\* of functions from $F_p^k$ to $F_p$ is defined as follows.

$$\mathrm{MMH}^* = \{ g_x : F_p^k \rightarrow F_p | x \in F_p^k \}$$

where *x, m* are vectors, and the functions $g_x$ are defined as follows.

$$g_x(m) = m x\bmod p = \sum_{i=1}^n m_i\,x_i\bmod p$$

In the case of MAC, $m$ is a message and $x$ is a key where $m = (m_1,\ldots,m_k)$ and $x = (x_1,\ldots,x_k), x_i, m_i \in \!F_p$.

MMH\* should satisfy the security requirements of a MAC, enabling say Ana and Bob to communicate in an authenticated way. They have a secret key $x$. Say Charles listens to the conversation between Ana and Bob and wants to change the message into his own message to Bob which should pass as a message from Ana. So, his message $m'$ and Ana's message $m$ will differ in at least one bit (e.g. $m_1 \ne m'_1$).

Assume that Charles knows that the function is of the form $g_x (m)$ and he knows Ana's message $m$ but he does not know the key *x* then the probability that Charles can change the message or send his own message can be explained by the following theorem.

::: {#o20 .statement kind=statement/theorem cue=inline-head name="Theorem 1"}

**Theorem 1[^o21]**:The family MMH\* is ∆-universal.

Proof:

Take $a\in F_p$, and let $m , m'$ be two different messages. Assume [without loss of generality](wikipedia://en/296000) that $m_1 \ne m'_1$. Then for any choice of $x_2,x_3,\ldots,x_s$, there is

$$\begin{aligned} {\Pr}_{x_1}[g_x (m)-g_x (m')\equiv a \mod p] &= {\Pr}_{x_1}[(m_1 x_1+m_2 x_2+ \cdots +m_k x_k )-(m'_1 x_1+m'_2 x_2+\cdots+m'_k x_k )\equiv a \mod p]\\ &= {\Pr}_{x_1}[(m_1-m'_1)x_1+(m_2-m'_2)x_2+ \cdots +(m_k-m'_k)x_k]\equiv a \mod p]\\ &= {\Pr}_{x_1}[(m_1-m'_1)x_1+\textstyle \sum_{k=2}^s(m_k-m'_k)x_k\equiv a \mod p]\\ &= {\Pr}_{x_1}[(m_1-m'_1)x_1\equiv a - \textstyle \sum_{k=2}^s(m_k-m'_k)x_k \mod p]\\ &=\frac {1}{p} \end{aligned}$$

To explain the theorem above, take $F_p$ for $p$ prime represent the field as $F_p = \underbrace{\big\{ 0,1,\ldots,p-1 \big\}}_p$. If one takes an element in $F_p$, let say $0\in F_p$ then the probability that $x_1=0$ is

$${\Pr}_{x_1 \in \!{F_p}}(x_1=0)= \frac {1}{p}$$

So, what one actually needs to compute is

$${\Pr}_{(x_1,\ldots,x_k)\in \!{F_p^k}} (g_x(m)\equiv g_x(m')\mod p)$$

But,

$$\begin{aligned} {\Pr}_{(x_1,\ldots,x_k)\in \!{F_p^k}}(g_x(m)\equiv g_x(m')\mod p) &= \sum_{(x_2,\ldots,x_k)\in \!{F_p^{k-1}}} {\Pr}_{(x_2^'\cdots,x_k^')\in \!{F_p^{k-1}}}({x_2 = x_2^'},\ldots,{x_k = x_k^'})\cdot {\Pr}_{x_1\in \!F_p}(g_x(m)\equiv g_x(m')\mod p)\\ &= \sum_{(x_2,\ldots,x_k)\in \!{F_p^{k-1}}} \frac {1}{p^{k-1}} \cdot \frac {1}{p}\\ &=p^{k-1}\cdot \frac {1}{p^{k-1}} \cdot \frac {1}{p}\\ &=\frac {1}{p} \end{aligned}$$

From the proof above, $\frac{1}{p}$ is the [collision](https://en.wikipedia.org/wiki/Hash_collision) [probability](wikipedia://en/22934) of the attacker in 1 round, so on average $p$ verification queries will suffice to get one message accepted. To reduce the collision probability, it is necessary to choose large *p* or to concatenate $n$ such MACs using $n$ independent keys so that the collision probability\] becomes $\frac{1}{p^n}$. In this case the number of keys are increased by a factor of $n$ and the output is also increased by $n$.

:::

### MMH\*32 {#MMH*32}

Halevi and Krawczyk[^o21] construct a variant called $\mathrm{MMH}^*_{32}$. The construction works with 32-bit [integers](https://en.wikipedia.org/wiki/Integers) and with the [prime](wikipedia://en/23666) integer $p=2^{32}+15$. Actually the prime *p* can be chosen to be any prime which satisfies $2^{32}<p<2^{32}+2^{16}$. This idea is adopted from the suggestion by Carter and Wegman to use the primes $2^{16}+1$ or $2^{31}-1$.

$\mathrm{MMH}^*_{32}$ is defined as follows:

$$\mathrm{MMH}^*_{32}=\left\{g_x (\left\{0,1\right\}^{32} )^k \right\} \to F_p,$$

where $\left\{0,1\right\}^{32}$ means $\left\{0, 1, \ldots, 2^{32}-1\right\}$ (i.e., binary representation)

The functions $g_x$ are defined as follows.

$$\begin{aligned} g_x (m)&\ \overset{\underset{\mathrm{def}}{}}{=}\ m \cdot x \bmod (2^{32}+15)\\ &=\textstyle \sum_{i=1}^k m_i \cdot x_i \bmod (2^{32}+15) \end{aligned}$$

where

$$x= (x_1,\ldots,x_k ),\ m=(m,\ldots,m_k )$$

By theorem 1, the [collision](https://en.wikipedia.org/wiki/Collision) [probability](wikipedia://en/22934) is about $\epsilon = 2^{-32}$, and the family of $\mathrm{MMH}^*_{32}$ can be defined as *ϵ*-almost ∆ Universal with $\epsilon = 2^{-32}$.

### The value of *k* {#The_value_of_k}

The value of *k* that describes the length of the message and key [vectors](wikipedia://en/132729) has several effects:

- Since the costly modular reduction over *k* is multiply and add operations increasing *k* should decrease the speed.
- Since the key *x* consist of *k* 32-bit integers increasing *k* will results in a longer key.
- The probability of breaking the system is $1/p$ and $p\approx 2^k$ so increasing *k* makes the system harder to break.
