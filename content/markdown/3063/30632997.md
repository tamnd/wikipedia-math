# MinHash

::: {#o1 .subject cue=lead name="MinHash"}

In [computer science](https://en.wikipedia.org/wiki/Computer_science) and [data mining](wikipedia://en/42253), **MinHash** (or the **min-wise independent permutations** [locality sensitive hashing](https://en.wikipedia.org/wiki/Locality_sensitive_hashing) scheme) is a technique for quickly estimating how [similar](wikipedia://en/1004743) two sets are. The scheme was published by [Andrei Broder](https://en.wikipedia.org/wiki/Andrei_Broder) in a 1997 conference,[^o3] and initially used in the [AltaVista](https://en.wikipedia.org/wiki/AltaVista) search engine to detect duplicate web pages and eliminate them from search results.[^o2] It has also been applied in large-scale [clustering](wikipedia://en/669675) problems, such as [clustering documents](https://en.wikipedia.org/wiki/Document_clustering) by the similarity of their sets of words.[^o3]

:::

## Jaccard similarity and minimum hash values {#Jaccard_similarity_and_minimum_hash_values}

The [Jaccard similarity coefficient](wikipedia://en/2203756) is a commonly used indicator of the similarity between two sets. Let $U$ be a set and $A$ and $B$ be subsets of $U$, then the Jaccard index is defined to be the ratio of the number of elements of their [intersection](wikipedia://en/23476429) and the number of elements of their [union](wikipedia://en/47949):

$$J(A,B) = {{|A \cap B|}\over{|A \cup B|}}.$$

This value is 0 when the two sets are [disjoint](wikipedia://en/39359), 1 when they are equal, and strictly between 0 and 1 otherwise. Two sets are more similar (i.e. have relatively more members in common) when their Jaccard index is closer to 1. The goal of MinHash is to estimate $J(A,B)$ quickly, without explicitly computing the intersection and union.

Let $h$ be a [hash function](https://en.wikipedia.org/wiki/Hash_function) that maps the members of $U$ to distinct integers, let $perm$ be a random [permutation](wikipedia://en/44027) of the elements of the set $U$, and for any subset $S$ of $U$ define $h_{\min}(S)$ to be the minimal member of $S$ with respect to $h \circ perm$—that is, the member $x$ of $S$ with the minimum value of $h(perm(x))$. (In cases where the hash function used is assumed to have pseudo-random properties, the random permutation would not be used.)

Now, applying $h_{\min}$ to both $A$ and $B$, and assuming no hash collisions, we see that the values are equal ($h_{\min}(A) = h_{\min}(B)$) if and only if among all elements of $A\cup B$, the element with the minimum hash value lies in the intersection $A \cap B$. The probability of this being true is exactly the Jaccard index, therefore:

$$\text{Pr}[ h_{\text{min}}(A) = h_{\text{min}}(B) ] = J(A,B),$$

That is, the [probability](wikipedia://en/22934) that $h_{\min}(A) = h_{\min}(B)$ is true is equal to the similarity $J(A,B)$, assuming drawing $perm$ from a uniform distribution. In other words, if $r$ is the [random variable](wikipedia://en/25685) that is one when $h_{\min}(A) = h_{\min}(B)$ and zero otherwise, then $r$ is an [unbiased estimator](wikipedia://en/8450479) of $J(A,B)$. $r$ has too high a [variance](wikipedia://en/32344) to be a useful estimator for the Jaccard similarity on its own, because $r$ is always zero or one. The idea of the MinHash scheme is to reduce this variance by averaging together several variables constructed in the same way.

## Algorithm {#Algorithm}

### Variant with many hash functions {#Variant_with_many_hash_functions}

The simplest version of the minhash scheme uses $k$ different hash functions, where $k$ is a fixed integer parameter, and represents each set $S$ by the $k$ values of $h_{\min}(S)$ for these $k$ functions.

To estimate $J(A,B)$ using this version of the scheme, let $y$ be the number of hash functions for which $h_{\min}(A) = h_{\min}(B)$, and use $y/k$ as the estimate. This estimate is the average of $k$ different 0-1 random variables, each of which is one when $h_{\min}(A) = h_{\min}(B)$ and zero otherwise, and each of which is an unbiased estimator of $J(A,B)$. Therefore, their average is also an unbiased estimator, and by standard deviation for sums of 0-1 random variables, its expected error is $O(1/\sqrt{k})$.[^o8]

Therefore, for any constant $\varepsilon > 0$ there is a constant $k = O(1/\varepsilon^{2})$ such that the expected error of the estimate is at most $\varepsilon$. For example, 400 hashes would be required to estimate $J(A,B)$ with an expected error less than or equal to .05.

### Variant with a single hash function {#Variant_with_a_single_hash_function}

It may be computationally expensive to compute multiple hash functions, but a related version of MinHash scheme avoids this penalty by using only a single hash function and uses it to select multiple values from each set rather than selecting only a single minimum value per hash function. Let $h$ be a hash function, and let $k$ be a fixed integer. If $S$ is any set of $k$ or more values in the domain of $h$, define $h_{(k)}(S)$ to be the subset of the $k$ members of $S$ that have the smallest values of $h$. This subset $h_{(k)}(S)$ is used as a *signature* for the set $S$, and the similarity of any two sets is estimated by comparing their signatures.

Specifically, let *A* and *B* be any two sets. Then $X = h_{(k)}(h_{(k)}(A) \cup h_{(k)}(B)) = h_{(k)}(A \cup B)$ is a set of *k* elements of $A \cup B$, and if *h* is a random function then any subset of *k* elements is equally likely to be chosen; that is, $X$ is a [simple random sample](wikipedia://en/23809392) of $A \cup B$. The subset $Y = X \cap h_{(k)}(A) \cap h_{(k)}(B)$ is the set of members of $X$ that belong to the intersection $A \cap B$. Therefore, |$Y$|/$k$ is an unbiased estimator of $J(A,B)$. The difference between this estimator and the estimator produced by multiple hash functions is that $X$ always has exactly $k$ members, whereas the multiple hash functions may lead to a smaller number of sampled elements due to the possibility that two different hash functions may have the same minima. However, when $k$ is small relative to the sizes of the sets, this difference is negligible.

By standard [Chernoff bounds](wikipedia://en/741759) for sampling without replacement, this estimator has expected error $O(1/\sqrt{k})$, matching the performance of the multiple-hash-function scheme.

### Time analysis {#Time_analysis}

The estimator $|Y|/k$ can be computed in time $O(k)$ from the two signatures of the given sets, in either variant of the scheme. Therefore, when $\varepsilon$ and $k$ are constants, the time to compute the estimated similarity from the signatures is also constant. The signature of each set can be computed in [linear time](https://en.wikipedia.org/wiki/Linear_time) on the size of the set, so when many pairwise similarities need to be estimated this method can lead to a substantial savings in running time compared to doing a full comparison of the members of each set. Specifically, for set size $n$ the many hash variant takes $O(n k)$ time. The single hash variant is generally faster, requiring $O(n)$ time to maintain the queue of minimum hash values assuming $n >> k$.[^o3]

## Incorporating weights {#Incorporating_weights}

A variety of techniques to introduce weights into the computation of MinHashes have been developed. The simplest extends it to integer weights.[^o12] Extend our hash function $h$ to accept both a set member and an integer, then generate multiple hashes for each item, according to its weight. If item $i$ occurs $n$ times, generate hashes $h(i,1), h(i,2), \ldots, h(i,n)$. Run the original algorithm on this expanded set of hashes. Doing so yields the [weighted Jaccard Index](wikipedia://en/2203756#Weighted_Jaccard_similarity_and_distance) as the collision probability.

$$J_\mathcal{W}(x,y) = \frac{\sum_i \min(x_i,y_i)}{\sum_i \max(x_i,y_i)}$$

Further extensions that achieve this collision probability on real weights with better runtime have been developed, one for dense data,[^o13] and another for sparse data.[^o14]

Another family of extensions use exponentially distributed hashes. A uniformly random hash between 0 and 1 can be converted to follow an exponential distribution by [CDF inversion](wikipedia://en/45705). This method exploits the many beautiful properties of the [minimum of a set of exponential variables](wikipedia://en/45906#Distribution_of_the_minimum_of_exponential_random_variables).

$$H(x) = \underset{i}{\operatorname{arg\,min}} \frac{-\log(h(i))}{x_i}$$

This yields as its collision probability the [probability Jaccard index](wikipedia://en/2203756#Probability_Jaccard_similarity_and_distance)[^o15]

$$J_\mathcal{P}(x,y) = \sum_{x_i\neq 0 \atop y_i \neq 0} \frac{1}{\sum_{j} \max\left(\frac{x_j}{x_i}, \frac{y_j}{y_i}\right)}$$

## Min-wise independent permutations {#Min-wise_independent_permutations}

In order to implement the MinHash scheme as described above, one needs the hash function $h$ to define a [random permutation](https://en.wikipedia.org/wiki/Random_permutation) on $n$ elements, where $n$ is the total number of distinct elements in the union of all of the sets to be compared. But because there are $n!$ different permutations, it would require $\Omega(n \log n)$ bits just to specify a truly random permutation, an infeasibly large number for even moderate values of $n$. Because of this fact, by analogy to the theory of [universal hashing](wikipedia://en/4024666), there has been significant work on finding a family of permutations that is "min-wise independent", meaning that for any subset of the domain, any element is equally likely to be the minimum. It has been established that a min-wise independent family of permutations must include at least

$$\operatorname{lcm}(1, 2, \cdots, n) \ge e^{n-o(n)}$$

different permutations, and therefore that it needs $\Omega(n)$ bits to specify a single permutation, still infeasibly large.[^o2]

### Practical min-wise independent hash functions {#Practical_min-wise_independent_hash_functions}

Because of the above impracticality, two variant notions of min-wise independence have been introduced: restricted min-wise independent permutations families, and approximate min-wise independent families. Restricted min-wise independence is the min-wise independence property restricted to certain sets of cardinality at most $k$.[^o19] Approximate min-wise independence has at most a fixed probability $\varepsilon$ of varying from full independence.[^o20]

In 1999 [Piotr Indyk](https://en.wikipedia.org/wiki/Piotr_Indyk) proved[^o21] that any [k-wise independent family of hash functions](https://en.wikipedia.org/wiki/K-independent_hashing) is also approximately min-wise independent for $k$ large enough. In particular, there are constants $c,c'>0$ such that if $k\ge c \log\tfrac{1}{\epsilon}$, then

$$\Pr_{h\in \mathcal H}[h(x)<\min h(X)]=\frac{1}{|X|+1}(1\pm\epsilon),$$

for all sets $|X|\le \epsilon n c'$ and $x \not\in X$. (Note, here $(1\pm\epsilon)$ means the probability is at most a factor $1+\epsilon$ too big, and at most $1-\epsilon$ too small.)

This guarantee is, among other things, sufficient to give the Jaccard bound required by the MinHash algorithm. That is, if $A$ and $B$ are sets, then

$$\Pr_{h\in\mathcal H}[\min h(A) = \min h(B)] = \frac{|A\cap B|}{|A\cup B|}\pm\epsilon.$$

Since [k-wise independent hash functions](https://en.wikipedia.org/wiki/K-independent_hashing) can be specified using just $k\log n$ bits, this approach is much more practical than using completely min-wise independent permutations.

Another practical family of hash functions that give approximate min-wise independence is [Tabulation hashing](https://en.wikipedia.org/wiki/Tabulation_hashing).

## Applications {#Applications}

The original applications for MinHash involved clustering and eliminating near-duplicates among web documents, represented as sets of the words occurring in those documents.[^o3][^o2][^o24] Similar techniques have also been used for clustering and near-duplicate elimination for other types of data, such as images: in the case of image data, an image can be represented as a set of smaller subimages cropped from it, or as sets of more complex image feature descriptions.[^o25]

In [data mining](wikipedia://en/42253), (Cohen Datar Fujiwara Gionis 2001) use MinHash as a tool for [association rule learning](wikipedia://en/577053). Given a database in which each entry has multiple attributes (viewed as a [0–1 matrix](wikipedia://en/4109196) with a row per database entry and a column per attribute) they use MinHash-based approximations to the Jaccard index to identify candidate pairs of attributes that frequently co-occur, and then compute the exact value of the index for only those pairs to determine the ones whose frequencies of co-occurrence are below a given strict threshold.[^o27]

The MinHash algorithm has been adapted for [bioinformatics](wikipedia://en/4214), where the problem of comparing genome sequences has a similar theoretical underpinning to that of comparing documents on the web. MinHash-based tools[^o28][^o29] allow rapid comparison of [whole genome sequencing](https://en.wikipedia.org/wiki/Whole_genome_sequencing) data with reference genomes (around 3 minutes to compare one genome with the 90000 reference genomes in [RefSeq](https://en.wikipedia.org/wiki/RefSeq)), and are suitable for speciation and maybe a limited degree of microbial sub-typing. There are also applications for metagenomics [^o28] and the use of MinHash derived algorithms for genome alignment and genome assembly.[^o30] Accurate average nucleotide identity (ANI) values can be generated very efficiently with MinHash-based algorithms.[^o31]

:::

## Other uses {#Other_uses}

The MinHash scheme may be seen as an instance of [locality-sensitive hashing](https://en.wikipedia.org/wiki/Locality-sensitive_hashing), a collection of techniques for using hash functions to map large sets of objects down to smaller hash values in such a way that, when two objects have a small distance from each other, their hash values are likely to be the same. In this instance, the signature of a set may be seen as its hash value. Other locality sensitive hashing techniques exist for [Hamming distance](wikipedia://en/41227) between sets and [cosine distance](https://en.wikipedia.org/wiki/Cosine_distance) between [vectors](wikipedia://en/32533); locality sensitive hashing has important applications in [nearest neighbor search](https://en.wikipedia.org/wiki/Nearest_neighbor_search) algorithms.[^o33] For large distributed systems, and in particular [MapReduce](https://en.wikipedia.org/wiki/MapReduce), there exist modified versions of MinHash to help compute similarities with no dependence on the point dimension.[^o34]

## Evaluation and benchmarks {#Evaluation_and_benchmarks}

A large scale evaluation was conducted by [Google](https://en.wikipedia.org/wiki/Google) in 2006 [^o36] to compare the performance of Minhash and [SimHash](https://en.wikipedia.org/wiki/SimHash)[^o37] algorithms. In 2007 Google reported using Simhash for duplicate detection for web crawling[^o38] and using Minhash and [LSH](https://en.wikipedia.org/wiki/Locality-sensitive_hashing) for [Google News](https://en.wikipedia.org/wiki/Google_News) personalization.[^o39]
