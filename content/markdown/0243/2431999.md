# Verifiable random function

::: {#o1 .subject cue=lead name="Verifiable random function"}

[In](https://en.wikipedia.org/wiki/Instagram) [cryptography](wikipedia://en/18934432), a **verifiable random function** (**VRF**) is a public-key [pseudorandom function](https://en.wikipedia.org/wiki/Pseudo-random_function) that provides proofs that its outputs were calculated correctly. The owner of the [secret key](https://en.wikipedia.org/wiki/Secret_key) can compute the function value as well as an associated proof for any input value. Everyone else, using the proof and the associated [public key](https://en.wikipedia.org/wiki/Public_key) (or *verification key*[^o12]), can check that this value was indeed calculated correctly, yet this information cannot be used to find the secret key.[^o2]

:::

A verifiable random function can be viewed as a public-key analogue of a [keyed cryptographic hash](https://en.wikipedia.org/wiki/Hash_function)[^o2] and as a [cryptographic commitment](https://en.wikipedia.org/wiki/Cryptographic_commitment) to an exponentially large number of seemingly random bits.[^o7] The concept of a verifiable random function is closely related to that of a **verifiable unpredictable function** (VUF), whose outputs are hard to predict but do not necessarily seem random.[^o7][^o3]

The concept of a VRF was introduced by [Micali](https://en.wikipedia.org/wiki/Silvio_Micali), [Rabin](wikipedia://en/298404), and [Vadhan](https://en.wikipedia.org/wiki/Salil_Vadhan) in 1999.[^o3][^o4] Since then, verifiable random functions have found widespread use in cryptocurrencies, as well as in proposals for protocol design and cybersecurity.

::: {#o6 .definition kind=definition/construction cue=heading name="Constructions"}

## Constructions {#Constructions}

In 1999, Micali, Rabin, and Vadhan introduced the concept of a VRF and proposed the first such one.[^o3] The original construction was rather inefficient: it first produces a *verifiable unpredictable function*, then uses a [hard-core bit](https://en.wikipedia.org/wiki/Hard-core_bit) to transform it into a VRF; moreover, the inputs have to be mapped to primes in a complicated manner: namely, by using a prime sequence generator that generates primes with overwhelming probability using a [probabilistic primality test](wikipedia://en/183751).[^o7][^o3] The verifiable unpredictable function thus proposed, which is provably secure if a variant of the [RSA problem](https://en.wikipedia.org/wiki/RSA_%28cryptosystem%29) is hard, is defined as follows: The public key *PK* is $(m, r, Q, coins)$, where *m* is the product of two random primes, *r* is a number randomly selected from $\mathbb{Z}_m^*$, *coins* is a randomly selected set of bits, and *Q* a function selected randomly from all polynomials of degree $2k^2 - 1$ over the field $GF(2^k)$. The secret key is $(PK, \phi(m))$. Given an input *x* and a secret key *SK*, the VUF uses the prime sequence generator to pick a corresponding prime $p_x$ (the generator requires auxiliary inputs *Q* and *coins*), and then computes and outputs $r^{1/p_x} \pmod{m}$, which is easily done by knowledge of $\phi(m)$.[^o3]

In 2005, an efficient and practical verifiable random function was proposed by Dodis and Yampolskiy.[^o7][^o8] When the input $x$ is from a small domain (the authors then extend it to a larger domain), the function can be defined as follows:

$$F_{SK}(x) = e(g, g)^{1/(x+SK)} \quad\mbox{and}\quad p_{SK}(x) = g^{1/(x+SK)},$$

where *e*(·,·) is a [bilinear map](wikipedia://en/4365). To verify whether $F_{SK}(x)$ was computed correctly or not, one can check if $e(g^x PK, p_{SK}(x))=e(g,g)$ and $e(g, p_{SK}(x))=F_{SK}(x)$.[^o7][^o8] To extend this to a larger domain, the authors use a tree construction and a [universal hash function](https://en.wikipedia.org/wiki/Universal_hash_function).[^o7] This is secure if it is hard to break the "q-Diffie–Hellman inversion assumption", which states that no algorithm given $(g, g^x, \dots, g^{x^q})$ can compute $g^{1/x}$, and the "q-decisional bilinear Diffie–Hellman inversion assumption", which states that it is impossible for an efficient algorithm given $(g, g^{x}, \ldots, g^{(x^q)}, R)$ as input to distinguish $R=e(g,g)^{1/x}$ from random, in the group $\mathbb{G}$.[^o7][^o8]

In 2015, Hofheinz and Jager constructed a VRF which is provably secure given any member of the "(n − 1)-linear assumption family", which includes the [decision linear assumption](wikipedia://en/12765269).[^o9] This is the first such VRF constructed that does not depend on a "Q-type complexity assumption".[^o9]

In 2019, Bitansky showed that VRFs exist if non-interactive witness-indistinguishable proofs (that is, weaker versions of [non-interactive zero-knowledge proofs](wikipedia://en/11589052) for [NP problems](wikipedia://en/21562) that only hide the witness that the prover uses[^o12][^o10]), non-interactive cryptographic commitments, and single-key constrained pseudorandom functions (that is, pseudorandom functions that only allow the user to evaluate the function with a preset constrained subset of possible inputs[^o11]) also do.[^o12]

When an [Oblivious Pseudorandom Function](https://en.wikipedia.org/wiki/Oblivious_Pseudorandom_Function) is based on [asymmetric cryptography](https://en.wikipedia.org/wiki/Asymmetric_cryptography), possession of the public key can allow the client to verify the output of the function, by checking a [digital signature](wikipedia://en/59644) or a [zero-knowledge proof](wikipedia://en/450541).

In 2020, Esgin et al. proposed a [post-quantum secure](wikipedia://en/26605226) VRF based on [lattice-based cryptography](wikipedia://en/18657553).[^o13]

:::

## Uses and applications {#Uses_and_applications}

VRFs provide deterministic pre-commitments for low entropy inputs which must be resistant to brute-force [pre-image attacks](wikipedia://en/969477).[^o15] VRFs can be used for defense against offline enumeration attacks (such as [dictionary attacks](wikipedia://en/53785)) on data stored in hash-based data structures.[^o2]

### In protocol design {#In_protocol_design}

VRFs have been used to make:

- Resettable [zero-knowledge proofs](https://en.wikipedia.org/wiki/Zero-knowledge_proofs) (i.e. one that remains zero-knowledge even if a malicious verifier is allowed to *reset* the honest prover and query it again[^o17]) with three rounds in the bare model[^o7][^o9]
- Non-interactive lottery systems[^o7][^o9]
- Verifiable transaction escrow schemes[^o7][^o9]
- Updatable zero-knowledge databases[^o9]
- E-cash[^o9]

VRFs can also be used to implement [random oracles](wikipedia://en/451286).[^o18]

### In Internet security {#In_Internet_security}

DNSSEC is a system that prevents attackers from tampering with [Domain Name System](https://en.wikipedia.org/wiki/Domain_Name_System) messages, but it also suffers from the vulnerability of zone enumeration. The proposed NSEC5 system, which uses VRFs, provably prevents this type of attack.[^o20]
