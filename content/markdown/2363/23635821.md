# Dinic's algorithm

::: {#o1 .subject cue=lead name="Dinic's algorithm"}

**Dinic's algorithm** or **Dinitz's algorithm** is a [strongly polynomial](https://en.wikipedia.org/wiki/Strongly_polynomial) algorithm for computing the [maximum flow](https://en.wikipedia.org/wiki/Maximum_flow) in a [flow network](wikipedia://en/645676), conceived in 1970 by Israeli (formerly Soviet) computer scientist [Yefim Dinitz](https://en.wikipedia.org/wiki/Yefim_Dinitz).[^o2] The algorithm runs in $O(|V|^2|E|)$ time and is similar to the [Edmonds–Karp algorithm](wikipedia://en/239230), which runs in $O(|V||E|^2)$ time, in that it uses shortest augmenting paths. The introduction of the concepts of the *level graph* and *blocking flow* enable Dinic's algorithm to achieve its performance.

:::

## History {#History}

Dinitz invented the algorithm in January 1969, as a master's student in [Georgy Adelson-Velsky](https://en.wikipedia.org/wiki/Georgy_Adelson-Velsky)'s group. A few decades later, he would recall:[^o12]

In 1970, Dinitz published a description of the algorithm in [*Doklady Akademii Nauk SSSR*](https://en.wikipedia.org/wiki/Proceedings_of_the_USSR_Academy_of_Sciences). In 1974, [Shimon Even](https://en.wikipedia.org/wiki/Shimon_Even) and (his then Ph.D. student) Alon Itai at the [Technion](https://en.wikipedia.org/wiki/Technion_–_Israel_Institute_of_Technology) in Haifa were very curious and intrigued by Dinitz's algorithm as well as [Alexander V. Karzanov](wikipedia://en/61154506)'s related idea of blocking flow. However it was hard for them to decipher these two papers, each being limited to four pages to meet the restrictions of journal *Doklady Akademii Nauk SSSR*. Even did not give up, and after three days of effort managed to understand both papers except for the layered network maintenance issue. Over the next couple of years, Even gave lectures on "Dinic's algorithm", mispronouncing the name of the author while popularizing it. Even and Itai also contributed to this algorithm by combining [BFS](wikipedia://en/97026) and [DFS](wikipedia://en/97034), which is how the algorithm is now commonly presented.[^o12]

For about 10 years of time after the Ford–Fulkerson algorithm was invented, it was unknown if it could be made to terminate in polynomial time in the general case of irrational edge capacities. This caused a lack of any known polynomial-time algorithm to solve the max flow problem in generic cases. Dinitz's algorithm and the [Edmonds–Karp algorithm](wikipedia://en/239230) (published in 1972) both independently showed that in the Ford–Fulkerson algorithm, if each augmenting path is the shortest one, then the length of the augmenting paths is non-decreasing and the algorithm always terminates.

::: {#o5 .definition cue=heading name="Definition"}

## Definition {#Definition}

Let $G = ((V,E),c,f,s,t)$ be a network with $c(u,v)$ and $f(u,v)$ the capacity and the flow of the edge $(u,v)$, respectively.

The **residual capacity** is a mapping $c_f\colon V\times V \to R^+$ defined as,

1. if $(u,v)\in E$,

$$c_f(u,v) = c(u,v) - f(u,v)$$

1. if $(v,u)\in E$,

$$c_f(u,v) = f(v,u)$$

1. $c_f(u,v) = 0$ otherwise.

The **residual graph** is an unweighted graph $G_f = ((V, E_f), c_f|_{E_f}, s, t)$, where

$$E_f = \{(u,v)\in V \times V \colon\; c_f(u,v) > 0\}.$$

An **augmenting path** is an $s$–$t$ path in the residual graph $G_f$.

Define $\operatorname{dist}(v)$ to be the length of the shortest path from $s$ to $v$ in $G_f$. Then the **level graph** of $G_f$ is the graph $G_L = ((V, E_L), c_f|_{E_L}, s,t)$, where

$$E_L = \{(u,v)\in E_f \colon\; \operatorname{dist}(v) = \operatorname{dist}(u) + 1\}.$$

A **blocking flow** is an $s$–$t$ flow $f'$ such that the graph $G' = ((V,E_L'), s, t)$ with $E_L' = \{(u,v) \colon\; f'(u,v) < c_f|_{E_L}(u,v)\}$ contains no $s$–$t$ path. [^o6][^n1]

:::

::: {#o9 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

**Dinic's Algorithm**

*Input*: A network $G = ((V, E), c, s, t)$.

*Output*: An $s$–$t$ flow $f$ of maximum value.

1. Set $f(e) = 0$ for each $e\in E$.
1. Construct $G_L$ from $G_f$ of $G$. If $\operatorname{dist}(t) = \infty$, stop and output $f$.
1. Find a blocking flow $f'$ in $G_L$.
1. Augment flow $f$ by $f'$ and go back to step 2.

:::

## Analysis {#Analysis}

It can be shown that the number of layers in each blocking flow increases by at least 1 each time and thus there are at most $|V|-1$ blocking flows in the algorithm. For each of them:

- the level graph $G_L$ can be constructed by [breadth-first search](wikipedia://en/97026) in $O(E)$ time
- a blocking flow in the level graph $G_L$ can be found in $O(VE)$ time[^o11]

with total running time $O(E + VE) = O(VE)$ for each layer. As a consequence, the running time of Dinic's algorithm is $O(V^2 E)$.[^o12]

Using a data structure called [dynamic trees](https://en.wikipedia.org/wiki/Dynamic_trees), the running time of finding a blocking flow in each phase can be reduced to $O(E \log V)$ and therefore the running time of Dinic's algorithm can be improved to $O(VE \log V)$.

::: {#o14 .statement kind=statement/generalization cue=heading name="Special cases"}

### Special cases {#Special_cases}

In networks with unit capacities, a much stronger time bound holds. Each blocking flow can be found in $O(E)$ time, and it can be shown that the number of phases does not exceed $O(\sqrt{E})$ and $O(V^{2/3})$.[^o15] Thus the algorithm runs in $O(\min\{V^{2/3}, E^{1/2}\}E)$ time.[^o16]

In networks that arise from the [bipartite matching](https://en.wikipedia.org/wiki/Bipartite_matching) problem, the number of phases is bounded by $O(\sqrt{V})$, therefore leading to the $O(\sqrt{V} E)$ time bound. The resulting algorithm is also known as [Hopcroft–Karp algorithm](wikipedia://en/5944391). More generally, this bound holds for any *unit network* — a network in which each vertex, except for source and sink, either has a single entering edge of capacity one, or a single outgoing edge of capacity one, and all other capacities are arbitrary integers.[^n1]

:::
