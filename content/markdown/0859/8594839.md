## Features {#Features}

- **Hidden containers**: Whether hidden containers (an encrypted container (A) within another encrypted container (B) so the existence of container A can not be established)[^o123] can be created for [deniable encryption](wikipedia://en/1055437). Note that some [modes of operation](https://en.wikipedia.org/wiki/Block_cipher_modes_of_operation) like CBC with a plain IV can be more prone to [watermarking attacks](wikipedia://en/7228413) than others.
- **Pre-boot authentication**: Whether authentication can be required before booting the computer, thus allowing one to encrypt the [boot disk](https://en.wikipedia.org/wiki/Boot_disk).
- **[Single sign-on](https://en.wikipedia.org/wiki/Single_sign-on)**: Whether credentials provided during pre-boot authentication will automatically log the user into the host operating system, thus preventing [password fatigue](https://en.wikipedia.org/wiki/Password_fatigue) and reducing the need to remember multiple passwords.
- **Custom authentication**: Whether custom authentication mechanisms can be implemented with third-party applications.
- **Multiple keys**: Whether an encrypted volume can have more than one active [key](wikipedia://en/53039).
- **Passphrase strengthening**: Whether [key strengthening](https://en.wikipedia.org/wiki/Key_strengthening) is used with plain text passwords to frustrate [dictionary attacks](wikipedia://en/53785), usually using [PBKDF2](wikipedia://en/1568244) or [Argon2](wikipedia://en/48963187).
- **Hardware acceleration**: Whether dedicated [cryptographic accelerator](https://en.wikipedia.org/wiki/Cryptographic_accelerator) expansion cards can be taken advantage of.
- **[Trusted Platform Module](wikipedia://en/2936835)**: Whether the implementation can use a TPM [cryptoprocessor](https://en.wikipedia.org/wiki/Cryptoprocessor).
- **Filesystems**: What filesystems are supported.
- **[Two-factor authentication](https://en.wikipedia.org/wiki/Two-factor_authentication)**: Whether optional [security tokens](https://en.wikipedia.org/wiki/Security_tokens) ([hardware security modules](https://en.wikipedia.org/wiki/Hardware_security_module), such as Aladdin eToken and [smart cards](https://en.wikipedia.org/wiki/Smart_cards)) are supported (for example using [PKCS#11](https://en.wikipedia.org/wiki/PKCS11))

## Layering {#Layering}

- **Whole disk**: Whether the whole physical disk or logical volume can be encrypted, including the partition tables and master boot record. Note that this does not imply that the encrypted disk can be used as the boot disk itself; refer to pre-boot authentication in the features comparison table.
- **Partition**: Whether individual [disk partitions](https://en.wikipedia.org/wiki/Disk_partition) can be encrypted.
- **File**: Whether the encrypted container can be stored in a file (usually implemented as encrypted [loop devices](https://en.wikipedia.org/wiki/Loop_device)).
- **Swap space**: Whether the [swap space](https://en.wikipedia.org/wiki/Swap_space) (called a "pagefile" on Windows) can be encrypted individually/explicitly.
- **Hibernation file**: Whether the [hibernation file](https://en.wikipedia.org/wiki/Hibernation_file) is encrypted (if hibernation is supported).

## Modes of operation {#Modes_of_operation}

Different modes of operation supported by the software. Note that an encrypted volume can only use one mode of operation.

- **CBC with predictable IVs**: The CBC ([cipher block chaining](https://en.wikipedia.org/wiki/Cipher_block_chaining)) mode where [initialization vectors](wikipedia://en/105971) are statically derived from the sector number and are not secret; this means that IVs are re-used when overwriting a sector and the vectors can easily be guessed by an attacker, leading to [watermarking attacks](wikipedia://en/7228413).
- **CBC with secret IVs**: The CBC mode where initialization vectors are statically derived from the encryption key and sector number. The IVs are secret, but they are re-used with overwrites. Methods for this include ESSIV and encrypted sector numbers (CGD).
- **CBC with random per-sector keys**: The CBC mode where random keys are generated for each sector when it is written to, thus does not exhibit the typical weaknesses of CBC with re-used initialization vectors. The individual sector keys are stored on disk and encrypted with a master key. (See [GBDE](wikipedia://en/8708466) for details)
- **LRW**: The Liskov-Rivest-Wagner tweakable narrow-block mode, a mode of operation specifically designed for disk encryption. Superseded by the more secure XTS mode due to security concerns.[^o244]
- **[XTS](wikipedia://en/3395256#XEX-based_tweaked-codebook_mode_with_ciphertext_stealing_%28XTS%29)**: XEX-based Tweaked CodeBook mode (TCB) with CipherText Stealing (CTS), the [SISWG](https://en.wikipedia.org/wiki/IEEE_P1619) (IEEE P1619) standard for disk encryption.
- **[Authenticated encryption](wikipedia://en/2244296)**: Protection against ciphertext modification by an attacker
