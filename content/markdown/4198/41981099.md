# Tox (protocol)

::: {#o1 .subject cue=lead name="Tox"}

**Tox** is a [peer-to-peer](https://en.wikipedia.org/wiki/Peer-to-peer) instant-messaging and video-calling protocol that offers [end-to-end encryption](wikipedia://en/1065362). The stated goal of the project is to provide secure yet easily accessible communication for everyone.[^o3] A [reference implementation](https://en.wikipedia.org/wiki/Reference_implementation) of the protocol is published as [free and open-source software](https://en.wikipedia.org/wiki/Free_and_open-source_software) under the terms of the [GNU GPL-3.0-or-later](https://en.wikipedia.org/wiki/GNU_General_Public_License).

:::

## History {#History}

### Inception {#Inception}

An idea of developing a secure peer-to-peer messenger which would later turn into Tox sparked on the anonymous imageboard [4chan](https://en.wikipedia.org/wiki/4chan)[^o6] amidst the allegations that [Skype](https://en.wikipedia.org/wiki/Skype) provided the [NSA](wikipedia://en/21939) with access to their infrastructure and encryption, just before they were bought by Microsoft.[^o7][^o8]

The initial commit to [GitHub](https://en.wikipedia.org/wiki/GitHub) was pushed on June 23, 2013, by a user named irungentoo.[^o9] Unofficial community builds became available as early as on August 23, 2013,[^o10] with the first official builds made available in October 2013.[^o11] On July 12, 2014, Tox entered an alpha stage in development and a redesigned download page was created for the occasion.[^o12]

### Tox Foundation controversy {#Tox_Foundation_controversy}

During the first two years of its life, the project's business and monetary side was handled by Tox Foundation, a California-registered corporation.[^o14] On July 6, 2015 an issue was open on the project's GitHub, where a third party stated[^o15] that Tox Foundation's sole board member, Sean Qureshi, used an amount of money in the thousands of US dollars to pay for their college tuition,[^o16] with those funds coming from Tox Foundation's participation in [Google Summer of Code](https://en.wikipedia.org/wiki/Google_Summer_of_Code). When asked for additional clarification, irungentoo, on behalf of the project's team, confirmed the allegations.[^o17] On July 11, 2015 the project's infrastructure and repositories were moved to a new locations, due to the fact that Qureshi controlled the original project's domains and servers. In the project's blog the development team has announced their "disassociation" with Tox Foundation and Qureshi in particular, and further addressed the issue.[^o18] This situation caused many prominent contributors to cease Tox-related activity.[^o19]

### Project's fork and Rust implementation {#Project's_fork_and_Rust_implementation}

Sometime during 2016, the original reference implementation saw a steady decline in development activity,[^o21] with the last known commit currently dated Oct 2018.[^o22] This caused the project to split, with those interested in continuing the development creating a new fork of Tox core[^o23] called "c-toxcore" around the end of September 2016.

Currently c-toxcore is being developed by a collective known as the TokTok Project.[^o24] They describe their mission as "to promote universal freedom of expression and to preserve unrestricted information exchange".[^o25] Their current goals are to continue slow iterative development of the existing core implementation, along with in-parallel development of a new reference implementation in [Rust](https://en.wikipedia.org/wiki/Rust_%28programming_language%29).[^o24][^o26]

Initially, the Rust implementation of the protocol library was split in two halves, one handling most of the grunt work of communication with the network, and another one responsible specifically for bootstrap node operation. In December 2022 those were merged, with developers stating that code was now mature enough to support basic communication and bootstrap node operations using TCP connections. As of June 2023 the development is still ongoing, but no client implementations using Rust core library is available yet.[^o26]

### Security audit and related concerns {#Security_audit_and_related_concerns}

Although the original core library implementation and its forks have been available for the general public for almost a decade, none of them have been reviewed by a competent third-party security researcher.

In 2017, [WireGuard](https://en.wikipedia.org/wiki/WireGuard)'s author Jason A. Donenfeld opened an issue on the project's GitHub page[^o28] where he stated that c-toxcore is vulnerable to key compromise impersonation (KCI) attacks. Donenfeld attributed his find to the fact that Tox is relying on "homebrew crypto" developed by "non-experts" to facilitate handshakes. He also criticized some other design choices used by Tox developers as well, like using raw [ECDH](wikipedia://en/3357958) values as encryption keys.

This report has caused developers to put an additional disclaimer on the project's GitHub page,[^o29] stating that Tox is an experimental cryptographic network library that has not been formally audited by an independent third party that specializes in cryptography or cryptanalysis, with a separate disclaimer that users may use it on their own risk.

In March 2023, a post on the project's blog[^o30] stated that one of the community members is working to redesign the cryptographic mechanism used by Tox to perform handshakes using the AKE mechanisms used in the Noise Protocol Framework. This post also contains a detailed explanation of the original vulnerability.

## Features {#Features}

### Encryption of traffic {#Encryption_of_traffic}

Users are assigned a public and private key, and they connect to each other directly in a fully [distributed](https://en.wikipedia.org/wiki/Distributed_Hash_Table), peer-to-peer network. Users have the ability to message friends, join chat rooms with friends or strangers, voice/video chat, and send each other files. All traffic over Tox is end-to-end encrypted using the [NaCl](https://en.wikipedia.org/wiki/NaCl_%28software%29) library, which provides [authenticated encryption](wikipedia://en/2244296) and [perfect forward secrecy](https://en.wikipedia.org/wiki/Perfect_forward_secrecy).

### Additional messaging features {#Additional_messaging_features}

Tox clients aim to provide support for various secure and anonymised communication features; while every client supports [messaging](https://en.wikipedia.org/wiki/Instant_Messaging), additional features like [group messaging](https://en.wikipedia.org/wiki/Chat_Room), [voice and video calling](https://en.wikipedia.org/wiki/Voip), [voice and video conferencing](https://en.wikipedia.org/wiki/Videoconferencing), typing indicators, [message read-receipts](https://en.wikipedia.org/wiki/Email_tracking), [file sharing](https://en.wikipedia.org/wiki/File_sharing), profile encryption, and [desktop streaming](https://en.wikipedia.org/wiki/Desktop_sharing) are supported to various degrees by mobile and desktop clients. Additional features can be implemented by any client as long as they are supported by the core protocol. Features that are not related to the core networking system are left up to the client. Client developers are strongly encouraged to adhere to the Tox Client Standard[^o34] in order to maintain cross-client compatibility and uphold best security practices.

### Usability as an instant messenger {#Usability_as_an_instant_messenger}

Though several apps that use the Tox protocol seem similar in function to regular instant messaging apps, the lack of central servers similar to [XMPP](https://en.wikipedia.org/wiki/XMPP) or [Matrix](wikipedia://en/46246817) currently has the consequence that both parties of the chat need to be online for the message to be sent and received. The Tox enabled messengers deal with this in separate ways: some prevent the user from sending the message if the other party has disconnected, while others show the message as being sent when in reality it is stored in the sender's phone waiting to be delivered when the receiving party reconnects to the network.[^o36]

## Reception {#Reception}

Tox received some significant publicity in its early conceptual stage, catching the attention of global online tech news sites.[^o38][^o39][^o40][^o41] On August 15, 2013, Tox was number five on [GitHub](https://en.wikipedia.org/wiki/GitHub)'s top trending list.[^o42] Concerns about [metadata](https://en.wikipedia.org/wiki/Metadata) leaks were raised, and developers responded by implementing [Onion routing](https://en.wikipedia.org/wiki/Onion_routing) for the friend-finding process.[^o43] Tox was accepted into the [Google Summer of Code](https://en.wikipedia.org/wiki/Google_Summer_of_Code) as a Mentoring Organization in 2014 and 2015.[^o44][^o45]
