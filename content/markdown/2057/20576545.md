# Function application

::: {#o1 .subject cue=lead name="Function application"}

In [mathematics](wikipedia://en/18831), **function application** (or **evaluation**) is the act of taking a [function](wikipedia://en/185427) and an input from its [domain](wikipedia://en/50263) to obtain the corresponding value from its [range](wikipedia://en/275991). In this sense, function application can be thought of as the opposite of function [abstraction](wikipedia://en/454446).[^o2]

:::

It is central to [programming languages](wikipedia://en/23015) derived from [lambda calculus](wikipedia://en/18203), such as [LISP](https://en.wikipedia.org/wiki/LISP) and [Scheme](https://en.wikipedia.org/wiki/Scheme_%28programming_language%29), and also in [functional languages](https://en.wikipedia.org/wiki/Functional_language). It has a role in the study of the [denotational semantics](wikipedia://en/55275) of computer programs, because it is a [continuous function](wikipedia://en/743106) on [complete partial orders](wikipedia://en/572352). Function application is also a continuous function in [homotopy theory](wikipedia://en/61994831), and, indeed underpins the entire theory: it allows a homotopy deformation to be viewed as a continuous path in the space of functions. Likewise, valid mutations (refactorings) of computer programs can be seen as those that are "continuous" in the [Scott topology](https://en.wikipedia.org/wiki/Scott_topology).

::: {#o4 .definition kind=definition/notation cue=heading name="Representation"}

## Representation {#Representation}

Function application is usually depicted by juxtaposing the variable representing the function with its argument encompassed in [parentheses](https://en.wikipedia.org/wiki/Parentheses). For example, the following expression represents the application of the function *ƒ* to its argument *x*.

$$f(x)$$

In some instances, a different notation is used where the parentheses aren't required, and function application can be expressed just by [juxtaposition](https://en.wikipedia.org/wiki/Juxtaposition). For example, the following expression can be considered the same as the previous one:

$$f\; x$$

The latter notation is especially useful in combination with the [currying](wikipedia://en/6600) isomorphism. Given a function $f : (X \times Y) \to Z$, its application is represented as $f(x, y)$ by the former notation and $f\;(x,y)$ (or $f \; \langle x, y \rangle$ with the argument $\langle x, y \rangle \in X \times Y$ written with the less common angle brackets) by the latter. However, functions in curried form $f : X \to (Y \to Z)$ can be represented by juxtaposing their arguments: $f\; x \; y$, rather than $f(x)(y)$. This relies on function application being [left-associative](https://en.wikipedia.org/wiki/Left-associative).

When mathematical notation is represented in a digital document, the invisible zero-width [Unicode](https://en.wikipedia.org/wiki/Unicode) characters 2061 and 2062 can be used to distinguish concatenation meaning function application from concatenation meaning multiplication.

:::

## As an operator {#As_an_operator}

Function application can be defined as an [operator](wikipedia://en/22213), called [apply](https://en.wikipedia.org/wiki/Apply) or $\$$, by the following definition:

$f \mathop{\,\$\,} x = f(x)$

The operator may also be denoted by a [backtick](https://en.wikipedia.org/wiki/Backtick) (\`).

If the operator is understood to be of [low precedence](wikipedia://en/212980) and [right-associative](https://en.wikipedia.org/wiki/Right-associative), the application operator can be used to cut down on the number of parentheses needed in an expression. For example;

$$f(g(h(j(x))))$$

can be rewritten as:

$f \mathop{\,\$\,} g \mathop{\,\$\,} h \mathop{\,\$\,} j \mathop{\,\$\,} x$

This can be equivalently expressed using [function composition](wikipedia://en/195947) as:

$$(f \circ g \circ h \circ j)(x)$$

or even:

$$(f \circ g \circ h \circ j \circ x)()$$

if one considers $x$ to be a [constant function](wikipedia://en/320861) returning $x$.

## Set theory {#Set_theory}

In [axiomatic set theory](https://en.wikipedia.org/wiki/Axiomatic_set_theory), especially [Zermelo–Fraenkel set theory](wikipedia://en/152214), a function $f: D \mapsto R$ is often defined as a [relation](wikipedia://en/22517558) ($f \subseteq D \times R$) having the property that, for any $x \in D$ [there is a unique](https://en.wikipedia.org/wiki/There_is_a_unique) $y \in R$ such that $(x,y) \in f$.

One is usually not content to write "$(x,y) \in f$" to specify that $y$, and usually wishes for the more common function notation "$f(x) = y$" . Function application, or more specifically, the notation "$f(x)$", is not present in the usual signature of set theory, but may be added to the theory as a binary [function symbol](wikipedia://en/174908) $\bullet ( \bullet )$ if desired without any loss of expressiveness by defining:[^o7]

$$X(Y) = \left\{ \begin{array}{lll} z & \text{if } X \text{ is a function, and } (Y,z) \in X \\ \varnothing & \text{otherwise} \\ \end{array} \right.$$

Or, more formally:[^o8][^o9]

$$X(Y) = z \iff (\exists D,R ( X \in R^D \land ((Y,z) \in X))) \lor (\forall D,R(X \notin R^D \lor (Y,z) \notin X) \land z = \varnothing),$$

where $R^D$ denotes [set exponentiation](https://en.wikipedia.org/wiki/Set_exponentiation): the set of all functions from $D$ to $R$.

In prose: $X(Y) = z$ if there exists a domain $D$ and range $R$ such that $X$ is a function from $D$ to $R$ and $(Y,z) \in X$; or (the negation of former) and $z = \varnothing.$ The choice of using the [empty set](wikipedia://en/9566) $\varnothing$ when $X(Y)$ is undefined is arbitrary to ensure that the notation defined for the entire [domain of discourse](wikipedia://en/229180).[^o10]

If $\Psi(X,Y,z)$ denotes the formula on the right side of the [biconditional](https://en.wikipedia.org/wiki/Biconditional) above, for any two sets, $X,Y$ the formula $\Psi$ associates a unique object $z$: $\forall X,Y \, \exists! z \, \Psi(X,Y,z)$. Therefore the language of set theory can use an [extension by definition](wikipedia://en/12219849) to include the function application operation $\bullet ( \bullet )$ [conservatively](wikipedia://en/1840214).

## Programming {#Programming}

In computer programming, function application often refers to calling or executing a procedure, rather than a true mathematical function (see [functions in computer programing](https://en.wikipedia.org/wiki/Function_%28computer_programming%29)), with similar rules for its behavior.

Function application corresponds to [beta reduction](https://en.wikipedia.org/wiki/Beta_reduction) in [lambda calculus](wikipedia://en/18203).

### Apply function {#Apply_function}

Related to the apply operator, the function **apply** applies a function to a variable *list* of arguments. *[Eval](https://en.wikipedia.org/wiki/Eval)* and apply are the two interdependent components of the *eval-apply cycle* in Lisp, described in [SICP](https://en.wikipedia.org/wiki/Structure_and_Interpretation_of_Computer_Programs).[^o13] This is supported in languages with [variadic functions](https://en.wikipedia.org/wiki/Variadic_function), because this is the only way to call a function with an indeterminate (at compile time) number of arguments.

#### Common Lisp and Scheme {#Common_Lisp_and_Scheme}

In [Common Lisp](https://en.wikipedia.org/wiki/Common_Lisp) **apply** is a function that applies a function to a list of arguments (note here that "+" is a variadic function that takes any number of arguments):

```lisp
(apply #'+ (list 1 2))
```

Similarly in Scheme:

```scheme
(apply + (list 1 2))
```

#### C++ {#C++}

In [C++](https://en.wikipedia.org/wiki/C++), Bind [^o16] is used either via the std namespace or via the boost namespace.

#### C# and Java {#C#_and_Java}

In [C#](https://en.wikipedia.org/wiki/C_Sharp_%28programming_language%29) and [Java](https://en.wikipedia.org/wiki/Java_%28programming_language%29), variadic arguments are simply collected in an array. Caller can explicitly pass in an array in place of the variadic arguments. This can only be done for a variadic parameter. It is not possible to apply an array of arguments to non-variadic parameter without using [reflection](https://en.wikipedia.org/wiki/Reflection_%28computer_science%29). An ambiguous case arises should the caller want to pass an array itself as one of the arguments rather than using the array as a *list* of arguments. In this case, the caller should cast the array to `Object` to prevent the compiler from using the *apply* interpretation.

```java
variadicFunc(arrayOfArgs);
```

With version 8 lambda expressions were introduced. Functions are implemented as objects with a functional interface, an interface with only one non-static method. The standard interface

```java
Function<T,R>
```

consist of the method (plus some static utility functions):

```java
R apply(T para)
```

#### Go {#Go}

In [Go](https://en.wikipedia.org/wiki/Go_%28programming_language%29), typed variadic arguments are simply collected in a slice. The caller can explicitly pass in a slice in place of the variadic arguments, by appending a `...` to the slice argument. This can only be done for a variadic parameter. The caller can not apply an array of arguments to non-variadic parameters, without using reflection..s := \[\]string{"foo", "bar"} variadicFunc(s...)

#### JavaScript {#JavaScript}

In [JavaScript](https://en.wikipedia.org/wiki/JavaScript), function objects have an `apply` method, the first argument is the value of the `this` keyword inside the function; the second is the list of arguments:

```javascript
func.apply(null, args);
```

[ES6](https://en.wikipedia.org/wiki/ECMAScript#6th_Edition_–_ECMAScript_2015) adds the spread operator `func(...args)`[^o20] which may be used instead of `apply`.

#### Lua {#Lua}

In [Lua](https://en.wikipedia.org/wiki/Lua_%28programming_language%29), apply can be written this way:

```lua
function apply(f,...)
  return f(...)
end 
```

#### Perl {#Perl}

In [Perl](https://en.wikipedia.org/wiki/Perl), arrays, hashes and expressions are automatically "flattened" into a single list when evaluated in a list context, such as in the argument list of a function

```perl
# Equivalent subroutine calls:
@args = (@some_args, @more_args);
func(@args);

func(@some_args, @more_args);
```

#### PHP {#PHP}

In [PHP](https://en.wikipedia.org/wiki/PHP), `apply` is called `call_user_func_array`:

```php
call_user_func_array('func_name', $args);
```

#### Python and Ruby {#Python_and_Ruby}

In [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) and [Ruby](https://en.wikipedia.org/wiki/Ruby_%28programming_language%29), the same asterisk notation used in defining [variadic functions](https://en.wikipedia.org/wiki/Variadic_function) is used for calling a function on a sequence and array respectively:

```python
func(*args)
```

Python originally had an apply function, but this was [deprecated](https://en.wikipedia.org/wiki/Deprecated) in favour of the asterisk in 2.3 and removed in 3.0.[^o25]

#### R {#R}

In [R](wikipedia://en/376707), `do.call` constructs and executes a function call from a name or a function and a list of arguments to be passed to it:

```r
f(x1, x2)
# can also be performed via
do.call(what = f, args = list(x1, x2))
```

#### Smalltalk {#Smalltalk}

In [Smalltalk](https://en.wikipedia.org/wiki/Smalltalk), block (function) objects have a `valueWithArguments:` method which takes an array of arguments:

```smalltalk
aBlock valueWithArguments: args
```

#### Tcl {#Tcl}

Since [Tcl](https://en.wikipedia.org/wiki/Tcl_%28programming_language%29) 8.5,[^o29] a function can be applied to arguments with the `apply` command

```tcl
apply func ?arg1 arg2 ...?
```

where the function is a two element list {args body} or a three element list {args body namespace}.

## Universal property {#Universal_property}

Consider a [function](wikipedia://en/185427) $g:(X\times Y)\to Z$, that is, $g\in [(X\times Y)\to Z]$ where the bracket notation $[A\to B]$ denotes the [space of functions](https://en.wikipedia.org/wiki/Space_of_functions) from *A* to *B*. By means of [currying](wikipedia://en/6600), there is a unique function $\mbox{curry}(g) :X\to [Y\to Z]$. Then **Apply** provides the [universal morphism](https://en.wikipedia.org/wiki/Universal_morphism)

$$\mbox{Apply}:([Y\to Z]\times Y) \to Z,$$

so that

$$\mbox {Apply}(f,y)=f(y)$$

or, equivalently one has the [commuting diagram](https://en.wikipedia.org/wiki/Commuting_diagram)

$$\mbox{Apply} \circ \left( \mbox{curry}(g) \times \mbox{id}_Y \right) = g$$

More precisely, curry and apply are [adjoint functors](wikipedia://en/53991).

The notation $[A\to B]$ for the space of functions from *A* to *B* occurs more commonly in computer science. In [category theory](wikipedia://en/5869), however, $[A\to B]$ is known as the [exponential object](wikipedia://en/2237858), and is written as $B^A$. There are other common notational differences as well; for example *Apply* is often called *Eval*,[^o31] even though in computer science, these are not the same thing, with [eval](https://en.wikipedia.org/wiki/Eval) distinguished from *Apply*, as being the evaluation of the quoted string form of a function with its arguments, rather than the application of a function to some arguments.

Also, in category theory, *curry* is commonly denoted by $\lambda$, so that $\lambda g$ is written for *curry*(*g*). This notation is in conflict with the use of $\lambda$ in [lambda calculus](wikipedia://en/18203), where lambda is used to denote bound variables. With all of these notational changes accounted for, the adjointness of *Apply* and *curry* is then expressed in the commuting diagram

*Image: ExponentialObject-01.svg.* Universal property of the exponential object

The articles on [exponential object](wikipedia://en/2237858) and [Cartesian closed category](wikipedia://en/237037) provide a more precise discussion of the category-theoretic formulation of this idea. Thus the use of lambda here is not accidental; the [internal language](https://en.wikipedia.org/wiki/Internal_language) of Cartesian closed categories is [simply typed lambda calculus](wikipedia://en/1986011). The most general possible setting for *Apply* are the [closed monoidal categories](wikipedia://en/1396924), of which the cartesian closed categories are an example. In [homological algebra](wikipedia://en/139410), the adjointness of curry and apply is known as [tensor-hom adjunction](https://en.wikipedia.org/wiki/Tensor-hom_adjunction).

## Topological properties {#Topological_properties}

In [order theory](wikipedia://en/361924), in the category of [complete partial orders](wikipedia://en/572352) endowed with the [Scott topology](https://en.wikipedia.org/wiki/Scott_topology), both *curry* and *apply* are [continuous functions](wikipedia://en/6122) (that is, they are [Scott continuous](https://en.wikipedia.org/wiki/Scott_continuous)).[^o33] This property helps establish the foundational validity of the study of the [denotational semantics](wikipedia://en/55275) of computer programs.

In [algebraic geometry](wikipedia://en/1997) and [homotopy theory](wikipedia://en/61994831), *curry* and *apply* are both continuous functions when the space $Y^X$ of continuous functions from $X$ to $Y$ is given the [compact open topology](https://en.wikipedia.org/wiki/Compact_open_topology), and $X$ is [locally compact Hausdorff](https://en.wikipedia.org/wiki/Locally_compact_Hausdorff). This result is very important, in that it underpins homotopy theory, allowing homotopic deformations to be understood as continuous paths in the space of functions.

## Other instances {#Other_instances}

The [Curry–Howard correspondence](wikipedia://en/254299) relates function application to the logical rule of [modus ponens](wikipedia://en/18900).
