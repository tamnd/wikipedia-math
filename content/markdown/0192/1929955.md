# Complement (complexity)

::: {#o1 .subject cue=lead name="Complement"}

In [computational complexity theory](wikipedia://en/7543), the **complement** of a [decision problem](wikipedia://en/8336) is the decision problem resulting from reversing the *yes* and *no* answers.[^o2] Equivalently, if we define decision problems as sets of finite [strings](wikipedia://en/27701), then the [complement](wikipedia://en/54347) of this set over some fixed domain is its complement problem.[^o3]

:::

For example, one important problem is whether a number is a [prime number](wikipedia://en/23666). Its complement is to determine whether a number is a [composite number](wikipedia://en/82289) (a number that is not prime). Here the domain of both the original problem and of the complement is the set of all [natural numbers](https://en.wikipedia.org/wiki/Natural_numbers).[^o4]

There is a [Turing reduction](wikipedia://en/1188375) from every problem to its complement problem.[^o5] The complement operation is an [involution](wikipedia://en/293450), meaning it "undoes itself", or the complement of the complement is the original problem.

One can generalize this to the complement of a [complexity class](wikipedia://en/502426), called the **complement class**, which is the set of complements of every problem in the class.[^o6] If a class is called **C**, its complement is conventionally labelled **co-C**. Notice that this is *not* the complement of the complexity class itself as a set of problems, which would generally contain a great deal more problems.

A class is said to be *closed under complement* if the complement of any problem in the class is still in the class.[^o7] Because there are Turing reductions from every problem to its complement, any class that is closed under Turing reductions is closed under complement. Any class that is closed under complement is equal to its complement class. However, under [many-one reductions](wikipedia://en/362983), many important classes, especially [NP](wikipedia://en/21562), are believed to be distinct from their complement classes (although this has not been proven).[^o8]

The [closure](wikipedia://en/293802) of any complexity class under Turing reductions is a superset of that class that is closed under complement. The closure under complement is the smallest such class. If a class is intersected with its complement, we obtain a (possibly empty) subset that is closed under complement.

Every deterministic complexity class (**[DTIME](wikipedia://en/658538)**(*f*(*n*)), **[DSPACE](wikipedia://en/658520)**(*f*(*n*)), for any *f*(*n*)) is closed under complement,[^o9] because one can simply add a last step to the algorithm that reverses the answer. This doesn't work for nondeterministic complexity classes, because if there exist both computation paths that accept and paths that reject a particular instance, and all the paths reverse their answer, there will still be paths that accept and paths that reject — consequently, both the original machine and the modified machine accept the instance.

Similarly, probabilistic classes such as [BPP](wikipedia://en/4079), [ZPP](wikipedia://en/54772), [BQP](wikipedia://en/4080) or [PP](wikipedia://en/659322) that are defined symmetrically with regard to their *yes* and *no* instances are closed under complement, whereas classes such as [RP](wikipedia://en/54771) and **co-RP** that define their probabilities with one-sided error are not (currently known to be) closed under complement.

Some of the most surprising complexity results shown to date showed that the complexity classes [NL](wikipedia://en/1145955) and [SL](wikipedia://en/1174919) *are* in fact closed under complement (see [Immerman–Szelepcsényi theorem](wikipedia://en/2827371)), whereas before it was widely believed they were not. The latter has become less surprising now that we know **SL** equals **[L](wikipedia://en/1149999)**, which is a deterministic class.

Every class that is [low](wikipedia://en/2006468) for itself is closed under complement.
