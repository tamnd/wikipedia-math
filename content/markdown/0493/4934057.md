# Pre-shared key

::: {#o1 .subject cue=lead name="Pre-shared key"}

In [cryptography](wikipedia://en/18934432), a **pre-shared key** (**PSK**) is a [shared secret](wikipedia://en/7111246) which was previously shared between the two parties using some [secure channel](wikipedia://en/592935) before it needs to be used.[^o2]

:::

## Key {#Key}

To build a key from a shared secret, the [key derivation function](wikipedia://en/449781) is typically used. Such systems almost always use [symmetric key](https://en.wikipedia.org/wiki/Symmetric_key) cryptographic algorithms. The term PSK is used in [Wi-Fi](https://en.wikipedia.org/wiki/Wi-Fi) encryption such as [Wired Equivalent Privacy](wikipedia://en/422014) (WEP), [Wi-Fi Protected Access](wikipedia://en/422017) (WPA), where the method is called [WPA-PSK](https://en.wikipedia.org/wiki/WPA-PSK) or WPA2-PSK, and also in the [Extensible Authentication Protocol](https://en.wikipedia.org/wiki/Extensible_Authentication_Protocol) (EAP), where it is known as [EAP-PSK](https://en.wikipedia.org/wiki/EAP-PSK). In all these cases, both the [wireless access points](https://en.wikipedia.org/wiki/Wireless_access_point) (AP) and all clients *share* the same key.[^o4]

The characteristics of this secret or key are determined by the system which uses it; some system designs require that such keys be in a particular format. It can be a [password](wikipedia://en/24304), a [passphrase](https://en.wikipedia.org/wiki/Passphrase), or a [hexadecimal](wikipedia://en/13263) string. The secret is used by all systems involved in the cryptographic processes used to secure the traffic between the systems.

[Crypto systems](https://en.wikipedia.org/wiki/Crypto_system) rely on one or more keys for confidentiality. One particular attack is always possible against keys, the [brute force key space search attack](https://en.wikipedia.org/wiki/Brute_force_attack). A sufficiently long, randomly chosen, key can [resist](wikipedia://en/5749) any practical brute force attack, though not in principle if an attacker has sufficient computational power (see [password strength](wikipedia://en/4459886) and [password cracking](wikipedia://en/477981) for more discussion). Unavoidably, however, pre-shared keys are held by both parties to the communication, and so can be compromised at one end, without the knowledge of anyone at the other. There are several tools available to help one choose strong passwords, though doing so over any [network](https://en.wikipedia.org/wiki/Computer_network) connection is inherently unsafe as one cannot in general know who, if anyone, may be eavesdropping on the interaction. Choosing keys used by cryptographic algorithms is somewhat different in that any pattern whatsoever should be avoided, as any such pattern may provide an attacker with a lower effort attack than brute force search. This implies [random](https://en.wikipedia.org/wiki/Random) key choice to force attackers to spend as much effort as possible; this is very difficult in principle and in practice as well. As a general rule, any software except a [cryptographically secure pseudorandom number generator](wikipedia://en/182249) should be avoided.
