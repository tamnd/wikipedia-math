# Parameterized approximation algorithm

::: {#o1 .subject cue=lead name="Parameterized approximation algorithm"}

A **parameterized approximation algorithm** is a type of [algorithm](wikipedia://en/775) that aims to find approximate solutions to [NP-hard](wikipedia://en/54681) [optimization problems](wikipedia://en/1126536) in [polynomial time](wikipedia://en/405944) in the input size and a function of a specific parameter. These algorithms are designed to combine the best aspects of both traditional [approximation algorithms](wikipedia://en/563105) and [fixed-parameter tractability.](wikipedia://en/603026)

:::

In traditional approximation algorithms, the goal is to find solutions that are at most a certain factor $\alpha$ away from the optimal solution, known as an $\alpha$-approximation, in polynomial time. On the other hand, parameterized algorithms are designed to find exact solutions to problems, but with the constraint that the running time of the algorithm is polynomial in the input size and a function of a specific parameter $k$. The parameter describes some property of the input and is small in typical applications. The problem is said to be fixed-parameter tractable (FPT) if there is an algorithm that can find the optimum solution in $f(k)n^{O(1)}$ time, where $f(k)$ is a function independent of the input size $n$.

A parameterized approximation algorithm aims to find a balance between these two approaches by finding approximate solutions in FPT time: the algorithm computes an $\alpha$-approximation in $f(k)n^{O(1)}$ time, where $f(k)$ is a function independent of the input size $n$. This approach aims to overcome the limitations of both traditional approaches by having stronger guarantees on the solution quality compared to traditional approximations while still having efficient running times as in FPT algorithms. An overview of the research area studying parameterized approximation algorithms can be found in the survey of Marx[^o2] and the more recent survey by Feldmann et al.[^o3]

## Obtainable approximation ratios {#Obtainable_approximation_ratios}

The full potential of parameterized approximation algorithms is utilized when a given [optimization problem](wikipedia://en/1126536) is shown to admit an $\alpha$-approximation algorithm running in $f(k)n^{O(1)}$ time, while in contrast the problem neither has a polynomial-time $\alpha$-approximation algorithm (under some [complexity assumption](wikipedia://en/7543), e.g., $\mathsf{P}\neq \mathsf{NP}$), nor an FPT algorithm for the given parameter $k$ (i.e., it is at least [W\[1\]-hard](wikipedia://en/603026#W_hierarchy)).

For example, some problems that are [APX-hard](wikipedia://en/2018925) and [W\[1\]-hard](wikipedia://en/603026#W_hierarchy) admit a **parameterized approximation scheme (PAS)**, i.e., for any $\varepsilon>0$ a $(1+\varepsilon)$-approximation can be computed in $f(k,\varepsilon)n^{g(\varepsilon)}$ time for some functions $f$ and $g$. This then circumvents the lower bounds in terms of polynomial-time approximation and fixed-parameter tractability. A PAS is similar in spirit to a [polynomial-time approximation scheme (PTAS)](wikipedia://en/666431) but additionally exploits a given parameter $k$. Since the degree of the polynomial in the runtime of a PAS depends on a function $g(\varepsilon)$, the value of $\varepsilon$ is assumed to be arbitrary but constant in order for the PAS to run in FPT time. If this assumption is unsatisfying, $\varepsilon$ is treated as a parameter as well to obtain an **efficient** **parameterized approximation scheme (EPAS)**, which for any $\varepsilon>0$ computes a $(1+\varepsilon)$-approximation in $f(k,\varepsilon)n^{O(1)}$ time for some function $f$. This is similar in spirit to an [efficient polynomial-time approximation scheme (EPTAS).](https://en.wikipedia.org/wiki/Efficient_polynomial-time_approximation_scheme)

### *k*-Cut {#k-Cut}

The [*k*-cut](wikipedia://en/25358908) problem has no polynomial-time $(2-\varepsilon)$-approximation algorithm for any $\varepsilon>0$, assuming $\mathsf{P}\neq \mathsf{NP}$ and the [small set expansion hypothesis](wikipedia://en/73292008).[^o6] It is also W\[1\]-hard parameterized by the number $k$ of required components.[^o7] However an EPAS exists, which computes a $(1+\varepsilon)$-approximation in $(k/\varepsilon)^{O(k)}n^{O(1)}$ time.[^o8]

### Travelling Salesman {#Travelling_Salesman}

The [Travelling Salesman problem](https://en.wikipedia.org/wiki/Travelling_Salesman_problem) is [APX-hard](https://en.wikipedia.org/wiki/APX-hard) and [paraNP-hard](wikipedia://en/603026) parameterized by the [doubling dimension](wikipedia://en/30152339) (as it is [NP-hard](wikipedia://en/54681) in the [Euclidean plane](wikipedia://en/15575410)). However, an EPAS exists parameterized by the [doubling dimension](wikipedia://en/30152339), and even for the more general [highway dimension](https://en.wikipedia.org/wiki/Highway_dimension) parameter.[^o10]

### Steiner Tree {#Steiner_Tree}

The [Steiner Tree problem](wikipedia://en/498304) is FPT parameterized by the number of terminals.[^o12] However, for the "dual" parameter consisting of the number $k$ of non-terminals contained in the optimum solution, the problem is [W\[2\]-hard](wikipedia://en/603026#W_hierarchy) (due to a folklore reduction from the [Dominating Set problem](wikipedia://en/1747972)). Steiner Tree is also known to be [APX-hard](wikipedia://en/2018925).[^o13] However, there is an EPAS computing a $(1+\varepsilon)$-approximation in $2^{O(k^2/\varepsilon^4)}n^{O(1)}$ time.[^o14] The more general Steiner Forest problem is NP-hard on graphs of treewidth 3. However, on graphs of [treewidth](wikipedia://en/3987086) $t$ an EPAS can compute a $(1+\varepsilon)$-approximation in $2^{O(\frac{t^2}{\varepsilon}\log \frac{t}{\varepsilon})}n^{O(1)}$ time.[^o15]

### Strongly-Connected Steiner Subgraph {#Strongly-Connected_Steiner_Subgraph}

It is known that the Strongly Connected Steiner Subgraph problem is W\[1\]-hard parameterized by the number $k$ of terminals,[^o17] and also does not admit an $O(\log^{2-\varepsilon} n)$-approximation in polynomial time (under standard [complexity assumptions](wikipedia://en/7543)).[^o18] However a 2-approximation can be computed in $3^{k}n^{O(1)}$ time.[^o19] Furthermore, this is best possible, since no $(2-\varepsilon)$-approximation can be computed in $f(k)n^{O(1)}$ time for any function $f$, under Gap-[ETH](wikipedia://en/26434552).[^o20]

### *k*-Median and *k*-Means {#k-Median_and_k-Means}

For the well-studied metric clustering problems of [*k*-median](https://en.wikipedia.org/wiki/K-median_problem) and [*k*-means](wikipedia://en/1860407) parameterized by the number $k$ of centers, it is known that no $(1+2/e-\varepsilon)$-approximation for k-Median and no $(1+8/e-\varepsilon)$-approximation for k-Means can be computed in $f(k)n^{O(1)}$ time for any function $f$, under Gap-[ETH](wikipedia://en/26434552).[^o22] Matching parameterized approximation algorithms exist,[^o22] but it is not known whether matching approximations can be computed in polynomial time.

Clustering is often considered in settings of low dimensional data, and thus a practically relevant parameterization is by the [dimension](wikipedia://en/8398) of the underlying [metric](wikipedia://en/20018). In the [Euclidean space](wikipedia://en/9697), the k-Median and k-Means problems admit an EPAS parameterized by the dimension $d$,[^o23][^o24] and also an EPAS parameterized by $k$.[^o25][^o26] The former was generalized to an EPAS for the parameterization by the [doubling dimension](wikipedia://en/30152339).[^o27] For the loosely related [highway dimension](https://en.wikipedia.org/wiki/Highway_dimension) parameter, only an approximation scheme with [XP](wikipedia://en/603026) runtime is known to date.[^o28]

### *k*-Center {#k-Center}

For the metric [*k*-center problem](wikipedia://en/25385291) a 2-approximation can be computed in polynomial time. However, when parameterizing by either the number $k$ of centers,[^o30] the [doubling dimension](wikipedia://en/30152339) (in fact the dimension of a [Manhattan metric](https://en.wikipedia.org/wiki/Manhattan_metric)),[^o31] or the [highway dimension](https://en.wikipedia.org/wiki/Highway_dimension),[^o30] no parameterized $(2-\varepsilon)$-approximation algorithm exists, under standard [complexity assumptions](https://en.wikipedia.org/wiki/Complexity_theory_%28computation%29). Furthermore, the k-Center problem is W\[1\]-hard even on [planar graphs](wikipedia://en/24314) when simultaneously parameterizing it by the number $k$ of centers, the [doubling dimension](wikipedia://en/30152339), the [highway dimension](https://en.wikipedia.org/wiki/Highway_dimension), and the [pathwidth](wikipedia://en/5133142).[^o32] However, when combining $k$ with the doubling dimension an EPAS exists,[^o32] and the same is true when combining $k$ with the [highway dimension](https://en.wikipedia.org/wiki/Highway_dimension).[^o33] For the more general version with vertex capacities, an EPAS exists for the parameterization by k and the doubling dimension, but not when using k and the highway dimension as the parameter.[^o34] Regarding the pathwidth, k-Center admits an EPAS even for the more general [treewidth](wikipedia://en/3987086) parameter, and also for [cliquewidth](wikipedia://en/16795502).[^o35]

### Densest Subgraph {#Densest_Subgraph}

An [optimization](wikipedia://en/1126536) variant of the [*k*-Clique problem](wikipedia://en/249254) is the Densest *k*-Subgraph problem (which is a 2-ary [Constraint Satisfaction problem](wikipedia://en/211652)), where the task is to find a subgraph on $k$ vertices with maximum number of edges. It is not hard to obtain a $(k-1)$-approximation by just picking a [matching](wikipedia://en/581797) of size $k/2$ in the given input graph, since the maximum number of edges on $k$ vertices is always at most ${k \choose 2}= k(k-1)/2$. This is also [asymptotically](wikipedia://en/44578) optimal, since under Gap-[ETH](wikipedia://en/26434552) no $k^{1-o(1)}$-approximation can be computed in FPT time parameterized by $k$.[^o37]

### Dominating Set {#Dominating_Set}

For the [Dominating set problem](https://en.wikipedia.org/wiki/Dominating_set_problem) it is W\[1\]-hard to compute any $g(k)$-approximation in $f(k)n^{O(1)}$ time for any functions $g$ and $f$.[^o39]

## Approximate kernelization {#Approximate_kernelization}

[Kernelization](https://en.wikipedia.org/wiki/Kernelization) is a technique used in [fixed-parameter tractability](wikipedia://en/603026) to pre-process an instance of an [NP-hard](wikipedia://en/54681) problem in order to remove "easy parts" and reveal the NP-hard core of the instance. A kernelization algorithm takes an instance $I$ and a parameter $k$, and returns a new instance $I'$ with parameter $k'$ such that the size of $I'$ and $k'$ is bounded as a function of the input parameter $k$, and the algorithm runs in polynomial time. An **$\alpha$-approximate kernelization algorithm** is a variation of this technique that is used in parameterized approximation algorithms. It returns a kernel $I'$ such that any $\beta$-approximation in $I'$ can be converted into an $\alpha\beta$-approximation to the input instance $I$ in polynomial time. This notion was introduced by Lokshtanov et al.,[^o41] but there are other related notions in the literature such as Turing kernels[^o42] and **$\alpha$**-fidelity kernelization.[^o43]

As for regular (non-approximate) kernels, a problem admits an α-approximate kernelization algorithm [if and only if](wikipedia://en/14922) it has a parameterized α-approximation algorithm. The proof of this fact is very similar to [the one for regular kernels](https://en.wikipedia.org/wiki/Kernelization#Kernelizability_and_fixed-parameter_tractability_are_equivalent).[^o41] However the guaranteed approximate kernel might be of exponential size (or worse) in the input parameter. Hence it becomes interesting to find problems that admit polynomial sized approximate kernels. Furthermore, a **polynomial-sized approximate kernelization scheme (PSAKS)** is an **$\alpha$**-approximate kernelization algorithm that computes a polynomial-sized kernel and for which **$\alpha$** can be set to $1+\varepsilon$ for any $\varepsilon>0$.

For example, while the Connected [Vertex Cover](wikipedia://en/562782) problem is FPT parameterized by the solution size, it does not admit a (regular) polynomial sized kernel (unless $\textsf{NP}\subseteq \textsf{coNP/poly}$), but a PSAKS exists.[^o41] Similarly, the Steiner Tree problem is FPT parameterized by the number of terminals, does not admit a polynomial sized kernel (unless $\textsf{NP}\subseteq \textsf{coNP/poly}$), but a PSAKS exists.[^o41] When parameterizing Steiner Tree by the number of non-terminals in the optimum solution, the problem is W\[2\]-hard (and thus admits no exact kernel at all, unless FPT=W\[2\]), but still admits a PSAKS.[^o14]
