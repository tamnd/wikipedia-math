# Johnson's algorithm

::: {#o2 .subject cue=lead name="Johnson's algorithm"}

**Johnson's algorithm** is a way to find the [shortest paths](https://en.wikipedia.org/wiki/Shortest_path) between [all pairs of vertices](https://en.wikipedia.org/wiki/All-pairs_shortest_path_problem) in an [edge-weighted](https://en.wikipedia.org/wiki/Weighted_graph) [directed graph](wikipedia://en/19721986). It allows some of the edge weights to be [negative numbers](wikipedia://en/154616), but no negative-weight [cycles](wikipedia://en/168609) may exist. It works by using the [Bellman–Ford algorithm](wikipedia://en/221244) to compute a transformation of the input graph that removes all negative weights, allowing [Dijkstra's algorithm](wikipedia://en/45809) to be used on the transformed graph.[^o3][^o4] It is named after [Donald B. Johnson](https://en.wikipedia.org/wiki/Donald_B._Johnson), who first published the technique in 1977.[^o5]

:::

A similar reweighting technique is also used in a version of the successive shortest paths algorithm for the [minimum cost flow](https://en.wikipedia.org/wiki/Minimum_cost_flow) problem due to Edmonds and Karp,[^o6] as well as in [Suurballe's algorithm](https://en.wikipedia.org/wiki/Suurballe's_algorithm) for finding two disjoint paths of minimum total length between the same two vertices in a graph with non-negative edge weights.[^o7]

## Algorithm description {#Algorithm_description}

Johnson's algorithm consists of the following steps:[^o3][^o4]

1. First, a new [node](wikipedia://en/638899) $q$ is added to the graph, connected by zero-weight [edges](https://en.wikipedia.org/wiki/Edge_%28graph_theory%29) to each of the other nodes.
1. Second, the [Bellman–Ford algorithm](wikipedia://en/221244) is used, starting from the new vertex $q$, to find for each vertex $v$ the minimum weight $h(v)$ of a path from $q$ to $v$. If this step detects a negative cycle, the algorithm is terminated.
1. Next the edges of the original graph are reweighted using the values computed by the Bellman–Ford algorithm: an edge from $u$ to $v$, having length $w(u, v)$, is given the new length $w(u,v) + h(u) - h(v)$.
1. Finally, $q$ is removed, and [Dijkstra's algorithm](wikipedia://en/45809) is used to find the shortest paths from each node $s$ to every other vertex in the reweighted graph. The distance in the original graph is then computed for each distance $D$($u$, $v$), by adding $h(v) - h(u)$ to the distance returned by Dijkstra's algorithm.

In this reweighted graph, all edge weights are non-negative, but the shortest path between any two nodes uses the same sequence of edges as the shortest path between the same two nodes in the original graph. The algorithm concludes by applying Dijkstra's algorithm to each of the four starting nodes in the reweighted graph.

## Correctness {#Correctness}

In the reweighted graph, all paths between a pair $s$ and $t$ of nodes have the same quantity $h(s) - h(t)$ added to them. The previous statement can be proven as follows: Let $p$ be an $s-t$ path. Its weight W in the reweighted graph is given by the following expression:

$$\left(w(s, p_1) + h(s) - h(p_1)\right) + \left(w(p_1, p_2) + h(p_1) - h(p_2)\right) + ... + \left(w(p_n, t) + h(p_n) - h(t)\right).$$

Every $+h(p_i)$ is cancelled by $-h(p_i)$ in the previous bracketed expression; therefore, we are left with the following expression for *W*:

$$\left(w(s, p_1) + w(p_1, p_2) + \cdots + w(p_n, t)\right)+ h(s) - h(t)$$

The bracketed expression is the weight of *p* in the original weighting.

Since the reweighting adds the same amount to the weight of every $s-t$ path, a path is a shortest path in the original weighting if and only if it is a shortest path after reweighting. The weight of edges that belong to a shortest path from *q* to any node is zero, and therefore the lengths of the shortest paths from *q* to every node become zero in the reweighted graph; however, they still remain shortest paths. Therefore, there can be no negative edges: if edge *uv* had a negative weight after the reweighting, then the zero-length path from *q* to *u* together with this edge would form a negative-length path from *q* to *v*, contradicting the fact that all vertices have zero distance from *q*. The non-existence of negative edges ensures the optimality of the paths found by Dijkstra's algorithm. The distances in the original graph may be calculated from the distances calculated by Dijkstra's algorithm in the reweighted graph by reversing the reweighting transformation.[^o3]

## Analysis {#Analysis}

The [time complexity](wikipedia://en/405944) of this algorithm, using [Fibonacci heaps](https://en.wikipedia.org/wiki/Fibonacci_heap) in the implementation of Dijkstra's algorithm, is $O(|V|^2\log |V| + |V||E|)$: the algorithm uses $O(|V||E|)$ time for the Bellman–Ford stage of the algorithm, and $O(|V|\log |V| + |E|)$ for each of the $|V|$ instantiations of Dijkstra's algorithm. Thus, when the graph is [sparse](https://en.wikipedia.org/wiki/Sparse_graph), the total time can be faster than the [Floyd–Warshall algorithm](wikipedia://en/230401), which solves the same problem in time $O(|V|^3)$.[^o3]
