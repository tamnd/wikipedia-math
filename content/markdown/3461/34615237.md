# Equivalence (formal languages)

::: {#o1 .subject cue=lead name="Equivalence"}

In [formal language](wikipedia://en/10939) theory, **weak equivalence** of two [grammars](https://en.wikipedia.org/wiki/Formal_grammars) means they generate the same set of strings, i.e. that the formal language they generate is the same. In [compiler theory](https://en.wikipedia.org/wiki/Compiler_theory), where only [context-free grammars](wikipedia://en/6759) are considered, weak equivalence is distinguished from **strong** (or **structural**) **equivalence**, which additionally means that the two [parse trees](https://en.wikipedia.org/wiki/Parse_tree) are reasonably similar in that the same semantic interpretation can be assigned to both.[^o2]

:::

Two grammar formalisims are **weakly equivalent** if they define the same set of string languages. This notion is an instance of [weak equivalence in homotopy theory](wikipedia://en/34615176). Vijay-Shanker and Weir (1994)[^o3] demonstrated that [linear indexed grammars](https://en.wikipedia.org/wiki/Indexed_grammar), [combinatory categorial grammars](https://en.wikipedia.org/wiki/Combinatory_categorial_grammar), [tree-adjoining grammars](https://en.wikipedia.org/wiki/Tree-adjoining_grammar), and [head grammars](https://en.wikipedia.org/wiki/Head_grammar) are weakly equivalent formalisms in that meaning.

On the other hand, if two grammars generate the same set of derivation trees (or more generally, the same set of abstract syntactic objects), then the two grammars are strongly equivalent. Chomsky (1963)[^o15] introduces the notion of strong equivalence, and argues that only strong equivalence is relevant when comparing grammar formalisms. Kornai and Pullum (1990)[^o4] and Miller (1994)[^o5] offer a refined notion of strong equivalence that allows for isomorphic relationships between the syntactic analyses given by different formalisms. Yoshinaga, Miyao, and Tsujii (2002)[^o6] offers a proof that for any [LTAG](https://en.wikipedia.org/wiki/Tree-adjoining_grammar) formalism, there is a strongly equivalent [HPSG](https://en.wikipedia.org/wiki/Head-driven_phrase_structure_grammar) one.

## Context-free grammar example {#Context-free_grammar_example}

*Image: Parse Tree Derivations ETF.svg.* *Left:* one of the parse trees of the string "1+2\*3" with the first grammar. *Right:* the only parse tree of that string with the second grammar.

As an example, consider the following two [context-free grammars](wikipedia://en/6759),[^o8] given in [Backus-Naur form](https://en.wikipedia.org/wiki/Backus-Naur_form):

```bnf
<expression> ::= <expression> "+" <expression> | <expression> "-" <expression>
               | <expression> "*" <expression> | <expression> "/" <expression> 
               | "x" | "y" | "z"   |   "1" | "2" | "3"   |   "(" <expression> ")"
```

```bnf
<expression> ::= <term>   | <expression> "+" <term>   | <expression> "-" <term>
<term>       ::= <factor> |       <term> "*" <factor> |       <term> "/" <factor>
<factor>     ::= "x" | "y" | "z"   |   "1" | "2" | "3"   |   "(" <expression> ")"
```

Both grammars generate the same set of strings, viz. the set of all arithmetical expressions that can be built from the variables "x", "y", "z", the constants "1", "2", "3", the operators "+", "-", "\*", "/", and parentheses "(" and ")". However, a [concrete syntax tree](https://en.wikipedia.org/wiki/Concrete_syntax_tree) of the second grammar always reflects the usual [order of operations](wikipedia://en/212980), while a tree from the first grammar need not.

For the example string "1+2\*3", the right part of the picture shows its unique parse tree with the second grammar;[^o9] evaluating this tree in [postfix order](https://en.wikipedia.org/wiki/Postfix_traversal) will yield the proper value, 7. In contrast, the left picture part shows one of the parse trees for that string with the first grammar; evaluating it in postfix order will yield 9.

Since the second grammar cannot generate a tree corresponding to the left picture part, while the first grammar can, both grammars are not strongly equivalent.

## Generative capacity {#Generative_capacity}

In linguistics, the **weak generative capacity** of a [grammar](https://en.wikipedia.org/wiki/Generative_grammar) is defined as the set of all strings generated by it,[^o12] while a grammar's **strong generative capacity** refers to the set of "structural descriptions"[^o13] generated by it.[^o14] As a consequence, two grammars are considered weakly equivalent if their weak generative capacities coincide; similar for strong equivalence. The notion of *generative capacity* was introduced by [Noam Chomsky](https://en.wikipedia.org/wiki/Noam_Chomsky) in 1963.[^o15][^o14]
