# Discriminator

::: {#o1 .subject cue=lead name="Discriminator"}

In [computing](https://en.wikipedia.org/wiki/Computing), a **discriminator** is a [field](https://en.wikipedia.org/wiki/Field_%28computer_science%29) of characters designed to separate a certain element from others of the same [identifier](https://en.wikipedia.org/wiki/Identifier_%28computer_languages%29). As an example, suppose that a program must save two unique [objects](https://en.wikipedia.org/wiki/Object_%28computer_science%29) to memory, both of whose identifiers happen to be foo. To ensure the two objects are not conflated, the program may assign *discriminators* to the objects in the form of numbers; thus, foo (1) and foo (2) distinguish both objects named foo.

:::

This has been adopted by [programming languages](wikipedia://en/23015) as well as digital platforms for [instant messaging](https://en.wikipedia.org/wiki/Instant_messaging) and [massively multiplayer online games](https://en.wikipedia.org/wiki/Massively_multiplayer_online_game).

## In instant messaging {#In_instant_messaging}

A discriminator is used to disambiguate a [user](https://en.wikipedia.org/wiki/User_%28computing%29) from other users who wish to identify under the same username.

### Discord {#Discord}

On [Discord](https://en.wikipedia.org/wiki/Discord), a discriminator used to be a four-digit suffix added to the end of a [username](https://en.wikipedia.org/wiki/Username). This allowed for up to 10000 [user accounts](https://en.wikipedia.org/wiki/User_account) to take the same name.

#### Transition away from discriminators {#Transition_away_from_discriminators}

In 2023, co-founder [Stanislav Vishnevskiy](https://en.wikipedia.org/wiki/Stanislav_Vishnevskiy) wrote on a company blog post about the [technical debt](https://en.wikipedia.org/wiki/Technical_debt) caused by the discriminator system, stating that the system resulted in nearly half of the company's friend requests failing to connect. The platform implemented discriminators in the early days of the service, he wrote. When the platform was initially introduced, the [software developers](https://en.wikipedia.org/wiki/Software_developer)' priority was to let its users take any username they want without receiving a “your desired username is taken” error. Discord had no friend system at first, thus letting people take names in different [letter cases](https://en.wikipedia.org/wiki/Letter_case), making usernames case-sensitive.[^o5]

Discord also introduced a global display name system, wherein a user may input a default nickname to be shown on top of the messages they sent in lieu of their platform-wide username, Vishnevskiy touted on [Reddit](https://en.wikipedia.org/wiki/Reddit).[^o6]

The platform created a transition process to a system of [pseudonyms](https://en.wikipedia.org/wiki/Pseudonym#online_activity) wherein all new usernames would be case-insensitive lowercase and limited to the [ASCII](https://en.wikipedia.org/wiki/ASCII) characters of A–Z, 0–9, the [full stop](https://en.wikipedia.org/wiki/Full_stop) and the [underscore](https://en.wikipedia.org/wiki/Underscore). The transition would happen over the course of months, with the accounts that were registered the oldest, and paid subscribers, receiving the opportunity to reserve their name earlier.

This change was criticized online for being a step backward, as users could be a risk of being impersonated. A notable [indie game](https://en.wikipedia.org/wiki/Indie_game) studio noted that it could no longer claim its own name on the platform.[^o7] Discord pointed to its processes for users with high visibility and longstanding business relationships with the company for reserving a username under the new system. The old discriminator-oriented system also mitigated the rush to get unique usernames for sale on the [black market](https://en.wikipedia.org/wiki/Black_market), leading to [swatting](https://en.wikipedia.org/wiki/Swatting) and [online harassment](https://en.wikipedia.org/wiki/Online_harassment).[^o8][^o6]

## In digital distribution {#In_digital_distribution}

[Battle.net](https://en.wikipedia.org/wiki/Battle.net) implements a suffix of four-digit numbers to its usernames.

## In computer data storage {#In_computer_data_storage}

### Common Object Request Broker Architecture {#Common_Object_Request_Broker_Architecture}

A discriminator is a typed tag field present in the [Common Object Request Broker Architecture](https://en.wikipedia.org/wiki/Common_Object_Request_Broker_Architecture), the [interface description language](https://en.wikipedia.org/wiki/Interface_description_language) of the [Object Management Group](https://en.wikipedia.org/wiki/Object_Management_Group). It exists as type and value definitions of [tagged unions](wikipedia://en/453395) that determine which union member is selected in the current union instance. This is done by introduction of the classic [C](https://en.wikipedia.org/wiki/C_%28programming_language%29) switch construct as part of the classic C union.[^o12][^o13] Unlike in some conventional programming languages offering support for unions, the discriminator in IDL is not identical to the selected field name. Here is an example of an IDL union type definition:

```c
union Register switch (char) 
{
    case 'a':
    case 'b': short AX;

    case 'c': long EAX;

    default:  octet AL;
};
```

The effective value of the *Register* type may contain AX as the selected field, but the discriminator value may be either 'a' or 'b' and is stored in memory separately. Therefore, IDL logically separates information about the currently selected field name and the union effective value from information about the current discriminator value. In the example above, the discriminator value may be any of the following: 'a', 'b', 'c', as well as all other characters belonging to the IDL `char` type, since the `default` branch specified in the example *Register* type allows the use of the remaining characters as well.

### Other interface definition languages {#Other_interface_definition_languages}

The [Microsoft Interface Definition Language](https://en.wikipedia.org/wiki/Microsoft_Interface_Definition_Language) also supports tagged unions, allowing to choose the discriminator via an [attribute](https://en.wikipedia.org/wiki/Java_annotation) in an enclosing structure or function.[^o15]

## In deserialization {#In_deserialization}

When deserializing data from a data serialization format such as [JSON](https://en.wikipedia.org/wiki/JSON) in a object-oriented language, a type discriminator may be used for polymorphic deserialization.

In this example the discriminator field is named "\$type".

A serialization of a book.

```json
{
  "$type": "book",
  "title": "Do Androids Dream of Electric Sheep?",
  "author": "Philip K. Dick"
}
```

A serialization of a movie.

```json
{
  "$type": "movie",
  "title": "Titanic",
  "director": "James Cameron"
}
```

Both data serializations share a common field here named "\$type" which serves as the type discriminator. The book have the book-specific field "author", while the movie have the movie-specific field "director".

This facilitates the deserialization of data to different [classes](https://en.wikipedia.org/wiki/Class_%28programming%29) depending on the value of the type discriminator.

## Alternatives {#Alternatives}

A [friend code](https://en.wikipedia.org/wiki/Friend_code) is a unique twelve-digit number that could be exchanged with friends and be used to maintain individual friend lists in each [video game](https://en.wikipedia.org/wiki/Video_game). Friend codes were generated from an identifier unique to a copy of a game and the [universally unique identifier](https://en.wikipedia.org/wiki/Universally_unique_identifier) corresponding to that of a user's device.[^o18]
