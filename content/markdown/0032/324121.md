# Lsh

::: {#o1 .subject cue=lead name="Lsh"}

**lsh** is a [copyleft](https://en.wikipedia.org/wiki/Copyleft) implementation of the [Secure Shell](wikipedia://en/28814) (SSH) [protocol](https://en.wikipedia.org/wiki/Protocol_%28computing%29) version 2, by the [GNU Project](https://en.wikipedia.org/wiki/GNU_Project)[^o11][^o12][^o14][^o15] including both [server](https://en.wikipedia.org/wiki/Server_%28computing%29) and [client](https://en.wikipedia.org/wiki/Client_%28computing%29) programs. Featuring [Secure Remote Password protocol](https://en.wikipedia.org/wiki/Secure_Remote_Password_protocol) (SRP) as specified in secsh-srp[^o4][^o5] besides, [public-key authentication](https://en.wikipedia.org/wiki/Public-key_authentication). [Kerberos](wikipedia://en/16947) is somewhat supported as well. Currently however for password verification only, not as a [single sign-on](https://en.wikipedia.org/wiki/Single_sign-on) (SSO) method.

:::

lsh was started from scratch and predates [OpenSSH](wikipedia://en/25490426).[^o6]

Karim Yaghmour concluded in 2003 that lsh was "not fit for use" in production [embedded Linux](https://en.wikipedia.org/wiki/Embedded_Linux) systems, because of its dependencies upon other software packages that have a multiplicity of further dependencies. The lsh package requires the GNU MP library, [zlib](https://en.wikipedia.org/wiki/Zlib), and liboop, the latter of which in turn requires [GLib](https://en.wikipedia.org/wiki/GLib), which then requires [pkg-config](https://en.wikipedia.org/wiki/Pkg-config). Yaghmour further notes that lsh suffers from [cross-compilation](https://en.wikipedia.org/wiki/Cross-compilation) problems that it inherits from glib. "If ... your target isn't the same architecture as your host," he states, "LSH isn't a practical choice at this time."[^o13]

[Debian](https://en.wikipedia.org/wiki/Debian) provides packages of lsh as `lsh-server`,[^o7] `lsh-utils`, `lsh-doc` and `lsh-client`.[^o8]
