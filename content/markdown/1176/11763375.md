# Concatenated error correction code

::: {#o1 .subject cue=lead name="Concatenated error correction code"}

In [coding theory](wikipedia://en/321869), **concatenated codes** form a class of [error-correcting codes](https://en.wikipedia.org/wiki/Error-correcting_code) that are derived by combining an **inner code** and an **outer code**. They were conceived in 1966 by [Dave Forney](https://en.wikipedia.org/wiki/Dave_Forney) as a solution to the problem of finding a code that has both exponentially decreasing error probability with increasing block length and [polynomial-time](https://en.wikipedia.org/wiki/Polynomial-time) decoding [complexity](wikipedia://en/7543).[^o2] Concatenated codes became widely used in space communications in the 1970s.

:::

## Background {#Background}

The field of [channel coding](https://en.wikipedia.org/wiki/Channel_coding) is concerned with sending a stream of data at the highest possible rate over a given [communications channel](https://en.wikipedia.org/wiki/Communications_channel), and then decoding the original data reliably at the receiver, using encoding and decoding algorithms that are feasible to implement in a given technology.

[Shannon's channel coding theorem](wikipedia://en/3474289) shows that over many common channels there exist channel coding schemes that are able to transmit data reliably at all rates $R$ less than a certain threshold $C$, called the [channel capacity](wikipedia://en/231204) of the given channel. In fact, the probability of decoding error can be made to decrease exponentially as the block length $N$ of the coding scheme goes to infinity. However, the complexity of a naive optimum decoding scheme that simply computes the likelihood of every possible transmitted codeword increases exponentially with $N$, so such an optimum decoder rapidly becomes infeasible.

In his [doctoral thesis](https://web.archive.org/web/20121012080412/http://mitpress.mit.edu/catalog/item/default.asp?tid=5813&ttype=2), [Dave Forney](https://en.wikipedia.org/wiki/Dave_Forney) showed that concatenated codes could be used to achieve exponentially decreasing error probabilities at all data rates less than capacity, with decoding complexity that increases only polynomially with the code block length.

## Description {#Description}

*Image: Concatenated codes diagram.png.* Schematic depiction of a concatenated code built upon an inner code and an outer code.

*Image: Concatenation of Reed–Solomon code with Hadamard code.svg.* This is a pictorial representation of a code concatenation, and, in particular, the [Reed–Solomon code](https://en.wikipedia.org/wiki/Reed–Solomon_code) with n=q=4 and k=2 is used as the outer code and the [Hadamard code](wikipedia://en/7428961) with n=q and k=log q is used as the inner code. Overall, the concatenated code is a $[q^2,k \log q]$-code.

Let *C*<sub>*in*</sub> be a \[*n*, *k*, *d*\] code, that is, a [block code](wikipedia://en/1134659) of length *n*, [dimension](wikipedia://en/38267) *k*, minimum [Hamming distance](wikipedia://en/41227) *d*, and [rate](https://en.wikipedia.org/wiki/Code_rate) *r* = *k*/*n*, over an alphabet *A*:

$$C_{in}: A^k \rightarrow A^n$$

Let *C*<sub>*out*</sub> be a \[*N*, *K*, *D*\] code over an alphabet *B* with |*B*| = |*A*|<sup>*k*</sup> symbols:

$$C_{out}: B^K \rightarrow B^N$$

The inner code *C*<sub>*in*</sub> takes one of |*A*|<sup>*k*</sup> = |*B*| possible inputs, encodes into an *n*-tuple over *A*, transmits, and decodes into one of |*B*| possible outputs. We regard this as a (super) channel which can transmit one symbol from the alphabet *B*. We use this channel *N* times to transmit each of the *N* symbols in a codeword of *C*<sub>*out*</sub>. The *concatenation* of *C*<sub>*out*</sub> (as outer code) with *C*<sub>*in*</sub> (as inner code), denoted *C*<sub>*out*</sub>$\circ$*C*<sub>*in*</sub>, is thus a code of length *Nn* over the alphabet *A*:[^o2]

$$C_{out} \circ C_{in}: A^{kK} \rightarrow A^{nN}$$

It maps each input message *m* = (*m*<sub>1</sub>, *m*<sub>2</sub>, ..., *m*<sub>K</sub>) to a codeword (*C*<sub>*in*</sub>(*m*'<sub>1</sub>), *C*<sub>*in*</sub>(*m*'<sub>2</sub>), ..., *C*<sub>*in*</sub>(*m*'<sub>N</sub>)), where (*m*'<sub>1</sub>, *m*'<sub>2</sub>, ..., *m*'<sub>N</sub>) = *C*<sub>*out*</sub>(*m*<sub>1</sub>, *m*<sub>2</sub>, ..., *m*<sub>K</sub>).

The *key insight* in this approach is that if *C*<sub>*in*</sub> is decoded using a [maximum-likelihood approach](https://en.wikipedia.org/wiki/Maximum_likelihood_decoding) (thus showing an exponentially decreasing error probability with increasing length), and *C*<sub>*out*</sub> is a code with length *N* = 2<sup>*nr*</sup> that can be decoded in polynomial time of *N*, then the concatenated code can be decoded in polynomial time of its combined length *n*2<sup>*nr*</sup> = [*O*](https://en.wikipedia.org/wiki/O_notation)(*N*⋅log(*N*)) and shows an exponentially decreasing error probability, even if *C*<sub>*in*</sub> has exponential decoding complexity.[^o2] This is discussed in more detail in section Decoding concatenated codes.

In a generalization of above concatenation, there are *N* possible inner codes *C*<sub>*in*,*i*</sub> and the *i*-th symbol in a codeword of *C*<sub>*out*</sub> is transmitted across the inner channel using the *i*-th inner code. The [Justesen codes](wikipedia://en/18557138) are examples of generalized concatenated codes, where the outer code is a [Reed–Solomon code](https://en.wikipedia.org/wiki/Reed–Solomon_code).

::: {#o6 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

**\1.** The distance of the concatenated code *C*<sub>*out*</sub>$\circ$*C*<sub>*in*</sub> is at least *dD*, that is, it is a \[*nN*, *kK*, *D*'\] code with *D*' ≥ *dD*.

*Proof:* Consider two different messages *m*<sup>1</sup> ≠ *m*<sup>2</sup> ∈ *B*<sup>*K*</sup>. Let Δ denote the distance between two codewords. Then

$$\Delta(C_{out}(m^1), C_{out}(m^2)) \ge D.$$

Thus, there are at least *D* positions in which the sequence of *N* symbols of the codewords *C*<sub>*out*</sub>(*m*<sup>1</sup>) and *C*<sub>*out*</sub>(*m*<sup>2</sup>) differ. For these positions, denoted *i*, we have

$$\Delta(C_{in}(C_{out}(m^1)_i), C_{in}(C_{out}(m^2)_i)) \ge d.$$

Consequently, there are at least *d*⋅*D* positions in the sequence of *n*⋅*N* symbols taken from the alphabet *A* in which the two codewords differ, and hence

$$\Delta(C_{in}(C_{out}(m^1)), C_{in}(C_{out}(m^2))) \ge dD.$$

**\2.** If *C*<sub>*out*</sub> and *C*<sub>*in*</sub> are [linear block codes](https://en.wikipedia.org/wiki/Linear_block_code), then *C*<sub>*out*</sub>$\circ$*C*<sub>*in*</sub> is also a linear block code.

This property can be easily shown based on the idea of defining a [generator matrix](wikipedia://en/6133005) for the concatenated code in terms of the generator matrices of *C*<sub>*out*</sub> and *C*<sub>*in*</sub>.

:::

## Decoding concatenated codes {#Decoding_concatenated_codes}

A natural concept for a decoding algorithm for concatenated codes is to first decode the inner code and then the outer code. For the algorithm to be practical it must be [polynomial-time](https://en.wikipedia.org/wiki/Polynomial-time) in the final block length. Consider that there is a polynomial-time unique decoding algorithm for the outer code. Now we have to find a polynomial-time decoding algorithm for the inner code. It is understood that polynomial running time here means that running time is polynomial in the final block length. The main idea is that if the inner block length is selected to be logarithmic in the size of the outer code then the decoding algorithm for the inner code may run in [exponential time](https://en.wikipedia.org/wiki/Exponential_time) of the inner block length, and we can thus use an exponential-time but optimal [maximum likelihood decoder](wikipedia://en/1940782#Maximum_likelihood_decoding) (MLD) for the inner code.

In detail, let the input to the decoder be the vector *y* = (*y*<sub>1</sub>, ..., *y*<sub>*N*</sub>) ∈ (*A*<sup>*n*</sup>)<sup>*N*</sup>. Then the decoding algorithm is a two-step process:

1. Use the MLD of the inner code *C*<sub>in</sub> to reconstruct a set of inner code words *y*' = (*y*'<sub>1</sub>, ..., *y*'<sub>*N*</sub>), with *y*'<sub>*i*</sub> = MLD<sub>*C*<sub>in</sub></sub>(*y*<sub>i</sub>), 1 ≤ *i* ≤ *N*.
1. Run the unique decoding algorithm for *C*<sub>out</sub> on *y*'.

Now, the time complexity of the first step is [*O*](https://en.wikipedia.org/wiki/O_notation)(*N*⋅exp(*n*)), where *n* = *O*(log(*N*)) is the inner block length. In other words, it is *N*<sup>*O*(1)</sup> (i.e., polynomial-time) in terms of the outer block length *N*. As the outer decoding algorithm in step two is assumed to run in polynomial time the complexity of the overall decoding algorithm is polynomial-time as well.

### Remarks {#Remarks}

The decoding algorithm described above can be used to correct all errors up to less than *dD*/4 in number. Using [minimum distance decoding](https://en.wikipedia.org/wiki/Minimum_distance_decoding), the outer decoder can correct all inputs *y*' with less than *D*/2 symbols *y*'<sub>*i*</sub> in error. Similarly, the inner code can reliably correct an input *y*<sub>*i*</sub> if less than *d*/2 inner symbols are erroneous. Thus, for an outer symbol *y*'<sub>*i*</sub> to be incorrect after inner decoding at least *d*/2 inner symbols must have been in error, and for the outer code to fail this must have happened for at least *D*/2 outer symbols. Consequently, the total number of inner symbols that must be received incorrectly for the concatenated code to fail must be at least *d*/2⋅*D*/2 = *dD*/4.

The algorithm also works if the inner codes are different, e.g., for [Justesen codes](wikipedia://en/18557138). The [generalized minimum distance algorithm](https://en.wikipedia.org/wiki/Generalized_minimum_distance_decoding), developed by Forney, can be used to correct up to *dD*/2 errors.[^o9] It uses [erasure](https://en.wikipedia.org/wiki/Erasure_code) information from the inner code to improve performance of the outer code, and was the first example of an algorithm using [soft-decision decoding](https://en.wikipedia.org/wiki/Soft-decision_decoding).[^o10][^o11]

## Applications {#Applications}

Although a simple concatenation scheme was implemented already for the 1971 [Mariner](https://en.wikipedia.org/wiki/Mariner_8) Mars orbiter mission,[^o16] concatenated codes were starting to be regularly used for [deep space](https://en.wikipedia.org/wiki/Deep_Space_Network) communication with the [Voyager program](https://en.wikipedia.org/wiki/Voyager_program), which launched two [space probes](https://en.wikipedia.org/wiki/Space_probe) in 1977.[^o14] Since then, concatenated codes became the workhorse for efficient error correction coding, and stayed so at least until the invention of [turbo codes](https://en.wikipedia.org/wiki/Turbo_codes) and [LDPC codes](https://en.wikipedia.org/wiki/LDPC_codes).[^o16][^o14]

Typically, the inner code is not a block code but a [soft-decision](https://en.wikipedia.org/wiki/Soft-decision_decoder) [convolutional](wikipedia://en/40962) [Viterbi-decoded](https://en.wikipedia.org/wiki/Viterbi_decoder) code with a short constraint length.[^o15] For the outer code, a longer hard-decision block code, frequently a [Reed-Solomon code](https://en.wikipedia.org/wiki/Reed-Solomon_code) with eight-bit symbols, is used.[^o2][^o16] The larger symbol size makes the outer code more robust to [error bursts](https://en.wikipedia.org/wiki/Error_burst) that can occur due to channel impairments, and also because erroneous output of the convolutional code itself is bursty.[^o2][^o16] An [interleaving layer](https://en.wikipedia.org/wiki/Forward_error_correction#Interleaving) is usually added between the two codes to spread error bursts across a wider range.[^o16]

The combination of an inner Viterbi convolutional code with an outer [Reed–Solomon code](https://en.wikipedia.org/wiki/Reed–Solomon_code) (known as an RSV code) was first used in *[Voyager 2](https://en.wikipedia.org/wiki/Voyager_2)*,[^o16][^o17] and it became a popular construction both within and outside of the space sector. It is still notably used today for [satellite communications](https://en.wikipedia.org/wiki/Satellite_communication), such as the [DVB-S](https://en.wikipedia.org/wiki/DVB-S) [digital television](https://en.wikipedia.org/wiki/Digital_television) broadcast standard.[^o18]

In a looser sense, any (serial) combination of two or more codes may be referred to as a concatenated code. For example, within the [DVB-S2](https://en.wikipedia.org/wiki/DVB-S2) standard, a highly efficient [LDPC code](https://en.wikipedia.org/wiki/LDPC_code) is combined with an algebraic outer code in order to remove any resilient errors left over from the inner LDPC code due to its inherent [error floor](https://en.wikipedia.org/wiki/Error_floor).[^o19]

A simple concatenation scheme is also used on the compact disc (CD), where an interleaving layer between two Reed–Solomon codes of different sizes spreads errors across various blocks.

:::

## Turbo codes: A parallel concatenation approach {#Turbo_codes:_A_parallel_concatenation_approach}

The description above is given for what is now called a serially concatenated code. [Turbo codes](wikipedia://en/497535), as described first in 1993, implemented a parallel concatenation of two convolutional codes, with an interleaver between the two codes and an iterative decoder that passes information forth and back between the codes.[^o14] This design has a better performance than any previously conceived concatenated codes.

However, a key aspect of turbo codes is their iterated decoding approach. Iterated decoding is now also applied to serial concatenations in order to achieve higher coding gains, such as within serially concatenated convolutional codes (SCCCs). An early form of iterated decoding was implemented with two to five iterations in the "Galileo code" of the [Galileo space probe](https://en.wikipedia.org/wiki/Galileo_%28spacecraft%29).[^o16]
