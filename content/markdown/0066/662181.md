# Irrational base discrete weighted transform

::: {#o1 .subject cue=lead name="Irrational base discrete weighted transform"}

In [mathematics](wikipedia://en/18831), the **irrational base discrete weighted transform** (**IBDWT**) is a variant of the [fast Fourier transform](wikipedia://en/11512) using an [irrational](wikipedia://en/20647689) base; it was developed by [Richard Crandall](wikipedia://en/9210048) ([Reed College](https://en.wikipedia.org/wiki/Reed_College)), [Barry Fagin](https://en.wikipedia.org/wiki/Barry_Fagin) ([Dartmouth College](https://en.wikipedia.org/wiki/Dartmouth_College)) and [Joshua Doenias](https://en.wikipedia.org/wiki/Joshua_Doenias) ([NeXT Software](https://en.wikipedia.org/wiki/NeXT))[^o2] in the early 1990s using [Mathematica](https://en.wikipedia.org/wiki/Mathematica). It implies a fast, practical implementation of large-number [modular multiplication](https://en.wikipedia.org/wiki/Modular_multiplication) on modern computers, at asymptotically 2× faster than non-modular [FFT multiplication](https://en.wikipedia.org/wiki/FFT_multiplication).[^o3][^o12]

:::

It is most notably used in the [Great Internet Mersenne Prime Search](wikipedia://en/12917).

::: {#o5 .definition kind=definition/construction cue=heading name="Algorithm"}

## Algorithm {#Algorithm}

The IBDWT method, as applied to the Lucas-Lehmer test for Mersenne primes (which requires repeated squaring modulo a Mersenne number $M_p = 2^p - 1$), is based on four key elements developed by Crandall and Fagin:[^o8]

- **Balanced-radix representations**: Allows digits to be signed (e.g., in the range $-W/2 \le x_j < W/2$), which reduces error bounds.[^o8]
- **Variable-base digit representations**: Allows each digit $x_j$ to have its own base $W_j$.[^o8]
- **Weighted cyclic convolutions**: The multiplication is performed using a Discrete Weighted Transform (DWT).[^o8]
- **Irrational numeric bases**: The base used for the transform is irrational.[^o8]

This approach avoids the need for zero-padding the arrays and performs the multiplication modulo $M_p$ directly.[^o8] The algorithm to compute the product $xy \pmod{M_p}$ is as follows:[^o8]

1. Choose a run length (signal-length) $N < p$.[^o8]
1. Establish a variable base representation for the numbers. For example, $x = \sum_{j=0}^{N-1} x_j 2^{\lceil pj/N \rceil}$.[^o8] Each term is usually between 16 and 20 bits if using double-precision terms. The maximum size of each term is determined empirically, at least before the contribution of Percival 2003.
1. Define a weight-signal $a$ where each component $a_j = 2^{\lceil pj/N \rceil - pj/N}$, approximated by floats in the interval \[1, 2).[^o8]
1. Compute the forward DWT for both numbers: $\mathcal{X} \leftarrow DWT_{(N,a)}x$ and $\mathcal{Y} \leftarrow DWT_{(N,a)}y$. This is practically computed using a standard DFT (like an FFT) as $DWT_{(N,a)}x \triangleq DFT_{(N)}(ax)$.[^o8]
1. Perform a component-wise product of the transformed arrays: $\mathcal{Z} \leftarrow \mathcal{X}\mathcal{Y}$.[^o8]
1. Compute the inverse DWT: $z \leftarrow DWT_{(N,a)}^{-1}\mathcal{Z}$. This is computed as $z = a^{-1} DFT_{(N)}^{-1}(\mathcal{Z})$.[^o8]
1. Round the resulting components to the nearest integer: $z \leftarrow \text{round}(z)$, optionally checking the roundoff error is no greater than 0.4 (greater indicates too many integer bits stuffed into each term).[^o8]
1. Adjust the resulting digits $\{z_n\}$ to restore the variable-base radix representation. This step handles carries and borrows. Single-step partial carrying is sufficient.[^o8]

## Applications {#Applications}

Double-precision IBDWT is used in the [Great Internet Mersenne Prime Search](wikipedia://en/12917)'s x86 client [Prime95](https://en.wikipedia.org/wiki/Prime95) to perform modular multiplication in the [Lucas–Lehmer test](wikipedia://en/325739) and Fermat primarily tests. The prime95 IBDWT library *gwnum* is also used in programs such as [PrimeGrid](wikipedia://en/3255603)'s [LLR2 and PRST](wikipedia://en/15371861#LLR_software). It is chosen because x86 CPUs since Pentium 4 have so much double-precision floating-point computing power that it is much faster to multiply numbers using IBDWT than to do so using a more straightforward integer FFT (NTT).

Double-precision IBDWT has also been ported to other CPU architectures in the form of [Glucas](https://en.wikipedia.org/wiki/Glucas). It has also been ported to GPUs in the form of CUDALucas, GPUowl, and PRPLL.[^o8]

IBDWT can also be done using integer arithmetic modulo 2<sup>64</sup>-2<sup>32</sup>+1, a [number theoretic transform](https://en.wikipedia.org/wiki/Number_theoretic_transform). This approach was first demonstrated by Nick Craig-Wood in *ARMPrime*.[^o9] This too has been ported to GPUs, providing an alternative for consumer GPUs with weak double-precision computing power but acceptable 32-bit integer power, especially Nvidia models from the 2020s boasting "1:1" or "1:2" 32-bit integer multiplication speed but "1:64" double-precision speed relative to 32-bit floating-point.[^o10]

### Derived methods {#Derived_methods}

Granger and Scott demonstrated using IBDWT-inspired "GRP (generalized [repunit](wikipedia://en/215056) prime) multiplication" to accelerate eliptic curve cryptography over F(2<sup>521</sup>-1), the [P-521](https://en.wikipedia.org/wiki/P-521). This is a Karatsuba-like technique featuring a cyclic convolution similar to IBDWT.[^o12]
