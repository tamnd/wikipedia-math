# Cellular Message Encryption Algorithm

::: {#o1 .subject cue=lead name="Cellular Message Encryption Algorithm"}

In [cryptography](wikipedia://en/18934432), the **Cellular Message Encryption Algorithm** (**CMEA**) is a [block cipher](wikipedia://en/4594) which was used for securing [mobile phones](https://en.wikipedia.org/wiki/Mobile_phone) in the [United States](https://en.wikipedia.org/wiki/United_States). CMEA is one of four [cryptographic](wikipedia://en/18934432) primitives specified in a [Telecommunications Industry Association](https://en.wikipedia.org/wiki/Telecommunications_Industry_Association) (TIA) standard, and is designed to [encrypt](https://en.wikipedia.org/wiki/Encrypt) the control channel, rather than the voice data. In 1997, a group of cryptographers published attacks on the [cipher](wikipedia://en/5244) showing it had several weaknesses which give it a trivial effective strength of a 24-bit to 32-bit cipher.[^o3] Some accusations were made that the [NSA](https://en.wikipedia.org/wiki/NSA) had pressured the original designers into crippling CMEA, but the NSA has denied any role in the design or selection of the algorithm. The [ECMEA](https://en.wikipedia.org/wiki/ECMEA) and [SCEMA](https://en.wikipedia.org/wiki/SCEMA) ciphers are derived from CMEA.

:::

CMEA is described in 5159634. It is [byte-oriented](https://en.wikipedia.org/wiki/Byte-oriented), with variable [block size](wikipedia://en/294065), typically 2 to 6 bytes. The [key size](wikipedia://en/5749) is only 64 bits. Both of these are unusually small for a modern cipher. The algorithm consists of only 3 passes over the data: a non-linear left-to-right diffusion operation, an unkeyed linear mixing, and another non-linear diffusion that is in fact the inverse of the first. The non-linear operations use a keyed [lookup table](https://en.wikipedia.org/wiki/Lookup_table) called the *T-box*, which uses an unkeyed lookup table called the *CaveTable*. The algorithm is [self-inverse](wikipedia://en/293450); re-encrypting the ciphertext with the same key is equivalent to decrypting it.

CMEA is severely insecure. There is a [chosen-plaintext attack](wikipedia://en/63852), effective for all block sizes, using 338 chosen plaintexts. For 3-byte blocks (typically used to encrypt each dialled digit), there is a [known-plaintext attack](wikipedia://en/517019) using 40 to 80 known plaintexts. For 2-byte blocks, 4 known plaintexts suffice.

The "improved" CMEA, CMEA-I, is not much better: chosen-plaintext attack of it requires less than 850 plaintexts in its adaptive version.[^o4]
