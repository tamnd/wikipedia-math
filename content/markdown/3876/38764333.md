# Uncertain database

::: {#o1 .subject cue=lead name="Uncertain database"}

An **uncertain database**[^o2] is a kind of [database](https://en.wikipedia.org/wiki/Database) studied in [database theory](https://en.wikipedia.org/wiki/Database_theory). The goal of uncertain databases is to manage information on which there is some [uncertainty](wikipedia://en/63778). Uncertain databases make it possible to explicitly represent and manage uncertainty on the data, usually in a [succinct](https://en.wikipedia.org/wiki/Succinct_data_structure) way.

:::

::: {#o4 .definition cue=heading name="Formal definition"}

## Formal definition {#Formal_definition}

At the basis of uncertain databases is the notion of [possible world](wikipedia://en/780566). Specifically, a possible world of an uncertain database is a (certain) database which is one of the possible realizations of the uncertain database. A given uncertain database typically has more than one, and potentially infinitely many, possible worlds.

A formalism to represent uncertain databases then explains how to succinctly represent a set of possible worlds into one uncertain database.

:::

## Types of uncertain databases {#Types_of_uncertain_databases}

Uncertain database models differ in how they represent and quantify these possible worlds:

- **Incomplete databases**[^o6][^o7] are a compact representation of the set of possible worlds – the use of [NULL](https://en.wikipedia.org/wiki/NULL_%28SQL%29) in SQL, arguably the most commonplace instantiation of uncertain databases, is an example of incomplete database model.
- [Probabilistic databases](https://en.wikipedia.org/wiki/Probabilistic_database)[^o8] are a compact representation of a [probability distribution](wikipedia://en/23543) over the set of possible worlds.
- [Fuzzy databases](https://en.wikipedia.org/wiki/Fuzzy_database)[^o9] are a compact representation of a [fuzzy set](wikipedia://en/56601) of the possible worlds.

Though mostly studied in the [relational](https://en.wikipedia.org/wiki/Relational_model) setting, uncertain database models can also be defined in other [relational models](https://en.wikipedia.org/wiki/Relational_model) such as [graph databases](https://en.wikipedia.org/wiki/Graph_database)[^o10] or [XML databases](https://en.wikipedia.org/wiki/XML_database).

### Incomplete database {#Incomplete_database}

The most common [database model](https://en.wikipedia.org/wiki/Database_model) is the [relational model](https://en.wikipedia.org/wiki/Relational_model). Multiple incomplete database models have been defined over the relational model, that form extensions to the [relational algebra](wikipedia://en/175285). These have been called[^o12] Imieliński–Lipski algebras:

- Relations with [NULL](https://en.wikipedia.org/wiki/NULL_%28SQL%29) values, also called [Codd](https://en.wikipedia.org/wiki/Edgar_F._Codd) tables
- c-tables[^o6]
- v-tables[^o6]

::: {#o14 .example cue=heading name="Example"}

### Example {#Example}

The following table is a relation of an incomplete database, described in the formalism of [NULL](https://en.wikipedia.org/wiki/NULL_%28SQL%29) values:

::: {#o15 .table cue=table}

| id | Name | Salary |
|---|---|---|
| 1 | Alice | 10,000 |
| 2 | Bob |  |
| 3 | Charlie |  |

:::

There are infinitely many possible worlds for this incomplete database, obtained by replacing the "NULL" values with concrete values. For instance, the following relation is a possible world:

::: {#o16 .table cue=table}

| id | Name | Salary |
|---|---|---|
| 1 | Alice | 10,000 |
| 2 | Bob | 8,000 |
| 3 | Charlie | 12,000 |

:::

:::
