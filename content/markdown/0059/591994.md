# Cryptographic protocol

::: {#o1 .subject cue=lead name="Cryptographic protocol"}

A **cryptographic protocol** is an abstract or concrete [protocol](https://en.wikipedia.org/wiki/Communications_protocol) that performs a [security](wikipedia://en/15036)-related function and applies [cryptographic](https://en.wikipedia.org/wiki/Cryptographic) methods, often as sequences of [cryptographic primitives](wikipedia://en/4928985). A protocol describes how the algorithms should be used and includes details about data structures and representations, at which point it can be used to implement multiple, interoperable versions of a program.[^o2]

:::

Cryptographic protocols are widely used for secure application-level data transport. A cryptographic protocol usually incorporates at least some of these aspects:

- [Key agreement](https://en.wikipedia.org/wiki/Key_agreement) or establishment
- Entity [authentication](wikipedia://en/47967), perhaps using an [authentication protocol](https://en.wikipedia.org/wiki/Authentication_protocol)
- Symmetric [encryption](wikipedia://en/10294) and [message authentication](wikipedia://en/46671693) [key](wikipedia://en/53039) material construction
- Secured application-level data transport
- [Non-repudiation](wikipedia://en/52491) methods
- [Secret sharing](wikipedia://en/458253) methods
- [Secure multi-party computation](wikipedia://en/646233)

For example, [Transport Layer Security](wikipedia://en/187813) (TLS) is a cryptographic protocol that is used to secure web ([HTTPS](wikipedia://en/13586)) connections.[^o3] It has an entity authentication mechanism, based on the [X.509](https://en.wikipedia.org/wiki/X.509) system; a key setup phase, where a [symmetric encryption](https://en.wikipedia.org/wiki/Symmetric_encryption) key is formed by employing public-key cryptography; and an application-level data transport function. These three aspects have important interconnections. Standard TLS does not have non-repudiation support.

There are other types of cryptographic protocols as well, and even the term itself has various readings; Cryptographic *application* protocols often use one or more underlying [key agreement methods](https://en.wikipedia.org/wiki/Key_agreement), which are also sometimes themselves referred to as "cryptographic protocols". For instance, TLS employs what is known as the [Diffie–Hellman key exchange](wikipedia://en/7903), which although it is only a part of TLS *per se*, Diffie–Hellman may be seen as a complete cryptographic protocol in itself for other applications.

## Advanced cryptographic protocols {#Advanced_cryptographic_protocols}

A wide variety of cryptographic protocols go beyond the traditional goals of data confidentiality, integrity, and authentication to also secure a variety of other desired characteristics of computer-mediated collaboration.[^o5] [Blind signatures](wikipedia://en/428273) can be used for [digital cash](https://en.wikipedia.org/wiki/Ecash) and [digital credentials](https://en.wikipedia.org/wiki/Digital_credential) to prove that a person holds an attribute or right without revealing that person's identity or the identities of parties that person transacted with. [Secure digital timestamping](wikipedia://en/14155727) can be used to prove that data (even if confidential) existed at a certain time. [Secure multiparty computation](https://en.wikipedia.org/wiki/Secure_multiparty_computation) can be used to compute answers (such as determining the highest bid in an auction) based on confidential data (such as private bids), so that when the protocol is complete the participants know only their own input and the answer. [End-to-end auditable voting systems](https://en.wikipedia.org/wiki/End-to-end_auditable_voting_systems) provide sets of desirable privacy and auditability properties for conducting [e-voting](https://en.wikipedia.org/wiki/E-voting). [Undeniable signatures](https://en.wikipedia.org/wiki/Undeniable_signature) include interactive protocols that allow the signer to prove a forgery and limit who can verify the signature. [Deniable encryption](wikipedia://en/1055437) augments standard encryption by making it impossible for an attacker to mathematically prove the existence of a plain text message. [Digital mixes](https://en.wikipedia.org/wiki/Anonymous_re-mailer) create hard-to-trace communications.

## Formal verification {#Formal_verification}

Cryptographic protocols can sometimes be [verified formally](https://en.wikipedia.org/wiki/Formal_verification) on an abstract level. When it is done, there is a necessity to formalize the environment in which the protocol operates in order to identify threats. This is frequently done through the [Dolev-Yao](https://en.wikipedia.org/wiki/Dolev-Yao) model.

Logics, concepts and calculi used for formal reasoning of security protocols:

- [Burrows–Abadi–Needham logic (BAN logic)](wikipedia://en/196882)
- [Dolev–Yao model](wikipedia://en/3989298)
- [π-calculus](wikipedia://en/420373)
- [Protocol composition logic (PCL)](wikipedia://en/24649771)
- Strand space[^o8]

Research projects and tools used for formal verification of security protocols:

- Automated Validation of Internet Security Protocols and Applications (AVISPA) and follow-up project AVANTSSAR.[^o9][^o10]
  - Constraint Logic-based Attack Searcher (CL-AtSe)[^o11]
  - Open-Source Fixed-Point Model-Checker (OFMC)[^o12]
  - SAT-based Model-Checker (SATMC)[^o13]
- Casper[^o14]
- [CryptoVerif](wikipedia://en/33892403)
- Cryptographic Protocol Shapes Analyzer (CPSA)[^o15]
- Knowledge In Security protocolS (KISS)[^o16]
- Maude-NRL Protocol Analyzer (Maude-NPA)[^o17]
- [ProVerif](https://en.wikipedia.org/wiki/ProVerif)
- Scyther[^o18]
- [Tamarin Prover](https://en.wikipedia.org/wiki/Tamarin_Prover)[^o19]
- Squirrel[^o20]
- StrandsRocq[^o21]

### Notion of abstract protocol {#Notion_of_abstract_protocol}

To formally verify a protocol it is often abstracted and modelled using [Alice & Bob notation](https://en.wikipedia.org/wiki/Security_protocol_notation). A simple example is the following:

$$A\rightarrow B:\{X\}_{K_{A,B}}$$

This states that [Alice](wikipedia://en/679079) $A$ intends a message for Bob $B$ consisting of a message $X$ encrypted under shared key $K_{A,B}$.
