# Hamiltonian completion

*Image: Hamiltonian completion.svg.* A cycle connecting all points already exists in the top graph (marked by bold edges as opposed to the thin edges which aren't part of the cycle), but edge additions are necessary to make the middle and bottom graphs [Hamiltonian](https://en.wikipedia.org/wiki/Hamiltonian_graph) (marked by dotted blue lines).

::: {#o1 .subject cue=lead name="Hamiltonian completion"}

The **Hamiltonian completion** problem is to find the minimal number of edges to add to a [graph](wikipedia://en/325806) to make it [Hamiltonian](https://en.wikipedia.org/wiki/Hamiltonian_graph).

:::

The problem is clearly [NP-hard](https://en.wikipedia.org/wiki/NP-hard) in the general case (since its solution gives an answer to the [NP-complete](https://en.wikipedia.org/wiki/NP-complete) problem of determining whether a given graph has a [Hamiltonian cycle](https://en.wikipedia.org/wiki/Hamiltonian_cycle)). The associated [decision problem](wikipedia://en/8336) of determining whether *K* edges can be added to a given graph to produce a Hamiltonian graph is NP-complete.

Moreover, Hamiltonian completion belongs to the [APX](wikipedia://en/2018925) [complexity class](wikipedia://en/502426), i.e., it is unlikely that efficient [constant ratio approximation](https://en.wikipedia.org/wiki/Constant_ratio_approximation) algorithms exist for this problem.[^o2]

The problem may be solved in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) for certain classes of graphs, including [series–parallel graphs](wikipedia://en/9938559)[^o3] and their subgraphs,[^o4] which include [outerplanar graphs](wikipedia://en/352343), as well as for a [line graph](wikipedia://en/675231) of a tree[^o5][^o6] or a [cactus graph](wikipedia://en/9944209).[^o7]

Gamarnik et al. use a linear time algorithm for solving the problem on trees to study the asymptotic number of edges that must be added for sparse [random graphs](wikipedia://en/358477) to make them Hamiltonian.[^o8]
