# Risch algorithm

::: {#o1 .subject cue=lead name="Risch algorithm"}

In [symbolic computation](https://en.wikipedia.org/wiki/Symbolic_computation), the **Risch algorithm** is a method of indefinite integration used in some [computer algebra systems](wikipedia://en/54427) to find [antiderivatives](wikipedia://en/2823). It is named after the American mathematician [Robert Henry Risch](wikipedia://en/62778769), a specialist in computer algebra who developed it in 1968.

:::

The [algorithm](wikipedia://en/775) transforms the problem of [integration](https://en.wikipedia.org/wiki/Integration_%28calculus%29) into a problem in [algebra](wikipedia://en/1816587). It is based on the form of the function being integrated and on methods for integrating [rational functions](wikipedia://en/361210), [radicals](wikipedia://en/235029), [logarithms](wikipedia://en/17860), and [exponential functions](wikipedia://en/9678). Risch called it a [decision procedure](https://en.wikipedia.org/wiki/Decision_procedure), because it is a method for deciding whether a function has an [elementary function](wikipedia://en/10412) as an indefinite integral, and if it does, for determining that indefinite integral. However, the algorithm does not always succeed in identifying whether or not the antiderivative of a given function in fact can be expressed in terms of elementary functions. Specifically, the algorithm cannot solve the [constant problem](wikipedia://en/18308428), which is [undecidable](wikipedia://en/15631055) when it needs to determine whether an arbitrary complex number expression is equal to zero.

The complete description of the Risch algorithm takes over 100 pages.[^o2] The **Risch–Norman algorithm** is a simpler, faster, but less powerful variant that was developed in 1976 by [Arthur Norman](https://en.wikipedia.org/wiki/Arthur_Norman_%28computer_scientist%29).

Some significant progress has been made in computing the logarithmic part of a mixed transcendental-algebraic integral by Brian L. Miller.[^o3]

## Description {#Description}

The Risch algorithm is used to integrate [elementary functions](wikipedia://en/10412). These are functions obtained by composing exponentials, logarithms, radicals, trigonometric functions, and the four arithmetic operations (+ − × ÷). [Laplace](wikipedia://en/344783) solved this problem for the case of [rational functions](https://en.wikipedia.org/wiki/Rational_functions), as he showed that the indefinite integral of a rational function is the sum of a rational function and a finite number of constant multiples of logarithms of rational functions. The algorithm suggested by Laplace is usually described in calculus textbooks; as a computer program, it was finally implemented in the 1960s.

[Liouville](wikipedia://en/341810) formulated the problem that is solved by the Risch algorithm. Liouville proved by analytical means that if there is an elementary solution $g$ to the equation $g' = f$ then there exist constants $\alpha_{i}$ and functions $u_{i}$ and $v$ in the field generated by $f$ such that the solution is of the form

$$g = v + \sum_{i<n} \alpha_i \ln (u_i)$$

Risch developed a method that allows one to consider only a finite set of functions of Liouville's form.

The intuition for the Risch algorithm comes from the behavior of the exponential and logarithm functions under differentiation. For the function $f e^{g}$, where $f$ and $g$ are [differentiable functions](wikipedia://en/330206), we have

$$\left(f \cdot e^g\right)^\prime = \left(f^\prime + f\cdot g^\prime\right) \cdot e^g, \,$$

so if $e^{g}$ were in the result of an indefinite integration, it should be expected to be inside the integral. Also, as

$$\left(f \cdot(\ln g)^n\right)^\prime = f^\prime \left(\ln g\right)^n + n f \frac{g^\prime}{g} \left(\ln g\right)^{n - 1}$$

then if $(\ln g)^{n}$ were in the result of an integration, then only a few powers of the logarithm should be expected.

## Problem examples {#Problem_examples}

Finding an elementary antiderivative is very sensitive to details. For instance, the following algebraic function (posted to sci.math.symbolic by [Henri Cohen](https://en.wikipedia.org/wiki/Henri_Cohen_%28number_theorist%29) in 1993[^o6]) has an elementary antiderivative, as [Wolfram Mathematica](wikipedia://en/49024) since version 13 shows (however, Mathematica does not use the Risch algorithm to compute this integral):[^o7][^o8]

$$f(x) = \frac{x}{\sqrt{x^4 + 10 x^2 - 96 x - 71}},$$

namely:

$$\begin{aligned} F(x) = - \frac{1}{8}\ln &\,\Big( (x^6+15 x^4-80 x^3+27 x^2-528 x+781) \sqrt{ x^4+10 x^2-96 x-71} \Big. \\ & {} - \Big .(x^8 + 20 x^6 - 128 x^5 + 54 x^4 - 1408 x^3 + 3124 x^2 + 10001) \Big) + C. \end{aligned}$$

But if the constant term 71 is changed to 72, it is not possible to represent the antiderivative in terms of elementary functions,[^o10] as [FriCAS](wikipedia://en/20506812) also shows. Some [computer algebra systems](wikipedia://en/54427) may here return an antiderivative in terms of *non-elementary* functions (i.e. [elliptic integrals](wikipedia://en/9960)), which are outside the scope of the Risch algorithm. For example, Mathematica returns a result with the functions EllipticPi and EllipticF. Integrals in the form $\int \frac{x+A}{\sqrt{x^4+ax^3+bx^2+cx+d}}\, dx$ were solved by [Chebyshev](wikipedia://en/149568) (and in what cases it is elementary),[^o9] but the strict proof for it was ultimately done by [Zolotarev](https://en.wikipedia.org/wiki/Yegor_Ivanovich_Zolotarev).[^o10]

The following is a more complex example that involves both algebraic and [transcendental functions](wikipedia://en/297021):[^o11]

$$f(x) = \frac{x^2+2x+1+ (3x+1)\sqrt{x+\ln x}}{x\,\sqrt{x+\ln x}\left(x+\sqrt{x+\ln x}\right)}.$$

In fact, the antiderivative of this function has a fairly short form that can be found using substitution $u = x + \sqrt{x + \ln x}$ ([SymPy](https://en.wikipedia.org/wiki/SymPy) can solve it while FriCAS fails with "implementation incomplete (constant residues)" error in Risch algorithm):

$$F(x) = 2 \left(\sqrt{x+\ln x} + \ln\left(x+\sqrt{x+\ln x}\right)\right) + C.$$

Some Davenport "theorems"Davenport has not been mentioned to this point in the article, and his name only appears once later, and not in the context of theorems. are still being clarified. For example in 2020 a counterexample to such a "theorem" was found, where it turns out that an elementary antiderivative exists after all.[^o12]

## Implementation {#Implementation}

Transforming Risch's theoretical algorithm into an algorithm that can be effectively executed by a computer was a complex task which took a long time.

The case of the purely transcendental functions (which do not involve roots of polynomials) is relatively easy and was implemented early in most [computer algebra systems](wikipedia://en/54427). The first implementation was done by [Joel Moses](https://en.wikipedia.org/wiki/Joel_Moses) in [Macsyma](https://en.wikipedia.org/wiki/Macsyma) soon after the publication of Risch's paper.[^o15]

The case of purely algebraic functions was partially solved and implemented in [Reduce](https://en.wikipedia.org/wiki/Reduce_%28computer_algebra_system%29) by [James H. Davenport](https://en.wikipedia.org/wiki/James_H._Davenport) – for simplicity it could only deal with square roots and repeated square roots and not general [radicals](https://en.wikipedia.org/wiki/Radical_expression) or other non-quadratic [algebraic relations](wikipedia://en/404001) between variables.[^o16]

The general case was solved and almost fully implemented in Scratchpad, a precursor of [Axiom](https://en.wikipedia.org/wiki/Axiom_%28computer_algebra_system%29), by Manuel Bronstein, there is Axiom's fork FriCAS, with active Risch and other algorithm development on GitHub.[^o17][^o18] However, the implementation did not include some of the branches for special cases completely.[^o19][^o20] , there is no full implementation of the Risch algorithm.[^o21]

## Decidability {#Decidability}

The Risch algorithm applied to general elementary functions is not an algorithm but a [semi-algorithm](https://en.wikipedia.org/wiki/Semi-algorithm) because it needs to check, as a part of its operation, if certain expressions are equivalent to zero ([constant problem](wikipedia://en/18308428)), in particular in the constant field. For expressions that involve only functions commonly taken to be [elementary](wikipedia://en/10412) it is not known whether an algorithm performing such a check exists (current [computer algebra systems](wikipedia://en/54427) use heuristics); moreover, if one adds the [absolute value function](wikipedia://en/991) to the list of elementary functions, then it is known that no such algorithm exists; see [Richardson's theorem](wikipedia://en/13463844).

This issue also arises in the [polynomial division algorithm](https://en.wikipedia.org/wiki/Polynomial_division_algorithm); this algorithm will fail if it cannot correctly determine whether coefficients vanish identically.[^o23] Virtually every non-trivial algorithm relating to polynomials uses the polynomial division algorithm, the Risch algorithm included. If the constant field is [computable](https://en.wikipedia.org/wiki/Computable), i.e., for elements not dependent on $x$, then the problem of zero-equivalence is decidable, so the Risch algorithm is a complete algorithm. Examples of computable constant fields are $\mathbb{Q}$ and $\mathbb{Q}(y)$, i.e., rational numbers and rational functions in $y$ with rational-number coefficients, respectively, where $y$ is an indeterminate that does not depend on $x$.

This is also an issue in the [Gaussian elimination](wikipedia://en/13035) matrix algorithm (or any algorithm that can compute the [nullspace](https://en.wikipedia.org/wiki/Nullspace) of a matrix), which is also necessary for many parts of the Risch algorithm. Gaussian elimination will produce incorrect results if it cannot correctly determine whether a pivot is identically zero.
