# Probabilistically checkable proof

::: {#o1 .subject cue=lead name="Probabilistically checkable proof"}

In [computational complexity theory](wikipedia://en/7543), a **probabilistically checkable proof** (**PCP**) is a type of [proof](wikipedia://en/82285) that can be checked by a [randomized algorithm](wikipedia://en/495383) using a bounded amount of randomness and reading a bounded number of bits of the proof. The algorithm is then required to accept correct proofs and reject incorrect proofs with very high probability. A standard proof (or [certificate](wikipedia://en/14933760)), as used in the [verifier](https://en.wikipedia.org/wiki/Formal_verification)-based definition of the [complexity class](wikipedia://en/502426) [NP](wikipedia://en/21562), also satisfies these requirements, since the checking procedure deterministically reads the whole proof, always accepts correct proofs and rejects incorrect proofs. However, what makes them interesting is the existence of probabilistically checkable proofs that can be checked by reading only a few bits of the proof using randomness in an essential way.

:::

Probabilistically checkable proofs give rise to many complexity classes depending on the number of queries required and the amount of randomness used. The class $\operatorname{PCP}[r(n), q(n)]$ refers to the set of [decision problems](wikipedia://en/8336) that have probabilistically checkable proofs that can be verified in polynomial time using at most *r*(*n*) random bits and by reading at most *q*(*n*) bits of the proof. Unless specified otherwise, correct proofs should always be accepted, and incorrect proofs should be rejected with probability greater than 1/2. The [PCP theorem](wikipedia://en/3001241), a major result in computational complexity theory, states that $\operatorname{PCP}[O(\log n), O(1)] = \operatorname{NP}$.

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

Given a [decision problem](https://en.wikipedia.org/wiki/Computational_problem#Decision_problem) *L* (a [language](wikipedia://en/10939) over an [alphabet](wikipedia://en/4292269) Σ), a **probabilistically checkable proof system** for *L* with completeness *c*(*n*) and soundness *s*(*n*), where $0 \le s(n) \le c(n) \le 1$, consists of a prover and a verifier. Given a claimed solution *x* of length *n*, which might be false, the prover produces a proof *π* which states *x* solves $L$ ($x \in L$, the proof is a string in $\Sigma^{\ast}$). And the verifier is a randomized [oracle Turing Machine](wikipedia://en/22431) *V* (the *verifier*) that checks the proof *π* for the statement that *x* solves $L$ (or $x \in L$) and decides whether to accept the statement. The system has the following properties:

- **Completeness**: For any $x \in L$, given the proof *π* produced by the prover of the system, the verifier accepts the statement with probability at least *c*(*n*),
- **Soundness**: For any $x \notin L$, then for any proof *π*, the verifier mistakenly accepts the statement with probability at most *s*(*n*).

For the [computational complexity](wikipedia://en/7543) of the verifier, the verifier is polynomial time, and we have the *randomness complexity* *r*(*n*) to measure the maximum number of random bits that *V* uses over all *x* of length *n* and the *query complexity* *q*(*n*) of the verifier is the maximum number of queries that *V* makes to π over all *x* of length *n*.

In the above definition, the length of proof is not mentioned since usually it includes the alphabet set and all the witnesses. For the prover, we do not care how it arrives at the solution to the problem; we care only about the proof it gives of the solution's membership in the language.

The verifier is said to be *non-adaptive* if it makes all its queries before it receives any of the answers to previous queries.

The complexity class $\operatorname{PCP}_{c(n), s(n)}[r(n), q(n)]$ is the class of all decision problems having probabilistically checkable proof systems over binary alphabet of completeness *c*(*n*) and soundness *s*(*n*), where the verifier is non-adaptive, runs in polynomial time, and it has randomness complexity *r*(*n*) and query complexity *q*(*n*).

The shorthand notation $\operatorname{PCP}[r(n), q(n)]$ is sometimes used for $\operatorname{PCP}_{1, 1/2}[r(n), q(n)]$. The complexity class **PCP** is defined as $\operatorname{PCP}_{1, 1/2}[O(\log n), O(1)]$.

:::

## History and significance {#History_and_significance}

The theory of probabilistically checkable proofs studies the power of probabilistically checkable proof systems under various restrictions of the parameters (completeness, soundness, randomness complexity, query complexity, and alphabet size). It has applications to [computational complexity](wikipedia://en/7543) (in particular [hardness of approximation](wikipedia://en/20677277)) and [cryptography](wikipedia://en/18934432).

The definition of a probabilistically checkable proof was explicitly introduced by Arora and Safra in 1992, although their properties were studied earlier. In 1990 Babai, Fortnow, and Lund proved that **PCP**\[poly(*n*), poly(*n*)\] = **[NEXP](https://en.wikipedia.org/wiki/NEXP)**, providing the first nontrivial equivalence between standard proofs (**NEXP**) and probabilistically checkable proofs. The [PCP theorem](wikipedia://en/3001241) proved in 1992 states that $\operatorname{PCP}[O(\log n),O(1)] = \operatorname{NP}$.

The theory of [hardness of approximation](wikipedia://en/20677277) requires a detailed understanding of the role of completeness, soundness, alphabet size, and query complexity in probabilistically checkable proofs.

## Properties {#Properties}

From computational complexity point of view, for extreme settings of the parameters, the definition of probabilistically checkable proofs is easily seen to be equivalent to standard [complexity classes](https://en.wikipedia.org/wiki/Complexity_classes). For example, we have the following for different setting of $\operatorname{PCP}[r(n), q(n)]$:

- $\operatorname{PCP}[0, 0] = P$ ([P](wikipedia://en/658550) is defined to have no randomness and no access to a proof.)
- $\operatorname{PCP}[O(\log n), 0] = P$ (A logarithmic number of random bits doesn't help a polynomial time Turing machine, since it could try all possibly random strings of logarithmic length in polynomial time.)
- $\operatorname{PCP}[O(1),O(\log n)] = P$ (Without randomness, the proof can be thought of as a fixed logarithmic sized string. A polynomial time machine could try all possible logarithmic sized proofs and constant-length random strings in polynomial time.)
- $\operatorname{PCP}[\operatorname{poly}(n), 0] = \operatorname{coRP}$ (By definition of [coRP](wikipedia://en/54771).)
- $\operatorname{PCP}[0, \operatorname{poly}(n)] = \operatorname{NP}$ (By the verifier-based definition of [NP](wikipedia://en/21562).)

The PCP theorem and [MIP](wikipedia://en/160255#MIP) = NEXP can be characterized as follows:

- $\operatorname{PCP} [O(\log n),O(1)] = \operatorname{NP}$ (the PCP theorem)
- $$\operatorname{PCP} [\operatorname{poly}(n),O(1)] = \operatorname{PCP} [\operatorname{poly}(n),\operatorname{poly}(n)] = \operatorname{NEXP} (\operatorname{MIP} = \operatorname{NEXP}).$$

*Table of equalities*

::: {#o7 .table cue=table name="Table of equalities"}

| $\mathsf{PCP}[r(n), q(n)]$ | 0 | $O(1)$ | $O(\log n)$ | $\operatorname{poly}(n)$ |
|---|---|---|---|---|
| 0 | P | P | P | NP |
| $O(1)$ | P | P | P | NP |
| $O(\log n)$ | P | NP | NP | NP |
| $\operatorname{poly}(n)$ | coRP | MIP = NEXP | NEXP | NEXP |

:::

It is also known that $\operatorname{PCP}[r(n), q(n)] \subseteq \operatorname{NTIME}(\operatorname{poly}(n,2^{O(r(n))}q(n)))$. In particular, $\operatorname{PCP}[O(\log n), \operatorname{poly}(n)] = \operatorname{NP}$. On the other hand, if $\operatorname{NP} \subseteq \operatorname{PCP} [o(\log n),o(\log n)]$ then [P = NP](https://en.wikipedia.org/wiki/P_=_NP).

:::

## Linear PCP {#Linear_PCP}

A Linear PCP is a PCP in which the proof is a vector of elements of a finite field $\pi \in \mathbb{F}^n$, and such that the PCP oracle is only allowed to do linear operations on the proof. Namely, the response from the oracle to a verifier query $q \in \mathbb{F}^n$ is a linear function $f(q,\pi)$. Linear PCPs have important applications in proof systems that can be compiled into SNARKs.
