# PKCS 12

::: {#o3 .subject cue=lead name="PKCS 12"}

In [cryptography](wikipedia://en/18934432), **PKCS #12** defines an [archive file format](https://en.wikipedia.org/wiki/Archive_file) for storing many cryptography objects as a single file. It is commonly used to bundle a [private key](https://en.wikipedia.org/wiki/Private_key) with its [X.509](https://en.wikipedia.org/wiki/X.509) certificate or to bundle all the members of a [chain of trust](https://en.wikipedia.org/wiki/Chain_of_trust).

:::

A PKCS #12 file may be encrypted and signed. The internal storage containers, called "SafeBags", may also be encrypted and signed. A few SafeBags are predefined to store certificates, private keys and [CRLs](wikipedia://en/296365). Another SafeBag is provided to store any other data at individual implementer's choice.[^o4][^o5]

PKCS #12 is one of the family of standards called [Public-Key Cryptography Standards (PKCS)](wikipedia://en/616418) published by [RSA Laboratories](https://en.wikipedia.org/wiki/RSA_Laboratories).

The [filename extension](https://en.wikipedia.org/wiki/Filename_extension) for PKCS #12 files is `.p12` or `.pfx`.[^o6]

These files can be created, parsed and read out with the [OpenSSL](wikipedia://en/438819) `pkcs12` command.[^o7]

## Relationship to PFX file format {#Relationship_to_PFX_file_format}

PKCS #12 is the successor to [Microsoft](https://en.wikipedia.org/wiki/Microsoft)'s "PFX";[^o9] however, the terms "PKCS #12 file" and "PFX file" are sometimes used interchangeably.[^o6][^o7][^o10]

The PFX format has been criticized for being one of the most complex cryptographic protocols.[^o10]

## Normal usage {#Normal_usage}

The full PKCS #12 standard is very complex. It enables buckets of complex objects such as [PKCS #8](wikipedia://en/40387096) structures, nested deeply. But in practice it is normally used to store just one private key and its associated certificate chain.

PKCS #12 files are usually created using [OpenSSL](wikipedia://en/438819), which only supports a single private key from the command line interface. The Java keytool can be used to create multiple "entries" since Java 8, but that may be incompatible with many other systems.[^o12] As of Java 9 (released 2017-09-21), PKCS #12 is the default keystore format.[^o13][^o14]

A simpler, alternative format to PKCS #12 is [PEM](https://en.wikipedia.org/wiki/Privacy-enhanced_Electronic_Mail) which just lists the certificates and possibly private keys as [Base 64](https://en.wikipedia.org/wiki/Base_64) strings in a text file.

[GnuTLS](wikipedia://en/949758)'s *certtool* may also be used to create PKCS #12 files including certificates, keys, and CA certificates via **\--to-p12**. However, beware that for interchangeability with other software, if the sources are in PEM Base64 text, then **\--outder** should also be used.
