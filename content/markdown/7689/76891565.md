# Rao–Sandelius shuffle

::: {#o1 .subject cue=lead name="Rao–Sandelius shuffle"}

The **Rao–Sandelius shuffle** is a [divide-and-conquer algorithm](wikipedia://en/201154) for [shuffling](https://en.wikipedia.org/wiki/Shuffling) a finite [sequence](wikipedia://en/27838). The algorithm takes a list of all the elements of the sequence, and for each element draws a uniform random value from 0 to k-1. The list is broken up into k subsequences by the random value chosen, which are further shuffled.[^o2]

:::

For an array with $n$ entries, the algorithm consumes $O(n \log n)$ random digits and performs $O(n \log n)$ swaps. This appears worse than the [Fisher-Yates Shuffle](https://en.wikipedia.org/wiki/Fisher-Yates_Shuffle), which consumes $O(n \log n)$ random digits and performs $O(n)$ swaps. However, because of the random access pattern of the Fisher-Yates shuffle, the Rao-Sandelius Shuffle can be faster for large $n$ due to its cache friendliness.[^o3]

## Original method using random digit table {#Original_method_using_random_digit_table}

Rao described an algorithm for shuffling the numbers 1 through n using a table of random decimal digits.[^o5] Sandelius described a procedure for shuffling a deck with n cards using random decimal digits.[^o6] Sandelius includes the optimization that for a subdeck of length 2, you only need a single random digit. In the original, the order is kept for an odd random digit, and swapped for an even random digit. In either case the algorithm is as follows:

1. For each element to be shuffled, select a random digit 0 through 9.
1. Group elements that selected the same random digit into sub-lists.
1. Place the sub-lists in numerical order based on the digit selected.
1. Repeat on any sub-lists of size 2 or greater.

### Length 2 optimization {#Length_2_optimization}

Sandelius included the following optimization:[^o6] If the sub-list is of length 2, draw a single random digit. Swap the order if the digit is even, and leave it unchanged if the digit is odd.

## Implementation with random bits {#Implementation_with_random_bits}

It is straightforward to adapt a version of this algorithm to a computer using k=2.

1. For each element to be shuffled, select a random bit.
1. Place all the elements that selected 0 ahead of all elements that selected 1.
1. Repeat on the 2 sub-lists. This step can be parallelized.

The Size-2 speedup can also be applied in this case. Preserving the order if 1 is chosen, and swapping if 0 is chosen.

Here is pseudocode for an [in-place](https://en.wikipedia.org/wiki/In-place_algorithm) version of the algorithm (for a [zero-based](wikipedia://en/34541) [array](https://en.wikipedia.org/wiki/Array_data_structure)):

**function** rs\_shuffle(*A*, *n*): **if** *n* \< 2 **then** **return** **if** *n* = 2 **then**: *b* ← uniform random bit **if** *b* = 0 then exchange *A*\[0\] and *A*\[1\] **return** rs\_shuffle\_large(*A*, *n*)

**function** rs\_shuffle\_large(*A*, *n*): *front* ← 0 // Invariant 1: *front* is the index of the first // non-shuffled element *back* ← *n* - 1 // Invariant 2: *back* is the index of the last // non-shuffled element *outer:* **while** *true*: *b* ← uniform random bit **while** *b* ≠ 1 *front* ← *front* + 1 **if** *front* > *back* **then** **break** *outer* // (\*) *front* is now the index of an element // that belongs at the back. *b* ← uniform random bit **while** *b* ≠ 0 *back* ← *back* - 1 // Different due to (\*) above **if** *front* ≥ *back* **then** **break** *outer* exchange *A*\[*front*\] and *A*\[*back*\] // Restore Invariant 1 *front* ← *front* + 1 // Restore Invariant 2 *back* ← *back* - 1 **if** *front* > *back* **then** **break** *outer* // Because the two halves are disjoint, these // two calls could be done in parallel *rs\_shuffle*(*A*, *front*) *rs\_shuffle*(*A* + *front*, *n* - *front*)

The above uses a variation on the [Hoare partition scheme](wikipedia://en/3268249#Hoare_partition_scheme) to reduce the average number of swaps.

Each algorithm pass is effectively an [Inverse-GSR](wikipedia://en/39949312#Inverse) 2-shuffle.

## Performance {#Performance}

For large (e.g. $10^9$ items) data sets, the RS shuffle outperforms the more common [Fisher-Yates Shuffle](https://en.wikipedia.org/wiki/Fisher-Yates_Shuffle). It does this for two reasons:

1. It exhibits much better cache locality.
1. It is parallelizable. The Fisher-Yates shuffle is not.

Performance vs Fisher-Yates was measured by the authors of the [MergeShuffle](https://en.wikipedia.org/wiki/MergeShuffle) algorithm[^o10] and by the authors of the [VarPhilox GPU Shuffle](https://en.wikipedia.org/wiki/VarPhilox_Shuffle)[^o3]
