# McEliece cryptosystem

::: {#o1 .subject cue=lead name="McEliece cryptosystem"}

In [cryptography](wikipedia://en/18934432), the **McEliece cryptosystem** is an [asymmetric encryption](https://en.wikipedia.org/wiki/Asymmetric_encryption) algorithm developed in 1978 by [Robert McEliece](https://en.wikipedia.org/wiki/Robert_McEliece).[^o2] It was the first such scheme to use [randomization](wikipedia://en/495383) in the encryption process. The algorithm has never gained much acceptance in the cryptographic community, but is a candidate for "[post-quantum cryptography](wikipedia://en/26605226)", as it is immune to attacks using [Shor's algorithm](wikipedia://en/42674) and – more generally – measuring coset states using Fourier sampling.[^o3]

:::

The algorithm is based on the hardness of [decoding](wikipedia://en/1940782#Syndrome_decoding) a general [linear code](wikipedia://en/1866743) (which is known to be [NP-hard](https://en.wikipedia.org/wiki/NP-hard)[^o4]). For a description of the private key, an [error-correcting code](https://en.wikipedia.org/wiki/Error-correcting_code) is selected for which an efficient decoding algorithm is known, and that is able to correct $t$ errors. The original algorithm uses [binary Goppa codes](wikipedia://en/37834267) (subfield codes of [algebraic geometry codes](wikipedia://en/1882683) of a genus-0 curve over finite fields of characteristic 2); these codes can be efficiently decoded, thanks to an algorithm due to Patterson.[^o5] The public key is derived from the private key by disguising the selected code as a general linear code. For this, the code's [generator matrix](wikipedia://en/6133005) $G$ is perturbated by two randomly selected invertible matrices $S$ and $P$ (see below).

Variants of this cryptosystem exist, using different types of codes. Most of them were proven less secure; they were broken by [structural decoding](https://en.wikipedia.org/wiki/Structural_decoding).

McEliece with Goppa codes has resisted cryptanalysis so far. The most effective attacks known use [information-set decoding](wikipedia://en/1940782#Information_set_decoding) algorithms. A 2008 paper describes both an attack and a fix.[^o6] Another paper shows that for [quantum computing](wikipedia://en/25220), key sizes must be increased by a factor of four due to improvements in information set decoding.[^o7]

The McEliece cryptosystem has some advantages over, for example, [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29). The encryption and decryption are faster.[^o8] For a long time, it was thought that McEliece could not be used to produce [signatures](wikipedia://en/59644). However, a signature scheme can be constructed based on the [Niederreiter](wikipedia://en/21177402) scheme, the dual variant of the McEliece scheme. One of the main disadvantages of McEliece is that the private and public keys are large matrices. For a standard selection of parameters, the public key is 512 kilobits long.

## Scheme definition {#Scheme_definition}

McEliece consists of three algorithms: a probabilistic key generation algorithm that produces a public and a private key, a [probabilistic encryption](wikipedia://en/1051442) algorithm, and a deterministic decryption algorithm.

All users in a McEliece deployment share a set of common security parameters: $n, k, t$.

### Key generation {#Key_generation}

The principle is that Alice chooses a linear code $C$ from some family of codes for which she knows an efficient decoding algorithm, and to make $C$ public knowledge but keep the decoding algorithm secret. Such a decoding algorithm requires not just knowing $C$, in the sense of knowing an arbitrary generator matrix, but requires one to know the parameters used when specifying $C$ in the chosen family of codes. For instance, for binary Goppa codes, this information would be the Goppa polynomial and the code locators. Therefore, Alice may publish a suitably obfuscated generator matrix of $C$.

More specifically, the steps are as follows:

1. Alice selects a binary $(n, k)$-linear code $C$ capable of (efficiently) correcting $t$ errors from some large family of codes, e.g. binary Goppa codes. This choice should give rise to an efficient decoding algorithm $A$. Let also $G$ be any generator matrix for $C$. Any linear code has many generator matrices, but often there is a natural choice for this family of codes. Knowing this would reveal $A$ so it should be kept secret.
1. Alice selects a random $k \times k$ binary [non-singular matrix](wikipedia://en/217122) $S$.
1. Alice selects a random $n \times n$ [permutation matrix](wikipedia://en/238849) $P$.
1. Alice computes the $k \times n$ matrix ${\hat G} = SGP$.
1. Alice's public key is $({\hat G}, t)$; her private key is $(S, P, A)$. Note that $A$ could be encoded and stored as the parameters used for selecting $C$.

### Message encryption {#Message_encryption}

Suppose Bob wishes to send a message $m$ to Alice whose public key is $({\hat G}, t)$:

1. Bob encodes the message $m$ as a binary string of length $k$.
1. Bob computes the vector $c^{\prime} = m{\hat G}$.
1. Bob generates a random $n$-bit vector $z$ containing exactly $t$ ones (a vector of length $n$ and weight $t$)[^o2]
1. Bob sends Alice the ciphertext computed as $c = c^{\prime} + z$.

### Message decryption {#Message_decryption}

Upon receipt of $c$, Alice performs the following steps to decrypt the message:

1. Alice computes the inverse of $P$ (i.e. $P^{-1}$).
1. Alice computes ${\hat c} = cP^{-1}$.
1. Alice uses the decoding algorithm $A$ to decode ${\hat c}$ to ${\hat m}$.
1. Alice computes $m = {\hat m}S^{-1}$.

::: {#o14 .proof cue=heading name="Proof of message decryption"}

## Proof of message decryption {#Proof_of_message_decryption}

Note that ${\hat c} = cP^{-1} = m{\hat G}P^{-1} + zP^{-1} = mSG + zP^{-1}$, and that $P$ is a permutation matrix, thus $zP^{-1}$ has weight $t$.

The Goppa code $G$ can correct up to $t$ errors, and the word $mSG$ is at distance at most $t$ from $cP^{-1}$. Therefore, the correct code word ${\hat m} = mS$ is obtained.

Multiplying with the inverse of **$S$** gives $m = {\hat m}S^{-1}= mSS^{-1}$, which is the plain text message.

:::

## Key sizes {#Key_sizes}

Because there is a free choice in the matrix $S$, it is common to express ${\hat G}$ in "systematic form" so that the last $k$ columns correspond to the identity matrix ${\hat G} = ({\tilde G}|I)$. This reduces the key size to $(n-k) \times k$.[^o16][^o17] McEliece originally suggested security parameter sizes of $n=1024, k=524, t=50$,[^o2] resulting in a public key size of 524 × (1024 − 524) = 262,000 bits. Recent analysis suggests parameter sizes of $n=2048, k=1751, t=27$ for 80 [bits of security](https://en.wikipedia.org/wiki/Bits_of_security) when using standard algebraic decoding, or $n=1632, k=1269, t=34$ when using list decoding for the Goppa code, giving rise to public key sizes of 520,047 and 460,647 bits respectively.[^o6] For resiliency against quantum computers, sizes of $n=6960, k=5413, t=119$ with Goppa code were proposed, giving the size of public key of 8,373,911 bits.[^o18] In its round 3 submission to the NIST post quantum standardization the highest level of security, level 5 is given for parameter sets 6688128, 6960119, and 8192128. The parameters are $n=6688, k=5024, t= 128$, $n= 6960, k = 5413, t = 119$, $n=8192, k =6528, t = 128$ respectively.

## Attacks {#Attacks}

An attack consists of an adversary, who knows the public key $({\hat G}, t)$ but not the private key, deducing the plaintext from some intercepted ciphertext $y \in \mathbb{F}_2^n$. Such attempts should be infeasible.

There are two main branches of attacks for McEliece:

### Brute-force / unstructured attacks {#Brute-force_/_unstructured_attacks}

The attacker knows $\hat G$, the generator matrix of an $(n,k)$ code $\hat C$ that is combinatorially able to correct $t$ errors. The attacker may ignore the fact that $\hat C$ is really the obfuscation of a structured code chosen from a specific family, and instead just use an algorithm for decoding with any linear code. Several such algorithms exist, such as going through each codeword of the code, [syndrome decoding](wikipedia://en/1940782#Syndrome_decoding), or [information set decoding](wikipedia://en/1940782#Information_set_decoding).

Decoding a general linear code, however, is known to be [NP-hard](https://en.wikipedia.org/wiki/NP-hard),[^o4] and all of the above-mentioned methods have exponential running time.

In 2008, Bernstein, Lange, and Peters[^o6] described a practical attack on the original McEliece cryptosystem, using the information set decoding method by Stern.[^o22] Using the parameters originally suggested by McEliece, the attack could be carried out in 2<sup>\60.55</sup> bit operations. Since the attack is [embarrassingly parallel](wikipedia://en/1738712) (no communication between nodes is necessary), it can be carried out in days on modest computer clusters.

### Structural attacks {#Structural_attacks}

The attacker may instead attempt to recover the "structure" of $C$, thereby recovering the efficient decoding algorithm $A$ or another sufficiently strong, efficient decoding algorithm.

The family of codes from which $C$ is chosen completely determines whether this is possible for the attacker. Many code families have been proposed for McEliece, and most of them have been completely "broken" in the sense that attacks have been found that recover an efficient decoding algorithm, such as [Reed-Solomon codes](wikipedia://en/45600).

The originally proposed binary Goppa codes remain one of the few suggested families of codes that have largely resisted attempts at devising structural attacks.

:::

## Post-quantum encryption candidate {#Post-quantum_encryption_candidate}

A variant of this algorithm combined with NTS-KEM[^o25] was entered into and selected during the third round of the [NIST](https://en.wikipedia.org/wiki/National_Institute_of_Standards_and_Technology) [post-quantum encryption competition](wikipedia://en/56162225).[^o26]
