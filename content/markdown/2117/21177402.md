# Niederreiter cryptosystem

::: {#o1 .subject cue=lead name="Niederreiter cryptosystem"}

In [cryptography](wikipedia://en/18934432), the **Niederreiter cryptosystem** is a variation of the [McEliece cryptosystem](wikipedia://en/735452) developed in 1986 by [Harald Niederreiter](wikipedia://en/47275252).[^o2] It applies the same idea to the [parity check matrix](https://en.wikipedia.org/wiki/Parity_check_matrix), **H**, of a linear code. Niederreiter is equivalent to McEliece from a security point of view. It uses a syndrome as ciphertext and the message is an error pattern. The encryption of Niederreiter is about ten times faster than the encryption of McEliece. Niederreiter can be used to construct a [digital signature](wikipedia://en/59644) scheme.

:::

## Scheme definition {#Scheme_definition}

A special case of Niederreiter's original proposal was broken[^o4] but the system is secure when used with a [Binary Goppa code](wikipedia://en/37834267).

### Key generation {#Key_generation}

1. Alice selects a binary (*n*, *k*)-linear Goppa code, *G*, capable of correcting *t* errors. This code possesses an efficient decoding algorithm.
1. Alice generates a (*n* − *k*) × *n* parity check matrix, *H*, for the code, *G*.
1. Alice selects a random (*n* − *k*) × (*n* − *k*) binary [non-singular matrix](wikipedia://en/217122), *S*.
1. Alice selects a random *n* × *n* [permutation matrix](wikipedia://en/238849), *P*.
1. Alice computes the (*n* − *k*) × *n* matrix, *H*<sup>pub</sup> = *SHP*.
1. Alice's public key is (*H*<sup>pub</sup>, *t*); her private key is (*S*, *H*, *P*).

### Message encryption {#Message_encryption}

Suppose Bob wishes to send a message, *m*, to Alice whose public key is (*H*<sup>pub</sup>, *t*):

1. Bob encodes the message, *m*, as a binary string e<sup>m'</sup> of length *n* and weight at most *t*.
1. Bob computes the ciphertext as *c* = *H*<sup>pub</sup>*e*<sup>T</sup>.

### Message decryption {#Message_decryption}

Upon receipt of *c* = *H*<sup>pub</sup>*m*<sup>T</sup> from Bob, Alice does the following to retrieve the message, *m*.

1. Alice computes *S*<sup>−1</sup>*c* = *HPm*<sup>T</sup>.
1. Alice applies a [syndrome decoding](https://en.wikipedia.org/wiki/Syndrome_decoding) algorithm for *G* to recover *Pm*<sup>T</sup>.
1. Alice computes the message, *m*, via *m*<sup>T</sup> = *P*<sup>−1</sup>*Pm*<sup>T</sup>.

## Signature scheme {#Signature_scheme}

Courtois, Finiasz and Sendrier showed how the Niederreiter cryptosystem can be used to derive a signature scheme .[^o9][^o10]

1. Calculate $s=h(d)$, where $h$ is a [Hash Function](https://en.wikipedia.org/wiki/Hash_Function) and $d$ is the signed document.
1. Calculate $s_i = h(s|i), i = 0, 1, 2, \dots$, where $|$ denotes concatenation.
1. Attempt to decrypt $s_i$ until the smallest value of $i$ (denoted further as $i_0$) for which $s_i$ is decryptable is found.
1. Use the trapdoor function to compute such $z$ that $Hz^T=s_{i_0}$, where $H$ is the public key.
1. Compute the index $I_z$ of $z$ in the space of words of weight 9.
1. Use $\left[I_z|z\right]$ as the signature.

The Verification algorithm is much simpler:

1. Recover $z$ from index $I_z$.
1. Compute $s_1=Hz^T$ with the public key $H$.
1. Compute $s_2=h(h(d)|i_0)$.
1. Compare $s_1$ and $s_2$. If they are the same the signature is valid.

The index $I_z$ of $z$ can be derived using the formula below, where $i_1<\dots<i_9$ denote the positions of non-zero bits of $z$.

$$I_z = 1 + \sum_{n=1}^{9}{\binom{i_n}{n}}$$

The number of bits necessary to store $i_0$ is not reducible. On average it will be $log_2(9!)\approx 18.4$ bits long. Combined with the average $125.5$ bits necessary to store $I_z$, the signature will on average be $125.5+18.4\approx 144$ bits long.
