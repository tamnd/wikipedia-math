# Gap theorem

*See also [Gap theorem (disambiguation)](https://en.wikipedia.org/wiki/Gap_theorem_%28disambiguation%29) for other gap theorems in [mathematics](wikipedia://en/18831).*

::: {#o1 .subject cue=lead name="Gap theorem"}

In [computational complexity theory](wikipedia://en/7543), the **gap theorem,** also known as the **Borodin–Trakhtenbrot gap theorem,** is a major theorem about the complexity of [computable functions](wikipedia://en/1139338).[^o2]

:::

It essentially states that there are arbitrarily large computable gaps in the hierarchy of [complexity classes](wikipedia://en/502426). For any [computable function](wikipedia://en/1139338) that represents an increase in [computational resources](wikipedia://en/4628222), one can find a resource bound such that the set of functions computable within the expanded resource bound is the same as the set computable within the original bound.

The theorem was proved independently by [Boris Trakhtenbrot](wikipedia://en/2815679)[^o3] and [Allan Borodin](https://en.wikipedia.org/wiki/Allan_Borodin).[^o4][^o5] Although Trakhtenbrot's derivation preceded Borodin's by several years, it was not known nor recognized in [the West](https://en.wikipedia.org/wiki/Western_world#Cold_War_context) until after Borodin's work was published.

::: {#o7 .statement cue=heading name="Statement"}

## Statement {#Statement}

As an introductory example, suppose that we are considering [time complexity](wikipedia://en/405944) of a certain specific [Turing machine](wikipedia://en/30403) model. The set $\operatorname{TIME}(n^2)$ is the set of total computable functions, such that there exists some implementation of the function that computes it in time $\le n^2$ given an input size of $n$.

In general, any total computable function $t$ defines some $\operatorname{TIME}(t(n))$ time complexity class, and we expect that if $t'(n)$ is much larger than $t(n)$, for all $n$, then $\operatorname{TIME}(t'(n))$ should be larger than $\operatorname{TIME}(t(n))$. The gap theorem states that this is not necessarily so. Indeed, for any total computable $g$ such that $g(n) > n$ for all $n$, there exists some total computable function $t$, such that $\operatorname{TIME}(t(n)) = \operatorname{TIME}(g(t(n)))$. Intuitively, adding compute time might not allow us to compute more functions.

More generally, suppose $\Phi$ is an [abstract (Blum) complexity measure](wikipedia://en/2392005), then for any [total computable function](https://en.wikipedia.org/wiki/Total_computable_function) $g$ for which $g(x) \geq x$ for every $x$, there is a total computable function $t$ such that with respect to $\Phi$, the [complexity classes](wikipedia://en/502426) with boundary functions $t$ and $g \circ t$ are identical.

### Implications {#Implications}

For the special case of time complexity, this can be stated more simply as:

for any total computable function $g : \, \omega \,\to\, \omega$ such that $g(x) \geq x$ for all $x$, there exists a time bound $T(n)$ such that $\mathsf{DTIME}(g(T(n))) = \mathsf{DTIME}(T(n))$.

Similarly for the special case of [space complexity](wikipedia://en/338946).

Because the bound $T(n)$ may be very large (and often will be [nonconstructible](wikipedia://en/906783)) the gap theorem does not imply anything interesting for complexity classes such as [P](wikipedia://en/658550) or [NP](wikipedia://en/21562),[^o9] and it does not contradict the [time hierarchy theorem](wikipedia://en/184120) or [space hierarchy theorem](wikipedia://en/663050).[^o10]
