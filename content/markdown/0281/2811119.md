# L-notation

::: {#o1 .subject cue=lead name="L-notation"}

***L***-**notation** is an [asymptotic](wikipedia://en/641995) notation analogous to [big-O notation](https://en.wikipedia.org/wiki/Big-O_notation), denoted as $L_n[\alpha,c]$ for a [bound variable](https://en.wikipedia.org/wiki/Bound_variable) $n$ [tending to infinity](wikipedia://en/26551602). Like big-O notation, it is usually used to roughly convey the rate of growth of a [function](wikipedia://en/185427), such as the [computational complexity](wikipedia://en/7543) of a particular [algorithm](wikipedia://en/775).

:::

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

It is defined as

$$L_n[\alpha,c]=e^{(c+o(1))(\ln n)^\alpha(\ln\ln n)^{1-\alpha}}$$

where *c* is a positive constant, and $\alpha$ is a constant $0 \leq \alpha \leq 1$.

L-notation is used mostly in [computational number theory](wikipedia://en/511466), to express the complexity of algorithms for difficult [number theory](wikipedia://en/21527) problems, e.g. [sieves](wikipedia://en/1035915) for [integer factorization](wikipedia://en/15491) and methods for solving [discrete logarithms](wikipedia://en/181334). The benefit of this notation is that it simplifies the analysis of these algorithms. The $e^{c(\ln n)^\alpha(\ln\ln n)^{1-\alpha}}$ expresses the dominant term, and the $e^{o(1)(\ln n)^\alpha(\ln\ln n)^{1-\alpha}}$ takes care of everything smaller.

When $\alpha$ is 0, then

$$L_n[\alpha,c] = L_n[0, c] = e^{(c + o(1)) \ln\ln n} = (\ln n)^{c + o(1)}\,$$

is a [polylogarithmic function](wikipedia://en/445957) (a [polynomial function](https://en.wikipedia.org/wiki/Polynomial_function) of ln *n*);

When $\alpha$ is 1 then

$$L_n[\alpha,c] = L_n[1, c] = e^{(c + o(1)) \ln n} = n^{c + o(1)}\,$$

is a fully [exponential function](wikipedia://en/9678) of ln *n* (and thereby polynomial in *n*).

If $\alpha$ is between 0 and 1, the function is [subexponential](https://en.wikipedia.org/wiki/Sub-exponential_time) of ln *n* (and [superpolynomial](https://en.wikipedia.org/wiki/Superpolynomial)).

:::

::: {#o5 .example cue=heading name="Examples"}

## Examples {#Examples}

Many general-purpose [integer factorization](wikipedia://en/15491) algorithms have [subexponential time complexities](wikipedia://en/405944#Sub-exponential_time). The best is the [general number field sieve](wikipedia://en/152734), which has an expected running time of

$$L_n[1/3, c] = e^{(c+o(1))(\ln n)^{1/3}(\ln \ln n)^{2/3}}$$

for $c = (64/9)^{1/3} \approx 1.923$. The best such algorithm prior to the number field sieve was the [quadratic sieve](wikipedia://en/582340) which has running time

$$L_n[1/2, 1] = e^{(1+o(1))(\ln n)^{1/2}(\ln \ln n)^{1/2}}.\,$$

the third-fastest known factoring method: [Lenstra elliptic-curve factorization](wikipedia://en/154212) , which has running time

$$L_n[1/2, 2^{1/2}] = e^{(2^{1/2}+o(1))(\ln n)^{1/2}(\ln \ln n)^{1/2}}.\,$$

For the [elliptic curve](wikipedia://en/10225) [discrete logarithm](wikipedia://en/181334) problem, the fastest general purpose algorithm is the [baby-step giant-step](wikipedia://en/563928) algorithm, which has a running time on the order of the square-root of the group order *n*. In *L*-notation this would be

$$L_n[1, 1/2] = n^{1/2+o(1)}.\,$$

The existence of the [AKS primality test](https://en.wikipedia.org/wiki/AKS_primality_test), which runs in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time), means that the time complexity for [primality testing](https://en.wikipedia.org/wiki/Primality_testing) is known to be at most

$$L_n[0, c] = (\ln n)^{c+o(1)}\,$$

where *c* has been proven to be at most 6.[^o6]

:::

## History {#History}

L-notation has been defined in various forms throughout the literature. The first use of it came from [Carl Pomerance](wikipedia://en/2134159) in his paper "Analysis and comparison of some integer factoring algorithms".[^o8] This form had only the $c$ parameter: the $\alpha$ in the formula was $1/2$ for the algorithms he was analyzing. Pomerance had been using the letter $L$ (or lower case $l$) in this and previous papers for formulae that involved many logarithms.

The formula above involving two parameters was introduced by [Arjen Lenstra](wikipedia://en/6850292) and [Hendrik Lenstra](https://en.wikipedia.org/wiki/Hendrik_Lenstra) in their article on "Algorithms in Number Theory".[^o9] It was introduced in their analysis of a [discrete logarithm](wikipedia://en/181334) algorithm of [Coppersmith](wikipedia://en/540090). This is the most commonly used form in the literature today.

The Handbook of Applied Cryptography defines the L-notation with a big $O$ around the formula presented in this article.[^o10] This is not the standard definition. The big $O$ would suggest that the running time is an upper bound. However, for the integer factoring and discrete logarithm algorithms that L-notation is commonly used for, the running time is not an upper bound, so this definition is not preferred.
