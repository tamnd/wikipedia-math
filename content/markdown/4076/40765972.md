# One in ten rule

::: {#o1 .subject cue=lead name="One in ten rule"}

In [statistics](wikipedia://en/26685), the **one in ten rule** is a [rule of thumb](https://en.wikipedia.org/wiki/Rule_of_thumb) for how many [predictor](wikipedia://en/437701) parameters can be estimated from data when doing [regression analysis](wikipedia://en/826997) (in particular [proportional hazards models](https://en.wikipedia.org/wiki/Proportional_hazards_models) in [survival analysis](wikipedia://en/419259) and [logistic regression](wikipedia://en/226631)) while keeping the risk of [overfitting](wikipedia://en/173332) and finding [spurious correlations](https://en.wikipedia.org/wiki/Spurious_correlation) low. The rule states that one predictive variable can be studied for every ten events.[^o2][^o3][^o4][^o5] For logistic regression the number of events is given by the size of the smallest of the outcome categories, and for survival analysis it is given by the number of [uncensored](wikipedia://en/11548952) events.[^o4] In other words: for each feature we need 10 observations/labels.

:::

For example, if a sample of 200 patients is studied and 20 patients die during the study (so that 180 patients survive), the one in ten rule implies that two pre-specified predictors can reliably be fitted to the total data. Similarly, if 100 patients die during the study (so that 100 patients survive), ten pre-specified predictors can be fitted reliably. If more are fitted, the rule implies that overfitting is likely and the results will not predict well outside the [training data](https://en.wikipedia.org/wiki/Training,_validation,_and_test_sets). It is not uncommon to see the 1:10 rule violated in fields with many variables (e.g. gene expression studies in cancer), decreasing the confidence in reported findings.[^o6]

## Improvements {#Improvements}

A "one in 20 rule" has been suggested, indicating the need for [shrinkage](wikipedia://en/8301951) of regression coefficients, and a "one in 50 rule" for [stepwise selection](wikipedia://en/4877759) with the default [p-value](wikipedia://en/554994) of 5%.[^o5][^o8] Other studies, however, show that the one in ten rule may be too conservative as a general recommendation and that five to nine events per predictor can be enough, depending on the [research question](https://en.wikipedia.org/wiki/Research_question).[^o9]

More recently, a study has shown that the ratio of events per predictive variable is not a reliable statistic for estimating the minimum number of events for estimating a logistic prediction model.[^o10] Instead, the number of predictor variables, the total sample size (events + non-events) and the events fraction (events / total sample size) can be used to calculate the expected prediction error of the model that is to be developed.[^o11] One can then estimate the required sample size to achieve an expected prediction error that is smaller than a predetermined allowable prediction error value.[^o11]

Alternatively, three requirements for prediction model estimation have been suggested: the model should have a global shrinkage factor of ≥ 0.9, an [absolute difference](wikipedia://en/28021681) of ≤ 0.05 in the model's apparent and adjusted [Nagelkerke R<sup>2</sup>](wikipedia://en/71389706), and a precise estimation of the overall risk or rate in the target population.[^o12] The necessary sample size and number of events for model development are then given by the values that meet these requirements.[^o12]

## Other modalities {#Other_modalities}

For highly [correlated](wikipedia://en/157057) input data the one-in-10 rule (10 observations or labels needed per feature) may not be directly applicable due to the high correlation of the features: For images there is a rule of thumb that per class 1000 examples are needed.[^o14] This would mean that for a [binary classification](wikipedia://en/205393) of images (with fictive 1000 [pixel](https://en.wikipedia.org/wiki/Pixel) x 1000 pixel per image, i.e. 1 000 000 features per image), we would only require 2000 labels /1 000 0000 pixel = 0.002 labels per pixel or 0.002 labels per feature. This is however only due to the high (spatial) correlation of pixels.
