# Circular shift

*Image: Uppercase basic Latin alphabet forming a circle clockwise.svg.* Enciphering a letter of the latin alphabet with a key of value $26k$, where $k$ is a relative integer, leads to a circular shift of $|k|$ full turns.

::: {#o1 .subject cue=lead name="Circular shift"}

In [combinatorial](wikipedia://en/5170) [mathematics](wikipedia://en/18831), a **circular shift** is the operation of rearranging the entries in a [tuple](wikipedia://en/132729), either by moving the final entry to the first position, while shifting all other entries to the next position, or by performing the inverse operation. A circular shift is a special kind of [cyclic permutation](wikipedia://en/449166), which in turn is a special kind of [permutation](wikipedia://en/44027). Formally, a circular shift is a [permutation](wikipedia://en/44027) σ of the *n* entries in the tuple such that either

:::

$\sigma(i)\equiv (i+1)$ [modulo](wikipedia://en/20087) *n*, for all entries *i* = 1, ..., *n*

or

$\sigma(i)\equiv (i-1)$ [modulo](wikipedia://en/20087) *n*, for all entries *i* = 1, ..., *n*.

The result of repeatedly applying circular shifts to a given tuple are also called the **circular shifts** of the tuple.

For example, repeatedly applying circular shifts to the four-tuple (*a*, *b*, *c*, *d*) successively gives

- (*d*, *a*, *b*, *c*),
- (*c*, *d*, *a*, *b*),
- (*b*, *c*, *d*, *a*),
- (*a*, *b*, *c*, *d*) (the original four-tuple),

and then the sequence repeats; this four-tuple therefore has four distinct circular shifts. However, not all *n*-tuples have *n* distinct circular shifts. For instance, the 4-tuple (*a*, *b*, *a*, *b*) only has 2 distinct circular shifts. The number of distinct circular shifts of an *n*-tuple is $\frac{n}{k}$, where $k$ is a [divisor](wikipedia://en/49492) of $n$, indicating the maximal number of repeats over all subpatterns.

In [computer programming](https://en.wikipedia.org/wiki/Computer_programming), a **bitwise rotation**, also known as a circular shift, is a bitwise operation that shifts all bits of its operand. Unlike an [arithmetic shift](https://en.wikipedia.org/wiki/Arithmetic_shift), a circular shift does not preserve a number's sign bit or distinguish a [floating-point number](https://en.wikipedia.org/wiki/Floating-point_number)'s [exponent](https://en.wikipedia.org/wiki/Exponent) from its [significand](wikipedia://en/419250). Unlike a [logical shift](https://en.wikipedia.org/wiki/Logical_shift), the vacant bit positions are not filled in with zeros but are filled in with the bits that are shifted out of the sequence.

## Implementing circular shifts {#Implementing_circular_shifts}

Circular shifts are used often in [cryptography](wikipedia://en/18934432) in order to permute bit sequences. Unfortunately, many programming languages, including [C](https://en.wikipedia.org/wiki/C_%28programming_language%29), do not have operators or standard functions for circular shifting, even though virtually all [processors](https://en.wikipedia.org/wiki/Processor_%28computing%29) have [bitwise operation](wikipedia://en/264399) instructions for it (e.g. [Intel x86](https://en.wikipedia.org/wiki/Intel_x86) has ROL (Rotate Left) and ROR (Rotate Right)). However, some compilers may provide access to the processor instructions by means of [intrinsic functions](https://en.wikipedia.org/wiki/Intrinsic_function). In addition, some constructs in standard [ANSI C](https://en.wikipedia.org/wiki/ANSI_C) code may be optimized by a [compiler](https://en.wikipedia.org/wiki/Compiler) to the "rotate" [assembly language](https://en.wikipedia.org/wiki/Assembly_language) instruction on [CPUs](https://en.wikipedia.org/wiki/CPU) that have such an instruction. Most C compilers recognize the following idiom, and compile it to a single 32-bit rotate instruction.[^o3][^o4]

```C
/*
 * Shift operations in C are only defined for shift values which are
 * not negative and smaller than sizeof(value) * CHAR_BIT.
 * The mask, used with bitwise-and (&), prevents undefined behaviour
 * when the shift count is 0 or >= the width of unsigned int.
 */

#include <stdint.h>  // for uint32_t, to get 32-bit-wide rotates, regardless of the size of int.
#include <limits.h>  // for CHAR_BIT

uint32_t rotl32 (uint32_t value, unsigned int count) {
    const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
    count &= mask;
    return (value << count) | (value >> (-count & mask));
}

uint32_t rotr32 (uint32_t value, unsigned int count) {
    const unsigned int mask = CHAR_BIT * sizeof(value) - 1;
    count &= mask;
    return (value >> count) | (value << (-count & mask));
}
```

This safe and compiler-friendly implementation was developed by [John Regehr](https://en.wikipedia.org/wiki/John_Regehr),[^o5] and further polished by Peter Cordes.[^o6][^o7]

A simpler version is often seen when the `count` is limited to the range of 1 to 31 bits:

```C
uint32_t rotl32 (uint32_t value, unsigned int count) {
    return (value << count) | (value >> (32 - count));
}
```

This version is dangerous because if the `count` is 0 or 32, it asks for a 32-bit shift, which is [undefined behaviour](https://en.wikipedia.org/wiki/Undefined_behaviour) in the C language standard. However, it tends to work anyway, because most [microprocessors](https://en.wikipedia.org/wiki/Microprocessor) implement `value >> 32` as either a 32-bit shift (producing 0) or a 0-bit shift (producing the original `value`), and either one produces the correct result in this application.

## Applications {#Applications}

[Cyclic codes](wikipedia://en/4706825) are a kind of [block code](wikipedia://en/1134659) with the property that the circular shift of a codeword will always yield another codeword. This motivates the following general definition: For a [string](wikipedia://en/27701) *s* over an alphabet *Σ*, let *shift*(*s*) denote the [set](wikipedia://en/26691) of circular shifts of *s*, and for a set *L* of strings, let *shift*(*L*) denote the set of all circular shifts of strings in *L*. If *L* is a cyclic code, then *shift*(*L*) ⊆ *L*; this is a necessary condition for *L* being a [cyclic language](https://en.wikipedia.org/wiki/Cyclic_language). The operation *shift*(*L*) has been studied in [formal language theory](https://en.wikipedia.org/wiki/Formal_language_theory). For instance, if *L* is a [context-free language](wikipedia://en/6867), then *shift*(*L*) is again context-free.[^o12][^o13] Also, if *L* is described by a [regular expression](wikipedia://en/25717) of length *n*, there is a regular expression of length [O](wikipedia://en/44578)(*n*<sup>3</sup>) describing *shift*(*L*).[^o14]
