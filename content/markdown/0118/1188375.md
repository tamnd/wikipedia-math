# Turing reduction

::: {#o1 .subject cue=lead name="Turing reduction"}

In [computability theory](wikipedia://en/155414), a **Turing reduction** from a [decision problem](wikipedia://en/8336) $A$ to a decision problem $B$ is an [oracle machine](wikipedia://en/22431) that decides problem $A$ given an oracle for $B$ (Rogers 1967, Soare 1987) in finitely many steps. It can be understood as an [algorithm](wikipedia://en/775) that could be used to solve $A$ if it had access to a [subroutine](https://en.wikipedia.org/wiki/Subroutine) for solving $B$. The concept can be analogously applied to [function problems](wikipedia://en/663345).

:::

If a Turing reduction from $A$ to $B$ exists, then every [algorithm](wikipedia://en/775) for $B$ can be used to produce an algorithm for $A$, by inserting the algorithm for $B$ at each place where the oracle machine computing $A$ queries the oracle for $B$. However, because the oracle machine may query the oracle a large number of times, the resulting algorithm may require more time asymptotically than either the algorithm for $B$ or the oracle machine computing $A$. A Turing reduction in which the oracle machine runs in [polynomial time](https://en.wikipedia.org/wiki/Polynomial_time) is known as a **[Cook reduction](wikipedia://en/159695#Turing_reductions)**.

The first formal definition of relative computability, then called relative reducibility, was given by [Alan Turing](wikipedia://en/1208) in 1939 in terms of [oracle machines](wikipedia://en/22431). Later in 1943 and 1952 [Stephen Kleene](https://en.wikipedia.org/wiki/Stephen_Kleene) defined an equivalent concept in terms of [recursive functions](https://en.wikipedia.org/wiki/Mu-recursive_function). In 1944 [Emil Post](https://en.wikipedia.org/wiki/Emil_Post) used the term "Turing reducibility" to refer to the concept.

::: {#o3 .definition cue=heading name="Definition"}

## Definition {#Definition}

Given two sets $A,B \subseteq \mathbb{N}$ of natural numbers, we say $A$ is **Turing reducible** to $B$ and write

$$A \leq_T B$$

[if and only if](wikipedia://en/14922) there is an [oracle machine](wikipedia://en/22431) that computes the [characteristic function](wikipedia://en/240790) of *A* when run with oracle *B*. In this case, we also say *A* is ***B*-recursive** and ***B*-computable**.

If there is an oracle machine that, when run with oracle *B*, computes a [partial function](wikipedia://en/23577) with domain *A*, then *A* is said to be ***B*-[recursively enumerable](https://en.wikipedia.org/wiki/Recursively_enumerable_set)** and ***B*-computably enumerable**.

We say $A$ is **Turing equivalent** to $B$ and write $A \equiv_T B\,$ if both $A \leq_T B$ and $B \leq_T A.$ The [equivalence classes](wikipedia://en/9260) of Turing equivalent sets are called **[Turing degrees](wikipedia://en/764405)**. The Turing degree of a set $X$ is written $\textbf{deg}(X)$.

Given a set $\mathcal{X} \subseteq \mathcal{P}(\mathbb{N})$, a set $A \subseteq \mathbb{N}$ is called **Turing hard** for $\mathcal{X}$ if $X \leq_T A$ for all $X \in \mathcal{X}$. If additionally $A \in \mathcal{X}$ then $A$ is called **Turing complete** for $\mathcal{X}$.

### Relation of Turing completeness to computational universality {#Relation_of_Turing_completeness_to_computational_universality}

Turing completeness, as just defined above, corresponds only partially to [Turing completeness](wikipedia://en/30621) in the sense of computational universality. Specifically, a Turing machine is a [universal Turing machine](wikipedia://en/71435) if its [halting problem](wikipedia://en/21391870) (i.e., the set of inputs for which it eventually halts) is [many-one complete](wikipedia://en/362983) for the set $\mathcal{X}$ of recursively enumerable sets. Thus, a necessary *but insufficient* condition for a machine to be computationally universal, is that the machine's halting problem be Turing-complete for $\mathcal{X}$. Insufficient because it may still be the case that, the language accepted by the machine is not itself recursively enumerable.

:::

::: {#o6 .example cue=heading name="Example"}

## Example {#Example}

Let $W_e$ denote the set of input values for which the Turing machine with index *e* halts. Then the sets $A = \{e \mid e \in W_e\}$ and $B = \{(e,n) \mid n \in W_e \}$ are Turing equivalent (here $(-,-)$ denotes an effective [pairing function](wikipedia://en/1145848)). A reduction showing $A \leq_T B$ can be constructed using the fact that $e \in A \Leftrightarrow (e,e) \in B$. Given a pair $(e,n)$, a new index $i(e,n)$ can be constructed using the [*S* theorem](wikipedia://en/2330936) such that the program coded by $i(e,n)$ ignores its input and merely simulates the computation of the machine with index *e* on input *n*. In particular, the machine with index $i(e,n)$ either halts on every input or halts on no input. Thus $i(e,n) \in A \Leftrightarrow (e,n) \in B$ holds for all *e* and *n*. Because the function *i* is computable, this shows $B \leq_T A$. The reductions presented here are not only Turing reductions but *many-one reductions*, discussed below.

:::

::: {#o8 .statement kind=statement/fact cue=heading name="Properties"}

## Properties {#Properties}

- Every set is Turing equivalent to its complement.
- Every [computable set](wikipedia://en/332264) is Turing reducible to every other set. Because any computable set can be computed with no oracle, it can be computed by an oracle machine that ignores the given oracle.
- The relation $\leq_T$ is transitive: if $A \leq_T B$ and $B \leq_T C$ then $A \leq_T C$. Moreover, $A \leq_T A$ holds for every set *A*, and thus the relation $\leq_T$ is a [preorder](wikipedia://en/23582) (it is not a [partial order](https://en.wikipedia.org/wiki/Partial_order) because $A \leq_T B$ and $B \leq_T A$ does not necessarily imply $A = B$).
- There are pairs of sets $(A,B)$ such that *A* is not Turing reducible to *B* and *B* is not Turing reducible to *A*. Thus $\leq_T$ is not a [total order](wikipedia://en/30330).
- There are infinite decreasing sequences of sets under $\leq_T$. Thus this relation is not [well-founded](https://en.wikipedia.org/wiki/Well-founded).
- Every set is Turing reducible to its own [Turing jump](wikipedia://en/1681091), but the Turing jump of a set is never Turing reducible to the original set.

:::

## The use of a reduction {#The_use_of_a_reduction}

Since every reduction from a set $A$ to a set $B$ has to determine whether a single element is in $A$ in only finitely many steps, it can only make finitely many queries of membership in the set $B$. When the amount of information about the set $B$ used to compute a single bit of $A$ is discussed, this is made precise by the *use* function. Formally, the *use* of a reduction is the function that sends each natural number $n$ to the largest natural number $m$ whose membership in the set $B$ was queried by the reduction while determining the membership of $n$ in $A$.

## Stronger reductions {#Stronger_reductions}

There are two common ways of producing reductions stronger than Turing reducibility. The first way is to limit the number and manner of oracle queries.

- Set $A$ is **[many-one reducible](wikipedia://en/362983)** to $B$ if there is a [total computable function](wikipedia://en/1139338) $f$ such that an element $n$ is in $A$ if and only if $f(n)$ is in $B$. Such a function can be used to generate a Turing reduction (by computing $f(n)$, querying the oracle, and then interpreting the result).
- A **[truth-table reduction](wikipedia://en/2695407)** or a **weak truth-table reduction** must present all of its oracle queries at the same time. In a truth table reduction, the reduction also gives a Boolean function (a **truth table**) that, when given the answers to the queries, will produce the final answer of the reduction. In a weak truth table reduction, the reduction uses the oracle answers as a basis for further computation depending on the given answers (but not using the oracle). Equivalently, a weak truth table reduction is one for which the use of the reduction is bounded by a computable function. For this reason, weak truth table reductions are sometimes called "bounded Turing" reductions.

The second way to produce a stronger reducibility notion is to limit the computational resources that the program implementing the Turing reduction may use. These limits on the [computational complexity](wikipedia://en/7543) of the reduction are important when studying subrecursive classes such as [P](wikipedia://en/658550). A set *A* is **[polynomial-time reducible](wikipedia://en/159695)** to a set $B$ if there is a Turing reduction of $A$ to $B$ that runs in polynomial time. The concept of **[log-space reduction](wikipedia://en/1174850)** is similar.

These reductions are stronger in the sense that they provide a finer distinction into equivalence classes, and satisfy more restrictive requirements than Turing reductions. Consequently, such reductions are harder to find. There may be no way to build a many-one reduction from one set to another even when a Turing reduction for the same sets exists.

## Weaker reductions {#Weaker_reductions}

According to the [Church–Turing thesis](wikipedia://en/6854), a Turing reduction is the most general form of an effectively calculable reduction. Nevertheless, weaker reductions are also considered. Set $A$ is said to be **[arithmetical](wikipedia://en/2342451) in** $B$ if $A$ is definable by a formula of [Peano arithmetic](https://en.wikipedia.org/wiki/Peano_arithmetic) with $B$ as a parameter. The set $A$ is **[hyperarithmetical](https://en.wikipedia.org/wiki/Hyperarithmetical_hierarchy) in** $B$ if there is a [recursive ordinal](https://en.wikipedia.org/wiki/Recursive_ordinal) $\alpha$ such that $A$ is computable from $B^{(\alpha)}$, the *α*-iterated Turing jump of $B$. The notion of **[relative constructibility](wikipedia://en/343335#Relative_constructibility)** is an important reducibility notion in [set theory](wikipedia://en/27553).
