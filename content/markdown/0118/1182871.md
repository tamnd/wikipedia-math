# Hard-core predicate

::: {#o1 .subject cue=lead name="Hard-core predicate"}

In [cryptography](wikipedia://en/18934432), a **hard-core predicate** of a [one-way function](wikipedia://en/363890) *f* is a [predicate](https://en.wikipedia.org/wiki/Predicate_%28mathematics%29) *b* (i.e., a function whose output is a single bit) which is easy to compute (as a function of *x*) but is hard to compute given *f(x)*. In formal terms, there is no [probabilistic polynomial-time (PPT) algorithm](https://en.wikipedia.org/wiki/Bounded-error_probabilistic_polynomial) that computes *b(x)* from *f(x)* with probability [significantly greater](https://en.wikipedia.org/wiki/Negligible_function_%28cryptography%29) than one half over random choice of *x*.[^o2] In other words, if *x* is drawn uniformly at random, then given *f(x)*, any PPT adversary can only distinguish the hard-core bit *b(x)* and a uniformly random bit with negligible [advantage](wikipedia://en/4636092) over the length of *x*.[^o3]

:::

A **hard-core function** can be defined similarly. That is, if *x* is chosen uniformly at random, then given *f(x)*, any PPT algorithm can only distinguish the hard-core function value *h(x)* and uniformly random bits of length *\|h(x)|* with negligible advantage over the length of *x*.[^o4][^o5]

A hard-core predicate captures "in a concentrated sense" the hardness of inverting *f*.

While a [one-way function](wikipedia://en/363890) is hard to invert, there are no guarantees about the feasibility of computing partial information about the [preimage](https://en.wikipedia.org/wiki/Preimage) *c* from the image *f(x)*. For instance, while [RSA](https://en.wikipedia.org/wiki/RSA_%28algorithm%29) is conjectured to be a one-way function, the [Jacobi symbol](wikipedia://en/97313) of the preimage can be easily computed from that of the image.[^o2]

It is clear that if an [injective function](wikipedia://en/45196) has a hard-core predicate, then it must be a one-way function. [Oded Goldreich](https://en.wikipedia.org/wiki/Oded_Goldreich) and [Leonid Levin](https://en.wikipedia.org/wiki/Leonid_Levin) (1989) showed how every one-way function can be trivially modified to obtain a one-way function that has a specific hard-core predicate.[^o6] Let *f* be a one-way function. Define *g(x,r) = (f(x), r)* where the length of *r* is the same as that of *x*. Let *x<sub>j</sub>* denote the *j*<sup>th</sup> bit of *x* and *r<sub>j</sub>* the *j*<sup>th</sup> bit of *r*. Then

$$b(x,r) := \langle x, r\rangle = \bigoplus_j x_j r_j$$

is a hard core predicate of *g*. Note that *b(x, r)* = \<*x, r*> where \<·, ·> denotes the standard [inner product](wikipedia://en/14856) on the [vector space](wikipedia://en/32370) (**Z**<sub>2</sub>)<sup>*n*</sup>. This predicate is hard-core due to computational issues; that is, it is not hard to compute because *g(x, r)* is [information theoretically](wikipedia://en/14773) lossy. Rather, if there exists an algorithm that computes this predicate efficiently, then there is another algorithm that can invert *f* efficiently.

A similar construction yields a hard-core function with *O(log |x|)* output bits. Suppose *f* is a strong one-way function. Define *g(x, r)* = *(f(x), r)* where |*r*| = 2|*x*|. Choose a length function *l(n)* = *O(log n)* s.t. *l(n)* ≤ *n*. Let

$$b_i(x, r) = \bigoplus_j x_j r_{i+j}.$$

Then *h(x, r)* := *b<sub>1</sub>(x, r) b<sub>2</sub>(x, r) ... b<sub>l(|x|)</sub>(x, r)* is a hard-core function with output length *l(|x|)*.[^o7]

It is sometimes the case that an actual bit of the input *x* is hard-core. For example, every single bit of inputs to the RSA function is a hard-core predicate of RSA and blocks of *O(log |x|)* bits of *x* are indistinguishable from random bit strings in polynomial time (under the assumption that the RSA function is hard to invert).[^o8]

Hard-core predicates give a way to construct a [pseudorandom generator](https://en.wikipedia.org/wiki/CSPRNG) from any [one-way permutation](https://en.wikipedia.org/wiki/One-way_permutation). If *b* is a hard-core predicate of a one-way permutation *f*, and *s* is a random seed, then

$$\{ b(f^n(s))\}_n$$

is a pseudorandom bit sequence, where *f<sup>n</sup>* means the n-th iteration of applying *f* on *s*, and *b* is the generated hard-core bit by each round *n*.[^o2]

Hard-core predicates of trapdoor one-way permutations (known as **trapdoor predicates**) can be used to construct [semantically secure](wikipedia://en/960585) public-key encryption schemes.[^o2]
