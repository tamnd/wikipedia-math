# MS-CHAP

::: {#o1 .subject cue=lead name="MS-CHAP"}

**MS-CHAP** is the [Microsoft](https://en.wikipedia.org/wiki/Microsoft) version of the [Challenge-Handshake Authentication Protocol](wikipedia://en/71649), (CHAP).

:::

## Versions {#Versions}

The protocol exists in two versions, MS-CHAPv1 (defined in 2433) and MS-CHAPv2 (defined in 2759). MS-CHAPv2 was introduced with pptp3-fix that was included in [Windows NT 4.0](https://en.wikipedia.org/wiki/Windows_NT_4.0) SP4 and was added to [Windows 98](https://en.wikipedia.org/wiki/Windows_98) in the "Windows 98 Dial-Up Networking Security Upgrade Release"[^o3] and [Windows 95](https://en.wikipedia.org/wiki/Windows_95) in the "Dial Up Networking 1.3 Performance & Security Update for MS Windows 95" upgrade. [Windows Vista](https://en.wikipedia.org/wiki/Windows_Vista) dropped support for MS-CHAPv1.

::: {#o5 .application cue=heading name="Applications"}

## Applications {#Applications}

MS-CHAP is used as one authentication option in Microsoft's implementation of the [PPTP](https://en.wikipedia.org/wiki/PPTP) protocol for [virtual private networks](wikipedia://en/147130). It is also used as an authentication option with [RADIUS](https://en.wikipedia.org/wiki/RADIUS)[^o6] servers which are used with [IEEE 802.1X](https://en.wikipedia.org/wiki/IEEE_802.1X) (e.g., [WiFi](https://en.wikipedia.org/wiki/WiFi) security using the [WPA-Enterprise](wikipedia://en/422017) protocol). It is further used as the main authentication option of the [Protected Extensible Authentication Protocol](https://en.wikipedia.org/wiki/Protected_Extensible_Authentication_Protocol) (PEAP).

:::

## Features {#Features}

Compared with CHAP,[^o8] MS-CHAP:[^o9][^o10] works by negotiating CHAP Algorithm 0x80 (0x81 for MS-CHAPv2) in LCP option 3, Authentication Protocol. It provides an authenticator-controlled password change mechanism. It provides an authenticator-controlled authentication retry mechanism and defines failure codes returned in the Failure packet message field.

*Image: MSCHAPv2\_Flow.pdf.*

MS-CHAPv2 provides mutual authentication between peers by piggybacking a peer challenge on the response packet and an authenticator response on the success packet.

MS-CHAP requires each peer to either know the plaintext password, or an MD4 hash of the password, and does not transmit the password over the link. As such, it is not compatible with most [password storage](wikipedia://en/24304#Form_of_stored_passwords) formats.

## Flaws {#Flaws}

Weaknesses have been identified in MS-CHAP and MS-CHAPv2.[^o12] The [DES](wikipedia://en/7978) encryption used in NTLMv1 and MS-CHAPv2 to encrypt the [NTLM](https://en.wikipedia.org/wiki/NTLM) password hash enable custom hardware attacks utilizing the method of brute force.[^o13]

As of 2012, MS-CHAP had been completely broken. The divide-and-conquer attack only requires breaking a single DES key, which is not difficult with modern [GPUs](https://en.wikipedia.org/wiki/GPU) and [FPGAs](https://en.wikipedia.org/wiki/FPGA).[^o14] MS-CHAP as a whole can be viewed as a smoke-and-mirrors protocol, in that ~80% of the protocol provides no real security; it just makes the construction very complicated and thus appear infeasible to crack. In reality, this ~80% is either plaintext messages, or messages easily derived from those sent in plaintext. The actual security core is reduced to the NTLM password hash and DES encryptions keyed by the hash output, which is fundamentally weak.

After [Windows 11](https://en.wikipedia.org/wiki/Windows_11) 22H2, with the default activation of Windows Defender Credential Guard, users can no longer authenticate with MSCHAPv2. The developers recommend a move from MSCHAPv2-based connections to certificate-based authentication (such as PEAP-TLS or [EAP-TLS](https://en.wikipedia.org/wiki/Extensible_Authentication_Protocol#EAP-TLS)).[^o15]
