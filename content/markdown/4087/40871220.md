# Polling system

::: {#o1 .subject cue=lead name="Polling system"}

*Image: Polling system.svg.* Polling server serving *n* queueing nodes

In [queueing theory](wikipedia://en/50578), a discipline within the mathematical [theory of probability](wikipedia://en/23542), a **polling system** or **polling model** is a system where a single server visits a set of queues in some order.[^o2] The model has applications in computer networks and [telecommunications](https://en.wikipedia.org/wiki/Telecommunications),[^o3] [manufacturing](https://en.wikipedia.org/wiki/Manufacturing)[^o4][^o5] and [road traffic management](https://en.wikipedia.org/wiki/Road_traffic_management). The term polling system was coined at least as early as 1968[^o6][^o7] and the earliest study of such a system in 1957 where a single repairman servicing machines in the British cotton industry was modelled.[^o8]

:::

Typically it is assumed that the server visits the different queues in a cyclic manner.[^o2] Exact results exist for waiting times, marginal queue lengths and joint queue lengths[^o9] at polling epochs in certain models.[^o10] [Mean value analysis](wikipedia://en/22440733) techniques can be applied to compute average quantities.[^o11]

In a [fluid limit](wikipedia://en/40878507), where a very large number of small jobs arrive the individual nodes can be viewed to behave similarly to [fluid queues](wikipedia://en/33791981) (with a two state process).[^o12]

## Model definition {#Model_definition}

A group of *n* queues are served by a single server, typically in a cyclic order 1, 2, …, *n*, 1, …. New jobs arrive at queue *i* according to a [Poisson process](https://en.wikipedia.org/wiki/Poisson_process) of rate *λ*<sub>*i*</sub> and are served on a [first-come, first-served](https://en.wikipedia.org/wiki/First-come,_first-served) basis with each job having a service time denoted by an [independent and identically distributed random variables](wikipedia://en/30876902) *S*<sub>*i*</sub>.

The server chooses when to progress to the next node according to one of the following criteria:[^o14]

- exhaustive service, where a node continues to receive service until the buffer is empty.
- gated service, where the node serves all traffic that was present at the instant that the server arrived and started serving, but subsequent arrivals during this service time must wait until the next server visit.
- limited service, where a maximum fixed number of jobs can be served in each visit by the server.[^o15]

If a queueing node is empty the server immediately moves to serve the next queueing node.

The time taken to switch from serving node *i* − 1 and node *i* is denoted by the random variable *d*<sub>*i*</sub>.

### Utilization {#Utilization}

Define *ρ*<sub>*i*</sub> = *λ*<sub>*i*</sub> E(*S*<sub>*i*</sub>) and write *ρ* = *ρ*<sub>1</sub> + *ρ*<sub>2</sub> + … + *ρ*<sub>*n*</sub>. Then *ρ* is the long-run fraction of time the server spends attending to customers.[^o17]

## Waiting time {#Waiting_time}

### Expected waiting time {#Expected_waiting_time}

For gated service, the expected waiting time at node *i* is[^o14]

$$\mathbb{E}(W_i) = \frac{1+\rho_i}{2} \mathbb{E}(C) + \frac{(1+\rho_i) \text{Var}(C_i)}{2 \mathbb{E}(C)}$$

and for exhaustive service

$$\mathbb{E}(W_i) = \frac{1-\rho_i}{2} \mathbb{E}(C) + \frac{(1-\rho_i) \text{Var}(C_{i+1})}{2 \mathbb{E}(C)}$$

where *C*<sub>*i*</sub> is a random variable denoting the time between entries to node *i* and[^o20]

$$\mathbb{E}(C) = \sum_{i=1}^n \frac{\mathbb{E}(d_i)}{1-\rho}$$

The variance of *C*<sub>*i*</sub> is more complicated and a straightforward calculation requires solving *n*<sup>2</sup> linear equations and *n*<sup>2</sup> unknowns,[^o21] however it is possible to compute from *n* equations.[^o22]

## Heavy traffic {#Heavy_traffic}

The workload process can be approximated by a [reflected Brownian motion](wikipedia://en/35046943) in a heavily loaded and suitably scaled system if switching servers is immediate[^o24] and a [Bessel process](wikipedia://en/7646799) when switching servers takes time.[^o25]

::: {#o27 .application cue=heading name="Applications"}

## Applications {#Applications}

Polling systems have been used to model [Token Ring](https://en.wikipedia.org/wiki/Token_Ring) networks.[^o28]
