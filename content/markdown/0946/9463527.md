# Algebraic modeling language

::: {#o1 .subject cue=lead name="Algebraic modeling language"}

**Algebraic modeling languages** (**AML**) are high-level [computer](https://en.wikipedia.org/wiki/Computer) [programming languages](https://en.wikipedia.org/wiki/Programming_languages) for describing and solving high complexity problems for large scale [mathematical](https://en.wikipedia.org/wiki/Mathematical) computation (i.e. large scale [optimization](https://en.wikipedia.org/wiki/Optimization_%28mathematics%29) type problems).[^o2] One particular advantage of some algebraic [modeling languages](https://en.wikipedia.org/wiki/Modeling_language) like [AIMMS](https://en.wikipedia.org/wiki/AIMMS),[^o2] [AMPL](https://en.wikipedia.org/wiki/AMPL),[^o3] [GAMS](https://en.wikipedia.org/wiki/General_Algebraic_Modeling_System),[^o2] [Gekko](wikipedia://en/57256998), [MathProg](https://en.wikipedia.org/wiki/MathProg), [Mosel](https://en.wikipedia.org/wiki/FICO_Xpress),[^o2][^o4] and [OPL](wikipedia://en/45712685) is the similarity of their syntax to the mathematical notation of optimization problems. This allows for a very concise and readable definition of problems in the domain of optimization, which is supported by certain language elements like sets, indices, algebraic expressions, powerful sparse index and data handling variables, [constraints](wikipedia://en/7418540) with arbitrary names. The algebraic formulation of a model does not contain any hints how to process it.

:::

An AML does not solve those problems directly; instead, it calls appropriate external algorithms to obtain a solution. These algorithms are called [solvers](https://en.wikipedia.org/wiki/Solver) and can handle certain kind of [mathematical problems](wikipedia://en/256700) like:

- linear problems
- integer problems
- (mixed integer) quadratic problems
- [mixed complementarity problems](wikipedia://en/6439136)
- [mathematical programs with equilibrium constraints](https://en.wikipedia.org/wiki/Mathematical_programs_with_equilibrium_constraints)
- constrained nonlinear systems
- general nonlinear problems
- non-linear programs with discontinuous derivatives
- nonlinear integer problems
- global optimization problems
- [stochastic optimization](wikipedia://en/7325543) problems

## Core elements {#Core_elements}

The core elements of an AML are:

- a modeling language interpreter (the AML itself)
- solver links
- [user interfaces](https://en.wikipedia.org/wiki/User_interfaces) (UI)
- data exchange facilities

::: {#o7 .statement cue=named-heading name="Design principles"}

## Design principles {#Design_principles}

Most AML follow certain design principles:

- a balanced mix of declarative and procedural elements
- [open architecture](https://en.wikipedia.org/wiki/Open_architecture) and interfaces to other systems
- different layers with separation of:
  - model and data
  - model and solution methods
  - model and [operating system](https://en.wikipedia.org/wiki/Operating_system)
  - model and interface

### Data driven model generation {#Data_driven_model_generation}

Most modeling languages exploit the similarities between structured models and relational databases [^o14] by providing a database access layer, which enables the modelling system to directly access data from external data sources (e.g. these[^o9] table handlers for AMPL). With the refinement of analytic technologies applied to business processes, optimization models are becoming an integral part of [decision support systems](https://en.wikipedia.org/wiki/Decision_support_system); optimization models can be structured and layered to represent and support complex business processes. In such applications, the multi-dimensional data structure typical of OLAP systems can be directly mapped to the optimization models and typical MDDB operations can be translated into aggregation and disaggregation operations on the underlying model [^o10]

:::

## History {#History}

Algebraic modelling languages find their roots in matrix-generator and report-writer programs (MGRW), developed in the late seventies. Some of these are MAGEN, MGRW (IBM), GAMMA.3, DATAFORM and MGG/RWG. These systems simplified the communication of problem instances to the solution algorithms and the generation of a readable report of the results.

An early matrix-generator for LP was developed around 1969 at the Mathematisch Centrum (now CWI), Amsterdam.[^o12] Its syntax was very close to the usual mathematical notation, using subscripts en sigmas. Input for the generator consisted of separate sections for the model and the data. It found users at universities and in industry. The main industrial user was the steel maker Hoogovens (now Tata Steel) where it was used for nearly 25 years.

A big step towards the modern modelling languages is found in UIMP,[^o13] where the structure of the [mathematical programming](wikipedia://en/52033) models taken from real life is analyzed for the first time, to highlight the natural grouping of variables and constraints arising from such models. This led to data-structure features, which supported structured modelling; in this paradigm, all the input and output tables, together with the decision variables, are defined in terms of these structures, in a way comparable to the use of subscripts and sets. This is probably the single most notable feature common to all modern AMLs and enabled, in time, a separation between the model structure and its data, and a correspondence between the entities in an MP model and data in relational databases. So, a model could be finally instantiated and solved over different datasets, just by modifying its datasets.

The correspondence between modelling entities and [relational data models](https://en.wikipedia.org/wiki/Relational_database),[^o14] made then possible to seamlessly generate model instances by fetching data from corporate databases. This feature accounts now for a lot of the usability of optimization in real life applications, and is supported by most well-known modelling languages.

While algebraic modelling languages were typically isolated, specialized and commercial languages, more recently algebraic modelling languages started to appear in the form of open-source, specialized libraries within a general-purpose language, like [Gekko](wikipedia://en/57256998) or [Pyomo](https://en.wikipedia.org/wiki/Pyomo) for [Python](https://en.wikipedia.org/wiki/Python_%28programming_language%29) or [JuMP](https://en.wikipedia.org/wiki/JuMP) for the [Julia language](https://en.wikipedia.org/wiki/Julia_%28programming_language%29).
